Reading:
- A, B: AppKit's own key-view loop (autorecalculatesKeyViewLoop): a focused view goes on to the next key view after it in
  the window's order and back to the one before it, whether or not it is a key view itself (A: canBecomeKeyView false,
  AppKit's nearest thing to tabindex=-1). Tab -> First, Shift+Tab -> Before, as Chrome.
- C, D: an explicit loop that links only the stops and leaves Box's nextKeyView nil (the macOS host's shape): Tab leaves
  the focus on Box, with or without an initialFirstResponder. (Their Shift+Tab reaches Before only through the
  previousKeyView that AppKit's first-display loop left on Box; the Exact host's Shift+Tab stays on the box.)
- E, F: the same explicit loop with Box.nextKeyView = First and no stop pointing to Box (what syncKeyViewLoop already does
  for a clicked paragraph): Tab -> First.
