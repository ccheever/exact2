surfaces: web
agent: Claude Code (Claude Opus 5.5)
task: add reading and writing NFC tags to a book's screen

### Rough

- A local `derive reading` hid the module's `reading` event, so `main
  reading=tagRead` failed `lower-unknown-attr` with the event in the `use`
  line. Renamed the derive to `inProgress` (now in
  `docs/agent-pitfalls.md`). About 20 minutes.
- The binding types an `option<…>` field of a module's shape as required
  (`T | null`), so each `NDEFRecordInit` written from `app.ts` spells out
  `mediaType`, `id`, `encoding` and `lang` as `null`, and `errorMessages`
  names every cause. The type check every build runs caught it.
- On the web, a write held on the permission prompt and then allowed lost
  its arguments (`host/web-js/modules.js` re-decided it without them), so
  it failed `TypeError` and the alert said the tag could not be written.
  Fixed in the runtime.
- Driving: `prefer extension nfc.field=blank` is refused ("JSON Parse
  error"); the value is JSON, `nfc.field="blank"`. `tree <id>` finds a
  closed dialog's nodes too, so whether the panel shows is read from
  `state panelShown`. A dialog's `id` is no target; give it a `testId`.

### Lean in

- The declared substitute drove every case without a radio: tags declared
  once, `nfc.field` to bring one into the field, tickets for cancel and
  timeout, and `state extensions.nfc` showing what each tag holds after a
  write.
- `prefer visibilityState hidden` suspended a scan and, on return, read the
  tag still in the field, which is the whole of the background drive.
