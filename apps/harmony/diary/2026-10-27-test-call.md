surfaces: web, ios, macos
agent: Claude Code, Claude Opus 5.5
task: add a test call that records and plays back a few seconds

## Rough

The call's list needed fields no declared keyed list had: an entry stamped with its start, a send refused by
name for an entry in the wrong state, an entry that ends rather than leaves, and a field admission reads
(`inCall`). Each was added to the declared list for every module (`runner/src/runner/modules/declared/update.rs`,
`host/web-js/update.js`), not to the app.

Harmony's `package.json` is its backend's and names no `@exact/recording`, so the test call cannot place the
recorder's waveform view; the screen shows the call's state instead.

## Lean in

The declared substitute let the whole call (dial, connect, record, play back, hang up, hold) be driven in
Chromium and on the macOS runner with `tap @ref hold|unhold|mute|hangup`, before any system call screen exists.

## Needed

- calls: provided as the module's own state, with Media Session's call actions on the web; no CallKit or Core-Telecom yet
- recording: provided, smooth
- microphone: provided, smooth

## Checkpoints

- editing app.contract: smooth
- web build: smooth
- driving the app: smooth in Chromium; the iOS build of the test call was not driven

## Rough (the web's call controls)

In a browser with no agent the test call was never placed: an extension with no web implementation refuses its sends
outside the agent, so the declared list that answers under the agent did not. `@exact/calls` now carries a web
implementation that answers from that list and adds Media Session's `hangup` and `togglemicrophone`. Headless
Firefox and WebKit play no sound, so the take's playback never ends there and the drive dispatches its `ended`.

## Rough (Linux)

Under the agent on Linux the test call connected and then stayed connected: `getUserMedia` answers
`NotSupportedError` there, a refused mutation runs no `then`, and nothing ended the call. A denied microphone
permission did the same on every host. The test call now reads `failure(callOpened)` and `failure(callStarted)`
and ends the call `failed`. Finding it took one drive; a refusal path in a `then` chain is easy to miss.

## Rough (CallKit)

On an iOS 27 simulator with `--bind calls`, CallKit first refused the test call's start as `unentitled`: `device.calls`
derived only the `audio` background mode, and CallKit wants `voip` too; the line now derives both. With it, CallKit
performs the start and the call claim is made, then ends the call itself about 60 ms later with no `didActivate`. The
app hears it as a hang-up and stops cleanly. Whether a phone does the same is drive 12's question.
