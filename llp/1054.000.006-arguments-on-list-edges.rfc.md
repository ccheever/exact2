# LLP 1054.000.006: Arguments on list edge events

**Type:** RFC
**Status:** Draft
**Systems:** Contract analysis (`handler_arity`), runner (`dispatch_edge`); no plan format change
**Author:** Claude (Opus 5.5) for Charlie Cheever
**Date:** 2026-09-26
**Related:** LLP 1054 L7/D4 (the finding); LLP 1054.000 C5 (the question, left for Charlie); LLP 1027.004 (bounded answers; the edge events); LLP 1010 §6 (collections); reviews `llp/reviews/1054.000.003-004.{claude,astra,grok}.md` (both received reviews recommended C5 on its own)

## Summary

`reachstart`, `reachend` and `refresh` are the only handler attributes that
refuse arguments (`contract/analyze/src/lib.rs:438-440`). So a handler cannot
tell which list reached its edge, or how far that list had loaded.

This RFC lets them take arguments, like `press`:

```
each f in feeds key=f.id
  list virtualized=true reachend=more(f.id, f.cursor) refresh=pull(f.id) …
```

The arguments are evaluated in the list node's scope when the event is
dispatched. An edge event has no payload, so the action's parameters are
exactly the bound arguments.

The plan already carries every handler's arguments, `handlers[].args`, and
`dispatch` already evaluates them for host events
(`runner/src/runner/event.rs:782-785`). Only the analysis rule and the
runner-only edge path change.

## Motivation

- **Which list.** Bluesky keeps one virtualized list per pinned feed mounted,
  inside `each f in feeds` (`screens.contract:240-242`). `reachend=more`
  cannot say which feed reached its end.
- **How far.** A `reachend` fires on a short list while its first page is
  still loading (LLP 1054 D3). To avoid asking for page two before page one
  lands, the port guards each `more*` action with a count it reads off the
  lists through an extra resource: `resource loads = loaded(homeFeeds,
  authorFeeds)` (`app.contract:91`) and `if loads.feed > feedAsked`
  (`app.contract:229-236`). The same guard is repeated for notifications,
  search, people and chat (`:237-243`, `:349`, `:359`). With arguments, the
  handler receives the list's own progress, and the extra resource goes away.
- **Bounded answers need it.** LLP 1027.004 moves a list's window into its
  resource's arguments. For more than one list, the handler must know which
  window to move and from which cursor. Astra: "C5 must bind progress/cursors
  as well as identity to remove `loaded(...)`".

## Design

### D1 — The rule

`handler_arity("reachstart" | "reachend" | "refresh", given)` becomes
`Some(given..=given)`. An edge or refresh event appends no payload, so the
action takes exactly the arguments bound at the site. A bare name
(`reachend=more`) is zero arguments, as today. The analysis
(`contract/analyze/src/lib.rs:559`) and lowering
(`contract/lower/src/lib.rs:1392`) share the rule, so both follow.

### D2 — Evaluation at dispatch

`dispatch_edge` (`runner/src/runner/event.rs:640-671`) evaluates
`handler.args` in the node's frames, as `dispatch` does. It then runs the
action with them instead of `Vec::new()`. The frames come from `self.find(view)`,
already called there. A host `refresh` goes through `dispatch`, which already
evaluates the arguments.

The values are read when the edge fires, not when the list was built. A
cursor that moved since the last realization is the one the handler sees.

### D3 — What stays the same

- **Gating.** An edge is dispatched only when the list has a handler for it
  (`edge_handlers`, `runner/src/instance/collection/mod.rs:234`). Arguments
  don't change that.
- **The journal line.** It keeps `reachend view N (action)`.
- **Deferred edges.** They are woken as before (`collection.rs:180`), and
  arguments are evaluated when they finally dispatch.
- **Plan format.** No change: `handlers[].args` already exists for every
  event, and edge handlers simply had none.

## What an app writes

```
action more(feed: string, cursor: string) writes window
  window = cursor          // or a per-feed map the source keys on
…
list virtualized=true reachend=more(f.id, f.cursor)
```

For the Bluesky guard: `reachend=moreFeed(f.loaded)` with
`if loaded > feedAsked`. The `loads` resource is deleted.

## Tests

- **Compiler.** `reachend=more(f.id)` type-checks against
  `action more(id: string)`. An action with a different parameter count is
  refused with the existing handler-arity diagnostic. `collection_edges.rs:481`
  (`reachstart=change(0, 2)`) moves from a refusal to an accepted case, and a
  wrong-count case replaces it.
- **Runner.** Two lists in an `each` each dispatch `reachend` with their own
  key. An argument read from state sees the value at dispatch, not at build.
  A deferred edge evaluates at its dispatch.
- **Consumer.** The Bluesky port's `loaded(...)` resource and the `*Asked`
  counters it feeds are replaced by bound arguments. Driven on the web: scroll
  a pinned feed to its end and exactly one page request is issued.

## Costs

About 10 lines across two files, plus tests. There is no new vocabulary,
because it relaxes a refusal. The only consumer is Bluesky, which is not
admitted (LLP 1054.000's consumer bar). Messages' transcript is one list and
needs no arguments.
