## Consumer and scope

Charlie requested a standalone Windows Skirmish, an exact2 Windows implementation
including its game engine, engine LLPs before changes, and continuously tested
commits to main. This admits the Windows target deferred in `rules/DEFERRED.md`.
The take is single-player Skirmish first: multiplayer and general Windows app
features wait behind a working, measured game. No core engine dependency, Hermes
requirement, new blocking gate or forked simulation is introduced.

## Implementation

1. Reuse `exact-linux::Presenter` as the existing portable native presenter. It
   already owns Contract, layout, text, agent, input, image and GPU-module seams.
   `host/windows` adds only a winit Windows event loop and softbuffer presentation
   of that presenter's frame. Naming/extracting the shared presenter can follow a
   separately justified refactor; duplicating it would create divergent behavior.
2. Remove unconditional Unix dependencies from the shared code: isolate Unix file
   descriptor methods, provide a nonblocking wake stream on Windows, and use a
   real Windows/IANA time-zone implementation. Existing Linux wake/poll behavior
   stays byte-for-byte in its Unix branch. Local file reads on Windows must still
   reject directories/special files before decoding.
3. Generate a Windows executable shell beside the existing game shells. Extend
   the existing bake to recognize binary Windows roots and native DLL filenames.
   Keep exact-gpu's signed/baked product identity validation before loading. The
   game remains a lazily loaded DLL. Enable DX12 for the Windows GPU target;
   Vulkan remains available, with adapter errors reported rather than hidden.
4. Forward physical key codes, mouse buttons, pointer coordinates/motion, wheel,
   resize and focus loss through Presenter. Coordinates and framebuffer dimensions
   use one scale consistently; a focus loss releases held input. Close exits the
   event loop. A minimized window stops presenting, and idle apps do not busy-loop.
5. Package the executable, GPU DLL and baked assets together. Headless agent and
   screenshot modes use the same presenter and remain available for repeatable
   gameplay verification. `scripts/agent.mjs` exposes the Windows stdio carrier,
   and game proof receipts include the packaged executable, DLL and assets rather
   than reusing another platform's build receipt. No web server is necessary at runtime.
   The Windows-machine proof baseline requires all native simulation modes, native
   release and cross-web agreement, matching the existing Linux-machine baseline.
   Other hosts retain their native lanes. The parent reviewer approved this scope
   extension on 2026-10-04; no baseline pins precede actual successful observations.
6. The native agent's `tap ... contextmenu` delivers an ordinary mouse move,
   right-button down and up through `Presenter.pointer_aux`, at the same checked
   projected target center as the browser. Refuse non-canvas, covered and held
   contact targets; do not turn an unsupported context menu into primary activation.
   This closes the RTS right-click proof gap. A touch leaves Chrome pointer ID 2
   and the native presenter ID 1 in saved input even when the world is identical.
   A genuine final mouse command aligns those input states without changing raw
   platform IDs, save bytes or the exact cross-platform byte-comparison bar.
   The parent approved this narrow extension on 2026-10-04 with a route/input test.
7. Bake the app manifest's display name as a separate Windows entry argument;
   use it for the window title without changing the compatibility app ID. The
   generated Windows shell uses the GUI subsystem in release builds, while
   preserving inherited agent stdin/stdout pipes. Verify PE subsystem 2 and an
   actual pipe exchange, then repeat the packaged game agent smoke after baseline
   capture. The parent approved this narrow launch extension on 2026-10-04.
8. Honor `tap(target, {contextmenu: true, at: [x, y]})` as a point in logical
   coordinates relative to the target's projected top-left corner, on Windows,
   Linux and browser carriers. Without `at`, preserve the center default. Parse
   exactly two finite numbers, require the point inside the target and viewport,
   and hit-test that point before any input; refuse covered, non-canvas and held
   contact native requests. Browser carriers send the ordinary right mouse button
   at that same point. Other carriers explicitly refuse the new point form until
   qualified. Skirmish minimap orders exposed the dropped-coordinate bug. Test an
   off-center point, malformed/outside points and unchanged input on refusal.
   The parent reviewed and approved this narrow correction on 2026-10-04 before
   implementation; the raw pointer identity and save contract remain unchanged.
   Verification: 42 native surface tests and ten Windows tooling tests pass,
   including actual trusted Chrome right-button events at an off-center point,
   strict pair/bounds/cover/held-contact refusals, and no input on refusal. Native
   host strict Clippy, formatting, caps and boot checks pass. The Playwright path
   carries the same point but was not browser-qualified on this Windows machine.
9. Add inherited CSS `cursor` through the schema, with the bounded vocabulary
   `auto` (initial), `default`, and `crosshair`. Contract bindings and both web
   targets emit this ordinary CSS property; Windows maps the effective style at
   the hit point to the OS cursor. Re-evaluate after commits/redraws, even with a
   stationary pointer, and revert after unmount, focus loss or pointer leave.
   `auto` preserves existing host/control defaults. An authored HUD control must
   explicitly set `cursor="auto"` to override the canvas's inherited targeting
   cursor, as CSS requires. No images, pointer lock, gameplay state or new layout
   semantics are involved. CSS inheritance and initial value follow
   [CSS UI 4 §5.1.1](https://www.w3.org/TR/css-ui-4/#cursor).

   Parent review approved this slice on 2026-10-04 before implementation, with
   the stationary-pointer, unmount/focus/leave and HUD override checks above.
   Windows and web are the qualified rendering targets of this slice. Linux's
   software pointer and AppKit retain their existing pointer until separately
   implemented and swept; the semantic row is carried, but their cursor rendering
   is explicitly unsupported, as host-specific affordance rows can have no
   rendering on other hosts. No native cross-host parity is claimed. Touch-only
   devices have no cursor. Reject other keywords and image cursor values in this
   bounded row; test parsing, inheritance/clear, dynamic updates, hit coverage and
   browser computed style. The parent explicitly approved qualifying the other
   native adapters separately rather than blocking the Windows consumer.

   Verification: schema parsing/inheritance/clear, CSS emission and the native
   presenter's fixed-position hit sweep pass, including a covered HUD, a dynamic
   change without pointer motion, and unmount. An actual compiled JS-target app
   in Chrome reports default, crosshair, auto on clear/invalid binding, and absent
   after unmount, while the HUD stays auto. Windows strict Clippy passes; the
   locked desktop still prevents observing the physical OS cursor or focus/leave
   visually. The broader Contract/kernel/web checks pass with the existing
   10,000-row `a_theme_flip_restyles_each_touched_row_once` case excluded after
   its owned test process exceeded several minutes and was stopped. That slow
   case is not a passing full-web-gate claim. Separate web fixes reserve the
   already-emitted scrollstart/liststyle data words and update the Caltrain
   state fixture for its existing tv field; neither changes cursor semantics.

and CPU UI composition followed by a window upload. This is a native correctness
baseline, not a zero-copy or performance-parity claim. Measure Skirmish frame

direct swapchain presentation with a GPU-composited Contract overlay through the
same module ABI, reviewed before changing ownership. Do not encode Windows-only
gameplay or reduce simulation fidelity to conceal a host cost.

## Windows game audio slice (2026-10-04)

**Implementer:** Codex, starting 2026-10-04, under Charlie's standalone Windows
game and engine-parity request. The existing `SurfacePlayer` chooses real outputs
only for Apple and web; Windows has no device implementation. Skirmish also has
not yet authored sound definitions or opted into `game.audio`. The Linux host's
discarded `exact:audio` message is Apple's session-policy request, so Windows does
not need a new message protocol to open a device. It does need lifecycle delivery.

Reuse the existing `Output`/`Player` path, saved sound descriptions, synth/sample
PCM, spatial gain calculation, voice ranking, and pause/seek generation rules
from LLP 1046.003 AU3/AU4. Move the current Apple SPSC queues, retained-PCM owner,
and mixer into a shared native implementation; keep its existing fixtures and
Apple AudioUnit boundary. Windows supplies a WASAPI shared-mode output over that
same mixer. It requests interleaved float stereo at 48 kHz with the platform's
format conversion, and renders only the endpoint's available frames when its
event fires. The device and COM interfaces belong to one dedicated thread.
Mixing keeps the existing 32 voices, 64 MiB retained-PCM budget, bounded commands,
10 ms gain ramps, interpolation, and non-finite/clipping firewall. No alternate
game audio state, realtime allocation, or callback-side Arc release is added.

The owner requests suspend/resume/shutdown through bounded revisioned state and
an event. Suspension stops and resets the endpoint. Before acknowledging resumed
readiness the device clears old mixer voices and acknowledges discarded commands,
so queued pre-suspension audio cannot escape before the Player resynchronizes.
Even a coalesced suspend/resume pair changes the revision and resets output.
Resume uses the Player's current world offsets through the existing epoch
mechanism. Drop wakes and joins the device
thread before releasing PCM or allowing the GPU library to unload. Add a default
no-error query to `Output` so a Windows render/device failure reaches
`SurfacePlayer`: it logs the failure, disposes the device, and uses the existing
300-live-frame retry. A missing endpoint refuses explicitly. Device invalidation
reopens the current default endpoint on retry; automatic migration from an
otherwise healthy endpoint after the default changes is not claimed in this
slice. Agent/seekable surfaces continue to open no device.

Forward the existing GPU lifecycle ABI from the Windows host: minimize/occlusion
maps to hidden/visible and focus loss/return maps to interruption/resumption.
The presenter retains the two independent states and applies them to newly
mounted surfaces, so a replacement cannot start sound while the window is still
hidden or unfocused. Ordinary game pause continues through `Transport.playing`.
These notifications affect presentation ownership, never saved simulation data.

**Qualification:** keep the existing mixer/player/surface tests green and add
focused failure/retry and host lifecycle delivery cases. Run native audio and
renderer tests, strict lint and format; compile the unchanged Apple path where
the available cross toolchain permits. A Windows device probe must establish
accepted render frames and a nonzero signal through WASAPI loopback, then silence
on suspend/stop and resumed playback; inspect stereo balance and sampled/synth
mixing through the existing mixer fixtures. Finally build and drive the existing
audio fixture with a live Windows clock and verify agent clocks stay silent.
Device/loopback evidence is distinguished from a human hearing the speakers.
Skirmish may then use original procedural command, selection and shot cues through
the existing sound API, coordinated with its gameplay owner; no Blizzard assets.

WASAPI references: [stream flags](https://learn.microsoft.com/en-us/windows/win32/coreaudio/audclnt-streamflags-xxx-constants)
and [loopback capture](https://learn.microsoft.com/en-us/windows/win32/coreaudio/loopback-recording).

**Audio review, 2026-10-04:** independent Codex parent reviewer approved this
slice before implementation. Preserve shared mixer bounds and independent hidden /
interruption state. Every startup/error path must wake and join the COM worker
before PCM or library release. Coalesced suspend/resume still resets stale voices;
retries must not spin or retain an old device. Loopback qualification detects only
the known probe signal and never retains unrelated system audio. Qualify the Apple
refactor with available compile/tests and name unavailable cross-builds. Accepted
by implementer; one same-family review, no cross-family review claimed.
