## Summary

LLP 1054 lists thirty-two open findings from the Bluesky port. The first
draft proposed twelve changes (R1–R12) as one lane. Two reviews (a Claude
subagent, the same family as the author, and GPT-6 Astra at maximum effort)
found it **not ready as a package**. Both said the same four things: R1
(a source says its answers changed) and R2 (keep an identical request in
flight) change the request lifecycle and interact badly. R3 as written
added an unbounded queue. R5 (wildcard grants) reverses a deliberate
security decision. R6 put P1's cause in the wrong place. Grok 4.7 was
requested and **not received**: its CLI is not installed here.

This revision follows the reviews. The changes split three ways:

- **Landed** (§Landed): the reservation fix that replaces R3, the Taffy fix
  for P1 (R6), AppKit clipping (R7, R8), screenshots that wait for images
  (R9), the script fixes (R10), the compiler items (R11), the Rust shape
  generator (R4), and the date on Linux (R12). Every one of these is small,
  tested, and adds no vocabulary an app writes.
- **Designed and landed after** (§Deferred, now LLP 1054.000.000): R1 and
  R2 together — `mutation m … refreshes r` and keeping an identical
  request on an argument-only re-ask. So did C4 (`first`), L9 (Contract
  diagnostics last) and R4's first consumer (the Bluesky data crate).
- **Decisions for Charlie** (§For Charlie): R5 moves here with a default
  of no. C1–C6 are revised as the reviews advised.

## Landed

### R3 → admission charges request buffers; the worker waits for the ceiling (D5)

The first draft wanted over-budget reads to wait in an unbounded queue, with
a deadline that does not exist. Both reviews rejected that. The actual
defect was narrower. `reservation` charged an independent job its whole
response ceiling at admission, while `next_job` already charges the rest
when a job starts and waits for bytes. That is the same bug LLP 1041 §8.4
fixed on the ordered lane.

Both lanes now charge a waiting job only its request buffers. A running job
is charged its ceiling, and a finished one what it keeps. The count limit
(128) still refuses, so the waiting queue is bounded by count, and by bytes
through the charged buffers. A ceiling the lane can never hold (more than
32 MiB reserved, so any `max_response_bytes` from about 16 MiB up) is
refused at admission, not left waiting forever. Linux shares the file.

Tests: `an_independent_read_over_the_budget_waits_instead_of_refusing` (the
port's two 8 MiB reads), and the ceiling refusal added to
`byte_budget_and_illegal_opt_ins_refuse_before_transport`.

### R6 → Taffy patch 14: a flex item's contribution clamps before its margin (P1)

The Claude review asked where P1 actually lives, and Astra said the
collection measures its wrapper's border box by contract. Dumping kernel
frames settled it: the kernel was wrong, not UIKit. Taffy's intrinsic
main-size contribution added the item's margin, then took `max` with its
flex basis and clamped by its min/max size. A negative margin was
swallowed by the clamp. In the reduced case the column measured 330
against the browser's 286. The fix clamps the inner size and then adds
the margin, on both the preferred-size branch and the measured branch
(`vendor/taffy/EXACT-PATCHES.md`, patch 14, marked to upstream).

This fixes iOS, macOS and Linux at once, and the collection contract is
unchanged. Test: `contract/cli/tests/it/negative_margin.rs` (five row forms
plus the port's profile header, each checked against the browser's
arithmetic).

### R7 — AppKit clips `overflow: hidden` to the rounded box (P2)

An AppKit node with hidden overflow sets `clipsToBounds` (on a layer-backed
view, the layer's `masksToBounds`). When all four radii are equal, it also
sets `layer.cornerRadius` to that radius. Unequal radii clip to the
unrounded box, as UIKit's layer does. Astra noted that `layer.mask` already
carries `clip-path`. Composing an asymmetric rounded mask with it is not
done, and that deviation is declared in LLP 1001. Test:
`ClipMacTests` (the avatar case, removal restoring no radius).

### R8 — AppKit clips a clamped paragraph (P3)

A text node with `line-clamp` clips to its box. The premise changed after
review: CSS's `line-clamp` does not imply `overflow: hidden`, but exact2's
web adapter emits it with its clamp (`host/web/src/css.rs`). This is parity
with the web's *effective* behaviour, and a text node is always the block
paragraph that rule applies to. A line in the old code had reset
`clipsToBounds` from overflow alone, later in the same `applyStyle`. The
new test caught it. Test: `ClipMacTests.testAClampedParagraphClipsItsDrawing`.

### R9 — web screenshots wait for images; `layout <testId>` already worked (A1, A2)

`screenshot` on the web waits up to 3 s for every `img` in the viewport to
be `complete` (a broken image counts as finished) and reports
`imagesPending` when it gave up. `clock settle` is unchanged. The Claude
review warned that wall-clock network waits do not belong in the clock the
agent owns. Verified: the port's signed-in feed shot shows every avatar
with no sleep, and the screenshot took 241 ms. A2 was wrong: `layout`
already resolves a testId. iOS image settling stays QUEUE's line.

### R10 — the scripts (O2, O5)

- **An outside app builds its web output under its own target**
  (`scripts/app.mjs` `webDist()`: `EXACT_WEB_DIST`, else
  `<app>/target/web-dist` for an app outside the repo, else `host/web/dist`).
  `build.mjs`, `dev.mjs`, `serve.mjs` and the agent all read it. One app's
  build can no longer replace another's page under a running server. This
  fixes O5, where a warning would only have reported it (both reviews).
  `serve.mjs` also names the app it serves.
- **Prerequisites are fetched when missing, not probed on every build.**
  Missing std sources are checked once, with a marker written only when
  they are present, and fetched `--locked`. The app workspace's
  `cargo fetch --locked` runs only after a build fails on an offline miss.
  The warm path does no work.
- binaryen: every message that names version 132 now links its release
  download. A missing or different binaryen still builds, unsplit or
  unoptimized, as before. It stays a warning, not a failure.
- `host/apple/build.mjs` uses Xcode's developer directory when
  `xcode-select` names the Command Line Tools and Xcode is installed, and
  says so.
- L9, *done 2026-09-26:* when a host build fails and the app has an
  `app.contract`, `scripts/app.mjs` runs `contract build` once. If the
  Contract does not compile, the build ends with every diagnostic, and
  only those, with paths relative to where it ran. A successful build pays
  nothing.
  Completed 2026-10-02: the block is the last thing printed (the build
  scripts end there, no stack after it, `contractLast`), and the JS
  target's compiler (`exact-web-js js`, the default web build's first
  step) prints every refusal too, not the first with its path doubled.

### R11 — the compiler names reserved words and each component's cost (L2, L10)

A keyword in a name position says: "expected a name, found `key`, a
reserved word: choose another name (`keys`, `myKey`)". `contract build`
prints the node cost of each component, with inlined uses included, after
its summary line (the port's: `Row 535 (5×), PostRow 380 (5×), …`). Counts
are inclusive of nested components, so they do not sum to the total. Totals
were already printed (Astra).

### R4 — `contract rust`: Rust shapes from the plan (D1)

`contract rust <file.contract> [-o shapes.rs]`, beside `contract types`, is
generated from the plan's types table as the TypeScript is (the Claude
review). It emits one `pub struct` per named shape, fields in declaration
order, with `camelCase` and hyphens mapped to `snake_case` and keywords
escaped (`r#type`). Types map as `number` → `f64`, `bool`, `string` →
`String`, `unit` → `()`, `option<T>`, `list<T>` → `Vec<T>`, and a shape →
its struct. Each struct has `From<&T> for Value` and
`TryFrom<&Value> for T`, which checks the field count. `contract::rust` is
a library function, so a data crate's `build.rs` can call it with no
recursive cargo and `include!` the result from `OUT_DIR`.

Swapping two same-typed fields passes the runner's shape check. A named
field cannot be swapped. Verified: the port's 30 shapes generate and
compile against `exact_runner`, and a `Session` round-trips. Test:
`contract/cli/tests/it/rust_shapes.rs`. The port's data crate now generates
them in `build.rs`, and builds `Session`, `Change` and `Loads` from them.
Shapes that hold posts stay positional until its posts are structs too.

### R12 — the date on Linux (X1)

The Linux host sets `exactTime` at boot: epoch = wall time − the clock's
elapsed time, as Apple does. The offset is the local zone's current offset
in minutes east, from `localtime_r` (so named zones and `/etc/localtime`
work). A zero offset unless `TZ` is fixed would have been wrong on
ordinary systems (both reviews).

## Deferred: R1 and R2 need one design

*Done 2026-09-26:* designed in LLP 1054.000.000 and landed. R1 is a
declaration, `mutation m as shape T refreshes a, b`. At the send, the runner
re-reads those resources: it shows what the source answers now and sends
nothing. At the reply, it refreshes them, forced. R2 keeps a ticket only on
an argument-only, unforced re-ask with an equal plain-HTTP request, which
amends LLP 1016 D5. The Bluesky port dropped `rev` from nine resources and
seven actions. RealWorld dropped `changeStamp`/`authStamp` from five
resources. The constraints below were the brief.

Both reviews rated these blockers as written, and they interact: an R2
that keeps an identical GET in flight can let a pre-mutation reply satisfy
the refresh R1 asked for. A design must settle all of the following:

- **Where invalidation is declared.** A source-side `changed()` is
  invisible in the plan and in `state`. Contract already has `refresh r`
  in action bodies, and a declared form (a resource that refreshes after a
  mutation) may be enough. `apps/realworld` is the in-repo consumer
  (`changeStamp`/`authStamp`), and it should migrate in the same change.
- **Transport.** Every forwarding source (`Storage`, `Mixed`, `Placed`,
  `Anonymous`, `Swappable`, the TypeScript `Module` natively and on the
  web), worker envelopes, and the Rust module ABI (`rustAbi`) must carry
  it. A default-empty method on a forwarder silently drops it. TypeScript
  parity (LLP 1027.001) must be settled too.
- **Transactions.** Invalidations must be kept across a refused commit
  (checkpoint/restore). They must merge with `refresh_next` rather than be
  overwritten, and must survive a `parse_for` that returns `Later`. A
  source that marks itself must not loop.
- **Freshness.** Only an argument-caused, unforced re-ask may keep a
  request in flight. `refresh`, an R1 mark, a store revision and
  `data_ready` must never keep one, and neither may storage or continuation
  requests. Equality is `Request`'s derived `PartialEq`, compared together
  with `forced`. `forgotten` must still fire for parking sources. The
  change is recorded as an amendment to LLP 1016 D5.

## For Charlie

- **R5 — wildcard `net.fetch` hosts (D7).** *Ruled yes by Charlie,
  2026-09-26:* "a wildcard grant is probably worth it actually, and the
  developer should just use it carefully. Going through the bsky.social
  entryway might be causing unnecessary latency." Built as vendor/ibex2
  patch 1: `net.fetch scheme://*.domain`, fetch only. A cross-origin
  redirect drops credentials. There is no public-suffix check. The draft's
  recommendation, kept for the record: **Recommend no.** ibex2 excludes
  wildcards on purpose, and LLP 1016 D6 matches origins whole. A dot-count
  rule admits `*.co.uk`. Native redirects keep `Authorization` across
  origins, while the web uses `redirect: "error"`. The port's entryway
  route works. If you want it anyway, it needs a public-suffix policy,
  redirect credential stripping, normalization shared by Rust and JS, and
  subset rules for scopes. That is an ibex change.
- **C1 — button content alignment (L3).** Corrected premise: `button` is a
  flex column with *no* default alignment. You decided that on 2026-09-23
  ("One native button, flex column"). Centring both axes would match a
  bare `<button>` for one child. Every app with a top-left button label
  would move. Recommend deciding both axes and the multi-child case
  together, or leaving your 09-23 decision as it is. *Decided 2026-10-04:
  reversed; a `button` is Chrome's `<button>`, centred on both axes as a
  block button is (LLP 1001 §1; LLP 1054.000.001 is superseded).*
- **C2 — independent `GET` by default (D6). Recommend no** (both reviews
  agree). Independence promises that parsing may reorder, and a `GET`
  alone does not promise that. The landed R3 removes the refusals, not the
  serialization.
- **C3 — implicit record placeholders (L8). Conditional.** A generated
  zero must stay a placeholder (pending), never a baked answer. Nested
  records, options, activation, failure and carry need defining first.
  RealWorld's `emptyFeed`/`emptyArticle`/`emptyProfile` are the in-repo
  case.
- **C4 — `first(list) -> option<T>` (L5). Done 2026-09-26** (the roster's
  `first`; the Bluesky port uses it for a post's and a quote's first
  picture); `last` when a consumer needs it. It does not solve "find the
  viewer in a list".
- **C5 — `reachend` with bound arguments (L7/D4).** The draft said no once
  R2 landed. Astra disagreed: request reuse supplies neither list identity
  nor progress. Recommend considering bound arguments on their own,
  shared with `reachstart` and `refresh`.
- **C6 — pull to refresh on the web and AppKit (P4). Recommend no.** Apps
  give a refresh button where needed.
- **Consumer bar.** DEFERRED admits named consumers, and Bluesky is not
  one. Everything landed above is a fix to existing behaviour, or tooling
  (R4, R11) that RealWorld and every Rust data crate would use. Admitting
  Bluesky as a consumer is your call.
