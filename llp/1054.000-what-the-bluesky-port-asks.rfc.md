# LLP 1054.000: What the Bluesky port asks of exact2

**Type:** RFC
**Status:** Draft
**Systems:** Runner (re-asking, invalidation, in-flight requests), Contract compiler (a Rust shape generator, diagnostics, plan-size report, reserved words), native HTTP executor (admission), grants (web glue, native request checks), Apple presenters (list row sizing, AppKit clipping and line-clamp), web glue and agent driver (image settling, `layout <testId>`), scripts (prerequisites, served app), Linux host (the date)
**Author:** Claude (Opus 5.5) for Charlie Cheever
**Date:** 2026-09-26
**Related:** LLP 1054 (the findings, by id); LLP 1016 (requests and settlement), LLP 1016.000; LLP 1027.000.000 (the date); LLP 1036.001 (outside apps; D2 scaffold and D5 Hermes stay there); LLP 1041 §8.4 (native admission); LLP 1012 (agent API); LLP 1017.000; issue `clip-path-subset-of-css`

## Summary

LLP 1054 lists thirty open findings from the Bluesky port. This RFC
proposes what to do about each. Twelve are **implement now**: small,
additive, with no new app-facing vocabulary beyond what an existing rule
already implies:

1. a source can say which of its answers changed (D2);
2. a re-ask that would send the same request keeps the one in flight (D3);
3. independent reads over the budget wait instead of being refused (D5);
4. a Rust shape generator, the Rust twin of `contract types` (D1);
5. host-suffix `net.fetch` grants (D7);
6–8. three host-parity fixes (P1–P3);
9. the agent's settle waits for images, and `layout` takes a testId (A1, A2);
10. the scripts report every missing prerequisite at once, name the app
    `serve.mjs` serves, and surface Contract diagnostics last (O2, O5, L9);
11. the compiler names reserved words and reports plan size per component
    (L2, L10);
12. the date on Linux (X1).

Six are **decisions for Charlie**, because each changes a default or the
language: button centring (L3), ordered-by-default HTTP (D6), implicit
record placeholders (L8), list indexing (L5), `reachend` arguments
(L7/D4), and pull to refresh beyond iOS (P4). The rest stay where they
are already covered (O1, O3 in LLP 1036.001; L4 in its issue) or are
accepted as they are (O4, L6, A3–A5, D8).

## Design

### R1 — A source can say its answers changed (D2)

`DataSource` gains `fn changed(&mut self) -> Vec<String>`, defaulting to
none: the **source names** whose answers may now differ for the same
arguments. The runner asks after every call into the source that can
change it (`answer`/`answer_for` for a `send`, `parse`/`parse_for` for a
reply) and, before settlement, marks every resource whose source is named
as needing a re-ask, exactly as `refresh(resource)` does today. A re-ask
that answers `Now` with an equal value changes nothing downstream.

*Why source names, not resource names:* the source does not know the
app's resource names, and every resource of a source shares its answer
function. *Why not a return value on `Answer`:* a reply that changes
several sources (a chat send changes `chats` and `convos`) would need a
list anyway, and `parse` already returns the mutation's own value.

The port deletes its `rev` state and the argument from eight resources.
Tests: a `send` whose answer marks a source re-asks that source's
resources in the same commit; an unmarked source is not re-asked.

### R2 — A re-ask that would send the same request keeps the one in flight (D3)

When settlement re-asks a resource whose request is in flight and the
source answers `Later` with a request **equal** to the one in flight
(method, URL, headers, body, scheduling), the runner keeps the in-flight
ticket, updates the arguments it will `parse` with to the new ones, and
sends nothing. Any other answer (`Now`, or a different request) behaves as
today: the old ticket is forgotten.

Equality is the request's own, so it cannot keep a request whose
authorization or body changed. `parse` then receives the latest arguments,
which is what a source reading its arguments at reply time expects. The
port's two workarounds (lists waiting on `clock == 0`, the `loaded(...)`
guard) become unnecessary for correctness; the guard stays harmless.

### R3 — Independent reads over the budget wait (D5)

Native admission keeps its byte budget, but an independent read that does
not fit **waits** in arrival order until finished reads release enough,
instead of being refused. The count limit also queues. A wait longer than
the host's request deadline fails as today's timeout does. Ordered-lane
behaviour is unchanged. The refusal remains for one request larger than
the whole budget, which can never fit.

The `independent_http(max_response_bytes)` doc comment gains the
arithmetic ("reserves this much of a 32 MiB budget while in flight").

### R4 — Rust shapes from Contract (D1)

`contract rust <file.contract> [-o shapes.rs]`, beside `contract types`:
for each shape, a `pub struct` with the declared fields in declaration
order (`string` → `String`, `number` → `f64`, `bool` → `bool`, `list<T>`
→ `Vec<T>`, `option<T>` → `Option<T>`, a shape → its struct) and
`impl From<&T> for Value` writing `Value::record` in declaration order. A
data crate's `build.rs` may run it into `OUT_DIR` and `include!` the file.
Field order is then the compiler's, not a comment's.

Additive: no data crate changes unless it opts in. The port migrates its
`Session`, `Change` and `Loads` builders as the first consumer.

### R5 — Host-suffix grants (D7)

A `net.fetch` grant's host may begin with `*.`:
`net.fetch https://*.host.bsky.network` admits `https://a.host.bsky.network`
and `https://b.c.host.bsky.network`, not `https://host.bsky.network` and
not another scheme or port. One matcher, shared by the runner
(`request::io_grants`-adjacent), the web glue's `granted()` and the native
executor's check, with one test table run in Rust and in the glue's test.
The wildcard is refused anywhere but the leftmost label, and with fewer
than two labels after it (`*.com` is refused at bake). The native check
is ibex2's `GrantSet` (`vendor/ibex2/src/grant.rs`, vendored from the ibex
checkout), so the change lands in ibex2 and is vendored back.

### R6 — iOS list rows honour negative margins (P1)

The iOS collection's row height comes from the row root's laid-out extent.
The fix measures the row as the kernel does (the root's margin box), so a
child's negative margin inside the row cannot inflate it. Regression: the
port's profile header shape, measured on the web and iOS to the point.

### R7 — AppKit clips to rounded overflow (P2)

A node with `overflow: hidden` and a border radius masks its subviews to
the rounded rect (`layer.cornerRadius` + `masksToBounds` on the clipping
container), as iOS already does. Regression: an image in a rounded,
clipped box has transparent corners in a layer render.

### R8 — AppKit clips a clamped paragraph (P3)

A text node with `line-clamp` clips its drawing to its box, as CSS's
line-clamp implies `overflow: hidden`. Regression: one unbreakable word
wider than its box draws nothing past the box.

### R9 — The agent's settle waits for images; `layout` takes a testId (A1, A2)

`clock settle` on the web also waits, up to its existing deadline, for
every `img` in the viewport to finish (`complete`), and reports how many
it gave up on. `layout <testId>` resolves as `tree <testId>` does. (iOS
image settling is QUEUE's existing line; this RFC does not duplicate it.)

### R10 — The scripts say everything at once (O2, O5, L9)

- `host/web/build.mjs` checks every web prerequisite before building and
  prints all that are missing, each with its install line: the nightly
  and `rust-src`, std's fetched dependencies, the app workspace's fetched
  dependencies, and binaryen at the pinned version (with its release
  download line). It runs the two `cargo fetch`es itself when online.
- `host/apple/build.mjs` detects `xcode-select` naming the Command Line
  Tools with Xcode installed, uses Xcode for the build, and says so.
- `serve.mjs` prints which app it serves (from `exact.json`) and warns
  when `EXACT_APP_DIR` names a different one.
- A build that fails in a host crate's `build.rs` on a Contract error
  prints that diagnostic alone, last.

### R11 — The compiler names reserved words and reports plan size (L2, L10)

A name position holding a keyword says "`key` is a reserved word".
`contract build` prints, after its summary line, the five components with
the most inlined nodes (uses × nodes). `host/web/build.mjs` prints the
plan's share of the wasm.

### R12 — The date on Linux (X1)

The Linux host sets `exactTime` from `SystemTime` at boot, as Apple does,
with a zero offset unless `TZ` names a fixed offset. The agent substitute
epoch (LLP 1027.000.000 D3) stays that RFC's.

### For Charlie

- **C1 — Centre a button's content (L3).** Make `button`'s default
  `justify-content: center` (with `align-items: center` already), matching a
  bare `<button>`. Every existing app that relies on a top-aligned button
  label would move; Messages and Caltrain set both explicitly. Recommend yes.
- **C2 — Independent reads by default for `GET` (D6).** Recommend no: LLP
  1016's rule that overlap is an explicit promise stands; R3 removes the
  harm, and R10's doc line removes the surprise.
- **C3 — Implicit record placeholders (L8).** A record resource with no
  `else` bakes the shape's zero value (empty strings, `false`, `0`, empty
  lists). Recommend yes, with `pending(r)` as the loading signal.
- **C4 — List indexing (L5).** `first(list)`/`last(list)` returning
  `option<T>` as roster functions. Recommend yes; general `xs[i]` no.
- **C5 — `reachend` arguments (L7/D4).** Recommend no once R2 lands.
- **C6 — Pull to refresh on the web and AppKit (P4).** Recommend no for
  now: neither platform has a native control, and the web's page-level
  gesture is the browser's.

### Not proposed

O1 and O3 are LLP 1036.001's (D2, D5). L4 is issue
`clip-path-subset-of-css`. O4 (a metrics bin template) waits for the
scaffold. L6 (display on a list root) is a deliberate collection rule. A3
is issue `macos-offscreen-capture-can-be-transparent`. A4 is LLP
1035.003's. A5 is correct behaviour. D8 is the cost of explicit time and
is small once R1 exists.

## Open questions

1. R1: should the runner also re-ask a marked source's resources that are
   *not* displayed (beneath the top of a stack)? Proposed: yes, as
   `refresh` does.
2. R2: is a request's `grants` scope part of its equality? Proposed: yes.
3. R3: should a queued read count toward "in flight" for the agent's
   settle? Proposed: yes; it has been asked for.
