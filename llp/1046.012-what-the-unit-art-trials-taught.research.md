# LLP 1046.012: What the unit art trials taught

**Type:** Research (a record, with recommendations)
**Status:** Draft, 2026-10-07. Written at Charlie's request at the end of a day of art trials in Skirmish. It decides nothing. Its asks that overlap LLP 1046.011 are already ruled there and are cited, not reopened.
**Systems:** `gpu` (`shaders.rs`, `fixture.rs`), `game/render` (`surface.rs`, `hooks.rs`, `hooks/pipelines.rs`), `game/engine` (generated models, saves), `game/app/shells.mjs`, `scripts/exact.mjs`, docs (`game/README.md`, `game/engine/README.md`, `docs/agent-pitfalls.md`)
**Author:** Claude (Opus 5.5) for Charlie Cheever
**Date:** 2026-10-07
**Related:** LLP 1046.011 (what authored unit art asks; D2, D3 and D4 are the asks this record reinforces); LLP 1046.008 §3 (presentation state); LLP 1046.006.000 (render hooks); LLP 0382 (fail closed loudly in debug); four Skirmish authoring diaries of 2026-10-07 (two sent, receipt `b4649137`; two local)

## Summary

On 2026-10-07, one agent session made four passes at Skirmish's unit art, which had read as "plastic-y and generic":

| | Trial | What it produced |
|---|---|---|
| T1 | A hard-surface siege tank modelled and baked in headless Blender | Three glTF parts with worn, baked PBR maps |
| T2 | An organic, hand-painted marine, also from Blender | Voxel-fused forms with painted-light maps, on the existing walk and recoil joints |
| T3 | A cartoon look from one game-side post pass | Depth outlines, normals rebuilt from depth, banded light, over every unit, building and the terrain |
| T4 | Cartoon pass 2: faces, chibi proportions, a closer camera, larger units, brighter light | Every one of the 24 units, plus a build-time switch between three art styles |

**None of the four needed an engine change.** The renderer was never the limit. The look moved with authored content, proportion, camera distance and light. What cost time was tooling around the engine:
- an offscreen fixture that compiled a missing shader as empty text;
- hook pipeline errors that never reach `error()`;
- a stale captured lock that blocked `test-rust` all day;
- no verb that generates `.shells/`.

The best part of the day was also tooling: a 24-unit roster rendered offscreen through the engine's own renderer in about six seconds. Every art decision was judged from those renders.

Section 1 lists the frictions, section 2 what to keep, section 3 recommendations with confidence.

## 1. Frictions

### F1. An offscreen fixture compiles an unregistered shader as empty text

**Seen in T3.** Skirmish's post pass is a render hook whose WGSL is registered at run time (LLP 1030 D8). The offscreen example rendered frames with no post pass and reported nothing. Debug prints finally showed the hook pipeline failing validation with `Unable to find entry point 'vs'`.

**Cause.** `exact_gpu::shaders::shader_module` (`gpu/src/shaders.rs:129`) builds its descriptor from `shader_source(name).unwrap_or_default()`. Its doc comment says empty text is unreachable because "it refuses to create a surface first". That refusal lives in the host's module path. A fixture that builds a `WorldSurface` directly never passes through it, so the empty string goes straight to the compiler. The fix was to call `set_shader` for every entry of the game's `SHADERS` before the first frame, which Skirmish's `scene_shot` example now does by hand.

**Cost:** about 15 minutes.

**What would have helped:**
- `shader_module` refusing by name in debug builds ("shader `fog` has no registered source"), per LLP 0382;
- `fixture` offering a one-call registration from a shader directory and a registry, so every offscreen example stops copying the same loop.

### F2. Hook pipeline errors reach readiness but not `error()`

**Seen in T3.** Both offscreen examples assert `surface.error().is_none()` after each frame. That held while the hook pipeline was failing.

**Cause.** `Pipelines::error()` records the failure (`game/render/src/hooks/pipelines.rs:67`). Skirmish's `Hooks::error` forwards it, as the trait asks (`game/render/src/hooks.rs:252`, default `None`). The surface puts it only into the readiness reasons (`game/render/src/surface.rs:826`, "render hook: …"). That report is what the agent reads. A fixture loop has no reason to read it, and `WorldSurface::error()` (`surface.rs:205`) does not include it.

**A second, quieter case.** Hook pipelines validate asynchronously (`Pipelines::update` polls a validation future). A fixture that captures as soon as assets settle gets frames without the post pass and no signal that anything is pending. Skirmish works around both cases with 24 warm-up frames.

**What would have helped:** one of these.
- A fixture helper that renders until readiness has no reasons, then returns any reasons it gave up on. This is the most general.
- `error()` including a hook error that has never had a validated set. Once a set has validated, a later rejected update keeps drawing the old set, so readiness is the right place for that case.

### F3. A stale captured lock blocked native tests in every session

**Seen in T1 to T4.** `bun exact.mjs test-rust` refused before running anything: "cannot update the lock file .shells/Cargo.lock because --locked was passed". The SDK checkout had moved to Parley. `8dde07780` later updated the SDK's and in-tree games' locks, but a game captured earlier still drifts. Offline, `shells.mjs --update-lock` failed to download `harfrust`. Every session fell back to `cargo test` on the logic crate.

The native host, `exact.mjs test` and `prove` were never run on any of today's art. That gap is the real cost: the proof pins may now be stale against the new default look, and no tool said so.

This is LLP 1046.011 D2, already ruled (a `lock` verb, a copy-time warning). This record adds the evidence that it recurred across four sessions on one day, and that it hides more than tests: it hides the proof.

### F4. Nothing named the command that generates `.shells/`

**Seen in the first roster render.** `cargo run --example …` in the game's `render/` crate failed with "failed to read .shells/Cargo.toml", because the bake had not run on this checkout. `bun exact.mjs` lists no bake or shells verb. The agent read exact2's scripts and ran `bun ../exact2/game/app/shells.mjs .` directly.

**Cost:** about 5 minutes.

**What would have helped:**
- an `exact.mjs bake` verb, or a `shells` verb;
- the example crates' manifests carrying a comment, or the error pointing, at the command that writes `.shells/`.

### F5. Cosmetic generated models enter the save identity

**Seen in T3.** Registering trial models with `w.generated_model` at setup made every older fixture save refuse to restore ("asset `…` identity is missing"). This is correct, and `game/engine/README.md` says generated models are identity-checked. It is still easy to walk into for a model that only changes how something looks. Baking the models as streamed assets fixed it.

**What would have helped:** a pitfall entry, symptom first: "older saves refuse after adding a generated model; cosmetic models belong in the bake".

### F6. A box-normalised root makes every round part an ellipse

**Seen in T4.** Skirmish scales each unit's root to `(diameter, height, diameter)` and authors parts in a unit box. That is a sensible pattern, and likely a common one. Every sphere under such a root is an ellipsoid, so cartoon eyes and civilian heads came out as poles until the game added a helper that undoes the aspect.

**Cost:** about 15 minutes.

**What would have helped:** a note in the engine README's model section. Nothing more: the engine is right, and a uniform-scale child type would add a concept for one helper's worth of savings.

### F7. `cargo fmt` in a game reformats files the change never touched

**Seen in T4.** exact2 checks its own formatting (`game/README.md`, `cargo fmt --all -- --check`). A game's `test-rust` does not, so Skirmish's tree drifted, and one `cargo fmt` rewrote about 40 unrelated files. They were reverted by hand.

**Cost:** about 5 minutes.

**What would have helped:** `exact new` writing a `rustfmt.toml`, and `test-rust` running `cargo fmt --check` on the game's crates as a lint. Low priority, since the drift is the game's.

### F8. Team colour multiplies a neutral texture

**Seen in T2.** A painter's hue shifts inside team areas (violet shadows, warm highlights) had to be baked as tinted multipliers. That works. The `present` and `MaterialOverrides` path ruled in LLP 1046.011 §8.1 covers per-material colour. A team mask in the model shader would give painters more control, but nothing today needs it.

### F9. Authored art is heavy in the game repo

**Seen in T1 and T2.** Keeping all three art styles switchable meant checking in the Blender sources, the GLBs and every baked payload, including the RGBA8 fallbacks. That grew Skirmish's repo by about 130 MB, almost all of it textures. This is evidence for LLP 1046.011 D3 (a texture cap and a printed cost per model), already ruled.

## 2. What to keep

**K1. The offscreen roster render.** `exact_gpu::fixture` plus `WorldSurface`, driven by a game example, rendered all 24 units in close-up, plus an overview and three gameplay scenes, in about six seconds on Metal. That covers both the game's camera and close-up. Every round of T1 to T4 was judged from it, including the round that showed the first tank read as "a flat slab with a pencil barrel" at gameplay zoom.

This supports LLP 1046.011 D4 (`exact.mjs look`). It also suggests `look` should accept a game-provided gallery, a roster of the game's own entities, as well as a single model. Comparing styles across the whole roster was what made the calls easy.

**K2. The glTF bake took Blender's output unchanged:**
- base, ORM, normal and occlusion maps;
- a shared ORM image;
- `KHR_materials_emissive_strength`;
- content-named textures shared between models.

**K3. One render hook restyled the whole game.** `FINAL_DEPTH` and `HDR_POST` were exactly the right inputs for outlines and banded light. There was no engine change, and every building and the terrain followed for free.

**K4. `Environment` was enough for a cartoon light rig.** Its zenith, horizon, ground and ambient terms, plus a second unshadowed `DirectionalLight` as fill, gave flat, clean bands with no shader change.

**K5. Presentation-only art made three styles cheap.** Skirmish's art is presentation, never saved (LLP 1046.008 §3). A build-time `option_env!("SKIRMISH_ART")` const selects classic, sculpted or cartoon. All three share saves, pins and the 430 logic tests, which pass under each style. The presentation/state split paid for itself here more than anywhere else so far.

**K6. Named joint entities let a caricature be a remap, not a redraw.** The motion system only rotates each unit's named joints (`art-{id}-leg{i}`, `-weapon`, …), and sets the body's height. So T4's chibi proportions are one mapping applied to existing part positions: shorter legs, a larger head about the neck. It touched no animation and redrew no unit by hand.

## 3. Recommendations

Confidence is how sure this record is that the change is worth making, not how hard it is.

| | Recommendation | Where | Size | Confidence |
|---|---|---|---|---|
| R1 | `shader_module` refuses an unregistered name in debug builds; `fixture` offers one-call registration from a directory and a registry | `gpu/src/shaders.rs`, `gpu/src/fixture.rs` | small | high |
| R2 | A fixture helper that renders until readiness is clear and returns any reasons left; `error()` includes a hook error when no set has ever validated | `gpu/src/fixture.rs`, `game/render/src/surface.rs` | small | high |
| R3 | Build LLP 1046.011 D2 first; the copy-time warning should also say that `prove` and the native host are blocked | `game/app/shells.mjs`, `scripts/exact.mjs` | small | high |
| R4 | An `exact.mjs bake` (or `shells`) verb, and the missing-`.shells/` error naming it | `scripts/exact.mjs` | small | high |
| R5 | `look` (1046.011 D4) takes a game-provided gallery as well as one model | `scripts/exact.mjs`, game template | medium | medium |
| R6 | Pitfall entries for F5 (generated models and save identity) and F6 (round parts under a box-normalised root) | `docs/agent-pitfalls.md`, `game/engine/README.md` | tiny | medium |
| R7 | `exact new` writes `rustfmt.toml`; `test-rust` runs `cargo fmt --check` on game crates | template, `scripts/exact.mjs` | small | low |

Not recommended:
- **A team mask in the model shader (F8).** No game needs it yet; `present` covers today's case.
- **A uniform-scale child concept (F6).** A note does the job.
- **Any PBR, TAA, SSAO or grading work.** Four art directions on one day found the renderer adequate for each.
