## Summary

The agent sees Exact's logical tree (`tree`) and one node's native facts
(`layout <target>`.`native`). It does not see what UIKit or AppKit has
mounted. r2 adds two **forms of `layout`** on iOS and macOS. There is no new
operation, no devtools UI and no views layer.
1. **`layout <target> native`** (D1) is a bounded, depth-limited dump of the
   views and flat-leaf layers under a node. It is pure observation, with no
   verdicts.
2. **`layout agree`** (D2) reports only the disagreements that can be judged
   soundly:
   - `stray`: a view where Exact owns the subview list that no live node,
     kept tree or named chrome accounts for;
   - `parked-visible` and `leaving-interactive`: a kept tree that shows or
     takes input;
   - `frame`: an ordinary, untransformed, unprojected, settled node whose view
     frame differs from the kernel's by more than a physical pixel;
   - `hidden`: a node's own `isHidden` disagrees with the closed set of reasons
     a host may hide it for.

   Every walk reports how complete it was. An incomplete walk never passes.

## 1. Motivation

What exists:
- `layout` lists `presenter.views` whose `window` is not nil (`AgentIOS.swift:194-229`).
- `layout <target>` walks one node's ancestors (`:246-400`).
- `state.pool` gives counts only (`NodePoolIOS.swift:426`, `FlatLeavesIOS.swift:311`).

Nothing looks **down** into the platform hierarchy. Yet the presenter
deliberately keeps views the model has retired, and draws some nodes without a
view:
- A parked tree stays mounted with only its root hidden (`NodePoolIOS.swift:274-283`).
- An exit keeps its views, made non-interactive (`PresenceIOS.swift:17-31`).
- Flat leaves are merged `CAShapeLayer` runs (`FlatLeavesIOS.swift:228-286`).
- The viewport moves into presented controllers and back (`ModalIOS.swift:265`, `:295`).

A bug in any of these looks the same from `tree` and `layout`: the model is
right and the screen is not. The agent can only guess from a screenshot.

## 2. Decisions

### D1 — `layout <target> native`: observation only

Request: `{"op":"layout","id":V,"native":{"depth":3,"limit":200}}`.
- CLI: `layout <target> native [<depth>]`.
- `depth` is an integer from 1 to 12, and `limit` an integer from 1 to 2000. The defaults are 3 and 200.
- `native` must be an object with no other keys.
- `native` without `id`, or together with `agree`, `at` or `world`, is refused by name.

Liveness is checked first. The runner's `node` message validates the id. Only
an id the runner calls retired is refused as `stale node #V` (LLP 1035.002
D3). The root of the walk is then:
- an ordinary node or a `pending` heavy leaf: its own `NodeView` (the wrapper
  exists; only its embedded object waits, `HeavyLeavesIOS.swift:58`);
- a flat leaf: the parent's container, filtered to the run layer that paints
  it, with `root: "flat-run"`;
- an inline run: its paragraph owner, with `root: "inline-owner"`;
- an SVG element: its `svg` node's view, with `root: "svg-owner"`.

A live id with none of these is answered as
`subviews: {"unavailable": "no platform view for #V (…reason)"}`. It is never
reported as stale.

The reply carries the tags (`epoch`, `incarnation`, `clock`, `session` on the
sample hosts) and `viewport` and `node`, the ordinary `layout <target>` node
explanation. It carries **no `nodes` listing**. `node.native` gains:

```
"subviews": {
  "root": "view" | "flat-run" | "inline-owner" | "svg-owner",
  "depth": 3, "limit": 200, "count": 57, "complete": true,
  "truncated": ["depth" | "limit"],          // only when cut
  "entries": [
    { "kind": "view", "depth": 0, "class": "NodeView", "node": 12,
      "frame": {"x":0,"y":88,"w":390,"h":44},      // viewport space, model (not presentation) geometry,
                                                  //   transforms and scrolls folded in (LLP 1012 §1)
      "hidden": false, "alpha": 1,
      "interactive": true,                        // iOS isUserInteractionEnabled; absent on macOS
      "layer": {"masksToBounds": false, "zPosition": 0, "transform": [1,0,0,1,0,8]} },
                                                  // layer absent when AppKit's is nil; transform only when not identity, "3d" when not affine
    { "kind": "view", "depth": 1, "class": "UIImageView", "role": "glyph", "owner": 12, … },
    { "kind": "layer", "depth": 1, "class": "CAShapeLayer", "role": "flat-run",
      "leaves": [14, 15, 16], "leafCount": 3,        // ≤ 16 listed
      "path": {"x":56,"y":98,"w":300,"h":1},          // path.boundingBoxOfPath, viewport space
      "attached": true, "hidden": false, "opacity": 1 },
    { "kind": "view", "depth": 1, "class": "UITextView", "role": "editor", "owner": 17,
      "opaque": "platform", "children": 9 }      // an interior Exact does not own: counted, not entered
  ]
}
```

- Other sublayers are not walked: borders, shadows, text rasters and
  gradients belong to their view.
- `role` uses D3's names. An entry with neither `node` nor `role` is
  `"role": "unaccounted"`. That is observation, not a verdict; D2 owns verdicts.
- The web answers `subviews: {"unavailable": "the DOM is the tree; layout <target> names the element"}`.
- Linux answers `{"unavailable": "no platform views"}`.

### D2 — `layout agree`: four sound kinds

Request: `{"op":"layout","agree":true}` or `{"op":"layout","agree":true,"limit":32}`.
- CLI: `layout agree`.
- `agree` must be `true`. `limit` is an integer from 1 to 500 and defaults to 32.
- `id`, `native`, `at` and `world` are refused alongside it. r2 has no scoped
  form, because a scoped walk could not establish `stray` above its root.

The reply is tags + `viewport` + `agreement`, with **no `nodes` listing**:

```
"agreement": {
  "complete": true,
  "incomplete": [],              // reasons: "walk-cap" | "frames-cap" | "in-flight" | "spanned" | "no-window"
  "roots": { "walked": ["ExactView", "modal #31 (retiring)"], "excluded": [] },
  "coverage": {
    "stray":  { "judged": 640, "opaque": 85 },
    "kept":   { "parkedRoots": 6, "leaving": 0 },
    "frame":  { "compared": 512, "sizeOnly": 40,
                "skipped": { "transformed": 3, "animating": 0, "placed": 0, "route": 2, "projected": 4,
                             "deferred": 0, "flat": 31, "inline": 12, "svg": 0, "offWindow": 40 } },
    "hidden": { "compared": 552, "claimed": { "placement": 0, "segments": 2, "menus": 1, "navigation": 0, "swipe": 0, "toolbar": 0 } }
  },
  "counts": { "stray": 1, "parked-visible": 0, "leaving-interactive": 0, "frame": 1, "hidden": 0 },
  "disagreements": [
    { "kind": "frame", "id": 41, "kernel": {"x":0,"y":132,"w":390,"h":44}, "native": {"x":0,"y":176,"w":390,"h":44}, "delta": {"x":0,"y":44,"w":0,"h":0} },
    { "kind": "stray", "class": "UIView", "under": 40, "frame": {"x":0,"y":0,"w":390,"h":44} }
  ],
  "tolerance": { "px": 0.33 },
  "truncated": ["disagreements"]           // only when the list was cut; counts stay complete
}
```

**The kernel's side** is a private message, `{"op":"frames","limit":20000}`,
answered in `runner/src/agent.rs` beside `node` and `tags`. It is not an
operation (LLP 1012 §1). Its reply:

```
{"epoch":E,"incarnation":I,"clock":C,"complete":true,
 "nodes":[[id, parent|null, x, y, w, h, bits], …]}
```

- `nodes` is in preorder.
- `x, y, w, h` is the kernel's parent-relative frame, as `node` reports it.
- `bits`: 1 means the node's **own** `display` is `none`. 2 means any of
  `translate`, `translate_z`, `rotate`, `rotate_axis`, `scale` or `transform`
  is not initial on the node.
- Past `limit` nodes the message stops with `complete: false`, and the report
  says `incomplete: ["frames-cap"]`.

The host reads tags before the walk and again after it. If they differ, it
reports `incomplete: ["spanned"]` (LLP 1035.002 D3).

**The kinds:**

| kind | judged when | disagreement |
|---|---|---|
| `stray` | a subview of a view whose subview list Exact owns (D3) | it is not a live node's own view, a D3 owned identity, a member of a parked tree, or a member of a leaving tree |
| `parked-visible` | every parked root (`NodePool` exposes `parkedRoots`) | the root is not `isHidden` |
| `leaving-interactive` | every `presenter.leaving` root | `isUserInteractionEnabled` is true, or `accessibilityElementsHidden` is false (`PresenceIOS.swift:28-29`) |
| `frame` | D3's eligibility rule | an edge differs from the kernel frame by more than `px`; or, when only the size is eligible, `w` or `h` does |
| `hidden` | a live node's own view, in a window | `isHidden` is true and no D3 hider claims the view; or a hider requires it hidden (`placementHidden`) and it is not |

Polarity and scope:
- `hidden` compares the view's **own** `isHidden` only. Ancestor hiding is not
  inherited into the expectation.
- Own `display: none` is not an `isHidden` reason on either Apple host.
  `display: none` gives the node a 0×0 frame, which `frame` checks.
- `alpha` and opacity are not compared: press feedback and motion change them
  legitimately.

**`frame` eligibility** applies to an ordinary node:
- the node is live, its view is `presenter.views[id]`, and the view is in a window;
- it is not in a held modal's deferred geometry (`ModalHost.holdsGeometry(id)`,
  a query over `deferGeometry`'s saved ops, `ModalIOS.swift:187`);
- the view's `transform` and `layer.transform` are identity, and bit 2 is clear;
- no geometry animation (`bounds`, `position`, `transform`) is on its layer,
  using `nativeGeometryInFlight`'s test, and the motion engine has nothing in
  flight for it;
- it has no `placedAncestor`;
- it is not a route root, and not claimed by a projection (D3).

The comparison uses the model `frame` in the view's superview coordinates.
Ancestors' transforms do not enter. The origin is compared only when the
superview is the parent `NodeView` itself, or a container whose `frame`
equals the parent's `bounds` and whose `bounds.origin` is zero. In a scroll
view's content, an inset clip box or a canvas overlay, only the size is
compared (`sizeOnly`). A collection-owned list's row root is `sizeOnly` too,
until the row origin is verified (§5); its descendants are compared fully.
While `nativeInFlight()` holds, `frame` compares nothing and the report says
`incomplete: ["in-flight"]`.

**Tolerance** is one physical pixel on each edge: `1 / displayScale` (iOS) or
`1 / backingScaleFactor` (macOS).

**Cut from r1, with the reasons in §0:** `orphan`, `detached`, `order`,
`alpha`, `transform`, `interactive`, `clip`, `hit` and flat-leaf geometry.
`orphan` and `detached` need a closed account of every host that keeps a live
node's view out of the window: inactive routes, unselected tabs, held sheets.
r2 does not have one.

**The web and Linux** answer `agreement: {"unavailable": "…"}`, with a reason.
- JS target: "no independent model: the page is the tree".
- wasm target: "not implemented: app drives run the JS target".
- Linux: "no platform views".

### D3 — Ownership, hiders and projections: closed lists

**Where `stray` is judged.** Only in a subview list Exact owns:
- a `NodeView` and its `container`;
- its `clipBox`, glass content view, and its own `ScrollView`'s content;
- the `Viewport` and the document `root`;
- a modal controller's view as the presenter fills it.

Inside a view Exact does not own, every non-`NodeView` subview is counted as
`opaque` and not judged. Any `NodeView` found there is still matched against
the model. Views Exact does not own:
- `UITextView` / `UITextField`, `WKWebView`, a `UIControl`, a video player view;
- a native module's box;
- a hooked node's view (`props["hook"]`, `ElementHooks.swift:123`, whose
  owner may customize it);
- `UINavigationController` and tab-bar controller views.

**Owned identities** are matched by `===`, never by class:
- per node: `symbolView`, `materialView`, `glassSlot`, `glassGroupView`,
  `vibrancyView`, `clipBox`, `metal`, `overlay`, `field`, `textArea`, `scroll`,
  the heavy leaf's embedded view, the control's mount (`ControlsIOS.swift:119`),
  the segment bar and value (`SegmentsIOS.swift:223-227`), the menu overlay
  button (`MenusIOS.swift:141`), and the swipe table, cell and carrier
  (`SwipeActionsIOS.swift:207-263`);
- presenter chrome: the navigation controller views `NavigationHost` holds,
  the tabs holder, modal background views, the keyboard probe, `ExactView`'s
  probe, and the freeze snapshot. The snapshot is held by its route controller
  as `frozen`; `NavigationIOS.swift:59` gains the reference.

There is one class allowlist entry: `_UIScrollViewScrollIndicator`, as a
direct subview of a `UIScrollView` Exact owns. It is matched exactly. If
UIKit renames the class, the indicator becomes a `stray`: a loud failure,
not a silent one. The pool's eligibility test (`NodePool.children`) stays
private and is not reused.

**Hiders** are hosts that may set a live node's own `isHidden`. Each gains
`hides(_ view: NodeView) -> Bool` over the state it already keeps:
- `placement`: `placementHidden` (`NodeViewIOS.swift:207`);
- `segments`: tabs replaced by a bar, an adopted list (`SegmentsIOS.swift:205`, `:274`);
- `menus`: popover nodes not presented (`MenusIOS.swift:112-116`, `:276`);
- `navigation`: a lifted header (`NavigationBarIOS.swift:342`);
- `swipe`: row content (`SwipeActionsIOS.swift:289`);
- macOS `toolbar` (`ToolbarMac.swift:277`) and macOS `menus` (`MenusMac.swift:137`).

**Projections** decide which kinds apply:

| projection | stray | kept kinds | frame | hidden |
|---|---|---|---|---|
| canvas placement (LLP 1014 D5) | judged | n/a | skipped (`placed`) | claimed (`placement`) |
| navigation route root | judged under it | n/a | skipped (`route`) | judged |
| segmented bar over tabs | bar owned | n/a | tabs skipped (`projected`) | claimed (`segments`) |
| menu popover / confirmation | owned overlay | n/a | skipped (`projected`) | claimed (`menus`) |
| swipe row and actions | owned | n/a | skipped (`projected`) | claimed (`swipe`) |
| macOS window toolbar | n/a | n/a | skipped, system-owned (`AgentMac.swift:282`) | claimed (`toolbar`) |
| collection row root | judged | parked roots | `sizeOnly` | judged |
| keyboard toolbar, popovers in another window | excluded: outside the roots | | | |

**Roots.**
- iOS walks the session's `ExactView`, then each controller view in
  `ModalHost`'s `layers + retiring`, deduplicated by identity. The modal host
  exposes these as `inspectionRoots`, so a dismissal in progress is still
  walked (`ModalIOS.swift:129-140`, `:304`).
- macOS walks only the session's `ExactView`. Its window may hold the other
  session (`ExactHostMac/main.swift:53`) and sheets of unproven ownership.
  Those windows are named in `roots.excluded`.
- If the `ExactView` is not in a window (a native screen has replaced it),
  the report says `incomplete: ["no-window"]`.

### D4 — Bounds: the whole reply is bounded

| reply part | bound |
|---|---|
| `layout <target> native` | entries ≤ `limit` (≤ 2000, about 200 B each); `leaves` ≤ 16 per entry; no `nodes` listing |
| `layout agree` | disagreements ≤ `limit` (≤ 500); no `nodes` listing; `coverage` and `counts` are fixed-size |
| walk | ≤ 20,000 views, else `incomplete: ["walk-cap"]` |
| `frames` (in process, never sent to the driver) | ≤ 20,000 nodes, else `incomplete: ["frames-cap"]` |

`counts` covers every disagreement found. It is complete only when
`complete` is true; otherwise it counts what was walked. Both forms are
opt-in and never run implicitly. Both read on the main thread, with no action
run between the runner's part and the host's part. They neither lay out nor
hit-test. `metrics.mjs --inspection` prints their size and latency on
Carousel and the two-session host, and never gates on them.

### D5 — The smoke, and what proves it

`scripts/smoke-inspect.mjs` exports `agree(s, label, check)`. It runs
`clock settle`, then `layout agree`. It records a failure in each of these
cases:
- the settle does not settle;
- the reply is missing;
- `complete` is false (each `incomplete` reason is named);
- `coverage.stray.judged` or `coverage.hidden.compared` is 0;
- `coverage.frame.compared` is 0 (any non-empty app has an ordinary node);
- for each listed disagreement, rendered as D6 renders it.

`smoke.mjs` calls it at these points:
- after step 2, on every app's first frame;
- after step 4 and after step 5, for Caltrain;
- after step 8, the nested-scroll fixture;
- once per session in `host` and `host-ios`, after step 3's push and pop;
- on Linux and the web, it asserts the `unavailable` envelope instead.

**The pooling drive** runs when the app is Carousel (`--app carousel`, whose
feed is `list virtualized=true`, `apps/carousel/app.contract:66`):
1. `tap feed-far`, then `clock settle`.
2. Assert that `state.pool.parks` and `state.pool.takes` both grew. This shows
   that rows retired and were reused, with no assumption about how much stays
   parked.
3. Assert that `agreement.coverage.kept.parkedRoots` equals `state.pool.parked`
   from the same settled moment.
4. `layout agree` reports zero disagreements and `complete: true`.

**What runs it.** No asynchronous entry point runs `smoke.mjs` today
(`scripts/async.mjs:51-80` lists none), and r2 does not add one. The smoke
proof is manual. The implementer runs:
- `bun scripts/smoke.mjs ios --app caltrain`;
- `bun scripts/smoke.mjs ios --app carousel`;
- `bun scripts/smoke.mjs host-ios`;
- the `macos` and `host` equivalents.

The output is recorded in this RFC at landing. The asynchronous proof is the
XCTests, which `async.mjs` runs as `build.mjs --test --ios` for every commit
under `host/apple`:
- **`NodePoolIOSTests`**: park a row, and the report is clean with the root
  counted. Unhide the parked root, and the report says `parked-visible`.
- **`PresenceIOSTests`**: begin an exit, and the report is clean. Re-enable
  the root's interaction, and it says `leaving-interactive`.
- **`ScrollChainIOSTests`**: a plain `UIView` added to a node's own
  `ScrollView` is `stray`. A real scroll indicator is not.
- **A new `AgreementIOSTests`**:
  - an ordinary node moved 2 pt is `frame`;
  - a node under press feedback, moved, is `skipped.transformed`, not a disagreement;
  - an ordinary node set `isHidden` is `hidden`;
  - a segment-replaced tab is `claimed.segments`;
  - during a retiring modal's dismissal, `roots.walked` names the retiring controller;
  - a `frames` reply cut at its cap gives `complete: false`.

## 5. Deferred, and open questions

Deferred until there is a sound definition. Each needs the named fact first:
- **Flat-run geometry:** a run's path compared with the union of its leaves'
  kernel boxes, in the container's space.
- **`order` and `transform`:** used z-index (position type, the parent's
  display) and the host's composition inputs (press feedback, keyboard lift,
  context transforms, perspective) as a pure function.
- **`clip`:** per axis, against the actual scroll container, `clipBox` and
  mask attachment.
- **`hit`:** needs an occlusion model, which this RFC refuses. Fixture
  assertions at known points cover it instead.
- **`orphan` and `detached`:** a closed list of the hosts that keep a live
  node's view out of the window.

Open:
- **Collection row origins.** Does a collection-owned row's origin in its
  list's content equal the kernel frame? If the first Carousel run shows it
  does, the row root moves from `sizeOnly` to `compared`.
- **Inset clip boxes.** Is a `clipBox` ever inset from its node's bounds,
  for example to the padding box? If it never is, its children's origins
  become comparable.
- **macOS sheets.** Should a session own its sheets explicitly, so they can
  join `roots.walked`?
