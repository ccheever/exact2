**Type:** RFC
**Status:** Draft (r1)

**Author:** Claude (Opus 5.5) for Charlie Cheever
**Implementer:** Claude (Opus 5.5), branch `feat/svg-complete`, from 2026-09-26, stage by stage in §4's order
**Date:** 2026-09-26 (r1)
**Related:** LLP 1055 (the first slice this completes: its §0 limits and D12 refusals are this RFC's work list), LLP 1002 / 1003 (motion: one engine, the browser as oracle), LLP 1001 (declared deviations), LLP 1047 (pay for what you use), LLP 1019 (fonts), `rules/NOT-DOING.md` §Motion ("SVG, complete, as the browser renders it", Charlie 2026-09-26), `~/bench/cryptobench/SPEC.md` (the price flash). ## Summary

Charlie, 2026-09-26: "why wouldn't we just do a complete SVG implementation here? i think this will be useful and we're using it now." LLP 1055 built the first slice: eight elements, the presentation properties, and CSS animations over `opacity`, `stroke-dashoffset` and `r`. Everything that RFC refused or declared as a limit is now a stage.

This RFC lists what SVG 2 and the CSS that applies to it bring beyond the first slice, decides each item, says how each host paints it, and orders the stages by what real apps draw: **charts first, then icons, then illustrations**.

Three decisions shape everything else:
1. **One resolver in Rust (D1).** Native hosts stop asking each node for its computed style. A kernel walk resolves an `svg` into a scene: inheritance, `use` instances, references, units, transforms, and paint. The Apple and Linux hosts only map that scene to layers or backend calls. The web keeps the real SVG DOM; the browser is still the renderer and the oracle.
2. **Islands for what a compositor cannot do (D2).** Masks, filters and patterns are rendered to pixels in Rust, then composited: tiny-skia on Linux, and the same Rust code over a Core Graphics bitmap on Apple. Everything else stays vector and animatable: `CAShapeLayer` on Apple, vello or tiny-skia calls on Linux.
3. **References resolve like the web, and ids stay unique (D3).** `url(#id)` and `href="#id"` look in the referencing `svg` first, then in document order. The web host rewrites ids so that a component instantiated forty times does not paint forty charts with the first row's gradient.

**Recommendation:** build stages 1–11 in order (§4). Refuse `foreignObject` (D13) and a short list of legacy or scripting features (§7). Each stage lands with tests, Chrome parity on every host, and the `svg-gallery` fixture extended.

## 2. Decisions

### D1. One resolved scene, computed in Rust

**Today.** Apple's `svg.rs` and Linux's `paint/svg.rs` each walk the subtree. Each calls `computed_style` per element, which walks ancestors again. Each re-derives geometry and paint. That was tolerable for eight elements. It is not tolerable once inheritance crosses `use`, paint names a gradient, and lengths resolve against a nested viewport.

**Choice.** `kernel/src/svg/scene.rs` resolves one `svg` into a `Scene`: a tree of `Item`s (group, shape, text, image, use instance) with everything resolved.
- **Inherited style is carried down the walk.** It is not looked up per node, and a `use` instance inherits from the `use`, not from the original's parent. This is SVG 2 §5.6, and a lookup through ancestors cannot express it.
- **Lengths are resolved against the nearest viewport.** Percentages use the viewport's width, height, or normalized diagonal √((w²+h²)/2), as SVG 2 §8.9 says.
- **Transforms become one affine per item**, composed as CSS Transforms 1 §6 composes them (D5).
- **Paint becomes a `ResolvedPaint`:** none, a colour, or a server reference with its fallback, the server's resolved stops, units and transform.
- **Clip, mask and filter references are resolved to items** (D10, D14), and markers to instances (D9).
- **Presented values from the motion engine** (a running transition or a sampled animation) are read at resolve time, so every host sees the same instant.

Native hosts consume the scene. Apple serializes it as the `svg` op's JSON (the first slice's format grows fields; it does not fork). Linux paints it directly. The web does not need it to paint. It uses the same resolver for two things: id rewriting (D3) and hit-test parity tests. The resolver is plain data over the kernel arena. An `svg`-free plan pays only its code size (LLP 1047).

### D2. What stays vector, and what becomes an island

| Feature | Web | Apple | Linux |
|---|---|---|---|
| Shapes, strokes, dashes, `g`, opacity, transforms | SVG DOM | `CAShapeLayer`, `CALayer` per `g`/transform | `svg_path` (vello / tiny-skia) |
| Linear and radial gradients | SVG DOM | a content layer drawn with `CGContext.drawLinearGradient` / `drawRadialGradient` (two-circle, so focal points are exact), masked by the shape's `CAShapeLayer` | peniko gradient brush (vello); tiny-skia `LinearGradient` / `RadialGradient` (two-point conical) |
| `clipPath` | SVG DOM | `CALayer.mask` holding `CAShapeLayer`s (clip rule honoured) | `push_clip` with the clip path; vello `push_layer` |
| `pattern`, `mask`, `filter` | SVG DOM | **island:** the subtree rendered in Rust (tiny-skia) to a premultiplied bitmap at device scale, then a `CALayer` with that image as contents (or as the mask of the masked subtree) | **island:** the same Rust code into a pixmap; the CPU painter composites it, and the GPU painter draws it as an image brush |
| Text | SVG DOM | glyph outlines from Core Text as paths into `CAShapeLayer`s | glyph outlines from cosmic-text/swash as paths into `svg_path` |

**Why islands.** Core Animation has no luminance mask, no public filter chain on iOS, and no pattern paint. vello has no filters. A single Rust implementation of mask, pattern and the filter primitives, used on both native hosts, is one place to be right. The web gets the browser's own rendering and serves as the oracle. An island is re-rendered only when something inside it changes. An animation inside an island is sampled (D15), because the island is pixels.

**Why gradients are not islands.** A chart's area fill under a draw-in must keep its Core Animation dash or path animation. A content layer masked by the animated `CAShapeLayer` does that and stays crisp at any zoom.

### D3. References: `id`, `url(#…)`, `href`

- **Grammar.** Paint is `url(#id)` with an optional fallback (`url(#g) red`, `url(#g) none`), as SVG 2 §13.2 says. Reference attributes are `href` (plus `xlink:href`, accepted as the same) on `use`, `textPath`, `image` and gradients. The properties `clip-path`, `mask`, `filter` and `marker-*` take `url(#id)`.
- **Resolution.** A reference looks in its own `svg` subtree first, then through the rest of the document in tree order, and takes the first match. The web resolves only in document order. The difference matters only when ids repeat, which is exactly the case the web gets wrong for components: the second chart row's `url(#fade)` paints with the first row's gradient. This is a declared improvement on the web's behaviour. The web host makes it visible by rewriting every SVG `id` it emits to `x<svg view id>-<id>`, and every reference to the rewritten id the kernel resolved. The DOM ids differ from the authored ones. Nothing reads them except the page's own references (no app JS).
- **Missing or wrong-type targets.** Paint falls back to the fallback colour, or to `none` when there is none. A missing `clip-path`, `mask` or `filter` target leaves the element unclipped, unmasked and unfiltered, as Chrome does. `use` of a missing target renders nothing. These are errors in SVG 2, but what Chrome draws is the standard here.
- **Cycles** (`use` of an ancestor, a pattern whose content paints with itself, a gradient `href` loop) render nothing for the offending reference, as Chrome does. The resolver carries a visiting set.
- **Liveness.** The kernel keeps an id index. It is rebuilt only when an `id` prop changes or a node carrying one is created or destroyed. A change inside a referenced element marks every `svg` that references it dirty.
- **Contract.** A literal reference to an id not declared in the same file is refused at compile time (`lower-svg-ref`). Computed references are resolved at run time.

### D4. Geometry, units and the view box

- **CSS geometry properties become rows, as SVG 2 defines them.** `x`, `y`, `rx`, `ry` (their initial is `auto`, and they copy each other as the first slice does), `cx`, `cy`, `r` (already rows), `width` and `height` (already rows), and `d` (the value is `none` or `path("…")`; the `d="…"` attribute is its presentation attribute). The first slice's `x`, `y`, `rx` and `ry` props are deleted.
- **`ellipse`** joins: `cx`, `cy`, `rx`, `ry`, with `auto` radii taking the other radius (SVG 2 §10.4).
- **Attributes CSS cannot set stay props:** `x1`, `y1`, `x2`, `y2`, `points`, `pathLength`, `viewBox`, `preserveAspectRatio`, the gradient and pattern coordinates, and the text positioning lists. A length prop is stored as its authored text and parsed by `kernel/src/svg/length.rs`.
- **Units.** User units (unitless) and `px`; the absolute units `in`, `cm`, `mm`, `pt`, `pc` (converted at lowering at 96 px per inch); `%`, resolved against the nearest viewport per axis (§8.9); `em` and `rem` against the computed `font-size` and the root's. `ex`, `ch`, `vw`, `vh` and friends are refused by name until a consumer needs them. `ex` and `ch` need font metrics at resolve time.
- **The intrinsic ratio.** An `svg` with a valid `viewBox` has an intrinsic aspect ratio of width over height (CSS Images 3 §4 for SVG). It has no intrinsic size unless `width`/`height` are set. The kernel feeds the ratio to Taffy's `aspect_ratio` when the author gave none. The 300×150 default object size applies only when neither a size nor a ratio is known. This replaces LLP 1055 §0's limit.
- **Nested `svg`** establishes a new viewport: `x`, `y`, `width`, `height`, its own `viewBox` and `preserveAspectRatio`, and a clip unless `overflow: visible`. This is SVG 2 §8.2's equations, already in `view_box_transform`.

### D5. Transforms on SVG elements

- **Rows.** The `transform` row is CSS `transform`: a list of `matrix`, `translate`, `translateX/Y`, `scale`, `scaleX/Y`, `rotate`, `skew`, `skewX/Y`. It accepts SVG's attribute grammar, with unitless numbers, commas, and `rotate(a cx cy)`, as its presentation attribute. Other rows: `transform-origin` (initial `0 0` for SVG elements), and `transform-box` (`view-box` initial; `fill-box`, `stroke-box`, `content-box`, `border-box`). The individual `translate`, `rotate` and `scale` rows also apply to SVG elements, as CSS applies them.
- **Composition** (CSS Transforms 2 §6.1): `translate(origin) · translate · rotate · scale · transform · translate(−origin)`, in the element's user space. `fill-box` makes the origin relative to the object bounding box, so `transform-origin: center` with `transform-box: fill-box` spins an icon about its own middle.
- **`transform` on HTML boxes** stays out. Boxes have the individual properties. A general `transform` on boxes is its own consumer and its own row semantics, including hit testing and layout overflow. Contract refuses `transform` on a box, by name, and points at `translate`/`rotate`/`scale`.
- **Hosts.**
  - Web: CSS, so the browser.
  - Apple: each transformed item becomes a pair of layers. The outer layer carries the individual transform properties, with `anchorPoint` at the origin, so Core Animation's `transform.translation`, `transform.rotation.z` and `transform.scale` key paths animate them. The inner layer carries the static `transform` matrix.
  - Linux: one affine per item.
- **`vector-effect: non-scaling-stroke`** (SVG 2 §13.8): the stroke is drawn in the host coordinate space. The resolver sends that item's path already transformed to the `svg`'s pixel space, with the stroke width unscaled. This is the sparkline idiom with `preserveAspectRatio="none"`.

### D6. Colour animation and transition

- **Properties.** `Property` gains `Color`, `BackgroundColor`, `Fill`, `Stroke`, `StopColor` and `FloodColor`. `Value` grows to four components. Colours interpolate in premultiplied sRGB, which is what CSS Color 4 §12.3 says for legacy colour syntax and what Chrome does for hex and `rgb()`.
- **Paint interpolation.** `fill` and `stroke` interpolate only between two colours, with `currentcolor` resolved to the used colour at sampling. `none` and servers switch discretely at 50%, as CSS does for a non-interpolable pair.
- **`light-dark()`** resolves to the current scheme's colour before interpolation. A scheme change during an animation re-resolves both endpoints.
- **Hosts.**
  - Web: CSS, as for every property.
  - Apple: `background-color` on a box lowers to Core Animation `backgroundColor` on its layer. `fill` and `stroke` on a shape lower to the `CAShapeLayer`'s `fillColor`/`strokeColor`, or to the gradient layer's opacity when a server is involved. `color` on a text leaf is sampled by the engine, and the paragraph re-rasters per sampled frame. This is the one colour property whose pixels Core Text bakes. A re-raster of one short label is well under a millisecond. The tint alternative (the glyphs as an alpha mask over an animated colour layer) is owed if the benchmark shows the cost. An animated `color` that reaches `currentcolor` paint in an `svg` is sampled for those shapes.
  - Linux: sampled by the engine, as every property is.
- **The benchmark.** The price flash is a keyed animation: `keyframes flashUp from color="#16a34a" to color="#000000"`, set on the price text, restarted by a new key per tick. That is `~/bench/cryptobench/exact-svg2`.

### D7. Paint servers

- **`linearGradient`, `radialGradient` and `stop`.** Attributes: `x1`/`y1`/`x2`/`y2`; `cx`/`cy`/`r`/`fx`/`fy`/`fr`; `gradientUnits` (`objectBoundingBox` initial, `userSpaceOnUse`); `gradientTransform`; `spreadMethod` (`pad`, `reflect`, `repeat`); `href` to inherit attributes and stops from another gradient (SVG 2 §14.2.3); `stop` `offset` (a number or a percentage). `stop-color` and `stop-opacity` are CSS rows, not inherited. Stop offsets are clamped monotonic, as SVG 2 says.
- **Object bounding box.** The bbox is computed in the resolver from geometry. It is the fill bbox, without stroke, as SVG 2 §8.10 defines. A zero-width or zero-height bbox makes an `objectBoundingBox` server render as the fallback, or as none: Chrome draws nothing for it.
- **`pattern`.** Attributes: `x`, `y`, `width`, `height`, `patternUnits`, `patternContentUnits`, `viewBox`, `preserveAspectRatio`, `patternTransform`, `href`. The tile is rendered as an island (D2) at device scale times the transform's scale. It is then tiled: a pattern image on Apple's content layer, and an image brush or pattern shader on Linux.
- **`paint-order`** (`normal`, or any order of `fill`, `stroke`, `markers`): the resolver orders an item's paint layers.
- **Apple spread methods.** `CGGradient` pads only. `reflect` and `repeat` are drawn by repeating the stop list across the bbox's extent in gradient space. That is exact, because the stops are piecewise linear.

### D8. `defs`, `symbol`, `use`: the shadow-tree semantics that matter

- **`defs`** and **`symbol`** never render directly. `symbol` renders only through `use`, with its `viewBox`, `preserveAspectRatio`, `x`, `y`, `width` and `height` (SVG 2 §5.5).
- **`use`** renders an instance of its target, translated by `x`/`y`. A `symbol` or `svg` target takes the `use`'s `width` and `height`, defaulting to 100%. The rules that matter:
  - **Inheritance.** The instance inherits from the `use`, not from the target's parent. This is what makes `fill="currentcolor"` icons take each use's colour.
  - **Own rows.** The target's own rows (and its class rows) still apply to it. Contract has no selectors, so none can match into the instance.
  - **Liveness.** A change to the target re-renders every instance.
  - **Events** on an instance go to the `use` element: it is the event target, as the shadow tree's retargeting makes it.
  - **Animations** on the target run on each instance, with each instance's own start: the instance is created when the `use` is.
  - **Cross-`svg` references.** An icon sprite (`svg` holding a `defs` of `symbol`s, `use`d from other `svg`s) resolves through the document index (D3).
- **Not in the scene.** Instances are not kernel nodes. They exist in the resolved scene only, so the kernel's tree stays the authored tree. On the web, `use` is native and the browser builds the shadow tree.

### D9. `marker`

`marker-start`, `marker-mid`, `marker-end` and the `marker` shorthand are inherited rows. A `marker` element takes `markerWidth`, `markerHeight` (3 initial), `refX`, `refY`, `orient` (`auto`, `auto-start-reverse`, or an angle), `markerUnits` (`strokeWidth` initial), `viewBox` and `preserveAspectRatio`. Vertices and their directions come from the resolved path, per SVG 2 §13.9's vertex rules, including the bisector at mid vertices and the direction at a closed subpath's start. Each marker is an instance, like `use`, painted after the shape's fill and stroke, unless `paint-order` says otherwise. `context-fill` and `context-stroke` in a marker take the referencing shape's paint. On `path`, `line`, `polyline` and `polygon` only.

### D10. `clipPath` and `mask`

- **`clipPath`.** Attributes: `clipPathUnits`, and children that are shapes, `text` or `use`. `clip-rule` is an inherited row. `clip-path` on an SVG element takes `url(#…)` or a CSS basic shape. The existing `clip_path` row's grammar grows `url()`, and a basic shape on an SVG element is resolved against `transform-box`'s reference box. Clip children union, each with its own `clip-rule`. A `clip-path` on the `clipPath` itself intersects, as SVG 2 §14.3.5 says. Hosts:
  - Web: native.
  - Apple: a `CAShapeLayer` mask per clip child in a mask container layer, opaque fill, the clip rule as its fill rule.
  - Linux: `push_clip` with the path.
- **`mask`.** Attributes: `maskUnits` (`objectBoundingBox`; region −10%/−10%/120%/120%), `maskContentUnits`, `x`/`y`/`width`/`height`. `mask-type` is a row: `luminance` (initial) or `alpha`. The mask's content is rendered as an island. For `luminance`, the island computes luminance with the sRGB coefficients (0.2125, 0.7154, 0.0721) over the premultiplied sRGB values, as CSS Masking 1 §7.2 says and Chrome does. Hosts:
  - Apple: the result is the contents of the masked item's `CALayer.mask`.
  - Linux: tiny-skia's `Mask` of type luminance or alpha.
  - vello: the GPU painter composites the masked subtree as an island too (vello has no luminance mask).
- **CSS `mask` properties beyond `mask: url(#…)`** (`mask-image` with gradients, `mask-size`, `mask-repeat`, `mask-composite`) are HTML-box features. They are refused on SVG elements, by name.

### D11. Text: `text`, `tspan`, `textPath`

- **Positioning.** `x`, `y`, `dx`, `dy` and `rotate` are lists, applied per character (per addressable character, SVG 2 §11.4). `text-anchor` (`start`, `middle`, `end`) is applied per text chunk. `dominant-baseline` takes `auto`, `alphabetic`, `middle`, `central`, `hanging`, `text-top`, `text-bottom`, `ideographic` and `mathematical`; `alignment-baseline` and `baseline-shift` take the same set on `tspan`. `textLength` and `lengthAdjust` (`spacing`, `spacingAndGlyphs`) are supported. So are `letter-spacing`, `word-spacing` and `white-space` (SVG 2 uses CSS `white-space`; `xml:space` is accepted as its legacy alias). The font rows already exist and are inherited.
- **Text content.** Contract's `text` inside an `svg` is the SVG `text` element. Its string children and `tspan`s are its content, the same inline-run model boxes use (a `text` with runs). A `tspan` takes paint, font and positioning.
- **Shaping is the host's.** Only the host has the fonts.
  - Web: native.
  - Apple: the resolver sends each text chunk (string, font descriptor, positioning lists, anchor, baseline) in the scene. Swift shapes it with Core Text, using the same font resolution as boxes (LLP 1019). It turns glyphs into one `CGPath` per chunk (`CTFontCreatePathForGlyph`), placed per the positioning lists, and gives the path to a `CAShapeLayer`. Fill, stroke, dashes, gradients and clips then apply to text as to any shape.
  - Linux: the same through cosmic-text shaping and swash outlines into `svg_path`.
  - Both native hosts report each chunk's advance to the resolver, for `text-anchor` and for hit testing and the bbox. The advance is measured the way boxes' text is measured, through the kernel's `TextMeasurer`, so the scene stays one pass.
- **`textPath`** (`href` to a `path`, or the `path` attribute; `startOffset` as a length or a percentage; `side`; `method="align"`; `spacing="exact"`): glyphs are placed along the referenced path's arc length. Each glyph's midpoint sits on the path, rotated to the tangent. Glyphs off either end are not rendered (SVG 2 §11.8.3). The path's arc-length table comes from the resolver.
- **Accessibility.** The text is exposed as the `svg`'s accessible text in document order, unless the `svg` has a label.
- **Refused:** vertical text (`writing-mode: vertical-*` on SVG text), `glyph-orientation-*`, SVG fonts, and `method="stretch"`.

### D12. `image` inside SVG

`href` (a URL, as boxes' `imageSource` takes one), `x`, `y`, `width`, `height` (rows; `auto` takes the image's intrinsic size), `preserveAspectRatio` (initial `xMidYMid meet`; the image's ratio is fitted into the viewport and clipped to it). Hosts reuse their image pipelines (LLP 1011): decode, cache and failure behaviour are the same as `<img>`. On Apple, a `CALayer` with the decoded image as contents, `contentsGravity` and a clip. On Linux, the backend's image draw. An SVG image as the source (`href` to an `.svg` file) is refused in v1. It is a second document with its own resolver input, and no consumer has one.

### D13. `foreignObject`: refused

HTML inside SVG puts boxes (views, with layout, text input, focus and native controls) under an SVG transform, clip, mask or filter. On the web that is free. On native hosts it would make every SVG ancestor a view, or render native views into an island's pixels, which breaks their interaction. No chart, icon or illustration needs it: the pattern is to position a box over the `svg`, which is also what React Native SVG users do. `foreignObject` is refused by name, and the error names that pattern. This is the one permanent refusal among the elements.

### D14. Filters

- **Elements.** `filter` with `x`/`y`/`width`/`height` (region initial −10%/−10%/120%/120%), `filterUnits`, `primitiveUnits`, `color-interpolation-filters` (`linearRGB` initial, and `sRGB`). The primitives, in stage order:
  - **Stage 9a (the common set):** `feGaussianBlur` (`stdDeviation` x/y, `edgeMode` none), `feOffset`, `feFlood` (`flood-color`, `flood-opacity` as rows), `feComposite` (`over`, `in`, `out`, `atop`, `xor`, `arithmetic`), `feMerge`/`feMergeNode`, `feColorMatrix` (`matrix`, `saturate`, `hueRotate`, `luminanceToAlpha`), `feDropShadow`, and `feBlend` (the separable modes).
  - **Stage 9b:** `feMorphology`, `feComponentTransfer` (`table`, `discrete`, `linear`, `gamma`), `feTile`, `feImage` (a reference to an element only), `feTurbulence`, `feDisplacementMap`, and `feConvolveMatrix`.
  - **Stage 9c:** the lighting primitives (`feDiffuseLighting`, `feSpecularLighting` and their lights). They are last because no chart or icon uses them.
- **Inputs and regions.** `in`/`in2` take `SourceGraphic`, `SourceAlpha`, named results and the previous result. `BackgroundImage` is deprecated and refused. Each primitive has its own subregion.
- **CSS `filter` functions on SVG elements** (`blur()`, `drop-shadow()`, `brightness()`, `contrast()`, `grayscale()`, `hue-rotate()`, `invert()`, `opacity()`, `saturate()`, `sepia()`) lower to the equivalent primitive chains, as Filter Effects 1 §12 defines them.
- **Implementation.** `exact-svg-raster` (§3) holds the primitives as pure functions over a premultiplied RGBA buffer with a pixel-to-user transform, shared by both native hosts. The Gaussian blur is three box blurs when σ ≥ 2.0, as the spec's approximation and Chrome do, and a true kernel below that. Colour-space conversion to linearRGB and back is done once per filter, not per primitive.
- **Hosts.**
  - Web: native.
  - Apple and Linux: islands (D2). The filtered subtree renders at device scale into the filter region, runs the chain, and composites. An animation under a filter is sampled while it runs.
- **Dependencies.** The primitives are ours, about 1,000 lines across primitives. That is less than a dependency on resvg's filter crate, which would also drag its own tree types.

### D15. Animation beyond `opacity`, `stroke-dashoffset` and `r`

- **Transform animation on SVG elements:** `translate`, `rotate`, `scale` (D5). On Apple, lowered to the outer layer's key paths. Elsewhere, sampled.
- **Geometry.** `cx`, `cy`, `r`, `x`, `y`, `width`, `height`, `rx` and `ry` interpolate as lengths. `d` interpolates when both paths have the same command list after normalization to absolute commands (CSS Shapes / SVG Paths: otherwise discrete). `Value` does not grow to a path. A `d` animation holds its keyframe paths in the row (the same `animations` codec with a path payload), and interpolation is per coordinate.
  - Apple: `d` lowers to Core Animation's `path` key path, which interpolates matched paths natively. `x`/`y`/`cx`/`cy` on a shape without a transform lower to `position`. Everything else is sampled, and the scene is re-sent per frame only for the changed items.
  - `points` is not a CSS property. It animates only through SMIL (D16).
- **Islands.** Anything inside an island (mask content, pattern tile, filter input) is sampled, and the island re-renders per frame while the animation runs. This is declared: an animated blur costs a filter pass per frame on native.
- **Inherited animated values** (LLP 1055 §0's limit) flow down in the resolver: an animated `stroke-dashoffset` or `color` on a `g` reaches the shapes that inherit it. When the ancestor's animation is lowered, the same spec is attached to each inheriting descendant's layer.
- **`display: none`** on an animated node or its ancestor cancels its animations on native hosts, as on the web. Showing it again starts them anew (CSS Animations 1 §3). This replaces LLP 1055 §0's limit.

### D16. SMIL: lowered to CSS animations

Chrome runs SMIL (`animate`, `set`, `animateTransform`, `animateMotion`), and icon sets and illustration tools export it. The choice is between executing SMIL natively on the web and emulating it on native hosts, or lowering it once.

**Choice.** Contract lowers each SMIL element into its target's `animation` row, plus a synthesized `keyframes` rule. Every host, the web included, then runs one mechanism.

| SMIL | Lowered to |
|---|---|
| `attributeName` | the matching row (it must be animatable here) |
| `from`/`to`/`by`/`values` | keyframes; `by` adds to the underlying value, as `from + by` |
| `keyTimes`, `keySplines`, `calcMode` | offsets; per-interval `cubic-bezier`; `discrete` → `steps(1, end)` per interval; `linear`; `paced` → offsets from the value distances, computed at lowering for literals |
| `dur`, `repeatCount` (`indefinite`), `repeatDur` | duration, iteration count; `repeatDur` → a fractional count |
| `begin` (a single offset) | delay; negative offsets allowed |
| `fill="freeze"` | `forwards`; `remove` (initial) → `none` |
| `set` | a `steps(1, start)` keyframe pair |
| `animateTransform type=translate/scale/rotate/skewX/skewY` | the `transform` row's function list, with `additive="sum"` composing after the element's own `transform`, as SVG says |
| `animateMotion` (`path`, `mpath`, `keyPoints`, `rotate="auto"`/`auto-reverse`/angle) | CSS `offset-path: path(…)`, `offset-distance`, `offset-rotate`, rows that apply to SVG elements only here |

**Refused, by name:**
- event and syncbase `begin`/`end` values (`click`, `a.end+1s`, `accessKey`, `wallclock`): these are timing graphs, and `animation` events plus state cover the interactive case;
- `restart`, `min`/`max` and `accumulate="sum"`: until a consumer needs them;
- `additive="sum"` on anything but `animateTransform`.

**Declared deviations.**
- **The web's DOM holds CSS animations, not SMIL elements.** The pixels match Chrome's SMIL, and the parity smoke checks exactly that. No app JS reads `SVGAnimationElement`. The agent's `clock` seeks both, because WAAPI sees CSS animations and not SMIL.
- **SMIL's document timeline starts at the `svg`'s insertion.** Chrome starts it at document load. Rows mount later than the document, and a SMIL icon in a list row should start with its row, as CSS does (LLP 1055 D9).

### D17. Interaction and accessibility

- **`pointer-events`** is an inherited row: `auto` (= `visiblePainted`), `none`, `visiblePainted`, `visibleFill`, `visibleStroke`, `visible`, `painted`, `fill`, `stroke`, `all`, with SVG 2 §15.6's meaning. `visibility` (`visible`, `hidden`, `collapse`) becomes an inherited row that SVG elements honour, as CSS does.
- **Handlers on SVG elements** (`press`, `hover`, and every pointer handler boxes take) are admitted. The `svg` stays the one native view. On a native host, a pointer event in the `svg` asks the kernel's `svg::hit(svg, point)`. It walks the resolved scene in reverse paint order. For each item it tests the fill (winding rule, in the item's inverse transform) and the stroke (distance to the flattened path ≤ half the stroke width, joins approximated by round). It honours `pointer-events`, clips, and the `svg`'s own box. It returns the element, or the `use` element for an instance. The host then dispatches to that element's view id. Bubbling follows the kernel's tree, as it does for boxes. The web is native.
- **Hover** on native: the `svg`'s pointer-move tracking re-runs `hit` and sends enter and leave per element.
- **Accessibility.**
  - A `title` child is the element's accessible name, and `desc` its description (SVG 2 §5.9, SVG-AAM).
  - `role`, `aria-label`, `aria-hidden` and `tabindex` on SVG elements map as they do on boxes.
  - An element with a handler, or an explicit `role`, becomes an accessibility element with its bbox as the frame: on Apple, a `UIAccessibilityElement` (or an `NSAccessibilityElement` on macOS) under the `svg`'s view. Elements without either are presentational, and the `svg` is one image whose label is its own `title`, `aria-label`, or else nothing.
  - `title` is not a tooltip on native hosts (the web shows one). This is declared: native has no hover tooltip on touch, and a macOS tooltip is owed.
- **`a` inside SVG** is a `g` with `href`: a link, with the box `a`'s navigation and hit-testing semantics. It is in this stage.

### D18. Animation events

`animationstart`, `animationiteration`, `animationend` and `animationcancel` handlers (Contract `animationend=action`) are admitted on any node.
- Web: native events.
- Native: the engine reports phase changes when it is advanced. A lowered animation's phases are known in closed form from its start, so the host schedules a timer for the next boundary. It never polls. Iteration events on an infinite animation fire once per period, and only while a handler is registered: an unhandled infinite pulse never wakes the app.

Cheap enough to take in stage 11.

### D19. Styling: `class=`, `currentColor`, and what else CSS brings

- **`class=`** on SVG elements is admitted. A style set's rows apply if they apply to the element, and any other row is a compile error naming it.
- **`currentcolor`** is accepted wherever a colour is: `fill`, `stroke`, `stop-color`, `flood-color`, `lighting-color`, and the fallback of a `url()` paint. It resolves to the element's computed `color`, and in a `use` instance, to the instance's inherited `color`.
- **`display: none`** on an SVG element removes it and its subtree from rendering. `visibility: hidden` hides an element, but its visible descendants still render, as CSS says.
- **`mix-blend-mode`** and **`isolation`** on SVG elements:
  - Web: native.
  - Apple: `CALayer.compositingFilter` on macOS; on iOS, an island (no public blend on `CALayer`).
  - Linux: vello `Mix` / tiny-skia `BlendMode`.
  
  Stage 10 takes these.

## 3. What each host needs, summarized

- **Kernel:** the resolver, lengths, references and index, bbox, markers' vertices, and `hit`. No pixels.
- **The island rasterizer's home.** tiny-skia is already a dependency of the Linux host. On Apple it is not. The islands live in a new crate, `exact-svg-raster` (tiny-skia plus the filter primitives), linked by the Apple and Linux hosts. The kernel stays dependency-free, and the web links nothing new (LLP 1047). The Apple host already links Rust, so an island is one FFI call returning a premultiplied bitmap for a `CGImage`.
- **Apple Swift:** `SvgScene.swift` grows content layers (gradients), a mask container (clips), transform layer pairs, text shaping, island images, and accessibility elements. It stays one file per concern: `SvgPaint.swift` (servers) and `SvgText.swift` (glyphs) join it, each ≤ 1,500 lines.
- **Linux:** `paint/svg.rs` becomes a consumer of the scene. `Backend` gains gradient brushes, image brushes and masks.
- **Web:** new tags in the SVG namespace, id rewriting, the new CSS rows, and nothing per frame.

## 5. Verification

- **Kernel unit tests:** lengths and units, the resolver's inheritance through `use`, reference resolution order and cycles, bbox, transform composition against Chrome's `getCTM()`, marker vertices, `hit` against Chrome's `elementFromPoint` on the gallery, gradient spread expansion, and filter primitives against Chrome pixels on small fixed inputs.
- **Motion:** colour interpolation samples pinned to Chrome's `getComputedStyle` at a paused `currentTime`, as LLP 1055 pinned the timing model. The same for transform and geometry.
- **Contract:** every new tag and attribute, the SMIL lowering table (each row one test), and each refusal.
- **Parity smoke (`bun scripts/smoke.mjs svg`).** It turns LLP 1055's hand comparison (QUEUE) into a smoke. The web renders `apps/svg-gallery` in Chrome as the reference. Each native host renders the same frozen pages. The smoke then crops each fixture by its layout box, registers it within ±20 px, and reports mean |Δ| and the share of pixels off by more than 32, per fixture and host. The thresholds are LLP 1055's measured residue (antialiasing and Chrome's 1× raster): mean ≤ 4/255 and ≤ 6% off per fixture. A fixture beyond them fails with its crop pair written out. The smoke is async-lane apparatus (it drives four hosts), not a sixth blocking check.
- **XCTest:** the Apple layer tree for each stage (content layers, masks, transform pairs, accessibility elements), and paused-layer presentation for each lowered property.

## 6. Costs

- **Rows.** Roughly 30 new style rows across the stages (geometry 4, transform 3, `vector-effect`, `paint-order`, stops 2, markers 3, `clip-rule`, `mask-type`, text 5, `pointer-events`, `visibility`, flood 2, `color-interpolation-filters`, offset 3, blend 2), and about 40 props. The mask grows from two words to three.
- **Size.**
  - Web wasm: grows by the resolver's reference index and the new codecs only. The web paints nothing itself.
  - Apple: grows by the resolver, `exact-svg-raster` and tiny-skia (about 0.4 MB, measured before stage 8 lands; if it matters, it becomes a capability module per LLP 1047).
  - Linux: already links tiny-skia.
- **One second rasterizer on Apple.** Islands are tiny-skia pixels composited into Core Animation. Their antialiasing differs from Core Graphics' by a pixel's shade. The parity thresholds absorb it, and the gallery measures it.
- **Per-frame work for sampled animations inside islands** (D15), declared.

## 7. What this refuses

Permanent, each by name with its reason:
- `foreignObject` (D13);
- `script` and `style` elements inside `svg`: there is no app JS, and Contract has no selectors; its `style` sets are the stylesheet;
- SVG fonts;
- `cursor` elements;
- `BackgroundImage` / `enable-background`;
- event and syncbase SMIL timing (D16);
- `vector-effect` values other than `none` and `non-scaling-stroke`, which SVG 2 marks at risk and Chrome does not ship.

Until a consumer needs them:
- `ex`, `ch`, `vw`, `vh` and other lengths;
- vertical SVG text;
- `textPath` `method="stretch"`;
- an SVG file as an `image` source;
- CSS `mask-*` longhands on SVG elements;
- `transform` on HTML boxes;
- `restart`, `min`/`max`, `accumulate`.
