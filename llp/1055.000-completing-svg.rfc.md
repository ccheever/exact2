## Summary

Charlie, 2026-09-26: "why wouldn't we just do a complete SVG implementation here? i think this will be useful and we're using it now." LLP 1055 built the first slice: eight elements, the presentation properties, and CSS animations over `opacity`, `stroke-dashoffset` and `r`. Everything that RFC refused or declared as a limit is now a stage.

This RFC lists what SVG 2 and the CSS that applies to it bring beyond the first slice, decides each item, says how each host paints it, and orders the stages by what real apps draw: **charts first, then icons, then illustrations**.

Three decisions shape everything else:
1. **One resolver in Rust (D1).** Native hosts stop asking each node for its computed style. A kernel walk resolves an `svg` into a scene: inheritance, `use` instances, references, units, transforms, and paint. The Apple and Linux hosts only map that scene to layers or backend calls. The web keeps the real SVG DOM; the browser is still the renderer and the oracle.
2. **Islands for what a compositor cannot do (D2).** Masks, filters and patterns are rendered to pixels in Rust, then composited: tiny-skia on Linux, and the same Rust code over a Core Graphics bitmap on Apple. Everything else stays vector and animatable: `CAShapeLayer` on Apple, vello or tiny-skia calls on Linux.
3. **References resolve like the web, and ids stay unique (D3).** With unique ids, `url(#id)` and `href="#id"` resolve exactly as the web resolves them. When ids repeat (a component instantiated forty times), the target nearest the reference in the tree wins, and the web host rewrites ids so the page shows that choice. Otherwise forty charts would paint with the first row's gradient.

**Recommendation:** build the stages in §4's order (r2 splits and reorders them). Emit `foreignObject` on the web and defer it on native (D13, §8 ruling 5), and refuse a short list of legacy or scripting features (§7). Each stage lands with tests, Chrome parity on every host, and the `svg-gallery` fixture extended.

**Not accepted:**
- **Astra: resolve with standard document order only, and add component-level id hygiene.** Contract inlines components, so no scope survives into the kernel. The deepest-common-ancestor rule is that hygiene, expressed in the tree. With unique ids it is identical to the web.
- **Astra: keep SVG attribute grammar and CSS grammar in separate rows.** Both reviewers agree that one row accepting both grammars is fine. Grok recommends it. The web host always emits CSS grammar.
- **Grok: markers only on four elements must be declared.** They will be on every shape instead (above). *Reversed in stage 7:* Chrome 154 draws markers on `path`, `line`, `polyline` and `polygon` only, and the web is the oracle, so Grok was right.

### Stage 1 as built

Everything in §4's stage 1 is built on every host:
- **Kernel:** `kernel/src/svg/scene.rs` resolves the scene; `length.rs` handles units and percentages, and `transform.rs` the list, the origin and the affine arithmetic. `ellipse` is `SvgEllipse`, and a nested `svg` is `SvgViewport`. `x`, `y`, `rx` and `ry` are rows (the props are deleted), `cx`, `cy` and `r` are dimension rows, and `x1`–`y2` hold their authored text. New rows: `transform`, `transform-origin`, `transform-box`, `vector-effect` and `visibility`. A view box is the natural ratio.
- **Contract:** SVG elements take `class=`, components may root in a `g`, and number literals and computed numbers are coerced into length props. All dimension rows accept `in`, `cm`, `mm`, `pt` and `pc`.
- **Web:** new elements are emitted as the SVG DOM. `transform` is emitted in CSS grammar. A nested `svg`'s `x`, `y`, `width` and `height` are emitted as attributes, because Chrome 154 lays out a nested `svg` from its attributes and ignores those CSS properties. This was measured: with CSS only, `getCTM()` shows 100% sizing at 0,0.
- **Apple:** the scene JSON is serialized from the resolver. Swift adds transform pairs, nested viewports (anchor at the bounds' origin, so a sublayer transform applies from there) and non-scaling strokes.
- **Linux:** the painter walks the resolved scene.

**Parity,** `bun scripts/smoke.mjs svg`, page 1 of `apps/svg-gallery` (nine fixtures, each 120×80 pt). Native captures are brought to 1 px/pt and converted from the display profile to sRGB. Each crop is registered within ±3 px and compared with Chrome 154 at 1×:

### Stage 2 as built: colour and transform motion

- **Motion:** `Value` has four components. `color`, `background-color`, `fill` and `stroke` animate and transition in premultiplied sRGB (`motion/src/color.rs` parses the legacy colour syntax the kernel admits). Eight samples are pinned to Chrome 154's `getComputedStyle` at a paused `currentTime`, all within one 8-bit step (`colour_samples_match_chrome`). The keyframe wire carries each property's own number of components.
- **Kernel:** a node gets colour targets only when its `transition` or `animation` names a colour; `fill` and `stroke` only on SVG nodes. A `none` paint or a `light-dark()` pair retires the target, so it does not interpolate (the second is a declared stage-2 limit). `display: none` on a node or an ancestor cancels its animations, and showing it restarts them: the receipt names `display_changed` nodes.
- **The resolver** carries a moving inherited value (`color`, `fill`, `stroke`, the dash offset) from the node that animates it to the descendants that inherit it. A node's own engine slot counts only where it sets the row or animates the property itself; otherwise its slot holds the inherited row and would mask the ancestor's motion.
- **Apple:** `fill` and `stroke` animations on a shape lower to Core Animation. Their tracks are sampled every sixteenth of each interval, because Core Animation interpolates `CGColor`s in the display's colour space rather than sRGB: without the samples, a red-to-blue midpoint was off by 7 levels. The engine samples, per node (`Engine::set_node_sampled`), what Core Animation cannot play: a container's inherited motion, colours of differing alpha, and a shape painted by a gradient. A box's `color` or `background-color` motion re-sends its style with the presented values, together with the descendants that inherit that `color`. Transform animations on SVG elements are sampled, and their scenes rebuilt.
- **iOS** pools rows that hold an `svg`. `SvgHost.forget`, called on release, already drops the scene and every Core Animation spec.
- **Not built:** animation events (D18). They move after stage 5. The benchmark needs none.
- **The benchmark:** `~/bench/cryptobench/exact-svg2` (bundle `dev.exact.cryptobench.svg2`, built against this branch) flashes the price with `keyframes flashUp/flashDown` on `color`, restarted by each flash's key. It was driven on an iPhone 17 Pro simulator with live ticks: the updated price shows mid-flash green at the next frame.

### Stage 3 as built: references and paint servers

- **Kernel:** `defs`, `linearGradient`, `radialGradient`, `stop`, `use` and `symbol` are node types. Paint takes `url(#id)` with a fallback. The kernel indexes `id` props beside test ids, and `Kernel::resolve_id` implements D3's nearest-candidate rule. `svg/server.rs` resolves a gradient: its `href` chain (own stops replace the template's), SVG 2's defaults, the bounding box, the units, the transform and the spread. `stop-color` (`currentcolor` resolved in the stop's own tree), `stop-opacity` and `paint-order` are rows. A `use` of a `symbol` or `svg` is a viewport, and a `use` of anything else is a placed instance. Both inherit from the `use`, and each instance item has its own key (`Item::uid`).
- **Linux:** gradients are tiny-skia shaders and peniko brushes (two circles, pad/reflect/repeat), interpolated unpremultiplied as Chrome's SVG gradients are. `paint-order` orders the fill and stroke calls. A retained region captures an `svg`'s resolved scene and replays it.
- **Apple:** a shape with a gradient or a non-normal paint order paints through part layers. A gradient part is drawn by Core Graphics at the scale it shows at, masked by the shape's fill or stroke. `reflect` and `repeat` repeat the stops, which is exact for linear and concentric radial gradients; a moving focus pads (owed to the islands of stage 8). A circle's gradient moves with its origin-centred path. iOS canvas capture now takes presentation values, dash phases and masks.
- **Web:** every SVG `id` becomes `x<view id>`, and paint URLs, `href` and `clip-path` URLs name the id of the target the kernel resolved. A radial gradient's `cx`, `cy` and `r`, and a `use`'s `x`, `y`, `width` and `height`, are emitted as attributes.

### Stage 4 as built: clipping

- `clipPath` (`clipPathUnits`, children that are shapes or `use`), `clip-rule`, and `clip-path: url(#id)` on SVG elements. The resolver builds the union of the children in the clipped element's own user space (`svg/scene/clip.rs`) and intersects the `clipPath`'s own `clip-path`. A missing reference does not clip, and an `objectBoundingBox` clip on an element with no box hides it.
- Linux multiplies coverage masks (CPU) or nests clip layers (GPU). Apple masks the element's layer with one opaque shape per child, and the nested clip becomes the mask's mask. The web references the clip by its DOM id. Contract refuses a `url()` clip on a box.
- **Not built:** basic shapes on SVG elements, and `shape-rendering`. Core Animation antialiases every path, and vello cannot turn antialiasing off, so `crispEdges` needs a drawn layer on Apple.

### Stage 5 as built: text

- **Kernel:** inside an `svg`, `text` and `tspan` are SVG node types (Contract tracks the depth, so a box's `text` stays a box). `svg/scene/text.rs` resolves a `text` into chunks of runs. White space collapses as CSS `normal` does, and a chunk's edges are trimmed. An `x` or `y` on a `tspan` starts a chunk, and a run carries its first `dx` and `dy`. Each run has its font, fill and stroke. `text-anchor` and `dominant-baseline` are rows. The host shapes, since only it has the fonts (D11).
- **Baselines**, measured in Chrome 154 and used by the hosts: `middle` shifts by half the x-height, `central` by (ascent − descent)/2, `hanging` by 0.8·ascent, `ideographic` by −descent, `mathematical` by ascent/2, all with integer ascent and descent. The first run's font sets a chunk's baseline.
- **Apple** shapes each run with Core Text and the presenter's fonts (LLP 1019). A run's glyph outlines become one path in a `CAShapeLayer`, so fill, stroke, dashes and paint animations apply as they do to any shape.
- **Linux** paints each run through its text engine, in its pinned font. It fills only: stroking text is owed. The parity smoke gives Linux's text fixtures a looser bound (mean 14, 16%), because the font differs from Chrome's.
- **Web** emits `text` and `tspan`.
- **Refused as later stages:** per-character `x`/`y`/`dx`/`dy` lists past the first value, `rotate`, `textLength`/`lengthAdjust`, and `textPath`.

### Stage 6 as built: presses and `pointer-events`

- **Contract:** an SVG element that renders takes `press`. On `defs`, a gradient, `stop`, `symbol`, `clipPath` or `tspan`, it is refused, because a definition renders only where it is referenced. Every other handler on an SVG element is refused as a later stage, so no handler works on the web and silently fails on a native host. `pointer-events` is an inherited row with SVG 2's eleven values.
- **Kernel:** `Scene::hit` (`svg/scene/hit.rs`) walks the resolved scene topmost first. It tests the fill by its rule, and the stroke by distance to the flattened path within half the width. That treats every join and cap as round, and dash gaps as stroke (declared). It goes through clips and honours `visibility`. A `use` instance hits as its `use`. Text is not hit yet.
- **Linux:** the pointer and the agent's `tap` hit through `Scene::hit`, on the presented values. The press bubbles up the kernel's tree, as a box's press does.
- **Apple** hits its presented layers: a shape's fill, its stroked outline (caps, joins and dashes as Core Graphics strokes them), clip masks, and `pointer-events: none`. The other `pointer-events` values read as `visiblePainted` on Apple for now. The press goes to the nearest element with a handler. Touch, click, the agent's tap and VoiceOver activation all take this path. Apple hits what is on screen mid-animation, where the kernel's scene holds the underlying value.
- **The agent's `tap` on an `svg`** presses the element drawn at its centre, as a finger there would. SVG elements have no box of their own for the agent to address yet.
- **Not built (owed to D17):** hover and the other pointer handlers on native hosts; `title`/`desc` and per-element accessibility elements; `a` inside SVG; text hit testing.

### Stage 7 as built: markers

- **Kernel:** `marker` is a node type that renders only through a reference. `marker-start`, `marker-mid` and `marker-end` are inherited rows (`none` or `url(#id)`), and Contract's `marker` sets all three. `svg/scene/marker.rs` places an instance at each vertex. A vertex is the end of each authored command, so the parser records where each command's segments end, and an arc drawn as several cubics is one vertex. Each subpath's start is a vertex, and so is the point a `Z` returns to. The direction bisects the tangents in and out. A closed subpath's start takes the closing segment as its incoming direction, and a zero-length close keeps the direction it arrived with. `orient` takes `auto`, `auto-start-reverse` (the start marker only) and an angle in `deg`, `rad`, `grad` or `turn`. `markerUnits="strokeWidth"` scales by `stroke-width`. The view box maps the content onto `markerWidth` × `markerHeight` (default 3), with `refX`/`refY` on the vertex. The content inherits from the marker's own ancestors, and Contract gives `marker` the UA's `overflow: hidden`. An instance is keyed by its vertex, so each one is its own layer, and a marker inside its own content draws nothing.
- **Which shapes:** `path`, `line`, `polyline` and `polygon`, as Chrome 154 draws them. r2's "every basic shape" was SVG 2's text. Chrome does not do it, and the web is the oracle.
- **Paint order:** markers paint where `paint-order` puts them: before, between or after the fill and stroke. Linux splits the shape's paint around them. Apple writes a marked shape as a group standing for it (its opacity, transform and clip), holding its paint parts and its markers in that order. The web is native. Markers take no hits.
- **Not built:** `context-fill`/`context-stroke`; `refX`/`refY` keywords (`left`, `center`, `right`, `top`, `bottom`); a marker in another `svg`, which is the same liveness gap as a sprite.

**Parity after stage 7,** on seven pages: 30 fixtures per host. The two marker fixtures are at mean |Δ| 0.48 and 1.11 on Linux, 1.21 and 1.39 on macOS, and 1.21 and 1.33 on iOS, all within the bound. The residue is the antialiasing of small filled heads.

### Stage 8 as built: masks, patterns, and the island module

- **Kernel:** `mask` and `pattern` are node types that render only through a reference. `mask` (a style row, `none` or `url(#id)`; the field is `svg_mask`, the CSS property `mask`) and `mask-type` (`luminance` initial, or `alpha`) are rows. `maskUnits`, `maskContentUnits`, `patternUnits`, `patternContentUnits` and `patternTransform` are props. A region's `x`, `y`, `width` and `height` are the geometry rows. `svg/scene/island.rs` resolves both as it resolves a `use`: the content inherits from the definition's own ancestors, and each reference is its own instance, with its own keys. A mask becomes `Item.mask`: its region (−10%/−10%/120%/120% of the box by default) and its content, in the masked element's user space. A pattern becomes `ShapePaint.pattern`: the tile in pattern space, `patternTransform`, and the content with the view box or content units applied. `href` templates give the attributes and the first children found. A tile with no area disables the paint, and a mask with no box masks everything away, as Chrome draws them.
- **Web:** `mask`, `pattern` and their attributes are emitted natively. The region is emitted as attributes, and ids are rewritten as for every reference.
- **Linux** paints an island with a child painter over tiny-skia, then composites it through `Backend::surface_image`, so the CPU and GPU painters share it (`paint/island.rs`). A mask renders the element and the mask's content over the region. `exact-svg-raster` turns the content into coverage, and the coverage scales the element. A pattern's tile is rendered at the scale it shows at. It then becomes a repeating tiny-skia pattern shader, or a vello image brush with `Extend::Repeat`.
- **Apple** builds an island's source from the layers the scene already makes. A sub-scene (`SvgIsland.swift`) holds the content and is rendered by Core Animation's own `render(in:)`. So text, gradients and clips come along, and they antialias as the rest of Apple's SVG does. On macOS the sub-scene's root is geometry-flipped, because off screen a Mac layer draws its contents images bottom up.
  - **Masks:** the module turns the content into coverage, and the image becomes the mask of the element's layer, inside its clip mask when it has one. Each mask is cached by the digest of its spec.
  - **Patterns:** the rendered tile is repeated by a Core Graphics pattern whose matrix maps pattern space to the bitmap's device space, and the result is masked by the shape like a gradient part. Core Graphics' own `draw(_:in:byTiling:)` takes its phase from the device, not from pattern space, and tiling by hand left seams.
- **Refused as before or owed:** the CSS `mask-*` longhands (D10); a mask on a mask; animation inside an island shows the model value on Apple (D15 wants it sampled); `reflect`/`repeat` of a radial gradient with a moving focus on Apple.

### Stage 9 as built: filters (9a, 9b and 9c)

## 2. Decisions

### D1. One resolved scene, computed in Rust

**Today.** Apple's `svg.rs` and Linux's `paint/svg.rs` each walk the subtree. Each calls `computed_style` per element, which walks ancestors again. Each re-derives geometry and paint. That was tolerable for eight elements. It is not tolerable once inheritance crosses `use`, paint names a gradient, and lengths resolve against a nested viewport.

**Choice.** `kernel/src/svg/scene.rs` resolves one `svg` into a `Scene`: a tree of `Item`s (group, shape, text, image, use instance) with everything resolved.
- **Inherited style is carried down the walk.** It is not looked up per node, and a `use` instance inherits from the `use`, not from the original's parent. This is SVG 2 §5.6, and a lookup through ancestors cannot express it.
- **Lengths are resolved against the nearest viewport.** Percentages use the viewport's width, height, or normalized diagonal √((w²+h²)/2), as SVG 2 §8.9 says.
- **Transforms become one affine per item**, composed as CSS Transforms 1 §6 composes them (D5).
- **Paint becomes a `ResolvedPaint`:** none, a colour, or a server reference with its fallback, the server's resolved stops, units and transform.
- **Clip, mask and filter references are resolved to items** (D10, D14), and markers to instances (D9).
- **Presented values from the motion engine** (a running transition or a sampled animation) are read at resolve time, so every host sees the same instant.

Native hosts consume the scene. Apple serializes it as the `svg` op's JSON (the first slice's format grows fields; it does not fork). Linux paints it directly. The web does not need it to paint. It uses the same resolver for two things: id rewriting (D3) and hit-test parity tests. The resolver is plain data over the kernel arena. An `svg`-free plan pays only its code size (LLP 1047).

### D2. What stays vector, and what becomes an island

| Feature | Web | Apple | Linux |
|---|---|---|---|
| Shapes, strokes, dashes, `g`, opacity, transforms | SVG DOM | `CAShapeLayer`, `CALayer` per `g`/transform | `svg_path` (vello / tiny-skia) |
| Linear and radial gradients | SVG DOM | a content layer drawn with `CGContext.drawLinearGradient` / `drawRadialGradient` (two-circle, so focal points are exact), masked by the shape's `CAShapeLayer` | peniko gradient brush (vello); tiny-skia `LinearGradient` / `RadialGradient` (two-point conical) |
| `clipPath` | SVG DOM | `CALayer.mask` holding `CAShapeLayer`s (clip rule honoured) | `push_clip` with the clip path; vello `push_layer` |
| `pattern`, `mask`, `filter` | SVG DOM | **island:** the subtree rendered in Rust (tiny-skia) to a premultiplied bitmap at device scale, then a `CALayer` with that image as contents (or as the mask of the masked subtree) | **island:** the same Rust code into a pixmap; the CPU painter composites it, and the GPU painter draws it as an image brush |
| Text | SVG DOM | glyph outlines from Core Text as paths into `CAShapeLayer`s | glyph outlines from cosmic-text/swash as paths into `svg_path` |

**Why islands.** Core Animation has no luminance mask, no public filter chain on iOS, and no pattern paint. vello has no filters. A single Rust implementation of mask, pattern and the filter primitives, used on both native hosts, is one place to be right. The web gets the browser's own rendering and serves as the oracle. An island is re-rendered only when something inside it changes. An animation inside an island is sampled (D15), because the island is pixels.

**Why gradients are not islands.** A chart's area fill under a draw-in must keep its Core Animation dash or path animation. A content layer masked by the animated `CAShapeLayer` does that and stays crisp at any zoom.

### D3. References: `id`, `url(#…)`, `href`

- **Grammar.** Paint is `url(#id)` with an optional fallback (`url(#g) red`, `url(#g) none`), as SVG 2 §13.2 says. Reference attributes are `href` (plus `xlink:href`, accepted as the same) on `use`, `textPath`, `image` and gradients. The properties `clip-path`, `mask`, `filter` and `marker-*` take `url(#id)`.
- **Resolution (r2).** With one candidate, it is the target, wherever it is in the document: the web's rule. With several (a component instantiated forty times, each declaring `id="fade"`), the candidate sharing the deepest common ancestor with the reference wins, ties in tree order. Each instance therefore finds its own `defs`. The web picks the first in the document and paints forty rows with the first row's gradient. This is a declared improvement that only applies to duplicate ids. The web host makes it visible by rewriting every SVG `id` it emits to `x<view id>` (unique by construction), and every reference, in every channel, to the id of the target the kernel resolved. The DOM ids differ from the authored ones. Nothing reads them except the page's own references (no app JS). `href` wins over `xlink:href`. External `url()` is refused by name.
- **Missing or wrong-type targets.** Paint falls back to the fallback colour, or to `none` when there is none. A missing `clip-path`, `mask` or `filter` target leaves the element unclipped, unmasked and unfiltered, as Chrome does. `use` of a missing target renders nothing. These are errors in SVG 2, but what Chrome draws is the standard here.
- **Cycles** (`use` of an ancestor, a pattern whose content paints with itself, a gradient `href` loop) render nothing for the offending reference, as Chrome does. The resolver carries a visiting set.
- **Liveness.** The kernel keeps an id index. It is rebuilt only when an `id` prop changes or a node carrying one is created or destroyed. A change inside a referenced element marks every `svg` that references it dirty.
- **Contract.** A literal reference to an id declared nowhere in the file is a compile-time warning, not an error: the target may come from another component at run time.

### D4. Geometry, units and the view box

- **CSS geometry properties become rows, as SVG 2 defines them.** `x`, `y`, `rx`, `ry` (their initial is `auto`, and they copy each other as the first slice does), `cx`, `cy`, `r` (already rows), `width` and `height` (already rows), and `d` (the value is `none` or `path("…")`; the `d="…"` attribute is its presentation attribute). The first slice's `x`, `y`, `rx` and `ry` props are deleted.
- **`ellipse`** joins: `cx`, `cy`, `rx`, `ry`, with `auto` radii taking the other radius (SVG 2 §10.4).
- **Attributes CSS cannot set stay props:** `x1`, `y1`, `x2`, `y2`, `points`, `pathLength`, `viewBox`, `preserveAspectRatio`, the gradient and pattern coordinates, and the text positioning lists. A length prop is stored as its authored text and parsed by `kernel/src/svg/length.rs`.
- **Units.** User units (unitless) and `px`; the absolute units `in`, `cm`, `mm`, `pt`, `pc` (converted at lowering at 96 px per inch); `%`, resolved against the nearest viewport per axis (SVG 2's units rules: `x`, `width`, `cx`, `rx` against the width; `y`, `height`, `cy`, `ry` against the height; `r` against the normalized diagonal). `em`, `rem`, `ex`, `ch`, `vw`, `vh` and friends are refused by name until a consumer needs them (r2: `rem` is the document root's font size, not the `svg`'s, so it needs the runner's root style). `stroke-width` and dash lengths stay numbers, and a percentage there is refused by name.
- **The intrinsic ratio.** An `svg` with a valid `viewBox` has an intrinsic aspect ratio of width over height (CSS Images 3 §4 for SVG). It has no intrinsic size unless `width`/`height` are set. The kernel feeds the ratio to Taffy's `aspect_ratio` when the author gave none. With neither dimension known, the box takes the offered width (Chrome's stretch fit), or 300 px when the offer is indefinite, and its height from the ratio. The 300×150 default object size applies when there is no ratio. This replaces LLP 1055 §0's limit. Chrome 154, measured: 400×200 in a 400 px block, 60×30 with `width=60`, 300×150 with no view box.
- **Nested `svg`** establishes a new viewport: `x`, `y`, `width`, `height` (`auto` is 100% of the parent viewport), its own `viewBox` and `preserveAspectRatio`, and a clip unless `overflow: visible` (the UA's `hidden`). This is SVG 2 §8.2's equations, already in `view_box_transform`.

### D5. Transforms on SVG elements

- **Rows.** The `transform` row is CSS `transform`: a list of `matrix`, `translate`, `translateX/Y`, `scale`, `scaleX/Y`, `rotate`, `skew`, `skewX/Y`. It accepts SVG's attribute grammar, with unitless numbers, commas, and `rotate(a cx cy)`, as its presentation attribute. Other rows: `transform-origin` (initial `0 0` for SVG elements), and `transform-box` (`view-box` initial; `fill-box`, `stroke-box`, `content-box`, `border-box`). The individual `translate`, `rotate` and `scale` rows also apply to SVG elements, as CSS applies them.
- **Composition** (CSS Transforms 2 §6.1): `translate(origin) · translate · rotate · scale · transform · translate(−origin)`, in the element's user space. `fill-box` makes the origin relative to the object bounding box, so `transform-origin: center` with `transform-box: fill-box` spins an icon about its own middle.
- **`transform` on HTML boxes** is deferred, not refused (§8 ruling 3: "i think we will want it in the future"). Boxes have the individual properties. A general `transform` on boxes is its own consumer and its own row semantics, including hit testing and layout overflow. Until a consumer takes it, Contract refuses `transform` on a box, by name, and points at `translate`/`rotate`/`scale`.
- **Hosts.**
  - Web: CSS, so the browser.
  - Apple: each transformed item becomes a pair of layers. The outer layer carries the individual transform properties, with `anchorPoint` at the origin, so Core Animation's `transform.translation`, `transform.rotation.z` and `transform.scale` key paths animate them. The inner layer carries the static `transform` matrix.
  - Linux: one affine per item.
- **`vector-effect: non-scaling-stroke`** (SVG 2 §13.8): the stroke is drawn in the host coordinate space. The resolver sends that item's path already transformed to the `svg`'s pixel space, with the stroke width unscaled. This is the sparkline idiom with `preserveAspectRatio="none"`.

### D6. Colour animation and transition

- **Properties.** `Property` gains `Color`, `BackgroundColor`, `Fill`, `Stroke`, `StopColor` and `FloodColor`. `Value` grows to four components. Colours interpolate in premultiplied sRGB, which is what CSS Color 4 §12.3 says for legacy colour syntax and what Chrome does for hex and `rgb()`.
- **Paint interpolation.** `fill` and `stroke` interpolate only between two colours, with `currentcolor` resolved to the used colour at sampling. `none` and servers switch discretely at 50%, as CSS does for a non-interpolable pair.
- **`light-dark()`** resolves to the current scheme's colour before interpolation. A scheme change during an animation re-resolves both endpoints.
- **Hosts.**
  - Web: CSS, as for every property.
  - Apple: `background-color` on a box lowers to Core Animation `backgroundColor` on its layer. `fill` and `stroke` on a shape lower to the `CAShapeLayer`'s `fillColor`/`strokeColor`, or to the gradient layer's opacity when a server is involved. `color` on a text leaf is sampled by the engine, and the paragraph re-rasters per sampled frame. This is the one colour property whose pixels Core Text bakes. A re-raster of one short label is well under a millisecond. The tint alternative (the glyphs as an alpha mask over an animated colour layer) is owed if the benchmark shows the cost. An animated `color` that reaches `currentcolor` paint in an `svg` is sampled for those shapes.
  - Linux: sampled by the engine, as every property is.
- **The benchmark.** The price flash is a keyed animation: `keyframes flashUp from color="#16a34a" to color="#000000"`, set on the price text, restarted by a new key per tick. That is `~/bench/cryptobench/exact-svg2`.

### D7. Paint servers

- **`linearGradient`, `radialGradient` and `stop`.** Attributes: `x1`/`y1`/`x2`/`y2`; `cx`/`cy`/`r`/`fx`/`fy`/`fr`; `gradientUnits` (`objectBoundingBox` initial, `userSpaceOnUse`); `gradientTransform`; `spreadMethod` (`pad`, `reflect`, `repeat`); `href` to inherit attributes and stops from another gradient (SVG 2 §14.2.3); `stop` `offset` (a number or a percentage). `stop-color` and `stop-opacity` are CSS rows, not inherited. Stop offsets are clamped monotonic, as SVG 2 says.
- **Object bounding box.** The bbox is computed in the resolver from geometry. It is the fill bbox, without stroke, as SVG 2 §8.10 defines. A zero-width or zero-height bbox makes an `objectBoundingBox` server render as the fallback, or as none: Chrome draws nothing for it.
- **`pattern`.** Attributes: `x`, `y`, `width`, `height`, `patternUnits`, `patternContentUnits`, `viewBox`, `preserveAspectRatio`, `patternTransform`, `href`. The tile is rendered as an island (D2) at device scale times the transform's scale. It is then tiled: a pattern image on Apple's content layer, and an image brush or pattern shader on Linux.
- **`paint-order`** (`normal`, or any order of `fill`, `stroke`, `markers`): the resolver orders an item's paint layers.
- **Apple spread methods.** `CGGradient` pads only. `reflect` and `repeat` are drawn by repeating the stop list across the bbox's extent in gradient space. That is exact, because the stops are piecewise linear.

### D8. `defs`, `symbol`, `use`: the shadow-tree semantics that matter

- **`defs`** and **`symbol`** never render directly. `symbol` renders only through `use`, with its `viewBox`, `preserveAspectRatio`, `x`, `y`, `width` and `height` (SVG 2 §5.5).
- **`use`** renders an instance of its target, translated by `x`/`y`. A `symbol` or `svg` target takes the `use`'s `width` and `height`, defaulting to 100%. The rules that matter:
  - **Inheritance.** The instance inherits from the `use`, not from the target's parent. This is what makes `fill="currentcolor"` icons take each use's colour.
  - **Own rows.** The target's own rows (and its class rows) still apply to it. Contract has no selectors, so none can match into the instance.
  - **Liveness.** A change to the target re-renders every instance.
  - **Events** on an instance go to the `use` element: it is the event target, as the shadow tree's retargeting makes it.
  - **Animations** on the target run on each instance, with each instance's own start: the instance is created when the `use` is.
  - **Cross-`svg` references.** An icon sprite (`svg` holding a `defs` of `symbol`s, `use`d from other `svg`s) resolves through the document index (D3).
- **Not in the scene.** Instances are not kernel nodes. They exist in the resolved scene only, so the kernel's tree stays the authored tree. On the web, `use` is native and the browser builds the shadow tree.

### D9. `marker`

`marker-start`, `marker-mid`, `marker-end` and the `marker` shorthand are inherited rows. A `marker` element takes `markerWidth`, `markerHeight` (3 initial), `refX`, `refY`, `orient` (`auto`, `auto-start-reverse`, or an angle), `markerUnits` (`strokeWidth` initial), `viewBox` and `preserveAspectRatio`. Vertices and their directions come from the resolved path, per SVG 2 §13.9's vertex rules, including the bisector at mid vertices and the direction at a closed subpath's start. Each marker is an instance, like `use`, painted after the shape's fill and stroke, unless `paint-order` says otherwise. `context-fill` and `context-stroke` in a marker take the referencing shape's paint. On `path`, `line`, `polyline` and `polygon` only.

### D10. `clipPath` and `mask`

- **`clipPath`.** Attributes: `clipPathUnits`, and children that are shapes, `text` or `use`. `clip-rule` is an inherited row. `clip-path` on an SVG element takes `url(#…)` or a CSS basic shape. The existing `clip_path` row's grammar grows `url()`, the basic shapes and a geometry box, whose default `border-box` is the `fill-box` of an element without a CSS layout box (r2: never `transform-box`). `clipPathUnits` defaults to `userSpaceOnUse`. Clip children union, each with its own `clip-rule`. A `clip-path` on the `clipPath` itself intersects, as SVG 2 §14.3.5 says. Hosts:
  - Web: native.
  - Apple: a `CAShapeLayer` mask per clip child in a mask container layer, opaque fill, the clip rule as its fill rule. The children union.
  - Linux: the children unioned into one coverage mask, never successive clip pushes (which intersect).
- **`mask`.** Attributes: `maskUnits` (`objectBoundingBox`; region −10%/−10%/120%/120%), `maskContentUnits`, `x`/`y`/`width`/`height`. `mask-type` is a row: `luminance` (initial) or `alpha`. The mask's content is rendered as an island. For `luminance`, the island computes luminance with CSS Masking's coefficients (0.2126, 0.7152, 0.0722), applied once, to premultiplied RGB (r2). Hosts:
  - Apple: the result is the contents of the masked item's `CALayer.mask`.
  - Linux: tiny-skia's `Mask` of type luminance or alpha.
  - vello: the GPU painter composites the masked subtree as an island too (vello has no luminance mask).
- **CSS `mask` properties beyond `mask: url(#…)`** (`mask-image` with gradients, `mask-size`, `mask-repeat`, `mask-composite`) are HTML-box features. They are refused on SVG elements, by name.

### D11. Text: `text`, `tspan`, `textPath`

- **Positioning.** `x`, `y`, `dx`, `dy` and `rotate` are lists, applied per character (per addressable character, SVG 2 §11.4). `text-anchor` (`start`, `middle`, `end`) is applied per text chunk. `dominant-baseline` takes `auto`, `alphabetic`, `middle`, `central`, `hanging`, `text-top`, `text-bottom`, `ideographic` and `mathematical`; `alignment-baseline` and `baseline-shift` take the same set on `tspan`. `textLength` and `lengthAdjust` (`spacing`, `spacingAndGlyphs`) are supported. So are `letter-spacing`, `word-spacing` and `white-space` (SVG 2 uses CSS `white-space`; `xml:space` is accepted as its legacy alias). The font rows already exist and are inherited.
- **Text content.** Contract's `text` inside an `svg` is the SVG `text` element. Its string children and `tspan`s are its content, the same inline-run model boxes use (a `text` with runs). A `tspan` takes paint, font and positioning.
- **Shaping is the host's.** Only the host has the fonts.
  - Web: native.
  - Apple: the resolver sends each text chunk (string, font descriptor, positioning lists, anchor, baseline) in the scene. Swift shapes it with Core Text, using the same font resolution as boxes (LLP 1019). It turns glyphs into one `CGPath` per chunk (`CTFontCreatePathForGlyph`), placed per the positioning lists, and gives the path to a `CAShapeLayer`. Fill, stroke, dashes, gradients and clips then apply to text as to any shape.
  - Linux: the same through cosmic-text shaping and swash outlines into `svg_path`.
  - Both native hosts report each chunk's advance to the resolver, for `text-anchor` and for hit testing and the bbox. The advance is measured the way boxes' text is measured, through the kernel's `TextMeasurer`, so the scene stays one pass.
- **`textPath`** (`href` to a `path`, or the `path` attribute; `startOffset` as a length or a percentage; `side`; `method="align"`; `spacing="exact"`): glyphs are placed along the referenced path's arc length. Each glyph's midpoint sits on the path, rotated to the tangent. Glyphs off either end are not rendered (SVG 2 §11.8.3). The path's arc-length table comes from the resolver.
- **Accessibility.** The text is exposed as the `svg`'s accessible text in document order, unless the `svg` has a label.
- **Refused:** vertical text (`writing-mode: vertical-*` on SVG text), `glyph-orientation-*`, SVG fonts, and `method="stretch"`.

### D12. `image` inside SVG

`href` (a URL, as boxes' `imageSource` takes one), `x`, `y`, `width`, `height` (rows; `auto` takes the image's intrinsic size), `preserveAspectRatio` (initial `xMidYMid meet`; the image's ratio is fitted into the viewport and clipped to it). Hosts reuse their image pipelines (LLP 1011): decode, cache and failure behaviour are the same as `<img>`. On Apple, a `CALayer` with the decoded image as contents, `contentsGravity` and a clip. On Linux, the backend's image draw. An SVG image as the source (`href` to an `.svg` file) is refused in v1. It is a second document with its own resolver input, and no consumer has one.

### D13. `foreignObject`: the web's now, deferred on native (§8 ruling 5)

HTML inside SVG puts boxes (views, with layout, text input, focus and native controls) under an SVG transform, clip, mask or filter. On the web that is free. On native hosts it would make every SVG ancestor a view, or render native views into an island's pixels, which breaks their interaction. No chart, icon or illustration needs it: the pattern is to position a box over the `svg`, which is also what React Native SVG users do. r2: `foreignObject` is deferred, not refused forever (Astra: HTML labels in diagrams are a real use; a box subtree under a native container inside the scene is a design, not an impossibility). It is refused by name until that design exists, and the error names the positioned-box pattern.

**Ruling (2026-09-27).** Charlie: "our general philosophy should be allow platforms to reach their full platform rather than sanding everything down to lowest common denominator." So the web does not wait for native. The web host emits `foreignObject` (`x`, `y`, `width`, `height`) with its box children as real HTML inside, through the web host's normal path for boxes. On native hosts the tag is refused by name at run time, where the host meets it, and the error names the positioned-box pattern. The Contract compiler cannot refuse it at compile time, because one plan serves every host. The carve-out is recorded in `rules/NOT-DOING.md` under "SVG, complete".

### D14. Filters

- **Elements.** `filter` with `x`/`y`/`width`/`height` (region initial −10%/−10%/120%/120%), `filterUnits`, `primitiveUnits`, `color-interpolation-filters` (`linearRGB` initial, and `sRGB`). The primitives, in stage order:
  - **Stage 9a (the common set):** `feGaussianBlur` (`stdDeviation` x/y, `edgeMode` none), `feOffset`, `feFlood` (`flood-color`, `flood-opacity` as rows), `feComposite` (`over`, `in`, `out`, `atop`, `xor`, `arithmetic`), `feMerge`/`feMergeNode`, `feColorMatrix` (`matrix`, `saturate`, `hueRotate`, `luminanceToAlpha`), `feDropShadow`, and `feBlend` (the separable modes).
  - **Stage 9b:** `feMorphology`, `feComponentTransfer` (`table`, `discrete`, `linear`, `gamma`), `feTile`, `feImage` (a reference to an element only), `feTurbulence`, `feDisplacementMap`, and `feConvolveMatrix`.
  - **Stage 9c:** the lighting primitives (`feDiffuseLighting`, `feSpecularLighting` and their lights). They are last because no chart or icon uses them.
- **Inputs and regions.** `in`/`in2` take `SourceGraphic`, `SourceAlpha`, named results and the previous result. `BackgroundImage` is deprecated and refused. Each primitive has its own subregion.
- **CSS `filter` functions on SVG elements** (`blur()`, `drop-shadow()`, `brightness()`, `contrast()`, `grayscale()`, `hue-rotate()`, `invert()`, `opacity()`, `saturate()`, `sepia()`) lower to the equivalent primitive chains, as Filter Effects 1 §12 defines them.
- **Implementation.** `exact-svg-raster` (§3) holds the primitives as pure functions over a premultiplied RGBA buffer with a pixel-to-user transform, shared by both native hosts. The Gaussian blur is three box blurs when σ ≥ 2.0, as the spec's approximation and Chrome do, and a true kernel below that. Colour-space conversion to linearRGB and back is done once per filter, not per primitive.
- **Hosts.**
  - Web: native.
  - Apple and Linux: islands (D2). The filtered subtree renders at device scale into the filter region, runs the chain, and composites. An animation under a filter is sampled while it runs.
- **Dependencies.** The primitives are ours, about 1,000 lines across primitives. That is less than a dependency on resvg's filter crate, which would also drag its own tree types.

### D15. Animation beyond `opacity`, `stroke-dashoffset` and `r`

- **Transform animation on SVG elements:** `translate`, `rotate`, `scale` (D5). On Apple, lowered to the outer layer's key paths. Elsewhere, sampled.
- **Geometry.** `cx`, `cy`, `r`, `x`, `y`, `width`, `height`, `rx` and `ry` interpolate as lengths. `d` interpolates when both paths have the same command list after normalization to absolute commands (CSS Shapes / SVG Paths: otherwise discrete). `Value` does not grow to a path. A `d` animation holds its keyframe paths in the row (the same `animations` codec with a path payload), and interpolation is per coordinate.
  - Apple: `d` lowers to Core Animation's `path` key path, which interpolates matched paths natively. `x`/`y`/`cx`/`cy` on a shape without a transform lower to `position`. Everything else is sampled, and the scene is re-sent per frame only for the changed items.
  - `points` is not a CSS property. It animates only through SMIL (D16).
- **Islands.** Anything inside an island (mask content, pattern tile, filter input) is sampled, and the island re-renders per frame while the animation runs. This is declared: an animated blur costs a filter pass per frame on native.
- **Inherited animated values** (LLP 1055 §0's limit) flow down in the resolver: an animated `stroke-dashoffset` or `color` on a `g` reaches the shapes that inherit it. When the ancestor's animation is lowered, the same spec is attached to each inheriting descendant's layer.
- **`display: none`** on an animated node or its ancestor cancels its animations on native hosts, as on the web. Showing it again starts them anew (CSS Animations 1 §3). This replaces LLP 1055 §0's limit.

### D16. SMIL: native on the web, a defined subset lowered on native hosts (§8 ruling 2)

*Ruled (Charlie, 2026-09-27, §8 ruling 2: "new rec for SMIL seems good").* The web runs real SMIL natively (all of it, held, seeked and settled by the agent clock through `pauseAnimations()`/`setCurrentTime()`). Native hosts get the subset below, lowered to CSS animations and refused by name beyond it. Parity for the subset is measured against Chrome's own SMIL. The r2 text below is the native subset; its "on every host, the web included" and the declared deviations about the web's DOM no longer apply to the web.


Chrome runs SMIL (`animate`, `set`, `animateTransform`, `animateMotion`), and icon sets and illustration tools export it. One mechanism on every host matters more than executing SMIL natively on the web (LLP 1002: one engine, the browser as oracle). Contract lowers **a stated subset** of SMIL into its target's `animation` row plus a synthesized `keyframes` rule. Anything outside the subset is refused by name.

| SMIL | Lowered to |
|---|---|
| `attributeName` naming a row this schema can animate | that row; a non-row target (`points`, stop `offset`, `viewBox`, filter parameters) is refused by name until a row or an attribute track exists |
| `values`, or `from`/`to` | keyframes; `to` alone omits the 0% keyframe, so it starts from the live underlying value (the engine already fills missing endpoints live) |
| `by` alone, `from`+`by` | refused in the subset (additive), except on `animateTransform` below |
| `keyTimes` | offsets; omitted, the values are evenly spaced |
| `calcMode` (default `linear`; `paced` for `animateMotion`) | `linear`; `spline` → per-interval `cubic-bezier` from `keySplines`; `discrete` → each value holds for its own interval (n values without `keyTimes` each hold 1/n), as step holds; `paced` → offsets from literal value distances, and refused when a value is computed |
| `dur`, `repeatCount` (`indefinite`), `repeatDur` | duration; iteration count, `min(repeatCount, repeatDur/dur)` when both are given |
| `begin` (one clock offset) | delay, negative allowed; a list, an event, a syncbase or `end` is refused whole |
| `fill="freeze"` / `remove` | `forwards` / `none` |
| `set` | a value held for the active duration (hold keyframes at 0% and 100%), pinned against Chrome |
| `animateTransform type=translate/scale/rotate/skewX/skewY` | the `transform` row; `rotate`'s centre is interpolated as its own numbers; `additive="sum"` post-multiplies onto the element's own list (the animated function applies in local space, before the base transform), pinned with `getCTM()`; several on one element are precomposed into one keyframe list in document order |
| `animateMotion` (`path`, `mpath`, `rotate="auto"`/`auto-reverse`/angle) | CSS `offset-path`, `offset-distance`, `offset-rotate` with `offset-anchor: 0 0` (SMIL moves the user-space origin, not the centre); `mpath` includes the referenced path's transform; `keyPoints` are baked into the `offset-distance` keyframes |

**Refused, by name:** event and syncbase timing (`click`, `a.end+1s`, `accessKey`, `wallclock`), `end`, begin lists, `restart`, `min`/`max`, `accumulate="sum"`, and additive animation outside `animateTransform`.

**Declared deviations:**
- The web's DOM holds CSS animations, not SMIL elements. No app JS reads `SVGAnimationElement`.
- SMIL's timeline starts at the element's insertion, not at document load, as CSS animations do (LLP 1055 D9).
- The claim that the pixels match Chrome's SMIL has its own oracle. A gallery page shows the authored SMIL raw in Chrome, beside the lowered page, and the smoke compares the two.

**Recorded alternative (Astra):** run native SMIL on the web (seeking with `pauseAnimations()`/`setCurrentTime()`) and implement the admitted SMIL model in the engine for native hosts. That is two executors for one feature, and it is not taken.

### D17. Interaction and accessibility

- **`pointer-events`** is an inherited row: `auto` (= `visiblePainted`), `none`, `visiblePainted`, `visibleFill`, `visibleStroke`, `visible`, `painted`, `fill`, `stroke`, `all`, `bounding-box`, with SVG 2's meaning. `visibility` (`visible`, `hidden`, `collapse`) becomes an inherited row that SVG elements honour, as CSS does.
- **Handlers on SVG elements** (`press`, `hover`, and every pointer handler boxes take) are admitted. The `svg` stays the one native view. On a native host, a pointer event in the `svg` asks the kernel's `svg::hit(svg, point)`. It walks the resolved scene in reverse paint order. For each item it tests the fill (winding rule, in the item's inverse transform) and the stroke. r2: the stroke is tested against its outline, with caps, joins, the miter limit and dashes, in the non-scaling space when `vector-effect` says so. It honours `pointer-events`, visibility and clips. Masks, filters and `opacity: 0` do not change hits. Content outside the `svg`'s box is hit only when the `svg` does not clip. It returns the element, or the `use` element for an instance. The host then dispatches to that element's view id. Bubbling follows the kernel's tree, as it does for boxes. The web is native.
- **Hover** on native: passive pointer tracking (a mouse on macOS; iOS has no hover) re-runs `hit` and sends enter and leave per element. It never takes a gesture from a scroll view.
- **Accessibility.**
  - A `title` child is the element's accessible name, and `desc` its description (SVG 2 §5.9, SVG-AAM).
  - `role`, `aria-label`, `aria-hidden` and `tabindex` on SVG elements map as they do on boxes.
  - An element with a handler, or an explicit `role`, becomes an accessibility element with its bbox as the frame: on Apple, a `UIAccessibilityElement` (or an `NSAccessibilityElement` on macOS) under the `svg`'s view. Elements without either are presentational, and the `svg` is one image whose label is its own `title`, `aria-label`, or else nothing.
  - `title` is not a tooltip on native hosts (the web shows one). This is declared: native has no hover tooltip on touch, and a macOS tooltip is owed.
- **`a` inside SVG** is a `g` with `href`: a link, with the box `a`'s navigation and hit-testing semantics. It is in this stage.

### D18. Animation events

`animationstart`, `animationiteration`, `animationend` and `animationcancel` handlers (Contract `animationend=action`) are admitted on any node.
- Web: native events.
- Native: the engine reports phase changes when it is advanced. A lowered animation's phases are known in closed form from its start, so the host schedules a timer for the next boundary. It never polls. Iteration events on an infinite animation fire once per period, and only while a handler is registered: an unhandled infinite pulse never wakes the app.

Cheap enough to take in stage 11.

### D19. Styling: `class=`, `currentColor`, and what else CSS brings

- **`class=`** on SVG elements is admitted. A style set's rows apply if they apply to the element, and any other row is a compile error naming it.
- **`currentcolor`** is accepted wherever a colour is: `fill`, `stroke`, `stop-color`, `flood-color`, `lighting-color`, and the fallback of a `url()` paint. It resolves to the element's computed `color`, and in a `use` instance, to the instance's inherited `color`.
- **`display: none`** on an SVG element removes it and its subtree from rendering. `visibility: hidden` hides an element, but its visible descendants still render, as CSS says.
- **`mix-blend-mode`** and **`isolation`** on SVG elements:
  - Web: native.
  - Apple: `CALayer.compositingFilter` on macOS; on iOS, an island (no public blend on `CALayer`).
  - Linux: vello `Mix` / tiny-skia `BlendMode`.
  
  Stage 10 takes these.

## 3. What each host needs, summarized

- **Kernel:** the resolver, lengths, references and index, bbox, markers' vertices, and `hit`. No pixels.
- **The island rasterizer's home** (amended by §8 ruling 4 and §0's stage 8: `exact-svg-raster` holds only the pixel work, a loaded module on Apple; Core Animation rasterizes Apple's islands, so tiny-skia stays off Apple). r2's text: tiny-skia is already a dependency of the Linux host. On Apple it is not. The islands live in a new crate, `exact-svg-raster` (tiny-skia plus the filter primitives), linked by the Apple and Linux hosts. The kernel stays dependency-free, and the web links nothing new (LLP 1047). The Apple host already links Rust, so an island is one FFI call returning a premultiplied bitmap for a `CGImage`.
- **Apple Swift:** `SvgScene.swift` grows content layers (gradients), a mask container (clips), transform layer pairs, text shaping, island images, and accessibility elements. It stays one file per concern: `SvgPaint.swift` (servers) and `SvgText.swift` (glyphs) join it, each ≤ 1,500 lines.
- **Linux:** `paint/svg.rs` becomes a consumer of the scene. `Backend` gains gradient brushes, image brushes and masks.
- **Web:** new tags in the SVG namespace, id rewriting, the new CSS rows, and nothing per frame.

## 5. Verification

- **Kernel unit tests:** lengths and units, the resolver's inheritance through `use`, reference resolution order and cycles, bbox, transform composition against Chrome's `getCTM()`, marker vertices, `hit` against Chrome's `elementFromPoint` on the gallery, gradient spread expansion, and filter primitives against Chrome pixels on small fixed inputs.
- **Motion:** colour interpolation samples pinned to Chrome's `getComputedStyle` at a paused `currentTime`, as LLP 1055 pinned the timing model. The same for transform and geometry.
- **Contract:** every new tag and attribute, the SMIL lowering table (each row one test), and each refusal.
- **Parity smoke (`bun scripts/smoke.mjs svg`).** It turns LLP 1055's hand comparison (QUEUE) into a smoke. The web renders `apps/svg-gallery` in Chrome as the reference. Each native host renders the same frozen pages. The smoke then crops each fixture by its layout box, registers it within ±20 px, and reports mean |Δ| and the share of pixels off by more than 32, per fixture and host. The thresholds are LLP 1055's measured residue (antialiasing and Chrome's 1× raster): mean ≤ 4/255 and ≤ 6% off per fixture. A fixture beyond them fails with its crop pair written out. r2: registration is ±3 px, not ±20, so a placement error cannot hide. Stage 1 registers at 0,0 everywhere. Text and blur are judged by numeric fixtures (advances, baselines, bboxes, σ) with their own stated tolerances, not by this threshold. The smoke is async-lane apparatus (it drives four hosts), not a sixth blocking check.
- **XCTest:** the Apple layer tree for each stage (content layers, masks, transform pairs, accessibility elements), and paused-layer presentation for each lowered property.

## 6. Costs

- **Rows.** Roughly 30 new style rows across the stages (geometry 4, transform 3, `vector-effect`, `paint-order`, stops 2, markers 3, `clip-rule`, `mask-type`, text 5, `pointer-events`, `visibility`, flood 2, `color-interpolation-filters`, offset 3, blend 2), and about 40 props. The mask grows from two words to three.
- **Size.**
  - Web wasm: grows by the resolver's reference index and the new codecs only. The web paints nothing itself.
  - Apple: grows by the resolver, `exact-svg-raster` and tiny-skia (about 0.4 MB, measured before stage 8 lands; if it matters, it becomes a capability module per LLP 1047).
  - Linux: already links tiny-skia.

- **Per-frame work for sampled animations inside islands** (D15), declared.

## 7. What this refuses

Permanent, each by name with its reason:
- `script` and `style` elements inside `svg`: there is no app JS, and Contract has no selectors; its `style` sets are the stylesheet;
- SVG fonts;
- `cursor` elements;
- `BackgroundImage` / `enable-background`;
- event and syncbase SMIL timing (D16);
- `vector-effect` values other than `none` and `non-scaling-stroke`, which SVG 2 marks at risk and Chrome does not ship;
- `hatch`, `hatchpath`, `mesh`, `meshgradient` and `solidcolor`, which Chrome does not implement (r2);
- external references (`url(other.svg#id)`, `href` into another file) (r2);
- 3D transform functions on SVG elements (`matrix3d`, `rotateX`/`rotateY`, `perspective`): one affine per item is the model (r2).

Until a consumer needs them:
- `foreignObject` on native hosts (D13; the web emits it, §8 ruling 5);
- `switch` and conditional processing (`systemLanguage`, `requiredExtensions`), `view` and fragment views; `metadata` is accepted and never painted (r2);
- iOS `mix-blend-mode` (§0);
- `em`, `rem`, `ex`, `ch`, `vw`, `vh` and other relative lengths, and percentages on `stroke-width` and dashes;

- `textPath` `method="stretch"`;
- an SVG file as an `image` source;
- CSS `mask-*` longhands on SVG elements;
- `transform` on HTML boxes (deferred, not refused: §8 ruling 3);
- `restart`, `min`/`max`, `accumulate`.

## 8. Rulings (Charlie, 2026-09-27)

The six questions r2 asked, as Charlie answered them. Each ruling replaces the question it answers, and the decisions above are amended to match.

1. **Duplicate ids (D3): accepted as recommended.** With duplicate ids, the target nearest the reference in the tree wins, and the web host rewrites ids so the page shows that choice. With unique ids, this is exactly the web's resolution. Built in stage 3.
2. **SMIL (D16): accepted, as re-proposed.** Charlie: "new rec for SMIL seems good." It replaces r2's "lower everywhere", in the same spirit as `foreignObject` (ruling 5):
   - **Web:** the browser runs real SMIL natively, all of it, not a subset. SMIL is wired into the agent clock through `SVGSVGElement.pauseAnimations()` and `setCurrentTime()`, so `clock` holds, seeks and settles it as it does CSS animations.
   - **Native hosts:** D16's stated subset, lowered at compile time to CSS animations, and refused by name beyond it.
   - **Parity:** the subset is measured against Chrome's own SMIL (the raw SMIL page in Chrome against the native host), not against a lowered web page.
   
   Stage 11 keeps its place after stages 8–10.
3. **`transform` on HTML boxes (D5): deferred, not refused.** Charlie: "i think we will want it in the future." Contract still refuses it on a box by name, pointing at `translate`/`rotate`/`scale`, until a consumer takes it. It is owed, not out (`QUEUE.md`).
4. **The island rasterizer (§3): accepted, as a loaded capability.** Charlie: "0.4MB matters when we considered embedding, so let's proactively move it into a separately loaded module." The island code is an optional capability, loaded on demand the first time an island needs it (LLP 1047 D1's loaded tier, as LLP 1009's GPU module is), and never linked into the core host. §0 (stage 8 as built) records the module, what an island shows while it loads, and the size measured before and after.
5. **`foreignObject` (D13): deferred on native, allowed on the web now.** Charlie: "our general philosophy should be allow platforms to reach their full platform rather than sanding everything down to lowest common denominator." The web host emits `foreignObject` with real HTML inside. The boxes inside go through the web host's normal path. On native hosts it is refused by name, and the error names the positioned-box pattern. `rules/NOT-DOING.md` records the carve-out under "SVG, complete".
6. **iOS `mix-blend-mode` (§0): accepted as recommended.** It is declared unsupported on iOS until a backdrop-owning design exists. The web, macOS and Linux take it in stage 10.

## Addendum (2026-09-27): the grnl branch's `path` node, folded in

A branch porting grnl built its own vector primitive in parallel, LLP 1065:
a `path` node (SVG's `<svg viewBox><path d>` as one box) with `stroke-start`
and `stroke-end` fractions for a pen-order draw, `marker` declarations and
paths of paths. When the branches merged, this RFC's SVG stood and that node
was removed with its rows, props, codecs (`paint` kept as main's, `marker`
gone), hosts' views and tests; its file is deleted. What it carried, and
where it lives now:

- **Pen-order drawing.** One `path` per stroke, each drawn by
  `pathLength="1"` and `stroke-dasharray="1"` with `stroke-dashoffset`
  animated from 1 to 0 (LLP 1055 D6; lowered to Core Animation on Apple),
  staggered by `animation-delay` for pen order. What
  is lost: one fraction along a whole multi-subpath `d` in subpath order;
  an author splits the mark into one `path` per subpath.
- **Paint motion on `fill` and `stroke`,** `light-dark()` pairs and springs
  included: D6 and LLP 1062 D3/D9, one colour path for boxes and shapes.
- **Non-scaling strokes:** D4's `vector-effect`.
- **Full path grammar for `clip-path`** (its D8): CSS's
  `path([nonzero | evenodd,] "<data>")` now parses its data with this RFC's
  parser (`svg::parse_d_whole`, refused whole on any error, as CSS refuses
  the declaration) and carries the fill rule to every host: Apple's mask and
  hit test, Linux's tiny-skia and Vello clips, the web's CSS text. Main's
  clip took absolute `M L Q C Z` only.
- **A zero-length subpath is a dot** (its D9): SVG 2 §13.4.7, `M p Z` or
  `M p L p` under round or square caps paints the cap. Held on Linux's CPU
  painter (`host/linux/tests/it/svg.rs`); the branch's rule for dots under
  its trim has no counterpart, since there is no trim.
- **Markers:** D9's `marker` element; the branch's file-level `marker`
  declaration is gone.

Dropped with no counterpart: `stroke-start`/`stroke-end` (not CSS; SVG
spells the effect with dashes), the trim-reveals-dashes rule (its D10), and
`path` with no `svg` around it.
