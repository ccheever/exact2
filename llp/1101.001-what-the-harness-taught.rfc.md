## Summary

The second terminal consumer is a coding agent. That is the kind of app
everyone builds for terminals now, and the hardest kind for a terminal UI
to get right. It was built on the spike in a day:

- a Contract screen of 380 lines (`apps/harness/terminal.contract`);
- a Rust data module (`apps/harness/data`, 40 tests);
- providers for Anthropic, OpenAI, OpenRouter (the picker shows its live
  catalog), Ollama, and a scripted offline model;
- tools that read, list, grep, run shell commands and edit files, asking
  before anything that changes the machine;
- stress commands for art, images, Unicode, and eleven animations.

Charlie ran it and found it better than most harnesses he has used. The
reason is structural, and it is LLP 1101 D10. Settled transcript entries
are printed once into the terminal's own scrollback, and only the live
tail is redrawn, so scrolling, selection, copy and tmux belong to the
terminal. Those are the properties Charlie named where other harnesses
fail.

Both reviewers agreed that is the result to build on. They also agreed
that r1's plan aimed its biggest item at the wrong layer. r1 proposed
freezing printed history inside layout. History, though, lives in three
places:

- the data module's snapshot, rebuilt on every push;
- the view, which mounts every entry;
- the kernel tree.

A layout freeze touches only the third. So r2's center is **settle
finely, then retire**:

- The data module settles a reply block by block while it streams.
- The host tells the app, through the runner's existing host-record
  source, which entries it has printed.
- The app stops carrying printed entries in its snapshot and view.

The kernel tree is then about a screen tall however long the session
runs.

Around that, r2 puts the fixes the reviewers found more urgent than r1's
list:

- arrow keys that move the caret in a multi-line prompt;
- approvals that a typed-ahead key cannot answer;
- prompts kept, not dropped, while the agent is busy;
- tool output and cancellation with real bounds;
- a live-region diff that leaves a selection alone;
- a dialog an action can open.

## 1. What held

- **Inline mode (LLP 1101 D10) is the product.** The rule: a
  `role="log"` node's children before its first `aria-busy` child are
  printed once and never repainted, and everything below them is the live
  region. That was enough for a streamed transcript with tool calls,
  approvals and animations.
  - *Through a VT emulator:* a recording replayed through `vt100`
    (`host/terminal/examples/replay.rs`) kept 4,133 intact scrollback rows
    after `/stress 300`. The count is from that run's output; the tool
    prints it and does not store it.
  - *In tmux 3.7:* the whole transcript was in tmux's own history, the
    approval key worked, and the screen survived a resize to 50×20.
- **The push path (LLP 1016.002) is the right way to report long work.**
  - The data module's own threads stream HTTP and run child processes,
    then call `Native::changed("session")`. The runner asks `session()`
    again and gets the text so far.
  - Coalescing the announcements loses nothing, because the snapshot
    holds everything.
  - The host needed no request executor: a socket to wake its loop, and
    `apply_announced()`.
- **The vocabulary held again.**
  - Everything is ordinary tags and CSS in `ch`/`lh`: markdown blocks,
    tool entries with a `⎿` gutter, an approval box, a model dialog, a
    completion list, a password field, a status line.
  - The one new thing the host had to understand was `aria-busy`. It was
    in the schema but never lowered, and now it is.
- **Keys as on the web.** A `key` handler runs first, and the default
  runs unless the handler called `preventDefault()`. That is how the
  prompt takes Enter, Shift+Enter, Tab, the history arrows and Ctrl-C.
  The compiler's `lower-handler-tag` diagnostic taught the pattern.
- **A shared shapes file is a good seam.** `shapes.contract` came first.
  A sub-agent then built the data module against it in parallel, and the
  runner's boot-time shape check would have caught any drift.
- **Text-first verification.** The headless verbs, the VT replay, and
  `.ans` screenshots rendered through a browser verified everything here.
  `analyze-call-stale-read` caught a real ordering bug before it ran.
- **Size and start.**
  - The release binary is 6.9 MB (3.5 MB gzipped) and links only
    `libSystem` and `libiconv`.
  - It prints its first frame in 10–30 ms, including compiling its entry.
    About 1 MB of the binary is that compiler, which is a development
    convenience (Q4).

## 2. Findings

Each finding has its evidence and, where one exists, the proposal (§3)
that answers it. Findings first raised by a reviewer say so.

**F1. History is carried in three places, every commit.**
- *The three places:*
  - `session()` builds a value for every entry on every push
    (`data/src/value.rs`).
  - The view mounts an `EntryView` per entry, and passes the 100 ms
    spinner `tick` into all of them, so every entry gets new props
    during a turn.
  - `after_commit` lays out the whole root and walks the tree for focus,
    `scrollFollowEnd` and images; the inline writer walks it once more
    for the transcript.
- *Measured after `/stress 300` (`host-dev` build):* 1–2 ms of layout per
  frame; resident memory 70 MB, against 12 MB at start. Charlie's longer
  session reached 166 MB.
- *Answered by:* P1.

**F2. Debug builds stall on long documents.**
- *Measured:* with the same frame, 0.5–2 s per layout in debug, against
  1–2 ms in `host-dev`.
- *What profiling shows:* `sample` points to no single debug-only check.
  The time is spread over Taffy's flexbox and the kernel's per-node
  bridge (style masks, copies), unoptimized.
- *Tried and reverted:* optimizing Taffy alone in the dev profile still
  left 500 ms frames.
- *Answered by:* P1 (lay out a screen, not a session); in the meantime the
  terminal host develops in `host-dev`, as `build.mjs` already does for
  Apple. This is a loop rule, not a kernel change.

**F3. The live region was repainted whole, and that destroyed selections.**
- *The bytes:* each frame cleared to the end of the screen and wrote every
  live row. Plasma at 80×30 is about 43 KB per frame. That cost is
  inherent, since every cell changes, and a spinner tick resent the whole
  tail.
- *The selection (Grok):* the erase also cleared any selection in the
  live region, such as in the approval box or the prompt, on every
  spinner tick.
- *Answered by:* P3 (built, §4).

**F4. ibex2's SSE streams drop messages.** That is right for latest-value
feeds and wrong for token deltas. The harness never used it for tokens:
it accumulates them below the seam and answers the text so far, so
coalescing is safe. *Answered by:* P4, as documentation only.

**F5. An action cannot open a dialog.** `/model` could not open the
picker; only the Ctrl-O invoker could. The `/key` box had to be a `when`
overlay without a dialog's focus trap. *Answered by:* P5.

**F6. (r1's "view branching nests without end" was wrong.)** `else when`
exists and is in the guide. A flat chain compiles; checked 2026-10-06
after both reviewers named it. The harness's nested `when`/`else`
pyramids were the author's. They are rewritten, and nothing is proposed.

**F7. Two CSS whitespace traps.**
- *Collapsed spaces:* a space at the start or end of its own `text`
  (`"› "`, `"  ⎿  "`) collapses away in a flex row.
- *Overflow:* `width: 100%` with borders and padding overflows under
  `content-box`. That one is already a candidate in
  `docs/agent-pitfalls.md`.
- *Answered by:* P7.

**F8. Small Contract gaps.**
- *Spinner frames:* a spinner's frame came from a split string. A list of
  frames plus `at` is the right spelling (Astra), so nothing is proposed.
- *`light-dark()`:* it must be a string. That belongs in the pitfalls.
- *Name collisions:* the guide already documents `syntax-call-ambiguous`
  for host-command names. A collision between an action and a
  data-module source wasn't tested.

**F9. `preventDefault` reaches the host as a command.** The first host
guessed from "did the tree change", which the signal replaced; the guess
is still computed in `dispatch` and is dead. *Answered by:* P9.

**F10. Terminal facts are invisible to the app.**
- *Colour depth:* it is assumed truecolour.
- *Image protocol:* chosen from environment variables, it is wrong in two
  cases (Grok). tmux always gets half-blocks, even over kitty with
  passthrough. WezTerm is classed as iTerm2.
- *Answered by:* P10.

**F11. Typed-ahead keys answered an approval.**
- *What happened:* in a pseudo-terminal run, keys typed before the
  approval appeared answered it twice:
  - the `n` of `/unicode` hit a "No" shortcut;
  - an Enter meant for the prompt pressed the autofocused "Yes" on a
    shell command nobody saw.
- *What the reviewers added:* a delay proves nothing about attention
  (Astra), and keys decoded in the same read as the event that opened
  the prompt arrive with no clock involved at all (Grok).
- *Answered by:* P11.

**F12. Images use a protocol only once settled.** In the live region, and
in full screen, they are half-blocks. *Answered by:* P12, waiting on P1.

**F13. The terminal's border rule was process-global.**
- The border rule was a one-way `AtomicBool`.
- The 8×16 cell is two constants, and both reviewers' readings land on
  keeping them: D3's "bake and run time resolve alike".
- *Answered by:* P13.

**F14. Process.** A sub-agent's crate joined the workspace before it
compiled, which broke every build for about ten minutes. Pixel checks
needed a detour through Chrome, and pseudo-terminal runs needed a
hand-made Python driver. *Answered by:* P14.

**F15. The prompt's vertical arrows left the field (Grok).**
- In the multi-line textarea, ArrowUp and ArrowDown fell through to focus
  traversal unless the app claimed them for history.
- So the caret could not move between lines, and focus left the prompt.
- Parent D6 says arrows belong to the focused field.
- *Answered by:* P15.

**F16. A rejected prompt was lost (Astra).** `sendText` cleared the draft
at once, and the data module refuses a prompt while a turn runs. *Answered
by:* P16.

**F17. Work outlived its cancellation (Astra).**
- *Shell output:* the shell tool read stdout with an unbounded
  `read_to_end` and capped it afterwards.
- *Shell cancellation:* cancelling killed the shell but not its
  descendants, and a background child holding stdout open could keep the
  reader waiting.
- *HTTP:* a cancelled stream's reader thread could stay blocked.
- *The test missing:* "the UI stopped showing the work" and "the work
  stopped" were not separately tested.
- *Answered by:* P17.

**F18. A long reply was one busy entry (both).**
- The live region shows its last screenful. Everything above is neither
  visible nor in scrollback until the reply ends.
- Every token re-parsed the whole accumulated Markdown.
- *Answered by:* P1's settling half.

**F19. "Printed" was a count of children, not their identity (Astra).**
- Replacing a prefix with another of equal length would go unnoticed.
- `aria-busy="false"` is not, in ARIA, a promise never to change again.
  Treating it as one is an Exact policy, and it should be stated as one.
- *Answered by:* P1's contract.

**F20. Resize trusts a cursor row the emulator has moved (Grok).** On a
width change the terminal reflows its scrollback, and the host's idea of
where its live region starts goes stale. *Answered by:* P18.

r1's P2 (hunt the debug cost), P6 (view branching) and P8 (string
access) are withdrawn: see F2, F6 and F8.

**P1 — Settle finely, then retire.** This is the change that makes a long
session cost what a short one does.

- **Settle finely (the data module).**
  - A streaming reply becomes a run of entries: one per finished Markdown
    block, and one busy tail.
  - A block is finished when the parser has begun a later top-level block
    and no fence or list is still open. A blank line alone is not enough;
    the producer decides.
  - Settled blocks print as they finish, so a long reply scrolls by in the
    terminal's own scrollback while it streams.
  - Only the tail is re-parsed per token.
- **Report what was printed (the host).**
  - The host writes `exactSurface("terminal")` through the runner's
    existing host record (`Runner::set_surface_record`). The record holds
    `printed`, the key of the last log child it has written to scrollback.
  - It keys children by identity, not by count.
- **Retire (the app).** The harness reads that record and sends
  `retire(id)`. The data module then stops answering entries through that
  id in `session()` (it keeps them for the model's history), and the view
  stops mounting them.
- **The contract**, stated as Exact policy rather than as ARIA's meaning:
  - In inline mode, a log child that is not `aria-busy` is final. Its
    identity is its key.
  - If the app changes it after it was printed, the change does not
    reach the screen.
  - If the app removes printed children and adds new ones (`/clear`),
    they are new.
  - The host never re-lays-out what it has printed.
- **Done when:** at `/stress 3000` with a spinner running, the tail's
  layout time and the kernel's retained node count are flat in history
  length, and resident memory grows only by the model history (which
  `State.history` keeps and the model needs).
- **What r1 recommended instead:** a host-side layout freeze. It is not
  needed once retirement exists. If a later profile says otherwise, the
  CSS name for it is `content-visibility` (Grok).

**P3 — A relative live-region diff (built).**
- When the region's height and width are unchanged and nothing new
  settled, the host writes only the changed cells. Its moves are relative
  to the region's top (down by rows, to a column), never absolute and
  never an erase.
- Otherwise it repaints the region whole.
- Its test is P14's replay: a spinner tick's bytes stay small and never
  include settled rows.

**P4 — The push path is the documented way to report long work.**
- A pitfalls paragraph: token deltas accumulate in the data module, and
  the resource answers the text so far. Coalescing is safe only for that
  shape.
- r1's bounded lossless queue is cut (both reviewers). It stays on
  ibex2's list for a consumer with events it cannot reproduce, and when
  it comes it needs byte bounds, ordered completion, and cancellation
  that unblocks the producer (Astra).

**P5 — Dialogs from actions.**
- `showModal(id)` opens `id` as a modal on the open stack and focuses its
  first `autofocus` or focusable descendant.
- `close(id)` closes it, gives back the focus it took, and fires its
  `close` handler.
- Bare `close()` stays quit (Grok: `close` already means that).
- `show(id)`, the non-modal form, waits until a host implements non-modal
  focus (Astra).
- In inline mode an open dialog is painted in the live region.

**P7 — The whitespace lint.**
- `lint-space-collapses` (a warning) fires when a literal leading or
  trailing space sits in a `text` whose `white-space` collapses and which
  is a flex item. It suggests `white-space="pre"` for meaningful spaces
  and `gap` for spacing between items.
- The box-model half implements the candidate already written in
  `docs/agent-pitfalls.md`, worded as "may overflow".

**P9 — `prevented` on the dispatch result.** The dispatch's own result
carries whether a handler called `preventDefault()`. It belongs to the
event, not to every commit (Astra). The host's tree-diff guess is
deleted.

**P10 — Terminal facts.**
- The host publishes `exactSurface("terminal")` = `{ mode, images,
  colors, printed }`: whether it runs inline or full screen, the image
  protocol in use, the colour depth, and P1's printed key. It is a host
  record, not a media feature; parent D5 already says the image protocol
  is not one.
- The harness shows `/image`'s real path.
- The `color` media fact (D5) and quantization follow when an app needs
  fewer than 24 bits.
- Image protocol detection fixes WezTerm (kitty) and honours
  `EXACT_TERM_IMAGES`.

**P11 — Approvals a typed-ahead key cannot answer.**
- The host counts the frames it writes. A node remembers the count when
  it appeared. A key read before a frame that included the node cannot
  press it, by shortcut or by Enter/Space on focus. No timer.
- The harness's approval takes no default focus, so Enter answers
  nothing and the choice is `1`, `2`, `3` or Esc.
- Neither proves attention. Together they stop the two accidents F11
  recorded.

**P12 — Kitty images in the live region.**
- Use image ids: place with `a=p`, delete with `a=d`, and re-place on
  every move of the region.
- iTerm2 stays half-blocks there.
- After P1, since ids for nodes about to be retired are waste (Grok).

**P13 — The border rule on the kernel instance.**
- `Env` (the per-kernel context layout already receives) gains the
  terminal's border rule. The terminal host sets it; every other host
  never sees it.
- `COLUMN` and `ROW` stay fixed (D3).
- Astra's point that `ch`/`lh` resolve as 8/16 on every surface stands.
  Until a GUI host resolves font-relative units, a non-terminal entry
  should refuse them. That is a compiler check, and it is noted here, not
  built.

**P14 — The writer's replay as a regression test.**
- `examples/replay.rs` becomes a test over recorded bytes. It asserts:
  - settled rows appear once;
  - a spinner frame stays under a small byte bound;
  - the screen after a scripted session matches.
- Headless `print` draws the document, not what the writer sent, so it
  cannot stand in (Astra).
- A `record` verb and an `agent.mjs terminal` guide follow parent D8, not
  this document.

**P15 — Caret movement in a textarea.**
- In a `textarea`, ArrowUp and ArrowDown move the caret by visual line,
  keeping the column, and never move focus.
- The harness claims ArrowUp only on the first line (older history) and
  ArrowDown only on the last (newer).
- Tab still moves focus.

**P16 — Queue prompts.**
- A prompt sent while a turn runs is queued and shown as queued. It runs
  when the turn ends.
- Esc during a turn interrupts it and leaves the queue.
- This matches the harnesses people already know.

**P17 — Bounds and real cancellation.**
- *Output:* the shell tool reads into a bounded buffer as it goes.
- *Processes:* it starts commands in their own process group and kills the
  group.
- *The reader:* it never waits on a descendant holding stdout.
- *Network:* HTTP reads time out in short slices and check for
  cancellation between them.
- *Tests:* ones that assert the process and the thread are gone, not only
  that the entry settled.
- An adversarial local provider (Astra's idea) drives these and P1: a huge
  reply, a stall mid-event, an approval under typed-ahead input, excessive
  tool output, and a resume after cancel.

**P18 — Re-anchor after a resize.**
- After a size change, the host asks the terminal for the cursor
  (`CSI 6 n`). It already parses the answer for P5's inline clicks.
- From the answer it erases from the live region's start and repaints.
- What is in scrollback stays as the terminal reflowed it (Q2).

## 5. Questions, answered

- **Q1, P1's form:** retirement through the host record and an
  app-to-data-module `retire(id)`, not a host-only freeze (both
  reviewers).
- **Q2, resize:** never re-lay-out what is in scrollback; it reflows by
  the terminal's rules. Repaint only the live region, re-anchored (P18).
- **Q3, full screen:** the entry or the flag chooses, never the presence
  of a `role="log"` (both). Parent D10's default stays full screen; the
  harness passes inline.
- **Q4, the compiler in the binary:** answered by `rules/RULES.md`, since
  the boot path compiles nothing. A development binary may compile its
  entry, and a shipping one bakes its plan.

Still open:

- **Q5:** is the harness becoming a daily tool, or staying a stress
  consumer? That decides when persistence, resume and context limits
  matter (Astra).
- **Q6:** how large may the busy tail become, and what happens when an
  approval's preview is taller than the screen?
- **Q7:** can retirement reuse the runner's collection windowing (LLP
  1047.000) instead of a second lifetime mechanism?

## 7. The first slice, measured (2026-10-06, `e412bb81f`)

All of §4's first slice was built.

**P1's done-when holds.**
- *The run:* the harness ran in a pseudo-terminal, at 100×30, through the
  real inline writer. It did `/stress 3000`, then the adversarial
  `chaos` turn: a 3,000-line streamed reply with a 3 s stall, an
  approval, and a 5 MB tool output. Then an animation.
- *Scrollback:* 42,280 rows, replayed through `vt100`.
- *Kernel nodes:* about 189 live nodes once printed entries are retired,
  against about 1,000 a screen of transcript needs mounted. The streaming
  turn peaks around 2,350 and returns to 189.
- *Layout:* the median is 0.07 ms per commit, and the maximum outside the
  stress itself is 4 ms.
- *Memory:* 67 MB resident, flat from the first seconds to the end.

**The one spike.** The moment `/stress 3000` hands over 3,000 entries in
one answer, before any can print and retire: 111,592 nodes and a 1.5 s
layout. A real session never appends that much at once. A stress command
that wants a flat line should release its entries in screen-sized
batches.

**The writer.** A unit test drives it into `vt100` (P14's first form). It
checks:
- each settled row lands exactly once;
- a spinner tick writes under 120 bytes and never re-sends settled rows.

**The rest.**
- *Arming (P11):* by frame count, with no timer. The approval has no
  default focus.
- *Caret (P15):* moves by visual line.
- *Queue (P16):* prompts queue during a turn.
- *Cancellation (P17):* kills the process group within a second.
  Cancelled HTTP reads stop within about 250 ms. Both are tested on the
  processes and threads themselves, not only on the screen.
- *Dialogs (P5):* `showModal(id)`/`close(id)` open and close the
  harness's model and key dialogs from typed commands.
- *Border rule (P13):* it lives on the kernel's `Env`.
