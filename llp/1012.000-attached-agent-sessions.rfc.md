# LLP 1012.000: Attached agent sessions and a wait that does not move the clock

**Type:** RFC
**Status:** Draft
**Systems:** Tooling (`scripts/agent.mjs`: a session that outlives one invocation), Agent API (a form of `clock` that waits for replies and leaves the clock alone), Apple, web and Linux hosts (nothing, under the recommended option), Smoke (`scripts/smoke.mjs`)
**Author:** Claude (Opus 5.5) for Charlie Cheever
**Date:** 2026-09-24
**Related:** LLP 1012 §2 (the clock; `clock settle` waits for requests, bounded), §8 "Not in v1" (attaching, 1012:561-562), "Amended (LLP 1018)" (agent mode's empty store, 1012:579-580); LLP 1016 (requests in flight); LLP 1035.003 D5 (a precedent: platform timing added as a form of `clock settle`, not an operation); `rules/NOT-DOING.md` §Agent API (the eight; a ninth replaces one, :289); the Crew port report, 2026-09-24 (Seth), items D5, D7, D15, D16

## Summary

Two changes to how an agent drives an app, neither a ninth operation:

1. **A session can outlive one `agent.mjs` invocation.** `--keep` leaves
   the app and its carrier running behind a small resident driver;
   `--attach` sends later operations to it; `--detach` ends it. An agent can
   look at a result and decide its next step without replaying from boot.
2. **`clock replies`** waits, bounded, for the requests in flight to
   answer, and does not move the clock. It is the wait for network that
   today can only be had by `clock settle` (which also runs timers and
   motion to a fixed point) or by padding a run with reads.

## Motivation

The Crew port report (2026-09-24) lists four driver frictions:

- **D5.** "`agent.mjs` relaunches the app on every invocation. State
  (including an in-memory store) is lost between calls, so a whole flow must
  be one argv list."
- **D7.** "No real-time wait in the driver. `clock +N` does not wait for
  network, and `clock settle` hangs." The agent "spammed `layout`/`state`
  ops as a sleep."
- **D15.** "Long driver runs die silently", which one-argv-list flows
  (D5) make longer.
- **D16.** Reads used as a wait let `clock +N` padding race the agent
  clock to t=38000 in ~2 s of wall time, so "ordinary 200 ms requests look
  like 38 s stalls" in the journal.

Today a session is a process by construction:

- The CLI opens a session (`scripts/agent.mjs:1448`) and closes it in a
  `finally` (`:1482-1484`).
- On a simulator the app is launched with `simctl launch --console
  --terminate-running-process` (`:664`); "closing hangs up the socket,
  which ends the app" (`:651`).
- The iOS app accepts exactly one connection (`AgentIOS.swift:82-88`), and
  `Agent.serve` ends the process when that stream closes
  (`Agent.swift:41-66`, `exit(0)` at `:65`).
- macOS and Linux carry the protocol over the child's stdio; the web over
  a DevTools pipe to a Chrome the driver owns. Neither can be re-attached
  by a second process.
- LLP 1012 recorded this as a v1 limit: "attaching to an already running
  app (a session is a process; the dev loop wants the same resident
  channel)" (1012:561-562).

The wait: `clock` with a time "does not wait: a reply lands when it lands"
(1012:326-327). A reply is pumped at whatever the agent clock reads when it
arrives (`Session.swift:397-402`), and journal lines are stamped with that
clock only (`runner/src/runner.rs:732-735`). So the only honest wait for
network is `clock settle`, which also seeks every transition and fires every
timer it crosses; with a poll task and a slow endpoint it is the wrong tool.

**Fixed separately, in the same batch of work, and not re-proposed here:**
`clock settle` taking one deadline for the whole call on Apple and Linux (it
restarted twenty seconds per round, up to sixteen rounds), driver errors
that name the operation index and the app's exit, and the driver's clock
seeded from the app under `--timing platform`.

## Design

### D1 — `--keep` starts a resident driver; `--attach` talks to it

`bun scripts/agent.mjs <host> --keep [ops…]` opens a session as today, runs
any operations given, prints a session record, and leaves a background Bun
process holding the session object `open()` returns — carrier, `s.now`,
`logCursor`, a held contact, the pointer calibration, the source maps. It
listens on a Unix socket in a private temporary directory. `--attach [ops…]`
connects to that socket, sends the operations as JSON lines, and prints the
replies exactly as a single run would. `--detach` closes the session the way
the `finally` does today and ends the process. An idle limit (ten minutes
without a request) does the same, so an abandoned session does not keep a
simulator app alive for a day.

The record (`$TMPDIR/exact-agent/<host>-<app>.json`, never in the repo)
holds: the resident driver's pid and socket path, the host, the app, the
launch time, and the app's pid when the carrier reports one. `--attach`
refuses, naming the record, when the pid is gone. One kept session per
host and app; `--keep` on a live record refuses rather than replacing it.

*Rejected: the app accepts connections in a loop and survives a hangup under
a keep flag; the CLI reconnects and restores `s.now` from `tags` and the log
cursor from the record.* It needs a host change per carrier (iOS's accept
loop is small, but macOS and Linux would need a socket carrier beside stdio,
and the web a DevTools port instead of a pipe — a listening port on a shared
machine), and every piece of driver state would need a reconstruction path
that can drift from the one in memory. The phone carrier connects outbound
to the driver (1012:30-35) and would need to reconnect as well. A resident
driver keeps every carrier's transport as it is and reconstructs nothing.

### D2 — The store is the process's

Agent mode boots with an empty store and persists nothing (1012:579-580).
A kept session keeps that rule: the store lives as long as the app process,
so an in-memory store survives between `--attach` calls (Seth's case) and
is gone at `--detach`. `EXACT_STORE=real` behaves as it does today.

### D3 — Hosts, in order

The resident driver is carrier-agnostic, so every host that `open()`
reaches gets it at once: the iOS simulator and macOS (the report's hosts),
the web (the dev loop's), Linux. The physical phone works through the same
bridge, but its 45-second per-request limit and the idle timer UIKit
disables for agent launches only (1012:36-37) need a run on the device
before it is claimed. The sample host's `--session <label>` routing is
unchanged: an attached client names a label as a single run does.

### D4 — `clock replies`: wait for requests; leave the clock where it is

A form of `clock`, as `settle` is. The host waits until `state.pending` is
empty or the settle bound passes (twenty seconds on native hosts; the web's
`SETTLE_DEADLINE_MS`, `host/web/glue.js:1125`), pumping each reply as it
lands and committing it at the current agent clock. No timer fires and no
motion is seeked, because the clock does not move. The reply is
`{clock, settled, pending, waitedMs}`: `settled: false` names what is
still out, and `waitedMs` is wall time, so a reader of the journal can tell
a 200 ms request from a 38-second agent-clock gap (D16).

*Rejected: a ninth operation `wait <ms>`.* Waiting wall time is what the
clock-in-the-agent's-hands design removed (1012 §6, "`clock` replaces
`wait`"), and `rules/NOT-DOING.md` §Agent API (:289) would take an operation
off for it. *Rejected: changing `clock settle` to skip timers.* Its
fixed-point meaning is what the smoke and LLP 1035.003 D5 depend on.

### D5 — Smoke

One step in `scripts/smoke.mjs web` (the seconds loop) and the same in the
`ios` smoke: `--keep tree`; `--attach "tap <button>"`; `--attach state`
shows the tap's effect and the same `clock`; `--attach "clock replies"`
after a request-starting tap reports `settled: true` with the clock
unchanged; `--detach`; the app pid from the record is gone. No new check or
script: these are steps in the existing smoke.

## Cost and what it touches

- `scripts/agent.mjs`: `--keep`, `--attach`, `--detach`, the record, the
  resident loop around the existing `open()`/`s.op`, and `clock replies`
  in `s.clock` (`:1120-1130`) and the CLI switch (`:1476`). Roughly 150
  lines; nothing in `open()`'s carriers changes.
- Hosts, for D4 only: the `replies` branch beside `settle` in
  `Agent.swift` `clock` (`:225-286`), `host/linux/src/agent.rs`, and
  `host/web/glue.js` `clock` (`:1244-1252`) — each a call to the existing
  wait-for-replies helper without the advance.
- LLP 1012: strike "attaching" from §8's "Not in v1"; §2 gains the
  `replies` form beside `settle`.
- The resident process is apparatus under `rules/RULES.md` §Agents; it is
  proposed here and needs Charlie's approval before an agent builds it.
