## Summary

Stage 1, end to end: a phone types one URL into the dev menu and runs the
live plan — the same URL a browser opens — with the link rung as the
contract, no server branching, bundled everything, and the agent carrier
provably unreachable from the LAN. Four landing steps, each verified by
driving before the next starts; then the RFC's delivery notes and the
`1023.001` spec transcribed from what landed. Stages 2–3 are outlined at
the end with their triggers and are not scheduled by this document.

## 1. Ground rules for the build

- **No new checks, scripts, registries, or config files.** Everything lands
  inside files that exist, except: the Apple shared loader (one new Swift
  file beside the bridge), the Linux locator module (one new `.rs`), and
  `dist/exact.json` (a build output, not a source). Each is named here so
  the human approval is this plan's acceptance.
- **The five checks green at every landing step**, staged-explicit-paths
  only (the tree is shared with a peer session). `boot` cannot move: no web
  boot-path changes exist in Stage 1 (`dev.js` is dev-only and stays the
  single injected module).
- **Fix loops get three rounds** per step, then stop and say so. The known
  risk pockets are §5.
- **Verify by running.** Every step ends with a driven check from §4's
  matrix, not a grep.

## 2. Stage 1 in four landing steps

### Step 1 — the server side: envelope, link, hello, bind

All Node, all in `host/web/`.

**`build.mjs`** (writes `dist/`):
- After the wasm and plan land, read `dist/app.plan` and write the *static*
  envelope `dist/exact.json`: `{ "exact": 1, "app": { "name": <resolveApp
  name> }, "plan": { "url": "./app.plan", "sha256": <full lowercase hex>,
  "bytes": <n>, "formatVersion": <u32>, "kernelSchema": <u64 hex> } }`. No
  `events`, no `seq` (static form, D2); no `app.id` until Stage 2's header
  work (unknown/absent fields are the envelope's evolution rule).
- `formatVersion` and `kernelSchema` come from the plan bytes themselves —
  the header is fixed-layout (LLP 1005 §2 / plan/build.rs:498): magic bytes
  0–3, `FORMAT_VERSION` LE u32 at offset 4, `FORMAT_DIGEST` LE u64 at 8,
  `kernel_schema_digest` LE u64 at 16, `compiler_identity` LE u64 at 24. A
  ~10-line Node reader; no new Rust surface, nothing hand-mirrored — the
  offsets are the generated encoder's, cited not re-derived.
- Inject `<link rel="alternate" type="application/vnd.exact.envelope+json"
  href="./exact.json">` into `dist/index.html` at build time, the way
  `dev.mjs` already splices `dev.js` — so the static rung works under
  `serve.mjs` and any dumb host with no server logic at all.

**`dev.mjs`**:
- Track the current revision: when the resident compiler reports a plan
  (including its un-pushed first plan — the `continue` at dev.mjs:67 must
  not skip this), sha256 `dist/app.plan` (~12 KB; `node:crypto`, sub-ms)
  and hold `{ seq, digest, bytes }`.
- `/exact.json` served live: the static file plus `"seq"` and
  `"events": "./__dev"`.
- The SSE hello: on `/__dev` connect, send `{ seq, digest }` before adding
  the client (closes the fetch-then-subscribe race, RFC D3). `{ seq }`
  pushes gain `digest` too, so a reconnecting client compares one shape.
- The bind: default `0.0.0.0`; `--loopback` / `EXACT_LOOPBACK=1` restores
  `127.0.0.1`. Print both URL forms — every non-internal IPv4 from
  `os.networkInterfaces()`, private-range (192.168/10/172.16–31) first,
  never silently picking one — plus a first-run line naming the macOS
  firewall prompt (D8).
- Hygiene that rides the exposure: containment becomes
  `path === dist || path.startsWith(dist + '/')` (the agent.mjs:104 form;
  today's `startsWith(dist)` admits a `dist-…` sibling); `.json` joins the
  MIME map (none today, dev.mjs:131) and `.plan` becomes
  `application/vnd.exact.plan`; GET/HEAD only.

**`serve.mjs`**: the same bind default, flag, and containment fix — three
lines. It serves `dist/` verbatim; the static `exact.json` is already
there. It is not the Stage 1 critical path (grok r1 LOW, agreed).

*Closes with:* browser at both URLs unchanged; `curl` of `/exact.json` from
a second machine shows the live form; `--loopback` makes that second-machine
curl fail; sha256 in the envelope matches a local hash of the fetched plan.

### Step 2 — the Apple loader and the typed URL

**Shared loader** — one new file `host/apple/swift/PlanURL.swift` (both
presenters use it; the shared directory is exactly for this, LLP 1008):
- `resolve(U)`: GET `U` with `Accept: application/vnd.exact.envelope+json,
  text/html;q=0.9` (sent from day one; the server does not branch until
  Stage 2). If the response is the envelope type, use it; if HTML, a
  bounded parser-free scan (first 16 KB, first match wins, no entity work
  beyond `&amp;`) for the `rel="alternate"` link with our MIME type, then
  fetch its href resolved against the final response URL (post-redirect,
  D2). Same-origin enforced. Anything else is a typed error naming `U`.
- `fetchPlan(envelope)`: refuse on `exact` major ≠ 1 or `kernelSchema`
  mismatch *before* downloading; fetch `plan.url`; verify `bytes` and
  `sha256` (CryptoKit); hand bytes up. Every failure returns an error and
  the caller keeps the last good app — the swap happens only after a
  successful boot (D3's transaction; the boot call is the same
  `exact_boot_plan`-carrying path `EXACT_DEV_PLAN` uses today).
- `subscribe(events)`: minimal SSE over `URLSession` streaming — `data:`
  lines, JSON frames, the hello comparison, reconnect re-compares. `{seq}`
  → re-run `fetchPlan` and swap-on-success. `{rebuilt}` → session-terminal:
  keep the last good app, surface "rebuild the native host" through the
  same path a failed dev plan uses today, stop re-fetching until Reload.
  `{error}` → surface, keep running.

**The locator**: the presenters' existing `EXACT_DEV_PLAN` handling
(macos/ios `main.swift`) branches on `http(s)://` — a URL means the
envelope flow instead of the mtime poll. No third variable (panel r2).
Under `EXACT_AGENT=1` the URL form stands down unless explicitly given —
smokes stay deterministic.

**The dev menu** (17350d0): an "Open project…" row — a text field seeded
with the last value (`UserDefaults`, key `exact.dev.url`, dev builds only —
declared here as dev apparatus), driving the same loader; Reload becomes
"re-fetch now" when a URL is active.

**The dev plist**: the iOS dev client's Info.plist (assembled by
`host/apple/build.mjs`) gains `NSAllowsLocalNetworking` and
`NSLocalNetworkUsageDescription`, dev builds only — never a store shape
(D8). First-fetch bounded retry while the local-network permission prompt
is unresolved.

*Closes with:* macOS app booted from `http://127.0.0.1:8765/`, edit →
new frame carrying state; then the same from a **physical iPhone** via the
typed URL over the LAN — the slice's reason to exist.

### Step 3 — the Linux locator

`host/linux/src/` gains one module: the same locator branch on the
`EXACT_DEV_PLAN` value (host/linux/src/app.rs's poll path today). The host
links no system libraries and takes no new crates, so HTTP here is a
std-only `TcpStream` HTTP/1.1 client — GET + Host header, Content-Length
bodies, and the SSE stream read as lines — the same posture as the
hand-rolled RFB server in `vnc.rs` (the in-repo precedent for exactly this
trade). Plain `http` only; an `https` URL is a clear refusal naming the
limitation. Same transaction, same `{rebuilt}` terminality, same sha256
(the workspace already carries a SHA-256 for the plan format's digest —
reuse, add nothing).

*Closes with:* `caltrain-linux` on a fleet box booted from the Mac's LAN
URL, edit → new frame; headless, driven by the agent over stdio as ever.

The full §4 matrix run and recorded (numbers, not adjectives), the RFC

## 3. What Stage 1 deliberately does not touch

No server `Accept` branch (Stage 2 — the link rung is what Stage 1
proves). No `app_id`, no `format.json` change, no registry, no launcher,
no mDNS, no remote assets (a plan referencing an asset the bundle lacks is
refused with "rebuild the client"), no auth, and no behavior change for
release binaries — network loading compiles only into dev-capable hosts
(§8's door, closed from the first commit).

## 4. The verification matrix (from RFC §9.1, made concrete)

Happy paths, per host: web unchanged at both binds; macOS via env-URL;
iOS simulator via env-URL; **iOS device via typed URL**; Linux via
env-URL. Hot loop timed: `{seq}` → first frame on the LAN, against the
100 ms dev-restart row (recorded as measured; the budget verdict is
diagnostic, LLP 1007 §7).

Adversarial, each with its expected refusal text:
- tampered plan (serve a byte-flipped copy) → sha256 refusal, last good
  keeps running;
- truncated plan → bytes/decode refusal, same;
- stale schema (a plan baked before a kernel change) → refused from the
  envelope's `kernelSchema` *before* download;
- an edit landing between envelope fetch and SSE connect → the hello's
  `{seq, digest}` triggers the re-fetch;
- SSE connection killed mid-session → reconnect, hello compare, correct
  catch-up;
- `{rebuilt}` (touch a data-crate file) → "rebuild the native host," last
  good still on screen, Reload after a host rebuild recovers;
- from a second machine: artifact URLs reachable, **agent carrier and
  `scripts/agent.mjs`'s server unreachable**, and everything unreachable
  under `--loopback`;
- path traversal against the tightened containment (the `dist-` sibling
  probe included);
- weird-castle through `exact.mjs` — the loop is app-independent
  (`EXACT_APP_DIR` is the only difference the server knows).

## 5. Risks, and where each stops

- **SSE over URLSession** buffering quirks (delivery batching on iOS).
  Fallback inside the three rounds: byte-stream delegate reads. If a third
  round still misbehaves: fall back to short-poll of `/exact.json` `seq`
  (the envelope already carries it), say so in the delivery notes, keep
  the SSE contract server-side.
- **The local-network permission dance on a real device** (the prompt
  races the first fetch). Bounded retry is planned; if hardware behavior
  defeats it, the stop is a written recipe in the RFC (prompt first via a
  deliberate no-op connect from the menu), not silent retries.
- **Std-only HTTP on Linux** growing beyond its brief. The brief is GET +
  SSE against our own dev server, nothing else; if it wants more than
  ~150 lines, stop and bring the question back rather than vendoring a
  client.
- **The shared tree.** Both sessions edit this checkout; every commit
  stages explicit paths, and any file the peer has dirty gets committed
  as HEAD-plus-my-hunks or not at all.

## 6. Stages 2 and 3 — outline and triggers only

**Stage 2 — identity and negotiation** (trigger: Stage 1 landed and
Charlie ratifies the `DataSource::app_id()` leaning, RFC §10): `app_id` in
the header via `format.json` + `formatVersion` bump (moving both constants
through the one authority); bake writes it from `DataSource::app_id()`;
the `Accept` branch and `Vary: Accept` on `dev.mjs` (clients already send
the header — zero client changes); refusals that name apps. Touches the
plan format — lands with its own review pass.

**Stage 3 — the registry, the launcher, discovery** (trigger: a second
baked app actually wanted in one binary, or Charlie calls for the
launcher): the `BundleEntry` macro (single-entry expands to today's code;
web `host!` untouched); `apps/launcher/` with `openProject(url)` and
host-fed discovery snapshots; system DNS-SD only (`dns-sd` /
Network.framework advertise + `NWBrowser`; Linux waits for Avahi or stays
typed-URL); "Open project…" grows the browse list above the URL field; the
no-cross-app-carry drop list; store admission semantics per RFC §5.

Deferred behind all three, each with its trigger in the RFC: remote
digest-addressed assets, Linux Avahi, a data-crate compatibility digest.
