## Two concrete gaps

Skirmish assembles a unit from a meshless root and parented primitive parts.
Today's `Visible(false)` affects only the entity carrying it. Hiding the root
leaves its body parts, shadows and pick targets visible. Forest also has hidden
Deer parents with eyes/antlers; moving them underground currently masks this
gap. Rivals hides individual parts, which must remain locally hidden. The
socket-follow tests intentionally allow a visible follower of a hidden owner:
that relation is not `Parent` and retains its existing behavior.

The renderer already supports read-only `Hooks`, HDR post-processing, sampled
final depth, shader registries and lifecycle reset (LLP 1046.006.000). Skirmish
can implement its own fog shading there. Generated external-game shells only
emit the plain/audio/assets `module!` forms, so an author currently cannot wire
a presentation crate without editing generated files. No new engine fog API,
shader language, executor, or render-stage hook is needed.

## A. Effective visibility

Add `World::is_visible(entity) -> bool`: a living entity is visible only when
its local `Visible` row (absent means true) and every living `Parent` ancestor
are true. A local true never overrides a hidden ancestor. Removing a parent's
false row reveals descendants except those retaining their own false row.
The query reads current rows, including writes while paused and before a
propagate. It does not modify components, simulation time, hashes or saves.

Dead entities, dangling parent chains and unrepaired cycles are not visible.
Check complete entity generations, not recycled indices. Runtime propagation
continues repairing cycles by removing its existing highest-index edge; saved
cycles retain their existing refusal. Orphan reaping remains unchanged. A
stale parent's child may therefore be hidden before the next reap instead of
briefly rendering as a root. `SocketFollow` alone does not inherit visibility;
an explicit `Parent` on that follower still does.

Use this one query in primitive/model/sprite/particle extraction, shadow-caster
selection, spatial picking and reported agent visibility, and placed canvas
child presentation. Apply it to directional, point and spot illumination too,
including the sun exposed to hooks. Camera choice, transform propagation,
simulation, collision, spatial-near queries and audio remain independent of
visibility. Explicitly hiding a light now suppresses its contribution; this is
part of the reviewed semantic change. A hidden emitter's drawing is suppressed;
its deterministic particle timeline keeps running so reveal does not restart it.

Audit retained render records: a parent or visibility write, birth/death,
component insertion/removal, reparent or restore must invalidate any affected
batch/quad/light/placed result even when no transform changed or tick advanced.
Most mesh feed versions already carry Parent, Visible and entity revisions;
lights and placed extraction need explicit review. No stale shadows, lights,
pick proxies or agent "inside" visibility after hiding an ancestor.
The existing mesh batch predicate does not consume its stored Parent revision:
add the missing reparent dependency and prove it with a paused, reparent-only
mesh/model/shadow regression. Hidden lights must be filtered before nearest-light
slot selection so they cannot starve visible lights; test more hidden lights
than the budget, directional sun/fill fallback, and the hook's sun together.

Start with a bounded parent-chain query and no retained visibility cache. Measure
1,000 multipart entities and a deliberately deep chain. If hierarchy walks cost
enough to justify a cache, review the measured design before adding it; it must
be derived and invalidated on all the events above, never serialized. Existing
hierarchy propagation is not rewritten just to provide a boolean query.

## B. Authored presentation crate

Admit optional `game.presentation` in app.json with exactly `crate`, `type`,
and optional `shaders`. It names the fixed authored directory `presentation/`.
The crate name follows the existing authored-crate convention, ending in
`-presentation`; `type` and `shaders` are validated Rust paths relative to that
crate, not arbitrary Rust expressions. `shaders` omitted uses the existing
empty registry. `presentation/Cargo.toml` must name that package and set
`package.workspace = "../.shells"`, as authored logic/data do. Validate before
writing the generated workspace; reject unknown fields, malformed paths, missing
manifests and package/workspace mismatches with author-facing errors.

Only the GPU adapter gains `game-presentation = { package, path }` and emits
`module!(game_logic::Game, [audio/assets], hooks = game_presentation::Type,
shaders = game_presentation::REGISTRY)` through existing macro forms. The
presentation crate may depend on game logic for resource types; generated
logic, host adapters and build-time logic metadata never depend on presentation.
The authored dependency graph must not route presentation back into logic.
The hook-absent generated sources and dependency graph remain unchanged.
Validate transitive production dependencies from actual Cargo metadata, including
renamed, path, target-specific and build dependencies; checking generated text
alone is insufficient. Test the refusal against an indirect renamed dependency.

Include presentation in workspace membership, lock/metadata accounting and
ordinary package tests; keep deterministic-logic linting scoped to logic.
Presentation still gets normal strict Rust linting. Existing `gpu.shaderRoots`
and `gpu.shaderPreludes` own shader discovery/reflection/delivery. Explicitly
include presentation source/manifests/shaders in build receipts, watch inputs,
snapshots and proof fingerprints. Changing them must invalidate a built app.
They live in a clean checkout; no undeclared sibling renderer or shell edits.

This boundary enables Skirmish to upload its saved CPU vision mask and shade
the resolved scene using existing HDR_POST/FINAL_DEPTH. The game's knowledge,
targeting permissions, hidden-unit/effect filtering and save semantics remain
game-owned. Hooks do not make final-depth fog correct for arbitrary translucent
surfaces; Skirmish's first slice uses opaque terrain and separately gated units.

## Amendment (2026-10-04): derived presentation state, and `game.render`

Revision note: chosen with Opus 5.5 and Astra, both at max effort, per Charlie.
Charlie asked for the best design between this plan as landed (M) and the fix2/core +
fix2/render branches (F), rather than the one that landed first. Two independent,
mutually blind reviews converged; they are recorded verbatim in
`llp/reviews/1046.008-game-presentation-seams.opus.md` and `.astra.md`. This
amendment supersedes B's naming and adds the derived-state model; A stands.

1. **One GPU extension crate, `game.render = { crate, hooks, shaders? }`, in
   `render/`, crate suffix `-render`.** B's implementation is kept whole
   (validation before writes, the unfiltered transitive Cargo graph check, now
   `renderGraph`, strict lint, exact-gpu aliases only when declared, receipts,
   watch inputs, Windows membership, re-reading in prepareGame). Only its names
   change: "presentation" now means derived appearance state alone, and the
   crate holds hooks and shaders. `game.presentation` fails with its rename.
   Shader sources stay explicit (`gpu.shaderRoots`, `gpu.shaderPreludes`);
   `bun game/new.mjs --render` scaffolds the crate and writes that root. The bake
   assembles the inventory once (each shader after its preludes) into
   `.shells/shaders`, named by `EXACT_GAME_SHADERS`, which the render crate's
   build reflects; preludes may name the renderer's own sets
   (`exact-game-render:frame`, `:material`, `:material_shadows`), so a game never
   names SDK source paths. The render-crate executor trait is renamed
   `Executor` (and `ModelPresentation` `ModelExecutor`) so "presentation" means only
   author-facing derived state (fix2/render).
2. **Derived presentation state.** `#[derive(Presentation)]` components (not
   resources) are excluded from saves (a save carrying them is refused), hashes
   and rest, and ticks cannot read them. `Game::present` receives a restricted
   `Present<'_>` (deterministic simulation reads, writes to presentation
   components on existing entities, `rng(salt)` from seed, tick and salt); a
   runtime guard that stays armed after a caught panic is its second layer. Rows
   are cleared before each present. It runs after setup, after a fully restored
   state (journal and publications first), after argument changes and tool
   edits, and at observed boundaries (the last two ticks of an advance); paranoid
   modes present every tick and compare. Presentation writes are not simulation
   mutations; an empty world pays a fast path.
3. **Stock appearance controls:** `Offset`, `Opacity`, `Tint`, `NodeMaterials`,
   `MaterialOverrides`. Drawn pose is `drawn(parent)·local·offset` and opacity
   multiplies down the Parent chain, computed in A's bounded walk
   (`World::drawn`, landed on fix2/core). Pending fix2/render: one
   displayed-pose path serving rendering, sorting, bounds, shadows, hooks and
   retained model poses (picking, physics and gameplay keep simulated poses);
   overrides that replace base factors, so a zero channel can be replaced;
   opacity 0 removing primitive shadows, which dither like model shadows, with
   the docs saying this is coverage fading and what custom shaders must do
   themselves; change detection by content digest, scanned only where the
   controls are present.
4. **Visibility** is A as landed: a hard gate on every render path; Opacity or
   ViewModel never reveal a child of a hidden ancestor. The shared predicate is
   exposed to hook authors (`RenderWorld::is_visible`, fix2/render) and to
   `Present::is_visible`.
5. **LOD:** one entity-level reference distance and one selected level on every
   path; hysteresis is presentation-only (fix2/render).
6. **Agents and proofs** distinguish simulated from displayed poses; settled means
   simulation-settled; looks are proven by presentation-value and pixel tests at an
   explicit tick and alpha, separately from hash pins.
7. **Authoring rule:** save the cause, derive the appearance (engine README).
8. **wind-fixture** is the committed public `game.render` consumer, on the
   reflected shader/prelude inventory.

Qualification: equal hashes and saves with presentation on or off across restore,
seek and both paranoid modes; every-tick and boundary-only presents draw the same;
pixel tests (bobbing multipart root, faded multipart tree with shadows, hidden
ancestor over Opacity and LOD, primitive tint, an override replacing a zero
channel); the renderGraph refusal test; wind-fixture GPU and proofs on native and web.


## Amendment (2026-10-05): presentation swaps

Charlie's orchestrator, for the Grow a Garden art pass (QUEUE: "`Game::present`
cannot swap a mesh, move a light or change the sky"; "Changing a look restarts the
game"). Three stock presentation components replace what the simulation draws,
keeping present a pure function of simulation, arguments and tick and the paranoid
comparison as it is:

1. **`DrawnMesh { mesh, lod, material }`** draws in place of the entity's `Mesh` and
   `ModelLod` (levels belong to a model) and, when set, its `Material`, or on a bare
   pose with no `Mesh`. Every draw path reads it (primitive and model batches, LOD,
   shadows, dimensions, material floats, glow); picking, physics, animation, sockets
   and save asset checks keep the simulated mesh. Its models are requested like a
   `Mesh`'s; the feed digests content, so an unchanged rewrite rebatches nothing.
2. **`DrawnLight`** (`Directional`, `Point`, `Spot`) is the entity's light as drawn,
   in place of any simulated one or on a bare pose; it is posed with `Offset`, and
   visibility, `Lit`, `LightShadows` and slot selection treat it as a simulated light.
3. **`DrawnEnvironment { environment, ambient_occlusion }`** on the drawn camera
   replaces the `Environment` and `AmbientOcclusion` resources for its frames. This
   keeps presentation resources unsupported: a world-wide look rides on the camera.

`Opacity` now also multiplies particle and sprite alpha, and hides them at 0, so a
look can hide an emitter that is simulated in every look.

A look that changes only these is a `#[live]` argument: the world is set up for
every look (Garden registers every look's generated models and places every look's
props as bare poses), and `present` draws the chosen one, so a switch keeps the
world and every look has the same hash. Cost: setup generates every look's models
(Garden: about 55 ms native release for three generated looks, against 2.5–28 ms for
one), and present rebuilds a swap per entity at every boundary (Garden's art pass at
12,100 plants: about 4 ms a 60 Hz live frame, native release, against 0.04; 0.05 ms at
100 plants). Qualification: engine `presentation.rs` (a live look swaps a mesh, a light
and the sky; equal hashes; requested models), renderer `swap_tests.rs` (drawn
shapes, materials, levels and no rebatch on rewrite; drawn sun, fill, point light
and camera sky; particle opacity), Garden's `every_look_plays_the_same_garden`
(equal hashes across looks, a classic save restoring in each, live switches) and its
art-pass tests under both paranoid modes, and the web host driven through the switch.
