## Summary

`@exact/recording` records the microphone to a file and reports its level,
on the web, iOS, macOS and Android, with every other target of LLP 1133 D8
a visible `later` or `absent`. Its tier 1 is the web's: Media Capture's
`getUserMedia({audio})` opens the microphone and answers a stream of
tracks, MediaStream Recording's `MediaRecorder` records a stream, and a
track's level is a live source named after WebRTC statistics'
`audioLevel`:

```
use getUserMedia, microphoneStatus, MediaStream, MicrophoneStatus from "@exact/media-capture"
use startMediaRecorder, stopMediaRecorder, audioLevel,
  MediaRecorderInfo, RecordedMedia, AudioLevel from "@exact/recording"

state trackId = ""
state recorderId = ""
mutation opened as shape MediaStream then arm
mutation started as shape MediaRecorderInfo then begun
mutation saved as shape RecordedMedia then filed
resource level = audioLevel(track=trackId, history=200) as shape AudioLevel else empty()

action record
  send opened = getUserMedia(audio=true)
action arm
  match opened
    case some(s)
      trackId = s.tracks[0].id
      send started = startMediaRecorder(stream=s.id, path="app:/data/takes/take-" + next)
    case none
      trackId = ""
action begun
  match started
    case some(r)
      recorderId = r.id
    case none
      recorderId = ""
action stop
  send saved = stopMediaRecorder(recorder=recorderId)
```

```ts
import { getUserMedia } from "@exact/media-capture";
import { startMediaRecorder } from "@exact/recording";

const stream = await getUserMedia({ audio: { echoCancellation: false } });
const recorder = await startMediaRecorder({ stream: stream.id, mimeType: "audio/mp4",
  path: "app:/data/takes/memo", apple: { mode: "measurement" } });
```

Tier 2 reaches the audio session's mode and category options on Apple,
Android's audio sources and privacy flag, and each platform's encoder
settings. Tier 3 hands the app's Swift the capture's `AVAudioEngine` and a
mixer carrying the input, and its Kotlin the `AudioRecord.Builder`.

Three things this module is the first to need, and which reach beyond it,
are decided here (§3, D7, D10):

- **The media-capture surface is shared with the camera.** `getUserMedia`,
  a track and its id, the device list and the two permission facts are one
  interface, `@exact/media-capture`, so that an app using both modules
  imports one `getUserMedia` and a later recording with both sound and
  picture is one stream. That package owns every capture, one per device
  for the process; a session holds leases on it. Tracks are host-owned
  objects named by id in one table, as LLP 1133.003 D2 made video tracks,
  so a package consumes a track it did not open.
- **The audio session stays the host's.** One owner sets the category for
  every sound, video, sequence and capture in the process (LLP 1096 D8);
  a capture is one more claim on it, which the owner composes. The owner
  is reachable by every package, not only exact2's.
- **A package gains what the recorder's app module had,** and what
  native handles need: a session end that finalizes its files, the session
  clock, the app's foreground, admitted file paths to write, the
  audio-session claim, permissions and grants per name and argument, and
  the disposal of a handle the app never received.

The consumer is the recorder (`apps/recorder`), whose own Swift and page
module, 534 lines, are deleted: the path a third party takes from an app's
module to a package (§11).

## 1. What exists

**The recorder** (LLP 1067.000) is one app native module per session,
on the web, macOS and iOS: `modules/apple/Recorder.swift` taps
`AVAudioEngine`'s input node, writes the input to a CAF file with
`AVAudioFile`, keeps a level 20 times a second, and draws `<waveform-view>`
from those levels each display frame; `modules/web/index.js` does the same
with `getUserMedia`, an `AnalyserNode` and `MediaRecorder` into the origin
private file system. Its TypeScript asks the module to start, stop and list
takes. The levels never cross into Contract: the smoke holds that three
seconds of recording make no request (`scripts/smoke-recorder.mjs`). Under
the agent both modules substitute a synthetic level on the session's clock,
so the takes read the same on every host.

Its Swift sets the audio session itself: `setCategory(.record)` and
`setActive(true)` on start, `setActive(false)` on stop
(`Recorder.swift:102–151`). That breaks LLP 1096 D8, under which
`AudioSession.swift` is the only `setCategory` caller: while the recorder
records, `.record` silences the app's own sounds and video, and the sound
arm's next hold sets the category back to `.ambient`, which has no input,
stopping the take.

**The package seam** as geolocation built it, and notifications and the
clipboard extend it (LLP 1133.004 D5–D6, LLP 1133.006 D8): an Apple
implementation is a class with `init(changed:agent:log:)` (with `emit:`
after LLP 1133.004), `later`, `call` and `release`
(`host/apple/modules/ExactExtensions.swift`); an Android one subclasses
`ExactExtension`, with `later`, `release` and `resumed`; a web one exports
`implementation({changed})`. An admitted `app:/` path reaches an
implementation as a file it may read (LLP 1133.006 D8 item 3). A package
has none of these, which the recorder's app module has
(`ExactModuleContext`, LLP 1067.000 D6): a `destroy` at session end, the
session clock (`now()`), the data directory, and, on Apple, a way to
reach `AudioSession`, which is `package`-internal to ExactKit.

**Grants:** `device.microphone` is a row of `runner/src/device.rs`, with
`NSMicrophoneUsageDescription`, the hardened-runtime entitlement
`com.apple.security.device.audio-input` and `Permissions-Policy:
microphone`; it has no Android column.

**`rules/DEFERRED.md`** lists "microphone input" among what LLP 1096 leaves
out of sounds (the 1096 entry's "Still out"). This module admits capture to
a file and a level, not the microphone as a sound source (§13, §15
question 6).

## 2. Tier 1

### D1 — Media Capture's and MediaStream Recording's names

The names. The first six are Media Capture's, imported from
`@exact/media-capture` (D3); the rest from `@exact/recording`:

| Name | Kind | Web | Contract | Data code |
|---|---|---|---|---|
| `getUserMedia(audio=…)` | send; a request | `navigator.mediaDevices.getUserMedia({audio})` | `send s = getUserMedia(audio=true)` | `await getUserMedia({audio: true})` |
| `stopTrack(track=)` | send, answers nothing | `MediaStreamTrack.stop()` | `stopTrack(track=id)` | `await stopTrack({track})` |
| `setTrackEnabled(track=, enabled=)` | send, answers nothing | `track.enabled = …` | statement | `await setTrackEnabled(…)` |
| `mediaStreamTrack(track=)` | live source; a fact | the track's attributes and `getSettings()` | `resource t = mediaStreamTrack(track=id)` | `await mediaStreamTrack({track})` |
| `enumerateDevices()` | live source; a fact | `enumerateDevices()`, re-read at `devicechange` | `resource d = enumerateDevices()` | `await enumerateDevices()` |
| `microphoneStatus()` | live source; a fact; `sync` | `"mediaDevices" in navigator`, `permissions.query({name: "microphone"})` | `resource m = microphoneStatus()` | `await microphoneStatus()` |
| `startMediaRecorder(stream=, …)` | send | `new MediaRecorder(stream, options).start()` | `send r = startMediaRecorder(…)` | `await startMediaRecorder(…)` |
| `stopMediaRecorder(recorder=)` | send | `stop()` and its last `dataavailable` | `send x = stopMediaRecorder(recorder=id)` | `await stopMediaRecorder({recorder})` |

| `mediaRecorderState(recorder=, interval=)` | live source; a fact; polled while `interval` is given | `state` and the recorder's events | `resource r = mediaRecorderState(recorder=id)` | `await mediaRecorderState({recorder})` |
| `isTypeSupported(type=)` | source; `sync` | `MediaRecorder.isTypeSupported(type)` | `resource ok = isTypeSupported(type="audio/ogg")` | `await isTypeSupported({type})` |
| `audioLevel(track=, interval=, history=)` | live source, polled; a fact; `sync` where the host has `call` | none: a declared deviation, below | `resource level = audioLevel(track=id)` | `await audioLevel({track})` |

**Values.** One representation on every target:

| Shape | Fields |
|---|---|
| `MediaStream` | `id`, `active`, `tracks: MediaStreamTrack[]` |
| `MediaStreamTrack` | `id`, `kind` (`"audio"` here), `label`, `enabled`, `muted`, `muteReason` (`idle`, `interrupted`, `background`, `silenced`; the camera adds `in-use`), `readyState` (`live`, `ended`), `settings: MediaTrackSettings`; `apple`, `android` result words (D4) |
| `MediaTrackSettings` | the audio constrainable properties of Media Capture §4.3.8: `deviceId`, `groupId`, `sampleRate`, `sampleSize`, `channelCount`, `echoCancellation`, `autoGainControl`, `noiseSuppression`, `latency`; each what the track actually applied |
| `MediaDeviceInfo` | `deviceId`, `kind` (`audioinput` here), `label`, `groupId` |
| `MicrophoneStatus` | `available`, `state` (`granted`, `prompt`, `denied`, `unknown`), `apple`, `android` |
| `MediaRecorderInfo` | `id`, `state` (`inactive`, `recording`, `paused`), `mimeType`, `audioBitsPerSecond`, `path`, `duration` (ms recorded, pauses excluded), `reason` (why it last paused or stopped: `requested`, `interrupted`, `background`, `track-ended`, `error`, `session-ended`), `error: option<string>`, `result: option<RecordedMedia>` |
| `RecordedMedia` | `path`, `mimeType`, `duration`, `size` (bytes) |
| `AudioLevel` | `audioLevel`, `totalAudioEnergy`, `totalSamplesDuration`, `levels: number[]` |

**Errors** are the specifications' `DOMException` names, as LLP 1133.006
D8 item 2 answers them (`{error, message}`, a `DOMException` in
TypeScript, `failure(…).code` in Contract): `NotAllowedError` (denied, or
a caller the origin rule refuses, with `message` `person-required`, D9),
`NotFoundError` (no input device, or an id the session does not hold),
`NotReadableError` (the platform would not give the input: an active call,
a failed session activation), `InvalidStateError` (a recorder operation
in the wrong state, as §2.3 of MediaStream Recording says),
`NotSupportedError` (a target without an implementation, a `mimeType` the
target cannot write, an inactive stream), `AbortError`, `SecurityError`.
`OverconstrainedError` arises only from `exact` constraints, which stage 1
does not take (below).

**Declared deviations,** each because the web's form is an object a
function cannot hold:

- **Objects are ids.** A stream, a track and a recorder are objects the
  session holds (D6); a call names one by its `id`, a string, as LLP
  1133.003 D2 names a video track, and the declaration types each such
  field as a handle (D10). `stopTrack(track=)` is
  `track.stop()`; `startMediaRecorder(stream=, …)` is the constructor and
  `start()` together.
- **A recording is a file, not `Blob` events.** The recorder writes to the
  `app:/` path the app names, which the admission checks against the
  calling source's `fs.write` grant (D10), and `dataavailable` does not
  reach data code. The path may omit the extension, and then the recorder
  adds the container's (`.m4a`, `.webm`, `.ogg`, `.wav`); a written
  extension that disagrees with `mimeType` is `NotSupportedError`.
  `startMediaRecorder` answers the full path at once, so an app that keeps
  it can find a take whose process ended before `stop` (D6). The file then
  plays (`audio src=` takes an `app:/` file, LLP 1042), shares and uploads
  (`exactBodyFrom`) by that path. Reason: a take is megabytes, and nothing
  in the app needs its bytes in JavaScript.
- **A recorder's state is a value.** The web's `start`, `stop`, `pause`,
  `resume` and `error` events are `mediaRecorderState`'s fields. A stopped
  recorder's state is sticky: `inactive` with its `reason` and `result`
  stays until the session ends, so a recorder that stops by itself (its
  track ended, an error, the session's end) cannot lose its result to
  coalescing (LLP 1133 D6 rule 7), and needs no event protocol.
  `stopMediaRecorder` on a stopped recorder answers that same result.
- **The level** has no web API: a page computes it from an `AnalyserNode`.
  Its names are WebRTC statistics' for a local source
  (`RTCAudioSourceStats`): `audioLevel`, linear from 0 (silence) to 1
  (0 dBFS), the RMS of the last `interval`; `totalAudioEnergy` and
  `totalSamplesDuration`, from which an app averages any span as
  `sqrt(ΔtotalAudioEnergy / ΔtotalSamplesDuration)`, as that specification
  says. `levels` is the module's own: the last `history` intervals'
  `audioLevel`, oldest first. A waveform reads `levels`, so two answers
  that coalesce lose no bar.
- **The level is polled.** The runner asks `audioLevel` again every
  `interval` (default 50 ms) of the session's clock while a reader reads
  it and its track is live, as a page reads an analyser each animation
  frame and AppKit code polls `AVAudioRecorder.updateMeters()`; at most
  one ask of a source is in flight. The implementation computes levels as
  audio arrives and never announces one per buffer. **An answer covers
  every interval since the last answer delivered,** however many polls the
  clock skipped or coalesced: `levels` gains one entry per elapsed
  interval (up to `history`, default 100), and the two totals integrate
  the whole span. So a jump of the agent's clock (`clock +3000`, which a
  seek may deliver as one advance) yields the 60 bars three seconds make,
  as the recorder's synthetic waveform does today. `mediaRecorderState`
  is polled the same way when the app gives it an `interval`, for an
  elapsed time; otherwise it is answered again only when the state
  changes.
- **Constraints are bare values,** which Media Capture treats as `ideal`:
  `audio=MediaTrackConstraints(echoCancellation=false, deviceId=d)`. A
  constraint the target cannot apply is not applied, and `settings` says
  what was. The `{exact}` and `{ideal}` dictionaries, and so
  `OverconstrainedError`, wait for a consumer.
- **`enumerateDevices`** follows Media Capture's exposure rule on every
  target: while `microphoneStatus().state` is not `granted`, it answers one
  `audioinput` with empty `deviceId` and `label`; once granted, every
  input. iOS lists inputs only for a session whose category records
  (`availableInputs`), so on iOS the list is read while a capture runs;
  before the first capture of the process it holds the built-in
  microphone alone (reading more would set a recording category and
  interrupt other apps' audio), and afterwards it is the last one read.

`getUserMedia`'s `video=` is the camera's (§3, LLP 1133.008).

### D2 — Unsaid options are the platform's; written ones are the web's

LLP 1133 D4: what the author omits is the platform's default; what the
author writes takes the web's meaning.

| Option | Web | Apple | Android |
|---|---|---|---|
| `echoCancellation`, `noiseSuppression`, `autoGainControl` omitted | the browser's (Chrome, Firefox and Safari turn them on) | none: the input node unprocessed, as a hand-built recorder has it | `AudioSource.MIC`, the platform's generic recording source, with no effect added |
| `echoCancellation=true` | the browser's | the input node's voice processing ([`setVoiceProcessingEnabled`](https://developer.apple.com/documentation/avfaudio/avaudioionode/setvoiceprocessingenabled(_:))) | `AcousticEchoCanceler` on the record's session where `isAvailable()`, else `VOICE_COMMUNICATION` |
| `noiseSuppression=true`, `autoGainControl=true` | the browser's | voice processing (one switch on Apple; `settings` reports all three on) | `NoiseSuppressor`, `AutomaticGainControl` where available |
| `deviceId` | the browser's device | iOS: `setPreferredInput` with the `availableInputs` port whose `uid` it is; macOS: the input node's device | `AudioRecord.setPreferredDevice` |
| `sampleRate`, `channelCount` | the browser's | the session's preferred sample rate and input channels (iOS), the device's format (macOS) | the `AudioRecord`'s format |
| `mimeType` omitted | the browser's (WebM and Opus in Chrome, Ogg and Opus in Firefox, MP4 and AAC in Safari) | `audio/mp4` with AAC, as Voice Memos and an `AVAudioRecorder` app write | `audio/mp4` with AAC (`MediaCodec` and `MediaMuxer`) |
| `audioBitsPerSecond` omitted | the browser's | the encoder's default for the format | the encoder's default |

**Echo cancellation on Apple** is voice processing on the capture
engine's I/O node, which references what that engine plays. The app's own
sounds play through the sound arm's engine (LLP 1096 D8), a different one,
so tier 1 does not promise to cancel them: `echoCancellation=true` on
Apple means voice processing is on, and the ceiling test (§6) lists the
app's own sound in the reference as not reached. Stage 2 measures whether
the platform cancels the other engine's output anyway and records it; if
it does not and a consumer needs it, the sound arm renders into the
capture engine while voice processing runs, which is that consumer's
amendment.

## 3. Shared with the camera

### D3 — Media Capture's surface in one package, which owns every capture

`getUserMedia`, `MediaStream`, `MediaStreamTrack`, `MediaDeviceInfo`,
`stopTrack`, `setTrackEnabled`, `mediaStreamTrack`, `enumerateDevices`,
`microphoneStatus` and `cameraStatus` are Media Capture's, not this
module's or the camera's. Declared twice, they collide: an app importing
both modules has two `getUserMedia` (`contract-use-duplicate`), and a
recording with sound and picture needs one stream holding both kinds of
track, which two packages each opening their own inputs cannot make (LLP
1133.001 D2 rule 3's one runtime owner holds within a package, not across
two). Declaring them in one module and moving them later breaks every
import (LLP 1133.001 D2 rule 5).

So:

- **`@exact/media-capture` declares them,** with an implementation per
  platform, and is the only package that opens an input. Apps import the
  shared names from it; there is no re-export (LLP 1091 has none, and LLP
  1133.001 D4 lets no library carry a binding). `@exact/recording`
  declares `MediaRecorder`'s names, `isTypeSupported` and `audioLevel`;
  the camera declares its preview and `ImageCapture`. An app depends on
  both packages directly, as LLP 1133.001 D4 requires of native code
  (`exact add recording` writes both lines), and `@exact/recording` pins
  `@exact/media-capture` exactly (LLP 1133.001 D9).
- **One capture per device, for the process.** The implementation keeps
  each open input in a process-wide table (one `AVAudioEngine` and its
  input node, one `AudioRecord`, one `MediaStreamTrack` source on the
  web) and gives each session **leases**: a track is a lease, and the
  capture runs while any lease in the process is live. Ending a session's
  last lease does not stop another session's; the capture stops when the
  process's last lease ends. This is LLP 1133.004 D7's shape: the host
  keeps what is one per process and hands sessions their part.
- **Configuration, by the first lease.** What configures the input itself
  (the device, voice processing, the sample rate and channels, Android's
  source and privacy flag, the audio-session mode and options of D7) is
  set by the lease that opens the capture. A later lease on the same
  device with other constraints gets the capture as it is, and its
  `settings` say what applied, as Media Capture's constraints are ideals
  a source may not meet; a development build names the disagreement
  (`media-capture-constraints-differ`). The configuration changes only
  when no lease is live, so one session's take never loses audio because
  another's settings changed. A lease on another device opens another
  capture where the platform allows it (macOS, the web) and fails
  `NotReadableError` where it has one input route (iOS, Android).
- **One track table, with two owners.** A track is a host-owned object
  named by id in one per-session table, the one LLP 1133.003 D2 made for
  `video srcObject=`, so that a `video` (or later an `audio`) finds a
  camera's or a microphone's track as it finds a decoder's. A track has an
  owner that sets its lifetime: a generated track (`VideoTrackGenerator`)
  belongs to the data resource that made it (1133.003 D2, unchanged); a
  captured track belongs to its session (D6). A stream is a set of track
  ids in the same table, so `startMediaRecorder(stream=)` resolves a
  stream to its tracks through the public context (D10). A consumer
  subscribes to a track's buffers (`AVAudioPCMBuffer` and `AVAudioTime`
  on Apple, PCM frames on Android, the `MediaStreamTrack` itself on the
  web) and never opens the input, so a recorder and a level on one track
  share one capture. Android's `MediaRecorder` class, which owns its own
  capture, is not used.
- **Two grants, required per name and argument.** `device.microphone`
  gates `audio=`, `microphoneStatus`, and every name of `@exact/recording`;
  `device.camera` gates `video=` and `cameraStatus`. One does not satisfy
  the other, at bake (`grant-missing`, per name and per literal argument,
  where today one line of an interface's list satisfies every name,
  `contract/cli/src/grants.rs`) and at admission (a computed argument).
  `getUserMedia(audio=true, video=true)` needs both decisions: admission
  takes them one after the other through LLP 1133.002 D9's queue (the web
  and Android ask both in one platform request), fails `NotAllowedError`
  if either is `denied` before any device opens, and releases whatever it
  opened if the second fails (D10 item 9).

How a camera's `AVCaptureSession` relates to this audio capture (whether
a video with sound takes its audio from this fan-out or from the capture
session's own audio output) is the camera RFC's to decide, inside
`@exact/media-capture`; either way a consumer subscribes to a track. On
iOS an `AVCaptureSession` must not configure the app's audio session
itself (`automaticallyConfiguresApplicationAudioSession` false), or it
takes D7's owner's place. The two RFCs must agree on the names, the
shapes, the lease, the one table, the two grants and that flag. LLP
1133.008, written beside this one, builds the video half on this
section, adds `applyConstraints` and a video track's attach point for
outputs, and stops a track no consumer uses (taken here, D6); its
Summary imports the shared names from `@exact/camera`, which this
section's "no re-export" refuses, so one of the two changes before
either is built. §15 question 1 asks the ruling.

### D6 — Objects, threads and lifetimes

- **A handle is the app's once it is delivered.** A stream, track or
  recorder made by a request is the request's until the runner delivers
  the answer that carries its id; only then is it the session's. A reply
  the runner drops (a superseded mutation, a forgotten answer, a refused
  commit, the session ending first) makes the runner tell the
  implementation to dispose of every handle the reply's declared handle
  fields name (D10 item 10), so a `getUserMedia` whose mutation was
  superseded during the prompt never leaves a microphone open with no
  id in the app.
- **Per session.** A delivered stream, track or recorder belongs to the
  session, as the recorder's do today (LLP 1067.000 D3). It outlives the
  answer that made it and a data activation, so a native dev reload of
  TypeScript leaves a take recording. An id from another session is
  `NotFoundError`.
- **Per process.** The input device, its capture and the audio session
  are the process's (D3, D7), so the sample host's two sessions record
  from one microphone, each its own take (LLP 1031; `smoke.mjs host --app
  recorder`).
- **Ending.** A track ends at `stopTrack`, when the platform takes its
  device away (unplugged, `readyState` `ended`), and at session end. A
  recorder whose tracks have all ended stops by itself (`reason`
  `track-ended`), as MediaStream Recording stops a recorder when its
  stream becomes inactive.
- **With no consumer, the microphone stops,** as LLP 1133.008 D3 rules for
  the camera. A track's consumers are its recorders that are not
  `inactive` and its `audioLevel` readers. A live track with none releases
  its lease (the capture stops when no lease in the process is live, and
  the platform's indicator goes out) and reads `muted`, `muteReason`
  `idle`; a new consumer takes the lease again with no new prompt, and is
  a start under D9. So a forgotten track does not leave the room
  recorded, and a recorder paused for an hour keeps its lease, as it must
  to resume.
- **An orderly end finalizes.** The package context gains `destroy` (D10
  item 1). At a native session's end it stops every recorder of the
  session and waits for each file to be finished (Android's
  `MediaMuxer.stop()` included), then ends its tracks. A writer that has
  not finished after a second is closed as it stands and journaled.
- **A process that ends mid-take** (a crash, the system ending it) never
  reaches `destroy`. The Apple implementation writes `audio/mp4` as
  fragmented MP4 (`AVAssetWriter`'s
  [`movieFragmentInterval`](https://developer.apple.com/documentation/avfoundation/avassetwriter/moviefragmentinterval),
  one second), so the file plays up to its last fragment; WAV is readable
  up to what was written. Android's `MediaMuxer` writes MP4's index at
  `stop()`, so an unfinished MP4 there is unreadable: the recipe says so,
  and an app that needs a crash-safe take there asks for Ogg (API 29) or
  WAV.
- **The web promises less.** A page's end (reload, close, navigation) is
  not an orderly end: HTML discards a destroyed document's queued tasks
  ([destroy a document](https://html.spec.whatwg.org/multipage/document-lifecycle.html#destroy-a-document)),
  and MediaStream Recording promises a playable file only for a complete
  recording, its `timeslice` a minimum, not a period
  ([`start()`](https://www.w3.org/TR/mediastream-recording/#dom-mediarecorder-start)).
  So on the web a take ends at `stop` or not at all: the implementation
  appends each slice the browser delivers (asked every second) to the
  file as it arrives, and at `pagehide` asks for the rest; what the store
  received is kept, with no promise of how much or that it plays. The
  recorder's next session reads such a file's `size` and no `duration`.
- **Threads, and a writer that falls behind.** Every entry into a package
  is on the main thread (LLP 1067.000 D4). Buffers arrive on the
  platform's audio thread; the capture computes levels there into a
  lock-free cell and hands each buffer to each subscriber through a
  bounded single-producer queue, two seconds of audio long. Each recorder
  drains its queue on its own serial queue, which encodes and writes.
  Nothing on the audio thread allocates, locks or waits. A recorder whose
  queue is full (its disk or store slower than the input) stops with
  `reason` `error`, `error` `"the writer fell behind"`, and a finished
  file of what it wrote: a take with a hole in the middle is worse than
  one that ends. A `later` that stops a recorder replies from its queue
  when the file is finished.
- **The engine** is made at the process's first capture and stopped when
  its last lease ends; it is not made under the agent.

## 5. The audio session

### D7 — One owner, and a capture is a claim on it

LLP 1096 D8's owner (`AudioSession.swift`) stays the only caller of
`setCategory` and `setActive`. It gains capture claims beside its holders
of sound and its players, and becomes reachable from every package through
its context (D10), since a third party's speech or call module needs it
as much as this one (LLP 1133.001 D8). The recorder's own
`setCategory(.record)` is deleted with its module.

What the owner sets, on iOS and tvOS (the Mac has no session; the web
sets `navigator.audioSession.type`, W3C Audio Session, where it exists):

| Claims | Category | Mode | Options |
|---|---|---|---|
| none | unchanged (LLP 1096 D8) | — | — |
| sound or players only | the app's `audio_session`: `.ambient` or `.playback` | `.default` | none (`.playback` stays non-mixable, LLP 1098 D8) |
| a capture | `.playAndRecord` | the capture's `apple.mode`, else `.default` | the capture's `apple.categoryOptions`, else `.defaultToSpeaker` and `.allowBluetoothHFP` |
| two claims disagreeing | the mode and options of the claim that started the running capture hold until no capture runs (D3's first lease); a development build names the other (`recording-session-conflict`), and its `settings` say what applied | | |

The web's Audio Session type while capturing is `play-and-record`.

Why `.playAndRecord`, and not `.record`, for a capture with no output:
[`.record`](https://developer.apple.com/documentation/avfaudio/avaudiosession/category-swift.struct/record)
silences the app's playback, so a sound or a video started during a take
would be silent, and changing the category when one starts reconfigures
the route and stops the capture engine. `.defaultToSpeaker` keeps the
app's output on the speaker rather than the receiver, where
`.playAndRecord` would otherwise put it, and `.allowBluetoothHFP` offers a
headset's microphone as the platform's own recorders do. Not mixable:
starting a capture interrupts other apps' audio, as Voice Memos does;
`apple.categoryOptions=["mixWithOthers"]` is the word for an app that
should not.

The category changes when a capture starts and when the last ends, and
nowhere else while one runs, so a capture is never reconfigured under
itself. A change of category or route stops a running `AVAudioEngine`.
No engine observes `AVAudioEngineConfigurationChange`: LLP 1096 D8
records why (its observer runs on the engine's queue, which deadlocks
when the main thread tears the engine down). Instead the owner observes
[`routeChangeNotification`](https://developer.apple.com/documentation/avfaudio/avaudiosession/routechangenotification)
on the main queue and tells each holder, and each holder lets its stopped
engine go and opens another on the main thread, the sound arm's "engine
found stopped" path made prompt rather than waiting for the next `Play`.
A voice due during the reopening is journaled `sound skipped: route
change`; one not yet due plays. The capture reopens its own engine the
same way, and its recorders journal the gap (`capture reopened: route
change, N ms`) rather than pause, since nothing interrupted the person.
While a capture runs, a media session (LLP 1098) is under
`.playAndRecord`, not its `.playback`; whether Now Playing keeps it is
measured in stage 2 and recorded.

**Running in the background.** The host keeps the process running while
hidden only when `AudioSession.playsInBackground`, today `.playback`
with `audio` in `UIBackgroundModes`
(`AudioSession.swift`; `PageFacts.suspended`, LLP 1125 D4). It becomes:
`audio` in `UIBackgroundModes`, and either the category is `.playback` or
a capture claim allowed to run in the background is held (D8). Otherwise
`.playAndRecord` would make a recording app with the background mode
suspend, and stop an app's background sequence for the length of a take.

### D8 — Interruptions, the foreground and the background

**Interruptions** (a call, Siri, an alarm; on iPad a closed Smart Folio)
deactivate the session. The owner observes them, by iOS 27's life-cycle
notifications where present and the interruption notification before
([Handling audio interruptions](https://developer.apple.com/documentation/avfaudio/handling-audio-interruptions)),
and tells each claim. While the input is interrupted:

- each track reads `muted` true, as Media Capture's `mute` means ("the
  source is temporarily unable to provide data");
- each recording recorder **pauses** (`state` `paused`, `reason`
  `interrupted`): a declared deviation from MediaStream Recording, which
  records silence while a track is muted. It follows the platform, where
  playback pauses on an interruption and the app decides whether to resume
  (`AVPlayer` does so by itself, by the same Apple article); a take with a
  silent gap the length of a phone call is a tell.
- When the interruption ends the tracks unmute, and the recorders stay
  paused for the app to resume (`resumeMediaRecorder`). The app reads
  `reason` to say why.

Android's capture policy silences an app whose capture another app takes
([Sharing audio input](https://developer.android.com/media/platform/sharing-audio-input)):
`isClientSilenced` sets `muted` and pauses the recorder the same way. On
the web, `mute` is the browser's, and the recorder does what the browser's
does.

**Leaving the foreground,** unsaid:

| Target | Recording continues | Otherwise |
|---|---|---|
| iOS | with `audio` in `host.ios.backgroundModes`: the session stays active and the process runs (D7's background rule), and iOS shows its recording indicator | tracks mute, recorders pause with `reason` `background`, the claim is released; on return the tracks unmute |
| Android | `later`: a foreground service of type `microphone` holding `FOREGROUND_SERVICE_MICROPHONE` ([service types](https://developer.android.com/develop/background-work/services/fgs/service-types)), which the roster's `foreground-service` module provides | as iOS without the mode |
| macOS | yes: a Mac app keeps its input in the background | — |
| web | the browser's (desktop browsers keep a hidden tab's capture; iOS Safari does not) | — |

**Starting in the background** is refused: a `getUserMedia`,
`startMediaRecorder`, `resumeMediaRecorder` or `setTrackEnabled(enabled=true)`
while the app is not in the foreground fails `NotAllowedError`, whoever
called (D9; the foreground is the context's fact, D10 item 3). iOS refuses to start recording in the background
(Apple DTS, [forum 120038](https://developer.apple.com/forums/thread/120038);
no documented exception), and Android's while-in-use rule forbids
starting a microphone service there; a wake never prompts or starts a
capture (LLP 1114.001 D4).

## 7. Permission

### D9 — LLP 1133.002 §4, with one rule for capture

**Declare.** `device.microphone <purposeKey>` (LLP 1133.002 D6). The row
gains its Android column, `android.permission.RECORD_AUDIO`. Derived:
iOS and macOS `NSMicrophoneUsageDescription`, whose text the system prompt
shows; macOS `com.apple.security.device.audio-input`; the web's
`Permissions-Policy: microphone=(self)`; Android `RECORD_AUDIO`. An app
that uses a microphone name, or `getUserMedia` with a literal `audio=`,
without the line is refused at bake (`grant-missing`, per name, D3), and
a computed `audio=` without it fails `NotAllowedError` at admission, so no
binary asks for the microphone without its purpose string.

**Read.** `microphoneStatus().state`, one meaning on every target
(LLP 1133.002 D8):

| Platform state | `state` |
|---|---|
| iOS `AVAudioApplication.recordPermission` `undetermined` | `prompt` |
| iOS `granted`; macOS `AVCaptureDevice.authorizationStatus(for: .audio)` `authorized` | `granted` |
| iOS `denied`; macOS `denied`, `restricted` | `denied` |
| macOS `notDetermined` | `prompt` |
| Android `RECORD_AUDIO`, by LLP 1133.002 D8's history | as geolocation's |
| web `permissions.query({name: "microphone"})` | the same word; `unknown` where the browser does not name `microphone` |

iOS records silence, not an error, without permission
([requestRecordPermission](https://developer.apple.com/documentation/avfaudio/avaudioapplication/requestrecordpermission(completionhandler:))),
so the implementation never treats a running engine as granted; it reads
the state before it starts.

**Ask.** `getUserMedia` is the request; while `prompt` it asks through
`AVAudioApplication.requestRecordPermission` (iOS 17 and later; the
`AVAudioSession` method before), `AVCaptureDevice.requestAccess(for:
.audio)` on macOS, `Activity.requestPermissions` on Android, and the
browser's own on the web. One request at a time, through D9 of LLP
1133.002's queue. Explain and recover as LLP 1133.002 D11 says, with
`openURL("app-settings:")`.

**Who may start a capture.** LLP 1133.002 D12's origin table holds, with
one change: **starting a capture (`getUserMedia`, `startMediaRecorder`,
`resumeMediaRecorder`, and `setTrackEnabled(enabled=true)`, which turns a
silenced track's room audio back on) is refused to a tool invocation and
to a wake in every state, granted included** (`NotAllowedError`,
`person-required`). This is who called; whether the app is in the
foreground is a separate fact with its own refusal (D8). A tool may stop,
pause, disable and read.
Geolocation lets a tool read a position the app is granted, because a
position is a value the app already has the right to. Opening a
microphone records the room the person is in, and the platform's
indicator is the person's only notice of it; an agent acting through the
app's tools must not be able to start that without the person, until the
delegation LLP 1133.002 D12 describes exists and says otherwise. Any of
the app's own code in a foreground session may start one (LLP 1133 §0).
§15 question 2.

`@exact/media-capture`'s declaration has `getUserMedia` with
`"grants": {"audio": "device.microphone", "video": "device.camera"}` (a
grant per argument, required when the argument is present and not
`false`), `"request": true`, `"origin": "app"`, `"foreground": true`, and
`"handles"` naming the answer's stream and track ids.

**The seam additions,** each general, each proved by the out-of-tree
fixture before this package uses it (LLP 1133.001 D8):

1. **An orderly end:** `destroy()` on the implementation, on every native
   host, called before the session's runtime and module are destroyed;
   the host waits for it up to a bound (a second; D6). The web has no
   such end (D6).
2. **The session clock:** `now()` in the context, the agent's under the
   agent, as `ExactModuleContext.now()` is.
3. **The foreground:** the context reports the app's foreground and
   background on Apple and Android (Android's `resumed()` widens to both;
   the web's is `visibilitychange`), and admission reads the same fact for
   a name declared `"foreground": true` (D8).
4. **A path to write, for an object's life:** `{"type": "path", "access":
   "write"}`, admitted against the calling source's `fs.write` as LLP
   1133.006 D8 item 3 admits a read. With `"for": "<handle>"` the file is
   checked out to the handle the call makes, not to the call: the end of
   the mutation that started it does not cancel it (item 3's `AbortError`
   rule does not apply), the session's end finalizes it (item 1), and the
   grant is checked again when the file is finished. On the web the
   host's store appends a slice as a new chunk of the file, without
   copying what is there (`host/web/storage-fs.js`'s `appendFile` copies
   the whole file each time today), and an `audio src=app:/…` reads the
   chunks.
5. **The audio-session claim** (D7): `context.audioSession.claim(mode:,
   options:, background:)`, returning a claim the implementation
   releases, told of interruptions, route changes and the foreground. On
   the web the same object sets `navigator.audioSession.type`.
6. **The track table** (D3): one per session, holding tracks and streams
   with their owners; `add` for the implementation that opens an input,
   and `lookup(id)` and `subscribe(buffer:, ended:)` for one that
   consumes, on every host.
7. **A polled live source:** `"poll": "<option>"`: the runner asks again
   each period of that option on the session clock while a reader reads
   it, keeps at most one ask in flight, and the implementation's answer
   covers the time since the last delivered answer (D1). Motion and the
   other sensors will meet the same seek clock.
8. **Who called, and where the app is:** `"origin": "app"`, admitted from
   a person's input or the app's own code and refused to a tool
   invocation and a wake (`person-required`) in every permission state
   (D9), beside LLP 1133.006 D8's `"person"`; and `"foreground": true`,
   refused while the app is in the background (`NotAllowedError`).
9. **Grants per name and per argument,** at bake and admission (D3),
   where today one line of an interface's list satisfies every name; and
   a request needing several permission decisions takes them in order,
   fails before any device opens if one is `denied`, and releases what it
   opened if a later one fails.
10. **Handles:** `handle<kind>` in a declaration types an id field. A
    reply carrying handles is provisional until the runner delivers it;
    a reply the runner drops makes it call `dispose(ids)` on the
    implementation (D6). Camera sessions, decoders and connections need
    the same rule.
11. **Preferred values reach an implementation that is its own
    substitute** (§10): under the agent each call and poll carries the
    runner's preferred value for that name, if any, beside `agent: true`.

Each is apparatus under `rules/RULES.md` and lands with this ruling.

### D11 — Callers

Contract reads `microphoneStatus`, `mediaStreamTrack`,
`mediaRecorderState`, `audioLevel` and `enumerateDevices` as sources, and
sends the rest from actions. Data code calls every name through its
generated binding (LLP 1133 D6 rule 1), in Promise form. Requests:
`getUserMedia` (it can prompt). `sync`: `microphoneStatus` and
`audioLevel`, on Apple through `call`; elsewhere their synchronous forms
throw `NotSupportedError`. An app that shows a level reads it in Contract;
an app that analyses audio does so in a tier 3 tap, not in data code,
which never sees samples.

### D13 — Cost

An app that does not import the module links none of it, derives no
`RECORD_AUDIO` or microphone key, and loads no page code (LLP 1047.001).
One that does loads it with the app's module after first pixel; nothing
runs before first pixel. Stage 2 records the implementation's size.

**The level's cost decides where the waveform is drawn.** A level at the
default 50 ms is twenty runner commits a second while it is read. The
budget: 2 ms of main-thread time per update (commit, layout and paint of
the waveform), 5% of the main thread at that rate, on an iPhone 17 Pro's
simulator **on the live clock** (the agent's clock skips time and
measures nothing here). Stage 0 measures it first, with a Contract
waveform over a synthetic polled source, before the recorder's own view
is deleted. If it passes, the recorder draws `levels` in Contract. If it
fails, this module ships a view of its own, `<audio-waveform track=…>`,
which reads the track's levels below the runner as `video srcObject=`
reads frames, styled by the author's CSS (`color`, `background-color`),
and stage 0 builds the package views it needs (LLP 1133.001 D1's
`views`) rather than waiting for the camera; `audioLevel` stays tier 1
for a meter.

## 10. The substitute

**The implementation is its own substitute** (LLP 1133.006 D8 item 4):
under the agent each implementation runs, told so, opens no device, asks
the OS for nothing, makes no engine and calls no hatch. The declared
`permission` (`microphone`, the status `microphoneStatus`, its field
`state`, the denial `NotAllowedError`) stays the runner's, so tickets,
`prefer permission.microphone` and `--permission microphone=…` work as
geolocation's do (LLP 1133.002 §6).

Under the agent, on every target with an implementation:

- `getUserMedia` while `granted` answers a stream with one track, `label`
  `"Agent microphone"`, its ids from a counter the session's seed fixes;
  while `prompt`, a `permission` ticket first, as the runner holds it
  before the call reaches the implementation.
- **The signal** is defined once, in the interface's conformance suite:
  at session-clock time *t* ms, the level is the recorder's present
  synthetic formula sampled at step ⌊*t* / 50⌋, so a screenshot after
  `clock +N` is the same on every host and every run. `audioLevel`
  answers it, with D1's rule for the time since the last answer;
  `totalAudioEnergy` and `totalSamplesDuration` integrate it.
- A recorder's `duration` is session-clock time recorded. Its file is
  WAV, 16-bit PCM, of a tone whose amplitude follows the signal, written
  at `stop` into the agent's private store at the requested path, and
  answered as `audio/wav` whatever `mimeType` asked, so a drive can play,
  share and upload a take. Production's encoders are the conformance
  suite's to test, not a drive's.
- **Preferred values reach it** (D10 item 11). `prefer extension
  recording.mediaStreamTrack={"muted":true}` is read as an interruption
  begun, and clearing it as its end; `prefer extension
  recording.audioLevel={"audioLevel":0}` holds the signal at that level.

Why the implementation and not a declaration: a recorder is a state
machine on the session clock that writes a file, and a declared substitute
would need a new vocabulary (handles, elapsed time, a written file) in
the runner and in the web runtime both, for one module. The costs: each
implementation carries a synthetic path, which the conformance suite
holds equal across hosts, as the recorder's smoke does today; and **a
target with no implementation cannot drive the module's captures**. On
such a target (Linux and Windows today) the declared part still answers
under the agent (the permission and `microphoneStatus`, with `available`
false) and every capture call fails `NotSupportedError`, as in
production. LLP 1133.001 §6 drives a module on a target before its
implementation exists; for a module that is its own substitute, that
waits for the implementation. §15 question 5.

**Disclosure:** `state.extensions` lists the session's streams, tracks
(with their subscribers), recorders with their state and path, each
claim on the audio session, and each answer's origin.

**Production:** none of it.

## 11. The consumer: the recorder

### Moving an app's module to a package

The recorder's Swift and page module are deleted; its `app.json` loses
`modules`; its `app.ts` loses its native sources. What each piece became,
which is what a third party moving its own module does:

| The app's module had | The package uses |
|---|---|
| `ExactModule` with `later`, `call` and topics | an implementation class per platform answering declared names; `changed` by name |
| one instance per session, `destroy` | the same, with D10's `destroy` |
| `context.agent`, `now()` | `agent`, D10's `now()` |
| `context.data` and its own `takes.json` | a path the app names, admitted against its grant (D10); the app keeps its own list |
| `setCategory(.record)` | a claim on the host's session (D7) |
| `<waveform-view>`, drawn from its own levels | the app's Contract drawing `levels` (D13 says when that changes) |
| `native.call({op: 'status'})` in TypeScript | `microphoneStatus()` read in Contract, `sync` on Apple |

Every row that is not a renaming is a gap in the public seam that only an
app's module could cross, closed here for every package.

### The recorder after

- `"@exact/recording"` and `"@exact/media-capture"` in a `package.json`,
  the grant `device.microphone purpose.microphone` and `fs.write
  app:/data/takes` (now in `app.ts`'s grants), and no `modules`.
- Contract: the Summary's actions; `Record` disabled while
  `microphoneStatus()` is `denied`, where a line and, on native targets,
  an Open Settings button take its place; a `Pause` button; the waveform
  as a row of bars over `level.levels` (or D13's view); the elapsed time
  from `mediaRecorderState(recorder=recorderId, interval=100)`'s
  `duration`.
- `app.ts`: `takes()` lists `app:/data/takes` with `storage.fs` and keeps
  each take's duration and average level, which `filed` passes it.
- A recorder that stops by itself (its track ended, the session's end)
  shows its saved take from `mediaRecorderState`'s `result`.
