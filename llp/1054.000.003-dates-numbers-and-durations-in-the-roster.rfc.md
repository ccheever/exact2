## Motivation

### What an app does today

- **Time sources.**
  - `now()` is elapsed milliseconds. It moves only in `advance`
    (`runner/src/runner/commit.rs:149-301`).
  - The date arrives as the host fact `exactTime`, at launch only
    (`host/web/glue.js:1353`,
    `host/apple/Sources/ExactKit/Session.swift:908-918`,
    `host/linux/src/app.rs:300-311`).
- **Bluesky** (`~/projects/bluesky-exact2`, at `e686fcc`):
  - **Its clock.** It derives a minute clock (`app.contract:42`). That clock
    moves because the 250 ms `settle` timer (`:499-500`) commits four times
    a second. `every(30000, tick)` (`:250-251`) writes `ticks`, which
    nothing reads.
  - **The clock as an argument.** `clock` is an argument of ten resources
    (`:49-180`). Eight carry it only so that the source rebuilds their
    labels, which re-asks the list each minute (LLP 1054 D8). `unread` and
    `hasNew` poll on it, legitimately.
  - **Its sources wait for the date** before fetching:
    - `data/src/reads.rs:207, 317, 441, 512, 765`;
    - `chat.rs:130, 200`.
  - **Its Rust formats:**
    - `ago` → `now`, `42s`, `5m`, `3h`, `6d`, `Sep 3`, `Sep 3, 2024`
      (`data/src/fmt.rs:123-153`). It has five call sites: post, quote,
      conversation, notification and message (`model.rs:308, 521`,
      `chat.rs:170, 246`, `reads.rs:620`).
    - `date` → `Sep 26, 2026 at 1:02 PM` (`fmt.rs:158-177`; the test is at
      `:273`, and the doc comment's `AM` is a typo).
    - `month_year` → `September 2023` (`fmt.rs:180-200`).
    - `count` → `1.2K` (`fmt.rs:203-220`). It truncates, and it has eight
      call sites.
- **Caltrain.**
  - `formatClockTime`, UTC `h:mm AM`, is the roster's only time formatter
    (`runner/src/stdlib.rs:315-327`).
  - It has two call sites (`apps/caltrain/app.contract:278, 320`).
  - Caltrain's clock is a simulated slot, `nowMs`, so it is not a
    relative-time caller.

### Why the roster, and why the runner has to know

A Contract `fn` can compute Bluesky's label: about 360 plan bytes per call
site (the r1 reviews). It still leaves two problems:
- **Nothing wakes it.** A `fn` over `now()` reads the clock, so it is
  re-evaluated on every commit that moves the clock. In Bluesky that is four
  times a second per mounted row. It doesn't update at all without an app
  timer. Only the formatter knows when its text next changes.
- **The source still formats.** `date`, `month_year` and `count` keep a
  view-model string in the source (LLP 1058 R1).

## Design, part A: the formatters (accepted 2026-09-27; implementing)

Implementation note (Claude (Opus 5.5), 2026-09-28). Landed as specified, with
these differences from the text above:
- **D7's order**: a non-finite argument or an offset past ±1080 minutes is
  `""`; then TimeClip (truncate toward zero, so `-0.5` is the epoch); then the
  shift; then the shifted wall time must fall in years 1–9999, else `""`.
  There is no zero sentinel for `formatTime` or `formatDate`: `0` is
  Jan 1, 1970, as in Intl. A sentinel, if part B keeps one, is
  `formatRelativeTime`'s alone and tests the raw argument before TimeClip.
- **Declared differences from Intl**: a fractional offset is floored (Intl
  accepts only whole-minute offset zones); years outside 1–9999 print `""`
  where Intl prints an era-less `Dec 31, 1` or `Jan 1, 10000`.
- **D9 is table-driven**: a parameter declared as string literals in
  `format.json` (`"medium" | "month-year"`) is checked by the compiler
  (`type-format-style`); part B's `update` can use the same spelling.
- **D8's seam is narrower**: `FormatLink` is `Option<fn(Stdlib, &[Value]) ->
  Option<Value>>`, and `Env` gained only `format`. The use-set scan walks every
  code range through a generated `Plan::each_code`, not one pass over the
  pool, so a malformed range can't hide a call.
- **The core grows**: every web app pays for the scan and D7's range check,
  about +1.3 KB raw / +0.9 KB brotli on Caltrain (unoptimized builds; wasm-opt
  was not installed). Caltrain links 0 B of `exact_runner::format`; the
  capability's own code is about 2.1 KB raw.
- **Tests**: `runner/tests/it/format.rs` (486 date/time and 107 number rows
  from Bun 1.4.2 / ICU 78.1), `contract/cli/tests/it/format.rs`, a use-set
  test, and a web boot refusal (`Unlinked("format")`). Caltrain's tree and
  screenshot are identical before and after; `smoke.mjs web` passes.

### D1 — `formatTime(epochMs, utcOffset, "short") -> string`, in the core

- **What it prints.** The time of day of the shifted instant `epochMs +
  utcOffset × 60,000`, as `Intl.DateTimeFormat("en-US", { timeZone: "UTC",
  timeStyle: "short" })` prints it: `1:02 PM`.
- **Only `"short"`.** `"medium"` has no caller. `long` and `full` print a
  zone name.
- **Core, not `format`.** It replaces `formatClockTime` at the same size,
  plus one multiply-add.
- **Composing.** An app joins a date and a time itself (`${date} at
  ${time}`), because Intl's joiner varies by ICU version.

### D2 — `formatDate(epochMs, utcOffset, style) -> string`

The calendar date of the shifted instant, as `Intl.DateTimeFormat("en-US",
{ timeZone: "UTC", …options })`:

| `style` | options | 2026-09-26 | caller |
|---|---|---|---|
| `"medium"` | `dateStyle: "medium"` | `Sep 26, 2026` | Bluesky's focused post and chat stamp (`fmt.rs:158`) |
| `"month-year"` | `month: "long", year: "numeric"` | `September 2026` | Bluesky's "Joined" (`values.rs:98`) |

- **`"long"` is dropped** (Charlie, 2026-09-27). It returns with RealWorld's
  migration, and it would be a regression there across a daylight-saving
  change (`apps/realworld/app.ts:22-25` uses the browser's zone).
- **Other styles are held** (Refused).

### D3 — `formatNumber(n, "compact") -> string`

`Intl.NumberFormat("en-US", { notation: "compact", roundingMode: "trunc",
signDisplay: "negative" })`:

| n | 0 | −0 | 999 | 1,000 | 1,250 | 1,999 | 12,345 | 999,999 | 1,234,567 | 10⁹ |
|---|---|---|---|---|---|---|---|---|---|---|
| out | `0` | `0` | `999` | `1K` | `1.2K` | `1.9K` | `12K` | `999K` | `1.2M` | `1B` |

- **This is Bluesky's `count` for nonnegative integer counts** under 10⁹.
  It floors fractions and clamps negatives, and Intl doesn't (Astra).
  Bluesky prints 10⁹ as `1000M`, and Intl's `1B` is the answer.
- **Blank at zero stays in the app**: `n > 0 ? formatNumber(n, "compact") :
  ""`.

### D6 — Zone and locale

- **A fixed offset, not the IANA zone.** Zone rules are tzdata, hundreds of
  KB in Rust. Asking the browser's `Intl` would break one-body parity.
- **What that costs.** A past instant on the far side of a daylight-saving
  change is shifted by the wrong hour. D4's relative units are durations and
  never use the offset. Its date fallback uses the runner's offset.
- **`en-US` only**, until an admitted app ships a second strings table and
  shows a date (Refused).

### D7 — Deterministic, bounded input

- **Pure, except for part B.** `formatRelativeTime` also reads the runner's
  clock and `WallTime`. One Rust body serves every host.
- **TimeClip first**: clip the instant, then shift. `-0.5` is `1970-01-01
  00:00` and prints `12:00 AM`.
- **Range.** The shifted instant must fall within years 1–9999.
- **Invalid input gives `""` from every entry.** That covers non-finite
  numbers, out-of-range instants, and a `utcOffset` outside ±1,080
  (`WallTime::validate`, `runner/src/time.rs`). This is a declared difference
  from Intl.
- **`thenMs == 0` gives `""`.** Negative instants are formatted.
- **Declared deviation.** AM/PM follows U+0020, as Bun 1.4.2 prints it. The
  oracle normalizes.

### D8 — Linked by use, the router's way

The router is the model. Routing is reached only through
`RunnerLinks.router`, a function pointer (`runner/src/runner.rs:365-402`).
`ALL` fills it, and the web registers it
(`host/web-capabilities/src/router.rs:8-11`). Format does the same.

- **Bodies.** A runner module, `runner/src/format/`. It uses no
  `core::fmt`.
- **The seam.** `RunnerLinks.format: FormatLink` is an `Option<fn(Stdlib,
  &[Value], &WallTime, f64) -> Option<(Value, f64)>>`. It returns the
  string and the next boundary: ∞ for part A's entries, D5.1 for part B.
  - `Env` gains `format` and `wall`. Part B adds the label report (D5.3).
  - `stdlib::call` (`vm.rs:766`) passes the entries through.
  - The runner's `Env` literals are `runner.rs:1211` (the `env()` helper),
    `settlement.rs:276, 346`, `instance.rs:370` (a struct update), three
    `vm.rs` tests and `instance/collection/tests.rs:96`.
    `canvas2d.rs:665` is canvas's own `Env`.
- **Every path that boots with `ALL` links it**: the native hosts
  (`delivery.rs:34, 60`), the render host, the bake
  (`contract/cli/src/lib.rs:559`) and the tests.
- **The use-set.** `Capability::Format` is the seventh bit (`uses.rs`).
  `uses()` walks each code body for a `Call` of `formatDate` or
  `formatNumber`, plus `formatRelativeTime` when part B lands.
- **The web.**
  - `exact_web::Linked` gains `format`.
  - `host/web-capabilities/src/format.rs` registers it.
  - `contract::web_linked` gains the `Format` arm.
- **Refusal.** A plan that uses `format` against an artifact that doesn't
  link it is refused at boot, `Unlinked("format")`.

### D9 — `style` and `update` must be string literals

- **The check.** Each entry's style, and `formatRelativeTime`'s `update`,
  must be a string literal naming a listed value. Otherwise the compiler
  refuses with `type-format-style`. The precedent is `path()`
  (`contract/types/src/routes.rs:150-163`).
- **Part B does not depend on the literal** for dependencies (D5.2).
- **No shadowing.** A user `fn` with a roster name is refused,
  `contract-fn-shadows-roster` (`contract/types/src/lib.rs:961-971`).
- **Wrappers.** A wrapper `fn` cannot forward a style or an update.

### D10 — `formatClockTime` leaves the roster

- **The migration.** Caltrain's two calls become `formatTime(d.at, 0,
  "short")`.
- **Where it differs.** `NaN` now prints `""`. `-0.5` now prints `12:00 AM`
  (TimeClip), where it printed `11:59 PM` (floor).
- **Diagnostics.** The corpus rejects and
  `contract/cli/tests/it/diagnostics.rs` move to the new name.

## Design, part B: live relative labels (Draft r4)

### D4 — `formatRelativeTime(thenMs, "elapsed", update) -> string`

**The label.** Δ is the label's wall time (D5.1) minus `thenMs`.
- **The style is `"elapsed"`.** It prints the time elapsed, compactly, and
  a date once that is too long ago. Its policy is Bluesky's
  (`fmt.rs:123-153`), not Intl's.
- **Why not `"narrow"`.** Intl's `RelativeTimeFormat` with `style: "narrow"`
  prints `5m ago` (Bun), and a web author would expect that. `"narrow"`,
  `"short"` and `"long"` stay free for Intl's meaning when a caller wants
  `… ago` (Refused).
- **The spellings are Intl's.** A unit is `Intl.DurationFormat("en-US",
  { style: "narrow" })` of `{ unit: n }`: `42s`, `5m`, `3h`, `6d`.

| Δ | `"minute"` | `"second"` | text changes at |
|---|---|---|---|
| < 5 s, or in the future | `now` | `now` | `then` + 60 s / + 5 s |
| 5–59 s | `now` | `42s` | + 60 s / the next second of Δ |
| < 60 min | `5m` | `5m` | the next minute of Δ |
| < 24 h | `3h` | `3h` | the next hour of Δ |
| < 30 d | `6d` | `6d` | the next day of Δ |
| ≥ 30 d, same local year | `Sep 3` | `Sep 3` | the viewer's next New Year |
| ≥ 30 d, earlier year | `Sep 3, 2024` | `Sep 3, 2024` | never |

- **Units truncate**: 119 s is `1m`.
- **The date forms** are `{ month: "short", day: "numeric" }` and
  `{ dateStyle: "medium" }` at the runner's `utcOffset` (D6). Bluesky uses
  UTC today, so this is a correction.
- **Future timestamps** (clock skew) say `now`, as Bluesky does.
- **`update` is `"minute"` or `"second"`**, and it is required.
  - Roster arity is fixed, so it is always written. All three reviewers
    kept it.
  - `"minute"` is the default. The authoring notes and every example use
    it. It says `now` under a minute, because a seconds label that doesn't
    tick is wrong within a second.
  - SwiftUI's `Text(date, style: .relative)` is live by default too.
- **Bluesky.** It may pass `"second"` at its five `ago` sites to keep
  `42s`. Its other labels are `"minute"`.

### D5 — Live labels: one deadline, kept by the runner

1. **The label's clock is quantized.**
   - The grid is q = 15,000 ms for `"minute"` and 1,000 ms for `"second"`.
   - The label reads t = `floor(now_ms / q) × q` from the runner's clock,
     plus `epochAtZero`, and the `utcOffset` from `WallTime`
     (`runner/src/time.rs`). These are runner state the host sets and the
     agent controls. It is not an ambient system read.
   - It returns the text and **the next grid point at which the text
     changes**, as elapsed time. That is D4's last column, moved up to the
     grid.
   - A label is therefore at most 15 s (or 1 s) late. Every deadline sits on
     a shared grid, so wakes coalesce however many rows there are.
   - Until the host says the date (`epochAtZero == 0`), the label is `""`
     and reports nothing. A bake sees the same, so no relative label is
     ever baked.
   - **The seam.** Part A's landing change links the pure entries through
     `FormatLink = Option<fn(Stdlib, &[Value]) -> Option<Value>>` (working
     tree, `runner/src/runner.rs:428`). Part B widens it to D8's shape,
     which also passes `&WallTime` and the clock and returns the boundary.
     That is one signature and its two fillers.
2. **Two dependency inputs**, `Input::Wall` and `Input::Labels`, beside
   `Input::Clock`. There are four places to change, and each is compared as
   the clock is:
   - `Layout` gains `wall()` and `labels()`. `width()` becomes `clock() + 3`
     (`runner/src/instance/deps.rs:72-77`).
   - `inputs()` maps the two new bits (`:266-282`). Today every bit from
     the clock bit on is `Input::Clock`.
   - `Seen` and `Deps::changed` hold and compare the wall (epoch and offset
     bits) and the generation (`:350-352, 419-427`).
   - `Settled` and `unchanged` do the same (`runner/src/runner/settlement.rs:12-20, 202`).

   `wall` changes when `set_time` changes the epoch or the offset.
   `labels` is a generation number, bumped at the deadline (item 4).

   The scan (`deps.rs:390-392`) sets both bits on every `Call` of
   `formatRelativeTime`, and **not** the clock bit. Every call is live, so
   the scan never needs the literal. A plan is never trusted: the VM traps
   `TypeMismatch` on an `update` other than the two listed values. The
   compiler never emits one (D9).

   So a 250 ms timer re-evaluates no label.
3. **Reporting.**
   - **The sink.** The runner keeps `label_due: Cell<f64>`, the minimum
     reported since the last bump. It lives in
     `runner/src/runner/labels.rs`, beside `Env`'s other borrowed state.
     `Env` carries `labels: Option<&Cell<f64>>`.
   - **Who reports.** Only the paths that produce what the tree shows pass
     `Some`: settlement's two `Env`s (`settlement.rs:276, 346`) and
     `update_tree` (`runner/src/runner/lists.rs:58`). `update_tree` covers
     both settled and geometry-only updates. A row that scrolls in reports.
   - **Who doesn't.** The `env()` helper (`runner.rs:1210`) passes `None`.
     So actions (evaluated once), `eval`, and `list_text`'s read-only
     projection of unmounted rows (`lists.rs:24-39`,
     `instance/text.rs:136-145`) report nothing.
4. **The bump**, exact.
   - At the top of `settle` (`settlement.rs:160`), which every commit
     runs: `if now_ms >= label_due { labels += 1; label_due = ∞ }`.
   - Every live site then re-evaluates and reports, so `label_due` is whole
     again.
   - The invariant is that **between commits, `now_ms < label_due`**. Each
     live label's text is constant from its evaluation until the deadline
     it reported, and `label_due` is the minimum of those deadlines.
   - So an incremental update and a full one (`set_full_evaluation`,
     `runner.rs:1149`) show the same text at every commit. That is
     LLP 1005 §8.
5. **The wake.**
   - `timer_due_ms` (`runner.rs:1072-1079`) chains `label_due` with the
     timers and `then`s.
   - `advance_within` (`commit.rs:149-301`) gets one step after its loop.
     When `label_due <= landed`, it calls `commit_again(vec![], "labels")`
     (`settlement.rs:63-79`), which settles and updates with nothing asked.
     `recommit` would return without committing (`:55-57`). The journal
     reads `labels (0 asked again)`.
   - **The step is skipped when the loop broke for a send**
     (`commit.rs:229-231, 283-286`). The clock stays at that timer's time,
     and that commit's own settle already bumped anything due by then. The
     next advance handles the rest after the reply lands, so no request the
     stop preserves is dropped (LLP 1016 D5).
   - **At most one label step per `advance` call**, always the last step. It
     runs no action. `TIMER_FIRE_LIMIT` is never reached on labels' account:
     at the limit, the loop returns before the step.
   - `clock settle` is motion's settle time (`host/web/src/host.rs:629-635`),
     and it is unaffected.
6. **The first date.**
   - `set_time` re-asks only `exactTime` resources (`runner/src/runner/time.rs:68-71`),
     and `recommit` returns without committing when there are none.
   - r4: when the wall changed and any site reads `Input::Wall`, `set_time`
     calls `commit_again(which, "time")`. A plan with a label and no
     `exactTime` resource therefore fills its labels at the first report.
   - The wall change re-evaluates every relative call, so `set_time` also
     resets `label_due` to ∞.
7. **Refusal.**
   - The checkpoint (`commit.rs:16-28`) carries `label_due`, so a refused
     ordinary commit restores it. If it is due, the next frame's label step
     handles it.
   - **A refused label step is used up**, as a timer's tick is
     (`commit.rs:204-205, 260-261`). After `conclude`, `label_due` becomes
     `landed + 60,000`. A persistently refusing app, such as a derive `now()
     >= 60000 ? 1 / 0 : 0`, retries once a minute, never every frame.
   - The generation is not restored. It only counts, so a bump that outlives
     a rollback forces one re-evaluation at the next commit, in both modes.
   - A dev reload starts at `label_due = ∞` and reports at its first update.
8. **Hosts.** The wake needs no host change: every host already schedules on
   `timer_due_ms` and calls `advance` when it is due
   (`host/web/timer-glue.js:4-27`, `Session.swift:1159`,
   `host/linux/src/display.rs:483`). Two changes are needed, though:
   - **Re-tell the time** (LLP 1027.000.000 D2, never built).
     - Why: Apple's `now()` is `CACurrentMediaTime()`
       (`Session.swift:89-90`), which stops while the device sleeps. After
       an hour locked, every label would be an hour young.
     - When: hosts call `set_time` again on resume or visibility, and on a
       system clock or zone change. `set_time` ignores drift under a second
       (`time.rs:60-65`), so an unchanged clock commits nothing.
     - Web: `pageChanged` (`glue.js:349`), which `visibilitychange` already
       drives, also calls `exact_set_time` outside the agent.
     - Apple: `tellTime` (`Session.swift:907-918`) also runs on the
       foreground notifications `PageFacts` already observes
       (`PageFacts.swift:82-90`), and on `.NSSystemClockDidChange`,
       `.NSSystemTimeZoneDidChange` and, on iOS,
       `UIApplication.significantTimeChangeNotification`.
     - Linux has no foreground. It re-tells before each timer wake outside
       the agent (`display.rs:483`).
     - The agent already re-tells after every `clock` (`glue.js:1180`,
       `Session.swift:919-928`).
   - **Advance before delivering.**
     - The problem: the runner's clock moves only in `advance`. An event or
       a reply commits at the last advanced time (web `host.rs:568, 1206`).
       After an idle stretch, a reply's new row would show a label computed
       against a stale clock (`now`, say), and the next frame would correct
       it (`8m`). That is a visible flash.
     - The change: each Rust host's `dispatch_at` and reply path calls
       `advance_timed(now_ms)` first and prepends its receipts, as the web's
       `resize` already does (`host.rs:687-690`). The sites are:
       - web `host.rs:548, 1197`;
       - Apple `host/apple/src/host.rs:786, 708`;
       - Linux `host/linux/src/host.rs:707, 654`.
     - Under the agent, the runner already stands at the host's clock, so
       the extra advance is a no-op.
     - In wall time, an overdue timer then fires before the tap that
       follows it, rather than at the next frame.
9. **Not in resource arguments.** The compiler refuses `formatRelativeTime`
   reached from a resource's arguments, directly or through a derive or a
   `fn`, with `type-relative-in-resource`. It walks them beside
   `check_function_cycles` (`contract/types/src/checks.rs:12`).
   - Why: a label there would re-ask the resource at every bump. That is
     the footgun this RFC exists to remove from Bluesky.
   - The result: a label step asks no resource, by construction.
   - An action may still write a label into a slot. That is a one-time
     snapshot in keyed data, which is what explicit static means (Refused).
10. **Inspection.** `state.time` gains `labelDue` (`null` at ∞) beside
    `epochAtZero` (`runner/src/agent.rs:638`). It is a field on an existing
    read, not an operation.

**What it costs to run.**
- **`"minute"`**: at most 4 label bumps a minute (the 15 s grid), and only
  when some label's text changes. In Bluesky, whose 250 ms timer crosses
  each grid point first, that is zero extra commits.
- **`"second"`**: one bump a second while a mounted second-label is under a
  minute old. Then it falls back to minute boundaries.
- **Each bump** re-evaluates every mounted live label. This is Astra's
  example: 50 minute labels cost at most 200 evaluations a minute (r3's
  design could cost 2,500). Each evaluation is integer arithmetic and one
  short string.
- **Each bump also touches lists.** Each virtualized list with a label in
  its rows takes one ordinary data change:
  - its reorder preview ends (`instance/collection/mod.rs:283-285`);
  - its height estimates are invalidated in O(1) (`:332`), so the host
    re-measures the mounted rows;
  - its revision advances (`:340-348`).

  In minute mode that is at most 4 a minute per list. Bluesky today
  changes its lists' data once a minute, through the re-ask.
- **A label step is an ordinary commit at a new clock.** A derive that
  reads `now()` sees it, as on a timer commit. By D5.9, no resource is
  asked for the label's sake.

**Virtualized lists.** Only mounted rows evaluate, so only they report. A
row that leaves keeps its old deadline in the minimum, which costs at most
one early wake, and that wake re-reports from the rows actually mounted.
There is no timer per row and no state per row.

### Bluesky's migration (acceptance)

In `~/projects/bluesky-exact2`, in its own repository, after part B lands:
- **Arguments.** The eight label-carrying resources lose `clock`. `unread`
  and `hasNew` keep it as a poll key.
- **Guards.** The date guards go, since no source formats against the date
  any more. They are at `reads.rs:207, 317, 441, 512, 765` and
  `chat.rs:130, 200`. Cold load then fetches at boot instead of after the
  date.
- **Timers.** `tick`, `ticks` and `every(30000, tick)` go. The 250 ms
  `settle` timer stays (LLP 1058's concern).
- **Call sites.** The five `ago` call sites become `formatRelativeTime(t,
  "elapsed", …)`. The shapes' `time: string` becomes `createdAt: number`.
- **Acceptance.** The driven check in Tests passes against it.

### What is not new

- No plan field: the literal is in the code.
- No opcode, no host ABI, and no agent operation.
- Caltrain's `formatCountdownMinutes` could report a deadline the same way,
  but its clock is simulated, so it is untouched.

## What an app writes

Today, Bluesky's pattern, compiled as printed with `target/release/contract
build`. It gives 1 slot, 1 derive, 2 resources, 1 action, 1,091 bytes:

```
shape Time
  epochAtZero: number
  utcOffset: number
shape Post
  id: string
  text: string
  time: string

component App
  resource time = exactTime() as shape Time
  state ticks = 0
  derive clock = (time.epochAtZero > 0 ? time.epochAtZero + floor(now() / 60000) * 60000 : 0)
  resource feed = posts(clock) as shape list<Post>
  action tick writes ticks
    ticks = ticks + 1
  task clockwork mount
    every(30000, tick)
  view
    column
      each p in feed key=p.id
        text `${p.text} · ${p.time}`
```

With both parts. **The syntax below is proposed**: none of the four entries
exists at `23a7e269`.
- **How it was compiled.** It compiles today to 0 slots, 2 resources and
  1,194 bytes, with stand-in `fn`s of the same signatures, for example
  `fn formatRelativeTime(t: number, s: string, u: string): string = ""`.
  That checks the syntax, not the behavior.
- **The stand-ins are deleted when the rows land**, because a `fn` with a
  roster name is then refused.
- **Without the formatter lines.** A label-only version with no `time`
  resource is 772 bytes, and D5.6 makes it work.

```
shape Time
  epochAtZero: number
  utcOffset: number
shape Post
  id: string
  text: string
  createdAt: number
  likeCount: number

component App
  resource time = exactTime() as shape Time
  resource feed = posts() as shape list<Post>
  view
    column
      each p in feed key=p.id
        text `${p.text} · ${formatRelativeTime(p.createdAt, "elapsed", "minute")}`
        text (p.likeCount > 0 ? formatNumber(p.likeCount, "compact") : "")
        text `${formatDate(p.createdAt, time.utcOffset, "medium")} at ${formatTime(p.createdAt, time.utcOffset, "short")}`
```

- **`posts` no longer takes the clock**, so a minute passing asks nothing.
- **No `ticks`, no `every`, and no `clock` derive** for labels.

## Refused, with the trigger

| Held | Returns when |
|---|---|
| `update: "static"` | A real caller. The likely design then is Claude's option (b), static relative to a reference instant the app holds in keyed data. For example `formatRelativeTime(t, "elapsed", loadedAt)` against a `loadedAt` slot an action sets. It is a pure function, bakeable, with no state per row. r3's "formatted at the commit that evaluates its site, fresh on remount" was rejected for three reasons: it breaks LLP 1005 §8 (full evaluation refreshes it, incremental doesn't, `settlement.rs:183`); it depends on each host's row window (`rules/DEFERRED.md:291`); and it reads the stale runner clock. |
| Per-boundary label buckets, or one generation per grid | A profile where label re-evaluation, or a list's re-measure at a bump, is a measurable share of a commit. The grid already caps bumps at 4 a minute. |
| Holding a bump while a list's reorder preview is live | A reorderable list that shows a live label. |
| `calendarDiff` | A view branches on a calendar day. It would return an `option<number>`, never `NaN`. |
| `formatDuration` | A view owns a playhead. It would take **seconds** (`host/web/media-glue.js:63`). |
| `formatNumber` `"grouped"`, `"integer"`, `"percent"` | A call site. |
| `formatDate` `"long"`, `"short"`, `"weekday"`, `"full"`, public `"month-day"` | A caller: RealWorld's migration, or Messages once its labels move to the view. |
| Intl's `… ago` (`RelativeTimeFormat`, as `"narrow"`/`"short"`/`"long"`), signed futures (`in 3m`) | A caller who prints them. Typetour's `12m ago` is a literal prop. |
| Other locales | An admitted app that ships a second strings table and shows a date. |
| Named zones (tzdata) | A caller whose past-timestamp labels must be right across daylight-saving changes. |
| A clock-wide wake for `fn`s, or a pattern language | Not planned. A roster entry that knows its boundary is the mechanism. |

## Open questions for Charlie

1. **The name.** r4 uses `formatRelativeTime(thenMs, "elapsed", update)`.
   It keeps your third argument, and it keeps one entry for the relative
   family, where Intl's `"narrow"`, `"short"` and `"long"` can later mean
   `5m ago` as they do on the web. The alternative is
   `formatElapsed(thenMs, update)`. It is shorter and says nothing about
   Intl, but it would be a second entry once `… ago` arrives. Overrule
   either way.
2. **The minute grid.** 15 s means a `"minute"` label is at most 15 s late
   (`1m` shows between 60 s and 75 s), with at most 4 wakes a minute
   however many rows. A 1 s grid (r3) is on time but can wake up to 60
   times a minute. 30 s halves the wakes again. r4 picks 15 s.
3. **Resource arguments.** r4 refuses a label there at compile time (D5.9)
   rather than documenting it. That makes "a label wake asks nothing" a
   guarantee. It costs one typer check.
