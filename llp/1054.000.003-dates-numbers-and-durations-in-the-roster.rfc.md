## Summary

Four roster entries. Three are one **linked capability**, `format`: a plan
that calls none of them links none of their code (LLP 1047).

| entry | where | caller | example |
|---|---|---|---|
| `formatTime(epochMs, utcOffset, "short")` | core | Caltrain, Bluesky | `1:02 PM` |
| `formatDate(epochMs, utcOffset, style)` | `format` | Bluesky (and RealWorld, see D2) | `Sep 26, 2026` |
| `formatNumber(n, "compact")` | `format` | Bluesky | `1.2K` |
| `formatRelativeTime(thenMs, "narrow", update)` | `format` | Bluesky | `5m` |

`formatRelativeTime` reads the runner's own clock, and `update` says whether
the label keeps up with it:
- **`"minute"`** (the recommended default) is live: `5m` becomes `6m` at the
  minute, `3h` becomes `4h` at the hour, and a date label changes only at New
  Year.
- **`"second"`** is live and ticks under a minute.
- **`"static"`** is formatted when its site is evaluated, and not again for
  the clock alone.

The runner keeps one deadline, the earliest boundary among the labels it
has evaluated, and reports it through the `timer_due_ms` every host already
schedules on. There is no app timer, no clock argument, and no host change.
The agent's `clock +N` drives it exactly.

`formatClockTime` leaves the roster. Outputs are `Intl`'s in `en-US`,
measured with Bun 1.4.2 (JavaScriptCore, ICU 78.1). The strings r2 quoted
from Node 26.9.0 (ICU 78.3) agree.

## Motivation

### What an app does today

- **Time sources.** `now()` is elapsed milliseconds. It moves only on a
  commit (`runner/src/runner/commit.rs:149-299`). The date arrives as the
  host fact `exactTime`, at launch only (`host/web/glue.js:1300`,
  `host/apple/Sources/ExactKit/Session.swift:857-865`,
  `host/linux/src/app.rs:303`).
- **Bluesky** (`~/projects/bluesky-exact2`, at `e686fcc`):
  - It derives a minute clock (`app.contract:42`) and ticks it with
    `every(30000, tick)` (`:250-251`).
  - `clock` is an argument of ten resources (`:49-180`). Eight carry it only
    so that the source rebuilds their labels, which re-asks the list each
    minute (LLP 1054 D8). `unread` and `hasNew` poll on it, legitimately.
  - Its Rust formats:
    - `ago` → `now`, `42s`, `5m`, `3h`, `6d`, `Sep 3`, `Sep 3, 2024`
      (`data/src/fmt.rs:123-153`), at five call sites: post, quote,
      conversation, notification and message (`model.rs:308, 521`,
      `chat.rs:170, 246`, `reads.rs:620`);
    - `date` → `Sep 26, 2026 at 1:02 AM` (`fmt.rs:158-177`), for a focused
      post and a chat stamp;
    - `month_year` → `September 2023` (`fmt.rs:180-200`);
    - `count` → `1.2K` (`fmt.rs:203-220`), which truncates, at eight sites.
  - A 250 ms timer (`app.contract:499-500`) advances the clock four times a
    second.
- **Caltrain.** `formatClockTime`, UTC `h:mm AM`, is the roster's only time
  formatter (`runner/src/stdlib.rs:315-327`). It has two call sites
  (`apps/caltrain/app.contract:278, 320`). Caltrain's clock is a simulated
  slot, `nowMs`, so it is not a relative-time caller.

### Why the roster, and why the runner has to know

A Contract `fn` can compute Bluesky's label. The r1 reviews compiled one at
about 360 plan bytes per call site. Local calendar days are two `floor`s, not
civil-from-days. (r2 said otherwise, citing a 1.9 KB figure that was for a
whole date formatter.) The `fn` still leaves two problems.

- **Nothing wakes the label.** A `fn` over `now()` makes its site read the
  clock, so it is re-evaluated on every clock-moving commit. In Bluesky that
  is four times a second per mounted row. It also doesn't update at all
  unless the app keeps a timer running. Only the formatter knows when its
  text will next change, so only a roster entry can tell the runner.
- **The source still formats.** Bluesky's `date`, `month_year` and `count`
  keep a view-model string in the source (LLP 1058 R1). The source has to
  answer again to show one optimistic `+1`.

## Design

### D1 — `formatTime(epochMs, utcOffset, "short") -> string`, in the core

- **What it prints.** The time of day of the shifted instant `epochMs +
  utcOffset × 60,000`, as `Intl.DateTimeFormat("en-US", { timeZone: "UTC",
  timeStyle: "short" })` prints it: `1:02 PM`.
- **Only `"short"`.** `"medium"` has no caller. `long` and `full` print a
  zone name.
- **Core, not `format`.** It replaces `formatClockTime` at the same size,
  plus one multiply-add. Every app already links that body today, so
  Caltrain gains no capability and the core doesn't grow.
- **Composing.** An app joins a date and a time itself, with its own text
  (`${date} at ${time}`). Intl's joiner varies by ICU version: Bun 1.4.2's
  `{dateStyle: "medium", timeStyle: "short"}` gives `Sep 26, 2026 at
  1:02 PM`, and older ICU gives `, `.

### D2 — `formatDate(epochMs, utcOffset, style) -> string`

The calendar date of the shifted instant, as `Intl.DateTimeFormat("en-US",
{ timeZone: "UTC", …options })`:

| `style` | options | 2026-09-26 | caller |
|---|---|---|---|
| `"medium"` | `dateStyle: "medium"` | `Sep 26, 2026` | Bluesky's focused post and chat stamp (`fmt.rs:158`) |
| `"month-year"` | `month: "long", year: "numeric"` | `September 2026` | Bluesky's "Joined" (`values.rs:98`) |
| `"long"` | `dateStyle: "long"` | `September 26, 2026` | RealWorld (`apps/realworld/app.ts:21-25`), **only if** it migrates in the same change |

- **What changes for Bluesky.** Its focused-post line becomes
  `${formatDate(t, time.utcOffset, "medium")} at ${formatTime(t,
  time.utcOffset, "short")}`, the same text.
- **Other styles are held** (Refused). `"month-day"` is used only by D4's
  fallback, where it stays internal.

### D3 — `formatNumber(n, "compact") -> string`

`Intl.NumberFormat("en-US", { notation: "compact", roundingMode: "trunc",
signDisplay: "negative" })`:

| n | 0 | −0 | 999 | 1,000 | 1,250 | 1,999 | 12,345 | 999,999 | 1,234,567 | 10⁹ |
|---|---|---|---|---|---|---|---|---|---|---|
| out | `0` | `0` | `999` | `1K` | `1.2K` | `1.9K` | `12K` | `999K` | `1.2M` | `1B` |

- **This is Bluesky's `count`** for every input under 10⁹. Its crate prints
  10⁹ as `1000M`, and Intl's `1B` is the answer.
- **`signDisplay: "negative"`** prints −0 as `0` (the default prints `-0`).
- **Blank at zero stays in the app**: `n > 0 ? formatNumber(n, "compact") :
  ""`. The source returns `likeCount: number`, and an optimistic `+1` is a
  view change.

### D4 — `formatRelativeTime(thenMs, "narrow", update) -> string`

**The label.** Δ is the wall time now (D5) minus `thenMs`. The one style,
`"narrow"`, is Bluesky's (`fmt.rs:123-153`), and its policy is exact2's, not
Intl's. The spellings are Intl's: a unit label is
`Intl.DurationFormat("en-US", { style: "narrow" })` of `{ unit: n }`, which
gives `42s`, `5m`, `3h` or `6d`.

| Δ | `"minute"` / `"static"` | `"second"` | next boundary |
|---|---|---|---|
| < 5 s, or in the future | `now` | `now` | `then` + 60 s / + 5 s |
| 5–59 s | `now` | `42s` | + 60 s / the next second |
| < 60 min | `5m` | `5m` | the next minute of Δ |
| < 24 h | `3h` | `3h` | the next hour of Δ |
| < 30 d | `6d` | `6d` | the next day of Δ |
| ≥ 30 d, same local year | `Sep 3` | `Sep 3` | the viewer's next New Year |
| ≥ 30 d, earlier year | `Sep 3, 2024` | `Sep 3, 2024` | none |

- **Units truncate**: 119 s is `1m`.
- **The date forms** are `{ month: "short", day: "numeric" }` and
  `{ dateStyle: "medium" }` at the runner's `utcOffset` (D6). Bluesky
  computes them in UTC today, so this is a correction.
- **Future timestamps** (clock skew) say `now`, as Bluesky does
  (`fmt.rs:128-130`).
- **`update`, precisely:**
  - **`"minute"`**: live. Under a minute the label is `now`, because a
    seconds label that doesn't tick would be wrong within a second.
  - **`"second"`**: live, and `42s` ticks each second until the minute.
  - **`"static"`**: the minute column, formatted against the runner's clock
    at the commit that evaluates its site. The site is not re-evaluated when
    only the clock moves. It is re-evaluated when something else it reads
    changes: its row's `thenMs`, the date's first arrival (D5), or the row
    being mounted again (a virtualized list's row that scrolls back in is
    new). "Rendered" means mounted.
- **Why `"minute"` is the default.** The roster has fixed arity, so
  `update` is always written. The authoring notes and every example use
  `"minute"`. It matches what an "ago" label claims, and Charlie's "prob
  not" for seconds. It costs at most one wake per distinct boundary second
  among the mounted labels (D5).

### D5 — Live labels: one deadline, kept by the runner

This is how a label updates without an app timer. It is the only new runtime
mechanism in this RFC.

1. **The wall time is the runner's.** The call reads `epochAtZero` and
   `utcOffset` from the runner's `WallTime` (`runner/src/time.rs:24-31`)
   and `now()` from the clock. It reads them the way `now()` already reads
   the clock, not as an ambient system read. Both are runner state the host
   sets and the agent controls (LLP 1027.000.000 D3: `--epoch`,
   `--time-zone`). Until the host says the date (`epochAtZero == 0`), the
   label is `""`. That is also what a bake sees, so no relative label is
   ever baked.
2. **Two dependency inputs**, beside the existing clock bit
   (`runner/src/instance/deps.rs:350-352, 390-392`):
   - **`wall`** changes when `set_time` changes the epoch or the offset.
     Every relative call reads it, so a blank label fills in once the date
     arrives.
   - **`labels`** is a generation number, bumped when the clock passes the
     label deadline. Live calls read it. Static calls don't.

   Neither call reads the clock bit. So Bluesky's 250 ms timer re-evaluates
   no label, and a live label runs only at its own boundaries. The scan
   tells the modes apart by the literal before the `Call` (D9 guarantees one
   is there). `deps.rs` `changed` and settlement's `unchanged`
   (`runner/src/runner/settlement.rs:266`) compare the two inputs as
   they compare the clock.
3. **Reporting.** A live evaluation returns its next boundary (D4's last
   column) as elapsed time: `boundary − epochAtZero`, rounded **up to the
   next whole second**. The runner keeps one `f64`, `label_due`, which is
   the minimum reported since the last bump. It lives in a `Cell` beside
   `conformed`, because `Env` is borrowed immutably. Sites, derives and
   resource arguments report. An action's evaluation does not: it runs once.
   A live label inside a resource's arguments re-asks that resource at each
   boundary. That is what the author wrote; the authoring notes say not to.
4. **The bump.** At the top of `settle` (`settlement.rs:160`), which every
   commit runs, `if now_ms >= label_due { labels += 1; label_due = ∞ }`.
   Every live site is then re-evaluated, reports again, and `label_due` is
   whole again. Any commit that crosses the deadline absorbs the wake: a
   timer, an answer, a tap.
5. **The wake.** `timer_due_ms` (`runner/src/runner.rs:1014-1021`) chains
   `label_due` with the timers and `then`s. `advance_within`
   (`commit.rs:149`) gets one step after its loop: if `label_due <=` the
   landed clock, one commit with no action, journaled `labels at <ms>`.
   - A label wake is always the **last** step of an advance, and there is
     **at most one** per advance. It runs no action, so nothing between
     commits can observe a label.
   - So an agent's `clock +86400000` fires the day's timers and then one
     label commit. It never meets `TIMER_FIRE_LIMIT` on labels' account.
6. **Hosts don't change.** Web (`host/web/timer-glue.js:4-8`, which clamps
   to 2³¹−1 ms and advances only when due), Apple (`Session.swift:710-711`)
   and Linux (`host/linux/src/display.rs:483`) already schedule on
   `timer_due_ms` and call `advance`. `clock settle` is motion's settle time
   (`host/web/src/host.rs:631-635`) and is unaffected.
7. **Refusal and reload.** The checkpoint carries `label_due` and the
   generation, so a refused commit restores them. A dev reload starts with
   `label_due = ∞`, and its first update reports again.

**What it costs to run.**
- **Rounding** makes a label at most 1 s late, and the runner wakes for
  labels at most once a second, however many rows are mounted.
- **`"minute"`** labels wake once per distinct boundary second. That is at
  most min(rows, 60) a minute, usually far fewer, and zero in Bluesky,
  whose 250 ms timer crosses each deadline first.
- **`"second"`** wakes once a second while a mounted label is under a
  minute old, then falls back to `"minute"`'s rate.
- **Each wake** re-evaluates the live labels and nothing else. No resource
  is asked again.

**Virtualized lists.** Only mounted rows evaluate, so only they report. A
row that leaves keeps its old deadline in the minimum, which costs at most
one early wake. That wake re-reports from the rows actually mounted. There
is no timer per row and no per-row state.

**What is not new.** No plan field (the literal is in the code), no opcode,
no host ABI, no agent operation. `logs` shows each label commit. Caltrain's
`formatCountdownMinutes` could report a deadline the same way, but its clock
is simulated. It is not touched.

### D6 — Zone and locale

- **A fixed offset, not the IANA zone.** `exactTime` now carries
  `timeZone`, but naming a zone needs its rules: tzdata, hundreds of KB in
  Rust. Asking the browser's `Intl` per call instead would make the web
  format differently from native, which breaks the one-body parity that
  makes the browser an oracle.
- **What that costs.** `formatDate`/`formatTime` take the offset as an
  argument (Caltrain passes `0`, Bluesky `time.utcOffset`). D4's date
  fallback uses the runner's. A past instant on the far side of a
  daylight-saving change is shifted by the wrong hour: from summer, a winter
  23:30 shows as 00:30 the next day. D4's relative units are durations and
  never use the offset.
- **When the offset is set.** Hosts set it at launch only (Motivation).
- **`en-US` only.** `resolvedLocale` picks the app's strings table
  (LLP 1060), but no admitted app ships a second table and shows a date. A
  locale's CLDR data waits for one (Refused).

### D7 — Deterministic, bounded input

- **Pure except D5.** `formatTime`, `formatDate` and `formatNumber` read
  only their arguments. `formatRelativeTime` also reads the runner's clock
  and `WallTime`, and nothing else. One Rust body serves every host.
- **TimeClip first.** An instant is truncated toward zero as ECMA-262's
  TimeClip does, so `-0.5` is `1970-01-01 00:00` and prints `12:00 AM`.
- **Range.** The shifted instant must fall within years 1–9999. That
  excludes Intl's era-less years ≤ 0 and years past four digits. Engines
  disagree before 1582 too (proleptic Gregorian); that stays an oracle
  concern, not a range rule.
- **Invalid input gives `""` from every entry.** That covers non-finite
  numbers, out-of-range instants, and a `utcOffset` outside ±1,080
  (`WallTime::validate`, `time.rs:34-45`). Intl prints `NaN` and `∞` for
  numbers and throws for dates. This is declared. Contract stores only
  finite numbers, but an inline `1 / 0` can reach a call.
- **`thenMs == 0` gives `""`.** Zero is the number type's zero, what a
  placeholder row holds. Negative instants are formatted.
- **Declared deviation: AM/PM follows U+0020.** ICU 72+ has U+202F.
  Bun 1.4.2 and Node 26.9.0 print U+0020, as `formatClockTime` always has.
  The oracle normalizes.

### D8 — Linked by use, the router's way

The router is the model. The runner depends on `exact-route` and reaches
routing only through `RunnerLinks.router`, a function pointer
(`runner/src/runner.rs:365-402`). `ALL` fills it, and the web registers it
from `host/web-capabilities/src/router.rs:8-11`. When no entry names it, the
linker drops it. Format does the same.

- **Bodies.** A runner module, `runner/src/format/`, not a new crate. Like
  `surface_record` and `canvas2d`, nothing outside `RunnerLinks` names it.
  It holds civil-from-days (integer-only, Hinnant's), the month tables, the
  compact suffixes, D4's table and boundaries, and no `core::fmt`.
- **The seam.** `RunnerLinks.format: FormatLink`, an `Option<fn(Stdlib,
  &[Value], &WallTime, f64) -> Option<(Value, f64)>>` that returns the
  string and the next boundary (∞ for the pure entries). `ALL` fills it and
  `CORE` doesn't. `Env` gains `format`, `wall` and the label cell.
  `stdlib::call` (`vm.rs:766`) passes the three entries through. `Env` is
  built in nine places (`runner.rs:1152`, `settlement.rs:276, 346`,
  `canvas2d.rs:665`, `instance.rs:381`, three `vm.rs` tests and one
  collection test).
- **Every path that boots with `ALL` links it.** That is the native hosts
  (`runner/src/runner/delivery.rs:34, 60`), the render host, the bake
  (`contract/cli/src/lib.rs:516`) and the tests. Native linking by use comes
  after the web (LLP 1047 §10), so native delivery has no use-set to encode
  yet.
- **The use-set.** `Capability::Format`, named `"format"`, is the seventh
  bit (`uses.rs:20-50`, `ALL` becomes `[_; 7]`). `uses()` adds it when one
  pass of `vm::instructions` over `plan.code` meets a `Call` of
  `formatDate`, `formatNumber` or `formatRelativeTime`.
- **The web.**
  - `exact_web::Linked` gains `format: exact_runner::FormatLink`
    (`host/web/src/link.rs:19-45`), counted in `uses()` (`:62-83`) and
    passed by `runner_links()` (`:123-130`).
  - `host/web-capabilities/src/format.rs` registers it, as `router.rs`
    does, and `ALL` there names it.
  - `contract::web_linked` (`contract/cli/src/logic.rs:99-134`) already
    writes `linked!(…)` from the use-set's names. It gains only `Format` in
    the no-exports arm.
- **Refusal.** On the web, a plan using `format` against an artifact that
  doesn't link it is refused at boot, `Unlinked("format")`, by the existing
  `admit` (`link.rs:133-142`). `EXACT_WEB_LINK=all` links it in
  development.

### D9 — `style` and `update` must be string literals

- **The check.** The compiler checks that the style argument of each entry,
  and `formatRelativeTime`'s `update`, is a string literal naming a listed
  value. Otherwise it refuses with `type-format-style`. The precedent is
  `path()`'s literal route name (`contract/types/src/routes.rs:150-163`).
- **Why it matters beyond validation.** The literal is also how D5's scan
  knows a call's mode.
- **No shadowing.** A user `fn` can't share a roster name: it is refused,
  `contract-fn-shadows-roster` (`contract/types/src/lib.rs:961-971`). (r2
  said such a `fn` shadowed the entry. It doesn't.)
- **Wrappers.** A wrapper `fn` cannot forward a style or an update. Its
  parameters also can't be called `style`, a reserved word.

### D10 — `formatClockTime` leaves the roster

- **The migration.** Caltrain's two calls become `formatTime(d.at, 0,
  "short")`, the same text for every valid instant.
- **Where it differs.**
  - `formatClockTime(NaN)` printed `12:00 AM` through `as i64`
    (`stdlib.rs:316`). `formatTime` prints `""`.
  - `formatClockTime(-0.5)` printed `11:59 PM`, because it floors.
    `formatTime` prints `12:00 AM`, because it truncates (TimeClip).
- **Diagnostics.** The corpus rejects and
  `contract/cli/tests/it/diagnostics.rs:842-843` move to the new name.

## What an app writes

Today, Bluesky's pattern. This compiles (`cargo run -q --release -p
contract -- build`: 1 slot, 1 derive, 2 resources, 1,091 bytes):

```
component App
  resource time = exactTime() as shape Time
  state ticks = 0
  derive clock = (time.epochAtZero > 0 ? time.epochAtZero + floor(now() / 60000) * 60000 : 0)
  resource feed = posts(clock) as shape list<Post>
  action tick writes ticks
    ticks = ticks + 1
  task clockwork mount
    every(30000, tick)
  view
    column
      each p in feed key=p.id
        text `${p.text} · ${p.time}`
```

With r3. **Proposed: the four entries don't exist yet.** It compiles today
(0 slots, 2 resources, 1,170 bytes) with stand-in `fn`s of the same
signatures. The `fn`s are deleted when the rows land, because a `fn` with a
roster name is then refused:


## Open questions for Charlie

1. **The default.** `update` is a required third argument, and everything
   written uses `"minute"`. Would you rather have two arguments with
   `"minute"` implied, and `"second"`/`"static"` spelled as styles
   (`"narrow-second"`)? r3 prefers the explicit argument: it reads plainly
   in review and the compiler checks it.
2. **Bluesky under a minute.** With `"minute"`, a post under a minute old
   reads `now`, where the port prints `42s`, which today is computed against
   a clock up to a minute stale. `"second"` keeps `42s` ticking, at one wake
   a second while a fresh post is on screen. r3 recommends `"minute"`.
3. **`"static"`** is formatted at the commit that evaluates its site, so it
   is fresh again when its row remounts. Is that what you meant by "static",
   or should it be fixed from first mount until the row's data changes? That
   would take per-row state, which r3 avoids.
4. **RealWorld's `"long"` date.** Migrate it in the same change (moving
   formatting out of its TypeScript), or drop `"long"` until it does?
