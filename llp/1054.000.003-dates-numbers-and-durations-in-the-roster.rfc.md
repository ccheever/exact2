# LLP 1054.000.003: Dates, numbers and durations in the roster

**Type:** RFC
**Status:** Draft r2 (r1 reviewed by Claude and Astra, both NOT READY; this revision answers them. Grok's r1 run was cancelled; Grok reviews r2 in LLP 1056's panel)
**Systems:** Roster (`plan/tables/format.json` `stdlib`), a linked capability `format` (a new crate above the runner, reached through `RunnerLinks`; LLP 1047), Contract compiler (a literal check on one argument), Caltrain (migration off `formatClockTime`)
**Author:** Claude (Opus 5.5) for Charlie Cheever
**Date:** 2026-09-26 (r1 and r2)
**Related:** LLP 1054 D8 (the finding); LLP 1054.000 §Not proposed; LLP 1027.000.000 D4 and open question 3 (this answers it); LLP 1027.000 (explicit time); LLP 1005 §5 and LLP 1004 D4/D6 (the roster); LLP 1047 (pay for what you use: the linked tier); LLP 1056 P1 (the plan this serves); LLP 1054.000.005 (`trim`, the same digest bump); reviews `llp/reviews/1054.000.003-004.{claude,astra,grok}.md`

## Summary

Contract can show a timestamp only as a string a data source made. A
relative label ("5m ago") is correct only for the minute it was made in. So an
app that shows one passes a clock into every list resource, and each list
is re-asked every minute to rebuild its labels. Bluesky does this for eight
list resources (LLP 1054 D8). Its `unread` and `hasNew` take the clock as a
poll key, which is legitimate and stays.

LLP 1027.000.000 D4 already says where such text belongs: "In Contract, as a
derive over `time.epochAtZero + now()`… not a request". Its open question 3
asks whether Contract gets a date formatter. This RFC answers **yes**, with
six roster entries in one **linked capability**, `format`. A plan that calls
none of them links none of their code (LLP 1047).

| entry | fixture | example |
|---|---|---|
| `formatDate(epochMs, utcOffset, style)` | Bluesky, RealWorld, Messages | `"Sep 26, 2026"` |
| `formatTime(epochMs, utcOffset, style)` | Caltrain, Messages, Bluesky | `"1:02 PM"` |
| `formatRelativeTime(thenMs, nowMs, style)` | Bluesky, Typetour | `"5m ago"` |
| `calendarDiff(thenMs, nowMs, utcOffset, unit)` | Bluesky (same year?), Messages (yesterday?) | `1` |
| `formatNumber(n, style)` | Bluesky, Weatherlight, RealWorld | `"1.2K"`, `"12,345"`, `"42%"` |
| `formatDuration(ms, style)` | Charlie's request; video UIs | `"3:05"` |

Each output is what `Intl` prints in `en-US` for the same (value, unit) or
date. The browser, checked through a pinned Node/CLDR, is the test oracle.
Two things are exact2's policy, not Intl's, and are marked as such: how a
relative duration picks its unit, and the `timer` duration style.
`formatClockTime` leaves the core, and Caltrain migrates.

## Motivation

### What an app does today

- **Time sources.** `now()` is elapsed milliseconds (`runner/src/stdlib.rs:50`).
  The date arrives as the host fact `exactTime`, with `epochAtZero` and
  `utcOffset` (`runner/src/time.rs:9-11`).
- **Caltrain.** The only time formatter in the roster is Caltrain's
  `formatClockTime`, UTC `h:mm AM` (`stdlib.rs:113-126`).
- **Bluesky** (outside the repo):
  - It derives `clock` (`app.contract:42`) and passes it to `homeFeeds`,
    `authorFeeds`, `threads`, `notes`, `results`, `convos`, `chats` and
    `session`, so each is re-asked every minute
    (`runner/src/runner/settlement.rs:385-405` reuses an answer only when
    the arguments are equal).
  - Its Rust makes `"5m"`, `"Sep 3"` / `"Sep 3, 2024"` and `"1.2K"`
    (`data/src/fmt.rs:112-145, 192-209`).
- **RealWorld** makes `"September 26, 2026"` in TypeScript with a
  hand-written month table (`apps/realworld/app.ts:21-25`), and shows
  counts raw (`app.contract:447`).
- **Messages** stores the calendar-relative labels as fixtures:
  `"9:41 AM"`, `"Yesterday"`, `"Monday"` (`apps/messages/app.ts:10-15`).
- **Weatherlight** rounds and appends `%` in TypeScript seven times
  (`apps/weatherlight/app.ts:102-112`).

### The alternatives, weighed

**A labels resource from a pure source.** It re-answers once a minute, but a
row inside `each p in feed.posts` can't find its own label. Contract has no
list indexing (LLP 1054 L5), and a child component can't own a per-row
resource (`type-child-resource`). Astra points out that nested `each`/`when`
can join the two lists. That works, but it is O(rows²) in the view.

**Static labels from the source, with a `fn` in the view to pick one.** The
reviews' strongest alternative, and it works today:
- The source returns `createdAt: number` plus the time-invariant strings
  `"Sep 3"`, `"Sep 3, 2024"` and `"1:02 PM"`.
- A Contract `fn` over `floor` chooses `"now"`, `"5m"`, `"3h"` or the date
  label from `nowMs - createdAt`.
- The Claude review compiled Bluesky's exact `ago` this way, at +360 plan
  bytes per call site.

It fixes the re-ask. What it leaves:
- the view-model leakage LLP 1056 R1 names (the source still formats the dates);
- a copy of the logic at each call site (plan size is wasm size, LLP 1054 L10);
- no answer for number grouping, or for local calendar days, which need
  civil-from-days arithmetic. The Claude review built one from `fn`s at about
  1.9 KB per call site.

This RFC recommends the roster for those parts, and the `fn` route for
anything an app wants that the roster doesn't cover (Bluesky's bare `"5m"`,
below).

**Cost of the roster.** Opus noted that roster bodies were linked into every
app, because `stdlib::call` is one `match`. D8 makes them a linked capability,
so an app that uses none of them pays nothing, and the objection goes away.

## Design

### D1 — `formatDate(epochMs, utcOffset, style) -> string`

The calendar date of the **shifted instant** `epochMs + utcOffset × 60,000`
in the proleptic Gregorian calendar, as `Intl.DateTimeFormat("en-US", options)`
with `timeZone: "UTC"` formats that instant.

| `style` | Intl options | 2026-09-26 | fixture |
|---|---|---|---|
| `"medium"` | `dateStyle: "medium"` | `Sep 26, 2026` | Bluesky's other-year label |
| `"long"` | `dateStyle: "long"` | `September 26, 2026` | RealWorld |
| `"month-day"` | `month: "short", day: "numeric"` | `Sep 26` | Bluesky's same-year label |
| `"weekday"` | `weekday: "long"` | `Saturday` | Messages |
| `"short"` | `dateStyle: "short"` | `9/26/26` | Messages' older-than-a-week label |

`"full"` is dropped: it had no fixture (both reviews).

### D2 — `formatTime(epochMs, utcOffset, style) -> string`

One style, `"short"`: `timeStyle: "short"`, e.g. `1:02 PM`. Fixtures are
Caltrain, Messages and Bluesky. `"medium"` is dropped for lack of a fixture.
`long` and `full` print a zone name, which the runner doesn't have. A date
and a time are joined by the app, with Intl's joiners: `" at "` after
`"long"`, `", "` after `"medium"`/`"short"`.

### D3 — `formatRelativeTime(thenMs, nowMs, style) -> string`

One style, `"narrow"`. Its fixtures are Bluesky and Typetour's `"12m ago"`.
`"short"`/`"long"` are dropped for lack of a fixture.

1. **Unknown date.** If `nowMs ≤ 0` or `thenMs ≤ 0`, the answer is `""`.
   `epochAtZero` is 0 until the host says the date.
2. **Future.** If `thenMs > nowMs` (a client-set `createdAt` with clock skew),
   the answer is `"now"`. Intl would say `"in 3s"`, which Bluesky
   deliberately doesn't show (`fmt.rs:117-120`). This is exact2's policy.
3. **Now.** If Δ = `nowMs − thenMs` is under 1,000 ms, the answer is `"now"`.
   That is Intl's `numeric: "auto"` for 0 seconds.
4. **Otherwise, exact2's buckets.** Intl formats a (value, unit) pair and
   doesn't choose the unit, so the choice is exact2's. Δ is truncated:

| Δ | unit | value |
|---|---|---|
| < 60 s | second | ⌊Δ / 1 s⌋ |
| < 60 min | minute | ⌊Δ / 1 min⌋ |
| < 24 h | hour | ⌊Δ / 1 h⌋ |
| < 30 d | day | ⌊Δ / 1 d⌋ |
| < 365 d | month | max(1, ⌊Δ / 30.4375 d⌋), Δ unfloored |
| otherwise | year | max(1, ⌊Δ / 365.2425 d⌋), Δ unfloored |

   The pair is rendered as `Intl.RelativeTimeFormat("en-US", { style:
   "narrow", numeric: "always" }).format(−value, unit)`: `1s ago`,
   `5m ago`, `3h ago`, `2d ago`, `2mo ago`, `3y ago`.

The months-and-years rows are approximations. An app that wants the calendar
switches to a date past some age, as Bluesky does at 30 days (What an app
writes).

**Bluesky's bare `"5m"`** has no Intl spelling and one fixture. It stays an
app `fn` (the reviews). The roster doesn't grow a `"narrow-bare"`.

### D4 — `calendarDiff(thenMs, nowMs, utcOffset, unit) -> number`

The number of local calendar `"day"`s or `"year"`s from `thenMs`'s shifted
date to `nowMs`'s: 0 is today or this year, 1 is yesterday or last year.
This replaces r1's `calendarDays` and adds the year the Claude review found
missing (`"Sep 3"` versus `"Sep 3, 2024"`).

- **Bad input.** Any invalid argument (D7) gives `NaN`. It is a `number`, so
  there's no type contradiction (Astra's blocker). Every comparison with
  `NaN` is false, so a `c == 0 ? … : c == 1 ? … : …` chain falls through to
  its last branch, which the app points at a formatter that prints `""` for
  the same bad input.
- **Offset semantics.** This is **fixed-offset** calendar arithmetic, not
  the viewer's historical calendar. The `utcOffset` of *now* is applied to
  both instants. So a timestamp from before a daylight-saving change is
  shifted by the wrong hour. From summer, a winter timestamp at 23:30
  local shows as 00:30 the next day. Around a change, "yesterday" can be
  off by one for timestamps within an hour of midnight (Astra's Los Angeles
  example). Named zones need tzdata (hundreds of kilobytes), which is refused
  until an app needs it. The offset is also fixed at launch on all three
  hosts. None of them watches for zone changes (`Session.swift:787-790`,
  `glue.js:1362`, `host/linux/src/app.rs:288-296`).

### D5 — `formatNumber(n, style) -> string`

`Intl.NumberFormat("en-US", options).format(n)`:

| `style` | Intl options | examples | fixture |
|---|---|---|---|
| `"grouped"` | *(defaults: up to 3 fraction digits)* | `12,345.679`, `0.5` | RealWorld counts |
| `"integer"` | `maximumFractionDigits: 0` | `12,346`; 2.5 → `3`; −2.5 → `-3` | Weatherlight temperatures |
| `"compact"` | `notation: "compact"` | `999`, `1.2K`, 1,250 → `1.3K`, `12K`, 999,999 → `1M`, `1.5M`, `1B` | Bluesky counts |
| `"percent"` | `style: "percent"` | 0.42 → `42%`, 0.425 → `43%` | Weatherlight |

- **Rounding is Intl's.** It is half away from zero, applied to the shortest
  round-trip decimal of the double, so 1.005 at two digits is `1.01`, where
  `toFixed` gives `1.00`. The runner already prints shortest decimals
  without `core::fmt` (`exact_num::Shortest`), and rounding operates on
  those digits.
- **Compact differs from Bluesky's crate**, which truncates (1,250 → `1.2K`).
  Intl rounds. This RFC follows Intl.
- **Edge values are Intl's:** `NaN`, `∞`, `-∞`, `-0`.

A count isn't time-varying, so the source could format it (the Claude
review). The case for the roster is LLP 1056 R1: a source returns
`likeCount: number`, and one optimistic `+1` doesn't mean re-formatting in
two languages.

### D6 — `formatDuration(ms, style) -> string`

The sign, then |ms| split into whole hours, minutes and seconds, formatted
as `Intl.DurationFormat("en-US", { style })`. Milliseconds are truncated and
there are no days (26 h is `26:00:09`). Negative durations are signed
(`-1:23:45`). An all-zero duration uses `secondsDisplay: "always"` (`0s`),
which is itself an Intl option.

| `style` | 1:23:45 · 3:05 · 0:07 · 0 |
|---|---|
| `"digital"` | `1:23:45` · `0:03:05` · `0:00:07` · `0:00:00` |
| `"timer"` *(exact2's)* | `1:23:45` · `3:05` · `0:07` · `0:00` |
| `"narrow"` | `1h 23m 45s` · `3m 5s` · `7s` · `0s` |

- **`"timer"` is the media-player form.** It is `"digital"` with the hours
  omitted below one hour and the minutes then unpadded. It has no Intl
  spelling and is tested against a table.
- **Why here.** A player's position is time-varying and lives in the view
  (`timeupdate`, `contract/analyze/src/lib.rs:427`). A source can't format it
  without being re-asked every frame. The in-repo video player uses native
  controls today. Charlie asked for this on 2026-09-26.
- **Dropped:** `"short"`/`"long"`, with no fixture.

### D7 — Deterministic, locale-free, bounded input

- **Pure.** Every input is an argument. Nothing reads a clock, a zone
  database or a locale (LLP 1027.000 D1). One Rust body serves every host.
- **`en-US` only**, like the rest of the roster (LLP 1005 §5). A locale waits
  for a launch fact (LLP 1053 G9).
- **Range.** A date input whose shifted instant falls outside years
  1–9999 is invalid. That excludes Intl's era-less years ≤ 0, five- and
  six-digit years, and the pre-1582 calendar disagreement between engines
  (the Claude review). Non-finite inputs and `utcOffset` outside ±1,080
  are invalid. Unlisted styles are refused at compile time (D9).
- **Invalid input** gives `""` from every string entry, and `NaN` from
  `calendarDiff` (D4).
- **Declared deviation: AM/PM is preceded by U+0020.** ICU 72+ uses U+202F,
  engines patched it back unevenly, and Node 26.9.0 prints U+0020.
  `formatClockTime` always has. The oracle normalizes.

### D8 — Linked by use

The six entries are the linked capability `format` (LLP 1047 D1), beside
`router`, `markdown`, `motion` and `collections` (`runner/src/uses.rs:19-38`).

- **The use-set.** `exact_runner::uses` adds `Capability::Format` when the
  plan's code calls any of the six. That is a scan of `Call` operands, and
  the plan format doesn't record it.
- **The seam.** The bodies live in a crate above the runner (`exact-format`).
  The runner reaches them through `RunnerLinks.format`, an
  `Option<fn(Stdlib, &[Value]) -> Option<Value>>`, beside `router`
  (`runner/src/runner.rs:335-343`). The generated entry fills it when the
  use-set names `format` (`contract::web_linked`, `contract/cli/src/logic.rs:63-93`,
  and the Apple and Linux entries). The runner's `Cargo.toml` doesn't name
  the crate.
- **Refusal.** A plan using `format` against an artifact that doesn't link
  it is refused at boot, `Unlinked("format")` (LLP 1047 D6).
  `EXACT_WEB_LINK=all` links it in development (D7).
- **Size** is measured when it lands, raw and brotli-11, for Caltrain (links
  it) and the video player (doesn't), in 1047's table.

### D9 — `style` and `unit` must be string literals

The compiler checks that the style argument of `formatDate`, `formatTime`,
`formatRelativeTime`, `formatNumber` and `formatDuration`, and the unit
argument of `calendarDiff`, is a string literal naming a listed value.
Otherwise it refuses with `type-format-style`.

- The check runs after name resolution and arity, so a user `fn` of the
  same name shadows it as any roster name is shadowed
  (`contract/types/src/lib.rs:625`).
- The precedent is `path()` / `routes::location`
  (`contract/types/src/routes.rs:123-163`).
- **Limitation, stated:** a wrapper `fn` cannot forward a style parameter.
  `fn when(t, s) = formatDate(t, 0, s)` is refused, even when it is called
  with a literal.

### D10 — `formatClockTime` leaves the roster

Caltrain's two calls become `formatTime(t, 0, "short")`. That is the same text
for every valid instant, but not for invalid ones:
- `formatClockTime(NaN)` printed `"12:00 AM"` through `as i64`
  (`stdlib.rs:115`);
- `formatClockTime(-0.5)` printed `"11:59 PM"` where Intl prints `12:00 AM`;
- both now follow D7.

The corpus rejects and `contract/cli/tests/it/diagnostics.rs:842-843` move to
the new name. This is cleanup, not a NOT-DOING trade. The roster's gate is
its fixture rule.

## What an app writes

```
resource time = exactTime() as shape Time
derive minute = time.epochAtZero > 0 ? time.epochAtZero + floor(now() / 30000) * 30000 : 0
action tick writes ticks
  ticks = ticks + 1
task clock mount
  every(30000, tick)

fn when(t: number, n: number, off: number): string = n - t < 2592000000 ? formatRelativeTime(t, n, "narrow") : calendarDiff(t, n, off, "year") == 0 ? formatDate(t, off, "month-day") : formatDate(t, off, "medium")
…
text when(p.createdAt, minute, time.utcOffset)
```

- **A derive, not a slot the tick writes.** It changes the moment `exactTime`
  arrives, and dependents re-run only when its value changes
  (`runner/src/instance/deps.rs:276-289`). r1's slot showed blanks for up to
  30 s after launch (both reviews).
- **The tick** only moves the clock. `now()` advances on timer commits
  (`runner/src/runner/commit.rs:143-243`).
- **Resolution.** A 30 s tick keeps labels within 30 s. Seconds-level labels
  need a 1 s task and pay for it. An app with a 30 s tick shows `"now"`
  under that granularity with `n - t < 30000 ? "now" : …`, rather than a
  frozen `"5s ago"`.
- **Feeds no longer take the clock.** `homeFeeds` and the rest lose their
  `clock` argument. `unread`/`hasNew` keep it as a poll key.

## Costs

- **Plan format.** Six `stdlib` rows added and one removed, together with
  `trim` (LLP 1054.000.005): one `FORMAT_DIGEST` change, one re-bake, one
  update cohort (`bake/src/compat.rs:297-300`). No opcode.
- **Code.** A new crate, `exact-format`: civil-from-days (integer-only,
  Hinnant's), name tables, the `en` plural rule, shortest-decimal rounding,
  and six formatters. It uses no `core::fmt`. The existing `format!` calls
  in `stdlib.rs:54, 66, 125` belong to the entries that stay or leave, and
  aren't copied (r1 wrongly said the file avoided `format!`).
  `RunnerLinks.format`, the use-set arm, and the entry generation for web,
  Apple and Linux.
- **Compiler.** The literal check and one diagnostic.
- **Nothing crosses the data seam.** The hosts already deliver `exactTime`.

## Tests

- **Oracle table.** Expected strings, derived once from Node 26.9.0 / ICU
  78.3 and reviewed, written as a Rust test table: data in a test, not a
  generated file (RULES' generated-file rule).
  - every style over about 200 instants: month and year ends, leap days,
    years 1 and 9999, negative epochs within range, offsets −720, 0, +345,
    +840;
  - `formatRelativeTime` at each bucket edge (999 ms, 1 s, 59.999 s, 60 s,
    29.999 d, 30 d, 60.9 d, 364.999 d, 365 d, 730 d), plus future inputs;
  - `formatNumber` rounding cases (1.005, 2.5, −2.5, 1,250, 99,950,
    999,999, −0, NaN, ∞);
  - `formatDuration` at 0, 7 s, 3:05, 59:59, 1:00:00, 26:00:09, negative.
- **`calendarDiff`.** Across local midnight in positive and negative offsets,
  across a year boundary, and `NaN` for invalid input.
- **Invalid input.** Every string entry gives `""` outside the range.
- **Compiler.** A non-literal, unknown or forwarded style refuses. A user
  `fn` named `formatDate` shadows the entry. `formatClockTime` is unknown.
- **Capability.** A plan without the six links no `exact-format` symbol (an
  artifact check, as for Markdown). A plan with them against a
  non-linking artifact is refused at boot. `EXACT_WEB_LINK=all` links it.
- **Runner.** A view site calling `formatRelativeTime(p.at, minute,
  "narrow")` re-evaluates on a timer commit while the resource that supplied
  `p` is not asked. LLP 1056 P6's `asks` shows it.
- **Caltrain.** `bun scripts/smoke.mjs web` is unchanged after migration.

## Refused

- **A pattern language, other locales, named zones, an ambient wall
  clock.** As r1, for the reasons given there.
- **Styles without a fixture:** date `full`, time `medium`, relative
  `short`/`long`, duration `short`/`long`, and `"narrow-bare"`. Each is
  added by fixture.
