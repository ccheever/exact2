## Summary

A supported CSS property keeps its meaning when a node enters a native scroll
view, a navigation controller, a sheet, an inline paragraph or an embedded
session. An author never repeats `color` on every text node, never perturbs
layout to force a repaint, and never adds a platform branch to recover a
documented default.

Messages proved the boundary is not dependable yet with one property —
`color`, which the kernel now inherits through logical ancestors (LLP 1001
§6) — and the code shows the repair is a special case: `text_color()` and
`spellcheck()` are the only two inherited getters, hand-written, uncached,
with **no invalidation in the kernel** (an ancestor's write dirties the
ancestor alone; the Apple host re-derives every descendant per frame to
notice), and **no `inherited` metadata in the schema** at all. The ten other
CSS-inherited rows the kernel has — `font_size`, `font_weight`,
`font_style`, `font_family`, `line_height`, `letter_spacing`,
`font_variant_numeric`, `direction`, `white_space`, `text_align` — do not
inherit on native hosts; the Markdown readers thread them through as props
to every run (`queue/`, 2026-09-08). That is the next failing property, with
two consumers, and it is this RFC's first slice.

The decisions: **inheritance is schema metadata and one generated
mechanism** (D1), **the first slice is the text rows into inline runs** (D2),
**authored presence and computed value stay distinct** (D3), **the kernel
owns invalidation, with two reasons** (D4), **`light-dark()` stays a pair
until the painting host** (D5, LLP 1034 restated with the appearance-change
rules), **text geometry measured is text geometry painted, with the
baseline as the one declared remainder** (D6), **clipping composes for
paint and hit-test, held by a fixture that does not exist yet** (D7),
**comparisons declare fonts, scale and tolerance first** (D8), **a
declared-but-unimplemented prop is deleted** (D9), and **two `queue/` defects
are semantic and two are not** (D10).

## 1. Motivation — the boundary as the code has it

**Colour.** The root declared `color="light-dark(#000000, #ffffff)"`; the
native inbox heading and sender names painted black on a cold dark launch;
the browser inherited. `NodeRef::text_color()` (`kernel/src/kernel.rs:77-87`)
now walks `arena.parent` until a slot's *own* mask has `TextColor`, else the
schema default; it preserves the pair. The Apple projection resends a
descendant's dictionary when its computed colour changes
(`host/apple/src/host.rs:707-730`, the comment: "Ancestor color changes and
reparenting can affect an otherwise untouched descendant"). Held by
`kernel/tests/apply.rs:906` (two levels, reparent, cleared overrides fall
back up the chain) and `host/apple/tests/host.rs:263` (the pair reaches an
untouched descendant and an `input`; an overriding subtree is not resent; a
resize emits no style op).

**What the repair does not do.** `txn::style_changed` marks only the written
slot (`kernel/src/txn.rs:552-572`); `SetChildren` dirties the two parents
and touches nothing beneath (`txn.rs:475-492`). So the kernel's own receipt
cannot name a descendant whose inherited colour changed; the host diffs.
The schema's row attributes are `bit, field, codec, admitsAuto, layout,
text, default` (`kernel/build.rs:57-69`) — there is no `inherited`, and
`grep inherit kernel/tables/schema.json` is empty. Eleven rows carry
`text: true`; `text_color`, `text_align`, `clip_path` carry neither `layout`
nor `text`.

**Runs.** `arena.text_runs` builds each run's `TextStyle` from *that child's
own* `StyleProps` (`kernel/src/arena.rs:255`, recursing at `:284-288`); the
Apple run builder reads each node's own numbers (`NodeText.swift:49-58`).
Colour is the one row that reaches a run from its paragraph. The readers
(`apps/markdown`, `apps/llp`) pass `font-size`/`line-height` as props to
every run because of it (LLP 1033 D6; `queue/` 2026-09-08).

**Geometry.** Taffy's rounding is off (`kernel/src/layout.rs:64-69`) and the
fixture asserts `(0.25, 80.125, 120.5, 86.625)`, a half-point edit moving a
sibling by exactly 0.5, idempotent re-layout and rehydration equality
(`kernel/tests/apply.rs:106`). Apple text measurement preserves an
*authored* fractional line height; the intrinsic width and a `normal`
paragraph height are still ceiled (`Text.swift`, "keep intrinsic width and
`normal` height measurement separate: changing their rounding also changes
wrapping and the established host parity" — removing them changed
Caltrain's scroll extent and canvas readback) and painted baselines still
round (`baseline.rounded()`, documented provisional). A UILabel/CoreText/
WebKit comparison found no single baseline adjustment that matches both
(`queue/`). One host test allows a 0.5-point tolerance on a 16.25-point line
measured through the registered callback (`host/apple/tests/host.rs:556-559`);
with the kernel's rounding gone that tolerance hides nothing and is
tightened in slice 1.

**Clipping.** `clip.rs` parses and canonicalizes `path()` with absolute
`M L Q C Z` (`kernel/src/clip.rs:13-64`); the commands cross the batch as
JSON (`host/apple/src/style.rs:64-74`); `ClipPath.swift` builds one `CGPath`
and a `CAShapeLayer` mask; hit-testing rejects points outside the path
before walking children (`NodeViewIOS.swift:550`, `NodeViewMac.swift:562`);
the web emits the declaration. **No host test covers clip-path**, Linux
does not paint it, and nothing composes the clip with a transform and a
scroll offset under a single fixture.

**Appearance.** Colour rows are `ColorValue::{Fixed, LightDark}`
(`kernel/src/style.rs:372-379`); the web emits the function
(`css.rs:204-207`) except `shadow_color`, resolved to its light half because
`box-shadow` cannot carry one (`css.rs:52-66`, declared); Apple resolves
against the owning view's appearance (`NodeViewMac.swift:600-623`,
`NodeViewIOS.swift:611-620`). On an appearance change macOS invalidates the
paragraph spec, repaints and re-applies field colours, guarded by
`hasSchemeColor` (`NodeViewMac.swift:635-642`); iOS does the same
**unconditionally** (`NodeViewIOS.swift:368-373`). Text engine caches are
keyed by a colour-carrying `Spec`, metric keys are colour-stripped
(`Text.swift:93-105`) — so an appearance change repaints and never
remeasures, which is the right shape. Native editors do not inherit a
scheme-aware ancestor colour (`queue/`, "editable text color").

**Focus.** The kernel has no focus opcode (`schema.json:1188-1220`, eight
ops). `focus("id")` is a command the host executes after the batch
(`Session.swift:539-551`, `PresenterIOS.swift:216-230`); refusals are
silent. `initialFocus` (prop 38) has no handler in any host or the runner.
The lifecycle is 1035.001's; the kernel-side facts are D9's.

**Not a semantic defect.** The long native bubble is ~262 points wide,
Exact's 277 on the iPhone and 277.5 in Chrome, with the same three lines,
and a browser probe keeps 277.5 under flex, block, inline-block,
fit-content and grid. Native Messages shrinks a balloon to its wrapped
ink; CSS does not. Narrowing the native kernel alone would create a host
disagreement; the ask is a product design (D10).

## 2. Decisions

### D1 — `inherited` is schema metadata; one generated mechanism serves every inherited row

`kernel/tables/schema.json` gains one boolean row attribute, `inherited`,
on exactly the rows CSS inherits among the 89: `text_color`, `font_family`,
`font_size`, `font_weight`, `font_style`, `line_height`, `letter_spacing`,
`font_variant_numeric`, `direction`, `white_space`, `text_align`. Rows CSS
does not inherit stay unmarked — `text_decoration_line` (CSS *propagates*
a decoration to inline descendants at paint; that is the paragraph owner's
painting rule, not inheritance), `text_overflow`, `line_clamp`, `clip_path`,
`overflow`, every box row. `kernel/build.rs` generates `StyleMask::INHERITED`
and one getter, `NodeRef::computed(StyleId) -> StyleValue`, that walks the
logical ancestors to the nearest own row and falls back to the schema
default; `text_color()` becomes `computed(TextColor)`. Props are not rows:
`spellcheck()` stays the one hand-written prop getter (HTML's own
algorithm, LLP 1001 §1), and `lang` joins it when a consumer needs it.

A consumer never reads a row's raw value for an inherited row; the arena's
`text_runs`, the Apple projection and the agent's reads go through
`computed`. This is the "one declaration authority" rule applied to
inheritance: a second hand-written catalogue of inherited rows is refused.

### D2 — The first slice is the text rows into inline runs, on the web's rule

A `text` node's runs (the `text` children the kernel measures as one
paragraph, LLP 1001 §6) compute their `TextStyle` from D1's getter: a run
with no `font_size` of its own measures at its paragraph's; a run with its
own `font_weight` keeps it; the paragraph's `line_height` governs the line
box the way CSS's does. The browser already behaves so (`<span>` inside a
`<div>`); the kernel and the Apple host follow it; Linux's paragraph cache
reads the same runs. The readers drop their prop threading; Messages keeps
working unchanged (it authors every run).

Fixture (kernel): a paragraph `font-size=20 line-height=24` with three
runs — bare, `font-weight=700`, `font-size=12` — measured through the
reference measurer; then the paragraph's size set to 24 (the runs remeasure
and the paragraph's frame changes), a run reparented into a `font-size=14`
paragraph (its metrics follow the new parent), the paragraph's row cleared
(back to 16). Fixture (Apple host tests): the same tree's batch carries the
computed rows to each run's dictionary, an ancestor change resends only the
runs without their own row, a resize resends none. Browser parity: the
`layout` box of each run on the web and the iPhone within the driver's two
decimals, on the declared font.

### D3 — Authored presence and computed value stay distinct, and both are visible

The own `StyleMask` remains the record of what the author wrote
(`kernel/build.rs:1025-1045`); `computed` never writes back
(`kernel/tests/apply.rs:933` asserts exactly this for colour and stays the
rule). A dynamic binding that sets a row is authored presence; a class
expansion is authored presence (the compiler expanded it, LLP 1017.000 P6).
1035.002 reports, per row, `authored` / `inherited from #id` / `initial`
from these two facts and nothing else. No host may synthesize a value into
the mask to make its own life easier — the Apple projection's computed
colour is sent in the dictionary, not written into the arena.

### D4 — The kernel owns invalidation, with two reasons

A write to an inherited row on node N dirties N and every logical
descendant that does not override the row: `PAINT_DIRTY` for
`text_color`, `TEXT`-dirty routed to the measure owner for the text rows
(the existing `txn.rs:543-549` path), stopping at a descendant that has its
own row. `SetChildren` dirties the moved subtree the same way from its new
parent's computed values. The layout receipt and the batch then name the
descendants themselves, and the Apple host's per-frame re-derivation
(`host.rs:707-730`) is deleted — the kernel says what changed, the host
sends it.

Two reasons, kept apart: **paint** (colour, appearance) refreshes cached
ink and assigned native field colours and never remeasures; **geometry**
(font rows, `line_height`, `letter_spacing`, `white_space`, `direction`)
remeasures and rebreaks. A cache key contains the dependencies of the
cached result and nothing else (`Spec.geometry` is the model). A repeated
unchanged write emits nothing (the host test's "a resize emits no style
op" extends to "an identical ancestor write emits nothing").

Cost: a subtree walk on an inherited-row write, bounded by the subtree.
Measured on Messages (≈200 nodes) and the LLP 0566 reader before the
per-frame diff is removed; a global recomputation pass is refused.

### D5 — `light-dark()` stays a pair until the painting host resolves it; appearance refresh is one rule on both Apple hosts

LLP 1034 stands: the pair is stored, the web emits the function, Apple and
Linux resolve against the owning surface. What this adds: (a) the
appearance-change response is one rule — invalidate the paragraph spec,
repaint, re-apply assigned native colours — guarded by "this node or a run
of it carries a scheme-aware value" on **both** hosts (iOS today
invalidates every node; macOS guards); (b) native editors take their
computed `text_color` through D1, so a field inside a dark root paints its
text white without an own row (the `queue/` gap closes in slice 1, it is the
same getter); (c) a process-wide dark flag never enters the logical tree,
and a native wrapper (sheet, navigation controller, embedded session)
changes which view's appearance resolves the pair, never the pair.

### D6 — Text geometry measured is text geometry painted; the ceilings and the baseline are the declared remainder

The kernel's frames carry fractions (landed); an authored line height is
measured as written (landed); the host paints at the measured geometry.
Three roundings remain on Apple and stay **as declared deviations in LLP
1008 §3** until a targeted reproduction decides each: the ceiled intrinsic
width, the ceiled `normal` paragraph height (both because removing them
moved Caltrain's scroll extent and canvas readback — a parity number the
smoke pins), and the baseline rounded to a logical point (because the one
UILabel/CoreText/WebKit comparison found no adjustment matching both). The
reproduction is one fixture: a line at several fractional sizes and line
heights beside a `UILabel` and Chrome at the same declared font, recording
width, height and baseline per engine; then each rounding goes or stays
with its number. The 0.5-point tolerance in `host.rs:556-559` is tightened
to the driver's precision in slice 1 so nothing is hidden meanwhile.

**Native text padding repaired (Codex, 2026-09-10):** Apple wrapped and painted
the outer box even though the kernel had allocated padding. Paragraph layout
and painting now use the content box; AppKit selection and link hits follow it.
A padded text and text inside an equivalent padded container previously differed
by a line of wrapping and the inset. The corrected iOS captures agree to within
one RGB level per channel for left/center/right alignment, changed padding,
restoration and removal/recreation. The browser supplies the content-inset rule;
this does not establish cross-engine glyph or ellipsis equality. Messages quoted
replies and both empty-result labels exercise the repair. Swift regressions hold
wrapping at unchanged outer width and padded/aligned link and word-selection hits.
macOS geometry/actions pass, but its capture is all-transparent and its pixels
remain unverified (`/tmp/messages-text-padding/verification.json`).

### D7 — Clipping composes for painting and hit-testing, held by one fixture

`clip-path`, `overflow`, a presentation transform and a scroll offset
compose in one order on every host: the clip is in the node's border-box
space, the transform applies to the clipped result, the scroll offset
moves both. The fixture: a clipped, rotated child inside a scrolled
container; `screenshot` shows the clipped pixels at the transformed
position; `tap` at a point outside the path but inside the box reaches the
node underneath; `layout <node>` (1035.002) reports the clip chain. Today
there is no host test at all for the row; the fixture lands with this
slice's tests on Apple and the web, and Linux declares the gap in LLP 1015
§7 until its painter fills the path.

### D8 — A comparison declares fonts, device scale and tolerance first

A native-versus-browser or native-versus-native comparison names the
declared font (LLP 1019), the device scale, the OS/device configuration
and the tolerance before it runs, and separates a semantic difference (a
box in the wrong place) from a rasterization difference (a glyph's
antialiasing). Full visual equality across font engines is not a
meaningful blanket assertion. When the finding is a paint discrepancy, the
evidence is the saved pixels, never a screenshot preview — the record's
image-preview "defects" were the preview's.

### D9 — A declared-but-unimplemented prop is deleted

`initialFocus` (prop 38) is declared in the schema and handled nowhere. It
leaves the schema; when a consumer wants first-focus-at-mount it returns as
HTML's `autofocus` with HTML's rule (one per document, honoured at
mount). Delete; don't deprecate. A restart with carried state (a dev
reload, a delivered update) is the same document (Charlie, 2026-09-23):
focus follows the focused node's place in the runner's tree — its index
among its siblings at each level, and its type — and the restarted tree
autofocuses nothing; a node mounted later still may. A fresh boot
autofocuses.

### D10 — Which `queue/` defects are semantic

- **`line-height` unitless is a ratio** (implemented 2026-09-11,
  [1035.000.000](1035.000.000-css-line-height.rfc.md)): the generated row
  preserves `Number`, `Length` and `Normal`. Ratios resolve against each
  receiving font; zero stays explicit. Compiler, web, native measurement,
  painting and editors carry those meanings, including the paragraph strut.
- **Percentage width inflates an auto-height flex column** (implemented
  2026-09-11, [1035.000.001](1035.000.001-reader-percentage-layout.rfc.md)):
  Taffy's cache no longer promotes an intrinsic result into a definite-width
  layout with unresolved descendant percentages. Both readers use the original
  percentage-width declarations; a browser-backed overwide-token fixture holds
  the repair.
- **Wrapped-ink bubble sizing**: not CSS, not a kernel change. If Messages
  wants it, it is an explicit shared design (a `width: fit-content` variant
  or a text-measure-driven `max-width`), proposed on its own with the web
  behaving the same way.
- **The 62-point large-title travel**: navigation-bar ownership, 1035.001
  D9, not scroll physics.

## 3. What this deliberately does not add

All of CSS; a second layout engine; per-host app sources; a conformance
check category (the parity fixtures ride the existing tests and smoke); a
process-wide appearance in the tree; a hand-written inherited-row list in
any host; a global recomputation pass; a promise that UIKit pixels equal
browser pixels.

## 4. Landing order

1. **Slice 1 (this implementer, from 2026-09-09):** D1's `inherited`
   attribute and generated `computed`; D2's runs on the kernel and the
   Apple host with the two fixtures and the browser comparison; D4's
   kernel-owned invalidation replacing the host's per-frame diff; D5(b)'s
   editors; D6's tolerance tightened; D9's deletion. Acceptance: the readers
   drop their prop threading and read the same on macOS and the web;
   Messages' iPhone and web drives unchanged; the five checks green; the
   invalidation cost printed by `metrics.mjs` on Messages.
2. **Slice 2, line height implemented:** D10 through 1035.000.000, with both
   readers as consumers. D7's clip fixture remains separate.
3. **Slice 3, reader width implemented:** D10 through 1035.000.001, reduced
   against Chrome and driven on all four hosts. D6's baseline investigation
   remains separate, with its observed differences still recorded.
4. **Slice 4:** the next failing property a consumer demonstrates. Focus
   across sheet dismissal is 1035.001's slice 2, verified through 1035.002.

Each slice passes initial creation, mutation, reversal, removal/reload
and two consumers before it is called done. Unsupported behaviour is
recorded as unsupported (LLP 1015 §7's list; 1035.002's `applied:
unsupported`), never returned as a plausible default.

**Implemented refinements (2026-09-11, from LLP 1036):** Charlie directed

## 5. Open questions

- Should `computed` cache? The colour walk is uncached and unmeasured;
  slice 1 measures the run remeasure cost on the 0566 reader before adding
  a per-node computed column. Leaning: no cache until a number says so.
- `direction` inherits in CSS and the kernel has no RTL box layout (LLP
  1001 §9). Marking it inherited is correct and cheap; the box layout stays
  out.
- Does Linux's paragraph cache take computed runs for free? Its `cosmic-text`
  spans are built from the same `text_runs`; expected yes, verified in
  slice 1's Linux smoke.

## 7. What this amends, at acceptance

- **LLP 1001 §1**: the `inherited` attribute in the schema table and the
  generated `computed` getter; `initialFocus` removed from the prop table.
  **§3**: inherited-row invalidation of descendants, two reasons. **§6**:
  runs compute their style through `computed`; `text_color()` is an
  instance of it. `line-height` gains its kind in slice 2.
- **LLP 1008 §2**: the projection sends computed inherited rows for runs
  and editors and stops re-deriving descendants per frame. **§3**: the
  baseline deviation, declared with the fixture's numbers. **§9**: one
  appearance-change rule on both hosts.
- **LLP 1007**: nothing — the browser is the oracle; the clip fixture joins
  its tests.
- **LLP 1015 §7**: clip-path painting named as a gap until filled.
- **LLP 1033 D6**: the readers' workaround removed.
- **`queue/`**: the text-rows line deleted at slice 1; the `line-height`
  and percentage-width lines at their slices; the editable-text-colour and
  text-padding lines at slice 1.
