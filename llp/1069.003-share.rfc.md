# LLP 1069.003: `share` — the system share sheet, by the Web Share API's names

**Type:** RFC
**Status:** Draft; Charlie's rulings recorded 2026-09-27 (§Rulings, which overrides the text below where they differ)
**Systems:** Contract (`share` joins the host commands in `contract/types/src/checks.rs`; named arguments on a command); Runner (none: a command is already `(name, args)` in `Outcome.commands`); Web host (`glue.js`'s `command` op: `navigator.share`); Apple host (`ExactKit/Session.swift`'s command queue: `UIActivityViewController`, `NSSharingServicePicker`); Linux host (`presenter.rs` `run_commands`: refused); the journal (`exact_log`, LLP 1035.001 D6); the page facts (LLP 1069.000's `exactPage()`: one field, `canShare`)
**Author:** Claude (Opus 5.5) for Charlie Cheever
**Date:** 2026-09-27
**Related:** LLP 1069 §5 #4 (the survey item this is); LLP 1069.000 (device facts: `exactPage()`, where `canShare` lives); LLP 1069.002 (the media picker: the files a later `share` could carry); LLP 1069.007 (agent substitutes: how a test answers the sheet); LLP 1005 §3 (commands); LLP 1030 D7 (`deliveryCheck`: a command whose outcome is a fact, the precedent D2 declines); LLP 1031 (embedding: why the command lives in `ExactKit`, not the executables); LLP 1035.001 D6 (the journal); LLP 1054 X6 (the `share` symbol role, added with nothing to press)

## Rulings (Charlie, 2026-09-27)

- **Q1: the outcome goes to the journal only** for now. A readable `shared`/`dismissed` fact waits for a consumer.
- **Q2: native hosts do not enforce user activation** (the same ruling as LLP 1069.002 Q2). **This overrides D4's refusal.** `share` runs from any action on native. The web's own rule applies in the browser.
- **Q3: `canShare` lives on LLP 1069.000's `exactPage()`.**

## Summary

An action says

```
action shareLink
  share(url=`https://bsky.app${menuPath}`, title=post.author)
```

and the host opens its share sheet with that URL and title:

| host | what opens | anchored to |
|---|---|---|
| web | `navigator.share({ title, text, url })` | the browser's own |
| iOS | `UIActivityViewController` | the node whose input ran the action (iPad popover) |
| macOS | `NSSharingServicePicker` | the same node, `.minY` edge |
| Linux | nothing; the command is refused into the journal | — |

`share` is a **command**, like `copyText` and `openURL`: fire-and-forget,
answered by the host, with no result the app reads (D2). Its argument names
are the Web Share API's dictionary members (`title`, `text`, `url`), passed
as named arguments. Whether a host can share at all is one fact the app
reads before it draws the button: `canShare` on LLP 1069.000's `exactPage()`
source (D5). Files come later (D7); receiving a share is not in this RFC.

The consumer is Bluesky (`ccheever/bluesky-exact2`, admitted 2026-09-27).
Its post menu's "Copy link" (`app.contract:387`) is today's workaround: it
calls `copyText` and toasts. LLP 1054 X6 gave it a `share` symbol with
nothing behind it.

## Motivation

Every content app shares: a post, a link, a note. Expo ships it as
`expo-sharing` (and React Native's `Share`); the web ships it as
`navigator.share`. exact2's only outward hand-offs are `copyText` and
`openURL`, so a port copies a link and tells the user to paste it
somewhere, which is what Bluesky does.

The web has the name and the vocabulary, and each native host has exactly
one system control for it. Nothing needs a new node, a new shape or a
runner change: the compiler learns one name, and three hosts learn one arm.

## Design

### D1 — A host command with the Web Share API's member names

`share` joins `HOST_COMMANDS` (`contract/types/src/checks.rs:671`). It takes
named arguments only, each a string, at least one of `text` or `url`:

```
share(url=link)
share(text=quote, url=link)
share(title="Journal", text=body)
```

The names are `ShareData`'s (Web Share API §2.1.1), so a reader who knows
`navigator.share` knows this. Named arguments already exist in the grammar
(`Expr::NamedArg`, used by `t(...)` and `surface=`); the checker learns
them for this one command and refuses positional arguments, an unknown
name, a duplicate, or a call with neither `text` nor `url`, each by name.
Lowering orders them as `(title, text, url)` with `none` for an absent one,
so the plan's `Command` op and every host's `(name, args)` stay as they are.

`url` must be an absolute `http:` or `https:` URL; a host refuses anything
else into the journal (D4). The browser resolves a relative URL against the
document, which would make the same source mean different things on web
and native; an app that shares its own pages builds the absolute URL, as
Bluesky already does for `copyText`.

*Rejected:* one record argument, `share({ ... })`. Contract has no record
literal, and adding one for a single command is a language change for a
spelling that named arguments already give.

### D2 — No answer: the outcome goes to the journal, not the app

`navigator.share` returns a promise that resolves when the user shares and
rejects with `AbortError` when they dismiss. `UIActivityViewController`'s
`completionWithItemsHandler` reports the same two outcomes plus the chosen
activity. The question is whether the app should read that.

It shouldn't, in this RFC. An app that shares doesn't change its state on
the outcome: Bluesky's toast says "Copied" because a copy is invisible, and
a share sheet is not. Making `share` a request with an answer would make it
a resource (a `pending` slot, a ticket, a superseding rule) for a value
nobody consumes. And "which app did they pick" is information the web
doesn't give (only resolve or reject), so it could not be portable.

Each host journals the outcome (`share: shared`, `share: dismissed`,
`share: refused: <reason>`) through `exact_log`, so an agent reads it with
`logs` and a test asserts it. If a consumer later needs the outcome in the
app, it becomes a field on a fact, as `deliveryCheck` reports through
`exactDelivery` (LLP 1030 D7), not a new command shape.

### D3 — Anchored to the node whose input ran the action

On an iPad and on macOS the sheet is a popover and needs a source view and
rect. The anchor is **the node that received the input event whose action
issued the command**: the host already knows it, because it dispatched the
event, and it is what the user pressed. `UIActivityViewController`'s
`popoverPresentationController.sourceView`/`sourceRect` and
`NSSharingServicePicker.show(relativeTo:of:preferredEdge:)` take that node's
view and bounds.

An action that no node's input ran (a keyboard shortcut, a menu-bar
command on macOS) anchors to the window's content view, centred. That is
UIKit's own fallback for a popover without a source.

The command queue that runs this lives in `ExactKit`'s `Session.swift`,
beside `copyText`, not in `ExactIOS`/`ExactMac`'s delegates beside
`openURL`. An embedder (LLP 1031) gets it without writing an arm, and the
session is the thing that knows the dispatched node.

### D4 — Only from an input, on every host

`navigator.share` requires transient user activation: called from a timer,
or after an `await`, it rejects with `NotAllowedError`. The web glue already
runs commands inside the input dispatch, while activation is live (the
comment on `copyText`, `glue.js:733`), so a `share` in a pressed action
works. A `share` in an action run by a task (`every(...)`) or by an answer
arriving does not.

Native hosts could share from anywhere. They refuse instead, so the source
means the same thing on every host: a `share` issued outside an input
dispatch is journaled as `share: refused: no user input` on all four. The
host knows which it is, because it is the host that called `dispatch`
rather than advancing the clock.

*Rejected:* letting native hosts share from a task. A sheet that opens
unasked on iOS and never on the web is the kind of divergence the web
standard exists to prevent, and no consumer wants a sheet the user didn't
ask for.

### D5 — `canShare` is a fact the app reads before drawing the button

Share is missing on desktop Firefox, on Chrome for Linux, and on the Linux
host. A button that does nothing is worse than no button, so the app needs
to know before it draws one. That is a host fact, not a command result:

| host | `canShare` |
|---|---|
| web | `typeof navigator.share === "function"` |
| iOS, macOS | `true` |
| Linux | `false` |

It is one boolean field on LLP 1069.000's `exactPage()` source, beside
`visibilityState` and `onLine`, read the way
`prefersReducedMotion` is read from `exactViewport`:

```
resource page = exactPage() as shape Page   // LLP 1069.000 D2
...
  when page.canShare
    button press=shareLink
      image "symbol:share"
  else
    button press=copyLink
      image "symbol:link"
```

The web's `navigator.canShare(data)` answers a narrower question: can this
particular payload be shared, which matters for files. It is not needed
until D7.

*Rejected:* a fallback inside the host, such as copying the URL on a
browser without `navigator.share`. It would do something the author did not
write and the user did not ask for, and the author, who knows whether
"copied" or "open in a new tab" fits, can write the fallback with
`canShare`.

### D6 — Under the agent, a substitute answers the sheet

A system share sheet is outside the app's views: `tree` can't see it and
`tap` can't reach it, and headless Chrome has no sheet to show. Under the
agent (LLP 1069.007), each host opens no system sheet. It records the
request as a pending presentation, visible in `state` with its `title`,
`text`, `url` and anchor, and the agent resolves it as `shared` or
`dismissed`; D2's journal line follows. The shape of that substitute
(which operation resolves a pending system presentation) is LLP 1069.007's
to decide, not this RFC's. This RFC requires only that `share` be built
behind the host's substitute point from the start.

### D7 — Files are a later slice

Web Share Level 2 adds `files`: `File` objects, checked with
`navigator.canShare({ files })`. The two sources of a file in exact2 are:

- **A picked image or video** (LLP 1069.002): the picker's answer is a
  handle the host still holds.
- **An app file** (`app:/data/...`, `app:/cache/...`): Fieldnotes' backups,
  a rendered export.

Both need the command to name a file the host can open, and the host to
turn it into a `File` (web: from IndexedDB or the picked `File`), a file
URL (iOS: an `NSItemProvider`), or an `NSURL` (macOS). The argument is
`files=[...]` of those handles or `app:/` paths, gated by the `fs.read`
grant already governing that path. It waits for 1069.002's handle shape
and a consumer (Fieldnotes sharing a backup is the likely one).

## Not in this RFC

- **Receiving shares:** an iOS share extension, a macOS Share menu
  extension, or the web's Web Share Target (a manifest `share_target`).
  Each is an app entry point, not a command. On Apple it is a separate
  extension target with its own process. It belongs with routing
  (LLP 1038: an incoming share as a `navigate` event with parameters) when
  a consumer asks.
- **Choosing or excluding activities** (`excludedActivityTypes`, custom
  `UIActivity`). The web can't, so the source shouldn't.
- **Clipboard fallback.** Rejected in D5.

## Verification

- **Compiler:** unit tests in `contract/types` for each refusal in D1
  (positional, unknown name, duplicate, neither `text` nor `url`) and for
  the lowered order.
- **Web:** a `glue.js` test that a `share` inside an input dispatch reaches
  `navigator.share` with the three members, and one from a timer is
  journaled as refused. `smoke.mjs web` shares a URL through the agent's
  substitute and reads the journal line.
- **iOS:** an XCTest that the controller's popover source is the pressed
  node's view on an iPad simulator (the anchor is the thing an iPhone run
  can't catch), plus the smoke on the iPhone.
- **macOS:** the picker's anchor view is the pressed node's.
- **Linux:** `run_commands` journals `share: refused: unavailable`, and
  `canShare` reads `false`.
- **Bluesky:** the post menu shows Share where `canShare` holds and Copy
  link where it doesn't, on web, macOS and iOS.

## Slices

1. **Compiler and the text/URL command on every host (D1–D4).** About a
   day on the web and Linux, a day or two on Apple for the anchor on iPad
   and macOS.
2. **`canShare` (D5):** lands with LLP 1069.000's source, or as a field on
   `exactViewport` if 1069.000 hasn't landed.
3. **The agent substitute (D6):** with LLP 1069.007.
4. **Files (D7):** behind LLP 1069.002 and a consumer.
