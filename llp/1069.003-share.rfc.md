## As built (2026-09-27)

Slices 1 and 3, on every host; slice 2 had landed with LLP 1069.000.

- **Compiler (D1):** `share` is a host command whose arguments the checker
  takes by name only (`type-share-argument`: positional, unknown, duplicate,
  not a string, neither `text` nor `url`; five reject fixtures in
  `contract/corpus/rejects.txt`). Lowering orders them `(title, text, url)`,
  `none` for an absent one (`contract/lower/src/expr.rs` `command_args`).
- **The dispatching view (D3), in the runner, not the hosts.** r2 had each
  Swift input closure pass its id to `apply`. `Runner::dispatch` is the one
  door every host event goes through, so the runner stamps `source` on each
  `Command` an event's action issues (`None` for a timer, an answer, a
  continuation), and every host's `command` op carries it. That covers the
  key and menu paths without a closure each, and the web and Linux get the
  anchor for the hold's summary too. This departs from r2's "the runner is
  unchanged"; the `Command` struct gains one field.
- **One rule for every host** (`runner/src/share.rs`): `Share::from_args`
  / `from_json` check the data (an absolute `http:`/`https:` URL with a host,
  at least one of text or url); `arm` refuses into the journal (`share:
  refused: <reason>`), holds under the agent, or says present. The web glue
  and `ExactKit` reach it through one new export, `exact_share` (web and
  Apple ABIs); Linux calls it directly. A held share's answer is journaled in
  `agent::answer` (`share: shared` / `share: dismissed`), so no host has an
  answer arm.
- **Web:** `navigator.share` is called inside the dispatch with the members
  given; resolve is `shared`, `AbortError` is `dismissed`, anything else
  `refused: <name>`.
- **Apple** (`ExactKit/Share.swift`, so an embedder gets it): the anchor is
  `source`'s view; a view not on screen (a hidden popover's row) anchors to
  that popover's shown invoker; no source, or none of those, the window's
  content centred. iOS presents `UIActivityViewController` (the title is the
  subject an activity takes) with its popover at the anchor; macOS shows
  `NSSharingServicePicker` at `.minY`. Presented from any action (Q2).
- **Linux:** refused `unavailable`; held under the agent.
- **The hold (D6)** is not tied to its node: a menu row that closes its menu
  with the press would retire the request it just made. Its `name` in
  `pending` is therefore `share`; `args` carries `anchor`. No `--answer
  share=shared` fixture: LLP 1069.007's `--answer` is not built.
- **Consumer:** Fieldnotes' editor has **Share…** where `page.canShare`
  holds, sharing the note's title and body. Building it found that
  `exactPage` was missing from `exact_plan::runner_owned_source`, so any app
  with a TypeScript source that read `exactPage()` failed its `tsc` step
  (`Sources` demanded an `exactPage` provider); fixed here.
- **Bluesky** (`ccheever/bluesky-exact2`, not edited): the post menu's "Copy
  link" (`app.contract:387`) becomes a `when page.canShare` Share item,
  `share(url=\`https://bsky.app${menuPath}\`, title=post.author)`, with Copy
  link in its `else`, and the component reads `resource page = exactPage()
  as shape Page`. It picks up the `runner_owned_source` fix with exact2.

**Verified by driving** `contract/corpus/share.contract` on web, macOS, the

## Summary

An action says

```
action shareLink
  share(url=`https://bsky.app${menuPath}`, title=post.author)
```

and the host opens its share sheet with that URL and title:

| host | what opens | anchored to |
|---|---|---|
| web | `navigator.share({ title, text, url })` | the browser's own |
| iOS | `UIActivityViewController` | the pressed node's view (iPad popover), D3 |
| macOS | `NSSharingServicePicker` | the same, `.minY` edge |
| Linux | nothing; refused into the journal | — |

`share` is a **command**, like `copyText` and `openURL`: fire-and-forget,
with no result the app reads (D2). Its argument names are the Web Share
API's `ShareData` members, passed as named arguments. Whether a host can
share is `canShare` on `exactPage()` (D5). Files come later (D7); receiving
a share is not in this RFC.

The consumer is Bluesky (`ccheever/bluesky-exact2`, admitted 2026-09-27).
Its post menu's "Copy link" (`app.contract:387`) is today's workaround.

## Motivation

Every content app shares. Expo ships `expo-sharing`; the web ships
`navigator.share`. exact2's only outward hand-offs are `copyText` and
`openURL`, so a port copies a link and asks the user to paste it.

The web has the name and the vocabulary, and each native host has exactly
one system control for it. The compiler learns one name, and three hosts
learn one arm.

## Design

### D1 — A host command with the Web Share API's member names

`share` joins `HOST_COMMANDS` (`contract/types/src/checks.rs:682`). It takes
named arguments only, each a string, at least one of `text` or `url`:

```
share(url=link)
share(text=quote, url=link)
share(title="Journal", text=body)
```

Named arguments exist in the grammar (`Expr::NamedArg`, used by `t(...)`
and `surface=`); the checker learns them for this command and refuses, by
name, positional arguments, an unknown name, a duplicate, or neither `text`
nor `url`. Lowering orders them `(title, text, url)` with `none` for an
absent one, so the plan's `Command` op and every host's `(name, args)` stay
as they are.

`url` must be an absolute `http:` or `https:` URL; a host refuses anything
else into the journal. A relative URL would resolve against the document on
the web and against nothing natively.

*Rejected:* one record argument, `share({ ... })`. Contract has no record
literal.

### D2 — No answer: the outcome goes to the journal

`navigator.share` resolves on share and rejects with `AbortError` on
dismiss; `completionWithItemsHandler` reports the same two plus the
activity. The app doesn't read either (ruled):

- An app that shares doesn't change its state on the outcome, and a sheet
  is visible where a copy isn't.
- An answer would make `share` a resource (a `pending` slot, a ticket,
  supersession) for a value nobody consumes.
- "Which app they picked" isn't portable: the web gives only resolve or
  reject.

Each host journals `share: shared`, `share: dismissed` or `share: refused:
<reason>` through `exact_log`. An agent reads it with `logs`. A later
consumer gets a field on a fact, as `deliveryCheck` reports through
`exactDelivery` (LLP 1030 D7), not a new command shape.

### D3 — Anchored to the node whose input ran the action

On iPad and macOS the sheet is a popover and needs a source view and rect:
`popoverPresentationController.sourceView`/`sourceRect`, and
`NSSharingServicePicker.show(relativeTo:of:preferredEdge:)`. The anchor is
the node that received the input whose action issued the command.

**What the host knows today (checked in r2):** not this. The runner's
`Command` is `{name, args}` (`runner/src/runner.rs:47-52`); the batch
carries no source. `Session.swift:478` has the pressed id at
`apply(runtime.press(id, now: now()))`, but `apply(_:)` drains
`pendingCommands` with no view (`Session.swift:716-748`). So this RFC adds
one host change: each input closure in `Session.swift` (`onPress`,
`onChange`, the key and menu paths) passes its view id to `apply`, which
hands it to the command queue with the batch's commands. The runner is
unchanged.

The fallbacks, in order:

1. **The pressed view is not in a window.** A menu item is the common
   case: Bluesky's Share is a post-menu item. On iOS a popover menu is
   projected to a `UIMenu` whose `UIAction` presses the row's id
   (`MenusIOS.swift:292-293`, LLP 1021 D3), and the row's own view is never
   on screen. Anchor to the menu's invoker, which the presenter holds.
2. **No input ran the action** (a timer, an answer, a keyboard shortcut, a
   menu-bar command): the window's content view, centred. UIKit's own
   fallback for a popover without a source.

The queue lives in `ExactKit`'s `Session.swift`, beside `copyText`, not in
`ExactIOS`/`ExactMac`'s delegates beside `openURL`. An embedder (LLP 1031)
gets it without writing an arm.

### D4 — User activation: the browser's rule, not ours

`navigator.share` requires transient user activation: from a timer, or
after an `await`, it rejects with `NotAllowedError`. The web glue runs
commands inside the input dispatch while activation is live (the comment on
`copyText`, `glue.js:727-728`), so a `share` in a pressed action works on
the web.

Native hosts share from any action (ruled): a task, an answer, a timer.
On the web the same `share` is refused by the browser and journaled
`share: refused: NotAllowedError`. The authoring guide documents the
difference; no host enforces the web's rule.

### D5 — `canShare` is a fact the app reads before drawing the button

Share is missing on desktop Firefox, Chrome for Linux, and the Linux host.
A button that does nothing is worse than none. `canShare` is one boolean on
`exactPage()` (LLP 1069.000 D2 owns the source and its per-host table):

```
resource page = exactPage() as shape Page
...
  when page.canShare
    button press=shareLink
      image "symbol:share"
  else
    button press=copyLink
      image "symbol:link"
```

The web's `navigator.canShare(data)` answers a narrower question (this
payload, which matters for files). It waits for D7.

*Rejected:* a fallback inside the host, such as copying the URL where
`navigator.share` is missing. The author, who knows whether "copied" or
"open in a new tab" fits, writes it with `canShare`.

### D6 — Substitute

LLP 1069.007 D7's paragraph for this capability:

1. **Shape:** a request, command-shaped, with no answer to the app; its
   outcome is a journal line (D2).
2. **Pending:** under the agent no host opens a sheet. `state.pending`
   lists `{ticket, device: {capability: "share", args: {title, text, url,
   anchor}}}`, `anchor` being the view id D3 chose. **Answer:** `tap @t
   shared` or `tap @t cancel`; the journal line follows (`share: shared`,
   `share: dismissed`). **Fixture:** `--answer share=shared`. `delivery` is
   `substituted`.
3. **Fact:** `canShare` defaults to `true` under the agent on every host,
   Linux included, because the substitute answers there (`prefer can-share
   false` tests the other branch).
4. **Web override:** none in CDP; the glue holds the request under
   `?agent=1`.

### D7 — Files are a later slice

Web Share Level 2 adds `files`, checked with `navigator.canShare({ files })`.
exact2's files are `app:/` paths: a picked file under `app:/tmp/picked/`
(LLP 1069.002 D3) or an app file under `app:/data` or `app:/cache`. The
argument would be `files=[...]` of `app:/` paths, gated by the `fs.read`
grant already governing each. The host turns a path into a `File` (web,
from the storage entry), a file URL in an `NSItemProvider` (iOS) or an
`NSURL` (macOS). It waits for a consumer; Fieldnotes sharing a backup is
the likely one.

## Not in this RFC

- **Receiving shares:** an iOS share extension, a macOS Share menu
  extension, the web's Web Share Target. Each is an app entry point, not a
  command, and on Apple a separate extension process. It belongs with
  routing (LLP 1038: an incoming share as a `navigate` event) when a
  consumer asks.
- **Choosing or excluding activities.** The web can't.
- **Clipboard fallback.** Rejected in D5.

## Verification

- **Compiler:** unit tests in `contract/types` for each refusal in D1 and
  the lowered order.
- **Web:** a glue test that a `share` inside an input dispatch reaches
  `navigator.share` with the three members, and one from a timer is
  journaled `refused: NotAllowedError`. `smoke.mjs web` shares through the
  substitute and reads the journal line.
- **iOS:** an XCTest on an iPad simulator that the popover's source is the
  pressed node's view, and the menu invoker's for a menu item (the anchor
  is what an iPhone run can't catch); the smoke on the iPhone.
- **macOS:** the picker's anchor view is the pressed node's; a `share` from
  a timer opens the picker.
- **Linux:** `run_commands` journals `share: refused: unavailable`, and
  `canShare` reads `false` outside the agent.
- **Bluesky:** Share where `canShare` holds, Copy link where it doesn't, on
  web, macOS and iOS.

## Slices

1. **Compiler and the text/URL command on every host (D1–D4),** with the
   dispatching view carried to the queue (D3). About a day on the web and
   Linux, a day or two on Apple for the anchors.
2. **`canShare` (D5):** lands with LLP 1069.000's `exactPage()`.
3. **The substitute (D6):** after LLP 1069.007's first slice.
4. **Files (D7):** behind a consumer.

## Decided

1. The outcome is journaled only; a readable fact waits for a consumer (D2).
2. Native hosts share from any action; the web's activation rule is the
   browser's (D4).
3. `canShare` is on `exactPage()` (D5).
