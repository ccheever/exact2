# LLP 1069.010: The Mac as a document platform

**Type:** RFC
**Status:** Draft; Charlie's rulings recorded 2026-09-27 (§Rulings, which overrides the text below where they differ)
**Systems:** Apple host (`ExactMac/main.swift`'s one window; `DocumentsMac.swift`'s open seam; `DevMenuMac.swift`'s File menu; `NSSavePanel`, Open Recent, window tabs), iOS host (`UIDocumentPickerViewController`, opening in place), Web host (the File System Access API, `launchQueue`), the manifest (`file_handlers`, `launch_handler`), storage (a document path beside `app:/` in grants and `storage.fs`), Agent API (a picker answered without a panel), `rules/DEFERRED.md` ("no generic file input")
**Author:** Claude (Opus 5.5) for Charlie Cheever
**Date:** 2026-09-27
**Related:** LLP 1069 §4 B4 and §5 #13 (the survey this refines); LLP 1033 D1–D3 (`file_handlers`, `exact install`, every opening ends at `open-file`) and its "what remains"; LLP 1031 D7 (instance-scoped sessions; two sessions pay two Hermes heaps); LLP 1021 (menus); LLP 1045 D10 and LLP 1069.002 (the media picker, which shares this document's delivery shape); LLP 1069.007 (a capability answered by the agent); LLP 1069.008 (permissions derived from grants); LLP 1027.001 (portable storage requests); LLP 1048 (the `head` tag); `vendor/ibex2/src/grant.rs` (`PathPrefix`: `app:/` or an absolute path)

## Rulings (Charlie, 2026-09-27)

- **The trade: taken.** `rules/DEFERRED.md` now admits a picker for the types in `file_handlers`, plus the export copy. Take: none named (Charlie: "idk what to trade it for, maybe relax the limit slightly").
- **Q2, the Mac App Store: a later goal, not now** (Charlie: "don't make any design decisions that make it harder later on but we don't need to do the work for now"). D1's handles and D5's recents must stay expressible as sandbox security-scoped bookmarks. No sandbox work is done.
- **Q3: two windows sharing one database are supported,** and `navigate-new` is not refused for apps with a store. What is owed is the cross-window notification: a committed write announces an LLP 1016.002 topic, and the other session's readers re-ask. It lands with Fieldnotes.
- **Q4: every write is already committed.** No `.terminateLater`.

## Summary

An exact2 app can already *open* a document on macOS. `file_handlers` in
the manifest becomes `CFBundleDocumentTypes`. There are four routes: Finder,
Open With, the command line and ⌘O. All four deliver a path to the one
`open-file` node, and the app's Rust reads it (LLP 1033 D1–D3).

That's where it stops. A document app on the Mac is expected to do more:

- **Save anywhere.** There is no `NSSavePanel`. Fieldnotes' backup is
  written to `app:/data/backups` and then "ready to copy", because it can't
  go anywhere else.
- **Open a second document beside the first.** There is one global `window`
  in `main.swift`, and a second open replaces the document.
- **Keep an Open Recent menu.**
- **Give TypeScript logic a way to read what was opened.** A path is only
  readable from Rust's `std::fs`, ungated. A grant is `app:/…` or an
  absolute prefix fixed at bake, so a TypeScript source can't read a file
  the user just chose.

This RFC proposes six pieces, all named by the web where the web has a name:

1. **A chosen document is a handle, not a path (D1).** The host mints a
   `doc:` path per chosen file or folder, good for the session and admitted
   by one grant, `fs.document`. It is the File System Access API's
   `FileSystemHandle`. On the Mac it is a security-scoped URL; on iOS it is
   the picker's URL.
2. **The pickers are the web's three calls, as commands (D2):**
   `showOpenFilePicker`, `showDirectoryPicker` and `showSaveFilePicker`.
   Each result arrives at a node the command names, as LLP 1045 D10's
   `upload` does.
3. **Export is a copy the host makes (D3).** The app writes an `app:/` file,
   and the host copies it to where the user chose, or offers it as a
   download on the web. Fieldnotes needs nothing more.
4. **A second document opens in a second window (D4)** when the manifest's
   W3C `launch_handler` says `navigate-new`. Each window gets one session,
   through LLP 1031's instance-scoped sessions. Window tabs come with it
   from AppKit.
5. **Open Recent (D5)** via `NSDocumentController.noteNewRecentDocumentURL`,
   with no `NSDocument`.
6. **The window title and edited state (D6)** come from the app's `head`
   tag, not from the host guessing from a path.

**Deliberately not built:**

- `NSDocument`'s ownership of saving, undo and versions (D7). The runner owns
  state, and the app autosaves.
- Security-scoped bookmarks that outlive a launch. That would be a durable
  capability grant, which `rules/DEFERRED.md` refuses.
- Quick Look, thumbnails and Spotlight/App Intents (§Not in this RFC).

**The trade.** This widens LLP 1045 D10's "no generic file input" to "the
types the manifest's `file_handlers` declares". The take is Charlie's
(Question 1).

## Motivation

Two consumers, in order.

**The Markdown reader and the LLP reader (LLP 1033).** Charlie reads this
corpus in them. Today:

- A second `mdview` hands its file to the running copy, and the first
  document is gone.
- ⌘N does nothing.
- There is no Open Recent.
- Relaunching opens nothing, because `window.isRestorable = false`.
- The window title is derived by the host from the opened path
  (`ExactDocuments.windowTitle`), because "the app has no hook that fires
  when a resource settles" (1033 D7).
- The reader's "what remains" lists iOS file opening and the browser's
  `launchQueue`.

**Fieldnotes (the storage consumer).** It keeps notes in SQLite and writes
a JSON backup to `app:/data/backups/fieldnotes.json`. The only way out of
the app is the clipboard: "Your saved backup is ready to copy." Restoring
means pasting JSON into a text area. A notes app is expected to have
File ▸ Export… and Import…, a `.json` a person can put in Dropbox, and the
same on the web as a download. Fieldnotes is TypeScript on a worker, so
Rust's ungated `std::fs` escape isn't available to it. It needs a grant.

**Expo has no counterpart** (LLP 1069 §4), because Expo doesn't ship macOS.
A cross-platform runtime whose Mac apps behave like Mac apps is a
difference an Expo developer can't get elsewhere.

## Design

### D1 — A chosen document is a handle, named `doc:`

Every route that brings a user-chosen file or folder into the app mints a
**document path**, `doc:/<n>/<name>`. The host keeps the real location
behind `<n>`:

- **macOS:** a security-scoped URL, with `startAccessingSecurityScopedResource`
  held while the session lives. It is a no-op for today's unsandboxed
  Developer ID builds, and required under the App Sandbox.
- **iOS:** the `UIDocumentPickerViewController` URL, under the same access
  calls.
- **Web:** a `FileSystemFileHandle` or `FileSystemDirectoryHandle` held by
  the glue.

The routes are: Finder, Open With, the command line, ⌘O, a dropped file,
`launchQueue` on the web, and "Open in" from Files on iOS.

`storage.fs` reads and writes a `doc:` path as it does an `app:/` one:

- `readFile`, `writeFile` and `atomicWriteFile` on a file handle.
- `readdir` and paths beneath it on a folder handle (the LLP reader opens a
  folder).
- `..` refused as `PathPrefix` already refuses it.

One grant admits it:

```
fs.document read          // Markdown, LLP reader
fs.document readwrite     // an editor that saves in place
```

`PathPrefix::new` gains the `doc:` namespace beside `app:`. A `doc:` path
exists only once the host has minted it, so the grant admits *what the user
chose*, never a location the app names. The host forgets every handle when
the session ends.

The value delivered to `open-file` becomes the document path. An app that
wants the real path for display asks `storage.fs.stat(doc)` for its `name`.
That is `FileSystemHandle.name`, and the web never exposes more. Rust apps
that read with `std::fs` today (the Markdown data crate) keep working on
macOS during a transition that isn't one: they move to LLP 1027.001's
storage requests in the same change. Delete, don't deprecate.

*Rejected:* delivering absolute paths and widening grants to `/`. It works
unsandboxed on the Mac and nowhere else. The web has no paths, iOS has
per-URL access, and the grant would stop meaning anything.

*Rejected:* a handle that outlives the launch (a security-scoped bookmark
on Apple, a handle kept in IndexedDB on the web). That is a durable
capability grant, which `rules/DEFERRED.md` refuses. D5 gets Open Recent
without it on today's unsandboxed Mac builds.

### D2 — The three pickers are the web's calls, issued as commands

| command | macOS | iOS | web | Linux |
|---|---|---|---|---|
| `showOpenFilePicker(id, multiple?)` | `NSOpenPanel`, files | `UIDocumentPickerViewController(forOpeningContentTypes:)` | `showOpenFilePicker`; else a hidden `<input type=file>` | refused, journaled |
| `showDirectoryPicker(id)` | `NSOpenPanel`, folders | the same picker, `.folder` | `showDirectoryPicker`; else `<input type=file webkitdirectory>` | refused |
| `showSaveFilePicker(id, suggestedName)` | `NSSavePanel` | `UIDocumentPickerViewController(forExporting:)` after D3's copy | `showSaveFilePicker`; else D3's download | refused |

The accepted types come from `file_handlers`, never from the command, so
the app can't widen them per call. That is also what bounds the trade
(below).

The result arrives the way LLP 1045 D10's media does and today's ⌘O does:
as a `change` on the node the command names. The value is the `doc:` path,
or an empty string on cancel, which keeps whatever was open (LLP 1033's
milestone). Where the host exposes the panel's type filter, the
declarations in `file_handlers` set it. ⌘O becomes
`showOpenFilePicker("open-file")`, issued by the host's File menu for any
app that declares documents, as it is today.

**It has to be a command.** The web grants the pickers only under transient
user activation. The runner processes a click synchronously inside the DOM
event, so a command emitted by that click's handler runs while the
activation holds. A data source asking later would not.

*Rejected:* one `pick(kind)` command with host words. The web has three
calls with three results, and the names are free.

### D3 — Export and import are copies the host makes

Most apps that "save a file" are exporting: a backup, a CSV, a rendered
image. For them the handle of D1 is more than they need. D3 covers them
with no `fs.document` grant:

- **`saveFile(id, from, suggestedName)`.** The host copies the `app:/` file
  `from`, which the app already wrote under its own grant, to where the user
  chooses:
  - macOS: `NSSavePanel`, then a copy.
  - iOS: the exporting document picker.
  - Web: `showSaveFilePicker` where it exists, or a download
    (`<a download>`) in Safari and Firefox.

  The result at `id` is the chosen name, or empty.
- **Import is D2's `showOpenFilePicker`.** Then the host copies the chosen
  file *into* `app:/tmp/…` and delivers that `app:/` path, so a read-only
  import needs no `fs.document` grant either.

Fieldnotes then has File ▸ Export Backup… (`saveFile`) and Import Backup…
(an open that copies in) on three hosts, with the grants it already has.

### D4 — A second document opens in a second window, when the manifest says so

The manifest takes the W3C Web App Manifest's `launch_handler`:

- **`client_mode: "navigate-existing"`** is today's behaviour, and the
  default for an app that declares documents: an opened document replaces
  the current one.
- **`client_mode: "navigate-new"`** opens each document in a new window.
  File ▸ New Window (⌘N) opens an empty one.
- **`client_mode: "focus-existing"`** brings the window forward and
  delivers nothing new.

On macOS each window gets one `ExactSession` and one `ExactView`, which is
exactly what LLP 1031 built for embedders. `main.swift`'s global `window`
becomes a list owned by the app delegate, and document delivery goes to
the key window's session, or to a new one under `navigate-new`. The
consequences:

- **Window tabs come free.** `NSWindow.tabbingMode = .automatic` with a
  shared `tabbingIdentifier` gives the system's tab bar and
  View ▸ Show Tab Bar.
- **Memory is the cost.** LLP 1031 D7 counts it: a second session is a
  second runner and, for a TypeScript app, a second Hermes heap. The Rust
  readers pay only the runner and the plan's values. It is measured with
  `metrics.mjs` on the LLP reader before this ships.
- **Shared storage between windows.** Two sessions of Fieldnotes would open
  one SQLite file. Whether ibex2-sqlite's per-session connection is safe
  there, and whether one window should hear the other's writes (LLP
  1016.002's topics are the obvious carrier), is Question 3. Until it is
  answered, Fieldnotes stays `navigate-existing`.

iOS already has windows through scenes. `navigate-new` on an iPad opens a
scene per document, and the same rule applies with `UIScene`. The web
opens a tab, which is `launchQueue`'s own behaviour for `navigate-new`.

*Rejected:* one session showing several documents in its own tabs. That is
an app's choice in Contract already, and it isn't what ⌘N means on a Mac.

### D5 — Open Recent without `NSDocument`

Whenever a document path is minted from a real file URL on macOS, the host
calls `NSDocumentController.shared.noteNewRecentDocumentURL(url)`.
AppKit's File ▸ Open Recent is populated from that list, and choosing an
entry calls `application(_:open:)`, which is route four of LLP 1033 D3.
Nothing else is needed. The list is the system's, and "Clear Menu" works.

This depends on today's unsandboxed build. Under the App Sandbox the
recent list needs security-scoped bookmarks, which is D1's refused durable
grant. A Mac App Store build will need it or will have no Open Recent
(Question 2). iOS keeps its recents in Files, and the web has none. Both
are declared absences, not deviations.

### D6 — The title and the edited mark are the app's `head`

LLP 1048's `head` tag already carries `title` for pages. On macOS and iOS
that title becomes the window title (`NSWindow.title`, the scene's
`title`), which removes `ExactDocuments.windowTitle`'s guess from a path
(LLP 1033 D7 put it in the host only because the app had no hook).

The edited mark is the one piece the web has no name for, since a page has
no "unsaved" dot. It is declared as a deviation: a `head` attribute
`edited` sets `NSWindow.isDocumentEdited`. `representedURL`, for the proxy
icon, is set by the host from the window's document path. The web's
nearest behaviour, `beforeunload`, stays out: the app autosaves (D7).

### D7 — No `NSDocument`; the app saves

`NSDocument` owns reading, writing, the undo manager, autosave, versions
and the close/quit dialogs. Each of those is state the runner already owns
(LLP 1005) or the app's data source already writes. Two owners of "is this
saved?" is the four-disagreeing-layers bug the root map warns about.
Instead:

- **Autosave is the app's.** An editor writes through its source on change
  or on a timer (Fieldnotes already writes every edit to SQLite).
- **No versions browser, and no "Revert To".** Time Machine still works on
  the file.
- **No save-on-quit dialog.** `applicationShouldTerminate` stays
  unimplemented. An app that must flush writes on quit is Question 4.

## Carrying the vocabulary to iOS and the web

| piece | macOS | iOS | web |
|---|---|---|---|
| declared types | `file_handlers` → `CFBundleDocumentTypes` (built) | the same plist, plus `LSSupportsOpeningDocumentsInPlace` | `file_handlers` in the manifest (installed PWA) |
| arrival | `application(_:open:)`, argv, drop (built) | `scene(_:openURLContexts:)` | `launchQueue.setConsumer` (Chromium) |
| open / folder / save | D2 | D2 | D2, with fallbacks |
| export / import | D3 | D3 | D3 (download where no save picker) |
| windows | D4 | scenes | tabs |
| recents | D5 | Files | none |
| title | D6 | D6 | `document.title` (already) |

The Linux host refuses every picker and journals the refusal. It has no
file manager to hand off to, and its documents arrive through
`EXACT_LAUNCH_URL`, as today.

## The trade

`rules/DEFERRED.md` (LLP 1045 D10) allows `fileinput` "in one form — an
image/video picker … no generic file input". D2 and D3 are file input, so
this needs a line moved.

**Proposed line:** a picker for the types an app declares in
`file_handlers`, plus the export copy. It unblocks the Markdown reader's
remaining surfaces and Fieldnotes' backups. The types stay bounded by the
manifest, so no app gets a picker for "any file".

**What comes off is Charlie's to name** (Question 1). Candidates, from what
this document chooses not to do anyway:

- Quick Look and thumbnail extensions.
- App Intents.
- The browser's handle persistence.

## Verification

- **Agent.** A panel isn't drivable (LLP 1033 "what remains"). Under LLP
  1069.007, in agent mode a picker command doesn't open a panel. It is
  answered by `type <id> <path>`: the path is minted into a `doc:` handle
  exactly as a chosen file would be, and `state` shows the picker as
  pending until answered. The existing `type open-file …` route becomes
  that same answer, so no ninth operation is added.
- **Smoke.** `smoke.mjs macos --app markdown` opens two documents under
  `navigate-new` and reads both windows' trees. The carrier addresses a
  window by its session, as `agent.mjs host --session a` does.
- **Fieldnotes.** Fieldnotes exports on macOS, web and iOS, and the export
  is checked by reading it back through import.

## Slices, in consumer order

1. **Markdown/LLP reader, macOS:**
   - D5 Open Recent.
   - D6 title from `head` (delete `windowTitle`).
   - D4 `launch_handler`, windows and tabs.
   - Measure the second session.
2. **Fieldnotes:** D3 export and import on macOS, then the web, then iOS.
3. **D1 and D2:** `doc:` handles, `fs.document`, the three pickers. The
   Markdown data crate moves from `std::fs` to storage requests.
4. **Readers on iOS and the web:** Files "Open in", `launchQueue`.

## Not in this RFC

Each has a trigger that would bring it back:

- **Quick Look preview and thumbnail extensions.** Each is a second
  executable that renders the document without the app. The native Rust
  renderer of LLP 1048 could supply one. Trigger: a reader people install.
- **Spotlight, Shortcuts and Siri through App Intents** (Expo 58's
  `expo-app-intents` is alpha). Trigger: an app with an action worth
  invoking outside itself.
- **The App Sandbox and Mac App Store distribution.** `exact release` is
  Developer ID today (LLP 1033 D8). The sandbox would need D5's bookmarks
  and the entitlement `com.apple.security.files.user-selected.read-write`.
- **`NSDocument`, versions, iCloud documents, and `UIDocumentBrowserViewController`
  as the iOS root.**
- **Drag out of the app** (a document to Finder). Dropping *in* is a route
  in D1.
- **Services, Share menu and printing.** Sharing is LLP 1069.003.

## Questions for Charlie

1. **The trade.** Does "a picker for the types in `file_handlers`, plus the
   export copy" come off `DEFERRED.md`, and what goes on in its place?
2. **The sandbox.** Is a Mac App Store build a goal? If so, D5 needs
   security-scoped bookmarks, a durable grant that `DEFERRED.md` refuses.
3. **Shared storage.** Two windows of one app sharing one SQLite database:
   supported (with LLP 1016.002 topics as the carrier), or `navigate-new`
   refused for apps with an ordered store?
4. **Writes at quit.** Should an app be able to hold quit until its writes
   flush (`applicationShouldTerminate` → `.terminateLater`), or is "every
   write is already committed" the rule?
