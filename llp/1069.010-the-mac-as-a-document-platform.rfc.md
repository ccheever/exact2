## Summary

An exact2 app can already *open* a document on macOS. `file_handlers` in
the manifest becomes `CFBundleDocumentTypes`; Finder, Open With, the
command line and ⌘O all deliver a path to the one `open-file` node, and the
app's Rust reads it (LLP 1033 D1–D3). That's where it stops:

- **Save anywhere.** There is no `NSSavePanel`. Fieldnotes' backup is
  written to `app:/data/backups` and then "ready to copy".
- **A second document beside the first.** There is one global `window`
  (`main.swift:113`), and a second open replaces the document.
- **Open Recent.**
- **TypeScript can't read what was opened.** A path is readable only from
  Rust's `std::fs`, ungated. A grant is `app:/…` or an absolute prefix fixed
  at bake.

This RFC proposes six pieces, named by the web where the web has a name:

1. **A chosen document is a handle, not a path (D1).** The host mints a
   `doc:` path per chosen file or folder, good for the session and admitted
   by `fs.read doc:` / `fs.write doc:`. It is the File System Access API's
   `FileSystemHandle`.
2. **The pickers are the web's calls, as commands (D2):**
   `showOpenFilePicker`, `showDirectoryPicker`, `showSaveFilePicker`. Each
   result arrives at a node the command names, as LLP 1069.002's does.
3. **Export is a copy the host makes; import is LLP 1069.002's element
   (D3).** Fieldnotes needs nothing more.
4. **A second document opens in a second window (D4)** under the W3C
   `launch_handler`'s `navigate-new`, one session per window (LLP 1031).
   Window tabs come with it. Windows may share one store.
5. **Open Recent (D5)** via `noteNewRecentDocumentURL`, with no
   `NSDocument`.
6. **The edited mark (D6)** as a `head` attribute; the title already comes
   from `head`.

**Deliberately not built:** `NSDocument`'s ownership of saving, undo and
versions (D7); handles that outlive a launch (a durable capability grant,
which `rules/DEFERRED.md` refuses); the App Sandbox (a later goal, kept
possible); Quick Look, thumbnails and App Intents.

## Motivation

**The Markdown reader and the LLP reader (LLP 1033).** Charlie reads this
corpus in them. Today:

- A second `mdview` hands its file to the running copy, and the first
  document is gone.
- ⌘N does nothing; there is no Open Recent.
- Relaunching opens nothing (`window.isRestorable = false`, `main.swift:121`).
- The window title comes from `ExactDocuments.windowTitle`'s guess from the
  path (`main.swift:176`, `:291`, `:304`).
- The reader's "what remains" lists iOS file opening and `launchQueue`.

**Fieldnotes (the storage consumer).** It writes a JSON backup to
`app:/data/backups/fieldnotes.json`. The only way out is the clipboard;
restoring means pasting JSON into a text area. A notes app is expected to
have File ▸ Export… and Import…, and the same on the web as a download.
Fieldnotes is TypeScript on a worker, so it needs a grant, not `std::fs`.

**Expo has no counterpart** (LLP 1069 §4): Expo doesn't ship macOS.

## Design

### D1 — A chosen document is a handle, named `doc:`

Every route that brings a user-chosen file or folder in mints a **document
path**, `doc:/<n>/<name>`. The host keeps the real location behind `<n>`:

- **macOS:** a security-scoped URL, with
  `startAccessingSecurityScopedResource` held while the session lives. A
  no-op for today's unsandboxed Developer ID builds, required under the
  sandbox, and the thing a security-scoped bookmark would later be made
  from (ruled: stay expressible that way).
- **iOS:** the `UIDocumentPickerViewController` URL, under the same calls.
- **Web:** a `FileSystemFileHandle` or `FileSystemDirectoryHandle` held by
  the glue.

The routes: Finder, Open With, the command line, ⌘O, a dropped file,
`launchQueue` on the web, and "Open in" from Files on iOS.

`storage.fs` reads and writes a `doc:` path as it does an `app:/` one:
`readFile`, `writeFile` and `atomicWriteFile` on a file; `readdir` and paths
beneath it on a folder (the LLP reader opens one); `..` refused as
`PathPrefix` refuses it.

The grants are the existing file grants over the new namespace:

```
fs.read doc:/      // the Markdown and LLP readers
fs.write doc:/     // an editor that saves in place
```

`PathPrefix::new` gains `doc:` beside `app:`, so the grammar and `ibex2`'s
checks are unchanged (`vendor/ibex2/src/grant.rs`, `fs.read` / `fs.write`).
A `doc:` path exists only once the host has minted it, so the grant admits
*what the user chose*, never a location the app names. The host forgets
every handle when the session ends.

The value delivered to `open-file` becomes the document path. An app that
wants a display name asks `storage.fs.stat(doc)` for its `name`
(`FileSystemHandle.name`; the web exposes no more). Rust apps that read with
`std::fs` today (the Markdown data crate) move to LLP 1027.001's storage
requests in the same change. Delete, don't deprecate.

*Rejected:* absolute paths and grants widened to `/`. It works unsandboxed
on the Mac and nowhere else, and the grant would stop meaning anything.

*Rejected:* a separate `fs.document read|readwrite` capability (r1's
spelling). It duplicates `fs.read`/`fs.write` and bypasses `PathPrefix`.

*Rejected, for now:* a handle that outlives the launch (a bookmark on
Apple, a handle in IndexedDB on the web). A durable capability grant;
`rules/DEFERRED.md` refuses it.

### D2 — The web's pickers, issued as commands

| command | macOS | iOS | web | Linux |
|---|---|---|---|---|
| `showOpenFilePicker(id, multiple?)` | `NSOpenPanel`, files | `UIDocumentPickerViewController(forOpeningContentTypes:)` | `showOpenFilePicker`; else refused (Safari, Firefox) | refused |
| `showDirectoryPicker(id)` | `NSOpenPanel`, folders | the same picker, `.folder` | `showDirectoryPicker`; else `<input type=file webkitdirectory>` | refused |
| `showSaveFilePicker(id, suggestedName)` | `NSSavePanel` | `UIDocumentPickerViewController(forExporting:)` after D3's copy | `showSaveFilePicker`; else D3's download | refused |

These open a document **in place** and yield a `doc:` handle. A read-only
copy is LLP 1069.002's `input type=file`, which works on every browser;
that is why a browser without `showOpenFilePicker` refuses rather than
falling back to it with different semantics.

- **Types** come from `file_handlers`, never from the command, so an app
  can't widen them per call. That bounds the trade.
- **The result** arrives as `change` on the node the command names, as LLP
  1069.002's does: the `doc:` path, or `cancel` (HTML's event) on cancel,
  which keeps whatever was open (LLP 1033's milestone). ⌘O becomes
  `showOpenFilePicker("open-file")`, issued by the host's File menu for an
  app that declares documents, as today.
- **User activation.** The web grants these pickers only under transient
  activation; the glue runs a command inside the click's dispatch, so a
  pressed action works. Native hosts don't enforce it (LLP 1069.002's
  ruling applies here too).
- **Linux** refuses and journals it; the substitute (§Substitute) answers.

*Rejected:* one `pick(kind)` command with host words. The web has three
calls with three results, and the names are free.

### D3 — Export is a copy the host makes; import is LLP 1069.002

Most apps that "save a file" are exporting: a backup, a CSV, a rendered
image. D1's handle is more than they need.

- **`saveFile(id, from, suggestedName)`.** The host copies the `app:/` file
  `from`, which the app already wrote under its own grant, to where the
  user chooses: `NSSavePanel` then a copy on macOS; the exporting document
  picker on iOS; `showSaveFilePicker`, or a download (`<a download>`) in
  Safari and Firefox, on the web. The result at `id` is the chosen name, or
  `cancel`. The web has no single name for "copy this file out", so the
  name is a declared deviation.
- **Import is LLP 1069.002's `input type=file`,** with `accept` naming a
  `file_handlers` type. The host copies the chosen file into
  `app:/tmp/picked/` and delivers `Picked` records, so a read-only import
  needs no `doc:` grant.

Fieldnotes then has File ▸ Export Backup… (`saveFile`) and Import Backup…
(the element) on three hosts, with the grants it already has.

### D4 — A second document opens in a second window, when the manifest says so

The manifest takes the W3C Web App Manifest's `launch_handler`:

- **`client_mode: "navigate-existing"`** is today's behaviour, and the
  default for an app that declares documents.
- **`"navigate-new"`** opens each document in a new window; ⌘N opens an
  empty one.
- **`"focus-existing"`** brings the window forward and delivers nothing.

On macOS each window gets one `ExactSession` and one `ExactView`, what LLP
1031 built for embedders. `main.swift`'s global `window` becomes a list
owned by the app delegate; document delivery goes to the key window's
session, or to a new one under `navigate-new`.

- **Window tabs come free.** `tabbingMode = .automatic` with a shared
  `tabbingIdentifier`.
- **Memory is the cost.** A second session is a second runner and, for a
  TypeScript app, a second Hermes heap (LLP 1031 D7). Measured with
  `metrics.mjs` on the LLP reader before this ships.
- **Two windows share one store** (ruled). Two sessions of Fieldnotes open
  one SQLite file through two connections in one process, which SQLite
  supports; the spec verifies it under ibex2-sqlite's journal mode. What is
  owed is the notification: a committed write in one session announces an
  LLP 1016.002 topic that the other session's readers watch, and they
  re-ask. The app owner, which holds both sessions, carries it. It lands
  with Fieldnotes; until then Fieldnotes stays `navigate-existing`.

iOS has windows through scenes: `navigate-new` on an iPad opens a scene per
document. The web opens a tab, `launchQueue`'s own behaviour.

*Rejected:* one session showing several documents in its own tabs. That is
an app's choice in Contract already, and not what ⌘N means on a Mac.

### D5 — Open Recent without `NSDocument`

Whenever a document path is minted from a real file URL on macOS, the host
calls `NSDocumentController.shared.noteNewRecentDocumentURL(url)`. AppKit's
File ▸ Open Recent fills from that list; choosing an entry calls
`application(_:open:)`, route four of LLP 1033 D3. "Clear Menu" works.

This depends on today's unsandboxed build. Under the sandbox the list needs
security-scoped bookmarks, which D1's `startAccessing…` URL can make; that
is the path kept open for a Mac App Store build (ruled), not built now. iOS
keeps its recents in Files, and the web has none: declared absences.

### D6 — The title is the app's `head`; the edited mark is a deviation

**The title is built.** The head's `title` (LLP 1048.003 D1) already reaches
the window: `Session.swift:678` hands it to the presenter, and on macOS
`ToolbarMac.swift:42-58` sets `NSWindow.title` from it (the scene's title on
iOS, `PresenterIOS.swift:1000`). What is left is for the readers to emit
`head title`, and then to delete `ExactDocuments.windowTitle`'s guess from a
path (`DocumentsMac.swift:64`, used at `main.swift:176`, `:291`, `:304`).

**The edited mark** has no web name: a page has no "unsaved" dot. It is a
declared deviation, a `head` attribute `edited` that sets
`NSWindow.isDocumentEdited`. `representedURL`, for the proxy icon, is set by
the host from the window's document path. `beforeunload` stays out: the app
autosaves (D7).

### D7 — No `NSDocument`; the app saves

`NSDocument` owns reading, writing, undo, autosave, versions and the
close/quit dialogs. Each is state the runner owns (LLP 1005) or the data
source writes. Two owners of "is this saved?" is the four-disagreeing-layers
bug the root map warns about.

- **Autosave is the app's.** An editor writes through its source on change
  or on a timer (Fieldnotes writes every edit to SQLite).
- **No versions browser, no "Revert To".** Time Machine still works.
- **No save-on-quit dialog and no quit hold.** Every write is already
  committed (ruled); `applicationShouldTerminate` stays unimplemented.

## Carrying the vocabulary to iOS and the web

| piece | macOS | iOS | web |
|---|---|---|---|
| declared types | `file_handlers` → `CFBundleDocumentTypes` (built) | the same, plus `LSSupportsOpeningDocumentsInPlace` | `file_handlers` in the manifest (installed PWA) |
| arrival | `application(_:open:)`, argv, drop (built) | `scene(_:openURLContexts:)` | `launchQueue.setConsumer` (Chromium) |
| open in place / folder / save | D2 | D2 | D2, where the browser has it |
| export / import | D3 | D3 | D3 (download where no save picker) |
| windows | D4 | scenes | tabs |
| recents | D5 | Files | none |
| title | `head` (built) | `head` (built) | `document.title` (built) |

The Linux host refuses every picker and journals it. Its documents arrive
through `EXACT_LAUNCH_URL`, as today.

## The trade (taken)

`rules/DEFERRED.md` allowed `fileinput` "in one form — an image/video
picker … no generic file input". Widened 2026-09-27: a picker for the types
an app declares in `file_handlers`, plus export and import copies to and
from `app:/`. The types stay bounded by the manifest, so no app gets a
picker for "any file". No take was named (Charlie: "maybe relax the limit
slightly").

## Substitute

LLP 1069.007 D7's paragraph:

1. **Shape:** requests, command-shaped; the answer arrives as `change` on
   the named node.
2. **Pending:** a picker command under the agent opens no panel.
   `state.pending` lists it with `capability` `open-file`, `open-directory`,
   `save-file` or `export`, and `args` (the node id, `multiple`,
   `suggestedName`, the `file_handlers` types). **Answer:** `type @t <path>`
   (the path minted into a `doc:` handle exactly as a chosen file would be;
   for `save-file` and `export`, the chosen name, the copy written into a
   scratch directory the driver reads back), `tap @t cancel`. **Fixture:**
   `--answer open-file=<path>`. `delivery` is `substituted`.
3. **Web override:** none for the File System Access pickers; the glue
   holds them.

Today's `type open-file <path>` stays what it is: typing into the node,
which now mints a `doc:` handle for the path.

## Verification

- **Smoke.** `smoke.mjs macos --app markdown` opens two documents under
  `navigate-new` and reads both windows' trees, addressing a window by its
  session, as `agent.mjs host --session a` does.
- **Fieldnotes.** Exports on macOS, web and iOS, and reads the export back
  through import; with two windows open, an edit in one appears in the
  other after the topic's re-ask.

## Slices, in consumer order

1. **Markdown/LLP reader, macOS:** D5 Open Recent; `head title` in the
   readers and `windowTitle` deleted (D6); D4 `launch_handler`, windows and
   tabs; the second session measured.
2. **Fieldnotes:** D3 export on macOS, then the web, then iOS; import
   through LLP 1069.002's element; the cross-window topic (D4).
3. **D1 and D2:** `doc:` handles, the `fs` grants over them, the three
   pickers. The Markdown data crate moves from `std::fs` to storage
   requests.
4. **Readers on iOS and the web:** Files "Open in", `launchQueue`.

## Not in this RFC

Each has a trigger that would bring it back:

- **Quick Look preview and thumbnail extensions.** A second executable that
  renders the document; LLP 1048's native renderer could supply one.
  Trigger: a reader people install.
- **Spotlight, Shortcuts and Siri through App Intents.** Trigger: an app
  with an action worth invoking outside itself.
- **The App Sandbox and Mac App Store distribution.** A later goal (ruled):
  D5's bookmarks and `com.apple.security.files.user-selected.read-write`.
  Nothing here may make it harder.
- **`NSDocument`, versions, iCloud documents,
  `UIDocumentBrowserViewController` as the iOS root.**
- **Drag out of the app.** Dropping in is a route in D1.
- **Services, Share menu and printing.** Sharing is LLP 1069.003.

## Decided

1. The trade is taken: a picker for `file_handlers` types, plus export and
   import copies; no take named.
2. The Mac App Store is a later goal: handles and recents stay expressible
   as security-scoped bookmarks; no sandbox work now (D1, D5).
3. Two windows may share one store; the cross-window notification over an
   LLP 1016.002 topic is owed and lands with Fieldnotes (D4).
4. Every write is already committed; no quit hold (D7).
5. Import is LLP 1069.002's element; the document grants are `fs.read doc:`
   and `fs.write doc:` (D1, D3).

## As built: slice 1 (2026-09-27)

Built by Claude (Opus 5.5): the Markdown and LLP readers on macOS. Where
the build differs from the design above, it says so here.

- **The title (D6).** Both readers emit `head title`. Markdown's is the
  file's name (the welcome document's is "Markdown"): with a window per
  document, two windows or tabs from one folder have to tell apart, so the
  folder rule of LLP 1033 D7 no longer fits it. The LLP reader keeps that
  rule through `head`: "LLP — exact2". `ExactDocuments.windowTitle` and its
  XCTest are deleted; a window is called by the app's name until its head
  arrives (`ToolbarMac.swift`, unchanged).
- **`launch_handler` (D4).** `app.json` takes the W3C key
  (`scripts/app.schema.json`: `client_mode` a mode or the W3C list, `auto`
  meaning the default). The Apple bake writes the first mode it has as
  `ExactLaunchMode` beside `CFBundleDocumentTypes`, so only an app that
  declares documents gets one. Both readers say `navigate-new`.
- **Windows (D4).** `ExactMac/main.swift` holds a list of `DocumentWindow`s
  (a window, its `ExactSession`, its `ExactView`). Every route in ends at one
  router, `ExactDocuments.route`: Launch Services, the command line, ⌘O,
  and Open Recent. Under `navigate-new` the window in front takes a
  document while it shows none, and otherwise a new window does: a session
  labelled `window-2`, `window-3`, …, booted from the plan the first one
  runs (`EXACT_PLAN` included), cascaded from the window in front, or a tab
  of it when its tab bar is showing. `focus-existing` delivers only to a
  window that shows nothing. File ▸ New Window (⌘N) and the tab bar's +
  are `newWindowForTab:`. Every window has the bundle id as its
  `tabbingIdentifier`, so Window ▸ Merge All Windows and the "prefer tabs"
  setting work. Closing a window destroys its session (LLP 1031 D2) and
  drops its label from the carrier. A followed link still opens in its own
  window, as a link does on the web. `setScheme` is still the app's
  appearance, so choosing dark in one window darkens both.
- **Open Recent (D5).** `ExactDocuments.deliver` notes every path it
  delivers that exists (`noteNewRecentDocumentURL`), so every route but a
  path typed into the field adds to the list. The list is
  `NSDocumentController`'s; **the menu is drawn by the host**
  (`RecentMenu` in `DevMenuMac.swift`) from `recentDocumentURLs`, with
  "Clear Menu" sent to `NSDocumentController`. AppKit fills its own recent
  menu only for a menu a nib names, or one named through the private
  `_setMenuName:`, which the Mac App Store refuses (ruled: keep it
  possible). Choosing an entry calls the router, not
  `application(_:open:)`. Names that repeat get their folder added, as
  AppKit's own menu does.
- **The carrier (no new operation).** A session made after the carrier
  started joins it (`Agent.route(label, session)`), so `--session
  window-2` addresses the second window as `agent.mjs host --session a`
  does. `state` gains `documents`: the launch mode, each window (session,
  title, document, key, tab count, first pixel, the footprint before it
  opened), `recent`, the Open Recent menu's titles as drawn, and the
  process footprint. `agent.mjs --open <document>` (repeatable) names the
  Mac command line, the terminal's route in (LLP 1033 D3), which an agent
  run now honours; the boot smoke still doesn't. `smoke.mjs macos` step 16
  opens two documents for a `navigate-new` app, reads both windows' trees
  by session, and checks each window's title against its `Head` and Open
  Recent against both.
- **Measured (the second session).** `agent.mjs --open` with the same
  document once and twice, three runs each, the process's physical
  footprint after `clock settle`. Markdown (`apps/markdown/README.md`): one
  window 25–28 MB, two 34–35 MB, so the second session costs **7–8 MB**.
  LLP (the `llp/` corpus): one window 64–66 MB, two 96–100 MB, so **31–36
  MB**, most of it the corpus index each session's data source holds.
  Time to first pixel for the second window, from the router asking for it
  to its first draw: **32–47 ms** (the first window's is 100–145 ms from
  process start). Both readers are Rust, so no Hermes heap is in these.
- **Not verified by driving.** Clicking an Open Recent entry or Clear
  Menu, ⌘N, the tab bar's +, merging into tabs, and closing a window (the
  agent drives no menu bar and closes no window). The Launch Services
  route into a running app (`open -a`, a second `mdview`): the agent runs
  a bare executable, which Launch Services doesn't route to. An agent run
  adds its documents to the real Open Recent of the bundle id it shares
  with the installed reader; the smoke opens files in the checkout for
  that reason.

## As built: slice 2 (2026-09-27)

Built by Claude (Opus 5.5): Fieldnotes' export (D3) on macOS, the web and
iOS, read back through LLP 1069.002's import. Where the build differs from
the design above, it says so here.

- **The command.** `saveFile(id, from, suggestedName)` is a host command
  of three strings (`type-save-file-argument` otherwise, one reject
  fixture). `id` names the element whose `change` takes the chosen name
  (the name only, never a path) and whose `cancel` takes a dismissed
  panel. Fieldnotes names a hidden `input`, as its import names a hidden
  file input; any element will do, so the runner now takes `cancel` on any
  element (it was a file input's alone).
- **One rule on every host** (`runner/src/save_file.rs`). The runner
  refuses into the journal (`saveFile: refused: <reason>`) a `from` that is
  not a plain `app:/<root>/<file>` or that no `fs.read` grant covers
  (component-wise, as `PathPrefix` reads it: `app:/data/backups` covers
  `app:/data/backups/x`, never `app:/data/backupsx`), a suggested name
  that is not a file name, and an unknown `id`; the host then fires
  `cancel` at the element when there is one. Under the agent it holds
  `export`; otherwise it says present. The journal says `saveFile: saved`,
  `saveFile: cancelled`, never a path or a chosen name.
- **One door for rulings.** `exact_share` became `exact_command` on the web
  and Apple ABIs (`runner/src/commands.rs` routes `share` and `saveFile`),
  so the pickers of slice 3 need no new export. Delete, don't deprecate.
- **macOS:** an `NSSavePanel` sheet on the session's window, typed by the
  suggested name's extension; the copy replaces what the person agreed to
  replace, under `startAccessingSecurityScopedResource` (a no-op
  unsandboxed; what the sandbox would need, ruled Q2). The `app:/` file
  comes from a new agent-channel op, `appFile`, which the Apple host
  answers from the roots storage configured (`host/apple/src/picker.rs`).
- **iOS:** the file is copied under the suggested name into a scratch
  directory and handed to `UIDocumentPickerViewController(forExporting:
  asCopy: true)`; the scratch copy is removed when the picker finishes.
  The picker is the same `Picker` object as import's, which routes its
  delegate calls (`SaveFile.swift`).
- **Web:** `showSaveFilePicker({suggestedName})` is called synchronously in

## As built: slice 3 (2026-09-27)

Built by Claude (Opus 5.5): D1's `doc:` handles and D2's three pickers on
macOS, iOS, the web and Linux; the Markdown reader reads through storage.
Where the build differs from the design above, it says so here.

- **The grammar.** `PathPrefix::new` takes `doc:/` beside `app:/` (an Exact
  patch to `vendor/ibex2/src/grant.rs`; `realized_fs` keeps it logical, as
  it keeps `app:`), so `fs.read doc:/` and `fs.write doc:/` parse and check
  as every file grant does.
- **The table** (`exact_data::documents`). `mint` gives `doc:/<n>/<name>`
  for a real path (canonicalized, so `/tmp` and `/private/tmp` are one
  handle; a file that does not exist yet, a save, keeps its spelling),
  owned by a session; `<n>` is never reused. `resolve` refuses a handle
  never minted or forgotten, a first segment that is not the handle's
  name, and `.`, `..` or empty segments. `doc:/<n>` itself is a read-only
  directory holding only its entry. Apple's owner is the `ExactSession`,
  whose `destroy` forgets its handles and stops their security scopes;
  Linux has one session (owner 0); the web's table lives as long as the
  page.
- **Storage over it** (`data/host/src/documents.rs`; the web's
  `documents-glue.js`). A storage request on a `doc:` path is checked
  against `fs.read doc:/` or `fs.write doc:/`, then runs on the real
  location: `readFile`, `writeFile`, `atomicWriteFile` (staged beside the
  target, then renamed), `appendFile`, `stat`, `readdir`, `mkdir`, and `rm`
  (not recursive); `realpath`, `rename` and `copyFile` are refused. It
  needs no app directories, so a drive without `--storage` still reads
  what it opened. On the web a write asks the handle for `readwrite` first.
  **Not built:** `doc:` paths from TypeScript sources, whose storage runs
  in the JS runtime's own ibex2 session (QUEUE).
- **The routes.** The value delivered to `open-file` is the document path,
  minted where each host receives it: Apple's session (`documentValue`,
  every change at a node whose `testId` is `open-file`, which covers
  Launch Services, the command line, ⌘O, Open Recent and a typed path),
  Linux's `Host::dispatch_at`. **Two deviations.** A file arriving by a
  host route is delivered beneath a handle to its folder
  (`doc:/<n>/<folder>/<file>`, `open_route`), so the reader keeps listing
  what is beside it and following relative links; a picker's choice is
  minted exactly. Under the App Sandbox the folder would not be readable,
  and the file alone would be minted instead (not built; nothing here
  prevents it). And only an app granted `fs.read doc:/` gets a document
  path: the LLP reader still reads its corpus with `std::fs` and still
  receives the path it always did (its move is QUEUE'd; the design says
  every such app moves in this change). ⌘O stays the host's own panel, a
  route, rather than becoming `showOpenFilePicker("open-file")` as D2 said,
  so that it lists the folder too; its URL is kept under its security
  scope. A followed `doc:` link is delivered to the session it came from.
- **The pickers** (`runner/src/file_pickers.rs`, one rule for every host,
  through `exact_command`). `showOpenFilePicker(id)` or `(id, multiple)`,
  `showDirectoryPicker(id)`, `showSaveFilePicker(id, suggestedName)`
  (`type-file-picker-argument` otherwise). The handles arrive as `change`
  on the element `id` names, one per line under `multiple`; a dismissal is
  `cancel`; the journal says `<command>: chosen`, `cancelled` or `refused:
  <reason>`, never a path. Types come from `CFBundleDocumentTypes` on Apple
  and the web build's `manifest.json` `file_handlers`, never the command.
  macOS: an `NSOpenPanel` or `NSSavePanel` sheet. iOS:
  `UIDocumentPickerViewController(forOpeningContentTypes:asCopy: false)`
  (`.folder` for a directory); a save moves an empty scratch file under the
  suggested name with `forExporting:asCopy: false`, whose new location is
  the handle. Web: the browser's picker, called once the lazy module has
  loaded (still inside the press's activation window, but not synchronously
  as `saveFile`'s is); a browser without it refuses (`refused:
  unavailable`) and fires `cancel`, as ruled. Linux refuses the same way.
  Every chosen URL on Apple stays under `startAccessingSecurityScopedResource`
  until its session ends.
- **The substitute.** `pending` shows `open-file` (`{id, multiple}`),
  `open-directory` (`{id}`), `save-file` (`{id, suggestedName}`). `type @t
  <path>…` is checked before the hold is spent (absolute paths, one unless
  `multiple`); each native host mints the paths, and the web page is sent
  each file's bytes, a folder's tree, or a name, which it keeps as handles
  that behave as the browser's. **Not built:** reading back what an app
  wrote through a web `save-file` substitute. `--answer` fixtures are not
  built (LLP 1069.007).
- **Markdown** (`apps/markdown/data`, now wrapped in `exact_data_host::
  Storage` and granted `fs.read doc:/`). `open(path)` is storage requests:
  `fs.stat`; a folder's `fs.readdir` for its README; `fs.readFile`; the
  folder's `fs.readdir` for the list beside it (skipped for a file chosen
  alone, whose handle holds nothing else); then the parse on the host's
  worker, or inline in a browser, which has none. A path never minted is
  refused (`… is not a document you opened`) over the open document. Links
  resolve lexically beside the document; one that leaves the chosen
  folder names no document and is refused on open. The header gains
  **Open…** and **Folder…** (`showOpenFilePicker("open-file")`,
  `showDirectoryPicker("open-file")`), so the web reader opens local files
  in Chromium for the first time.
- **Verified by driving.** macOS Markdown with `--open <file>`: the field
  holds `doc:/1/notes/README.md`, the document and the list beside it come
  through storage, a sibling opens, a typed path lands in the same handle,
  `doc:/77/…` is refused and the document stays. The pickers fixture
  (`contract/corpus/file-pickers.contract`) on macOS, the web and Linux:
  each picker held with its summary, two paths for one file refused,
  `doc:` handles delivered (two lines under `multiple`), a folder, a save
  name, `tap @N cancel` firing `cancel`; it is now a `smoke.mjs` step on
  every host. Markdown's Folder… and Open… under the agent on the web,
  macOS and the iOS simulator: the folder's README with its list, a
  sibling, a file alone. Unit tests: the table, storage over it with and
  without the grant, and Markdown's storage steps and superseded parse.
- **Not verified.** A real `NSOpenPanel`, `NSSavePanel` or document picker
  choice; a real browser picker (only the agent's handles); a write
  through a real `FileSystemFileHandle`; anything under the App Sandbox;
  a phone.

## As built: slice 4 (2026-09-27)

Built by Claude (Opus 5.5): the readers open documents handed to them on
iOS (Files "Open in") and on the web (`launchQueue`).

- **iOS.** The iOS `Info.plist` had no document types at all; it now takes
  the Mac's `CFBundleDocumentTypes` from `file_handlers`, with
  `LSSupportsOpeningDocumentsInPlace`, and `UTImportedTypeDeclarations`
  for a non-`public.` type the manifest names (Markdown's
  `net.daringfireball.markdown`: its extensions and MIME type, conforming
  to plain text), so Files can match it. A file URL reaching the scene —
  `scene(_:willConnectTo:)`'s `urlContexts` on a cold launch,
  `scene(_:openURLContexts:)` while running — is minted exactly (the file
  alone, under its security scope) and delivered to `open-file` once the
  session has booted (`ExactSession.openDocument`); every other URL is a
  link, as before. One scene: `navigate-new` scenes on an iPad are not
  built.
- **Web.** The web build's `manifest.json` now carries `file_handlers`
  (less `inode/directory`, which is the Apple bake's word for a folder)
  and `launch_handler`, so an installed app registers for its types and
  the pickers of slice 3 offer them (they offered every type before).
  After first pixel, a page with `launchQueue` loads `documents-glue.js`,
  whose consumer mints each launched `FileSystemFileHandle` and delivers
  it to `open-file`.
- **Verified by driving.** iOS simulator, Markdown: launched with
  `EXACT_LAUNCH_URL=file://…/other.md` the field holds `doc:/1/other.md`
  and the document is "Other"; `xcrun simctl openurl booted
  file://…/README.md` while it runs opens "Notes" as `doc:/2/README.md`;
  `plutil` shows the document types, `LSSupportsOpeningDocumentsInPlace`
  and the imported Markdown type. Web, headless Chrome outside the agent
  with a stub `launchQueue` (defined over Chrome's own): the consumer is
  set, `launched.md` opens as `doc:/1/launched.md`; Open… (trusted click,
