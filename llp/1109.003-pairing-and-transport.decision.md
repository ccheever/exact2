The root Contract owns resources and mutations. Every command refreshes the snapshot when it settles; connection status alone does not load the shell.

[inferred] The app owns one native module, with transport calls and subsequent native views under the existing `ExactModule` interface. Keep the nine Foundation transport files as app-local source copies, preserving source identity and marking each mobile adaptation. This is the selected app-module layout and mobile policy adaptation, not a separate reproduction of the TypeScript-only Gap 001. ## Alternatives

A new mobile protocol client duplicates reducers and breaks the handoff's reuse requirement. Compiling the whole desktop native module imports AppKit and desktop controls. Editing shared auth constants would change the desktop client. An additive shared metadata API could reduce copied Swift later, but requires its own shared commit and review; it is not necessary for this app-local implementation.

## Stable history reader and thread ownership

[decision] The root now declares a zero-argument `snapshotRead` resource for
native reads, watches and drains. Its serial feeds a synchronous `snapshot`
projection; theme, clock and local projection changes do not retire the
reader. The canonical client retains the transcript, and `fleet.saved` retains
the current catalog. The reader stores only routing/status metadata, fenced by
read ownership and connection identity. A completed metadata write invalidates
older reads and notifies the existing watched topic; it creates no new store.

[decision] A matching thread open owns a scalar, invocation-local token.
Watched refreshes preserve it, and selecting an already loaded active thread
preserves its history. Successful subscription registration clears only its
own token and emits an owned wake, so an early inbox marker can reach drain and
ACK. Explicit Refresh retires the old open before replacing it. A refresh or
synchronize invocation may release only transfer descriptors it observed,
through its still-live answer. It never borrows another answer's native handle
or pending promise. Truly retired answers and the prior command-owned lease
limitation still rely on native expiry/reset.

[decision] The existing `preferences` resource and `appearance` application
are the sole root preference writer. The asynchronous metadata reader no
longer reads, watches or reapplies composer preferences. Send admission keeps
its existing authoritative preference read. The unused read-then-project
`mobileSnapshot` wrapper is deleted. The strict reconnect fixture accepts only
the one wake with the current generation, environment, thread and subscription.
No desktop client, native store, wire API, heap or response limit changes.
