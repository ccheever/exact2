# LLP 1041.007.000: Scenes as baked worlds

**Type:** RFC
**Status:** Draft
**Systems:** Game add-on — proposed `game/scene/`; `game/engine` (`Data`, the World's type registry, `World::save`/`load`); `game/dev.mjs`; the assets seam. Contract syntax (the lexer, reused). Agent driver (source locations).
**Author:** Claude (Fable 5.1) for Charlie Cheever
**Implementer:** unassigned — one of two competing proposals under [LLP 1041.007](1041.007-scene-authoring-language.rfc.md)
**Date:** 2026-09-18
**Related:** [1041.007](1041.007-scene-authoring-language.rfc.md) (the concept and the comparison), [1041.006](1041.006-game-development-experience.rfc.md) §6–§7 (restart/continue; typed JSON scenes), [1041.001](1041.001-agent-interface-to-a-game.rfc.md) (no ninth operation), LLP 1006 and 1017.000 (Contract as built: `fn`, `use`, `style`, the reject corpus), 1035.002 D6 and 1035.005 D1/D3 (the development source map; the formatter), LLP 1019 D1 (declared assets, as fonts), `game/README.md` in the game lane, `rules/RULES.md`, `rules/NOT-DOING.md`

## Summary

A scene is written in Contract's form, means only constants, is checked by
the game's own Rust types, and is baked **by the real engine into a world
save**. Loading a level is `World::load` — a path that exists, is versioned,
and already carries worlds across dev reloads, agent captures and player
saves. There is no scene format, no scene loader and no schema, and the
language costs the shipped module zero bytes.

`game/README.md` already says one derive gives "the save game, the hash, the
agent's JSON, the level file, and what a dev reload carries." This makes the
fourth item true, with a language in front of it:

1. **Form** — Contract's lexer and idioms; A-Frame's model (the web's
   declarative entity–component scene): an entity is a line, a component is
   a typed line beneath it, a prefab is a parameterized entity, a use site
   patches. (D1, D2)
2. **Constants only** — no expression survives the bake, so evaluation *is*
   the type check and there is no runtime. (D3)
3. **One authority** — the compiler is a strict `Data` reader over the
   game's linked types. No schema, generated or kept. (D4)
4. **The artifact is a save** — measured on Lanterns: same hash as Rust
   `setup`, 28 KB, 0.46 ms to load. (D5, §4)
5. **The loop** — a scene edit never touches `cargo`; restart by default,
   a three-way *continue* on request, on every host that can receive bytes;
   entity → source; and the running game can write the file. (D6–D8)

Lanterns' 289 lines of world construction become 98 lines of scene
(Appendix A) and about a dozen of Rust.

## Author's assessment — not now (2026-09-18)

Charlie asked, after reading this, whether it is worth building or a thought
exercise. My answer: the design holds, and I would not build the language
yet. The rest of this document is the case *for*; this is the weighing.

- **Performance: nothing.** §4 measured it away — load is 4× slower than
  Rust construction at Lanterns' size, both under a millisecond; at 200,000
  entities the answer is Rust in `setup` either way.
- **Ergonomics: real, moderate, and not free.** Construction is about half
  of each game's logic crate (289 of 583 lines in Lanterns, 69 of 130 in
  Beacons) and the scene form cuts it 2–3×, part of which is only
  `rustfmt`'s one-field-per-line. The price is a third language no model
  has seen, in a game that already has Rust, Contract, a manifest and a
  proof script. The project's own evidence says construction is not the
  bottleneck: both twins build their worlds in code (Godot's `main.tscn`
  is a ten-line stub), and three rounds of judges' asks never mention it.
- **Iteration speed: the win that matters does not need a language.** The
  pain is that a `setup` edit does not reach a carried world. D6's merge
  fixes that for Rust `setup` as it stands — see below. Going from ≈0.4 s
  to ≈0.1 s is invisible beside an agent's turn.
- **What only scenes-as-data can give:** content reload on a host that
  cannot hot-load code (a phone); levels delivered as data (OTA, or made by
  players); capture (D8). Each is real. None has a consumer today.

**Do instead, language-free, a few hundred lines in the add-on:**
(a) *continue* for `setup` edits — a `Sim` keeps its tick-0 save (0.15 ms,
28 KB on Lanterns) and carries it; after a swap the new module holds base
(the carried tick-0), theirs (its own fresh `setup`) and mine (the carried
world), and merges by name and component on `Data` bytes; (b)
`#[track_caller]` on `spawn_named` in development builds, surfaced as
`source` in `state world:x`. Entity → source and live world edits, for
every game, now.

**Reopen this document when** a game's authored world outgrows code (levels
as separate files, or `setup` past ~500 lines); a person, not an agent, is
doing level design and wants capture; levels must ship as data; phone-first
iteration becomes normal; or gameplay moves to TypeScript, in which case
scenes are decided with it. D4–D5 (the real engine bakes a save) are what I
would keep under any front-end, astra's included.

## 1. What an author writes

```
const iron = Material(color=rgba(0.12, 0.08, 0.06), metallic=0.35, roughness=0.7)

prefab Block(at: vec3, size: vec3)
  Transform position=at
  Mesh Box(size=size)

prefab Lantern(at: vec3)

  entity "bulb"

scene Island
  resource Physics gravity=vec3(0, -12, 0)

  entity "crate" Block(at=vec3(6, 0.6, 8), size=vec3(1.2))
    Material color=rgba(0.45, 0.24, 0.09) roughness=0.78
    Body kind=Dynamic mass=3 damping=0.45 spin_damping=8
  entity "player"
    Transform position=vec3(0, 0.65, 12)

    entity "fox"

  entity "camera"
    Camera fov_y_degrees=45
    Follow target=Entity(ref("player")) offset=vec3(10, 8.5, 14) lag=0.12

  entity "lantern-7"  Lantern(at=vec3(12, 0, -8))
  entity "lantern-12" Lantern(at=vec3(10, 2.4, 8))
  each i in range(18)
    entity `tree-${i}` Tree(at=ring(rand(i, 0), mix(13, 16.5, rand(i, 1)), 1.05))
```

What Rust keeps — whatever reads an argument, and the tick:

```rust
fn setup(world: &mut World, args: &Options) {
    world.load_scene("Island");                 // D5: World::load on the baked asset
    world.reseed(args.seed);
    world.insert_resource(Session { phase: u32::from(args.started),
        jump_press: args.jump_press, light_press: args.light_press, ..Session::default() });
    publish(world);
}
```

Field and variant names are the Rust types', exactly as `state` prints them,
so a reply can be pasted into a file (§10 Q1 asks whether that is the right
spelling). `Box(half=size * 0.5)` beside `Box(size=size)` is the kind of
invariant a prefab exists to hold once; `Collider::of(&mesh)` holds it in
Rust today, and JSON would hold it six times by hand.

## 2. Decisions

### D1 — Contract's form, by reuse

`.scene` files use Contract's lexical grammar unchanged — indentation
blocks, `//` comments, strings and `${}` templates, the hyphen rule,
bracket-aware continuation — by depending on `contract-syntax`'s `Lexer`,
which is already `pub` and depends on nothing. The declaration grammar is
the scene's own. Its expressions are Contract's plus two forms Contract has
no use for: a list `[a, b]` and named arguments in a call,
`Fog(density=0.008)`. Shared idioms, same meaning: `fn` (one expression,
inlined, no recursion), `use Name from "./props.scene"`, `each x in list`,
`when`/`else`, diagnostics as `file:line:col [id] message` with stable ids
and a reject corpus of one fixture per id. One deliberate difference: a
scene compile reports **every** error in one run (entities are independent;
RULES' loop-shape rule), where `contract::compile` returns one.

### D2 — Entities are lines, components are typed lines, a use site patches

The web's declarative entity–component model is A-Frame's: an entity is an
element, a component is an attribute, a mixin is a reusable bundle, a
primitive is a parameterized template. This is that model in Contract's
grammar, one fact per line.

- `entity "name"` spawns. Its indented body holds component lines and child
  entities; nesting *is* `Parent` (writing `Parent` by hand is refused — one
  way). The name is a string expression; a duplicate is refused naming both
  sites.
- A component line is `Type`, then one value (`Mesh Box(size=s)`,
  `Material iron`, `Visible false`), or `field=expr` pairs, or a value then
  pairs (a base, then patches). It means `T::default()` read through
  `Data`'s record-patch rule — the rule saves, dev carries and
  `json::read_into` already follow. Pairs may continue on indented lines.
- `prefab Name(param: type = default)` is one entity's body with typed
  parameters — Contract's `component` with `props`. `entity "lantern-7"
  Lantern(at=…)` instantiates it, and the lines under a use **patch** it: a
  component line patches the prefab's by field, `entity "bulb"` patches the
  prefab's child of that local name, anything new is added. Names inside a
  prefab are local; the world sees `lantern-7/bulb`.
- A roster is written as lines, not as a table: twelve `entity … Lantern(…)`
  lines are the table, each its own diff line and its own source location.
  `each` and `when` expand at bake and are for generated repetition.
- `resource Type …` at scene level, same line rule. `asset fox =
  "./art/Fox.glb"` declares a file as Contract's `font` does (LLP 1019
  D1): checked to exist, digested at bake. `const name = expr`.

No mixins (a `const` value plus patches covers them), no removal of a
prefab's component at a use site (a `when` on a parameter does it), no
slots (children under a use are added).

### D3 — No expression survives the bake

A scene describes tick 0, so every expression is a constant and
**evaluation is the type check**: there is no inference pass, no bytecode
and nothing to interpret on a device. The compiler evaluates (f64, with
`exact_game::math`'s libm so two builders agree), expands, and hands values
to D4. Values: number, string, bool, `none`, list, record, a declared
asset, and `ref("name")` — checked to exist, reads as an `Entity` or as its
name, may point forward.

The roster is closed and pure. WGSL's constructors for vectors (`vec3(1.2)`
splats; `+ - * /` componentwise); `dot cross length normalize mix clamp min
max abs floor ceil round sqrt sin cos atan2 pi tau`; `euler axis_angle
look_at`, with angles that carry a unit as CSS angles do (`deg(45)`,
`turn(0.25)`); CSS colours to floats (`rgb("#ffb43b")`, `rgba(r, g, b)`);
`range(n)`; `map(k=v, …)`; and `rand(key, …)`, a hash of its arguments and
the scene's name — not the world's RNG, so a bake is reproducible and the
world's stream does not depend on decor. No recursion, finite `each`, an
entity cap (Slice D's 100,000): the bake always terminates and is
byte-identical for identical inputs.

The boundary this draws: a value that must change after tick 0 is the
tick's. *The first scene that wants a binding is evidence for the tick* —
LLP 1017.000 P5's rule for `fn` and loops, moved one layer down.

### D4 — The Rust types are the only authority; the compiler is a strict reader

The compiler has no schema and no component list. The bake links the game's
logic crate for the build machine — as a build-dependency of the generated
GPU shell, whose `build.rs` already bakes art (`exact_game_bake::bake_art`),
and as one small generated binary the dev server runs on a save. It creates
a headless `World`, runs the game's registrations, and for each component
line finds the type **by name in the World's own registry** — the one
`World::load` uses — and calls `Data::read` with a `Reader` over the
evaluated value tree, strict. Every value node carries its span, so a
refusal lands on the character that caused it:

```
island.scene:13:13 [scene-field] Transform has no field "positon" — did you mean "position"?
island.scene:16:22 [scene-field] Collider.shape: Box has no field "size"; fields: half
island.scene:86:30 [scene-ref] no entity named "plyer" in scene Island; nearest: "player"
```

(Positions are Appendix A's, for the mistakes an author would make there.)

Three asks of the engine, all small:

- `Registration` gains one function pointer — *read this type onto this
  entity from a `dyn Reader`*. It already holds `make` for `load`.
- Strict reading: refuse unknown fields and wrong arity. This exists,
  uncommitted, in the 1041.006 scene lane (`Reader::strict`,
  `Reader::unknown`, the derive's use of them) and is the part of that work
  this proposal needs as written. The derive's refusal should also name the
  type's fields or variants — it knows them — so did-you-mean costs nothing.
- `Game::register(world)`, called before `setup`, so a bake knows the types
  without running `setup`.

Invariants a Rust constructor enforces today (`Synth::validate`,
`Mesh::validate`) must move to where reading can run them; Slice D met the
same need with `checked::<C>`. And `Default` must be the useful value,
because a line patches a default: `Animation clip="Survey" looped=true` is
only `Animation::looping("Survey")` if the defaults agree (not verified).

### D5 — The artifact is a save; the loader is `World::load`

The bake makes a `World` at the game's `HZ` with a fixed seed (`setup`
reseeds after the load), spawns named entities in source order, then
inserts (two passes, so a `ref` is a real `Entity` by the time a component
reads it), and writes `World::save()` behind a small header: scene name,
source digest, game ID, the asset table. `setup` begins with `world.load_scene("Island")`, which is
`World::load` on that asset. It travels on the assets seam the game lane is
landing (S3a, in flight): `scenes/island.scene` bakes to
`assets/island.world` beside `art/fox.glb` → `assets/fox.model`, the game
declares it in `Game::ASSETS`, and "setup and tick zero wait for all
declared bytes, on headless hosts too." The runtime already "decodes only
`bin` Data"; a save is that. Never inside the module — so a content edit
never reaches `cargo`, and an update bundle (LLP 1030) can carry a level.

Nothing else is new: no artifact format, no loader, no name resolution at
load, no interchange document. Scene compatibility is save compatibility —
fields by name, additions default, `SAVE_VERSION` and `migrate` as today —
and a scene is rebaked whenever the module is, which costs milliseconds.

v1 loads one scene per world (`load` replaces; Rust adds what it likes
after). Additive loading and spawning a prefab at runtime need the entity
handles inside components remapped, which needs the codec to know an entity
when it sees one. That is S4's ask, not v1's.

### D6 — Restart by default; *continue* is a three-way merge

A save of `island.scene` runs the bake tool — a process start, a parse, a
few hundred reads; no `cargo` — and the dev server swaps the asset. By
default the world **restarts** from it with the app around it untouched:
1041.006 §6's *restart*, made cheap. Target: under 100 ms save-to-frame on
the web, measured as 1041.006 §8 prescribes. (Contract's loop is ~20 ms.)

*Continue* runs natively on real `World`s and arrives through the seam that
already swaps modules (`Surface::carry`/`restore`): base = the old bake,
theirs = the new bake, mine = the carried live world. Per named entity and
component: if mine equals base, take theirs; otherwise keep mine and say
so. New entities spawn; entities the edit removed despawn if play had not
touched them. The journal gets the report — `scene: applied 3; kept
crate.Transform (moved by play)`. Identity is the name; an unnamed entity
is not patchable and is reported. A component that holds an entity handle
cannot be copied between two separately built worlds without remapping it —
S4's codec ask — so until then such components are kept and reported (a
correction: the first draft of this section missed it). Godot ships this as an opt-in debug
option (*Synchronize Scene Changes*); here it is `Data` equality and two
seams that exist.

When 1041.006 B2's input recorder exists there is an exact alternative:
restart into the new scene and replay the recorded input, which shows what
the edit *does* to the run instead of approximating it.

Both reach every host that can receive bytes — a phone included, where a
code edit is a rebuild, a signature and a relaunch. How well a development
build receives a changed asset on a device today is LLP 1030's fact, not
this document's.

### D7 — Entity → source, and the vocabulary in one command

Beside the artifact the compiler writes a development-only map keyed by the
artifact's digest: entity name → declaration span and prefab call chain;
component → span. The driver reads it and adds `source: island.scene:97:3 ←
Lantern island.scene:18` to `state world:lantern-7` replies and to proof
failures. No host reads it and no bake ships it — the shape NOT-DOING
admitted on 2026-09-10 (1035.002 D6), extended from plan nodes to entities.

`scene types` prints every registered component and resource in scene
syntax, fields with their defaults, by writing `T::default()` through D8's
writer: what an agent may say, in one command, never out of date.

### D8 — The running game can write the file

`Data`'s `Writer` has the events its `Reader` has. A scene-syntax writer
(~150 lines) prints any value as scene text, so a `state` reply pastes into
a file. **Capture** goes one step further: diff the live world against the
base bake and write the differences back as patch lines at each entity's
declaration or use site. D2's patch rule makes that always possible without
touching a prefab — whatever differs can be said as a line under the
entity. Push the crate to where it should start, capture, and the file says
so. No editor application: the running game and a text file.

### D9 — Where it lives, and what it costs

`game/scene/`: front-end, bake driver, merge, and a CLI (`scene build |
types | fmt`), in the add-on's workspace, depending on `contract-syntax` by
path for the lexer. **Core changes: none. Runtime bytes: none** — the
module calls `World::load`. Estimate (unmeasured): parser ~600 lines,
evaluation and expansion ~500, the `Reader`/`Writer` bridge ~350, bake
driver and merge ~300, CLI ~150 — about 1,900 lines against Contract's
10,900, because there is no inference, no bytecode, no plan and no runtime.
`scene fmt` follows 1035.005 D1 (trivia kept, one continuation rule) and
should share that printer rather than precede it.

## 3. One edit, end to end

*Move `lantern-7` two metres east.* The agent reads `state
world:lantern-7`; the reply says `source: island.scene:97`. It changes
`vec3(12, 0, -8)` to `vec3(14, 0, -8)` and saves.

- **Web.** The bake runs; the world restarts from the new scene with the
  HUD and the rest of the app untouched. With *continue*, the lantern and
  its three children move beside a player who is standing there — play had
  not touched them — and the count, the timer and the pushed crate stay.
- **Phone.** The same bytes, by whatever path a development build receives
  a changed asset (D6's caveat). Nothing is compiled, signed or relaunched.
- **Today.** Edit Rust; the module rebuilds (≈0.4 s warm on the web in the
  lane's measurements; rebuild, sign, install and relaunch on a phone); the
  carried world still shows the old lantern; restart.

## 5. What it refuses

- **Bindings, rules, any expression at runtime.** Reopen when two games'
  ticks are, measured, mostly `a.field = f(b.field)` plumbing.
- **Scene syntax in `.contract`, or Contract knowing a component.** The two
  files meet by name — `surface=world(…)`, `app.json`'s `game` — and the
  ruling on new Contract syntax is untouched.
- **A schema**, kept or generated; **a second artifact format**; **parsing
  scene text on a device** (the boot rule).
- **`test` blocks in scenes.** Worlds already have `Sim` tests and
  `proof.mjs` with one vocabulary.
- **Generated content at scale.** `each` is for authored repetition.
  200,000 cubes, and anything seeded by an argument, stay Rust in `setup`,
  after the load.
- **An LSP, an editor, a write-back tool in v1.**

## 6. Alternatives weighed

- **Typed JSON as the authored file (1041.006 §7).** Right about authority,
  initial conditions and restart. As a thing to *write*: no comments,
  constants, arithmetic, parameters or checked references; twelve lanterns
  are 48 rows, or a fragment mechanism spelled in JSON — a language with no
  grammar and no spans. As an artifact: a second format and loader beside
  saves.
- **TypeScript evaluated at bake, types as generated `.d.ts`.** The
  strongest alternative: agents are fluent, loops and functions are free,
  editors work today. Against: not total or hermetic without a sandbox;
  entity → source only by stack capture; capture cannot patch arbitrary
  code, where a closed grammar can always say a difference as a line; a
  JavaScript toolchain in the content loop. It would sit on D4 and D5
  unchanged — the back-end here is front-end-agnostic, and it is the part I
  would keep under any syntax.
- **Components declared in the scene language, Rust generated** — the
  `kernel/tables/schema.json` pattern. The compiler would link nothing and
  run anywhere. But the engine's components carry hand-written `Data`,
  methods and invariants in Rust; the generated half would be the smaller
  half, and the authority would split in two.
- **A Rust macro, or better builders.** `cargo` stays in the content loop,
  and there is no data to diff, merge, deliver or capture into.
- **glTF or a DCC tool as the scene.** glTF stays how geometry arrives; a
  scene says what things *are*, in components no DCC tool knows.
- **Compiling scene text inside the dev module.** The fastest conceivable
  loop, and two paths to a world; production could not use it.

## 7. Against 1041.006 Slice D

**Keeps:** the authority rule; a scene is an initial condition, never a
saved game; restart and continue as distinct intents; the digest-bound
source map; strict reading, as written in that lane; a `SceneIdentity`
resource naming the digest a world came from. **Replaces:** JSON as the
authored file; the `EXSCENE` artifact; `Types`' bake and decode closures;
`prepare`/`instantiate`; hex transport. If a tool ever needs to emit scenes,
JSON is a second front-end to the same bake — `json::from_str_strict` onto
the same `World` — not a second pipeline.

## Appendix A — `island.scene`: Lanterns' world

Everything constant that `setup` and its helpers build today. Shapes follow
the Rust types; §4 names the two spots not checked against a decoder.

```
// island.scene — every constant fact Lanterns' `setup` builds today.
// Rust keeps what reads an argument (the seed, Session) and the tick.

asset fox = "./art/Fox.glb"
```
