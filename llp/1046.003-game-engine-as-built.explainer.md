## What exists

- **`exact-game`** (`game/engine`, no GPU, no host): one `Data` trait (a derive with no
  `syn`) behind save, hash, JSON, levels and dev-carry; a `World` whose components
  live in paged slots under a presence bitmask (iteration is ascending entity index
  by construction, so a restored world replays exactly), borrowed per row
  ([Row leases](#row-leases-2026-09-23)); `Sim` — fixed ticks under a
  host clock in integer microseconds, input as named actions, setup and live
  arguments, saves in world time; the agent's reads as JSON; synthesized audio as
  saved state and journal lines. Executed game and saved-pile cards agree on arm64
  macOS, x86-64 Linux and Chrome wasm.
- **`exact-game-render`** (`game/render`): the GPU holds the last two ticks'
  transforms by slot and blends them in the vertex shader; per frame the CPU writes
  one uniform block and one draw per mesh batch per geometry pass; shadow cascades
  draw casters again. PBR, cascaded sun shadows, bloom, sky,
  fog. `WorldSurface<G>` is the `exact_gpu::Surface` a canvas binds.
- **`exact-game-audio`** owns synthesis/playback; the engine owns saved definitions
  and voices. **`exact-game-physics`** uses Rapier with validated opaque continuation
  snapshots; the home-grown solver is deleted.
- **The grey box** (`game/games/greybox`, LLP 1046.000 S0): an exact2 app whose
  world is a guest in a `canvas`, whose HUD is that canvas's Contract children, and
  whose proof (`proof.mjs`) is a script in the eight operations.
- **Twins and bench** (`game/twins`, `game/bench`): the same scenes and the same small
  game in Godot 4.7 and three.js, with diaries.

Two rules came out of review and belong to LLP 1012/1016's family: **a surface
pending creation is in flight** (an agent operation waits for the lazily loaded GPU
module instead of racing it), and **a world never advances its own clock** (it
answers `settleAt`; the host's loop comes back).

**Task 001, scored** (`game/diaries/001-scores.md`): a fresh builder made the same
small game here that fresh builders made in Godot and three.js; two blind judges
gave three.js 29, Godot 26 and this engine 19 of 30 — it won Repeatable and lost
Small, Loop and the HUD boundary. `exactSurface` is the first answer; the rest are
in "What is owed". The game is rebuilt from scratch and re-scored after them.

**The Apple half runs** (macOS, 2026-09-17): the grey box driven through
`scripts/agent.mjs macos` — Play, a held key under the agent's clock, `state
world:player` — gives the pinned position of the web and the headless sim.

Found and fixed on the way, not a game's bug: a bake's build script watched its own
receipt and the web bake passed an explicit dep-info path, which together made every
build re-link the app wasm (a minute under fat LTO) — a logic-only edit now rebuilds
in under a second; and on the web a canvas mounted after boot
never triggered the lazy GPU module load outside agent mode.

## E2 — saves and the world loop

A capture `screenshot run.world world save` and session setup `--world run.world`
reach the complete simulation through the defaulted surface carry/restore seam.
Web and macOS proofs close the original browser/process, open from its save, and
continue to the same full save bytes (queued jump, held input, journal included).
The macOS grey box also matches the web's pinned position and hash.

The web dev server reads the two cdylibs' dep-info: GPU-only Rust edits use
`gpu-dev` and a side output directory, preserving the complete dist marker. The
page swaps code without navigating, retaining publisher ownership and republishing
before render. Contract restart carries unique surface names; physical view ids
are reassigned. See `game/README.md` for the fresh-world command and duplicate
instance limitation.

## Persistence and deletions

World/Sim containers are EXGAME v3 / EXSIM v5. Opaque numeric vectors use bulk
little-endian bytes, JSON shows length/hash summaries, and old containers refuse
by name. Saved message delivery queues are excluded from simulation hashes;
restore retains the touch viewport until the host replaces it. The storage mutation
epoch remains; tick stamps, float-run views, duplicate renderer Bloom/Fog types,
partial-history copying and the committing Play destructor are deleted. Renderer
CPU timing belongs to its caller and seekable draws make no perf clock calls.

## Feel — the first numbers, and frame pacing (2026-09-18)

The probe is the bench's (`game/bench/probes/`), one command, preflighted on an
unlocked idle console. The first honest row for this engine: 50/50 edges, 6.9 ms
median event-to-drawn-state, zero hitches, no repeated positions — and judder 0.106,
which the raw trace proved to be the web host's frame clock: Chrome's rAF timestamp
wanders around the vsync grid under load while frames land on it, and the world was
drawn exactly where that clock said. `host/web/pace.js` snaps the live clock to the
display's lattice (the Apple host already renders at `CADisplayLink.targetTimestamp`);
the paced run drew identical displacements on 176 of 180 frames. The same traces
showed input latency to be a tick-phase lottery (6.9 vs 18.0 ms on one build), which
F2b answers by running a tick that is due before the next frame now. Full tables
against the twins wait for a quiet sitting.

**Decided without asking, added:** the pacer lives in the web host (a host's frame
clock is presentation-aligned, as the Apple host's already was), not in the module;
the assets record is one `Model` per glTF with raw RGBA8 mips; `Game::ASSETS` is a
const on the game, not a manifest row.

### One SDK lock (2026-09-23)

This revises R12's "one workspace owner, one lock authority" (Dawn, 2026-09-19). R12
kept each game's generated `.shells` workspace as the owner and made a captured
`Cargo.lock` per game the lock authority. In practice nine 76 KB, ~3,200-line locks
went stale together whenever the core's dependency graph moved, and nothing refreshed
them; the template seed went stale with them, so the starter could not bake; and each
game carried a `logic/Cargo.toml` naming a workspace only a bake creates, so a fresh
clone's `cargo test` failed. The owner stays; the authority moves:

- A game is `logic/src/lib.rs`, `app.contract`, `proof.mjs`, its tests, the
  tool-written `pins.json`, and `app.json` only for authored keys. Its crate is
  `<Game::ID>-logic`, so a clone under another directory name still links its tests;
  a generated `.shells/logic/Cargo.toml` builds the author's sources in place.
- The lock authority is the SDK's `game/app/shells.lock`: the lock of a generated union
  of every shell's dependencies (engine crates, hosts, runner, data host, the
  wasm-bindgen family). A game's shell lock is that lock pruned to the game's graph by
  one offline Cargo resolution, refused if any package version or checksum is not the
  SDK lock's, then resolved `--locked --offline` like every bake, deploy and proof.
  Dependency edges are not compared: they follow from the versions and the activated
  features. No local cache chooses a version.
- A game that adds dependencies writes `logic/Cargo.toml` (SDK crates as
  `exact-game.workspace = true`) and captures its own `Cargo.lock` with `--update-lock`:
  R12's flow, now opt-in. SDK crates alone (the fixtures' physics, render and bake)
  need no lock of the game's own.
- `bun game/app/shells.mjs --update-lock` rewrites the SDK lock and `bun app/shells.mjs
  --test` refuses a stale one: one lock goes stale in one place, with one command.
- `bun game/app/shells.mjs <game> --test` is the documented test command and works in
  a fresh clone with no bake and no environment variables.
- Found on the way: `game/bake`'s `exact-game.workspace = true` did not resolve from a
  workspace outside `game/`, so an out-of-tree game with `art/` could not resolve; it is
  a path dependency now.

Migrating an old-layout game (tennis): delete `logic/Cargo.toml` when it names only
`exact-game`, otherwise rewrite its SDK path dependencies as `.workspace = true`; delete
`app.json` if it is `{}`; delete `Cargo.lock`, and restore it only if `bun
game/app/shells.mjs game/games/<g> --test` then refuses packages outside the SDK lock
(refresh it with `--update-lock`); run `bun game/prove.mjs <g>`. The in-tree games moved

## Row leases (2026-09-23)

The commonest gameplay loop, each enemy stepping toward the player, read the player's
`Transform` inside the loop that mutated the enemies' `Transform`s, and panicked: a
mutable lease locked its whole column, the message named only the component, and
release and web builds abort. Charlie's brief made per-row borrowing the fix; the
design below is this lane's (Charlie's to overrule). Contract: `game/engine/README.md`
§Borrowing; code: `game/engine/src/storage/lease.rs`.

- **A lease covers rows, not columns.** Each column keeps a stack of live single-row
  holds `{row, kind, caller}`; `pages` and engine reads are the same record with an
  every-row index. A query registers once, at its first `iter`/`one`/`for`, as a
  *shape* in a world-owned table: its term columns by storage identity, its filters,
  each term's kind and its caller. It holds exactly the rows the shape matches until
  the query and every row guard it yielded drop. A row request tests the few live
  holds on its column and evaluates live shapes at that one row; a registering query
  tests live holds at their rows and intersects its shape word by word with any
  overlapping shape where one side is exclusive. Nothing is written per row.
- **Why a shape, not per-row borrow state.** Per-row bytes or per-page bitmaps marked
  as the iterator yields cost a read-modify-write per row per term, plus a clearing
  pass, against a two-nanosecond loop. `iter()` yields plain references that can be
  collected, so a query must keep every yielded row marked until it drops anyway:
  marking buys nothing a shape does not. A guard per row that marks only the current
  row would also admit reads of other matched rows, but it changes `iter()`'s items
  from `&mut T` to guards, pays a set and clear per row, and cannot survive
  `collect()`. Marking the matched set when the query is built costs O(words) per
  query and cannot see filters the builder adds afterwards. A shape costs one table
  entry per query and is exact.
- **The lease starts at the first iteration**, so builder filters narrow it: holding
  `w.require::<Transform>("player")` across a mutable query `.with::<Enemy>()` works.
  A query that is built but never iterated leases nothing; physics' guard against a
  live writer now holds `pages` of its four columns instead of an unused query. A
  mutable query still advances its column's write revision when it is built.
- **Copies need no lease.** `local_position`, `global_position`, `near*` and parent
  walks copy a row out and only check that no exclusive lease holds it: one counter
  load when the column has no writer. Hierarchy resolution runs under `&mut World`
  and holds one `pages::<Transform>()` instead of a lease per node.
- **Refusals name both sides**: component, entity name and handle, both kinds and
  both `#[track_caller]` locations. The hot path returns a unit refusal; the message
  is re-derived on the cold path.
- **Leaks stay safe.** A shape points at boxed storages that live exactly as long as
  the table. `spawn`, `despawn`, `insert` and `remove` advance a stamp before any
  `&mut` storage access; a leaked shape from an earlier stamp is never dereferenced
  again and holds every row of its columns, as a leaked guard held its column before.
- **Measured** on this Mac (arm64), shared with six other lanes: load averages ran
  from 10 to 430, so wall-clock pairs swung by ±30% and more on untouched paths. The load-free
  record is instructions retired per operation (`/usr/bin/time -l`, one metric per
  process, differenced against zero repetitions), baseline 4eca9a09 against this change:

  | path | before | after | ratio |

  | `iter()` row, `(&mut Transform, &Spin)`, 100k | 73.6 | 73.1 | 0.99 |
  | consuming row guards, same loop | 106.9 | 108.5 | 1.02 |
  | `get` / `get_mut`, 100k rows | 266 / 243 | 290 / 286 | 1.09 / 1.18 |

## AU4 — sampled sounds and band-limited oscillators (2026-09-23)

**Band-limited oscillators.** Square and saw subtract a two-sample polynomial
band-limited step (PolyBLEP) at each discontinuity, using the per-sample phase
advance the synth already computes; sine, triangle and noise are unchanged, so the
pinned chime and noise PCM hashes hold. Measured as harmonic power over power
between the harmonics' DFT bins (a 4,800-sample window holding whole periods at
48 kHz; `cargo test -p exact-game-audio alias -- --nocapture`):

| wave | 440 Hz | 1,760 Hz | 3,520 Hz | 7,040 Hz |
|---|---:|---:|---:|---:|
| square, naive | 21.2 dB | 15.3 dB | 11.5 dB | 9.6 dB |
| square, PolyBLEP | 37.0 dB | 32.0 dB | 24.9 dB | 32.8 dB |
| saw, naive | 19.4 dB | 13.3 dB | 9.9 dB | 6.8 dB |
| saw, PolyBLEP | 35.5 dB | 28.9 dB | 24.5 dB | 23.0 dB |

The sample on an edge now takes the step's midpoint, and a band-limited square at
exactly Nyquist is silent. PCM is presentation, outside saves and hashes, so no
simulation pin moves.

**Sampled sounds.** A game puts `.wav` and `.ogg` files in `art/`; the bake writes
one `.sound` per stem, delivered through the same seam as models and levels
(`Surface::assets`/`Surface::asset`, `Game::ASSETS` gating setup). A `Sample`
definition names that asset; `World::sounds` copies the delivered frames, rate and
channels into the saved definition, so a voice's length is simulation state and
the PCM is not. The primitive module decodes `.sound` as it does `.level.json`:
samples need `game.audio: true` only.

*Where decoding happens (decided without asking; Charlie's to overrule).* At bake
time, to 16-bit PCM. The module then holds only the layout's inverse (a prefix sum
and an interleave), so no Vorbis decoder ships in any game. The `.sound` layout is
planar with each channel's wrapping first differences, chosen by measurement.

committed; synthetic signals generated):

the smaller total; for music it is not, which is what is owed.

*Saved forms.* `Sound` is `Synth` or `Sample`. A synth definition keeps its original
record and a voice writes its new fields (`offset`, `pan`, `fade`) only when set, so
a synth-only world saves and hashes byte-for-byte as before (a test pins a
definition, voice list, save and world hash; greybox's pins do not move). A sample
definition is a record whose one field is `sample`. The asset's content identity
joins the save's existing `assetIdentity` (levels use it), outside the hash: two
worlds with same-shaped but different PCM hash alike, and restoring a save into the
wrong one refuses by name.

*Voices.* One-shot and looping sample voices share the synth voice's builder: gain,
pitch (playback rate), `pan` (a balance after spatial gains), `offset` (seconds in,
wrapping for loops) and `fade_in`; `audio::stop` and `audio::fade` (ramp to zero,
then remove) journal. A voice of a looping definition has no end tick; the Player
takes its offset modulo the loop, as it does for sources. A sample has no
60-second limit, looping or not: its bytes are bounded instead. A synth keeps its
60-second cap because it is rendered whole. A sample definition's gain is applied at playback because its PCM is shared.

*Budgets.* Two, each refusing by name: 32 MiB of resident 16-bit sample PCM per
world, checked at bake and at delivery (an over-budget declared sound is Failed and
setup waits); and the Player's existing 32 MiB for synthesized PCM, which samples
do not touch. Apple's retained-PCM bound is their sum.

*Outputs.* One `Pcm` type, `F32` mono (synth) or `I16` interleaved mono/stereo
(sample), started at the source's own rate; outputs resample to the device. Web
builds an `AudioBuffer` per allocation and rate and routes source → (splitter) →
left and right gains → merger → destination: the same left/right gain law as the
Apple mixer, which reads either sample width and interpolates each channel. The
stereo panner node is gone; its equal-power law was exact only for mono. Null and
recording outputs are unchanged; agent clocks and headless hosts open no device and
still journal.

*Found on the way, not audio's.* Since 034d2ac3 (2026-09-22) the gpu-dev Linux
host bake gated its GPU identity card on `compat.inputs.trust`, which is `null`
for an updater-free app (`deploy.store = "0"`, every game's default), so every
game's gpu-dev Linux host refused its own module ("GPU module has no baked
identity") and `prove.mjs --hosts linux` failed before any assertion; the Linux
release stage, which binds the product digest, was unaffected. The lane gated the
card on the resolved trust passed into `receipt::emit`; the integration kept the
loop lane's equivalent fix (f8dcc864, which also restores the product card's trust)
and dropped this one. Greybox's captured lock was also stale against the core on
origin/main; the loop lane's SDK lock replaced it.

*Proven* (2026-09-23, this Mac): `bun game/prove.mjs audio-fixture --hosts linux,web`
filled the first pins with Linux gpu-dev (Off, Save, FreshGame), Linux release and
web agreeing, 0 failures; the ordinary Linux proof passes in 0.9 s. With
`EXACT_AUDIO_PROBE=1` the web proof passes the live probe (trusted-gesture resume,
a running context, the Vorbis drone as a 22,050 Hz stereo `AudioBuffer`, the 16-bit
blip at 22,050 Hz mono, peak analyser RMS 0.19). Greybox on Linux and web keeps its
pins (tick 0 `0xf560b8cf6dd9601d`, tick 90 `0xc92812672686717e`, continuation save).
The Apple mixer is covered with fixture buffers (16-bit stereo per-channel
resampling, mixing with a synth voice, the callback writing interleaved stereo);
no macOS or iOS proof of the fixture ran.

*Owed.* Compressed delivery for long sounds: stream-decoding Vorbis or Opus on
demand, or the platforms' own decoders (`decodeAudioData`, AudioToolbox), measured
against the ~45 KB gzip above; loop points inside a sample; spatialized stereo
sources are balanced per channel, not downmixed; Apple resamples linearly; the
fixture's macOS/iOS proofs and a listen on a device.

## Compressed textures (2026-09-23)

Charlie's brief (the textures lane): GPU-compressed textures end to end, closing the
item owed since S3a. What was built:

- **Per-family payloads, one record.** The baker writes each texture three times
  beside its authored name: `x.tex` (RGBA8), `x.bc.tex` (BC7 colour and data, BC5 a
  normal-only map, BC4 an occlusion-only map) and `x.astc.tex` (ASTC 4×4). All three
  are the engine's `.tex` `Data` record with a new `format` field (`TextureData.format`;
  records without it decode as RGBA8), so they stay digest-addressed like every
  asset and the module decodes them with the code it already had. KTX2 was the
  alternative: another parser in the module, and its value (supercompression)
  needs a transcoder, which the brief ruled out.
- **The device chooses, the host fetches by name.** `exact_gpu::requested_features`
  asks every adapter for `texture-compression-bc` and `-astc` where it has them;
  `Surface::device_ready` now carries the granted features (a core signature change:
  the render surface is its one implementor). The world and models name only
  `x.tex`; the surface maps a request to its family's file (BC, else ASTC, else
  RGBA8) and a delivery back to the authored name, so no host changed and the
  simulation never sees a family. The GPU-less Linux host fetches RGBA8, which
  validates and hashes as before; texture bytes are outside world hashes, and no
  pin moved. A missing family file falls back to the RGBA8 file; a replacement
  device of another family retires the old files and re-requests.
- **Upload as delivered.** Block levels are written whole-block per level (physical
  extents for levels under 4×4), after a named refusal where the device lacks the
  format's feature or edge limit. Residency, digest reuse, retirement and
  device-loss recovery are unchanged: textures are resident by authored name, and
  the web device-loss fixture still refetches its one texture once per loss epoch.
- **What the material samples decides the format.** The shader now reads a normal
  map's XY and rebuilds Z, so RGBA8, BC5 and two-channel ASTC draw alike (the only
  pixel-affecting shader change; no fixture has a normal map). MASK colour keeps
  every texel on its side of the cut: coverage-preserving mips are made in RGBA8,
  texels are then moved 8 alpha bytes from the cut, and ASTC searches `thorough`
  with alpha weighted as the three colours together (coverage within 2 of 64
  texels at 8×8, exact at every other level). Nearest-filtered PNG sprites keep
  their palette: a family file holds blocks only where every level decodes
  exactly, else RGBA8 — the sprite fixture's strip ships RGBA8 in all three.
- **Encoders.** The baker links Intel's ISPC kernels through
  `ctt-intel-texture-compressor` (prebuilt for macOS, Linux and Windows on arm64 and
  x86-64; `intel_tex_2` was tried first: its ASTC entry point is `unimplemented!()`
  and Apple's linker warns on its objects) and ARM's reference `astcenc` through
  `ctt-astcenc` (vendored C++ built by `cc`, which also decodes for the tests).
  BC7 uses the `basic` profile and ASTC `medium`, both striped across cores: the
  helmet's five 2048² maps bake in 3.6 s, the Fox in 0.2 s (release). Release
  profiles compile build scripts unoptimized, so `game/Cargo.toml` optimizes the
  baker and its encoders there. Encoded bytes may differ between SIMD variants;
  tests pin quality, not bytes.
- **ASTC 4×4, not 6×6.** WebGPU requires a block texture's base size in whole
  blocks, and power-of-two textures are never whole 6×6 blocks. Measured anyway
  (top level, PSNR against RGBA8): the Fox 69.3 dB at 4×4 and 58.9 at 6×6; a
  1448×1084 photo 43.3 and 37.0; the helmet's base colour 49.5 and 40.2, its
  metallic-roughness 44.7 and 39.1. 6×6 would cost 5–10 dB where it is allowed.
- **The cap is 4096² for blocks.** A block texture now reaches 4096²; its RGBA8
  fallback drops levels above 2048², which is the same 22.4 MB of device memory.
  A texture that is not whole 4×4 blocks ships RGBA8 in every file, capped alike.

Quality (top level; `cargo test -p exact-game-bake --test samples -- --nocapture`):
Fox BC7 61.2 dB, ASTC 69.3; helmet base BC7 48.4 / ASTC 49.5, metallic-roughness
44.7 / 44.7, emission 57.0 / 56.1, occlusion BC4 48.5 / ASTC 60.7, normal BC5 53.1 /
ASTC 52.6 (XY); the asset fixture's crate above 40 dB in both. Small levels (8×8 to
32×32) measure 29–36 dB in both families, reported, not bounded. Drawn through the
renderer on this Mac (`tests/compressed.rs`: base, normal, metallic-roughness and

## Split, 2026-09-23 — the engine as a module of its own (lane split)

`game/`'s promise was "apps without a world carry none of it"; within one app it now extends to
screens. LLP 1009 D6 lets an app declare **GPU modules** beside its primary `<app>-gpu`:
`app.json` `gpu.modules` maps a module name to the surfaces it registers, and module `m` is the
crate `<app>-gpu-m`. A world is `exact_game_render::module!` unchanged, so an engine module is a
three-line crate. The bake binds the routing into the compatibility inputs (`gpuModules`) and one
signed digest per module (`embedded.gpuModules.<m>`); an app that declares none bakes the same
bytes as before. Each host loads an artifact the first time one of its canvases mounts and routes
by name: the web through `gpu-modules.js` and one `gpu-glue.js?artifact=<stem>` instance per
artifact (`gpu/<m>.js`, `gpu/<m>_bg.wasm`), Apple with a module per canvas
(`libexact_gpu_<m>.dylib`), the headless Linux host with a library per canvas. Devices, loss and
recovery are per artifact; the dev server rebuilds and swaps only the artifacts an edit reaches.

Weird Castle is the consumer: `gpu/` keeps the title's night, `gpu-world/` is the Beacons world.
Measured on this Mac (web, shipped with `wasm-opt -Oz`, bytes fetched from the agent's carrier):

| | before (one module) | after (night + world) |
|---|---|---|
| before first pixel | 1547.0 KiB / 641.9 gzip | 1547.1 KiB / 642.0 gzip (glue.js +87 B) |
| title, after first pixel | 1040.9 KiB / 437.6 gzip | 522.5 KiB / 221.8 gzip |
| the GPU wasm at the title | 883 KiB / 398 gzip | 360 KiB / 180 gzip |
| when the world mounts | +0 | +880.7 KiB / 350.3 gzip (world wasm 751 / 321, its glue 48 / 14) |
| tap → first world frame | 57 ms | 145 ms (headless Chrome, local server) |

Unoptimized (this Mac's default build, no binaryen) the title's module went from 1979 KiB (497
gzip) to 801 KiB (234), the world's is 1808 KiB (412). Natively each artifact carries its own
wgpu, naga and Metal backend: macOS opens 4.25 MB instead of 5.14 MB at the title (unstripped as
bundled; 3.34 vs 4.06 MB stripped) and 4.98 MB more for the demo, so the bundle grows 4.1 MB — a
shared wgpu library would be the next trade, and is not built. On web, macOS and the Linux host
the agent showed the title requesting or opening no engine artifact, the demo loading it, and the
world's hashes at ticks 60, 108 and 193 equal to the single-module build's. A world-only edit
under the dev server rebuilt only the world artifact and swapped it in 36 ms, the world carried
(tick 1817 → 1923).

**Decided without asking (Charlie's to overrule):** a module is declared, not discovered — the
host must know an artifact before it loads it; a declared module on Apple loads on the turn after
its canvas mounts (the primary as before); runtime shader assets stay the primary's, because the
native ABI does not name a registry's shaders; modules on a game app are refused (its one module
is generated). **Owed:** module shader assets natively; the native size duplication; an iOS
device run; a real device-loss drive with two artifacts (covered by the router's tests and each
artifact's existing recovery, not by a destroyed device).

## Tennis, the second game (2026-09-23, lane `tennis`)
