## Summary

The one way to make JS evaluation ~0 without removing JS: evaluate at
build time, persist an image, restore at launch. This RFC holds that
option honestly as a **bounded feasibility spike with kill gates in
priority order** — eligibility first, economics second — and no
commitment beyond the spike.

## Kill gates (any failure ends the RFC)

0. **Contingency (a standing prerequisite, not a feasibility gate):** if 0565.002 lands and the purity
   census shows the apps that matter are plan-pure at boot, this dies.
1. **Eligibility & parity certificate (the first feasibility gate):** define the deterministic
   snapshot-eligibility rule — what may be evaluated at build time
   and imaged. Refusal classes (enumerated, fail-closed): **secrets, credentials,
   and authority-bearing tokens — categorically, declared or not,
   they never enter an image**; undeclared ambient reads (clock,
   randomness, environment); top-level effects/errors — the rule is
   **full external effect/error equivalence between image-boot and
   eval-boot, or refuse imaging** (not merely eager-set-observed
   timing); runtime authority; OS/native handles and pointers;
   unsupported host objects. Per-launch initialization is *outside* the image by rule.
   A parity harness proves image-boot ≡ eval-boot on the certificate's
   domain. No certificate, no spike continuation.
2. **Economics:** projected launch-path win vs the landed .001/.002
   reality on the same G1 hardware; under ~30 ms p50, no-go.
3. **Maintenance:** if the mechanism requires a maintained Hermes
   fork/divergence (GC, object layout), that carries its own go/no-go
   with a named maintenance cost — "Ibex is ours" covers the
   integration, not Hermes internals.

## Spike shape (carrier-neutral; narrow first)

Candidates, selected by Hermes/Ibex feasibility, not assumed:
(a) **framework/provider-realm image** (the Zygote shape — smallest,
safest, the starting point), (b) serialized heap restore,
(c) immutable mapped segments. The census measures what the post-eval
heap of the real blog/caltrain graphs contains per manifest class;
rebinding design starts from the module-operation table. Image
identity: the §Revised lower-bound tuple, as an admitted digest-bound
artifact via a commissioned Exact/Ibex amendment — never a trusted
blob, and dev-unarmed-only until the armed posture exists.

## Open questions

- OQ1: whether the framework-realm image alone (no app heap) already
  clears the economics gate — if yes, stop there permanently.
- OQ2: copy-on-write behavior of mapped segments under minor GC — the
  hardest technical question; the spike's first measurement.
- OQ3: ownership of the ibex-side RFC if go.
