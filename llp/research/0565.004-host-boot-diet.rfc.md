## Summary

Spawn → EXFF paint measures ~222 ms p50 (Band A) and none of it is app
code. This RFC has two halves. **First, Milestone 0-cold (this RFC owns the COLD half only — the
restart-session variant is .003's):** extend G1 — schema, producer, registered rows, completeness
rules — with the parent §4 partition's host subphases
(process/dyld+frameworks, window/surface, kernel init, EXFF/artifact
load, evaluation, dispatch/layout, commit→present) and the two product
clocks (visible; real-input-serviceable), then land same-run receipts
on Class A hardware. **No cut binds a budget before its subphase
exists in a committed session.** Second, the cut classes — each
individually landable with a same-host before/after signpost receipt
and no behavior change (LLP 0560: anything made lazy stays
tree-visible when it materializes). Targets: the `spawn→host-ready` caps are **the parent §5's** (this
RFC sets no independent numbers — currently ≤110 ms at R2, ≤55 ms at
R3, provisional pending M0-cold, which may redistribute them between
cut classes).

## The cut classes (post-M0; each lands separately)

1. **Link/load:** dyld-closure audit; merge/static-link; dead-strip;
   order files; deferred non-boot framework init.
2. **JS pages off the critical path (tournament):** delay
   Hermes/ibex dylib load until after the plan/EXFF first frame vs
   merging those pages — R3 may gain more from *removing* them from
   the pre-frame path than from optimizing their load; measured
   head-to-head, one winner binds.
3. **Parallelism:** window/surface before kernel init where 0297
   allows; runtime-thread boot overlap **verified with signposts**
   (the 0322 design claims it; M0 receipts prove or refute it) —
   attributed by the parent §4 critical-path-residue rule, never
   double-counted.
4. **Presentation tail:** first CA commit carries the first frame
   (0490 clock); no layout pass the first frame doesn't need.
5. **Caches:** font *data* persisted (bytes/descriptors/metrics,
   tuple-keyed like the metric cache) with per-process
   re-registration; remaining boot-window file I/O → mmap or
   post-paint. EXFF artifact mmap runs as an attributed experiment
   (replay is already 2.4–2.6 ms; the win, if any, is in load/page-in,
   and the receipt decides).
6. **Size (diagnostic):** pages faulted before first paint — the
   regression explainer, not a gate.
