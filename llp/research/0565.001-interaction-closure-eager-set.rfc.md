## Summary

JS evaluation is on the startup critical path because eagerness is
decided by *reachability*. This RFC makes it decided by the **Boot
Activation Manifest** (parent §6): a compiler-owned classification of
every module into `eager-js` (the boot activation set — the modules
that *produce the first frame* plus those its declared handlers and
mount-eager tasks/resources require) and `deferred-js` (everything
else, behind **compiler-generated activation boundaries**). A boundary is an extraction, not a skip — and **v1 places boundaries
only at already-asynchronous seams** (literal dynamic imports,
existing deferred-delivery/suspension points): converting a
synchronous static import into an async activation would change the
host-event/action contract and top-level initialization order, and
0535 supplies no Plan/native suspension lowering — so sync→async
conversion is OUT of v1, recorded as the future path gated on
explicit Plan/native suspension, pending-event, fencing, and error
semantics. ESM/CJS evaluation order and observable effects are
preserved because the eager set is a complete, semantically closed
graph AND no synchronous seam changes shape. **Deferred groups are
admitted AND linked at boot** (matching 0413.001, which links during
admission); **first touch pays evaluation only**, budgeted and
receipted — link cost is attributed once, in the boot
`acquisition/admission` slice, whose cap and levers are owned by the
parent §5 and .004 (composition-size growth from deferred groups is
priced there, acknowledged here). Target: the `evaluation` slice bound at the parent §5 cap
(provisional pending M0-cold; parent §5 is the authority).

## Design sketch

1. **Classification (compile/produce time):** the manifest's JS
   classes are computed from the route's Plan — the initial tree's
   render-producing modules, its bound handlers' code (**excluding handlers .002's certificate
   proves plan-pure** — they need no JS ever), mount-eager
   tasks/resources — with **totality** (every module classified),
   **effect rules** (a module whose top-level effects the eager set
   observes cannot defer; the compiler proves it or keeps it eager),
   and **admission rules** (the manifest is digest-bound composition
   content; verifier-recomputable). This is commissioned compiler
   work: 0485 declares the data; nothing existing computes the
   closure. 0535 is precedent for suspension points, not the
   mechanism.
2. **Extraction:** deferred classes become separate admitted record
   groups behind activation boundaries (their own entries in the
   composition; the linker sees complete graphs on both sides). No
   statically-imported module is ever "present but unevaluated."
3. **Fallback:** manifest absent/invalid ⇒ deterministic
   reachability-eager (today's behavior), loudly reported — never a
   partial manifest.
4. **Budgets:** the L-D row gains the activation-set count (down-only,
   per route); the `evaluation` slice binds at **the parent §5 cap**
   (this RFC sets no independent number — parent §5 is the single
   authority; its current provisional cap is 55 ms); first-touch
   evaluation gets its own receipt row (diagnostic first, budget
   later).
