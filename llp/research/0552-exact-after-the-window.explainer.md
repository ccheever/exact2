## Summary

After the breaking window, an Exact app is **a plan** — a contiguous buffer of relational tables the compiler emits from Contract source (0485 §2, LAW) — run by **one Rust engine** on every platform (0505 row 1; 0480/0483 Accepted): natively on Apple, Windows, Android, and Linux hosts, and as wasm over the real DOM on the web (0483 §2; 0517 DESIGN). It talks to **one kernel** through **one wire format** (0507 §4, LAW), and every other subsystem — motion, input, routing, styling, data, capabilities, localization, the agent surface — is recast in the same shape: *a decision expressed as data, evaluated by an owner-declared evaluator, crossing typed budgeted capability edges, emitting receipts, held to one semantics by a conformance corpus* (0504 §1). JavaScript leaves the frame path on native (0478 §2.3) and becomes one projection among several at the module boundary (0525 F3). The window exists because Exact is pre-1.0 with zero external users, which makes this "the cheapest moment Exact will ever have" for every one of these changes (0504 §1; 0505 §1), and it closes not on a date but when six named conjuncts are green or explicitly author-waived (0506 D1). At that commit, "Exact stops being a program and becomes a platform" (0514 M10).

## 1. The one move, made everywhere

*Status: the pattern sentence is 0504's (Review, a derived map); the arc it summarizes spans LAW, DECIDED DIRECTION, and DESIGN documents alike.*

The Refresh family is long because it applies one idea to a dozen subsystems, not because it has a dozen ideas. The idea, stated once in 0504 §1 and quoted here so the rest of this document can lean on it:

> *decision as data* (plans, manifests, recipes, filters, grants, cells), evaluated under an *owner-declared evaluator topology* — usually one shared Rust engine, sometimes deliberately N engines held to one semantics by an instrument — with *typed, budgeted capability edges*, *receipts out the side* (one causal evidence stream), and *a conformance corpus as the instrument* (engines never diverge by hope).

The arc: RFC 0478 asked whether Contract could run at full speed; 0479–0485 answered with the flat plan; 0486–0489 unified layout semantics beneath it; 0490/0491 rebuilt the GPU and kernel substrates in the same window; 0492–0500 extended the pattern across motion, input, routing, the agent surface, verification, styling, data, capabilities, and the dev loop (0504 §1). After the map was first drawn: 0505 decided the twelve hard rows in one sitting; 0506 gave the window an exit; 0507–0520 wrote the platform specifications; 0524–0529 brought the native module boundary into the same window (0506 D1(f)); 0532–0543 took up the authoring experience, localization, progressive delivery, forms, and lists (each cited in its section below).

Two consequences of the pattern are worth holding onto before the details. First, **"one engine" does not mean one implementation of everything**: where two engines are deliberate (Taffy and browser CSS for layout; a kernel token table and CSS custom properties for styling), the corpus is the instrument that keeps them one — "the 2× tax does not collapse to one implementation but to bounded per-engine behavior plus a corpus" (0479 §2.1; 0485 §4.1). Second, **break-compat is not delete-capability**: every decided row carries a keep-list (0505 §1). React stays as a fully supported tier; what dies is the hand-authored second binding (0505 row 6).

A third thing a newcomer must hold: **the window and the program are not the same size.** 0506 D2 says anything not on D1's list is post-window work. Much of what follows is explicitly post-window by its own text — the authoring closeout (0532 §0; 0514 M11), nearly all of localization (0536 §5), all of progressive delivery (0537 §5), the list break (0540 §8.6), the Edition-2 folds. The window is the ABI freeze; the program is larger and continues after it.

## 2. You write Contract

*Status: Contract v1 Edition 1 (0508) and its three flagged extensions (0521, 0535, 0539) are LAW. Boundary inference (0531) is DESIGN (Draft); 0519's census licensed experiments, not adoption (0519 §3).*

The surface a developer touches is unchanged in spelling — the indent grammar, the `contract` block, Facet imports, the Acto loop (0478 §2.1; 0481 §7) — and narrowed in semantics. Contract v1, Edition 1 (0508, ratified 2026-08-20) is a **closed language**:

- **Types are closed and inferred.** Primitives, string enums, tagged sums, closed objects, single-type arrays, `Option<T>`. State annotations are a compile error — types come from initializers (0508 §4.1, §4.6). There is no `any`, no open object, no generic yet (**OPEN**, 0508 §13 item 1).
- **Absence is `Option`-only.** `T | null` is not a type; `none` is the only absence; there is no observable `undefined`; out-of-bounds indexing yields `none` rather than trapping, because the type system made the trap unreachable (0508 §4.1–4.2, §6.3; 0505 row 10).
- **Values, not references.** Assignment copies; aggregate `==` is rejected in favor of named equivalence relations (0508 §4.4, §5.1).
- **Actions are reducers; tasks never write state.** An action is `(state, event, env) → (state′, Command[])` with a closed command vocabulary and **no `await`**; anything asynchronous is a `task` that dispatches typed events back into actions (0508 §7.1, §10.3; 0485 §7). "Submit then navigate" is three actions and one task line (0485 §7.7).
- **Dynamic data access is in-language, never an escape.** A `cursor` follows a key across reorders; bare `items[i]` compiles but *widens visibly* against a budget (0508 §10.2; 0485 §6.2). 0518's Ruling A adopts that sentence verbatim as one of its two ceilings — 0518 itself is Draft (**OPEN** until W2 adopts it).
- **Boundaries are parsed with `shape`.** External data enters through `resource x = expr as shape T`, exact and detached (0508 §9).

Three accepted extensions sit behind flags as Edition-2 material, each a numbered 0508 §14 amendment and each **default-off**: `staticDependencies` (0521 — the compiler-emitted graph is the *sole* scheduling authority in flagged mode; runtime read observation remains as a shadow validator, and 0521 explicitly does **not** delete it — deletion has its own later gate, 0521 §1, §8); `actionSegments` (0535 — an awaited action becomes a journaled sequence of atomic transactions, the 0522 Option C ruling; it requires `staticDependencies`, and has **no plan encoding or native runner yet** — AS-D3/D4, OPEN); and `contractForms` (0539 — a `form` node that is a pure projection of LLP 0091's `SemanticFormRecord`; spelling only, every runner fail-closed until its package lands, 0539 §12). A fourth, **boundary inference (0531, DESIGN)**, would let project-local components omit `props` and derive `shape`s from provider metadata as *reviewed, untrusted* proposals, because the migration census put 75% of rejections at exactly those two seams (0519 Summary; 0531 §2). If adopted, "annotate" becomes "accept a materialized block the compiler wrote" (0531 §2.3) — under Edition 1 today, annotations are simply illegal (0508 §4.6).

The escape hatch for dynamic *computation* — islands, in exactly three lanes (0518 Ruling B, Draft, **OPEN**) — is designed to shrink: recurring island reasons become language features (0518 §6). Only a fail-closed format reservation for it has landed (0485 Amendment 2).

## 3. The compiler emits a plan; one engine runs it

*Status: the plan format (0485) and the deriving RFCs 0480/0482/0483 are LAW (Accepted; 0480's D1-bytes stays gated). The web embedding (0517) is DESIGN (Draft) with four named ABI blockers. Mode 3 is OPEN.*

**"The plan is the program."** The deployable artifact is not an IR tree that engines walk but a contiguous, position-independent, `mmap`-able buffer of relational tables — Slots, Nodes, Bindings, Deps (topologically ordered at build time), Regions, Actions, Exprs, Strings — that precompiled loops index into. It is data, not code; every *schematic* fact is resolved at build time and only *instances* (active branches, keys, cardinalities) remain runtime-parametric (0480 §2.2; 0485 §2). Output is byte-identical for the same source under the same compiler version *and configuration* (0485 §3.2). Loading is an admission pass — "never trusted indexing" (0485 §3.4). Motion graphs are *referenced* sibling artifacts the plan points at, never plan opcodes (0485 §3.3.14); graphics sub-programs likewise sit beside the plan (0485 §8.1) under 0490/0512's authority.

What static totality buys is the whole program in miniature: replay, impact analysis, fan-out as a number, **cost claims in the contract block** (`fanout x <= N`, `plansize <= 96kb`) that *fail the build* when exceeded (0485 §9.2), and a `PlanAdmissionCertificate` that classifies every executable context fail-closed — anything unmapped is class 5, "never class 1 by optimism" (0485 §11). Whether *contiguity itself* (mmap sharing, density) is the cause of the measured speedup is deliberately **OPEN** — D1-bytes is gated on a 2×2 ablation (0480 §14).

**One engine, every platform** (0505 row 1, decided). On native the loop is input → runtime thread → reducer → dense slots → dirtied derives → encoded ops → presenter, with zero JavaScript in it (0478 §2.3). On the web the direction is the **same Rust engine compiled to wasm driving the real DOM** through a Plan Host Interface (0483 §2 option (b), decided), behind three cutover gates — corpus green on wasm/DOM, priced wasm cost, a cheap TS seam (0483 §2; 0514 M2) — and behind 0517's four M2-registration blockers (boot-config format, result-header layout, symbol spellings, clock imports; 0517 §13, **OPEN**). The compiled-TS web tier is demoted and then deleted (0503 §4.2). The Rust mirror of the TS interpreter, `interp.rs`, is deleted at dual-run green; **the TypeScript tree-walker survives as the conformance oracle**, off the dev path (0505 row 2; 0514 M1). A second *mode* — generated Rust for OS shells, widgets, and embedded targets — is specified in 0485 §12.3 with its own gated go decision (0480 §5 frames it as the build-time choice); whether it earns its place is **OPEN** (0485 §1.2).

The numbers the corpus has actually banked: the flat-plan runner at p50 8.8 ms vs the interpreter's 163 ms on the pre-registered 10K keyed-rebind workload (0479 Summary; F2 PASS). Cold start at 114 ms p50 vs ~224 ms under Hermes and 80 vs 204 MiB RSS are **desktop diagnostics, directional rather than device-banked** (0478 §1.2); the targets are ≤100 ms on a pinned iPhone and ≤40 MiB (0478 §2.4). The update-path targets (p50 < 10 µs) are reasoned, not promoted, until the D1-bytes ablation runs (0480 §6.3, §14). A non-obvious ruling on the latency path: **a discrete update is not parallelized by default** — thread dispatch alone exceeds the p50 target, and latency *variance* is itself the defect (0482 §1; tier-2 is replay-only, 0485 Amendment 1) — while 0485 §13.4 admits worker-parallel keyed rebind, bulk derives, and parallel mount only behind certificate and cutoff gates.

## 4. The substrate: kernel, layout, wire, GPU, lists

*Status: all LAW as of the 2026-08-23 acceptances — kernel (0491), EXWF (0507), native boundary (0510), GPU (0490/0512), layout (0486–0488), Canvas 2D (0529), lists (0540/0543) — with the shipping list still the JS windower until the L-rungs land.*

**The kernel** (0491, Accepted 2026-08-22) becomes "a copied-in, borrow-parsed binary command stream with transactional apply and columnar binary exports"; "shared memory" is retired from its description and the "zero-copy" brand, ~40% true, with it (0491 §4). The string-keyed prop model was the root cause of most of the drift (0491 Summary), so the nine workstreams replace it with a generated typed `PropId` arena (WS-A), declaration authorities that generate every codec (WS-B), a columnar `EXNODE` export with one crossing per sync (WS-C), the EXWF wire break (WS-D), one `ExactStatus` and per-kernel host-services objects (WS-E), a population-zero deletion sweep including the direct-setter write path (WS-F), a three-crate split with a machine-checked dependency DAG (WS-G), dirty epochs and a `SemanticFrame` flight recorder (WS-H), and the semantic corrections that are only cheap now (WS-I) (0491 §3). The kernel adds **no threads** and rejects process-level parallelism outright (0491 §2, OQ9). Seven companion amendments to 0507/0515/0510/0492/0496 remain owner-gated before the affected gates activate (0491 §8; 0504 row 88).

**Layout** is "one language, two engines" (0486, Accepted 2026-08-23): Taffy in the kernel and real CSS in the browser, held to one semantics by a closed operator catalog, an algorithm-free Layout Profile that generates the web defaults, four parity tiers (Semantic, Frame, Band, Decision), and a dual-engine harness that drives real Chromium through CDP and emits a divergence catalog (0486 §4–§6; its §13 lists the unfrozen parts). Choice layout is a pure three-valued `select` with a fixture corpus that outranks prose (0487 §3–§4, Summary — honestly 2 production + 18 prototype fixtures). The one feedback channel from layout back to the runtime is budgeted at **no more than one frame**, one-directional per frame, with no deadband — because hysteresis would make size classes history-dependent and the server has no history (0488 §4.1, §5).

**The wire** is EXWF (0507, LAW): one commit engine, two ingress forms (byte frames and in-process Rust structured-apply), validate-then-apply, fail closed — "no silent fallbacks, truncations, or best-effort decodes" (0507 §4). Every cross-stream node reference is a six-field raw address; `exwfFrameRevision` and `exwfSchemaDigest` move in lockstep or admission fails (0507 §5, §8). Compatibility is per-dimension epochs, never one flip (0507 §9.3). The whole break is reviewed as one artifact, the **break package** (0491 Week 0).

**The native boundary** (0510, LAW) is the security spine: an issued grant carries its *complete* authority embedded at admission; the manifest's `permissions` field is deleted, not deprecated, and entitlements are computed from a closed content-addressed fold map (0510 §5). Continuing any effect under a durable capsule requires a seven-item lease predicate to bind (0510 §6.2; 0476 A1).

**GPU** (0490, 0512, LAW): WebGPU is the only public low-level GPU API on every platform — verbatim W3C on the web, and on native a **pinned Exact profile with a ledgered deviation list** ("no unqualified full-W3C claim exists on native" until a platform's suite passes, 0512 §1.1). `ExactMotionClock` is *the* frame loop; SharedValues are the one value graph, so a gesture drives a shader at display rate with zero per-frame JS (0490 §3). Layout owns geometry — GPU content never influences it — and zero demand must cost zero frames (0512 §5). Standard Canvas 2D is the 2D floor — implemented *as* `OffscreenCanvas` on native, shipped complete or not at all (0529, Accepted 2026-08-23; native exposure details, GPU sharing, and video sources OPEN, 0529 §5).

**Lists** (0540/0543, LAW since 2026-08-23) decide that lists stop being a JS windower re-deriving positions from estimates. The kernel classifies participants of a certified one-axis root as visible/prerender/hidden against real boxes before paint; a hidden row keeps its plan row, semantics, and retained box and releases only its native view; **a measured item is never re-estimated**; scroll anchoring is a kernel-emitted atomic delta — "no anchor view, no event-ignore window, no translation hack" (0540 §1–§2). A bounded frame hold becomes the second registered customer of the one sanctioned servicing wait — the 0297 §4.4 amendment landed at 0540's acceptance (2026-08-23): the sanctioned set is now {live-resize wait, visible-content hold}, B9's uniqueness becoming set-membership (0297 §4.4; 0540 §3.6) — with every preset starting on `fallback` until the hold proves itself on physical hardware (0540 §3; 0543 §11). 0139 is superseded at that acceptance (0540 §8.1); the JS windower remains the shipping code until the ladder's L4 rung makes the new lowering the default (0514 §4's third sibling-ladder row).

## 5. Everything else is data too

*Status: motion (0492), routing (0494), styling (0497), web style lowering (0520), localization (0536), progressive delivery (0537), and route payloads (0513) are LAW (0492/0494/0497 Accepted 2026-08-23). Text input (0493) remains DESIGN (Review).*

- **Motion** (0492, Accepted): every animation, gesture, transition, and state machine compiles to one value graph evaluated by `exact-motion`, on every platform, in the first release — decided (0505 row 7). JS leaves the frame path; `runOnJS` is deleted; consequences exit only through receipted `motion.command` (0492 §4.5). With a virtual clock and a *pinned evaluator build*, a (schedule, input log) pair replays to bit-identical values; cross-architecture math determinism is a separate claim (0492 §4.2).
- **Text input** (0493, DESIGN — still Review): a phone field rejects a letter on the keystroke path with zero JS, via three HTML-mirrored typed props — spelling and host-hook coverage still OPEN (0493 §10); a host without the pre-editor hook is never "Tier A" because it is post-render by construction (0493 §4.5). Rust would become strictly more capable than JS-on-native here, because synchrony is free in-process and forbidden across the runtime thread (0493 §6).
- **Routing** (0494, Accepted): routes are data — a 0485 Entrypoints extension generated from the filesystem (the amendment is a pending ask, 0504 row 4) — matched and committed by a pure Rust core; hosts are thin glue with a fixture row each, so a link-interception failure "becomes a red conformance row" (0494 §4). Data readiness is Aquifer's record; the router only asks (0494 §4.3). 0494 recorded that auth lifecycle had no owner; **0516 now designates that owner** (0516 §5). Thread home and deep links are OPEN (0494 OQ1, OQ6).
- **Styling** (0497, Accepted): RecipeIR is the single authority and **React bindings are generated from RecipeIR** — decided (0505 row 6): "the parity gate is generation itself" (0497 OQ7). The native kernel token table with compiler-derived dependency domains (a theme flip as O(1) wire) is 0497's design, measurement-gated (0497 §4.2, F-B); web gets CSS custom properties and the real cascade. Web style lowering (0520, LAW) gives every web tier one `WebStyleBundle` and one CSS emitter; tier equivalence means identical computed style (0520 §15).
- **Localization** (0536, LAW): the compiler extracts strings into per-locale catalogs addressed by `(planDigest, locale, catalogDigest)`; one pinned MessageFormat 2 formatter runs natively and as wasm; the browser's `Intl` is a differential oracle that may never produce user-visible output (0536 §3). Most of an app's words — its data — are explicitly not this RFC's to localize (0536 §4). Almost all of it is post-window (0536 §5).
- **Delivery** (0513, 0537, LAW): a route payload is **cells-authoritative** — the cells section is semantic truth, the tree an optional provenance-stamped projection, and "a tree without the cells it derives from is unverifiable pixels" (0513 §4.2). A streamed response is an immutable digest-bound base wrapped in a separately versioned envelope whose segments "are never a cheaper way past admission" (0537 §2.3; post-window, 0537 §5). Before the engine boots, a Contract action with a server projection is a real `<form method="post">` evaluated on the same Rust evaluator server-side; with the engine live it is *still* a POST to the same handler, intercepted only when every allowed outcome can be committed — "the runner upgrades transport and adoption, never execution locus" (0537 §3.1; 0538 §2.3).

## 6. Data, authority, identity

*Status: all LAW as of the 2026-08-23 acceptances — cells (0509), the native boundary (0510), capsules (0476), session identity (0515), the Aquifer program (0498), the capability stack (0499), and auth lifecycle (0516).*

**Aquifer** (0498/0509, LAW) is the data tier: cells — named, typed, state-machined values — evaluated by one Rust cell engine inside the plan runner. Apps *declare* data; declarations compile into the plan's Cells table; the only edge to the outside is a **data provider**, a typed capability feeding the engine through a `ProviderEvent` channel (0498 §4.3–4.4, ruled). **Snapback is a data provider behind Aquifer, never the architecture itself** (0498 §8). A mounted `resource` is a subscriber handle, not the cell — which is what lets two components share one fetch (0498 §4.1). Identity is four joined keys, with the HMR key deliberately *outside* the cache key (0509 §4, LAW). "Show previous while loading" is a per-subscriber projection and can never satisfy readiness (0509 §5.4). Hydration, window restoration, pooled server sessions, and cross-runtime attach are **one mechanism — late-subscriber replay** (0498 §4.5), consumed by 0513's convergence law.

**The capability stack** (0499/0476/0510, LAW) is four layers — capsec, grants, operation descriptors, capsules — under one folding rule: authority folds *downward* through a closed table and nothing may mint laterally (0499 §3–§4; the fold table's content is 0510 §5.4, LAW). Every effectful invocation runs under an operation-bound carrier and may touch only that carrier's fold row (0499 §4.0). For a closed Contract plan the declared capabilities are its *complete* external authority surface; for Rust roots the stack is an audit surface, not a jail, because ambient syscalls are excluded by name (0499 §4.4). Durable authority — an upload that must survive restart — is a native-held receipt plus a sealed compare-and-transition lease; JS gets an opaque handle and nothing else (0476 §2–§3, LAW).

**Identity** (0515/0516, LAW): "session" means eight things, each with one owner, and a bare "session" in normative prose is a defect (0515 §4.2). Sign-in, sign-out, and account switch are *realm rotations* the data tier performs atomically — never events on the producer stream; `null` is the anonymous state and unauthenticated is a first-class realm (0516 §4, §6). Credentials are custodian-held: **platform authority is never JS-authored or exportable**, while app-backend credentials are a SHOULD-custody class and JS may hold short-lived access material (0516 §7). Every failure is fail-closed into a typed terminal — never a guessed principal, never a false anonymous (0516 §9). The five §11 decisions are taken (brokered login, realm-bound refresh, switch-only first release, a fail-closed durable sign-out cascade with per-kind opt-out, router extraction as a rebuild).

## 7. Native modules and the OS

*Status: the module research 0524–0528 is Active/Accepted; the commissioned Module Boundary RFC exists as LLP 0545 (Draft r1, 2026-08-23); the module epoch joining the window is LAW (0506 D1(f)). 0527's producer role is explicitly a proposal-stage hypothesis (0527 Summary); 0533 is a commission stub (OPEN in full).*

A native module is designed as **a capability provider with projections** (0525 F1): one generated interface authority, ModuleIR, from which every binding is generated — Contract first, TypeScript, Rust, host glue, *and the fake*; "an authority that cannot produce a fake is not an authority yet" (0525 F1, F6). JS is one projection, never the transport; the opcode module protocol is deleted outright (0525 F2–F3). Pure functions are not boundary operations at all — they link as library code into every tier (0525 F1). The module epoch joins the breaking window — "everything breaks at once," on a global train, no per-host cutover (0506 D1(f); 0530 §2.4) — with four named umbrella children: the sibling-operation-table → 0510 projection, the AdoptedControl generic-NativeView ABI, the installed-plane schema and per-kind ABI, and the semantic-child projection ABI (0506 D1(f); 0504 rows 34b–34e).

Native code hot-reloads through the architecture 0331 already built: a stable supervisor and a replaceable app worker, so you can edit Rust while an iPhone app stays open; each reload is one always-advancing publication, and state crosses only through the capsule (0524 F1, F3). The workload atlas classifies ~50 archetypes, and its most valuable rows are refusals: `fetch`, text, navigation chrome, semantic canvas, keyboard height, and Exact windows are *anti-modules* — core, not plugins (0526 §5, finding 6). 0527 hypothesizes that a pixel-producing module is a *role* a core node plays, with no thread or crash domain of its own (0527 §3.2, proposal-stage). 0528 proposes that platform controls become presenter vocabulary under a Control Adoption Contract and extensions run in a per-platform Extension Host with budget SKUs (0528 §3–§4); "a digest proves bytes, never safety" (0528 §7). Every capability-bearing OS callback **fails closed** until the installed-service principal exists — a system/no-user identity that is not a session and can never laterally mint (0533; **OPEN** in full). No share extension, widget, or notification is capability-bearing in the first release.

Expose — the stated downstream milestone — composes through exactly this: OS surfaces are Rust Native roots under 0331 holding 0510 grants (0331 §5.2; 0510 §4); a no-user root still gets a data session because unauthenticated is a realm (0509 §4.4). Expose readiness is deliberately **not** a freeze conjunct (0506 D3).

## 8. The agent and the verifier

*Status: Acto v2 (0511) is LAW; 0495 (the program) and 0496 (verification) are DESIGN (Review) — 0496's planted-defect principle is independently adopted by Accepted 0532 §10.*

**Acto** (0495 DESIGN; 0511 LAW) reads the substrate instead of mirroring it: every agent-facing projection *derives* from the structure the host renders from; a parallel reconstruction is a defect (0495 §4.1).
