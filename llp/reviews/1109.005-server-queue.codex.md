## Findings

1. **P1 — foreign durable pending operation can be overwritten.** `mobileQueueCommand` checks pending at entry, but its awaited admission guard only rechecks client.busy. A different persisted pending operation appearing while ID allocation waits is overwritten by this queue dispatch and then cleared. Actual witness: `writes:1,pendingPreserved:false`. The guard must distinguish its own durable operation from a foreign pending record at every pre-dispatch await.
2. **P1 — thumbnail resource returns while a sibling native answer remains in flight.** `Promise.all` rejects on the first superseded worker. Gated execution proves the resource has settled while another worker's native answer remains active (`settled:true,active:1`). All owned workers must settle before returning, without storing native handles/promises across answers.
3. **P2 — ordinary resource rereads duplicate signing and supersede earlier reads.** Every `mobileQueueRead` increments its serial even for the same owner/visit. Two gated reads mint twice; first rejects, second succeeds (`calls:2,successes:[false,true]`). Repeated event revisions can starve the queue's initial snapshot, which also waits for all thumbnails before exposing rows/dismiss. Use pure projection plus explicit stable request admission/pending metadata, as in the completed AnswerFile correction, or demonstrate equivalent root ownership.
