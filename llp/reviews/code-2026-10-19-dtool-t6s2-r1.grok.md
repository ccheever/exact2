## Findings

1. **SHOULD-FIX** — A paired client still gets a canvas, and its `src` is the remote browser's own loopback. D12 says that without the gateway a remote client has no canvas, because a loopback frame loads the viewer's machine. The frame is rendered whenever `hello.page` is set, with no `hello.local` check (`app.contract:1369-1373`, sandbox `allow-scripts allow-same-origin`). The real hello includes `page` for every caller (`scripts/tamber-server.mjs:692`). `pageOf` accepts any `http://127.0.0.1|localhost|[::1]` port except 7740 (`origins.ts:12-16`). Open the tool from the door, pair, and a server whose dev loop is on port 8080 makes that browser request `http://localhost:8080`. The URL carries no token. The stub already withholds `page` unless the asker is local (`stub/tamber-stub.ts:182`), so the new test never sees the frame. The commit notes the gateway is later; the frame is on now.

2. **SHOULD-FIX** — The pair form's instructions describe a gesture the real door refuses, and the test cannot see that. The hint says to open the address once, accept the certificate, then type the address and code on this page (`app.contract:1287-1290`). From the local tool (`http://127.0.0.1:7740`) that fetch is cross-origin. The door's Origin check returns 403 and sets no CORS header (`scripts/tamber-remote.mjs:149-153`), so the browser does not send the body: the code does not leave the machine, and `base` does not change. Accepting the certificate does not make the local page same-origin with the door. Pairing works when this page was itself served from `/__tamber/tool/` on that door. The remote-mode test pairs against the stub, which sends `access-control-allow-origin: *` and does not check Origin (`stub/tamber-stub.ts:108-110`), so it passes for a gesture a real door rejects. The stub's comment that the driver is another origin (`107`) is why it cannot enforce B; the test still claims the end-to-end pair.

3. **NIT** — `pairWith` keeps the previous run's token in the bound slots. It replaces `base` and `token` (`wire.ts:128`) and leaves the review JSON (`app.ts:772`), `heldToken` (`982`), undo entries (`797`), and `scrubbing.token` (`833`). `call` will put `bound` on the header to the new `base` (`wire.ts:99-100`). `loadScope` does that with no click when the scope is write (`app.ts:1163`). That send does not happen against a real door today. A page that holds the local token is the local tool, and pair to any other origin fails as in finding 2, before `base` changes. A page the door served cannot read `GET http://127.0.0.1:7740/__tamber/token`: the local server sends no CORS header, and from an https door that fetch is mixed content. Dropping those copies inside `pairWith` would make the rule the tool's.

4. **NIT** — The client does not apply the server's dynamic scope upgrades, so two "never sent" cases are only the disabled button. `needOf` marks every `drop` as `propose` and upgrades `inspect` only (`wire.ts:35`). The server also raises `drop` of another client's held proposal to `write` (`scripts/tamber-pairing.mjs:78-81`). The Drop button is enabled when `canWrite` or the row's client is this client (`app.contract:1856`, `1872`), so a propose client cannot press it for someone else's proposal; `dropHeld` itself sends whatever id it is given (`app.ts:1405-1406`). Cancel scrub is not gated on `canWrite` (`app.contract:1765`); Start and Keep are. A propose client cannot start a scrub, so Cancel is only reachable if a scrub object is still in memory. `scripts/design-tool-scope.test.mjs` compares the static tables and three `above` results. It does not call `needOf`, which is not exported, so a change to the inspect line would still pass. The server answers 403 for all of these.

5. **NIT** — The revoke test checks the screen and does not check that a later write stays unsent. After the stub revoke it expects the Revoked title and the `GONE` sentence (`app.test.contract:1796-1802`). It never fires Apply, undo, or commit afterward and asserts no further request. The hold-back is the `gone` flag in finding 1's security notes; this test would still pass if that flag stopped being checked after the poll that paints the screen.

Step 1's round-1 fixes listed above match the disposition. The stub's fixed code series, missing burn-after-five, cap of 8, and rate limit are the items that disposition left to the real server.
