NEEDS REWORK

§8 closes Astra 4 and Grok 5’s per-node exit shift, Astra 6’s play matching, Astra 8 / Grok 4 and 9’s local-time-zero rule, and Astra 9’s Signal measurement. On-screen lowered specs do go through `svg_lower::specs` (`host/apple/src/svg.rs:247`, `:571`, `:627`, `:681`, `:826`), which writes `play.hold` (`svg_lower.rs:262`), and `CssAnimations.make` holds that at `speed` 0 (`SvgScene.swift:178-195`). These are not closed: pending curves still die or move through paths that never call `sample` (Astra 1 / Grok 2), the target-timestamp clock breaks input seeks (Astra 2 / Grok 8), boot cannot arm the flag before the first batch (Astra 7 / Grok 8), and an idle clock’s second join is a live member D8 does not shift (Grok 7).

1. **P1 — Seeking the engine to `targetTimestamp` rejects live input and moves a release off its instant.** D5 puts `Engine::now` up to one interval ahead of wall time, and names only two clamps: `commit_tree`’s final seek (`host.rs:1299`, which today does not max, unlike the receipt seek at `host.rs:1267`) and `end_hold`. These still call `advance(input)` and return `ClockWentBackwards` before changing anything: `begin_transform_hold` (`hold.rs:135`), `update_transform_hold` (`hold.rs:178`), `begin_hold` (`hold.rs:214`), `update_hold` (`hold.rs:271`), `end_hold` (`hold.rs:346`). A photo drag refuses the packet when `now_ms / 1000 < engine.now` (`transform_drag_wire.rs:81-83`) and seeks that time again (`transform_drag.rs:340`). A height drag drops the shown-height sample unless the times are equal (`height_drag.rs:156`). Takeover then ticks at `max(wall, runner)` (`Agent.swift:489-503`, `:537`), which is behind that engine, so the agent’s first `tick` fails the same way. Clamping `end_hold`’s seek up to `engine.now` also starts the spring there (`hold.rs:363-364`), so D6’s `v·Δt` from the input time (`24563562f`) is dropped. **Fix:** keep `Engine::now` on the input clock. Have the motion tick sample and run `start_pending` at `targetTimestamp` without storing that instant as `now`. A release’s `start` stays the input time.

2. **P1 — A pending play’s `hold` makes a sampled play, including every exit, not live, so it never runs.** D1 stores `hold: Some(local)`. `live` is `hold.is_none()` (`animate.rs:41-42`). `schedule_animations` (`animate.rs:179-186`) and `advance_animations` (`animate.rs:368-376`) then drop the node from `animating`. `play_exit` inserts it (`animate.rs:295`) and the commit’s final `advance` (`host.rs:1299`) removes it before `present`. `quiescent` is only `running` and `animating` (`engine.rs:657-658`). Exits are sampled on purpose (`presence.rs:131-138`) and have no CA spec to carry them. After `start_pending` clears `hold`, nothing calls `schedule_animations`, so the exit stays at local 0 and `present` still destroys from the end captured at `play_exit` (`presence.rs:140-142`, `:305-309`). **Fix:** `live` treats `pending` as live until `start_pending`, which then calls `schedule_animations`. `present` destroys only from `exit_end`, which is `None` while any of that exit’s plays is pending.

3. **P1 — D7 turns the flag on before an engine exists, and the first batch is emitted inside boot.** `Session` builds a `Runtime` in `init` (`Session.swift:476`) and D7 arms the flag before `boot`. `Host::boot` constructs the engine and applies every initial play in that same call (`host.rs:451-546`, the comment at `:516-517`), then `present`s. Swift does not run between `Engine::new` and `sync.apply`. `prepare` / `commit_plan` build another host the same way, so a reload loses a flag set on the previous engine. `agentFreezes` assigns `clock = 0` before boot (`ExactIOS/main.swift:169`); a `didSet` there fires with no engine. **Fix:** latch the choice on the bridge. `Host::boot` applies it at `Engine::new`, before `sync.apply`, including the prepare/commit host. The `didSet` handles only `nil → some`, and it is idempotent once the engine exists.

4. **P1 — An idle clock’s pending members are not its only live members.** `join_clocks` treats any `hold` as a paused member (`clock.rs:107-114`). A pending play has `hold: Some(local)`, so a second join before the frame sees a busy clock, keeps the commit-time origin, and D8 then exempts that new play. `start_pending` shifts the origin and the first members only. The later play is live and stays on the unshifted phase. One commit is fine: joins are held to the end and `joins()` excludes every joiner in that commit (`clock.rs:85-90`). **Fix:** a `pending` play does not make the clock busy. Further joins before the frame join that pending origin and are pending too, so one `start_pending` shifts the origin and every member still pending.

5. **P2 — D6’s cancel exemption and D1’s settle wording disagree with the curves they name.** `HoldEnd::Cancel` is zero velocity (`hold.rs:341-343`). A still first frame drops no fling; the return spring takes the same processing-time jump §1 measures. Exempt only a non-zero release velocity. Kernel commits always pass `velocity: None` (`kernel/src/motion.rs:493` and the other three sites), so the `Change::velocity` arm does not cover this. `settle_time` “starts at the engine’s current time” (`D1`) is `now + (end − local)` for a play resumed at local `L`, and `end_time + (now − begin)` for a `Running`. `animations_settle_time` skips every hold (`animate.rs:386-388`), and `Running::end_time` is still `begin + delay + duration` (`transition.rs:419-425`). D3’s “offsets summed” is wrong for LLP 1099: `scale` is a product of factors, opacity replaces (`1099-uikit-springs.rfc.md:421-434`). A hold collapses those components at the presented value (`1099:543-547`); that read has to be each pending component at its own begin. The 64-fold (`1099:465-470`) needs a rule when one of the folded pair is pending: the survivor stays pending only if both were.

6. **P2 — §5 does not lock the holes above.** Add: `observe_path` reversal and interruption at `begin` (`path.rs:71`, `:100`); a sampled exit’s values after `start_pending`, not only its destroy time; boot’s first batch held (`"h":0`) with the latch on, and unchanged with it off; a second idle-clock join before the frame; `begin_hold` / `update_hold` / transform-drag / height-drag at a wall time behind the last frame instant; takeover `tick` when the engine leads the runner. The flag-off Rust suite stays off only if the latch defaults off. Swift sessions that boot with `clock == nil` will change.

7. **P3 — `spatial` and the offscreen renderer ignore the hold D4 describes.** `spatial` skips held plays (`engine.rs:674`), so a pending spatial exit does not request the full rate for that interval. The offscreen filter path runs a held spec from `CACurrentMediaTime` (`SvgScene.swift:189-190`) instead of `speed` 0. A `frame` behind `begin` (a tick queued behind owner work, `Bridge.swift:333-337`) needs an explicit rule: leave those curves pending. Clamping the shift to 0 starts them at the commit.

**Q1.** No. Routing `sample` and `easing_progress` through `begin` covers `advance`, `observe`, `observe_path`, reversal, and the pre-sample in `begin_transform_hold`. It does not cover `end_time` / `settle_time` (`engine.rs:681-686`), `spring_descriptor`’s `start` (`engine.rs:609-610`), `animations_settle_time`, `live` / `advance_animations`, `spatial`, or the clock busy scan. `play_transition` copies `start` (`played.rs:69-73`); Apple never calls it (D8).

**Q2.** A cancel should be pending. Only a non-zero release velocity should keep the release instant, and that `start` stays the input time when the engine is already ahead. `Change::velocity` is not an Apple commit path.

**Q3.** Yes. The refusals are `transform_drag_wire.rs:81-83`, the five `advance(now_s)?` calls in `hold.rs`, `transform_drag.rs:340`, and `height_drag.rs:156`. `commit_tree`’s final seek (`host.rs:1299`) and the agent’s `tick` (`Agent.swift:503`, `:537`) use a time that can sit behind `engine.now`. `arrange_now` already maxes (`arrange.rs:199`). `Host::frame` moving `now_ms` to the target (D5, unchanged) is the same lead, today limited to apps with frame tasks; D5 extends it to every motion tick.

**Q4.** No. Within one held commit, every joiner is excluded from the busy scan, so those plays are the only new members. A later commit before the frame sees the pending `hold` as a paused member (`clock.rs:109`), does not take the idle path, and is exempt under D8. Shifting the origin then leaves that play unshifted.
