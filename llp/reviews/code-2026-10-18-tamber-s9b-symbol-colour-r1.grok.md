# Review round 1, LLP 1121 stage 9 B (symbol images take their written colour), Grok 4.7 (xhigh)

**RIGHT WITH CHANGES.** The live rule is right: an untinted symbol image is marked when `says(TextColor)` is true, a direct `Control` child is left on the control tint, and a change to an ancestor’s colour or its written bit re-sends the image. The plan file was not on disk, and the Shelf and Bluesky-clone claims are not in this tree, so those were not checked. `PlatformDefaultsMacTests` is untouched, and no source file is over 1499 lines (`glue.js` is exactly 1499).

1. **BLOCKING** — `runner/src/instance/document.rs:124`. `DocTree::symbol_color` treats a written `color` as said and stops at the node’s own mask or the neutral route header. `NodeRef::says` (`kernel/src/kernel.rs:169`) also stops at a style start that masks `TextColor`: a neutral alert and its non-button children (`kernel/src/arena/alert.rs:76`, colour `-exact-secondary-label`) and a neutral field (`kernel/src/arena/control_text.rs:96`). A symbol under a written colour inside an alert is unmarked on the live web host and marked in a kernel-free document. `host/web/neutral.css:242` then paints that mark as `currentcolor` (the sheet’s secondary label). `host/web/tests/it/tint.rs:184` only compares a plain column, so the two documents agree there and the alert split is untested. Stop the walk at every `TextColor` start `says` uses (header, alert contexts 1, 3 and 4, neutral field), and add that alert to the tint test.

2. **SHOULD-FIX** — `host/apple/Sources/ExactGroupedLists/GroupedListIOS.swift:883`. A standard grouped row hides the page image and draws `UIImage(systemName:)`. The cell takes a concrete `tint_color` only (`:888`); `symbolColorWritten` and `text_color` are ignored, so the visible glyph stays the accent (or the destructive/disabled colour). The same row is a page image on the web and on the Mac, and the ruling’s face list (bar, tab, segment, button) does not include it. The reconfigure key is only `tint_color` (`:596`), so a colour change would not rebuild the cell either. Tint from `symbolInk` when the prop is set and no concrete tint is written, leave destructive and disabled to overwrite that, and put `symbolColorWritten` and `text_color` in `looks`.

3. **SHOULD-FIX** — `host/apple/Sources/ExactKit/Mac/TableInkMac.swift:65`. An emphasized selected row sets the symbol cell’s `backgroundStyle` whenever `tint_color` does not fix the ink. A written colour has no tint row, so a fixed `text_color` is repainted as the selected item’s text. Skip that when `symbolColorWritten == "1"` and `text_color.fixesInk` is true. A role or an unsaid symbol still takes the selected ink.

4. **SHOULD-FIX** — `kernel/src/txn.rs:1316`. `inherited_after_move` touches a moved node only when its computed inherited style changes. On the web a button start does not mask `TextColor` (`kernel/src/arena/control_text.rs:55`), so moving a symbol from a `Control` child to a plain parent flips `symbol_color_said` and leaves the colour the same. The web host updates touched nodes only (`host/web/src/host.rs:949`), and the image keeps the accent. Remember the flag (or “parent is `Control`”) before the move and touch the image when it flips. Cover it in `kernel/tests/it/symbol_color.rs`, which never reparents.

Direct button faces, bar items, tab faces, segments, and Mac toolbar items stay on the control tint: the kernel excludes a `Control`’s own image, and those drawing paths read `symbolName` and `tint_color`. A nested image is not a face. The web sheet’s later zero-specificity `:where(...[data-symbol-color])` loses to an authored `--exact-tint`, and the Chrome fixture checks `currentcolor`, `light-dark`, and a live colour change.
