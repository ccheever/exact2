Five fundamental issues remain, most serious first:

1. **`clock data` and `clock settle` are not empty under the synchronous oracle.**

   D4.1 confuses an answer landing with its consequences finishing. A successful action arms the mutation’s `then`; `advance` subsequently executes that action as another commit. The existing corpus explicitly expects `after == 0` following a tap and `after == 1` after `clock +0`. [semantics/Contract/Runtime.lean:846](/Users/ccheever/projects/exact2-wt-verify-review/semantics/Contract/Runtime.lean:846), [semantics/Contract/Runtime.lean:1116](/Users/ccheever/projects/exact2-wt-verify-review/semantics/Contract/Runtime.lean:1116), [semantics/corpus/mutations/then.contract:24](/Users/ccheever/projects/exact2-wt-verify-review/semantics/corpus/mutations/then.contract:24)

   Consequently, an empty `clock data` can leave an authored expectation checking the state before its continuation while the report counts the step as delivered.

   **Resolve:** deliver and trace a continuation drain on both sides, without firing timers, or leave these steps unsupported. The runner already provides `land_then` for that distinction. Treat `settle`’s additional behavior separately. [runner/src/runner/advance.rs:201](/Users/ccheever/projects/exact2-wt-verify-review/runner/src/runner/advance.rs:201)

2. **D8 cannot establish D1’s precondition for an action-specific `after`.**

   D1 requires one successful action commit and no other commits. One authored tap does not establish that. Besides due work before dispatch, the device test runner automatically advances time after steps according to mutation requests. That advance can execute additional work before the proposed property observation. [runner/src/runner/advance.rs:43](/Users/ccheever/projects/exact2-wt-verify-review/runner/src/runner/advance.rs:43), [scripts/agent-test.mjs:842](/Users/ccheever/projects/exact2-wt-verify-review/scripts/agent-test.mjs:842), [scripts/agent-test.mjs:918](/Users/ccheever/projects/exact2-wt-verify-review/scripts/agent-test.mjs:918)

   A continuation can therefore make a correct action appear wrong, or repair a broken action before its property is checked. Calling the device claim weaker does not fix this attribution error. D8 itself admits that the driver cannot see the commits.

   **Resolve:** ship device `always` first. Enable action-specific `after` only when the device supplies action identity, outcome and intervening-commit information sufficient to enforce D1. Otherwise mark it unsupported.

3. **D5 cannot identify class T from today’s refusal reasons.**

   `SlotType` and `DeriveType` do not mean “wrong type” exclusively. Conformance also requires finite numbers, and both refusal sites discard the offending value, retaining only the declaration’s name. [plan/src/value.rs:255](/Users/ccheever/projects/exact2-wt-verify-review/plan/src/value.rs:255), [runner/src/runner/commit.rs:464](/Users/ccheever/projects/exact2-wt-verify-review/runner/src/runner/commit.rs:464), [runner/src/runner/settlement.rs:324](/Users/ccheever/projects/exact2-wt-verify-review/runner/src/runner/settlement.rs:324)

   Thus a numeric write producing infinity receives the same `SlotType` category that D5 proposes failing as a checker bug. This is an existing tested refusal, not a hypothetical malformed program. [semantics/corpus/numbers/refuse-nonfinite.contract:7](/Users/ccheever/projects/exact2-wt-verify-review/semantics/corpus/numbers/refuse-nonfinite.contract:7)

   **Resolve:** distinguish type mismatch from non-finiteness where the value is available, and carry that classification into the observation. Until then, ambiguous reasons cannot truthfully be classified as T. Tests over canned reason strings cannot recover information those strings omit.

4. **The shared literal vocabulary does not yet describe a shared observation.**

   The differential observation prints a node’s own text and omits virtualized-list descendants. The device’s `expect text` can instead read a control’s value or concatenate descendant text. Unlabelled descendants’ text is absent from the differential observation altogether. [semantics/difftest/src/observe.rs:82](/Users/ccheever/projects/exact2-wt-verify-review/semantics/difftest/src/observe.rs:82), [semantics/difftest/src/observe.rs:173](/Users/ccheever/projects/exact2-wt-verify-review/semantics/difftest/src/observe.rs:173), [scripts/agent-test.mjs:22](/Users/ccheever/projects/exact2-wt-verify-review/scripts/agent-test.mjs:22)

   A button labelled by a child text node can therefore satisfy a device property and fail its harness counterpart without an app defect. Conversely, `tree missing` can pass because a row was excluded from observation. Literal syntax does not make these equivalent.

   **Resolve:** define and implement a common supported observation before promising one predicate across engines. The cheaper first slice is root-state properties; defer view predicates, or report excluded targets as unsupported rather than absent.

5. **A divergence cannot be shrunk against the same predicate on the runner alone.**

   D4 includes “the same divergence” in runner-only shrinking, followed by one Lean confirmation. Divergence is a relation between two executions. After removing an event, the candidate needs its own Lean result; the original result is no longer its expected observation. Today’s shrinker correctly calls the differential checker for each batch of candidates. [semantics/difftest/src/lib.rs:518](/Users/ccheever/projects/exact2-wt-verify-review/semantics/difftest/src/lib.rs:518)

   **Resolve:** separate shrinking policies. Runner property violations and classified refusals can shrink cheaply on the runner, then receive Lean confirmation. Differential failures require both engines during shrinking. Budget that cost explicitly.
