**Blockers remain.** The shared budget closes the reported reference-counting holes, but several inputs below 1 MiB still reach uncharged expansion or super-linear planning. Findings are from code inspection.

1. **blocker — CSS importers bypass the budget entirely.** [engine.rs:346](/tmp/rv-e23-5/tamber/src/import/engine.rs:346), [tailwind.rs:707](/tmp/rv-e23-5/tamber/src/import/tailwind.rs:707).

   Neither importer enters `Work`. Thirty nested `&&` selectors under `:root` produce one selector approximately **5 GiB** long. The 1,024-selector limit never fires because the list contains one entry. Tailwind’s `written_out` likewise recursively substitutes repeated `var()` references without charging output; its depth limit permits enormous branching. CSS colour alias resolution also lacks a depth bound.

   **Fix:** establish `Work` for both importers, charge calculated output lengths before substitution or concatenation, and bound recursive parser/alias traversal.

2. **blocker — Generated token paths are not charged.** [export.rs:529](/tmp/rv-e23-5/tamber/src/export.rs:529), [dtcg.rs:354](/tmp/rv-e23-5/tamber/src/import/dtcg.rs:354).

   A 512 KiB group name containing 8,192 tiny token definitions fits below the request limit but produces **4 GiB of dotted token names**. Export charges the original tree, which contains that prefix once; `flatten` duplicates it for every leaf. Ordinary DTCG’s `path.join(".")` has the same gap. Export reaches this before deciding that the names are unmapped.

   **Fix:** charge every generated path before constructing it, including intermediate prefixes. Account for copied definition filenames and types too, or retain shared references.

3. **blocker — Composite aliases still multiply uncharged object keys.** [dtcg/kinds.rs:59](/tmp/rv-e23-5/tamber/src/import/dtcg/kinds.rs:59).

   Use fourteen levels of doubled aliases ending in an object with one 256 KiB key and a numeric value. `inner` clones the key 16,384 times—**4 GiB**—while charging only traversal and scalar values. The input is roughly 256 KiB. Kind validation rejects the expanded object only afterward.

   **Fix:** charge keys and container allocation before collecting expanded objects/arrays. Prefer validating the required kind’s shape before recursively materializing it.

4. **blocker — Resolver sibling overrides are copied without charging.** [dtcg.rs:677](/tmp/rv-e23-5/tamber/src/import/dtcg.rs:677), [dtcg.rs:703](/tmp/rv-e23-5/tamber/src/import/dtcg.rs:703).

   Point 8,192 sources at an object containing `$ref` to `{"$value":0}` and a 512 KiB `$type` sibling. Only the tiny terminal object is charged. The sibling is copied during dereferencing, then retained in each `Def.ty`: approximately **4 GiB**, from a request below 1 MiB.

   **Fix:** charge sibling keys and values before inserting them, and charge retained definition metadata. Also move/remove the `a.clone()` in [dtcg.rs:277](/tmp/rv-e23-5/tamber/src/import/dtcg.rs:277): its charge currently occurs afterward, at line 279.

5. **blocker — Type resolution remains unbounded quadratic work.** [dtcg.rs:930](/tmp/rv-e23-5/tamber/src/import/dtcg.rs:930), [caller:1234](/tmp/rv-e23-5/tamber/src/import/dtcg.rs:1234).

   `type_of` has no budget charge, memoization, or chain limit. A chain of 20,000 untyped aliases ending in a typed boolean fits below 1 MiB and requires approximately **200 million alias hops per tuple**. With 64 contexts, that becomes approximately **12.8 billion**. Boolean reporting avoids `raw`, so its 256-name guard provides no protection.

   **Fix:** memoize type resolution per tuple and charge each unresolved edge; apply a consistent chain bound. Treat budget exhaustion as fatal to the import rather than continuing through the remaining planning passes.

6. **blocker — Re-import validation remains uncharged and potentially cubic.** [export.rs:1383](/tmp/rv-e23-5/tamber/src/export.rs:1383), [edit.rs:447](/tmp/rv-e23-5/tamber/src/edit.rs:447).

   Each accepted token reapplies the entire growing operation prefix. For 3,000 changed tokens with one operation each, that is **4,501,500 edit steps**, each reparsing the design at [edit.rs:193](/tmp/rv-e23-5/tamber/src/edit.rs:193). A compact incoming document can easily fit below 1 MiB.

   The repair loop permits up to four `apply_all` calls per colour candidate, followed by these prefix validations. Dials and marks add validations per distinct dial. None spends budget. Moreover, [export.rs:770](/tmp/rv-e23-5/tamber/src/export.rs:770) still scans a context’s token vector for every lookup; name deduplication alone did not remove quadratic diffing.

   **Fix:** index context winners, plan edits against one mutable representation, and validate batches with a bounded failure-isolation strategy. Charge validation work before invoking it.

7. **should-fix — `LIMIT` rejects a plausible 3,000-token × 64-context design.** [budget.rs:15](/tmp/rv-e23-5/tamber/src/budget.rs:15), [export.rs:764](/tmp/rv-e23-5/tamber/src/export.rs:764).

   By the implemented accounting, 3,000 five-character token names following `accent`, with normal colour objects and `$extensions.exact.source`, cost **537,008 units per context tree**. Incoming plus baseline across 64 contexts cost **68,737,024**, exceeding **67,108,864** before other charges. Shared-set references can keep the incoming document below 1 MiB.

   **Fix:** avoid duplicating identical trees across contexts, distinguish retained bytes from traversal work, and calibrate the limits with this legitimate fixture.

8. **should-fix — Exact-name precedence is fixed, but role-alias lookup remains inconsistent.** [export_dials.rs:289](/tmp/rv-e23-5/tamber/src/export_dials.rs:289).

   If a held operation names `-exact-background` and the declaration changes to the equivalent bare `background`, recomputation finds no token for its pin annotation. `apply_all` nevertheless resolves that operation through `edit::token_index` and applies it.

   **Fix:** use `edit::token_index` for marks, as round 4 requested, rather than exact-match followed by unrestricted case folding.

9. **should-fix — The family fix rejects valid quoted Tokens Studio stacks.** [dtcg/kinds.rs:198](/tmp/rv-e23-5/tamber/src/import/dtcg/kinds.rs:198).

   `{"type":"fontFamilies","value":"\"A  B\", serif"}` now fails because the whole stack contains quotation marks. Those quotes delimit a valid family name; they are not characters inside it. The existing `fontFamilies` branch deliberately accepts stack syntax.

   **Fix:** distinguish DTCG family-name data from Tokens Studio stack syntax. Parse the latter’s members before rejecting characters inside names.
