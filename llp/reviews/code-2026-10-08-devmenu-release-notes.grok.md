LAND WITH CHANGES

1. **MATERIAL** — `release-notes.md` is stamped lossily, and the whole file is read. `buildinfo.mjs:47` does `readFileSync(notesFile, 'utf8').trim().slice(0, NOTES_MAX)`. Invalid UTF-8 is replaced and still baked: bytes `68 e9 6c 6c 6f` become `h\uFFFDllo` under Bun 1.4.2. `slice(0, 8000)` counts UTF-16 code units, so 7999 `a`s plus an emoji leaves a trailing `U+D83D`; `plutil` keeps the plist and stores `U+FFFD`. A large file is loaded in full on every `buildInfo` call (a macOS `--bundle` calls it three times, `build.mjs:1259`, `1285`, `1288`). Empty and whitespace-only files are omitted (`ExactReleaseNotes` absent). `<`, `&`, newlines, and C0 controls round-trip through `plist()` (`build.mjs:258`) and `plutil`. **Fix:** read a bounded prefix, fail the build on invalid UTF-8 (name the file), and cut on Unicode scalars. Cover empty, invalid UTF-8, and the cap in `buildinfo.test.mjs` (today only the trimmed happy path, `buildinfo.test.mjs:39-42`).

2. **MINOR** — The Xcode line is the IDE version only. `xcode()` runs `xcodebuild -version` and joins the lines (`buildinfo.mjs:28-30`), which prints `Xcode 27.0 Build version 27A266a`. The SDK the link used is already known (`sdkName` at `build.mjs:693`, `--show-sdk-version` at `build.mjs:1163`; an `--archive` also writes `DTSDKName` at `build.mjs:464`) and `BuildInfo.lines` never shows it (`BuildInfo.swift:21`). A `designRequiresCompatibility` build (`COMPATIBLE_SDK`, `build.mjs:558`) still displays the host Xcode. A missing `xcodebuild` omits the key (`status` is null on ENOENT). **Fix:** pass that sdk name and version into `buildInfo` and put them on the same line.
