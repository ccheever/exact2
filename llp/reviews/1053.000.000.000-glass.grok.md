## §5

1. Keep a fixed duration. Do not wait for a `::view-transition-group` selector. Contract has no pseudo-element selectors, and LLP 1013 is where that syntax belongs. The duration has to be a closed-form function of the session clock that `Engine::settle_time` reports, with the frame at 175 ms written down as a number. "350 ms, dampingRatio 1, sampled as a cubic" is three different timings, and §2 never measured 350 ms.

2. A glass that enters or leaves alone stays an immediate swap, as today. A UIKit materialize is off the agent's clock, and §2 already shows macOS will not fade a glass view.

3. Leave `view-transition-name` to LLP 1013. This effect is a glass-container union on Apple. LLP 1013's effect is a snapshot crossfade of the whole element, on a flagged action, with the browser as the oracle. Shipping the row here locks the wire to the wrong meaning.

## Findings

**1. Blocker. Swift cannot read the gap the plan assigns it, and the gap it describes is not the one layout uses.**

D1 says `GlassGroup.swift`'s `glassGroupSpacing` turns `-1` into the element's gap: `column-gap` on a flex row, `row-gap` on a flex column, the larger of the two on a grid or a block, with a percentage resolved against the content box. §1 cites `Prepared.swift:58` as the channel those gaps arrive on.

`row_gap` and `column_gap` are kernel style rows, codec `f32`, default 0 (`kernel/tables/schema.json:1927-1938`). The Apple presenter drops them, and drops `flex_direction`, before Swift ever sees a style dictionary (`host/apple/src/style.rs:45-70`). `Prepared.swift:50-64` is the set of layout keys that do not stop a leaf from being flat. A gap-only change still produces a style op, and `applyStyle` does call `syncGlassGroup` (`host/apple/Sources/ExactKit/IOS/NodeViewIOS.swift:1065-1074`), but the dictionary it applies has no gap and no direction in it. `display` does cross, so the host can see flex versus grid versus block and still cannot see the axis.

A percentage never becomes a gap. `StyleValue::f32` accepts a finite number (`kernel/src/style.rs:484-489`). `rem` and `em` are already pixels by the time the row is stored (`kernel/tables/schema.json:1716`). Block layout then places children with zero inter-item gap (`vendor/taffy/src/compute/block.rs:633-637`). Using the larger gap on a grid breaks the spacing-equals-gap pattern the parent RFC measured: neighbors on the tighter axis sit closer than the spacing and merge at rest (`llp/1053.000.000-glass-groups.rfc.md:50`, `:137`).

Change D1. Resolve `auto` in the Apple Rust host, which still has the kernel style, and send points. Do it on both paths that can change it: `props_for` (`host/apple/src/host.rs:1408-1416`) when the prop is set, and `style_json_presented` (`host/apple/src/style.rs:505`) when the gap changes, because a gap change does not resend props. The axis is `column_gap` for `row` and `row-reverse`, `row_gap` for `column` and `column-reverse` (`kernel/src/style.rs:1060-1066`). On a grid, use the smaller of the two so neither axis merges at rest. On a block, use 0. Delete the percentage sentence. `layout` reports the applied points plus `auto: true` (`GlassGroup.swift:158-172` is where that object is built).

**2. Blocker. `-1` is not a free sentinel, and the web attribute the plan names is a second name.**

`glassGroup` is prop 216, kind `float` (`kernel/tables/schema.json:1239-1242`). A float attribute must type as a number (`contract/lower/src/values.rs:538-544`). The string `"auto"` is refused there, before the range check. The range check (`values.rs:497-508`) only sees a numeric literal. A bound value is not a literal. The running host clamps every finite value into 0…10,000 (`GlassGroup.swift:93-95`), which is the parent RFC's rule for bound values (`llp/1053.000.000-glass-groups.rfc.md:51`). Exactly `-1` today becomes a real group of spacing 0. The plan's sentence that negatives are refused is true only for literals.

The web writes the attribute `glassGroup` (`host/web/src/element.rs:728`) and prints the float with `css::num` (`element.rs:683`, `host/web/src/css.rs:692-705`), so `-1` becomes the text `-1`. The JS target discovers that DOM name by projecting the same writer (`host/web-js/src/style.rs:422-447`, `host/web-js/src/emit.rs:1087-1100`). `data-glass-group` is a different attribute.

Change D1. In `check_prop_value`, accept the string literal `"auto"` and compile it as the float `-1`, including that literal inside a choice. The expression compiler has to emit a float there: a ternary of a string and a number is `Ty::Unknown` (`contract/lower/src/expr.rs:413-423`), which already passes the type check, and the runner still stores a float. State that a bound numeric `-1` is `auto`, and that every other bound value still clamps. In `element.rs`, when the float is `-1`, write `glassGroup="auto"`. Keep the attribute name.

**3. Blocker. `view-transition-name` is the wrong declaration for this effect.**

The house rule is that a property that can follow CSS does follow CSS, and the web is the parity oracle (`CLAUDE.md:9-14`, `rules/RULES.md:51-53`). LLP 1002 D1/D2 says the same for motion: one CSS representation, the browser executes it, every other host matches the browser (`llp/1002-motion-v1.rfc.md:66-80`).

LLP 1013, still Draft, already owns this property. Its row is `view_transition_name`, codec `u16`, `0` meaning `none`, the Contract attribute `viewTransitionName`, the web value `view-transition-name:v<n>`, and the effect is a snapshot ghost on an action flagged `transition`, timed by the UA stylesheet (`llp/1013-view-transitions.rfc.md:38-40`, `:64-70`, `:82-103`). This plan's effect is an unflagged Apple glass union, 350 ms, content excluded, web inert. Those cannot be one row. Question 3 has the dependency backwards: the first definition becomes the wire.

The schema cannot express the row as written. Style fields are Rust identifiers (`kernel/build.rs:910`); `view-transition-name` does not compile. The next dense bit is 154 (`kernel/tables/schema.json:2742-2746`, `kernel/build.rs:630`). There is no custom-ident codec; an unknown codec panics the generator (`kernel/build/codec.rs:21-63`). A new text codec is a new `RowValue` arm, and `host/apple/src/style.rs:114-253` plus `host/web/src/css.rs:464-544` are exhaustive matches. A codec outside the JS allowlist fails the JS build (`host/web-js/src/style.rs:585-613`). A `u16` would be printed as `Npx` by the default number arm (`host/web/src/css.rs:534-537`).

Change D2. Do not add the style row. Pair with a host-policy string prop beside `glassGroup`, the same kind of name the parent RFC used because CSS has nothing that does this (`llp/1053.000.000-glass-groups.rfc.md:50`). The web writes the attribute and draws nothing. LLP 1013 keeps the CSS property for the effect CSS actually has.

**4. Blocker. Both morph triggers are gone by the time the plan looks, and the body is the content.**

D3 pairs at batch end and morphs when a glass body leaves by `exit-animation` or destroy, and another enters by create or by stopping being hidden.

Destroy removes the view inside the op, then `reconcile` runs (`host/apple/Sources/ExactKit/IOS/PresenterIOS.swift:748-756`, then `:811`). A `when`/`match` swap is a destroy plus a create (`llp/1013-view-transitions.rfc.md:38-40`). At batch end the leaving view is already out of the window unless something retained it. An exit keeps the view (`host/apple/Sources/ExactKit/IOS/PresenceIOS.swift:17-37`), and `endExit` removes it when the engine's exit ends, on the engine's timing, which is unrelated to 350 ms.

The usual exit fades opacity. Under a group, opacity is sampled and applied as `alpha` (`host/apple/src/svg_lower.rs:326-328`, `:429-456`; `PresenterIOS.swift:772-779`). `glassPath` records `alpha < 1` as `"opacity"` (`GlassGroup.swift:120-129`), and D4 isolates that glass so it merges with nothing (`llp/1053.000.000-glass-groups.rfc.md:62-64`). D3 then says an isolated body is not morphed. A fading exit is both the trigger and the cancellation.

The body is also the content. Children of a glass material sit in the effect's content view (`NodeViewIOS.swift:206`). A native glass button's body is the `UIButton` or `NSButton` that draws the title and symbol (`host/apple/Sources/ExactKit/IOS/NativeButtonsIOS.swift:45-49`, `host/apple/Sources/ExactKit/Mac/NativeButtonsMac.swift:48-52`). The fixture is that button swap. Animating the body's frame moves the label with it. iOS 26 corners are `cornerConfiguration`, set from the uniform radius (`NodeViewIOS.swift:931-936`); macOS sets `NSGlassEffectView.cornerRadius` (`NodeViewMac.swift:590-594`). Both views autoresize to the node bounds (`GlassGroup.swift:287-288`, `NodeViewMac.swift:573`), so a one-shot frame offset is overwritten on the next layout.

The clock will not play this. `svg.seek` runs at the start of `apply` (`PresenterIOS.swift:625`) and, under the agent, holds a Core Animation timeOffset (`host/apple/Sources/ExactKit/SvgScene.swift:76-78`, `:402-405`). The glass container unions model frames; §2 says AppKit's animator jumps. The display link runs only while `batch.motion` is set (`host/apple/Sources/ExactKit/Session.swift:897`) and only while `session.clock` is nil (`Session.swift:1363-1368`). The agent's `clock settle` advances to `engine.settle_time()` (`host/apple/src/host.rs:816-824`, `host/apple/Sources/ExactKit/Agent.swift:282-285`, `:364-367`). A host-owned 350 ms morph is invisible to that, and on a real device the link never starts for it. `screenshot … over 400 every 50` moves that same clock (`llp/1012.001.000-trustworthy-agent-drives.rfc.md:96-104`), so the film shows whatever one seek-sample writes, and only if the sample runs after the clock is stored (`Agent.swift:439-448` applies the advance batch before `session.clock` is updated, then applies the tick).

Change D3, or cut it (below). If it stays: capture the leaving body's frame while the exit or destroy op still has the view, and retain that body until the morph's own end even if `endExit` runs. One unambiguous pair per group per commit; anything else is today's swap. Say what "stops being hidden" is (`display: none` is a style, `NodeViewIOS.swift:797-803`; `placementHidden` sets `isHidden`, `NodeViewIOS.swift:201-208`). Reparenting a body out of a fading node is an exception to D4 and has to be written as one, with the children and the button title either traveling with the glass or given a specified split. Sample a closed form of `(clock - start)` from `apply` after the clock is stored, write model frames with autoresizing off, and set `frames.motion` for the wall-clock case. Register the end with the engine so `clock settle` lands on it. Name the position at 175 ms. On iOS 26, sample `cornerConfiguration`.

**5. Should-fix. The duplicate-name check claims a CSS rule Contract cannot decide.**

D2 says Contract refuses two elements that can be mounted at once with the same literal name, because CSS aborts a transition on duplicates. CSS applies that rule when a transition starts, to the elements that are actually participating. Contract has no "mounted at once" pass. `when`/`match` arms are not mounted together (`llp/1013-view-transitions.rfc.md:38-40`), so a tree walk refuses a legal pair and still misses a bound name and two `each` rows. `tags.rs` is 1,433 lines and `NodeViewMac.swift` is 1,468, against the 1,500-line cap (`rules/RULES.md:16`). A new analysis does not fit in `tags.rs`, and the morph does not fit in the node views.

Change D2 and D5. At the commit, inside one group, one leaving body and one entering body with the same key morph. Two live bodies with the key, or two pairs, do not. Delete the Contract test for duplicate names.

The literal range check is `contract/lower/src/values.rs:497-508`. Line 576 is `check_glass_group`, the D6 refusal. Android is deferred (`rules/DEFERRED.md:229`). D4's matrix is the web (attribute written), Linux (ignored), and Apple before 26 or with `LinkedDesign.liquidGlass` false (`host/apple/Sources/ExactKit/ControlKinds.swift:145-164`, checked for buttons at `NativeButtonsIOS.swift:91-94`). ## What to cut

Cut the morph from this RFC and land auto spacing alone, once D1 reads the kernel's points as in finding 1 and the sentinel and attribute are as in finding 2. The geometry idea in §2 is sound: the container unions frames the host writes, and a platform appear/disappear animation does not morph. The morph still needs its own pass over lifetime, isolation, content, and `settle_time` before anyone writes it.

If the morph stays in this document, cut `view-transition-name`, the compile-time duplicate check, percentage resolution, the claim that titles and children stay put, Android, and the unspecified spring. Keep the fixed duration, the refusal of a lone materialize, and the frame-by-frame union.
