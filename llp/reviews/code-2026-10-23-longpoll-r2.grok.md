## Should-fix

1. **`exact:reply` is special on every stream, and a coalesced long-poll reply never counts.** A server on an ordinary event stream can send `event: exact:reply`. The runner maps that message when the request is not a long poll (`runner/src/runner/commit.rs:1088`). `stream_tests.rs:313-316` calls this an ordinary message, and the assert passes if the event is mapped, because it only requires an error or an empty `heldReplies`. Web JS drops the name for every stream before the mapper (`host/web-js/ts-stream.js:147`, `host/web-js/rt.js:419`). On the Rust-on-JS path that short-circuit also skips `done`, so a first event of that name leaves `t.waiting` set. `readEvents` delivers only the last event of a chunk (`host/web/http-body.js:67`); if that event is `exact:reply`, the chunk is gone, coalesced count included. The native coalescer applies to every ticket (`host/apple/src/executor_stream.rs:204-215`): a queued `exact:reply` does not replace an event, and an event replaces a queued `exact:reply` without adding to `coalesced`. Wasm forwards the name (`host/web/glue.js:750`) and the runner maps it for a stream that is not a long poll.

   A held count cannot be forged. `long_poll_replied` and `count_held_reply` run only for a long poll (`commit.rs:1088`, `1098`, `1139`). Web `controller.replied` is called only from `readLongPoll`. A long-poll server cannot choose the event name: the host sets `''` or `exact:reply`, and a cursor with a control character is refused before it is placed in the wasm `id` (`host/apple/src/executor_longpoll.rs:297`, `host/web/http-body.js:184`).

   The same coalescer drops a long poll's own count. The increment happens when the marker is fulfilled (`commit.rs:1088`). A marker that finds an event already queued is discarded (`executor_stream.rs:208-210`); an event that finds a marker queued replaces it (`211-214`) and the marker is never fulfilled. Events re-ask with no wait (`executor_longpoll.rs:125`), so an event and the following immediate 204 share that window whenever the runner has not drained. `clock held` succeeds only when `heldReplies` rises (`scripts/agent-held.mjs:36`). Web and wasm count one reply each, at `replied()` or fulfill time. Gate the drop and the coalescer on the request being a long poll, and count a long-poll reply when the host observes it.

2. **A web long poll that ends on a grant denial does not raise `heldReplies`.** `host/web/http-body.js:191` (the next URL is outside the grants) and `:200` (the final response URL is; the body is cancelled) return without `replied()`. `rt.js:410` then only calls `longPollEnded`. Native counts every terminal outcome of a still-pending long poll (`commit.rs:1098`); wasm fulfills that outcome into the same path. `clock held` treats leaving the held list as no reply (`scripts/agent-held.mjs:8-9`, `36`), so a poll that is already held times out on web after an off-grant redirect and completes on native. Abort and let-go correctly skip the count (`http-body.js:190`, `225`, `234`). Call `replied()` on those two returns.

3. **A JSON array is a cursor on the web and the end of the stream natively.** `cursorOf` (`host/web/http-body.js:183`) accepts any object, and `typeof [] === 'object'`. `Object.hasOwn` is true for `"0"` and `"length"`, so `from: "0"` or `"length"` on a JSON array keeps the poll going. Native `Value::get` with a string key is `None` unless the value is an object (`executor_longpoll.rs:291`; serde_json `Index for str`), so the same body ends as `Response`. Require a plain object before `hasOwn`.

## Nits

- **IMF-fixdate.** Web requires one space and a three-letter weekday (`http-body.js:153`). Native splits on any whitespace and ignores the weekday token (`executor_longpoll.rs:421-423`), and it does not range-check day or hour. A year that fits in `i64` can overflow that day math; in debug the panic is caught and the poll ends as Aborted (`executor_longpoll.rs:79`, `171`). Web's four-digit year cannot reach that. Extra spaces wait on one host and fall through to backoff on the other.
- **A non-boolean `same_cursor_event` becomes false** (`js/src/wire.rs:64-67`, `data/src/envelope.rs:242`). The seam rejects a byte above 1 (`logic/abi/src/lib.rs:514`). Web requires a boolean (`http-body.js:165`). A worker envelope that sends the string `"event"` heartbeats, and a same-cursor reply is then dropped. The prelude and the wasm batch always write a boolean.
- **Float cursors in `[9e15, 2^53)`.** `Number::as_i64` is `None` for a float, and the fallback requires `abs < 9e15` (`executor_longpoll.rs:302-305`), so a decimal or exponent in that band is `Refused` natively and accepted on the web (`http-body.js:185`, `Number.isSafeInteger`). An integer lexeme in that band is accepted on both. `1e3` and `1.0` agree (`"1000"`, `"1"`). `2^53` is refused on both.

## Round 1

Fixed. A heartbeat and a busy status (408, 429, 502, 503, 504) call `replied` / `noEvent` before the wait (`executor_longpoll.rs:128-147`, `http-body.js:203-209`); `waited()` is false once `replied` is set (`runner/src/runner.rs:359-361`); wasm resolves `opened` from `controller.replied` (`glue.js:752`); web JS clears `t.waiting` (`rt.js:418`). `pause` sees an abort that has already fired (`http-body.js:175`). `Retry-After: 0` and a past date take the 1s floor (`executor_longpoll.rs:146`, `http-body.js:209`). Status and `content-type` are judged before the body is read, and 204, 304, busy, and `text/event-stream` cancel it, on both hosts. Cursors are whole numbers inside `2^53`, at most 4096 bytes, with no control characters. `long_poll` without `stream` is refused (`runner/src/request.rs:455-458`, seam encode `logic/abi/src/lib.rs:356`, tag-10 decode `:522`, plain executor `executor_core.rs:1327`); web enters the poll only for `stream && longPoll` (`http-body.js:383`). `from` allows one dot (`request.rs:213-214`, prelude, `ts-stream`, `longPollRefusal`). `sameReq` includes `longPoll` (`rt.js:398`). `ts-fetch` rejects `exactLongPoll` without `exactStream` before the mutation branch (`ts-fetch.js:19-20`). A bad same-byte is not a boolean, and `longPollRefusal` runs before a socket opens (`rust-data.js:103`). Names are code points. Whitespace is ASCII on both hosts. A BOM is stripped natively (`executor_longpoll.rs:263`) and by `TextDecoder`. `millis_up` rounds up (`executor_longpoll.rs:178`). `Retry-After` is IMF-fixdate only; the parser gap above is what is left of that nit.

## What holds

Grants run on every re-ask. Native `admit_hop` runs before every open and every redirect hop (`vendor/ibex/crates/ibex2/src/stdlib/fetch.rs:403-405`). Web checks the URL it is about to ask and the final `response.url` (`http-body.js:191`, `200`). The next ask is the original URL plus the cursor, percent-encoded, with that one parameter replaced (`executor_longpoll.rs:325-347`, `http-body.js:228`). A cursor cannot change origin or path.

One request is in flight. The body stops at the stream ceiling. The cursor is at most 4096 bytes. Backoff and `Retry-After` are capped (30s ±20%, 60s). Events, and `sameCursor: "event"`, re-ask immediately, as specified. A network error or a timeout is not a reply (`executor_longpoll.rs:148-156`, `http-body.js:236-239`): the poll stays in the clock's wait through the backoff, `retrying` shows on `state.streams`, and the 1s floor covers heartbeats and busy replies, `Retry-After: 0` included. Abort is checked at the loop top, in `pause`, on a body error, and before an event is delivered; native `message()` returning false stops a forgotten ticket. Let-go does not count.

`Request::long_poll_refusal` (stream, `http:`/`https:`, GET, no body, names of 1–256 code points, `from` with at most one `.`) is checked on the native stream and plain paths, both seam directions, the worker envelope, `js/src/wire.rs`, the wasm batch, and the web host before a socket opens. Linux uses this executor through `executor_core`. On a long poll the marker is not mapped: the runner returns before the mapper (`commit.rs:1088-1090`), and web drops it before `deliver`.
