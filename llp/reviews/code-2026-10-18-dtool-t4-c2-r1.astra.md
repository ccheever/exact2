1. **[P1] Held rows can edit the wrong style.** [tamber-inspect.mjs:254](/tmp/rv-dt-t4s2/scripts/tamber-inspect.mjs:254) joins held rows against the **selected node’s** bindings. An active hold can resolve to an ancestor instead. Select a child styled `Inner` inside a pressable `Outer`, both declaring active opacity: the host reports Outer’s held value, but the join offers `set-state Inner active opacity`. I reproduced that incorrect target in memory. Resolve the actual held node, or refuse editing when its provenance is unknown.

2. **[P2] An open state draft survives a stale selection and remains writable.** [app.contract:824](/tmp/rv-dt-t4s2/apps/design-tool/app.contract:824) stores no selection identity or source revision and clears the existing draft guards. After another client changes the row and the app rebuilds, the inspector disables its row buttons, but the open draft re-proposes against the latest digests and Apply remains available. A mocked client run confirmed a transaction using the new digest with the old draft. Bind the draft to its originating selection and invalidate it when that selection becomes stale.

3. **[P2] Compiler-renamed styles produce invalid `set-state` addresses.** [tamber-inspect.mjs:192](/tmp/rv-dt-t4s2/scripts/tamber-inspect.mjs:192) copies the map’s class name directly. If two files declare `style Card`, compilation can rename the second to `Card__post`; the source file still declares `Card`. The offered `{style:"Card__post", file:"post.contract"}` therefore fails `set-state`’s source lookup. Recover the authored declaration name from `at`, rather than treating the compiled name as the write address.

4. **[P2] Hover and focus-visible state rows receive no editor.** [tamber-inspect.mjs:191](/tmp/rv-dt-t4s2/scripts/tamber-inspect.mjs:191) requires binding `state` and `at`, but this compiler emits those only for lowered active rows. Hover/focus looks are compiled separately from the mapped node bindings. Holding `style Card :hover opacity=0.5` consequently produces a held opacity row without an editable state rung. The join needs provenance for those looks too.

5. **[P2] Opening the state editor substitutes the rendered value for the authored value.** [app.contract:1241](/tmp/rv-dt-t4s2/apps/design-tool/app.contract:1241) passes `r.value`. For `background-color="accent.pressed"`, the field starts with the resolved colour; opening it already proposes replacing the token reference with an unconditional literal. Applying without typing can therefore change other modes and disconnect future token updates. Preserve the authored token/expression when initializing the field. Current web held reports can also supply `var(...)` text that is not valid Contract input.

6. **[P2] Held token-valued rows lose their token alternative.** [tamber-inspect.mjs:256](/tmp/rv-dt-t4s2/scripts/tamber-inspect.mjs:256) assigns `editable: state` directly, bypassing `editable()`. Even when a held row carries token metadata, it gets neither the advertised token/state chain nor a token link. The inspector reads its token action from `editable`, so that action disappears. The new held-row test covers only literal opacity and misses this.

7. **[P2] Package styles are advertised as writable.** [tamber-inspect.mjs:194](/tmp/rv-dt-t4s2/scripts/tamber-inspect.mjs:194) checks neither ownership nor membership in the server’s writable files. A package under `node_modules` receives an edit action; an external linked package can additionally receive an absolute `file`. `set-state` rejects both because package sources are read-only. Offer a refusal reason instead.
