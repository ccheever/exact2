1. should-fix. An iOS list row that was `glassGroup="auto"` keeps `glassGroupAuto` after the view is recycled onto a numeric group, so `layout` still reports `auto: true`.

Evidence. `NodePoolIOS.swift:448` clears only `props["glassGroup"]` and calls `syncGlassGroup()`. It does not clear `glassGroupAuto`. Reuse then does `applyStyle` followed by `applyProps(set:clear:[])` (`PresenterIOS.swift:703-704`). `applyStyle` replaces the style dictionary (`NodeViewIOS.swift:1068`), so `glass_group_spacing` does not survive, and `glassGroupSpacing` (`GlassGroup.swift:96-100`) falls through to the numeric prop. `applyProps` with an empty clear list leaves `glassGroupAuto` at `"true"`. `glassAgentFields` (`GlassGroup.swift:165-167`) adds `auto: true` whenever that flag is set. The normal update path does not have this hole: `paragraph.rs:280-298` clears props that disappeared, and `glass_auto_props` (`style.rs:610-614`) plus the style prepend (`style.rs:576-582`) omit both the flag and the key once the kernel prop is no longer `-1`. Mac has no equivalent recycle.

Failing scenario. An iOS list shows a row with `glassGroup="auto"` and `gap=8`, then recycles that view onto a row with `glassGroup=12`. After the create ops, the container spacing is 12, and `native.glassGroup` is `{"spacing": 12, "auto": true, ...}`.

Fix. In `recycle()`, set `props["glassGroupAuto"] = nil` in the same branch that clears `glassGroup`, before `syncGlassGroup()`.
