# Review: LLP 1080.002 (Accessibility tree)

**Reviewer:** Astra (codex gpt-6-astra, max), requested by Charlie, 2026-10-03

**Verdict:** NOT READY — the proposed joins and proofs can produce incorrect or vacuously passing observations.

1. **High — `data-exact-id` already has a meaning that this design would overwrite.**

   D4 proposes storing numeric view IDs there. The JS compiler already emits authored identifiers into that attribute, and the runtime selects them when resolving dynamic `url(#…)` references ([emit.rs:956](/Users/admin/.config/tuft/sessions/1791014443.232549/worktrees/exact2/host/web-js/src/emit.rs:956), [rt.js:732](/Users/admin/.config/tuft/sessions/1791014443.232549/worktrees/exact2/host/web-js/rt.js:732)). Inspection would therefore change SVG rendering. Q2’s broader claim that CSS never selects `data-exact-*` is also false ([style.rs:400](/Users/admin/.config/tuft/sessions/1791014443.232549/worktrees/exact2/host/web-js/src/style.rs:400)).

   **Edit:** Choose a distinct inspection attribute. Specify how existing and subsequently created elements receive it; consider stamping the current elements in one batched evaluation immediately before inspection, avoiding a new creation hook.

2. **High — Exact view IDs cannot identify corresponding nodes across hosts.**

   D5 groups and compares replies by numeric `id`, including the wasm/JS comparison in stage 1. JS IDs are allocated lazily when an agent or capability first requests them ([rt.js:607](/Users/admin/.config/tuft/sessions/1791014443.232549/worktrees/exact2/host/web-js/rt.js:607)); they are not the Rust runner’s IDs. Existing conformance deliberately compares structural fields and `testId`, rather than numeric identity ([conform.mjs:103](/Users/admin/.config/tuft/sessions/1791014443.232549/worktrees/exact2/host/web-js/conform.mjs:103)).

   The proposed text equivalence is also based on incorrect implementation facts: iOS exposes an ordinary paragraph as one element; an interactive paragraph exposes its complete text **plus** interactive runs, not one element per run ([TextInteraction.swift:58](/Users/admin/.config/tuft/sessions/1791014443.232549/worktrees/exact2/host/apple/Sources/ExactKit/TextInteraction.swift:58), [TextInteraction.swift:70](/Users/admin/.config/tuft/sessions/1791014443.232549/worktrees/exact2/host/apple/Sources/ExactKit/TextInteraction.swift:70)). Joining all names with spaces can duplicate words and lose link semantics.

   **Edit:** Define cross-host correspondence independently of runtime IDs, including duplicate identifiers and unmatched nodes. The cheaper first proof compares explicitly named fixture controls; defer general text grouping and order parity until their equivalence rules are demonstrated.

3. **High — The native walks cannot support the claimed exposure and reading-order guarantees.**

   D2’s iOS traversal manufactures exposure and order, while only `order` is labelled reproduced. Sorting sibling views and recursively descending them does not reproduce VoiceOver’s ordering across ungrouped containers: UIKit explicitly documents horizontal-row navigation and `shouldGroupAccessibilityChildren` changing that behavior ([UIAccessibility.h:170](/Applications/Xcode-27.0.0.app/Contents/Developer/Platforms/iPhoneOS.platform/Developer/SDKs/iPhoneOS.sdk/System/Library/Frameworks/UIKit.framework/Headers/UIAccessibility.h:170)). The alpha threshold is asserted without an accessibility-specific source. Pruning presumed modal exclusions also prevents the resulting tree from independently proving those exclusions.

   AppKit provides a separate [navigation-order accessor](https://developer.apple.com/documentation/appkit/nsaccessibility-c.protocol/accessibilitychildreninnavigationorder?changes=__6&language=objc); ordinary children order is insufficient. Stage 3’s XCTest snapshot is not automatically a VoiceOver oracle either: UIKit expressly allows a different automation hierarchy ([UIAccessibilityContainer.h:60](/Applications/Xcode-27.0.0.app/Contents/Developer/Platforms/iPhoneOS.platform/Developer/SDKs/iPhoneOS.sdk/System/Library/Frameworks/UIKit.framework/Headers/UIAccessibilityContainer.h:60)).

   **Edit:** Narrow the first native reply to observed accessibility properties with explicit coverage limits. Remove unsupported exposure/order guarantees, use AppKit’s navigation accessor, and require independent evidence before reconstructed iOS exclusions or order become parity assertions.

4. **High — The web collector would rewrite its own oracle.**

   D2 folds descendants of selected roles into their parent’s name even though Chrome has already computed both names and exposure. ARIA’s presentational-children rule has exceptions, including focusable descendants; it does not authorize deleting every descendant or recomputing the parent’s accessible name. [WAI-ARIA §7](https://www.w3.org/TR/wai-aria-1.2/#tree_exclusion)

   Order also needs an explicit algorithm: Chromium’s returned array is assembled using a breadth-first queue, not emitted as the proposed depth-first transcript. [inspector_accessibility_agent.cc:94](https://raw.githubusercontent.com/chromium/chromium/main/third_party/blink/renderer/modules/accessibility/inspector_accessibility_agent.cc)

   **Edit:** Preserve Chrome’s computed names and unignored semantic nodes. Build traversal through `childIds`, explicitly promote children through ignored ancestors, and keep any display-only text folding separate from the observations and findings. Add a focusable-descendant fixture.

5. **High — Nearest-ancestor ownership gives the wrong IDs for the central Apple proof.**

   The swipe projection’s accessible cell **contains** the authored button; it is not inside that button. The cell explicitly stores `control = body` and copies its identifier ([SwipeActionsIOS.swift:263](/Users/admin/.config/tuft/sessions/1791014443.232549/worktrees/exact2/host/apple/Sources/ExactKit/IOS/SwipeActionsIOS.swift:263)). D4 would join it to the enclosing row owner, contradicting stage 2’s promised button ID. Inline accessibility elements likewise already carry the run’s own ID, which an ancestor-only join would replace with the paragraph’s ID ([TextInteraction.swift:116](/Users/admin/.config/tuft/sessions/1791014443.232549/worktrees/exact2/host/apple/Sources/ExactKit/TextInteraction.swift:116)).

   Moreover, swipe rows remain projected while VoiceOver or Switch Control runs; an ordinary idle agent read does not necessarily exercise that hierarchy ([SwipeActionsIOS.swift:7](/Users/admin/.config/tuft/sessions/1791014443.232549/worktrees/exact2/host/apple/Sources/ExactKit/IOS/SwipeActionsIOS.swift:7)).

   **Edit:** Join through existing semantic ownership—cell control, inline run, segment owner—before falling back to ancestry. Specify the assistive-technology state required by the swipe regression proof, and verify both projected and ordinary states.

6. **High — Apple traversal roots violate session scope and can miss presented content.**

   A session owns an `ExactView`, not a universally defined root view controller ([ExactViewIOS.swift:14](/Users/admin/.config/tuft/sessions/1791014443.232549/worktrees/exact2/host/apple/Sources/ExactKit/IOS/ExactViewIOS.swift:14)). Modal presentation moves its viewport into a separately presented controller ([ModalIOS.swift:265](/Users/admin/.config/tuft/sessions/1791014443.232549/worktrees/exact2/host/apple/Sources/ExactKit/IOS/ModalIOS.swift:265)); descending only the presenting controller’s view can omit the sheet.

   Conversely, starting macOS inspection at the key window includes unrelated content and other sessions. The sample host explicitly contains two sessions with overlapping IDs ([ExactHostMac/main.swift:1](/Users/admin/.config/tuft/sessions/1791014443.232549/worktrees/exact2/host/apple/Sources/ExactHostMac/main.swift:1)).

   **Edit:** Define session-owned roots, associated presentations and permitted surrounding chrome. Stop joins at foreign session boundaries and use the session’s containing window, not global key-window state. Include two-session, unmounted-session and presented-sheet proofs.

7. **High — The findings cannot be computed from the specified inputs and reply shape.**

   `axFindings(tree, ax)` needs facts the JS `tree` currently omits: its property projection does not include inertness, accessibility-hidden state, modal state or `semanticTag` ([agent.js:10](/Users/admin/.config/tuft/sessions/1791014443.232549/worktrees/exact2/host/web-js/agent.js:10), [agent.js:28](/Users/admin/.config/tuft/sessions/1791014443.232549/worktrees/exact2/host/web-js/agent.js:28)). D3 also omits the interaction flag required by D8’s UIKit unnamed rule.

   Modal detection is undefined: an open `dialog` is not necessarily modal—the existing web input code specifically checks `dialog:modal` ([input-glue.js:46](/Users/admin/.config/tuft/sessions/1791014443.232549/worktrees/exact2/host/web/input-glue.js:46)). `modal: V|null` cannot distinguish no modal from a modal with no Exact ID. “Null neighbours inside the same platform container” provides no precise targeting boundary.

   **Edit:** Specify the complete wire contract: normalized intent fields, ancestor context for targeted reads, interaction facts, actual modal status, modal/container references within the response, findings shape, and unavailable responses. Define targeting against that topology rather than “neighbours.”

8. **High — The proposed smoke can pass without exercising the failures it claims to prevent.**

   “No findings” passes for an empty Caltrain AX tree. Absence of the decoration and inert child likewise proves little without positive coverage assertions. Hand-written replies test the finding function but cannot catch a collector that drops the offending elements.

   The requested Caltrain “station sheet” does not exist: `openStations` selects a stations screen containing the search field ([app.contract:84](/Users/admin/.config/tuft/sessions/1791014443.232549/worktrees/exact2/apps/caltrain/app.contract:84), [app.contract:295](/Users/admin/.config/tuft/sessions/1791014443.232549/worktrees/exact2/apps/caltrain/app.contract:295)). The claim that no host can expose an intended-inert subtree is also unsuitable for a regression plan: UIKit’s exclusion is an assigned property, which a test can deliberately clear after mounting ([NodeViewIOS.swift:209](/Users/admin/.config/tuft/sessions/1791014443.232549/worktrees/exact2/host/apple/Sources/ExactKit/IOS/NodeViewIOS.swift:209)).

   **Edit:** Require expected named elements, successful ownership joins and complete coverage before accepting zero findings. Add controlled negative cases through the real collector, followed by repaired cases. Use an existing Messages modal or dialog fixture for modal containment.

9. **Medium — The web join can combine observations from different document states.**

   D1 takes runner tags first; D4 then performs separate asynchronous AX, DOM and geometry reads. The carrier’s evaluations are separate requests ([agent.mjs:196](/Users/admin/.config/tuft/sessions/1791014443.232549/worktrees/exact2/scripts/agent.mjs:196)), and LLP 1012 expressly permits host I/O between operations. D7’s “main thread with no action between” does not make several CDP calls atomic. A reload can also produce another JS page whose reported incarnation is again `1` ([agent.js:65](/Users/admin/.config/tuft/sessions/1791014443.232549/worktrees/exact2/host/web-js/agent.js:65)).

   **Edit:** Bracket collection with tag and document-identity checks; report `spanned` or refuse an inconsistent join, with bounded retries. Specify how detached DOM nodes and navigation invalidate the result. Preserve LLP 1035.002’s existing consistency mechanism rather than inventing persistent snapshot tokens.

10. **Medium — The stated limits bound neither collection work nor all output.**

    A 500-element output limit follows an unlimited runner subtree materialization ([runner/src/agent.rs:279](/Users/admin/.config/tuft/sessions/1791014443.232549/worktrees/exact2/runner/src/agent.rs:279)), full AX retrieval and `DOM.getDocument(depth:-1)`. Actions, identifiers and other native strings remain unbounded. `limit` has no maximum or validation rules. Computing an exact omitted-element count would itself require finishing the walk.

    Truncation also changes correctness: comparing two 200-character prefixes can conceal different names, while listing IDs absent from a truncated side creates false parity findings.

    **Edit:** Define validated request limits, visitation/depth/byte budgets, cycle handling and bounds for every variable field. Mark truncation per field and distinguish unknown remainder size from a known count. Partial reads must not produce complete-absence, full-order or full-name equality claims.

11. **Medium — The browser plan cannot supply all the promised frames and guest coverage.**

    CDP’s AX nodes have optional DOM associations and no geometry field; `getFullAXTree` is frame-scoped. [Accessibility.pdl:170](https://raw.githubusercontent.com/ChromeDevTools/devtools-protocol/master/pdl/domains/Accessibility.pdl) Reading the nearest Exact owner’s rectangle therefore gives an owner box, not necessarily the exposed text or control’s frame. There is no joined ID to measure for `id:null` elements. The existing carrier attaches one page target, which does not establish coverage of out-of-process iframe targets ([agent.mjs:162](/Users/admin/.config/tuft/sessions/1791014443.232549/worktrees/exact2/scripts/agent.mjs:162)).

    **Edit:** Make frames optional and identify their source; label owner rectangles as owner rectangles. Explicitly exclude unsupported guest trees with a coverage reason, or specify frame-target traversal and coordinate conversion. Clarify that geometry uses one batched evaluation—the current “three calls” wording also permits an evaluation per ID.

12. **Medium — The role and state mapping is not sufficiently defined for strict parity.**

    UIKit’s adjustable trait describes increment/decrement behavior, not exclusively sliders ([UIAccessibilityConstants.h:86](/Applications/Xcode-27.0.0.app/Contents/Developer/Platforms/iPhoneOS.platform/Developer/SDKs/iPhoneOS.sdk/System/Library/Frameworks/UIKit.framework/Headers/UIAccessibilityConstants.h:86)). Apple also distinguishes the combinations of traits used for a [toggle button](https://developer.apple.com/documentation/uikit/uiaccessibilitytraits/togglebutton?changes=_7); unconditional `toggleButton → switch` loses that distinction. Exact’s current checkbox exposes button traits plus a textual checked value ([ControlsIOS.swift:30](/Users/admin/.config/tuft/sessions/1791014443.232549/worktrees/exact2/host/apple/Sources/ExactKit/IOS/ControlsIOS.swift:30)).

    D3 leaves name precedence, numeric versus textual values, mixed checked states and pressed states undefined. D5’s blanket “missing field is never a finding” can hide a missing supported semantic. Recording a deliberate difference in LLP 1008 also does not change a smoke that fails on every parity result.

    **Edit:** Define normalization and capability rules for the fixture controls first, preserving raw facts. Distinguish unsupported observations from missing semantics. Keep broader parity informational until executable comparison rules exist.

13. **Medium — The secure-value guarantee is incorrect for Chrome.**

    D7 says a secure field’s value is absent on the web. Chromium’s CDP serializer includes nonempty control values, and its password path can return a masked string; absence is not the contract. [inspector_type_builder_helper.cc:700](https://raw.githubusercontent.com/chromium/chromium/main/third_party/blink/renderer/modules/accessibility/inspector_type_builder_helper.cc), [ax_node_object.cc:4556](https://raw.githubusercontent.com/chromium/chromium/main/third_party/blink/renderer/modules/accessibility/ax_node_object.cc)

    **Edit:** Remove the platform-specific bullets/absence assertion. Define an explicit protected-value policy—preferably omission—and test it on each supported collector, without reading editor contents as a fallback.

14. **Medium — The landing plan does not actually schedule its proofs or complete its deletions.**

    The async lane’s command list invokes neither `smoke.mjs` nor `scripts/app.test.mjs`; adding a smoke step does not make it run per commit ([async.mjs:51](/Users/admin/.config/tuft/sessions/1791014443.232549/worktrees/exact2/scripts/async.mjs:51)). `smoke.mjs` already ends at line 1,499, so its expansion needs an explicit space trade ([smoke.mjs:1499](/Users/admin/.config/tuft/sessions/1791014443.232549/worktrees/exact2/scripts/smoke.mjs:1499)).

    D9 also misses Linux tests that require the deleted field ([native_buttons.rs:134](/Users/admin/.config/tuft/sessions/1791014443.232549/worktrees/exact2/host/linux/tests/it/native_buttons.rs:134), [paint.rs:1047](/Users/admin/.config/tuft/sessions/1791014443.232549/worktrees/exact2/host/linux/tests/pinned/paint.rs:1047)). The existing cross-host smoke’s name assertion needs a Linux-specific unavailable expectation.

    **Edit:** Name the async commands and required artifacts, include the unit tests, and budget the source-file changes. Rewrite all consumers in the deletion commit. None of this requires a sixth blocking check.

15. **Medium — The accessibility-audit scope amendment remains an explicit acceptance prerequisite.**

    Keeping this within `tree` satisfies the operation-count rule, but it does not admit automatic audit findings and parity checks. The draft acknowledges that D9 lacks a take or waiver; deleting already implemented decorations is not clearly removing a doing-list item. The binding rule requires that trade or Charlie’s recorded waiver ([DEFERRED.md:543](/Users/admin/.config/tuft/sessions/1791014443.232549/worktrees/exact2/rules/DEFERRED.md:543)).

    **Edit:** Record the actual scope decision before acceptance. The cheaper alternative is to land bounded observations and their correctness proofs first, leaving automatic findings and generalized parity outside that slice.
