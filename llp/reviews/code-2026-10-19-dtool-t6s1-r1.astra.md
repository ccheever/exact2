No **BLOCKER** found in this static review. These issues should be addressed:

1. **SHOULD-FIX — Revoke can target a replacement server’s client.** [pairing.ts:39](/tmp/rv-dt-t6s1/apps/design-tool/pairing.ts:39) calls `call` without a server-run binding. If the server restarts while the old list remains visible, [app.ts:89](/tmp/rv-dt-t6s1/apps/design-tool/app.ts:89) can reacquire its token and retry. Client names restart too: an old `remote:laptop#1` row can revoke a newly paired `remote:laptop#1`. Bind the operation to the run that supplied the displayed list.

2. **SHOULD-FIX — The stub lets a read-scoped client enable inspect mode.** The new gate at [tamber-stub.ts:151](/tmp/rv-dt-t6s1/apps/design-tool/stub/tamber-stub.ts:151) admits `{method:"inspect", refresh:true, on:true}` as `read`. After establishing presence through `/events`, that request reaches [tamber-stub.ts:189](/tmp/rv-dt-t6s1/apps/design-tool/stub/tamber-stub.ts:189), skips the refresh-only branch and assigns the client as inspector. The real server’s [scope-specific handler](/tmp/rv-dt-t6s1/scripts/tamber-server.mjs:735) returns cached selections without changing builds. Mirror that distinction.

3. **SHOULD-FIX — Revocation during body receipt produces the wrong response.** At [tamber-stub.ts:317](/tmp/rv-dt-t6s1/apps/design-tool/stub/tamber-stub.ts:317), authentication precedes `await req.json()` and is never rechecked. Begin an events request, revoke its client, then finish the body: it still receives events with 200. The equivalent `/__tamber` request instead dereferences a removed client at [line 150](/tmp/rv-dt-t6s1/apps/design-tool/stub/tamber-stub.ts:150). Both should return `401 GONE`, as the real server does.

4. **SHOULD-FIX — The stub advertises expiries it never enforces.** [tamber-stub.ts:158](/tmp/rv-dt-t6s1/apps/design-tool/stub/tamber-stub.ts:158) stores no code deadline, and [line 126](/tmp/rv-dt-t6s1/apps/design-tool/stub/tamber-stub.ts:126) ignores token expiry. An unused code still pairs after two minutes; a token still authenticates after twelve hours. These should produce the real server’s expired-code 403 and expired-token `401 GONE`, with the expiry event and list update.

5. **SHOULD-FIX — Stub revocation leaves client-owned state behind.** [tamber-stub.ts:129](/tmp/rv-dt-t6s1/apps/design-tool/stub/tamber-stub.ts:129) removes the token and emits `revoked`, but leaves presence, inspect ownership, pins, holds and scrubs intact; held proposals are not marked revoked. For example, a paired writer can enable inspect, then disappear from Clients after revocation while remaining the build’s inspector. The real server clears those effects and marks retained proposals.

6. **SHOULD-FIX — A failed Clients read has no recovery path.** [app.contract:650](/tmp/rv-dt-t6s1/apps/design-tool/app.contract:650) refreshes only when locality or `changes.clients` changes, or Revoke completes. If one `clients` request fails while hello and polling remain healthy, the error persists indefinitely: ordinary polling does not change those arguments, and there are no client rows to revoke. Add an explicit retry or retry failed reads without refreshing successful lists on build statuses.

7. **SHOULD-FIX — The tests do not establish the authorization or revocation guarantees.** [app.test.contract:1712](/tmp/rv-dt-t6s1/apps/design-tool/app.test.contract:1712) discards the issued token; the revoke assertions check text and row removal only. A revoke that leaves the token usable would pass. The tests meaningfully cover the local happy path, but need coverage for token rejection after revoke, paired-client exclusion from the panel/local methods, and displayed `pair-code`/`clients` refusals.

8. **NIT — Pair input handling differs from A2.** [tamber-stub.ts:293](/tmp/rv-dt-t6s1/apps/design-tool/stub/tamber-stub.ts:293) only uppercases codes. Typing `7Q2KDM4X01` without the hyphen fails here but succeeds against the real server. A numeric code receives 403 here instead of 400. Preserve deterministic codes while matching normalization and validation.

9. **NIT — `/events` bypasses the shared scope table and last-seen update.** [tamber-stub.ts:317](/tmp/rv-dt-t6s1/apps/design-tool/stub/tamber-stub.ts:317) checks only token identity. Current scopes all permit events, so this is not presently an elevation, but it contradicts the every-method check. A paired client doing only event polls also retains its pairing-time `lastSeen`, unlike the real server.
