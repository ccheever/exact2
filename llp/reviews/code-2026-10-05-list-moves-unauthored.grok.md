Both advance `revision` (`mod.rs:582-584`) and leave `count` alone. The commit is a `dispatch`, so `Unauthored::All` is off. Idle rows take the new box with no transition (`motion/src/engine.rs:511-515`). Concrete input: rows `[1, 2, 3]` with `layout-transition`, replaced by `[3, 1, 2]`, or one row's text growing. Count stays 3 and the rows jump. One equality covers every list, so a count change on any list leaves every list's row moves authored in that layout, and a same-count edit snaps every list. Inserts and removes still play (the count changes). A running transition still retargets (`engine.rs:517`, kernel test `kernel/tests/it/presence.rs:489-491`). A gesture reorder still moves: `arrange_rebase` releases `Property::Translate`. **Fix:** bump a per-list data generation only from `update_data` when `changed`. `feedback`, `scroll_into_view`, and `release_pins` also bump `revision`, so `revision` cannot be that signal. Apply `ListRows` only to rows whose own list's data generation is unchanged.

A `resize=fit` action whose commit moves a node with `layout-transition`, or a reorder cancel started by that report, settles those moves. **Fix:** set `All` only around the report's own `commit_tree` layout, and clear it before `arrange_after_commit` and `finish`.
