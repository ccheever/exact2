## BLOCKER

**1. D5 hit-testing cannot see the front-most node.** A click is resolved by walking the last `layout` `nodes[]` boxes and taking the front-most. Those boxes are in ascending id order, with presentation transforms folded in, and they are not paint order or hit targets (`llp/foundation/1012-agent-api-v1.spec.md:247-254`). The JS target returns the same rectangles from `getBoundingClientRect` in tree order (`host/web-js/agent.js:270-284`). A layout box is not the control's hit target (`llp/1035.004-native-visual-affordances.rfc.md:396-401`). Overlaps, clips, `pointer-events`, dialogs, and native chrome select the wrong node. **Fix:** one relayed point-pick that uses the host's hit test (the page already has `elementsFromPoint` in `host/web/geometry-glue.js:93-102`; `tap` already hit-tests natively) and returns that view id. Keep boxes for outlines only.

**2. D5's token chain does not exist on the web JS target, which is the default canvas.** Step 2 says a row names its token because the kernel keeps the token beside the value (LLP 1121 D7, `llp/1121-tamber.rfc.md:572-575`). The JS target keeps no kernel (`llp/1121-tamber.rfc.md:613`). Its `layout <id>` stores `getComputedStyle` colors and marks a class or inline rule `authored` (`host/web-js/agent.js:116-146`). A token painted as `var(--x-surface-card)` arrives as `rgb(...)`. Fail-closed then treats that as an authored literal, and `set-row` can write the computed color back. That is the exact1 write-back failure D5 says it closed. The documented map join does not repair it: `scripts/agent-inspect.mjs:67-79` reads `/exact.json`'s `dev.sourceMap`, and `host/web-js/dev.mjs:217-222` forwards `/exact.json` to the resident wasm loop, a different plan. The JS map is only a static `app.plan.map.json` (`host/web-js/build.mjs:646-649`). **Fix:** the JS runtime must report the specified token from its D7 map beside the computed value, in the runner's row shape. Publish that build's map on its own envelope. Until both exist, a web tile has file and line only, and a row with no token reference stays read-only.

**3. D6 `set-row` addresses source by a plan-site span, and that span is not stable.** The map is keyed by the plan digest. Formatting changes locations while the plan digest stays the same (`docs/reference.md:210-212`); the driver keeps one map per plan digest (`scripts/agent-inspect.mjs:99`). A client that refreshes the file digest and reuses the matching plan's ranges writes into the wrong span. Component expansion makes the site the wrong identity anyway: each instantiation is its own plan node with the same source span (`contract/lower/src/sites.rs:26-37`). The server today may write params and state parts only (`llp/1121-tamber.rfc.md:839-840`), not an arbitrary paint row. **Fix:** the server resolves the row at write time from the file digest plus a source identity (file, span checked against a source digest recorded in the map, or component id + element). Parse the value as that row's type and apply it as an AST edit through `contract fmt`. Refuse tag-origin rows (`sites.rs:64-71`). Do not accept a client span justified only by the plan digest.

**4. D3's relay forwards LLP 1012 unchanged, including a client-chosen screenshot path.** `screenshot` writes a host path (`llp/foundation/1012-agent-api-v1.spec.md:229`, `scripts/agent.mjs:492-509`). D12 gives every paired client the canvas through that relay (`llp/1122-design-tool.rfc.md:317-320`); D13 then says the relay exists only at `write` scope (`:330-332`). A remote `write` client can therefore `tap` and `type` on a signed-in phone and choose where the PNG is written. A `read` or `propose` client, who D12 says sees the same canvas, gets no relay at all. **Fix:** split the relay. Look operations (`layout`, server-captured screenshot bytes, `clock`, `prefer`) for `read` and `propose`. Input (`tap`, `type`) only for `write`, journaled. The server picks the capture file and returns bytes or a loopback URL. Do not forward `path`, `logs`, or `perf`.

## MAJOR

**5. D8's fifth `prefer` group is the wrong operation.** `prefer` sets device facts in `media`, `page`, and `fold` (`scripts/agent-prefer.mjs:1-11`). A new input is a form of `tap` (`rules/DEFERRED.md:839-842`). A press is already `tap` phases `down` / `hold` / `up` (`llp/foundation/1012-agent-api-v1.spec.md:226`); iOS answers phases `unsupported`. Pinning one node's `:active` is writable host state, which LLP 1035.002 §3 refuses. §7's "nothing in the runner or kernel" is false: every host's press tracker has to grow this. **Fix:** a development-only `tap` form that pins `:active`, `:hover`, or `:focus-visible` on one id until cleared, on hosts that already track that state. Leave `prefer` to device facts. Keep Q4's blind fallback if this is refused.

**6. D6's systemic default reverses exact1 §3.1 while citing it.** 0158 defaults a component to its component rung and a raw node to the source node, and offers theme scope, never defaults it, because an accidental token edit is the mistake the ladder exists to prevent (`~/projects/exact1/llp/0158-design-mode.rfc.md:214-224`). D6 defaults to the token whenever the row holds one, and only withholds the dial (`llp/1122-design-tool.rfc.md:189-196`). With the live table, that scrub recolors every use immediately. **Fix:** default to the param when the row reads one, otherwise the source row. Offer token and dial. One gesture widens, with the blast-radius outline.

**7. D5's "templates, not copies" covers `each` and misses components and styles.** Outlines follow one plan site (`:145-149`). A component body is one span expanded into many sites (`contract/lower/src/sites.rs:29-31`), so `set-row` changes every instance while the outline shows one. A `class:<Name>` row is `authored` in the runner (`llp/1035.002-native-result-inspection.rfc.md:152-158`) but the ladder has no style rung, so an instance write forks the node and leaves the style. There is no per-instance paint store (LLP 1121 D15: params are not props), so the chip "Just this" is false inside a component. **Fix:** outline every mounted node with that source span. Edit `class:` rows on the style. Label the source-row rung "this template". "Just this" only for a non-repeated app-level node.

**8. D6 says every edit is live, then says `set-row` reloads.** Act-first applies at once on every tile (`:198-199`). `set-row` and `set-state` rebuild and reload (`:217-218`, LLP 1121 D13). A template or state edit says "rebuilds" on the chip before the gesture.

A hand edit has no client name for the stale-inverse message (`subscribe` names a client only for a client write). **Fix:** the dev loop owns tile processes and a local carrier table keyed by build id. Add a server `commit` that commits only design files the server wrote, or drop commit from the tool and show the diff. Attribute a non-client change as on disk.

## MINOR
