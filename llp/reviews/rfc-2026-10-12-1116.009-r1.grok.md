# Grok 4.7 (xhigh) review of LLP 1116.009 r1

## Decisions

**D1. RIGHT.** A `reload` that returns to the launch instant is a false relaunch. habit-tracker lost a test and a doc search to it in two rounds. Keeping the virtual time the test had reached, with zone, locale and seed unchanged, matches a phone that restarts at 9:05.

**D2. WRONG DIRECTION.** recipe-finder's blank page is a location no route matches ("boot refused … invalid router"). Sending that location to the root and replacing the URL makes the address bar lie. A well-made web app keeps the URL and shows a not-found state in the shell. An authored `notfound` route still wins. `/event/999` and flashcards' missing deck are a matched route whose id names nothing. A root redirect never sees them. `pattern list-detail` has to write that empty state ("No such recipe", and a way back) as the body of the detail route.

**D3. RIGHT WITH CHANGE.** A transparent sheet is an unsaid surface, so the platform owes it an opaque one, and an authored background still wins. On a wide web window a modal route should be a centered dialog. That is the web-look rule that a phone column across the desktop is a stretched phone. The change has to say the host presents the route. `navigation-stack` teaches `position="absolute" inset=0` on the modal column, and habit-tracker, contacts and event-rsvp all copied it. If that authored inset still sizes the route, the graded full-window sheet stays. The inset fills the dialog. iOS stays a sheet.

**D4. RIGHT WITH CHANGE.** event-rsvp's "Create an event" sits on the right because the header has two children and `justify-content="space-between"`, copied from the three-item sheet bar in `navigation-stack`. Centre the inline title of a sheet or dialog bar. A wide-window page title stays leading. The same rule on every route header would centre event-rsvp's home title, "gather", in a bar that is meant to read as a web page. The recipe has to stop authoring that `space-between`. An authored justification beats a platform centre, so the create page would not move.

**D5. RIGHT WITH CHANGE.** focus-timer and recipe-finder both had `width="100%"` plus padding, content-box, past the phone viewport, with `verify` clean. The finding should be that case. A platform bar or sheet that overflows must not be a finding, and neither should a nowrap readout or a row that scrolls on purpose. Round 10 already showed builders stripping a correct control to silence `check`.

**D6. RIGHT.** `AGENTS.md` already says to read `help` and to open `--help` only for a flag. Builders still open `--help` because `help` does not list `verify`'s platform and `--shots`, or `agent`'s `--storage`, `--size` and operations. One screen, and the colour roles on `contract vocab background-color`, is the right fix. It is a few turns, not the token gap.

**D7. RIGHT.** The content-design timer puts round buttons on a stretched row with `space-between` and no `max-width`. That is water-tracker's gap. A second, larger copy of the SummaryCard number is the doubled total. Keep both edits inside the existing examples.

## The larger lever

D1–D7 are the right defect list and the wrong-sized token plan. habit-tracker's extra commands were eight bare `date +%H:%M` (the harness requires a real timestamp), seven recipe reads, six help reads, three clock searches and four server commands. D1 and D6 cover the clock and the help. The diary's knowledge section is the mass: start-here, then about 450 lines because the lookup table matched nine rows (dates, storage, web layout, content, sheets, navigation, responsive, after-a-write, fetch) before any code. Docs and help grew this round, 942 KB to 1,065 KB. Each of those reads is cached on every later turn.

The lever is a `pattern` that writes the ordinary app (list, sheet, storage, a clock test, the wide layout, the missing-id state) so those files stay closed. Round 12 will not show React near 1.0× on D6 alone.

On quality, the four React losses are all one point, or a 7–7 called for React. Exact2 won contacts, flashcards, focus-timer and tip-splitter while looking plainer, on routes, Back and dark mode. The losses are those same strengths with a hole: a blank unknown location, a missing id, a desktop sheet, a header, a wide-column slip. React's search, illustrations and rings are extra product, and the neutral look is correctly out of scope. It did not decide the four wins. D2–D4 and D7, with the changes above, are the quality set.

## Principles

D2 as written breaks "write the web": the address is part of the web platform (`web-look` already treats the status-bar address as real). D3 fits it, once the dialog is the host's presentation and the author's background still wins. D4 fits a sheet bar and fights a wide page header. Author-over-platform is the constraint on D3 and D4, because the losing apps authored the inset and the `space-between` the recipes show.

## Verdict

**READY WITH CHANGES.** Keep the URL and show a platform not-found. Make the missing-id state part of `list-detail`. Make the wide-web dialog the host's presentation, with the recipe's inset filling it. Centre sheet and dialog titles only, and drop authored `space-between` from the header example. Scope the overflow finding to content-box padding. Add the pattern-write so a normal build does not open the nine recipes.
