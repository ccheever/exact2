## Findings

[P1] Treat a `#` in a default as a param reference only when it is a full param name — `apps/design-tool/moves.ts:21`

Detach of `fill: color = "#1e2732"` (design does not set it, row `background-color="param.fill"`) calls `moveOps` and gets `[]`, because `p.default.includes('#')` is true. `proposeEdit` then shows "This param is set by the app's design, or its default reads another param" (`app.ts:823`). Neither is true. `shown` only rewrites internal param-token names, so a hex or `light-dark(#fff, #000)` default stays as written (`contract/lower/src/params.rs:211`), and the same check does correctly refuse `color-mix(in oklab, post.contract#PostButton.fill 88%, black)` (`contract/cli/tests/it/tamber_params.rs:98`). The row should be set to `#1e2732` and `fill` removed. Because every real param-to-param default contains `#`, this return also means the closure loop (`app.ts:826`) never runs against the compiler. It only runs on the stub.

[P1] Derive the new param or token kind from the row — `apps/design-tool/moves.ts:29`

`kindOf` never reads `t.addr.row`. A quoted value that is not a known token name, a leading color function, or a bare number becomes `length`. Promoting template `background-color="transparent"` (or `"white"`) to param `ground` sends `{op:'add-param', kind:'length', default:'transparent'}` plus `set-row` value `param.ground`. That is the `rowkind` case: a length param on `background-color` is `tamber-kind` (`contract/cli/tests/it/tamber_params.rs:179`). The same guess sends `box-shadow="0 1px 2px #0008"` and `font-family="Georgia"` as `length`, and `font-size="16"` as `number`. A number token is only legal on `opacity`, `line-height`, `flex-grow`, `font-weight`, `-exact-press-scale`, and `-exact-press-opacity` (`contract/lower/src/theme.rs:1384`). The text reader at this commit already accepts all of those quoted values (`scripts/tamber-inspect.mjs:245`). A mapped token name (`accent.fill`), a leading `#1e2732`, `8px`, and `0.5` on opacity are classified correctly.

[P1] Leave a param in place when another row still reads it — `apps/design-tool/moves.ts:22`

Detach always emits `remove-param` for the short name, then only adds names parsed from `tamber-param-unused` (`moves.ts:27`, `app.ts:826`). Card with `background-color="param.fill"` and `border-color="param.fill"`, default `accent.fill`, design unset: the ops are `set-row` of `accent.fill` on the background and `remove-param` of `fill`. The border row still reads `param.fill`, so the compile reports `tamber-param-unknown` (`contract/lower/src/params/rewrite.rs:579`), `unread` returns `[]`, and the loop stops. A param row has no other write: `rowOf` sets `edit: ''` and offers only Detach (`inspector.ts:61`). D6 removes the param only when this write leaves it unreachable.
