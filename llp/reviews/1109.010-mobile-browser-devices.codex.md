## Findings and corrections

1. Browser epoch invalidation was lost during an older list request. The executable witness starts an old-epoch list, delivers a new-epoch event, then resolves the old list. Before correction needsRefresh changed true→false and the old tab remained. An invalidation counter now preserves the need for a fresh authoritative list, and newer-epoch buffered events are retained. The same witness now retains needsRefresh=true. Files: browser-review-epoch.ts, -before.log, -after.log.

2. Stream retry markers did not resubscribe. T3Transport removes a stream on Exit and later emits _retryDue; it does not reopen it itself. BrowserRead kept its subscription ID, while shared watchDevice ignores markers and retains its ID. Read→due→read produced one subscribe instead of two. Browser now resets its subscription on due. App-local mobileDevicesEvents observes due before the shared drain and DeviceRead explicitly resubscribes through the existing native RPC; the shared device reducer remains unchanged. Updated witness routes the marker through both app-local and shared handlers and now sees two subscriptions each. Files: browser-review-retry.ts, -before.log, -after.log.

3. Failed automatic retries retained their trigger. Root tasks key on needsRefresh and not-pending, so permission/network failure would immediately start another retry on every mutation completion, bypassing native backoff. Before correction both browser/devices needsRefresh remained true after a permission denial. The read attempt now consumes its observed trigger even on failure, retaining only newer invalidations. Witness now reports false/false. Files: browser-review-failed-retry.ts, -before.log, -after.log. Older permission/subscription awaits also receive read-serial guards so they cannot overwrite a newer read's grants.

4. Native status from tab A could enable controls after selecting B because owner identified only environment/thread/generation. Executable witness gates statusA, selectsB, then releases A: before correction B.canNavigate becomes true. Status replies now include tabId or hostId/deviceId, and adapters require both captured selection and returned native target. Fallback selection after closed/removed targets clears native status. Witness now remains false; the after witness includes tabId=one, matching the new native payload. Files: browser-review-status.ts, -before.log, -after.log.

5. Old WK navigation/process callbacks and delayed identity checks could fail a replacement viewer. Final callbacks check alive and exact WKWebView identity; periodic identity responses also check captured target and view serial. Script messages already required current main-frame WK identity. Correction inspected in source, not a WK execution harness.

6. File chooser and dialog callbacks could answer a different remote request. Initial choose overwrote mutable chooser even while an old document picker remained presented; its callback would upload those files to the new URL. Final chooser captures version/URL and exact picker identity, invalidates replaced/control-lost pickers and checks again before upload dispatch. Dialog callbacks capture key/version, and command dispatch revalidates that private token after its native identity await before stripping token fields from the actual remote command. Correction inspected in source; no remote chooser/dialog operated.

7. Initial upload assembled every selected file plus multipart body into Data on the main thread. It now writes an owned temporary multipart file off-main in1MiB chunks, checks cancellation per file/chunk, sends URLSession.uploadTask(fromFile:) and removes temporary bytes on completion/failure/stale ownership. This preserves actual source URI-backed file upload rather than adding an arbitrary file-size limit.

8. Download completion only checked alive after a pre-network identity check. The final helper rechecks the captured transport target before sharing or showing an error. Stale files are removed; destroyed views cancel tasks/dismiss presentation and clear owned temporaries. No cross-environment late share is intentionally permitted.

9. Audio-session ownership initially released immediately after fire-and-forget JS stop. Each WK instance now has its own UUID lease, retained until setAllMediaPlaybackSuspended completion. An old view's completion cannot release the replacement WK's distinct lease. Source inspection only; Apple media suspension behavior was not exercised.
