## 1. Verdict

**RETHINK.** The RFC identifies a real cost and several worthwhile syntax changes, but bundles them with an insufficiently specified async model, unsafe persistence evolution, and library expansion the census does not establish. Approve a smaller sequence of independently measured changes; treat async data and durable records as separate designs whose correctness and operational costs must be settled first.

## 2. The most important issues, ranked

### 1. D6 has not demonstrated that its `await` is sugar

Today a mutation’s `then` takes **no parameters**, while queued requests retain **the source and its arguments**. LLP 1089’s lifted action calls execute within the caller’s transaction; that mechanism does not itself retain an invocation’s locals across a delayed reply. See the [mutation checker](/Users/ccheever/projects/exact2/contract/analyze/src/lib.rs:251), [queue representation](/Users/ccheever/projects/exact2/runner/src/runner/queue.rs:25), and [core action semantics](/Users/ccheever/projects/exact2/semantics/Contract/Syntax.lean:87).

For example, two invocations of `save(id)` must each retain their own `id`, draft snapshot, reply, and continuation. A generated shared slot for captures would be wrong. A valid translation using per-invocation envelopes may exist, but the RFC must specify it, including overlapping invocations, two awaits, failures, component disappearance, and queue policy.

There is also a fundamental change to the author’s model: **one authored action containing `await` becomes several transactions**. A later failure cannot undo an earlier committed segment. The existing runner explicitly treats `then` as a separate commit whose refusal leaves the reply standing. [Commit implementation](/Users/ccheever/projects/exact2/runner/src/runner/commit.rs:584)

`state items = await loadItems(query)` creates another misleading expectation: an ordinary state initializer runs once, whereas a resource reacts to changing arguments, has placeholders and failure state, and is not an ordinary writable slot. Calling both `state` hides knowledge the builder still needs.

**Change:** separate plain function exports and generated adapters from Contract `await`. Keep an explicit resource declaration, infer its signature where possible, and require a complete concurrency and failure contract before adopting await. Define one authority for the TypeScript/Contract boundary types.

### 2. D7’s evolution policy can destroy data while preserving types

Type-correct decoding is not a safe migration policy:

- Renaming `title` to `body` looks like dropping one field and introducing another; the proposed result loses the text.
- Adding an `id` with the empty-string default can give every existing record the same identity.
- Changing units while retaining `number` preserves the type and corrupts the meaning.
- Dropping unknown fields destroys information needed by an older app version after rollback.
- A type mismatch still permits discarding user data.

This is particularly dangerous because current persistence restores the initializer on a mismatch and then persists slots at boot. The fallback can overwrite the recoverable original. Logging the event does not protect it. [Persistence implementation](/Users/ccheever/projects/exact2/runner/src/runner/persist.rs:29)

**Change:** remove automatic zero-filling as the general migration rule. Require explicit defaults or versioned transformations, preserve incompatible stored data, and prevent fallback values from silently replacing it. Define stable storage identity independently of incidental source renaming. “Delete; don’t deprecate” for language spellings should not become permission to delete a person’s journal.

D6 does not make this problem disappear: JSON in `localStorage` merely transfers migration responsibility to each app.

### 3. The persistence cap does not establish either startup or write performance

RULES budgets **the entire interactive cold start at 100 ms p50**, not just reading and decoding one persisted value. A per-value 1 MB limit also leaves aggregate persisted size, allocation, validation, initial derivation, and rendering unbounded.

The cited 294 ms measurement concerns approximately **11.4 MB of JSON at 25,000 messages**. The same table reports 10.6 ms for the comparison at 1,000 messages, approximately 450 KB. These are useful warnings, not measurements of the proposed persistence implementation or its startup budget. [Original measurements](/Users/ccheever/projects/exact2/llp/1027.003-value-transfer-and-shared-storage.research.md:138)

Moving disk writes off the main thread is insufficient. Current Rust and web implementations encode every persisted slot after each commit before checking whether its encoded value changed. An unrelated timer tick can therefore serialize an unchanged journal. [Rust persistence](/Users/ccheever/projects/exact2/runner/src/runner/persist.rs:57), [web persistence](/Users/ccheever/projects/exact2/host/web-js/persist.js:54)

The IndexedDB fallback also needs a boot protocol: its requests are asynchronous, so it cannot transparently replace synchronous restoration before the first frame. [IndexedDB specification](https://w3c.github.io/IndexedDB/#asynchronously-execute-a-request)

**Change:** measure complete startup and interaction costs, establish an aggregate budget, avoid encoding unchanged slots, and specify ordered writes, durability acknowledgment, quota failures, and termination during a save. A cap’s log message is not an adequate user-facing failure policy.

### 4. The census supports a narrower proposal than the RFC presents

I reproduced the primary census counts. The strongest evidence is:

| Construct | Features, across both models |
|---|---:|
| View `if` | 71/80 |
| View `for` | 59/80 |
| Typed state | 45/80 |
| `.length` | 40/80 |
| Recognized method calls | 31/80 |

But the experiment is explicitly conditioned. The [guide](/Users/ccheever/bakeoff/priors-guide.md) says tags are HTML’s names and that anything loaded or saved belongs in `app.ts`; the [prompt](/Users/ccheever/bakeoff/priors.py) requests both files. Consequently, HTML tags, exported functions, imports, and the absence of `persist` are not independent votes about the best architecture.

Several omitted details materially weaken particular decisions:

- `Math.*` appears in **0/80** primary samples.
- Separating the combined `let/const` row gives **20 features using `let`, zero using `const`**. D2’s extra spelling has no support there.
- Direct method counts give `find` in **11 features**, but `reduce` in one, `toUpperCase` in one, and no `.toSorted`, `.padStart`, or `.flatMap`.
- The census reports **32 features with `Date.now`/`new Date` in `app.ts`**, and **12 with `Math.random`**. Fundamental boundary violations are considerably more prominent than the “six truthiness guesses” argument suggests.
- The primary corpus contains no detected multi-component examples. It says little about larger apps, reusable components, or effects across component lifetimes.

The [census script](/Users/ccheever/bakeoff/census.py) uses regex categories, sometimes combining distinct constructs. Its truthiness detector recognizes selected variable names; six is not a comprehensive count.

**Change:** use the census to nominate experiments. Report frequency among opportunities to use a construct, actual repair cost, and semantic success—not merely presence among 80 generated features. Validate on different app families, larger compositions, additional models, and later model versions.

### 5. The dangerous uncanny valley is code that compiles with the wrong meaning

The RFC focuses on refused TypeScript. Silent disagreement is more serious.

The targeted [Muse countdown](/Users/ccheever/bakeoff/guesses/priors2/muse/countdown/app.contract) writes:

```contract
secondsLeft = secondsLeft - 1
if secondsLeft <= 0
  secondsLeft = 0
  running = false
```

Under Contract’s documented snapshot semantics, the condition reads the old value, so this would stop the timer one tick late. More familiar syntax does not remove that learning requirement. The pre-state behavior is even a [proved transaction law](/Users/ccheever/projects/exact2/semantics/Contract/Axiomatic.lean:353).

Other proposed “familiar” forms introduce similar discrepancies:

- `xs[i]` lowering directly to `at(xs, i)` makes negative indices count from the end and truncates fractional indices. That is the existing [`at` behavior](/Users/ccheever/projects/exact2/semantics/Contract/Eval.lean:168), not JavaScript bracket access.
- HTML `dialog open` is not itself modal presentation or a two-way state binding. Modal presentation is a separate operation. [HTML dialog specification](https://html.spec.whatwg.org/multipage/interactive-elements.html#the-dialog-element)
- `p` and `span` cannot simply become indistinguishable text aliases without addressing layout and composition expectations; `label` entails more than supplying an accessible name.
- `toSorted` being stable does not establish cross-host determinism for inconsistent comparators: ECMAScript explicitly leaves that ordering implementation-defined. [ECMAScript sorting specification](https://tc39.es/ecma262/multipage/indexed-collections.html#sec-sortindexedproperties)

**Change:** prioritize familiar names with faithful, bounded meanings. Preserve explicit signals for genuinely different behavior. T4 must count behavioral surprises and unsuccessful repairs, not just compiler refusals.

LLP 1115 supports familiar vocabulary and native presentation; it does not independently mandate JavaScript expression semantics. LLP 1081 explicitly excludes expression functions from its CSS naming rule.

### 6. T1/T2 overstate what the existing proofs establish

The Lean work is substantial, but its scope matters:

- `dont_go_wrong` establishes well-typed configurations and absence of specified wrong states; it permits legitimate refusal and poisoning. It does not establish successful application behavior. [Theorem](/Users/ccheever/projects/exact2/semantics/Contract/BootSound.lean:386)
- The mutation model uses synchronous oracle answers, does not model sends behind real in-flight requests, and excludes mutation `pending` reads from generation. These are central to D6. [Documented restrictions](/Users/ccheever/projects/exact2/semantics/README.md:677)
- Persistence semantics receives decoded values and already admits arbitrary types. It does not validate durable encoding, schema migration, crash consistency, or the size budget. [Persistence scope](/Users/ccheever/projects/exact2/semantics/README.md:718)
- T1 says derives never read the clock, but the repository explicitly tests derives reading `performanceNow()`. That is currently a discouraged idiom, not the claimed language prohibition. [Existing corpus case](/Users/ccheever/projects/exact2/semantics/corpus/timers/derive-now.contract)

Also, `contract lean` consumes the compiler’s parsed and expanded program. If a new frontend rewrite produces the same wrong core tree for both backends, runner-versus-Lean comparison can agree. [Lean emission pipeline](/Users/ccheever/projects/exact2/contract/cli/src/lean.rs:43)

**Change:** classify spelling changes, elaborations, semantic additions, and host protocols separately. Give nontrivial elaborations independent expected-behavior tests or a preservation argument. Keeping the core AST unchanged is valuable, but does not prove the new surface language correct.

### 7. The 17% calculation is plausible accounting, not a demonstrated upper bound

I reproduced the regression: approximately **14.0k tokens/step plus 0.248M/MB-step for GPT**, and **70.7k plus 0.231M for Muse**, with the reported R² values. [Regression script](/Users/ccheever/bakeoff/replayfit.py)

Using the RFC’s rounded assumptions produces:

| Builder | Estimated saving | Fraction of Exact tokens |
|---|---:|---:|
| GPT | 0.274M | 16.7% |
| Muse | 0.640M | 17.4% |

However:

- Removing topic documentation does not remove the underlying concepts, especially resources, failures, permissions, and transactions.
- Repair-step estimates include carried documentation, creating potential overlap with documentation savings.
- Two removed lookups and half of repair costs are assumptions, not established intervention effects.
- The topic cohort and baseline-token cohort differ.
- Changes can alter authored code, later steps, and repair trajectories; the regression is descriptive, not a causal ceiling.

There is also an arithmetic interpretation issue: **0.274M closes about two-thirds of GPT’s 0.41M gap**, not half. Applying a 17% reduction to round 15’s ratios still leaves approximately **1.39× React** and **1.05× SwiftUI**.

The topic allocation needs a reproducible audit trail. Current `topics.py r14 r15 ab2-A` returns **2.34 GPT doc MB-steps**, versus the RFC’s 2.06; Muse matches at 3.42. It includes 9.72 MB-steps attributed to a command batch containing a process listing. This may explain an intentional correction, but exclusions and section allocations should be published. [Topic accounting](/Users/ccheever/bakeoff/topics.py)

**Change:** call this an optimistic scenario under stated assumptions. Measure total, cached, fresh, output, wall time, and quality separately. A rewrite can be worthwhile without closing the whole gap, but the estimate does not establish that this particular bundle is necessary.

### 8. The stages obscure attribution and underestimate migration and human costs

S1 combines four decisions, including nullable elaboration and a semantic library expansion, while describing itself as spelling. A positive aggregate result could conceal a harmful subdecision; a negative result would not identify what to remove.

The corpus migration really is **449 tracked Contract files**, plus embedded Contract in tests, generated starters, documentation, and external consumers. A mechanical source rewrite also needs to preserve persisted names, route identity, and other externally meaningful identifiers. Open branches need a coordinated cutover before the temporary rewriter disappears.

One-spelling discipline is valuable, but D2 adds an unsupported `const` synonym and D1 adds two nullable type forms without presenting their separate evidence. More generally, the RFC assumes Charlie and James share the census’s preferences without testing human comprehension of complete programs.

**Change:** split decisions into independently reversible experiments before undertaking each corpus migration. Keep semantic implementation and mechanical rewriting reviewable separately, cover external apps and active branches, and have the human authors read representative complete before/after apps. Preserve distinctions such as `resource` when they explain behavior the reader must understand.

## 4. Answers to the RFC’s §9 questions

1. **Is the bound right, and is the rewrite worthwhile?**  
   The arithmetic supports roughly 17% under its assumptions; the causal upper-bound claim does not. Small changes can justify a rewrite through durable simplicity and measured savings, but this estimate does not justify every proposed decision.

2. **Will TypeScript-looking syntax invite more refused TypeScript?**  
   Possibly; the frozen census cannot answer how models respond to the changed language. More importantly, it already contains sequential-state assumptions that familiar syntax would allow to remain wrong. Measure fresh generations, repairs, and executed behavior together.

3. **Is `null` with narrowing worth it?**  
   Keep `none`/`match` in the first stage and evaluate nullable syntax separately. A complete proposal must include implicit wrapping—[GPT’s navigation example](/Users/ccheever/bakeoff/guesses/priors2/gpt/notes-nav/app.contract) assigns a `Note` directly to `Note?`—as well as narrowing, optional chaining, assignments, and await boundaries; renaming `none` alone does not satisfy that prior. Restricted lexical elaboration may avoid making the core Lean type system flow-sensitive.

4. **Should pushed screens follow option state instead of routes?**  
   Keep routes as the primary model. The census demonstrates how models express selection, not that people should lose history, deep links, restoration, or adaptive presentation. A state binding could later be an adapter over route identity; URL absence itself does not inherently prevent split presentation.

5. **Is await sound, and is awaited state the right resource spelling?**  
   Await can be sound, but the proposed translation has not established it. Specify per-invocation captures, queue scope, commit boundaries, failure continuations, refresh timing, and pending aggregation; retain a resource marker. Imported handles must preserve per-call capability scope, and imports must not cause app JS to execute before first pixel.

6. **Is D7 decoding sufficient, is 1 MB affordable, and is it needed after D6?**  
   No, unestablished, and independently worth testing. Safe persisted records could eliminate an entire data module for many of the 14 local-record apps, a larger conceptual saving than changing its syntax—but only with an acceptable durability and evolution design.

7. **What does the RFC miss?**  
   Eliminating an abstraction can save more than disguising it. Compare safe record storage or generated local-data adapters against D6; address tooling/tests, the largest remaining GPT documentation topic; and measure maintenance tasks as well as first builds. One failed documentation-packaging experiment does not eliminate all opportunities in targeted examples, generated interfaces, shorter tool output, or context management, and future models may change the balance.

## 5. Anything the RFC should measure before deciding

- **Smaller controlled stages.** Separate existing-operation syntax, nullable elaboration, new library behavior, navigation, data adapters, await, and persistence. Rewrite the relevant guide for each arm and report net knowledge still required.
- **Independent outcomes.** Preserve a frozen corpus for compatibility, generate a new corpus to detect newly invited assumptions, and execute behavioral tests. More parser coverage can expose more diagnostics even when the language improves.
- **Held-out generalization.** Use new app families, multi-component apps, network failures, larger datasets, and maintenance of existing apps. Pair and randomize comparisons; report uncertainty by builder and platform and define a quality non-inferiority criterion before grading.
- **Async adversarial cases.** Double taps, out-of-order replies, two awaits, failed first/second requests, queued work, navigation away, and captured locals versus fresh state. Exercise native and web implementations with controlled reply scheduling.
- **Durable-data evolution and performance.** Upgrade and rollback real stored fixtures; rename fields, change types and units, exceed quotas, interrupt writes, and reopen multiple windows. Measure complete startup p50/p95, peak memory, unchanged commits, single-record edits, and aggregate stored size on the slowest supported devices.
- **Capability isolation.** Verify app/session/test separation and that the new storage namespace cannot access secrets, `exact.kept.*`, or `exact.state.*`, which are currently protected separately. [Store boundary](/Users/ccheever/projects/exact2/runner/src/store.rs:261)
- **Complete-program comprehension and migration cost.** Have Charlie and James review representative apps, and rehearse conversion of fixtures, external apps, and an active branch. Count implementation and ongoing maintenance cost alongside builder savings.
