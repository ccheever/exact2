## Findings

1. **HIGH —** `host/linux/src/presenter.rs:369`. On any GPU `finish` error (`render_to_texture`, `poll`, `map_async`), `frame()` replaces the picture with white, **clears `boxes`**, and sets `dirty = false`. CPU fallback exists only in `open_backend` at boot (`presenter.rs:121`); there is no later path. The display loop paints first, then reads input (`display.rs:255`, `display.rs:287`): `Button`/`press_at` call `hit()` on that empty list (`display.rs:303`), so a persistent device/readback failure makes every click miss, and a transient one drops the input that arrived in that iteration. Resolve: keep the last good boxes; leave `dirty` true (or immediately rebuild a `Raster` and retry); do not present a blank as success.

2. **HIGH —** `host/linux/src/vnc.rs:322`. `ClientCutText` does `vec![0u8; n as usize]` for a big-endian `u32` from the client. `EXACT_VNC=1` listens on `0.0.0.0:5900` (`vnc.rs:107`, `app.rs:19`). A client that completes the handshake (3.7/3.8 `None`, or 3.3 with any 16-byte “password”) can OOM the DRM-master process. The same reader will `<<` a client-supplied `shift` in `PixelFormat::pixel` (`vnc.rs:77`); a shift `≥ 32` panics on overflow in debug and is undefined-as-shift in release — FLAG on the exact rustc/release codegen, but the shift is unsanitized. Cap or reject `n`; reject `shift >= 32` / overlapping channel fields; the bind-all default is what the spec wrote, but it makes the alloc a network bug, not a local one.

3. **MEDIUM —** `host/linux/src/text.rs:511`. The CPU painter places glyphs with `LayoutGlyph::physical` (pixel snap + swash bitmaps) at `text.rs:476`. The GPU painter rebuilds runs from raw `g.x` / `g.x_offset` / `g.y` and then `draw_glyphs(...).hint(true)` (`gpu.rs:353`). The comment at `text.rs:508` claims these are “the same numbers the raster path snaps to pixels”; they are the pre-snap layout, and the CPU path then snaps and rasterizes a hinted bitmap. That is where subpixel bins, stem weights, and coverage will leave a band — more at `EXACT_SCALE != 1`. `tests/paint.rs:30` runs each assertion on each backend **independently**; it never diffs GPU vs CPU, and text only checks `darkest < 120`. Fills at `#eeeeee` can pass while glyph ink does not match. Drive both backends into one pixmap pair and assert a band; put GPU glyphs through the same `physical` positions (or document the deviation in LLP 1015). FLAG: cosmic-text 0.19 field units for `x_offset`/`y_offset` are not in the tree; if they are not ems, `glyph_runs` is additionally wrong. FLAG: vello 0.10 `Mix::Normal` + layer alpha (`gpu.rs:379`) vs tiny-skia’s isolated pixmap (`raster.rs` `push_opacity`) — motion tests only require ink to lighten by 60, not to match.

4. **MEDIUM —** `host/linux/src/gpu.rs:170`. The pipeline cache is `std::fs::write` in place. A crash mid-write leaves a truncated `pipelines-*.bin`. The next boot still sets `cached = data.is_some()` (`gpu.rs:134`) and reports “pipeline cache” even if wgpu dropped the bytes. Write to a sibling temp and `rename`; set `cached` from whether `get_data()` matched a validated load. Metal is fine: `PIPELINE_CACHE` is gated, so that path is not written. FLAG: wgpu 29 `fallback: true` is claimed in the SAFETY comment at `gpu.rs:140` to make corrupt bytes an empty cache “never a crash”; that is a wgpu/driver contract, not something this tree proves.

5. **MEDIUM —** `kernel/src/arena.rs:225`. An empty `TextInput` is measured as `" "`. CSS’s empty `<input>` strut is font metrics (ascent/descent/line-gap), not U+0020. A space has a non-zero advance, so min-content / shrink-to-fit width is a space glyph, not the UA `size=20` ch width and not zero. The painter does not use that space: empty value and empty placeholder paint `shown == ""` (`paint.rs:410`) and the caret height falls back to `font_size * 1.2` (`paint.rs:432`) while layout used the space’s line box. The 26 pt → 45 pt fix is real; calling it “the web’s rule” in LLP 1015 §6 is not. Measure a zero-width run that still produces a line box (or inject the strut from `normal_line_height`) and paint the same spec the kernel measured.

6. **MEDIUM —** `host/linux/src/vnc.rs:332`. On reader exit, `drop(writer)` detaches the writer. It can be blocked in `changed.wait` (`vnc.rs:241`) until the next `publish`. A client that disconnects on a static frame leaks a thread and a `TcpStream` until something dirties the display (Caltrain timers hide this; a still screen does not). Notify the condvar (or shut the clone down and wait) on teardown. RFB type `1` (`FixColourMapEntries`) is also missing from the reader match — FLAG whether Screen Sharing ever sends it; any client that does is disconnected as `unknown client message`.

7. **LOW —** `host/linux/src/display.rs:4`. r1 comments survived r2: display still says “nothing GPU joins at all: the painter is the CPU’s”; `host/linux/Cargo.toml` still describes the host as painting “with tiny-skia”. `QUEUE.md:125` still lists “the DRM path unexercised” under Linux gaps while LLP 1015 §6 records the minisforum KMS run. The code is the authority; these descriptions contradict it.

**Checked, not raised.** ABS span uses `.max(1)` (`input.rs:123`). With VNC, `poll` timeout stays `-1` unless motion/timers/images ask otherwise — no busy-loop, no wake on `publish`. Boot-time Auto → CPU is real; shader compile at `Gpu::new` matches the amended boot rule. Files are under 1,500 lines. `vello`/`wgpu` are ordinary `host/linux` deps, not a core-crate feature. 3.3 sends security type `2`, a 16-byte challenge, ignores the 16-byte reply, then `SecurityResult = 0`; 3.7 has no result after `None`; 3.8 does. That is “any password,” not a DES encrypt — honest in the spec. FLAG: we cannot execute a Screen Sharing handshake from these files.
