## BLOCKING

`contract/syntax/src/clock.rs:59` and `contract/cli/src/sources.rs:942`

`resolve_clock_timelines_in` runs before `splice_members` (`sources.rs:979`) and builds the names that shadow a timeline only from the component struct as parsed. `members.outer` is already filled, and the other file's states, derives, resources, mutations, and actions are not in that set.

```
timeline spin
component App
  members "./more.contract"
  view
    box animation-timeline=spin
      text "x"
```

```
members App
  state spin = 1
```

Written as one component, `spin` is a state, so `animation-timeline=spin` stays an identifier. Split, the clock pass rewrites it to `"-exact-clock(spin)"` and the animation runs on the timeline. The quoted form `animation-timeline="spin"` is refused with `contract-timeline-quoted` in the split program and kept in the one-file program. Same for any component whose view sits in a different file from the shadowing member.

Fix: when collecting those locals, include `c.members.outer` (the same kinds the pass already treats as shadows). Do that before the view walk, while `outer` is still set.

## MAJOR

`contract/lower/src/params/rewrite.rs:565` and `contract/lower/src/params/rewrite.rs:713`, called from `contract/cli/src/sources.rs:207`

`rewrite` walks `file.components` only, and it runs before the splice. The state and derive scan that refuses `param.` (`tamber-param-scope`) never sees a members block.

```
component App
  params
    title: string = "Hi"
  members "./more.contract"
  view
    text title="param.title" "x"
```

```
members App
  state title = "param.title"
```

One component refuses `tamber-param-scope` on the state. Split, the view's `param.title` is rewritten, the state is not scanned, and the program compiles with the state value left as the text `param.title`.

Fix: run that same state and derive scan on `file.members`. Any `param.` there is illegal, so the block does not need the host's param list.

`contract/cli/src/sources/uses.rs:276`

`reaches` walks `targets` (use edges) only. A `members` line is stored on `parts` (`sources.rs:828`) and is still a load edge: the host stays on the active stack while the members file loads, so a `use` back to the host is `contract-use-cycle`.

```
fn helper(): number = 1
component App
  members "./more.contract"
  view
    text `${n}`
```

```
members App
  state n = helper()
```

The members file does not see `helper`, so scope records `contract-use-missing`. `reaches(app, more)` is false, and `contract fmt --uses` writes `use helper from "./app.contract"`. The next compile refuses that line with `contract-use-cycle`. The cycle message that tells the author to move `helper` to a third file is skipped.

Fix: in `reaches`, also walk each unit's `parts[].unit`, host to members file, the same way `targets` is walked.

## MINOR

`contract/syntax/src/scope.rs:354`

`Rewriter::component` binds every `members.outer` name before it walks state initializers. The type checker, after the splice, gives an initializer only props, injects, and earlier states (`contract/types/src/component.rs:167` and `initializer_scope` at `1228`).

```
use helper from "./math.contract"
component App
  state n = helper(1)
  members "./more.contract"
  view
    text `${n}`
```

```
members App
  action helper
    n = 1
```

`math.contract` declares `fn helper(x: number): number = x`. The initializer's call is treated as the later action, so `rename` is skipped and `contract fmt --uses` does not add `use helper`. The compile then stops at `type-initializer-scope`. Writing that `use` by hand renames the call to the `fn`, which is what the initializer is allowed to call. Identifiers are unaffected: a later state is still refused by `initializer_scope` because idents are not rewritten.

Fix: bind another file's states, derives, resources, mutations, and actions only where this file's own members of those kinds are bound. Props and injects stay first. Action bodies, derives, resources, and the view already match the type checker, because those see every member.

## Checked and fine

Splice order matches the one-file vectors. `splice` inserts each kind at the index counted among the host's own members, last line first, so several lines, two lines at the same place, and `persist` (matched by name in `Component::persists`) come out in source order.

The single-file fast path (`sources.rs:836`) is safe. `prepare_members` runs first. A `members` line loads another unit or fails, and an unlisted block in the only file is `contract-members-unlisted`.

Cache and cycles: one unit per resolved path. Two lines, or a `use` and a line, share that unit and the second line is `contract-members-twice`. A line that names the file being loaded is `contract-use-cycle`. A block no line lists is `contract-members-unlisted`. Owner, twice, and duplicate spans carry the writing file's `source_id`, and `Sources::resolve` fills both the primary file and `related`.

A members file sees the component's props and injects through `declared` and `outer`, and a call to an action in another file stays the written name and resolves on the spliced component. A member whose name equals another file's `fn` or shape is handled by `declared` winning over `local`, with `unique_names` renaming that `fn` or shape when `bindings()` sees the member. A file that `use`s the `fn` rewrites the call to the unique name.
