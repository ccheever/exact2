# Review round 2, LLP 1121 stage 9 A1 (Apple draws icon paths), Grok 4.7 (xhigh)

**RIGHT WITH CHANGES.** Round 1's separate nonzero fills, `f32` text, Mac orientation, and path-icon tint all hold. Three of that round's fixes are still wrong in the cases below.

1. **SHOULD-FIX** — A path icon that returns to a centered fit keeps the stretched bitmap. `host/apple/Sources/ExactKit/IOS/NodeViewIOS.swift:615`. `layoutSymbol` stores the em-square image on `image`, then for any non-centered fit replaces `leaf.image` with a square of side `max(content.width, content.height)`. `object-fit: none`, and `scale-down` once the em square fits, set `contentMode` to `.center` and then skip that assignment. The image view keeps the previous bitmap and draws it at that point size. A 24-point icon that was scale-down in a 10-point box, then laid out at 40 points, stays a 10-point image in the middle. `object-fit` is not in `symbolKey`, so a style change does not go through `showSymbol` either. When the mode is `.center`, set `leaf.image` back to `image`.

2. **SHOULD-FIX** — The widget snapshot meet-fits the viewBox into the content box and ignores `object-fit`. `host/apple/Sources/ExactSnapshot/SnapshotLeaves.swift:259`. `symbol(fit:)` uses `fit` for an SF Symbol and not for `symbolPath`. Linux, the web, and the page hosts object-fit an em square (the font size) into the content box, then meet the viewBox into that square (`host/linux/src/paint/svg.rs:140`). A square viewBox with the default `fill` matches. A wide viewBox in a wide box does not: contain of `40×10` into `100×50` is a 50×12.5 icon on Linux and a 100×25 icon here. `cover` and `none` differ even for a square viewBox. Place the em square with the same object-fit (`fill` as contain), meet `IconPath.fitted` into that rect, and clip to the content box.

3. **SHOULD-FIX** — A template SVG on watchOS is refused as if it were not one colour. `contract/lower/src/icons.rs:195`. Excluding `watchos` at line 186 is right (no watch page draws the path), but a template still has an `svg`, so it takes the `tamber-icon-svg` arm. `not_template` and `fix` are both empty, and the diagnostic says `` `assets/…` is no one-colour shape () `` and `To fix it, ;`. When the file is a template, emit `tamber-icon-missing` and say a watch needs an `sf` source. Keep `tamber-icon-svg` for a real `not_template`.

4. **NIT** — Stage 6 F2 still says every target draws a template. `llp/1121-tamber.rfc.md:2950`. The stage 9 note says a watch still needs an `sf`. Add that exception to the F2 per-target sentence.

Round 1 otherwise holds. Each `;` path is filled on its own (`icon_path.rs:21`, `IconPath.swift:62`); a CoreGraphics probe of the same top-left buffer the pixel test reads shows a flipped `NSImage` bar at y=2 inking the top rows, so that test does catch an upside-down image. `format!("{v}")` is the shortest round-trip decimal. `iconPathTint` is never nil, so the Mac path does not fall through to `unsaidSymbolTint`. Tint and colour are applied on every `updateSymbol`; the source string is in `symbolKey`. Roles and `sf/` names send no path. The path props are priced three name-bytes high (`content_region.rs:396`, 26 against `symbolPath` + `symbolViewBox` = 23) and the 6× factor still over-admits. `NodeViewIOS.swift` is 1469 lines. The Xcode suite and the tvOS build were not re-run.
