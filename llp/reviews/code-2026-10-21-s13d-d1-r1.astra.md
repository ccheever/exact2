No blockers found. I found no build-output change in the refactor itself, but three issues in the write check:

1. **Major — Splitting font expressions loses whole-expression checks and diagnostic spans.** [contract/lower/src/theme/rows.rs:160](contract/lower/src/theme/rows.rs:160)

   `grouped()` replaces each conditional expression with separate literal rows, while lowering passes the complete expression to `tokens_named()`. For `column font=(on ? "a" : "b")` containing text, making `a` vary across an axis produces `tamber-inherited-axis` at `"a"` in the write check, versus the conditional expression’s span in the build.

   It also misses cross-arm validation: start with `a` and `b` both `400 1rem`, then change `a` to `italic 400 1rem`. Each isolated arm passes, so the write succeeds; the build rejects the complete choice with `tamber-type-longhands`.

   **Fix:** Preserve and judge complete `font`/`font-family` expressions under both designs. Add exact-diagnostic tests for conditional inherited-axis errors, differing longhands, and mixed token/literal arms.

2. **Major — An unchecked shorthand counts as having passed before.** [contract/lower/src/theme/rows.rs:453](contract/lower/src/theme/rows.rs:453)

   `.map(|_| ())` treats `tokens_named()` returning `Ok(None)` as success. In lowering, that result delegates to further validation.

   For example, start with token `choice = 1` and `text "x" font="choice"`. The build already rejects the unsupported shorthand with `lower-css-shorthand`, but this judge records success. Changing `choice` to `"Georgia"` then produces `tamber-kind`, and `check()` incorrectly blocks the write as newly breaking the row.

   **Fix:** Distinguish passed, failed, and unchecked results. Refuse only rows positively known to have passed before; alternatively, share the compiler’s fallback validation too. Add a regression for an already-invalid font shorthand changing to a wrong-kind token. This violates the before/after rule; it is not a demonstrated rejection of a successfully building after-design.

3. **Minor — Font-context interning is quadratic and source spans prevent useful deduplication.** [contract/lower/src/theme/rows.rs:136](contract/lower/src/theme/rows.rs:136)

   Every context linearly searches `seen`. `Fonts` equality includes `Attr`/expression spans, so identical inline `font-family` declarations at different source locations become distinct contexts. With N such elements, collection performs O(N²) comparisons and retains duplicate rows for subsequent checks.

   **Fix:** Intern contexts using a semantic key that excludes source spans, retaining diagnostic locations separately. Extend performance coverage through actual scanning/grouping with repeated inline font contexts. The current budget test constructs rows with `fonts: None`, so it exercises neither this path nor font validation.

The shared declared-font clone and lazy per-element `Fonts::of` construction look correct. The new tests cover direct tokens and class-derived families, but miss the cases above.
