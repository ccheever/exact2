1. **blocker — Shortened names can reassign existing mode IDs to different contexts.** [code.ts:113](/tmp/rv-e4-3/tools/figma-tamber/src/code.ts:113), [mapping.ts:155](/tmp/rv-e4-3/tools/figma-tamber/src/mapping.ts:155).

   Names are assigned in default-first order, but reconciliation looks up previous IDs by those names. With the test’s long axis name, `appearance-of-the-darker-scheme=black, light` and its Dark counterpart collide after truncation. Change only the export’s default from Light to Dark: the shortened labels exchange contexts, and the writer consequently exchanges what the existing IDs mean. Explicitly selected modes now show the wrong context. `contextsMoved()` reports no change, so no confirmation appears.

   **Fix:** reconcile through the full context string → previous mode ID. Reserve surviving contexts’ IDs before assigning new modes; treat shortened names solely as presentation.

2. **should-fix — Rollback runs for clean and already-undone attempts.** [code.ts:176](/tmp/rv-e4-3/tools/figma-tamber/src/code.ts:176), [code.ts:190](/tmp/rv-e4-3/tools/figma-tamber/src/code.ts:190).

   On a 1-mode file, the inner catch undoes the first attempt; `pull(doc, 1)` then throws before another write, and the outer catch triggers another undo. A foreign collection refusal also reaches undo before any mutation.

   Figma documents a history undo, not an idempotent restoration of a private snapshot. These paths rely on undocumented empty-commit behavior and risk affecting preceding history. The [test double](/tmp/rv-e4-3/tools/figma-tamber/src/code.test.ts:39) cannot expose that risk because repeated undo simply restores the same snapshot.

   **Fix:** validate and gather asynchronous reads before the mutation boundary; track actual changes per attempt and undo each dirty attempt exactly once. Verify both refusals in Figma with a preceding unrelated edit that must survive.

3. **should-fix — A missing stored ID falls back to an unrelated object’s name.** [code.ts:64](/tmp/rv-e4-3/tools/figma-tamber/src/code.ts:64), [code.ts:75](/tmp/rv-e4-3/tools/figma-tamber/src/code.ts:75).

   Delete the pulled collection, then create an unrelated `Tamber` collection containing `accent/fill`. `holding()` adopts it by name, without checking ownership, and Push can propose its values against the old baseline. Apply refuses the foreign collection, but Collect does not. Missing mode IDs similarly fall back to names.

   **Fix:** when a stored ID exists, make it authoritative. Report a missing object instead of falling back. Restrict any initial name lookup to explicitly accepted ownership.

4. **should-fix — Keeping the default mode deletes another context’s surviving mode ID.** [code.ts:119](/tmp/rv-e4-3/tools/figma-tamber/src/code.ts:119).

   In the new default-removal test, dropping `dark-style=black, light` makes the original default take `dark-style=dim, light`. That context’s existing mode ID is then removed. Its context survives, but explicit selections of its old mode lose their binding. The confirmation only describes bindings to contexts that disappeared.

   **Fix:** preserve surviving context IDs. If the default constraint prevents the requested reconciliation, refuse with an explanation or explicitly preview and confirm every additional ID replacement before applying it.

5. **should-fix — Family quoting remains incomplete.** [mapping.ts:112](/tmp/rv-e4-3/tools/figma-tamber/src/mapping.ts:112), [export_kinds.rs:254](/tmp/rv-e4-3/tamber/src/export_kinds.rs:254).

   **Fix:** quote apostrophes in the plugin serializer; escape quotes and backslashes in the importer. Test edited family lists through the actual import path.

6. **should-fix — Pull discards unread-value diagnostics.** [code.ts:161](/tmp/rv-e4-3/tools/figma-tamber/src/code.ts:161).
