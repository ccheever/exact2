## BLOCKER

**1. Unicode whitespace is trimmed; CSS does not trim it.** `contract/lower/src/icon_svg.rs:382`, `:404`, `:424`, `:439`, `:452`

`trim()` strips every Unicode White_Space character. CSS whitespace is only tab, LF, FF, CR, and space. `&#160;` (U+00A0) is a normal XML character, `decode` turns it into a real NBSP, and both the allowlist and `property` then delete it.

```xml
<path style="fill-rule: evenodd; fill-rule: nonzero&#160;" d="M0 0h4v4H0Z M1 1h2v2H1Z"/>
```

The reader’s last declaration becomes `nonzero`, so the template is nonzero. CSS keeps the ident `nonzero` plus NBSP, drops that declaration, and paints `evenodd`. The same trim on the property name (`&#160;fill-rule: evenodd` on a `<g>`, inherited by a nested path) makes the reader apply a rule CSS never sees. A trailing NBSP on an attribute (`fill-rule="evenodd&#160;"`) is the same hole: `attribute_refused` and `property` both trim it to `evenodd`.

Fix: trim only CSS whitespace in `importance`, `property`, `attribute_refused`, and the declaration name. Any other character stays in the token and fails the grammar.

**2. Parentheses in a skipped property invent a `fill-rule`.** `contract/lower/src/icon_svg.rs:376` and `:421`

`style_refused` and `property` both split on every `;`. Names in `STYLE_REFUSED_ELSEWHERE` skip value checks (`:386`). `(` and `)` are not in the token ban list. CSS only splits on a semicolon at parenthesis depth 0.

```xml
<path style="display: (; fill-rule: evenodd; display: block)" d="M0 0h4v4H0Z M1 1h2v2H1Z"/>
```

The allowlist accepts this: both `display` values are skipped, and `fill-rule: evenodd` matches the grammar. `property` records `evenodd`. The display lost-check sees `block)`, which is not `none`, so it does not fire. CSS sees one invalid `display` value; the semicolon sits inside the `(` block. The path keeps the initial nonzero rule. `display: (; fill: black; display: block)` on a path with `fill="none"` is the fill version: the reader paints black, CSS keeps `none`.

Fix: split declarations only at depth 0 in both `style_refused` and `property`, and refuse an unbalanced `(` `)`. `transform: scale(2)` stays one declaration, so the transform reason still names it.

**3. `fill: inherit` is legal and not computed.** `contract/lower/src/icon_svg.rs:335`, `:536`, `:637`

`color` and `fill-rule` drop `inherit` and keep the parent (`:540`, `:545`). `fill` stores the literal and passes it down. The grammar allows it on a style or a presentation attribute.

```xml
<g fill="none"><g fill="inherit"><path d="M0 0h1"/></g></g>
```

CSS paints nothing. The reader’s paint is the string `"inherit"`, which is not `none`, so the template is a filled shape.

```xml
<g fill="red"><path fill="inherit" d="M0 0h1"/></g>
<g fill="blue"><path fill="inherit" d="M2 0h1"/></g>
```

Both paints are the string `"inherit"`, so the one-colour check passes. CSS paints red and blue.

Fix: resolve `fill: inherit` the same way as `fill-rule` (initial fill is black). A child of `fill="none"` must stay `none`.

**4. The colour grammar accepts non-colours, including a transparent `rgb()`.** `contract/lower/src/icon_svg.rs:318` and `:649`

`rgb(` / `rgba(` / `hsl(` / `hsla(` accept any mix of digits and ` .,%/+-`, or those plus `d`, `e`, `g`. An empty argument list passes, because `Iterator::all` on an empty iterator is true. The translucent check only looks for `/`, an `rgba`/`hsla` prefix, `transparent`, and 4- or 8-digit hex.

`fill="rgb(0, 0, 0, 0)"` and `style="fill: rgb(0, 0, 0, 0%)"` are real CSS (comma alpha on `rgb()`), fully transparent, and become an opaque template. `fill="none"` plus `style="fill: rgb()"` or `style="fill: hsl(deg)"` is invalid CSS, so the browser keeps `none`, while `value_read` accepts it and the reader paints a solid.

Fix: accept only a real component list (three or four numbers or percentages; `deg` only as the hue unit). Treat a fourth comma component, or an alpha other than `1` / `100%`, as translucent. Anything else fails the grammar.

## MAJOR

**6. The JS call matcher misses ordinary spellings of the same call.** `contract/cli/tests/it/icon_path_readers.rs:192`

Fix: allow `?.` and whitespace before `(`, skip one level of grouping parentheses, and treat a regex literal whose pattern is `|` or `:` as that argument.
