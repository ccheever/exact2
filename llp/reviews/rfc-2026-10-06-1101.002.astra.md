# Round 1

**Overall assessment**

Yes—the experience supports Exact’s terminal direction, and most proposals address real problems. **I would approve the direction, but revise the plan before treating all sixteen changes as implementation-ready.**

The central lesson is larger than “test the writer”: **application state, computed layout, emitted output, and what the terminal currently displays are different states.** Input handling, retirement, inspection, and diagnostics need an explicit relationship to the last successful presentation.

My strongest objections are to P5’s equivalence between retirement and windowing, P7’s return to invisible default fields, and P14’s replacement of the workload that exposed a performance problem.

I read the RFC fully and skimmed the supplied context. This is a static, read-only review; no files changed. The bundle lacks the workspace root, runner implementation, and compiler lowering, so I could not run the suite, verify gate costs, or independently reproduce the reported measurements.

**Novel ideas**

1. **Make successful presentation produce one small internal receipt.** Include frame generation, input scope, geometry/origin, and printed prefix. Commit it after output succeeds. P1 observes it, P3 targets it, arming refers to it, and P5 consumes it. This could replace several loosely coordinated counters and caches without adding Contract vocabulary.

2. **Use equivalence tests to find bugs that screenshots miss.** Feed identical input sequences through different byte chunk boundaries; compare incremental output with a fresh repaint; compare paced versus batched settlement after both finish. Include hyperlinks, wide graphemes, cursor state, and attributes. These tests target invariants rather than one golden screen.

3. **Make style provenance inspectable through existing `layout`/`tree` output.** For a surprising three-row field, report which rows came from the terminal UA sheet, a class, or the element. The broader Exact lesson is that agents need to see effective defaults, not infer them from unexpected geometry.

**Open questions**

- **What exactly does “printed” acknowledge?** Successful write, flush, or terminal processing? Choose an implementable guarantee and name it accurately.
- **What is the supported transcript shape?** One vertical log, multiple logs, nested components, interactive children, or arbitrary CSS? Start narrow.
- **What bounds one unfinished block?** Define both computational cost and how a person inspects content above the live viewport.
- **Does layer opening retain the instant-menu constraint?** If not, explicitly replace it with a measured opening budget and correct invalidation.
- **What does `/clear` erase?** Model context, app transcript, current screen, terminal scrollback, or several separately specified things?
- **Is the harness now a daily tool?** That determines the priority of persistence, resume, and real context limits.
- **What may `exactSurface` carry?** I favor typed, read-only host facts; existing viewport facts and lifecycle events should retain their own established channels.

## Findings

1. **High — An open dialog gets printed into permanent transcript history.** [term.rs:385](/private/tmp/claude-501/-Users-ccheever-projects-exact2/99504d5c-e64b-441e-a7cc-ed36489b5317/scratchpad/code-review-1101.002/code/host/terminal/src/term.rs:385)  
   Open the model picker while a reply streams or paced stress runs. When another log entry settles, `host.render(from, count)` paints the open layers too: `paint()` overlays them on every requested slice. The writer therefore prints dialog content over transcript text, then acknowledges the obscured entries as printed, allowing retirement. This is an existing writer defect the new tests miss.  
   **Fix:** render settled transcript slices without layers or other transient presentation state. Test settlement while a dialog remains open.

2. **High — A multi-screen output burst can panic in the new VT collector.** [vt.rs:109](/private/tmp/claude-501/-Users-ccheever-projects-exact2/99504d5c-e64b-441e-a7cc-ed36489b5317/scratchpad/code-review-1101.002/code/host/terminal/src/vt.rs:109)  
   A four-row terminal booting a log with twenty short rows can scroll more than four rows in one 4096-byte chunk. `collect()` sets that larger scrollback offset before calling `screen().rows()`. In installed `vt100` 0.15.2, `visible_rows()` computes `screen_rows - scrollback_offset`; this underflows in debug builds. The subsequent `.take(take)` cannot prevent it.  
   **Fix:** collect frequently enough to bound the offset, or use a corrected scrollback reader. Add a single-frame, multi-screen burst test.

3. **High — Typed-ahead keys can still submit an unseen dialog field.** [keys.rs:172](/private/tmp/claude-501/-Users-ccheever-projects-exact2/99504d5c-e64b-441e-a7cc-ed36489b5317/scratchpad/code-review-1101.002/code/host/terminal/src/keys.rs:172)  
   Put an opener and a dialog containing an input with `submit=` in a fixture. Deliver `Enter`, `x`, `Enter` in one read. The first Enter opens and focuses the input; the remaining keys edit and submit it before any frame shows it. Both key-handler dispatch and `field_key()` precede the arming check. The new regression covers only button activation.  
   **Fix:** apply arming to activation through newly focused controls, including field submission and key handlers, and test this field-based sequence.

4. **Medium — Modal transitions leave incorrect birth records, causing both premature activation and dropped keys.** [host.rs:668](/private/tmp/claude-501/-Users-ccheever-projects-exact2/99504d5c-e64b-441e-a7cc-ed36489b5317/scratchpad/code-review-1101.002/code/host/terminal/src/host.rs:668)  
   Open a dialog, dismiss it without a handler/commit, then reopen it with two Enters in one read. `or_insert()` retains its old birth frame, so the second Enter activates it immediately. Conversely, editing inside a dialog invokes `after_commit()`, which removes background controls from `born`; closing without another commit never registers them again. A restored opener with only `commandfor` can then ignore Enter indefinitely.  
   **Fix:** reconcile birth records on every modal-scope transition, rearming newly exposed controls only after presentation.

5. **Medium — `printed` is still not scoped to its log, contrary to §0 P5.** [term.rs:343](/private/tmp/claude-501/-Users-ccheever-projects-exact2/99504d5c-e64b-441e-a7cc-ed36489b5317/scratchpad/code-review-1101.002/code/host/terminal/src/term.rs:343)  
   Print log A through child `"1"`, then replace it with log B. Changing `self.log` does not clear `through`; B can initially expose A’s acknowledgement. If B subsequently prints its own child `"1"`, publication is suppressed because the string equals `published`. A retirement task either sees stale acknowledgement state or misses the new acknowledgement. The harness’s globally increasing IDs conceal this.  
   **Fix:** associate acknowledgements and publication comparisons with a log generation, and make that scope available to retirement consumers.

6. **Medium — A second click can activate a dialog that the first click closed.** [pointer.rs:83](/private/tmp/claude-501/-Users-ccheever-projects-exact2/99504d5c-e64b-441e-a7cc-ed36489b5317/scratchpad/code-review-1101.002/code/host/terminal/src/pointer.rs:83)  
   Deliver two clicks on a dialog’s closing action in one input read. The first closes the layer; the second still finds its button in `presented.hits`. Because `layers` is now empty, `click()` presses that closed dialog button again. Closed dialogs remain mounted, so their handlers remain callable.  
   **Fix:** reject hits outside the current interaction scope, or invalidate the old scope’s targets until another frame is presented.
