**Changes required: one security BLOCKER remains.**

1. **BLOCKER — HTTPS loopback still permits framing another service on the viewer’s machine.** [pairing.ts:35](/tmp/rv-dt-t6s3r3/apps/design-tool/pairing.ts:35) checks HTTPS but does not exclude loopback. Pair through `https://127.0.0.1:7743`—for example, TLS carried through a tunnel—and a reply naming `https://127.0.0.1:8443/canvas/remote%3AAda%231/` with 43 `A` characters passes. The browser navigates to the viewer’s service on 8443; trusting port 7743 did not authorize it. Isolated probes confirmed this for `127.0.0.1`, `localhost`, and `[::1]`. [The new test](/tmp/rv-dt-t6s3r3/scripts/design-tool-scope.test.mjs:140) explicitly accepts this production path. Reject loopback canvas destinations; HTTPS alone does not establish that the host is another machine.

2. **SHOULD-FIX — The 10-second cleanup retains the grant in state and creates another persistent copy.** [app.contract:846](/tmp/rv-dt-t6s3r3/apps/design-tool/app.contract:846) assigns the entire grant URL to `canvasSettled`; `canvasAt.frame` remains unchanged. After settling, the iframe’s `src` and tree URL become clean, but [agent state](/tmp/rv-dt-t6s3r3/host/web-js/agent.js:464) exposes both copies. If entry stalls, a state capture at 12 seconds still contains an unspent grant valid until 30 seconds. The new slot also survives a failed refresh or revocation clearing `canvasAt`. The previously deferred state exposure remains, with an additional copy; the cleanup comment’s claim is incorrect. Use a non-secret settlement marker and clear or redact the grant-bearing values.

3. **SHOULD-FIX — Settling forcibly navigates the canvas and can interrupt entry.** [The timer](/tmp/rv-dt-t6s3r3/apps/design-tool/app.contract:818) changes [canvasSrc](/tmp/rv-dt-t6s3r3/apps/design-tool/app.contract:684) to `/` without knowing whether entry succeeded. If entry takes 12 seconds, the navigation at 10 seconds can abort it before the session cookie arrives; `/` then [returns 404 without a session](/tmp/rv-dt-t6s3r3/scripts/tamber-canvas.mjs:413). If entry succeeds quickly and the user navigates to another screen, the timer sends them back to the root and replaces the document. An established gateway cookie survives, but the running page does not. This follows the [HTML navigation rules](https://html.spec.whatwg.org/multipage/browsing-the-web.html#navigate). Cleanup needs an acknowledged handoff that preserves the running document.

The remaining URL unit test cannot detect premature mounting, timer-driven navigation, retained grants, or broken reload actions.
