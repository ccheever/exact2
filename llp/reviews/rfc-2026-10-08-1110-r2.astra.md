1. **Blocker — The proposed authoring syntax does not compile on native.** [D6](/Users/ccheever/projects/exact2-wt-laneC/llp/1110-live-snapback-reads.rfc.md:266) assumes Hermes can execute an async generator. The [resident bundler](/Users/ccheever/projects/exact2-wt-laneC/js/bake/src/resident.rs:154) preserves that syntax, then [bake invokes Hermes](/Users/ccheever/projects/exact2-wt-laneC/js/bake/src/lib.rs:995). I ran an in-memory Rolldown→pinned-Hermes probe: it fails with **“async generators are unsupported.”** This blocks bake and every native placement before the proposed prelude runs. **Fix:** specify build-time lowering to a supported iterator implementation, including generated source types, and verify `await`, yields, throws and `return()`/`finally` with the pinned VM.

2. **Blocker — Iterator identity arrives too late.** [D2](/Users/ccheever/projects/exact2-wt-laneC/llp/1110-live-snapback-reads.rfc.md:143) communicates iterator status through a yielded message. Before its first yield, an iterator awaiting HTTP is indistinguishable from an ordinary promised answer. The currently inspected [enqueue code](/Users/ccheever/projects/exact2-wt-laneC/runner/src/runner/commit.rs:1013) likewise derives `iterating` only from a carried count or `yielded`. Thus its first request remains keepable for newer arguments, contrary to D2. A finite iterator’s final `Answer::Now` also carries no evidence needed to enforce “resources only.” **Fix:** carry logical iterator identity from detection, independently of whether a message exists. Use it for keepability, mutation/worker refusal, admission and agent state. Reserve the 16-stream capacity then—not at the first message as [D4 says](/Users/ccheever/projects/exact2-wt-laneC/llp/1110-live-snapback-reads.rfc.md:218)—and list open, zero-message iterators in `state.streams`.

3. **Blocker — The message-plus-next-round transaction lacks complete failure and supersession semantics.** An iterator resumes through an ordinary HTTP outcome. [Ordinary fulfillment](/Users/ccheever/projects/exact2-wt-laneC/runner/src/runner/commit.rs:1289) releases a restored ticket only for admission, data or shape failures; [stream-message fulfillment](/Users/ccheever/projects/exact2-wt-laneC/runner/src/runner/commit.rs:1330) releases it for any settlement failure. A downstream trap can therefore restore an already-consumed iterator ticket, with no future reply. Also, [the next-round path](/Users/ccheever/projects/exact2-wt-laneC/runner/src/runner/commit.rs:1454) detects a superseding re-ask only by finding another pending ticket: an `ask_again` that answers `Now` must supersede the iterator too. [Discard](/Users/ccheever/projects/exact2-wt-laneC/runner/src/runner/commit.rs:1150) identifies only continuation requests, leaving HTTP-round cleanup unspecified. **Fix:** define atomic message/Store/count/next-request handling, terminal cleanup after failed settlement, and supersession by both `Now` and `Later`. Require cases covering initial-ask rollback, resumed-message rollback, `ask_again`, and equal-argument refresh.

4. **Blocker — “Every forwarding source carries it unchanged” is false.** [D2](/Users/ccheever/projects/exact2-wt-laneC/llp/1110-live-snapback-reads.rfc.md:146) misses adapters that reconstruct requests. [Storage replaces the entire request](/Users/ccheever/projects/exact2-wt-laneC/data/host/src/lib.rs:126), losing `yielded`. A main-placed TypeScript module sharing Store grants with a worker also passes through [Mixed’s turn envelope](/Users/ccheever/projects/exact2-wt-laneC/data/src/mixed.rs:369); the currently inspected [envelope rejects yielded answers](/Users/ccheever/projects/exact2-wt-laneC/data/src/envelope.rs:43). “Place this module on main” therefore does not resolve every refusal. [Placed additionally consumes continuation rounds internally](/Users/ccheever/projects/exact2-wt-laneC/data/src/placed.rs:378). **Fix:** explicitly preserve iterator metadata through request rewriting and envelope serialization, or refuse every unsupported composition accurately. Define reservation release per turn; do not implicitly hold an ordered set for the stream’s lifetime.

5. **Should-fix — Snapback’s idle polling breaks the claimed JS-target cancellation.** [D5 says every Snapback poll starts inside the pump’s `next()`](/Users/ccheever/projects/exact2-wt-laneC/llp/1110-live-snapback-reads.rfc.md:249), but [D8 repeats unchanged polls without yielding](/Users/ccheever/projects/exact2-wt-laneC/llp/1110-live-snapback-reads.rfc.md:306). After the first unchanged response, the next fetch starts after an `await` inside the same outstanding `next()`, outside the proposed synchronous ownership scope. An in-memory probe produced attachment flags `[true, true, false]` for the first three polls. Queuing `return()` cannot abort that third await. **Fix:** give every poll an explicitly owned abort signal; for example, return an iterator wrapper whose `return()` aborts its controller immediately before delegating to the generator. Check cancellation before repeating a poll. Test an unchanged timeout followed by forget.

6. **Should-fix — `seq` alone misses valid Snapback invalidations.** [D8 yields only when `seq` changes](/Users/ccheever/projects/exact2-wt-laneC/llp/1110-live-snapback-reads.rfc.md:306), although the server also wakes for [store identity and generation changes](/Users/ccheever/projects/snapback/snapback4/crates/snapback4/src/serve_changes.rs:67). The existing [Rust client checks all three](/Users/ccheever/projects/exact2-wt-laneC/snapback4/client/src/client.rs:940). Replacing a store or backend at the same sequence leaves readers stale; emitting another identical `seq` would still not re-ask them. **Fix:** retain the stream’s own `(store_id, generation, seq)` cursor, send `store_id` on subsequent polls, and make readers depend on an invalidation value that changes for any component. Test equal-sequence replacement and generation changes. The separate cursor and initial `wait=0` are otherwise sound.

7. **Should-fix — D3’s universal settle promise is not implemented by the executor plan.** [D3 excludes all iterator host work after its first message](/Users/ccheever/projects/exact2-wt-laneC/llp/1110-live-snapback-reads.rfc.md:163). However, JS-target [storage increments the global in-flight count unconditionally](/Users/ccheever/projects/exact2-wt-laneC/host/web-js/ts-data.js:185), independently of `rt.js` stream accounting. The wasm realm [holds and drains storage inside its current turn](/Users/ccheever/projects/exact2-wt-laneC/host/web/module-glue.js:226); simply relaying tag 4 does not define a yielded value plus a storage continuation. **Fix:** specify storage ownership, turn release and settle classification on both web targets, including storage issued after an await; otherwise narrow the supported iterator operations. Test `yield value; await heldStorageOperation()` across executors.

8. **Should-fix — Aborting the client request does not promptly free the server worker as claimed.** [D5 asserts that connection close frees Snapback’s long-wait worker](/Users/ccheever/projects/exact2-wt-laneC/llp/1110-live-snapback-reads.rfc.md:239). The proposed URLs omit `heartbeat=1`; [the server enables disconnect-detecting writes only with that parameter](/Users/ccheever/projects/snapback/snapback4/crates/snapback4/src/serve_changes.rs:23). Otherwise it waits on a [condition variable until a change or deadline](/Users/ccheever/projects/snapback/snapback4/crates/snapback4/src/serve_changes.rs:77), without checking the socket. Repeated refreshes can leave abandoned server waits occupying capacity. **Fix:** use the existing heartbeat mode and state its cancellation latency, or explicitly budget abandoned waits until timeout. Verify server-side worker release, not merely client abort.

9. **Should-fix — Loopback speed is not a delivery barrier.** [D3 claims B’s poll reply precedes A’s completed settle on loopback](/Users/ccheever/projects/exact2-wt-laneC/llp/1110-live-snapback-reads.rfc.md:183). The server [notifies waiting polls](/Users/ccheever/projects/snapback/snapback4/crates/snapback4/src/serve_ephemeral.rs:90); it does not await their execution, network delivery or B’s host pump. The surrounding conditional statement is honest, but this justification is not. **Fix:** require a bounded observation loop for real-network drives until B exposes the expected cursor/value. Scripted executor tests can retain exact deterministic delivery.
