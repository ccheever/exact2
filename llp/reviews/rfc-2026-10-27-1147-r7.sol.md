1. **An uncapped web `scrollend` timer can still wait forever without any scrolling.**

   [D7’s web row](/Users/admin/Developer/exact2-timer-wait-points/llp/1147-timers-that-may-wait.rfc.md:292) permits checks only inside `requestAnimationFrame` while the document reports visible. The [wake rule](/Users/admin/Developer/exact2-timer-wait-points/llp/1147-timers-that-may-wait.rfc.md:328) gives a held, uncapped timer no independent wake.

   Document visibility does not establish rendering availability. Chromium explicitly stops animation callbacks for offscreen cross-origin iframes while script execution continues. Page visibility follows the containing top-level page, so scrolling an iframe offscreen need not produce `visibilitychange`. ([Chromium’s rendering-throttling documentation](https://chromium.googlesource.com/chromium/src/+/HEAD/third_party/blink/renderer/core/frame#throttling), [HTML page visibility](https://html.spec.whatwg.org/multipage/interaction.html#page-visibility))

   Embed an otherwise quiet Exact app cross-origin in a visible page, then scroll its iframe offscreen before `after(100, save, wait=scrollend)` becomes due. Following D7, its deadline timeout requests an animation callback that never runs. There is no session scroll to end, no visibility transition, and no cap. The save remains unfired indefinitely while the iframe stays offscreen. R7 fixes the hidden-tab instance of r6’s failure, but rendering throttling leaves the same failure reachable.

   **Instead:** Define a timer-driven liveness path for render-throttled documents independently of page visibility, including how interrupted scrolls are retired. If that cannot preserve the chosen exclusion guarantee, explicitly refuse uncapped `scrollend` in embedded documents.
