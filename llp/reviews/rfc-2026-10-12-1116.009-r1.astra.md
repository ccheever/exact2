# GPT-6 Astra (xhigh) review of LLP 1116.009 r1

**Overall: READY WITH CHANGES.** D1–D6 are useful repairs, but insufficient as the main response to React’s persistent token gap and presentation wins.

1. **D1 — RIGHT.** Preserving elapsed virtual time across reload matches the operation being tested and removes a repeated debugging detour. Keep fresh-test initialization distinct from reloading an existing test; persistence and day-boundary behavior should remain testable together.

2. **D2 — WRONG DIRECTION as a silent root redirect.** Recovering from a blank page is right; replacing the requested URL conceals broken links and loses the user’s destination. Supply a recoverable missing-page fallback with a Home action, preserving the URL, and teach an authored `notfound` through the starter/pattern. Separately, `/event/999` **matches** a route: missing-record handling must be in the detail pattern. Root fallback cannot fix that failure. [Event grade](/Users/ccheever/bakeoff/rounds/r11/grades/event-rsvp/grade.md)

3. **D3 — RIGHT WITH CHANGE.** An opaque surface and desktop dialog directly address repeated failures. Apply the bounded form presentation only where sizing/presentation is unsaid; modal routes can also contain substantial editors. Preserve authored dimensions, backgrounds and navigation behavior. Coordinate this with LLP 1115.000 D4.8, which already specifies a wide-window card over a backdrop, so there is one implementation and presentation policy.

4. **D4 — RIGHT WITH CHANGE.** Fix accidental right-edge titles, but “as the iOS bar does” is insufficient justification for web presentation. Centering is a reasonable default for an inline dialog title, not a universal web convention. Explicit author alignment and layout must win; examples that author the unwanted layout need correction rather than host overrides.

5. **D5 — RIGHT WITH CHANGE.** Detect unintended loss of content, while distinguishing legitimate scrolling and intentional clipping. Also prevent the recurring repair: teach explicit `border-box` in padded percentage-width examples. Merely detecting the same mistake earlier still costs a repair cycle; changing the kernel’s bare CSS default would violate LLP 1115.

6. **D6 — RIGHT WITH CHANGE.** Consolidated help and complete vocabulary answers are useful, but expand the decision to reduce the **total onboarding and verification path**, with measured targets. A larger mandatory help screen could increase carried context unless it actually replaces other reads.

7. **D7 — RIGHT WITH CHANGE.** Generalize beyond water-tracker: content should determine width, grouping and hierarchy. The current [web-look recipe](/Users/ccheever/projects/exact2/docs/recipes/web-look.md) discourages a centered phone-width column, yet React’s winning water-tracker uses a focused centered composition. Teach when to constrain content and when multiple columns help. Avoid turning “one number” into a ban on useful contextual repetition.

Total tokens were approximately 913k versus 537k; cached input alone was 852k versus 472k. Fresh input plus output was actually slightly lower for Exact2. This does not support a fundamental authoring-language rewrite; it supports reducing context carried through orchestration. Existing `RingProgress`, `StatBar` and other parts already support much of this. Improve their composed examples and the guidance that selects them, rather than adding another component catalogue or pursuing unrelated extra features.
