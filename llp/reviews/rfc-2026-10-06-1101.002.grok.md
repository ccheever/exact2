## Concerns

**High — P4 fights LLP 1021, and it may be solving a bug the lowerer was already supposed to prevent.** §3 P4 makes a closed dialog or popover lay out as `display: none`, on every host, by a host-owned open bit. LLP 1021 D2 says the opposite for this machinery: the kernel lays the subtree out whether or not it is showing, and opening is no relayout and no dispatch (`llp/1021-menus.rfc.md:115-120`). The same RFC says a `dialog` tag lowers the HTML absolute-position default so a closed dialog consumes no flow (`:165-166`). The harness dialogs do not set `position` (`terminal.contract:290`, `:299`). HTML does use `dialog:not([open]) { display: none }`, and opening then does relayout. Exact already declined that for menus, on purpose.

`display: none` on a closed popover drops the instant-menu property. On a dialog it also means `layer_rows()` (`host.rs:709-712`) is 0 until a layout pass after open, so the inline writer cannot size the live region from the box it has. Paint already omits closed layers. The blank rows are flow contribution, which absolute positioning is there to remove.

What resolves it: before any kernel change, measure one closed `dialog` with no `position` attribute and report whether the root's height includes it. If it does, the defect is the terminal path not honoring 1021's absolute default. If it does not, P4 is a fix for a bug this tree no longer has. Keep popovers laid out while hidden either way.

## Novel ideas

- **Treat the virtual terminal as the framebuffer, and delete the second painter for anything called a screen.** The writer test, `examples/replay.rs`, and headless `print` are three viewers of one byte stream. The useful design is that there is one. A golden `.ans` for a scripted harness session (banner, picker, wheel, Escape, `/clear`, `/clear`, a mock reply) will catch the next round better than a general record/replay framework. `replay.rs` already prints scrollback and the screen. The missing piece is that the bytes come from the live writer, not from a file someone remembered to capture.

- **Make the assistant marker carry the model id into scrollback.** Scrollback is immutable and the status line is not, which is why Charlie could not reconstruct the session. `⏺ mock` or `⏺ sonnet` on the settled row is the attribution. It costs nothing at layout time, it survives `/clear`'s absence, and it makes P12 true even when the model never "changes." Keep it out of the history sent back to the model.

- **Check every user-agent sheet against the schema column it is injected into.** A test walks the terminal sheet and fails if a length is not legal for that row's `terminal` admission. LLP 1104's pixel padding would have failed in the same commit that added the sheet, with no merge and no person. The same test is the one that keeps the next GUI sheet from landing in a terminal entry. P7 is one sheet. This is the rule that makes the next sheet safe.

- **Make `/clear` a host operation on the log, with a generation the writer stores beside `printed_any`.** The epoch `each` exists so the log's node key changes, because that is the only signal the writer understands. The second `/clear` bug was that inference. A `generation` prop on `role="log"`, incremented by the app, is one signal. The writer clears when it changes and does not consult the printed set. The component in suggestion 7 can hide it. Apps stop wrapping the log in `each epoch in [session.epoch]`.

- **Fail a frame that asks where the cursor is and does not get an answer.** That single assertion in `Screen::feed` locks the inline coordinate space. The click test passing by manually calling `answered` is how the next query bug ships. The virtual terminal in P1 is this helper, finished.
