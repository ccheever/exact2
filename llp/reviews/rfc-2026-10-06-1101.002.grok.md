## Findings

### 1. High — headless scrollback panics in debug, then stops recording

`code/host/terminal/src/vt.rs:102`

`collect` treats `screen().scrollback()` as the number of stored rows. In vt100 0.15.2 that value is the view offset. The code sets the offset to `usize::MAX`, which clamps to `scrollback.len()`, reads that back as `len`, then calls `set_scrollback(len - at)` and `screen().rows()`. `rows()` builds its iterator with `rows_len - scrollback_offset` (`vt100-0.15.2/src/grid.rs:125`). The first window uses offset = the full scrollback length.

Failure: a 4×30 screen, ten `line i\r\n` writes, then that sequence. Debug run: offset 7, screen 4 rows, panic `attempt to subtract with overflow` at `grid.rs:125`. `cargo test` and `cargo run` are debug by default, so `settled_rows_are_written_once_and_a_tick_costs_bytes` (30×4, six adds, then `text(true)`) panics on the render that pushes scrollback past four rows, and so does headless `print --all` or `until` after more than one screen of history.

In a release build the subtraction wraps. The outer `take` still copies only scrollback rows for that window, so the text is likely right until the cap. I did not run a release build. At the 100_000 cap, `seen == len` stays true forever, so lines that scroll off after the cap never append to `scrolled`. `print --all` keeps the first 100_000 lines and drops the rest.

Fix: snapshot each newly scrolled row while the delta is at most the screen height (`set_scrollback(delta)` and read the top `delta` rows). Past the cap, append when the newest history row changes. Keep offsets ≤ the screen height.

### 2. High — inline resize draws before it knows where the cursor is

`code/host/terminal/src/term.rs:374`

On a size change the real terminal has already reflowed. `Inline::frame` still emits `CSI {cursor_row}A` from its remembered in-region row (`term.rs:374`), then `CSI J` and a full repaint (`resized` forces `fresh`, `term.rs:378` and `:412`), and only then `CSI 6n` (`term.rs:454`). `answered` (`term.rs:462`) only updates the click origin.

Failure: a 24-row inline region occupying rows 18–23, cursor on the last row (`cursor_row == 5`), history above. Widen the window. Reflow leaves the cursor on row 20. The writer moves up 5 to row 15, erases to the bottom, and repaints the region there. History that reflow put on rows 15–23 is erased. The CPR then anchors clicks to that damaged region. The LLP’s resize note says the size change asks where the cursor is so the live region can be re-anchored after reflow. The ask happens after the damage.

`a_resize_reanchors_the_pointer` (`tests/screen.rs:157`) boots 40×12, opens a short dialog, resizes to 30×10, and clicks `gamma`. The fixture fits, so the region stays at the top. vt100 `set_size` resizes rows and clamps the cursor; it does not reflow scrollback. Dropping the resize query leaves origin at 0 from the dialog-open query, and the click still hits. The test passes without the re-anchor it names.

Fix: on resize, write only the CPR and draw on the next frame from the answered row. Add a case with wrapped history above the region.

### 3. High — typed-ahead text enters a field the read just opened

`code/host/terminal/src/keys.rs:77`

`armed` (`host.rs:431`) allows a key only when `born < read_at`. `open_layer` records the new controls at the current frame (`host.rs:669`). Enter, Space, and shortcuts consult `armed`. `field_key` does not, and neither does the `key=` dispatch at the start of `key` (`keys.rs:172`). One stdin read sets `read_at` once and then dispatches every key in the buffer (`term.rs:673`).

Failure: focus is the harness prompt. One read contains `/key`, Enter, `sk-secret`, Enter (buffered while a frame was busy). Enter runs `onKey` → `sendText("/key")` → `showModal("keys")` (`terminal.contract:132`). The dialog’s autofocus password field is born this read (`terminal.contract:315`, `submit=saveKey`). The following characters insert in `field_key`. The second Enter hits `field_key`’s Enter arm (`keys.rs:155`) and submits, so `saveKey` stores the key before any frame showed the dialog.

`a_key_typed_ahead_does_not_reach_a_dialog_it_opened` (`tests/screen.rs:110`) sends two Enters to a button. The second Enter is armed and correctly does nothing. The test never sends a character to an autofocus field.

Fix: in `field_key`, and before dispatching `Event::Key`, require `armed`. A field already on screen still accepts input, because its `born` is older than `read_at`. Extend the test with characters plus Enter into an autofocus field.

### 4. Medium — `wheel` accepts a node that has no cells

`code/host/terminal/src/cli.rs:260`

§0 and the As built list say `tap`, `type`, and `wheel` refuse a node that is not on the screen. `tap` and `type` call `on_screen`. `wheel` calls `wheel_on` (`pointer.rs:115`), which walks the node and its parents and scrolls the first presented scroller.

Failure: the dialog list is three rows, `epsilon` is below it. `tap_refuses_what_is_not_on_the_screen` asserts `epsilon` is off screen. `wheel epsilon 1` still returns success and scrolls the list, because the list is an ancestor and is presented. The error text is “no scroller on the screen holds #id”, which is a different condition. The test never calls the verb, so deleting the `on_screen` check from `tap` would also stay green.

Fix: require `on_screen` before `wheel_on`. Point the test at the verb.

### 5. Medium — `until` matches scrollback

`code/host/terminal/src/cli.rs:287`

The verb comment and the failure string say the screen must show the text. The poll uses `vt.text(true)`, which is the screen plus `scrolled`.

Failure: a long transcript has pushed `hello` off the visible screen, or `/clear` has erased the screen with `CSI H CSI 2J` and left the line in scrollback. `until hello` returns on the first poll. The visible screen does not contain it.

Fix: search `text(false)`, or only rows appended since the verb started.

### 6. Medium — Page Up/Down moves the first scroller by almost the terminal height

`code/host/terminal/src/pointer.rs:105`

`page` takes `scrollers.first()` and scrolls by `size().1 - 2` rows. Paint pushes a scroller before its children (`paint.rs:230`, children at `:257`), so `first()` is the outermost. An open layer clears the list and records only the layer’s scrollers (`paint.rs:77`), which is right. The distance is the terminal, not that scroller’s `h`.

Failure: the model list (`terminal.contract:297`) is the dialog’s inner `scroll`, shorter than the screen by the title, the hint, and the region above the dialog. On a 24-row terminal, Page Down adds 22 rows. A viewport of about 15 rows skips a screen of models. The test app’s list is `max-height="3lh"`; Page Down there jumps by `rows - 2` and lands on the last item. A terminal shorter than 2 rows makes the delta negative, so Page Down scrolls up.

Fix: page the focused scroller, or the one under the cursor, by that rect’s `h` (keep a one-row overlap if you want one).

### 7. Medium — paced stress sleeps 30 ms and does not wait until the batch has retired

`code/apps/harness/data/src/commands.rs:303`

§0 P14 is screen-sized batches. §5 says each batch settles and retires before the next. As built says twenty at a time. The code uses `BATCH = 20`, pushes 20 entries, calls `changed()`, and sleeps 30 ms. It never reads `printed` or the host. A terminal of 8 rows and one of 60 both get 20. The comment says the pause is for the host to print and retire.

Failure: 20 large `/stress` entries take longer than 30 ms to paint and retire. The next 20 arrive while the first 20 are still on screen, which is the pile-up P14 is there to avoid. Whether 30 ms is enough at the ~2000 entries/s measured in 1101.001 depends on the machine and the entries. `paced_stress_releases_every_entry_in_batches` only checks that the data module’s entry count grows by multiples of 20. No host runs.

Fix: wait until the host’s `printed` id covers the batch, and size the batch from the screen height. Keep the burst form as the unpaced command.

### 8. Medium — `printed` is one global id, and a new log does not reset it

`code/host/terminal/src/term.rs:527` and `:342`

§0 P5 says `printed` is published after the bytes are flushed, JSON-escaped, and scoped to the log it came from. Flush-then-publish is in the live loop (`term.rs:620` then `:627`) and in `Vt::render`. `json_string` escapes quotes, backslashes, and controls. The record is only `mode`, `images`, `colors`, and `printed`. Replacing the log (`term.rs:342`) clears the screen and the printed set, and leaves `through` as it was. Publish runs only when `through != published` (`term.rs:627`, `vt.rs:81`).

Failure: a log prints child `"1"`, so `published` is `"1"`. A new log reuses ids from `"1"`. Its first child prints, `through` is `"1"` again, and the publish is skipped. A retire task keyed on `terminal.printed` never sees a change, so a new log whose only child is `"1"` is never retired. The harness avoids this only because `State::id` (`state.rs:236`) never reuses a number, including across `/clear`. The guide does not claim log scoping, so this is a §0 miss rather than a false guide sentence.

Fix: reset `through` and `published` when the log key changes, and put the log’s identity on the record the task reads.

### 9. Low — three headless verbs succeed without doing the operation

`code/host/terminal/src/cli.rs:264`, `:271`, `:310`

- `wheel epsilon nope` parses with `unwrap_or(1)` and scrolls one row.
- `resize soon` ignores an unparsable size and exits 0.
- `screenshot /no/such/dir/x.txt` prints the error and still exits 0.

An agent treats each as done. Fix: fail the process on a bad number, a bad size, and a failed write.

## Missing

- No headless case that a terminal-profile field is one row (fill, ink, disabled opacity 0.5, no border, no padding). That is the LLP 1104 failure this profile exists to stop. The screen-test fixture is compiled with `contract::compile`, which is `Profile::Web`, and it has no fields.
- No typed-ahead case that sends characters into an autofocus field.
- No resize case with wrapped history, and no assertion that would fail if the resize query were removed.
- `print --all` has no passing check that scrollback text matches what was printed. The test that reads `text(true)` hits finding 1 first.
- P4’s kernel change, P10’s lint, and P16’s launcher were cut on purpose. The closed-dialog row count test is present. P5’s view half was deferred on purpose; the printed record is only partly there (finding 8).

## Simplifications

- One scrollback snapshot, taken as each line scrolls off, replaces the full-buffer walk and the 100_000 second log.
- Page and wheel should share one choice of scroller and one row count from the presented painting.
- Resize should be a two-step state: ask, then draw. The queue of in-region rows goes away once drawing waits for the answer.
- `until` should read the visible screen, and a bad `wheel` or `resize` argument should fail the verb the way `tap` does.
