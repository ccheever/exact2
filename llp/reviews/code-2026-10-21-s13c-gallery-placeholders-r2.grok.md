**1. `handler()`.** A conflict falls back to `noop`. Comparison is on the type list only (`inert.rs:84`), which matches the type checker and the arity check: payload parameter names are not required to match the table. Two handlers with the same types and different names (`scroll`’s `scrollLeft`/`scrollTop`, `resize`’s `width`/`height`) are different `BTreeMap` keys, so `unique` gives the second action a `_2` suffix; one prop given to both keeps the first use’s names. A bare use on a `Use` is skipped (`inert.rs:73` matches only `Node::Element`). Uppercase tags parse as `Use`, lowercase tags as `Element`, and a `Use`’s children are still walked, so a pass-through to another component stays `noop`.

A non-handler attribute cannot produce a non-empty payload. `handler_parameters` is the payload table, and every event in that table is a handler. `resize=<ident>` is the resize event (two numbers), the same reading the type checker uses; a CSS `resize` is a string literal, which this walk does not look at. An empty non-handler use such as `aria-label=set` mixed with a real payload forces `noop`, and lowering already rejects an action on a string, bool, or number attribute, so that cell is refused either way.

Shadowing matches the compiler. `each` (`inert.rs:138`) threads a `for` item and its index into the body only, and a `match`’s `some.0` into the some-branch only (`:144`). The none-branch keeps the outer names. Props, state, and actions share one frame, so a state cannot hide a prop. The `Shadowed` fixture locks the `for` case: without the binding, `symbol` would become `"back"`.

**3. `names_symbol()`.** A role is assigned only when the image’s first positional is exactly `[Text("symbol:"), Expr(Ident(prop))]` and that ident is not shadowed (`inert.rs:108`). The first test locks that fallback: `symbol` is not a role, and the gallery writes `symbol="back"`.
