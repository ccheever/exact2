## Review (verbatim)

The RFC’s native shape is sound: one reserved request, callback to the source, and `ASWebAuthenticationSession` for a private-use scheme. It is not ready to build. The first consumer is AT Protocol OAuth (PKCE + PAR + DPoP), and the web arm as written cannot complete that flow. D3 also treats Apple’s custom-scheme matcher as path-exact, which it is not.

## Findings

### 1. BLOCKER — PAR puts `state` and PKCE outside the authorize URL; D4 and D7 still parse that URL

AT Protocol OAuth requires PAR (RFC 9126). The authorize URL the host opens is `authorization_endpoint?client_id=…&request_uri=…`. `state`, `code_challenge`, `code_challenge_method`, and `redirect_uri` live in the PAR body. RFC 9126 forbids repeating those parameters on the authorize request.

D4 has the web glue check that “the URL’s `state` matches the request’s.” The request body in D1 is `{url, callback, ephemeral}` — there is no `state` field, so the glue can only parse `url`. On the Bluesky path that parse is empty. Either the glue treats missing `state` as a match (CSRF check gone) or it refuses every PAR callback.

D7 has the same assumption: `state.pending` is there so a test can read `code_challenge_method=S256` and `state` from the query, and `--answer auth=` substitutes `{state}` from “the request’s `state`.” Those values are not in the query. The fixture cannot mint a callback whose `state` matches what the source stored.

**Resolve:** Put `state` on the request body and in `pending.args`. The host compares the callback’s `state` to that field. Tests assert `pending.args.state` and `request_uri`. The source still checks `state` and `iss` (RFC 9207) before the token POST (D6 step 6). Do not parse OAuth fields out of the authorize URL.

### 2. BLOCKER — Web popup channel: `opener.postMessage` plus a `closed` poll fails under COOP. Touches ruling Q4

D4 opens `url` with `window.open`, has `/.exact/auth/callback` post `location.href` to `window.opener` (target: the page origin), and treats `closed === true` on a 500 ms poll as 499.

Authorization servers commonly send `Cross-Origin-Opener-Policy: same-origin` (Google and GitHub do; this RFC’s motivation names both). After that header, the opener’s `WindowProxy` is severed: `window.opener` in the popup is `null`, and Chrome reports `closed === true` on the opener’s reference while the popup is still up (Chrome COOP/`closed` behavior). The glue then answers 499 while the person is still signing in, and the callback page’s `postMessage` never arrives. If `closed` stays false and `opener` is null, the request waits forever; D4 has no timeout.

Ruling Q4 forbids a **redirect** fallback (navigating the app window). A same-origin relay after the provider redirects to `/.exact/auth/callback` is a different channel: `BroadcastChannel`, or `localStorage` plus a `storage` event. Those survive COOP because the callback document is the app origin. Q4 still stands; the popup channel as written does not.

**Resolve:** Keep the popup. On the callback page, post via `BroadcastChannel` (and `opener.postMessage` if `opener` is still there). Complete on the first authentic message. Treat `closed` as 499 only when no message arrived **and** the channel is idle; do not take `closed === true` as cancel by itself. Bound the wait.

Also: check `event.source === popup` as well as `event.origin` (D4’s origin check). Ticket-named `window.open` names are guessable (`host/web/glue.js` tickets start at 1 in the TS executor, `js/src/prelude.js:139`). Use an unguessable name or none.

### 3. BLOCKER — The source’s `redirect_uri` on the web is the HTTPS callback page; the sample always sends the native scheme

D2/D4: the bake maps a granted native callback to `https://<app origin>/.exact/auth/callback`, and the provider registers that URL. D1’s sample still calls `openAuthSession(url, { callback: 'social.exact.bluesky:/oauth' })` with a `url` the source built.

The host opens `url` unchanged. The AS redirects the popup to whatever `redirect_uri` was in PAR. A `social.exact.bluesky:` redirect inside a browser popup does not load the static page, so postMessage never runs. The bake mapping of the **grant** does not change the **protocol** `redirect_uri`.

**Resolve:** The source sends the redirect URI this host will actually receive: native `social.exact.bluesky:/oauth`, web `https://<origin>/.exact/auth/callback` (pin trailing slash vs `index.html`; OAuth matching is exact). `openAuthSession`’s `callback` option is that same string. Client metadata lists both. Give the source a way to know the web callback (documented well-known path plus `origin` from `app.json` / the page).

### 4. BLOCKER — D3 says Apple matches the full callback, path included; `.customScheme` matches the scheme only

D3: “Only a URL matching the full granted callback, path included, completes the session,” attached to `ASWebAuthenticationSession.Callback.customScheme(scheme)` / `.https(host:path:)`.

Apple’s `Callback.https(host:path:)` (iOS 17.4 / macOS 14.4) matches host and path; query is allowed. `Callback.customScheme(_:)` and the older `callbackURLScheme:` initializer match **the scheme only**. The first consumer’s callback is `social.exact.bluesky:/oauth`. A completion of `social.exact.bluesky:/anything?code=…` satisfies Apple’s matcher.

RFC 8252 §8.10 requires the client to match the entire redirect URI. PKCE still binds the code to the verifier; path matching is the host’s half of that rule.

**Resolve:** After every successful completion (both callback kinds, including the 17.0 `callbackURLScheme:` path), the host accepts the URL only if scheme, host, and path equal **this request’s** `callback` (query and fragment allowed). Compare to the request’s callback, not to any granted callback. Then fulfill 200. Document that Apple’s matcher is insufficient for private-use schemes.

The 17.0 / 14.0 floor vs 17.4 / 14.4 `Callback` API in D3 is right (`host/apple/build.mjs:85-86`). HTTPS callbacks answering 501 below 17.4 is right. An app that wants HTTPS callbacks raises `minimumOS` or lives with 501.

### 5. BLOCKER — The callback page’s script will not run under the render server’s CSP

D4: bake emits `/.exact/auth/callback/index.html`, “about twenty lines,” which posts `location.href` and closes.

`host/render/src/serve.rs` `csp()` (`:1256-1267`) sets `script-src` to `'self'`, `'wasm-unsafe-eval'`, and sha256 hashes of `capture()`, `module-prelude.js`, and `app.js`. There is no `'unsafe-inline'`. An inline script on the callback page does not run. The popup never posts. Same hang/false-499 as finding 2.

`frame-ancestors 'self'` is already there (`:1266`), which is what you want for this page.

**Resolve:** External script at a same-origin URL (`'self'`), or add this file’s sha256 to `csp()` the way `capture()` is hashed. Pin that in D4. No third-party script on that page.

### 6. BLOCKER — `window.open` has to run in the press batch; today’s `request` op does not. Touches ruling Q4

D4: a press gives transient user activation; “the glue executes a request in the batch that follows it.”

A press is synchronous: `click` → `send(wasm.exact_dispatch(…))` → `applyBatch` (`host/web/glue.js:490`, `:813-814`). The `request` op then does `httpHelpers().then(({ request }) => request(op, host))` (`:695-697`). `httpHelpers()` is `moduleReady.then(() => loadAfterPaint('./http-body.js', …))` (`:7-8`). That is at least a microtask, and may wait on after-paint load. Safari’s `window.open` policy is the user-activation call stack of the click. The survey already lists this as unmeasured (LLP 1069 §7 open item 6).

Worker-placed sources (LLP 1027.002) produce the request on another thread; activation is already gone when the glue runs.

Ruling Q4: a blocked popup is 428 and the person taps again. If `window.open` always runs off the click stack, Safari 428s every time and tap-again does not help.

**Resolve:** For `exact-auth:`, call `window.open` synchronously inside `apply()` in the press batch, before returning from `send()`. Do not go through `httpHelpers().then`. Worker-placed `exact-auth:` answers 428 (or require main-thread placement for this request). Measure Safari.

### 7. MATERIAL — D3’s 409 and 1016 D5 supersession both apply, and they collide

D3: at most one session per window; a second is 409; when the runner forgets the ticket, the host `cancel()`s.

LLP 1016 D5: a resource has one in-flight request; new arguments forget the old ticket and send a new one. Double-tap sign-in is that case: forget ticket 1, send ticket 2.

If the host 409s ticket 2 because ticket 1’s sheet is still up, the successor never starts. If it `cancel()`s ticket 1 and starts ticket 2, 409 is wrong. Completion after `cancel()` can still fire; `host/apple/src/executor_core.rs:241-284` already drops forgotten HTTP outcomes. The auth arm needs the same “ticket still held” check before 200/499 (`host/web/glue.js:678` uses `exact_request_active` for surfaces).

**Resolve:** One live session per window. A request that **supersedes** that session’s ticket: `cancel()`, then start. A request for a **different** live session in the same window: 409. Fulfill only if `holds(ticket)` is still true. Supersession does not fulfill 499.

### 8. MATERIAL — `exact-auth:` has to leave the ordered HTTP lane, as `native.later` does

LLP 1067 D3 puts `native.later` on the independent lane with a 1 MiB ceiling and `handoff` (`host/apple/src/executor_core.rs:419-421` is `is_native()` only). Default `Request::post_json` is ordered (`runner/src/request.rs:122-133`; TS `fetch` is ordered unless `exactIndependentHttp` is set, `js/src/prelude.js:132-140`).

An auth sheet lasts minutes. On the ordered lane it holds every subsequent ordered fetch and storage job for that time. Apple routing today sends non-native, non-continuation work to the HTTP executor (`host/apple/src/abi.rs:223-228`); `exact-auth:` would be grant-refused as a URL.

**Resolve:** `Request::is_auth` next to `is_native`. Presenter-owned, handed off, independent, small ceiling (callback URLs are tiny). TS `openAuthSession` sets `exactIndependentHttp` the way `native.later` does (`js/src/prelude.js:309`). Host grant check is `auth.session` / `auth.callback`, using `net.fetch` origin grammar (`host/web/glue.js:864-877`), before any HTTP.

### 9. MATERIAL — Unregistered private-use scheme is the right pattern; the stated reason is wrong

D2: a private-use scheme “needs nothing”; not registering it “keeps another app from claiming the callback.” RFC 8252 §7.1 / §8.1.

`ASWebAuthenticationSession` intercepts the redirect inside the session. That is why the code never becomes a LLP 1038 D8 `navigate` event, and why `CFBundleURLTypes` should stay empty. Another app can still register the same scheme. Non-registration stops **this** app from receiving the URL via `openURL` if the session fails. Unique reverse-DNS plus PKCE is the interception mitigation.

The kill-resume sentence in D6 step 2 (“an app killed while the sheet is up can finish”) does not hold on this design: the session dies with the process, and with the scheme unregistered there is no incoming URL to finish with. Still store verifier and `state` before `openAuthSession` (needed for in-process completion).

**Resolve:** Rewrite D2’s rationale around session interception and the rejected `navigate` path. Drop the kill-resume claim. Keep the scheme unregistered.

### 10. MATERIAL — Sample grants and D6 step 7 are not enough for the Bluesky OAuth source

D1 sample: `net.fetch https://bsky.social`, `auth.session https://bsky.social`, `auth.callback social.exact.bluesky:/oauth`, `secret.keep bluesky.session`.

The running port’s grants are already wider (`bluesky-exact2/data/src/session.rs:20`: `*.host.bsky.network`, public AppView, `bsky.session`, `bsky.theme`). OAuth discovery as D6 step 1 writes it also needs the PDS `/.well-known` documents and typically `plc.directory`. Verifier/`state` and the DPoP key need their own `secret.keep` names (1069.005 D1b uses `bluesky.dpop`). `GrantSet::parse` rejects unknown capabilities (`vendor/ibex/crates/ibex2/src/grant.rs:355`); `io_grants` today only strips `surface.*` (`runner/src/request.rs:20-26`). `auth.*` (and 1069.008’s `device.*`) must be stripped or every host fails to parse grants.

D6 step 7: refresh “as the port refreshes an app-password session today (`refreshSession`), with a DPoP proof.” App-password refresh is `com.atproto.server.refreshSession` (`session.rs:141-152`). OAuth refresh is `grant_type=refresh_token` at the **token endpoint**, DPoP-bound (RFC 9449). Following step 7 as written cannot refresh an OAuth session.

D6 step 6’s `iss` check (RFC 9207) is load-bearing for AT Protocol (many authorization servers). The host answers 200 for any URL that matches the request callback; mix-up defense is the source’s.

**Resolve:** Expand the sample grants. Strip `auth.*` in `io_grants`. Name OAuth refresh as the token endpoint. Keep `iss` + `state` as a source MUST.

### 11. MATERIAL — HTTPS callbacks need `webcredentials:` in the entitlement **and** the AASA; the cited helper emits `applinks:`

D2: an https callback “needs an associated domain (`webcredentials:host`)” and “joins the domains `host.ios.associatedDomains` produces (`host/apple/build.mjs:435`).” LLP 1069.008 D2’s table agrees on `webcredentials:host`.

`build.mjs:435` prefixes `applinks:` (boolean `true` → `applinks:${origin host}`; arrays are copied as given). `host/web/build.mjs:322-324` writes AASA with `applinks` only. Apple’s `Callback.https` requires the **`webcredentials`** associated-domain service; RFC 8252 §7.2’s claimed HTTPS URIs are Universal Links (`applinks:`). D8 passkeys also need `webcredentials` AASA.

First consumer uses a private-use scheme, so this is not on the critical path for Bluesky’s first cut.

**Resolve:** From `auth.callback https://host/path`, write `webcredentials:host` into the entitlement **and** a `webcredentials.apps` entry in AASA. Leave `applinks:` to LLP 1038 D8 routing. Cite RFC 8252 §7.2 as the product intent; cite Apple’s `webcredentials` requirement as the session API.

### 12. MATERIAL — Session object lifetime, presentation context, and callback matching algorithm are unspecified

D3 creates `ASWebAuthenticationSession` on the main thread and sets `presentationContextProvider`. The host must **retain** the session until the completion handler runs; releasing it cancels. `start()` returning `false` (nil anchor, no scene) is 502.

Match algorithm to pin: scheme + host + path equal the request `callback`; query and fragment ignored for the grant and allowed on the result; reject userinfo, unexpected ports, and `http:` for claimed HTTPS. Private-use form is RFC 8252 §7.1 `scheme:/path` (one slash); pin that exact string in client metadata.

Agent journal: runner `Outcome::summary` never includes a body (`runner/src/request.rs:290-295`); `enqueued` logs `POST exact-auth:` (`runner/src/runner/lines.rs:63-78`). That supports D1’s claim for the runner journal. LLP 1069.007 D3 journals device answers; D7 here must say the auth line is `device auth <ticket> answered` / `cancelled` with **no callback URL**. `--answer` / `type @t` still carry a fixture URL in the driver command; production agent mode is off.

## Strengths worth keeping

- **One reserved request, no new field** (D1), same seam as `native.later` (LLP 1067 D1): tickets, `pending`, supersession, failure-as-data, worker placement.
- **Callback to the source**, never `navigate` (rejected LLP 1038 D8). Authorization code is an HTTP-shaped body `parse` consumes; runner journal and `state.store` already omit bodies and secret values (`request.rs:290-295`, `agent.rs:556-563`). Same rule as LLP 1018 D5.
- **Two grants** with the existing one-capability-one-target grammar (`grant.rs:290-294`): `auth.session` allowlists where the sheet may go; `auth.callback` allowlists where it may return.
- **Private-use scheme unregistered** with `ASWebAuthenticationSession` (D2/D3), and WKWebView / `SFAuthenticationSession` refused. Right pattern for RFC 8252 on Apple.
- **Protocol left in the source** (D6): PKCE, PAR, DPoP, token POST, `secret.keep`. Host cannot enforce PKCE when PAR hides the challenge; putting it in the app is honest.
- **DPoP key home follows LLP 1069.005 Q3** (ruling Q3): JWK under `secret.keep` natively, non-extractable `CryptoKey` in IndexedDB on the web (where `secret.keep` is `localStorage`, `glue.js:633-641`).
- **PAR before the press** on the web (D4) is the right authoring rule for activation.
- **Substitute** (D7) matches LLP 1069.007 D3/D4/D7: `capability: "auth"`, `type @t` / `tap @t cancel`, `--answer auth=`, `delivery: "substituted"`, no CDP override.
- **Linux 501** (D5) written down instead of a third shape.
- **OS-version split** in D3 for `Callback.https` vs `callbackURLScheme:`.
