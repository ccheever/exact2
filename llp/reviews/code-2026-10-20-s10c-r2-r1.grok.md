## Blocking

1. **Every URL in the ACME document is fetched.** `scripts/tamber-acme.mjs:56` (directory, `newNonce`, `newAccount`, `newOrder`), `:74` (`Location`), `:90` (`authorizations`), `:100` (`challenge.url`), `:104` (`finalize`), `:105` (`certificate`). `fetch` follows redirects, so a 307 carries the signed POST off-origin. Nothing requires `https:` or the directory’s origin. `res.json()` / `res.text()` buffer the whole body, and `until` (`:79`) only checks `patience` after `post` returns, so a peer that never answers leaves `certify` stuck: the connector stays up and relayed clients are never admitted.

2. **The TXT name is whatever the server puts in the authorization.** `scripts/tamber-acme.mjs:92` skips an already-`valid` authorization with no identifier check. `:96-98` publishes `_acme-challenge.${authz.identifier.value}` even when that is not one of `names`. `scripts/tamber-relay.mjs:93` writes it into `txt: ${record} ${value}` on the connection that just sent the bearer token, so a CR, LF, or space in the identifier adds another relay command. `dnsHook` (`scripts/tamber-relay.mjs:116`) does not interpolate the record into `sh -c` (env only, `stdio: 'ignore'`), but it also does not limit the bytes, and `:118` puts the raw record in the error that gets logged. The digest is bound to this account’s thumbprint, so this is not a cross-account DNS-01 theft; it is still a confused deputy into the hook and a header injection into the relay.

3. **The name check accepts a certificate that does not cover the wildcard.** `scripts/tamber-acme.mjs:109` uses `checkHost(n.replace(/^\*\./, 'x.'))`, and `fits` (`:146`) uses the same probe. For a requested `*.acct.relay.test` that probe is `x.acct.relay.test`, and `checkHost` is truthy for a certificate whose only SAN is `DNS:x.acct.relay.test` (returns that name) and for `DNS:*x.acct.relay.test` (partial wildcards default on). Neither covers `s1-tool.acct.relay.test`. The key check at `:108` is real. `scripts/tamber-remote.mjs:441` then sets `held` with no `covers()` on the session names, so clients are taken on that certificate. A bad certificate is also what `fits` will keep.

4. **A refusal does not stop ACME.** `connectRelay` never resends a refused token (`scripts/tamber-relay.mjs:161`). `ended` (`scripts/tamber-remote.mjs:396`) runs once and `clearInterval`s `renewal` while it is still null. The in-flight `get().then` at `:442` arms the daily interval anyway. After a revoke or `close()` during issuance, that interval keeps calling `relayTxt` / the hook for the life of the process. `hold()` throwing inside that callback is also outside the rejection handler: `held` stays null, the connector is not closed, and nothing retries.

## Should-fix

5. **`keyAt` follows links.** `scripts/tamber-acme.mjs:120-123`. `existsSync` / `statSync` / `readFileSync` use the target. A symlink already at `key.pem` or `account-key.pem`, mode 0600, is the account key or the certificate key. `keep` (`:128-132`) only replaces a link on write (`wx` + `rename`). `lstat` and refuse anything that is not a regular file; do the same for the directory before writing.

6. **The wildcard is not tied to this account.** `scripts/tamber-remote.mjs:389` and `:437`, `parentOf` at `scripts/tamber-relay.mjs:78`. With no certificate yet, any same-parent pair is accepted, including `a.com` / `b.com`, and the order is `*.<that parent>`, not `*.<account>.<relay host>`. Let’s Encrypt will refuse a public-suffix wildcard; a hostile relay still chooses the order. The stub’s suffix check (`scripts/tamber-relay.test.mjs:52`) is not in this client.

7. **The DNS hook is given the relay token.** `scripts/tamber-relay.mjs:116` copies `process.env`, including `EXACT_RELAY_TOKEN`, into the hook. Scrub that variable. Output is discarded; the timeout is 300s (`:117`).

8. **Tests miss the checks above.** They would still pass if those checks were deleted. `scripts/tamber-acme-stub.mjs:50` accepts `jwk` on every request, so a client that never sends `kid` still passes. `scripts/tamber-acme.test.mjs:21` only checks a stub certificate that really is the wildcard; nothing feeds a leaf for `x.<parent>` or a different key. `scripts/tamber-relay.test.mjs:719` asserts the stub’s refusal, not that the client declines to send the name. The hook test (`:731`) never checks `clear`, stdout, or a metacharacter in the record. `relayTxt` has no untrusted-certificate case (the pool dial does, `:213`). `csr`’s unit test (`scripts/tamber-acme.test.mjs:70`) only looks for the name bytes; the stub and an `openssl req -verify` do check the signature.
