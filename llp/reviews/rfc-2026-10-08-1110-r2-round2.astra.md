1. **Blocker — A refused refresh can restore a ticket whose iterator was already destroyed.** In `js/src/lib.rs:884–903`, a new HTTP-backed call immediately replaces and forgets the old call. But `runner/src/runner/commit.rs:103–153` restores the old pending ticket if settlement refuses. With equal arguments, `js/src/turns.rs:120–125` retains the replacement because both HTTP rounds have `continuation: None`; the old HTTP reply can then resume the new iterator. This leaves the transaction fold in RFC lines 196–203 incomplete. **Fix:** preserve logical-call identity on HTTP rounds and defer supersession cleanup until the commit stands. Test an equal-argument refresh followed by a downstream refusal, then deliver the original reply.

2. **Blocker — Shape failures strand native and wasm iterator calls.** `js/src/lib.rs:937–939` removes the parked call before decoding its next message; a shape error at lines 688–696 or 1006–1008 returns without re-parking or calling `__exact_forget`. Consequently, `forgotten` cannot find it, while the prelude still holds the iterator, its next fetch and its reservation. The wasm path similarly removes `waiting` before validation (`js/web/src/lib.rs:233–236,335–343`), and only sends forget when its remaining tables shrink (`695–705`). This contradicts D2’s failure cleanup and D4’s released reservations. **Fix:** retain the call identity through validation and explicitly retire it on every decoding, shape or budget failure. Test repeated malformed yields, checking `finally`, outstanding work and capacity recovery.

3. **Blocker — The JS target has two iterator-lifetime leaks.**
   - `host/web-js/ts-data.js:294–325` releases the reservation on failure, but neither stops subsequent pulls nor calls `return()`. `rt.js:405` removes the terminal ticket from `Open`, preventing subsequent abort cleanup. An in-memory probe produced a terminal shape error, then another pull and delivery when the outstanding wait resolved, with zero reservations and no `return()` call.
   - Reservations are acquired during `answer` (`ts-data.js:381–383`), before the opener runs. A discarded reread (`rt.js:507–508`) or rolled-back commit (`188–194`) never releases them. A probe exhausted all 16 slots without starting any opener.

   **Fix:** give each iterator an idempotent disposal operation covering failed pumping, discarded answers and rollback. Guard pumping and flushing after disposal, cancel scheduled flushes, and release each reservation exactly once.

4. **Should-fix — The promised browser Worker refusal is missing.** RFC D6, line 332, promises the same named refusal as native worker placement. However, `host/web/module-worker.js:139–150` ignores the iterator marker on tag 3, and its `finish` handles only tag 1 (`103–113`). A worker-marked prelude probe returned a marked tag 1 and subsequently tag 4. Thus it can issue the first poll, then fail with “fetch has no URL” when tag 4 arrives without an attached request (`js/web/src/lib.rs:352–357`). **Fix:** reject and forget the iterator at the Worker’s initial marked reply, before pumping it further. Refusing worker placement is consistent with the recorded scope; this implementation does not enforce that refusal.

5. **Should-fix — Storage settlement changes Contract’s `pending(resource)` semantics.** RFC D1, lines 85–90, preserves “false after the first message”; D3 separately makes local work hold settle. But `runner/src/runner.rs:311–313` classifies an iterator’s local rounds as in flight, and `commit.rs:1082–1089` uses that same predicate for `pending_res`. Consequently, storage after a message makes `pending(resource)` true natively, while the JS target keeps it false (`host/web-js/rt.js:475–476`). **Fix:** separate the resource’s first-message pending flag from the host’s settle-work predicate. Test a yield followed by storage and another network wait, comparing Contract output and agent state across executors.

6. **Should-fix — Native lowering misses valid async-generator syntax.** `js/bake/src/typescript.mjs:149–156` detects generators with a whitespace-only regex and skips `node_modules`. The valid declaration `async/*comment*/function* events(){yield 1}` passes parsing but does not trigger lowering; I reproduced this with the checked-in detector. Imported dependencies can likewise introduce an unsupported generator. The first disposition therefore does not fully establish D1’s native support. **Fix:** detect async generators from parsed bundled input, including dependencies, or always apply the required lowering. Exercise this through the production bake path and pinned Hermes.

7. **Nit — D6 overstates bake deferral.** RFC line 333 says iterator answers have no compiled value. A finite iterator instead becomes tag 0 (`js/src/prelude.js:1169–1171`), which `js/src/source.rs:265–267` accepts in `query`. A probe of `yield 1; yield 2` returned `{tag:0,value:2}`. **Fix:** either defer upon identifying any iterator during bake, or document the finite, host-work-free exception.

The Snapback folds are sound: an independent cursor avoids watermark spin; store/generation identity prevents missed invalidations; the initial `wait=0`, `heartbeat=1` and empty `ephTables` match `serve_changes.rs:12–28,64–85`. The offline-first value deliberately enables cached readers. Per-request admission and Storage forwarding fit the existing mechanisms, and the native worker occupancy cost is disclosed honestly.

D3 also correctly withdraws the delivery-barrier claim: bounded repeated `clock settle` calls remain conditional observations, not guaranteed delivery.
