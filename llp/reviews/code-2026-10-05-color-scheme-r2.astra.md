1. **[kernel/src/motion/paint.rs:264](/tmp/x23/kernel/src/motion/paint.rs:264) — must-fix: a live scheme change is mistaken for boot correction.** In a light session, changing an existing subtree from `normal`/`light` to `dark` starts the correct colour transition during `sync`. Apple’s subsequent first differing view report sets `first=true`; `apply(..., snap=true)` removes that transition, and `set_node_dark(..., playing=true)` recolours existing keyframes. This contradicts both transition behaviour and LLP 1062 D9’s preservation of playing keyframes. **Fix:** distinguish initialization from a report confirming an authored scheme change; preserve existing transitions and animation colours. Test the transition midpoint and an already-playing keyframe across this change.

2. **[host/apple/src/host.rs:1270](/tmp/x23/host/apple/src/host.rs:1270) — must-fix: new keyframes still start with the wrong appearance.** Ordinary motion synchronization starts animations before the new computed scheme reaches the engine. Changing an already-reported dark subtree to light while starting a new animation therefore starts that animation dark; the later report has `first=false` and never corrects it. Inline runs and SVG shapes have an additional problem: they have no `NodeView` to report their inherited scheme, so their keyframes can remain in the session’s scheme even at boot. **Fix:** establish each animation node’s effective appearance before adopting its animation row, including viewless nodes, while retaining the appearance of existing plays. Add same-commit scheme/start and inherited inline/SVG animation tests.

3. **[host/apple/Sources/ExactKit/Session.swift:1289](/tmp/x23/host/apple/Sources/ExactKit/Session.swift:1289) — must-fix: replay can skip appearances after a runtime restart.** `finishBoot` and `presentCommitted` replace the Rust host and reset views, but preserve `schemeDark`, `viewDark`, and pending reports. Reloading the same dark subtree with the same IDs makes `noteAppearance` return at line 1316 because Swift remembers the previous report, although the new engine has never received it. Background keyframes consequently return to the session’s scheme. **Fix:** reset appearance-report state when replacing the runtime, before applying its new tree, then replay after its initial scheme report. Test reloading the same plan with background-only keyframes.

One ancestor lookup per ghost suffices. Add a pixel assertion during a grouped drag, retaining the existing exclusion from hit-testing.
