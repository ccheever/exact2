1. **MAJOR — Runner geometry is missing or stale.** [alert.rs:265](/tmp/dt3-rv-b1/host/linux/src/presenter/alert.rs:265), [top.rs:1322](/tmp/dt3-rv-b1/host/linux/src/presenter/top.rs:1322). Reporting happens only at opening and closing. With an attached display, `box_of()` reads the previous picture, which has no newly opened popover; no report follows display acknowledgement. Headless reports become stale after resizing, scrolling the invoker, or changing content. Autofocus callbacks also run before the initial report and therefore still read the popover as closed. The new test checks only a subsequent query in a stationary, headless presentation.

2. **MAJOR — Popover transforms are applied twice to structural geometry.** [alert.rs:712](/tmp/dt3-rv-b1/host/linux/src/presenter/alert.rs:712). `PaintedBox.rect` already includes CSS transforms, but [`top_layer_frames`](/tmp/dt3-rv-b1/runner/src/runner/shown.rs:40) requires the rectangle before the root’s own transform. The runner applies that transform again. A translated popover consequently reports shifted coordinates; scaling and rotation also corrupt descendant geometry and `elementsFromPoint`. Report the untransformed placement.

3. **MAJOR — A second invoker reopens an already open popover.** [alert.rs:700](/tmp/dt3-rv-b1/host/linux/src/presenter/alert.rs:700), [alert.rs:716](/tmp/dt3-rv-b1/host/linux/src/presenter/alert.rs:716). Open through button A, then click button B with the same `popovertarget`. B is not the stored invoker, so its down closes the popover; its subsequent toggle opens it again. HTML exempts buttons targeting the open popover, irrespective of which button opened it. Resolve the clicked button’s current invocation instead of comparing only with `open.invoker`. [HTML light-dismiss rules](https://html.spec.whatwg.org/multipage/popover.html#popover-light-dismiss)

4. **MAJOR — Agent taps can activate controls covered by the popover.** [alert.rs:734](/tmp/dt3-rv-b1/host/linux/src/presenter/alert.rs:734). `alert_outside_tap()` dismisses based on DOM containment before `tap_at()` computes coordinates or checks occlusion. Naming a page button completely covered by an auto popover removes the cover and presses that button. A physical click there hits the popover and does not dismiss it. Determine whether the tap actually lands outside before closing.

5. **MAJOR — The accessibility change loses visible popover content beneath clipping ancestors.** [access.rs:1081](/tmp/dt3-rv-b1/host/linux/src/presenter/access.rs:1081). Walking the popover through the page carries its ancestor scroller’s clip and scroll adjustment into `access_emit()`. A popover authored inside an overflowing container but painted outside its scrollport consequently loses accessible controls or receives clipped bounds. Previously, the separate popover walk used the viewport. Keep the page exposed while resetting the rendering scope at the open popover.

6. **MAJOR — The updated Tab test asserts the wrong order.** [authored_dialog.rs:466](/tmp/dt3-rv-b1/host/linux/tests/authored_dialog.rs:466), [authored_dialog_windows.rs:521](/tmp/dt3-rv-b1/host/linux/tests/authored_dialog_windows.rs:521). HTML inserts an invoked popover’s focus scope after its invoker. In this fixture, Tab from `close` should reach `outside`, and Tab from `open` should enter the popover. The implementation still sorts raw tree order, and the changed expectations bless that mismatch. [HTML focus-navigation scopes](https://html.spec.whatwg.org/multipage/interaction.html#focus-navigation-scope-owner)

7. **MAJOR — A dialog opened as a popover loses its required initial focus.** [alert.rs:249](/tmp/dt3-rv-b1/host/linux/src/presenter/alert.rs:249). `<dialog popover="auto">` is non-modal, but HTML explicitly runs **dialog focusing steps** for it. Gating the first-stop and root fallbacks on `modal` now leaves focus outside when no descendant has autofocus. The new fixtures use `column role="dialog"`, so they miss this regression. [WPT dialog-popover focus cases](https://github.com/web-platform-tests/wpt/blob/master/html/semantics/popovers/popover-focus.html)

The broader sweep also found these pre-existing parity gaps that the fix leaves in place:

8. **MAJOR — Light dismissal still occurs too early.** [alert.rs:703](/tmp/dt3-rv-b1/host/linux/src/presenter/alert.rs:703). This runs during `pointer_down()`. HTML records the down target and dismisses on a matching up; Chrome’s newer click-based implementation also waits until release. An outside down followed by cancellation or release inside must not immediately close the popover. The current complete-click tests cannot distinguish this. [HTML algorithm](https://html.spec.whatwg.org/multipage/popover.html#popover-light-dismiss), [Chromium change announcement](https://groups.google.com/a/chromium.org/g/blink-dev/c/RxOpZkL4yqM/m/kxPldvWwAgAJ)

9. **MAJOR — Some page keyboard operations remain intercepted.** [typing.rs:626](/tmp/dt3-rv-b1/host/linux/src/presenter/typing.rs:626), [alert.rs:631](/tmp/dt3-rv-b1/host/linux/src/presenter/alert.rs:631). `alert_key()` consumes every key before the ordinary shortcut and Back handling. Physical Control/Meta chords enter this path directly through `hardware_key()`, so page `aria-keyshortcuts` stop working despite retained page focus. Alt+Left also misses Back handling. Separately, `system_back()` consumes manual popovers because `alert_close_request()` returns true even when it refuses to close.

10. **MINOR — Context menus still treat popovers as modal.** [edit_menu.rs:50](/tmp/dt3-rv-b1/host/linux/src/presenter/edit_menu.rs:50), [top.rs:1171](/tmp/dt3-rv-b1/host/linux/src/presenter/top.rs:1171). The remaining `top_open()` guards suppress right-click editing menus, Shift+F10, and authored long-press/context-menu handling. A page field beneath a manual popover can now receive focus and typing but cannot use these operations.

11. **MAJOR — Nested presentation still destroys its parent.** [alert.rs:170](/tmp/dt3-rv-b1/host/linux/src/presenter/alert.rs:170), [top.rs:507](/tmp/dt3-rv-b1/host/linux/src/presenter/top.rs:507). Every opening calls `replace_surface()`. Opening a popover from a modal dialog therefore closes the dialog and removes its modal protection; opening a nested auto popover closes its ancestor instead of retaining the stack. A single `alert` and `shown_popover` cannot implement these HTML cases. [HTML popover stacking](https://html.spec.whatwg.org/multipage/popover.html#show-popover)

12. **MINOR — Manual popovers incorrectly restore previous focus.** [alert.rs:315](/tmp/dt3-rv-b1/host/linux/src/presenter/alert.rs:315). The new containment condition still restores `open.restore` for manual popovers. Open a manual popover with an autofocus field, then call `hidePopover()`: focus jumps back to the prior control. HTML does not record a restoration target for manual popovers, and WPT explicitly tests that distinction. [WPT manual focus restoration](https://github.com/web-platform-tests/wpt/blob/master/html/semantics/popovers/popover-focus.html)
