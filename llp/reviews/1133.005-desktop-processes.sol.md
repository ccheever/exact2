VERDICT: NOT READY

1. **MATERIAL — The executor binding and admission route remain unspecified.** RFC:515–525 says adding an executor implementation enables ordinary module binding. Existing bindings generate one-options-object Promise calls serialized as JSON (`js/bake/src/typescript.mjs:1032–1053`); native streams are expressly refused (`host/apple/src/executor_core.rs:1099–1106`). Neither represents the proposed mapper callback, binary data and opaque child handle. **Resolve:** specify the declaration, generated binding and executor request protocol, including common admission, source-scoped grants, origin, substitution and release. The D5 vocabulary exception is reasonable; it does not itself define this route.

2. **MATERIAL — Process exit is confused with completion of output.** RFC:227–244 ends the stream at `exit` while promising lossless output. Stdio can remain open after exit, which is why Node distinguishes [`exit` and `close`](https://nodejs.org/api/child_process.html#event-close). The clone explicitly drains both pipes, bounded at five seconds, before finalizing or restarting (`T3LocalBackendManager.swift:323–335`). **Resolve:** separate exit, pipe EOF and final completion; flush decoders and accepted chunks before completion or restart. Define the bound when descendants retain pipe handles.

3. **MATERIAL — Restart and kill need an incarnation-aware lifecycle.** RFC:308–310 reuses a handle across restarts, but existing staged operations address only the stream ticket (`runner/src/request.rs:562–573`). A delayed write, `end` or signal needs a defined relationship to the replacement child. Separately, RFC:245 calls `child.kill` a release, while RFC:251–253 says it is not. **Resolve:** address staged operations, probes and escalation timers to an incarnation; reject stale operations and reset stdin state. Distinguish signalling from release, including restart suppression and whether nonterminating signals receive any escalation.

4. **MATERIAL — Streaming stdin lacks a progress protocol.** RFC:232–240 provides per-turn quotas but no transport-wide buffering contract or writable notification. A quiet child that consumes several MiB before producing output cannot be fed reliably through mapper events alone. D7 also imposes transport bounds and cumulative per-answer bounds, not merely per-turn bounds (`llp/1016.000-answers-that-keep-coming.rfc.md:236–242,381–390`). **Resolve:** define bounded stdin buffering with acknowledgements, `drain`, or an awaitable write mechanism that preserves commit staging. Include large streaming stdin in the ceiling test.

5. **MATERIAL — The secret-field guarantee misses existing text-bearing channels.** RFC:438–442 sanitizes ordinary event `value`, but existing `beforeinput` carries both replacement text and the prior value (`host/apple/Sources/ExactKit/FieldInput.swift:69–81`). Web `beforeinput`, selection and ancestor keyboard handlers expose text too (`host/web-js/rt.js:926,931,1132–1137`). **Resolve:** specify redaction or refusal across every text-bearing event and read, including ancestor handlers, paste, selection, IME and replacement paths. Define the new `length` payload, which current `InputEvent` lacks (`contract/types/src/selection.rs:173–183`), and drive these cases on each field target.

6. **MATERIAL — Held secrets need an explicit volatile storage contract.** RFC:432–448 reuses `store.get/set/forget` while excluding persistence and carry. Today `Store::set` produces durable writes, and `snapshot` carries stored values (`runner/src/store.rs:386–399,464–470`; `runner/src/runner.rs:714`); the web persists writes to localStorage (`host/web-js/rt.js:385–393`). **Resolve:** define the volatile provider/tier, exclusion from snapshots and durable writes, conflicting `secret.keep`/`secret.hold` names, source-scoped access, and field synchronization with committed `set/forget`.

7. **MATERIAL — Tool-origin execution can trigger the system UI that the parent forbids.** RFC:530–540 permits every operation from tools because none opens a prompt. Yet RFC:595–600 expressly allows children to trigger app-attributed protected-file prompts. Free arguments and arbitrary programs can also open UI. This conflicts with parent D6 rule 3 and its refusal of tool-opened prompts (`llp/1133-the-standard-library.rfc.md:349–356,557–560`). **Resolve:** define an enforceable origin policy for these indirect effects, or explicitly request an amendment. “Spawn itself has no prompt” does not settle it.

8. **MATERIAL — Scratch `home:` does not isolate real SSH execution.** RFC:604–622 runs real children by default while claiming the drive never reads the person's `~/.ssh`. Framework path remapping cannot constrain external programs. [OpenSSH uses the passwd home directory](https://github.com/openssh/openssh-portable/blob/master/ssh.c#L550); changing `HOME` alone is insufficient. The clone currently requires an agent SSH substitute and supplies isolated configuration (`T3Ssh.swift:52–55,344–348`). **Resolve:** require appropriate doubles or actual child isolation, or narrow the guarantee and retain explicit configuration, identity and agent isolation in consumer drives.

9. **MATERIAL — The claimed Swift deletions require additional capabilities.** RFC:736–744 overstates what stages 0–2 free:
   - Runtime installation reads bundle resources and uses an interprocess lock and symlink/mode validation (`T3LocalRuntime.swift:73–105,179–201`). Bundle resources currently require native `Bundle.main.resourceURL` access (`docs/reference.md:718–724`).
   - Askpass requires an executable 0700 helper (`T3SshAuth.swift:39–47`), while RFC:686–690 defers the host helper and treats `chmod` only as a possible launcher follow-up.
   - Editor discovery checks executability throughout arbitrary PATH directories (`T3RemoteEditors.swift:109–131`). Existing `stat` exposes no executable-access result (`vendor/ibex/crates/ibex2/src/stdlib/fs.rs:324–333`).

   **Resolve:** admit or name these dependencies and provide concrete migrations, or narrow the deletion table and 3,882-line claim.

10. **MATERIAL — Readiness cannot reproduce the SSH tunnel behavior.** RFC:311–316 accepts only 2xx and repeats timeout rounds. The tunnel accepts any status below 500 and fails after twenty seconds (`T3Ssh.swift:422–432,555–567`). A healthy endpoint returning 401 or 404 never becomes ready. **Resolve:** provide a success-status policy and timeout action, or demonstrate another supported implementation of that consumer behavior.

11. **MATERIAL — Linux crash cleanup is weaker than the table implies.** RFC:467–472 uses `PR_SET_PDEATHSIG` as crash cleanup. It targets the immediate child, is cleared in forked descendants, depends on the creating thread, and needs installation-race handling. [Linux documentation](https://man7.org/linux/man-pages/man2/PR_SET_PDEATHSIG.2const.html). Process groups also do not contain descendants that deliberately leave them. **Resolve:** state the precise cleanup boundary and implement the parent recheck/thread-lifetime requirements. Also specify the platform setup needed for descriptor closure and signal-mask reset; those guarantees do not follow from plain Rust `Command` alone.

12. **MATERIAL — The ceiling test is incomplete.** RFC:554–574 omits ordinary file-backed/merged stdio, suspend/resume and Windows verbatim argument handling. Tier 1 permits only pipe/ignore and excludes `SIGSTOP`/`SIGCONT`; tier 3 offers nothing. The priority row claims tier 2 coverage, but D10 provides no Linux priority control. These are established [Node options](https://nodejs.org/api/child_process.html#optionsstdio) and [Foundation operations](https://developer.apple.com/documentation/foundation/process/resume%28%29). **Resolve:** reach each through a tier or name its intentional exclusion and reason. Mark listed-but-deferred tier-2 features as deferred, rather than counting them as reached.

13. **MATERIAL — Stage 0 cannot yet deliver its promised substitute-first drive.** RFC:659–669 puts substitutes in stage 0 but process execution in stage 1; its substitute is another executable using that transport. It also leaves agent-clock behavior for restart, readiness and timeouts undefined. **Resolve:** provide a synthetic event substitute, or move enough execution machinery into stage 0 to make the drive runnable. Specify clock behavior and failure injection. Launch flags and `state` forms preserve the existing operation count.

14. **MINOR — Finish the declarations, examples and ruling text.** RFC:479–487 lacks D9-required platform links and precedence explanations. Further corrections:
   - RFC:401 compares login-PATH lookup to Node, although [Node honors `options.env.PATH`](https://nodejs.org/api/child_process.html); declare the deviation.
   - RFC:343–349 omits the clone's Nushell handling (`T3LocalShellEnvironment.swift:36–50`) and a reliable Linux fallback.
   - RFC:199–203 passes the bootstrap envelope through resource arguments, although it contains secrets (`T3LocalBackendManager.swift:51–58`). Build it inside data code.
   - Q1's claim that extension arguments inherently become Contract values is inaccurate; data-code `native.later` already sends request-body bytes (`js/src/prelude.js:1257–1263`). Retain the valid ordered-stream objection.
   - Q7's waiver text says the held-secret field is absent outside desktops, contradicting stage 2's web/iOS scope. Add Expose's missing target cell. Keep binary cost explicitly pending measurement.

The resource-owned process lifetime, executor ownership, commit-staged input and lossless receive backpressure are sound foundations. Named environment grants, explicit executable targets and post-first-pixel capture address real consumer needs. The grant discussion correctly avoids claiming to sandbox child behavior, and Windows' native-drive requirement is appropriate. Most D9 headings are present, but the contracts above prevent the checklist and consumer-completion claims from being considered satisfied. No files were edited.
