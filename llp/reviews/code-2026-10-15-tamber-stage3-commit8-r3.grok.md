**Medium** — `tamber/src/import/dtcg.rs:159` (`is_token`), `:201`, `:224` (`deep`), `:262` (`walk`). A `$ref` with no `$value` is a token alias in `walk`, but `is_token` only looks for `$value` or a legacy `value`. `deep` therefore merges it with a group instead of replacing the path. Inherited `button: {"$ref":"#/color/red"}` plus a local group `button.bg` becomes `{ "$ref", "bg" }`. `walk` then sees a `$ref` to a token, emits the alias, and returns without walking `bg`, so `bg` is dropped. The other way, a local `{"$ref":"{someGroup}"}` over an inherited group is merged before the `$ref` is followed, so the inherited children survive the replacement. A `$value` token still replaces wholesale, which is why the round-2 extend test passes. Separately, `$extends` of a real token is `continue` at line 201, not an error. Format 2025.10 §6.4 says `$extends` must not target a token and §6.4.6 says that is an error; the import succeeds with the extends ignored. Treat a `$ref` that points at a token as a leaf in `deep` (the other side replaces the whole path), and return an error when `$extends` or a group `$ref` targets a token.

**Medium** — `tamber/src/import/dtcg.rs:714`. An unreached set is expanded with `?`, so a bad `$ref`, a cycle, or a depth error in a set `resolutionOrder` never applies aborts the whole import. Those sets are not part of the resolution; record the failure on that set and continue. The same call passes a fresh `BTreeSet` for `reached`, so a nested `#/sets/…` discovered there is forgotten and that set is expanded again, duplicating "never reaches" rows. `expand` also records the raw pointer suffix (`:628`): `#/sets/a~1b` marks `a~1b`, not the set key `a/b`, so a set the order did use is expanded a second time and reported unused. Decode the pointer the way `pointer_segments` does, and thread the same `reached` set through the unused pass.

**Medium** — `tamber/src/import/dtcg.rs:959`, with the layer order at `:523`. Axis values are discovered by walking layers in `tokenSetOrder`, and `vs[0]` becomes the default. `tokenSetOrder` is precedence among sets that apply to one tuple, not which theme is the default. Themes Calm then Loud with order `["loud","calm"]` import `brand = loud | calm`, so every differing token's default and `when` lines follow Loud. A shared set listed first still keeps theme order, because its scopes were pushed in theme order; the flip happens when the earliest set belongs only to a later theme. The Lion fixture lists casual before business and green before blue, so the existing test does not catch it. Record each axis's value order from theme order (first theme in the group is the default), and keep `tokenSetOrder` as layer precedence only.

**Medium** — `tamber/src/import/dtcg.rs:553` and `:594`. `Doc::relative` pops `..` on an empty stack, so a reference that leaves the source root resolves to a file inside it. From `tokens.json`, `../colors.json` and `../../colors.json` both become `colors.json` when that file was loaded. The same clamp happens from `sub/a.json` with one `..` too many. There is no filesystem escape, because only the preloaded list is searched, but the wrong in-tree file is selected. Return an error when `..` would leave the root. Second, `deref` merges sibling keys onto the resolved value and returns the final target's document (`:594`). `expand` then resolves those siblings against that document (`:632`). A sibling `./colors.json` written on the reference object in `r.json` is resolved as `sub/colors.json` when the target lives in `sub/`. References inside the target are already resolved against the target, which is what the round-2 test covers. Resolve sibling overrides against the document that contained the reference object.

**Medium** — `tamber/src/import/dtcg.rs:204` and `:882`. Path depth past 64 is refused (`:257`), and `type_of` walks alias chains in a loop (`:841`). `$extends` does not. `extended` recurses with only a cycle check, and `Resolve::seen` still recurses one frame per hop after `type_of` has already walked the chain. A cycle returns an error. An acyclic chain of a few thousand extends or aliases does not: it overflows the stack instead of returning the nesting error. Cap the extends stack at 64, and resolve aliases in `seen` iteratively, the way `type_of` does.

Checked and not defects:

- The memo in `Resolve::seen` (`:867`) is sound. Each alias has one target, so a cycle is a property of the node, not of the caller. Successes are memoized always. A failure is memoized only when `visiting.len() <= 1`, and the caller pre-seeds `visiting` with the start path, so only the entry node's real error is stored. In-cycle failures are recomputed. A memoized cycle error is a true error for every later entry.
- One set selected by themes of two groups is active if any of its scopes match (`:1062`). That is the Tokens Studio union: the set is on when any active theme enables it. A single-theme group stored as `Scope::Base` is always on, because that theme is always selected. AND across the groups would drop the set from tuples where only one of those themes is active.
- The written-name check (`:96`, `:939`) does not false-positive. Distinct spellings that sanitise to one identifier are refused on purpose (`Brand Tone` / `brand-tone`), and the same raw spelling is inserted once. The miss is the other way: two sources that emit the identical raw string are not refused. An empty theme group uses the axis name `"theme"` (`:511`), and a real group named `theme` writes that same string, so they merge into one axis. Same for two themes whose names are both empty (`ident` makes `x`). That is low. Refuse when two groups or two themes in one group produce the same identifier, even if the raw strings match.

One further low: in `expand`, a non-string `$ref` is not pushed (`:622`) but `src.get("$ref").is_some()` still pops (`:643`). On an empty stack that pop is a no-op; nested under a real `$ref` it drops the parent frame and can hide a cycle. Pop only when this call pushed.
