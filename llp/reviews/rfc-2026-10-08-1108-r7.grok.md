READY WITH CHANGES

1. MAJOR — `snapback4/ts/snapback.ts:616` (`upload` at 608–632); `snapback4/client/src/media.rs:519` and `:535`. A wipe discards an upload only when that upload’s exchange is already in the map. The driver calls `op: 'upload'` after `await fs.readFile`, and that call is not a queue step. Sign-out or an `E_AUTH` round can finish first: `media_wipe` clears the maps and `unlink` is awaiting the two folders, the device is free, then `op: 'upload'` inserts a new exchange, the POST succeeds, and `upload_reply` records facts. A later write naming that id predicts. That is the case D8 states as “an upload it overtakes records no facts” (`llp/1108-media-from-snapback.rfc.md:750`) and the README states as an upload still in flight (`snapback4/README.md:408`). D4’s narrower rule, an exchange the wipe already let go (`rfc:564`), holds for a POST that has started, and `snapback4/ts/media.test.ts:282` only stalls the HTTP response after that exchange exists. Hand out the exchange on the queue before `readFile`. The wipe step holds the queue across `media_wipe` and both removals, so the exchange cannot be created in the gap after the maps are cleared. Stall `readFile` in the test, run `clearMedia` (and the `E_AUTH` round), then release the read: expect `E_STALE` and a write that stays pending.

MAJOR — `snapback4/ts/snapback.ts:251` (`wipeNow` at 250–254); `snapback4/ts/snapback.ts:519`; `snapback4/client/src/media.rs:507`. `wipeNow` sets `partition.wipe = false` before `media_wipe` returns. If that call throws (the device is busy, or `save` of the empty manifest fails), the round’s `.catch(() => undefined)` at line 523 drops the error and `sync()` still resolves with `E_AUTH`. The flag is already clear, so nothing retries. `media_wipe` clears both exchange maps before `save` (line 507, then 511), so a failed save drops in-flight replies while the manifest and the files stay. The next open keeps every path the manifest still names, and a refused session still shows its photos. The branch `if (partition.wipe) return` at line 521 never sees the flag, because `wipeNow` has already cleared it. Clear the flag only after `media_wipe` has returned and both folders are removed; on a throw, leave it set so the next queue step runs the wipe again, and let that failure reject the round. Persist the empty manifest before dropping exchanges.

MINOR — `host/web/picker-glue.js:40`. `appURL` returns `made()` for a path in the picked-file map before the removal generation is consulted. `storage.fs` `rm` revokes a URL already made for that path (`host/web/storage-fs.js:371`), then a later `appURL` builds a new one from the `File` still in the map, including a path removed while this call was the one that would have checked `removedSince`. Cache and tmp photo paths are not in that map: a removed photo gets no URL, and the picker tests and the Chrome `rm` test cover that. Check the generation for a picked path too, and drop the map entry when that path is removed.

What holds: the slice-1 path that the tests drive. One queue orders the kept check, the publication, the post-round check, the wipe, the open sweep, and the close of the transient folder. A download’s exchange is handed out on the queue before the GET, so a wipe during the transfer is `E_STALE` and writes nothing. An upload whose POST is already on the wire is discarded the same way, and the facts stay when the reply was taken before the wipe. After a wipe that completes, the next `asset` asks the server. Kept files, expiry only at `asset(id, now)`, the 64 MiB LRU cap, one transient path, and the `once` rules (a `416` does not spend the view; `accept-ranges: none` spends it and writes nothing) match the server and are implemented in the core. The manifest is written before the bytes; a failed write or a short file is `asset_lost` and fetched again. Open sweeps names the manifest does not list, and a removal that throws is finished at the next open. The driver does not read a clock. On the web, `rm` and a rename’s source revoke the object URL for that path and everything under it, a removal during `appURL` yields no URL, and `readdir` basenames join correctly with the sweep.
