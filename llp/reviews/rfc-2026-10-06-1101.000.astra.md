# Round 1

**Overall assessment**

Yes: **terminal apps are a good direction for Exact, and this is a useful authoring report.** The explicit terminal view, ordinary Contract logic, Taffy layout, and text-based inspection form a coherent design.

I would revise the implementation plan before proceeding. The proposal emphasizes reducing authoring friction, but the spike exposes more consequential gaps in keyboard reachability, input handling, admission checks, and text layout. Two proposed solutions also need changing: **P1 should initially be a lint, and P6 should not infer usability from min-content size.**

This was a static, read-only review. I read both LLPs fully and checked the supplied spike; I did not build or run it. The compiler lowerer and tag mapping are absent, so their reported behavior remains unverified.

**Strengths**

- **§1 G1 — ordinary application logic survives.** The fixture’s state, filtering, and actions contain no terminal-specific operations. That supports the architecture, although shared resources and persistent storage remain untested. See [terminal.contract:5](/private/tmp/claude-501/-Users-ccheever-projects-exact2/99504d5c-e64b-441e-a7cc-ed36489b5317/scratchpad/review-1101.000/spike/apps/todo/terminal.contract:5) and parent §11.
- **§1 G2 and P9 — text-first inspection is a substantial advantage.** Cheap, readable output can make both development and regression diagnosis unusually effective.
- **P5 and “Not proposed: bare integers as cells” — composition preserves the language.** Keeping CSS defaults and extracting useful components is the right response to repetitive styling.
- **P7–P8 — good scope discipline.** Keeping general Contract issues and cross-surface focus styling out of terminal-specific vocabulary is sensible.
- **Parent D7 — painting directly from the kernel tree is a strong foundation.** The spike follows this architecture; there is no need to introduce another widget or layout framework.

**Concerns**

1. **High — the admission profile promises more than it currently checks.**

   The border escape is real: `check_attrs` processes only `AttrTarget::Styles`, skipping other targets. Length validation handles literals and ternaries but ignores other expression forms. Grid track properties are marked `admit`, bypassing cell-length validation altogether. See [terminal.rs:92](/private/tmp/claude-501/-Users-ccheever-projects-exact2/99504d5c-e64b-441e-a7cc-ed36489b5317/scratchpad/review-1101.000/spike/contract/cli/src/terminal.rs:92), [terminal.rs:108](/private/tmp/claude-501/-Users-ccheever-projects-exact2/99504d5c-e64b-441e-a7cc-ed36489b5317/scratchpad/review-1101.000/spike/contract/cli/src/terminal.rs:108), and [schema-and-build.diff:311](/private/tmp/claude-501/-Users-ccheever-projects-exact2/99504d5c-e64b-441e-a7cc-ed36489b5317/scratchpad/review-1101.000/spike/schema-and-build.diff:311).

   **Resolution:** validate normalized styles through the existing CSS parsers while unit information remains available. Cover shorthands, grid tracks, classes, imported components, and computed values. Explicitly choose how unresolved values are handled; passing them unchecked cannot support “refused at bake.” Keep admission rules in the schema rather than accumulating special cases in `terminal.rs`.

2. **High — basic keyboard and paste behavior deserves priority over component polish.**

   Two concrete findings:

   - Tab order comes from nonempty **clipped paint rectangles**. Off-screen rows therefore disappear from the traversal set, before `reveal` can scroll them into view. ArrowUp/Down use the same traversal. The existing keyboard test only exercises the short fixture. See [paint.rs:108](/private/tmp/claude-501/-Users-ccheever-projects-exact2/99504d5c-e64b-441e-a7cc-ed36489b5317/scratchpad/review-1101.000/spike/host/terminal/src/paint.rs:108), [host.rs:158](/private/tmp/claude-501/-Users-ccheever-projects-exact2/99504d5c-e64b-441e-a7cc-ed36489b5317/scratchpad/review-1101.000/spike/host/terminal/src/host.rs:158), and [todo.rs:53](/private/tmp/claude-501/-Users-ccheever-projects-exact2/99504d5c-e64b-441e-a7cc-ed36489b5317/scratchpad/review-1101.000/spike/host/terminal/tests/todo.rs:53).
   - `decode` creates a fresh `Decoder` for each read, losing its `pasting` state. A paste split across reads can turn a subsequent newline into Enter. Printable pasted characters also become ordinary key events, which can invoke shortcuts when no field is focused. See [term.rs:77](/private/tmp/claude-501/-Users-ccheever-projects-exact2/99504d5c-e64b-441e-a7cc-ed36489b5317/scratchpad/review-1101.000/spike/host/terminal/src/term.rs:77) and [term.rs:156](/private/tmp/claude-501/-Users-ccheever-projects-exact2/99504d5c-e64b-441e-a7cc-ed36489b5317/scratchpad/review-1101.000/spike/host/terminal/src/term.rs:156).

   **Resolution:** derive focus traversal from eligible semantic nodes, then reveal the selected node. Reconcile focus after removal/filtering. Preserve decoder state across reads and deliver paste as text to an accepting field. Add long-list and fragmented-paste cases to the existing tests.

3. **Medium — P1 confuses an authoring convention with CSS’s unit semantics.**

   `ch` and `lh` are font-relative lengths, not horizontal and vertical types. `padding-top="2ch"` is valid and, under this spike’s metrics, exactly one row. Conversely, `height="0.5lh"` still requires rounding despite using the preferred unit. [CSS Values and Units](https://www.w3.org/TR/css-values-4/#font-relative-lengths)

   The proposed `gap` exception also misses wrapping: a single value sets both gaps, and a wrapping flex row uses the cross-axis gap between lines. `flex-basis` must be checked against the **parent flex container’s** direction. [CSS gap semantics](https://www.w3.org/TR/css-align-3/#gaps), [Flexbox](https://www.w3.org/TR/css-flexbox-1/#flex-basis-property)

   **Resolution:** start with an axis-aware warning that recommends a spelling and explains its resolved size. Keep hard errors for unsupported values. Document grid, wrapping, fractional values, and unknown directions; remove “makes the trap impossible.”

4. **High — terminal layout policy leaks into shared kernel behavior.**

   The border switch is a process-global atomic that can only be enabled. Meanwhile, the generated shared style setter converts `ch`/`lh` using fixed 8/16 metrics without a terminal-context check. This makes independent kernel instances difficult to reason about and gives these CSS units the wrong semantics outside the terminal. See [cells.rs:22](/private/tmp/claude-501/-Users-ccheever-projects-exact2/99504d5c-e64b-441e-a7cc-ed36489b5317/scratchpad/review-1101.000/spike/kernel/src/style/cells.rs:22) and [schema-and-build.diff:9](/private/tmp/claude-501/-Users-ccheever-projects-exact2/99504d5c-e64b-441e-a7cc-ed36489b5317/scratchpad/review-1101.000/spike/schema-and-build.diff:9).

   **Resolution:** make metrics and border quantization instance-local. Keeping a fixed virtual 8×16 cell for terminal layout is reasonable; making it ambient process state is unnecessary. Other hosts should resolve font-relative units correctly or refuse them until implemented.

5. **Medium — P3 and P5 need behavioral contracts, not just appearances.**

   Checkbox support is more than drawing three characters. The painter registers `Control` nodes as hit targets but has no control-painting branch; `press` handles fields and press handlers; the current tree printer does not export checked state. See [paint.rs:108](/private/tmp/claude-501/-Users-ccheever-projects-exact2/99504d5c-e64b-441e-a7cc-ed36489b5317/scratchpad/review-1101.000/spike/host/terminal/src/paint.rs:108), [host.rs:247](/private/tmp/claude-501/-Users-ccheever-projects-exact2/99504d5c-e64b-441e-a7cc-ed36489b5317/scratchpad/review-1101.000/spike/host/terminal/src/host.rs:247), and [main.rs:49](/private/tmp/claude-501/-Users-ccheever-projects-exact2/99504d5c-e64b-441e-a7cc-ed36489b5317/scratchpad/review-1101.000/spike/host/terminal/src/main.rs:49).

   **Resolution:** specify intrinsic size, naming, disabled behavior, Space activation, `input`/`change` payloads, and controlled `checked` behavior. Replace the outer task button with a checkbox row; do not merely replace its `[x]` text with a nested interactive control.

   Similarly, decide whether the filters are radio choices, toggle buttons, or actual tabs. Real tabs imply panels and a particular keyboard model, not merely bold underlined text. [WAI tabs pattern](https://www.w3.org/WAI/ARIA/apg/patterns/tabs/)

6. **Medium — P4’s help needs a shared definition of “active command.”**

   The statement that `shortcut` walks visible nodes is inaccurate. It searches the hit list without checking rectangle size, disabled state, or scope; invisible nodes can enter that list. Duplicate bindings resolve to the first match. See [host.rs:292](/private/tmp/claude-501/-Users-ccheever-projects-exact2/99504d5c-e64b-441e-a7cc-ed36489b5317/scratchpad/review-1101.000/spike/host/terminal/src/host.rs:292).

   **Resolution:** dispatch and help should consume the same derived set of active bindings, including scope, eligibility, precedence, and names. Define `?` conflicts, modal focus, Esc, and focus restoration. Expose the help through agent inspection too.

   Keep a small visible “`? help`” hint. Removing the footer entirely makes the new discovery mechanism harder to discover; its Tab/Enter instructions also are not encoded in `aria-keyshortcuts`.

7. **Medium — P6’s inferred minimum is unreliable; P7’s proposed lint rule is too broad.**

   Min-content size answers an intrinsic-sizing question, not “can a person use this interface?” The fixture deliberately gives its panel and scroller `min-height=0`, allowing the essential content area to collapse. See [terminal.contract:54](/private/tmp/claude-501/-Users-ccheever-projects-exact2/99504d5c-e64b-441e-a7cc-ed36489b5317/scratchpad/review-1101.000/spike/apps/todo/terminal.contract:54).

   Likewise, `flex-grow=1 min-height=0` does not establish a bound by itself. It needs an appropriate bounded flex ancestor and shrink behavior; it is not generally equivalent to `flex=1`.

   **Resolution:** use explicit minimum dimensions, with temporary CLI arguments if necessary. Preserve app state across the fallback screen. Repair the scroll lint by recognizing the layout context, not another pair of attribute spellings.

8. **Medium — text-first evidence needs stronger layout and semantic checks.**

   Parent D3 says the painter never rewraps. The spike does: measurement floors available pixels to columns, while painting wraps again at a width obtained from rounded edges. Fractional flex widths can therefore produce different wrapping limits. See [measure.rs:49](/private/tmp/claude-501/-Users-ccheever-projects-exact2/99504d5c-e64b-441e-a7cc-ed36489b5317/scratchpad/review-1101.000/spike/host/terminal/src/measure.rs:49), [measure.rs:165](/private/tmp/claude-501/-Users-ccheever-projects-exact2/99504d5c-e64b-441e-a7cc-ed36489b5317/scratchpad/review-1101.000/spike/host/terminal/src/measure.rs:165), and [paint.rs:299](/private/tmp/claude-501/-Users-ccheever-projects-exact2/99504d5c-e64b-441e-a7cc-ed36489b5317/scratchpad/review-1101.000/spike/host/terminal/src/paint.rs:299).

   Also, `.txt` omits styles and cursor state. Two screens with different focus or selected-filter styling can have identical text. See [grid.rs:179](/private/tmp/claude-501/-Users-ccheever-projects-exact2/99504d5c-e64b-441e-a7cc-ed36489b5317/scratchpad/review-1101.000/spike/host/terminal/src/grid.rs:179).

   **Resolution:** establish one authoritative wrapping result and test fractional widths. Keep `.txt` first, paired with focused/checked/selected assertions and styled-grid evidence when relevant. Exercise CJK, combining characters, wide glyph replacement, and actual writer output.

**Suggestions — ranked by value for cost**

| Rank | Change | Cost / payoff |
|---|---|---|
| 1 | Add an explicit foundation item covering keyboard reachability and paste; expand the existing todo tests. | Small–medium; directly prevents broken interaction. |
| 2 | Broaden P1/P2 into reliable profile validation, with axis guidance as a lint. | Medium; makes compiler acceptance trustworthy. |
| 3 | Do P7/P9’s documentation work, and repair misleading examples in the parent. | Tiny; immediately improves authoring. |
| 4 | Implement P6 using explicit dimensions only. | Small; resolves a demonstrated failure without a heuristic. |
| 5 | Implement P3 as a complete checkbox interaction, retaining the task’s full-row usability. | Medium; improves behavior, semantics, and authoring together. |
| 6 | Extract local styles/components before committing P5’s built-in API. | Small initially; lets a second consumer test the abstractions. |
| 7 | Build P4 after command eligibility and focus scopes are defined. | Medium; useful, but more than an overlay painter. |
| 8 | Keep P8 deferred and hover tracking demand-driven. | Avoids work the fixture did not need. |

For **P2**, keep `thin`/`medium`, document radius quantization, and recommend `border-radius="1ch"` without inventing a terminal keyword. Define mixed-edge and per-corner behavior.

For **P5**, a reusable truncating text style/component may buy more than a generic pressable `Row`. Keep panel decoration separate from automatic filling and scrolling. A title in a border is attractive, but it should not drive a new painter primitive before a real consumer requires it. If `fieldset`/`legend` are implemented, preserve their grouping semantics. [HTML fieldset](https://html.spec.whatwg.org/multipage/form-elements.html#the-fieldset-element)

Correct the summary’s “first three are compiler checks”: P3 is host control work.

**Novel ideas**

- **Explain cell rounding through the existing `layout` operation.** Show authored value → resolved layout length → snapped boundaries, linked to source. This diagnoses cross-axis mistakes, percentages, flex distribution, and clipping more effectively than increasingly restrictive unit rules.
- **Find usable size boundaries experimentally.** Run the same short interaction test across a range of viewport sizes and report the smallest dimensions where its assertions hold. Use that evidence to choose explicit minima; do not derive them from intrinsic geometry.
- **Make help an executable consistency check.** Every displayed help entry should correspond to a currently invocable action. Existing tests can compare the help contents with dispatch eligibility, catching stale hints, disabled commands, and scope mistakes.

**Open questions**

- Does terminal-profile acceptance guarantee supported runtime behavior, or only validate statically recognizable values?
- What is the intended collection interaction: Tab through individual controls, or one collection stop with arrow navigation? Which HTML/ARIA semantics select that behavior?
- What determines command scope, and where do host shortcuts sit relative to application handlers?
- Which existing semantic-name and control-state machinery can the terminal reuse?
- How will one wrapping result survive layout, snapping, painting, and inspection?
- What minimum useful milestone justifies maintaining this surface: a persistent todo, the shared-data LLP reader, or both?

**Recommended next step**

Revise this RFC around one expanded todo slice: thirty items, long and Unicode titles, real checkboxes, keyboard-only traversal, fragmented paste, filtering away the focused item, and shrinking below the declared minimum then restoring.

Use that slice to settle admission, focus, control semantics, and text layout. Then author the LLP reader before promoting a broader `exact:terminal` library. That will provide substantially better evidence for the abstractions than more polishing of the three-item fixture.
