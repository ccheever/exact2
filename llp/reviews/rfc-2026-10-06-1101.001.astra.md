# Round 1

**Overall assessment**

Yes—this is a good direction, and the harness supplies much stronger evidence than the todo fixture. **The strongest result is the interaction model: an immutable transcript in terminal scrollback, with a small live region.** Preserve that.

I would revise the plan before implementing P1–P14. It currently understates the difficulty of history retirement, proposes an unreliable approval fix, and prioritizes some conveniences ahead of correctness problems. My priorities would be: **intentional approvals, reliable cancellation, bounded live work, then authoring improvements.**

This was a static, read-only review. I read the RFC fully, its parent and sibling, both sibling reviews, and the relevant supplied code. I changed nothing. The bundle lacks the full kernel, runner, and ibex2 executor, so I could not independently reproduce the performance measurements or verify F4’s executor implementation.

**Concerns**

1. **High — P11 does not prevent accidental approval.**

   A delay cannot establish that someone saw a prompt. More concretely, the current approval’s **Yes button has autofocus**, while the composer becomes disabled. Enter can therefore activate Yes through ordinary focused-button behavior, without using `aria-keyshortcuts`. The loop also applies announcements before handling already-ready input, with repaint occurring on the next iteration. See [terminal.contract:216](/private/tmp/claude-501/-Users-ccheever-projects-exact2/99504d5c-e64b-441e-a7cc-ed36489b5317/scratchpad/review-1101.001/spike/apps/harness/terminal.contract:216), [keys.rs:176](/private/tmp/claude-501/-Users-ccheever-projects-exact2/99504d5c-e64b-441e-a7cc-ed36489b5317/scratchpad/review-1101.001/spike/host/terminal/src/keys.rs:176), and [term.rs:456](/private/tmp/claude-501/-Users-ccheever-projects-exact2/99504d5c-e64b-441e-a7cc-ed36489b5317/scratchpad/review-1101.001/spike/host/terminal/src/term.rs:456).

   **Resolve it:** remove default affirmative focus; guard every activation path, including Enter, Space, and shortcuts; associate queued input with the interaction state under which it was received; and prevent one input batch from activating controls introduced during that batch. Require an explicit choice for consequential approvals. A presentation boundary is useful bookkeeping, but must not be described as proof of human attention. Do not impose a universal 300 ms delay on unrelated controls.

2. **High — P1(a) cannot meet P1’s flat-memory acceptance criterion.**

   Freezing layout leaves several growing representations intact:

   - `State` retains both rendered entries and model conversation history.
   - Every session answer reconstructs values for every entry.
   - Each model round clones the conversation.
   - The image cache retains decoded sources without eviction.

   See [state.rs:236](/private/tmp/claude-501/-Users-ccheever-projects-exact2/99504d5c-e64b-441e-a7cc-ed36489b5317/scratchpad/review-1101.001/spike/apps/harness/data/src/state.rs:236), [value.rs:111](/private/tmp/claude-501/-Users-ccheever-projects-exact2/99504d5c-e64b-441e-a7cc-ed36489b5317/scratchpad/review-1101.001/spike/apps/harness/data/src/value.rs:111), [agent.rs:156](/private/tmp/claude-501/-Users-ccheever-projects-exact2/99504d5c-e64b-441e-a7cc-ed36489b5317/scratchpad/review-1101.001/spike/apps/harness/data/src/agent.rs:156), and [image.rs:136](/private/tmp/claude-501/-Users-ccheever-projects-exact2/99504d5c-e64b-441e-a7cc-ed36489b5317/scratchpad/review-1101.001/spike/host/terminal/src/image.rs:136).

   **Resolve it:** split P1 into bounded UI lifetime, bounded resource answers, image-cache policy, and conversation retention. I favor a hybrid: host/runner retirement plus a bounded data window identified by stable entry IDs. Keep archived conversation data separately if needed.

   Change “resident memory is flat” to an explicit accounting statement: which memory is bounded, which remains proportional to retained conversation, and where archives live. `DEFERRED.md` already makes this distinction for virtualized lists.

3. **High — the immutable-prefix contract is underspecified.**

   `aria-busy=false` is not a permanent immutability guarantee. ARIA permits a rendered element to become busy again during subsequent modifications. Turning that state into irreversible output is an additional Exact policy, not simply web behavior. [WAI-ARIA’s definition](https://www.w3.org/TR/wai-aria-1.2/#aria-busy)

   The writer also tracks a **child count**, not entry identity. It detects clearing only when the settled count decreases. Replacing a prefix with another prefix of equal length would not be recognized. See [host.rs:270](/private/tmp/claude-501/-Users-ccheever-projects-exact2/99504d5c-e64b-441e-a7cc-ed36489b5317/scratchpad/review-1101.001/spike/host/terminal/src/host.rs:270) and [term.rs:270](/private/tmp/claude-501/-Users-ccheever-projects-exact2/99504d5c-e64b-441e-a7cc-ed36489b5317/scratchpad/review-1101.001/spike/host/terminal/src/term.rs:270).

   **Resolve it:** declare an explicit append-only contract for inline rendering. Define stable IDs, reset generations, settlement, mutation after printing, interactive descendants, and layout dependencies on retired content. Retiring arbitrary CSS subtrees is harder than retiring a constrained vertical transcript.

   D1 does not require the terminal view to be unaware of its medium—it expressly makes that view terminal-specific. Protect the shared data model, but do not use D1 to rule out a necessary consumption cursor.

4. **High — cancellation and output bounds deserve a proposal of their own.**

   The shell tool collects stdout with unbounded `read_to_end`; the result cap is applied afterward. Cancellation kills the immediate shell, not its descendants. On ordinary shell exit, joining the reader can still wait for a background descendant holding stdout open. See [tools.rs:366](/private/tmp/claude-501/-Users-ccheever-projects-exact2/99504d5c-e64b-441e-a7cc-ed36489b5317/scratchpad/review-1101.001/spike/apps/harness/data/src/tools.rs:366).

   Similarly, HTTP cancellation returns from the receiver loop while the reader thread can remain blocked in `read_line`. The test explicitly acknowledges this. See [providers/mod.rs:303](/private/tmp/claude-501/-Users-ccheever-projects-exact2/99504d5c-e64b-441e-a7cc-ed36489b5317/scratchpad/review-1101.001/spike/apps/harness/data/src/providers/mod.rs:303) and [openrouter.rs:249](/private/tmp/claude-501/-Users-ccheever-projects-exact2/99504d5c-e64b-441e-a7cc-ed36489b5317/scratchpad/review-1101.001/spike/apps/harness/data/tests/openrouter.rs:249).

   **Resolve it:** bound output while reading, own and terminate subprocess groups, make blocked network reads interruptible, and test resource cleanup across repeated cancellation. “The UI stopped showing work” and “the work stopped” need separate assertions.

   - **Wrapping disagreement:** measurement floors available width to columns, while painting wraps again using snapped content width. Sharing the wrapping function does not ensure sharing the wrapping result. 6. **Medium — long streaming responses remain an unbounded live region.**

   An assistant response stays one busy entry until the stream ends. The inline writer displays only the final screenful of that live content. Earlier parts therefore disappear from view without entering scrollback until settlement. Meanwhile, each token reparses the accumulated Markdown. See [agent.rs:191](/private/tmp/claude-501/-Users-ccheever-projects-exact2/99504d5c-e64b-441e-a7cc-ed36489b5317/scratchpad/review-1101.001/spike/apps/harness/data/src/agent.rs:191) and [term.rs:285](/private/tmp/claude-501/-Users-ccheever-projects-exact2/99504d5c-e64b-441e-a7cc-ed36489b5317/scratchpad/review-1101.001/spike/host/terminal/src/term.rs:285).

   **Resolve it:** test one very long response, not only thousands of settled entries. Define how people inspect earlier streaming text and oversized approval previews. Coalesce parsing work, and investigate progressive settlement of genuinely finalized blocks.

7. **Medium — P5 is valuable, but the existing stack does not supply full dialog semantics.**

   The terminal currently routes `show` and `show-modal` to the same operation, and focus traversal is restricted to the top layer. That cannot implement both nonmodal and modal behavior faithfully. The existing `"close"` command also means quit. See [host.rs:174](/private/tmp/claude-501/-Users-ccheever-projects-exact2/99504d5c-e64b-441e-a7cc-ed36489b5317/scratchpad/review-1101.001/spike/host/terminal/src/host.rs:174) and [host.rs:549](/private/tmp/claude-501/-Users-ccheever-projects-exact2/99504d5c-e64b-441e-a7cc-ed36489b5317/scratchpad/review-1101.001/spike/host/terminal/src/host.rs:549).

   **Resolve it:** start with the needed `showModal(target)` and targeted close behavior. Specify target resolution, execution after commit, focus restoration, Escape/cancel, and close events. Add `show()` when nonmodal behavior is implemented. The distinction belongs to the [HTML dialog contract](https://html.spec.whatwg.org/multipage/interactive-elements.html#the-dialog-element).

The syntax parser is absent, so this establishes a discrepancy, not proof that the implementation works. Compile a minimal example before scheduling a language feature. Some details behind that ranking:

- **The harness currently discards rejected drafts.** `sendText` clears the composer immediately, while `submit` refuses ordinary prompts when already busy. Preserve the draft until acceptance, or deliberately queue it. This is a more immediate usability improvement than another animation. - **P14 must verify what actually appeared.** Headless inline `print` renders the entire current document; it does not exercise the inline writer’s history or cursor accounting. A correct headless screenshot can coexist with broken terminal output. - **P7 should say “may overflow.”** Flex shrinking and containing-block constraints matter. Whitespace warnings must account for inherited styles; recommend `gap` for spacing between items and `pre` for meaningful literal whitespace.
- **P8 should not add grapheme-indexed `at` just for a spinner.** A list of frame strings plus existing list `at` already represents that problem. Grapheme access could be useful, but should have an explicit indexing model consistent with Contract’s existing UTF-16 string operations.
- **P9 belongs on an event-dispatch result.** Cancellation describes an event, including a handler that changed no state; it is not naturally a property of every commit.
- **P13 needs two fixes:** instance-local border policy, and correct context-dependent unit resolution. The `ch`/`lh` parser currently uses fixed constants independently of the terminal flag. Moving only the flag is insufficient. - **P4 needs byte bounds as well as message counts**, ordered completion/error delivery, and cancellation that unblocks producers. Avoid making lossy delivery an invisible default for arbitrary SSE.
- **P10 contradicts parent D5 on images:** the parent explicitly treats image protocol as an internal capability, not a web-named application fact. Keep it inspectable through tooling unless a real application decision needs it. Prioritize colour fallback and keyboard negotiation over displaying protocol names.
- **Keep P14 within the project’s scope rules.** Writer fixtures are useful now; a shipped session record/replay facility is explicitly deferred. Map the driver onto the existing ten operations and virtual clock rather than promoting `wait` into the permanent API.

I would also close existing Q2–Q4 now: leave already-printed output alone on resize, choose inline/fullscreen explicitly rather than inferring it from `role="log"`, and bake shipping plans. The no-compilation boot rule already answers the last question.

**Novel ideas**

1. **Make settlement finer than a model turn.** Keep a small mutable suffix while completed blocks enter scrollback. This improves reading during long responses and limits repeated parsing/layout. Markdown has nonlocal constructs, so the producer must explicitly establish finality; an arbitrary blank line is insufficient.

2. **Offer an optional history inspector over an archive.** Normal operation retains terminal-owned scrollback. An explicit command temporarily opens a searchable, reflowable, bounded full-screen view for old messages and complete tool output, then returns to inline mode. That allows the live UI to release old nodes without sacrificing inspection.

3. **Use an adversarial local provider as the next fixture.** Have it emit a huge response, stall mid-event, request approval during typed-ahead input, produce excessive tool output, and resume after cancellation. Vary terminal read boundaries independently. This one consumer would expose more architectural weaknesses than additional visual demos.

**Open questions**

- Is the harness becoming a daily-use coding tool, or remaining an Exact stress consumer? That determines when persistence, resume, and model-specific context limits become essential.
- What exactly becomes immutable: source content, rendered blocks, layout, or terminal bytes? What happens when an app violates that promise?
- Which historical information must remain searchable or available to the model, and which representations can be discarded?
- How large may the mutable tail become? What is the interaction when a response or approval exceeds the viewport?
- Can history retirement reuse existing runner collection lifetime/windowing machinery, avoiding a second lifecycle mechanism?
- What constitutes successful cancellation: immediate UI response, stopped side effects, reclaimed resources—and within what bounds?
- Which small real-terminal matrix will establish the promise: direct terminal, tmux, and a fragmented remote connection?

**Recommended next step**

Revise the RFC around **one trustworthy long-session experiment**. First fix approval activation, rejected-draft loss, and cancellation/output bounds. Drive the real inline writer through the adversarial local provider, including resize and fragmented input.

Measure snapshot construction, settlement, layout, painting, bytes written, retained nodes, and retained data at several history sizes. Use those results to choose P1’s implementation and validate P3. Keep the RFC exploratory until that slice has an implementer and date; leave live images and PNG tooling behind it.
