**1. BLOCKER — `host/web-js/live-time.js:116` (clear at `:95`).** A default JavaScript page is server-rendered and adopted (`host/web-js/build.mjs` `--render rust`; `rt.js:1399` sets `Adopt` when the checkpoint script is present and `#exact-root` already has an element). The document writer puts the runner's `text` in the element and then writes the fallback children (`host/web/src/document.rs:708` and `:837`), and `data-time-shown` is already on the tag (`host/web/src/element.rs:835`). Before the runtime runs, that page is correct: one formatted text node, and `time[data-time-shown] > *` hides the fallback span. `liveTime` then always does `if (!shown) { shown = document.createTextNode(''); e.prepend(shown); … }`. It never reuses the text node the renderer already wrote. `adopt()` in `rt.js:650` skips non-element nodes and leaves them in the tree. After hydration the time shows the formatted string twice. Later ticks write only the prepended node, so the server string freezes beside the live one. When the instant cannot format, `shown?.remove()` at line 95 drops only the live node and removing `data-time-shown` reveals the fallback, leaving the server text node next to the children. That is the double-draw this commit is fixing, on the path production pages take. `host/web/live-time-glue.js:38` already does the right thing: it reuses `firstChild` when that child is a text node, and `text(null)` removes it. A fresh `--render none` build has no prior text node (`emit.rs:1408` emits children, then `liveTime`), so the dev loop stays correct. The agent and the fixture miss it because `agent.js:47` reads only `firstChild`, and conform compares `props.text` plus box width. Relative and timer reservations are wider than twice the current short string, so the synthetic `time` contract (relative, timer, countdown only) still fits. `date-medium`, the default format, reserves only the current string (`kernel/src/time.rs:244`), so doubling it also grows the box past wasm and the native hosts.

Fix: if `firstChild` is already a text node, adopt it as `shown` instead of prepending, and drop any extra leading text nodes. On `text == null`, remove every leading text node, matching `live-time-glue.js` `text()`.

**2. SHOULD-FIX — `host/web/live-time-glue.js:29`.** `sync()` sets `min-inline-size` for every connected time that has `data-time-reservation` and whose parent is not a `data-exact-text` paragraph. The JavaScript compiler passes `reserve=false` when the time has a `width` or `max-width` binding (`host/web-js/src/rows.rs:52`), because a CSS minimum wins over a smaller `width` and over `max-width`. The kernel only grows the intrinsic offer (`kernel/src/time.rs:249`) and leaves a definite width alone, so Apple and Linux keep the author's size. `time datetime=… format="relative" width=40` (or `max-width=40`) stays at 40 on the JavaScript target and on the native hosts, and grows to the reservation on the wasm page. The native-fixture row has no width, so that suite stays green. The module's own comment says it should match those two.

Fix: in `sync()`, if `el.style.width` is set or `el.style.maxWidth` is set, clear `min-inline-size` and return, the same way an inline parent already does. The wasm host writes authored style into `cssText`, so those inline declarations are the author's. The style `MutationObserver` already re-enters `sync` after a later style write.

**3. NIT — `host/web/live-time-glue.js:8`.** `fontKeys` omits `fontVariantAlternates`, `fontVariantEmoji`, `fontOpticalSizing`, and `textOrientation`, which `host/web-js/live-time.js:60` copies onto the measure span. `text-orientation` changes the inline size in `vertical-rl` and `sideways-rl`, which is what `live-time.test.mjs` asserts for the JavaScript module. Horizontal fixture fonts still match.

Fix: use the same `fontKeys` list.

Checked and holding: fallback children stay hidden only while the time has a text prop, on both targets, once the shown text is a single node (wasm already; JavaScript after finding 1). An inline time's parent carries `data-exact-text`, and `sync()` skips the reservation. Before the module loads, create writes the formatted string while `childElementCount` is 0, children attach without removing that text node, and a later update is stored on `exactTimeText` and applied in `install`. The style observer writes `min-inline-size` only when it differs, so the re-entrant mutation stops. `destroy` disconnects both observers, and a late `install` bails on `retiredViews` or a disconnected element. The wasm agent tree is the kernel's; the JavaScript agent still walks the hidden fallback elements. This commit does not touch Apple or Linux. `live-time.test.mjs` covers `live-time.js` only, and nothing asserts a single text node, `text(null)`, or an authored width.
