**NOT READY.** One input class is decided wrong: a call written in a `members` block does not count actions spliced into other components of that same file.

## Finding

`contract/cli/src/sources/members.rs:305` chooses the action set with `match d.in_block`: a call inside a block is checked only against `component_of` (the one component that owns the block), and every other deferred call is checked only against `own` (actions of the file’s components after the splice). D6 requires both counts when a call is in both places.

D6 (`llp/1091.002-a-component-across-files.rfc.md:83-88`): the method-name checks count, as before, the `fn`s, shapes, and actions of the file the call is written in, and also the actions the component declares in its other files. The colon states both: a call in a members block counts every action of its component, and any call in a file that lists members files counts the actions of that file’s components once their blocks are spliced in. The loader decides this after the splice.

The parser’s `declared` (`contract/syntax/src/parser.rs:338`) sees only `fn`s, shapes, and actions written on `file.components` in that file’s text. An action that arrives through a `members` line is invisible there, so the call is deferred (`in_block` is true for the whole block, `contract/syntax/src/parser/component.rs:26`). After the splice, `Card`’s action `trim` is on `part.contract`’s component, but the block call never consults that set.

`app.contract`:

```
use Card from "./part.contract"
component App
  members "./part.contract"
  view
    column
      text shown
      Card()
```

`part.contract`:

```
component Card
  members "./bits.contract"
  view
    text "c"
members App
  derive shown = " x ".trim()
```

`bits.contract`:

```
members Card
  action trim
    let x = 1
```

What happens: the program is accepted. `shown` is the built-in `trim(" x ")`, the string `"x"`. The same `action trim` written directly on `Card` in `part.contract` is `syntax-method-shadowed` (the suite at `contract/cli/tests/it/members.rs:500`). D6 says the spliced action counts the same way, for any call in the file that lists `./bits.contract`, including this derive.

The free spelling is the other outcome. Change the derive to `derive shown = trim(" x ")`. The compiler reports `syntax-method-form` on that line in `part.contract`. D6 says `Card`’s spliced action counts, so the free call is kept, as it is when `action trim` is written on `Card` in the same file (`declared` skips the deferral). `trim` is not a member of `App`, so the type checker resolves it as the roster function and the program compiles, with `shown` equal to `"x"`.

Fix: for a deferred call with `in_block`, test the union of `component_of` for that unit and `own`. Keep the existing condition `names.contains(&d.name) == d.if_action`. A call outside a block stays on `own` alone, so an action that exists only in the block still does not decide a `fn` or another component in the members file. When the name is in `own`, raise the file-local `syntax-method-shadowed` wording (`rename this file's trim`); when it is only in `component_of`, keep the deferred wording. A file that lists no members files has an `own` set the parser already applied, so those programs stay as they are.
