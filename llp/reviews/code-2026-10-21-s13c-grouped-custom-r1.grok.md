**VERDICT: RIGHT WITH NITS**

The Harmony case is right. A visible custom row's first shown `symbol:` child is drawn at that node's font size with scale `.large`, at its own size, centered, and the separator uses the same x `carry` places the row at, plus the row's content-box min x. For a sheet symbol row that is 56. For a sheet row with no leading symbol, the content box is the row inset (16, or the cell margin once the kernel has applied it), so the line stays on the margin. `carry` is enough while the row stays custom and on screen: every batch's `mount` and `willDisplay` call it again, so a child swap is re-marked, and the setter returns when the flag is unchanged.

Setting the flag does not feed layout. `updateSymbol` queues `SymbolMeasure.size` without the large scale, asynchronously, and the kernel drops that report for a symbol it already measured. The sheet's box is 24 by 20 anyway. Point size `-exact-body` plus scale `.large` is the same glyph as UIKit's body text style at scale `.large` at each body size on the ramp. Authored font size, weight, and symbol rendering still go into the configuration. tvOS never builds this list (`groupedList` is nil there). Both files stay under the 1,500-line cap (1482 and 1492). `contentBox()` as `package` matches `layoutBounds` in the same package.

1. **should-fix** — `listSymbol` sticks after the row leaves the list cell. `GroupedCustomRowsIOS.swift:16-20` only writes the flag on children that are shown at `carry` time. `NodeExtrasIOS.swift:331` then redraws the symbol, and nothing else clears it: `GroupedListIOS.swift:1280` (`restore`, including `remove`), the standard-cell branch at `GroupedListIOS.swift:1041`, and `NodePoolIOS.swift:499` (`recycle` keeps the glyph and the flag). A row that stops being custom is drawn by UIKit, but the image node keeps the list look. It shows again when the list host goes away and the section is unhidden, or when a `children` op moves that image out of the row. A `display: none` sibling is skipped by the loop, so it keeps the flag too. Clearing it on every `restore` would toggle it twice a batch and queue a new intrinsic each time. Clear it when the view actually leaves the custom row.

2. **should-fix** — The separator inset is a physical left x stored in a directional leading inset. `GroupedCustomRowsIOS.swift:30-31` uses `grid.layout.minX` (the same x `carry` uses, so in left-to-right it is in the cell's space) plus `contentBox().minX`. `GroupedListIOS.swift:606` assigns that to `bottomSeparatorInsets.leading`. In right-to-left, leading is the right edge, and this module already treats that direction as real (`margins()`, the fold insets). The content's start then insets from the wrong side. `contentBox()` also adds `bounds.minX` (`ContentBox.swift:39`), which on a scroll-view row is the content offset. An authored bottom edge is fine: `owned` hides that separator before the inset is written. Editing `.leading` on the configuration UIKit passes into the handler is well-defined. The other edges stay the ones it resolved, and the new test shows 56 replacing the custom cell's 16.

3. **nit** — An authored fit or box does not change the glyph. `NodeViewIOS.swift:597-598` forces `object-fit` to center and turns clipping off whenever `listSymbol` is set. That is required for the sheet's 24 by 20 `contain`, which would scale a large-scale glyph back down into the 20-point height. Font size, weight, and `symbol_rendering` still apply (`NodeViewIOS.swift:570`, `Affordances.swift:122`). An authored `object-fit`, or a width and height other than the sheet's slot, still draws the body-size large glyph in the middle of whatever box the kernel laid out.

4. **nit** — The drawn image's size and the measured size disagree, and one reuse path reports the drawn one. `NodeViewIOS.swift:587` queues the medium-scale measure, which matches the kernel and does not move this row. The image itself is the large glyph. `NodePoolIOS.swift:589` (`finishReuse`) reports `image?.size`, so a parked image that still has `listSymbol` would hand the kernel the large size. Grouped lists are not virtualized, so that only happens when an ancestor list parks the tree. Hit testing still uses the node's box. The image view does not take hits.
