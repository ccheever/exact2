# Design review: LLP 1108.001 r3, GPT-6 Astra

Reviewer: GPT-6 Astra (codex exec, xhigh, read-only), 2026-10-08, blind, on lane/media-slices-2-3 with r3 and the pre-r3 slice-2 draft in the tree. Same brief for both families.

NOT READY

1. **MAJOR — §§2.3–2.5: full-size external-memory pressure conflicts with the 256 MiB bound.** The engine defaults to 64 MiB ([js/src/lib.rs:103](/Users/ccheever/projects/exact2-wt-media23/js/src/lib.rs:103)), installed as Hermes’s maximum heap ([js/src/shim.cc:197](/Users/ccheever/projects/exact2-wt-media23/js/src/shim.cc:197)). [Hermes’s pressure registration](https://raw.githubusercontent.com/facebook/hermes/refs/heads/main/API/hermes/hermes.cpp) checks whether the increment exceeds that maximum; [Hades rejects such an increment](https://raw.githubusercontent.com/facebook/hermes/main/lib/VM/gcs/HadesGC.cpp). Consequently, composing an 80 MiB Blob from an existing 40 MiB Blob can fail while the store holds only 120 MiB. Reporting the full backing size on every slice also duplicates pressure. **Change:** define GC-pressure accounting separately from the store quota, including shared buffers and pressure-registration failures. Test an 80 MiB composed Blob and repeated slices under the default engine configuration.

2. **MAJOR — §2.4: collision checking only live URLs resurrects revoked identities.** Each engine restarts the same seeded stream ([js/src/lib.rs:311](/Users/ccheever/projects/exact2-wt-media23/js/src/lib.rs:311)). Once teardown removes its URLs, the replacement engine’s first draw is available again. An in-memory probe using the repository’s `agentStream` reproduced the same URL resolving to different bytes after removal and restart. A stale URL can therefore display new content—or revoke the replacement object—contradicting §§2.4 and 2.6. **Change:** ensure URL identities are not reused across engine lifetimes, reconcile that with the replay promise, and test both stale acquisition and stale revocation after a seeded reload.

3. **MAJOR — §§1.6/1.8: the JS target has no specified connection between answer abandonment and save publication.** Its TypeScript answer returns only a promise ([host/web-js/ts-data.js:330](/Users/ccheever/projects/exact2-wt-media23/host/web-js/ts-data.js:330)); replacing a resource ticket does not cancel that promise ([host/web-js/rt.js:516](/Users/ccheever/projects/exact2-wt-media23/host/web-js/rt.js:516)). Moreover, `answering.call` is cleared immediately after invoking the source (:322), so capturing it cannot identify saves started after an `await`. R3’s native/wasm per-ticket flag does not cover this executor. **Change:** specify an answer-owned publication token propagated through asynchronous continuations and invalidated by committed abandonment. Test a save started after `await`, followed by refresh or region removal while publication waits.

4. **MAJOR — §1.6: the publication lock resolves ordering, but stalled native I/O still lacks timeout completion.** Staging and writing run synchronously on the executor worker ([host/apple/src/executor_core.rs:966](/Users/ccheever/projects/exact2-wt-media23/host/apple/src/executor_core.rs:966), [executor_save.rs:153](/Users/ccheever/projects/exact2-wt-media23/host/apple/src/executor_save.rs:153)); `Staged::publish` blocks in `sync_all` before renaming ([app_fs_unix.rs:755](/Users/ccheever/projects/exact2-wt-media23/vendor/ibex/crates/ibex2/src/stdlib/app_fs_unix.rs:755)). Clearing publication authority cannot return `Timeout` while those calls remain blocked. **Change:** specify bounded off-thread save work and independent request settlement, retaining its worker reservation until blocked work actually exits, as `exactBodyFrom` already does ([executor_body.rs:102](/Users/ccheever/projects/exact2-wt-media23/host/apple/src/executor_body.rs:102)). Test stalled staging, writes, and sync—not just cancellation before rename.

5. **MAJOR — §2.6: releasing the video acquisition on item replacement can race resource-loader callbacks.** Replacement occurs at [host/apple/videoarm/VideoArm.swift:380](/Users/ccheever/projects/exact2-wt-media23/host/apple/videoarm/VideoArm.swift:380), while the proposed delegate reads on another queue. Item replacement does not establish that its current callback has stopped reading the pointer. Apple also keeps the [resource-loader delegate weakly](https://developer.apple.com/documentation/avfoundation/avassetresourceloader/delegate). **Change:** explicitly retain an item-specific loader owner; let callbacks retain the acquired buffer, cancel/detach old requests on replacement, and release only after the last callback/owner finishes. Test replacement and destruction during a held range callback.

The status/header gate, preserved refusal bodies, pseudo-header carrier, and client staging/publication split resolve parent Astra r4 #7 at the design level. The other material earlier corrections are represented in r3. Charlie’s slice order is respected; I found no additional boot-path, apparatus, or source-cap violation. No files were modified.
