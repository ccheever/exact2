1. **SHOULD-FIX — Obsolete responses can corrupt a new pairing.** In [wire.ts:88](/tmp/rv-dt-t6s2r2/apps/design-tool/wire.ts:88), `askToken()` checks `paired` before awaiting `res.json()`. Pairing can complete during that await, after which the local response overwrites the paired token. `BEFORE` prevents leakage, but subsequent requests fail. Separately, a delayed 401 from an earlier pairing unconditionally clears the **new** session at [line 120](/tmp/rv-dt-t6s2r2/apps/design-tool/wire.ts:120). Check the request’s session generation before changing credential state. The scope test delays `fetch`, so it misses the JSON-completion race and re-pairing race.

2. **SHOULD-FIX — The stub can still write a scrub after expiry.** The new [authorization callback](/tmp/rv-dt-t6s2r2/apps/design-tool/stub/tamber-stub.ts:81) checks membership in `paired`, without checking the deadline. If a scrub release starts before expiry and waits on a slow preview, no subsequent request need trigger `who()`’s sweep; release can then write after expiry. The real server checks the deadline through `pairs.live()`. Explicit revocation is now handled, but the callback must also reject an expired entry independently of the sweep.

3. **SHOULD-FIX — Cached selections are seeded before their build metadata.** [waitChanges:1027](/tmp/rv-dt-t6s2r2/apps/design-tool/app.ts:1027) prepends cached selections before the hello resynchronization. On a fresh reader whose poll reports `missed`, `buildsNow` is empty, so the selection records `at: ""`. The subsequent [hello/latch](/tmp/rv-dt-t6s2r2/apps/design-tool/app.ts:1089) immediately marks it “its build has moved on.” That disables its token links and editing provenance despite the cached selection being current. Establish the build snapshot before constructing the restored selection; also avoid replaying older events over a newer refresh snapshot.

4. **SHOULD-FIX — Read-scope drafting controls remain enabled.** [“Only this mode”](/tmp/rv-dt-t6s2r2/apps/design-tool/app.contract:1703) still creates a draft through an unguarded action and produces a scope refusal. Other omissions include the [pin selectors and font field](/tmp/rv-dt-t6s2r2/apps/design-tool/app.contract:1517), held-proposal token/override/item checkboxes at lines 1830, 1846 and 1865, the Remove dialog opener, and the import-kind selector. Lock drafting controls at their applicable scope and guard the drafting actions. The wire contains forbidden requests; the promised greying remains incomplete.

5. **SHOULD-FIX — The integration test bypasses the real remote boundary.** [design-tool-pair.test.mjs:23](/tmp/rv-dt-t6s2r2/scripts/design-tool-pair.test.mjs:23) starts an ordinary local server. Its handmade proxy strips `Origin` and forwards every path, including the local token endpoint. It therefore cannot validate stage B’s Origin restriction, remote-only authentication or path restrictions—the mismatch round 1 specifically identified. Use the actual trusted-tunnel or TLS listener. Also, revocation happens after the browser has exited and is checked directly against the local origin, so this test does not establish that revocation ends the running tool’s access through the door.

6. **NIT — The secrecy assertions claim more coverage than they provide.** [The checks](/tmp/rv-dt-t6s2r2/scripts/design-tool-pair.test.mjs:66) cover observed proxy paths, returned agent state/logs, and literal secret bytes in the retained browser profile. They do not inspect server stdout/stderr, requests elsewhere, live session storage, or encoded storage values. The profile lookup and browser shutdown are appropriate; the raw-byte scan is useful but narrower than “no storage.” Strengthen those observations or narrow the claim.
