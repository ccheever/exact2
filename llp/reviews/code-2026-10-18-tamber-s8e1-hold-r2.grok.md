# Review round 2, LLP 1121 stage 8 E1 (held states), Grok 4.7 (xhigh)

**RIGHT WITH CHANGES.** Round 1’s blocking defects are fixed in `6ff6628fb`: a settled wasm generation lets the hold go unsaid (`holdQuiet` before `replaceChildren`) and takes it again under the same plan; registration with no hold and a failed correspond both frame `hold: null` at a new revision; only a report of the last revision counts; the JS target serializes holds, loads `rt.js` beside `app.js`, and puts `held` on layout and selections; `unsupported` is owner-only; instance paths compare with sorted keys; a real press already on the held node keeps its paint; hover and focus snap, and leaving the node lets them go. The approved plan file is not on disk. What remains is below.

1. **SHOULD-FIX — An in-flight wasm `hold()` can still delete the server hold across a generation.** `host/web/dev.js:695-711`, `host/web/glue.js:1354`, `scripts/tamber-builds.mjs:193-195`, `scripts/tamber-builds.mjs:365`. `hold()` yields on the glue wait (up to 2s) and on `planDigest()` before it walks `exact.views`. `reloadGeneration` is not on that queue. `holdQuiet` only stops the observer. A walk that resumes on the new tree with the old site reports `{kind:'held', state:null, reason:'gone', revision}` for the revision `holdSent` still names, so the server deletes the hold. The status that follows calls `replayHold` with `always` false, which returns immediately when the record is already gone. Capture `exact.generation` before those awaits. If it changed, return without reporting and let `rehold` (same plan) or the status replay (new plan) own the frame. A same-plan unmount that is not a generation swap must still report `gone`.

2. **SHOULD-FIX — A JS instance path that fails to resolve compares equal to `[]`.** `host/web-js/inspect-dev.js:179`, `host/web-js/inspect-dev.js:447`, `host/web-js/inspect-dev.js:468`. `instanceOf` returns `null` when an `each` row’s key cannot be found. `canonical` is `JSON.stringify(v ?? [])`, so that `null` becomes `"[]"`. A hold with an empty instance path then matches that element. One such mounted node is held; the real `[]` node plus one failure becomes two and answers `gone`. Skip the element when `instanceOf` returns `null`, the same as `nodeOf` already does.

3. **SHOULD-FIX — `held` in the listing can disagree with the live hold.** `scripts/tamber-builds.mjs:377-392`. A hold `unsupported` deletes `holds` and tells the owner, and leaves `b.held` at whatever state was last applied, so the listing shows `hold: null` and `held: {state: <previous>}`. A non-null `held` report is stored whenever `revision === holdSent`, including when `holds` has no record (the positive report that follows a `replaced` at the clear frame’s own revision). On `what === 'hold'`, set `b.held = null`. Apply a non-null `held` state only while `holds.get(id)` is present.

4. **SHOULD-FIX — `active` holds a link that has no press handler.** `host/web/input-glue.js:351-353`. The selector is `[data-exact-on~=press],a[data-view][href]`. The ruling and LLP 1122 D8, and the §10 body at `llp/1121-tamber.rfc.md:3495`, resolve `active` to the innermost node with a `press` handler; a site with no press node answers `gone`. A mouse press does not paint a bare link (`input-glue.js:407-414`). `closest("[data-exact-on~=press]")` only; otherwise `{reason:'gone'}`. Correct the “After review round 1” bullet at `llp/1121-tamber.rfc.md:3515`, which documents the wider selector.

5. **SHOULD-FIX — A hold stored with no plan digest never corresponds.** `scripts/tamber-builds.mjs:196`, `scripts/tamber-builds.mjs:365`. Correspondence runs only when `h.plan && plan && h.plan !== plan`. A status applies the first digest only when both the previous and the new digest are truthy (`was && b.planDigest !== was`). A hold taken while `planDigest` was still null keeps its old site numbers across later plans: the null-to-first change does not replay, and every later `replayHold` skips `correspond` because `h.plan` is still null, then adopts the new digest. Replay whenever a digest is newly known or differs, and correspond when the stored plan is missing.

6. **SHOULD-FIX — Re-applying the current revision reports `replaced` and ends the hold.** `host/web/dev.js:709`, `host/web-js/inspect-dev.js:473`, `scripts/tamber-builds.mjs:251-254`, `scripts/tamber-builds.mjs:377-379`. `exact.hold` always `letGo("replaced")` first, and that callback reports `replaced` at the frame’s revision. A newer revision is ignored, which is the round-1 fix. A second delivery of the same revision is not: the polled queue resends the unacked answer (`ack < last.seq`), the `replaced` report matches `holdSent` and deletes `holds`, and the following positive `held` does not put the record back. The wasm generation path avoids this only because `holdQuiet` lets go without a callback before `rehold`. In the dropped callback, skip the report when the replacement is a frame with the same revision. An agent `hold` that never updates `channel.hold` must still report `replaced`.
