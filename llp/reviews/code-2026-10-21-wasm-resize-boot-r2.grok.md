1. **Round 1 is closed.** The first-size promise sits in `mediaAttaching` (`host/web/glue.js:558`), and `finally` deletes that same promise. Module replacement still calls only `waitForInflight` (`host/web/glue.js:1300`), which goes through `httpHelpers()` to `moduleReady` and never sees this set, so a pending first size cannot stall activation. Reload calls `el.exactResize?.()` (`host/web/glue.js:1348`) before `mediaAttaching.clear()` (`host/web/glue.js:1353`), so a settle already inside `Promise.all` is woken. The geometry case waits until `exact.observeResize` exists, then one frame, then two more only if the tab row was already observed (`host/web/tests/resize-boot.test.mjs:155-161`), and throws at 20s if the glue never runs. There is no successful time fallback. The prerequisite reads `bake.json` at `binary.configuration.flags.EXACT_WEB_LINK` (`host/web/tests/resize-boot.test.mjs:31`), the same path `scripts/app.mjs` writes.

2. **Each hold is released once.** `landed` only fulfills the promise, and `finally` runs once, so a second call is a no-op. First report: the kind-39 `send` is in `try`/`finally`. No box: `!isConnected || !getClientRects().length` fulfills before the timer is armed. The 2s bound (`__exactFirstSizeBound ?? 2000`) is armed only after resize-glue and `geometryLoading` settle, then cleared from `first.then`. Both destroy sites call `el.exactResize?.()` (`host/web/glue.js:603` and `host/web/glue.js:825`); a same-batch create-then-destroy misses the pre-pass and hits the `case "destroy"` call after `attach` stored the resolver. Reload resolves every view still in the map, then clears the set. A load or `observe` rejection hits the per-element `.catch`, which fulfills. A shared `resizes` rejection releases each element’s own promise; one `observe` throw does not reject the shared promise.

3. **The hold cannot hang past the existing settle bound, and it does not slow a normal page.** `mediaAttached` (`host/web/glue.js:1077`) races the set against `SETTLE_DEADLINE_MS` (20s). `clock settle` awaits that at the start of each round (`host/web/glue.js:1232`) and loops while `mediaAttaching.size` is non-zero (`host/web/glue.js:1250`), at most 16 rounds. `clock data` does the same (`host/web/glue.js:1226`). A hung resize-glue or geometry-glue never arms the 2s timer, so that settle returns unsettled at 20s, as on the JS host. The live clock (`startClock`) and a non-agent page never read the set. Activation does not either.

4. **The conform wait is kept.** The JS host counts the first size in `inflight.n`, and conform compares only after `clock settle` (`host/web-js/conform.mjs:501`). Those holds already exist before the advance (the resize plan’s panel is in the boot tree), and `mediaAttached` waits for them before the clock moves. What moved out of `inflight` is the flow-stop wait at `host/web/glue.js:1238` and the `inflight` count on a plain `clock +N` (`host/web/glue.js:1248`). A jump on this host already did not wait for ticketless work except at a text-flow stop. The trailing `clock +60000` runs after boot settle has delivered the first size. The synthetic resize plan has no text flow, so this does not change a conform compare.

5. **The test fails for the cause it names.** Reports stay held, with the bound at `1e9`, until 300ms after settle starts, so a missing hold returns in a few milliseconds and `ms >= 300` fails. The no-box row is never delivered; if its promise stayed in the set, settle would hit 20s and `settled` would be false. The geometry gate stays shut until resize-glue has evaluated. That flag is set at module eval, while `observe()` itself waits on `geometryLoading`, so opening the gate there cannot deadlock. If the chain does not wait for geometry, the tab row is observed before the gate opens, the extra frames let `frame()` read `geometry?.read(...) ?? 0`, and `widths > 10` fails. A dist without `EXACT_WEB_LINK=all` is skipped instead of failing that same assertion.
