## Findings

1. **SHOULD-FIX.** While another design file is open, a newer describe of the app design does not refresh or clear the part list. `libraryParts` is updated only from `loadDesign` when the open file is the app design (`app.ts:716-719`). Opening `other.tamber` correctly refuses to replace the map with that file's components. The app design is still described, by `loadAppAxes` (`app.ts:1350-1359`): no `file` argument, so it is the app design (`tamber_base.rs:161`), and on success it writes `designAxes` and drops `ir.components`. Scenario: the app design has been read, so the outline lists `surface` and `body · its slot`. The user opens another design file. Someone edits the library so `body` is no longer the slot and `footer` exists. `filesAt` changes, `loadDesign(other)` skips the map, `loadAppAxes` describes the app and ignores `parts`. A fresh selection still shows `body · its slot` and never lists `footer`. The opposite describe, one that no longer includes `parts`, leaves the old list in place. On the app file itself (`file === ""`, the boot path and the contract test) replace-and-clear works. Until D3 the real map is empty either way, so this does not mis-draw today. `designAxes` in that same `loadAppAxes` callback is the pattern that already keeps an app-design fact current while another file is open.

2. **NIT.** The sentence "Its rows are the package's recipe: read only here." (`app.contract:1630`) is broader than the guard. `editable` returns a param rung before it ever consults the package reason (`tamber-inspect.mjs:366-375`). A library row whose whole value is one component param still gets `selrow-edit`; that writes the app's param, not the package file. A value that names a token can still get `selrow-link` ("Open …") with `rung` null; the branch editor already treats a package token as read-only (`app.ts:771`). The new test uses a hex row, so neither control appears, and the assertions match that payload. review2 is met: the view does not invent a write, and the guarded row renders reason text with no write control.

3. **NIT.** The new test never holds a state, so `heldrow-link`, `heldrow-state`, and `heldrow-row` are unasserted. Held recipe rows share `row()` with the base row, and the selection-only outline matches (a). A hold on the library node itself would sit under the same read-only sentence with the same guard.

4. **NIT.** The stub's part groups are `"box"` and `"text"` (`app.test.contract:2004`). Declared groups are identifiers such as `paint`, `shape`, `space`, and `control` (`parser/anatomy.rs:24-35`). The outline ignores `groups`, so the test still matches `library()`'s `{name, groups, slot}` shape. A later assertion on groups would be copying the wrong vocabulary.
