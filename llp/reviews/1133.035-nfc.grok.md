1. **MATERIAL — Tier 1 on iOS is an NDEF session, which cannot write.** D5 (line 237) makes `NFCNDEFReaderSession` the reader and switches to `NFCTagReaderSession` only when `apple.polling` asks for a tag type (D11, line 405). D7 (lines 300–318) then writes with `NFCNDEFTag.queryNDEFStatus`, `writeNDEF`, and `writeLock`. D4 (lines 210–213) treats `once` as that session invalidating after the first tag, citing Apple's tag-reader sample. D15 (line 514) puts only `TAG` in `com.apple.developer.nfc.readersession.formats`. From memory of Apple's Core NFC docs: `NFCNDEFReaderSession` delivers `[NFCNDEFMessage]` from `readerSession(_:didDetectNDEFs:)` and has no write API; `invalidateAfterFirstRead` is that session's initializer flag. `queryNDEFStatus`, `writeNDEF`, and `writeLock` are on `NFCNDEFTag`, reached only after `NFCTagReaderSession.connect(to:)`. The tag session has no `invalidateAfterFirstRead`. The entitlement value `TAG` is the one Apple documents as read-and-write and pairs with the tag session; `NDEF` pairs with the NDEF session. A session whose format is missing from the array fails at `begin()`. One shared session also cannot be `invalidateAfterFirstRead` while any non-`once` claim is still live (D6, lines 260–273). **Decision:** Tier 1 read and write both use `NFCTagReaderSession`. The unsaid polling set is `.iso14443`, `.iso15693`, `.iso18092`, and the unsaid Info.plist lists include the NDEF Type 4 AID `D2760000850101` and the NDEF FeliCa system code (I remember it as `0x12FC`; the wildcard `0xFF` is rejected). `apple.polling` narrows that set and is what adds `apple.tag`; it does not change session class. App-supplied AIDs and system codes are added to those NDEF entries. While any claim is live, the session's polling is the union of the live claims. `once` drops that claim after its first successful NDEF read and invalidates the shared session only when no claim remains. The entitlement value stays `["TAG"]`. `serialNumber` on iOS is the tag identifier at tier 1. Checklist item 14 records a tag session: a detected tag with no NDEF raises `readingerror` and the scan continues; a tag the session does not report (no matching AID) leaves the scan waiting.
