## Run 1

DO NOT LAND

1. **BLOCKING** — After a frame task, the agent’s seek hears every timer at the last display wall. `frame_at` stores the wall in `input_cap` and leaves the runner at `targetTimestamp` (`host/apple/src/first_frame.rs:51-56`). `wall` clears that cap only once a later wall time has caught the runner (`first_frame.rs:62-68`). While frame tasks are firing, every callback resets the cap and the following tick’s wall is still behind the target, so the cap stays set for the whole session. Takeover turns the rule off (`Agent.swift:489-492`, `Session.swift:399`) and does not clear the cap (`first_frame.rs:74-78`). The stepped seek then calls `advance_until_request`, which never calls `wall` (`host/apple/src/host.rs:903-905`); `land_then` does not either (`host.rs:910-912`). Both commit through `engine_time`, which clamps every receipt to the stale cap (`host.rs:1252-1253`, `first_frame.rs:96-101`). The rule is already off, so those curves start at that instant. The `tick` after the seek (`Agent.swift:537`) finally calls `wall` and jumps the engine to the landed time, so a timer that was due seconds later is sampled as if it had been running since the old wall. `Host::advance` does call `wall` first (`host.rs:895-898`); the production path uses `untilRequest: true` (`Agent.swift:648`). The takeover test uses `advance` and never calls `frame_at` (`host/apple/src/first_frame_tests.rs:129-138`), so it stays green. **Fix:** clear `input_cap` when the rule turns off, and call `wall(now_ms)` at the start of `advance_until_request`, before the runner moves. Add a host test: `frame_at`, then `start_on_frame(false, …)`, then `advance_until_request` across two timer dues, and assert each curve’s begin is its own due time.

2. **MINOR** — While a curve is pending, `spring_descriptor` and `spring_frames` report the unshifted `running.start` (`motion/src/engine.rs:621-646`). D1 says that reported start is `start + (sample_time − begin)`. `play_transition` copies the same raw start, leaves the `Running` on the slot, and does not drop `self.pending` (`motion/src/engine/played.rs:69-77`), so a later `present_frame` can still move it after the host has copied it. No current host calls these with the switch on. **Fix:** if `pending` is `Some(begin)`, report and hand over `start + (sample_time − begin)`, `take_running`, and remove the key from `self.pending`.

3. **MINOR** — `Engine::remove` / `remove_property` drop the slot and `self.running` but leave the `self.pending` key (`motion/src/engine.rs:350-392`). `forget_clock` drops membership and leaves `clocks.pending` (`motion/src/engine/clock.rs:225-228`). A stale running key is inert (`present_frame` shifts only a curve that still has `pending`), and `quiescent` does not read `self.pending` (`engine.rs:674-676`). An orphan clock origin does keep `quiescent` false until the next `start_clocks`. **Fix:** drop that node’s keys in `remove` / `remove_property`, and drop `clocks.pending` (and the origin) when the removed node was the clock’s last member.

4. **MINOR** — The new tests pin “pending linear opacity starts at the next frame” and “one `frame_at` leaves `engine.now` at the wall”. They would not fail the bug in finding 1, a resample that skipped `advance` (a linear opacity at local 0 is 0 either way), path reversal, a fling beside a pending curve with `shown` already past the release, play matching, drag bind/unbind, clock resume/rebind with the switch on, in-tick birth, flights, or exits. The RFC’s Swift cases (two dropped callbacks, filtered-SVG pixels, bare `take`, prepare-then-commit) are not in the commit. `boot()` turns the latch on after `Host::boot` (`first_frame_tests.rs:34-46`), so it does not pin the production order, which does set the latch before `sync.apply` (`host.rs:462`, `host.rs:534`). **Fix:** add the `frame_at` + `advance_until_request` test from finding 1, one post-`present_frame` assertion that a cached mid-curve value is replaced by the sample at the frame, and the switch-on lone-resume / paused-rebind cases already described in §5.

5. **NIT** — `exit_end` folds from `sample_time` (`motion/src/engine/first_frame.rs:117-121`), so an exit that has already finished reports `sample_time` rather than `start + end_time`. Destroy still happens on that present (`presence.rs:329-331`). **Fix:** fold the real ends only.

6. **NIT** — Unbind now calls `schedule_animations` even with the switch off (`motion/src/engine/timeline.rs:102`). A node that is not on a clock was previously left out of `animating` by `seek_timeline`; it now resumes from the timeline’s local time. That is the resume D3 describes. Worth a switch-off assertion so the suite records it.

File caps hold (`host.rs` 1482, `Session.swift` 1499, `abi.rs` 1399). The first-frame split matches the surrounding style. With the switch off, `shown` stays 0 and `pending` stays empty, so the shared engine’s new branches are idle apart from finding 6. Web and Linux never call `present_frame`.

## Run 2

DO NOT LAND

1. **BLOCKING** — After `frame_at`, the wall cap is not the input clock. `frame_at` stores the wall and `frame` leaves the runner and `host.now_ms` at the target (`first_frame.rs:51-57`, `host.rs:923-931`). Holds then assign `self.now_ms = input` with no `max` and no `wall()` (`holds.rs:73`, `height_drag.rs:130` and `:207`, `transform_drag.rs:239`, `:266`, `:337`). `begin_hold` / `update_hold` / `update_transform_hold` have already moved `engine.now` to that input (`hold.rs:215`, `:272`, `:179`).
   - A transform or height release then commits a receipt stamped at `runner.now_ms()` (`transform_drag.rs:129-133`; the runner ignores a time behind itself, `runner/src/runner/commit.rs:305-310`). `engine.advance(engine_time(target))` seeks back to the stale cap (`host.rs:1252-1254` and `:1285-1286`, `first_frame.rs:96-101`) and trips `ClockWentBackwards`. Debug builds assert. Release builds drop the seek.
   - A move that only rewinds `now_ms` makes the next `wall()` drop the cap, because the clear compares the cap to `host.now_ms` (`first_frame.rs:62-68`). The following `dispatch_at` is heard at the frame target, past the wall. `dispatch_at` itself is fine only while `now_ms` is still the target (`host.rs:877-882`); `first_frame_tests.rs:107-125` covers that and then calls `engine.begin_hold` directly.
   - The cap also outlives the takeover. `set_start_on_frame(false, _)` does not clear it (`first_frame.rs:83-90`, `Session.swift:399`). `advance_until_request` does not call `wall()` (`host.rs:903-905`), and the agent's jump uses that mode whenever a timer sends (`Agent.swift:641-648`). Those commits are applied at the old cap, so a timer's curve does not begin at its due time. `Agent.swift:486` still says a runner ahead of the wall is not a known path; a frame task is that path.
   - **Fix:** On every hold, drag, and release, call `wall(now_ms)` and set `self.now_ms = now_ms.max(self.now_ms)`. Clear the cap only when the wall passes `runner.now_ms()`. Clear it in `set_start_on_frame(false, _)`, and call `wall(now_ms)` at the start of `advance_until_request`. Add a host test: `frame_at(133, 120)`, then a transform release and a height release at 125, must leave `engine.now() == 0.125` without the commit assert; `dispatch_at` at 128 must leave `0.128`; `advance_until_request(400)` must hear a timer due at 200 at `0.200`.

No Apple caller, and web/Linux never set the latch, so nothing ships wrong. **Fix:** if `pending` is `Some(begin)`, report `start + (sample_time() - begin)`.

## Run 3

LAND

1. MINOR — `Engine::set_start_on_frame(false, at)` does not floor `at` at the sampling time. D5 puts that floor on the engine. The host does (`host/apple/src/first_frame.rs:84`); the engine presents `at` as given (`motion/src/engine/first_frame.rs:29-33`). A call with `at` behind a pending `begin` turns the switch off and leaves that curve pending: `present_frame` only starts `begin <= frame` (`first_frame.rs:60`) and nothing calls it again, so the curve stays in `running` or `animating` and every sample stays at `begin`. Fix: `present_frame(at.max(self.sample_time()))` inside `set_start_on_frame`.

2. MINOR — While a curve is pending, `spring_descriptor` and `spring_frames` report the raw `running.start` (`motion/src/engine.rs:627`, `643`). D1 says that start moves with the wait, the same way `Running::end_at` does (`motion/src/transition.rs:427-428`). No Apple production caller, and web and Linux never set the latch, so this is latent. Fix: report `start + pending.map_or(0.0, |b| (sample_time() - b).max(0.0))`.

3. MINOR — `play_transition` leaves the curve pending (`motion/src/engine/played.rs:69-78`). D8 says a played transition is never pending. The key stays in `self.pending`, so the next `present_frame` shifts the engine's start after the host has copied the unshifted one, and `retire_played` keeps sampling at `begin` until that frame. Apple has no caller; Linux calls it with the switch off. Fix: clear `pending`, drop the key from `self.pending`, and hand over the stored start.

4. MINOR — The new tests miss the paths that fail closed. `motion/tests/it/first_frame.rs` does not run the lone-resume case (`motion/tests/it/clock.rs:136`) or the paused rebind (`clock.rs:209`) with the switch on, and does not pause, drop, replace, reorder, or drag-bind. The fling equality (`first_frame.rs:130-132`) presents at 0.5 and releases at 0.52, so a fling that dropped `v·(shown − release)` still passes. `host/apple/src/first_frame_tests.rs` never births a curve inside a tick, never lands a flight, and never destroys an exit. §5's XCTests (missed target, filter pixels, prepare then take over then commit) are absent. Fix: replay the two clock tests with `set_start_on_frame(true)` and a `present_frame` before the pause; add the shown-ahead fling, one in-tick birth, and one flight land.

5. NIT — `CssAnimations.renderTime` is process-global (`SvgScene.swift:92`). A nested filter's first picture calls `encode` from `scene.apply` (`SvgFilterLive.swift:99-101`), and that encode's `defer` clears `renderTime` (`SvgFilterLive.swift:290-291`) before the outer encode finishes placing later held animations. `beginFrame` uses the local `at`, so those later placements can disagree with the frame. Fix: save and restore the previous value.

6. NIT — Unbind always calls `schedule_animations` (`motion/src/engine/timeline.rs:102`), including with the switch off and with no clock. Parent did not, so after the one dirty frame from the timeline change the node left `animating` and the play froze. `animation.rs:624-628` reads a single `frame()` and passes on that leftover dirty either way. The comment says the play goes back on the clock, so the new behavior matches the comment. If web or Linux depended on the freeze, schedule only when `pending` is set or the node is on a clock, and assert a second advance in that test.

7. NIT — §5 still says the prepared host's committed batch has started specs and that the agent's clock is at least `shown`. r4 D7 does not regenerate the stored batch and leaves the agent clock unchanged. The code follows D7: a prepared host only gets `set_start_on_frame` (`host/apple/src/abi.rs:1330-1332`), and `Session.clock`'s `didSet` passes that clock through (`Session.swift:399`). Fix the §5 sentences to match D7.
