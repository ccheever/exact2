The [chat-rooms](/Users/ccheever/bakeoff/rounds/r17/records/chat-rooms.json), [contacts](/Users/ccheever/bakeoff/rounds/r17/records/contacts.json), and [stopwatch](/Users/ccheever/bakeoff/rounds/r17/records/stopwatch.json) records establish them; the RFC should acknowledge them without assuming they all need framework fixes.

For §9:

1. **Keep the split, but extend Exact’s ownership to its supplied components. Confidence: high.** Do not automatically reflow arbitrary authored rows. Preserve CSS; make semantic form rows and reusable parts adaptive, and let D2 expose authored-layout failures. D2 is a prerequisite: the builder and person must see the same layout. Shared lowering changes need web and Mac references too.

2. **Reject forced Increase Contrast fills. Confidence: high.** Leaving the accent unsaid is good. Darkening an authored accent under ordinary display settings replaces one Exact-specific rule with another. The [UIKit probe](/private/tmp/claude-501/-Users-ccheever-projects-exact2/f19557c6-522e-4e0d-ad80-d6dfdf293992/scratchpad/inv-c/uikit/main.swift) explicitly requests high-contrast colours; its [screenshot](/private/tmp/claude-501/-Users-ccheever-projects-exact2/f19557c6-522e-4e0d-ad80-d6dfdf293992/scratchpad/inv-c/uikit/hc.png) shows ordinary UIKit keeping bright fills. Delete the black-label override and respect actual traits. Report contrast concerns separately; offer an authored tinted style or colour choice instead of silently recolouring.

3. **Approve Done/Search and ordinary-button focus preservation on iOS, with limits. Confidence: medium-high.** Done fits Exact’s existing dismissal behavior. Keep these changes in the iOS presenter; the [Mac native-button path already preserves focus](/Users/ccheever/projects/exact2/host/apple/Sources/ExactKit/Mac/NativeButtonsMac.swift:177). Keep submission/focus policy explicit rather than making `enterkeyhint` an undocumented behavior switch: HTML defines it as a presentation hint. Keyboard inference must also permit all valid values—`step="any"` and fractional minima defeat “no fractional step means integer.” [HTML keyboard hints](https://html.spec.whatwg.org/dev/interaction.html#input-modalities:-the-enterkeyhint-attribute), [number input rules](https://html.spec.whatwg.org/multipage/input.html#number-state-(type=number)).

4. **Expect some verification cost; §7 cannot yet distinguish improvement from noise. Confidence: high.** Measure the added pass directly and total time to a satisfactory app, including repairs. More detected defects can initially increase tokens while improving quality. A fixed ±15% allowance is not an estimate of uncertainty.

The larger lever is **making the copied path complete and reliable**. Replace problematic examples rather than accumulating warnings. The [swipe recipe](/Users/ccheever/projects/exact2/docs/recipes/list-rows.md:32) exposes substantial machinery; a reusable composition in existing Contract could reduce both mistakes and learning cost without expanding the language. Prefer that to guessing deletion intent from English labels or minus symbols. “Every inline delete is a tell” is too broad, as are universal prescriptions for large titles or haptics. Teach the context in which each belongs.

Also qualify the token diagnosis: [1116.013’s measured result](/Users/ccheever/projects/exact2/llp/1116.013-the-context-builders-carry.rfc.md) rejected the shorter-first-read intervention because builders fetched the same knowledge in more steps. Less prose alone is not an established lever.

For §7, use two complementary comparisons:

- **Frozen round-17 apps on old/new Exact:** identical state and traits, with checks for the specific failures, interactions and accessibility—not just appearance.
- **Repeated, interleaved old/new builder runs:** pinned revisions, both models, calibrated blind grading, and some unseen prompts. Reuse 1116.013’s experimental structure. Report paired uncertainty, feature completeness, severe defects, tokens and time.

Calibrate the grader against native references first. It already mistakes real segmented controls for custom ones. Count validated defects by severity and exercised opportunities; “under four tells” can remain a dashboard target, but cannot establish success.

**Verdict: READY WITH CHANGES.** Top three recommendations, in order:

1. Make device-faithful verification and adaptive Exact-owned components the first priority.
2. Remove forced high-contrast recolouring; preserve authored choices and each platform’s behavior.
3. Improve complete reusable patterns, then prove gains with repeated paired measurements and calibrated grading.
