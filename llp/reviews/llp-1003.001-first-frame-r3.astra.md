NEEDS REWORK

1. **P1 — Frame tasks still put the input clock ahead of the wall.** D5 explicitly leaves `Host::frame` unchanged, but it advances `Host::now_ms` to the target, then `commit_tree` advances `Engine::now` there ([host.rs:919](host/apple/src/host.rs:919), [host.rs:1299](host/apple/src/host.rs:1299)). A subsequent, earlier wall-time drag still fails validation ([transform_drag.rs:203](host/apple/src/transform_drag.rs:203)). **Fix:** separate logical frame/receipt times from the input-validation clock throughout `Host::frame`, preserving timers’ due times. Test a frame task followed by input before its target timestamp.

2. **P1 — The specified tick order leaves cached transition values behind `shown`.** D5 advances first, then raises `shown`; D2 describes activation and dirtying, but no subsequent sampling. Today `advance` caches transition values, and `frame` reads that cache ([engine.rs:538](motion/src/engine.rs:538), [engine.rs:580](motion/src/engine.rs:580)). Existing curves therefore need an explicit resample after activation. **Fix:** make `present_frame` activate, sample and retire at the effective sampling time. Apply that same time to direct hold samples ([hold.rs:128](motion/src/engine/hold.rs:128), [hold.rs:367](motion/src/engine/hold.rs:367)) and exit/flight deadline comparisons.

3. **P2 — Filtered SVG is still not held exactly.** R2 Astra 8/Grok 7 remain open. Reseeking installs a *running* animation relative to one wall read ([SvgScene.swift:190](host/apple/Sources/ExactKit/SvgScene.swift:190)); rendering uses a later wall read, after transaction flushing ([SvgFilterLive.swift:298](host/apple/Sources/ExactKit/SvgFilterLive.swift:298), [SvgFilterLive.swift:317](host/apple/Sources/ExactKit/SvgFilterLive.swift:317)). The intervening time advances pending motion. **Fix:** pass one explicit renderer instant through installation and rendering, or materialize held values. Add the missing delayed filtered-SVG pixel test to §5.

4. **P2 — The missed-target disagreement has no one-frame bound.** Ticks are asynchronous, and subsequent callbacks skip ticks while one remains outstanding ([Session.swift:597](host/apple/Sources/ExactKit/Session.swift:597), [Frames.swift:63](host/apple/Sources/ExactKit/Frames.swift:63)). Consecutive late deliveries can leave sampled motion behind absolute-time CA throughout the animation. **Fix:** promise recovery at the next *on-time submission*, or define coherent late-batch resampling. Test multiple missed targets; “the next tick agrees” is insufficient.

5. **P2 — Bare takeover still uses two different instants.** D7 starts pending curves at the engine’s existing sampling time, while `clock take` selects a potentially later wall/runner/shown time and returns without ticking ([Agent.swift:492](host/apple/Sources/ExactKit/Agent.swift:492)). Lowered playback then seeks to `clock − start`, while sampled values remain at their start ([SvgScene.swift:178](host/apple/Sources/ExactKit/SvgScene.swift:178)). **Fix:** pass the takeover instant into the ABI and activate/sample both executors there without firing runner timers. Test bare `take` after a long gap.

6. **P2 — Updating a prepared engine does not update its prepared batch.** D7 propagates the switch to candidates, but preparation caches a separate batch that commit later emits unchanged ([abi.rs:99](host/apple/src/abi.rs:99), [abi.rs:847](host/apple/src/abi.rs:847)). Prepare-on → takeover-off → commit can reinstall `"h":0` after the engine cleared pending. **Fix:** refresh or append activation operations to the cached candidate batch. Test that ordering.

7. **P2 — Clock pause/resume needs an explicit membership rule.** D3 makes resumes pending; D8 excludes pending plays from busy membership. Applied in today’s order, a sole paused member’s resume can make its clock appear idle and reset its origin ([animate.rs:103](motion/src/engine/animate.rs:103), [clock.rs:87](motion/src/engine/clock.rs:87)). Also, an idle clock joined only by paused plays has a pending origin but no pending curve to wake the link. **Fix:** retain resumed membership before assigning pending state, and define frame demand for pending origins. Run the existing lone-resume and paused-rebind cases with the switch on ([clock tests:136](motion/tests/it/clock.rs:136)).

8. **P3 — D4’s resumed start is misstated.** `"s"` must become `frame − held_local`, as D2 specifies, not always the frame instant ([RFC:116](llp/1003.001-motion-starts-at-the-first-frame.rfc.md:116), [RFC:190](llp/1003.001-motion-starts-at-the-first-frame.rfc.md:190)). Correct the wording.

The earlier scalar/path freezing, reversal, settle formulas, ordinary play ownership, exit enqueue/deadline accounting, flight offsets and LLP 1099 component findings are addressed at design level. Pending scheduling/spatial demand and trigger-aligned Signal measurements are also addressed. Every checked on-screen lowering path uses `svg_lower::specs`; native press feedback remains independent. §8 overstates closure of the clock, asynchronous delivery, takeover/reload and filtered-renderer findings above.

- **Q1:** Yes: cached transitions, direct hold samples, and the `engine.now()` deadline reads in [presence.rs:306](host/apple/src/presence.rs:306) and [flights.rs:148](host/apple/src/flights.rs:148).
- **Q2:** Yes; consecutive late batches remove the claimed bound.
- **Q3:** Not fully; see finding 7. Resume, rebind and drag-unbind need explicit membership-preserving transitions.
- **Q4:** Pending cancel adds a stationary return interval, but loses no release velocity. It is a defensible choice; measure cancellation latency alongside native motion.

Simpler implementation: retain curve-owned pending state, with one sampling-time accessor and one activation/resampling path shared by display frames and takeover.
