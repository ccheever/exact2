1. **Blocker.** On the wasm module realm, an iterator's first round is an unmarked continuation, and a refusal of the commit that consumes that round leaves the ticket pending forever. `js/web` returns `Request::continuation` as soon as the realm defers the turn, before the prelude runs, and that request has neither `iterator` nor `call` (`js/web/src/lib.rs:291-293`). `enqueue_round` therefore stores `iterating: false` (`runner/src/runner/rounds.rs:27-29`). The turn runs only after that commit stands (`host/web/module-glue.js:306-332`). A first turn that yields before it awaits comes back as tag 4 on the fulfillment of that continuation (`js/web/src/lib.rs:345-416` sets `iterator` only on the next request). `fulfill_measured` captured `iterating` from the continuation (`runner/src/runner/commit.rs:1205-1206`) and releases on any error only when that flag is set, or the error is `Data` or `Shape` (`commit.rs:1211-1224`). `gate_step`'s `TaskKey` (`runner/src/runner/gates.rs:33-34`), `settle`'s `DeriveType` and `Cycle` (`runner/src/runner/settlement.rs:336-338` and `:265`), and `Value::from_bytes`'s `Plan` (`commit.rs:1315`) are none of those. `conclude` then puts the continuation back (`commit.rs:118-119`, `142-153`). The page has already fulfilled it, so nothing will again. The tag-4 fetch that was enqueued and taken back has no `call` (`js/web` never sets `Request::call`), so `discard_request` (`commit.rs:1072-1075`) does not reach the realm. `forgotten` still sees the key in flight and keeps the parked call (`js/web/src/lib.rs:722-728`, `host/web/module-glue.js:367-371`). `clock settle` waits on that ticket, and the reservation stays taken. Native does not have this hole: `Module::mark` sets `iterator` and `call` before the runner sees the first round (`js/src/lib.rs:1119-1123`). The JS target never opens the stream if the asking commit throws (`host/web-js/rt.js:188-198`). The runner tests build a `Request` that is already marked, and `a_malformed_message_leaves_its_call_to_be_forgotten` only checks a shape error, which is a `Data` error and does release. No test fulfills a wasm continuation whose turn yielded and then refuses the commit with `TaskKey` or `DeriveType`. D2 requires `Request::iterator` from the first round and a release on any refusal (`llp/1110-live-snapback-reads.rfc.md:184-190`, `223-230`). Fix: once `fulfill_inner` has taken an answer with `yielded` or `iterator`, release that ticket on every error, and have `js/web` put the realm call id on `Request::call` so the round taken back is discarded. Add a wasm test whose first turn yields, whose commit then hits a gated task with a non-key, and which asserts the ticket is gone and the realm call was forgotten.

2. **Should-fix.** The 16-stream reservation is taken before the stream a re-read replaces is released, so a refresh at the cap fails. Natively `__exact_call` reserves during `answer`, and `forgotten` runs only after the commit stands (`js/src/prelude.js:1153-1160`, `js/src/lib.rs:783-785`). At 16 open iterators the new call fails, the commit is refused, and the old call stays, so every later refresh fails the same way. On the JS target `Out` runs the new opener before `closeLetGo` aborts the old ticket (`host/web-js/rt.js:210`, `host/web-js/ts-data.js:305-308`). The wasm realm runs the turn after `forgotten`, so a standing refresh there releases first. Fix: drop the replaced call's reservation before reserving the new one, and test a refresh while 16 are open on native and on the JS target.
