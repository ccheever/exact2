## Findings

1. **MATERIAL — D1, D6.** `.t` never applies the string-argument check, and a row action always goes through `.t`.
   **Problem.** `act` is specified to refuse a too-long string argument in parameter order. `.t` is specified as `commit(() => fn(...f(), ...v), "action")`, with no check. Every action whose body touches a row slot is compiled as `($r, ...)`, and the emitter inserts the row object before the empty-argument test (`emit.rs:1182–1189`), so the handler is never the plain wrapper. A row `input` / `change` whose value is `2²⁶ + 1` bytes is `StringTooLong { name }` on the runner (`commit.rs:424–436`, before the body) and is committed on JS. Zipping the contract parameter names from index 0 also checks `$r`, which is not a parameter, and skips the string.
   **Evidence.** `commit.rs:424–436` checks every parameter with `too_long` (`commit.rs:8–11`) before `vm::eval` of the body. D7 case 10 covers a slot store only.
   **Fix.** Build the argument list inside the commit callback, then run one check for both entry points, zipped to contract parameters with `$r` skipped. Add a case whose handler argument is `long(2^26 + 1)` and whose following step is unchanged, reason `StringTooLong { name }`.

2. **MATERIAL — D1, D3, §4.** An unmetered code is specified to be emitted as today, which deletes the checks D3 adds.
   **Problem.** D1 and the emitter test say an unmetered code is emitted exactly as today. A code is metered only when it contains `Map`, `Filter`, or `join`. Case 13 is a record around `long(2^26 + 1)` with no list step, so it is unmetered, and today's emitter builds that record with an array literal (`code.rs:325–331`) and no extent check. The runner traps `ValueTooLarge` in `Opcode::Record` (`vm.rs:658–668`). The same hole is every Caltrain template that becomes `cc`: D5 says those concatenations change, and §4 says the code is unchanged.
   **Evidence.** D4 says nothing is skipped. D3 puts `K` and `cc` on constructions outside loops, which is where an unmetered code builds them.
   **Fix.** Say an unmetered code gets no `$s` and still gets `K`, `cc`, and the checked calls. Point the emitter test at that.

3. **MINOR — D3.** An exact recount that reads the extent cache adds the `3u` upper bound.
   **Problem.** A cached array stores `3u` while that upper bound is under `MAX_VALUE_BYTES`, plus a flag. `nodesOf` is the lookup. A parent whose summed upper bounds cross the cap and whose exact bytes do not will trap if the recount trusts the stored upper bound. Example: 10,000 strings of 1,000 ASCII bytes are 10 MB exact and 30 MB upper, so they stay inexact; three copies are 30 MB exact and 90 MB upper. The runner succeeds. JS traps `ValueTooLarge`.
   **Evidence.** Case 12 is a flat ASCII map, so the cache is never read. Case 15 checks node identity, not bytes.
   **Fix.** An exact-mode add may use a cached byte count only when the flag is set. Otherwise it recomputes UTF-8, stores that total, and sets the flag. Add the three-copy case.

4. **MINOR — D1, D3.** `join`'s steps have two homes, and only one of them can see `$s`.
   **Problem.** D1 adds the list length to the local `$s`. D3 says `x_join`, in `budget.js`, takes those steps. A counter inside `x_join` cannot update the caller's `$s`. A join of 40,000 inside a map that has already run 40,000 then stays under the cap on JS and hits `IterationLimit` on the runner (`vm.rs:766–769` uses the one evaluation counter). Case 8 is a join alone, so either home passes it.
   **Fix.** Emit `$s += length` at the `Call`, then call `x_join` to join and check bytes. Say `x_join` has no counter. Add the nested pair.

5. **MINOR — D1, D6.** On a poisoned runner the argument thunk never runs.
   **Problem.** `commit` returns before its callback when `Poisoned` is set (`rt.js:142`). The runner evaluates handler arguments before `run_action`'s poisoned check (`event.rs:969–971`, `commit.rs:412–414`). A trapping argument is `Trap(...)` there and the poisoned refusal on JS.
   **Fix.** Force the thunk inside the refusal `try` and before the poisoned return. The body still does not run.

6. **MINOR — D3, D6.** The write-loop and `act` checks count UTF-8 from `rt.js`, which cannot see the counter.
   **Problem.** `budget.js` holds the exact counter and is not imported by `rt.js`. Case 10's `long(n)` is ASCII, so a `.length` check passes it. A string of `⌊2²⁶ / 3⌋ + 1` three-byte units is over `MAX_STRING` in UTF-8 and under it in UTF-16 units. `TextEncoder` matches the U+FFFD rule for a lone surrogate.
   **Fix.** State the one-shot test on those existing lines: if `length > ⌊MAX/3⌋`, compare the exact UTF-8 length. Keep the import direction.

7. **NIT — §1, D5.** The re-pin missed the JS sites, and `rt.js` is 1,499 lines.
   **Problem.** `emit.rs:466` is the paint branch; `act` is `emit.rs:433–434`. `memo` is `emit.rs:327–332`, not 370. The locale slot is `emit.rs:478–480`, not 339. `:429` is the `$r` parameter rewrite, not the `args()` callback (`:384` is that callback). `wc -l host/web-js/rt.js` is 1,499, so the file has one line under 1,500.
   **Fix.** Re-pin those four and cite 1,499.
