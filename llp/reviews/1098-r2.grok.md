## New

### MATERIAL

**D10 — the native carriers never send the host wire form.** Stage 1’s Linux test has to deliver the six actions and never a press. D10 names one encoding site: `kind === 'mediasession'` beside `history` at `scripts/agent.mjs:331`. That early-out is the web page carrier. Linux, Windows, and macOS use `openStdio`’s `input` (`:662`). Its last branch, `:670`, asks `{ op: 'type', id, text: opts.text, … }` for every kind other than the ones it lists. The iOS `input` does the same at `:802`. `guest` (`:667`, `:779`) does not carry `mediaSession` or `seconds`. Naming the kind at `:1123` and skipping reveal at `:1119` still lands in that type fallback, so `host/linux/src/agent.rs`’s tap arm never sees `mediaSession`. Fix: in both native `input` functions, `kind === 'mediasession'` asks `{ op: 'tap', id, mediaSession: opts.mediaSession, seconds }` and returns before the type fallback. The web path stays the in-page `exact.mediaSession.act` call.

**D9 — “the commit a claimant first appeared in” is not observable where the paragraph puts the memory.** D5’s Linux rule is mount recency, with document order only inside one commit. D9 tells `agent.rs`’s state walk (`:197–209`) to remember that commit. That walk runs when the agent asks for state. `NodeFlags::CREATED` is cleared during layout by `consume_layout_flags` (`kernel/src/arena.rs:814–824`), before `Presenter::after_commit` (`host/linux/src/presenter.rs:750`) returns. `Presenter` has no commit counter. A map filled while answering `state` gives every claimant first seen on that request the same moment; two claimants mounted in different commits between requests then tie, and preorder picks the one later in the tree. A map keyed only by `ViewId` also goes stale: a wire id is unique only among live nodes (`kernel/src/id.rs:44`) and a freed slot is reused with a new generation (`arena.rs:727`). Fix: on the presenter’s commit path, record first appearance under the row’s `NodeKey` (`kernel/src/export.rs:78`) with a counter the presenter owns. The state request reads that map. Same-commit ties stay document order. Windows agent mode uses this presenter (`host/windows/src/window.rs:98–103`).

### MINOR

**D3 — the latch’s hold condition opens the interval it is there to close.** The latch is set by the remote `play()`, and it “holds while the authored `paused` is false.” With `paused` bound, that write is the later mirror (`playing` → `paused=false` in the summary program). Until that commit, `media-glue.js:15` still pauses because `props.paused === 'true' || state.visibilityBlocked`, and `VideoModule.update` (`:171`) still writes `props["paused"] = "true"` while `visibilityBlocked`. A `play` handler that commits without changing `paused`, or an intersection callback in that window, pauses the element; the app’s mirror of that `pause` then clears the latch. The §5 test only requires that the mirror write itself stays playing, and on the current glue nothing in `play()` calls `syncPlayback` synchronously. Fix: set the latch on the remote play and leave it set across the `paused` value already bound. Clear it only when a later commit writes `paused` true, or when the element rises above the threshold. On Apple, suppress the overwrite at `VideoModule.swift:171` before it is sent.

**D6 — `rel` will not rewrite an artwork source.** The JS `exact.assetURL` is specified as `rel` (`rt.js:551–552`). `rel` returns its input unchanged unless the key is `src` or `poster` and the value is a root-absolute `/assets|deck|shaders/` path. `rel("mediaArtwork", "/assets/art.png")` is therefore the path unchanged, and on a release base `new URL` of that string resolves at the origin root. The wasm half is fine: `localAssetURL` (`glue.js:185–199`) takes the source string and has no key guard; a relative `assets/art.png` is left for `<base href="/">` in production and becomes a card blob when `devAssets` is set. Fix: apply the release rewrite to the artwork string without the `src`/`poster` guard (the pathname test alone, or `rel("src", v)`). Check `""` and `app:/` before calling it.
