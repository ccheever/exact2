r2 still has two blockers: inconsistent authored box sizes and an incomplete native activation path.

I audited `00bd519c3`, treating §2’s measurements as the record. All citations below refer to that revision. I read `1075.003` from the sibling checkout because it is absent from this commit. No files were modified.

1. **Blocker — D6 and D8 disagree about what an authored size includes.**

   D8 restores browser padding and borders while the reset retains `box-sizing: content-box`. Apple instead reports the entire native control as intrinsic content and places that control inside the node’s content box. Thus `width=100 height=40` produces a browser border box larger than 100×40, while Apple’s button occupies 100×40. This violates the parent RFC’s explicit distinction between platform-dependent content and authored box geometry. [index.html:27](/Users/ccheever/projects/exact2-wt-native-button/host/web/index.html:27), [layout.rs:918](/Users/ccheever/projects/exact2-wt-native-button/kernel/src/layout.rs:918), [1069.001:157](/Users/ccheever/projects/exact2-wt-native-button/llp/1069.001-form-controls.rfc.md:157).

   **Change:** Specify one box model before implementation. For this bounded slice, a concrete option is a declared native-button UA row `box-sizing: border-box` on every host, with conflicting overrides refused. Otherwise, account explicitly for native chrome insets in measurement and framing. Require explicit width, height and min/max geometry comparisons; natural-size screenshots will not expose this error.

2. **Blocker — Calling `presenter.press` does not preserve ordinary button activation semantics.**

   D4 transfers touch handling to the native control, bypassing the wrapper code that transfers focus, respects `retainFocus`, and ends editing. Making the wrapper eligible for focus does not execute those steps. iOS `presenter.press` only invokes `onPress`; macOS likewise performs no focus transfer. [NodeViewIOS.swift:1343](/Users/ccheever/projects/exact2-wt-native-button/host/apple/Sources/ExactKit/IOS/NodeViewIOS.swift:1343), [PresenterIOS.swift:494](/Users/ccheever/projects/exact2-wt-native-button/host/apple/Sources/ExactKit/IOS/PresenterIOS.swift:494), [NodeViewMac.swift:1385](/Users/ccheever/projects/exact2-wt-native-button/host/apple/Sources/ExactKit/Mac/NodeViewMac.swift:1385).

   It also changes handler resolution. An ordinary button without its own `press` can activate an ancestor handler; the proposed native action dispatches its own ID, for which the runner returns `NoHandler`. The ordinary iOS agent path resolves the ancestor and performs focus transfer, so agent tests can pass while physical activation differs. [NodeViewIOS.swift:1375](/Users/ccheever/projects/exact2-wt-native-button/host/apple/Sources/ExactKit/IOS/NodeViewIOS.swift:1375), [event.rs:881](/Users/ccheever/projects/exact2-wt-native-button/runner/src/runner/event.rs:881), [AgentIOS.swift:537](/Users/ccheever/projects/exact2-wt-native-button/host/apple/Sources/ExactKit/IOS/AgentIOS.swift:537).

   **Change:** Define a shared activation routine that resolves the target before focus changes, applies the appropriate focus/retention behavior, checks liveness, and dispatches once. Use it from native actions and agent activation. Test real activation with an edited field, a `retainFocus` ancestor, and an ancestor-only press handler. Also specify UIKit focus exclusion: hosted buttons currently enter `FocusSearch`’s foreign-view candidates, while D4 names only AppKit’s exclusion. [FocusSearchIOS.swift:31](/Users/ccheever/projects/exact2-wt-native-button/host/apple/Sources/ExactKit/IOS/FocusSearchIOS.swift:31).

3. **Should-fix — D8’s accent bridge still misses inheritance and dynamic JS writes.**

   Emitting `--exact-accent` only “on a native button” does not carry an ancestor’s declaration. The web CSS emitter visits explicitly set rows, while `accent_color` is inherited. Separately, the JS compiler’s ordinary dynamic style path emits one declaration; adding a second declaration in `css.rs` does not automatically make dynamic bindings update both. [css.rs:40](/Users/ccheever/projects/exact2-wt-native-button/host/web/src/css.rs:40), [schema.json:2703](/Users/ccheever/projects/exact2-wt-native-button/kernel/tables/schema.json:2703), [style.rs:490](/Users/ccheever/projects/exact2-wt-native-button/host/web-js/src/style.rs:490), [style.rs:564](/Users/ccheever/projects/exact2-wt-native-button/host/web-js/src/style.rs:564).

   **Change:** Emit the inheriting custom property wherever `accent-color` is declared, including ancestors, and add explicit multiple-write support to the JS binding path. Define clearing both declarations and translating explicit `auto` to `AccentColor`; a custom-property value of `auto` does not invoke `var()`’s fallback. Test bound ancestor accents, class clearing, local `auto`, and light/dark values.

4. **Should-fix — Refusing typography on the button does not establish D7’s platform-typography boundary.**

   `letter_spacing` and `text_transform` inherit. The existing `all: unset` therefore inherits them, and D8’s proposed `font` reset does not reset either property. A parent with letter spacing or uppercase transformation still changes the browser’s native face while Apple receives the untransformed title and platform typography. [schema.json:2222](/Users/ccheever/projects/exact2-wt-native-button/kernel/tables/schema.json:2222), [schema.json:2670](/Users/ccheever/projects/exact2-wt-native-button/kernel/tables/schema.json:2670), [index.html:27](/Users/ccheever/projects/exact2-wt-native-button/host/web/index.html:27).

   **Change:** Specify the complete inherited-typography boundary. Reset unsupported inherited properties on the web button—at least letter spacing and text transformation—and make Linux’s face measurement follow the same policy. Add a fixture with typography set on an ancestor, not merely forbidden attributes directly on the button.

5. **Should-fix — D6 leaves an animation route around its paint refusals.**

   Keyframes may contain `color`, `background-color`, border colours, tint and shadow. Those properties enter through one `animation` row; checking the button’s attribute names will not find them. D6 does not say whether motion is prohibited or restricted to its permitted opacity/transforms. [svg.rs:376](/Users/ccheever/projects/exact2-wt-native-button/contract/lower/src/svg.rs:376), [tags.rs:826](/Users/ccheever/projects/exact2-wt-native-button/contract/lower/src/tags.rs:826), [lib.rs:679](/Users/ccheever/projects/exact2-wt-native-button/contract/lower/src/lib.rs:679).

   **Change:** Explicitly admit opacity/transform motion and validate referenced keyframes against that property set, including animation longhands, class choices and exit animations. Refuse references whose permitted property set cannot be established. Otherwise the new refusal can reject a direct background declaration while accepting the same declaration through keyframes.

6. **Should-fix — D9 fixes mounting but leaves exit lifetime broken.**

   An exiting subtree stays mounted while its members leave the presenter’s live maps. Both control hosts then remove controls whose IDs are absent from the live index. A native button therefore loses its entire face immediately, even while its wrapper or ancestor continues fading. The glass pass’s weak registration cannot preserve a control that `ControlHost.sync` explicitly removes. [PresenceIOS.swift:17](/Users/ccheever/projects/exact2-wt-native-button/host/apple/Sources/ExactKit/IOS/PresenceIOS.swift:17), [ControlsIOS.swift:99](/Users/ccheever/projects/exact2-wt-native-button/host/apple/Sources/ExactKit/IOS/ControlsIOS.swift:99), [ControlsMac.swift:59](/Users/ccheever/projects/exact2-wt-native-button/host/apple/Sources/ExactKit/Mac/ControlsMac.swift:59). The glass-group contract expressly retains leaving membership while the view draws. [1053.000.000:60](/Users/ccheever/projects/exact2-wt-native-button/llp/1053.000.000-glass-groups.rfc.md:60).

   **Change:** Separate interactive lifetime from visual lifetime. Retire action/agent identity immediately, but retain the mounted control and its last configuration until `endExit`; do not reread its face from a retired kernel node. Test both a button’s own exit and an ancestor’s exit inside a glass group.

7. **Should-fix — D11 misses macOS shortcut/menu projection.**

   `ShortcutHost.nodes()` accepts only `kind == "button"`. A native `Control` carrying `aria-keyshortcuts` silently loses its shortcut and generated menu item. Simply admitting the new kind is insufficient: menu titles are assembled from mounted child `NodeView`s, which D5 removes. [ShortcutsMac.swift:53](/Users/ccheever/projects/exact2-wt-native-button/host/apple/Sources/ExactKit/Mac/ShortcutsMac.swift:53), [ShortcutsMac.swift:143](/Users/ccheever/projects/exact2-wt-native-button/host/apple/Sources/ExactKit/Mac/ShortcutsMac.swift:143).

   **Change:** Add `ShortcutHost` to the integration list: recognize native buttons and obtain names through the semantic face/accessibility reader. Preserve its existing disabled, modal and repeat checks. Test a standalone native button with a shortcut and a changing title. If excluded from this slice, refuse `aria-keyshortcuts` explicitly.

8. **Should-fix — D11 misses canvas controls and their focus-return behavior.**

   `action` is an admitted prop. Under an input canvas, it makes a node a surface control whose wrapper intercepts hits before the hosted button and emits phased module input rather than ordinary `press`. Ordinary HUD buttons also return pointer focus to the canvas through checks requiring `kind == "button"`; native controls fail those checks. [tags.rs:623](/Users/ccheever/projects/exact2-wt-native-button/contract/lower/src/tags.rs:623), [NodeViewIOS.swift:674](/Users/ccheever/projects/exact2-wt-native-button/host/apple/Sources/ExactKit/IOS/NodeViewIOS.swift:674), [CanvasSeams.swift:62](/Users/ccheever/projects/exact2-wt-native-button/host/apple/Sources/ExactKit/CanvasSeams.swift:62), [CanvasSeams.swift:19](/Users/ccheever/projects/exact2-wt-native-button/host/apple/Sources/ExactKit/CanvasSeams.swift:19).

   **Change:** For this slice, add a contextual refusal for native buttons in input-enabled canvases, including `action` controls. Supporting them requires an explicit phased-input adapter and native-button-aware focus return; D4’s primary-action callback does neither.

9. **Should-fix — Moving VoiceOver ownership drops existing accessibility state.**

   D4 specifies the native element’s name and disabled state, but ordinary wrappers also expose selected and expanded state. Those updates are guarded by `kind == "button"` on both Apple hosts, so they cease applying when the wrapper becomes a non-accessible `Control`. A label-only VoiceOver test misses the regression. [NodeViewIOS.swift:997](/Users/ccheever/projects/exact2-wt-native-button/host/apple/Sources/ExactKit/IOS/NodeViewIOS.swift:997), [NodeViewMac.swift:334](/Users/ccheever/projects/exact2-wt-native-button/host/apple/Sources/ExactKit/Mac/NodeViewMac.swift:334).

   **Change:** Transfer supported accessibility state to the native accessibility element, including updates and clearing, without accidentally turning the push button into a value control. Extend acceptance beyond labels to selected/expanded state changes.
