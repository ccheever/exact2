## Overall assessment

An open `net.fetch https://*` grant is the right capability, at the right layer. A Bluesky-hosted account is already covered by `https://*.host.bsky.network` (LLP 1054.000 R5, as built in `grants/src/lib.rs`). A third-party or self-hosted account is not: the PDS origin is the `#atproto_pds` endpoint inside a DID document, and anyone can publish one that names any URL. A prompt, a DID-shaped rule in the executor, and a proxy are weaker bounds with more machinery. The grant grammar is where reach is declared, and CSP already has this spelling. The change to make before ruling is the floor bolted onto that spelling.

## Concerns

### 1. MAJOR — The floor is not CSP's `https://*`, and it does not do what the RFC says it does

D1 admits only DNS names of two or more labels, on port 443, and refuses addresses and single-label names. It says this is CSP's meaning and that the refusals follow Local Network Access and "keep the open grant to the public internet."

CSP Level 3 does not say that. For a host-source, `*` matches only if the URL host is a domain, so address literals already fail (`§6.7.2.10`, step 1, before the `*` check). An omitted port matches the default port only (`§6.7.2.11`). A single-label domain matches. `https://localhost` matches `connect-src https://*`. Local Network Access is different again: it keys off the resolved address space, not the spelling of the URL.

So the two-label rule is a third policy. It does not keep the grant on the public internet. `https://pds.localhost` is two labels and is admitted. So is any name that resolves to a private address, which the RFC defers as DNS rebinding. On the served web, `csp()` copies the target verbatim (`host/render/src/serve.rs`), so the header is `https://*`, and that header allows `https://localhost`. Admission is parity, not a sandbox (`navigation.js`). The reach row will say the CSP enforces a rule the browser does not implement. The RFC calls three parsers agreeing on this floor the hard part. That work exists only because the floor is not the web's rule.

**Resolve it** by defining the grant as CSP's host-source `https://*`: HTTPS, default port, any domain, no address literals. Drop the two-label minimum. In the reach row, say that the served web enforces that CSP token and nothing stricter. State that a name which resolves to a private address is out of scope on native, as it already is for any granted name, and is not what this spelling filters.

## What it gets right

- The gap is real and narrower than the original field report. LLP 1054 D7's exact origins are already widened to one domain. Only a PDS outside that domain fails, for `auth.session` as well as `net.fetch`.
- Rejecting a per-origin prompt is right. The app chooses the origin, a person cannot judge a PDS hostname, and it would undo a grant set fixed at creation (`grants/src/lib.rs`, LLP 0067 §2) and LLP 1069.008's "What stays out," and pull durable capability grants off `rules/DEFERRED.md`.
- Rejecting a resolution rule in the executor is right. A `did:plc` document may name any endpoint, `did:web` is itself on an arbitrary domain, and Mastodon, Matrix, JMAP, and CalDAV do not share a resolver. Protocol knowledge does not belong in three executors.
- Rejecting a proxy is right. It moves the open reach onto a server exact2 does not run, puts DPoP-bound tokens on that path, and adds the latency Charlie refused on 2026-09-26. On the web, CORS already allows the direct call.
- Fetch only, exact `auth.callback`, per-hop refusal of `http` and of address literals, and no prompt, so an agent can drive it. Source scope can already keep the line on the source that declares it (`data/src/mixed.rs`, `scopedGrantSet`).
- Presentation is already open. Served `img-src` and `media-src` allow `https:`, and Apple's image loader fetches any `http`/`https` URL with no grant check (LLP 1011). This RFC opens data-module `fetch`, which is the remaining closed path. Keeping `net.websocket` exact until an app asks is the right cut. The social client's XRPC path is HTTP.

## Questions for Charlie

**Q1 and Q3 stand.** Yes, admit one open spelling. The 2026-09-26 line was "nothing wider" than one domain (`grants/src/lib.rs`: "`*.com` would be every site"). This is wider, and the loud reach row is the right control. No second acknowledgement. A binary release already follows from a changed grant ceiling (`scripts/app.mjs`).

**Q2 is framed short of the real choice.** The alternatives are not "our floor" versus "any port." They are CSP's `https://*` (any domain, port 443, no addresses, including single-label names) versus `https:` (any port). Recommend CSP's `https://*`. A non-default port is rare for a PDS a person actually signs into, and any port admits every service on every host. Do not add a two-label floor the served CSP cannot express.

Saying yes means a source that holds the line can attach the user's PDS token to any request it makes to any matching host. Redirects still drop `Authorization` across origins (`fetch.rs`). A direct request does not. That is the ceiling this grant is. The review row is what makes it visible.
