3. **MATERIAL — D1, line 148: Android’s `charging` mapping contradicts the chosen W3C semantics.**  
   Returning true only for `CHARGING` or `FULL` returns false for `UNKNOWN` and `NOT_CHARGING`. W3C assigns true when charging state cannot be reported and otherwise, reserving false for discharging. The RFC itself identifies a charger holding a charge limit as Android’s `notCharging` case at line 384. This also disagrees with its AC-powered macOS/Linux mappings. Evidence: [W3C §6.1.1](https://www.w3.org/TR/battery-status/#the-charging-internal-slot), [Android battery states](https://developer.android.com/reference/android/os/BatteryManager#BATTERY_STATUS_NOT_CHARGING).

   **Decision needed:** make Android follow the selected shared semantics, retaining its specific status in tier 2, or declare and justify the deviation.

4. **MATERIAL — D2, line 187: Linux’s selected route source excludes IPv6.**

Consequently, the specified “no default route → none” rule reports `type="none"` on a working IPv6-only Wi-Fi connection. This follows from the selected input, rather than an unspecified implementation detail. Evidence: [Linux kernel `/proc/net` documentation](https://www.kernel.org/doc/html/latest/filesystems/proc.html#networking-info-in-proc-net).

   **Decision needed:** choose route discovery covering both address families before claiming the Linux cell reports the app’s routed network.

1. **IN-DELTA — MATERIAL — D3, line 249: the Windows replacement loses modern Energy Saver states.**

   R2 replaces the modern GUID path with `Windows.System.Power.PowerManager.EnergySaverStatus`. That property’s [documented contract](https://learn.microsoft.com/en-us/uwp/api/windows.system.power.powermanager.energysaverstatus?view=winrt-26100) concerns Battery Saver and reports Disabled while plugged in. Windows 11 24H2’s [Energy Saver can remain enabled while plugged in](https://learn.microsoft.com/en-us/windows-hardware/design/component-guidelines/energy-saver). A [Microsoft employee’s response concerning this exact API](https://learn.microsoft.com/en-nz/answers/questions/5579583/powermanager-energysaverstatus-not-working-properl) recommends `EnergySaverStatus2` for the updated experience.

   The selected property therefore cannot reliably implement the promised fact: `lowPowerMode` may be false while the person has Energy Saver enabled.

   **Decision needed:** retain `GUID_ENERGY_SAVER_STATUS` on modern Windows with the legacy fallback, or choose an availability-checked equivalent that reports the updated setting.

2. **IN-DELTA — MATERIAL — D5, lines 322–326: network observation now depends on the battery backend.**

   R1 polled network files independently. R2 places polling of both battery and network files under “Without UPower.” On a Linux system with UPower installed but no NetworkMonitor portal, the plan consequently supplies no observer for route changes. A live `connection().type` can remain stale after switching networks.

   [UPower’s device interface](https://upower.freedesktop.org/docs/Device.html) exposes power properties, not route changes. The [NetworkMonitor portal’s `changed` signal](https://flatpak.github.io/xdg-desktop-portal/docs/doc-org.freedesktop.portal.NetworkMonitor.html#changed) can supply notification when present, but UPower does not establish its availability.

   **Decision needed:** make network observation or its polling fallback independent of whether UPower supplies battery information.

3. **PRE-EXISTING — MATERIAL — D2, lines 181–189; newly exposed by the WireGuard claim and §12 fixture at line 823: the chosen Linux files do not identify the app’s effective route.**

   `/proc/net/route` exposes only the main IPv4 routing table: the kernel’s [`fib_route_seq_start`](https://github.com/torvalds/linux/blob/master/net/ipv4/fib_trie.c#L2708) explicitly selects `RT_TABLE_MAIN`. WireGuard’s own [`wg-quick` default-route setup](https://git.zx2c4.com/wireguard-tools/tree/src/wg-quick/linux.bash#n212) installs the default in a separate table, normally 51820, and adds policy rules.

   Consequently, the specified discovery can select an overridden main-table interface. With an IPv4 policy default and only an endpoint host route in main, it can infer `none` despite working connectivity. This follows from the selected inputs; adding `/proc/net/ipv6_route` does not repair the IPv4 information gap. The new WireGuard classification cannot operate on a tunnel route discovery never sees.

   **Decision needed:** choose policy-aware route discovery, or narrow the Linux fact and its guarantees instead of describing it as the route carrying the app’s traffic.

4. **IN-DELTA — MINOR — D16, line 582; §12, lines 776–778: preferred foreign-platform result fields are preserved.**

   The runner stores the typed preference, [overlays it over the default](/private/tmp/claude-501/-Users-ccheever-projects-exact2/f4b5c629-4ed6-4746-9045-74f6106a629d/scratchpad/dev31/cap2/runner/src/runner/modules.rs:681), and [fills only absent option fields with `none`](/private/tmp/claude-501/-Users-ccheever-projects-exact2/f4b5c629-4ed6-4746-9045-74f6106a629d/scratchpad/dev31/cap2/runner/src/runner/modules.rs:1465). A supplied `android` result on Apple survives; it is not scrubbed.

   **Decision needed:** describe existing injection behavior and remove the impossible assertion, or explicitly propose target filtering.

5. **IN-DELTA — MINOR — §10, lines 719–722: absence of failure does not establish a known battery.**

   `known = not failed(battery)` is true while the initial read is pending. R2’s `empty()` placeholder has level zero, so Expose initially draws an empty battery before receiving a battery fact. Unsupported targets subsequently switch to the full fallback after failure.

   [The grammar distinguishes pending from failed](/private/tmp/claude-501/-Users-ccheever-projects-exact2/f4b5c629-4ed6-4746-9045-74f6106a629d/scratchpad/dev31/cap2/docs/contract-grammar.md:993), and [the runner marks unanswered placeholders pending](/private/tmp/claude-501/-Users-ccheever-projects-exact2/f4b5c629-4ed6-4746-9045-74f6106a629d/scratchpad/dev31/cap2/runner/src/runner/commit.rs:880).

   **Decision needed:** distinguish a successful battery answer from the initial placeholder when deciding whether its level is known.

6. **PRE-EXISTING — MINOR — D5, line 311: cleanup names the wrong release hook.**

   When the whole source loses its last reader, [the runner sends `release(name)`](/private/tmp/claude-501/-Users-ccheever-projects-exact2/f4b5c629-4ed6-4746-9045-74f6106a629d/scratchpad/dev31/cap2/runner/src/runner/modules/bound.rs:324), without arguments. `release(name, args)` handles disappearing argument groups. [LLP 1133.009 D10 item 12](/private/tmp/claude-501/-Users-ccheever-projects-exact2/f4b5c629-4ed6-4746-9045-74f6106a629d/scratchpad/dev31/cap2/llp/1133.009-recording.rfc.md:899) explicitly distinguishes them. Implementing only the named hook would leave observers running until session destruction.

   **Decision needed:** name `release(name)` for these argument-free sources’ last-reader cleanup.
