# Grok 4.7 (xhigh) review of LLP 1116.008 r1

**READY WITH CHANGES.** The token diagnosis is half right, and three decisions need a different lever than the one written.

**D1. RIGHT WITH CHANGE.** The silent miss is real: polls lost about ten minutes because `test` ran with no server, and five more because `agent` never starts one. A hard stop before the first test is the right fix. The stop has to follow the process that actually serves. Polls' root `server.ts` only imported the module that reads `DB`, and a textual scan of the entry file is what left the run empty. `agent` should use the same isolated database as `test`, say so in one line, and leave the dev database alone.

**D2. RIGHT WITH CHANGE.** On focus-timer the fresh input is level (65k against 62k), so the 1.84× gap is cached context re-sent: about 32 calls at ~31k against 22 at ~24k. Extra calls are the larger slice. The fatter context is still about a third, and the two multiply. The docs cut has already done its work: bytes fell 21% while Exact2-against-itself tokens fell only to 0.95× and commands stayed flat (1,116 to 1,105), with web drives up from 77 to 104. start-here already says no dev server is needed. Builders still ran `web --help`, which prints the background recipe, and then did that dance (focus-timer, tip-splitter, flashcards, event-rsvp). Change the help text, and have `verify` write the `.bake/shots` the builder prompt requires, the way React's Playwright run does.

**D3. RIGHT WITH CHANGE.** team-kanban lost because the large title never collapses and cards clip under the pinned control with no material. The SwiftUI app that won kept the segmented control fixed and used an inline title. Putting the switcher in the list as its first section makes a control that should stay put scroll away. The pitfall "a control above a list goes in the list" will push authors there. Fixed content should inset the scroller and let the title collapse. That is the platform bug (LLP 1115.000 D11). A pattern's switcher may live in the list. The blanket pitfall should not.

**D4. RIGHT.** Grocery lost on a short swipe from the row centre that never opened the actions, while UIKit's did. The row's snap scroll yielding to the list's swipe is the right gesture.

**D5. RIGHT.** Typing 250 past a max of 99 was the other reason grocery lost. Clamping on commit, as the stepper already does, holds the bound the author set. The web keeping the browser's own validation is the right split.

**D6. RIGHT.** Black ink on a saturated teal fill is a tell, and round 9's contrast fix created it. A light hue drawn as the Clock does, the tint at low opacity under label-coloured ink, leaves the hue to the author and the unsaid style to the platform. Saturated hues stay filled under white. Trivia was a tie with several other nits, so this alone will not move the SwiftUI record.

**D7. RIGHT.** Countdowns and expense-tracker replaced the system indigo accent with a custom pair because `check` judged a menu label as body text (3.9:1 in dark, under 4.5:1). That spends a repair turn and paints over the platform. Judging it at 3:1, as a button title already is, stops the repaint.

**What is missing.** D2 is the right token area only with the lever above. Help text and `verify`'s shot files will move the count. Another start-here sentence will not. The larger quality lever than D6–D7 is the keyboard. unit-converter lost because the live result stays under the keyboard and the list does not scroll it into view. expense-tracker's Save and book-club's Author field were covered the same way. Round 9's check never saw it: the builder dismissed the keyboard before the shot. That is unsaid keyboard behaviour (LLP 1115), and it is a bigger piece of the SwiftUI 3–4–1 than RoundButton or the indigo false finding. mood-journal's loss was the builder's calendar grid and a missing delete.

**Risks.** D1 is safe when the drive uses the test database and always says what it started. Starting the dev database, or refusing only one spelling of `process.env.DB`, repeats the polls loss or clobbers data. D3's pitfall can make Exact2 worse: a persona or filter that scrolls away is a new tell, and relocating the control leaves the clip in place. D6 holds author, then platform, then CSS: the author still names the hue.

**Changes:** (1) D1 follows the real server process and uses an isolated database. (2) D2 changes `web --help` and writes `verify` shots where the prompt looks. (3) D3 does not teach that every control above a list belongs in the list. Fixed content must inset and collapse. (4) A focused field's result stays on screen, as it does in a hand-built iOS app.
