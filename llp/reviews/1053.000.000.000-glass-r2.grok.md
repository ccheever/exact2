### Blocker. A choice of `"auto"` and a number never reaches the lowerer, and the arm that does compile is a string.

D1 says `glassGroup="auto"`, and a choice whose arms are numbers or `"auto"`, lowers to the float −1, with the prop kind, the wire, and the runner unchanged. §3 names `values.rs` and the prop lowering. The type pass runs first. A prop attribute is typed with `infer` (`contract/types/src/checks.rs:1167-1170`). A ternary or `match` must unify its arms (`contract/types/src/lib.rs:951-953`), and a string against a number is `type-branches` (`contract/types/src/lib.rs:1022-1031`). The number-or-string exception exists only for style attributes (`contract/types/src/checks.rs:1173-1188`). The lowerer then compiles with `typed_code` before `check_prop_value` (`contract/lower/src/lib.rs:1263-1265`). A mixed ternary that somehow arrived would be `Ty::Unknown` (`contract/lower/src/expr.rs:413-423`), which passes the prop check (`contract/lower/src/values.rs:538-544`), while the `"auto"` arm is still emitted as a string. The runner accepts only a number for a float prop (`runner/src/bridge.rs:48`). `glassGroup` is a float (`kernel/tables/schema.json:1239-1242`).

Change. In `check_attr`, treat `glassGroup` as the one prop whose ternary or `match` may mix the string literal `"auto"` with numbers. Any other string literal is refused there. Before `typed_code`, rewrite every `Expr::Str("auto")` in that value to the number −1, including a bare `glassGroup="auto"`, so both arms are floats. Keep the top-level numeric range check. `numeric_literal` does not walk into a choice (`contract/lower/src/values.rs:20-26`), so a literal −1 or −5 inside an arm stays unchecked, as every computed value does today; a numeric −1 that reaches the runner is auto, which D1 already says.

Clamp the resolved points to 0…10000 in the Rust resolver before either send. `host.rs` is 1482 lines. The new work is a call into `style.rs`.
