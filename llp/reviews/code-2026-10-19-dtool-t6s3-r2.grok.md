## Security pass

**Another host, the viewer's machine, the tool's origin.** `canvasFrame` (`apps/design-tool/pairing.ts:30-36`) parses the reply and the paired door with the same URL parser, then requires `https`, `u.hostname === d.hostname`, a different `port`, no userinfo, no query, no hash, and a pathname of exactly `/canvas/${encodeURIComponent(client)}/`. The string it returns is `${u.origin}` plus that path plus `#g=` plus the grant. The door is `wire.remote()` (`wire.ts:160`), which is `doorOf`'s origin (`wire.ts:51-58`), the address the user typed.

A reply of `http://127.0.0.1:5173/canvas/remote%3AAda%231/` against door `https://192.168.1.20:7743` fails the scheme check and the host check. `https://evil.example:7745/...` and `https://127.0.0.1:7745/...` fail the host check. `https://192.168.1.20:7743/...` fails the port check, so it is not the door origin the tool page is served from. `https://u:p@192.168.1.20:7745/...` and `https://192.168.1.20:7745@evil.example/...` both set `username` and are refused (the second's host is `evil.example`). Query, an existing fragment, and a path for `remote:Grace#1` are refused, and none of them are copied into the frame. The unit test locks each of those (`scripts/design-tool-scope.test.mjs:122-136`). The contract test locks the other-host wording and that the frame is absent (`apps/design-tool/app.test.contract:1808-1823`).

The one reply that does frame this machine is the one the disposition allows. Pairing with a tunnel door `http://127.0.0.1:7740` (`doorOf`, `wire.ts:54-56`) makes the door host `127.0.0.1`, so `https://127.0.0.1:7741/canvas/<client>/` passes. That is a different origin from the tool page at `http://127.0.0.1:7740` (`apps/design-tool/app.ts:27`): scheme and port both differ, and an https frame cannot be the http page. It is also not the round-1 case, the HTTP dev loop. The comment at `pairing.ts:28-29` ("Never this machine's own pages") is stronger than that rule.

**Client encoding.** Both sides use `encodeURIComponent`: the mint URL (`scripts/tamber-canvas.mjs:351`) and the check and the rebuilt frame (`pairing.ts:33-35`). A client is `remote:<name>#<n>` (`scripts/tamber-pairing.mjs:267-269`); the name is `/^[\w .-]{1,40}$/` (`tamber-pairing.mjs:237`). The characters that must be escaped are `:`, `#`, and space, which become `%3A`, `%23`, and `%20`. On this machine's URL parser (Node v26) the pathname of `https://192.168.1.20:7745/canvas/remote%3AAda%231/` is exactly `/canvas/${encodeURIComponent("remote:Ada#1")}/`, and `%41` stays `%41`. `canonical` (`tamber-canvas.mjs:87-95`) rejects percent-encoded unreserved characters (`%2d`, `%5f`, `%7e`, `%2e`, alphanumerics) and `%2f` / `%5c` / `%00`. `encodeURIComponent` never emits those for a legal client, and it does not emit a form `canonical` rejects for `:`, `#`, or space. Entry decodes the one segment (`tamber-canvas.mjs:404-408`) and compares it to the client the grant was minted for. A reply that leaves the colon raw lets `#` start the fragment; `u.hash` is then set and the frame is refused. A lowercase `%3a` also fails the equality check. Both fail closed.

**IPv6, case, trailing dot.** Comparison is on parsed hostnames, so case, IPv6 compression, and IPv4 aliases are folded before the check. `https://[2001:DB8::1]:7745` and `https://[2001:db8::1]:7743` share hostname `[2001:db8::1]`. `[::ffff:127.0.0.1]` becomes `[::ffff:7f00:1]` and does not compare equal to `127.0.0.1`. A trailing dot on a domain is kept (`evil.example.` ≠ `evil.example`), so that reply is refused. A trailing dot on an IPv4 address is stripped on both sides (`127.0.0.1.` → `127.0.0.1`), so it matches the same address. Hex, decimal, and short IPv4 (`0x7f000001`, `2130706433`, `127.1`) all become `127.0.0.1` and can match only a door that normalizes to that same address. Leading-zero IPv4 is octal (`192.168.001.020` → `192.168.1.16`); the frame origin is the normalized one.

**Grant charset.** The tool accepts `/^[\w-]{16,}$/` (`pairing.ts:33`), ASCII `[A-Za-z0-9_-]`, length 16 or more. The gateway accepts `/^[A-Za-z0-9_-]{43}$/` (`tamber-canvas.mjs:367`), and the mint is `randomBytes(32).toString('base64url')` (`tamber-canvas.mjs:347`), 43 characters of that alphabet. A real grant passes. `+`, `/`, `=`, `#`, `%`, whitespace, and non-ASCII fail the tool check, so none of them can close the fragment early. The frame is `#g=${grant}` with no extra encoding (`pairing.ts:35`); the alphabet makes that safe. Shorter and longer strings are framed and then 404 at entry. The 16-character floor is the disposition. The missing ceiling is nit 1.

**Grant lifetime.** Unchanged from the disposition, and not refiled. The grant sits in `canvasAt.frame` and in the iframe `src` (`app.contract:1389-1390`) until `canvasTick` changes. It is single-use and expires in 30s (`GRANT_MS`, `tamber-canvas.mjs:58`). The error strings are the transport error or the fixed refusal (`pairing.ts:50-52`); they do not include the grant or the URL.

## Tick, Try Again, tests

`canvasAt` is `loadCanvas(hello.local, hello.client, hello.epoch, canvasTick)` (`app.contract:676`). `loadCanvas` returns before the call when `local` is set, or `client`, `epoch`, or the door is empty (`pairing.ts:47-48`). Hello's epoch is one id per server process (`scripts/tamber-server.mjs:158`, returned at `:701`). The poll refreshes hello because `changes.paced` changes (`app.contract:816-817`), and while that refresh is in flight the retained hello keeps the same epoch, client, and `local`. The runner re-requests a resource only when its arguments change (`runner/src/runner/settlement.rs:159`). A steady poll does not mint. Boot does not mint either: the empty hello has no client and no epoch, so the first call returns the empty frame. Pairing fills `local`, `client`, and `epoch` together, which is one mint. That removes the round-1 extra mint that came from keying on `changes.epoch`.

`canvasTick` moves in two places. Try Again (`reloadCanvas`, `app.contract:835-836`) is shown only when `canvasAt.error` is set and the frame is empty, and it is disabled while `pending(canvasAt)` (`app.contract:1394-1395`). The previous answer already has an empty frame, so the retry does not replay a grant. A 429 stays on screen until the click; clicks are manual, against the server's 6-per-minute cap (`MINT_RATE`, `tamber-canvas.mjs:66`). `saveName` also increments the tick (`app.contract:863-867`). The first name is saved before pairing (the pair UI is under `not hello.ok`, `app.contract:1293`), so that increment does not mint. Saving again leaves the name screen (`app.contract:1284`), which had unmounted the iframe, and asks for a new grant. A failed hello blanks `epoch` (`app.ts:617`) and clears the frame with no mint; the next success mints once.

The unit test locks the rebuilt frame string and the refused cases named in the disposition. The new contract test locks the other-host error text, the missing frame, and Try Again bringing a frame back (`app.test.contract:1808-1827`). The stub grant is now 43 base64url characters (`stub/tamber-stub.ts:193`), so round 1's "UUID would not enter" nit is gone. The older contract assertion still only checks that `canvas-frame` is present (`app.test.contract:1796`). The success URL is the stub default, `https://127.0.0.1:<door port + 1>/canvas/<client>/`, which this check accepts. Neither test covers IPv6, a trailing dot, or host case. Those paths fail closed in the parser, as above.

## Findings

1. **NIT — the grant check has no ceiling.** `pairing.ts:33` accepts any `[A-Za-z0-9_-]` string of length 16 or more. The gateway will redeem only 43 (`tamber-canvas.mjs:367`). A paired server can return a multi-megabyte grant, and that string is copied into the iframe `src` and into contract state. Capping the length at 43 keeps every grant the gateway can redeem and drops the rest. Nothing in the alphabet can break out of `#g=`.

2. **NIT — Continue mounts the previous grant until the new mint settles.** `saveName` bumps `canvasTick` and clears `renaming` in one action (`app.contract:863-867`). The name screen goes away immediately (`app.contract:1284`), and the canvas section renders `canvasAt.frame` (`app.contract:1389-1390`). While the new request is pending, that value is the retained answer (`docs/contract-for-agents.md:910`). The iframe therefore loads the previous `#g=` for one round trip, then swaps to the fresh grant. The old grant is already spent, and a failed mint returns `frame: ''` and replaces it (`pairing.ts:50-52`; a returned record is an answer, `docs/contract-for-agents.md:1081`). Try Again does not do this: its retained frame is already empty. Leaving the frame blank while `pending(canvasAt)` after a tick change would close the window.

## Checked, and not findings

- The round-1 blocker (a remote door's reply frames `http://127.0.0.1:<dev port>`, the tool origin, or another host) is refused, and the refusal is tested.
- Grant-in-state and the missing C2 entry page stay deferred with the disposition. The sandbox string is unchanged: `allow-scripts allow-same-origin allow-forms allow-popups allow-modals allow-downloads`, no `allow-top-navigation` (`app.contract:1390`).
- Default ports both report `""` (`http://127.0.0.1:80`, `https://127.0.0.1`, `https://127.0.0.1:443`). A door on 80 and a canvas on 443 therefore compare equal and are refused. Deployed doors use an explicit high port, where the inequality holds. This fails closed.
- A redirect or a self-navigation from the accepted canvas host can leave that host afterward. The canvas JSON itself cannot name the destination. The same sandbox already wraps the local dev-loop frame.
- A stale canvas reply from an older pairing fails closed: the path must match the current `hello.client`, and the host must match the current door.
- Hostname case, IPv6 compression, IPv4-mapped addresses, and trailing dots do not open a second host. They either normalize to the door's host or fail the equality.

**Verdict:** nothing blocks (0 BLOCKER, 0 SHOULD-FIX, 2 NIT).
