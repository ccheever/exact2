**Material** — `host/apple/Sources/ExactKit/PaintOrder.swift:48`
A parent whose kernel rank is not 0, while any exit ghost is attached (`paintGhosts > 0`), is painted at rank 1. `paintRank` returns `1` instead of the stored rank. Take a parent at kernel rank −4 (z-index −2) beside an in-flow sibling (rank 0): for the whole exit, Apple paints the parent above that sibling. Take a parent at rank 20 (z-index 10) beside a sibling at rank 4 (z-index 2): Apple paints the sibling above the parent, ghost included. The web path only sets the parent's `isolation: isolate` and leaves its z-index alone (`host/web/presence-glue.js:322`), so the kernel rank is unchanged and those two cases paint the other way. `PaintOrderIOSTests.swift:109` and `:114` lock the override in (`setRank(-4)` and `setRank(10)` both expect `paintRank == 1`). Fix: while ghosts are present, bump only a 0 rank to 1 (`rank == 0 ? 1 : rank`), and change those two assertions to expect the stored rank.

**Material** — `host/web/src/element.rs:1008`
Any set `isolation` row makes `paint_css` return the authored declaration and skip `layers.isolated`. On the tree in `host/web/tests/it/paint_order.rs:248` — box `isolation: auto` (node 2) containing `position: absolute; z-index: 1` (node 3), then a later sibling `opacity: 0.5` (node 6) — `decide()` isolates node 2, so its kernel rank is 1, the same as the opacity sibling, and tree order paints node 6 above node 3. The live host keeps `isolation: auto` (the test at lines 258–261 asserts the isolate declaration is absent), node 3's z-index escapes into the root, and node 3 paints above node 6. The same skip drops host policy: a canvas with `isolation: auto` (node 5) stays unisolated. The server document appends `isolation: isolate` after the authored value (`host/web/src/document.rs:563`), and `paint.js:60` sets inline `isolation: isolate` whenever `isolated || policy`. Fix: when `layers.isolated(id)` is true, write `isolation: isolate` even if the row is `auto`; keep an authored `isolate` as it is. Update `authored_isolation_keeps_its_value` to expect that.

**Material** — `host/web-js/src/paint.rs:156`
A bound `transition` whose property word is not in `Property::ALL` / `all` / `border-color` sets `data-exact-motion-*`. The fallback is `t.trim()!=="" && t.trim()!=="none"`. `transition: "width 1s"`, `"margin 1s"`, or `"transform 200ms"` therefore makes `paint.js:30` set policy and isolate the box at rank ½. The kernel parser rejects those strings (`motion/src/parse.rs:79`, and `parse.rs:335` expects `UnknownProperty` for `"width 1s"`), so the row is never stored and `motion_stacks` is false: live web, Linux, and Apple leave the box at rank 0. A sticky header (rank 1) then paints under that row on the JS target and over it on every kernel host. A duration-only value such as `"200ms"` is fine — both sides treat a missing property as `all`. Fix: drop the fallback and return true only for `all`, `opacity`, `translate`, `scale`, and `rotate`.

**Material** — `host/linux/src/paint.rs:838`
Every `paint_selected`, including a scroll, rebuilds ranks with `Kernel::paint_order()`. `wheel_at` only sets `dirty` (`host/linux/src/presenter.rs:1208`); the next frame still calls `paint()`. `own()` scans all of a parent's children for an exclusion once per child (`kernel/src/paint_order.rs:284`). A parent of *k* siblings costs O(k²) style checks per frame, on top of the paint. A 10k-row list is about 10⁸ sibling checks per scroll frame, and the ranks did not change. The live web host caches that exclusion bit per parent and reruns only dirty lists at commit time (`host/web/src/layers.rs:43`); Apple publishes ranks from `emit_layout`, not from scrolling. Fix: keep the rank map until a receipt that can change stacking facts, and reuse it for damage and scroll repaints.

**Material** — `host/web-js/src/paint.rs:207`. A bound `transition` is marked stacking as soon as one comma-separated item names `all`, `opacity`, `translate`, `scale`, or `rotate`, and an item with no property name stacks only when every word matches a timing regex that has no `linear()`. `Transitions::parse` rejects the whole shorthand on any bad item, and accepts a missing property as `all`, including `linear()`. `"opacity 1s, width 1s"`, `"opacity 1s ease linear"`, `"opacity scale 1s"`, and `"opacity 1s spring(180, 12, 1)"` therefore set the policy bit on the JS target (rank ½, isolated) while the kernel stores no transition and the other hosts leave the box in flow. `"1s linear(0, 1)"` and `"200ms linear(0, 0.9 50%, 1)"` do the opposite: the kernel stacks them and the JS target does not. A sticky sibling at rank 1 paints under the box on one host and over it on the others. Treat the string as stacking only when it survives `Transitions::parse` and `motion_stacks`, including `linear()` and whole-shorthand rejection.

**Material** — `host/web-js/paint.js:39`. While `$paintWaiting` is set, `own()` returns the server snapshot and ignores the parent and siblings it was called with. `host/web/src/document.rs:586` stores `paint.own.z`, which is already null when `z-index` does not apply. A sliced keyed row with `z-index: 2` and `position: static`, rendered under `display: block`, stays in flow after the parent's display binding becomes `flex` or `grid` and until `adopt()`; the kernel then ranks it `4` and a `position: relative` sibling at rank 1 paints above it on the JS target and below it on every other host. The same return drops the `exclusion` argument, so a waiting text row does not gain structural policy when a sibling becomes an exclusion during the slice. Keep the authored `z-index` in the summary and recompute applicability and text-beside-exclusion policy on each flush, the way the non-waiting path does.

**Material** — `host/linux/src/presenter/delivery.rs:206`. Activating a staged bundle replaces `self.host` and leaves `self.brush.paint_epoch` in place. Reload clears it (`host/linux/src/presenter.rs:577`) because a new kernel can reuse the same epoch. A session whose kernel epoch is `N` (a fresh boot is `1` after the creating apply) paints, caches ranks at `N`, then activates an update whose new kernel is also at `N`. The next paint takes the old `BTreeMap` (`host/linux/src/paint.rs:838`); overlapping view ids keep the previous plan's ranks and missing ids rank `0` (`paint.rs:1283`), so sibling order stays the old tree's until a later commit happens to change the epoch. Clear `paint_epoch` on this path before the next paint. The rank test only calls `reload`, so it still passes.

**Material** — `host/apple/Sources/ExactKit/Mac/CaptureMac.swift:35`. Any non-empty `animationKeys()` copies every property from `presentation()`, which does not show model writes from the current uncommitted transaction. A shape layer with an in-flight `strokeEnd` (or opacity or transform) animation plus a same-turn model write of `path`, `backgroundColor`, or `bounds` captures the old presented value for that write; a layer with no animation captures the fresh model value. Order stays on the live model `zPosition`, so this does not undo the rank flush. Copy the model, then overlay only the keys in `animationKeys()` from the presentation layer, and do the same for masks.
