## Minor findings

1. `data/host/src/native.rs:127` opens `ibex2_sqlite::SqliteProvider` directly, so that path never touches the registry in `js/src/native_storage.rs:33`. A file that Rust source has open is still handed to `NativeStorage::sqlite`, and a file the module holds is still opened by that source. D3's required door is the TypeScript `storage.sqlite` provider, and `Reserving` covers that door in both orders, including a failed `close` (the count stays until `Held` drops) and a dropped `SqliteFile`. The module comment at `js/src/native_storage.rs:31` says the exclusion is whichever session in the process opened the file. That is true only for opens through `Reserving`. Route this `open` through the same registry when a Rust source and the slot can share a process. It should not block this lane.

2. `snapback4/README.md:1538` still shows `configure_storage(&mut self, data: PathBuf, cache: PathBuf, temporary: PathBuf)` forwarding those three paths. That no longer implements `exact_js::NativeModule`. The compiled wrappers in `apps/harmony/app/apple/src/lib.rs` and `apps/harmony/app/linux/src/main.rs` are the working shape: take `NativeStorage` and pass `data()`, `cache()`, and `temporary()` through to the adapter. `snapback4/README.md` is one of the files `scripts/check-snapback-readme.mjs` hashes, and that script says it is not a blocking gate, so the snippet can stay stale until the guide is edited. Leaving it does not make the tree fail to build.

3. `js/src/native_storage.rs:84` and `docs/contract-for-agents.md:2308` say the file is kept "until the answer drops." The thing that ends the reservation is dropping the `SqliteFile` from `sqlite()`, which the fixture holds across answers (`packages/fixtures/vault/native/lib.rs:19`). Say that the `SqliteFile` is what the module holds, and that its own SQLite must be closed before that value is dropped.

4. `js/src/native_storage.rs:48` canonicalizes the parent only. `/tmp` and `/private/tmp` therefore name one key, and a successfully resolved `app:` path always has a parent (`vendor/ibex/crates/ibex2/src/stdlib/app_fs_unix.rs:388` returns only after `open_parent`). The leaf keeps the caller's spelling. On a case-insensitive volume, `app:/data/notes.db` and `app:/data/Notes.db` are two keys and one file, so a directory grant (`sqlite.open app:/data`, which `snapback4/README.md` tells apps to write) lets both libraries open it. When the file exists, also refuse a matching device and inode.

5. `contract/cli/src/native/slot.rs:32` watches the app's `package.json`, and lines 84–85 watch an `exact.json` and shim only after a slot is found. Adding `"native"` to a dependency that is already in `package.json`, without otherwise changing a watched file, leaves a direct `cargo build` on the previous `module.rs`. `scripts/app-shells.mjs:300` does put the package name in the shell stamp, so `ensureShells` rewrites `.with_native(exact_native)` and that crate edit reruns the bake. Watch each direct dependency's `package.json` and `exact.json` from the build script as well.

6. `packages/fixtures/vault/test/linux.mjs:36` compares `#[path]` to `resolve(...)`, which does not resolve symlinks, while the bake writes `canonicalize` (`contract/cli/src/native/slot.rs:78`). A checkout reached through a symlink fails the bake assertion even though the factory path is right. Compare against the canonical path.
