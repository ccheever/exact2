## Review (verbatim)

## 1. Overall assessment

**NOT READY to implement R1–R12 as written.** The field report identifies useful problems, but the RFC underestimates the changes required to request lifecycle, transactional settlement, and security, and several factual premises need correction. This review uses `3c46f19f`; later working-tree edits are excluded, and all repository line references below refer to that commit. I modified no files and ran no builds; reported timings and visual reproductions remain the author’s evidence.

R4 addresses that directly through generation from Contract. See [report D1](/Users/ccheever/projects/exact2/llp/1054-bluesky-port-field-report.research.md:121) and [record validation](/Users/ccheever/projects/exact2/plan/src/value.rs:122).
- **The positive account of the data seam is supported by the implementation.** A send calls the source before action settlement, and parsing can return another request. That supports the optimistic UI and multi-step requests described in §7. See [refresh](/Users/ccheever/projects/exact2/host/apple/Sources/ExactKit/IOS/NodeViewIOS.swift:1208), [WebP handling](/Users/ccheever/projects/exact2/host/apple/Sources/ExactKit/RasterImage.swift:35), and [icon selection](/Users/ccheever/projects/exact2/host/apple/build.mjs:484).

## 3. Concerns

1. **BLOCKER — R1 needs a transaction and transport contract, not just a trait hook.**

   D2 overstates the existing limitation: unchanged arguments can already be re-asked through explicit refresh or a changed store revision. The missing mechanism concerns mutable source state outside that tracking. See [reuse conditions](/Users/ccheever/projects/exact2/runner/src/runner/settlement.rs:360).

   A consuming `changed()` introduces unresolved failure behavior. The runner checkpoints its store, pending requests, and refresh set, but not the source; restoring a refused commit could therefore lose already-drained invalidations. Action processing also **assigns** `refresh_next`, potentially overwriting invalidations collected earlier. A `parse_for()` returning `Later` takes an early return without settlement. See [checkpoint/restore](/Users/ccheever/projects/exact2/runner/src/runner/commit.rs:16), [refresh assignment](/Users/ccheever/projects/exact2/runner/src/runner/commit.rs:411), and [continuation return](/Users/ccheever/projects/exact2/runner/src/runner/commit.rs:661).

   The hook must also cross module boundaries: worker envelopes and Rust module replies currently carry results and store effects, but no invalidations. A default-empty method on an outer adapter can silently swallow the feature. See [worker envelope](/Users/ccheever/projects/exact2/data/src/envelope.rs:27) and [module reply decoding](/Users/ccheever/projects/exact2/logic/abi/src/lib.rs:356).

   **Resolve:** define invalidation delivery across adapters, workers, and module ABI; merge it with explicit refresh; specify preservation on refusal and behavior during multi-step replies; deduplicate and bound settlement. Also qualify “equal `Now` changes nothing downstream”: pending flags and store provenance are separately observable dependencies ([dependency comparison](/Users/ccheever/projects/exact2/runner/src/runner/settlement.rs:157)).

2. **BLOCKER — R2 confuses equal transport requests with equivalent source calls and freshness.**

   A concrete R1/R2 failure is: GET starts, a mutation succeeds, R1 invalidates the source, and R2 retains the identical pre-mutation GET. Its old response can satisfy the refresh and leave stale data displayed. Explicit refresh also has cache-bypass behavior stored in `RequestOut.forced`, **outside `Request` equality**. See [forced flag](/Users/ccheever/projects/exact2/runner/src/request.rs:408) and [native cache bypass](/Users/ccheever/projects/exact2/host/apple/src/executor_core.rs:641).

   “Parse with the latest arguments” is not the existing contract: pending requests retain the arguments originally asked. JavaScript calls and placed calls use arguments in their continuation identity; placed re-asks also create fresh continuation tokens, so they may never reach the proposed equal-HTTP optimization. See [pending request](/Users/ccheever/projects/exact2/runner/src/runner.rs:199), [JavaScript parked calls](/Users/ccheever/projects/exact2/js/src/lib.rs:755), and [placed calls](/Users/ccheever/projects/exact2/data/src/placed.rs:212).

   `Request` equality already includes grants, continuation, storage, and surface operations—not merely the five fields enumerated in R2 ([definition](/Users/ccheever/projects/exact2/runner/src/request.rs:60)). Retaining requests also adds memory costs: pending state currently stores no request body, and checkpoints clone pending state.

   **Resolve:** distinguish argument-only re-evaluation from a demand for fresh data; define which source call/continuation survives and how the replacement is discarded; preserve rollback and refusal handling. Restrict reuse to explicitly safe cases until those semantics exist. The claimed removal of both app workarounds needs consumer-level evidence.

3. **BLOCKER — D5’s arithmetic is wrong, and R3 leaves overload storage unbounded.**

   The independent reservation is approximately:

   `owned request storage + max(2 × response ceiling, 32 KiB) + 128 KiB`

   Consequently, an 8 MiB ceiling reserves **more than 16 MiB**, permitting at most one such outstanding reservation within 32 MiB—not four. The parameter is also a real response cap: it becomes the transport’s `max_body`. Reservations last until the UI drains results, not merely until network completion. See [reservation calculation](/Users/ccheever/projects/exact2/host/apple/src/executor_core.rs:437), [response cap](/Users/ccheever/projects/exact2/host/apple/src/executor_core.rs:647), and [reservation lifetime](/Users/ccheever/projects/exact2/host/apple/src/executor_core.rs:73).

   There is already a queue for admitted work. R3 proposes retaining work currently refused at admission, while also queueing beyond the count limit, without specifying any bound on waiting requests or their owned buffers. See [admission and queue insertion](/Users/ccheever/projects/exact2/host/apple/src/executor_core.rs:138).

   **Resolve:** correct D5 and the proposed documentation; bound waiting count and bytes separately from active/completed response reservations. Specify deadline origin, expiry wakeups, cancellation before dispatch, retirement, and agent pending state. Preserve the existing worker pool and ordered lane. Linux shares this executor, so this is one shared behavioral change ([Linux executor](/Users/ccheever/projects/exact2/host/linux/src/executor.rs:9)).

4. **BLOCKER — R5 changes the security model and misses redirect credential handling.**

   Exact-origin matching is explicitly deliberate in ibex2. A wildcard is new grant vocabulary and a broader trust decision, contrary to the RFC’s characterization of all R-items as implications of existing rules. See [origin policy](/Users/ccheever/projects/exact2/vendor/ibex/crates/ibex2/src/grant.rs:22).

   Requiring two suffix labels does not establish an ownership boundary: `*.co.uk` passes, as do shared hosting namespaces. The [Public Suffix List explanation](https://publicsuffix.org/learn/) documents precisely why dot-count rules do not establish that boundary.

   More immediately, native fetch rechecks grants after redirects but retains request headers when changing origin. A wildcard can therefore admit a sibling destination that receives the original Authorization header. Web glue instead uses `redirect: "error"`. See [native redirect handling](/Users/ccheever/projects/exact2/vendor/ibex/crates/ibex2/src/stdlib/fetch.rs:349), [URL replacement without credential removal](/Users/ccheever/projects/exact2/vendor/ibex/crates/ibex2/src/stdlib/fetch.rs:395), and [web request options](/Users/ccheever/projects/exact2/host/web/glue.js:699).

   The implementation inventory is incomplete too: speculative module fetching has another origin matcher, and `Origin` is shared by fetch and WebSocket grants. See [early-fetch matcher](/Users/ccheever/projects/exact2/host/web/module-glue.js:46) and [grant variants](/Users/ccheever/projects/exact2/vendor/ibex/crates/ibex2/src/grant.rs:125).

   **Resolve:** obtain Charlie’s decision on the expanded trust boundary; define canonical URL/host matching and public/shared-suffix policy; settle cross-origin redirect credentials; preserve source-scope attenuation and fetch-only scope. Test actual enforcement, redirects, and mixed-module scopes—not only matcher truth tables. This is not yet a three-call-site, 150-line fix.

5. **MATERIAL — R6’s proposed measurement contradicts the current collection contract.**

   The collection API explicitly measures the **wrapper’s border box**, not the authored root’s margin box. The wrapper establishes a flex formatting context to contain margins. UIKit reports that wrapper’s `bounds.height`; the native host also obtains wrapper heights directly from kernel frames. See [measurement contract](/Users/ccheever/projects/exact2/runner/src/instance/collection/api.rs:6), [wrapper construction](/Users/ccheever/projects/exact2/runner/src/instance/collection/views.rs:33), [UIKit measurement](/Users/ccheever/projects/exact2/host/apple/Sources/ExactKit/Collection.swift:378), and [kernel frames](/Users/ccheever/projects/exact2/host/apple/src/host.rs:917).

   P1 may be a real observed discrepancy, but these facts do not support the proposed diagnosis.

   **Resolve:** retain the original negative-margin fixture and identify where browser, kernel, wrapper, and UIKit dimensions diverge. Fix that layer while preserving the measurement contract. An iOS-specific adjustment could conceal a shared kernel layout defect.

6. **MATERIAL — R7’s single-radius fix does not implement the stated CSS behavior.**

   AppKit already computes four independently specified radii with CSS overlap reduction. A single `layer.cornerRadius` cannot represent that geometry. The node also already uses `layer.mask` for `clip-path`. See [rounded geometry](/Users/ccheever/projects/exact2/host/apple/Sources/ExactKit/Mac/NodeViewMac.swift:1225) and [existing mask](/Users/ccheever/projects/exact2/host/apple/Sources/ExactKit/Mac/NodeViewMac.swift:1097).

   **Resolve:** specify rounded overflow clipping for asymmetric radii, borders/padding, resize, and style removal. Any shape mask must compose with the existing clip path. Keep the uniform-avatar regression, but include an asymmetric case; UIKit’s current shortcut is not the web oracle.

7. **MATERIAL — R8 uses an incorrect CSS premise and is broader than web behavior.**

   `line-clamp` does not set `overflow: hidden`; it is a separate shorthand in the [CSS Overflow draft](https://drafts.csswg.org/css-overflow-4/#line-clamp). Exact2’s web adapter explicitly adds hidden overflow for its supported legacy-clamp implementation, and only for non-scrolling block layout. It skips flex/grid and scrolling cases. See [web clamp emission](/Users/ccheever/projects/exact2/host/web/src/css.rs:99).

   **Resolve:** describe this as parity with the web adapter’s *effective* clipping behavior. Apply the same eligibility conditions, preserve ordinary visible overflow, and cover the relevant text drawing paths. The long-word regression is useful; “clip every text node with positive clamp” is insufficiently scoped.

8. **MATERIAL — R9 partly implements an existing feature, and `complete` is insufficient for screenshot readiness.**

   At this commit, `layout(target)` already calls `find(target)`, which resolves test IDs and prefers active-route matches. A2 is incorrect for the documented agent API. See [layout](/Users/ccheever/projects/exact2/scripts/agent.mjs:961) and [target resolution](/Users/ccheever/projects/exact2/scripts/agent.mjs:986).

   A1 is supported: web settlement waits on request/motion work, without an image-ready condition ([settlement](/Users/ccheever/projects/exact2/host/web/glue.js:1232)). But HTML permits `img.complete === true` for broken images; decoding has its own readiness operation. See the [HTML image API](https://html.spec.whatwg.org/multipage/embedded-content.html#dom-img-complete).

   **Resolve:** remove the redundant layout proposal or identify a narrower reproducer. Bound image decoding/error handling by the existing deadline, distinguish failures from timeouts, and re-evaluate visible images after layout changes. Explain how newly queued work affects settlement; retain the explicit limitation that iOS image settling remains unresolved.

9. **MATERIAL — R10 must preserve supported build modes and report all failures.**

   O2’s “133 refused” wording is misleading: a non-pinned Binaryen selects an **unsplit build**, and absent `wasm-opt` permits an unoptimized build. Missing download guidance is real; an unconditional pinned-version prerequisite would change supported behavior. See [split eligibility](/Users/ccheever/projects/exact2/host/web/stages.mjs:26) and [fallback build paths](/Users/ccheever/projects/exact2/host/web/build.mjs:74).

   Automatic fetching also needs an explicit relationship to the current locked/offline build policy ([Cargo flags](/Users/ccheever/projects/exact2/scripts/app.mjs:109)). An online probe/fetch on every warm build would introduce latency and nondeterminism into the development loop.

   Finally, “that diagnostic alone, last” must not mean retaining only one error. The compiler already supports reporting all diagnostics, and fail-fast is banned. See [aggregate diagnostics](/Users/ccheever/projects/exact2/contract/cli/src/build.rs:58) and [binding rule](/Users/ccheever/projects/exact2/rules/RULES.md:22).

   **Resolve:** separate missing requirements from optional optimization capabilities; preserve locked/offline operation and bounded warm-path work; print all relevant Contract and Cargo diagnostics without artifact-message noise.

10. **MATERIAL — R10’s app-name warning does not fix O5.**

    The default output directory is shared, and each successful build replaces it. A server can consequently begin serving another app after its startup warning has already been printed. See [output selection](/Users/ccheever/projects/exact2/host/web/build.mjs:28) and [replacement behavior](/Users/ccheever/projects/exact2/host/web/build.mjs:52).

    `EXACT_WEB_DIST` already offers isolation, and `builtAppMatches()` already validates app identity and artifact agreement ([identity validation](/Users/ccheever/projects/exact2/host/web/serve.mjs:510)).

    **Resolve:** use the existing directory mechanism consistently for external apps, or enforce identity throughout serving. Merely printing a name is diagnostic improvement, not a fix. Separately explain the post-agent “build first” refusal; the reported message only establishes that the server could not obtain `app.wasm` ([startup check](/Users/ccheever/projects/exact2/host/web/serve.mjs:743)).

11. **MATERIAL — R12 would report an incorrect local-time fact on ordinary systems.**

    `utcOffset` is defined as minutes east of UTC in the viewer’s zone. Apple obtains the system zone’s current offset. Returning zero unless `TZ` contains a fixed offset mishandles named zones and systems configured without that environment variable. See [time contract](/Users/ccheever/projects/exact2/runner/src/time.rs:13) and [Apple implementation](/Users/ccheever/projects/exact2/host/apple/Sources/ExactKit/Session.swift:770).

    **Resolve:** obtain the actual host offset, including named-zone behavior, or make any restricted semantics an explicit decision rather than claiming Apple parity. Also preserve `epochAtZero = wall time − elapsed time`, including reload/carry behavior.

12. **MINOR — R4 and R11 are useful but need precise output contracts.**

    R4 omits `unit`, legal hyphenated identifiers, Rust keyword/name collisions, and generated dependency paths. Existing TypeScript generation handles the full type roster; Contract identifiers can contain hyphens. See [type generation](/Users/ccheever/projects/exact2/contract/cli/src/typescript.rs:29) and [identifier grammar](/Users/ccheever/projects/exact2/contract/syntax/src/lexer.rs:192). D1 also understates the hazard: swapping same-typed fields can pass runtime validation entirely.

    L10’s “plan size is invisible” should become “component attribution is missing”: total nodes and bytes are already printed. R11 must distinguish inclusive nested-component counts from additive totals, and raw plan bytes from compressed wasm attribution. See [existing summary and JSON contract](/Users/ccheever/projects/exact2/contract/cli/src/build.rs:109).

    **Resolve:** generate through a reusable compiler API rather than requiring recursive Cargo invocation from `build.rs`; define name mapping and all type cases. Reuse existing component provenance for attribution, keep machine-readable output clean, and label size measurements accurately.

13. **MINOR — The report’s inventory and confidence language need reconciliation.**

    There are 32 numbered open entries, or 31 after combining L7/D4, rather than 30. D2 is labeled S1 despite describing an app-level workaround, contrary to the report’s own severity definition. L6 is also too broad: a collection container permits literal `display: block`; the relevant refusal concerns other/dynamic display choices. See [severity definition](/Users/ccheever/projects/exact2/llp/1054-bluesky-port-field-report.research.md:38) and [collection restrictions](/Users/ccheever/projects/exact2/contract/lower/src/collection.rs:118).

    **Resolve:** distinguish historical observations, current limitations, and confirmed diagnoses. Give L1 an explicit disposition, clarify X7’s pending owner decision, and do not infer that R1 makes D8 inexpensive without measurement.

## 5. Open questions for the author or Charlie

- What is R1’s invalidation behavior when the source changes but the enclosing runner commit is refused? How does that decision cross worker and module boundaries?
- Does an explicit refresh or successful mutation require a request started afterward? If so, R2 needs a freshness distinction beyond request equality.
- Is Charlie approving trust in every descendant of a granted suffix? Is R5 intended only for hosted Bluesky PDSs, or also arbitrary federated PDS origins?
- For C3, how will a baked zero placeholder remain distinguishable from a genuine answer through activation, failure, and carry?
- Which external-app commit, minimal parity fixtures, and measurement records establish P1–P3 and the performance figures? X2’s source/build inspection should not be presented as driven gesture verification.

**Do not implement R1–R3, R5–R10, or R12 as written.** R1–R3 and R5 require substantive lifecycle/security decisions; the others need corrected diagnoses or narrower semantics.
