LAND WITH CHANGES

`cd vendor/ibex/crates/ibex2 && cargo test --lib -- fetch_async darwin_async fetch::tests` — 40 passed. The `head` order, `Flow::Skip`, redirect extraction, and the Darwin session setup match D1/D2. One terminal-outcome race has to be fixed before stage 1b builds on this machine.

1. **BLOCKING** — An abort and a completing hop can each publish, and the winner is whichever calls `finish` last. `abort` (`fetch_async.rs:266-277`) takes the exchange and drops the lock *before* `done` is set, then `cancel()`, then `finish`. `end` (`409-448`) calls `hop_ended`, drops the lock with `done` still false, and only then `finish`s. `finish` (`281-290`) is what sets `done`. D3's order (`rfc.md:248-252`) is "whichever happens first": a completed response stays the response; an abort's outcome is `AbortError`, and the platform's cancellation `end` is ignored (`rfc.md:144`, rule 4 at `:252`).

   On Darwin, `[task cancel]` returns immediately and `didCompleteWithError` runs on the lane queue. That callback can pass the `done` check in the gap before `finish(Err(aborted()))`, so the outcome becomes `TypeError: Failed to fetch — …` instead of `AbortError`. The other way, `end` has already taken the response and unlocked, and `abort` publishes `AbortError` over a response that completed. `finish`'s `done` flag still makes the publication unique — it just keeps the wrong one. The scripted cancel never re-enters the sink, so the tests cannot see it.

   **Fix:** decide under the lock. If `!done`, set `done`, `Option::take` the exchange and the upload, and build the outcome; drop the lock; then `cancel`, drop those two, then `events.outcome`. `end` commits the same way, so a response already accepted cannot be replaced and a cancellation `end` that arrives after an abort finds `done`. Keep calling `hop_ended` when `done` is already set.

2. **MATERIAL** — `released()` and `ibex2_darwin_task_release` run while `state` is held. `finish` sets `state.upload = None` at `fetch_async.rs:288` before unlocking. `end` sets `state.exchange = None` at `:415` and, on a body-dropping redirect, `state.upload = None` at `:423`, still inside the guard. `Upload::drop` (`94-98`) runs `released()` inline. D5 (`rfc.md:97`, `:331`) says that callback only posts a release. The task's `Arc` is the last holder when `prepare_body` fails inside `start` (`250-252`), on an abort before the body is lent, and on a 303/301/302 once URLSession has already freed the `NSData`. A `released` that takes this mutex deadlocks; one that calls back into the task re-enters it. Dropping the `Exchange` there also sends the ObjC release under the mutex.

   **Fix:** `Option::take` the `Arc<Upload>` and the `Exchange` and drop them only after the mutex is released. The `Mutex` inside `Upload` is never locked (`Drop` uses `get_mut`); a plain `Option` is enough.

3. **MATERIAL** — Metrics are not tied to a hop. `HopSink::metrics` (`451-453`) forwards a bare `HopMetrics`, and `FetchEvents::metrics` (`172`) has no hop id or URL. D2 (`rfc.md:177`) says the callback records the protocol on *that exchange*, and `didFinishCollectingMetrics` may arrive up to a second after `didComplete` (`darwin_task.mm:114-120`). `end` calls `next_hop` before that (`426-428`), and the default `next_hop` (`174-176`) starts the next hop immediately, so hop 1's `http/1.1` can be applied after hop 2's `h2`. Reading `state.current.url` at metrics time is the wrong fix; that URL has already moved.

   **Fix:** `HopSink` already stores `hop` (`339-341`). Pass the hop id and the hop URL captured at `start` on the metrics event, and have the consumer ignore a report whose hop it no longer has.

4. **MATERIAL** — The tests pin the single-threaded script and miss the paths that break. Present and passing: declared length before a followed 302, `Skip` plus `DeniedRedirect`, late `data` after a hop change, incremental `over_limit` against a later `end(Ok)`, oversized headers on an intermediate hop, one buffer across 307 and dropped on 303, platform-not-following, and a real 302 whose body is not collected. Not pinned:
   - `cancel` re-entering `end` before `finish` (finding 1), and an abort while `next_hop` is deferred.
   - 301/302 of a POST dropping the body, and 308 keeping it. Async coverage is 303 and 307 only.
   - `cookie` and `proxy-authorization` on the async machine. `a_cross_origin_hop_drops_credentials` checks `authorization` only (`fetch_async_tests.rs:345-356`).
   - `Manual`, `Error`, and `MAX_REDIRECTS` on `FetchTask`. Blocking `fetch_stream` covers `Manual` and the cap; nothing covers `Error`.
   - HEAD/204/205/304 exempt from the declared length. `FetchTask` uses `eq_ignore_ascii_case("HEAD")` (`fetch_async.rs:361`); `darwin_http.mm` is case-sensitive.
   - cookies, cache, and `HTTPMaximumConnectionsPerHost` actually applied. The blocking transport grew `ibex2_darwin_session_has_state` because a comment once claimed this while the session still had cookies. The new config (`darwin_task.mm:172-179`) copies `new_session` and is right, but nothing reads it back. No invalid-URL test either: the queued `end` plus `release_` at `222-228` is the path that frees the sink without a task pointer.

   **Fix:** one scripted test whose `cancel` calls `sink.end(Err(cancelled))` on the same stack, asserting `AbortError`; one deferred `next_hop` aborted before it runs; one POST 301 and one 308; cookie and proxy-authorization; `RedirectMode::Error`. On Darwin, an introspection getter for the cookie policy, the nil cache, and `HTTPMaximumConnectionsPerHost`, plus an invalid-URL exchange that completes once and drops its sink.

5. **MINOR** — A failure known at `start` can call the sink before `start` returns. `refused` (`darwin_async.rs:87-95`) comments "Delivered on this thread only" and then `std::thread::spawn`s `sink.end`. The spawned thread can run before `thread::spawn` returns, which breaks D1 (`rfc.md:129`). `FetchTask` does not hold `state` across `start` (`328`), so this is not the deadlock that sentence exists to prevent. The invalid-URL path already does the right thing by queueing on the lane queue (`darwin_task.mm:222-228`).

   **Fix:** deliver the `CString` failure on that same lane queue, and set a flag as the last act of `start` so the block cannot run until `start` has returned.

6. **NIT** — `endpoint` (`darwin_task.mm:35-37`) formats IPv6 as `address:port` with no brackets. `ibex2_async_data` (`darwin_async.rs:190`) calls `from_raw_parts` with no null check; a zero-length range would be undefined if `enumerateByteRanges` ever invoked one. Every lane names its queue `ibex2.lane` (`darwin_task.mm:183`), so crash logs cannot tell them apart. None of these affect this stage's behaviour.

What checked out: `head` is declared length, then the 64 KiB / 1024-entry cap (same `checked_add` and `>` as `check_headers`), then `Skip`, including a 3xx. `data` rejects the overflowing chunk and a later `end(Ok)` cannot replace `over_limit`. Late `head`/`data`/`end` after `done` or a changed hop id do not publish again. `admit_hop` / `redirect_step` are the old `fetch_stream` control flow; both callers drop the body when `drops_body`. The happy-path FFI frees the sink once in `release_`, frees the lent body from the `NSData` deallocator, retains the task until `Task::drop`, refuses redirects (`144-147`), and invalidates on drop (`193-198`). The state mutex is not held across `transport.start`, `events.outcome`, `hop_ended`, or `next_hop`. `fetch_async.rs` is 458 lines, `darwin_task.mm` 266, both tests files under 400.
