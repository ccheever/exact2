# Review round 1, LLP 1121 stage 9 A1 (Apple draws icon paths), Grok 4.7 (xhigh)

**RIGHT WITH CHANGES.** Stage 9 A1 does what the 17:03 ruling asks: an icon with no `sf` and a template path draws on Apple, an `sf` still wins, a non-template SVG still needs an `sf` (`tamber-icon-svg`), and a path icon’s tint is the written `-exact-tint-color` (the accent when that row names one) else `color`, applied on every `updateSymbol`. SF Symbol tint stays on the other branch. Nothing here blocks the design. The Mac image is right-side up and stays sharp: a bar at y=2 under `NSImage(flipped: true)` inks rows 2–5, and drawing the 24pt image into a 48pt view keeps `dstRect` at the image bounds while the CTM scales (`a=4 d=-4`).

1. **SHOULD-FIX** — Several `;` paths are filled as one winding union. `host/apple/src/icon_path.rs:18-38` concatenates every `;`-separated `d` into one command string (“together, one path's union”). `host/apple/Sources/ExactKit/IconPath.swift:62` and `:70` fill that `CGPath` once with `.winding`. Linux fills each segment on its own (`host/linux/src/paint/svg.rs:200-216`), and the web emits one `<path>` per segment (`host/web/glue.js:386`). `contract/lower/src/icon_svg.rs:391-394` accepts several `<path>` elements of one fill as a template (`M0 0h1;m2 2h1`). Disjoint paths and same-direction overlaps look the same. Opposite-winding overlaps punch a hole on Apple and stay solid on Linux and the web. A hole cut as opposite subpaths inside one `d` (no `;`) is already correct under one nonzero fill. **Fix:** fill each `;` segment separately, opaque black, source-over, the way `glyph_face` does. Keep emitting one string with several `M`s and split before the fill. Add a pixel test with two opposite-winding overlapping paths that stay solid.

2. **SHOULD-FIX** — iOS and tvOS rasterize the em square, then the image view scales that bitmap. `IconPath.swift:68-72` draws with `UIGraphicsImageRenderer` at `points` × `preferred()` scale. `host/apple/Sources/ExactKit/IOS/NodeViewIOS.swift:610-622` then aspect-fits that bitmap into the content box. The em square matches the kernel’s measure for a name with no glyph, and a box of that size is sharp at screen scale. A larger box (explicit width or height, `cover`) scales the bitmap. The cache key at `NodeViewIOS.swift:585` includes `points` and leaves out content-box size and display scale. tvOS uses this UIKit branch. The Mac rep redraws with the view’s CTM, so it stays sharp when the view is larger. **Fix:** draw the vector at the destination content rect × screen scale (object-fit in the painter, or a shape layer / vector image rep). Keep the em square as the intrinsic size only. When the bitmap depends on laid-out size and scale, put both in the cache key.

3. **SHOULD-FIX** — The tests do not show the pixels or the tint cases their names claim. `host/apple/tests/ExactKitTests/IconPathTests.swift:73-89` asserts a non-nil 24pt template image and tint RGB. The square `M 2 2 … 22 22` is symmetric, so an upside-down image or a blank image of that size still passes. The style rows are raw channel arrays, so AccentColor (`sys` `@tint`), an absent tint beside a system `color`, and the Mac `unsaidSymbolTint` fallback are never fed. `IconPathTests.swift:99-106` checks `CGPath` bounds and one fitted point and never renders a second `;` path. `host/apple/src/icon_path.rs:59-67` checks that the string starts with `M 2 2 C`, contains two `M`s, and contains no `Q` or `A`; it never checks cubic coefficients or a per-path fill. **Fix:** render an asymmetric bar at a small y and assert the inked rows on Mac and iOS. Two opposite-winding `;` paths must stay solid. Feed a style whose `tint_color` is the `@tint` role and one with the tint row absent, and assert accent versus text color, including the Mac path staying on the text color. Keep the existing channel-array retint.

4. **SHOULD-FIX** — On the Mac, a path icon with no resolvable tint uses the SF Symbol’s unsaid tint. `IconPath.swift:85-88` is the ruling for the rows the host actually sends: a written `tint_color` uses `symbolTint ?? inheritedTint` (a written `@tint` is the live accent; a concrete color is the channels), and a missing tint row uses `channels("text_color")`. `host/apple/Sources/ExactKit/Mac/NodeSymbolMac.swift:44` then assigns `iconPathTint ?? unsaidSymbolTint`. On the Mac that unsaid color is `secondaryLabelColor`, which the ruling keeps for SF Symbols and withholds from path icons. It runs only when `iconPathTint` is nil (no tint row, and `text_color` does not resolve). On iOS, `NodeViewIOS.swift:604` assigns `iconPathTint` alone, so a nil tint inherits the view’s live accent. Production style JSON always emits `text_color`, so this is the exceptional path. **Fix:** when the tint row is absent, use the text color and stop there. Assign the native text color (`NSColor.textColor` / `UIColor.label`, or `SystemColor.native`) so it stays live. A written `@tint` keeps `inheritedTint`. Leave `symbolTint ?? unsaidSymbolTint` on the SF Symbol branch.
