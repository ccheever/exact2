## Overall assessment

The direction is right and I would build *that*: a mounted component instance owns its `resource` / `mutation` / `task` lifetime; one clock; one data source; the current host request/reply protocol; a closed baked plan; no Aquifer; no second tree.

I would not build a new lifetime plane beside the instance tree, would not lift child effects into always-live root rows, and would not write one compiled `resources.initial` for a declaration that has many live copies.

`type-child-resource` is an implementation fence, not a language principle. The code still matches LLP 1017.000 P4c: children may own `state` / `derive` / `action`; resources, mutations, and tasks are refused (`contract/types/src/lib.rs`); settlement, pending bits, tickets, and timers are runner-wide arrays keyed by plan index (`runner/src/runner.rs`, `runner/src/runner/settlement.rs`). P4c already did the hard identity work for *slots* (`slots.owner` → `each` region, values on `RowSlots`, `LoadSlot` through frames). This RFC should extend that pattern to effects, not invent another one.

The previous 1017 panel traded per-instance resources away to get local state. Charlie's request reverses that trade for effectful children. That is allowed. It does not reopen shared caching, Aquifer (`rules/NOT-DOING.md`), or a second state/tree system.

## Strengths

- **D1's identity rule is the one the runner already implements for rows.** Two uses are independent; reorder by key keeps the row; remove/reinsert is a new `Row` (`runner/src/instance.rs`, `None =>` initialize, gone rows `destroy_all`). Scope identity as an instance allocation — not a source path, DOM id, or a key alone — is the same rule. "The compiler may realize a scope with the existing keyed-region machinery" is the right *kind* of reuse.
- **D2's no-implicit-cache rule is mandatory.** `DataSource::answer` is `(source, args)` with a `Store` (`llp/1005-plan-and-runner-v1.spec.md` §7). A runner-side merge by source+args would glue together calls that consult the store, clock, randomness, or credentials. Parent-owned resource, pass the *value* down, remains the share path.
- **D3/D5 match LLP 1016 as built.** Newest-wins is per target; forgotten tickets drop on `fulfill`; a dispatched mutation is not unsent (`Runner::forget`, `Runner::fulfill`). Logical cancellation without a new host abort is the existing promise.
- **D4's one clock is already true.** `Runner::advance_timed` is a seek over `plan.timers` (`runner/src/runner.rs`). The old "only the root has a clock" line is "only the root has *registrations*." Many owned timers on one seek is the smaller change.
- **D6's reload rule is the existing one.** `boot_carrying` keeps root slots by name, matching unowned resources, and the clock; row slots restart (`owner.is_some()` skipped in `carry` / `slot()`). Instance effects should restart the same way. No source-address matching.
- **Implementation direction §1–5 is the right crate order:** expand + types, `plan/tables/format.json` as authority, frames as storage, settle in the live environment, keep the host ABI. Fleet as a downstream proof, not a pinned-build rewrite, is in bounds.
- **Required verification list is the actual test plan.** Especially: two instances, reverse replies, `when`/`match`/`each`/slots/provide, reorder vs remove/reinsert, late timers, bake isolation, store/readiness, malformed ownership, agent ops rather than a ninth verb.

## The six panel questions

### 1. Is explicit lifetime ownership the right direction, and is there a smaller implementation?

**Yes, with a smaller implementation than a new lifetime system.**

Ownership is a *mounted instance of an existing site*, not a parallel object graph. The smallest complete cut:

1. Keep P4c expand-and-rename. An effectful use still inlines its view. Its `resource` / `mutation` / `task` (and, if it has them, its `state` / `action`) are lifted as renamed plan rows with an `owner`, exactly as `hot__3` is lifted today (`contract/syntax/src/inline.rs`).
2. Wrap **each effectful use** in a nonvisual scope region — preferred: new `RegionKind::scope` (one always-active arm, no subject, no key, no kernel node). Acceptable: a compiler-generated one-row `each` with a stable internal key and no item name leaking into the child (D1 already permits this). Do not use a fake `each` if `RegionKind` is changing anyway; a real `scope` kind is less lying.
3. Runtime values live on that region's frame (`RowSlots` plus an effects bag), looked up the way `LoadSlot` already looks up `owner` (`runner/src/vm.rs`).
4. Settlement evaluates unowned (root) derives/resources first, then each *live* owned declaration in its stacked frames, *before* publishing view bindings for that instance. Destroyed regions are not queried.
5. Tickets stay runner-unique (`next_ticket`). `Target` includes the instance lifetime, not only the plan index. Unmount forgets tickets. `fulfill` of an unknown ticket stays a drop.

That handles `when` / `match` / nested `each` / slots / provide because those already create and destroy nested `RegionInst`s. It does **not** handle them by compiling N root resource rows for a dynamic list, and it does **not** handle them by leaving the declaration live when the arm is gone.

Smaller still, and **wrong**: lift like state without a scope. A `when`-guarded child would still be a plan resource that `settle` evaluates with empty frames (`settlement.rs` `frames: &[]`). That is today's "conditional child's work into permanent root declarations." Do not do it.

Not smaller, and **wrong**: Aquifer, a query cache, a second instance tree, or a lifetime table keyed by list key across unmount.

### 2. Should every stateful child get a lifetime scope now, or only effectful ones?

**Only effectful ones, with one exception.**

Purely stateful children stay on the P4c path: singleton use → root slot, carried by name (`n__1` in `contract/cli/tests/instance.rs`); use inside `each` → row slot, not carried. Do not rewrite that.

If a child declares **any** `resource`, `mutation`, or `task`, **all** of its instance cells live on the same scope frame — including its `state`. Otherwise a singleton effectful child keeps today's root slot (carried on reload, survives `when` unmount) while D6 restarts its resource. That is D1's "retain its draft while restarting its asynchronous work." D6's "existing root carry rules" means the **application root's** slots, not lifted cells of an effectful instance.

Nested purely-stateful children of an effectful parent keep their own P4c identity (root or enclosing `each`), unless they themselves are effectful.

### 3. Can existing row frames safely carry owned effects without a second tree?

**Yes, if the owner is the per-use scope, not the enclosing `each` row.**

`Frame` already is the instance environment: `item`, `bound`, `region`, `row: RowSlots` (`runner/src/vm.rs`). `LoadSlot` / `StoreSlot` already branch on `slots.owner`. Dispatch already rehydrates frames for the hit view (`Runner::dispatch`). Row reuse already preserves `r.slots` across reorder.

Safe:

- Add `owner: opt:regions` on `resources`, `mutations`, `timers`, and on the mutation's result slot (same codec as `slots.owner` in `plan/tables/format.json`).
- Extend the owning frame with an effects bag (settled value, args, pending flag, tickets, timer `next_ms`, a monotonic lifetime). `Rc<RefCell<…>>` like `RowSlots`, so action eval and commit see one storage.
- `LoadResource` / `PendingResource` / `PendingMutation` / `Refresh` / `Send` resolve through `Frame` the way `LoadSlot` does. Today's opcodes already take `idx:resources` / `idx:mutations`; they do not need new opcodes if the VM uses the stacked frames.

Unsafe — this **is** a second identity, even if it sits in the same struct:

- Putting two sibling effectful uses' cells on the enclosing `each` `Row`. They would share one bag. D1 forbids that ("two uses are independent even when their props are equal").
- A side table keyed by `(decl, list key)` that outlives `destroy_all`. Remove/reinsert would inherit work.
- Evaluating owned resource args with `frames: &[]` (current `settle`). Args that read the item or a row slot would `Trap::BadScope` or silently see root placeholders (`Value::Unit` for owned slots at `boot_inner`).

`when` / `match` frames today have no `RowSlots` (`Active::Arm`). A scope region must be a real storage frame, not only a binding frame. That is still the same tree: `Child::Region` under the parent node.

Reconcile after the walk; do not give `instance.rs` a back-pointer into `pending`. `destroy_all` currently only emits `DestroyView` (`instance.rs`). Dropping a `Row` drops `RowSlots` by `Drop`, but it will **not** forget tickets or timers unless `Runner::update` diffs live lifetimes against `pending` / timer registrations before `take_requests`. That reconcile is the teardown fence. It is not a second tree.

### 4. What is the correct bake representation for per-instance resource values?

**Root declarations keep `resources.initial`. Owned declarations must not.**

Today bake boots once and writes every settled value onto the declaration (`contract/cli/src/lib.rs` `bake`: `runner.resource(&name)` then `set_resource_initial`). `Runner::resource(name)` is the first plan row with that name (`runner.rs`). Two live copies of one declaration, or two instances that should differ by props, collapse to one blob. D6's "cannot use the first instance's answer for all other instances" is a description of this function.

Correct representation:

| Kind | `resources.initial` | Extra |
|---|---|---|
| Unowned (root) | current compiled Now value | `reader` as today |
| Owned, store-reading | **empty** | `reader = true` on the **declaration** if any bake-time instance read the store |
| Owned, Later at bake and mounted | bake **refuses** (same as root: no I/O) | — |
| Owned, unmounted at bake (`when` false) | **empty**, no snapshot | first mount at runtime queries |
| Owned, Now and mounted | **empty** on the declaration | one `resource_boot` row per live instance |

`resource_boot` (name whatever `format.json` says; one table, generated decoder):

- `resource: idx:resources` — the **use-site** declaration (`usage__3`, not a shared template name)
- `keys: range` of enclosing `each` keys, outer first (empty for a singleton scope)
- `args: range` of the args actually queried
- `value: bytes`

Device boot: for each live instance, lookup `(resource, keys)`; if present **and** current args equal stored args **and** the value still conforms, use it; else `answer`. Never copy `resource_boot[0]` onto the declaration.

Smaller and acceptable only as an explicit D6 deviation: skip `resource_boot`, leave owned `initial` empty, re-query Now sources at device boot in the instance environment. First frame is then computed, not compiled, for those cells. Fleet's motivating children are likely `when`-guarded Laters, so they are unmounted at bake anyway. If the verification list keeps "bake with distinct instances," the table is the thing that makes that test true without I/O.

Bake still must not `advance` (it does not today) and must not treat timer registration as firing. `Runner::boot` already creates timer `next_ms` without firing.

### 5. What teardown, rollback, store, or pending-state edge is missing?

The RFC's D5/D6 sentences are directionally right and **underspecified against this code**. The missing edges are below in **Hazards**. The ones that will ship a wrong runner if skipped:

- Late-mount `Answer::Later` with no kept value (`settlement.rs` currently `RunnerError::Data`, message "answers later at boot", on **every** no-kept Later).
- `PendingResource` traps if `resources[i]` is `None` (`vm.rs`) — so `when pending(x)` cannot guard a first-pending child.
- `enqueue` then `update` that unmounts the owner (`run_action_inner` enqueues before `update`).
- `fulfill_inner` writes `self.slots[mutation.slot]` and `self.resources[i]`; owned mutation slots are root `Unit` placeholders today.
- Action rollback restores `self.slots`, `row_undo`, `pending_mut`; it does not know an effects bag.
- Store invalidation / `data_ready` / `keep_answer` are plan-index and **name** keyed (`kept.rs` `kept_name(resource name)`).
- Timers fire with `run_action(..., &[])` — `Trap::BadScope` for any owned write, and they ignore the instance's props.
- `has_timers()` is `!plan.timers.is_empty()`. Keep emitting plan rows for child tasks so a host that only checks at boot still drives `advance` before the first child mounts.

### 6. Is leaving cross-instance deduplication to the data source the right boundary?

**Yes.** Do not add a runner cache, request coalescer, or Aquifer.

The source already sees `(store, source, args)`. If two instances pass equal args into a pure function, the crate may intern. If they pass equal args into a store- or credential-dependent function, interning is a bug. The runner cannot tell those apart without a purity contract the RFC correctly refuses to invent.

Composition without a cache: the parent owns the resource and passes the settled value as a prop. That is a snapshot of a value, not a live cell — which is already how Contract works (values, not bindings). A child that needs its own refresh owns its own resource.

`refresh` is instance-local (D2). A parent `refresh` does not refresh children; a child `refresh` does not refresh siblings.

## Hazards

Severity: **Blocking** = wrong if the first implementation misses it; **High** = ships a class of Heisenbugs; **Note** = pin in the RFC so the implementer does not invent under pressure.

### H1. Instance identity — **Blocking**

- **Use site ≠ list key ≠ source path.** One effectful `Use` becomes one owned declaration row (renamed, P4c-style) plus one scope region at that site. Inside `each`, that one site has N frames, distinguished by the enclosing keys. Two uses in one row are two sites. Reusing the list key after removal is a new lifetime (`instance.rs` already does this for `Row`).
- **Do not key runtime storage by declaration index alone.** `Target::Resource(usize)` / `pending_res: Vec<bool>` / `refresh_next: Vec<usize>` are one-in-flight per plan row (`runner.rs`). N rows of `usage__3` would share one ticket, one pending bit, and one refresh.
- **Lifetime token** is a monotonic id on the frame, unique in the runner (same budget as `next_ticket`). Ticket uniqueness already fences replies *if* unmount removes the pending row. Keep both: forget on unmount, `fulfill` drops unknown tickets. A new instance must not reuse the old token.
- **Effectful singleton state must sit on the scope**, not on `owner: None` root slots. Otherwise reload/carry and `when` hide/show split state from work (Q2).
- **Synthetic `each` pitfall:** if the compiler uses a one-row `each`, the child's view must not bind the fake item, and the fake key must not be an author key. Prefer `RegionKind::scope`.

### H2. Conditional teardown — **Blocking**

- `when`/`match` switch already `destroy_all`s the old arm (`RegionInst::switch`). `each` already destroys gone rows. That is the unmount. **Hidden-but-mounted** (opacity, off-screen, inactive tab that still has a view) does **not** unmount; tasks keep running (D4). A `when false` is unmount. Pin that; authors who want a paused-but-alive child keep it mounted and pass a prop.
- `destroy_all` does not talk to `pending` or `timers`. After every committing tree walk, drop registrations whose lifetime is not in the live set, **before** `take_requests`. Otherwise this commit's `send`/`Later` is handed to the host for a component the same commit just destroyed, and a later `fulfill` writes into a successor or a root placeholder.
- Nested scopes unmount inside-out with the tree. An inner child's tickets die when the inner region dies, even if the parent stays.
- Component-level declarations are not view-conditional: a `when` *inside* an effectful child's view does not teardown that child's resources (they are not in the view). Only unmounting the **use** does. The author who wants "fetch only when expanded" puts the effectful use inside the `when`, or passes args that the source can no-op — do not add `task when [dep]`.

### H3. Bake representation — **Blocking**

See Q4. Additional pins:

- `bake()` must walk **live frames**, not `runner.resource(&name)`.
- Owned `resources.initial` stays empty even when exactly one instance existed at bake, so adding a second use cannot inherit the blob.
- `reader` may stay a declaration flag (any instance observed the store). Per-instance reader bits are a later optimization.
- Delivery resources (`exactDelivery`) stay runner-owned and root-shaped (LLP 1030 D7). Do not put them on a child.
- Bake still refuses mounted Later-without-kept. It does not start host I/O. It does not fire tasks.

### H4. Mutation rollback — **Blocking**

Today (`run_action_inner` / `fulfill_inner`):

- Now-answers write `self.slots[mutation.slot]` inside the commit.
- Later-sends enqueue only after `settle` succeeds.
- Failure restores `saved_slots`, `row_undo`, `commands`, `pending_mut`.
- Assignment to the mutation slot forgets the ticket (`assigned` → `forget`).

Owned mutations need the same transaction on the **frame bag**:

- Now-answer: write the instance's option slot (the owned slot, via `RowSlots` / effects), record undo like `row_undo`.
- Do not write the root placeholder (`boot_inner` pushes `Value::Unit` for `owner.is_some()` slots).
- `Send` must carry the current lifetime in `Outcome`, not only `idx:mutations` (`vm.rs` `out.sends.push((m, source, sargs))`).
- A refused settle must not enqueue, and must restore instance pending flags.
- Unmount does not undo a POST already given to the host (1016 D5). It only makes the reply inert.
- A new instance with the same list key starts at `none`, not pending, not the old `some`.

`act(name)` and timers currently pass `&[]` frames. A child task that `send`s must run with its frame stack or it is `Trap::BadScope` / writes the wrong slot.

### H5. Resource settlement — **Blocking**

Current order: `settle` (empty frames, all plan resources) then `update` (frames, kernel ops). Owned resources invert that.

Required order for a commit:

1. Apply action writes (root + owned) tentatively.
2. Settle **unowned** derives/resources (today's fixpoint, still empty frames except they may read root slots).
3. Walk the instance tree **without** requiring kernel equality yet: reuse frames by key, create bags for new keys, drop bags for gone keys (teardown tickets).
4. For each live scope, in tree order, evaluate that scope's resource **args in its stacked frames**, reuse if args+store-revision match, else `answer`. A sync (`Now`) value is visible to nested `when` / child scopes in this same pass.
5. If a store write happened, rescan live store-reading instances (today's `stale_store_reader` loop, but over frames, not `Vec` by decl).
6. Only then evaluate view bindings / emit kernel ops. Failure before apply rolls back writes, bags, and commands and leaves the kernel untouched. Failure after kernel ops begin still poisons (1005 §6).

**Late-mount Later (Fleet's actual case):** a child not present at bake, mounted by an action, source returns `Later`, no `initial`, no previous. Today's `settle` returns `Data`. That must become: pending true, **no value**, no host I/O until the commit stands, then one request.

**`pending(x)` must not require a value.** `Opcode::PendingResource` currently traps `Pending` when `resources[i]` is `None`. The author pattern `when pending(usage) … else usage.amount` cannot mount. Change: if this instance's pending flag is true and there is no value, `pending(x)` is `true`; `LoadResource` still traps `Pending` (so the `else` arm is not evaluated). An unconditional view read of a first-pending resource remains a trap; if it happens during `update` after the tree was mutated in memory, that is still poison unless the implementer evals the new instance's view before emitting ops. Prefer: create the bag and settle **before** realizing that instance's kernel nodes, so a trap there refuses the commit without `DestroyView`/`CreateView`.

**Resource args must be lowered in the owner scope**, not `types.component_scope(root)` at depth 0 (`contract/lower/src/lib.rs` currently does that for every resource). Owned slot inits already wait until `each_regions` exist and use `each_scopes`. Copy that. Substituting props as **live expressions** (like the view), not dispatch-time captures (like child actions' `@capture:` params), is what makes "changed props supersede" true. If args capture mount-time props, D2 is false.

**Sync resource gating further children** (required verification): parent/own Now value feeds a nested `when`/`each` in the same pass. That is step 4's tree order. A child's resource is not visible to the parent by name (no lifting into the parent's namespace). If the parent needs it, the parent owns it.

### H6. Timer environments — **Blocking**

- `Runner::timers` is `Vec` indexed by `plan.timers` (`boot_inner`, `advance_timed`). First due is `now + interval` at **boot**, for every declaration, whether or not a child exists.
- Fire: `run_action(action, Vec::new(), &[])` — no frames, so owned writes refuse; prop reads see root, not the instance.
- Tie-break: earliest `next_ms`, then **plan index**.

Required:

- A timer row has `owner`. No live owner instance → not registered. Mount: `next_ms = now_ms + interval` (D4), not boot time.
- Fire in that instance's current frames (live props, live slots). Reorder does not reset `next_ms` because the frame was reused. Remount allocates a new bag.
- Tie-break: `(due_ms, timer_decl_index, region_index, enclosing key path)`. Not pointer order.
- `has_timers()` stays "the plan declares any timer," so hosts that check once at boot still call `advance` before the first child mounts. If it becomes "any live timer," a host that does not re-check will never fire late-mounted tasks.
- `TIMER_FIRE_LIMIT` (4096) stays global. N instances of a 1 ms task will hit it sooner on a large seek. Retain existing bounded catch-up; do not invent per-instance limits in this cut.
- Bake/boot must not fire them. Registration is not a fire.

### H7. Store invalidation — **Blocking**

Today:

- `store_readers: Vec<bool>` per declaration; `ResourceState.store_revision`.
- Reuse is refused when a known reader’s revision mismatches (`settlement.rs`).
- A later resource in plan order that writes the store retriggers the pass.
- `data_ready` `recommit`s every `stale[i]` (`kept.rs`).
- `keep_answer` stores under the **resource name**.
- `carry().resources` is by name, skipping only `pending_res[i]`, **not** skipping owned (there are none yet).
- `recommit` clones `self.resources` as a whole-plan `Vec`.

Required:

- Store-dependence is per **live instance**. A child that reads the store dirties that instance when the revision moves, including when the writer was a sibling, a parent mutation `parse`, or `data_ready`.
- `keep_answer` / carried resource maps **must not** use a bare name for owned rows. D6 says instance effects restart: the small complete cut **does not keep or carry** owned answers. Root store-readers stay as they are.
- `data_ready` asks every **live** store-reading instance showing a placeholder, not `stale: Vec<bool>` by decl. An unmounted child is not asked.
- `Runner::resource_reads_store(name)` / bake's use of it is declaration-level; keep that for root and as a conservative declaration flag for owned.

### H8. Agent / host observation — **High**

`state` emits one JSON object keyed by declaration name and **skips** owned slots (`runner/src/agent.rs`). `pending()` is `(name, ticket)`. Two instances named `usage` (or one `usage__3` with N copies) collide or vanish.

Do not add a ninth operation. Additive `state.instances` (or include owned values as arrays of `{keys, value, pending}`) is enough for `expect state`. Tree text remains the primary proof, as `instance.rs` tests already do. `RequestOut.target` is a log string; the host fulfills by **ticket**. Keep the ABI. Optionally qualify the log name; do not make the host parse it.

### H9. Format / decode — **High**

`plan/tables/format.json` is the authority; `FORMAT_DIGEST` will change. Validating decode must refuse, not panic:

- `owner` that is `None` for a row that lowering marked owned, or dangling
- `owner` naming a `when`/`match` region rather than a `scope`/`each` (if that invariant is the one you choose — pin it)
- timer `owner` with an action that writes a different region's slots
- `resource_boot` naming a missing resource or a key that does not decode
- duplicate unowned names (owned names may repeat across owners only if you *don't* rename; I recommend rename-per-use so unowned uniqueness stays the rule)

Bump compiler identity as lowering's behavior change already does (`contract/lower/src/lib.rs` `compiler_identity`).

### H10. File size / process — **Note**

`runner.rs` is the commit shell; `settlement.rs` and `instance.rs` already exist because of the 1,500-line cap. Put owned settlement and teardown reconcile in those files (or one new `runner/src/runner/owned.rs`), not another 400 lines on `runner.rs`. No new check, no new agent verb, no Aquifer crate.

## Small complete implementation

Do this, in this order. Stop at the end of step 8. Do not add a cache, a second tree, or host protocol.

1. **`format.json`:** `owner: opt:regions` on `resources`, `mutations`, `timers`. `RegionKind` += `scope` (preferred). New `resource_boot` table as in Q4. Generated decoder checks as in H9.
2. **Expand / types:** remove `type-child-resource`. Type-check child bodies with their own resources/mutations/tasks (the independent `check_component` path already exists). At each effectful `Use`, allocate a scope tag, wrap the inlined view, lift declarations renamed `__n` with `owner = scope` — including that child's state. Stateful-only uses unchanged. Resource args: substitute props as live expressions, not `@capture` snapshots.
3. **Lower:** emit owned rows; compile owned resource args and owned slot inits in the owner region's item/scope, same as P4c row inits. Emit timer rows with owner. Do not evaluate owned resources at lower time.
4. **VM / Outcome:** `LoadResource` / pending / `StoreSlot` / `Send` / `Refresh` honor `owner` via frames. `Outcome.sends` / `refreshes` carry the lifetime (or the `RowSlots`/effects `Rc`) so commit can find the bag.
5. **Runner commit shell:** bags on frames; `Target` includes lifetime; unique tickets unchanged; rollback includes bag writes; enqueue **after** the tree walk, or enqueue then reconcile dead lifetimes before `take_requests`. `carry` skips owned. `keep_answer` skips owned.
6. **Settlement:** unowned fixpoint, then live-frame owned settlement in tree order, including first-Later-without-value. `pending(x)` true with no value. Store-revision rescan over live instances. `data_ready` over live placeholders.
7. **Timers:** register on mount; fire with frames; tie-break as H6; `has_timers` from the plan table.
8. **Bake:** walk live frames; never `set_resource_initial` on owned rows; write `resource_boot` for Now instances; refuse mounted Later; do not `advance`.
9. **Tests:** the RFC's list, as runner/corpus fixtures first, then `node scripts/agent.mjs` on web for one child timer + one child resource. Fleet component move is downstream and does not change the pinned build.

Pure components stay inlined. Child derives stay substituted expressions (they already become bytecode in the child's view, which will sit under the scope and eval with its frames). No runtime derive table per instance in this cut.

## Suggestions (non-blocking)

- Name the region kind `scope` in `format.json`, not `component`, so it does not look like a kernel node.
- Keep `type-child-resource` as a **retired** reject id in a comment or corpus note so old fixtures fail on a new id (`type-owned-effect` or just succeed). Prefer a new corpus file `owned-effects.contract` over overloading `instance.contract`.
- Document the author pattern for first-pending children: `when pending(x)` / `else` read. It is already 1016 D3's view shape.
- If `resource_boot` feels large for v1, ship empty owned initials **and** a bake test that two Now instances with different props produce different first-frame **device** values. Then add the table when a compiled child list is actually on the bake critical path.

- Whether `RegionKind::scope` or a synthetic `each` is the one they want in `format.json` this week. I prefer `scope`.
- Whether to spend the `resource_boot` table now or accept computed first frames for owned Now resources.
