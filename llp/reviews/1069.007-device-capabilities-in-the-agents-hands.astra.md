## Review (verbatim)

The approach is sound, but r2 is not yet a buildable cross-host protocol. At `ed59545d`, the landed seed/locale/time-zone flags, display `prefer`, and unanswerable `pending` claims match the code. The main blockers are production isolation, request identity and lifetime, and secret disclosure. Several CDP mappings and deterministic-execution guarantees also need correction. This review made no edits; six selected existing in-memory tests passed, and read-only probes confirmed the flag conflict below. Browser and native applications were not launched.

1. **BLOCKER — The production boundary does not enforce the promised isolation.**

   [D2:110](/Users/ccheever/projects/exact2/.claude/worktrees/agent-a1304ffcbfa2279e2/llp/1069.007-device-capabilities-in-the-agents-hands.rfc.md:110) selects substitutes using `?agent=1` / `EXACT_AGENT=1`, while line 146 promises that production ignores agent values. Today, [web glue:125](/Users/ccheever/projects/exact2/.claude/worktrees/agent-a1304ffcbfa2279e2/host/web/glue.js:125) checks only whether the query parameter exists—even `?agent=0` enables it. Production ships that glue through `host/web/build.mjs:100`. Apple’s `Session.swift:41` and Linux’s `app.rs:210` likewise use environment flags without a production restriction.

   A non-agent boot test cannot establish that a production artifact refuses an agent launch. Extending these gates to predictable `getRandomValues` makes this a security defect: authentication uses those bytes for PKCE verifiers.

   **Resolve:** define and enforce a trusted production/development boundary independently of launch parameters. Test production artifacts with agent parameters explicitly present. The real-device escape must also restore secure entropy. **Touches the seeded-random-stream ruling; the problem is its admission boundary, not repeatability in tests.**

2. **BLOCKER — Tickets lack a complete namespace and lifetime contract.**

   [D3:159](/Users/ccheever/projects/exact2/.claude/worktrees/agent-a1304ffcbfa2279e2/llp/1069.007-device-capabilities-in-the-agents-hands.rfc.md:159) explicitly leaves host/runner ticket collisions unresolved. D4 specifies only a driver-side pending check. Meanwhile, runner tickets restart at 1 (`runner/src/runner.rs:644`), and [fulfillment:756](/Users/ccheever/projects/exact2/.claude/worktrees/agent-a1304ffcbfa2279e2/runner/src/runner/commit.rs:756) silently drops forgotten tickets.

   Consequently, an answer checked before cancellation can become stale before delivery; after replacement, the same number can identify a different request. Command requests additionally lack rules for node removal, repeated invocation, session destruction, and duplicate answers.

   **Resolve:** specify a collision-free, JavaScript-safe identifier space scoped to session and host generation. The host must atomically validate and consume a live request before delivering its answer. Define retirement and stale-answer responses, including after asynchronous fixture copying. Fixtures and manual answers must share this protection.

3. **BLOCKER — Publishing raw request arguments leaks credentials.**

   [D3:154](/Users/ccheever/projects/exact2/.claude/worktrees/agent-a1304ffcbfa2279e2/llp/1069.007-device-capabilities-in-the-agents-hands.rfc.md:154) exposes the app’s arguments; D5 exposes the entire native request. The presence-only protection at line 144 applies only to facts.

   This has a concrete auth case: [1069.006:256](/Users/ccheever/projects/exact2/.claude/worktrees/agent-a1304ffcbfa2279e2/llp/1069.006-auth-session.rfc.md:256) publishes the authorization URL. OIDC permits an existing ID token in that URL’s `id_token_hint`. Arbitrary native request bodies can likewise contain tokens. [OpenID Connect Core §3.1.2.1](https://openid.net/specs/openid-connect-core-1_0.html#AuthRequest)

   **Resolve:** distinguish private execution arguments from an allowlisted inspection summary. D7 must require a disclosure policy covering pending arguments, fact replies, answer acknowledgments, validation errors, and journal lines. Auth codes and tokens must never be echoed. Preserve LLP 1018’s names-only store boundary.

4. **MATERIAL — Held requests need explicit treatment throughout the clock algorithm.**

   [D3:163](/Users/ccheever/projects/exact2/.claude/worktrees/agent-a1304ffcbfa2279e2/llp/1069.007-device-capabilities-in-the-agents-hands.rfc.md:163) changes `settle`, but its `clock +N` sentence addresses timeouts rather than waiting. Current numeric advances wait for pending requests before firing due timers: [Apple Agent:327](/Users/ccheever/projects/exact2/.claude/worktrees/agent-a1304ffcbfa2279e2/host/apple/Sources/ExactKit/Agent.swift:327), `host/linux/src/agent.rs:493`, and `host/web/glue.js:1219`.

   Thus a held auth request can still impose the twenty-second wait before the app’s cancellation timer runs. Mixed network/device requests also leave “returns at once” versus “network requests keep their wait” ambiguous.

   **Resolve:** classify held device work separately in every wait and advance loop. Specify mixed-request precedence, device requests created while waiting, and whether ready fixture completions drain before returning. Test a held request plus a due cancellation timer and an unrelated unfinished fetch. **Touches the immediate-`settle` ruling by making its implementation precise.**

5. **MATERIAL — The CDP fact mappings do not preserve the promised semantics.**

   All named methods exist, but [D5’s table:225](/Users/ccheever/projects/exact2/.claude/worktrees/agent-a1304ffcbfa2279e2/llp/1069.007-device-capabilities-in-the-agents-hands.rfc.md:225) is not a sufficient implementation:

   - `Page.setWebLifecycleState` accepts `frozen`/`active`. Chromium’s frozen branch hides **and freezes** the page; its active branch only unfreezes it. It is not a reversible visible/hidden fact setter. [Chromium implementation](https://raw.githubusercontent.com/chromium/chromium/main/content/browser/devtools/protocol/page_handler.cc)
   - `Network.emulateNetworkConditions` changes traffic as well as reported connectivity. Native `prefer online false` merely changes a fact. The method is also deprecated; `Network.overrideNetworkState` provides the fact override separately. [CDP schema](https://raw.githubusercontent.com/ChromeDevTools/devtools-protocol/master/json/browser_protocol.json)
   - Locale/zone CDP overrides alone cannot update Exact’s current reporter: [navigation.js:533](/Users/ccheever/projects/exact2/.claude/worktrees/agent-a1304ffcbfa2279e2/host/web/navigation.js:533) reads captured agent parameters.

   **Resolve:** specify the setter bridge and observable semantics for each fact, including visibility without suspending the driver and consistent network behavior across hosts.

6. **MATERIAL — The web request boundary is incomplete and contradicts the delivery ruling.**

   [D4:208](/Users/ccheever/projects/exact2/.claude/worktrees/agent-a1304ffcbfa2279e2/llp/1069.007-device-capabilities-in-the-agents-hands.rfc.md:208) requires substituted answers to report `substituted`; D5:223 says CDP overrides report `platform`. The picker sibling repeats both values at `1069.002:244` and `:247`.

   The listed CDP calls also leave protocol work unresolved. `Browser.setPermission` sets permission state; it does not create an interceptable permission-request ticket. File selection is supported, but the proposed mapping supplies no late `tap @t cancel` implementation. Passing an empty file list does not solve that: Chromium’s `SetFilesFromPaths` returns without dispatching cancellation. [CDP schema](https://raw.githubusercontent.com/ChromeDevTools/devtools-protocol/master/json/browser_protocol.json), [Chromium file-input implementation](https://raw.githubusercontent.com/chromium/chromium/main/third_party/blink/renderer/core/html/forms/file_input_type.cc)

   **Resolve:** define one held-request lifecycle, with CDP as a completion mechanism where suitable. Specify cancellation, permission prompting, and the grant/activation validation that substitution retains. Report substituted answer provenance consistently. **Touches the `delivery: "substituted"` ruling.**

7. **MATERIAL — `--epoch` is not the last missing deterministic launch input.**

   [First slice:330](/Users/ccheever/projects/exact2/.claude/worktrees/agent-a1304ffcbfa2279e2/llp/1069.007-device-capabilities-in-the-agents-hands.rfc.md:330) makes that claim, but every host still obtains `utcOffset` from the machine independently of the substituted IANA zone: `glue.js:1334`, [Session.swift:835](/Users/ccheever/projects/exact2/.claude/worktrees/agent-a1304ffcbfa2279e2/host/apple/Sources/ExactKit/Session.swift:835), and `host/linux/src/app.rs:298`. An agent can therefore report `timeZone: "UTC"` with a nonzero machine offset.

   Existing display preferences also lack deterministic launch initialization. [DisplayPreferences.swift:15](/Users/ccheever/projects/exact2/.claude/worktrees/agent-a1304ffcbfa2279e2/host/apple/Sources/ExactKit/DisplayPreferences.swift:15) starts without an override and reads accessibility settings; the web driver initializes its emulated preferences to `{}`.

   **Resolve:** include existing display defaults in the first slice and derive the offset from the selected zone and virtual date. Specify behavior across zone changes and DST boundaries. Verify equivalent launches under differing machine settings, not just two runs on one machine.

8. **MATERIAL — The native-module substitute cannot work solely at the request arm.**

   [D5:253](/Users/ccheever/projects/exact2/.claude/worktrees/agent-a1304ffcbfa2279e2/llp/1069.007-device-capabilities-in-the-agents-hands.rfc.md:253) assumes `native.later` produces a ticket while module code is disabled. In the default native agent configuration, [js/src/lib.rs:247](/Users/ccheever/projects/exact2/.claude/worktrees/agent-a1304ffcbfa2279e2/js/src/lib.rs:247) reports the module unavailable; `js/src/prelude.js:305` falls back to synchronous `native.call` when no later handler exists. No host-held request necessarily appears.

   Separately, `native.watch` supplies invalidation only. Its re-answer must read a value from somewhere, but the RFC disables the real module without defining substitute values or synchronous reads. [LLP 1016.002:32](/Users/ccheever/projects/exact2/.claude/worktrees/agent-a1304ffcbfa2279e2/llp/1016.002-changes-the-device-announces.rfc.md:32)

   **Resolve:** specify substituted availability, synchronous reads, topic values, and asynchronous requests together. Exercise the existing native seam end to end. The first-slice statement “No capability exists yet” is inaccurate, and §4’s “one branch” estimate omits this work.

9. **MATERIAL — D7 does not cover event lifetime, streams, or startup delivery.**

   [D7:278](/Users/ccheever/projects/exact2/.claude/worktrees/agent-a1304ffcbfa2279e2/llp/1069.007-device-capabilities-in-the-agents-hands.rfc.md:278) requires names and value shapes, but not ordering, coalescing, subscription lifetime, terminal outcomes, or initialization order.

   Latest-value facts can carry a watched position. They cannot, without additional rules, preserve two identical notification events or every partial result of a streaming request. `type <navigation root>` tests navigation after attachment; it does not specify cold-launch notification payloads or background delivery. Requests produced before driver readiness also need a defined holding path.

   **Resolve:** either narrow the universal claim to one-shot requests and latest-value facts, explicitly deferring other shapes, or extend the existing-operation protocol with event identity, bounded delivery, subscription termination, and bootstrap rules. Install holds and fixtures before any capability can reach the OS; driver readiness must not depend on answering them.

10. **MATERIAL — The advertised auth fixture cannot obtain its correlation state for PAR.**

    [D4:212](/Users/ccheever/projects/exact2/.claude/worktrees/agent-a1304ffcbfa2279e2/llp/1069.007-device-capabilities-in-the-agents-hands.rfc.md:212) offers a fixed callback URL for every auth request. The sibling adds `{state}` substitution, but [1069.006:80](/Users/ccheever/projects/exact2/.claude/worktrees/agent-a1304ffcbfa2279e2/llp/1069.006-auth-session.rfc.md:80) shows the actual request containing only an authorization URL with `client_id` and opaque `request_uri`, plus callback and ephemeral settings.

    With PAR, the state was sent in the earlier pushed request; it is not recoverable from that authorization URL. [RFC 9126 §1.1](https://www.rfc-editor.org/rfc/rfc9126.html#section-1.1)

    **Resolve:** define how the fixture provider correlates the PAR request and supplies a valid callback, or explicitly limit this fixture form. Do not obtain it by exposing the private store. Also specify completion ordering after the originating commit and the precedence of fixture answers versus manual answers.

11. **MATERIAL — A seed alone does not define a repeatable stream across hosts and reloads.**

    [First slice:333](/Users/ccheever/projects/exact2/.claude/worktrees/agent-a1304ffcbfa2279e2/llp/1069.007-device-capabilities-in-the-agents-hands.rfc.md:333) delegates to `1069.005 D2b`, which selects a generator at executor/realm creation but specifies neither its byte algorithm nor ownership and cursor lifetime. That sibling also preserves IDs in carried answers (`1069.005:227`).

    An implementation that reseeds a replacement executor can reuse a UUID already retained by the runner. Separate executors seeded identically can also produce identical sequences. Two fresh-run UUID comparisons would miss both defects.

    **Resolve:** define the algorithm, seed encoding, UUID consumption, stream scope, and reload behavior. Include shared cross-host vectors and a reload test retaining an earlier ID. Define consumption order or stream partitioning where execution can overlap. **Touches the seeded-random-stream ruling; it supplies the missing determinism contract.**

12. **MATERIAL — `--device real` conflicts with the existing physical-device flag.**

    [D8:293](/Users/ccheever/projects/exact2/.claude/worktrees/agent-a1304ffcbfa2279e2/llp/1069.007-device-capabilities-in-the-agents-hands.rfc.md:293) assigns a value-taking meaning to `--device`. Today [agent-launch.mjs:16](/Users/ccheever/projects/exact2/.claude/worktrees/agent-a1304ffcbfa2279e2/scripts/agent-launch.mjs:16) treats it as a boolean selecting a physical iPhone; `agent.mjs:898` rejects it on other hosts.

    A read-only parser probe produced `device: true` with `real` left among the operations.

    **Resolve:** give substitution mode a distinct flag and programmatic option, preserving independent selection of phone versus simulator. Define precedence against launch facts, fixtures, and secure entropy.
