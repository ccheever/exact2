# Code review: LLP 1080.000 real iOS taps, stages 0–1, round 2 (astra)

**Reviewer:** Astra (codex gpt-6-astra, xhigh), 2026-10-03, diff cd7d2533..20335328

**Verdict:** DO NOT SHIP — device ownership and timeout handling remain unsafe.

1. **High — Lock takeover can still admit two live owners.** At [touches.mjs:106](/Users/admin/.config/tuft/sessions/1791014443.232549/worktrees/exact2-1080.000/host/apple/touches.mjs:106), comparison and unlink remain separate. A contender’s initial exclusive create can fail just before the previous owner releases; `seen` then becomes `null`. After the takeover re-read also returns `null`, another process can successfully create its lock before this contender unlinks it and creates its own. Both sessions now own the device. Normal acquisition does not honor `.takeover`, so that guard cannot prevent this handoff race. Previous disposition 3 is incomplete. **Fix:** when the observed file has vanished, retry exclusive creation without unlinking; restrict stale removal to an existing, revalidated dead-owner token under the takeover guard.

2. **Medium — The public tap still waits about 120 seconds after a barrier timeout.** [touches.mjs:222](/Users/admin/.config/tuft/sessions/1791014443.232549/worktrees/exact2-1080.000/host/apple/touches.mjs:222) races the log request against one second but leaves the carrier request pending. The rejection then reaches [agent.mjs:939](/Users/admin/.config/tuft/sessions/1791014443.232549/worktrees/exact2-1080.000/scripts/agent.mjs:939), which awaits `tapRefusal`; that unconditionally requests another tree at [agent.mjs:740](/Users/admin/.config/tuft/sessions/1791014443.232549/worktrees/exact2-1080.000/scripts/agent.mjs:740). If the app remains wedged, the public call waits for the carrier’s 120-second deadline before reaching cleanup. The standalone barrier evidence misses this path. **Fix:** expire and invalidate the pending carrier request at the barrier deadline, skip diagnostic reads for transport failures, and initiate runner teardown immediately.

3. **Medium — Teardown releases ownership without establishing that xcodebuild exited.** [touches.mjs:130](/Users/admin/.config/tuft/sessions/1791014443.232549/worktrees/exact2-1080.000/host/apple/touches.mjs:130) sends SIGTERM, waits another three seconds, then unconditionally releases the lock. A stopped or unresponsive child can remain alive while another session starts; its referenced process and pipes can also keep a programmatic driver alive after `close()`. This contradicts dispositions 2–3’s completed-teardown guarantee. **Fix:** escalate to SIGKILL on the recorded PID after the grace period and confirm exit before releasing ownership; report teardown failure if termination cannot be established.

4. **Medium — Descendants of menu invokers bypass the stage-3 refusal.** [MenusIOS.swift:331](/Users/admin/.config/tuft/sessions/1791014443.232549/worktrees/exact2-1080.000/host/apple/Sources/ExactKit/IOS/MenusIOS.swift:331) checks `popovertarget` only on the requested node. Tapping an invoker’s text, image, or box by numeric ID therefore passes, although tapping its enclosing button is refused. [TouchIOS.swift:129](/Users/admin/.config/tuft/sessions/1791014443.232549/worktrees/exact2-1080.000/host/apple/Sources/ExactKit/IOS/TouchIOS.swift:129) never rechecks the hit view or enclosing invoker. The touch can return `platform` while the menu remains unavailable because agent mode omitted its native overlay. Previous disposition 5 is incomplete. **Fix:** check enclosing invokers and the resolved hit ancestry before injection, covering descendants and ancestor targets whose centers hit substituted controls.

5. **Medium — Concurrent cold starts on different simulators can destroy each other’s runner build.** The cache directory is shared by source/SDK/architecture/Xcode, while ownership is locked only per device. Two processes targeting different simulators can both pass [touches.mjs:37](/Users/admin/.config/tuft/sessions/1791014443.232549/worktrees/exact2-1080.000/host/apple/touches.mjs:37); either can then recursively remove the directory while the other compiles, signs, or installs from it. **Fix:** serialize construction by cache key, or build in unique directories and atomically publish the completed immutable bundle.

6. **Low — Every ordinary platform tap returns null instead of its required viewport coordinates.** [touches.mjs:236](/Users/admin/.config/tuft/sessions/1791014443.232549/worktrees/exact2-1080.000/host/apple/touches.mjs:236) returns `at: at ?? null`, but the driver calls `realTap` without `at`. Consequently, successful public taps violate LLP 1012’s `at: [x,y]` reply shape. The separate `aim` field contains scene coordinates and cannot substitute for viewport coordinates. **Fix:** include the resolved viewport point in the aim response and return it as `at`.
## Disposition

Claude (Opus 5.5), 2026-10-03, on `tuft/1080.000`, fix round 2 of 3. All six
were taken. The evidence is in `/tmp/exact-1080-touch/review2/` and was
gathered on the `exact-1080-touch` simulator.

1. **Taken.** When the lock file vanished between the exclusive create and the read, the lock is now taken by another exclusive create, in a bounded loop. It is never removed. A lock is removed only when it exists, holds a dead owner's token, and still holds the token seen, re-read under the exclusive `.takeover` file. Only takeovers remove a dead token, and takeovers are serialized, so a live owner's lock is never removed.
   - Evidence (`lockrace.mjs`): the committed `lock`, copied with only an export added, ran 25 rounds of 4 contenders handing the lock off, each holding it for 30–70 ms. All 100 owners had disjoint intervals, with no failures.
   - The same harness against 20335328's lock also showed no overlap. It does not reproduce the narrow window the review describes. The fix rests on the reasoning above, and the harness shows it did not regress.
2. **Taken.** On a barrier timeout, `realTap` now does three things:
   - It spends the app's carrier through `abandon`, which is `lines.fail` for the simulator. The pending request is rejected, and a late reply cannot answer a later request.
   - It ends the runner at once (`touches.end()`).
   - It throws an error marked `transport`, which `tapRefusal` now returns without any diagnostic read.

   Runner failures are marked the same way. Evidence (`barrier2.out`): a log read that never answered failed at 1,007 ms with the carrier abandoned and the runner ended once. `tapRefusal` with a session whose reads never answer returned the same error in 0 ms.
3. **Taken.** Teardown waits 3 s, sends SIGTERM and waits 3 s, then sends SIGKILL and waits 3 s, signalling only the recorded PID. It destroys the child's pipes. The lock is released only after the exit is confirmed. If the exit cannot be confirmed, the lock is kept and `close()` reports "did not exit after SIGKILL; the device's touch lock is kept". `openIOS` still cleans up the app before it rethrows that.
   - Evidence (`live2.out`): xcodebuild was stopped with SIGSTOP and then `close()` was called. The session closed in 6,031 ms, xcodebuild was gone, and the lock was released.
   - The path where exit cannot be confirmed was not driven: no process survives SIGKILL here.
4. **Taken.** `aim` checks stage 3's boundary for the target, every node enclosing it, and every node enclosing what the window's hit test finds at the point (`Agent.enclosing`). That runs after the point is resolved and before anything is returned. Evidence (`live2.out`, the `share.contract` fixture):
   - `tap more` (the invoker) was refused;
   - its label, tapped by numeric id, was refused "(through node #9)";
   - the plain text `can-share` was `platform`.
5. **Taken.** The runner is built in a directory of its own (`<key>.build-<pid>-<random>`) and published by one `rename`. A published runner is complete and never rewritten, and the build that loses the race uses the winner's. The `.xctestrun` now goes to the OS temp directory, not the cache. Evidence (`buildrace.out`): two cold builds started together from an emptied cache both succeeded, one directory was published, and no staging was left.
6. **Taken.** `aim` returns the viewport point as `at`, and `realTap` replies with it. Evidence (`live2.out`): `tap brand` replied `at: [116.9, 84.5]`, the middle of its `layout` box. The scene point `[116.9, 146.5]` stays in `aim`.
