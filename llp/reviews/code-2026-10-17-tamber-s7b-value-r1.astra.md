2. **P0 — One transaction can create two values for the same param.** [contract/cli/src/tamber_ops.rs:152](/tmp/rv-s7b-r1/contract/cli/src/tamber_ops.rs:152), [tamber/src/params.rs:85](/tmp/rv-s7b-r1/tamber/src/params.rs:85). Normalization consults only the original snapshot, so both lines are written. Planning takes the first; compilation and resolution take the last. Making the second value `80px` also bypasses range validation. Normalize against the evolving transaction and reject duplicate resolved identities consistently.

3. **P0 — Icon aliases are resolved before overrides, while planning never resolves them.** [contract/lower/src/theme.rs:251](/tmp/rv-s7b-r1/contract/lower/src/theme.rs:251), [tamber/src/params.rs:74](/tmp/rv-s7b-r1/tamber/src/params.rs:74). An override `Card.base = icon(sf "heart")` leaves `shown` as the star because `add_to` already copied its default. 4. **P0 — An ambiguous param read can return an unrelated token.** [contract/cli/src/tamber_serve.rs:699](/tmp/rv-s7b-r1/contract/cli/src/tamber_serve.rs:699). 6. **P1 — Validation runs only when the transaction contains `set-param`.** [contract/cli/src/tamber_serve.rs:1148](/tmp/rv-s7b-r1/contract/cli/src/tamber_serve.rs:1148).
