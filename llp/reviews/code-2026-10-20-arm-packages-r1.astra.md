# Quick review: Swift packages in the arm cache (1ed590a38d), Astra

**RIGHT WITH CHANGES**

1. **BLOCKING — Package filenames and boundaries are missing from the key.** [host/apple/build.mjs:1049](/tmp/rv-armpkg-astra/host/apple/build.mjs:1049), [995](/tmp/rv-armpkg-astra/host/apple/build.mjs:995). `packageSources` flattens every package, and the key hashes only their text; package source paths never enter `moduleArgs`. **Repro:** cache a package exposing `#filePath`, rename its Swift file and update `sources.swift` without changing its contents. The cached module retains the old path. Moving a helper between two packages while preserving flattened source order also produces the same key, despite changing which Swift module compiles it. I confirmed both key collisions in memory. Hash per-package source paths and contents, preserving package boundaries. Include the package compiler arguments too: package-only flags currently have no invalidation mechanism.

2. **BLOCKING — Later probes can cache old objects under new source contents.** [host/apple/build.mjs:1094](/tmp/rv-armpkg-astra/host/apple/build.mjs:1094), [1120](/tmp/rv-armpkg-astra/host/apple/build.mjs:1120). Package sources remain live files, while `placed` retains their first compiled objects. **Repro:** on an iOS simulator build with native tags and packages, let the module compile package version A; edit that package to B while the host compile finishes. When the Catalyst route fails and the simulator probe is compiled later, its key hashes B, but it links A because `placed` is already true. That probe can then be reused on subsequent B builds. An app roster derived from a package-exported value can consequently stay stale. Snapshot package sources once and use that snapshot for both compilation and every arm key.

3. **NIT — The commit’s “arm’s own target” explanation is inaccurate.** [host/apple/build.mjs:1099](/tmp/rv-armpkg-astra/host/apple/build.mjs:1099). Packages always compile for the build target; Catalyst/macOS probes use different targets. **Repro:** an iOS build with packages and native tags attempts a Catalyst probe against simulator/device package modules. This mismatch predates HEAD; correct the explanation rather than presenting it as a new regression. The QUEUE deletion correctly addresses temporary-path churn.

Otherwise, module names and the composed adapter are covered. Every package-linking call includes `-I packageDir`; early arms cannot trigger the uninitialized closure. Synchronous placement prevents reentrancy, and a package failure on the main module path aborts. No ordinary `.replace` misfire or additional resource/dependency compilation path surfaced.
