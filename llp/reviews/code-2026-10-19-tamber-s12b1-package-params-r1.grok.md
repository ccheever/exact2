# Review round 1, LLP 1121 stage 12 B1 (package components' params), Grok (grok 4.7, xhigh)

**RIGHT WITH CHANGES.** Identity (`<package>/<file>#Name` from the design's home, stable for `node_modules`, a link, and a vendored package), writes (the app's `params` block only), D7 retention (a set param is kept; an unset one keeps that default's chain and not a sibling token), `uses`, and refusal placement all hold. Release output is unchanged when no package design declares `component … params`. Changed sources are under the 1,500-line cap (`theme.rs` 1,454, `sources.rs` 1,424).

1. **SHOULD-FIX** — `describe`'s `short` treats two same-named components as unambiguous. `contract/cli/src/tamber_params.rs:263`. `short` looks only at `params::identities` (`contract/lower/src/params.rs:159`), which is Contract components. A package design component is not in that list. Two packages both declaring `Map`, or an app `Map` and a package `Map`, both come back as `short: "Map.pin"`, while `set-param` of that short name is `tamber-param-ambiguous` (`called` sees every param's identity). The two-package test checks the refusal and not `short`. Fix: decide `short` with `exact_tamber::params::called` on `folds(tokens, identities)`, the same rule as `resolve`, and return it only when that list has length 1.

2. **SHOULD-FIX** — A package param's default skips the package reference check. `contract/lower/src/theme/packages.rs:264`. `references` only looks at package-band lines. Param tokens are laid at `params::LINE` and above, so a default may name another package's token, an app token, or a dial (`pin: color = maps.pin` folds clean when `@acme/maps` is linked). A theme token in that file is `tamber-unknown-token`. Fix: in `package_references`, for each param whose identity file is a package design's `home`, apply the same own-token / role / base-name / no-dial rule to its folded names, and allow a `param.…` name of that same component. Report it at the default's span in the package file.
