# Design review: LLP 1108.001 r1, Grok

Reviewer: Grok 4.7 (xhigh, read-only), 2026-10-08, blind, on lane/media-slices-2-3 at 2f93b0ab4. Same brief as Astra's.

NOT READY

1. **BLOCKER** — §1.5 and §1.8 (wasm). `:exact-saved` does not survive the page fulfill path. `outcome_from` splits each header line on the first colon (`host/web/src/host.rs:79-85`). The line `:exact-saved: 42` becomes the name `""` and the value `exact-saved: 42`. `Response::saved` looks up the key `:exact-saved` (`runner/src/request.rs:529-533`) and finds nothing. A written response already has an empty body (`host/apple/src/executor_save.rs:108-112`), so the module sees a 2xx, `exactSaved == null`, and no bytes. Hermes is a different channel: pairs are JSON (`js/src/wire.rs:106-111`) and the prelude drops that name before `new Headers` (`js/src/prelude.js:557-565`). Carry the count in a fulfill field beside the header text. State that this line protocol cannot hold a colon in a name. On the JS target, do not put that name on the browser `Headers` object.

2. **BLOCKER** — §2.4 against §2.6. Revoke and the GC free the bytes once no `Blob` holds them. Apple `image` takes a no-copy pointer (`exact_blob_acquire` → `Data`) and `video` reads those bytes later on the loader queue. No pin covers an in-flight decode or an `AVAssetResourceLoaderDelegate`, so revoke is a use-after-free. "The view keeps its pixels" is true only if decode copied. `RasterInput.bytes` and `metadata` also read a file (`host/apple/Sources/ExactKit/RasterInput.swift:85-99`); a no-copy `Data` does not feed them. Make a host acquire a refcount that revoke and the finalizer leave alone until `exact_blob_release`. Copy at decode. Hold the video pin until the asset is released. Put that next to the free rule.

3. **MAJOR** — §1.3 does resolve Astra r4 #7 on the runtime: write only a `2xx` whose `when` headers match, before any body byte; any other body stays readable; the count comes back; the client publishes a unique staging file from the media queue after `asset_reply`, and deletes it when the exchange is stale. §1.6 then hands over only status, headers, and `exactSaved.bytes`. Parent D2's refusal arm is `{status, body}`. Say that a null `exactSaved` is read with `json()` and passed as that arm, and that the driver must not fall back to `arrayBuffer` plus `atomicWriteFile`. A `416` body is what tells `E_ASSET_RANGE` from a failed save.

4. **MAJOR** — §1.4's name `.<leaf>.<n>.exact-partial` is not what §1.8's `AppDirectories::stage` creates. The patch uses `.exact-<hex>.partial` from `getrandom` (`vendor/ibex/crates/ibex2/src/stdlib/app_fs_unix.rs:286-291`); `open_at` already adds `O_NOFOLLOW` (`app_fs_unix.rs:37`). §1.6's sweep `*.exact-partial` will not see those files. A fixed `<n>` with `O_EXCL` also sticks on a crash leftover. Use the patch's name and sweep `.exact-*.partial`.

5. **MAJOR** — §1.4's `content-length` check. The browser decodes `content-encoding` and still exposes the encoded `content-length`, so `blob.size` will not match and every gzipped 2xx save fails and drops the entry. Native ibex does not decode (`vendor/ibex/crates/ibex2/src/stdlib/fetch_body.rs`). The native writer already skips the check unless the coding is missing or `identity` (`executor_save.rs:135-139`); the spec does not. Compare only in that case, on both web carriers. `admission.js` `within` reads the decoded stream (`host/web-js/admission.js:43-53`).

6. **MAJOR** — §1.2's pre-send admission. Native refuses a missing parent before the request, because `stage` opens the parent (`host/apple/src/executor_core.rs:951-961`). On the web, `putBlob` throws `ENOENT` only inside the transaction (`host/web/storage-fs.js:109-112` and `:230-234`), after `http-body.js:229` has read the body. Check the grant and the parent before `fetch` on every executor. `ts-fetch.js:5` always enters `fetchWith`, which calls `within`; §1.8 needs an explicit branch that does not.

7. **MAJOR** — §2.4 and §2.2. "On the web, until the document ends" is the page. The wasm module realm is a hidden iframe removed on dispose (`host/web/module-glue.js:97-98` and `:368`) or a worker that is terminated (`module-glue.js:416`). Blob URLs die with that environment while the page is still up. Say the creating environment. A UUID minted in the Rust store must use the agent entropy draw (`js/src/prelude.js:194`, host op 11 at `module-glue.js:137`). `getrandom`, as `stage` uses, is not that stream, so a drive's tree will not repeat. Also state that a process-wide store (§2.3) is shared by two sessions of one app id: one bound, and each can resolve the other's URL.

8. **MAJOR** — §2.6 against the resolvers, and §2.3 against `wire.rs`. `NodeView.resolveSource` returns nil for every scheme except `http` and `https` (`host/apple/Sources/ExactKit/IOS/NodeViewIOS.swift:427-429`); `VideoModule` then sets `sourceError` and clears `src` (`VideoModule.swift:220-225`). `RasterInput.open` throws `unresolved` on the same schemes (`RasterInput.swift:55-56`) and the encoded cap is 64 MiB (`RasterImage.swift:55`). Linux `image_input` returns `None` for a non-relative name that is not `app:` or `data:` (`host/linux/src/image/assets.rs:101-102`). Branch on `blob:` before those rejections, and keep `encodedLimit`. A `Blob` request body cannot ride `request_from_json`, which only accepts `body` or `body_base64` (`js/src/wire.rs:41-44`). Resolve it on the same side channel as the response body, synchronously, before the host call returns.

9. **MINOR** — `js/src/prelude.js` is 1345 lines. The `Blob` surface in §2.3 crosses the 1500-line check if it is written into that file. Install it from another file. `host/web/glue.js` is 1499 lines; §2.6 is right to leave a browser `blob:` src alone (`glue.js:187-201` returns it unchanged).

Charlie's order, Q2, Q4, and a 64 MiB per-response cap match §0 and `MAX_BODY_FROM_BYTES`. The spec adds no check and no boot-path JS.
