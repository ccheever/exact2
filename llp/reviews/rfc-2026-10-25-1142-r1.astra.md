**Concerns**

1. **BLOCKING — D1 does not define a valid time breakdown.**

   [RFC:140](/Users/ccheever/projects/exact2-wt-review-1142/llp/1142-what-a-development-build-tells-an-agent.rfc.md:140) defines `other` as **overrun minus phase durations**. Overrun is lateness beyond a deadline; phase durations include work before that deadline. For example, 20 ms of measured work against a deadline 16.7 ms after its start produces a 3.3 ms overrun and an impossible `other = −16.7 ms`.

   The actual sampler retains the **maximum** qualifying turn overrun between samples, while batch timings accumulate. These are different quantities and potentially different intervals. Nested work also needs an accounting rule: the sampler explicitly permits nested applies. See [FrameSampler.swift:105](/Users/ccheever/projects/exact2-wt-review-1142/host/apple/Sources/ExactKit/FrameSampler.swift:105) and [FrameSampler.swift:180](/Users/ccheever/projects/exact2-wt-review-1142/host/apple/Sources/ExactKit/FrameSampler.swift:180).

   Two related accuracy problems:

   - **“0 transactions … rules the app out” is false.** The renderer derives that number from `seq`, not `batches`; `batch(nil, ms:)` still increments the batch count. It establishes no recorded transaction range, not absence of app work or app responsibility. See [agent-inspect.mjs:628](/Users/ccheever/projects/exact2-wt-review-1142/scripts/agent-inspect.mjs:628).
   - **`loaf.script` is not batch-apply time.** LLP 1079 distinguishes actual apply timing from summed script durations, and explicitly limits LoAF coverage to qualifying long frames. Renaming those values to common phases would imply comparability they do not have. See [1079:335](/Users/ccheever/projects/exact2-wt-review-1142/llp/1079-speed-hygiene-in-the-agents-hands.rfc.md:335).

   **Resolution:** specify the observation interval, attribution across interval boundaries, inclusive versus exclusive durations, and missing coverage. Either omit `other` initially or derive it from a measured enclosing interval using non-overlapping accounting. Unaccounted time must not be identified as AppKit work. Preserve each host’s measurement provenance.

   **Readiness / riskiest assumption / first probe:** not specified enough; the dangerous assumption is that these durations partition one frame. First exercise nested phases, a phase crossing a sample boundary, an on-time frame, and a late turn with no transaction range.

2. **MATERIAL — D2 confuses export identity with build identity.**

   [RFC:153](/Users/ccheever/projects/exact2-wt-review-1142/llp/1142-what-a-development-build-tells-an-agent.rfc.md:153) says the web exporter already supplies commit, dirty/clean state, and checkout path. The cited implementation supplies **current Git state at export time**, stores porcelain output in `working_tree`, and adds **no checkout path**. Copying this implementation would not justify “was built from `<commit>`.” See [serve.mjs:1128](/Users/ccheever/projects/exact2-wt-review-1142/host/web/serve.mjs:1128).

   A matching plan digest also establishes compatibility, not the original source revision: formatting changes can preserve the plan while changing source locations. The reader already documents this limitation at [agent-inspect.mjs:29](/Users/ccheever/projects/exact2-wt-review-1142/scripts/agent-inspect.mjs:29).

   **Resolution:** capture provenance at build time and distinguish native-host identity from the loaded plan’s identity. Specify `--plan` normalization for a plan, map, and directory, plus precedence over embedded/default maps. The flag already parses globally; the trace branch does not pass it to the reader—see [agent-launch.mjs:449](/Users/ccheever/projects/exact2-wt-review-1142/scripts/agent-launch.mjs:449) and [agent.mjs:1291](/Users/ccheever/projects/exact2-wt-review-1142/scripts/agent.mjs:1291).

   For genuine portability, retain the exact sidecar map with the trace, or let the **driver** embed it when packaging the trace. Neither requires a host to read a map.

   **Readiness / riskiest assumption / first probe:** the lookup extension is nearly buildable; provenance is not. The risky assumption is that commit plus dirty status can reconstruct the original map. First read a copied trace using only its preserved map, including a case where another compatible map has different source locations.

3. **BLOCKING — D3 lacks the execution contract needed to measure its example.**

   The current `perf frames` branch returns before processing `during`. Consequently, the proposed `perf frames live … during "tap … fling"` needs new orchestration, not just Apple support for `live`. See [agent-inspect.mjs:445](/Users/ccheever/projects/exact2-wt-review-1142/scripts/agent-inspect.mjs:445).

   Existing Mac behavior also changes the workload being measured:

   - The wheel path calls `settlePump()` before replying.
   - The normal post-scroll asynchronous pump is disabled in agent mode.
   - The sampler refuses activity while the session has a virtual clock.

   See [AgentMac.swift:710](/Users/ccheever/projects/exact2-wt-review-1142/host/apple/Sources/ExactKit/Mac/AgentMac.swift:710), [PresenterMac.swift:459](/Users/ccheever/projects/exact2-wt-review-1142/host/apple/Sources/ExactKit/Mac/PresenterMac.swift:459), and [FrameSampler.swift:114](/Users/ccheever/projects/exact2-wt-review-1142/host/apple/Sources/ExactKit/FrameSampler.swift:114).

   **Resolution:** define how the measurement window starts before input, how input executes while sampling remains active, and how completion/error restores clock mode. Specify monotonic clock advancement rather than restoring an obsolete timestamp; LLP 1079 already returns `live.from/to`. Define whether deltas mean total gesture displacement or something else, the momentum termination rule, and behavior when momentum outlasts the requested window. Held gestures need cleanup and reads that do not force settlement.

   **Readiness / riskiest assumption / first probe:** not specified enough. The main risk is measuring agent-induced scheduling rather than normal scrolling. First run the proposed combined command through the actual carrier, confirming native pumping and sampling continue during input, then verify a held band survives separate `layout` and `screenshot` operations.

4. **MATERIAL — D4 needs failure lifecycle and log-delivery semantics.**

   The proposed output shape is clear, but “count” is not: consecutive failures, lifetime failures, distinct messages, refused requests, and failed answers are different measures. The current state exposes only resources whose failure remains active. See [runner.rs:1266](/Users/ccheever/projects/exact2-wt-review-1142/runner/src/runner.rs:1266).

   The claimed journal failure marking also needs implementation. `Runner::log` currently stores a stamped string; it has no severity argument. Some failures arise in the runner, while host failures enter through the same string interface. See [runner.rs:1131](/Users/ccheever/projects/exact2-wt-review-1142/runner/src/runner.rs:1131).

   **Resolution:** specify counting/reset rules, timestamp units and clock, stale-ticket handling, and rollback behavior. Define how failure severity reaches host sinks without parsing prose, how duplicate delivery is prevented, and how D6 warnings reach logs even though D4 describes failures only. Update consumers of the existing string-valued `state.failed` together with the shape change. Name the implementation path for the web JS target as well as the runner.

   **Readiness / riskiest assumption / first probe:** partly specified. The main risk is incorrect counts or missed logs across settlement/rollback paths. First exercise failure → failure → success → failure, a stale reply, and a refused commit; check both state and emitted logs.

5. **MATERIAL — D5’s signal is specified; its file rendezvous is not.**

   `trace --pid` is supposed to signal an independently launched app and find its new trace. The existing writer uses the app’s temporary directory, a timestamp with second precision, and `trace-latest.json`; its identity contains no PID. The original stderr may be inaccessible to the requesting driver. See [FrameSampler.swift:284](/Users/ccheever/projects/exact2-wt-review-1142/host/apple/Sources/ExactKit/FrameSampler.swift:284).

   **Resolution:** define PID-to-output discovery, process/session identity, freshness, atomic completion, timeout/error handling, and multiple-session behavior. Require a way to establish that the target supports trace signals before signaling it: an unhandled `SIGUSR1` can terminate the process. Schedule export outside the raw signal handler.

   Also qualify §2’s statement that `trace` merely reads a file: `trace --pid` actively requests an export, although that does not itself add an Agent API wire operation.

   **Readiness / riskiest assumption / first probe:** not specified enough for reliable implementation. The risky assumption is that a PID identifies a discoverable fresh file. First export from an independently launched app with inaccessible stderr and an existing stale trace, then repeat rapidly and with two sessions.

6. **MATERIAL — D6 overstates what its heuristics establish.**

   [RFC:217](/Users/ccheever/projects/exact2-wt-review-1142/llp/1142-what-a-development-build-tells-an-agent.rfc.md:217) says 30 commits/s is half the display rate. That is true only at 60 Hz. The presenter explicitly accommodates other rates, including 120 Hz, at [PresenterMac.swift:483](/Users/ccheever/projects/exact2-wt-review-1142/host/apple/Sources/ExactKit/Mac/PresenterMac.swift:483).

   Reading the position variable is statically detectable; **rebuilding every following row is not thereby certain**. Position-only keys can preserve the same key set for existing positions while associating those positions with different records. Immutable or append-only lists present another different case. The warning at [RFC:223](/Users/ccheever/projects/exact2-wt-review-1142/llp/1142-what-a-development-build-tells-an-agent.rfc.md:223) should describe the identity risk conditionally.

   **Resolution:** define dispatches versus successful commits versus kernel transactions; distinguish multiple handlers on one node; specify aggregation across instances, window timing, virtual-clock behavior, and cooldown. Either measure scrolling explicitly or remove “while a scroller moved.” Emit numeric sites/digests from runtime diagnostics and symbolize in the driver; the `app.contract:<line>` example must not quietly require host map access.

   Defer the runtime “half the keys replaced” warning until its denominator, instance scope, cost, and false positives are established. Ordinary filtering or replacing a dataset can satisfy it legitimately.

   **Readiness / riskiest assumption / first probe:** the syntactic warning is close; runtime warnings are underspecified. The main risk is presenting legitimate work as a defect. First compare the motivating hover case against legitimate animation handlers, append-only/index-keyed lists, middle insertions, and intentional dataset replacement.

7. **MATERIAL — D7 needs broader test selection and collision handling.**

   Running macOS XCTests only when `host/apple` changes misses changes to the kernel, runner, compiler, and fixtures that those tests exercise. The existing `appleTouched` predicate deliberately covers non-documentation changes broadly. Reuse that coverage or justify a narrower dependency set. See [async.mjs:215](/Users/ccheever/projects/exact2-wt-review-1142/scripts/async.mjs:215).

   Add the macOS check name to `retainSkippedFailures` too; otherwise a later skipped run can discard the outstanding failure. See [async.mjs:257](/Users/ccheever/projects/exact2-wt-review-1142/scripts/async.mjs:257).

   A checkout hash into 1,000 ports reduces collisions; it cannot guarantee them away. Define explicit-port precedence and occupied-port behavior, and ensure fixture startup and baked origin use the same selection. The build-input premise is confirmed at [agent-launch.mjs:954](/Users/ccheever/projects/exact2-wt-review-1142/scripts/agent-launch.mjs:954).

   **Readiness / riskiest assumption / first probe:** the exit-status check is sufficiently concrete; tests and ports need these additions. First measure the macOS suite, check failure retention across a skipped run, and force a port collision. The six failing classes and build exit behavior remain unverified observations in this audit.

8. **MATERIAL — “Development builds only” does not match the cited existing gate.**

   [RFC:112](/Users/ccheever/projects/exact2-wt-review-1142/llp/1142-what-a-development-build-tells-an-agent.rfc.md:112) says the sampler and trace are absent from release builds today. They are not: `measured` excludes **production bakes**, while non-production release builds begin measurement on an agent request or trace. `saveTrace()` explicitly handles that case. See [FrameSampler.swift:22](/Users/ccheever/projects/exact2-wt-review-1142/host/apple/Sources/ExactKit/FrameSampler.swift:22) and [FrameSampler.swift:259](/Users/ccheever/projects/exact2-wt-review-1142/host/apple/Sources/ExactKit/FrameSampler.swift:259).

   **Resolution:** choose and name the exact admission predicate for the new diagnostics. If literal release-build exclusion is intended, reusing `FrameSampler.measured` is insufficient. Cover counters, timers, logging, compiler warnings, signals, and export—not just UI visibility.

   Fixed phase totals fit the existing `perf` allowance. Stack sampling, a new badge, and hosts reading maps should remain outside implementation pending explicit rulings. Apparatus additions also require the human approval specified by [RULES.md:63](/Users/ccheever/projects/exact2-wt-review-1142/rules/RULES.md:63).
