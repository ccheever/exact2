## Security pass

`canvasFrame` (`apps/design-tool/pairing.ts:35-37`) parses the reply and `wire.remote()` with the same URL parser, then requires both schemes to be `https:`, equal hostnames, a different port, no userinfo, no query, no hash, a pathname of exactly `/canvas/${encodeURIComponent(client)}/`, and a grant matching `/^[A-Za-z0-9_-]{43}$/`. The string it returns is `u.origin` plus that path plus `#g=` plus the grant. `remote()` (`apps/design-tool/wire.ts:160`) is the paired door origin, or `""` while local. `doorOf` (`wire.ts:51-58`) only produces an https origin or `http` to loopback.

A paired server answering `http://127.0.0.1:5173/canvas/remote%3AAda%231/` against door `https://192.168.1.20:7743` fails the scheme check and the host check. `https://evil.example:7745/...` fails the host check. `https://192.168.1.20:7743/...` fails the port check. A tunnel door `http://127.0.0.1:7744` fails because the door is not https, so `https://127.0.0.1:8443/canvas/...` is not framed. The unit test locks those cases (`scripts/design-tool-scope.test.mjs:125-140`).

`loadHello` (`apps/design-tool/app.ts:620-625`) sets `local` only when `remote() === ''` and the reply's `local` is not false. Paired, `page` and `frame` are `""` whatever hello says, so `pageOf` never runs and the local iframe (`app.contract:1413-1414`) is not taken. B's door refuses a pair whose `Origin` is not that door (`scripts/tamber-remote.mjs:187-199`), and the tool's pair request is a browser POST, so the tool page is the door's origin. The port check against the door is the check against the tool. An https door on loopback may still frame another port on that same host (`pairing.ts:35`, accepted at `design-tool-scope.test.mjs:140`); that is the TLS-door case from round 2.

The iframe is mounted only when `canvasAt.frame != ""` and `not pending(canvasAt)` (`app.contract:1405-1406`). A tick change keeps the previous answer while the new mint is in flight and unmounts the iframe for that interval, so the spent grant is not shown. Try Again and Reload Canvas both call `reloadCanvas` (`app.contract:847-848`).

## Findings

1. **SHOULD-FIX — The 10 s settle navigates the frame, so the entry document does not keep running.** `settleCanvasNow` (`apps/design-tool/app.contract:845-846`) stores the current frame and `canvasSrc` becomes `canvasAt.root` (`app.contract:684`), the gateway origin plus `/`. The host writes that by `setAttribute` whenever it differs (`host/web-js/rt.js:708`). Processing the iframe `src` attribute always navigates the child; the ancestor-URL bail-out does not apply, because the tool document is the door, not the canvas root.

   Concrete case. The door is `https://192.168.1.20:7743` and the frame is `https://192.168.1.20:7745/canvas/remote%3AAda%231/#g=<43-char grant>`. Entry POSTs the grant and the gateway answers 303 to `/` with `Set-Cookie: __Host-exact-canvas` (`scripts/tamber-canvas.mjs:382`). The child is then `https://192.168.1.20:7745/`, the app, with that cookie. At 10 s the attribute still holds the entry URL, so the new `src` of `https://192.168.1.20:7745/` is a navigation to the URL the document already has, which reloads it. The dev-loop streams and in-page state stop. The cookie is sent again (same host; a port is not part of the site, and `SameSite=Strict` still matches), so the gateway session id is still there and the app boots over. The page does not go on.

   If entry has not finished at 10 s, the child is still on `/canvas/<client>/#g=...`. That navigation destroys the document and cancels the POST. `GET /` has no cookie, and the gateway answers 404 (`tamber-canvas.mjs:411-413`). The frame never gets a session. Reload Canvas can mint again. Keep the entry document up: leave `src` on the entry URL once the child has moved itself to `/`, and drop the grant from state without a second parent navigation.

2. **SHOULD-FIX — After the settle the grant is still in state, and the settle copies it.** `canvasAt.frame` remains `origin/canvas/<client>/#g=<grant>` for as long as that answer is current (`pairing.ts:37`). `settleCanvasNow` assigns that whole string to `canvasSettled` (`app.contract:846`). The agent `state` reply returns both `resources` and `slots` (`host/web-js/agent.js:464`). The tree reads `iframe.getAttribute('src')` (`agent.js:79`), which is the root after the settle, so the tree drops the grant. A `state` read does not: `resources.canvasAt.frame` and `slots.canvasSettled` still contain `#g=`. The grant is live for 30 s (`GRANT_MS`, `tamber-canvas.mjs:58`). A read at 11 s, before entry has redeemed it, is an unspent bearer. After a later failed mint, `canvasAt.frame` becomes `""` and `canvasSettled` keeps the previous URL until the next successful settle. Remember which frame settled by the tick, and keep the grant out of both the slot and the retained resource answer.

3. **SHOULD-FIX — The contract tests do not cover a framed canvas, Reload, Try Again, or the settle.** `scripts/design-tool-scope.test.mjs:122-141` locks the pure function: another host, the door's own origin, the tunnel, a TLS door on loopback, and a grant that is not 43 base64url characters. The only contract assertion is the tunnel's error text and a missing frame (`apps/design-tool/app.test.contract:1795-1797`). `POST /__stub/canvas` exists so a test can name an origin (`apps/design-tool/stub/tamber-stub.ts:343-344`) and nothing calls it. Nothing taps `canvas-reload` or `canvas-retry`, nothing asserts the iframe stays unmounted while `pending(canvasAt)`, and nothing does `clock +10000` and checks that the frame `src` is the root. A paired hello with `local: true` and `page: "http://127.0.0.1:5173"` is also untested.

## What holds

`canvasTick` is only a cache key. `loadCanvas` returns before the call when `local` is set or `client`, `epoch`, or the door is empty (`pairing.ts:50`). Hello's epoch is one id per server run, and a steady poll does not change `hello.local`, `hello.client`, or `hello.epoch`, so it does not mint. The first Continue happens on the name screen, before pairing, so that tick does not mint. Continue while renaming increments the tick, unmounts the iframe with the name screen, and the new iframe waits until `not pending(canvasAt)`. Try Again is shown when `canvasAt.error != ""` and the frame is empty (`app.contract:1410-1412`); Reload Canvas is shown whenever a frame is up (`app.contract:1402-1404`). Both are disabled while the mint is pending. A returned error record has `frame: ""`, so the retry does not replay a grant. The task key is the frame URL (`app.contract:818`), and a new key restarts the 10 s timer, so a reload does not settle the new grant early.
