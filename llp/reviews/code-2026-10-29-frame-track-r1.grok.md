- **Method:** one brief (sha256 `4811315a0eefd110ffdb86b7d1664b6f7078ca90342432c3ed88d25676e0619c`), shared by both reviewers, blind to the other review. The author (Claude, x2-perf4's workers) is not a reviewer.
- **Transcription:** the final message, unedited.

The scroll track matches the plan on scheduling primitives, the capture gate, the ring, and the page size. Two measurement paths still drop or disturb the frames this exists to record.

`VERDICT: CHANGES`

1. **BLOCKER** — `host/apple/Sources/ExactKit/Agent.swift:160`. A `perf frames track` request is not a bounded frame read, so `Agent.handle` calls `ExactSession.drainAll()` before the track branch. `drainFill` waits on the owner on the main thread and then `landFill` can apply the queued batch. Health, report, and capture skip that wait. A track read during a glide can stall the main thread (the display link does not tick) and apply collection work into the motion being measured. The instance-level tests call `agent.handle(op:)` and never hit this path. Add `track` to the `boundedFrameRead` predicate the same way `capture` is included.

2. **MAJOR** — `host/apple/Sources/ExactKit/FrameHealthTrack.swift:45`. With no cursor, `asked` is set to the oldest retained row, so `dropped` is 0 after the ring wraps. `perf frames track read` (`scripts/agent-inspect.mjs:467`) sends no cursor, and the contract (`docs/contract-for-agents.md:3213`) says `dropped` is how a read past 4096 unread rows reports the overwrite. A 5,000-row track read from the driver returns the retained 4,096 rows and `dropped: 0`. Passing cursor `"0"` does report 904, and `FrameHealthTrackTests.swift:59` locks in the cursorless 0. Treat a missing cursor as position 0 (start at the oldest retained row, `dropped` = rows overwritten before it).

3. **MAJOR** — `scripts/agent-inspect.mjs:513`. `perf frames track stop` drains with `readTrack`, then calls `stop` and ignores that reply. `stop` is what returns the tail and releases the ring, so rows that arrive after the last `read` are freed and never joined. `readTrack` (`scripts/agent-inspect.mjs:468`) has the same hole if a later page comes back `track: false` (lease ended between pages): it returns the previous page, which can still say `more: true`, and `stop` then drops whatever remains. `scripts/agent-inspect.test.mjs:272` expects the `stop` body to be discarded. Merge the `stop` page's rows, `dropped`, and `more` into the result, and surface `no-track` instead of a partial page that still says `more`.

4. **MINOR** — `host/apple/Sources/ExactKit/FrameHealthTrack.swift:134`. The Mac phase is taken from `NSApp.currentEvent` inside the clip bounds callback. Any non-empty `phase` becomes `t` and any non-empty `momentumPhase` becomes `d`, including `.ended`, and a later bounds change still sees the last wheel event, so a layout move can be tagged `t` or `d`. The offset is always `contentView.bounds.origin.y` (line 138). The contract (`docs/contract-for-agents.md:3219`) says the scrolling axis, y unless the scroller moves only sideways, so a sideways Mac scroller records a still y. Capture the phase on the wheel event the handler is already in, and record x when the scroller moves only sideways.

5. **MINOR** — `host/apple/tests/ExactKitTests/FrameHealthTrackTests.swift:189`. The iOS test animates `setContentOffset` and accepts at least 5 rows. It does not drive a platform drag, so it never checks phase `t` then `d`, at-rest silence, or at least 30 rows on a 0.5 s glide. The Mac wheel test (line 241) allows any of `t`, `d`, `b`, and `-`, so a plain wheel that should be `-` still passes. Lease expiry is checked on read, not on the next feed. `FrameHealth.reset()` (line 127) drops the track on reload and clock change; nothing asserts that.

6. **NIT** — `host/apple/Sources/ExactKit/FrameHealth.swift:156`. `destroy()` does not clear `track`. The 64 KB ring stays until the session object deallocates, and `trackScrolled` does not consult `enabled`, so a scroll during `presenter.reset()` after teardown can still append. `reset()` already assigns `track = nil`; `destroy()` should do the same.

What holds: the new file adds no display link, timer, observer, or KVO. iOS feeds are the three existing `scrollViewDidScroll` sites; the Mac feed is the existing `NodeView.clipScrolled` bounds handler. The lease gate is the capture gate: `enabled && !virtual` (`FrameHealthTrack.swift:92` and `FrameHealthCapture.swift:26`), with `enabled` from `FrameHealth.configured` (core mode, or on unless this is a production bake). The ring is 4,096 × 16-byte rows, allocated only in `start`, replaced on a second start, and freed on stop, replace, clock change, and the next feed or read after `until`. A bad start returns before assignment. The scroller is a weak reference; `tracks` uses identity. Callers are main-thread (`scrollViewDidScroll`, the bounds notification, and the agent handler via `CFRunLoopPerformBlock` on main). Paging follows the row cursor with no skip or repeat while the cursor stays inside the retained window. `missed` is `max(0, round(interval / period) − 1)`, a gap of at least 0.5 s forces interval and `missed` to 0, and both are documented and tested. A worst-case page (20-digit cursor, `more: false`, `stopped`, full-width negative fields) stays at or under 3,991 bytes plus the newline, inside the 4,000-byte cap. The format id is `exact.frame-health.track/1`. #1141's test files are untouched. I did not run the suites.
