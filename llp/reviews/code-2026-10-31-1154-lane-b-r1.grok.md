## MATERIAL findings

1. `js/bake/src/lib.rs:68` always calls `library::link`, and `js/bake/src/library.rs:29-34` treats every Rust target absent from `native.library` as LLP 1154 D6. D2's map has no wasm entry; the web device is `web.assets`. `host/web/build.mjs:194` builds that crate for `wasm32-unknown-unknown` on `--bake`, `--wasm`, and a game. `scripts/deploy.mjs:1331` calls `bake()` (`scripts/deploy.mjs:648`) for every app that is not web-only, so delivery of an app that depends on the package dies in the web bake before any native target. The ordinary `web-build` exits at `host/web/build.mjs:145` and never reaches Cargo, so the web integration case can pass without compiling this crate. In `link`, return success and print no link lines when `TARGET` is `wasm32-unknown-unknown`. Keep the named refusal for a native target the declaration does not list, including Android.

2. The fetch runs only from `scripts/build-linux.mjs:23` and `host/apple/build.mjs:703`. `scripts/app.mjs:1251` `buildBake` does not call it, and `scripts/app.mjs:225` `lockedMetadata` only runs `cargo fetch --locked`. `scripts/deploy.mjs:676-690` `buildFor` is that cargo path. The deploy snapshot does not carry `~/.cache/exact/package-libraries/`. After finding 1, a native `buildFor` still hits `js/bake/src/library.rs:62-66` ("not fetched") for `aarch64-apple-ios` and for the Linux and macOS triples. The build fails closed and publishes no binary that carries the library. Call the same `prepareLibrary` fetch before Cargo inside `buildBake`, for an Apple or Linux target this seam links.

3. `scripts/package-libraries.mjs:126` copies a Linux library to `lib<link>.so` and never reads its SONAME. The comment at line 11 says the SONAME is that name "if it has one". With no `DT_SONAME`, GNU ld records the cache path it opened as `DT_NEEDED`. `$ORIGIN` does not apply to that dependency, the copy beside the binary is not what the loader opens, and the shipped binary contains a build-machine path. `appleView` already refuses a wrong install name (`scripts/package-libraries.mjs:150-152`). Refuse a `.so` whose SONAME is not `lib<link>.so`. The link test passes `-soname,libvault.so` itself, and on this Mac `bakeTarget('linux')` is the host triple, so that test never executes the ELF branch.

4. `scripts/package-libraries.mjs:147-152` follows symlinks. `existsSync` on `<link>.framework/<link>` succeeds when that name points outside the framework, and `relative(realpath(framework), realpath(binary))` then contains `..`. An install name that matches that string passes. `cpSync` at line 147 and `placeLibrary` at line 170 use `verbatimSymlinks`, so the bundle's `Frameworks` entry is that symlink. Require the resolved binary to stay inside the framework and the relative path to contain no `..` segment. `Versions/A/<link>` still passes.

5. `host/apple/build.mjs:1018` builds a widget's ExactCore through `sharedWidgetCore`. `host/apple/Package.swift:60` force-loads the app staticlib into that dylib, and `host/apple/widgets.mjs:178-181` runs that `swift build` with no `appleLinkArgs`. The product link (`host/apple/build.mjs:1228`) and the early link (line 851) pass them. Once the archive references the package's C symbols, the ExactCore link fails undefined, and the extension never gets the framework on its link or its run path. The reuse stamp at `host/apple/widgets.mjs:173` hashes the archive and the plan only, so a library change with the same object bytes does not relink it. Pass `appleLinkArgs(library, ios)` on that ExactCore link, with the same rpath policy as the product, and include the library's `sha256` in the stamp. The macOS and simulator tests have no widgets and only patch `linux/lib.rs`, so they do not reach this link.

## Minor findings

1. `scripts/package-libraries.mjs:89` allows `http:`, and `fetch` at line 109 follows redirects. The hash is still required. Allow `file:` and `https:` only.

2. `scripts/package-libraries.mjs:90` treats a triple that contains `-linux-` and does not end in `-android` as Linux. `js/bake/src/library.rs:36` refuses only `ends_with("-android")`. `armv7-linux-androideabi` would be linked as a `.so` with `$ORIGIN`. `aarch64-linux-android` is refused. Treat any triple containing `-android` as the named Android refusal.

3. `js/bake/src/library.rs:68-69` interpolates `native.link` into `cargo:` lines. The charset check is only in `scripts/package-libraries.mjs:83`, which `buildBake` does not run. A newline in the name injects a cargo directive once that target's cache file exists. Apply the same charset check in `link` before printing.

4. A present `exact.json` that does not parse is skipped: `js/bake/src/typescript.mjs:518` and `:626`, the `read` helper in `scripts/package-libraries.mjs:26`, and `js/bake/src/library.rs:77-78`. The package then builds with no library and no assets. Refuse a present, unreadable `exact.json` by name in all four readers.

5. The cache view is `<sha256>/<target>` (`scripts/package-libraries.mjs:120`). Changing `native.link` for the same bytes finds the old directory, `rename` throws `EEXIST`, and the build stops. Key the view by the link name, or replace a view whose placed name differs.

6. `scripts/package-libraries.mjs:102` refetches a cached file whose digest mismatches, and a bad refetch throws at line 114 before `rename`, leaving the bad file in place. The unit test seeds that file and does not require its removal. The next call will not adopt it. Remove the cache file when the new bytes do not match.

7. `js/bake/src/library.rs:7-8` says an Apple archive links nothing, while `link` still prints `rustc-link-lib` and an rpath for every Apple target (lines 56-71). `scripts/package-libraries.mjs:11` states the Linux SONAME as optional. Rewrite both sentences to match the checks in findings 3 and the Apple link.

## Declaration

The package root is the right file for this lane. D2's `exact.json` sits beside the TypeScript driver, and `exports["."]` is that driver. `contract/cli/src/package_views.rs:177-190` returns `None` unless `exports["."]` ends in `exact.json`, which is the right answer for a 1133 module. `nativePackages`, `library.rs` `declaring`, and `capturedSources` all read `<package root>/exact.json`, so they see `native.library` and `web.assets`. A reader that only follows `exports["."]` sees neither. When the lanes merge, `native.rust` and `native.class` have to be read from that same root file.

## Checked, not findings

The cached file is hashed on every read (`scripts/package-libraries.mjs:102`). New bytes are written to a temp name and renamed only after the hash matches (lines 113-118). An app with no `native.library` gets no link and no embed (`library.rs:23-24`, `appleLinkArgs` empty). Two direct `native` packages throw `bake-native-twice`. The early reuse check and the product `.linked` record both include the library sha (`host/apple/build.mjs:846`, `:1241`). Product rpaths are `@executable_path/Frameworks`, `@executable_path/../Frameworks`, or `$ORIGIN`. On Mac the framework is signed at `host/apple/bundle.mjs:114` before the bundle at line 132. On iOS it is placed at line 166 and signed with the other Frameworks at line 248, before the bundle at line 251. `assertArchiveFrameworks` (`host/apple/assets.mjs:631-632`) rejects a loose `.dylib` and accepts a `.framework`. When Cargo reports the link search, `scripts/app.mjs:1053` and `:1103` hash the cache directory under a name that contains the sha256, so a changed library changes `binary.sha256`. `web.assets` capture refuses an absolute path, a symlink (`real !== from`), and a path outside the package (`js/bake/src/typescript.mjs:524-525`). The digest covers those bytes. The served path is `/assets/<package>/<path>`, and `.wasm` is `application/wasm`. The JS dev loop rebuilds through `host/web-js/build.mjs`, which copies `capturedAssets`.
