**Blocking**

1. **R4 misses properties written by the image adapter.** [lower.rs:88](host/web-js/src/lower.rs:88) permits `background-color`, `object-position`, and several mask properties that [symbols.js:151](host/web-js/symbols.js:151) writes inline. A tinted image with a bound source and enum-selected background can therefore lower. Changing its arm lets the inline build’s `S` overwrite the adapter’s background; `Pc`’s class remains underneath that inline declaration. Refuse conflicting bindings on these images, and compare both builds after changing the style independently of the source.

2. **`revert-layer` changes meaning when moved into the stylesheet.** [lower.rs:303](host/web-js/src/lower.rs:303) admits this string, and [lower.js:16](host/web-js/lower.js:16) places it in an unlayered author rule. Inline `revert-layer` rolls back the inline declaration; the new rule rolls back unlayered author rules too. For example, an `h1` with enum-selected `margin-top: revert-layer` loses the shell’s heading-margin reset in the lowered build. Refuse this value unless its cascade semantics are preserved; add an equality case against the shell reset.

3. **Numeric literals do not preserve the inline compiler’s number semantics.** [lower.rs:450](host/web-js/src/lower.rs:450) emits Rust’s `inf`, whereas [code.rs:770](host/web-js/src/code.rs:770) emits `Infinity`. Nonfinite arm values are not refused, so an accepted plan can generate an unresolved `inf` identifier and fail at startup. Separately, [lower.rs:547](host/web-js/src/lower.rs:547) compares numeric literals by their stored bits: a plan comparing the same key against both `0` and `-0` gets different precomputed answers, although the emitted `===` selector treats them equally. Reuse the existing number serializer and JavaScript numeric equality, or explicitly refuse these cases.

4. **The staleness test does not exercise reuse of the saved sheet.** [lower-equal.test.mjs:226](host/web-js/lower-equal.test.mjs:226) installs it on `DOMContentLoaded`. This fixture’s module starts the app synchronously before that event, so `Pc` has already created a fresh sheet and cache. The callback then appends another `#exact-arms`. Install the old sheet before application execution, assert that exactly one sheet exists, and verify that the new runtime actually uses its existing `$built`.

5. **The required feed comparison can pass without running, and does not establish every-arm coverage.** [lower-equal.test.mjs:235](host/web-js/lower-equal.test.mjs:235) returns successfully when the ignored dataset is absent—as it is in this checkout. Even when present, [line 251](host/web-js/lower-equal.test.mjs:251) accepts any positive rule count up to seven. Make the dataset a mandatory prerequisite or generate it during setup, and assert that all seven arms were observed and compared.
