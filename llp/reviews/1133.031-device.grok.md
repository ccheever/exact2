## MATERIAL

**1. Linux `connection().type` classifies Wi-Fi as ethernet.** D2, line 187.

`/sys/class/net/<if>/type` is `ARPHRD_*`. Wi-Fi is `ARPHRD_ETHER` (1), the same value the row treats as ethernet (`include/uapi/linux/if_arp.h`). The `wireless` directory is the WEXT compatibility node (`CONFIG_CFG80211_WEXT`), so a mac80211 interface without it takes the ethernet arm. The durable wifi marker is the `phy80211` symlink. A default route through `tun` or WireGuard is the tunnel, while Android’s row (line 186) unwraps VPN-plus-wifi to wifi.

Decision: classify wifi by `phy80211` (or an equivalent that is not “type 1 means ethernet”), and state the VPN rule so tier 1 `type` means the same thing on Android and Linux.

**2. Linux `charging` is true while the battery is discharging.** D1, lines 138–140 and 149.

The same decision says `charging` is false when the battery is discharging. The Linux cell ORs “a Mains supply is `online`” over `status`, so `Discharging` plus any online mains node is `charging` true. `Not charging` (plugged, at a charge limit) is why the OR is there; it does not need to override `Discharging`. The cell also never names the supply. `/sys/class/power_supply/` includes hid batteries. The roster’s platform for this cell is UPower (`llp/1133.000-the-roster.rfc.md` line 159), whose `DisplayDevice` is the aggregate.

Decision: `charging` is false only when the chosen supply’s `status` is `Discharging` (`Not charging`, `Full`, `Charging`, and `Unknown` stay true). Use mains-online only when there is no system battery, which D1 already emulates. Name that supply.

**3. Linux `lowPowerMode` falls back to a firmware performance profile.** D3, line 243.

`power-saver-enabled` on the Power Profile Monitor portal is the desktop Power Saver flag. `/sys/firmware/acpi/platform_profile` is the kernel’s firmware profile (`low-power`, `cool`, `quiet`, `balanced`, `balanced-performance`, `performance`; kernel `sysfs-platform_profile`). A firmware `low-power` profile is not the person turning on Power Saver, and Power Saver often sets `quiet` or `cool`, or never touches that file. Headless has neither the portal nor, usually, the file. LLP 1133 D8 says to use the platform capability API where one exists. The roster names UPower, whose `ActiveProfile == power-saver` is the same fact when the portal is absent.

Decision: do not equate `platform_profile` with Low Power Mode. Portal `power-saver-enabled`, else the power-profiles `ActiveProfile`, else false (the same honest default Linux `saveData` already uses).

Metered cost is already tier 2 (`networkCostType`, `overDataLimit`). Question 3’s proposed yes is this mapping.

Decision: Windows `saveData` stays false until there is a user save-data setting. Do not publish `BackgroundDataUsageRestricted` as the same fact. (Not re-fetched this session; the property is documented at the URL on line 201.)

**2. UPower `Empty` and `PendingDischarge` are `charging` true.** IN-DELTA, MATERIAL. D1, line 151.

`State` is not the sysfs string. UPower's `Device.State` is Unknown, Charging, Discharging, Empty, FullyCharged, PendingCharge, PendingDischarge (UPower `Device` documentation; I could not re-fetch it). Decision: UPower `charging` is true for Charging, FullyCharged, PendingCharge, and Unknown, and false for Discharging, Empty, and PendingDischarge.
