## MATERIAL

**1. Linux `connection().type` classifies Wi-Fi as ethernet.** D2, line 187.

`/sys/class/net/<if>/type` is `ARPHRD_*`. Wi-Fi is `ARPHRD_ETHER` (1), the same value the row treats as ethernet (`include/uapi/linux/if_arp.h`). The `wireless` directory is the WEXT compatibility node (`CONFIG_CFG80211_WEXT`), so a mac80211 interface without it takes the ethernet arm. The durable wifi marker is the `phy80211` symlink. A default route through `tun` or WireGuard is the tunnel, while Android’s row (line 186) unwraps VPN-plus-wifi to wifi.

Decision: classify wifi by `phy80211` (or an equivalent that is not “type 1 means ethernet”), and state the VPN rule so tier 1 `type` means the same thing on Android and Linux.

**2. Linux `charging` is true while the battery is discharging.** D1, lines 138–140 and 149.

The same decision says `charging` is false when the battery is discharging. The Linux cell ORs “a Mains supply is `online`” over `status`, so `Discharging` plus any online mains node is `charging` true. `Not charging` (plugged, at a charge limit) is why the OR is there; it does not need to override `Discharging`. The cell also never names the supply. `/sys/class/power_supply/` includes hid batteries. The roster’s platform for this cell is UPower (`llp/1133.000-the-roster.rfc.md` line 159), whose `DisplayDevice` is the aggregate.

Decision: `charging` is false only when the chosen supply’s `status` is `Discharging` (`Not charging`, `Full`, `Charging`, and `Unknown` stay true). Use mains-online only when there is no system battery, which D1 already emulates. Name that supply.

**3. Linux `lowPowerMode` falls back to a firmware performance profile.** D3, line 243.

`power-saver-enabled` on the Power Profile Monitor portal is the desktop Power Saver flag. `/sys/firmware/acpi/platform_profile` is the kernel’s firmware profile (`low-power`, `cool`, `quiet`, `balanced`, `balanced-performance`, `performance`; kernel `sysfs-platform_profile`). A firmware `low-power` profile is not the person turning on Power Saver, and Power Saver often sets `quiet` or `cool`, or never touches that file. Headless has neither the portal nor, usually, the file. LLP 1133 D8 says to use the platform capability API where one exists. The roster names UPower, whose `ActiveProfile == power-saver` is the same fact when the portal is absent.

Decision: do not equate `platform_profile` with Low Power Mode. Portal `power-saver-enabled`, else the power-profiles `ActiveProfile`, else false (the same honest default Linux `saveData` already uses).

**4. Windows `saveData` is a background-transfer restriction.** D2, line 201, and question 3 (lines 815–818).

`ConnectionCost.BackgroundDataUsageRestricted` is true when background transfers are limited: roaming, over the data cap, or a metered policy. It is not a person asking every app to use less data in the foreground. Apple `isConstrained` and Android Data Saver (lines 198–205, including the allowlisted case) are that request, and Weatherlight slows a foreground forecast refresh on `saveData` (lines 634–645). Metered cost is already tier 2 (`networkCostType`, `overDataLimit`). Question 3’s proposed yes is this mapping.

Decision: Windows `saveData` stays false until there is a user save-data setting. Do not publish `BackgroundDataUsageRestricted` as the same fact. (Not re-fetched this session; the property is documented at the URL on line 201.)

**5. One process-wide observer is stopped by one session.** D5, lines 297–302.

Item 1 stops the observer on `release` of the last reader or on `destroy`. Item 2 shares that observer across every session. `destroy` is per session (`host/apple/modules/ExactPackage.swift` lines 214–216); process objects already key consumers by `session` (lines 75–76). The sample host runs two sessions. Ending one session, or releasing its last reader, stops the observer the other session still reads.

Decision: refcount readers across sessions. `destroy` drops only that session. Stop the observer when the process-wide count is zero.

**6. `thermalHeadroom` cannot be loaded, and the API-level premise is false.** D9 line 392, D11 lines 488–489, D14 line 527, D16 line 568.

`contract/cli/src/declaration.rs` lines 82–86 refuse an implementation `exact.json` whose `names` is non-empty (“an implementation's own sources and sends are not read yet”). The interface import pulls implementation shapes (lines 45–59), not those names. D12 adds the manifest element and explicitly adds nothing else (lines 100, 502–505). No consumer reads the source (question 5). `android.thermalStatus` is a result field and does load.

Line 527 says thermal status needs no guard because “the host's minSdk is 31”. `host/android/app/build.gradle.kts` lines 25–40 set `minSdk` from `host.android.minimumOS`, default `"12"` → 31, with `"10"` → 29 and `"11"` → 30, and `host/android/README.md` lines 19 and 1094 treat Android 10 and 11 as supported. `getThermalHeadroom` is API 30. An unguarded call crashes an Android 10 app. `NET_CAPABILITY_TEMPORARILY_NOT_METERED` (line 388) is API 30 as well. `getCurrentThermalStatus` at API 29 is fine on that floor.

Decision: drop the source until implementation `names` load, or add that loader change as a named seam. Do not claim the host minSdk is 31. Any API 30 call branches on `SDK_INT`.

**7. The battery example and Expose’s failure UI cannot both be built.** Summary lines 22 and 69; §10 lines 686–688; drive 9, lines 702–703.

`else empty(charging=true, level=1)` is the value a failed resource keeps (`docs/contract-for-agents.md` line 1141). That draws a bolt and “100%”. Drive 9 and lines 686–688 require, on Linux before stage 4, a full mark, no bolt, and a blank row. Line 69 already says `failed(battery)` is the feature test. A successful no-battery answer (Mac mini, Apple TV, simulator) is the emulated full charging battery; a failed read is not that answer. Drive 6’s bolt and “100%” are the agent default on a supported target (`getBattery` is unsupported only on linux and windows, lines 471–472), so they do not cover drive 9.

Decision: Expose draws the bolt and the percentage only when `failed(battery)` is false. The summary example has to show that branch.
