1. **SHOULD-FIX — The grant survives fragment stripping in inspectable parent state.** [pairing.ts:39](/tmp/rv-dt-t6s3/apps/design-tool/pairing.ts:39) returns the complete grant URL into [canvasAt](/tmp/rv-dt-t6s3/apps/design-tool/app.contract:672). It remains there until the arguments change or the tool unloads, and remains in the iframe’s `src`. C2’s `history.replaceState` only changes the child’s location. Agent [state](/tmp/rv-dt-t6s3/host/web-js/agent.js:464) and [tree](/tmp/rv-dt-t6s3/host/web-js/agent.js:79) expose these copies. If entry stalls, a diagnostic collected within 30 seconds can contain an unspent grant. Clear or redact the grant after handoff and include grants in the credential-leak checks.

2. **NIT — The tool does not enforce the separate-origin invariant.** [pairing.ts:38](/tmp/rv-dt-t6s3/apps/design-tool/pairing.ts:38) accepts any `doorOf` origin and matching pathname, including the tool’s own origin. With [this sandbox](/tmp/rv-dt-t6s3/apps/design-tool/app.contract:1383), an active same-origin page could access the parent and remove the sandbox. C1’s intended two-port configuration prevents that today; reject a reply naming the tool’s origin to preserve the boundary locally, as `pageOf` already does. Also reject existing query/fragment components and require the expected encoded client path.

3. **SHOULD-FIX — Recreating the frame replays a spent grant.** [canvasAt](/tmp/rv-dt-t6s3/apps/design-tool/app.contract:672) is keyed only by local/client/epoch. After successful entry, click the displayed name and Continue: [the name screen](/tmp/rv-dt-t6s3/apps/design-tool/app.contract:1277) removes and recreates the iframe without changing those arguments. It reloads the original grant URL, whose POST is refused because [the gateway already burned it](/tmp/rv-dt-t6s3/scripts/tamber-canvas.mjs:370). Retain a clean session URL after entry or obtain a fresh grant when a new entry is necessary.

4. **SHOULD-FIX — A transient mint failure leaves the canvas unavailable indefinitely.** [pairing.ts:36](/tmp/rv-dt-t6s3/apps/design-tool/pairing.ts:36) returns an ordinary settled error result. A timeout or 429 therefore remains cached while client/epoch stay unchanged. There is no canvas retry action; [the fallback only displays text](/tmp/rv-dt-t6s3/apps/design-tool/app.contract:1385). Add an explicit retry or bounded retry behavior that respects the mint limit.

5. **SHOULD-FIX — The new test proves iframe presence, not entry.** [The stub](/tmp/rv-dt-t6s3/apps/design-tool/stub/tamber-stub.ts:191) returns a UUID grant and has no gateway page; [the assertion](/tmp/rv-dt-t6s3/apps/design-tool/app.test.contract:1796) passes even when the frame loads a 404. Before C2, normal servers report no gateway; an injected C1 gateway [rejects the iframe’s GET](/tmp/rv-dt-t6s3/scripts/tamber-canvas.mjs:356). The real pairing test uses a tunnel without a gateway. Once C2 lands, verify successful entry, fragment removal, remount behavior, and revocation through the actual frame.

The remaining security trace looks sound: the current gateway generates a client-bound, single-use, 30-second grant; `loadCanvas` appends it as an encoded fragment and makes no redemption request itself. I found no explicit grant logging or error interpolation. Ordinary hello/poll refreshes **do not remint** when arguments stay equal—the [runtime compares arguments](/tmp/rv-dt-t6s3/host/web-js/rt.js:494)—so there is no steady polling churn against the six-per-minute bucket or eight-live-grant cap. Revocation immediately ends gateway requests and sessions; the tool removes the frame after its poll failure refreshes `hello`.
