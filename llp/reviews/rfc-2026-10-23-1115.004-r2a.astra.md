**B — Keep the spike, with native RichEdit as the default. Confidence: 85/100.**

Use `msftedit.dll`, plain-text mode and explicit TSF enablement under Fluent chrome. Compare both Shelf search and Excord’s growing multiline composer. The RFC’s search-only spike is too weak for the main control of a CJK-heavy chat client. [D7.0, lines 313–320](/Users/ccheever/projects/exact2/llp/1115.004-no-tells-on-windows.rfc.md:313)

The considerations check out as follows:

- **Airspace: the absolute objection is wrong.** DirectComposition supports one target below child HWNDs and another above them. The upper target can paint smoke and dialog content over a field. This solves that visual ordering problem, not arbitrary CSS interleaving, clipping or input routing: an obscured field must also stop receiving focus/input. D10.1’s separate popup HWND is another distinct case. [CreateTargetForHwnd](https://learn.microsoft.com/en-us/windows/win32/api/dcomp/nf-dcomp-idcompositiondevice-createtargetforhwnd)
- **Synchronization: a real risk, not established inevitable tearing.** `SetWindowPos` changes HWND geometry separately; DirectComposition’s atomic commit covers its own commands, not a documented transaction joining HWND movement, GDI repaint and swap-chain presentation. Film scrolling, continuous resize and composer growth on the NucBox. [SetWindowPos](https://learn.microsoft.com/en-us/windows/win32/api/winuser/nf-winuser-setwindowpos), [Commit](https://learn.microsoft.com/en-us/windows/win32/api/dcomp/nf-dcomp-idcompositiondevice-commit)
- **Text: the mismatch risk is real; “EDIT means ClearType” is too absolute.** Windows Desk explicitly requests `CLEARTYPE_QUALITY`; Exact requests hinted swash `Format::Alpha`. GDI offers other quality settings, but changing one does not guarantee matching metrics or ink. Compare actual fields and adjacent labels. [Desk font creation](/Users/ccheever/projects/exact2/apps/windows-desk/src/native.rs:706), [painter](/Users/ccheever/projects/exact2/host/linux/src/text/catalog.rs:638), [CreateFontW](https://learn.microsoft.com/en-us/windows/win32/api/wingdi/nf-wingdi-createfontw)
- **Input: native controls have a substantial head start, with qualifications.** Microsoft documents system TSF support for standard EDIT and RichEdit; RichEdit exposes `SES_USECTF`, documented as off by default. That is not proof that every current touch-keyboard or dictation feature works in the chosen configuration. Winit 0.30.13’s Windows IME implementation is IMM32. Reconversion itself is also available through IMM32, so it is not exclusively a TSF capability. [Native-control TSF support](https://learn.microsoft.com/en-us/archive/msdn-magazine/2007/july/speak-up-support-dictation-with-text-services-framework), [SES_USECTF](https://learn.microsoft.com/en-us/windows/win32/controls/em-geteditstyle), [winit source](https://github.com/rust-windowing/winit/blob/v0.30.13/src/platform_impl/windows/ime.rs), [reconversion](https://learn.microsoft.com/en-us/windows/win32/api/imm/ns-imm-reconvertstring)
- **“No Rust crate implements a text store”: unverified as an absolute.** I found experimental Rust implementation work, but no established reusable store I would put on S1’s critical path. Keep the RFC’s narrower wording, “no established … crate,” rather than claiming none exists. [Experimental implementation](https://zenn.dev/hzuika/scraps/ee45174d909c36)
- **Narrator: broadly correct, but integration remains.** Standard controls receive Microsoft-provided UIA support, sometimes through proxies rather than their “own” provider. A painted field needs Exact’s AccessKit integration. A mixed tree must expose one correctly named field, with correct focus and selection—not duplicate native and painted nodes. [UIA providers](https://learn.microsoft.com/en-us/windows/win32/winauto/uiauto-providersoverview)

**What changes my answer:** reproducible failures in native-field positioning, authored CSS, appearance or UIA integration that the painted alternative passes. Conversely, typing a committed CJK string is insufficient evidence for painted input: exercise candidate selection, cancellation, reconversion, touch suggestions and dictation replacement. Enter accepting a candidate must never send the chat message.

My mapping would be:

| Mac destination | Windows result |
|---|---|
| `app` / `about` | No app-named menu. About and related informational commands go to Help; Settings to File → Settings; platform Quit becomes File → Exit. Preserve explicitly authored command labels and actions. |

| No declaration | No automatically generated application menu bar. |

Do not import Mac app-wide enablement under modal dialogs mechanically: Windows owner-window modality must remain correct. Nor should a general menu bar consume caption drag space by default.
