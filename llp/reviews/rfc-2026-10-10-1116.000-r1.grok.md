**READY WITH CHANGES.** Round 2's losses are real regressions, copied doc bugs, and under-designed content. The five decisions point the right way. Three of them are too narrow for the evidence.

## 1. Decisions

**D1 — RIGHT.** Both bugs are LLP 1116's own changes, and the grades match the diagnosis: a `column` row loses the cell margins (team-kanban, household-list), and a filled-height scroller draws its last control under the home indicator (trivia-quiz). Restoring the margins, and laying content out above the bottom inset while scroll content still passes under it, is the right split. The lane must re-check the old white-band apps so the inset does not come back as a painted strip.

**D2 — RIGHT WITH CHANGE.** The grades show the docs teaching the failure: the core example and `chat-thread` clear the draft before the reply (chat-rooms, polls, household-list), and polls is one long form-plus-list because the core's picture is one screen. Clear only in `then` on an ok reply. Narrow the sheet rule to a multi-field create or edit; a single field may stay on the list, which is what the groceries example actually is. One sentence after that example, not only a template comment. Also fix pitfall 3 in `docs/start-here.md`: it still says a header's extra text is dropped and a count belongs in the content. The bar's subtitle is that text now, and the pitfall teaches the round-1 miss.

**D3 — RIGHT WITH CHANGE.** Rewriting "say less" into "the platform draws what you omit; you design the content" matches the losses. Weather is more native than Expo (platform 8 vs 7) and still loses for looking like Settings; mood-journal, habit-tracker, water-tracker, and focus-timer lose the same way. The existing "deliberate design is allowed" line already permitted a chart and did not change behavior, so the core has to state the job, with one short recipe as the picture. Do not have the framework invent heroes, rings, or insights tabs. Do give a grouped row the platform's title and secondary styles when the author sets none: household-list's same-font rows are an omitted presentation, which LLP 1115 already assigns to the platform, and writing `-exact-headline` on every row spends tokens. Keep inset-grouped for settings and forms. Say that a content screen is not another settings list.

**D4 — RIGHT.** Contacts is the case: a pushed web route has no Back control, and `tel:`/`mailto:` links are black text with the default cursor. That is LLP 1115's "back is always there" and link colour, missing on the web. Scope it to a pushed route.

**D5 — RIGHT WITH CHANGE.** The five topics are the counted greps (functions and timers 5, keyboard and files 4, after a write 3), and an under-80-line recipe is the right shape. The functions recipe must replace the core's lookup row that still sends builders to the grammar. As written, the grammar "stays the authority," so the new file can add a read. Do not add more recipes this round for clipboard, list state, or the other uncounted greps.

## 2. What is missing

The bigger token lever is not another index. Exact2's own cost fell by a third (4.0M to 2.7M), and it is still about 1.18× the comparison (1.32× on the web). The remaining mass is the long guides (~250 KB across the measured pairs) plus recipes already ~300 KB. Small web apps sit on the core-read floor (recipe-finder 1.4M vs 0.69M even though Exact2 won). More recipes will not move that floor.

The pairs still far over the comparison are the ones that hit framework and doc bugs: chat-rooms 9.4M vs 3.6M, polls 6.3M vs 3.2M, team-kanban 5.7M vs 2.4M. Fixing those should move tokens more than a function list.

One of those bugs is not in the RFC. Chat-rooms opens a long room one or two messages short of the newest, and the feature scores partial. `chat-thread` already teaches `scroll-start="end"` with `scrollFollowEnd=true`, and that combination is a known short-by-estimate behavior. Put it on the host lane. A recipe change will not fix a builder who copied the recipe.

The web-look recipe's centred `max-width="640px"` column is the contacts "stretched phone UI." That is a taught pattern, same class as D2, not a builder's free choice.

## 3. Risks

D3 can make Exact2 worse at its own goal if the core reads as "add a hero and a tint to every screen." Tokens go up, controls get restyled, and `no-tells` either blocks the design you just asked for or lets painted chrome through. Keep the obligation to a few lines, leave control chrome alone, and keep the recipe inside role colours.

D1's inset change can undo the white-band fix if it is implemented as padding around the scroller instead of a layout inset on the content box.

D2's sheet rule, stated too broadly, would push a one-field add into a sheet and fight the native pattern the core example is for.

## 4. Verdict

**READY WITH CHANGES.** Add the transcript open-at-end bug to the host lane. Correct the subtitle pitfall, and state the sheet rule next to the example as multi-field only. Give an unstyled grouped row platform title and secondary styles; do not generate content design. Point the functions lookup at the new recipe and stop citing the grammar there. Fold the 640px column correction into the docs lane.
