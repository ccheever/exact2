## 1. D11 reuses a yield that runs to completion and publishes once

A promise-returning mapper, "with the same per-turn budget and yield mechanism as an asynchronous answer," does not give Excord bounded work across turns. A yielded answer is asked again at once, with no clock movement, and `clock settle` runs it to the end (`docs/reference.md` around the Hermes turn-budget paragraph; LLP 1141.001 D10). The prelude refuses this path today: `scheduler.yield()` resolves immediately inside a mapper, and `__exact_message` throws if `exactStream` returns a promise (`js/src/prelude.js`). On the web JS target, a continuation still cannot send, because a page task is not tied to a call (LLP 1016.000 D7, 2026-10-18 as-built). D11.4 requires sends after a yield on that target anyway.

Excord's digest works because each slice is its own mutation. Heartbeats are a separate ask, later compressed frames stay queued, and guilds become visible before the queue is empty (`apps/excord/live.test.ts`, the large-READY and "frame that arrives while digest runs" tests). One snapshot when a mapper promise settles removes those intermediate publications. `JSON.parse` of a whole READY stays one native call over the budget, which the issue and §13.5 both admit, so the bounded scan has to remain somewhere. Deleting the digest then deletes the only interleaving point. Inbound ordering should stay serial: a heartbeat request is the next packet of the same zlib stream, and inflating it early lands inside READY. The outbound heartbeat is the thing that must run between slices, and an auto-drained yield never returns to that timer.

Amend D7 only for a suspension that returns to the host, is not drained by `clock settle`, can publish a snapshot per slice, and on web JS resumes inside an executor turn that already owns the socket. Keep Excord's digest until that path passes the existing READY and retirement drives. Qualify native `DecompressionStream` on its own LLP amendment. It does not make parsing preemptible and does not justify deleting the scheduler.
