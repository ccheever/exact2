**D1 — RIGHT WITH CHANGE.** Roles and `light-dark()` pairs are the right mechanism: they preserve authored brand while restoring adaptive presentation. But “a bare hex … breaks dark mode” is too broad. The demonstrated failure is fixed light surfaces mixed with adapting text and controls; fixed colours can also form an intentional, readable composition. Make the warning advisory and sensitive to that distinction, respecting explicit scheme declarations and avoiding noise for intentional artwork. Ship a compact, branded light/dark example in the patterns, including foreground/background relationships. Pairing alone does not guarantee legibility; check both appearances. [Mood Journal’s report]( /Users/ccheever/bakeoff/rounds/r4/grades/mood-journal/grade.md) strongly supports this priority.

**D2 — RIGHT.** A successful write must become visible without leaving the screen. This directly addresses a severe reliability failure and removes debugging work from every author who encounters it. Investigate presentation freshness rather than assuming the previously queued grouped-row bug is the cause: Countdowns updates its count while both the row and NEXT UP card remain absent. Round 4’s Workout Log also reports a blank Finish row until scrolling. These observations justify fixing the underlying invalidation problem, with the affected apps establishing the expected behaviour. [Countdowns report](/Users/ccheever/bakeoff/rounds/r4/grades/countdowns/grade.md)

**D3 — RIGHT WITH CHANGE.** Remove optional features, but replace the 120-line target with a target for total adaptation cost at preserved quality. Patterns earned their place by supplying structure; shortening them must retain routing, adaptive layout, save/refusal handling and useful verification. Comparing unrelated pattern users with nonusers cannot establish savings: app complexity and model behaviour confound it. Compare the same spec and model with the current pattern, reduced pattern and recipe, including reading, deletion and repair. Polls’ first win is encouraging, but its competitor’s blocking cancellation bug means that win alone does not establish the pattern’s value. [Polls report](/Users/ccheever/bakeoff/rounds/r4/grades/polls/grade.md)

**D4 — RIGHT WITH CHANGE.** Automatic stale-build handling removes a needless author obligation and can eliminate expensive model turns. However, combining build and drive does not itself reduce compilation, launch or verification work. Make the web-first, native-at-milestones workflow the principal cost intervention, with several interactions checked per native build. Measure model turns, actual rebuilds, build time and repair cycles separately. Native milestones must inspect real UIKit presentation, including light/dark appearance and a completed write; fewer checks are only a win if they preserve quality.

This recurring pattern supports making correct navigation easier to retain and adapt, rather than trimming patterns solely by size. It improves quality while avoiding reconstruction and repair. [Recipe Finder](/Users/ccheever/bakeoff/rounds/r4/grades/recipe-finder/grade.md), [Contacts](/Users/ccheever/bakeoff/rounds/r4/grades/contacts/grade.md)
- **Readable validation in the existing shared examples.** Focus Timer, Contacts, Grocery List, Countdowns and Water Tracker all receive complaints about inconspicuous error presentation. Give existing recipes/components a clear error treatment using platform roles and explicit meaning. This is a repeated quality defect that a small shared correction can address without another author design pass.
- **Evidence that measures the actual goal.** The supplied findings explicitly describe 22 pairs before two rebuilds, while the RFC’s final summary is missing. Complete the cleaned results and report cheaper **and** faster **and** preferred by stack and model. Attribute surplus turns before treating pattern length as the cause of Muse’s increase. The evidence supports investigating that hypothesis, not yet declaring it established.

**Risks to the goal and principles:** An indiscriminate colour warning can consume more tokens and discourage distinctive content; forcing palettes would violate author precedence. Oversimplified starters can recreate missing navigation and weak error handling. Web-only iteration can conceal native defects until late. None requires abandoning these decisions, but each needs an explicit boundary.

**Overall: READY WITH CHANGES.** Narrow D1’s warning and preserve branded examples; evaluate D3 by matched adaptation cost; make D4 reduce verification cycles while retaining native milestones; strengthen navigation and validation in existing starters; complete the cleaned baseline before claiming progress.
