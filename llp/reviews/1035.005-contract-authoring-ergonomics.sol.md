## 3. High: trivia is not kept by position

The implementation uses a global line-ordered trivia list rather than the structural attachment required by D1. [flush](/Users/ccheever/projects/exact2-wt-game-review/contract/syntax/src/fmt.rs:85) treats an unconsumed trailing comment like a standalone comment, while [raw](/Users/ccheever/projects/exact2-wt-game-review/contract/syntax/src/fmt.rs:161) emits generated `else`, `case`, component-argument, and continuation lines without consuming trivia.

For example:

```text
component A
  view
    when true
      text "a"
    else // why
      text "b"
```

formats as:

```text
component A
  view
    when true
      text "a"
    else
      // why
      text "b"
```

The parsed `Trivia::Trailing` becomes `Trivia::Comment`, so even the full AST changes. The same happens around `match` cases, continued attributes, and multiline component arguments. Leading blank groups are discarded by [fmt.rs:100](/Users/ccheever/projects/exact2-wt-game-review/contract/syntax/src/fmt.rs:100), and trailing blank groups are dropped by [finish](/Users/ccheever/projects/exact2-wt-game-review/contract/syntax/src/fmt.rs:112).

The corpus test cannot catch this because it clears `file.trivia` before comparing at [fmt.rs:49](/Users/ccheever/projects/exact2-wt-game-review/contract/cli/tests/fmt.rs:49).

The smallest fix is to follow D1 and attach trivia to declarations, nodes, sections, arms, attributes, and arguments. A narrower fix would retain spans for `else`, `case`, closing parentheses, and every printed continuation, then make all emitted lines consume trivia through the span-aware path.

## 4. Medium: sufficiently large number literals change semantic AST

The lexer accepts arbitrary decimal text into `f64` at [lexer.rs:202](/Users/ccheever/projects/exact2-wt-game-review/contract/syntax/src/lexer.rs:202). A decimal large enough to parse as infinity, such as `1` followed by 400 zeros, becomes `Expr::Number(INFINITY)`. The printer emits it with `format!("{n}")` at [fmt.rs:713](/Users/ccheever/projects/exact2-wt-game-review/contract/syntax/src/fmt.rs:713), producing `inf`.

Reparsing `inf` yields `Expr::Ident("inf")`, not a number. The negative form becomes `-inf`, changing from a negative numeric expression to negation of an identifier. Thus `parse(fmt(x)) != parse(x)` and compilation can change from a numeric plan value to an unknown-name rejection.

This is the non-trivia AST counterexample among numeric constructs. Ordinary finite negative numbers, computed values, templates, member chains, ternaries, regions, component arguments, and named surface arguments appear to preserve their AST.

The smallest fix is to reject nonfinite parsed numbers in the lexer. Preserving the original number lexeme in the AST would also work.

## 5. Medium: D2’s action-arity diagnostic stops at ordinary props

The normal action-prop case is implemented well: a component use records the prop label and bound action, and `analyze-action-arity` carries the declaration and binding as related spans.

Injected actions do not participate. [own_prop](/Users/ccheever/projects/exact2-wt-game-review/contract/analyze/src/lib.rs:253) deliberately accepts only indices below `c.props.len()`, excluding injects. The reject corpus acknowledges this at [rejects.txt:274](/Users/ccheever/projects/exact2-wt-game-review/contract/corpus/rejects.txt:274): a mismatched action supplied through `provide`/`inject` reaches `lower-handler-arity`, which has no two-sided D2 diagnostic.

The primary span is also imprecise for normal props. [Site::Handler](/Users/ccheever/projects/exact2-wt-game-review/contract/analyze/src/lib.rs:174) stores the attribute span, so `press=pick(id)` highlights `press` while the message describes `pick`.

The smallest fix is to infer arities for both props and injects, propagate arity through provides, and use the value expression’s span for the invoked action name.

## 6. Medium: the symbols command resolves a different import language from the compiler

The independent loader at [symbols.rs:109](/Users/ccheever/projects/exact2-wt-game-review/contract/cli/src/symbols.rs:109):

- Does not enforce the compiler’s `./` path requirement.
- Does not reject `..` or leaving the app directory.
- Silently skips a cycle instead of reporting `contract-use-cycle`.
- Does not verify that the used file declares the requested name.
- Resolves names by a global first match rather than the compiler’s validated merge.

Consequently, `contract symbols` can return a plausible index for a source graph that `contract build` rejects, or link a duplicate name to the wrong definition.

The smallest fix is to extract and share the compiler’s import graph loader while retaining each file separately for symbol output.

## 7. Medium: `contract fmt` is not total over accepted syntax

[fmt.rs:27](/Users/ccheever/projects/exact2-wt-game-review/contract/syntax/src/fmt.rs:27) rejects every component containing a `contract` section because the parser discards its body. The test at [parse.rs:395](/Users/ccheever/projects/exact2-wt-game-review/contract/syntax/tests/parse.rs:395) locks in that refusal.

A file accepted by the existing parser can therefore not be formatted, contrary to D1’s formatter-over-the-existing-parser requirement.

The smallest fix is to retain a contract block’s uninterpreted token lines in the AST and re-emit them. If `contract` blocks are truly outside the language, the alternative is to stop accepting them in the parser.

# Size and fit

The formatter and symbol index total 1,387 lines; including the 126-line diff helper, the slice is 1,513 lines.

The main duplication is:

- `fmt.rs` repeats grammar structure, declaration ordering, node and statement traversal, precedence, string escaping, and button desugaring.
- `symbols.rs` repeats import loading, namespace resolution, lexical-scope handling, and full AST traversal already present in the compiler and analyzer.
- The duplicated symbol resolver has already drifted from compiler behavior.

Retaining source order and trivia structurally in the AST would simplify the printer. Exposing compiler resolution results would reduce `symbols.rs` to serialization plus editor-specific symbol selection. Those changes could plausibly cut this slice roughly in half while improving correctness.

# Output conventions

The unified diff aims at an existing format, apart from the EOF defect.

The symbol and diagnostic JSON formats are bespoke:

- They do not follow LSP’s URI plus zero-based UTF-16 `Range`.
- They do not follow TypeScript’s usual textual diagnostic format.
- Symbol references use an array index rather than an LSP location or document symbol identity.
- Byte columns are awkward for web editors and are not identified by a schema/version field.

An LSP-shaped location would be reusable without committing to an LSP server.

# What is good

The implementation builds on the existing parser, preserves normal expression meaning and ordering, adds only the intended continuation form, gives ordinary action props a useful two-sided arity diagnostic, keeps successful JSON builds quiet, and has broad dynamic corpus coverage. The parser extraction is clean, and the diff helper is used.
