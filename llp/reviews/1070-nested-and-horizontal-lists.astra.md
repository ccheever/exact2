## Review (verbatim)

**Build with named changes: repair pin transfers, nested fill, cache validity and accounting, and gesture parity before implementation.**

1. **BLOCKER — N5 needs atomic chain transfer.** Merely extending `release_other_pins` can destroy the target: feedback currently releases other owners **before** updating the recipient ([traversal.rs:238](/Users/ccheever/projects/exact2-wt-nestllp/runner/src/instance/collection/traversal.rs:238)), and releasing a pin immediately re-realizes its collection ([mod.rs:1035](/Users/ccheever/projects/exact2-wt-nestllp/runner/src/instance/collection/mod.rs:1035)). Transferring focus between inner lists sharing an offscreen, pinned outer row could therefore retire that row. Preflight the complete new chain, preserve shared ancestors, then release only obsolete ownership. Test stale feedback, simultaneous category transfers, and ancestor deletion.

2. **BLOCKER — F1/F2 cannot be expressed by `limit: Some(0)`.** The runner always owes its local visible band and pins ([mod.rs:538](/Users/ccheever/projects/exact2-wt-nestllp/runner/src/instance/collection/mod.rs:538)); first geometry, resizing and pin changes override the limit to unlimited ([mod.rs:835](/Users/ccheever/projects/exact2-wt-nestllp/runner/src/instance/collection/mod.rs:835)). Thus an inner list inside an optional outer row still fills. Specify ancestor eligibility in the runner’s fill contract, preserve explicit inner pins/jumps/accessibility targets, and make LLP 1050.000’s unfinished motion signals and D3 implementation explicit staging dependencies. A host-only budget change is insufficient.

3. **MATERIAL — F2/F5 assume a settlement loop the collection does not have.** The cited report-layout-report loop belongs to the legacy path ([host.rs:962](/Users/ccheever/projects/exact2-wt-nestllp/host/apple/src/host.rs:962)); collection feedback performs one runner call and commits ([host.rs:705](/Users/ccheever/projects/exact2-wt-nestllp/host/apple/src/host.rs:705)). Moreover, outer coverage checks only outer wrapper rectangles ([CollectionIOS.swift:77](/Users/ccheever/projects/exact2-wt-nestllp/host/apple/Sources/ExactKit/IOS/CollectionIOS.swift:77)). A covered outer row can contain an underfilled inbox. Define settlement of newly created inner ports before native presentation, including underestimated sizes, and charge that work to the outer row. Linux’s shared two-report limit also needs attention ([collection.rs:594](/Users/ccheever/projects/exact2-wt-nestllp/host/linux/src/presenter/collection.rs:594)).

4. **MATERIAL — N2’s identity test does not establish index validity.** Keys can depend on inputs outside the items value; current code explicitly tracks those dependencies ([mod.rs:256](/Users/ccheever/projects/exact2-wt-nestllp/runner/src/instance/collection/mod.rs:256)). Identical `Rc` items therefore do not justify skipping key evaluation after remount. Cached zero sizes are especially dangerous: they can prevent rows from mounting and being measured again; existing invalidation restores their positive estimates ([mod.rs:128](/Users/ccheever/projects/exact2-wt-nestllp/runner/src/instance/collection/mod.rs:128)). Require a valid key-dependency proof, retain the necessary typed-key/duplicate metadata, and invalidate cached measurements—including zeroes—when row inputs or recreated local state differ.

5. **MATERIAL — N4 materially understates retained memory.** “40 bytes an item” omits substantial storage: the index contains order, map, row records and two tree arrays ([index.rs:86](/Users/ccheever/projects/exact2-wt-nestllp/runner/src/instance/collection/index.rs:86), [index.rs:515](/Users/ccheever/projects/exact2-wt-nestllp/runner/src/instance/collection/index.rs:515)). Keeping the items `Rc` also retains its value graph. The six-filmstrip estimate is unsupported. Define the 512-KiB charge over all retained allocations, reject oversized entries, specify pressure/background delivery to the runner, and measure actual retained bytes before choosing caps.

6. **MATERIAL — G2’s `touch-action` recommendation is wrong, and G3 misses an iOS change.** `pan-x` disables vertical browser panning; it does not hand vertical movement to the feed. Use `auto` for ordinary native orthogonal scrolling. This follows [Pointer Events §7](https://www.w3.org/TR/pointerevents/#the-touch-action-css-property) and the existing ancestor checks ([ScrollViewIOS.swift:39](/Users/ccheever/projects/exact2-wt-nestllp/host/apple/Sources/ExactKit/IOS/ScrollViewIOS.swift:39)). Separately, iOS agent wheels directly change offsets without reading containment ([AgentIOS.swift:564](/Users/ccheever/projects/exact2-wt-nestllp/host/apple/Sources/ExactKit/IOS/AgentIOS.swift:564)). Update that path too. Gate the edge-start recognizer rule on device cases covering insets, empty content and ancestor eligibility.

7. **MATERIAL — G1’s macOS latch needs a complete ownership and termination rule.** Specify zero-delta beginnings, cancellation, endings without momentum, momentum continuation, owner destruction and event retargeting. A local “through momentum’s end” flag is insufficient: AppKit can route non-momentum events under a changing pointer. [Apple’s event-routing documentation](https://developer.apple.com/library/archive/documentation/Cocoa/Conceptual/EventOverview/HandlingTouchEvents/HandlingTouchEvents.html) describes this distinction. Also, a trackpad check cannot erase the *already measured* phase-less diagonal mismatch: the agent emits those exact two-axis wheel events ([agent.mjs:306](/Users/ccheever/projects/exact2-wt-nestllp/scripts/agent.mjs:306)). Match Chrome’s recorded behavior or declare that deviation explicitly.

8. **MATERIAL — The traversal inventory misses selection and reorder.** Inner logical copy cannot find its collection: `list_region` descends ordinary children but not mounted collection rows ([text.rs:69](/Users/ccheever/projects/exact2-wt-nestllp/runner/src/instance/text.rs:69)). Reorder’s `edit_walk` has the same nesting refusal assumption ([traversal.rs:545](/Users/ccheever/projects/exact2-wt-nestllp/runner/src/instance/collection/traversal.rs:545)); horizontal preview motion is explicitly vertical ([reorder.rs:264](/Users/ccheever/projects/exact2-wt-nestllp/runner/src/instance/collection/reorder.rs:264)). Extend these paths with correct enclosing frames and axis geometry, or explicitly refuse unsupported reorder combinations. “Per-list” selection/reorder does not resolve these implementation gaps.

9. **MATERIAL — H2’s compile rules do not fully protect its geometry assumptions.** The index assumes starts are prefix sums ([mod.rs:1055](/Users/ccheever/projects/exact2-wt-nestllp/runner/src/instance/collection/mod.rs:1055)), while newly admitted flex alignment can introduce different origins. Require supported main-axis alignment and nonoverlapping inline margins, or model them. Reject inherited RTL too: `direction` is inherited ([schema.json:1940](/Users/ccheever/projects/exact2-wt-nestllp/kernel/tables/schema.json:1940)). Unequal min/max heights do not establish the promised content-independent cross size. Finally, reconcile §3.1’s supported flex columns with §8’s “only `row`” rule. See [CSS flex alignment](https://www.w3.org/TR/css-flexbox-1/#justify-content-property).

10. **MATERIAL — H4 needs an explicit ruling and motion semantics.** Real offscreen content changes are not all virtualization artifacts; the RFC itself acknowledges that counterexample. Estimate compensation is reasonable, but stabilizing genuine card resizes is a separate browser deviation. Furthermore, web corrections currently apply without a motion guard ([collection-glue.js:373](/Users/ccheever/projects/exact2-wt-nestllp/host/web/collection-glue.js:373)), whereas UIKit rejects them during tracking/deceleration ([CollectionIOS.swift:69](/Users/ccheever/projects/exact2-wt-nestllp/host/apple/Sources/ExactKit/IOS/CollectionIOS.swift:69)). Specify behavior during both ancestor and inner motion, implement the owed anchoring rule, and test real resizes separately from first measurements.

11. **MATERIAL — Acceptance omits assistive focus and simultaneous motion.** UIKit’s collection focus query observes first responders, not VoiceOver focus ([CollectionIOS.swift:121](/Users/ccheever/projects/exact2-wt-nestllp/host/apple/Sources/ExactKit/IOS/CollectionIOS.swift:121)). Define how assistive navigation occupies the bounded focus chain and realizes outer then inner targets before announcement. Add keyboard/VoiceOver, concurrent outer and inner motion, retirement during an inner fling, and presented-gap checks. Programmatic offset ladders alone cannot establish deceleration/rest-target behavior. The example wheel script also never establishes that the inbox has reached its end; derive that offset from geometry before asserting chaining.

12. **MINOR — Correct four current-code claims.** Linux already finds the nearest pin owner by walking ancestors first ([collection.rs:229](/Users/ccheever/projects/exact2-wt-nestllp/host/linux/src/presenter/collection.rs:229)). Raster throttling already checks **any** fast list ([ScrollPumpIOS.swift:258](/Users/ccheever/projects/exact2-wt-nestllp/host/apple/Sources/ExactKit/IOS/ScrollPumpIOS.swift:258)). Pool selection is global by shape, without matching the originating list, so reuse can cross live lists ([NodePoolIOS.swift:201](/Users/ccheever/projects/exact2-wt-nestllp/host/apple/Sources/ExactKit/IOS/NodePoolIOS.swift:201)). At estimate 128, current bootstrap is four rows, not sixteen ([mod.rs:218](/Users/ccheever/projects/exact2-wt-nestllp/runner/src/instance/collection/mod.rs:218)). The compiler-refusal and v2-wire claims are correct.

13. **MATERIAL — Make the take executable and refocus Charlie’s questions.** The entry honestly acknowledges that legacy deletion is already owed, but requiring it only before nesting permits horizontal capability to ship first. [DEFERRED.md:438](/Users/ccheever/projects/exact2-wt-nestllp/rules/DEFERRED.md:438) requires the take in the admitting PR, or a written waiver. Move deletion before the first capability stage, or obtain that waiver. Q1’s reset recommendation is sound; separate cache approval from it. Q2 is conditional on that real trade. Q3 is principally required Chrome parity, and Q4 can be the implementer’s sequencing decision. Ask explicitly about H4’s deviation and name the implementer/date. The proposed fixtures and existing test venues do not themselves add prohibited apparatus.
