## Should-fix

**Mode ids are stored under the display name, so a long context can take another context’s mode — `tools/figma-tamber/src/code.ts:66`**

`modeIds` is keyed by mode name (`code.ts:139`). Names over 40 characters are cut in `mapping.ts:155`, and the `… 2` suffix depends on which other contexts are truncated first. A later pull that changes that order (the export’s default moves, or a new context shares the same 39-character prefix) looks the new name up in the old map and binds the context to the other context’s mode id. That mode is then removed as stale, or the two contexts swap modes. Short names and a second pull with the same names stay correct. The design’s values are still written, but layers bound to those modes follow the wrong context.

Fix: resolve and store ids by the full context string (`contexts`), not by the truncated name. Keep the 40-character name only as what `renameMode` shows.

**An apostrophe in a family name makes push throw — `tools/figma-tamber/src/mapping.ts:127`**

`families()` quotes only `,`, `"`, and `\`. `familiesOf` treats `'` anywhere as the start of a quote and clears the characters already read. `Mike's Font, serif` — a string the plugin itself would write — never closes that quote, so `familiesOf` throws and the whole push stops. Quoted `'ACME, Sans'` is fine.

Fix: open a quote only at the start of a name. Keep refusing an unclosed quote there.

**Renames can collide — `tools/figma-tamber/src/code.ts:127`**

Modes are renamed straight to the final name, in plan order. After a swap, the first `renameMode` asks for a name the other mode still has. One renamed mode is handled (`code.test.ts` sets `Dim (light)` back). Two names exchanging places is not.

Fix: rename every touched mode to a unique temporary name, then to the final name.

## Figma Plugin API

`figma.triggerUndo()` reverts the document to the state at the last `figma.commitUndo()`. That is the current API text: plugin actions are not on the undo history until `commitUndo`, and `triggerUndo` returns to that state. Calling it inside the plugin is the supported rollback. It covers variable collections, modes, variables, values, and shared plugin data on nodes (including the baseline and plan on `figma.root`). `figma.clientStorage` is not the document and is not restored. The apply path does not touch it. The 1-mode path undoes the failed full write, then `pull(doc, 1)` throws before a second write; the outer `triggerUndo` returns to the `commitUndo` taken at that restored state.

`defaultModeId` is readonly, and there is no call that chooses a new default. `removeMode`’s page only says it removes the mode by id; the code does not call it on `defaultModeId`, and it does not remove the last remaining mode. `addMode` throws `in addMode: Limited to N modes only` (Starter is 1, so N below 2 becomes the Light/Dark error). Mode names cannot be longer than 40 characters (Variables REST). `collection.name` is writable; the authoring guide assigns it. `getVariableCollectionByIdAsync` returns a library collection by id, or null, which is what the alias read uses.

## Security

The token is sent only on `paired`, and only to `paired.server`, with `redirect: 'error'`. Pairing sends no token and stores `{server, token}` in one `clientStorage` key after success. A 401 clears the token only when the request object is that same `paired` value, then writes the cleared pair back as one entry. Nothing runs before `load`: `busy` starts true.

## Reconciliation

A renamed collection is found by the stored id and renamed back with `collection.name`. A renamed mode is found by its stored id and renamed back. A deleted collection is created again, unless some other collection now has that name and is not `owned`, in which case the pull is refused. The default mode taking a context keeps that mode id, writes the plan’s values onto it, and removes the extra id; layers that were pinned to the removed id fall back to Auto, which is that same context. The hole is the truncated-name key above, which can attach a stored id to a different context.
