## Blocking

**The printed CAA record does not stop the attack it claims to close.** `scripts/tamber-remote.mjs:445`, `docs/tamber-protocol.md:252`, `QUEUE.md:3`.

On `--relay-dns-hook` issuance the server tells the developer to publish only

`0 issuewild "letsencrypt.org; validationmethods=dns-01; accounturi=…"`.

RFC 8659 §4.3: an `issuewild` property is ignored for a name that is not a wildcard. An RRset that contains only `issuewild` does not restrict `tool.example.com` or `canvas.example.com`. The relay, which already receives traffic for those names, can still get a browser-trusted certificate for the exact hosts by TLS-ALPN-01 or HTTP-01. The docs say this record closes that. `QUEUE.md:3` says `--relay-name` with the hook already removes the residual. It does not.

Print `issue` (it covers wildcards when `issuewild` is absent), or both `issue` and `issuewild`, with the same parameters. Two more holes in the same line: `accounturi=${uri}` is the server's account `Location`, and a `;` in that URL splits CAA parameters, so a directory the operator pointed `--relay-acme` at can append parameters to a record the developer is told to publish; the issuer is hardcoded `letsencrypt.org`, so a non-LE directory gets the wrong issuer. The line is said only from the account callback during issuance, so a reused cached certificate never prints it. The BYO test stubs `say` (`scripts/tamber-relay.test.mjs:741`) and never checks the text.

## Should-fix

**Account check is an unanchored prefix.** `scripts/tamber-remote.mjs:391`. Without the hook, a greeting is accepted when both parents match and `parentOf(tool)` starts with `${account}.`. `foo.acct.evil.com` / `bar.acct.evil.com` passes, and the client orders `*.acct.evil.com` and sends that TXT name to the relay. The comment above it says the parent is the account under the relay's domain. Issuance still fails closed unless that zone is actually published, so this is the missing suffix (`${account}.${relayHost}`), not a key leak. Nothing tests it.

**The lock can be stolen from a live holder, and `finally` deletes whoever holds it.** `scripts/tamber-acme.mjs:196`, `:201`. Takeover is `!alive || age > stale` (600 s). A hook is allowed 300 s and each poll budget is 120 s, so a live issuance can outlast the lock. The waiter throws after about 5 minutes (`tries > 600`), which is also shorter than a slow hook, and `openRemote` then closes the connector. The `finally` always `unlinkSync(lock)`, including a successor's lock. Same-user mutual exclusion, not a cross-user read of the 0600 key.

**Authorization count is not capped.** `scripts/tamber-acme.mjs:127`. Each entry of `order.authorizations` gets its own `patience` (120 s) and its own request. A directory can return thousands of same-origin URLs inside the 256 KiB body, all for the one name asked for. The loop ends, but the bound is N times the budget. Cap it at `names.length` and use one deadline for the order.

**Extra DNS SANs are accepted.** `scripts/tamber-acme.mjs:59`, `:151`. `certifies` requires every requested name to be present. A directory that attaches further names to this key still passes, and `take` only checks that the session names match. Require the SAN set to equal the names asked for. Let's Encrypt will not add the apex on a wildcard-only order, so equality is safe. No test plants an extra name.

**Close does not cancel an issuance already in flight.** `scripts/tamber-remote.mjs:458`. The daily interval is not armed after close (that round-1 race is gone), and the initial failure path closes the connector. `REFUSED` or `close` during `get()` does not abort the order: the hook or `relayTxt` still runs, the TXT connection still sends the bearer, and `finally` still unpublishes. There is no tight retry loop; renewal failures wait a day and only warn.

**ACME `fetch` follows `NODE_TLS_REJECT_UNAUTHORIZED`.** `scripts/tamber-acme.mjs:82`. The relay dial forces `rejectUnauthorized` (`scripts/tamber-relay.mjs:220`); the ACME client uses global `fetch` with no equivalent. With that variable set to `0`, a network attacker can answer the directory and hand back a leaf that matches this key and these names, which `certifies` will install. They never receive the private key, and a browser rejects an untrusted leaf. The product does not set the variable; the relay test does (`scripts/tamber-relay.test.mjs:218`).

## Nits

- The checks above have no test: `redirect: 'error'`, the body cap, the account suffix, the CAA sentence, an extra SAN, or two long-lived processes adopting by fingerprint. The CSR test only checks that the name bytes appear in the DER. A separate `openssl req -verify` on a CSR from this code succeeded (SAN `DNS:*.acct.relay.test`).
- `hold` (`scripts/tamber-remote.mjs:31`) does not look at dates. If daily renewal keeps failing, an in-memory certificate is still served after `validTo`. Browsers reject it.
- A hook that calls `setsid` leaves the process group the timeout kills. The command is the developer's.
- A crash can leave `~/.exact/relay/<acct>/*.<pid>.tmp` beside the 0600 files.
