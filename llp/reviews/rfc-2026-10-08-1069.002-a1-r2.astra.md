**Two blockers remain. A1.9 overstates their resolution.**

1. **Blocker — the 24-second commit cutoff still permits a write after failure.** [A1.5:243](/private/tmp/imgrv/wt-d2/llp/1069.002-media-picker.rfc.md:243), [A1.9:344](/private/tmp/imgrv/wt-d2/llp/1069.002-media-picker.rfc.md:344).

   The revised text explicitly admits a write beginning before 24 seconds and finishing after 30. The existing [atomic writer](/private/tmp/imgrv/wt-d2/vendor/ibex/crates/ibex2/src/stdlib/app_fs_unix.rs:133) performs `write_all`, `sync_all`, then rename; none has a six-second completion bound.

   Concrete failure: compression begins its write at 23 seconds, `sync_all` stalls, the continuation fails at 30 seconds, and the prelude starts a queued replacement of `to`. The old compression subsequently renames over that replacement. This still violates “on any failure `to` is left as it was.”

   **Fix:** coordinate the waiter’s terminal outcome with commit authorization. Stage and sync the temporary file first; if timeout wins, prohibit replacement and clean up. If commit wins, the waiter must await its actual result instead of reporting failure and advancing the queue. A deadline check immediately before rename is insufficient without that coordination. Test a stalled write/commit crossing the waiter deadline, followed by another write. Also address the existing [timeout delivery](/private/tmp/imgrv/wt-d2/js/src/prelude.js:1373), which produces `failed`, not the promised `timeout`.

2. **Blocker — the web preflight still does not bound AVIF decoding.** [A1.5:224](/private/tmp/imgrv/wt-d2/llp/1069.002-media-picker.rfc.md:224).

   Taking the largest container `ispe` does not establish the dimensions encoded in the AV1 bitstream. Firefox calls its decoder before checking the decoded dimensions against `ispe`; rejection of a mismatch therefore occurs after decoding. [Firefox decoder implementation](https://github.com/mozilla-firefox/firefox/blob/main/image/decoders/nsAVIFDecoder.cpp#L1501)

   Concrete failure: an AVIF below 64 MiB advertises a small `ispe` but contains a 9000×9000 coded frame. The proposed reader admits it to `createImageBitmap`, defeating the pre-decode pixel limit even if the browser ultimately rejects it.

   **Fix:** require a preflight that bounds the coded image dimensions and relevant intermediate/auxiliary images, or refuse HEIF/AVIF variants for which that cannot be established. Add inconsistent container/bitstream fixtures and assert that `createImageBitmap` is never called. The ordinary JPEG/PNG header checks improve round 1, but do not justify A1.9’s claim for every admitted format.

3. **Should-fix — the revised JPEG memory bound is false.** [A1.5:233](/private/tmp/imgrv/wt-d2/llp/1069.002-media-picker.rfc.md:233).

   Only the **best accepted** JPEG is bounded by `maxBytes`. A rejected trial exceeds it by definition. With `maxBytes: 1`, even a tiny JPEG exceeds the claimed total of two bytes; a noisy 4000-pixel image can produce a large trial despite a small requested output budget. Both proposed encoders materialize the trial before checking its length.

   **Fix:** account for the full trial independently of `maxBytes`, including the browser’s resulting Blob. Release rejected trials promptly. If native output needs a hard allocation cap, specify a bounded output sink and treat exceeding it as a failed quality trial.

4. **Should-fix — stat-before/read/stat-after does not enforce the source-memory limit.** [A1.5:224](/private/tmp/imgrv/wt-d2/llp/1069.002-media-picker.rfc.md:224).

   Ibex’s current [read implementation](/private/tmp/imgrv/wt-d2/vendor/ibex/crates/ibex2/src/stdlib/app_fs_unix.rs:280) uses uncapped `read_to_end`. Another module can replace a small source with a much larger file between `stat` and opening it, or grow the opened file during reading. The final check detects the problem after allocating the bytes.

   **Fix:** inspect the opened descriptor and cap the actual read at 64 MiB plus one detection byte, then return `too-large`. Test replacement/growth during reading. The web’s immutable Blob can instead be size-checked before materialization.

5. **Should-fix — the cited browser jobs do not provide the proposed compression coverage.** [A1.7:315](/private/tmp/imgrv/wt-d2/llp/1069.002-media-picker.rfc.md:315), [A1.9:380](/private/tmp/imgrv/wt-d2/llp/1069.002-media-picker.rfc.md:380).

   [`conform-firefox` and `conform-webkit`](/private/tmp/imgrv/wt-d2/scripts/async.mjs:99) run app/Contract conformance through `host/web-js/conform.mjs`. They do not discover `js/web/tests/compress.rs`. A1.7 adds no compression fixture to their inputs, so both jobs can pass without executing this API or its worker path.

   **Fix:** name an actual Firefox/WebKit compression suite or fixture and wire it into those jobs. Exercise the public API, page and worker placement, orientation pixels, JPEG fallback/refusal, and destination preservation. A mock of the JS facade is useful but does not replace that integration coverage.

   The iOS argument also needs correction: the cited Unix-socket dependency alone does not establish simulator incompatibility. MacOS end-to-end plus iOS codec/Rust tests provide partial coverage; a minimal TypeScript call through the shipping iOS host would cover installation and dispatch without requiring the entire exact-js test suite.

The API placement, caller-named destination, grant pair, primitive wire arguments, early path refusal, patch number, and single host-owned search fit the code. The search matched the local Bluesky implementation in 48 in-memory cases; the one-pixel and exact-byte deviations are declared. The Linux refusal is justified by the workspace dependencies. A1.9’s choice of last-writer-wins across tabs is reasonable.

No files were changed, and native/browser codecs were not executed.

**Yes: findings 1 and 2 BLOCK implementing this design as written.**
