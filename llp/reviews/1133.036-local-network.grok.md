   That set is not the set of destinations that open a prompt. From knowledge of Apple’s TN3179 (https://developer.apple.com/documentation/technotes/tn3179-understanding-local-network-privacy), not re-fetched this session: local-network privacy follows the route. Traffic delivered to a local interface prompts, including a public address on the same subnet, link-local, and multicast; an RFC 1918 address reached through the default route, a VPN, or a tunnel does not; loopback does not; resolving a `.local` name does. From knowledge of the WICG Local Network Access spec (https://wicg.github.io/local-network-access/) and its predecessor (https://wicg.github.io/private-network-access/), also not re-fetched: Chrome’s local space adds 100.64.0.0/10 and treats an IPv4-mapped IPv6 address as the inner IPv4, and loopback is a more private space than local. A unicast name such as `nas.home.arpa` is the usual LAN origin and is only a “declared limit” (lines 357–361).

   The `GrantSet` sentence the RFC quotes (`grants/src/lib.rs` lines 228–229) constrains grant authority handed to a binding. D6 is a runtime origin rule, so that sentence does not force the prompt check to be a static spelling of the first URL. The socket is opened later. In `vendor/ibex/crates/ibex2/src/stdlib/fetch.rs`, `admit_hop` (lines 430–446) runs on every redirect immediately before `transport.open` (lines 403–411). A tool `fetch("https://evil.example/r")` that 302s to `http://192.168.1.1/` is admitted by `net.fetch https:` on the first URL; the hop is then admitted by `net.fetch http:` or `net.fetch local-network`, and the prompt opens. WebSocket admission (`vendor/ibex/crates/ibex2/src/task.rs` `open_websocket`, lines 757–794) is the same kind of gap for the URL it is given. Using `data_origin()` (`runner/src/runner/modules/admit.rs` lines 171–180) would also be the wrong origin: it is the least privileged origin of every in-flight request, which LLP 1133.002 D12 reserves for a call that cannot be traced.

   D8 then records “a connection to a local host succeeded” as `granted`. A success to a routed RFC 1918 address is a grant the person never gave, after which a tool fetch to an on-link address can prompt. The rule as written both misses prompts and invents grants. Because §12 makes it process-wide, it hits every app with a LAN origin.

   **Decision:** Keep `net.fetch local-network` a static grant. Refuse when the destination the stack will use can prompt: a `.local` name, an on-link address, Chrome’s local space including 100.64.0.0/10 and an unwrapped IPv4-mapped address. Where URLSession resolves a unicast name internally and the address is not visible before the prompt, state that residual as a limit. The claim that the hole is closed does not survive that case.
