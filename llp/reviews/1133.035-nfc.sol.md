1. **MATERIAL — §3 D8, §5 D11–D12: raw commands cannot reach non-NDEF tags.** Commands require a `reading` id, but a non-NDEF tag produces an argumentless `readingerror`. An ISO 7816 card without NDEF therefore supplies no id for its first APDU. `android.skipNdefCheck` makes this especially clear: Android documents that it prevents `Ndef` technology enumeration. [Android reader-mode documentation](https://developer.android.com/reference/android/nfc/NfcAdapter#enableReaderMode(android.app.Activity,%20android.nfc.NfcAdapter.ReaderCallback,%20int,%20android.os.Bundle)).

   **Fixing decision:** expose tag discovery independently of NDEF decoding, with a session-bound tag lease valid during the scan. Raw commands use that lease. Include a non-NDEF command exchange in acceptance; the proposed NDEF sticker’s `GET_VERSION` drive misses this defect.

2. **MATERIAL — §4 D10, §5 D11, §7 D15: command admission blocks the normal iOS workflow.** D15 makes tier 2 commands app-origin only. Emitted readings receive device origin in [events.rs:69](/private/tmp/claude-501/-Users-ccheever-projects-exact2/f4b5c629-4ed6-4746-9045-74f6106a629d/scratchpad/nfc-r1/capsule/runner/src/runner/modules/events.rs:69), and [admit.rs:533](/private/tmp/claude-501/-Users-ccheever-projects-exact2/f4b5c629-4ed6-4746-9045-74f6106a629d/scratchpad/nfc-r1/capsule/runner/src/runner/modules/admit.rs:533) rejects their app-only calls. A subsequent press cannot provide the ordinary alternative: Apple keeps its sheet onscreen while the session is active, while D11 invalidates command access once scanning ends. [Apple’s Core NFC walkthrough](https://developer.apple.com/videos/play/wwdc2019/715/).

   **Fixing decision:** authorize commands to the already claimed tag through the scan’s bounded authority, including commands caused by its discovery event. Preserve restrictions on starting independent sessions. This must be settled now for the advertised tier 2, separately from the explicitly deferred same-touch NDEF write.

3. **MATERIAL — §3 D6 and §5 D11–D12: concurrent claims lack a compatibility policy.** One session can request the default `NFCNDEFReaderSession`, while another requests `apple.polling`, requiring `NFCTagReaderSession`. Apple permits only one active reader session of any type. [Apple’s session documentation](https://developer.apple.com/documentation/corenfc/nfcreadersession-swift.class). Android similarly applies `skipNdefCheck` to the activity’s reader configuration, conflicting with another claim’s ordinary NDEF acquisition. [Android documentation](https://developer.android.com/reference/android/nfc/NfcAdapter#enableReaderMode(android.app.Activity,%20android.nfc.NfcAdapter.ReaderCallback,%20int,%20android.os.Bundle)).

   These choices change what existing claims can detect and whether their native session survives; they cannot safely remain an implementation’s arbitrary choice.

   **Fixing decision:** share only compatible configurations and reject incompatible additions as busy. Specify compatibility across scans, writes and future card emulation. Also reconcile D5’s promised sheet closure after success with another surviving claim.

4. **MATERIAL — §2 D5, §3 D7, §11 drive 16: Android cannot guarantee that multiple tags remain untouched.** Android’s public reader callback supplies one `Tag`, without a field inventory or tag-count operation. The named API therefore cannot establish that the selected tag is alone before writing or permanently locking it. This limitation follows from the documented [ReaderCallback interface](https://developer.android.com/reference/android/nfc/NfcAdapter.ReaderCallback#onTagDiscovered(android.nfc.Tag)); the universal refusal guarantee is unsupported.

   **Fixing decision:** retain multi-tag refusal where the platform exposes multiple detections, and explicitly document Android’s controller-selected behavior. Change drive 16 accordingly. A substitute that always refuses two tags cannot prove this production guarantee.

5. **BEYOND — §1, D4/D7 and §12 stage 1: the supposedly built web cancellation seam loses these calls.** The synchronous gesture branch directly invokes implementations at [modules.js:722](/private/tmp/claude-501/-Users-ccheever-projects-exact2/f4b5c629-4ed6-4746-9045-74f6106a629d/scratchpad/nfc-r1/capsule/host/web-js/modules.js:722), bypassing request tracking at line 438, which supersession relies on. Data calls likewise omit caller identity at [modules.js:862](/private/tmp/claude-501/-Users-ccheever-projects-exact2/f4b5c629-4ed6-4746-9045-74f6106a629d/scratchpad/nfc-r1/capsule/host/web-js/modules.js:862); their `kept()` predicate is checked after completion.

   A focused in-memory probe using the actual dispatch code confirmed cancellation for ordinary Contract sends, but none for superseded gesture sends or abandoned data sends. Consequently an abandoned scan can retain its claim, and Shelf’s abandoned data-code write can still modify a later tag.

   Make lifetime cancellation common to all dispatch routes while preserving synchronous gesture invocation. Add bound-implementation drives for both gesture-scan supersession and `tagBook` abandonment before relying on this seam.

6. **BEYOND — §3 D6 and §12 stage 3: Android exposes resume without the matching pause notification.** Stage 3 enables reader mode on `resumed()` and disables it on `foreground(false)`. However, [ExactActivity.kt:474](/private/tmp/claude-501/-Users-ccheever-projects-exact2/f4b5c629-4ed6-4746-9045-74f6106a629d/scratchpad/nfc-r1/capsule/host/android/canvas/src/main/java/dev/exact/canvas/ExactActivity.kt:474) calls `Extensions.paused()`, which only flips a Boolean at [Extensions.kt:538](/private/tmp/claude-501/-Users-ccheever-projects-exact2/f4b5c629-4ed6-4746-9045-74f6106a629d/scratchpad/nfc-r1/capsule/host/android/canvas/src/main/java/dev/exact/canvas/Extensions.kt:538). Visibility changes arrive through `onStop`, which need not follow a pause: a translucent activity can leave Exact visible. [Android lifecycle documentation](https://developer.android.com/guide/components/activities/activity-lifecycle#onpause).

   The extension cannot promptly perform the promised write cancellation at that transition. Add an explicit resumed-state notification, use it for NFC admission and claim suspension, and test pause without stop.

7. **IMPLEMENTATION-PHASE — §2 D2 and §8 D16–D17: preserve text-only Contract writes when implementing bytes refusal.** The inherited refusal operates by name, but `write`’s nested signature contains string-or-bytes data. Current binding generation constructs one options shape per name at [typescript.mjs:1241](/private/tmp/claude-501/-Users-ccheever-projects-exact2/f4b5c629-4ed6-4746-9045-74f6106a629d/scratchpad/nfc-r1/capsule/js/bake/src/typescript.mjs:1241). Stage 0 must provide a Contract-safe projection or equivalent declaration mechanism, so bytes refusal does not remove text writes wholesale. The particular representation does not decide readiness.

NOT READY
