The length-param path works. Duration and easing overrides never reach the rows, and an icon param whose default names another icon makes every edit rebuild.

1. **P0** — A duration or easing override is folded into the theme and then ignored where the row is written. `contract/lower/src/motion.rs:75` calls `add_to` and folds the default only. The loader substitutes that value in `contract/cli/src/sources.rs:176` before `declare_theme` applies the `params` block. Input: `fade: duration = "duration.fast"` (`duration.fast = 150ms`), row `transition="opacity param.fade"`, design line `PostButton.fade = 300ms`. The built transition is `150ms`. Fix: run the same layup as the compiler (override in place of the default, then fold) inside `motion::tokens` before `substitute`.

2. **P0** — Icon references are resolved too early, and `plan` never resolves them. `contract/lower/src/params.rs:120` copies an icon source inside `add_to`. `contract/lower/src/theme.rs:251` and `contract/cli/src/tamber_params.rs:33` apply the `params` line after that, so the copy is overwritten. `tamber/src/params.rs:66` has no copy step at all, so `foldable` (`tamber/src/session.rs:306`) gets `tamber-kind`, returns no fold, and `plan` (`tamber/src/session.rs:217`) classes every edit of that file as rebuild. Scrubs then 409. Input A: `glyph: icon = "icon.home"` and an `icons` token `icon.home`, no override — a color `set-token` is `rebuild`. Input B: `Button.glyph = icon.star` while `icon.star` is an icon token — the build refuses `tamber-kind`; the same text as a default succeeds. Fix: one helper that applies `params` lines and then resolves icon names, used by the compiler, `tamber_params::laid`, and `tamber::params::laid`.

3. **P1** — The two resolvers and the two layups disagree, so one param can be two lines. `tamber/src/params.rs:53` treats a short name as ambiguous only when two params have that short name, and `laid` keeps the first match (`tamber/src/params.rs:82`). `contract/lower/src/params.rs:398` refuses a short name when two components share the name, whichever has the param, and the compiler (`contract/lower/src/theme.rs:265`) and `tamber_params::laid` keep the last match. `param_names` (`contract/cli/src/tamber_ops.rs:156`) rewrites against the file before any op is applied, and `set_param` (`tamber/src/edit/params.rs:24`) matches the raw string. Input: `a.contract` `Card` has `inset`, `b.contract` `Card` has `gap`, design line `Card.inset = 9px` — the build is `tamber-param-ambiguous` and stays `4px`; `plan` applies `9px`. One transaction `set-param PostButton.radius=8px` then `set-param post.contract#PostButton.radius=4px` writes both lines; `plan` reads `8px`, the build reads `4px`. Fix: one resolver; match an existing line by the param it names; re-resolve each op against the text the previous op left; one winner.

4. **P1** — A new `params` line is refused when the block is not in `fmt`'s exact shape. `params_header` (`tamber/src/edit/params.rs:13`) requires the raw line to be `params`, while the parser strips a trailing comment (`tamber/src/syntax.rs:164`) and `tamber fmt` writes `params  // comment` (`tamber/src/fmt.rs:73`). A new entry is always indented two spaces (`tamber/src/edit/params.rs:31`), not to the block's indent, and it is inserted at the last token line, not after the block's trailing comments (`add-token` uses `block_end`). Input: a formatted `params  // overrides` plus `PostButton.radius = 8px`, then `set-param Row.gap=1px` — a second `params` block, and `check` refuses it. The same op on a block indented four spaces mixes indents and is refused the same way. Fix: find the header the way the parser does, take the entry indent from the block, and insert with `block_end`.

5. **P1** — Range errors miss a covered `when` and point at the wrong line. `folded` (`contract/lower/src/params.rs:280`) walks only winning tuple values and stops at the first failure; the compiler always records the name line (`contract/lower/src/theme.rs:269`). `param_values` (`contract/cli/src/tamber_ops.rs:188`) passes `&[]` and, on that path, emits no line (`contract/cli/src/tamber_ops.rs:193`). A `when` on a duration or an icon is reported on the synthetic name line `1 << 29`, and `design_refusal` (`contract/lower/src/theme.rs:684`) turns that into the component's default span. Input: range `0..40`, axes `density` and `size`, lines `when density=compact: 80px` plus `when density=compact size=small: 8px` and `when density=compact size=large: 8px` — `80px` never wins a tuple and is accepted. `set-param PostButton.radius=80px` returns `tamber-param-range` with no line. `set-param` of `PostButton.fade` with `when density=compact` returns `tamber-motion-axis` at line 536870912, or on the contract default, which has no `when`. Fix: check every `when` value, attribute the diagnostic to that line, and pass those spans from `param_values`.

6. **P1** — `explain` and `uses` do not answer an icon param, and the error leaks the hash. `lookup` (`contract/cli/src/tamber_serve.rs:699`) turns a resolved param into `param.f<hash>…`. `uses` (`contract/cli/src/tamber_serve.rs:949`) and `explain` (`contract/cli/src/tamber_serve.rs:923`) look only at `folding.tokens`. Icons are not there. `present` (`contract/cli/src/tamber_serve.rs:623`) runs only on `Ok`. An ambiguous short name is `Err` from `resolve` and falls through as a design token (`tamber_serve.rs:705`), so the reply is `no token`, not `tamber-param-ambiguous`. Input: `explain` or `uses` of `Button.glyph` — `no token param.f……Button.glyph`. Fix: resolve icons the same way `resolve` does, answer with the full name, and run `shown` on the error.

7. **P1** — `pinned` does not mark what D14 marks. `contract/cli/src/tamber_params.rs:126` splits the raw default, keeps words that are theme tokens only, and uses `contains` on the base value, not the `when` lines. Input: `glyph: icon = "icon.home"` set to `icon(sf "star")` — `pinned` is `[]`. `ink` set to `ink.muted` is not pinned either, because `ink.muted` contains `ink`. A base value that still says `radius.md` with `when density=compact: 8px` is not pinned. Fix: words of the default that name a token or an icon, absent from the words of the set value and its `when` lines.

8. **P2** — The new tests never leave the length happy path. `tamber/tests/it/edit_params.rs` and `contract/cli/tests/it/tamber_set_param.rs` do not build a duration row, an icon param, an ambiguous short name, a commented or four-space `params` header, a dominated `when`, or the line on a range diagnostic. `docs/tamber-protocol.md` (the *1.10* param bullet) says every non-motion param is live and scrubbed and that `explain` and `uses` answer for a param.

RIGHT WITH CHANGES
