1. **should-fix** — `host/linux/src/presenter/preferences.rs:264`. The fallback drain drops the tail and can stamp `turned` before this turn's draw. `trace_scrub` flushes only when a fifth scrub arrives, printing the previous four with `turned` copied from each frame's commit time, then keeps the new one. A desktop scrub shorter than five frames prints nothing, and the last one to four frames of any scrub that never gets `scrub_frame_drawn` stay in `PENDING` until the process exits. On Android the same drain runs inside `serve_live`, which can apply a whole poll's frames before `Native_frame` reaches `scrub_frame_drawn`, so those lines never receive the real hand-off time. The queue itself is capped at four; it does not grow without bound, and a line is not printed twice. Flush only from `scrub_frame_drawn`, or at the end of a presenter turn that did not draw, and do not drain in the middle of the `serve_live` loop.

2. **should-fix** — `host/linux/src/canvas/jni.rs:430`. A reader turn that applies a scrub and then returns null never marks it drawn. `Native_frame` calls `scrub_frame_drawn` only when it returns a new buffer (and on op 22). The `None` return (`jni.rs:414`), the identical-stream return (`jni.rs:430`), and the same-drawing return (`jni.rs:442`) skip it. `swatch.fill` is applied in `poll` / `frame` and then drawn by the Kotlin view, not as a new op stream, so the line sits in `PENDING`. The next op 22 or a later unrelated stream stamps `turned` with that later hand-off, or the four-deep fallback invents `turned` from the commit time. Call `scrub_frame_drawn` on every path that actually ran `h.frame()`, including the null returns.

3. **should-fix** — `host/linux/src/presenter/preferences.rs:259`. A failed stderr write panics while `PENDING` is held, and every later line is then discarded. `eprintln!` panics if the write fails. On Android, stderr is the logcat pipe, so a dead reader is `EPIPE`. The panic poisons the mutex, and both `trace_scrub` (`preferences.rs:259`) and `scrub_frame_drawn` (`preferences.rs:279`) return on `Err` and drop that frame. Take the records out, drop the guard, then write with `writeln!` to stderr and ignore the error. On poison, use `into_inner()` so a later frame is still recorded.
