DO NOT LAND

1. **MATERIAL — Three operation kinds bypass the list check.** In [ListRowsIOS.swift:32](host/apple/Sources/ExactKit/IOS/ListRowsIOS.swift:32), `where` constrains only `.rank`; `.children`, `.content`, and `.frame` match unconditionally. A children-only batch moving a route’s header behind its body therefore skips synchronization and leaves the old bar visible. Header recognition depends on that order ([NavigationBarIOS.swift:77](host/apple/Sources/ExactKit/IOS/NavigationBarIOS.swift:77)). **Fix:** evaluate the list/ancestry condition inside the shared case. A Swift compiler probe confirmed this pattern error.

2. **MATERIAL — List ancestry does not establish projection independence.** [ListRowsIOS.swift:22](host/apple/Sources/ExactKit/IOS/ListRowsIOS.swift:22) accepts every descendant. But header projection recursively walks through lists ([NavigationBarIOS.swift:81](host/apple/Sources/ExactKit/IOS/NavigationBarIOS.swift:81)): changing a heading inside a plain list within a header leaves the native title stale. Likewise, disabling a list-row Back control changes `canInvokeBack`, but skips updating `hidesBackButton` ([NavigationBarIOS.swift:426](host/apple/Sources/ExactKit/IOS/NavigationBarIOS.swift:426)). **Fix:** exclude navigation dependencies—including projected headers, named Back/scroll targets, tablists and route owners—from the fast path.

3. **MATERIAL — Unconditional `.present` acceptance strands tab badges.** [ListRowsIOS.swift:31](host/apple/Sources/ExactKit/IOS/ListRowsIOS.swift:31) accepts presentation operations anywhere. A settled tab badge receiving only `present(opacity: 0)` becomes transparent, but its native badge remains: `TabFace.badgeText` reads `alpha > 0` ([NavigationTabsIOS.swift:65](host/apple/Sources/ExactKit/IOS/NavigationTabsIOS.swift:65)). Previously that batch cleared the badge. **Fix:** synchronize presentation changes affecting projected content; test opacity crossing zero in both directions.

4. **MATERIAL — First-draw deferral is missing from `syncOwed`.** Synchronization clears `nativeMoved`, then returns before presenting a cold-launch modal when `firstDrawMs == nil`, without setting `pendingSync` ([NavigationIOS.swift:328](host/apple/Sources/ExactKit/IOS/NavigationIOS.swift:328), [NavigationIOS.swift:339](host/apple/Sources/ExactKit/IOS/NavigationIOS.swift:339)). If post-draw data readiness produces only list rows, every condition in `syncOwed` can be false and the declared modal stays unpresented. **Fix:** retain pending synchronization across this return and test a row-only first post-draw batch.

5. **MINOR — Tests do not exercise the navigation gate.** [ListRowsIOSTests.swift:22](host/apple/tests/ExactKitTests/ListRowsIOSTests.swift:22) tests the classifier alone; removing its use from `Presenter.apply` would still pass. Negative cases omit children/frame/content outside lists. **Fix:** add those cases, mounted navigation regressions above, deferred-sync coverage, and flat-leaf/nested-list cases. Include tvOS, which shares the defects but is excluded by the test’s platform guard.
