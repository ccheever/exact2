1. **High — Synthetic expressions still receive the token rung.** [scripts/tamber-inspect.mjs:77](/tmp/rv-dt-t2b5-r2/scripts/tamber-inspect.mjs:77) assumes equality between `token.text` and `names[0]` proves a declared token. The compiler names synthetic tokens by their entire expression, and the runner preserves that name. Consequently, an own `color="color-mix(in srgb, ink 60%, black)"` passes this check and offers the expression as an editable token. The new test supplies `names: ["ink"]`, which misses the real report shape. **Fix:** distinguish declared tokens from synthetic entries, refuse the latter’s rung and link their dependencies. Test a compiled expression’s actual report.

2. **High — A served design digest does not validate current disk contents.** [scripts/tamber-inspect.mjs:56](/tmp/rv-dt-t2b5-r2/scripts/tamber-inspect.mjs:56) accepts any changed design file whenever the build’s design equals `designServed()`. After applying live edit B over baked design A, save incompatible or invalid design C. The compiler retains snapshot B on error, so this comparison still succeeds and the selection remains editable against C. **Fix:** retain the source digests associated with each accepted design snapshot and validate current bytes against them; track scrub previews separately. Matching the applied design digest alone cannot waive the file check.

3. **Medium — Manifest-named designs without a `.tamber` suffix escape validation.** [scripts/tamber-inspect.mjs:51](/tmp/rv-dt-t2b5-r2/scripts/tamber-inspect.mjs:51) discovers the design by extension. Both `designPath()` and the compiler accept the filename specified by `app.json`; for `"tamber": "design/theme.tokens"`, changing or deleting that file leaves `designMoved()` returning success. **Fix:** identify the design explicitly through compiler metadata or its configured path, and fail closed when its required digest is unavailable.

4. **Medium — Cross-generation outlines remain incomplete, and the workaround violates map ownership.** [host/web/dev.js:236](/tmp/rv-dt-t2b5-r2/host/web/dev.js:236) initializes `channel.map` only after a reload. Normal first boot calls `client.adopt()` without setting it. If another page accepts a newer plan while this page’s reload is delayed or refused, its `ownSites()` fallback cannot resolve the outline. Meanwhile, [host/web/dev.mjs:359](/tmp/rv-dt-t2b5-r2/host/web/dev.mjs:359) gives selections only the current map, even when an older generation’s map is retained. The host-side map fetch also contradicts D4/D5 and `rules/DEFERRED.md`’s explicit prohibition; its search costs map nodes × requested locations on the page. **Fix:** retain and resolve plan/map pairs on the server, including the initial bake, and send each recipient its own qualified sites.

5. **Medium — An outstanding map fetch can outline a replacement generation or resurrect marks after Escape.** [host/web/dev.js:631](/tmp/rv-dt-t2b5-r2/host/web/dev.js:631) captures view/site associations before awaiting `ownSites()`, then uses those IDs against the current `exact.views` without rechecking generation or inspect mode. Reloads reuse view IDs, and local Escape can run during the fetch. A late response therefore outlines unrelated replacement nodes or creates marks after inspect has closed. **Fix:** capture generation and inspect identity, revalidate after the await, and discard obsolete work.

6. **Medium — A valid empty outline cannot clear existing marks.** [host/web/dev.js:633](/tmp/rv-dt-t2b5-r2/host/web/dev.js:633) returns before `unmark()` for both unavailable mappings and empty site sets. After outlining a token, sending the accepted request `outline {client, at: []}` leaves its previous boxes visible. Selecting a token with no uses has the same effect. **Fix:** distinguish an unavailable mapping from a valid empty result; clear marks for the latter.

7. **Medium — Outline ownership and disconnect cleanup remain missing.** [scripts/tamber-builds.mjs:324](/tmp/rv-dt-t2b5-r2/scripts/tamber-builds.mjs:324) receives no client identity and records no outline owner. Client A can own inspect mode, client B can replace its outlines, and B’s disconnect clears nothing because `owners()` and `clear()` track only pins and inspect. Write-scope enforcement and logging fixed only part of the first-round finding. **Fix:** record the latest outline’s owner and sequence per build, and clear that owner’s marks on disconnect without disturbing newer commands or A’s inspect mode.

8. **Low — The integration assertions still do not prove “every copy outlined.”** [scripts/tamber-server.test.mjs:485](/tmp/rv-dt-t2b5-r2/scripts/tamber-server.test.mjs:485) checks only a minimum overlay count. Wrong targets, extra marks and misplaced rectangles satisfy it. The test uses one build, and waiting for `plan ready` does not establish which generation the page accepted. **Fix:** use repeated instances and two running plans, wait for reported generation identity, and assert exact targets and rectangle alignment, including clearing and delayed-response cases.
