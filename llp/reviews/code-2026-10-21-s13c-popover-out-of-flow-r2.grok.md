**VERDICT: WRONG**

The out-of-flow popover, the sticky exclusion, the root percentage, and the hoist dirtiness all hold on the paths that were landed. Three kernel holes are still wrong.

1. **should-fix.** A top-layer popover and an absolute ancestor hoisted to the same owner are placed in `NodeId` order, and a lower popover id is placed before that ancestor has recorded its static position. `refresh_hoists` sorts absolutes by id (`kernel/src/layout/hoist.rs:25`) and, only for `top_layer`, walks through positioned ancestors to the tree root (`hoist.rs:34-44`), so both land on that root’s hoisted list. `place_hoisted` walks that list (`vendor/taffy/src/compute/common/absolute.rs:173`). `hoisted_absolute` returns `None` when `static_positions` has no entry (`vendor/taffy/src/tree/taffy_tree.rs:934`), and the parent also skipped `place` because the child is top-layer, so the popover is not placed. On a first layout that is a zero box; if a stale static position is still stored, it is placed from that and from the ancestor’s not-yet-updated location. The root then caches the pass, and nothing marks it dirty, so the miss sticks. Parent-before-child creation works, because the ancestor is placed first and records the static position during its own layout. It fails when the absolute wrapper is allocated later than the popover (a wrap or a reparent). A relative ancestor, the root’s own child, and a popover inside a sheet or other block root do not share that list: those ancestors are laid out before the root’s `place_hoisted`, or they are a different tree top.

2. **should-fix.** A top-layer child of a positioned grid records the grid-area static position, then is only hoisted. `static_rect` is the grid area whenever the grid contains absolutes (`vendor/taffy/src/compute/grid/mod.rs:796-805`), and the top-layer branch still stores that position (`grid/mod.rs:811-826`). The comment above it says the content box is the static position when the grid is not the containing block. Flex and block always record the content-box position (`vendor/taffy/src/compute/flexbox.rs:3206`, `vendor/taffy/src/compute/block.rs:1747`). This moves auto-inset placement. Percentage size still resolves against the root.

3. **should-fix.** Cover compensation still treats the parent as the containing block, and it now applies to every non-sticky popover. `top_layer::apply` runs first and forces `position: absolute` (`kernel/src/kernel/cover.rs:221-223`). The block at `cover.rs:253-267` then adds the immediate parent’s `Edges` cover onto length insets. Those insets resolve against the tree root. That matches a popover whose parent is the covered root; a nested edges-covered parent adds that parent’s cover to an inset measured from the root. `positioned_children` (`cover.rs:385-388`) restyles only children whose authored position is absolute, so a later cover change leaves a popover that is not authored absolute on its old length insets. Auto and percentage insets are left alone (`LENGTH_TAG` only).

4. **nit.** In-page Linux paint still adds ancestor scroll while walking a popover (`host/linux/src/paint.rs:1234-1241`). An explicit inset the kernel placed against the root therefore scrolls with the scroller. Auto insets still paint where the popover was written. Shell mode covers every popover whole (`host/linux/src/bars.rs:120-124`), so those are not painted. `paint/lift.rs` is drag-reorder. Terminal layer paint, the iOS lift, and Mac `PositionArea` place from the popover’s size and do not apply that scroll.

5. **nit.** `place_hoisted` unions the popover’s scrollable overflow into the owner (`vendor/taffy/src/compute/common/absolute.rs:175`), and publication uses that rect as content size (`kernel/src/layout/publication.rs:144`). A popover whose margin box extends past the root, one an intermediate overflow ancestor used to clip, lengthens the page’s scrollable content. A direct child of the root already contributed that way.

6. **nit.** `set_hoisted_absolutes` still says every box between the parent and the owner is static (`vendor/taffy/src/tree/taffy_tree.rs:1117-1121`). The top-layer walk hoists through positioned ancestors, and the origin sum at `taffy_tree.rs:945` is what keeps that placement aligned. `cover.rs:287` cites `style::taffy_style` for the popover skip; the predicate is `style::top_layer`.

What holds: an intermediate box on a hoist path cannot be a replay boundary (`kernel/src/layout.rs:717-718`, `kernel/src/layout/absolute.rs:161-162`), so editing it falls through to the root and `place_hoisted` runs again. The root’s own child is placed once. A sheet or `NSPopover` block is its own tree top; both-axis `AtMost` still clears insets and shrink-to-fits (`kernel/src/kernel/block.rs:166-200`). The relative-parent percentage test matches the root’s padding box. Opening or closing `popover` restyles the box and its covered ancestor. iOS `inFlow` uses the same sticky exclusion. PATCH 63 is the next patch number, the `Style` field is on `DEFAULT`, `PartialEq`, and both `CoreStyle` impls, and block, flex, and grid are the only absolute-placement sites. `engine_hash` omits `top_layer`; the interner still separates those styles by equality (`kernel/src/layout.rs:439`). Android has no popover geometry path of its own. No remaining test still expects an open popover to occupy its parent’s flow. Nothing covers the inverted-id hoist, a positioned grid’s static position, or a percentage against a sheet root.
