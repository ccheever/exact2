1. **MATERIAL — D3, §§3–4: the shared list budget needs substantially more implementation work.** The JS emitter generates native `.map`/`.filter` calls without a counter ([code.rs:433](/Users/ccheever/projects/exact2/.claude/worktrees/agent-ae5e6cce2a46e6a63/host/web-js/src/code.rs:433)); `x_join` and `x_includes` are likewise unmetered ([rt.js:1287](/Users/ccheever/projects/exact2/.claude/worktrees/agent-ae5e6cce2a46e6a63/host/web-js/rt.js:1287)). On Rust, ordinary stdlib calls receive neither the step counter nor the composite-value accounting; `join` has special VM handling ([vm.rs:763](/Users/ccheever/projects/exact2/.claude/worktrees/agent-ae5e6cce2a46e6a63/runner/src/vm.rs:763)). A short `concat` can also exceed `MAX_VALUE_BYTES` through large shared elements while staying below the step limit. **Fix:** specify shared evaluation-budget plumbing on both executors, account for constructed values, and test combined/nested operations, early-exiting `includes`, and oversized composite results.

2. **MATERIAL — D2: output bounds are insufficiently specified, particularly for `replaceAll` and `padStart`.** `MAX_STRING` counts **UTF-8 bytes**, not UTF-16 units ([vm.rs:19](/Users/ccheever/projects/exact2/.claude/worktrees/agent-ae5e6cce2a46e6a63/runner/src/vm.rs:19)). A length check alone therefore cannot bound multibyte padding. Replacement substitutions can expand quadratically: replacing each character with its preceding or following text can exceed the budget from a small input. Calling JS’s built-in and checking afterward allocates the oversized result first. Also, Bun confirms `"abc".padStart(Infinity, "") === "abc"`: an unconditional rejection of an excessive target length would disagree with JavaScript’s empty-fill return. [ECMAScript’s padding algorithm](https://tc39.es/ecma262/multipage/text-processing.html#sec-stringpad) specifies that return. **Fix:** define conversion and early-return order, then checked preflight or bounded construction, with the final well-formed result measured in UTF-8 bytes.

3. **MATERIAL — D2, §3: optional-argument insertion cannot be a name-based parser rewrite.** Scoped actions/action props deliberately take precedence over roster functions ([types/lib.rs:790](/Users/ccheever/projects/exact2/.claude/worktrees/agent-ae5e6cce2a46e6a63/contract/types/src/lib.rs:790); LLP 1006 §2). I compiled two-argument actions named `slice` and `padStart`, invoked through `press=…`; both succeed. Appending the proposed defaults during parsing would change their arity. **Fix:** accept optional roster arities after name resolution and insert defaults only for resolved stdlib calls. Apply the same normalization in the Lean exporter, which currently emits the parsed argument list directly ([lean.rs:313](/Users/ccheever/projects/exact2/.claude/worktrees/agent-ae5e6cce2a46e6a63/contract/cli/src/lean.rs:313)).

For the open questions:

- **Q1 — Admit session-owned lists.** D3 is justified. LLP 1017.003 already admits bounded traversal through `map`/`filter`/`join`, so “construction versus traversal” is the wrong boundary. Use bounded pure value operations versus durable ownership, I/O, and domain algorithms. D1’s UTF-16 comparison and D4’s initializer-scope decision are also sound.
- **Q2 — Choose U+FFFD normalization.** It fits the existing scalar-string representation and avoids surprising runtime traps. Specify normalization of the completed operation’s result, not individual fragments: Bun confirms `"😀".replaceAll("", "")` must retain the emoji.
- **Q3 — Prefer linking by use.** The kernel already isolates these tables on wasm and documents approximately 3–6 KiB of cost ([case.rs:31](/Users/ccheever/projects/exact2/.claude/worktrees/agent-ae5e6cce2a46e6a63/kernel/src/text/case.rs:31)). Reusing the existing link mechanism preserves layering and the boot path; measure unused, formatting-only, and case-using apps. Excluding case conversion from Lean is acceptable if explicit; differential generators must omit unsupported calls, and list syntax changes must update the big-step proofs too.
- **Q4 — Use the appropriate web spelling per surface.** Prefer HTML’s `tabindex` for the authored attribute; retain `scrollLeft` for the DOM property. `emojiPicker` and `navigationKey` are Exact extensions and need their own naming rationale. Choose one spelling without compatibility aliases; a sweeping naming RFC need not block the actual focus fix.
