Next I’ll check the compiler’s tail-call path and the three app diaries against what stage 1 claims.Stage 1 fits the compiler that exists: a call statement already parses, tail inlining already splices a callee into one commit, and the plan, runner, and JS target can stay put. Four holes in the draft would make an as-written implementation break Caltrain or miss the diary refactors.

## Findings

1. **MATERIAL** — D1, D8, §4. The ambiguity refusal breaks Caltrain and contradicts byte-identical plans. D1 refuses a call whose name is both an action in scope and a host command, so that an action cannot silently shadow `focus` or `share`. Today the host command wins: `check_command` only looks for an action when the name is not in `HOST_COMMANDS` (`contract/types/src/checks.rs:986`). Caltrain, the v1 app, is that pattern: `action setScheme` calls the host command `setScheme(scheme)` (`apps/caltrain/app.contract:109`). A probe of that shape builds with exit 0 (`cargo run -q -p contract -- build /tmp/setscheme.contract --json`). Under D1 it becomes `type-call-ambiguous`, so stage 1 does not leave every in-repo plan byte-identical, and §5's "fix any in-repo refusal" would rename the action and change the plan anyway. The corpus action `reload` (`semantics/corpus/mutations/refresh.contract:16`) does not call `reload()`, so the refusal-at-the-call sentence does not save Caltrain. **Fix:** keep today's rule: a host command wins. Binding `press=setScheme` still reaches the action. State that in D1 and drop `type-call-ambiguous`, or limit it to a call that is not a host command.

2. **MATERIAL** — D1, D7, §3. A child calling its own action is not the edit the syntax row names. `tail::resolve` looks up a flat root action by the marked name (`contract/syntax/src/inline/tail.rs:217`). Child actions are renamed to `name#n` (`contract/syntax/src/inline.rs:42`, `:447`). `subst_stmts` copies a command's name through and does not rewrite it (`contract/syntax/src/inline/subst.rs:305`). The cited marking (`inline.rs:483` and `:875`) only rewrites an action prop in tail position; the loop is `c.props`, not sibling actions and not injects (`inline.rs:488`). After that pass, `helper()` inside a child still says `helper`. Resolution then misses it or binds another component's action. D7's sentence about passing capture parameters ahead of the arguments does not say when, which parameters (the `@capture:` list at `inline.rs:459`, minus shadowed names at `:594`), or how that interacts with hygiene. Root calls, which are the spreadsheet and files cases, do not need this: root actions keep their names. The §4 sibling-call test does. **Fix:** expand same-component calls before lift, in that component's scope, with the hygiene `tail.rs` already uses. Lifting then substitutes the expanded body once, so both actions share one capture list and nothing is prepended. Leave prop and inject calls to the post-lift mark, and walk every command, with `props` chained to `injects`. Delete the capture-prepend rule, or spell the before-lift order so an implementer does not invent the after-lift one.

3. **MATERIAL** — D3, §4. The stale-read walk does not say whether exclusive arms stay exclusive, and the spreadsheet refactor depends on that. The rule is "some path" writes the slot in another frame. The procedure says the walk is LLP 1088 D8's and "the union is taken after the branch." In `sends.rs` those are different: arms are unioned (`sends.rs:146`), and a sequential `if k == "ArrowDown"` then `if k == "ArrowRight"` is saved only by `exclusive()` (`sends.rs:25`, used at `:109`). Files' `listKey` and the spreadsheet's `clipKey` are written as sequential literal tests, not `else` (`x2apps/spreadsheet/app.contract:354`). Calling `move(1, 0)` from each of those arms is the diary's "move and scroll into view" extract. A bare union refuses the second call, because `move` reads `ar` and writes `ar` (`app.contract:164`). A guarded walk, with D8's literal test, accepts it. The D3 examples use `move(1); move(1)` on one path and never an exclusive pair. **Fix:** store writes with their guards and refuse only when the write's guard is compatible with the path to the read, including D8's sequential literal test. Add that pair to the §4 accepted examples: two `if k == "…"` arms that each call `move`. Count a member read (`book.active`) as a read of the slot.

4. **MINOR** — D8, §4. The byte-identity claim does not cover the programs whose bytes would move. Action parameter names are plan strings (`plan/src/builder.rs:507`, written from `contract/lower/src/lib.rs:364`). A tail call renames the caller's parameters to `name@c{k}` (`inline/tail.rs:82`). `Stmt::Call` lowered in its own scope has no reason to do that, so a tail-call app's plan changes even when the opcodes match. A scan of every `.contract` under the repo found no action that calls one of its action props, so §4's in-repo byte compare stays green while "tail-call users included" is unchecked. Non-call apps stay identical if finding 1 is fixed and actions with no call are left untouched, which `tail::resolve` already does (`tail.rs:77`). **Fix:** for an existing tail call, emit the same parameter names and the same opcodes as today (argument `let`s, then the callee body, no extra opcode). Put one tail-call fixture in the byte compare.

5. **MINOR** — D4, §7.3. 1,024 is enough headroom. The bound is the right shape. Counted statement-like lines: files' `listKey` is about 80 and that app's largest; the spreadsheet's 48 actions are about 304 together; mail's largest action is about 26. A chain that calls the next action twice crosses 1,024 near depth 10. No diary app is close. The draft does not say whether nested `if` and `match` arms count, or whether the check runs after the body has been built. The stated threat is exponential duplication, and a check after full expansion allocates that body before refusing it. **Fix:** count every statement node, arms included, and return `syntax-call-size` as soon as the running total passes 1,024. Keep the number. The converted spreadsheet and files should land in the tens or low hundreds.

6. **MINOR** — D5, D8, D10. Three diagnostics are specified more tightly than the AST that carries them. `type-call-arity` must say "2 argument(s) after the 1 curried at `go=move(id)`". `Stmt::Call` is `{ action, args, body, span }` (D8) and does not record the curry count or the binding span. Hidden `@capture:` parameters have `ty: None` (`inline.rs:518`); checking the full lowered argument list against the full parameter list cannot produce that sentence. `symbols` computes writes from the authored component's `effects()` (`contract/cli/src/symbols.rs:348`), while tail inlining changes only `expanded.root`. `Action::effects` does not walk a call (`contract/syntax/src/ast.rs:515`), and the plan allowlist is that set (`lower/src/lib.rs:374`). A `Call` arm that ignores its body type-checks and then rejects the callee's writes at runtime. `type-unknown-command` for a root action named in a child requires finding that action on another component; a child's scope lookup misses it, which is why the message is "not a host command" today (`checks.rs:994`). **Fix:** put the authored argument count, the curried count, and the binding span on the call. Compute `symbols` writes and calls from the expanded action, and teach `effects()` to walk `Call.body`. Search every component before saying the name is out of `Row`'s scope.

7. **MINOR** — D8, §3 types row. Parameter refinement is in the wrong phase if it runs while checking the body. Handler refinement runs before action bodies (`contract/types/src/component.rs:204`, bodies at `:213`). LLP 1088 §9.2 stays deferred, so a type learned while checking `go` does not flow back into `move(dr, dc)` when `move` was checked earlier with `?`. The diary actions already annotate parameters (`move(dr: number, dc: number)`), so the spreadsheet extract survives. An untyped helper, which is what an agent will write first, does not. **Fix:** gather call arguments in the same pass as handler refinement, before `check_body`. Say that D8's "does not check `body` again" still requires the callee's parameters to be refined first.

8. **NIT** — D10. The grammar already has the statement. `statement` includes `IDENT "(" arguments ")"` (`docs/contract-grammar.md:154`). What changes is the prose at `:169` ("a standalone call statement is a host command") and the D8 sentence at `:625` ("after tail calls are inlined"). D10 names the file and not those lines. `contract-for-humans.md:279` and `contract-for-agents.md:238` are the same sentence as the table row at `:580`. **Fix:** name `:169`, `:238`, `:279`, and `:625` in D10. No new syntax production.

9. **MINOR** — §1, §4, §6. The diary value is real, and it is smaller than the RFC. Files can become one helper. `openItem`, the Enter arm of `listKey`, `openFocused`, and `openPlace` repeat `location`, `remember`, `ahead`, `query`, `sel`, and `cursorPath` (`x2apps/files/app.contract:332`, `:269`, `:348`, `:364`). `openFocused`'s directory arm still omits `anchorPath = ""`, which is the bug the diary describes. One `arrive(path)` call per action does not cross a frame: `go` reads `location` after writing it in the same body (`:135`), and that same-frame snapshot is what pushes the place being left (`fn remember` at `:21`). D3 leaves that alone. Spreadsheet "close the editor" is three assignments (`editing`, `inBar`, `firstKey`) copied in `down`, `commitMove`, `editorKey`, and `openSheet`. The send is not one helper: `down` and `openSheet` send `committed` (`:229`, `:522`) and `commitMove` sends `edited` (`:288`), because LLP 1088 D8 already refused two sends of `edited`. A call does not put those back together. `followSelection(r, c)` is a clean extract if the caller passes `r` and `c`. `clipKey` calling `move` needs finding 3. Mail does not need a non-tail call. The row binds the root actions directly (`x2apps/mail/list.contract:143`). A row-local `dx`, reset before a last `if`, with `archive(id)` last in the arm, is the tail call that shipped on 2026-10-03. The RFC says so in §1. The §4 rewrite that moves `swipeDx` back into the row can be done by documenting that form. **Fix:** keep general same-component calls and non-tail prop and inject calls; they are what files and the spreadsheet need. In §6, say plainly that documenting the tail call is the mail fix, and that D6 leaves the spreadsheet's two mutations in place. The simpler design that gets this value is finding 2's order: expand same-component calls before lift, generalize the existing prop and inject mark off the tail, keep D3 at the call boundary, keep the host command winning, and leave Lean for stage 2. A runtime opcode, return values, and same-frame D3 are the right rejections.
