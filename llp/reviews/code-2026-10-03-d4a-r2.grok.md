## New finding

**MATERIAL — A match on a state copied from a choice is marked checked, the slot becomes an open string, and both seams admit a non-member.** `contract/syntax/src/inline/subst.rs:191-192`, `contract/types/src/choices.rs:208-209`, `contract/types/src/component.rs:117`, `contract/syntax/src/inline.rs:362-370`.

An authored match is not marked unless expansion changes its subject text. The root walk starts with an empty map and clones the match unmarked. A child match on a string or a literal is `type-match-subject` in `check_children`, which runs before `expand_all` (`contract/types/src/lib.rs:1213-1229`), so the mark cannot rescue it.

The mark is any syntactic change (`replaced != subject`), including a rename. Lifting writes `mode` → `mode#N` into the substitution (`inline.rs:362-370`), so this match is marked even though no use-site value was substituted into the subject:

```contract
component Child
  props
    k: "a" | "b"
  state mode = k
  view
    text match mode
      case "a"
        text "A"
      case "b"
        text "B"
component App
  view
    Child(k="a")
```

`check_children` types `mode` as `"a" | "b"` and the match is exhaustive. The use site accepts `"a"`, and also `flag ? "a" : "b"`. Expansion then re-infers the lifted initializer with context-free `infer` (`component.rs:117`): a literal is `string` (`lib.rs` `Expr::Str`), and two literals joined are `string` (`choices.rs:51`). `case` returns `bool` without inferring `mode#N` (`choices.rs:208-209`), so the expanded recheck never reports `type-match-subject`. That recheck is what rejected this program before the mark existed.

Lowering stores that slot as a string row with no fields (`contract/lower/src/lib.rs:313`, `556-559`). The type code is `"s"` (`host/web-js/src/types.rs:81`). `Value::conforms` accepts every string when the row has no fields (`plan/src/value.rs:245-250`). Rust `init_slots` and JavaScript `devSignal` therefore both keep a carried `"c"` or `"nope"`. The last arm is the unconditional else, so the view shows `B`. The same widening happens for `state mode = flag ? k : "a"`. Matching the prop, or a derive of the prop, stays closed: there is no slot, and the test evaluates the use-site value. The new test covers that derive (`choices.rs:183`) and does not cover `state mode = k`.

The comment on `Expr::Case.checked` (`contract/syntax/src/ast.rs:929-932`) says the replacement was checked at the use and that the test may be a `fn`'s. A rename is not a use-site check, and a `fn` body is typechecked on the original tree, not substituted before the check.

**Fix:** infer a lifted state initializer with `given` against the type the child already checked, so a member literal stays the choice and the plan row keeps its fields. In `case`, still infer a `checked` subject and require a choice (exhaustiveness may then trust the declaration). Do not set the mark for a pure rename.
