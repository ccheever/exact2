## MATERIAL

### 1. D6, D7. A held future voice has no node, and `End` calls `stop` on it

**Problem.** The first window is scheduled from the press (D3), which is exactly while the timestamp is still `{0, 0}`. Future hits in that window wait with no source node. A same-commit choke or `stopSounds` — the case D4 exists for — then calls `stop(when)` on a node that was never started. `stop()` before `start()` throws in all three engines, and a held `Play` that later `start()`s without its `End` plays the whole clip.

**Evidence.** D6: a future voice "waits in the glue until the timestamp is live." D7: "`End` calls `stop(when)`." On the press, Chrome and WebKit both report `{contextTime: 0, performanceTime: 0}` inside the `pointerdown` handler, and `start(0)` succeeds there. WebKit is still `{0, 0}` after `resume()`'s promise resolves, while `state` is already `"running"`. `stop()` with no prior `start()` is `InvalidStateError` in Chrome ("cannot call stop without calling start first"), Firefox, and WebKit. The §5 web test checks that a future voice waits; it does not check an `End` that arrives during the wait.

**Fix.** A held voice is a record `{id, when, stopWhen}`. `End` sets `stopWhen` and does not touch a node. When the timestamp goes live, `start(when)` and, if `stopWhen` is set, `stop(stopWhen)`. Never call `stop` on a node that has not been started.

### 2. D6, §1. Firefox's press matches neither timestamp branch

**Problem.** The downbeat is scheduled inside the press handler (D7). On Firefox that handler is a third state the formula does not cover, so the turn that starts playback has no rule.

**Evidence.** §1 correctly says Firefox's first timestamp is `contextTime` 0 with a live `performanceTime`. The live branch requires `performanceTime > 0` and the context `running`. The other branch requires `{0, 0}`. Measured at construction: `state` `"suspended"`, `{contextTime: 0, performanceTime: 243}`. Synchronously inside the click: still `"suspended"`, `{contextTime: 0, performanceTime: 472.92}`, `currentTime` 0, and `start(0)` succeeds. `resume()` is a promise; `resume()` observed synchronously leaves the context suspended with that live `performanceTime`. After the promise, `contextTime` is still 0 and `performanceTime` is 279.92.

**Fix.** Give the third state a rule. While suspended with a live `performanceTime`, schedule with the same formula, using `start(0)` for a due voice, without waiting for `"running"`. Keep the held-record `End` from finding 1, so a choke in that turn is remembered.

### 3. D8, §5. A store ipa never wraps the sound dylib

**Problem.** Following D8's gate, a release store build of drums copies a loose `libexact_sound.dylib`. App Store Connect rejects that package, and the iOS loader the spec points at looks for a framework first.

**Evidence.** D8 names `leftOut`, the load list, and the copies at `build.mjs:1213–1218` and `:1316`. The third site is `build.mjs:1350`: `if (ipa)` calls `wrapFramework` only for `[webLoadName, 'ExactWeb']` and `[videoLoadName, 'ExactVideo']`. The comment at `build.mjs:363` and `VideoModule.swift:303–307` names ITMS-90171. `embeddedModule` (`VideoModule.swift:308–312`) returns `ExactVideo.framework/ExactVideo` when that path exists, otherwise the loose dylib; the iOS video load uses it (`VideoModule.swift:29`). §5's production check only asks that drums carry `libexact_sound.dylib`.

**Fix.** Name `wrapFramework(…, soundLoadName, 'ExactSound')` beside the web and video pair, and load the arm through `embeddedModule(framework: "ExactSound", dylib: "libexact_sound.dylib")`.

### 4. D8. `AudioSession.swift` as specified does not compile into the Mac kit

**Problem.** Stage 3 runs drums on macOS. The new file is specified as the only `setCategory` caller, with default `.ambient` and no platform split. `AVAudioSession` is unavailable on macOS, so ExactKit fails to build there.

**Fix.** The category and the ring-switch behavior are iOS and tvOS only, under the same ifdef. Mac starts `AVAudioEngine` with no `setCategory`.

### 5. D7, D10, §5. The JS `state` reply has no voice table

**Problem.** Conformance compares `state.sounds` across the wasm runner, the JS runtime, and the Linux host. Following the text, the JS reply has `output` and no `voices`, `live`, or `recorded`, so that comparison fails.

### D3, D4. The natural end uses `at` while the effective start is `max(at, t)`

**Problem.** A past `at` can store an end before the start. The voice is born ended, and an `End` in the past cuts an attack that D6 says is never skipped.

**Evidence.** D3 defines the effective start as `max(at, t)`. D4 writes the natural end as `at + 1000 × frames / rate` (`:288`). The journal example `at 1250 (asked 1240)` implies the stored `at` is the effective start. D6 says a voice the mapping puts in the past starts from its first frame.

**Fix.** `ends` is the effective start plus `1000 × frames / rate`. A past `at` does not emit an `End` before that time.

### D2. "Clamped" cites a glue that refuses
