## Blocks

**[P1] `line-height` is always sent as `number`, so a length value is refused — `apps/design-tool/moves.ts:62`**

`kindOf` maps `line-height` onto `number` before it looks at the text. A bare number stays a number, which that row accepts. A length stays a length and is still declared `number`, because the `px` suffix is added only when the kind is already `length` (`moves.ts:33`).

Promoting a template row `line-height="16px"` to param `leading` sends:

```json
{ "op": "add-param", "component": "Card", "name": "leading", "kind": "number", "default": "16px", "file": "card.contract" }
{ "op": "set-row", "file": "card.contract", "at": { "line": 4, "col": 9 }, "sha256": "…", "row": "line-height", "value": "param.leading" }
```

`line-height="1.2em"` is the same pair with `default: "1.2em"`. The token fold rejects both: a dimension is a length, not a number (`tamber/src/measure.rs:313`, reached from `tamber/src/check.rs:1063`). The parent of `54d7784b9f` classified by the text, so both values were `length`, and `line-height` admits a length as well as a number (`kernel/src/style/theme.rs:247`, `theme.rs:270`). The hint at `contract/lower/src/theme.rs:1384` only says those rows take a number. `opacity`, `flex-grow`, `font-weight`, `-exact-press-scale`, and `-exact-press-opacity` are number-only (`theme.rs:234`), so forcing `number` there is right. `line-height="1.4"` is right as `number`. A keyword weight such as `font-weight="bold"` is still refused, as a number value that is not a number; the parent sent `length`, which that row also refuses.
