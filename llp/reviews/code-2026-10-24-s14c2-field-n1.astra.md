2. **MAJOR — Unicode trimming changes CSS meaning.** [icon_svg.rs:382](contract/lower/src/icon_svg.rs:382), [icon_svg.rs:404](contract/lower/src/icon_svg.rs:404)  
   `style="fill-rule:&#160;evenodd"` and `fill-rule="&#160;evenodd"` pass and become even-odd. U+00A0 is not CSS whitespace, so these values are invalid in CSS and leave the inherited/default rule. The same hole exists around property names and inside `! important`. [CSS whitespace definition](https://www.w3.org/TR/css-syntax-3/#whitespace)  
   **Fix:** use CSS whitespace consistently in validation, property reading and importance handling; reject remaining unsupported characters.

3. **MAJOR — colour functions are a character allowlist, not a value grammar.** [icon_svg.rs:318](contract/lower/src/icon_svg.rs:318)  
   `style="fill:none;fill:rgb()"` passes. The reader chooses `rgb()` and emits a filled template; CSS discards that invalid declaration and retains `none`. Separately, `fill="rgb(0,0,0,0)"` passes both validation and the [alpha check](contract/lower/src/icon_svg.rs:651), although it is fully transparent. `hsl(0,0%,0%,0)` behaves likewise. [CSS colour grammar](https://www.w3.org/TR/css-color-4/#rgb-functions)  
   **Fix:** validate component counts, numbers, units and separators, and carry alpha information into the translucency refusal. Add both invalid-override and comma-alpha cases.

4. **MAJOR — admitted `fill: inherit` bypasses the effective-fill checks.** [icon_svg.rs:335](contract/lower/src/icon_svg.rs:335), [icon_svg.rs:536](contract/lower/src/icon_svg.rs:536)

CSS draws nothing. A translucent or gradient ancestor can be hidden the same way. This existing hole remains explicitly admitted by the new grammar. [Inheritance semantics](https://www.w3.org/TR/css-cascade-5/#inherit)  
   **Fix:** resolve `fill: inherit` against the parent, as `fill-rule` already does, before checking paint.
