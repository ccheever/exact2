## What holds

Round 1 is in place. The Rust seam refuses a raw `held` mark the way it refuses a deadline (`logic/abi/src/lib.rs:303`, test `logic/abi/src/tests.rs:395`). On web-js an answer is held only while every fetch it has out is held and no loose fetch is out (`host/web-js/held.js:11-12`); `heldAsks` keeps a ticket only while its owner still points at it (`held.js:8`); mutations are named and listed in `state.pending` only when held (`host/web-js/agent.js:492-493`). The `fetch` wrapper rejects a bad `exactHeld`, and `exactHeld` together with `exactStream`, before it counts; a stream never counts; a synchronous throw calls `end` once; both fulfillment and rejection run `finally(end)` before the caller’s `then` (`host/web-js/ts-fetch.js:17-29`). Abort stays on the request signal. Wasm entries are incarnation-guarded (`host/web/glue.js:757`, `holds` at `glue.js:952`) and `op.held` is `Request::is_held()` (`host/web/src/batch.rs:632`). GPU-pending clock replies are named on both web hosts. Linux `clock land` is named (`host/linux/src/agent.rs:1049`). Every expect-failure branch names held requests (`scripts/agent-test.mjs:620-625`). The prelude checks the boolean before it claims the stream (`js/src/prelude.js:747`, `call.stream` at `770`). Unmarked fetches, storage, continuations, surfaces, native calls, auth, and a stream before its first message still count: `waited()` is in flight and not held (`runner/src/runner.rs:357`), and `is_held()` is only a plain HTTP request (`runner/src/request.rs:393`). Edited sources stay at or under 1499 lines; `scripts/agent.mjs` hooks `clock held` on the existing line (`agent.mjs:1198`).

`clock held` is one driver function (`scripts/agent-held.mjs`, called from `scripts/agent.mjs:1198`). It sleeps on real time and polls `state`. That poll does not move the virtual clock, and it does not fire a timer that is not already due, on web-js (the `state` case never calls `advance`), wasm, Linux stdio (`pump(p.host().now())` only commits replies; `Presenter::advance` is separate; `frame()` paints), or Apple (`fireClock`, `advanceIfDue`, and the display-link tick all refuse agent mode). It then runs `clock data`. The wait is the set of held tickets in flight at the call. A new held request started during the wait is not added. An unknown name throws. No targets means all of them. The bound is 20 s, or the last token `30s` / `30ms`. Past it the reply is `settled: false, reason: 'held'`, naming the targets still out. A reply that drops the ticket, including the server’s own timeout, counts. Design-tool test 1 and the scrub drive use it after `clock +1`.

## SHOULD

1. On the Android reader, a `state` poll can fire a timer that is already due. `CanvasHost::agent` runs `frame_held` after every request (`host/linux/src/canvas/agent.rs:130-136`). When the driver owns the clock, `frame_held` skips frame tasks, then if a runner timer, a scroll end, or a hatch `after` is due at the frozen now it calls `Presenter::advance(now)` (`host/linux/src/canvas.rs:1203-1210`). That fires it. A timer due in the future stays put, and the clock does not move past now. Linux stdio, which `host/linux/held.test.mjs` drives, does not take this path. The host’s own note says no timer fires between requests (`host/linux/src/canvas/agent.rs:22-23`).

2. A held request superseded during the wait counts as a reply. The driver snapshots ticket ids and deletes one when it leaves `state.pending`’s held entries (`scripts/agent-held.mjs:16-20`). Supersede removes the old ticket without a server reply, and the replacement is not in the snapshot, so the wait ends and `clock data` does not wait for the new held ask. A new held request that does not replace a watched ticket is correctly ignored. Under a frozen clock this is uncommon; the design-tool sequence asks once, then waits.

3. `docs/card.md:181` still tells a builder to use `clock settle` after a push and never to wait in real time. D9 (`llp/1016.000-answers-that-keep-coming.rfc.md:520-528`), the contract (`docs/contract-for-agents.md:2974-2978`), and the reference (`docs/reference.md:1094-1097`) say to use `clock held`. The card’s one-line ops list was updated; that paragraph was not.

4. `6faa397d71` adds `game/games/look-sparks-91443/` (contract, logic, proof, pins, no `app.json`, no `Cargo.toml`). Nothing in D9 or the held tests refers to it.

## NIT

1. The public grammar is `[<n>s]` (`llp/1016.000-answers-that-keep-coming.rfc.md:522`, help and the card). The parser also accepts a trailing `<n>ms` (`scripts/agent-held.mjs:9`). The bound has to be the last word, which matches the written grammar: `clock held 30s changes` is an unknown-target error.

2. The timeout reply is built in the driver (`scripts/agent-held.mjs:24`) and never passes through the host, so it has no `epoch` or `incarnation`. Other clock replies are tagged (`host/linux/src/agent.rs:161`). The success path returns `clock data`’s reply, which is tagged. The ruling’s fields are present either way.

3. An unpolled expect failure still prescribes ``clock +<ms>`` then `clock data` (`scripts/agent-test.mjs:622`). The held suffix is appended, and it does not say `clock held`.
