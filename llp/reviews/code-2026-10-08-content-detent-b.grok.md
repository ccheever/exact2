## Should-fix

`ExactViewIOS.rebooted` never resends the screen, and `fit` will not send it when the size matches the cache.

`host/apple/Sources/ExactKit/IOS/ExactViewIOS.swift:386` resends insets and fold segments because a new runner has neither, then calls `fit`. `fit` sends `session.screen` only when the size differs from `lastScreen` (`:346`). `ModalHost.reset` (`host/apple/Sources/ExactKit/IOS/ModalIOS.swift:612`) dismisses every sheet with `closeTop(refit: false)` (`:619`), so `fit` does not run and `lastScreen` stays the previous window size. Both restart paths do that reset, apply the new batch, then call `rebooted`: `Session.finishBoot` (`host/apple/Sources/ExactKit/Session.swift:818`, `:826`) and `presentCommitted` (`:903`, `:913`). The new kernel is already installed with `screen: None`.

Reload a plan whose first frame presents a `fit-content` sheet while one is already up (dev reload, `Session.apply`). `fit` computes the same window size, skips `exact_screen`, and `vh`/`svh`/`lvh`/`dvh`/`vmin`/`vmax` fall back to the sheet. The oscillation these commits remove comes back. A cold launch is fine (`lastScreen` starts nil). A reload whose first frame is not a fit-content sheet is fine too: `rebooted` sees `screen == nil`, sends the clear, and the next present sends the real size.

Set `lastScreen = nil` at the start of `rebooted`, before `fit()`. `booted` is already true, so `session.screen` is not dropped. The deferred `fit` from `present` then sees the cache already updated.

## Checked

Screen comes from `ExactView`'s own bounds (safe-area inset unless the page covers the whole view), not the sheet, and is sent before `resize` (`ExactViewIOS.swift:286–349`). Rotation, split view, and window resize all go through `layoutSubviews` → `fit`, which updates the screen and then the sheet; the screen does not depend on the sheet height, so that settles. Only `layers.last` counts: a fit-content sheet on top uses the window; a medium, large, point, or fullscreen sheet on top clears it. Before the first fit the kernel viewport is still the window, so the first measure matches even while `screen` is `None`. A zero-size controller returns before the resize (`:271`); `viewDidLayoutSubviews` fits again and still sends the screen first.

Every CSS length goes through `ViewportUnit::basis` (`viewport.rs:53`): height, min/max, padding, margin, flex basis, `min`/`max`/`clamp`, and `column-width`. Field minima and button padding resolve against `arena.env()` on that same pass, so a screen change remeasures them. Image and canvas CSS sizes are ordinary dimensions. An `svg` element's box is too; SVG geometry still turns a viewport unit into 0, which predates this diff and cannot follow the sheet. With `EXACT_AGENT=1`, `fit` sets `screen` to the same logical window it forces `size` to (`:296–300`), and iOS never resizes that window to the sheet. Web, Linux, and macOS never call `set_screen`. With `screen == None`, `basis` is the old viewport read.

Percentages of the route and flex-grow take an indefinite height in the trial (`geometry.rs:175`). The route's own height is forced to auto; its min and max stay and now bind to the screen, so `min-height: 100vh` opens at the maximum and stays there. The bottom host cover is added to padding and subtracted again in `emit_fitted` (`layout.rs:341–355`), so a detent change in that cover cancels. The keyboard shrinks the sheet frame, not `screenFrame`. `emit_fitted` still skips a fixed-length scroller that did not move (`layout.rs:325`) and resends an extent only when the height changes (`:359`). Presented transition heights are still applied (`geometry.rs:120`). Removing the classifier did not drop those.
