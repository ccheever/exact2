## Findings

**should-fix** — Also bind `::1`, and refuse to start if that port is taken. `scripts/tamber-remote.mjs:192`

The plain listener is only `listen(server, tunnel, '127.0.0.1')`. On this machine `localhost` resolves to `::1` first, and the Host allowlist at `scripts/tamber-remote.mjs:99` admits `localhost` and `::1`. A forward aimed at `localhost:<port>` (the usual `ssh -L` spelling) connects to `::1`, where this process is not listening: that connect returns `ECONNREFUSED`. Another process can bind `::1` on the same port and receive that traffic. Startup still succeeds; both sockets stay up. Once pairing exists, that other process would see the paired token. The dev server already treats this as fatal (`host/web/serve.mjs:1044`, `alsoOnIPv6Loopback`).

Fix: listen on `::1` with the same handler and abort startup on `EADDRINUSE`, the way the dev loop does. Keep the public URL as `http://127.0.0.1:<port>`. That stays inside loopback. Binding both addresses also stops a squatter from serving a page on `http://localhost:<port>` while this process serves `127.0.0.1`.

**should-fix** — If the tunnel port is taken after the TLS listener has bound, close that listener and name the flag that failed. `scripts/tamber-remote.mjs:175`

`openRemote` binds `--remote` first, then the tunnel. A failure at `scripts/tamber-remote.mjs:192` throws before `close` is returned. Callers only run `doors?.close()` after assignment, so the TLS socket keeps accepting through `tamber.close()` (up to about seven seconds) and the message is `cannot open the remote listener: EADDRINUSE` (`scripts/tamber-server.mjs:1060`, `host/web-js/dev.mjs:1028`, `host/web/dev.mjs:1495`). A tunnel-only collision exits with nothing left listening. The process does exit; the main port is not reclassified as a tunnel.

Fix: on any listen failure, close every server already pushed, then throw an error that names the address (`--trust-tunnel 7444: EADDRINUSE`).

## Security pass

1. **Tunnel requests stay remote.** `remoteHandler` always sets `{allowed: true, local: false, remote: true, tunnel: true, peer}` from the socket (`scripts/tamber-remote.mjs:140`). No forwarding header is read. `/__tamber/token` is not in `WIRE`, so the handler returns 404 before the wire. The wire would also refuse it: `GET /__tamber/token` requires `access.local` (`scripts/tamber-server.mjs:482`). Every POST on `/__tamber`, `/__tamber/subscribe`, and `/__tamber/events` is 404 when `access.remote` is set, including a correct local token (`scripts/tamber-server.mjs:491`). The real-wire test covers `POST /__tamber`. `/__dev`, the install page, and the app are not on this server; a probe of `/__dev/install` was 404 and the wire was not called. The design tool's static files are served, with `frame-ancestors 'none'` on HTML, same as the TLS door. `addPort` still labels canvas `{tunnel: false}` and throws without `--remote` (`scripts/tamber-remote.mjs:198`).

2. **The main loopback listener is unchanged.** The flag only adds this second server. The development gate is still built from the dev port and `--allow-host` (`host/web/dev.mjs:61`). With or without the flag, a request to the main port is judged the same way.

   **Any port is safe against a browser page and against DNS rebinding.** Admission is the hostname, not the port. Origin, when present, must be `http://<raw Host>`, port included (`scripts/tamber-remote.mjs:127`). A page at `http://localhost:3000` that `POST`s `text/plain` to `http://127.0.0.1:<tunnel>/__tamber` sends `Origin: http://localhost:3000` and `Host: 127.0.0.1:<tunnel>`. That is 403, and the wire is not called. The browser sets Host from the URL, so it cannot present `Host: localhost:3000` while connecting to the tunnel port. A rebinding name stays the attacker's name: `Host: 127.0.0.1.nip.io` is 404. `localhost`, `127.0.0.1`, and `::1` are not attacker DNS names. WHATWG aliases of loopback (`2130706433`, `127.1`, `0x7f000001`) are admitted as `127.0.0.1`, and a foreign or serialized Origin against the raw Host is 403. `0` parses as `0.0.0.0` and is rejected. A missing Origin is allowed, on purpose, for the non-browser end of the tunnel; a browser cross-origin POST sends Origin. There is no `Access-Control-Allow-Origin`. A simple POST also cannot attach `x-exact-tamber-token` without a preflight, and `access.remote` would still 404.

3. **Cookies, timeouts, binding.** Cookie stripping is the TLS door's path: `req.headers`, `headersDistinct`, and `rawHeaders` (`scripts/tamber-remote.mjs:119`). The tunnel test covers one cookie; the two-header case is tested on TLS through the same function. `limit()` is the same 64-connection cap and the socket timer (10s to headers and between requests, cleared while a response is written). A collision with the dev port or the TLS port fails the process (exit 1) and does not serve the tunnel on the main listener. `::1` is the gap in finding 1. A probed `::1` connect was refused while `127.0.0.1` connected.

4. **The banner is loud enough and leaks nothing.** It is one stderr line, printed at listen time: `TRUSTED TUNNEL ON: http://127.0.0.1:<port> takes a tunnel's requests (--trust-tunnel). Only paired tokens work through it, never this machine's local token; point only a tunnel you run at it.` No token, fingerprint, or design. On the JS dev loop it is printed just before the URL lines; on the wasm loop, just after.

5. **Parsing, help, docs, QUEUE.** `remoteArgs` takes one `--trust-tunnel <port>`, `0`–`65535`, and rejects a missing or non-numeric value (`scripts/tamber-remote.mjs:74`). `web`'s `guardFlags` knows the flag takes a value. `tamber serve` skips that value when it finds the app directory (`scripts/tamber-server.mjs:1051`). Help lists it on `web --help all` and on `tamber` (`scripts/help.mjs:93`, `scripts/help.mjs:339`). The protocol doc matches the behavior (`docs/tamber-protocol.md:173`). The QUEUE entry is the canvas port, TLS-only in stage 10 (`QUEUE.md:138`). The help parity failure is finding 3.

6. **Tests prove the commit's stated cases and miss the ones in the nit above.** `scripts/tamber-remote.test.mjs` (13 tests) passed: no door without the flag, the banner prefix, remote+tunnel access, cookie stripped, `/` and `/__tamber/token` 404, a mismatched Origin 403, a non-loopback Host 404, and the real wire 404 for the local token on `POST /__tamber`. Timeouts are the shared `limit()` path, covered for TLS and not repeated on the plain socket.
