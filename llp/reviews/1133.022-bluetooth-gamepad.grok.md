If the sheet path never creates the manager until `requestDevice`, a granted install with the radio off never shows that line. **Decision:** on the sheet path, once `CBManager.authorization` is determined, make the one manager and map its state to `radio`. In AccessorySetupKit's mode, do not make it until an accessory is set up, as D18 already says.

10. **IN-DELTA, MINOR.** The summary recipe brings back the commit race D2 removed. Lines 46–48 send `playEffect` only when the `pads` resource's `current` is set. D2 (lines 235–239) says the implementation reads `current` when the send arrives, so the resource need not have committed. §10 (lines 660–662) sends whenever a pad is connected and ignores `NotSupportedError` only. A pad that is connected but unused (a stick does not set `current`, D2 lines 232–233) then fails `NotFoundError`, and the summary's guard skips the rumble whenever the resource is a commit behind. **Decision:** the action sends with no `index` and ignores `NotFoundError` and `NotSupportedError`. It does not read `pads.current` first.

11. **IN-DELTA, MINOR.** Stage 1 (lines 1325–1327) runs the shared-index check in Chromium on the JS target. `host/web/gpu-pads.js` is the wasm host's canvas poll, and §1 says that host binds no extension modules. The JS runtime has no pad sink that shares the browser's `Gamepad.index` with a canvas `InputEvent::Pad`. The check cannot fail there. It is real on macOS, the Android emulator, and Linux `uinput` (stages 2 and 5). **Decision:** do not schedule the shared-index check on the JS target until a canvas and the module share a page. Keep it on the bound native fixtures.

12. **IN-DELTA, IMPLEMENTATION-PHASE.** The abridged declaration (lines 510–519) still requires `"index": "number"` on `playEffect` and `setLight`, and it omits `resetEffects`. The substitute's `"preempts": "index"` (line 517) has to resolve an omitted index to `current` before it keys the timer, or drive 3's index 0 does not match. The normative text is D1 and D2. Spell the declaration to match when the package is written.

## Beyond

Package-emitted module events stay `CallOrigin::Device` (`runner/src/runner/modules/events.rs` lines 71 and 107). This RFC routes around that for lights. A later module that wants an app-origin send from its own event meets the same refusal. Marking the event an activation does not change a package emit, because `raise_emitted` passes `Device` before that match. There is still no standing exception.

The wasm host still binds no extension modules (§1, §19 lines 1266–1267). Motion already stopped there. Keeping Beacons' web proof on the JS fixture is the right local call.

The world's message origin is now D10 item 6, and §19 offers it to every device a world drives. It becomes that standing seam once it is the single sticky rule in finding 1. As written, the two readings are the defect.

The one native-slot handler is settled for this RFC by D10 item 5: desktop loops install a dispatcher, and a shell's inbox is the other half of that same handler. Later Linux and Windows modules wait on that landing, which §19 already records.

Claims and leases are the right shape for a process-wide device under per-session `destroy`, matching recording's capture. They hold for Bluetooth's link. They hold for pads only after a claim follows device identity (finding 4) and Android's table outlives the activity (finding 2). §19's request that LLP 1133.001 state the rule once for every module whose device outlives a session is the right place for it.
