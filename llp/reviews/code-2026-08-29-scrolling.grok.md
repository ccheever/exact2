## Verbatim review

The full review brief was truncated in the message; I’ll read the offloaded prompt so the review covers the complete source.The prompt file is longer than one read; I’ll continue from the truncation so the remaining source and specs are in the review.## Overall assessment

Nested scrolling on macOS is implemented as a hand-rolled `scrollWheel` policy plus a content-size heuristic, while layout still follows Taffy and the web host still lets CSS/the browser scroll. The chaining idea matches `overscroll-behavior: auto`, but the consume path can move **both** the inner scroller and the page, the new root `width: 100%` rule is not CSS `width: auto`, and `content_size` is not CSS scrollable overflow. Smoke only exercises phase-less, directly dispatched wheels and would still pass a double-scroll. Native is not swept to the web.

## Findings

1. **HIGH —** `Presenter.swift:209-219` (`ChainingScrollView.scrollWheel`). After `canConsume` is true the view always calls `super.scrollWheel`, then, if `contentView.bounds.origin` has not changed yet, applies the full delta itself. AppKit’s nested-`NSScrollView` path is exactly the one that often **does not** move this clip view and instead scrolls the **enclosing** scroller (the window viewport), or defers/animates momentum without an immediate origin change. One event can therefore (a) scroll the page via `super` and the inner view via the fallback, or (b) have the fallback fight a later momentum/rubber-band update. Horizontal is included in the fallback even when the consume test was vertical-only. Resolution: if the inner scroller should consume, do **not** call `super`; `scroll(to:)` + `reflectScrolledClipView` only (and only for the consuming axis). Restrict any AppKit-owned path to events you have shown AppKit actually moves (`phase`/`momentumPhase` ≠ `.none` **and** origin changed, or equivalent). Never use “origin unchanged” as a proxy for “AppKit declined.”

2. **HIGH —** `kernel/src/style.rs:1196-1203` (`taffy_style`). A root with `width: auto` is rewritten to `Dimension::percent(1.0)`. CSS block `width: auto` sizes the **margin box** to the containing block (`used = offer − horizontal margin − border − padding` under content-box). `width: 100%` sizes the width **then** adds padding/border/margin. Spec defaults are CSS’s (`1001` §2; only `position` and `text_align` are declared deviations), and the scroll fixture root is `column … padding=12`. On macOS that extra 24px makes `fitDocument` grow the page past the viewport (`Presenter.swift:399-405` + `hasHorizontalScroller = true` at `385-386`); the web host does not use this Taffy rewrite (`index.html` + “the browser lays out”). Resolution: compute the CSS used width from the offer at layout time, or otherwise stretch the root the way a block does, not as `width: 100%`. Re-check `max_width`, horizontal margins, and `AttachRoot` (`txn.rs:1226-1237`) after that — `taffy_style` on attach is the right hook, the formula is wrong. **FLAG:** `layout.rs` and the default `box_sizing` are not in this dump; if the kernel defaulted to border-box against CSS, padding would not expand the border box but margins still would.

3. **MEDIUM —** `host/apple/src/host.rs:751-754` and `884-894` (`content_size`). Content size is the max of the node’s border box and **direct** children’s border-box extents. CSS scrollable overflow is the padding edge **plus in-flow/out-of-flow descendants** (abspos, a tall grandchild through `overflow: visible`, transformed descendants). Padding-bottom of the scroll container is not added when children already overflow (CSS Overflow: end-edge padding is in `scrollHeight` in the engines the web host follows). `content` is emitted only when `scrolls_by_default()` is true, so a `View` with `overflow_y` set never gets a document size or an `NSScrollView`. Resolution: union the same descendant set CSS uses (stop at a clipper), add the scroll container’s end-edge padding, and key host scrolling off computed overflow, not only `ScrollView`/`List`.

4. **MEDIUM —** `kernel/src/style.rs:1100-1108` vs `host/web/index.html:941` vs `Presenter.swift:248-256`. CSS: if `overflow-y` is not `visible`/`clip`, a `visible` `overflow-x` computes to `auto` (both axes clip). Taffy gets `Scroll` only on Y unless `overflow_x` is set; the web rule is `overflow: auto` (both axes); macOS always builds a vertical-only `ChainingScrollView` (`hasVerticalScroller = true`, no `hasHorizontalScroller`) and never reads `overflow_x`/`overflow_y` in the presenter. `overflow: hidden` on a `ScrollView`/`List` still scrolls. Resolution: lower the CSS pairing in `to_taffy`; on web, set `overflow-x`/`overflow-y` from the rows (not a blanket `auto`); on macOS, create a scroller only when computed overflow is `auto`/`scroll`, enable the axes that scroll, and clip-only for `hidden`.

5. **MEDIUM —** `Presenter.swift:196-208`. Consume/chain is **dominant-axis only** (`abs(dy) >= abs(dx)`). CSS and the web host treat axes independently: at the vertical edge a remaining horizontal delta still scrolls the inner view; a vertical delta on a horizontally-only scroller chains. Here a mostly-vertical gesture at the Y edge forwards the **whole** event, so inner X is lost; the inverse swallows X that should chain. The `0.5` slop also chains while up to 0.5pt off the edge. Resolution: per-axis edge tests; split or partially forward the event; drop the slop or snap to the edge first.

6. **MEDIUM —** `Presenter.swift:191-194` and `216-217`. `scrollingDelta*` is used whenever it is non-zero. Precise trackpad deltas are points; a mouse wheel’s `scrollingDelta` is **lines**. The fallback subtracts that from `bounds.origin` as points, so a clicky wheel under-scrolls versus the browser’s typical line-height / ~40px tick (the smoke event is pixel-unit, so it hides this). Resolution: if `!hasPreciseScrollingDeltas`, multiply by line height (or the same px-per-line the web uses) before clamping.

7. **MEDIUM —** `Presenter.swift:382-389` and `248-256`. Window `viewport` is a stock `NSScrollView` with no `automaticallyAdjustsContentInsets = false`, no explicit `contentInsets = .zero`. Under a titled window the default inset shrinks `contentSize`, so `fitDocument`’s “never smaller than the viewport” min is not the clip’s visible size, and `ChainingScrollView`’s `doc − visible` max ignores insets. Nested scrollers inherit the same defaults. Resolution: turn automatic insets off (or feed the inset rectangle into layout **and** `maxX`/`maxY`). **FLAG:** window setup is not in this dump; this is certain only if `viewport` is the content view of a titled `NSWindow`.

8. **MEDIUM —** `main.swift:1244-1286` and `host/apple/smoke.mjs:1062-1069`. The experiment dispatches **phase-less** `NSEvent(cgEvent:)` via `scrollWheel(with:)`, not `NSWindow.sendEvent`. That is the path AppKit does not animate, which is why the fallback exists; it does not measure a real trackpad (phases, momentum, rubber-band) or prove hit-testing in the window. The harness never asserts that a **single** event moved inner XOR page (`direct→inner` is logged, not checked). `first(where: { $0.kind == "scroll" })` ignores `list`. The regex `via hit view \((\w+)\)` breaks if `String(describing: type(of:))` contains `.`. Default smoke does not load `scroll.contract` (`EXACT_PLAN` only skips Caltrain landmarks). Resolution: drive events through the window; assert per-event exclusivity and both node kinds; pin smoke to the fixture; do not claim trackpad chaining is covered. **FLAG:** `NSEvent` class name and default-app first `scroll` node were not executed here.

9. **MEDIUM —** `Presenter.swift:398-405` (`fitDocument`). Page document size is `contentSize` plus roots’ `frame.maxX`/`maxY`. CSS page overflow includes overflowing descendants (and abspos) of a non-scroll root. A root whose children paint outside its layout box does not grow the macOS page; the same tree on the web does. Combined with finding 2, a padded `width: 100%` root **does** grow the page horizontally. Resolution: size the document from the same scrollable-overflow union as the viewport, not only root frames.

10. **LOW —** Gaps the current shape makes expensive, even if v1 can omit the features: kernel still holds no offset (`1001` / “scroll always wins”), and `Host::boot_with` / `reset()` do not restore positions — reload restoration needs a stable host-side key that does not exist; `List` is a full `ChainingScrollView` of every child (`node.rs:141-143`, `Presenter.swift:248`), which fights future windowing; no `overscroll-behavior: contain`, scroll-snap, `scrollIntoView`, or keyboard/space page scroll (web and `NSScrollView` first-responder both have the last). None of these need to ship now; do not bake in APIs that assume inner offset is unrecoverable or that `List` == “all rows as views.”

## Disposition (orchestrator, 2026-08-29)

1. HIGH (fallback after `super` can double-scroll) — FIXED: a scroll node that can take the dominant axis scrolls itself deterministically and never calls `super`; it applies only the axes it can take (`Presenter.swift`, `ChainingScrollView`). Momentum arrives as further events and is applied the same way; rubber-banding on inner nodes is given up (LLP 1010 §3).
2. HIGH (`width: 100%` is not block auto width) — FIXED: a root's `width: auto` becomes `100%` under **border-box** sizing, so the border box fills the offer (the fixture root is 420 wide, was 444); margins on a root are not subtracted and an absolutely positioned root is exempt — both declared in LLP 1010 §1.
3. MEDIUM (`content_size` vs CSS scrollable overflow) — FIXED at the source: the kernel now publishes Taffy's `content_size` per node (`NodeRef.content`; padding and every descendant's overflow included) and the host uses it; `content` is emitted for every node whose effective overflow is not `visible`, not only `ScrollView`/`List`.
4. MEDIUM (overflow pairing, hidden, x) — FIXED: `to_taffy` pairs an unset `overflow_x` with a non-visible `overflow_y` (CSS Overflow §3); the presenter scrolls the axes whose effective overflow is `scroll`, clips for `hidden`, and reads effective overflow from the style dictionary, never the kind; the web's `overflow: auto` matches the pairing.
5. MEDIUM (dominant-axis only; 0.5 slop) — PARTLY: per-axis consumption within the view, slop removed; the *event* is still routed whole by its dominant axis (an `NSEvent` cannot be split) — declared in LLP 1010 §5.
6. MEDIUM (line deltas) — FIXED: `hasPreciseScrollingDeltas` decides; lines are scaled by 40 pt.
7. MEDIUM (content insets) — FIXED: `automaticallyAdjustsContentInsets = false`, zero insets, overlay scrollers on every scroll view.
8. MEDIUM (harness) — PARTLY: per-event exclusivity is asserted for the direct and hit-view deliveries, `list` nodes count, the regex accepts dotted type names, and the page is asserted not to move before the inner limit; events are still synthesized and phase-less, and the fixture is run by hand — both declared in LLP 1010 §4.
9. MEDIUM (`fitDocument` from root frames) — FIXED by 3: a root's `content` now carries descendant overflow; `fitDocument` still reads frames, which is correct once the root's own content is what the kernel lays out (declared: presentation transforms are not in either extent).
10. LOW (future seams) — RECORDED in LLP 1010 §5.
