On **d**, there is a genuine mismatch, not merely missing protocol plumbing. `CSS.getMatchedStylesForNode` describes inline styles, matched rules and inherited styles; `CSS.getComputedStyleForNode` returns property/value pairs. Neither is a general display format for “author / runner-resolved / platform-owned / unavailable.” A missing property does not explain *why* it is missing, and invalid or disabled CSS is not an honest substitute for an unavailable observation.

The decisive example is a native control whose runner reports inherited page colour while AppKit supplies its tint. Showing the inherited value as the control’s effective colour is wrong; pretending a platform selector overrode it also misstates Exact’s rules. A limited display of genuine declarations and observed values may work. **I do not know a stock Styles mechanism that presents all the required provenance faithfully without additional conventions.** That is the most likely reason this frontend loses to Tamber, but it does not invalidate the build-channel foundation.

**4. OVERSIGHTS**

- **Major — the frontend comparison can credit Chrome for improvements supplied by new backend reads.** Arbitrary tree browsing, instance targeting and additional host observations would benefit Tamber too. Comparing the completed prototype only against today’s inspector risks attributing those gains to Chrome. **Resolve:** record whether the chosen diagnosis improves because of newly available information or Chrome’s presentation of it. A second implemented frontend is unnecessary for that distinction.

- **Major — the identity tuple needs a lifetime that survives neither reboot nor replacement.** `Kernel` initializes incarnation to `1`; the runner explicitly warns that incarnations can repeat across host replacements. Apple inspection already keeps `ExactSession.generation` internally. The current selection report does not export that complete identity. **Resolve:** carry the host generation through requests, replies and selected-node reports, and exercise a same-plan reboot. - **Major — bounded responses do not yet imply bounded host work.** On macOS, targeted `layout(_:)` begins by calling the full `layout()`, which enumerates the presented views. The runner’s subtree read materializes the requested subtree; its shallow form returns one node rather than a bounded page of child records. **Resolve:** count the observation refactoring in the prototype budget and measure traversal work as well as response bytes. Trimming an already-built response does not meet the intended foundation. [AgentMac.swift](​/Users/ccheever/projects/exact2/host/apple/Sources/ExactKit/Mac/AgentMac.swift), [runner tree reads](​/Users/ccheever/projects/exact2/runner/src/agent/tree.rs)

- **Major — Stage 0 must demonstrate the actual information display, not just protocol attachment.** Beyond Styles, the stock UI must visibly distinguish snapshots, unavailable geometry and verified Contract locations. Returning custom fields does not make DevTools render them. **Resolve:** show those states in the recorded frontend before completing picking and lifecycle work. Also verify the actual DOM event flow: child expansion involves `DOM.setChildNodes`; native picking needs a selection event and resolvable node identity. Whether the chosen attachment requires Target/session machinery, Page initialization or Runtime calls is version-dependent. A direct single-target connection may avoid much of that machinery; do not implement a browser-wide target hierarchy speculatively.

None of these requires adding the deferred debugging or editing features.
