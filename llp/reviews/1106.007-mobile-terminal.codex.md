## Concerns

P3: make permission freshness precise if expanding the permission paragraph.
terminal-mobile.ts reads auth during preparation and stores permissions keyed by
connection/thread owner. Actions consult that prepared authorization; they do not
perform another auth HTTP read on every keystroke/action. Native transitions and
server enforcement provide the later checks. The present statement that checks
come from the real auth session is true, but should not be read as a fresh remote
check per input. Naming the preparation boundary would remove that ambiguity.

The reported 185-test aggregate is a point-in-time result that includes concurrent
slices. Keep it attributed to that run if later checks change the total; it is not
an independent terminal behavior measure. This is an evidence wording suggestion,
not a request to rerun the aggregate for this review.
