## Should-fix

**Creating a variable throws when another of our variables already has that name — `tools/figma-tamber/src/code.ts:157`.**

Variable names are unique per collection. `variableOf` finds a variable only by its token mark, and the preflight refuses only an unmarked variable of the plan name (`code.ts:111`). A variable this plugin made, renamed in Figma onto a name a different token needs, is neither. Pull then calls `createVariable` and Figma rejects the name. I renamed the `accent.fill` variable to `brand/new` and added a `brand.new` token: the pull threw `name already exists: brand/new` and undid. The file comes back; that design cannot be pulled until someone renames the variable by hand. The stand-in does not enforce unique variable names, so the suite stays green.

Fix: in the same preflight, if the name is held by a variable that is not this token's, and that variable carries our token mark, move it to a free temporary name before any final name is used (the same two-step already used for modes). Leave the unmarked refusal as it is, before `dirty`.

**Dropped variables are removed by walking the same array `remove` splices — `tools/figma-tamber/src/code.ts:153`.**

`getLocalVariablesAsync` in the stand-in returns the array `remove` mutates (`code.test.ts:60`). The mode loop already copies `col.modes` (`code.ts:140`); the variable loop does not. Dropping `AccentColor` and `accent.fill` together removed `AccentColor` and left `accent.fill` in the file, still carrying its token mark. Figma's own call returns a fresh array, so this may stay on the stand-in only. Copy the list before removing (`for (const x of [...variables])`) so a live list cannot skip the next dropped token.

## Nit

**The id match does not consult `taken` — `tools/figma-tamber/src/code.ts:108`.**

The name lookup skips an id already reserved or taken. The id lookup returns that collection even when this write has already assigned it. A plan this commit writes has one id per collection, so a new pull does not hit this. If `taken` already has `col.id`, leave that entry without a collection and let it create its own.

**An alias whose mode name is absent is read from the target's default mode — `tools/figma-tamber/src/code.ts:52`.**

The source mode's display name is looked up on the target collection, and a miss uses `defaultModeId`. A truncated name, or Light/Dark against a collection that uses full context names, resolves to a value. Push then sends that value for the source context. Report it unread when no mode has that name.

**Tokens are taken from the first context only — `tools/figma-tamber/src/mapping.ts:179`.**

A token present in later contexts and missing from the default context is omitted, and it is not listed in `skipped`. A token missing from a later context is skipped. Union the token names across the group's contexts and skip any that are missing from one of them.
