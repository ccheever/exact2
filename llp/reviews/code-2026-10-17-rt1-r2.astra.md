1. **Blocking — after Keep, subsequent gestures can compile every frame.** [host/web/dev.mjs:348](/private/tmp/rv-rt-2/host/web/dev.mjs:348), [host/web/src/dev.rs:637](/private/tmp/rv-rt-2/host/web/src/dev.rs:637). A successful release normally builds an empty batch because the preview already shows the written value. The resident compiler suppresses that notification, leaving `designSource` at the previous file digest. Every frame of the next gesture then fails the new digest guard and takes the full-compile fallback. **Fix:** report committed design/source metadata even when no token batch needs broadcasting.

2. **Blocking — delayed snapshots can resurrect an ended gesture.** [runner/src/runner/live.rs:106](/private/tmp/rv-rt-2/runner/src/runner/live.rs:106), [host/web-js/modes.js:211](/private/tmp/rv-rt-2/host/web-js/modes.js:211). Revision comparison only applies when scrub IDs match. Linux can fetch gesture A’s snapshot, receive gesture B and its Cancel restore through the independent commands worker, then receive A’s delayed snapshot. Its different ID bypasses the guard, and `base: null` allows it to restore A’s obsolete preview indefinitely. Unmarked committed snapshots similarly bypass ordering. **Fix:** order all design frames and snapshots by a server epoch and monotonically increasing revision, across gesture boundaries.

3. **Blocking — the new base guard can certify bytes the compiler never read.** [host/web/dev.mjs:581](/private/tmp/rv-rt-2/host/web/dev.mjs:581). `designBytes()` hashes the current file when a compiler reply arrives. If design B is saved while compilation of A finishes, the loop records B’s digest against A’s compiled design. A scrub opened on B then passes the guard but patches A; unchanged tokens retain A’s values. The patch command itself carries no expected base to validate inside `Session`. **Fix:** return the actual compiled input digest and validate it atomically when applying each patch.

4. **Blocking — tokens embedded in keyframes bypass the rebuild refusal.** [contract/cli/src/tamber_scrub.rs:90](/private/tmp/rv-rt-2/contract/cli/src/tamber_scrub.rs:90), [host/web/src/dev.rs:350](/private/tmp/rv-rt-2/host/web/src/dev.rs:350). With `chip` used both by an ordinary background and a colour keyframe, changing `chip` is classified live by the fold. The patch updates theme rows while retaining the old shape and compiled keyframe colour. A full compile changes the keyframes and therefore the shape. Verification catches this only after the gesture rests; incompatible previews have already been shown. **Fix:** cache dependencies embedded in compiled keyframes and classify changes to their closure as rebuild before publishing a frame.

5. **Should-fix — native numeric scrubs still transition.** [kernel/src/motion/paint.rs:103](/private/tmp/rv-rt-2/kernel/src/motion/paint.rs:103). The new `still()` flag is consulted only by `PaintMotion`. A number token used by `opacity` with `transition="opacity 400ms"` still passes through ordinary `MotionSync::apply` and animates on Apple/Linux; height transitions also retain their separate path. Frames and cancellation therefore trail the gesture. **Fix:** apply scrub suppression to affected numeric and height targets as well, preserving unrelated animations.

6. **Should-fix — web scrubs cancel unrelated transitions.** [host/web-js/modes.js:226](/private/tmp/rv-rt-2/host/web-js/modes.js:226), with the same rule in `host/web/dev.js`. The document-wide `transition:none!important` rule and forced flush terminate every active CSS transition. For example, a toast fading out while a background colour is scrubbed jumps to its endpoint on the next frame. Removing the attribute does not resume it. **Fix:** suppress only the properties and elements affected by the scrub.

7. **Should-fix — wide-colour cleanup periodically recompiles during a continuous drag.** [host/web-js/src/main.rs:163](/private/tmp/rv-rt-2/host/web-js/src/main.rs:163). After 3,072 interned colours, `design-serve` exits; its replacement runs `compile_path_all` before answering another frame. A palette producing dozens of distinct wide colours per update reaches this threshold within seconds, repeatedly interrupting sustained frame-rate delivery. **Fix:** reclaim obsolete frame colours between requests while retaining the compiled plan.
