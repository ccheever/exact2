A computed `opacity 1s spring(300, 30, 1)` does not parse (`contract/cli/tests/it/spelling.rs:168`) but still sets isolation in the browser.

## Findings

**1. Medium. The shared JS transition filter, which this delta introduced, lets some reserved names through.**

`host/web-js/src/style.rs:413` drops `(^|\s)(--exact-[-\w]*)(?=\s|$)`. `[-\w]` is ASCII. In `--exact-π 1s` the class stops at the hyphen, the lookahead then sees `π`, and the entry is kept. The previous mapper dropped on the prefix `--exact-` alone. `animation-trigger` is also absent from that alternation, while this same commit renames it (`tags.rs:775`), so a computed `animation-trigger 1s` is forwarded. Native `Transitions::parse` refuses both. The ordinary and pressed paths share this string, so both are wrong together.

Fix: consume the rest of the token (`--exact-\S*`) and add `animation-trigger` to the old-name list. Extend the tests at `style.rs:772` and `rows.rs:624` with a non-ASCII `--exact-` name and `animation-trigger`.

**2. Medium. A computed `clock(` is not refused on the JS target. It pauses the animation.**

`style.rs:525` and `:533` treat only `auto` and `-exact-clock(` as “leave play state alone.” `clock(Pending)` matches neither, so the string is stored on `--exact-animation-timeline` and `animation-play-state` is set to `paused`. `rows.rs:113` only recognizes `-exact-clock(`. The kernel’s `clock_name` (`timeline.rs:86`) returns `None` for `clock(Pending)`, and `parse_text` (`timeline.rs:159–162`) then leaves the row unset, which plays on `auto`. A literal is refused (`style_names.rs:325`, `spelling.rs:308`). A computed value is not.

Fix: on the JS timeline writes, drop a value whose function name is `clock` and is not `-exact-clock`, the same way a bad dynamic `clip-path` writes nothing. Keep `-exact-clock(` as the only clock form.

**3. Medium. Literal source still accepts the host colour form when the case is not lowercase.**

`values.rs:545` refuses a literal only when it contains the exact characters `--exact-`. `role` (`kernel/src/style/roles.rs:20–22`) lowercases first and then strips `var(--exact-`, so `background-color="var(--EXACT-label, #000)"` misses the ban and resolves as the label role. §9’s sentence that literal source refuses `var(--exact-<role>, …)` (`llp/1081-names-exact-invents.rfc.md:373`) does not hold for that spelling. Lowercase `var(--exact-label, …)` is refused.

Fix: fold the literal check the way `role` does, and add that string to the spelling tests.
