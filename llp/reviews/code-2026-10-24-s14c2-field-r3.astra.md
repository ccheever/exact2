1. **MAJOR — Parenthesized CSS still bypasses the lint.** [contract/lower/src/icon_svg.rs:136](contract/lower/src/icon_svg.rs:136)  
   A path with `fill-rule="nonzero" style="--x:(;fill-rule:evenodd;)"` passes `style_refused`. Then `property()` splits at the nested semicolons and incorrectly selects `evenodd`. CSS keeps that text inside the custom property; the path remains nonzero. Square brackets permit the same bypass. This can also conceal mixed rules. Bun’s CSS parser preserved both examples as custom-property values, consistent with [CSS’s block parsing](https://www.w3.org/TR/css-syntax-3/#consume-a-simple-block).  
   **Fix:** conservatively refuse parentheses and square brackets, or split declarations only at top-level semicolons; add both regression cases.

2. **MAJOR — `all` silently changes the effective fill rule.** [contract/lower/src/icon_svg.rs:286](contract/lower/src/icon_svg.rs:286)  
   `fill-rule="evenodd" style="all:initial"` is accepted and emitted as even-odd. In CSS, `all:initial` resets `fill-rule` to nonzero. The implementation never considers `all`, so two paths with different effective rules can pass as one rule. [CSS defines this reset explicitly.](https://www.w3.org/TR/css-cascade-5/#all-shorthand)  
   **Fix:** refuse `all` declarations with the attribute-based repair message, unless its cascade semantics are implemented.
