I found **one blocker**.

1. **blocker — [contract/lower/src/theme/rows.rs:530](contract/lower/src/theme/rows.rs:530): empty typing context can refuse an accepted write.**  
   With `one = 1` as the only number token, use:

   ```text
   fn toString(x: number): number = x
   component App
     view
       text "a" font-family="one" font-weight=toString(400)
   ```

   Removing `one` reaches the computed font-weight through its font-family. Before removal, `number_tokens()` bypasses the computed-string restriction. Afterwards, `computed_string_arm` re-infers the call using `Shapes::default()`, resolving `toString` as the string-returning builtin instead of the numeric user function. The checker therefore emits `lower-attr-type`; the compiler accepts both designs.

   **Fix:** retain the real scope/function signatures for this validation, or exclude unknown computed number rows conservatively. `Ty::Unknown` does not prevent the downstream re-inference.

2. **major — [contract/lower/src/theme/scan.rs:164](contract/lower/src/theme/scan.rs:164): unknown computed types lose diagnostic parity and the whole-row “passed before” guarantee.**  
   Inside `for p in picks key=p`, with `p: string`, use `-exact-press-scale=(on ? "one" : p)`. Changing `one` from `1` to `0` makes the build report **“computed value may name `one`”**, at the whole expression. The checker records `Unknown`, skips that validation, and instead reports the literal `"one"` failure at the literal’s span.

   If another number token was already `0`, the build already rejected this row before the write, but the weakened before-check passes and incorrectly attributes its failure to the write.

   **Fix:** skip computed number rows whose actual type is unavailable, or retain their real lowering type. Add tests for both diagnostic equality and an already-failing computed row.

3. **major — [contract/lower/src/theme/rows.rs:366](contract/lower/src/theme/rows.rs:366): removing or retyping the last number token bypasses validation.**  
   With `state pick = "2"` and `-exact-press-scale=pick`, a design containing `one = 1` builds. Removing `one`, or changing it to a colour, makes the build reject the string-valued row. But `numbers` examines only the after-fold, finds no touched Number token, and the identifier contributes no literal dependency, so the checker accepts.

   **Fix:** account for number tokens lost from the before-design, including kind changes. Add removal and Number→Colour/Length cases alongside the existing Number→Number test.

4. **minor — [contract/lower/src/theme/rows.rs:164](contract/lower/src/theme/rows.rs:164): computed grouping includes source locations.**  
   `Expr`’s derived Debug representation contains every `Span`. Identical `opacity=pick` rows on different source lines therefore form separate groups. Every number write then checks every such group against every number token. The existing budget test uses only `computed: None` and cannot detect this regression.

   **Fix:** use a structural key excluding locations, with explicit mapping for nested diagnostic spans. Measure collection and number-write costs on repeated computed rows; the literal-row grouping numbers do not establish D2’s cost.

5. **minor — [contract/cli/tests/it/tamber_rows_check.rs:227](contract/cli/tests/it/tamber_rows_check.rs:227): the modified exclusion test is vacuous.**  
   `for p in picks` lacks mandatory `key=` and produces `syntax-expected`. Retention never reaches lowering, leaving an empty row map. Consequently, all three acceptance assertions pass without testing their intended exclusions.

   **Fix:** write `for p in picks key=p` and assert that retention collected rows before testing the writes.
