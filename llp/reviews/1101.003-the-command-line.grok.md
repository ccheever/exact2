## Concerns

### 1. BLOCKING — D2's "nothing in flight" is not how the harness waits

Section D2. The named consumer is `harness --print --prompt`.

`resource session = session()` (`apps/harness/terminal.contract:50`) is an ordinary resource. `session()` returns the snapshot under the lock (`apps/harness/data/src/lib.rs:191-207`). `submit` records the turn, calls `changed()`, and returns; the model runs on another thread (`apps/harness/data/src/agent.rs:60-66`). Between chunks the runner has the last answer and an empty `pending`. LLP 1016.002's push path is the whole design of this app (LLP 1101.001 §1). A model reply is not "a request in flight."

What stays true for the whole turn is `aria-busy` on the entry (`apps/harness/terminal.contract:392`) and `session.busy`. D1 already uses that busy child as the stream boundary, and D2 never consults it. The first commit after `submit` returns has nothing pending and no stream, so D2 exits, drops timers, and writes a partial transcript with status 0.

An approval is the same hole with a worse status. The phase word for it is "Waiting for you" (`apps/harness/terminal.contract:44`), and the thread is blocked on `decision` (`apps/harness/data/src/state.rs:200-201`). Print mode never reads keys (D1). Nothing is pending, so the process exits 0 while a tool is waiting for a yes. The harness's rule is that shell and file tools ask first (`apps/harness/data/src/providers/mod.rs` around the approval comment). A non-interactive success here runs nothing and reports success.

D2 also cites LLP 1012.000 D4. That form waits until `state.pending` is empty or a twenty-second bound, and it does not move the clock, so timers do not fire. It does not drop them, and it does not know about this app's threads.

**Resolve:** Make done include "no `aria-busy` child of the log," no `state.background` work still queued or in flight (LLP 1097; `runner/src/agent.rs:882-887`), and no pending request or stream. An approval in print mode exits 1 and names the tool on stderr. Say explicitly that a data-module thread is invisible to `pending`, so the busy flag is the signal, not the request table.

### 2. BLOCKING — D4's `task … when` does not run the write, and D2 would drop it if it did

Section D4, citing `apps/harness/terminal.contract:109,131`.

Line 109 is `task disarm when quitArmed` followed by `after(2000, unarm)`. Line 131 is `close()` inside `sendText`, on the text `/quit`. LLP 1092 D7's grammar is a schedule (`after` or `every`), not an action. D8 arms that schedule at now + ms when the gate becomes true, and nothing runs on the edge itself. There is still no "reaction to a state change"; `DEFERRED.md` lists it under Motion as still out.

D2 then drops timers that are still pending. A boot `after(1, addAndClose)` is exactly such a timer. The first settled commit, with no request yet, exits and the write never happens. `todo add milk` and `harness --prompt` both need this missing boot action.

The path that already exists is LLP 1038 D5: the router slot is filled from the launch location before slot initializers, so a resource argument may read `searchParam`. That request is in flight until the source returns. A storage write keeps the process alive only if the source awaits it. LLP 1097's unawaited write is background work, not `pending`, and D2 does not wait for it. Exiting then kills the write.

**Resolve:** Specify the boot read as a resource argument (or say a one-shot timer is required and delete the drop rule for a timer that is already due). Say a command-line mutation awaits its storage. Stop citing `task when` as "runs the action, then `close()`."

### 3. BLOCKING — argv is not one grammar, and it does not match Linux or the router

Section D3, and the exit-2 row of D8.

D3 says a flag the host does not own becomes a query parameter. D8 says an unknown host flag exits 2. An implementer cannot tell which `--foo` is.

The Linux sentence is wrong. `launch_location` keeps the first non-flag argument and passes it through `location_of` (`host/linux/src/app.rs:46-50`). It does not join later words into segments, and it does not turn `--name value` into a query. `location_of` is not "as-is": non-http schemes drop or rewrite the authority (`route/src/location.rs:27-37`). `git remote add origin` on Linux is the location of `remote` only.

`encode_route_segment` is `route/src/table.rs:448`. `runner/src/stdlib.rs:144` is the VM call. The function returns an error for `""`, `"."`, and `".."`. D3 does not say the exit status of that error. Query encoding is unspecified (`+` versus `%20`). `searchParam` is `URLSearchParams.get`, the first value only (`route/src/location.rs:163-180`), so a repeated name is stored and then invisible to the app.

A miss is not a failed boot. `Router::launch` journals `no route matches {canonical}` and opens `/` (`route/src/router.rs:55-56`, `runner/src/runner/router.rs:266-278`). A plan with no router slot ignores the launch location (`runner/src/runner/router.rs:94`). "An entry with no routes accepts only `/`" and exit 2 with "no route for /x" are new host policy, and a `notfound` route absorbs the miss (LLP 1038, the chain rule). The message text also differs from the router's.

**Resolve:** One table: host flags and whether they take a value, query flags, `--`, encoding (the route crate's query encoder, not the path encoder), encode failure, no router, `notfound`, and a launch refusal. Say the host must treat the launch refusal as fatal before the fallback to `/`. Describe the Linux difference in that table instead of "the two agree."

### 4. BLOCKING — a file path and a pipe do not survive D3 and D1

Section D5, and the summary's `cat notes.md | mdview`.

D3 takes any argument that begins with `/` as the location. D5 says that for an `open-file` app the location comes only from a leading `/…` argument, and any other existing file is the document. An absolute path is both. `mdview /tmp/notes.md` is a route. macOS does the opposite: `exact run` absolutizes (`scripts/exact.mjs:111`) and the seam requires an absolute path.

`open_route` returns `None` for a relative path (`data/src/documents.rs:70-73`). For a file, it mints a handle to the parent directory and delivers `doc:/<n>/<name>` (`documents.rs:75-79`, `host/apple/src/picker.rs:195-222`). The raw path is not what the node receives, and only when the app lacks `fs.read doc:/`. Delivering `/dev/stdin` through that function mints `/dev` as the document root. That is a directory handle, not a pipe.

D1 enters print mode when stdout is not a TTY, or `--print`, or `--json`. `cat notes.md | mdview` in a terminal has a TTY on stdout, so it is not print mode. Today's `is_terminal` is false because stdin is not a TTY (`term.rs:60-62`), and the process takes the headless path. D1 does not name that combination. D5 also does not say which wins when both a file argument and a pipe are present, or what a missing relative path is (a route, or "no such file").

**Resolve:** For a plan with an `open-file` node, resolve file operands against the cwd before the location rule, and accept only those as documents. Deliver one `doc:` handle for that file. For a pipe, do not mint `/dev`. Stdin that is not a TTY, on an `open-file` entry, is print mode even when stdout is a TTY. State the precedence, and the exit status when the path does not exist.

### 5. MAJOR — `--json` is not the runner read D7 names, and D1 tells the writer to print a frame anyway

Section D7, and D1's third trigger.

`agent::state` (`runner/src/agent.rs:722-966`) is the clock, slots, derives, resources, `pending`, streams, store names, delivery, logic, collections, canvas, and surface refusals. It has no `navigation`. LLP 1012 §1 adds `navigation`, `focus`, and `keyboard` in the host, and on Linux each of those sections is `{"unavailable": true}`. "D7 calls the runner's read directly" and "plus `navigation.url`, the same on every host" cannot both be done. The terminal host records no router op today.

"A resource settled failed" has no public predicate. `failed_args` is private (`runner/src/runner.rs:376`). The journal line is `resource {name} failed: {why}` (`runner/src/runner/lines.rs:154-156`). A placeholder value in `state.resources` is not that signal.

D1 says `--json` is print mode, which streams log rows and writes the live region. D7 says `--json` writes one object and no frame. Both flags together are unspecified, as is whether a failed resource still prints the object.

The leak sentence covers LLP 1018's bearer token only. `--json` prints every slot and resource. The harness keeps provider keys out of `session` (`apps/harness/data/src/state.rs:209-210`); an app that puts a secret in a slot will print it. That is worth one sentence next to the LLP 1018 claim.

**Resolve:** Define the bytes as `agent::state` plus a terminal `navigation` section whose `url` is the launch result, or stop promising `navigation.url`. Name the failure check. Say `--json` suppresses the frame, including log streaming, and whether the object is written on exit 1.

### 6. MAJOR — D1 has two heights, and inline layout does not make `100%` a screen

Section D1.

Inline layout's offer is a definite width and `MaxContent` height (`host.rs:208-213`). Fullscreen's offer is the screen. `document()` uses `document_rows()` only in inline mode; fullscreen returns one frame (`cli.rs:119-124`). Percentage height against an indefinite containing block does not resolve to the viewport. The sentence that `100%` still means `--rows` (else the TTY, else 24) and the sentence that print mode lays out at the document height describe different offers. Todo's `height="100%"` column (`apps/todo/terminal.contract:40`) clips only under the fullscreen offer.

`exactViewport` height is pixels, `rows * ROW` (`host.rs:137`). The `columns` / `rows` fields LLP 1101 D5 wanted are not in `FIELDS` (`runner/src/viewport.rs:11-25`).

**Resolve:** Name the offer. Either print mode lays out at a definite `--rows` and then emits `document_rows()`, accepting the clip, or it lays out at max-content and `100%` does not mean the screen. `--size` is already a host flag (`cli.rs:146-149`); say how it relates to `--columns` and `--rows`.

### 7. MAJOR — `media: "print"` uses a CSS type for something CSS print is not

Section D6, question 2. `runner/src/viewport.rs` has no `media` field.

LLP 1106 D5 and `DEFERRED.md` (the LLP 1093 admission) keep `@page` and the `print` media query out until a paged-media consumer. This RFC sets `media` to `"print"` for "drop the input row and the scroller" while LLP 1106's PDF stays `"screen"`. When paged media is admitted, the same field would mean fragmentation, margins, and `@page`. `prefer`'s existing names are media features (`prefers-color-scheme`), not the media type (LLP 1012's `prefer` row).

**Resolve:** Keep the field off `exactViewport` until it means the CSS media type, or define the subset in D6 (no pagination, no `@page`, viewport height still the screen) and say the later admission is what adds the rest. Question 2 should ask that, not only whether the spelling is `media`.

### 8. MAJOR — the plan does not fail closed on the other host

Sections D4 and D9, citing LLP 1101 D1 and D9.

LLP 1101 D1 says the plan header marks a terminal entry and every other host refuses it. Nothing in `plan/` mentions a terminal profile. `Profile::Terminal` changes the text-field sheet (`contract/lower/src/fields.rs:25-34`, `:111-112`) and `compile_path_terminal` runs the view check (`contract/cli/src/lib.rs:485-497`). A `.plan` argument skips that check and is decoded (`cli.rs:172-174`). `Host::boot` accepts any plan. The write-on-navigation argument ("the plan cannot be served") is a compile path, not a property of the bytes.

**Resolve:** Either specify the header gate as work this RFC includes, or state that the safety property is "this entry file is not the web root" and a shared component that writes on `open` is the author's bug.

### 9. MAJOR — the install shim, as the Mac one is written, cannot be a pipe

Section D10. `scripts/exact.mjs:149-152` is `exec /usr/bin/open -a …`. `open` does not attach stdout and returns immediately. "As it does for the Mac today" names the directory and the command name; an implementer who copies the shim body will build a command that cannot print. The bake (which crate, which profile, where the plan bytes live, how `contract` is unlinked) is unnamed. The 100 ms figure in `RULES.md` is cold start to an interactive first frame; D10 applies it to first output and does not say whether that is the first streamed row or process start.

**Resolve:** The terminal shim execs the baked binary with the arguments and the stdio it was given. Name the bake the way the Apple bundle is named. Say the budget is time to the first byte with an idle local fixture, not time to a model reply.

### 10. MINOR — smaller claim and spec gaps

- §1 says nothing sets an exit status besides success, boot or compile failure, or a refused verb. A missing entry already exits 2 (`cli.rs:141`). A bad `.plan` hits `expect` and panics (`cli.rs:173-174`).
- `document` is the whole document only in inline mode (`cli.rs:120-123`). `exact-terminal`'s default mode is fullscreen (`host/terminal/src/main.rs:6`).
- no-color.org says a non-empty `NO_COLOR` disables ANSI color. It does not say bold, italic, and underline stay. D6 also does not say whether `--color=always` overrides `NO_COLOR`.
- D6's locale order is `LC_ALL`, then `LC_MESSAGES`, then `LANG`. `LC_MESSAGES` is the message catalog, not the formatting locale, and nothing says how `en_US.UTF-8` becomes the BCP 47 tag the rest of the system uses. LLP 1106 D1 summarizes this as `LANG`. `epoch`, `seed`, and a pipe's `prefers-color-scheme` ("may ask") are unspecified. On a TTY the host currently forces dark (`host.rs:156`) and does not query OSC 11; D5 of LLP 1101 is unbuilt, as §1 says.
- `--help`'s text, its exit status, SIGPIPE (Rust ignores it; a pipe closing on `println!` panics), and SIGTERM are unspecified. For a program whose purpose is a pipe, SIGPIPE should be an explicit quiet exit.

## Suggestions

- Use the busy child the harness already paints as the idle signal. That is one predicate for streaming (D1) and for done (D2), and it matches the code at `terminal.contract:392`.
- Start argv work from a resource argument that reads the launch location, which LLP 1038 D5 already allows. Keep `task when` for timers.
- Resolve file operands the way `exact run` does, then hand them to `open_route`, and special-case a non-regular stdin so the handle is not `/dev`.
- Put the argv grammar in one table in D3, including the Linux column, so "the two agree" cannot be written again.
- Treat `--json` as a projection a script can pin (`.derives`, `.resources`, `.navigation.url`), and say the rest of `state` grows. The summary's `jq .derives.left` is the stable use; the whole object is not.
- Leave `media` out of the first slice if the consumer is the harness transcript. The harness does not need a print layout. Todo's clipped `100%` column can be a fixture follow-up once the offer is named.

## 3. New concerns

### 1. BLOCKING — D2's done check runs before the harness's `aria-busy` is in the tree

**Section:** D2.

**Evidence:** A quiescent point "drains every announcement, fires every timer that is due, and lays out." The harness does not put busy into the tree inside `submit`. `changed()` enqueues the topic `"session"` (`apps/harness/data/src/state.rs:403-405`). `session()` is refreshed only when the host calls `apply_announced` (`apps/harness/data/src/lib.rs:5-12`, `runner/src/runner/time.rs:158-170`). Today's pump drains, then ticks (`host/terminal/src/cli.rs:205-210`).

At the 1 ms `ask` fire, `submit` sets `turn`, calls `changed()`, and returns `Answer::Now`. The `after` is spent. `state.pending` is empty. The tree still shows the previous session, so no node is `aria-busy`. A check at the end of that pass exits 0 and tears down the model thread that `start` just spawned (`agent.rs:66`).

The sentence "the app marks work busy before the send returns" is true of the mutex and false of the tree the host tests.

**Resolve:** Make the quiescent point a fixpoint: drain announcements, fire due timers, drain again, and repeat until a pass changes nothing. Run the done test only then. Say that `aria-busy` is read after `apply_announced`.

### 2. BLOCKING — the fixture has no output rule

**Section:** D1, §3, §5.

**Evidence:** Streaming is defined for children of `role="log"`, cut at the first busy child, which is what inline mode already does (`host/terminal/src/host.rs:362-389`, `term.rs:378-380`).
