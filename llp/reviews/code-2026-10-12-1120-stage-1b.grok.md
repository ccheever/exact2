LAND WITH CHANGES

1. **BLOCKING** — A charged upload is released only by the buffer's deallocator, so a read that never builds one leaks the file's bytes for the life of the executor. `sized` takes the file into `book.uploads` and `state.bytes` before the read (`executor_async.rs:610-624`). `read_at_most` failing, including growth (`Err(None)`, `:545-552`) and a cancel between chunks, posts an outcome and `Ended` only. `physical` subtracts `run.charge` (the response reservation) and never `uploads` (`:1006-1016`); `Released` is the only subtraction (`:754-758`) and it runs from `Upload`'s drop. No `Upload` means the charge never returns. The same path frees too early when a buffer does exist: `run_blocking` copies the body and drops the `Arc` at the start of the hop (`fetch_async.rs:621-625`), so the charge ends while the exchange is still on the wire. D5 is the later of the last sending hop's physical end (or the terminal transition, if none) and the buffer's last release. Fix: pair the two events — release the upload charge only once both have happened; on a terminal transition with no hop and no lent buffer (read failure, refusal, reader exit), drop it in that `Ended`.

2. **BLOCKING** — A deadline that wins against park is thrown away and the job runs again. The timer sets `timed_out` and only then posts the outcome (`executor_async.rs:781-797`). `sized` treats any non-`terminal` row as still open (`:581-613`) and can send `Park` or `Read`. `park` (`:629-652`) removes the `Running` row unless `terminal` is already set; it never reads `timed_out` and does not bump the generation. `Park` is applied on the reader, so it races the finisher's outcome: if `park` takes the lock first, `apply` no longer finds the ticket (`:725-728`) and the timeout is dropped. The row is back at the head with a new generation and a new deadline. Fix: under the state lock, `timed_out` is decisive — `sized` sends `Exit` and does not settle, `park` returns without requeueing. Bump the generation when disarming so a firing that has not yet checked the row becomes stale.

3. **BLOCKING** — The in-flight place is not held from selection to `start` for a redirect or a file upload's fetch, so the lane can resume 33 exchanges. The first hop of a non-file job is reserved in `take` (`:315-324`) and consumed in `Tracked::start` (`:1033-1041`). A next hop is only popped (`:248-255`); the comment says the place is held, and nothing increments `in_flight`. The same pass then `take`s another job while the count is still 31. The hop's `start` increments afterwards. A finished `exactBodyFrom` read does the same by pushing straight onto `hops` (`:542-543`) with no origin place either, so that first exchange also skips the per-origin check. Fix: under the lock, before the closure is queued or popped, take the in-flight place (and the origin place for a file upload's first hop); give it back in `physical` if that hop never calls `start`, as the first-hop `reserved` map already does.

4. **BLOCKING** — Pass-over runs before the byte check, so a head that does not fit, including a parked upload, is not the head. `select` continues past an HTTP/1.1 origin at 6 (`executor_async.rs:267-278`) and only then calls `take`, whose `None` is what stops a short-of-bytes head (`:280-282`). A parked upload is that head (`:629-652`) and holds no slot, but it is still an HTTP job: if its origin is already at 6, jobs behind it start and can take the bytes it is waiting on. D3 allows pass-over only when the job would fit the bytes; a parked upload stays the head and nothing behind it starts. Fix: if `take` would return `None`, `break` even when the origin is at its limit. Pass over only a job whose bytes fit.

5. **BLOCKING** — `forget` of a safe read does not post a terminal event, so the ordered slot stays until the reader returns. `forget` only flips `forgotten` and calls `abort` (`executor_core.rs:648-652`, `:682-684`). That reaches `FetchTask::abort`, which posts the outcome, only after `fetch` has built the task. Through sizing and the read, the only registration sets a cancel flag (`executor_async.rs:487-491`). A `stat` or a `read` that does not return holds `book.blocking` until the reader posts; D3 releases the slot at the terminal transition and keeps the permit until the reader's exit. A stalled disk stalls the ordered lane. Fix: the abort registration that `run` installs for a cancellable job posts `Event::Outcome(Aborted)` to that lane's finisher. `settle` already ignores a second outcome once `terminal` is set, so `FetchTask`'s later report is harmless. Do not abort a forgotten write; that path is right and covered.

6. **MATERIAL** — The h2 lift assertion does not wait for the new start. After six to `a` and one to `b`, `script.wait(7)` is already satisfied (`executor_async_tests.rs:172`, `:189`). `metrics` only posts to the finisher; the assert on `https://a.example.test/6` races the starter. Fix: `wait(8)` (or wait until that URL is present) before asserting.

7. **MATERIAL** — The ordered lane never reads the per-origin count. The cap check is under `lane == 1` (`executor_async.rs:267-278`), while `Tracked::start` still increments `origins[0]` (`:1035-1037`). A timeout releases the blocking slot with the task still live, so the next ordered resume to that origin can be the 7th; URLSession then queues it inside the deadline. D3's 6 is per lane. Fix: if the ordered job's origin is at 6 and not multiplexed, leave it queued and do not arm the deadline until a slot is free. Do not pass over it.

8. **MATERIAL** — A reader that fails to spawn drops `live` and never calls `physical` (`executor_async.rs:556-563`). If the timer has already settled the row, the second outcome is ignored, `live` hits 0, and the `Running` row, its charge, and an ordered slot stay forever. Fix: post `Ended` (or call the same path `Ended` uses) instead of decrementing `live` on the starter.

9. **MATERIAL** — The new tests pin the cap, pass-over plus the h2 lift, the ordered slot at timeout, both orders of the response charge, a forgotten write, and question 8. They do not pin a stale firing after disarm, the upload release on a failed read, a byte-short head that must not be passed over, the in-flight place on a redirect, `forget` of a safe read during the read, or an `http/1.1` report putting the origin back to 6. `the_suite_passes_on_the_asynchronous_core` (`executor_async_tests.rs:308-309`) reruns `executor::core::` only; `abi::executor_order_tests` never sees the machine. The response later-of itself is implemented: `settle` publishes with `bytes: 0` and clears the ordered slot (`executor_async.rs:942-976`); `physical` moves the charge only when `terminal && live == 0`, to the running charge (independent) or `retained` (ordered), or to nothing if `drained` (`:984-1016`).

Workers with the switch unset are the old path: `machine` stays `None`, `parked` is 0, and `complete` never reads `drained`. `start_on` passes no lanes, so render stays on workers. `asynch_lanes` is `DarwinLane` only on Apple outside tests. No state-lock hold across a transport call, closure, file read, or opaque drop; the decision channel is unbounded and `send` does not wait on the state lock, so the finisher, the reader, and the starter do not deadlock. The starter waits under the same lock as the predicate. `executor_async.rs` is 1211 lines and `executor_core.rs` 1474, both under the cap; nothing new is unused.
