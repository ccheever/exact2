## Verbatim review

**Adopt F’s derived presentation state and stock cosmetic controls, combined with M’s visibility inheritance and stronger build integration. Use one `game.render` declaration for the optional GPU hooks crate.** M alone does not solve ordinary cosmetic authoring without custom shaders; F addresses that problem, but the supplied implementation needs corrections before adoption.

This is a source review; I did not build or run tests. Branch citations below refer to line numbers in the supplied diff files.

For the authored crate, **F has the clearer names; M has the better implementation**.

`game.render`, `render/`, and `hooks` describe a GPU extension precisely and leave “presentation” available for derived appearance state. M’s `type` is consistent with `game.type`, but less informative. Both declarations ultimately generate the same `module!(…, hooks = …, shaders = …)` call, so maintaining both would create two spellings for one capability. See [M’s wiring](/tmp/design-capsule/game/app/shells.mjs:225) and [F’s wiring](/tmp/design-capsule/REVIEW/fix2-core.diff:138).

The material implementation differences favor retaining M’s machinery:

- **Validation:** Both check allowed fields, package naming, Rust paths, manifest existence, and workspace ownership. M validates before generated writes. More significantly, M checks actual, unfiltered Cargo dependency edges, including aliases and transitive normal/build/target dependencies, to prevent the GPU crate entering simulation or host metadata. F’s added declaration validation does not include that graph enforcement. See [shells.mjs:72](/tmp/design-capsule/game/app/shells.mjs:72), [shells.mjs:89](/tmp/design-capsule/game/app/shells.mjs:89), and [fix2-core.diff:118](/tmp/design-capsule/REVIEW/fix2-core.diff:118).
- **Build participation:** Both add the authored crate to workspace membership and ordinary tests. M additionally runs its own strict lint outside the simulation determinism restrictions and explicitly includes its source, manifest, and build script in surface receipts. Preserve those behaviors under the rename. See [shells.mjs:390](/tmp/design-capsule/game/app/shells.mjs:390) and [app.mjs:1087](/tmp/design-capsule/scripts/app.mjs:1087).
- **Shaders:** M retains explicit `gpu.shaderRoots` and `gpu.shaderPreludes`; F implicitly adds an optional `render/shaders` directory. Prefer M’s single explicit inventory, with scaffolding supplying the conventional path. Otherwise declaring that same root explicitly can encounter duplicate shader names, while a missing conventional directory is silently accepted. The schema should distinguish the `shaders` Rust registry symbol from shader source paths. See [app.schema.json:80](/tmp/design-capsule/scripts/app.schema.json:80), [app.mjs:54](/tmp/design-capsule/scripts/app.mjs:54), and [fix2-core.diff:4239](/tmp/design-capsule/REVIEW/fix2-core.diff:4239).

F’s central state model is worthwhile. A presentation pass that derives appearance from the current simulation, arguments, tick, and seed gives authors a manageable rule: save the cause, derive the appearance. Clearing previous presentation rows prevents accidental dependence on earlier presentation calls, while a separate random stream prevents visual tuning from consuming gameplay randomness. F includes useful tests asserting equal saves/hashes and restored presentation values. See [fix2-core.diff:996](/tmp/design-capsule/REVIEW/fix2-core.diff:996), [fix2-core.diff:1810](/tmp/design-capsule/REVIEW/fix2-core.diff:1810), and [fix2-core.diff:2375](/tmp/design-capsule/REVIEW/fix2-core.diff:2375).

**Hooks alone cannot provide the requested ordinary effects without additional renderer APIs or custom WGSL.** `RenderWorld` offers immutable extraction; `HookGpu` offers GPU access, not a stock pose/material override writer. Custom materials cover loaded, unskinned opaque models, with authored pipelines. Making each game implement bob, fades, or team colors through that interface pushes common renderer work into game code. Keep hooks for wind deformation, water, fog, and other custom GPU work; make everyday appearance changes stock functionality. See [hooks.rs:25](/tmp/design-capsule/game/render/src/hooks.rs:25), [hooks.rs:157](/tmp/design-capsule/game/render/src/hooks.rs:157), and [hooks/materials.rs:40](/tmp/design-capsule/game/render/src/hooks/materials.rs:40).

F nevertheless needs several substantive corrections.

1. **The brief overstates the implemented boundary.** `derive(Presentation)` produces a component marker; it does not implement presentation resources. Resource writes remain prohibited. Also, `Game::present(&mut World, …)` exposes substantially more authority than its contract permits. The postcondition compares only four bookkeeping values, and `sim_writes` disables its guard before panicking, so catching that panic disables subsequent write checks. Use a restricted presentation context, following the existing `RenderWorld` approach, with immutable simulation reads and presentation-only writes. Merely changing the argument to `&World` would not work because this ECS permits mutation through shared references. See [fix2-core.diff:548](/tmp/design-capsule/REVIEW/fix2-core.diff:548), [fix2-core.diff:1002](/tmp/design-capsule/REVIEW/fix2-core.diff:1002), [fix2-core.diff:1638](/tmp/design-capsule/REVIEW/fix2-core.diff:1638), and [fix2-core.diff:1712](/tmp/design-capsule/REVIEW/fix2-core.diff:1712).

2. **Restore rebuilds presentation too early.** It calls `present` before restoring the journal and publications. A presentation function reading a publication can therefore derive a different appearance immediately after restore despite identical saved simulation components. Install every permitted input before rebuilding presentation. Clearing output rows does not repair missing inputs. See [fix2-core.diff:1378](/tmp/design-capsule/REVIEW/fix2-core.diff:1378).

3. **The supplied render diff is not a complete replacement for the supplied core diff.** Core includes setup-write detection, presentation-read guards for pages/revisions/membership, and socket-offset histories that render’s corresponding sections lack. Integrate their intended union explicitly; accepting the render snapshot alone loses protections and the advertised socket behavior. See [core’s guards](/tmp/design-capsule/REVIEW/fix2-core.diff:1679), [core’s socket integration](/tmp/design-capsule/REVIEW/fix2-core.diff:3925), and [render’s scene changes](/tmp/design-capsule/REVIEW/fix2-render.diff:7815).

4. **Offset needs one consistent displayed-pose path.** F detects offset changes for GPU transform uploads, but retained model poses still select dirty pages from simulation pose changes. An otherwise stationary model whose offset changes can therefore retain stale CPU poses used for transparency and winding. See [fix2-render.diff:7552](/tmp/design-capsule/REVIEW/fix2-render.diff:7552), [world.rs:728](/tmp/design-capsule/game/render/src/world.rs:728), and [models.rs:659](/tmp/design-capsule/game/render/src/models.rs:659). There is also an authoring issue: F explicitly leaves ordinary `Parent` children unmoved while moving socket followers. Bobbing Forest’s deer root would leave its separately parented eyes and antlers behind. I would change Offset to affect the displayed parent hierarchy, while leaving simulation transforms untouched. See [F’s stated semantics](/tmp/design-capsule/REVIEW/fix2-core.diff:920) and [Forest’s multipart construction](/tmp/design-capsule/game/games/forest/logic/src/creatures.rs:75).

5. **The appearance controls do not yet cover the stated use cases consistently.** `NodeMaterials` and `MaterialOverrides` address models; ordinary `Material` remains simulation state. Garden’s primitive fruit therefore still needs a presentation tint/emission override. Further, “replacement” implemented by dividing out the original base color cannot replace zero channels: a red material cannot become green this way. Finally, primitive opacity leaves shadows intact, and custom materials ignore these controls. Add a primitive/model appearance path, implement actual base-factor replacement, and make zero opacity remove stock primitive shadows too. Document custom shader responsibilities explicitly. See [Garden’s material write](/tmp/design-capsule/game/games/garden/logic/src/garden.rs:313), [fix2-render.diff:1437](/tmp/design-capsule/REVIEW/fix2-render.diff:1437), [fix2-render.diff:7731](/tmp/design-capsule/REVIEW/fix2-render.diff:7731), and [the acknowledged shadow limitations](/tmp/design-capsule/REVIEW/fix2-render.diff:4110). The ordered dither itself is a reasonable cheap fade, provided it is described as coverage fading rather than smooth transparency.

6. **F’s LOD fallback changes the scene incorrectly.** Direct rendering, keep-all culling, and custom-material paths draw every level. LOD selection is semantic selection, not optional visibility culling; disabling culling must not draw overlapping representations. Selection also uses each draw’s bounds center, allowing differently centered submeshes or levels to choose inconsistent distance bands. Use one entity-level reference distance and one selected level across its parts and shadow passes, with defined material/node mappings across levels. Hold this implementation out until corrected. See [fix2-render.diff:4128](/tmp/design-capsule/REVIEW/fix2-render.diff:4128) and [fix2-render.diff:6506](/tmp/design-capsule/REVIEW/fix2-render.diff:6506).

The authoring distinction must remain about causality, not whether a field sounds cosmetic. Garden’s mutation roll and fruit weight remain simulation; their color and glow can be derived. Rivals’ recoil changes pitch/yaw used by subsequent shots, so that recoil and its RNG must remain simulation; weapon-mesh kick can be presentation. Likewise, F prohibits spawning presentation entities, so it does not remove the saved topology of Rivals’ tracer/explosion entities. Effects needing history require saved causal facts or an explicit renderer reset/reconstruction policy. See [Garden’s mutation logic](/tmp/design-capsule/game/games/garden/logic/src/garden.rs:265), [Rivals’ recoil](/tmp/design-capsule/game/games/rivals/logic/src/weapons.rs:201), and [Rivals’ effects](/tmp/design-capsule/game/games/rivals/logic/src/weapons.rs:385). `ModelLod` and `ParticleLook` are also ordinary components in F, so changing those authored rows still changes pins ([LOD](/tmp/design-capsule/REVIEW/fix2-render.diff:1492), [particles](/tmp/design-capsule/REVIEW/fix2-render.diff:1360)).

For agents and proofs, distinguish **simulation equivalence from visual equivalence**. F excludes presentation from settling, while component inspection still exposes it. That is useful, but “settled” consequently does not mean visually motionless. Screenshots should sample explicit tick/alpha, and diagnostics should distinguish simulated and displayed poses. Paranoid mode compares the simulation hash, which intentionally excludes presentation; it cannot establish visual equality. Preserve separate presentation-value and pixel assertions for restore/replay, with an explicit interpolation-history reset contract. See [fix2-core.diff:1839](/tmp/design-capsule/REVIEW/fix2-core.diff:1839), [inspect.rs:224](/tmp/design-capsule/game/engine/src/world/inspect.rs:224), and [fix2-core.diff:1306](/tmp/design-capsule/REVIEW/fix2-core.diff:1306).

The cost is real but controllable. F clears and reconstructs rows every tick, including during headless proofs and long seeks. Clearing scans storage masks and drops row contents; renderer content comparisons suppress unchanged uploads but still scan appearance data, and changed node looks trigger rebatching. The sparse test prints elapsed time without establishing a budget. Keep the simple rebuild semantics, add an empty fast path, retain reusable storage, and measure unchanged, animated, and seek workloads before accepting the cost. See [fix2-core.diff:1475](/tmp/design-capsule/REVIEW/fix2-core.diff:1475), [fix2-core.diff:1623](/tmp/design-capsule/REVIEW/fix2-core.diff:1623), [fix2-render.diff:7474](/tmp/design-capsule/REVIEW/fix2-render.diff:7474), and [fix2-render.diff:7564](/tmp/design-capsule/REVIEW/fix2-render.diff:7564).

M’s visibility inheritance should stay. It is a hard hierarchical gate, independent of local opacity, LOD selection, and render layer. A child’s opacity or `ViewModel` marker must never reveal it through a hidden ancestor. `ViewModel` already exists on main and retains its per-part, no-shadow semantics. `SocketFollow` alone deliberately does not inherit visibility. See [visibility.rs:5](/tmp/design-capsule/game/engine/src/scene/visibility.rs:5) and [scene.rs:505](/tmp/design-capsule/game/engine/src/scene.rs:505).

Preserve M’s `Parent` invalidation when merging: F’s older asset extraction still tests only local `Visible`, and its batch predicate lacks M’s reparent dependency. Keep Rivals’ local first-person body hides; hiding a common ancestor would also hide wanted descendants. Forest can use the inherited gate for eyes and antlers without copying flags. Opacity fades should not change gameplay collision or picking, whereas M’s hard visibility continues to affect picking. See [F’s local visibility check](/tmp/design-capsule/REVIEW/fix2-render.diff:7681), [M’s batch predicate](/tmp/design-capsule/game/render/src/world.rs:412), and [Rivals’ local hides](/tmp/design-capsule/game/games/rivals/logic/src/fighter.rs:157).

The specific design I recommend is:

1. **One GPU extension declaration:** `game.render = { crate, hooks, shaders? }`, authored in `render/`. Rename M’s declaration, directory, suffix, and `type` field; retain its validation, graph isolation, linting, receipts, and explicit shader inventory.
2. **One derived presentation pass:** `Game::present` receives a restricted context exposing deterministic simulation reads and writes only to presentation components on existing entities. Keep components-only scope initially. Rebuild after setup, completed ticks, fully restored state, and relevant paused argument/tool edits. No simulation RNG, events, entity allocation, or previous-call state.
3. **Stock appearance support:** retain Offset, Opacity, and model appearance overrides; add primitive tint/emission support. Compose Offset through the displayed parent/socket hierarchy exactly once, using the same displayed poses for rendering, sorting, bounds, shadows, and hooks. Preserve simulation-space physics and gameplay picking.
4. **Separate selection from appearance:** retain M’s inherited visibility and existing ViewModel behavior. Keep LOD in the renderer, with a single valid level on every supported path. Expose the shared visibility predicate to hook authors.
5. **Explicit reproducibility and cost:** preserve simulation pins when presentation output changes; verify derived rows and representative images separately through existing tests/proofs. Cover restore, paused edits, offset start/stop/removal, multipart sockets, primitive/model shadows, and LOD fallbacks. Migration from existing saved cosmetics may require a one-time repin.
6. **Keep hooks and the wind fixture:** use hooks for custom GPU algorithms. Update the fixture to use the reflected shader/prelude inventory instead of runtime string assembly and copied frame layouts ([fix2-core.diff:3096](/tmp/design-capsule/REVIEW/fix2-core.diff:3096), [fix2-core.diff:3216](/tmp/design-capsule/REVIEW/fix2-core.diff:3216)).

Delete or exclude the following from the integration:

- **From M:** the competing `game.presentation` spelling and the assumption that all cosmetic work belongs in hooks. Keep its implementation safeguards and visibility work.
- **From F:** duplicate shell-generation machinery, implicit optional shader-root discovery, unrestricted `&mut World` presentation access, unsupported resource claims, zero-channel “replacement,” and all-level LOD fallbacks. Exclude unrelated renderer/bake changes from this decision, especially automatic emitter stepping, which changes simulation behavior independently of presentation ([fix2-core.diff:1111](/tmp/design-capsule/REVIEW/fix2-core.diff:1111)).
