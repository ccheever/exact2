## Findings

**Blocker. A touch on a native button skips the focus, blur, and canvas work D4 says stays unchanged.**

D4 gives the platform control the touch and says `retainFocus`, collection pins, and Exact's focus behavior are unchanged because the node remains the focus owner (`llp/1069.011-native-buttons.rfc.md:62-64`). The hit test returns the subview, so those node methods do not run. On iOS the ordinary walk reaches a `UIButton` after the glass special case (`host/apple/Sources/ExactKit/IOS/NodeViewIOS.swift:692-701`). On macOS `super.hitTest` does the same (`host/apple/Sources/ExactKit/Mac/NodeViewMac.swift:702-708`). What then does not run is the press-focus and editor blur: iOS `touchesEnded` focuses unless `contextRetainsFocus`, then calls `endEditing` when the node did not take focus, then `finishPointerPress` (`NodeViewIOS.swift:1343-1352`); macOS `mouseDown` focuses or calls `makeFirstResponder(nil)` from the `retainFocus` walk (`NodeViewMac.swift:1385-1395`), and `mouseUp` completes the canvas press (`1443-1446`). `becomeFirstResponder` is also what updates collection pins (`NodeViewIOS.swift:248-251`, `NodeViewMac.swift:185-190`). `NSButton.refusesFirstResponder` means the platform control does not take that focus either, so a tap focuses nothing and leaves the keyboard up. `retainFocus` is the contract that a tap keeps the editing session, and the default is to end it (`llp/1001-kernel-v1.spec.md:167-173`). The iOS agent copies that block and then presses once (`host/apple/Sources/ExactKit/IOS/AgentIOS.swift:538-557`) and never synthesizes a touch (`429-435`). The macOS agent sends a real click (`host/apple/Sources/ExactKit/Mac/AgentMac.swift:523-544`), which the `NSButton` receives. Canvas return is the same gap: `returnsPointerFocusToCanvas` requires `kind == "button"` (`host/apple/Sources/ExactKit/CanvasSeams.swift:19-21`), and a control's kind is `"control"` (`host/apple/src/host.rs:1398-1399`).

Change D4 so the control's primary action is the touch path's whole result, once: focus the node unless `retainFocus` (iOS `contextRetainsFocus`, macOS the `retainFocus` walk), otherwise dismiss the editor (`endEditing` / `makeFirstResponder(nil)`), dispatch `press` once, and call `finishPointerPress`. Extend `returnsPointerFocusToCanvas` and `finishPress` to a control whose role is `button`. The iOS agent stays on the ordinary path and must not also send the control action. Delete the padding-press sentence (finding below) so there is no second hit target.

**Should-fix. `--exact-accent` on the button alone drops an inherited accent, and the keyword `auto` defeats the fallback.**

`accent-color` is inherited and defaults to `auto` (`kernel/tables/schema.json:2710-2715`). The web already emits it as the CSS property `accent-color` through the generic row spelling (`host/web/src/css.rs:415-437`). Emit an inherited `--exact-accent` wherever the row is set, and emit `auto` as nothing or as `AccentColor`. The symbol tint is a different variable: `--exact-tint` is non-inherited and starts at `#000` (`host/web/glue.js:356`), so D8's "set on the `img`" is required and is already specified.

**Should-fix. The default `data-button-style` attribute, written the way D8 says, makes the prop-name probe fail, and the generic writer emits a different name.**

The JS target learns a prop's DOM name by diffing attributes on a lone node of that type with and without a sample value (`host/web-js/src/style.rs:376-411`). That node is a bare `Control`, whose `type` is absent, so `props_for` inserts `type=checkbox` (`host/web/src/element.rs:719-720`). D8 writes `data-button-style` even for the default `bordered` (`llp/1069.011-native-buttons.rfc.md:77`). Writing that default on every `Control` puts the key in both snapshots, and `emit.rs` then has no name for the dynamic prop (`host/web-js/src/emit.rs:1151-1158`). The absent default belongs only on a native button (`type` `button`). Any node with the prop set still gains the attribute, which is the probe's "after". The existing fallback also emits `data-` plus the lowercased schema name with no hyphen (`element.rs:700-704`), so a generic `buttonStyle` becomes `data-buttonstyle` and misses `button[data-button-style]`. Require an explicit arm in `props_for` before that fallback, one hyphenated name.
