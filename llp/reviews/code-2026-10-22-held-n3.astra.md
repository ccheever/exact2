1. **BLOCKER — `appGlobal` exposes uncounted async facilities.** [ts-fetch.js:230](/tmp/rv-held/host/web-js/ts-fetch.js:230)

   Unrecognized functions are forwarded without accounting, and objects—including `globalThis.exact`—are returned unchanged. Thus sources can directly await browser pickers, or `exact.documents.files(...).readFile(...)`, `exact.extensions.call(...)`, and other host services without passing through the new wrappers.

   An in-memory probe using the actual document implementation, controlled admission and a pending `getFile()` produced **`inflight=0, held=1, plain=0` while the document read remained pending**.

   There is also a second route around the wrappers: [ts-fetch.js:216](/tmp/rv-held/host/web-js/ts-fetch.js:216) returns the page’s original property descriptors. `Object.getOwnPropertyDescriptor(globalThis, 'fetch').value` is the uncounted browser fetch; the probe confirmed this.

   Unsupported facilities must be unavailable, or their exposed interfaces must count work. Descriptor access must expose the same scoped values as ordinary property access.

2. **BLOCKER — a held upload excludes its preparatory storage read.** [ts-fetch.js:23](/tmp/rv-held/host/web-js/ts-fetch.js:23), [ts-body-from.js:52](/tmp/rv-held/host/web-js/ts-body-from.js:52)

   `fetch(..., { exactHeld: true, exactBodyFrom: 'app:/…' })` counts the entire operation as held, including loading the adapter and reading the file before HTTP starts. That read bypasses `storageOf` and its queue.

   The probe produced **`inflight=0, held=1, plain=0` while `requestBody()` was pending and no HTTP request had started**. The preparatory work needs ordinary accounting; only the subsequent HTTP wait may become held.

3. **BLOCKER — auth supersession leaks the new ordinary count.** [auth.js:125](/tmp/rv-held/host/web-js/auth.js:125)

   Supersession removes the previous session without resolving or rejecting its promise. Consequently, the wrapper added at line 106 never releases that session’s count.

   Reproduced with two sessions for the same target: after cancelling the replacement, `holds()` was empty but **`call.plain=1`**, keeping the answer counted beside its held fetch. Outside restored answer context, the same path leaks the global loose count and affects other held candidates. Supersession must settle the removed session.

The added wrappers themselves otherwise look sound:

- Synchronous throws release once and rethrow; fulfillment and rejection release through one `finally`. Probes also covered throwing `then` accessors and multiply-settling thenables.
- Receivers are preserved for WebCrypto, extension calls, native calls, and database/statement methods. Store methods use closures rather than `this`.
- `createSecretFacade` returns a mutable object. Native/storage/database wrappers are constructed before freezing; the changes do not mutate frozen service objects.
- Ordinary accounting and storage-queue accounting have separate increments and matching decrements. `counted()` changes `inflight` only when `t.counted` changes. **No double-decrement found.**
