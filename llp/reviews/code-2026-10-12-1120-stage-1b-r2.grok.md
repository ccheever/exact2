DO NOT LAND

The round-1 holes that were structural are closed: the park is one locked step and events carry the run, retirement drops readers and queued hops, exchanges take in-flight and origin places at selection (redirects wait only for the cap, as stage 1 says), a failed read releases its upload, the read is capped at the charged size, scope is checked before a `Now`, the deadline arms at start, directories open on the reader, a forgotten safe read frees the ordered slot, the ordered lane waits on its own origin limit, a reader that fails to spawn settles its run, a partial base set retires, and with the switch off the worker path is the old one. Linux production and the render host's `start_on` never enter the machine. `executor_core.rs` is 1498 lines. One release-table hole is still fatal, and the timeout claim overshoots D3.

1. **BLOCKING** — An upload whose first hop never starts leaks its file charge for the life of the executor. `read` marks the buffer lent and parks the bytes inside the hop closure, before `Upload` exists (`host/apple/src/executor_async.rs:835-864`). A timeout (or a forget that cancels) then drops that closure in `physical` (`executor_async.rs:1144-1148`) without a releaser, sets `ended`, and `release_upload` refuses to run while `buffer` is still true (`executor_async.rs:1169-1186`). D5 releases that charge at the terminal transition when no hop is outstanding: fill the cap, let the read finish, let the deadline fire, and the lane's budget stays short forever. Clear `buffer` when dropping a hop that has not been started, then release; set `buffer` only in the closure, next to `Upload::new`.

2. **MATERIAL** — A completion already posted loses to a deadline that fires before the finisher applies it. The timer sets `timed_out` under the lock and only then enqueues (`executor_async.rs:872-886`); `apply` drops any non-timeout event once that flag is set (`executor_async.rs:660-666`). D3.1 says a response that completed is the outcome even if the deadline fires afterwards. Post the timeout without pre-claiming and let the finisher decide in channel order; keep posting it before `abort`, so the cancellation's later error still sees `terminal`.

3. **MATERIAL** — A later independent upload can be parked in front of an earlier one. `sized` always `push_front`s (`executor_async.rs:796-804`), and several uploads size at once because sizing holds only the waiting charge. The later park becomes the head, so it runs first; `behind` sums `j.charge` only (`executor_async.rs:753`), not an already-parked file. Reinsert by admission order, behind jobs still queued that were ahead of it.

4. **MATERIAL** — Upload bytes stay charged until the whole run is terminal and `live == 0` (`executor_async.rs:1169-1172`), not until the last hop that sends the body. A 303 drops the `Upload` at that hop (`vendor/ibex/crates/ibex2/src/stdlib/fetch_async.rs:532-540`) and the releaser runs, but `ended` is still false, so a large file stays charged across the follow-up. Set the upload's physical end when the sending hop has ended and the buffer is gone.

5. **MATERIAL** — `BlockingAdapter` copies the body and drops the `Upload` before `open` (`fetch_async.rs:619-625`), so the releaser fires while the copy is still live, and the read loop never looks at the abort signal (`fetch_async.rs:641-655`). On the adapter a trickle after headers never reaches physical end, and the charge can be reused while the copy exists. Hold `hop.body` until after `sink.end` returns, and leave the loop when the signal is aborted.

6. **MATERIAL** — The new tests pin the cap, pass-over, h2 restore, ordered slot at timeout, later-of for a normal exchange, a forgotten write, question 8, scope, and the redirect cap (`executor_async_tests.rs`). They do not pin the leak in finding 1, a stale timer or `Ended` after a park, a failed read returning the file charge, retirement with a reader blocked in `recv`, or an ordered request waiting on its own origin. Add those four; the suite rerun does not reach them.

7. **NIT** — `u.buffer = true` is assigned twice (`executor_async.rs:835-840`). Delete the second.
