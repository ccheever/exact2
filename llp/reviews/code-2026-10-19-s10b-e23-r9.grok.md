## Blocker

**A slow subscriber still pins the whole held set.** `scripts/tamber-server.mjs:180` cuts a subscriber once `writableLength` passes 8 MiB, and `scripts/tamber-server.mjs:175–176` keeps at most 256 events and 64 MiB. Two other writes never take that check:

- The subscribe greeting writes every held proposal in one shot (`scripts/tamber-server.mjs:533`).
- A long poll does the same, plus every kept event (`scripts/tamber-server.mjs:562–570`), unless the client echoes `held` and `epoch`.

On the remote door the deadline is stopped for the whole answer (`scripts/tamber-remote.mjs:200–206`), and an SSE response never finishes. A client that has filled the hold list and then stops reading keeps each copy until the process exits. The door allows 64 connections (`scripts/tamber-remote.mjs:187`). The hold list is 64 proposals (`scripts/tamber-server.mjs:108`) whose cap is only `diff` + `review` (`scripts/tamber-server.mjs:945`); `ops` are stored as well (`:946`, `:956`). A propose client can fill that list (imports are within the 2 MiB child answer), then open many subscriptions or long polls. Each connection retains its own serialization of the set.

**Fix:** Byte-cap the serialized proposal, including `ops` and `changed`, before `proposals.set` and `send`, and cap the map’s total bytes the way events are capped. For the greeting and the long-poll body, if the payload or `writableLength` is over 8 MiB, `destroy()` the response or answer `missed: true` with empty `events` and `proposals`. Do not write `held()` onto a socket that is not reading.

## Should-fix

**`app.json` is still read without a bound on history and revert.** `designPath` (`scripts/tamber-server.mjs:126`) now requires a regular file of at most 1 MiB. `designRel` (`scripts/tamber-server.mjs:1035–1038`) still `readFileSync`s the manifest with no type or size check. `history` (read scope) and `revert` (propose scope) both call it (`:1046`, `:1076`). A FIFO there blocks the event loop, so an in-flight import’s RSS timer does not run; a multi-gigabyte manifest is read into the parent. A remote client cannot plant the file. The same stat-and-size check as `designPath` closes it. One helper should serve both.

**A missed `ps` sample still 503s a live planner and can signal a pid `ps` could not see.** `scripts/tamber-isolate.mjs:139` arms a 200 ms kill on any `null` sample and does not clear it when a later sample returns a number. `residentKb` (`:39`) turns timeout, `ESRCH`, and bad output into the same `null`. `stop` (`:122`) signals the group whenever `exit` has not been observed yet. Node runs timers before child-exit I/O, so that signal can still land after the planner has gone. Clear the timer on a numeric sample. Treat `ESRCH` as gone and let `close` keep the answer. Call `stop` only when a second probe fails and `process.kill(pid, 0)` shows the pid is still alive.

**The resident-memory stop can still pass 1 GiB during one `ps`.** Samples are dropped while a probe is in flight (`scripts/tamber-isolate.mjs:133–136`); that probe may run to its 300 ms timeout (`:39`). The kill line is 90% of 1 GiB (`:140`), about 100 MiB of headroom. An allocator faster than a few hundred MiB/s — the test hog is faster — is past 1 GiB before the late sample returns. If a probe is still in flight at the next 50 ms tick, `SIGKILL` the group without waiting out `ps`.

**`kept()` is still an uncapped read, and it follows a symlink directory.** `contract/cli/src/tamber_export.rs:160–177`, called from every `import-plan` (`contract/cli/src/tamber_import.rs:45`). `read_dir` follows a symlink at the baselines directory, then `read_to_string`s every `.json` with no total cap. A remote client cannot plant that link. The cost is the child’s RSS and the poll overshoot above. Refuse a symlink with `symlink_metadata`, and stop after a fixed number of bytes.

## Nits

- `scripts/tamber-isolate.mjs:94–97` — one `file.read` is the whole design. A short read is planned as the full file; the serve’s digest of the real file then conflicts, and the import 409s after three tries. Loop until `st.size` or EOF.
- `scripts/tamber-isolate.mjs:72` and `:94` — the 2 s races leave their timers armed when the read wins.
- `scripts/tamber-isolate.mjs:140` — the 413 text quotes the full 1 GiB bound while the stop is at 90%.
- `scripts/tamber-isolate.mjs:51` — `exit` and `close` kill the planner group. A `SIGKILL` of the wire does not run that hook, and on macOS the orphan has no address-space cap. `PR_SET_PDEATHSIG` (`SIGKILL`) in the Linux child covers the crash. Normal dev-loop shutdown is `SIGTERM`, then `close`, then `process.exit`, so this does not break restart.

## Remote propose client

1. **Source parsed in the shared serve or the wire parent.** No. `import` builds a fixed object and does not copy `resolved` (`scripts/tamber-server.mjs:1113`). The serve’s `import-plan` runs only for `marks_only` (`contract/cli/src/tamber_serve.rs:642`, `contract/cli/src/tamber_import.rs:20–25`) with kept baselines `&[]`. The parent checks string fields and `JSON.parse`s the body and the child answer; the theme parse is in the child. The design text is read in the parent, capped, and passed on stdin.

2. **Parent memory or the event loop.** Yes, the blocker: unread subscribe and long-poll snapshots. A hostile `app.json` can also stall the loop via `designRel`, and that needs a local file the client cannot create.

3. **Starvation past two outstanding, four waiting, and 30 s.** No. A sixth global arrival is an immediate 503, and a third import from the same client is too. Each waiter’s 30 s clock is independent of the jobs ahead of it.

4. **`resolved` or another local-CLI path.** No. Astryx is refused unless `request["resolved"]` is boolean true (`contract/cli/src/tamber_import.rs:224–226`). The wire never sets that field. Only `importTheme` does (`scripts/tamber-server.mjs:1464`). `import-plan` is not in `METHODS` (`scripts/tamber-server.mjs:112`).

A normal reimport is unchanged in shape: plan in the child, require a digest, hold on that file. The fixtures in the reimport tests are far under 4 MiB. Those tests were not run; the allowed `exact-tamber` integration suite passed, including its import tests.

A design under the existing 4 MiB cap is still read when the turn starts. Over 4 MiB is still 413. The new 2 s bound fails the read only if `realpath` and the read together exceed it.

Astryx’s package install is still `scripts/astryx-tokens.mjs`. The plan of that resolved JSON now uses the same watchdog as every other import (10 s, 2 MiB answer, about 1 GiB). A theme whose plan exceeds those limits fails where the old cargo spawn allowed 120 s and 64 MiB.

Dev-loop shutdown calls `tamber.close()`, which kills the planner group, then `process.exit`, which kills it again (`host/web/dev.mjs:994–998`). The group is the planner’s own. A successor that starts during `close`’s wait for the design server is reaped on exit and does not hold the design lock.
