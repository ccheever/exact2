**RIGHT WITH CHANGES.** R1 has unresolved runtime semantics and several incorrect assumptions about the existing hosts.

1. **BLOCKER — D2/D7: the residual language cannot represent everything admitted.** [RFC:313](/Users/admin/x2theme/exact2/llp/1121-design-system.rfc.md:313) requires every expression outside its residual whitelist to fold at build time. But `contrast-color(AccentColor)` needs the device’s accent, and `clamp(8px, 1em, 24px)` needs the receiving node’s font. Exact already distinguishes element-relative and parent-relative resolution ([relative.rs:5](/Users/admin/x2theme/exact2/kernel/src/style/relative.rs:5)). **Fix:** specify a closed, typed residual grammar and its resolution context; reject unsupported expressions. Distinguish one *build evaluator* from runtime resolution, and test browser/native residual equivalence.

2. **BLOCKER — D5/D7: the proposed CSS does not implement subtree modes.** [RFC:339](/Users/admin/x2theme/exact2/llp/1121-design-system.rfc.md:339) emits `:root[data-x-dark-style="dim"]`, but subtree pins put the attribute on another element, which never matches that rule. Merely removing `:root` also leaves derived variables problematic: `var()` references resolve before inheritance. [CSS Variables §2.3](https://www.w3.org/TR/css-variables/#cycles). **Fix:** define rules for every mode boundary, including inherited axes, nested overrides, and redeclaration of dependent properties. Gate this with simultaneous Light/Dim/Black previews and nested, independently pinned axes.

3. **MAJOR — D7: dynamic native colours still require Exact work.** [RFC:334](/Users/admin/x2theme/exact2/llp/1121-design-system.rfc.md:334) promises appearance changes with “no Exact work.” The cited [1095:407](/Users/admin/x2theme/exact2/llp/1095-platform-colours.rfc.md:407) explicitly requires resolving colours for `CGColor` layers, invalidating text caches, and reporting resolutions. [colors.rs:3](/Users/admin/x2theme/exact2/host/apple/src/colors.rs:3) also refreshes gradients, filters, SVG and transition targets. **Fix:** extend those paths to token/mode changes; retain per-view traits and define transition/keyframe behavior. A dynamic `UIColor` alone does not update all these consumers.

4. **MAJOR — D3/D7: token kinds are not sufficient row types or invalidation domains.** [RFC:180](/Users/admin/x2theme/exact2/llp/1121-design-system.rfc.md:180) permits one number in both opacity and line-height, yet D7 stores one domain per token. It also permits box-shadow values as text-shadow, although spread is rejected ([shadow.rs:221](/Users/admin/x2theme/exact2/kernel/src/style/shadow.rs:221)), and classifies icons as paint-only although source changes can require measurement ([txn.rs:1180](/Users/admin/x2theme/exact2/kernel/src/txn.rs:1180)). **Fix:** validate each token variant against its consuming row codec; derive effects per use from existing schema flags. Specify shorthand projection and retained authored bits. Drop the blanket `Copy + Eq` claim: existing float dimensions and vector shadows do not satisfy it.

5. **MAJOR — D7/D13: incremental updates omit dependency maintenance.** [RFC:516](/Users/admin/x2theme/exact2/llp/1121-design-system.rfc.md:516) says `set-token` changes only that token’s rows. If `accent.fill-pressed` was folded from `accent.fill`, changing the latter must also replace the former. An index “built at mount” also needs updates when dynamic rows change, nodes move, or instances retire. Existing inheritance propagation is explicit ([txn.rs:1330](/Users/admin/x2theme/exact2/kernel/src/txn.rs:1330)). **Fix:** specify transitive recomputation and atomic publication, plus index maintenance. Provide a separate JS-target implementation: that target has no runtime kernel ([relative.rs:9](/Users/admin/x2theme/exact2/kernel/src/style/relative.rs:9)), so kernel provenance cannot serve “every host.”

6. **MAJOR — D8: simultaneous-state composition is undecided.** [RFC:371](/Users/admin/x2theme/exact2/llp/1121-design-system.rfc.md:371) forbids combined selectors, but a node can still be hovered, active, focused and checked simultaneously. Which background wins, and what happens when the runner updates the base while a host overlay is active? Also, CSS `[aria-selected]` matches an attribute whose value is `"false"`. **Fix:** define per-property precedence, base-value restoration, class/inline merging, and transition ownership; use `[aria-selected="true"]` for selection.

7. **MAJOR — D8: requiring a state block regresses existing authored disabled looks.** [RFC:387](/Users/admin/x2theme/exact2/llp/1121-design-system.rfc.md:387) says nodes without parts retain default dimming. Today ordinary conditional paint and authored opacity already suppress it through `disabledStyled` ([disabled_look.rs:8](/Users/admin/x2theme/exact2/contract/lower/src/disabled_look.rs:8)), implementing [1115.000:400](/Users/admin/x2theme/exact2/llp/1115.000-no-tells-on-every-host.rfc.md:400). **Fix:** state parts should also produce that metadata; existing authored forms must continue to count. Otherwise the proposal reintroduces the double dim it intends to fix.

8. **MAJOR — D3/D7: dynamic names contradict token pruning.** Runtime strings may name any declared token ([RFC:203](/Users/admin/x2theme/exact2/llp/1121-design-system.rfc.md:203)), while only referenced tokens are emitted ([RFC:345](/Users/admin/x2theme/exact2/llp/1121-design-system.rfc.md:345)). A server-returned name may therefore exist in the design but disappear from the build. **Fix:** retain the reachable dependency closure when names are provably finite; otherwise include all eligible tokens. [1095:723](/Users/admin/x2theme/exact2/llp/1095-platform-colours.rfc.md:723) already specifies this conservative fallback for roles.

9. **MAJOR — D7/D12: binding identity and observation are missing.** [RFC:493](/Users/admin/x2theme/exact2/llp/1121-design-system.rfc.md:493) promises compiled native accessors that survive plan updates and immediately follow live changes, but defines neither stable identity across reordered `u16` tables nor refresh semantics for returned fonts/images. `resolve(token, modes)` also lacks font and view-trait context. The existing colour report table is process-global ([roles.rs:151](/Users/admin/x2theme/exact2/kernel/src/style/roles.rs:151)). **Fix:** define stable external names mapped to session-local handles, reload invalidation, contextual resolution and change subscriptions. Test two embedded sessions with different designs and modes.

10. **MAJOR — D9/D12: Android mappings target a framework Exact does not use.** [RFC:410](/Users/admin/x2theme/exact2/llp/1121-design-system.rfc.md:410) names Compose `SwitchColors`/`SliderColors`, and D12 assumes `CompositionLocal`. The actual host uses Views and Canvas, with no Compose or Material dependency ([Android README:5](/Users/admin/x2theme/exact2/host/android/README.md:5), [build.gradle.kts:1](/Users/admin/x2theme/exact2/host/android/canvas/build.gradle.kts:1)). **Fix:** map roles through the existing Rust painter and Android palette/field paths. Make Compose an optional consumer adapter, and qualify fidelity against the actual host implementation.

11. **MAJOR — D13: the assumed authenticated editor connection does not exist.** [RFC:551](/Users/admin/x2theme/exact2/llp/1121-design-system.rfc.md:551) relies on existing authentication. [developmentGate:282](/Users/admin/x2theme/exact2/scripts/install-page.mjs:282) checks Host and cross-site Origin; it does not authenticate LAN clients. An in-memory probe admitted a remote POST without credentials. **Fix:** specify an authenticated, project-scoped write capability separately from readable dev streams, source-digest preconditions, and atomic validate/write/publish. Reject swaps for a different plan/table identity.

12. **MAJOR — D11/§5: the first implementation slice is unnecessarily broad and unowned.** [Stage 2](/Users/admin/x2theme/exact2/llp/1121-design-system.rfc.md:662) requires every token kind before proving the three-colour-mode consumer; useful bindings then wait behind the separately gated editor. D11 additionally imports Facet’s spacing/density vocabulary while calling every value platform-owned. There is [no implementer](/Users/admin/x2theme/exact2/llp/1121-design-system.rfc.md:16), contrary to [RULES:58](/Users/admin/x2theme/exact2/rules/RULES.md:58). **Fix:** first land colour names, axes and font scaling with an owner/date; make bindings independent of the editor. Defer ramps and generalized base scales until named consumers require them; derive platform metrics from the existing schema.

13. **MAJOR — D2/D14: the interoperability premise is outdated and the export contract incomplete.** [RFC:167](/Users/admin/x2theme/exact2/llp/1121-design-system.rfc.md:167) says DTCG has no standard modes, but the [2025.10 Resolver Module](https://www.designtokens.org/tr/2025.10/resolver/) defines contexts and modifiers. “Every token, per mode, with `$type`” also leaves platform roles, `em`, icons and expressions without a conversion policy. **Fix:** pin DTCG Format/Resolver versions, separate Tokens Studio’s dialect, and define exact conversions, extensions and losses before promising the [no-diff round trip](/Users/admin/x2theme/exact2/llp/1121-design-system.rfc.md:682).

That contradicts the claim that inline `theme` remains the same grammar. **Fix:** preserve those names or explicitly amend D4 and update its consumer port in the same change.
