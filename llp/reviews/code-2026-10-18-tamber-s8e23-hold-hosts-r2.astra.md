# Review round 2, LLP 1121 stage 8 E2 (Apple) + E3 (Linux/Android) held states, Astra (gpt-6-astra, max)

**RIGHT WITH CHANGES**

1. **BLOCKING — Apple exit animations bypass hold retirement.** [PresenterMac.swift:1150](/tmp/rv-s8e23-r2/host/apple/Sources/ExactKit/Mac/PresenterMac.swift:1150) and [PresenterIOS.swift:941](/tmp/rv-s8e23-r2/host/apple/Sources/ExactKit/IOS/PresenterIOS.swift:941) call `holdGone()` through `views[id]`, but `beginExit` already removed the exiting subtree from that map. `endExit` only calls `forget()`, which does not release the hold. Removing a held card with an exit animation therefore leaves the server’s hold live. Session teardown has the same omission. **Fix:** retire holds before removing views from the common release/forget paths, preserving silent generation swaps. Test actual `.exit` → `.destroy` and session destruction, asserting one `gone` report at the held revision.

2. **BLOCKING — Apple shortcuts still bypass input-driven release.** The new hook in [KeyEvents.swift:140](/tmp/rv-s8e23-r2/host/apple/Sources/ExactKit/KeyEvents.swift:140) runs inside `keyEvent`, but Mac `routeKey` returns after a successful shortcut before reaching it. The [iOS agent shortcut path](/tmp/rv-s8e23-r2/host/apple/Sources/ExactKit/IOS/AgentIOS.swift:1092) likewise calls `press` directly. Focus a held button with an unmodified shortcut and invoke it: the action runs while the hold survives. **Fix:** clear qualifying holds at keyboard input entry, before shortcut/composition filtering, including UIKit key commands. The current test calls `keyDown` directly and misses these routes.

3. **SHOULD-FIX — Active holds omit platform button feedback.** [PressFeedback.swift:118](/tmp/rv-s8e23-r2/host/apple/Sources/ExactKit/PressFeedback.swift:118) never highlights native controls: they are excluded from the dim/tint paths, and without authored D7 rows the remaining paint/scale calls do nothing. A native button consequently acknowledges `active` without looking pressed. Linux/Android has the corresponding gap: [feedback.rs:59](/tmp/rv-s8e23-r2/host/linux/src/presenter/feedback.rs:59) derives the painter’s pressed control solely from a physical contact. **Fix:** compose held active with physical state in native highlighting and painted-control feedback. Test ordinary buttons without authored press rows, including down → hold → up.

4. **SHOULD-FIX — Linux resolves active through disabled descendants.** [held.rs:56](/tmp/rv-s8e23-r2/host/linux/src/presenter/held.rs:56) climbs to a press handler without checking disabled nodes; its later check starts at the resolved owner. A disabled child inside an enabled pressable therefore accepts an active hold although `contact_down` rejects real input there. Android inherits this. **Fix:** validate the requested node’s ancestry during resolution and stop at any disabled node. Add a disabled-child/enabled-press-parent case.

5. **SHOULD-FIX — iOS flat-child layout still cannot return held rows.** [AgentIOS.swift:358](/tmp/rv-s8e23-r2/host/apple/Sources/ExactKit/IOS/AgentIOS.swift:358) requires `textHost(id)`, which resolves views and inline runs but not flat leaves. Round 1 now allows active holds on flat children, yet `layout` for that same child returns “stale node” before attaching `held`. The added test checks `HeldState.rows` directly, not the layout response. **Fix:** resolve flat-leaf geometry/ownership in layout while retaining the requested identity, and test the actual agent response.
