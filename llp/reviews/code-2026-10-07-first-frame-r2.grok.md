1. **MATERIAL** — Agent takeover samples the batch at the last display target, then drops that instant, so the next seek rewinds in-flight curves and can retire one that ends in the gap. After a motion tick with no frame tasks, the runner stays on the wall and the engine’s `shown` is `targetTimestamp` (`host/apple/Sources/ExactKit/Frames.swift:64-78`, `host/apple/src/first_frame.rs:40-46`). Takeover sets the clock to `max(session.now(), runner)` (`Agent.swift:489-492`) and `Session.clock`’s `didSet` calls `startOnFrame(false, at:)` (`Session.swift:399`). The host floors that instant only at `engine.now()` (`host/apple/src/first_frame.rs:79`), not at `sample_time()`. `set_start_on_frame` then does `shown = shown.max(at)` and `advance(self.now)` while `shown` is still the future target (`motion/src/engine/first_frame.rs:35-36`, `54-108`), so the sample is `max(now, shown)` (`engine.rs:551-574`). Plays and springs that end in `(at, shown]` are retired there (`animate.rs:379-401`). `shown` is then set to `-inf`, and `present` emits those cached values (`first_frame.rs:69-73`, `presence.rs:316-338`). The next `tick`/`advance` at the agent clock is a forward input-clock move and a backward sample. Pending curves are unaffected: their `begin` is already the old sampling time, and `all` starts them at `max(at, begin)`. Already-running curves move by up to one frame interval. `a_takeover_before_a_curves_begin` (`motion/tests/it/first_frame.rs:228-240`) and `the_agents_takeover_starts_what_waits` (`host/apple/src/first_frame_tests.rs:174-183`) never have a running curve with `shown > at`, so both stay green. **Fix:** in `Engine::set_start_on_frame(false, at)`, sample at the same instant the engine will use afterward. Clear `shown` before the `advance` (the batch is then at `at`, which the host has floored at `engine.now()`), and add a test that presents a frame ahead of the wall, takes over at the wall with a curve already running, and asserts the takeover value equals the value after `advance(at)` and that a curve ending inside the gap is not retired. D5’s “larger of takeover and sampling time” is the other consistent choice: floor `at` at `sample_time()` before the sample and move `now` up with it, but then Swift must pass that same instant or the next `advance(wall)` is `ClockWentBackwards`. Do not sample at a `shown` that the same call discards.
