The practical failure modes, ranked:

1. **Optimizing against the wrong rendering path.** Robolectric native graphics plus Roborazzi is credible for static regression testing, not automatically a phone-equivalent oracle. Roborazzi specifically recommends hardware capture for fidelity and shadow problems. `RenderEffect` is supported, but behavior depends on runtime/API: a reported blur-edge defect was subsequently fixed, so blanket claims that it cannot render effects would also be wrong. The RFC specifies no versions with which to establish current fidelity. [Roborazzi guidance](https://github.com/takahirom/roborazzi#robolectric-options), [Robolectric’s resolved blur issue](https://github.com/robolectric/robolectric/issues/8955).

   Fonts need matching family resolution, fallback, variation axes, shaping, baselines, line breaking and nonlinear scaling—not merely identical files. Exact’s headless text uses Swash rasterization; Android replays glyphs through Canvas. More seriously, Android text fields use `EditText`’s measurement and drawing, while headless fields use Exact’s engine. Calibrating Compose alone misses this.

2. **Comparing different meanings of “box.”** `boundsInRoot` describes a clipped layout/semantics node, not every painted subpart. Merged semantics can hide children; unmerged semantics still does not expose every Canvas primitive. A checkbox’s check path or a field’s indicator need not have independent nodes. Exact likewise paints labels and indicators without giving each a kernel node. Distinguish layout, painted, touch and accessibility bounds; tag public content slots, measure text baselines/line counts, and use image analysis or explicitly maintained instrumentation for inaccessible parts. Compose exposes touch bounds separately for a reason. [SemanticsNode source](https://raw.githubusercontent.com/androidx/androidx/androidx-main/compose/ui/ui/src/commonMain/kotlin/androidx/compose/ui/semantics/SemanticsNode.kt).

3. **A permissive pixel test hiding visible defects.** A missing 20 × 20 dp checkbox occupies about **0.11%** of a 411 × 891 dp image, below the proposed 0.5% allowance. Compare component/part crops with explicit shadow margins. Blanket edge exclusion can erase precisely the outlines and indicator differences being tested. Keep ΔE2000 2 for flat interior probes and 0.5 dp as provisional geometry tolerances, calibrated per observable. Label-ink probes need coverage-aware sampling. Define colour-space/alpha handling and test threshold sensitivity against known defects.

4. **Clocks that do not control the same work.** Compose’s clock controls Compose work; it does not universally freeze Android drawing, window transitions or native animations. Android Compose ripple uses `RippleDrawable` and can animate on RenderThread. Specify event timing, frame synchronization and supported animation paths; leave unqualified paths to device observation. The existing reader screenshot carrier waits 400 ms and rejects filming, so it cannot provide the promised transient-frame capture unchanged. [Compose synchronization](https://developer.android.com/develop/ui/compose/testing/synchronization), [Android ripple implementation](https://raw.githubusercontent.com/androidx/androidx/androidx-main/compose/material/material-ripple/src/androidMain/kotlin/androidx/compose/material/ripple/Ripple.android.kt).

5. **Token completeness mistaken for implementation completeness.** Tokens provide much of the design vocabulary, but layout policies, padding/minimum sizes, state logic, paths, animation selection, tonal-elevation calculations and Android behavior live elsewhere. For example, upstream `TextFieldDefaults` declares the 56 dp minimum outside the token package. The cited `ContainerHeight` example needs verification against the actual pinned jar. I did not resolve that jar or independently establish the BOM’s Material version. [TextFieldDefaults source](https://raw.githubusercontent.com/androidx/androidx/androidx-main/compose/material3/material3/src/commonMain/kotlin/androidx/compose/material3/TextFieldDefaults.kt).

Decide now how accessibility nodes are normalized and how actions are exercised. Comparing class/name/state alone misses traversal, action outcomes and focus restoration. Ordinary `uiautomator dump` XML is insufficient for the promised action inventory; specify an instrumented `AccessibilityNodeInfo` reader.

Also decide the complete Material palette transport: today’s twelve roles omit, among others, `outline`, `onSecondaryContainer` and `primaryContainer`. Name O1’s implementer/date. Cut “looks the same on every phone,” “same font files means the phone’s text,” the universal edge mask, and automatic Expressive adoption. Make generated token snapshots build artifacts, or explicitly reconcile committing them with `DEFERRED.md`.
