## Findings

1. **MATERIAL — D8.** The 1 s deadline is not a timer any host wakes for.
   **Problem.** D8 arms "a runner-internal one-shot in the timer queue that `advance_timed` services" and says every host already wakes for it. `advance_within` fires only `self.plan.timers` and `then_due` (`commit.rs:239–249`, `:311–315`). Those rows are baked with the plan; nothing inserts a deadline at the drop. `timer_due_ms` reports that same pair (`runner.rs:1199–1207`). The web batch publishes it (`host.rs:1078–1081`), Linux sleeps on it (`display.rs:523`) and the agent's clock jumps only while it is due (`agent.rs:812–825`). After pointer-up the edge pump returns unless `phase` is `active` (`motion-glue.js:1031`). A board with no authored timer never calls back, so the ghost stays and the fixture's timeout step never runs.
   **Evidence.** D8's deadline paragraph. `ReorderHold.swift:209–216` starts its timer only inside `updateEdge`.
   **Fix.** Put `deadline_ms` on the session. Include it in `timer_due_ms` and in the due-selection of `advance_within`. On fire, that commit carries `ending: timeout`. Say `clock settle` reaches it because the deadline is visible there.

2. **MATERIAL — D8.** `ending` is on a struct the ghost hosts do not read, and a drop that stays active is cancelled.
   **Problem.** The web ghost learns from the batch op `reorder-state`, whose fields are `terminal`, `released`, and `frame` (`batch.rs:121–129`, `motion-glue.js:1126`). Swift learns from the reorder op's `phase` string, `active` | `settling` | `finished` | `refused` (`exact.h:358–360`). `ReorderHold.observe` breaks on any other string (`ReorderHold.swift:164–168`). On pointer-up, a phase still `.active` is cancelled and then finished (`:153–155`: a drop Rust leaves active does not stay up). A `holding` answer takes that path, so the send is retracted and the previews close.
   **Evidence.** D8's `reorder_frame` sentence. `arrange.rs:467–471` emits only `active` or `settling`.
   **Fix.** Carry `ending` on the batch those two already apply: a field of `reorder-state`, and a `holding` phase Swift keeps. In `ReorderHold.finish`, a holding answer skips `cancel` and `finished`. Linux, in process, reads `reorder_frame`.

3. **MATERIAL — D4, D12.** A drop into an empty column never certifies `before = none`.
   **Problem.** D4 says `certified_gap_excluding` with nothing excluded picks the gap, and D3's `min-height` makes an empty column a target. The gap function returns `None` when the index is empty (`gaps.rs:22–24`: missing measurement, never a guessed end). `move_preview` then leaves the preview uncertified (`reorder.rs:116–121`), and `preview_drop` fires only when `certified` matches (`:145–146`). The fixture requires this drop (`D12`).
   **Evidence.** `index/gaps.rs:22–24`. D12's empty list.
   **Fix.** An empty index with a positive port certifies gap 0, `before = none`, without a measured row. Cover it in the runner tests beside the fixture's empty-column step.

4. **MATERIAL — D5, D7.** A sample whose centre is outside the port replaces the sticky gap.

Releasing on the header, which D3 defines as a gutter, sends nothing.

   **Fix.** When the centre is outside the target port, do not call `preview_reorder_into`. `inside == false` keeps the last certified gap. Define that bit on `exact_reorder_move_into`; a true bit is the only sample that may move `before`.
