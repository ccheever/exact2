## Findings

1. **MEDIUM —** `gpu/reflect/src/lib.rs` ~207–209, ~367–380. `SIZE` and `min_binding_size` are `TypeInner::size()` / `Struct { span }` with no address-space adjustment. Naga stores one layout and then *validates* uniform 16-byte rules; it does not re-pad the type. That is the right offset source for fields (the Scene fixture is correct: `mat3x3` at 16, `array<Light,2>` at 64, `tint` at 96, `SIZE` 112, column 1 at byte 32). It is the wrong *binding* size when the store type is smaller than WebGPU’s uniform-buffer 16-byte multiple (`var<uniform> t: f32` → `NonZeroU64::new(4)` and a 4-byte `SIZE`). A runtime-sized `array<T>` has naga `size() == 0`, so `NonZeroU64::new(0)` is `None` — which is what wgpu wants for `layout: None`, FLAG on naga 30 returning 0 rather than one stride. Resolve: for `AddressSpace::Uniform`, emit `min_binding_size` / recommend `SIZE` as `max(naga_size, 16)` rounded up to 16; for dynamic arrays, test and document `None`.

2. **MEDIUM —** `gpu/reflect/src/lib.rs` ~490–498. A host-shareable struct that cannot be generated (runtime-sized member, f16, etc.) becomes `// \`struct Name\` is not generated: …` and the binding is still emitted. That comment lives in `OUT_DIR/shaders.rs`, which nobody reads on a green build. The crate’s pitch is “a shader edit is a compile error at the use site”; a skipped `Uniforms` is a missing type instead, and an author who only uses the binding const will pack by hand again. A `//` line is not an adequate signal. Resolve: `generate` / `reflect` should return `Err` for an unsupported *buffer* struct (same as unnamed structs, binding arrays, external textures), or emit a documented zero-variant type so the use site cannot silently ignore it. Keep the skip only for types that are not reachable from a binding.

3. **MEDIUM —** `gpu/reflect/src/lib.rs` ~717–793 (`emit_vertex_inputs`). `@location` inputs are tightly interleaved in *declaration* order, 4-byte scalars/vectors only, one buffer, `VertexStepMode::Vertex`. That is not WGSL layout: naga would put a `vec3` + `vec2` vertex struct at offsets 0 and 16 (span 24); the generator puts them at 0 and 12 (SIZE 20), which the reflect test locks in. It is internally consistent with `write`/`LAYOUT` and happens to match `map.wgsl` (vec2+vec4 = 24). It *is* a second declaration — alignment is safe only because 32-bit types keep offsets multiples of 4; mixed bare `@location` and a struct become `{Ep}Input`; `@builtin` is skipped (correct). Two vertex entry points that share a generated name (`if emitted.contains(&name) { continue }`, ~761–763) drop the second layout with no error; that is fine when they share one WGSL struct and silent when they do not. Resolve: document `LAYOUT` as a default convention, not a reflection; error on a second vertex EP that would reuse a name with a different attribute list; do not pretend this covers instance rate or multiple buffers.

4. **MEDIUM —** `gpu/src/fixture.rs` ~25–32, ~101–126. `Pixels::at` does not require `x < width`; `at(3, 0)` on a 3-wide image reads the first pixel of row 1 and does not panic. `read` sizes the staging buffer as `row * height` and then copies `texture.size()`, which includes `depth_or_array_layers`. `render` only builds a 2D mip-0 texture, so the helper’s own path is fine; the public `read` is not. Resolve: assert `x < width && y < height` (or return `Option`); size the buffer and the copy by `width × height × layers` or refuse non-2D / non-mip-0.

5. **MEDIUM —** `gpu/src/fixture.rs` ~128–132. `map_async(..., |_| {})` discards the `Result`; completion is inferred from `poll(wait_indefinitely)` plus `get_mapped_range`. That is the usual native pattern and the 3×2 padding test plus the viewed PPMs show it works on this Metal machine. FLAG: on a failed map (lost device, wrong usage), the callback’s `Err` is gone and the author only sees `map: …`; some Vulkan/Metal wgpu versions have wanted an explicit channel wait for the callback, not just poll. Resolve: `mpsc` the callback `Result`, `poll`, then `recv` — same as wgpu’s own readback example — so a backend that invokes the callback with `Err` after a successful poll still fails with the real cause.

6. **MEDIUM —** `gpu/tests/fixture.rs` ~54–58, `apps/caltrain/gpu/tests/map.rs` ~19–27, ~66. No adapter → `eprintln!` and `return`. `cargo test` on a GPU-less runner (typical fleet Linux without Vulkan, or a VM) is green and never compares a picture. D4’s fixture is then a local instrument, not a check. That does not violate “five checks / 60s”, but it means a wrong clear color or a swapped channel in `render`’s `Rgba8Unorm` target will not fail CI. Resolve: keep the skip for laptops, and run the GPU tests on one labelled host (or fail when `EXACT_GPU_REQUIRE=1`) so the parity path has a machine.

7. **MEDIUM —** tests vs. what the brief asked. `gpu/reflect/tests/reflect.rs` does establish naga offsets for `vec3`+`f32`, `mat3x3` column stride, nested `Light::write`, two groups, storage read vs. read_write, filterable texture + filtering sampler, visibility union, a skipped `@builtin`, `@location(2)` packed at 12, workgroup size, naga line `:2:`, and a `SOURCE` name clash. `apps/caltrain/gpu/tests/shaders.rs` locks the two production layouts and `bytes()`. `gpu/tests/fixture.rs` locks unpadded 3×2 and P6. `map.rs` locks the helper’s `at`/`count`/`wants` on a real adapter. Untested, and all reachable in this code: `generate()` (new/deleted file, bad stem, `read_dir` entry errors), the `//` skip path, `struct entry` vs. `pub mod entry`, two vertex EPs sharing a struct, a field named `type`, nested arrays, a matrix in a *real* shader on the GPU, storage textures (`{format:?}`), a binding used only in a helper (FLAG: naga’s `FunctionInfo` *does* union callee `GlobalUse`, so visibility is likely transitive, but nothing proves it), runtime-array `min_binding_size`, `GROUP_` collision, `Default` dropped for `array<_, 33>`, `write` into a short slice, `Pixels::save` when the directory is missing.

8. **LOW —** `gpu/reflect/src/lib.rs` ~346–350, ~388–392. Sampled `f32` textures are always `filterable: true` (unless multisampled); samplers are always `Filtering` or `Comparison`. WGSL does not say this. It is correct for aurora’s `children` (`Rgba8Unorm` + linear). An `rgba32float` sampled texture will fail at bind-group creation, not at generate. Resolve: document the default; if you ever need unfilterable, it has to be an extra annotation — it cannot be reflected.

9. **LOW —** `gpu/reflect/src/lib.rs` ~152, ~502, ~562. `ident()` raw-ifies field keywords; struct names, `pub mod {stem}`, and `pub const {konst}` do not. `RESERVED` is only `SOURCE`/`MODULE` (plus `GROUP_*` for bindings). A host-shareable `struct entry` collides with `pub mod entry`; a `struct type` emits `pub struct type` and the included file fails under the app crate’s `deny(missing_docs)` only after you stare at rustc. Resolve: run struct/entry-module names through the same reserved/keyword table.

10. **LOW —** `gpu/reflect/src/lib.rs` ~48–49, ~437. `read_dir` uses `filter_map(|e| e.ok())`, so one unreadable directory entry is dropped and will not appear in `cargo:rerun-if-changed`. Storage-texture `format: wgpu::TextureFormat::{format:?}` is naga’s `Debug` name; it matches today and becomes a build error if it ever does not. `write` does not zero padding (only `bytes()` does, via `[0u8; SIZE]`), so a reused destination keeps garbage in `vec3`/matrix column tails. Resolve: fail `generate` on a `read_dir` entry error; map `StorageFormat` with an exhaustive match; have `write` zero `out[..SIZE]` first or document that padding is caller-owned.

11. **LOW —** `gpu/src/fixture.rs` ~79, ~52–61. `render` targets `Rgba8Unorm` while presentable surfaces are `Bgra8Unorm`. That is the right cut for D1: Chrome `getImageData` is RGBA, and the surface rebuilds its pipeline for the format it is given, so the fixture measures the same shader math the browser would, not the Metal drawable’s channel order. Do not “fix” it to BGRA. `save` does not `create_dir_all`; a missing `EXACT_GPU_OUT` is a log line, not a test failure — acceptable. Native-only `fixture` in `exact-gpu` is more like `kernel/build.rs` than a new test crate; wasm correctly cannot `poll(wait_indefinitely)`. It does make `exact_gpu::fixture` a public native API of the production crate (cdylib should strip it if unreferenced — FLAG, not verified here).

**Rules / D5 / foreclosure (no extra numbered defects).** A new crate is not a check, script, or design doc under `rules/RULES.md` §Agents; it is the same move as `kernel/build.rs`, and a human already put the GPU module on the doing-list. Layering holds: reflect → naga only; `exact-gpu` does not depend on reflect; no cargo features on either crate (naga’s `wgsl-in` is a dependency feature). Boot path untouched. D5’s wording (“validated at build, compiled at first use”) still holds; generation is a stronger form of the same decision, not a second WGSL declaration except for vertex `LAYOUT`, `filterable`, and `has_dynamic_offset: false`. Foreclosed until someone changes the generator: WESL/imports (`parse_str` per file), instance-rate / multi-buffer vertices, dynamic offsets, `AddressSpace::Immediate`, pipeline-overridable constants, sharing one `Uniforms` type across shaders, generating the pipeline layout, web `gpu_readback`.
