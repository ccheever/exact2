Reviewed at HEAD (`ca47c46f2`), accounting for both later fixes. Tests were inspected, not run; no files were changed.

1. **High — Accept can silently lose the operations needed for redo.** [app.ts:798](/tmp/rv-dt-6/apps/design-tool/app.ts:798) reads `heldOps` after awaiting accept. The server removes the proposal and wakes polls before completing that response; a poll can therefore replace `heldOps` without this proposal. The undo entry then contains `ops: []`: Undo works, but Redo successfully executes an empty transaction and discards the redo entry. **Fix:** capture the proposal’s operations before awaiting anything, retain them with the inverse, and test accept → undo → redo with the poll delivered before the accept response.

2. **Medium — A late accept response can restore an obsolete undo entry after restart.** [app.ts:793](/tmp/rv-dt-6/apps/design-tool/app.ts:793) has the later `sameRun()` preflight, but lacks the post-request session check used by `writeEdit`, `undoLast`, and `redoLast`. If an old server’s successful response is delayed until after a poll detects a new epoch and clears the stacks, accept inserts the old inverse into the new session. **Fix:** capture the session before sending accept and reject its result if the session changed.

3. **Medium — Batched writes lose attribution highlights.** [app.ts:730](/tmp/rv-dt-6/apps/design-tool/app.ts:730) requires a cached read of each event’s exact `after` digest. If Alice changes token A and Bob changes token B before the next design read, only the final state is cached. B highlights; A never does, although its changed value is visible. **Fix:** associate the displayed read with the events it includes and retain attribution for every applicable event, without requiring a read of each intermediate state.

4. **Medium — Highlights lose file and cell identity.** [app.ts:730](/tmp/rv-dt-6/apps/design-tool/app.ts:730) keys attribution solely by token name, and [app.contract:542](/tmp/rv-dt-6/apps/design-tool/app.contract:542) applies it to every column. An edit to `brand.tamber` can highlight an unchanged same-named token in `app.tamber`, because the cached digest covers all files. Likewise, Alice’s dark-only edit followed by Bob’s light-only edit labels both cells as Bob’s. **Fix:** preserve changed file/token pairs and calculate attribution per affected column rather than per entire token row.

5. **Medium — Restart can suppress subsequent highlights.** [app.contract:287](/tmp/rv-dt-6/apps/design-tool/app.contract:287) keeps `faded` across epoch changes. After sequence 100 fades, restarting the server makes new events 1–100 fail `n.seq > faded`. **Fix:** make the fade cursor epoch-specific and reset it when the server run changes; test a restart after a highlight has expired.

6. **Medium — Unrelated edits can keep old highlights indefinitely.** [app.contract:302](/tmp/rv-dt-6/apps/design-tool/app.contract:302) restarts one shared timer whenever `lit.seq` changes, while retaining all events after `faded`. An agent changing any token every two seconds prevents an earlier, untouched token’s highlight from expiring. **Fix:** expire individual highlights three seconds after their appearance or latest relevant change, without extending them for unrelated events.

7. **Medium — A missed poll leaves the wrong attribution baseline.** [app.ts:719](/tmp/rv-dt-6/apps/design-tool/app.ts:719) initializes `lastFiles` only when the request’s epoch is empty. A `missed` response supplies current files and no events, so the previous baseline survives. If unseen edits changed a token from black to gray, the next client’s gray-to-white edit can be reported as black-to-white. **Fix:** establish a new baseline from `r.files` after a gap or epoch change, and keep snapshots separated by server run.

8. **Medium — Partial-accept choices omit their target files.** [app.ts:454](/tmp/rv-dt-6/apps/design-tool/app.ts:454) drops `o.file` from the supported operations’ labels. A proposal setting `surface.card` to the same value in two different files produces indistinguishable checkboxes. The person cannot reliably choose which file’s operation to accept. **Fix:** include the explicit or default design filename in each item’s visible and accessible label.

9. **Low — Added borders misalign the grid’s mode headers.** [app.contract:542](/tmp/rv-dt-6/apps/design-tool/app.contract:542) adds padding and borders to a width-96 cell while headers remain width 96. Under the required CSS `content-box` default, cells occupy 104 pixels, creating another eight pixels of misalignment per column. **Fix:** use consistent outer widths, for example `box-sizing="border-box"` on the cells.

10. **Low — Tests do not establish the claimed timing and stale-diff behavior.** [design-tool.test.mjs:503](/tmp/rv-dt-6/scripts/design-tool.test.mjs:503) advances twice before inspecting attribution, does not count polls, and asserts resource contents rather than rendered highlights or expiry. Its stale scenario changes `tone.warm` while the proposal edits `accent.fill`, so recomputation need not visibly change that diff. The [stub:72](/tmp/rv-dt-6/apps/design-tool/stub/tamber-stub.ts:72) also preserves the old diff and affected-token list when filtering operations. **Fix:** assert attribution after the first carrying poll, inspect rendered cells and timed expiry, and stale-edit the proposed token so the replacement must display a demonstrably new diff before acceptance.

**Verdict: Changes required before approval.**
