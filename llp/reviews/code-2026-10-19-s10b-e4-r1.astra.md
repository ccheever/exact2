**Two blockers remain.**

1. **blocker — Failed pairing can leak the previous server’s token.** [ui.ts:32](/tmp/rv-e4-1/tools/figma-tamber/src/ui.ts:32) changes `server` before pairing succeeds, retaining the old `token`. Pair with server A, attempt pairing with B that returns 403, then click Pull: A’s token goes to B. **Fix:** pair using a temporary endpoint and atomically replace the endpoint/token only after success; bind authenticated requests to that credential’s origin.

2. **blocker — Adding contexts can bypass conflict confirmation.** [code.ts:85](/tmp/rv-e4-1/tools/figma-tamber/src/code.ts:85) treats the previous collection’s mode count as its capacity. After a four-context pull, adding a third axis value produces six contexts: the check constructs split collections, while the saved plan contains `Tamber`. [mapping.ts:194](/tmp/rv-e4-1/tools/figma-tamber/src/mapping.ts:194) consequently finds no matching collection and reports no conflicts. If the file supports six modes, Apply updates the original collection and overwrites conflicting Figma edits without confirmation. **Fix:** compare baseline, Figma and fresh values by token/context identity, independently of collection layout.

3. **should-fix — Re-pulls do not reconcile obsolete modes or existing collections.** [code.ts:59](/tmp/rv-e4-1/tools/figma-tamber/src/code.ts:59), [code.ts:93](/tmp/rv-e4-1/tools/figma-tamber/src/code.ts:93). A full four-mode collection cannot become a two-context design with new mode names: obsolete modes remain, `addMode` fails, and the fallback retries the same collection. Conversely, splitting an existing collection leaves the original behind because only newly created collections enter `made`; existing canvas bindings then reference variables the plugin stops updating. **Fix:** reconcile owned modes and plan collection migrations before mutation, preserving bindings or explicitly refusing the migration. Clean up failed fallback writes and distinguish mode-limit failures from other API errors.

4. **should-fix — Name-based identity loses renamed variables and retains removed tokens.** [code.ts:33](/tmp/rv-e4-1/tools/figma-tamber/src/code.ts:33), [code.ts:66](/tmp/rv-e4-1/tools/figma-tamber/src/code.ts:66). Renaming a Figma variable makes Push ignore its edits; the next Pull creates another variable under the original name, leaving existing bindings on the old one. Removing a design token leaves its Figma variable behind permanently. The written `token` metadata is never read. **Fix:** persist collection/variable IDs or use ownership metadata, reconcile removed tokens, and handle changed variable types explicitly.

5. **should-fix — UI requests can consume each other’s replies or remain pending forever.** [ui.ts:22](/tmp/rv-e4-1/tools/figma-tamber/src/ui.ts:22). Two Pull clicks overwrite the single `checked` waiter; one export can proceed using another export’s conflict result. Main-thread errors merely display text and never reject the pending promise. **Fix:** correlate requests and replies with IDs, reject matching requests on errors, and serialize document-changing operations.

6. **should-fix — Alias traversal can emit malformed values.** [code.ts:19](/tmp/rv-e4-1/tools/figma-tamber/src/code.ts:19) returns an unresolved alias after eight hops, which Push treats as a colour, number or family. Cross-collection traversal also chooses the first enumerated value without consulting the target collection’s default mode. **Fix:** traverse with cycle detection until a concrete value is reached, resolve the target mode explicitly, and report unresolved aliases instead of serializing them.

7. **should-fix — Import refusals are hidden, including ordinary non-colour edits.** [ui.ts:54](/tmp/rv-e4-1/tools/figma-tamber/src/ui.ts:54). Changing a length, number, duration or family in only one scheme mode produces different Light/Dark values. The [importer rejects that](/tmp/rv-e4-1/tamber/src/export_kinds.rs:420), but the UI ignores `review.unmapped`, displaying either a generic message or only the successful proposal. **Fix:** validate these constraints and display every unmapped value and reason, including partial-success responses; explain which modes must agree.

8. **should-fix — Family names containing commas cannot survive an edit.** [mapping.ts:99](/tmp/rv-e4-1/tools/figma-tamber/src/mapping.ts:99), [mapping.ts:161](/tmp/rv-e4-1/tools/figma-tamber/src/mapping.ts:161). `["ACME, Sans", "serif"]` becomes `ACME, Sans, serif`; editing the fallback makes Push return three families. **Fix:** use quoted, escaped serialization and a corresponding parser, preserving individual family boundaries.

9. **nit — New collections ignore the export’s default context.** [code.ts:62](/tmp/rv-e4-1/tools/figma-tamber/src/code.ts:62) makes the first enumerated context the default mode. The fixture lists Dark first but declares Light as its default. **Fix:** create the exported default context first; use the corresponding scheme when splitting.
