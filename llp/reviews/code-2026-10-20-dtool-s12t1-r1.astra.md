1. **BLOCKER — Param levels can come from a different revision than the panel.** [app.ts:737](/tmp/rv-dt-s12t1/apps/design-tool/app.ts:737) resolves params after `readDesign` has finished its digest and tuple checks. These replies’ `files` and `modes` are ignored. If an app param override appears between describe and this resolve, the panel can show the old value and `set: false` alongside “wins: set for this app.” Include these requests in the existing consistent-read/retry boundary before publishing the snapshot.

2. **SHOULD-FIX — A failed resolve silently removes the winning-level information.** [app.ts:739](/tmp/rv-dt-s12t1/apps/design-tool/app.ts:739) skips an errored reply but returns `ok: true`. A timeout or server refusal therefore leaves an editable panel with no explanation or retry indication. Missing levels also need an explicit policy: the real server’s [icon resolve path](/tmp/rv-dt-s12t1/contract/cli/src/tamber_base.rs:213) returns before adding them. Report unavailable provenance or fail/retry the read.

3. **SHOULD-FIX — `r.set` does not establish that the param’s value still wins over the token.** [app.contract:2311](/tmp/rv-dt-s12t1/apps/design-tool/app.contract:2311) makes that claim for every app param line. For example, with `Pill.fill = accent.soft`, an app override making `accent.soft` red, and a blue package default, “Back to the package” changes the param’s resolved value to blue. The app param line remains, but the package token now wins. Account for aliases and conditional branches, or state only that the param’s app line remains.

4. **SHOULD-FIX — The displayed winner has no mode identity.** [app.ts:739](/tmp/rv-dt-s12t1/apps/design-tool/app.ts:739) always selects tuple zero; [app.contract:2304](/tmp/rv-dt-s12t1/apps/design-tool/app.contract:2304) says only “wins” and “it differs by mode.” With `mode=a` resolving to an app token and selected `mode=b` resolving to `space.lg`, the label still names the app token. Either follow the selected tuple or explicitly identify the first tuple’s modes.

5. **SHOULD-FIX — Dropping `name` loses provenance through another param.** [components.ts:36](/tmp/rv-dt-s12t1/apps/design-tool/components.ts:36) suppresses names for `app-param` and `default`. Suppose package `Card.inset` defaults to `param.gap` and the app sets `Card.gap`. Resolve correctly names `Card.gap`, but the inset row merely says “set for this app,” despite inset having no app line. Preserve the winning param’s identity when it differs from the displayed param; the same issue applies to another param’s default.

6. **SHOULD-FIX — The new request fan-out bypasses the existing concurrency and cancellation controls.** [app.ts:736](/tmp/rv-dt-s12t1/apps/design-tool/app.ts:736) correctly limits this work to package components while viewing the app design, but resolves every param, including collapsed or subsequently filtered controls. A package with 100 params adds 100 requests, each folding the design, on every read. `Promise.all` bypasses `RESOLVES_AT_ONCE` and keeps obsolete work queued after another read starts. Reuse the bounded, `wanted()`-aware request loop.

7. **SHOULD-FIX — The new fixture describes a state the real server cannot produce.** [app.test.contract:2118](/tmp/rv-dt-s12t1/apps/design-tool/app.test.contract:2118) gives two params the same default token, `accent.soft`, but opposite `reaches.app_set` values. That flag describes the token’s app override, so both must agree. The canned resolves also omit `modes` and supply two tuples against the stub’s four-tuple axes. Use distinct overridden/unoverridden tokens and complete server-shaped tuples. The real-server fixture has no params and drives the older token-grid reset, so it does not catch this mismatch.

8. **SHOULD-FIX — The levels test does not assert every level’s intended words.** [design-tool-levels.test.mjs:13](/tmp/rv-dt-s12t1/scripts/design-tool-levels.test.mjs:13) correctly extracts the six documented levels and checks key coverage and uniqueness, but asserts rendered wording for only three. Swapping the `base` and `role` labels would pass. Add explicit expected mappings for all six, including their name handling.

9. **NIT — The reset explanation disappears when there are no branches.** [app.contract:2305](/tmp/rv-dt-s12t1/apps/design-tool/app.contract:2305) renders the removal note only for `whens > 0`. With an ordinary `set.whens: 0`, only “Back to the default” remains. To meet the stated “each reset says what it removes” condition, always explain removal of the app line, adding the branch count when nonzero.
