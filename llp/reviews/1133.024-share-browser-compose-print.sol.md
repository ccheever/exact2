1. **MATERIAL — Text-only POST shares have no web delivery path.** D1 permits `POST` without files (RFC lines 185–193), but D6 converts only declarations containing files to GET (400–407). The receiving page cannot read a navigation’s POST body; the existing server also returns 405 for POST ([host/render/src/serve.rs:514](host/render/src/serve.rs#L514)). Chrome explicitly requires interception for [POST shares](https://developer.chrome.com/docs/capabilities/web-apis/web-share-target#processing_post_shares). **Resolution:** normalize every published web share target to GET while service workers remain deferred, or reject unsupported POST declarations explicitly.

2. **MATERIAL — The macOS composer cannot preserve CC/BCC.** D14 promises separate `to`, `cc` and `bcc` fields and refuses unsupported fields rather than dropping them (690–707). D15 selects `NSSharingService` (729–735), whose configuration provides one [`recipients`](https://developer.apple.com/documentation/appkit/nssharingservice/recipients) list and `subject`, without separate CC/BCC roles. The proposed status has no corresponding capability fields. **Resolution:** choose a path that preserves recipient roles, or define capabilities and refusal/fallback rules. A `mailto:` fallback can preserve roles without attachments; merging BCC into public recipients is unacceptable.

3. **MATERIAL — `openBrowser` loses the embedder’s external-navigation decision.** D11–D12 move opening into package implementations that directly present Safari or launch an external browser (539–589). Existing `Session.follow` delegates external navigation to the containing app ([Session.swift:1422](host/apple/Sources/ExactKit/Session.swift#L1422)); LLP 1031 D5 states that ownership boundary, and the superseded browser draft explicitly preserved it ([1114.004:207](llp/1114.004-in-app-browser.rfc.md#L207)). Supplying a presentation anchor does not preserve an embedder’s URL allowlist. **Resolution:** keep the package send, but provide a public context hook through which the containing app authorizes external navigation before launch, with a defined refusal result.

4. **MINOR — D21 names the wrong cancellation mechanism and overpromises dismissal.** Lines 1060–1061 use `release(name,args)` for cancelled sends. That operation releases source readers; pending sends already use `cancel(request)` ([ExactPackage.swift:197–211](host/apple/modules/ExactPackage.swift#L197), [bound.rs:226](runner/src/runner/modules/bound.rs#L226)). External handoffs that have answered `"opened"` no longer have pending UI Exact owns. **Resolution:** use the existing request cancellation mechanism and limit dismissal to owned presentations; elsewhere cancel outstanding work and discard its completion.

5. **MINOR — The Apple print fallback needs an explicit coverage/refusal rule.** D19 acknowledges that `ExactSnapshot` covers a limited vocabulary (931–939), but D17 accepts arbitrary elements. The snapshot renderer handles text, images, progress and containers; unsupported leaves can contribute no content ([SnapshotNode.swift:65](host/apple/Sources/ExactSnapshot/SnapshotNode.swift#L65)). **Resolution:** state that the fallback refuses unsupported subtrees rather than silently omitting content, and include representative supported and refused content in the probe. Full presenter coverage need not block the bounded Fieldnotes consumer.

6. **MINOR — The print oracle promises more equality than its inputs support.** D20 requires Fieldnotes’ page breaks to match Chrome on every host (1030–1031), although the kernel consumes each host’s line boxes. LLP 1093 deliberately used controlled line geometry and a bundled face for such comparisons ([1093:261–263](llp/1093-text-that-flows-across-boxes.rfc.md#L261)). Its existing fragmentation deviations also remain relevant ([fragment.rs:251](kernel/src/fragment.rs#L251)). **Resolution:** compare Chrome against controlled fixtures with matching text geometry and explicit expected deviations; verify ordinary consumer printing against its host’s layout.

7. **MINOR — Stage 6 depends on Stage 7.** Stage 6 drives the print package on Linux (1221–1227), but Stage 7 introduces the Rust package implementation slot (1229–1233). D22 identifies Linux’s print implementation as a user of that slot (1091–1096). **Resolution:** land and prove the Rust slot before the Stage 6 package drive.

8. **MINOR — Several target cells confuse absence with unfinished support.** D12/D15/D19 call Linux browser, email and print “absent” while naming their future portal implementations. LLP 1133 D8 reserves “absent” for a platform without the capability and “later” for implementation work ([1133:430–435](llp/1133-the-standard-library.rfc.md#L430)). Likewise, undetectable SMS-handler installation is not proof that web SMS handoff is unavailable; email already uses optimistic URI handoff. **Resolution:** label the Linux cells `later`; either give web SMS equivalent handoff semantics or describe it as intentionally unimplemented.

9. **IMPLEMENTATION-PHASE — Compose’s `#id` attachments must use a public capture seam.** D14 inherits screen pictures from `share(files=)` (695–696), while today their resolution belongs to the runner command ([share.rs:210](runner/src/share.rs#L210)); package context exposes admitted file paths ([ExactPackage.swift:170](host/apple/modules/ExactPackage.swift#L170)). **Resolution:** expose the existing capture machinery through the general context and prove the out-of-tree implementation. The helper’s exact API and factoring can be settled during implementation; this does not determine the verdict.
