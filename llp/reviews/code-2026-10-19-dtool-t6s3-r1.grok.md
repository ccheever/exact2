**1. BLOCKER — `loadCanvas` will frame the viewer's own loopback.** `apps/design-tool/pairing.ts:37-39` accepts any URL `doorOf` accepts whose path is `/canvas/<one segment>/`, then sets the frame to that URL plus `#g=<grant>`. `doorOf` (`apps/design-tool/wire.ts:51-58`) is the pairing-door check: `http` to `127.x.x.x`, `localhost`, or `[::1]`, and any `https` origin, including `https://127.0.0.1` and `https://localhost`. The comment on the source says "Never a loopback page on this machine" (`pairing.ts:32`). D12 says the same thing: a remote frame whose `src` is the developer's loopback loads the remote browser's own loopback (`llp/1122-design-tool.rfc.md:670-671`).

Concrete case. A paired server answers `canvas` with `{url: "http://127.0.0.1:<dev-loop-port>/canvas/pwned/", grant: "<any non-empty string>"}`. `doorOf` returns that origin. The path matches `/^\/canvas\/[^/]+\/$/`. The contract sets `iframe src` to that URL with `#g=` appended (`apps/design-tool/app.contract:1381-1383`), sandbox `allow-scripts allow-same-origin allow-forms allow-popups allow-modals allow-downloads`. The iframe navigation is a GET with `Accept: text/html`; the fragment stays in the document. On the viewer's dev loop, a path that names no file and is an app document is served the full client HTML and JS (`host/web-js/dev.mjs:957`). `/canvas/pwned/` qualifies: it starts with `/`, has no dot segment, no file extension, and is not `/__dev` (`scripts/origin.mjs:95-102`). That document runs as the dev-loop origin, which the dev gate treats as local, and its scripts can read `location.hash`. The remote server cannot open the viewer's loopback. This frame is what fetches it.

The same check accepts the tool's own origin, `http://127.0.0.1:7740/canvas/<client>/`. The local canvas refuses that port because a same-origin frame lifts `allow-scripts allow-same-origin` (`apps/design-tool/origins.ts:4-15`). The remote path skips `pageOf`: a remote hello forces `page` and `frame` to `""` (`apps/design-tool/app.ts:623`) and then frames whatever `canvas` names. Today `/canvas/` on the tool server is a script-less JSON 404 (`scripts/tamber-server.mjs:1153-1154`, `handle` returns false for a non-wire path), so that lift does not run. The stub returns exactly this URL (`apps/design-tool/stub/tamber-stub.ts:191`), and the contract test only checks that a `canvas-frame` node exists (`apps/design-tool/app.test.contract:1795-1796`).

**2. SHOULD-FIX — the frame is the server's string plus a fragment, so the origin check is the whole boundary.** Even after loopback is refused, `https://evil.example/canvas/x/` passes `doorOf` and the path regex. That document reads `location.hash`. Redeeming the grant needs a POST whose `Origin` is the canvas origin or the tool origin (`scripts/tamber-canvas.mjs:356-359`), so a third-party page cannot complete entry. It still occupies the canvas slot with the grant in the URL. The path's client segment is not compared with `hello.client`; a mismatch is burned at entry (`tamber-canvas.mjs:372`) and the frame 404s. A query on the server URL is sent on the iframe GET (entry 404s any query, `tamber-canvas.mjs:356`). A `#` already in the server URL swallows the tool's `#g=`. Leading whitespace: `doorOf` trims and accepts, then `new URL(url)` throws (`pairing.ts:38`) and the resource fails. Build the frame from the paired door's origin, the path `/canvas/<hello.client>/`, and the fragment alone, and refuse the tool's origin the way `pageOf` does.

**3. SHOULD-FIX — until C2's entry page, the frame navigates to a GET the entry refuses.** `enter` answers POST only (`scripts/tamber-canvas.mjs:356`). Setting `iframe src` is a GET. There is no static page that runs `history.replaceState` and POSTs the grant. The fragment stays off that request, and the gateway's log line is the client and the end reason (`tamber-canvas.mjs:316`), so the grant is not on the wire and not in that log. The iframe shows `{"message":"Not found."}`. `tamber serve` and `tamber tool` construct the server with no `canvas` (`scripts/tamber-server.mjs:1176`, `:1312`), so today the method 404s with `this server has no canvas gateway` (`tamber-server.mjs:658`), `loadCanvas` returns `frame: ""`, and the pane shows that error (`app.contract:1385`). The comment at `pairing.ts:28-31` describes the entry page as already stripping the fragment. The contract test's `canvas-frame` assertion is the stub, which has no entry page and is never loaded.

**4. SHOULD-FIX — the grant stays in contract state for the whole server run, and the pair test's secret scan does not look for it.** `canvasAt` is `loadCanvas(hello.local, hello.client, changes.epoch)` (`app.contract:672`). `changes.epoch` is the run id and stays put across polls (`apps/design-tool/app.ts:1092`). The frame string, including `#g=<grant>`, therefore sits until the server run changes (pair TTL defaults to 12h). The grant itself dies in 30s (`GRANT_MS`, `scripts/tamber-canvas.mjs:58`) or on one use. Readers of the live value: the iframe's `src` (the parent keeps the fragment), contract state, an agent's `state` reply, and the drive tree's `url` on `canvas-frame`. No other resource is passed the frame. The tool's own request is `POST /__tamber` with `{method: "canvas"}` and the token header (`pairing.ts:35`, `wire.ts:121-122`). `scripts/design-tool-pair.test.mjs:86-94` scans the token and the pairing code in paths, drive replies, server output, and the browser profile. With no gateway mounted, `frame` is `""` and that scan is green. Once a gateway is mounted, `state` and `tree` carry a live bearer for 30 seconds and a dead one for the rest of the run, and the scan still passes.

**5. NIT — one extra mint when the epoch fills in, and a remote-canvas flash before hello.** The runner re-requests a resource only when its arguments change (`runner/src/runner/settlement.rs:157-159`). Hello is refreshed whenever `changes.paced` changes (`app.contract:812-813`). `paced` is `answer ${answers}` and `answers` increments on every poll (`app.ts:970-971`), so hello is read every poll, while `hello.local`, `hello.client`, and `changes.epoch` stay equal. The long poll does not mint again, reload the frame, or spend the 6-a-minute cap (`MINT_RATE`, `tamber-canvas.mjs:66`) or the 8 live grants (`GRANTS_PER_CLIENT`, `:69`). A 429 would stick until an argument changed; the poll does not cause one. The extra mint is the boot sequence. `canvasAt`'s placeholder is `else empty(ok=true)`, so the first call is `loadCanvas(false, "", "")` while `changes.epoch` is `""`. On the local tool that is a 400 and no mint (`tamber-server.mjs:658`). After pairing, `pairedWith` refreshes hello only (`app.contract:670`). The first mint runs with the epoch still empty. The first successful poll copies the run id into `epoch` (`app.contract:821`), the arguments change, `loadCanvas` runs again, and the iframe src changes. Two mints, inside both caps; the first grant is abandoned. Hello's reply already carries `epoch` (`tamber-server.mjs:701`) and `loadHello` drops it (`app.ts:623-625`). On the local tool the same placeholder renders the remote canvas branch until `hello.local` becomes true.

**6. NIT — the stub's grant would not enter, and the test never looks at the frame URL.** The stub's grant is `crypto.randomUUID()` (`tamber-stub.ts:191`). Entry requires 43 base64url characters (`tamber-canvas.mjs:367`). The stub's URL is the tool origin and has no entry page. `app.test.contract:1795-1804` checks that `canvas-frame` appears and that it is gone after revoke. It does not check the origin, the path, or the fragment. Refusing loopback makes this test show `canvas-remote-none` instead, because the stub's URL is loopback. The test can point the stub at a non-loopback `https` URL. The revoke half is covered below.

## Checked, and not findings

The tool never puts the grant in a request it makes. The bad-URL refusal is a fixed string and `frame: ""` (`pairing.ts:38`). The failure string `` `No canvas: ${error}` `` (`pairing.ts:36`) shows the server's message; the mint errors do not contain the grant.

`NEEDS.canvas` is `'read'` (`wire.ts:32`), matching `METHOD_SCOPE` (`scripts/tamber-pairing.mjs:60`). The pair test's allow-list includes `canvas` (`scripts/design-tool-pair.test.mjs:81`).

The sandbox string matches the local canvas (`app.contract:1383` and `:1387`): no `allow-top-navigation`, no `allow-popups-to-escape-sandbox`. It is a boundary while the framed origin is another site. Finding 1 is the case where it is not.

A revoke ends the frame. A 401 sets `gone`, drops the token, returns the revoked text, and sends nothing more (`wire.ts:125`). The canvas sits in the `else` of `not hello.ok` (`app.contract:1286-1307`), so the revoked screen unmounts the iframe. The test waits one poll plus the 3s retry (`app.test.contract:1798-1804`, `app.contract:802-803`) and then expects the node gone. With a gateway mounted, `onEnd` deletes that client's grants and sessions and kills proxied streams immediately (`tamber-canvas.mjs:315-322`). The iframe element leaves on the next failed hello.
