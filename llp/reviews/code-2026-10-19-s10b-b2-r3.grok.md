## Guard

The two counters match the round-3 fix. The deadline stays armed while any body is still arriving, including an early 404 that does not read it. It is cleared only when every body has ended and a response is still open. It is armed again only when the connection is actually idle.

Checked on this tree with `timeoutMs` 400:

- Tunnel, two pipelined early 404s (response before the body, the production order at `scripts/tamber-server.mjs:491`): both 404, connection closed 402 ms after the answer.
- TLS keep-alive: a fast `POST`, then 200 ms later `/__tamber/events` waiting 1200 ms. Both came back 200, body `events-done`.
- SSE (`writeHead` + `write`, never `end`): still open, first chunk delivered, at 1.1 s.
- TLS, two requests in one write: 0 bytes, connection closed, no `uncaughtException`, and the next request still returned 200. Bun's fallback parser fails that closed, as `secure()` says at `scripts/tamber-remote.mjs:203-205`. Browsers do not pipeline.
- `close()` resolved and the process exited. One timer per connection, cleared on socket `close`. Over-cap sockets are destroyed without a map entry.

A legitimate long poll and the subscribe stream are not cut. Bun emits `end` once the body is read (a full `Content-Length` body stays `readableEnded: false` until then, or until the response ends and Bun drains it). `/__tamber/events` waits its 25 s only after `body()` (`scripts/tamber-server.mjs:495`, then `545`), and `/__tamber/subscribe` writes the stream after that read. Those clear the deadline while `outstanding > 0` (`scripts/tamber-remote.mjs:190-196`). A keep-alive client's next request is not cut when its headers arrive inside the idle window: that request arms its own deadline, and `finish` does not start an idle timer while another response is still open.

## Host and Origin

`hostOf` and `remoteNames` both go through `new URL`. On this Bun, an IPv6 `hostname` includes brackets; `remoteNames` slices them (`scripts/tamber-remote.mjs:91`) and `hostOf` strips them (`118`), so both sides use `::1` and `::ffff:7f00:1`. A certificate for `remoteNames('::1')` checks `::1`. `127.1`, `2130706433`, `0x7f000001`, and `127.0.0.1.` all become `127.0.0.1` on both sides, so a decimal Host and a canonical Origin compare equal (canvas probe: 200). Default ports are omitted on both sides. Userinfo in `Host` is rejected. `[::ffff:127.0.0.1]` becomes `[::ffff:7f00:1]`, which is not `127.0.0.1` and is not a tunnel loopback name, so it 404s. `localhost.` stays `localhost.` and is not admitted. A foreign Origin, the wrong scheme, or another port is 403 on the wire and on `addPort`. A missing Origin is still allowed, which is the non-browser end of the tunnel.

`targetOf` (`scripts/tamber-remote.mjs:125-132`) rejects `//`, `\`, a dot segment, and `%2e` / `%2f` / `%5c`, and requires the parsed path and query to equal the raw target. The suite's cases (`//a//b`, `/x/../__tamber`, `/__tamber/./events`, and the encoded forms) returned 404 with the wire uncalled.

## Should-fix

**A failed main bind leaves `[::1]` answering through `tamber.close()`.** `host/web/dev.mjs:1479` and `host/web-js/dev.mjs:1027`.

`alsoOnIPv6Loopback` binds `[::1]` first (`host/web/dev.mjs:1482`, `host/web-js/dev.mjs:1025`) and feeds those sockets in with `server.emit('connection')` (`host/web/serve.mjs:1050-1052`), so the dev handler, including `GET /__tamber/token`, runs without the main `listen` having succeeded. The new catches `await tamber?.close()` and do not close that server. `close()` waits up to about 7 s (`scripts/tamber-server.mjs:1007-1011`). For that whole window `[::1]` still answers, which is the failure the error text is warning about. On a game, `early.server` is already listening, and the `[::1]` failure catch at `host/web/dev.mjs:1482` leaves that server up for the same wait.

Fix: in those three catches, call `server.close()` and `server.closeAllConnections?.()` before `await tamber?.close()`. The HTTP server's `close` event is what closes the `[::1]` companion (`host/web/serve.mjs:1052`). The remote-bind path at `host/web/dev.mjs:1495` already does this.

## Nits

**JS `stop()` does not drop accepted connections.** `host/web-js/dev.mjs:1012`, used on remote-bind failure at `1028`. `server.close()` leaves in-flight requests running, and the `[::1]` companion stays up until the server emits `close`. A `GET /__tamber/token` already in progress still completes during `tamber.close()`. Call `server.closeAllConnections?.()` next to `server.close()`, as the wasm failure path does.

**When pairing removes the remote short-circuit, read the body before `await ready`.** `scripts/tamber-server.mjs:491-495`. The deadline is cleared on `end`, and Bun does not emit `end` until the body is read. Today `access.remote` returns before `await ready`, so remote and tunnel requests never sit there. The 25 s wait and the SSE stream are safe once `body()` has run. After pairing, a cold `ready` longer than the deadline would destroy the socket before that read. Move `body()` above `await ready`.
