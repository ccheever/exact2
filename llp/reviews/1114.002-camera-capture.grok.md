## Overall assessment

Admitting HTML's `capture` on the file input is the right capability and the right layer. It is what the web already does for one photo, it sits on the picker exact2 already has, the `device.camera` grant is the right gate, and the live viewfinder stays a separate module. ## Concerns

### 1. MAJOR — The iOS camera photo is a second image pipeline, and it drops what the picker is required to keep

D2 draws `info[.originalImage]` through `UIGraphicsImageRenderer`, then writes a JPEG, and calls that "the settings D6's HEIC conversion already uses" (`Picker.swift:172`). That function, `Picker.jpeg`, is ImageIO: quality 0.9, orientation applied, no location metadata, the color profile kept, and from iOS 18 an HDR gain map written back (`kCGImageSourceDecodeToHDR`, `kCGImageDestinationEncodeToISOGainmap`). LLP 1100 D13 names this rule "The picker keeps what the camera made."

A renderer pass flattens the still to an SDR bitmap first. ImageIO then compresses that bitmap, so the profile and the gain map never arrive. That is the camera button, which is the path most likely to be holding an HDR still. The web host stores the browser's file as the entry (LLP 1069.002 D5). The library button already calls `deliver`. Section 7's phone check ("the photo attaches upright") would not catch the loss.

`UIImagePickerController.InfoKey.imageURL` is the file URL. Hand that file to `deliver`. If the controller only yields a `UIImage`, encode once with `Picker.jpeg`'s ImageIO options. If that sheet's still has no gain-map file, say so as a deviation from D13. Remove the renderer.

## What it gets right

The attribute and its three values (`capture`, `user`, `environment`) are HTML's, and a literal is what lets the bake see it. The host table matches browsers: a phone opens the camera, a desktop opens the chooser, macOS ignores it the way desktop Safari does, and tvOS, Linux, and Windows already refuse every pick. The bake-time grant is the right layer, because iOS terminates a camera open that has no `NSCameraUsageDescription`; the runtime check matches `showNotification` and LLP 1069.008 D3. The agent reuses the pick hold, with `capture` in the args, and adds no driver. The system sheet is the right UI; `AVCaptureSession` and a viewfinder belong to the module in `QUEUE.md`, which is the split HTML Media Capture draws against Media Capture and Streams. The photo is not saved to the library, which the spec forbids. Refusing video until a consumer asks matches the DEFERRED line that still holds recording out. `UIImagePickerController.SourceType.camera` is still the supported system camera; the deprecated source types are the library ones. The code claims this rests on (the lowering refusal, the unused `device.camera` row, PHPicker / `NSOpenPanel`, the notify grant check) match the tree.
