## Should-fix

**1. An unmapped symbol takes a native tab out of the tab bar.**
`host/apple/src/abi/commands.rs:159-164` writes `symbol: null` when the role is not `sf/…` and is not in the symbol table. `TabBarFace.init` (`host/apple/Sources/ExactKit/IOS/SegmentsIOS.swift:42-43`) then returns nil because it requires `face.symbol`. A custom tab does not: `symbolName` for an unknown role is `""` (`host/apple/src/host.rs:1444-1448`) and the bar still builds, with a nil image when the name is empty (`SegmentsIOS.swift:55`, `:222`). Contract allows the failing source: a template whose first piece starts with `symbol:` is not checked against the table (`contract/lower/src/controls.rs:760-764`).

Failing input: a `tablist` of two `button appearance="auto" role="tab"` children, each with a title, one `image "symbol:send"` and the other `image "symbol:${name}"` while `name` is `nope`. The second face has a title and a null symbol, so `segmentFace` becomes `.title` (`Accessibility.swift:57-59`). The first still has both, so its `segmentFace` is nil. `SegmentsIOS.swift:257-271` then keeps the whole tablist authored. A symbol-only tab with that same template never becomes a segment either (`Accessibility.swift:57`), so it does not carry its label in the control. D4 says an unavailable symbol draws no image and keeps the label, on the first batch. `sf/not.a.symbol` already does that, because the bridge keeps a non-null string and `UIImage` is nil.

Fix: when `press_face` has a symbol the table does not name, emit `""` (same as `symbolName`), and leave JSON null only when there is no symbol. `TabBarFace` and the symbol segment then keep the tab.

**2. The Linux agent name is not the face title.**
D1 (`llp/1069.011.000-native-buttons-everywhere.rfc.md:31`) says the Linux accessible name is the label, otherwise the face title. `host/linux/src/agent.rs:445-460` names a native button under any role, then sets that name from `AccessibilityLabel` or `text()` (`agent.rs:406-418`), which returns the raw `Text` prop. `press_face` (`kernel/src/control.rs:303-309`) uses `text_runs()`, so whitespace is collapsed and `text-transform` is applied (`kernel/src/arena.rs:609-616`). Paint already uses the face title (`host/linux/src/paint.rs:1080-1082`). Apple’s native accessible text does too (`Accessibility.swift:21`).

Failing input: a parent with `text-transform="uppercase"` and `button appearance="auto" role="tab"` containing `text "Inbox"`, with no `aria-label`. The face title and the painted label are `INBOX`. The agent name is `Inbox`. The same split happens for `text "Sent  again"`: the face is `Sent again`, the agent name keeps the double space. `host/linux/tests/it/native_buttons.rs:127-135` only checks that one Enter yields `pressed 1`, so this stays green.

Fix: for `ControlKind::Button`, set `accessibleName` to `AccessibilityLabel`, otherwise `press_face`’s title, otherwise empty. Leave the raw walk for custom buttons.

**3. A symbol-only custom menu row does not show its label.**
D5 and §9: a row’s visible title is `title ?? label`, and a symbol-only row shows its label. Native rows do that via `face.shown` (`ControlKinds.swift:152`, `MenusIOS.swift:316`, `MenusMac.swift:103`). Custom rows still walk child views (`MenusIOS.swift:317-320`, `MenusMac.swift:104-107`). The symbol image is applied to custom rows (`MenusIOS.swift:296`, `MenusMac.swift:88`), so the blank title now sits beside an icon. Confirmations use the same `title(of:)`.

Failing input: a popover row `button aria-label="Share"` whose only child is `image "symbol:share"`. The face label is `Share` and the title is none. The menu item’s title is `""`. `NativeContextsIOSTests.swift:106-116` gives the custom row a symbol and no label, and asserts only that the image exists, so it does not catch this.

Fix: for an `isButton` row, use `face.shown` (`title ?? label`). Keep the child walk for a pressable row that is not a button.

**4. An iOS symbol segment keeps the previous title.**
The new symbol branch sets the image and returns (`SegmentsIOS.swift:137-144`). It never clears the segment title. The title branch does clear the image (`:145-148`). macOS clears the label in the symbol branch (`Mac/SegmentsMac.swift:96-102`). A new control inserts segments with title `""` (`SegmentsIOS.swift:296`) only when the count changes, so the first paint of a symbol-only segment is fine.

Failing input: a two-tab `tablist` that stays a segmented control. Tab 0 is `when icon` then `image "symbol:list"`, else `text "List"`. Tab 1 is `text "Other"`. After `icon` becomes true, segment 0 shows `List` and the symbol.

Fix: in the symbol branch, `setTitle("", forSegmentAt: index)` before setting the image, including on the cache hit.

**5. A held Enter or Space presses a native tab or menu item on every repeat.**
`key_down` presses a native button under any role (`host/linux/src/presenter/typing.rs:206-214`). `type_key` still treats only role `button` or `link` as activation (`typing.rs:139-143`), and the repeat gate is `down && !(activation && repeat)` (`typing.rs:154-160`). For role `tab`, `menuitem`, `menuitemcheckbox`, or `menuitemradio`, `activation` is false, so every key-down calls `key_down` and `dispatch_press` (`surface_controls.rs:525-545`) runs again. A native button whose role is `button` suppresses repeats. The new test calls `type_key` with `repeat: false` (`host/linux/tests/it/native_buttons.rs:127`), so it passes for a real single press and never sees the repeat. A legal native button is not inside a canvas (D9), so `surface_input` does not swallow the key.

Failing input: the test’s `role="tab"` button, then `type_key(tab, "Enter", "Enter", true, true)`. The count becomes `pressed 2`. The same call on a native `role="button"` stays at `pressed 1`. Space (`" "`) does the same.

Fix: count a native button as activation for Space, Enter, and NumpadEnter, beside role `button`. Leave link as it is (Enter only at `key_down`).

**6. A custom swipe action does not gain a system symbol.**
D1 and the summary at `llp/1069.011.000-native-buttons-everywhere.rfc.md:17` say a custom swipe action’s symbol is a `systemName` image, and a raster keeps the snapshot. `SwipeActionsIOS.swift:326-336` does that only for `isNativeButton`. The custom branch (`:338-355`) still snapshots the first subview.

Failing input: a trailing swipe action that is a custom `button aria-label="Mute"` with `image "symbol:notifications"`. iOS shows a snapshot of that image view, not `UIImage(systemName:)` of `bell`.

Fix: in the custom branch, if `face?.symbol` is set, use that system image and record it in the action-image map; keep the snapshot when the face is a raster.

**7. A blank text child before a symbol marks the image as trailing.**
`press_face` sets `leading` from `texts == 0` (`kernel/src/control.rs:320`). The previous `button_face` set it from `title.is_none()`. A blank title is none (`control.rs:307-309`), but the empty text node still increments `texts`. Grammar allows that text (`contract/lower/src/controls.rs:737`, `may_be_empty`). iOS then uses `.trailing` with no title (`NativeButtonsIOS.swift:132-134`). macOS uses `.imageOnly` whenever the title is nil (`Mac/NativeButtonsMac.swift:143`), so the mis-placement shows on iOS.

Failing input: `button appearance="auto" aria-label="Add"` with `text (busy ? "Add" : "")` and then `image "symbol:add"`. When `busy` is false, the title is none and `leading` is false, so the icon sits on the trailing edge of an empty button. Image-then-text stays leading.

Fix: set `leading` from `face.title.is_none()` at the first image, as `button_face` did.

## Nits

The implementation leaves the colour unset when a destructive action has no accent (`SwipeActionsIOS.swift:330-331`), which is what D6 asks, and nil passes that assert. So would green. Assert nil (unset) for that fixture.

**A missed face read looks like an empty fitting button.** `ButtonFace` defaults `button` and `fits` to true (`ControlKinds.swift:120-126`). `buttonFace` returns that value when the runtime is busy (`Bridge.swift:440-441`), and `init(json:)` keeps it when the JSON does not parse (`ControlKinds.swift:135`). A tab bar then fails closed (no title and no symbol), so this is a transient empty button, not a wrong tab.
