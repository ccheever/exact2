**No blocker found in static review.** I found no new local-token disclosure or acceptance path. Two boundary defects remain, plus incomplete security coverage.

- **Should-fix — [scripts/tamber-remote.mjs:195](/tmp/rv-e1-2/scripts/tamber-remote.mjs:195): a missing/default Host port accepts any Origin port.** When `at.port` is empty, the comparison becomes `port(o) === port(o)`. Thus `Host: tamber.example.com` passes with `Origin: https://tamber.example.com:8443`, even with `--allow-host tamber.example.com:443`. This also changes flag-off behavior on TLS and loopback tunnel requests whose Host port normalizes away. A foreign-port page can reach the unauthenticated pairing endpoint with a simple POST; paired-token authentication still applies elsewhere.

  The [allowlist comparison at line 312](/tmp/rv-e1-2/scripts/tamber-remote.mjs:312) additionally treats ports 80 and 443 as interchangeable when `at.port` is empty. Parsing public Hosts as HTTP loses an explicit `:80`, so `--allow-host name:443` admits `Host: name:80`, while `--allow-host name:80` admits bare `Host: name`.

  **Fix:** preserve the raw Host authority and compare independently computed hostname/effective-port tuples using HTTPS for public tunnel names and the door’s scheme for loopback. Never derive the expected port from the incoming Origin. Test omitted ports, explicit 80/443/8443, and mismatched Origin ports.

- **Should-fix — [scripts/tamber-remote.mjs:129](/tmp/rv-e1-2/scripts/tamber-remote.mjs:129): forwarding-header rejection still differs from the dev gate.** The hook checks three headers; [developmentGate](/tmp/rv-e1-2/scripts/install-page.mjs:288) rejects every `x-forwarded-*` header. A proxy rewriting Host to this loopback port and supplying only `X-Forwarded-Proto` or `X-Forwarded-Port` therefore receives null-origin CORS through the main port. The local token remains refused, but the claimed restriction to requests from this machine is bypassed.

  **Fix:** use the gate’s case-insensitive `forwarded || startsWith('x-forwarded-')` predicate. Test each forwarding header independently.

- **Should-fix — [scripts/tamber-remote.test.mjs:488](/tmp/rv-e1-2/scripts/tamber-remote.test.mjs:488): the null-origin tests still leave important claims unproved.** The tunnel test uses a wire stub that accepts unauthenticated requests; the main-port test checks `hello.scope` without attempting forbidden operations. The new port tests miss the mismatches above.

  **Fix:** add real-wire null-origin cases on both entrances for local-token rejection, read/propose scope denials and local-only methods. Cover all four WIRE paths, actual 429 responses exposing `Retry-After`, `Vary`, max-age, absent credentials permission, absent CORS outside WIRE, main-port flag-off behavior, and IPv6/mapped peers. Use a rebound Host with the **correct listening port** so its rejection proves the hostname check independently.

The remaining security conclusions from inspection:

- Sandboxed iframes, `data:` pages and opaque `file:` origins receive the same remote principal. Rebound DNS Host names fail the hook. Canonical loopback Hosts must match the socket’s local port; `::ffff:127.0.0.1` is accepted as a **peer**, while a mapped IPv6 Host is excluded.
- The main-port token GET can still return its body without CORS, as before; ordinary cross-origin scripts cannot read it. Privileged extensions capable of bypassing CORS already fall outside that protection.
- Added CORS is confined to WIRE, with `Origin: null`, POST, the two named request headers, `Vary: origin`, max-age 600 and no credentials permission. Non-WIRE preflights receive no plugin CORS. TLS receives none.
- Paired scopes and server-assigned identity remain enforced centrally. IPv4 loopback pages share the pairing bucket, including tunnel traffic reaching the same wire. Any admitted null-origin page can exhaust it and burn live codes—an acceptable conservative throttling tradeoff, with an availability cost. IPv6 and mapped address strings currently have separate buckets.
