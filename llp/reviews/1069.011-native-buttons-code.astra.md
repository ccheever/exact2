1. **should-fix — A drag starting on an iOS native button can activate it instead of scrolling.**

   **Evidence:** [NativeButtonsIOS.swift:14](/Users/ccheever/projects/exact2-wt-native-button/host/apple/Sources/ExactKit/IOS/NativeButtonsIOS.swift:14) introduces a `UIButton`, while [ScrollViewIOS.swift:29](/Users/ccheever/projects/exact2-wt-native-button/host/apple/Sources/ExactKit/IOS/ScrollViewIOS.swift:29) delegates cancellation to UIKit.    **Failing scenario:** Put a native button in scrollable content. Hold until the button begins tracking, then drag far enough to initiate scrolling while remaining within the button’s bounds, and release. Scrolling is refused and the button can press. The custom button’s touch is cancelled.

   **Fix:** Make `ScrollView.touchesShouldCancel` explicitly permit cancellation of `NativeButtonIOS`, preserving the existing canvas exception. Test an actual touch-and-pan sequence; `sendActions` cannot exercise this failure.

2. **should-fix — Native activation makes focus depend on finding a press handler.**

   **Evidence:** Both [NativeButtonsIOS.swift:58](/Users/ccheever/projects/exact2-wt-native-button/host/apple/Sources/ExactKit/IOS/NativeButtonsIOS.swift:58) and [NativeButtonsMac.swift:88](/Users/ccheever/projects/exact2-wt-native-button/host/apple/Sources/ExactKit/Mac/NativeButtonsMac.swift:88) return before doing any focus work unless they resolve a press recipient. They then use that recipient for focus and `retainFocus`. Custom UIKit buttons perform their own focus step before forwarding the touch at [NodeViewIOS.swift:1345](/Users/ccheever/projects/exact2-wt-native-button/host/apple/Sources/ExactKit/IOS/NodeViewIOS.swift:1345). The iOS agent independently starts its focus walk at the touched node at [AgentIOS.swift:538](/Users/ccheever/projects/exact2-wt-native-button/host/apple/Sources/ExactKit/IOS/AgentIOS.swift:538).

   **Failing scenario:** Focus an editor, then tap an iOS `button appearance="auto" focus=mark` with a title but no press handler on it or its ancestors. The editor retains focus and `mark` never runs; the equivalent custom button takes focus. With an ancestor-only press handler, an agent tap can focus the button while a physical native action focuses the ancestor or clears focus.

   **Fix:** Separate the touched button’s focus handling from press-target resolution, and share that routine with the ordinary activation and agent paths. Cover handler-free buttons and ancestor-only handlers, including intermediate `retainFocus` ancestors.

6. **should-fix — Authored opacity removes the web’s disabled appearance.**

Dynamic authored opacity is written inline by [rt.js:704](/Users/ccheever/projects/exact2-wt-native-button/host/web-js/rt.js:704), so it overrides that rule.

   **Fix:** Compose disabled dimming with authored opacity instead of competing for the same property—for example, apply disabled treatment to the control’s face/chrome independently. Test bound opacity and opacity animation.
