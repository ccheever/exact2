1. **Medium — Redo can still lose the proposer’s attribution.** [apps/design-tool/app.ts:977](/tmp/rv-dt-6r3/apps/design-tool/app.ts:977) looks up the proposer **after** awaiting accept. The server removes the proposal and wakes the poll before completing accept; if that poll finishes first, `held.find()` returns nothing. Accept → Undo → Redo then credits the person pressing Redo instead of the agent. **Fix:** capture the proposer alongside the operations before awaiting, or take it from the successful response. Test with the poll deliberately delivered before the accept response.

2. **Medium — Batched writes still attribute unchanged cells to the wrong client.** [apps/design-tool/app.ts:878](/tmp/rv-dt-6r3/apps/design-tool/app.ts:878) treats every cell as changed whenever either intermediate snapshot is missing. If Alice changes only a token’s dark value and Bob changes only its light value before the next read, both events highlight the whole row; Bob overwrites Alice’s dark-cell attribution. **Fix:** retain per-event changes by mode and colour scheme, including for intermediate states the UI never reads. Missing snapshots must not imply that every cell changed.

3. **Medium — Cell comparison loses mode identity when columns move.** [apps/design-tool/app.ts:875](/tmp/rv-dt-6r3/apps/design-tool/app.ts:875) compares snapshots using the same numeric tuple index and emits that historical column ID. Adding a mode before an existing mode shifts its index: the unchanged existing cell is compared with a different or missing old value and highlighted as changed. Earlier highlights can likewise attach to the wrong displayed mode. **Fix:** match cells by axis names, axis values and colour scheme, then map them to the current grid’s columns.

4. **Medium — Highlights still lack independent expiry and survive file switches.** [apps/design-tool/app.contract:390](/tmp/rv-dt-6r3/apps/design-tool/app.contract:390), [apps/design-tool/app.ts:883](/tmp/rv-dt-6r3/apps/design-tool/app.ts:883). All pending highlights appear immediately, but only the oldest event expires every three seconds. Ten batched edits therefore keep the last highlight visible for about thirty seconds. Switching files before expiry cancels the timer; returning starts another full interval. **Fix:** retain each displayed highlight’s deadline across file switches and expire every highlight whose deadline has passed.

5. **Medium — Batched hand edits remain unhighlighted.** [scripts/tamber-server.mjs:428](/tmp/rv-dt-6r3/scripts/tamber-server.mjs:428), [apps/design-tool/app.ts:867](/tmp/rv-dt-6r3/apps/design-tool/app.ts:867). A hand edit followed immediately by an agent write produces a disk event with `changed: null`. Without a read between them, `measure()` cannot identify the disk edit’s tokens, and the highlight walk stops there. The hand-edited cells remain unlit; older unrelated highlights also disappear. The guard prevents false attribution but does not finish the earlier finding’s fix. **Fix:** provide disk-event cell deltas from retained server state, or make the intermediate snapshots available.

6. **Low — Tests still do not prove first-poll attribution or short rendered highlights.** [scripts/design-tool.test.mjs:503](/tmp/rv-dt-6r3/scripts/design-tool.test.mjs:503) advances twice before inspection without counting carrying polls. The cell assertions inspect resource data, and [line 513](/tmp/rv-dt-6r3/scripts/design-tool.test.mjs:513) now waits twenty-four seconds before checking expiry. Delayed attribution or excessively persistent outlines can pass. **Fix:** count the carrying poll, inspect rendered cell borders after it, and assert expiry at each highlight’s deadline, including batched writes and file switches.
