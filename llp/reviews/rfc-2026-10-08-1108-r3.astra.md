NOT READY

1. **BLOCKER — D2, `asset_reply` / `media_due` / `media_clear`.** Manifest-first publication is not serialized with file completion. A reply can record an entry, a round or clear can remove it, and the pending write can then recreate and return the revoked file. Likewise, `asset_lost {id}` from an older download can erase a newer entry. Serialize publication and removal per partition; identify completions and failures by exchange/version, invalidate outstanding work on clear/close, and recheck authority before returning the path.

2. **BLOCKER — D2 upload row, D4.5, D7.** A single `changed` boolean sampled before `upload_reply` cannot detect credentials changing during the web device’s asynchronous persistence. It also misses a refresh still in flight with unchanged headers. Existing `refreshSession()` returns the replacement session but does not install it; waiting for its promise does not ensure every opener’s `headers()` supplies the new bearer. Define shared credential ownership and refresh adoption, check before **and after** receipt persistence, and await `forget_upload_facts` cleanup before completing a rejected upload or closing. Snapback’s `dist/local.js:1745–1778` explicitly handles this interval.

3. **MAJOR — D3, “Online, a kept file is shown without a download.”** The eventual-consistency trade is reasonable, but `asset_home` establishes local row authority, not session validity: it receives a viewer string and no bearer. A round can learn `E_AUTH` while the retained row still passes `asset_home`; D2 currently permits returning its file. Gate cached reads on known authentication/restore refusals and sign-out state. Document that *unobserved* remote revocation remains delayed until synchronization, while an observed refusal immediately prevents new handles.

4. **MAJOR — D3 removal guarantees; `host/web/picker-glue.js:35–53`, `host/web-js/symbols.js:60–67`.** Removing the file does not invalidate its displayed source. `appURL` retains its object URL, and `appSource` does not watch filesystem deletion. An in-memory execution of the existing glue confirmed the old URL remained readable after the backing entry disappeared. Specify how affected resources clear their image source and how host URLs are revoked on removal/release. The current “no runtime change” slice cannot promise that an already displayed asset stops showing after reconciliation.

5. **MAJOR — D3 transient files; D2 `release` and `clearMedia`.** Every caller receives the same `<partition>/<id>.<ext>` transient path. Two independent avatar consumers therefore share a lifetime accidentally: either can release the other’s file, including a newer download. Moreover, sign-out’s `clearMedia()` removes only kept paths. Give transient acquisitions independently releasable handles—unique paths are sufficient—and clear all transient handles and pending publications on sign-out.

6. **MAJOR — D2 `media_due`; D3 cap enforcement.** Aggregate eviction runs only at open and after rounds. Downloads run beside rounds, and admission checks only the individual object’s size. Several downloads after the last round can exceed 64 MiB indefinitely. Enforce the aggregate cap during each serialized retention publication, including concurrent reservations; define the transient fallback when the newly downloaded object cannot remain kept.

7. **MAJOR — D2/D3 explicit time; D4 refusal metadata.** The driver has no specified source of `now` for open-time and post-round checks: current `open(options)` and `sync()` take no timestamp. Nor is offline expiry driven when no call occurs. Define explicit timestamp arguments and a Contract-driven expiry check. Separately, D4 promises `retryAfter`, but D2’s media reply excludes `Retry-After`; Snapback reads that HTTP header, including seconds and HTTP-date forms. Carry it through and normalize using explicit time.

Ordering work incrementally is fine; leaving the required work ownerless is not a concrete implementation commitment. Assign implementers and dates for the ruled runtime work and Interview adoption.
