## Review (verbatim)

1. **HIGH — One `touched` flag can erase untouched fields. Confidence: high.**  
   [r2:208](/Users/ccheever/projects/exact2/llp/1027.003.000-bounded-application-work-claude.plan.md:208)

   Open a saved note `{title:"A", body:"B", pinned:true}` from a fresh editor, then change only its title. The proposed `edit(id)` never initializes the draft slots. `changeTitle` updates only `title`, but setting `touched=true` switches **body and pinned too**, exposing their stale `""` and `false` values. Saving then erases the body and unpins the note. Pin-first and body-first interactions have analogous failures. The existing actions confirm the single-field writes. [Fieldnotes Contract:63](/Users/ccheever/projects/exact2/apps/fieldnotes/app.contract:63)

   **Fix:** use per-field edited flags, or atomically copy all three displayed fields into draft state before the first change. Toggle the displayed pin value. Test each control as the first interaction.

   Editable derives themselves are supported by the compiler. The cited `backupText` example is actually `readonly=true`; it is inaccurate evidence, although the proposed binding is legal. [Lowering:1327](/Users/ccheever/projects/exact2/contract/lower/src/lib.rs:1327)

2. **HIGH — The proposed editor no longer has a correct reference baseline or saved-note identity. Confidence: high.**  
   [r2:204](/Users/ccheever/projects/exact2/llp/1027.003.000-bounded-application-work-claude.plan.md:204)

   Two concrete failures:

   - Open an existing note without typing. `originalTitle`, `originalBody`, and `originalPinned` are no longer initialized, but `reference*` still falls back to them. The loaded note immediately becomes dirty, blocking navigation.
   - Create and save a new note, edit it again, then discard. The successful save changes `editingId` through `saved.id`; `noteId` remains empty until another save action. Consequently `opened(noteId,…)` still describes the empty new-note record. Discard sets `touched=false` and displays empty fields instead of the saved note. [Existing references and save action](/Users/ccheever/projects/exact2/apps/fieldnotes/app.contract:47)

   The resource also lacks the editor generation that the prose requires it to qualify. Pending resources retain their previous answer; the shown derives contain no pending/id/generation qualification. [LLP 1016 D3](/Users/ccheever/projects/exact2/llp/1016-async-data-settlement.rfc.md:162)

   **Fix:** define one identity-qualified loaded baseline, request the effective saved ID with the editor generation, and reconcile `reference*`, discard, pending, and missing-note behavior around that baseline. Explicitly test “open is clean” and “new → save → edit → discard.”

3. **HIGH — The journal’s listed hooks miss durable mutation paths. Confidence: high.**

Other omitted paths include `react`’s nested reaction mutation and `expireDeleted`’s recovery-record removal. [Messages:284](/Users/ccheever/projects/exact2/apps/messages/app.ts:284), [381](/Users/ccheever/projects/exact2/apps/messages/app.ts:381), [117](/Users/ccheever/projects/exact2/apps/messages/app.ts:117)

4. **HIGH — D6’s signal misses durable changes and can leave the model permanently stale. Confidence: high.**  
   [r2:296](/Users/ccheever/projects/exact2/llp/1027.003.000-bounded-application-work-claude.plan.md:296)

   Start with acquired records, observe a replacement server store, then fail fetching `/schema`. `observe_store` has already durably cleared the old partition, but no watermark advanced, no record was applied, and no outbox entry necessarily settled. The proposed condition skips reconciliation and leaves the old conversations displayed. [Client reset/adoption path:139](/Users/ccheever/projects/exact2/apps/messages/snapback-client.ts:139), [pinned device’s durable reset:77](/Users/ccheever/.cargo/git/checkouts/snapback-92daed764a282cff/a397218/snapback4/crates/snapback4-device/src/device/store_identity.rs:77)

   **Fix:** maintain a reconciliation-needed latch across ticks. Set it after successful reset, adoption, relevant apply/publication, or settlement; preserve it through exceptions; clear it only after successful reread and model publication. S3.1’s ordinary empty-page test passes without covering these failures.

5. **HIGH — Holding the TS gate does not make native OFFSET paging consistent. Confidence: high.**  
   [r2:184](/Users/ccheever/projects/exact2/llp/1027.003.000-bounded-application-work-claude.plan.md:184)

   With 100 matching, unpinned notes, read IDs `100…51`. Another native connection pins ID `1`. The next `OFFSET 50` page contains `51…2`: ID `51` appears twice and ID `1` is never returned.

   Native connections use SQLite locking and finish each query separately; an open handle is not a transaction spanning these awaits. The provider even tests simultaneous separate connections. [Native query implementation:222](/Users/ccheever/projects/ibex/crates/ibex2-sqlite/src/lib.rs:222), [connection test:128](/Users/ccheever/projects/ibex/crates/ibex2-sqlite/src/tests.rs:128)

   Web’s exclusive file lock prevents this interleaving by refusing competing opens, but that does not establish native parity. [Web locks:80](/Users/ccheever/projects/exact2/host/web/storage-fs.js:80)

   **Fix:** use indexed keyset traversal plus a database revision checked across chunks, including writes from other owners, or provide a genuine read snapshot. Restart/refuse a changed scan. A missing-table retry must also discard already accumulated chunks.

6. **HIGH — The final UTF-16 slice still makes an admitted notebook unreadable. Confidence: high.**  
   [r2:148](/Users/ccheever/projects/exact2/llp/1027.003.000-bounded-application-work-claude.plan.md:148)

   Use body `"a".repeat(99) + "😀"`. SQLite’s prefix contains the complete emoji, but the retained `.slice(0,100)` produces 99 ASCII characters followed by a lone high surrogate. JSON serialization escapes it; the Rust answer decoder rejects it, failing the library answer. [Excerpt construction:42](/Users/ccheever/projects/exact2/apps/fieldnotes/app.ts:42), [browser answer decoder:156](/Users/ccheever/projects/exact2/js/web/src/lib.rs:156), [native failure path:551](/Users/ccheever/projects/exact2/js/src/lib.rs:551)

   **This is a pre-existing defect preserved by r2**, not a new consequence of SQLite’s character counting. It contradicts the intended admitted-notebook readability guarantee.

   **Fix:** retain the UTF-16 length ceiling but back off a cut that bisects a surrogate pair, and declare that correction. Test through the actual answer seam; the listed search-Unicode and maximal-size fixtures need not exercise this boundary.

7. **MEDIUM — OFFSET turns the declared scan into at least quadratic traversal. Confidence: high.**  
   [r2:174](/Users/ccheever/projects/exact2/llp/1027.003.000-bounded-application-work-claude.plan.md:174)

   There is no `(pinned,id)` ordering index in the schema. Each chunk repeats the table traversal and ordering work. With fixed chunks of 50, scanning N notes requires roughly N/50 full traversals: **Ω(N²/50)** row visits, with additional sorting costs. Even adding an index leaves cumulative OFFSET skipping quadratic. [Current schema:31](/Users/ccheever/projects/exact2/apps/fieldnotes/app.ts:31)

   SQLite’s limited sorter can retain `LIMIT+OFFSET` entries, approaching N on the last chunk; bounding the returned page does not bound that intermediate work. [SQLite sorter:149694](/Users/ccheever/.cargo/registry/src/index.crates.io-1949cf8c6b5b557f/libsqlite3-sys-0.38.2/sqlite3/sqlite3.c:149694)

   **Fix:** restore the sibling’s ordering index and keyset seeks. Add query-plan/work verification: all final-answer byte and static search-equivalence criteria can pass while this defect remains.

8. **MEDIUM — D10’s three constraints do not cover a fast anchor with a slow visible remainder, or end clamping. Confidence: high.**  
   [r2:418](/Users/ccheever/projects/exact2/llp/1027.003.000-bounded-application-work-claude.plan.md:418)

   A destination’s short anchor row can finish in 1 ms while the remaining visible rows require several frames. Constraint 3 then prohibits provisional content, although most of the viewport is unavailable. The implementation must either block to finish it or display the blank area constraint 2 forbids.

   Anchor-first also cannot guarantee immobility at the end. If rows below the anchor shrink, the new maximum scroll offset can fall below the anchor-preserving offset. Existing restoration explicitly clamps to that maximum, moving the anchor onscreen. [HeightIndex:315](/Users/ccheever/projects/exact2/runner/src/instance/collection/index.rs:315)

   **Fix:** base provisional publication on readiness of the **whole visible region**, and specify end-follow/clamping exceptions. Test fast-anchor/slow-neighbor and shrinking-tail cases.

   The supporting argument also overreads “scroll always wins”: it governs gesture arbitration. Existing native code deliberately settles destination geometry before returning the presentation batch; an estimated total extent does not establish an existing policy of presenting unfinished visible rows. [LLP 1002 D4](/Users/ccheever/projects/exact2/llp/1002-motion-v1.rfc.md:102), [native settlement:715](/Users/ccheever/projects/exact2/host/apple/src/host.rs:715)

## Disposition (Claude, 2026-09-20)

Every finding below was checked against the source before disposition. Findings 1, 2,
3, 4, 5, 7 and 8 were **independently raised by Grok 4.6 xhigh** in the same round, so
they are confirmed defects rather than hypotheses; the file is
`1027.003.000-bounded-application-work.grok.md`.

1. **Confirmed, fixed in r3.** A single `touched` flag exposes the stale `""`/`false`
   of the fields the user did not type in. r3 D4 uses per-field flags and toggles the
   displayed pin value. The `backupText` evidence was indeed `readonly=true` and is
   removed; the compiler does lower `value=` as an ordinary prop binding over any
   expression (`contract/lower/src/lib.rs:1327`), which is now the citation.
2. **Confirmed, fixed in r3.** r3 drops `original*` entirely, derives `reference*`
   from the loaded baseline, keys `opened` on `editingId` rather than `noteId`, and
   qualifies every editor derive on `opened.id == editingId`.
3. **Confirmed, and the most important finding of the round.** Verified at
   `apps/messages/app.ts:284` (`markRead`), `:285-289` (`setConversationUnread`),
   `:381-383` (`react`), `:117-121` (`expireDeleted`), `:353` and `:375` (direct
   `person.preview`/`time`/`unread`). The claim that rollback makes a missed key safe
   is false — a miss raises nothing. r3 D7 replaces per-mutation-site hooks with a
   per-source footprint declaration plus a debug-mode verifier that recomputes the
   whole snapshot and fails loudly on disagreement, and S3 gains every source in its
   durable-equivalence sequence.
4. **Confirmed, fixed in r3.** The reset path durably clears the partition before
   `/schema` can throw. r3 D6 uses a reconciliation-owed latch that survives
   exceptions and ticks, not a watermark comparison.
5. **Confirmed, fixed in r3 by a different route.** Rather than keyset over
   `(pinned, id)` plus a revision guard, r3 scans in `id DESC` keyset order and sorts
   the accumulated summaries by `(pinned, id)` in TypeScript at the end. A concurrent
   pin cannot move a row in `id` order, so the scan is pin-stable by construction and
   needs no cross-chunk revision check.
6. **Confirmed as pre-existing; fixed anyway.** `.slice(0,100)` can cut a surrogate
   pair, and `serde_json` rejects a lone-surrogate escape, so the answer fails. S1
   promises every admitted note is reachable, so r3 backs the cut off a bisected pair
   and declares the correction.
7. **Confirmed, fixed by finding 5's keyset.** `id` is the rowid, so the scan is an
   index walk and needs no new index.
8. **Confirmed, fixed in r3.** The threshold moves from the anchor's readiness to the
   whole visible region's, and end clamping is named as an exception. The
   "scroll always wins" citation is withdrawn — see the grok disposition, which
   supplies the mechanism r3 now uses instead.
9. **Confirmed by execution, not only inspection.** `sqlite3 :memory:` returns `''`
   for `substr(char(0)||'visible',1,20)` and 8 bytes for the same over
   `CAST(… AS BLOB)`. r3 extracts the prefix as a BLOB and decodes it.
10. **Confirmed, fixed in r3.** S2 now requires path-bounded key and range queries for
    directory operations too, and counts unrelated bytes for them.

The byte arithmetic correction is accepted: `host/web/storage-worker.js:85-99` charges
24 bytes per cell, so D2's result approaches ~1.2–1.4 MB rather than 600 KB. r3 states
the budget with the cell charge included.
