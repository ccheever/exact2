# Design review: LLP 1108.001 r3, Grok

Reviewer: Grok 4.7 (xhigh, read-only), 2026-10-08, blind, same tree and brief as Astra's.

NOT READY

1. **BLOCKER** — §1.6 against parent D2. The not-written, non-JSON reply is handed to the core as `{status, headers}` with the four media headers and no body. D2's sum, which §0 says stays authoritative for the client, is only `{status, headers, size} | {status, body} | {error}` (`llp/1108-media-from-snapback.rfc.md:241`, `:249`). A core built to that sum cannot decode the new arm. Sending the headers arm with a size makes the whole-object check (`:256-258`) look for a file that was not written. The write gate itself does resolve Astra r4 #7: §1.3 writes only a `2xx` whose `when` headers all match, decided before any body byte; a refusal stays readable; `accept-ranges: none` is not written when `when` requires `bytes`; the byte count comes back; the file is a unique path the media queue renames. Change: keep that gate, and amend D2 so this reply is the existing headers arm with `size` absent. The core treats a missing size plus `accept-ranges: none` as `E_ASSET_ONCE_UNSUPPORTED` until slice 3 and does not stat a path.

2. **MAJOR** — §1.4 and §1.6 name two publication orders, and neither is callable on the current staging API. §1.4 (lines 114–116) checks let-go, then syncs, then renames. §1.6 (lines 176–183) syncs first and allows only `renameat` after the lock. `Staged::publish` (`vendor/ibex/crates/ibex2/src/stdlib/app_fs_unix.rs:755-762`) is one `sync_all` then `renameat`, and the file is private. `forget` (`host/apple/src/executor_core.rs:427-429`) marks every running ticket forgotten but aborts only `run.abort`, stored solely for `safe()` GET/HEAD (`:535`). `finish` watches that signal (`:989`), so a forgotten POST still publishes. `complete` (`:555-559`) then drops the outcome, so §1.6's "the fetch settles as it would have, with the file" does not happen. On the web, `forgettable` / `letGo` (`host/web/glue.js:753`, `:954`) abort only GET/HEAD, and the save path checks that same signal (`host/web/http-body.js:244-248`). A stalled `sync_all` also holds the worker; `exactBodyFrom` already returns at the deadline from a watcher (`host/apple/src/executor_body.rs:126-142`). Change: one order in both sections — sync outside the lock, then under the mutex `forget` uses, rename only if the ticket is still held and the deadline has not passed. Split `publish` into `sync` and `rename`. Settle `Timeout` at the deadline while sync is still in the syscall, and unlink when it returns. On the web, `letGo` sets the flag for every save ticket, and `saveBody` checks it after `lockPaths` and before `putBlob`. Say a let-go that loses the race leaves the file and does not resolve the promise; the client's open sweep removes that staging path.

3. **MAJOR** — §2.3 copies a `Blob` body into `Request.body` inside the door call. `reservation` counts `body.capacity()` toward `MAX_REQUEST` of 4 MiB (`host/apple/src/executor_core.rs:28`, `:687-713`). `exactBodyFrom` stays under that cap by carrying a path and reading up to 64 MiB after admission (`executor_body.rs`). A `Blob` over 4 MiB fails "native request exceeds 4 MiB", which Fetch does not do and this spec does not declare. The wasm realm's `body_base64` path (§2.2) hits the same ceiling after the 4/3 expansion (`js/src/wire.rs:41-44`). Change: keep the bytes in the side table until the worker sends, and charge them like `body_from` (64 MiB, not part of the 4 MiB request), or state the 4 MiB ceiling on every executor, including the web.

4. **MAJOR** — §2.4's bake refusal does not defer the answer. `Module::step` defers only `Unavailable` with `code: "bake"` (`js/src/lib.rs:700-703`). `fail` copies `e.code` (`js/src/prelude.js:1010-1014`); storage sets that code (`:778`, `:838`). A bare `Error("object URLs are unavailable during bake")` is a failed answer, and the build does not ask again on the device. Change: throw the storage-shaped refusal `{kind: "Unavailable", code: "bake", message}` from Hermes, and from the JS-target bake if that bake evaluates the call.

5. **MINOR** — Parent D5 (`llp/1108-media-from-snapback.rfc.md:430-431`, `:444-445`) still says every executor, including the web, returns `blob:<app id>/<uuid>` and that a URL lives until the process ends. §2.2 and §2.4 correctly use the browser's URL on the web, an opaque origin for the Hermes form, and engine teardown. Say those two D5 sentences are amended here. A web implementer following D5 will mint a URL the page will not load (`host/web/glue.js:187-201` returns the string through; `host/web-js/symbols.js:37` sets it as `src`).

Round-2 items the text does close, checked against the code: full-value `when` (§1.1; the draft's `saveAdmits` at `host/web/http-body.js:277-279` still splits on commas — r3 governs), no web length compare (§1.4; `http-body.js:281-284`), the leading-colon line (`host/web/src/host.rs:81-86`), the D2b stream plus redraw (§2.4), the animation owner holding `Data` (§2.6; `AnimatedRaster.swift:173`, `:202`), wasm upload as `body_base64` (§2.2), `fetchEarly` skipping a save (`host/web/module-glue.js:54`), `saveBody` under `mutate` (`host/web/storage-fs.js:458-460`), and `TYPESCRIPT_RUNTIME` already 2 (`bake/src/compat.rs:38-42`). No apparatus, boot-path, or cap break. Slice order, the 64 MiB save cap, and the 256 MiB bound match Charlie's rulings.
