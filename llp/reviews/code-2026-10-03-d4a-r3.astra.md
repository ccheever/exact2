   component App
     state o = none
     derive d = match o { case some(k) => match k { case "a" => "A", case "b" => "B" }, case none => "none" }

Action checking subsequently refines `o` to `option<"a" | "b" | "c">`, but never rechecks the derive. Pressing the button therefore matches `"c"` against arms containing only `"a"` and `"b"`; the unconditional final arm produces `"B"`.

2. **MATERIAL — `fits` rejects valid choice values carried through options.**

   ```contract
   component App
     state o = some("x")
     view
       Child(k=match o { case some(x) => "a", case none => "b" })

     props
       k: "a" | "b"
     view
       text match k { case "a" => "A", case "b" => "B" }
   ```

   `given` correctly accepts the argument against the declared choice. After substitution, however, `fits` handles ternaries but not option matches. It infers the argument as `string` and rejects it. Providing this same expression to an injection reproduces the failure.

Expansion infers `x` as `string`, so the valid exhaustive match is refused. Adding only an `Expr::Match` branch to `fits` would not fix this variant.

   **Suggested fix:** Preserve contextual choice evidence through substitution and option bindings, or contextually check substituted expressions and their bound values against the already validated declaration.
