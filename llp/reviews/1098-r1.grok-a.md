## MATERIAL

**1. D6, D11, §4 stage 2 — the JS target rejects the six events.**
`host/web-js/src/emit.rs` has an exhaustive `EventKind` match and returns an error for anything else:

```1245:1249:host/web-js/src/emit.rs
                k => {
                    return Err(format!(
                        "node {i}: the `{}` event is not in the JS target",
                        k.name()
                    ))
```

Stage 2 names `media.js`, `rt.js:551`, and `glue.js` only (`llp/1098-the-media-session.rfc.md:749`). A program that binds `seekforward` fails the JS build with `the seekforward event is not in the JS target` before `media.js` runs. `rt.js` `on()` only routes names in `MEDIA_EVENTS` (`host/web-js/rt.js:826`, `host/web-js/media.js:14`).

Fix: add `emit.rs` to the stage-2 file list and add the six kinds to that match, routed through `on` the way `Loadedmetadata` and `Canplay` are.

**2. D2, D6, D11 — the record the runner builds does not conform on the JS target.**
The shape is `{ action, seekOffset, seekTime, fastSeek: bool }` (`llp/1098-the-media-session.rfc.md:256`). D11 decodes a payload of three numbers whose last is `0` or `1` (`:649–653`). D6 tells `media.js` to pass `[action, seekOffset, seekTime, fastSeek]` from the string `"15 0 0"` (`:409–423`). `conforms` accepts a bool only as a real boolean:

```12:12:host/web-js/shape.js
  if (c === "b") return typeof v === "boolean";
```

`act` then throws `argument N does not conform` (`host/web-js/rt.js:218–224`) and the action never runs. The wasm runner’s other records use `Value::Bool` (`runner/src/runner/event.rs:433–441`). The payload also has no `action` field; `Event::record` today returns `None` for `Event::Media` (`event.rs:482`). A three-number record does not match the four-field shape, so an action that takes the record fails conformance. For `previoustrack`, `nexttrack`, and `stop`, “`seekOffset` is the element’s offset for that direction” (`:261–262`) names no direction. For `seekto`, the spec requires `seekTime` (W3C Media Session §10, fetched copy lines 585–587). Defaulting an absent `seekTime` to 0 seeks to the start.

Fix: state that the runner writes `action` from the event name, then the two times, with `0`/`1` mapped to `false`/`true`, and that `media.js` passes that boolean. For the three non-seek actions, `seekOffset` and `seekTime` are 0 and `fastSeek` is false. If a platform `seekto` arrives without `seekTime`, do not dispatch.

**3. D11 — widening `media_payload`’s range admits the events between `canplay` and `drop`.**
The media kinds are a contiguous run, `loadedmetadata` through `canplay` (`plan/tables/format.json:623–636`). After that come `pan`, `select`, `refresh`, `input`, `cancel`, `panrelease`, the pointer and clipboard kinds, `beforeunload`, `wheel`, and `drop` (`:637–652`). The decoder refuses anything outside that run:

```512:516:runner/src/runner/event.rs
    pub fn media_payload(payload: &str) -> Option<Self> {
        let (name, value) = payload.split_once('\n')?;
        let kind = EventKind::from_name(name)?;
        if !(EventKind::Loadedmetadata as u8..=EventKind::Canplay as u8).contains(&(kind as u8)) {
```

D11 appends the six after `drop` and says this same inclusive check admits them (`llp/1098-the-media-session.rfc.md:638–653`). Extending the range through the new kinds also accepts `drop\n…` and `input\n…` as host-kind-19 media events.

Fix: leave `Loadedmetadata..=Canplay` as it is and add an explicit allow-list for the six. Add a runner test that `drop` and `input` through `media_payload` are still refused.

**4. D3 — a remote play does not win over `playbackVisibilityThreshold` once the app mirrors `paused`.**
D3 says a remote play or pause wins over `playbackVisibilityThreshold` until the app’s next change to `paused` (`llp/1098-the-media-session.rfc.md:314–317`), and D3 and D14 tell the app to mirror the element’s `play`/`pause` into that binding (`:309–313`, `:718–719`). The glue recomputes on every update and on every intersection callback:

```14:18:host/web/media-glue.js
  if (props.paused == null) { state.paused = undefined; return; }
  const paused = props.paused === 'true' || state.visibilityBlocked;
  if (paused !== state.paused || props.src !== state.applied.src) {
    state.paused = paused;
    if (paused) el.pause();
```

LLP 1042 §3 (`llp/1042-video.spec.md:110–120`) says a finite threshold overrides an authored `paused` binding while the element is below the threshold, and a manual `paused=true` wins. Unbound `paused` is consistent: `syncPlayback` returns at line 14, and `play()`/`pause()` end Chrome’s off-screen autoplay flag (`llp/1042-video.spec.md:97–108`). Bound `paused` is not. The podcast pattern is the failing one: the episode is off-screen with `paused=true`, a media-key play calls `el.play()`, the `playing` handler sets `paused=false`, and that write is the “next change” that ends the override, so the next `syncPlayback` pauses again.

Fix: specify a latch. A person-play override stays while the element is visibility-blocked and the authored `paused` is false, including the mirror write that sets it false. It clears when the app sets `paused` to true, or when the element is back in view and the authored value applies. A person-pause is the manual `paused=true` LLP 1042 already keeps.

**5. D1, D6, §1 — artwork resolution, as specified, publishes the wrong URL or drops the authored source.**
§1 says `{src:"assets/art.png"}` on `http://localhost:…/show/x` reads back as `…/show/assets/art.png`, “the wrong file” on a route (`llp/1098-the-media-session.rfc.md:136–139`). That measurement is true only with no `<base>`. Exact shells set `<base href="/">` (`host/web/index.html:5`, `host/web-js/build.mjs:395`) and the router `pushState`s the path (`host/web/navigation.js:63–83`), which does not change `document.baseURI`. The spec parses artwork against the API base URL (Media Session §6, convert-artwork, fetched copy lines 455–461).

Probe, same three engines, page `http://127.0.0.1:60205/…`:

| Page | `assets/art.png` read back |
|---|---|
| `/show/x`, no base (`baseURI` is the page) | `http://127.0.0.1:60205/show/assets/art.png` |
| `/base/show/x` with `<base href="/">` | `http://127.0.0.1:60205/assets/art.png` |
| load `/base/`, then `pushState` to `/show/x` (`baseURI` stays `…/`) | `http://127.0.0.1:60205/assets/art.png` |

`artwork:[{src:""}]` does not throw. It becomes the page URL with no base (`…/show/x`) and the document base with `<base href="/">` (`…/`). D1 requires `artwork=""` to claim (`:219–222`). Publishing that empty `src` makes the document its own artwork. The spec’s empty metadata (title, artist, and album all `""`, artwork length 0; §6 lines 435–441) then unsets the platform display (`§4.3` step 2) while Exact still counts the element as a claimant.

D6 also says both targets hand the glue `mediaArtwork` already resolved, by adding the name to `glue.js:443` and `rt.js:551` (`:401–407`). D10 says `metadata.artwork` is the authored source (`:556–558`). Those disagree. `syncMedia` copies the raw prop set into `el.exactMedia.props` before attribute resolution (`host/web/glue.js:24–28`, called at `:405`). Line 443 only changes the attribute passed to `setAttribute`. The glue reads props (`llp/1098-the-media-session.rfc.md:393–394`), so the `:443` edit never feeds it. On the JS target, `h()` runs `rel()` before `media()` copies attributes (`host/web-js/rt.js:551–558`, `host/web-js/media.js:39–44`). `rel()` rewrites only root-absolute `/assets|deck|shaders/` paths on a release base. `localAssetURL` (`host/web/glue.js:185–196`) returns a `blob:` URL when the dev asset map hits. A relative string left to `MediaMetadata` requests `/assets/art.png` and misses that blob.

Fix: keep the authored string on the prop and resolve only when constructing `MediaMetadata` (and when Apple loads the image). If the authored artwork is `""`, publish `artwork: []`. Say in §1 that the route measurement was taken on a page with no `<base>` and does not apply to Exact’s shell. Say that a blank claim (all strings empty and no artwork) still claims in Exact and unsets the platform metadata.

**6. D4, §2 — setting `playbackState` to `"paused"` does not publish a paused platform state.**
D4 says the web sets `navigator.mediaSession.playbackState` to `"playing"` while the owner is not paused and `"paused"` while it is (`llp/1098-the-media-session.rfc.md:326–330`). §2 says the browser infers the state when it is unset (`:159–160`). The spec’s actual playback state is the declared state only when the declaration is `"playing"`; otherwise it is the guessed state (Media Session §4.1, fetched copy lines 123–126). The guess is `"playing"` when any media element in the browsing context is potentially playing and not muted (lines 119–120). A declared `"paused"` or `"none"` does not override that guess. While the actual state is `"playing"`, the actual playback rate is the reported rate, and the reported position keeps moving (§4.5, lines 256–267). The actual rate is 0 only when the actual state is `"paused"`.

The IDL getter returns the declaration. The probe round-tripped `"paused"`, `"playing"`, and `"none"` on all three engines, so `readback.playbackState` can say `"paused"` while the platform’s actual state is `"playing"`. D5 allows a playing non-claimant its own default session only while no claimant is mounted (`:382–385`). With a paused claimant mounted, the page still owns the metadata, and a playing unmuted non-claimant keeps the actual state `"playing"`. The headset toggle then chooses `pause` (§4.4, line 216) and pauses the already-paused owner.

The single-element case matches D4. The probe’s ended clip does too.

Fix: call the attribute a declaration. State the §4.1 rule in D4, and state that a paused claimant does not force the platform to paused while any other unmuted element is potentially playing. Publish position on the events D4 already names; do not try to force the guess by pausing other elements.

## MINOR

**7. D5 — the prose describes a different owner than the numbered rule.**
The rule (`llp/1098-the-media-session.rfc.md:354–358`) keeps the claimant that most recently reported `play`, including after it pauses. The example says the trailer takes the lock screen “while it plays, and the episode keeps it otherwise if it played last” (`:368–370`). That reading hands the session back when the trailer pauses. Two `play` events in one commit have no tie-break; document order is specified only for mounts. Across LLP 1031 sessions, document order is not a total order.

Fix: say the trailer keeps the session after it pauses until another claimant plays or the trailer unmounts. For two plays in one commit, the later in document order wins. Across sessions, the order is registration order at the single coordinator. Re-run the rule on the remaining claimants when the owner unmounts.

**8. D10 — the grammar and the tests spell the action differently.**
The EBNF is `"tap" STRING "mediasession" IDENT` (`:601`). The contract test and §5 use a quoted action: `tap "audio" mediasession "seekto" 600` (`:618–620`, `:768–770`). Other steps quote the key (`contract/syntax/src/parser/steps.rs:273–278`). An implementer who follows the EBNF rejects the test in the same draft.

Fix: change the EBNF action to `STRING` and keep the quoted examples.

**9. D2, Summary, Q6 — the 15 s / 30 s skips are the driver’s, and Apple’s label.**
D2 is right that the web has no API to declare an offset (`:271–274`). The spec says `seekOffset` may be absent, and the page then chooses a sensible time (§10, lines 583–584). The Summary’s `skipBy` uses `details.seekOffset` (`:36–37`), and D2 prefers the platform’s value (`:243–244`). Chromium’s controller default, when a client seeks by “a few seconds,” is `kDefaultSeekTimeSeconds = 5` (`services/media_session/public/mojom/constants.mojom`). What Chrome’s media hub actually passes was not measured from Playwright. The conformance step `tap "audio" mediasession "seekforward"` / `expect state seek == 30` (`:618–619`) is the driver path, where absent seconds mean the element’s offset (`:580–582`).

Fix: say in the Summary and in Q6 that on the web the element’s offset is used only when the platform omits `seekOffset`, and that the `seek == 30` test does not assert Chrome’s hub. Keep default 10 as the page’s choice when the offset is absent.

**10. D2 — a bad computed offset does not fall back to 10 if a good one was already applied.**
D2 says an out-of-range computed offset reports `invalid-value` “and the default stands,” citing `media-glue.js:52` (`llp/1098-the-media-session.rfc.md:275–279`). That line reports the error and `continue`s, leaving the previous applied value (`host/web/media-glue.js:49–54`).

Fix: say the last finite value greater than 0 stands, and 10 is used only when none has been applied.

**11. D9, D10 — Linux lists play and pause as offered actions and then refuses the tap.**
The sample `actions` array includes `"play"` and `"pause"` (`llp/1098-the-media-session.rfc.md:547`) on a web `published` value. D9 refuses a Linux `play`/`pause` tap as `unavailable` because there is no player (`:526–527`). D2’s rule is that a bound handler is an offered action (`:280–284`); play and pause are not handlers (D3).

Fix: say Linux `actions` lists the six the owner handles, and that `play` and `pause` are absent there because the tap refuses them.

**12. D13, Q1 — the take deletes an inventory that Still out does not keep.**
Deleting LLP 1042 §5’s unimplemented extension (`llp/1042-video.spec.md:234–277`) matches RULES.md’s “a spec needs an implementer and a date.” The take paragraph names what returns with a consumer (`llp/1098-the-media-session.rfc.md:692–698`). The proposed DEFERRED “Still out” text (`:699–703`) does not include source and track children, the media controller, PiP and fullscreen results, DRM, downloads, or interruption and route policy for the media element (LLP 1096 resumes sounds; D8 does not resume the `AVPlayer`). The requirements list above that design (`llp/1042-video.spec.md:214–228`) would also keep a stale “lock-screen metadata and MPRemoteCommandCenter” bullet.

Fix: put those items in Still out with the return trigger “a consumer.” Strike the lock-screen bullet from LLP 1042 §5’s remaining-requirements list and point it here. No new tag; the Components count stays unchanged. The admission pattern matches the landed LLP 1096 entry (`rules/DEFERRED.md:386–404`).
