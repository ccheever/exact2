## Reconciliation

A first pull creates the collection, renames `Mode 1` to the export's default context, and stores that mode id under the full context. A re-pull with the same contexts, or with more, fewer, renamed, or reordered ones, resolves each surviving context through `contextIds` and will not give that id to a different context. A mode renamed in Figma is found by that id and renamed back, in two steps, so two modes that have traded names succeed even when a taken name is refused. A collection renamed in Figma is found by its stored id and renamed back to `Tamber`. A deleted collection is reported unread and is not read from a same-named stranger. Pull recreates it when the name is free, and refuses before any mutation when an unowned collection already has the name.

One collection splits into per-tuple collections when the mode cap refuses the single collection, and the old collection is removed. The way back creates a new collection. Those ids are new either way. `unused: …` is not looked up as a context. The parked mode is reused for its old context when that context is the only one without an id. It is given to a different new context when one sorts earlier, which is the should-fix above.

## Undo

`dirty` is set before the first mutation of `write` (create, rename, `removeMode`, variable edits, `setValueForMode`). Migration and `keep` run only after that, so they are inside the same dirty step. `dirty` is cleared when the step is committed, and again when it is undone. The 1-mode path undoes the first attempt once and does not undo again when `pull(doc, 1)` throws. The foreign-collection refusal throws before `dirty` is set, so `triggerUndo` is not called. The new test covers that refusal. It does not count undos on the 1-mode path. The stub restores one snapshot, so a second `triggerUndo` would not show there anyway. By inspection the 1-mode path calls it once.
