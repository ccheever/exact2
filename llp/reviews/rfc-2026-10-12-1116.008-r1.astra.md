# GPT-6 Astra (xhigh) review of LLP 1116.008 r1

**READY WITH CHANGES.** D1–D2 address real waste, but the RFC understates remaining context costs and misses verification problems that consume tokens and actively reduce quality.

**D1 — RIGHT WITH CHANGE.** Own the declared local server’s lifecycle, but replace textual `process.env.DB` detection with a reliable isolation contract. Polls already used a split server entry; demanding that the entry itself contain the spelling converts a detection bug into mandatory restructuring. Keep tests isolated, make `agent`’s use of the development database explicit, and stop only servers the command started. Automatic startup itself conflicts with no Exact principle.

**D2 — RIGHT WITH CHANGE.** Reuse verification screenshots and eliminate unnecessary dev-server management. Broaden this into one authoritative verification journey: build, exercise, inspect and export on the intended platform. Allow captures within a journey; requiring separate test endings merely to obtain pictures can create more work. Screenshots still need inspection, and first-screen/test-end coverage does not establish that intermediate interaction states work.

**D3 — RIGHT WITH CHANGE.** Moving this scaffold’s persona switcher into the list is a sensible authored design choice. “A control above a list goes in the list” is too general: pinned filters and controls are legitimate. Preserve that choice and fix fixed-content/bar composition independently. Moving the example must not become the workaround every author needs for native header behavior.

**D4 — RIGHT.** UIKit should own the gesture when UIKit owns the swipe actions. Removing competition from the emulated row is the platform principle applied directly. Judge ordinary short swipes and cancellation against a native list, not merely whether a sufficiently long drag eventually succeeds.

**D5 — RIGHT.** The declared bounds should hold when the native bounded control commits, including typed entry. Preserve intermediate editing text and ensure the committed value reaches application state before Save consumes it. Keeping browser validation on the web is consistent with platform-specific behavior.

**D6 — RIGHT WITH CHANGE.** Improve the default, but establish its appearance against the same-OS native reference. A categorical hue list plus low-opacity fill and label ink is not, by itself, evidence of “the Clock’s way.” Resolve the component’s unsaid presentation per platform; explicit fill, foreground and style must win. Passing `check` is insufficient evidence of native quality.

**D7 — RIGHT WITH CHANGE.** Correctly identify platform-owned labels, but avoid making accent color a blanket exemption for authored text. More importantly, repair the wider interaction between semantic controls and `check`: team-kanban’s builder removed `destructive=true` after a web contrast finding, and the iOS grader then criticized Delete’s missing destructive presentation. That is framework-induced degradation, not simply a builder slip. The token diagnosis is **directionally right but overstated**. The raw logs confirm focus-timer’s 25 commands versus React’s 17; approximately 451k of its 454k excess input tokens are cached context replay. Eliminating calls helps substantially. However, tip-splitter used 29 versus 27 commands while consuming approximately 1.01M versus 0.60M tokens. Context size remains material, and the reported 44KB median documentation intake still misses round 9’s 25KB target. Commands also imperfectly proxy model calls. Measure calls, carried context and cached/uncached tokens separately before declaring documentation solved. ([Exact log](/Users/ccheever/bakeoff/rounds/r10/logs/tip-splitter-exact2.jsonl), [React log](/Users/ccheever/bakeoff/rounds/r10/logs/tip-splitter-react.jsonl).)

The larger operational lever is **a trustworthy, single verification path**, beyond screenshot copying. Polls’ tests repeatedly exercised the stale scaffold until another prebuild; unit-converter hit overlapping-build freshness failures. Remove those repair turns, duplicated `test`/`verify`/manual drives, and unnecessary cross-platform repair work. Keep fast web iteration available, but don’t make satisfying web presentation checks a prerequisite to finishing an iPhone app. ([Polls diary](/Users/ccheever/bakeoff/rounds/r10/apps/polls-exact2/DIARY.md).)

The larger platform lever is **native screen composition during interaction**: keyboard, focused field, live result, fixed controls and scrolling content must work together. Unit-converter passed verification while its result disappeared during typing; team-kanban exposed the fixed-header clipping problem. Prioritize those over another button-color adjustment. Don’t automatically scroll arbitrary result text into view: provide a proven input/result recipe and inspect the keyboard-open journey. Mood-journal’s calendar alignment and flashcards’ reload/deep-link failures also justify correcting reusable examples, even when their immediate owner is the builder.

Required changes before implementation: strengthen D1’s server contract, expand D2 to reliable verification and freshness, narrow D3’s guidance, calibrate D6–D7 against native presentation, and explicitly schedule keyboard/header composition work.
