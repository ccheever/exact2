## Verbatim review

## Overall assessment

Core geometry is internally coherent: flipped coordinates, dominant-axis selection, 0.5-point edge tolerance, clamping, root attachment re-derivation, and minimum viewport sizing are sensible. However, several CSS-parity defects make authored scrolling behave differently across kernel, web, and macOS.

## Findings

1. **HIGH —** macOS ignores the effective `overflow_x`/`overflow_y` values. The host emits content extents solely for `ScrollView`/`List` types at [host/apple/src/host.rs:275](/private/tmp/claude-501/-Users-ccheever-projects-exact2/5ff4e6b5-3538-4658-9897-2da74dac71b9/scratchpad/review-scroll/capsule/host/apple/src/host.rs:275), and the presenter creates an `NSScrollView` solely from those kinds at [Presenter.swift:79](/private/tmp/claude-501/-Users-ccheever-projects-exact2/5ff4e6b5-3538-4658-9897-2da74dac71b9/scratchpad/review-scroll/capsule/host/apple/macos/Sources/ExactMac/Presenter.swift:79). `applyStyle` merely stores overflow rows at [Presenter.swift:132](/private/tmp/claude-501/-Users-ccheever-projects-exact2/5ff4e6b5-3538-4658-9897-2da74dac71b9/scratchpad/review-scroll/capsule/host/apple/macos/Sources/ExactMac/Presenter.swift:132). Consequently, a `View` with `overflow: scroll` cannot scroll, while a `ScrollView` with `overflow: hidden` or `visible` remains clipped and scrollable; axis-specific restrictions are also ignored by `ChainingScrollView`. Resolve this by deriving clipping, scroll-container creation, content extents, chaining, and scrollers from effective overflow values, including per-tag defaults.

2. **HIGH —** native scrollable-overflow extents are not CSS scrollable overflow. `content_size` unions only direct children’s untransformed layout boxes and the node’s own border-box size at [host/apple/src/host.rs:408](/private/tmp/claude-501/-Users-ccheever-projects-exact2/5ff4e6b5-3538-4658-9897-2da74dac71b9/scratchpad/review-scroll/capsule/host/apple/src/host.rs:408). This omits end padding, visible overflow from deeper descendants, and transformed overflow; the kernel discards Taffy’s computed `content_size` at [kernel/src/layout.rs:266](/private/tmp/claude-501/-Users-ccheever-projects-exact2/5ff4e6b5-3538-4658-9897-2da74dac71b9/scratchpad/review-scroll/capsule/kernel/src/layout.rs:266). Page sizing likewise considers only root frames at [Presenter.swift:230](/private/tmp/claude-501/-Users-ccheever-projects-exact2/5ff4e6b5-3538-4658-9897-2da74dac71b9/scratchpad/review-scroll/capsule/host/apple/macos/Sources/ExactMac/Presenter.swift:230), while transforms applied at [Presenter.swift:293](/private/tmp/claude-501/-Users-ccheever-projects-exact2/5ff4e6b5-3538-4658-9897-2da74dac71b9/scratchpad/review-scroll/capsule/host/apple/macos/Sources/ExactMac/Presenter.swift:293) never update either extent. Content can therefore be visible on web but unreachable on macOS. Publish Taffy’s overflow-aware content size, retain padding and absolute-descendant contributions, and incorporate presentation transforms into nested and document overflow bounds.

3. **HIGH —** replacing root `width:auto` with `100%` does not implement CSS block auto sizing. The schema defaults to `content-box` at [kernel/tables/schema.json:77](/private/tmp/claude-501/-Users-ccheever-projects-exact2/5ff4e6b5-3538-4658-9897-2da74dac71b9/scratchpad/review-scroll/capsule/kernel/tables/schema.json:77), but every auto-width root is rewritten to `percent(1.0)` at [kernel/src/style.rs:547](/private/tmp/claude-501/-Users-ccheever-projects-exact2/5ff4e6b5-3538-4658-9897-2da74dac71b9/scratchpad/review-scroll/capsule/kernel/src/style.rs:547). Taffy then adds content-box padding and border to that percentage at [vendor/taffy/src/compute/block.rs:154](/private/tmp/claude-501/-Users-ccheever-projects-exact2/5ff4e6b5-3538-4658-9897-2da74dac71b9/scratchpad/review-scroll/capsule/vendor/taffy/src/compute/block.rs:154), so a padded or bordered bare root exceeds its offer; margins also add outside it, and an absolute auto-width root is incorrectly forced to fill instead of shrink-to-fit. `AttachRoot` order itself is handled correctly at [kernel/src/txn.rs:465](/private/tmp/claude-501/-Users-ccheever-projects-exact2/5ff4e6b5-3538-4658-9897-2da74dac71b9/scratchpad/review-scroll/capsule/kernel/src/txn.rs:465), but the equality gate compares replicas of the same wrong rule. Implement block-root auto stretch using the offer while respecting margins, padding, borders, positioning, min/max constraints, and box sizing; test both attach orders and rehydration.

4. **HIGH —** the web host does not implement its declared per-tag/default semantics. Only `ScrollView`, not `List`, receives `data-scroll` at [host/web/src/host.rs:351](/private/tmp/claude-501/-Users-ccheever-projects-exact2/5ff4e6b5-3538-4658-9897-2da74dac71b9/scratchpad/review-scroll/capsule/host/web/src/host.rs:351), although both default-scroll in the kernel. Moreover, `overflow:auto` at [host/web/index.html:12](/private/tmp/claude-501/-Users-ccheever-projects-exact2/5ff4e6b5-3538-4658-9897-2da74dac71b9/scratchpad/review-scroll/capsule/host/web/index.html:12) makes a `ScrollView` scrollable on both axes, while the kernel defaults only y. Finally, CSS emission iterates only explicitly masked rows at [host/web/src/css.rs:31](/private/tmp/claude-501/-Users-ccheever-projects-exact2/5ff4e6b5-3538-4658-9897-2da74dac71b9/scratchpad/review-scroll/capsule/host/web/src/css.rs:31), so the declared `position:relative` baseline is absent and absolute descendants use a different containing block. Resolve the cross-axis default into one CSS-expressible policy, mark `List` consistently, and provide a base `position:relative` rule overridden by explicit absolute positioning.

5. **MEDIUM —** the manual fallback is not safe for all AppKit event classes. After `super.scrollWheel`, it synchronously tests exact origin equality and manually moves both axes at [Presenter.swift:43](/private/tmp/claude-501/-Users-ccheever-projects-exact2/5ff4e6b5-3538-4658-9897-2da74dac71b9/scratchpad/review-scroll/capsule/host/apple/macos/Sources/ExactMac/Presenter.swift:43), without consulting `phase`, `momentumPhase`, precision, or the selected dominant axis. **FLAG:** code alone cannot establish that AppKit always updates the origin synchronously; if it commits later, this can double-scroll. When fallback fires it also replaces momentum/rubber-banding with a clamped jump. Restrict any workaround to an identified event class and claimed axis, or observe AppKit’s completed transaction before applying it; add real phaseful, momentum, diagonal, and horizontal coverage.

6. **MEDIUM —** the smoke experiment cannot prove “inner first, then page,” absence of double-scrolling, or real event routing. It deliberately creates phase-less events at [main.swift:157](/private/tmp/claude-501/-Users-ccheever-projects-exact2/5ff4e6b5-3538-4658-9897-2da74dac71b9/scratchpad/review-scroll/capsule/host/apple/macos/Sources/ExactMac/main.swift:157), manually hit-tests and invokes `scrollWheel` rather than sending through the window event loop at [main.swift:177](/private/tmp/claude-501/-Users-ccheever-projects-exact2/5ff4e6b5-3538-4658-9897-2da74dac71b9/scratchpad/review-scroll/capsule/host/apple/macos/Sources/ExactMac/main.swift:177), and the assertion merely checks that both origins changed across 200 events at [host/apple/smoke.mjs:26](/private/tmp/claude-501/-Users-ccheever-projects-exact2/5ff4e6b5-3538-4658-9897-2da74dac71b9/scratchpad/review-scroll/capsule/host/apple/smoke.mjs:26). Both views could move concurrently and it would pass. The fixture is sound for its simple vertical case, but the harness must record each event and assert the page remains fixed until the inner limit, then moves; real queued phaseful input needs separate coverage.

7. **MEDIUM —** the zero-scrollbar-gutter layout contract is not pinned in AppKit. The kernel hard-codes `scrollbar_width = 0` at [kernel/src/style.rs:456](/private/tmp/claude-501/-Users-ccheever-projects-exact2/5ff4e6b5-3538-4658-9897-2da74dac71b9/scratchpad/review-scroll/capsule/kernel/src/style.rs:456), while nested and document scroll views enable native scrollers at [Presenter.swift:80](/private/tmp/claude-501/-Users-ccheever-projects-exact2/5ff4e6b5-3538-4658-9897-2da74dac71b9/scratchpad/review-scroll/capsule/host/apple/macos/Sources/ExactMac/Presenter.swift:80) and [Presenter.swift:213](/private/tmp/claude-501/-Users-ccheever-projects-exact2/5ff4e6b5-3538-4658-9897-2da74dac71b9/scratchpad/review-scroll/capsule/host/apple/macos/Sources/ExactMac/Presenter.swift:213) without fixing overlay/legacy style or inset behavior. A legacy vertical scroller can shrink a nested clip view after the kernel laid it out with no gutter, introducing unintended horizontal overflow. Pin overlay scrollers and zero adjustment/insets, or feed actual clip gutters back into layout; configure indicators from effective axes.

8. **LOW —** the current seam is insufficient for programmatic scrolling and future `List` windowing. `scrollCommand` and `virtualized` exist in the schema at [kernel/tables/schema.json:55](/private/tmp/claude-501/-Users-ccheever-projects-exact2/5ff4e6b5-3538-4658-9897-2da74dac71b9/scratchpad/review-scroll/capsule/kernel/tables/schema.json:55), but hosts treat them as inert generic properties, and native content extent is derived solely from materialized children. There is no scroll-offset event back to the runner, so a windowed list cannot select a visible range or declare its logical extent. Restoration across reload is explicitly out of v1, and snap/contain remain addable schema rows, but `List` needs a logical-extent plus offset/event seam before windowing can work.
