VERDICT: RIGHT WITH CHANGES

1. **BLOCKING — D2/D3: the example’s recipes cannot read its params.** `PlainSurface` and `QuietSurface` use `param.fill` and `param.quiet`, but file-level styles have no component owner. The compiler explicitly rejects this with `tamber-param-scope` ([rewrite.rs](/tmp/rv-1139-r2/contract/lower/src/params/rewrite.rs:510)); LLP 1121 §10 stage 7 A documents that restriction. **Fix:** keep param-dependent values on component nodes, including conditional rows, or explicitly design component-owned styles and their resolution rules. The example cannot retain both these spellings and the claim that today’s `class` model is unchanged.

2. **BLOCKING — D2: “node’s own rows beat its class’s rows, with no exception” contradicts state composition.** Under [LLP 1121 D8](/tmp/rv-1139-r2/llp/1121-tamber.rfc.md:716), a class’s `:disabled` background overrides the node’s ordinary background; node precedence applies within each state layer. **Fix:** state the complete D8 composition order and limit “node wins” to competing declarations within the same layer. Include a node base row versus class state row in the gate.

3. **BLOCKING — D2/D3/D6: conditional recipes cannot generally carry different host-state looks.** Conditional classes turn differing style values into ternaries ([class.rs](/tmp/rv-1139-r2/contract/lower/src/class.rs:44)). Host-known state rows then reject computed values with `lower-state-literal` ([states.rs](/tmp/rv-1139-r2/contract/lower/src/states.rs:373)). Two variants with different `:active` colours therefore fail, even when both styles contain literal token names. **Fix:** explicitly restrict v1 variants to identical host-state rows, or specify and implement conditional state-look selection. Gate variant changes while active, hovered and focused.

4. **BLOCKING — D4: one syntactic placement does not guarantee one rendered slot.** A single `children` inside `if show` satisfies “exactly once” and “outside any `for`,” yet disappears when `show` is false. Forwarding that placement through another component can also discard or duplicate it. The proposed plan-presence test does not prove runtime presence. **Fix:** validate placement through component expansion and control flow, requiring exactly one unconditional placement on every permitted path. Define the required containing part and test conditional and forwarded fills while preserving caller scope.

5. **BLOCKING — D2/D4: the foreclosure checks have straightforward escapes.** A slot ancestor’s own `scale=0` passes the listed checks and erases the subtree. A permitted `text` recipe with `font-size=0` can zero caller text. Positive dimensions with clipping and oversized borders can also eliminate the usable content area. Moreover, variant-dependent node attributes bypass groups entirely, despite groups being described as what variants may vary. **Fix:** define a conservative, mechanically checkable set of permitted effects on the expanded slot chain, including states and unmarked ancestors; apply group restrictions to variant-dependent rows regardless of spelling.

6. **BLOCKING — D4, §3 and §5 C/D: the server’s fast path lacks the information needed to enforce slot safety.** Current scrub frames fold cached design data without walking Contract; additional write checks run only during verification or release ([tamber_scrub.rs](/tmp/rv-1139-r2/contract/cli/src/tamber_scrub.rs:1)). Adding a compiler refusal alone would still let an invalid value paint temporarily. **Fix:** specify compiler-produced anatomy constraints, their token dependency closures and source-digest invalidation, and validate them before every scrub batch. Cover proposals, transactions and restoration semantics explicitly. Gate that an invalid frame is never broadcast.

7. **BLOCKING — D7 and §4: “existing reference encoding” is not a residual-expression contract.** The current value type carries concrete lengths or a named length, and the kernel’s special handling resolves bare base aliases ([measure.rs](/tmp/rv-1139-r2/tamber/src/measure.rs:71), [theme.rs](/tmp/rv-1139-r2/kernel/src/style/theme.rs:221)). The draft does not specify how expressions containing base references are encoded, validated or decoded, including mixed overridden/unset bases. **Fix:** define the canonical representation, admitted operations and units, limits, per-tuple evaluation, dependency recording and reader compatibility. Justify the no-digest-change claim from that design. Also put the proposed `resolve`/`explain` additions under `tamber/1.15`; B2 cannot both add reply fields and have “no wire.”

8. **BLOCKING — D5 and §5 D/E: the gallery has no defined construction path.** No syntax or manifest entry associates a component with its fixture. A package-relative Contract file is not automatically a runnable preview using the consuming app’s design. The draft also leaves preview-only token retention and registration with the live-edit server unspecified. **Fix:** declare fixture discovery, entry component, sample inputs, consuming-design composition, build registration and retention rules. Keep generated preview artifacts app-owned and out of release output. Define refusal or pagination when the variant product exceeds 16; “every variant” cannot silently truncate.

9. **SHOULD-FIX — D2/D5 and §3: distinguish Tamber IR, source maps and runtime plans.** `part=` must never reach a plan or host, yet §3 assigns reporting work to hosts and the gate asks whether nodes sit “under the slot’s part” in a plan. Existing `components` metadata is also generated only from components with params ([tamber_params.rs](/tmp/rv-1139-r2/contract/cli/src/tamber_params.rs:271)). **Fix:** specify anatomy in the Tamber IR, including paramless components, and component/part attribution in the development source map. Have the server enrich the joined selection; identify the map used by plan assertions.

10. **SHOULD-FIX — D2/D6: the row-group table is not yet an executable schema mapping.** D9’s control table contains colour-role names such as `Field`, `FieldText` and `placeholder`, not corresponding writable style rows ([schema.json](/tmp/rv-1139-r2/kernel/tables/schema.json:5988)). “Control-role rows” therefore leaves authoring syntax undefined. Likewise, “canonical rows after shorthand expansion” needs explicit side/corner mappings, and D8’s `-exact-press-scale` belongs to no group. **Fix:** enumerate canonical row membership, distinguish design-role overrides from node parameters, and explicitly admit or refuse press scale.

11. **SHOULD-FIX — D5: define the library-author write boundary and shared-style scope.** “In the library’s own package in development” does not identify which server root owns those files; all Tamber editing already occurs in development. The current ownership check deliberately excludes installed, linked and vendored packages ([tamber_contract.rs](/tmp/rv-1139-r2/contract/cli/src/tamber_contract.rs:68)). A part-qualified address also cannot make a shared file-level style affect only that part. **Fix:** define a separate authoring-root case, preserve canonical ownership and digest checks, and validate the compound address against source. Keep consuming-app package files read-only and show every style consumer in the edit’s scope. Preserve LLP 1122’s layout-row refusal.

12. **SHOULD-FIX — D1/D5: one `level` and the reset labels lose necessary scope.** A package expression can combine an app-overridden base with an unset base; a single provenance enum cannot describe that accurately. “Back to the package” also has no visible effect while an app param override still wins. Unqualified resets can remove all `when` branches despite LLP 1122 D6’s branch-specific editing rule. **Fix:** report provenance per tuple/value with its dependency chain, make reset targets and affected branches explicit, and disable or separately label resets shadowed by a higher override.

13. **SHOULD-FIX — D1: column-aware range checking covers defaults but leaves overrides and units unclear.** D15 checks defaults and overrides after folding, including indirect token edits. D1 extends only defaults reaching unset bases; terminal base spacings are `ch`, while ranges remain px. Existing range validation rejects non-px folded values ([params.rs](/tmp/rv-1139-r2/contract/lower/src/params.rs:333)). **Fix:** define one per-column numeric resolution rule for defaults, overrides and their dependency closures, including terminal conversion, and apply it consistently to writes and previews.

14. **SHOULD-FIX — D6 and §5: “no per-OS forks” exceeds the specified mechanical check.** A platform-dependent boolean can arrive through a prop, provider or opaque data-module result without the library directly reading a named platform fact. “The compiler knows each such input” does not define how those cases are classified. **Fix:** enumerate forbidden inputs and the propagation analysis, including component boundaries. Either reject unresolved dependencies or narrow the mechanical claim to explicit platform dependencies and leave semantic intent to review.

15. **SHOULD-FIX — D7 and §5 B2: the host oracle contradicts the checked-in implementation.** tvOS reads the **iOS** column, not neutral ([scale.rs](/tmp/rv-1139-r2/kernel/src/style/scale.rs:92), [Apple initialization](/tmp/rv-1139-r2/host/apple/src/scale.rs:13)). The cited `Env::cell_spaces` is also absent; the current kernel has `cell_borders`, while terminal coordinates are rounded by the presenter. **Fix:** derive target expectations from `column_for`/`describe.targets`, correct tvOS, and specify the terminal rounding operation or identify it as an explicit pending dependency.

16. **SHOULD-FIX — §5 final gate: the pixel oracle needs reproducible inputs and bounded exclusions.** A signed-out feed still changes with network data, assets and time. “Fixed screens” and rectangles with prose reasons do not establish repeatable zero-difference results, and unrestricted rectangles could exclude the components being qualified. **Fix:** pin fixtures, assets, clock, viewport, fonts and OS versions; record baseline provenance; constrain exclusions so the tested component regions remain covered. Require variant combinations and relevant states, not merely each prop value in isolation.
