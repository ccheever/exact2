LAND WITH CHANGES

1. **MINOR** — A long non-UTF-8 `release-notes.md` is stamped and the build succeeds. `releaseNotes` (`host/apple/buildinfo.mjs:37-41`) walks back over every `10xxxxxx` byte at the 16 KB cut, then fatal-decodes only what remains. A file of 16,389 `0x80` bytes returns `…` and does not throw. 16,384 `a`s plus one `0x80` drops the last `a`, appends `…`, and does not throw. Windows-1252 bytes in `0x80–0xBF` (curly quotes, em dash) on that boundary do the same. A 5-byte illegal file still throws, which is all `buildinfo.test.mjs:59-60` covers. **Fix:** keep the walk-back only when `bytes[end]` is a lead whose sequence does not fit in the first `NOTES_MAX` bytes; otherwise decode the bytes actually read with `fatal: true` so the existing error fires. Add those two buffers beside the 5-byte case.

2. **MINOR** — A `designRequiresCompatibility` build shows the host SDK. `buildInfo` (`host/apple/buildinfo.mjs:69-74`) always appends `xcrun --sdk <sdkName> --show-sdk-version`. The link records `COMPATIBLE_SDK` (`18.0` / `15.0`) with `-platform_version` (`host/apple/build.mjs:772`, `host/apple/build.mjs:783`), and `assertLinkedSdk` checks that value (`host/apple/build.mjs:1163`). The menu line is `Xcode 27.0 … · iphoneos 27.0` on a binary whose recorded SDK is 18.0. **Fix:** pass the version already chosen for `assertLinkedSdk` into `buildInfo` and print that.
