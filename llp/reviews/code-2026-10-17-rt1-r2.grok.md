The review is down to pinning line numbers on the native patch gate and a few remaining race paths before I write findings. I'll re-read those spots at HEAD and only cite what the code actually does.There is a blocking finding. The native web loop's patch path dies after the first successful Keep, and the same gap can paint a hand edit under an open scrub.

1. **blocking** — After the first Keep, every later scrub frame on the native web loop is compiled. A hand edit that compiles during an open scrub is patched on top of the new tokens.

`host/web/src/dev.rs:635-639`, `host/web/src/dev.rs:260-277`, `host/web/src/dev.rs:299`, `host/web/dev.mjs:348`, `host/web/dev.mjs:357`, `host/web/dev.mjs:574-581`

`scrubPatch` allows a patch only when the fold's design-file digest equals `designSource` (`host/web/dev.mjs:348`). That variable is assigned only when the compiler prints a `design` or `plan` line, and the value is a hash of the file at the moment the line is parsed (`designBytes`, `host/web/dev.mjs:255` and `:581`). The patch command itself is `patch <id> <values>` and carries no digest (`:357`). `Session::patch` clones whatever `self.design` holds (`host/web/src/dev.rs:331-333`).

`Session::build` still stores the newly compiled tokens on every value-only build (`dev.rs:299`). The main loop then prints nothing when that build's batch has no tokens (`dev.rs:635-639`). Two builds produce exactly that empty batch:

- **Keep.** `release` copies the preview into the committed tokens and clears the scrub (`dev.rs:260-265`). The batch is preview to compile (`:271-274`). When the patched frame matches the compile — the equivalence case — the batch is empty, so it is swallowed while the loop is idle. `designSource` stays on the pre-release hash. The next scrub's client reads the file that Keep just wrote (`scripts/tamber-scrub.mjs:169-171`). The gate sees a different digest and returns `{fallback:true}` before any patch. That scrub's own Keep is empty for the same reason, so `designSource` never catches up. Drag, release, drag again compiles every frame (~the old propose path) for the rest of the session, until some later idle edit happens to emit a non-empty `design` line.
- **Hand edit during a preview.** While `self.scrub` is set, the batch is shown-to-shown and is always empty (`dev.rs:267-274`), and `self.design` still becomes the compile of the file on disk (`:299`). The fold keeps using the digests from when the scrub opened (`tamber-scrub.mjs:98`, `planned.ok.files`). Those still equal `designSource`, so the gate passes and the next 16 ms frame overlays the gesture, folded against the old file, onto the hand edit's tokens. The watcher calls `compete()` only after `settle` (default 50 ms) plus a rescan (`scripts/tamber-server.mjs:376`, `:283`). A tool write is safe: `compete()` runs before the transaction (`:619`). A compile that finishes inside that settle window is previewed over, which is the race `docs/tamber-protocol.md:402-407` forbids. The verifier runs only after 150 ms of rest, so a drag in that window is not checked.

The JS loop does not have this stall: it records the digest of the bytes it just read even when the batch is empty and a scrub is showing (`host/web-js/dev.mjs:367-370`), and `scrubPatch` refuses the frame if the committed design object changed during the patch (`:627`). The TypeScript producer path updates `designSource` on every `reply.design`, including one it does not push (`host/web/dev.mjs:778-779`).

**Fix:** Have the compiler keep the sha256 of the design-file bytes that build actually read, and report it on every value-only build, including an empty batch that must not be pushed to builds. Store that digest on `Session`. Send it on the `patch` command. `Session::patch` returns `Ok(None)` without cloning when `self.design` was built from different bytes. Updating `designSource` from `designBytes()` when a line arrives leaves the in-flight command unchecked, and that hash is taken after compile, not from the bytes that were compiled.

The other round-2 fixes hold: `scrub-fold` with `verify: true` shares `write_checks` and a refusal ends the scrub as a mismatch; verify compares shape (and, on the JS loop, structure) and a compile error ends the scrub; a plan line and a non-kept JS rebuild call `compete()`; wasm verify runs off the compiler thread; `design-serve` keys its plan by shape plus digest and exits before the wide-colour table fills. c2's same-scrub rev drop, the long poll, and scrub frames shown without an authored transition did not show a separate defect.
