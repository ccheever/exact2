1. **Blocker — Native confirmation actions have no usable Contract representation.**

   A popover with `role="alertdialog"`, a native `button appearance="auto" press=remove` showing “Delete”, and a custom hide-only Cancel compiles. However, UIKit requires **both** actions to satisfy `closes`, so opening this confirmation returns without presenting anything. Adding the necessary `popovertarget="confirm" popovertargetaction="hide"` to Delete is rejected by Contract. Dialog actions have the same problem with `commandfor` and `command="close"`. [MenusIOS.swift:251](/Users/ccheever/projects/exact2-wt-buttons2/host/apple/Sources/ExactKit/IOS/MenusIOS.swift:251), [MenusIOS.swift:57](/Users/ccheever/projects/exact2-wt-buttons2/host/apple/Sources/ExactKit/IOS/MenusIOS.swift:57), [controls.rs:495](/Users/ccheever/projects/exact2-wt-buttons2/contract/lower/src/controls.rs:495).

   **Fix:** Distinguish close-only confirmation rows from opening invokers. Admit and validate the former while retaining the opening refusal. Test a confirmation compiled from Contract through presentation and activation.

2. **Should-fix — Native tabs and menu items press repeatedly when Enter or Space repeats.**

   `key_down` now recognizes native buttons under any role, but `type_key` still classifies activation keys using only roles `button` and `link`. Consequently, repeat suppression is bypassed for the newly admitted roles. For a native tab whose handler increments `n`, calling `type_key(tab, "Enter", "Enter", true, false)` followed by the same call with `repeat=true` increments twice. Hardware keys use this same path. [typing.rs:139](/Users/ccheever/projects/exact2-wt-buttons2/host/linux/src/presenter/typing.rs:139), [typing.rs:154](/Users/ccheever/projects/exact2-wt-buttons2/host/linux/src/presenter/typing.rs:154), [typing.rs:208](/Users/ccheever/projects/exact2-wt-buttons2/host/linux/src/presenter/typing.rs:208).

   **Fix:** Include native-button identity in `activation`, consistently with `key_down`. Extend the new Linux test to send repeated keydowns and assert one press.

3. **Should-fix — Contract admits native descendants that the macOS toolbar silently removes.**

   This input compiles:

   ```contract
   row role="toolbar" toolbarPlacement="window"
     button press=outer
       button appearance="auto" press=inner
         text "Inner"
   ```

   Toolbar eligibility accepts the outer custom button without inspecting its contents. Its text reader cannot read the native child’s face, so it produces an empty toolbar item targeting `outer`; hiding the authored toolbar makes `inner` unreachable. [ToolbarMac.swift:155](/Users/ccheever/projects/exact2-wt-buttons2/host/apple/Sources/ExactKit/Mac/ToolbarMac.swift:155), [ToolbarMac.swift:109](/Users/ccheever/projects/exact2-wt-buttons2/host/apple/Sources/ExactKit/Mac/ToolbarMac.swift:109), [ToolbarMac.swift:223](/Users/ccheever/projects/exact2-wt-buttons2/host/apple/Sources/ExactKit/Mac/ToolbarMac.swift:223).

   **Fix:** Keep the toolbar authored when a projected item contains another actionable control, or refuse that native-button placement during lowering. Reading the inner title alone would still lose its action.

4. **Should-fix — Projected native tabs lose their macOS shortcuts.**

   Two title-only native tabs with `press` handlers and `aria-keyshortcuts="Meta+1"` / `"Meta+2"` compile and become segments. Segmentation hides their authored nodes; shortcut discovery subsequently calls `toolbar.visible`, which rejects those hidden nodes. Neither their shortcuts nor shortcut menu items survive projection. [SegmentsMac.swift:69](/Users/ccheever/projects/exact2-wt-buttons2/host/apple/Sources/ExactKit/Mac/SegmentsMac.swift:69), [ShortcutsMac.swift:58](/Users/ccheever/projects/exact2-wt-buttons2/host/apple/Sources/ExactKit/Mac/ShortcutsMac.swift:58), [ToolbarMac.swift:119](/Users/ccheever/projects/exact2-wt-buttons2/host/apple/Sources/ExactKit/Mac/ToolbarMac.swift:119).

   **Fix:** Determine shortcut availability through the segment owner, ignoring projection hiding while retaining authored visibility, disabled and inert checks. Test shortcut dispatch after a complete presenter batch.

5. **Should-fix — Native tab-bar projection drops explicit accessible labels.**

   In a qualifying tablist, a native tab containing `image "symbol:inbox"` and `text "Inbox"`, with `aria-label="Inbox, three unread messages"`, loses that explicit name when projected. `TabBarFace` carries title, symbol and tint only; `UITabBarItem` receives the visible title, and the subsequent update writes only enabled state. The correctly labelled native button is hidden. [SegmentsIOS.swift:42](/Users/ccheever/projects/exact2-wt-buttons2/host/apple/Sources/ExactKit/IOS/SegmentsIOS.swift:42), [SegmentsIOS.swift:222](/Users/ccheever/projects/exact2-wt-buttons2/host/apple/Sources/ExactKit/IOS/SegmentsIOS.swift:222).

   **Fix:** Set each item’s accessibility label from the tab’s explicit label, falling back to its title. Update it every sync, including changes affecting only the label.
