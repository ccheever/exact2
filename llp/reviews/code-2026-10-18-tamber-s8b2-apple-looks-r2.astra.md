**RIGHT WITH CHANGES**

1. **BLOCKING — Opacity overlays compose incorrectly with delegated keyframes.** [PressPaint.swift:317](/tmp/rv-s8b2-r2/host/apple/Sources/ExactKit/PressPaint.swift:317) subtracts model `alpha`/`alphaValue`, as does `pressDepth`, while opacity keyframes remain delegated to Core Animation. [Additive animations add to the rendered value](https://developer.apple.com/documentation/quartzcore/capropertyanimation/isadditive). With model opacity 1 and a keyframe held at 0.4, hover opacity 0.8 produces **0.2**; pressing to absolute 0.6 produces **0**, rather than 0.6. **Fix:** keep affected opacity tracks engine-sampled when press paint or looks can override them, including when looks change live. Test the presented opacity with an existing keyframe, rather than only animation endpoints.

2. **BLOCKING — Border-colour resets still lose their initial value.** [looks.rs:69](/tmp/rv-s8b2-r2/host/apple/src/looks.rs:69) emits `null` for cleared border colours; Swift removes their keys. The border painter then falls back to another side or transparent, whereas the declared initial value is `currentcolor`. Red text with a blue border and `:hover { border-color: unset }` therefore loses its border instead of turning it red. **Fix:** serialize cleared border sides as the resolved current colour. Cover individual sides and focus resetting hover. Also strengthen [looks.rs:189](/tmp/rv-s8b2-r2/host/apple/src/looks.rs:189): indexing an absent JSON key returns null, so the current shadow assertion passes even when serialization omits the reset entirely.

3. **BLOCKING — Native Mac sheets and popovers never receive hover looks.** [HoverMac.swift:28](/tmp/rv-s8b2-r2/host/apple/Sources/ExactKit/Mac/HoverMac.swift:28) requires descent from `viewport`, excluding content reparented into native presentation windows. Moreover, [MouseChainMac.swift:537](/tmp/rv-s8b2-r2/host/apple/Sources/ExactKit/Mac/MouseChainMac.swift:537) bypasses `hoverAt` for those windows, so their pointer events never update looks. An ordinary box’s hover background consequently works on the page but fails inside a sheet or popover. **Fix:** track enter/leave paths for hosted presentation windows and accept their attached content roots while retaining stale-view rejection. Test actual pointer delivery in both presentations.

4. **BLOCKING — Inline text silently discards looks.** The new serialization at [looks.rs:36](/tmp/rv-s8b2-r2/host/apple/src/looks.rs:36) also reaches paragraph runs, but [BatchShapes.swift:165](/tmp/rv-s8b2-r2/host/apple/Sources/ExactCore/BatchShapes.swift:165) skips `looks`. Those runs have no `NodeView`, so the new view-based composition cannot recover them. A nested text span with a hover background is accepted but never displays it; inline focus looks have the same missing integration. **Fix:** preserve looks in the inline representation, compose them through inline hover/focus tracking, and invalidate the owning paragraph. Include a span without a hover handler.

5. **SHOULD-FIX — Removing an opacity fade leaves a fictitious segment.** [PressPaint.swift:259](/tmp/rv-s8b2-r2/host/apple/Sources/ExactKit/PressPaint.swift:259) records a fading segment before the zero-depth branch removes the animation immediately. A subsequent update samples that nonexistent fade. For base 1 and active target 0.5, changing the target to 1 at 40 ms and restoring 0.5 at 50 ms starts the replacement around **−0.19**, although the installed contribution is zero—an immediate opacity jump. **Fix:** clear or zero the tracked segment whenever its animation is removed. Test removal followed by restoration during the same press, including intermediate values.
