### 3. A default scan does not return the same UPC-A value on Apple and Android

**Where:** D3 (lines 252–256), D6 (line 350), D11 (lines 580–586).

**Problem:** D3 says a clean barcode's `rawValue` is the same everywhere because the symbology defines it. D11's mapping makes a UPC-A disagree, and a default scan on Apple never returns `upc_a` at all.

**Evidence:** `VNBarcodeSymbology` has no UPC-A. Vision and AVFoundation report it as EAN-13 with a leading zero (the `ean13` documentation this RFC cites). ML Kit's `FORMAT_UPC_A` returns format UPC-A and the 12-digit value. D11 converts to `upc_a` and strips the zero only when `upc_a` was requested and `ean_13` was not. D6's omitted `formats` means every supported format, which includes both, so the Apple default keeps `ean_13` and 13 digits. `getSupportedFormats` can still list `upc_a`. The web cell returns the browser's `BarcodeDetector` result with no normalization, so Chrome on macOS (Vision) can add a third spelling.

**Decision:** If the payload is 13 digits with a leading zero and `upc_a` is among the requested formats, including the default, every target reports `upc_a` and the 12-digit value. Report `ean_13` and 13 digits only when `upc_a` was not requested. Apply that normalization to the browser's result too.

### 4. `zh-TW` does not reach a Traditional Chinese model on ML Kit, and BestFit does not define that mapping

**Where:** D7 (lines 398–405), §9 (lines 894–897).

**Problem:** Tier 1 says `zh-TW` matches both Apple's and ML Kit's Traditional Chinese through ECMA-402 `LookupMatchingLocaleByBestFit`. ML Kit has no such model, and that algorithm does not promise that result. The agent then treats Traditional Chinese as available on Android.

**Evidence:** ML Kit's translation language list has one Chinese entry, `zh` (Simplified). There is no `zh-TW` or `zh-Hant` model; a best-fit fallthrough translates Traditional Chinese as Simplified. Apple's Translation framework does distinguish `zh-Hans` and `zh-Hant`. ECMA-402 leaves BestFit implementation-defined. This repo's own truncation (LLP 1060) is `zh-Hant-TW`, then `zh-Hant`, then `zh`. The agent's fixed list includes `zh-Hant` and applies no Android restriction (only tvOS is named), so a scripted drive of Traditional Chinese passes on Android and fails on a device.

**Decision:** Ship an explicit tag table. On Apple, `zh-TW` and `zh-Hant` select `zh-Hant`. On ML Kit, those tags are `unavailable` / `unsupported-options` until a Traditional Chinese model exists. The agent's list applies that restriction.
