## Findings

### 1. MATERIAL — D7, D8, §3

**Problem.** A child call is still a command when its body is typechecked, so §4's child cases fail before a `Stmt::Call` exists.

**Evidence.** `check_children` runs `check_component` on the authored child, then `expand_all` runs (`contract/types/src/lib.rs:1209`, `:1217`). Expansion is inside `expand` (`inline.rs:277` is today's `tail::resolve`, after lifting). On that authored body, `inc()` and a non-tail `cb()` are `Stmt::Command`. `check_command` refuses both (`checks.rs:986–993`). Those errors are kept (`prefer_call_sites` keeps the prefix counted before `expand_all`). Probes at `cargo run -q -p contract -- build --json`:

- `/tmp/llp1089-sibling.contract`, `action go` / `inc()` in `Row`: `type-unknown-command`, "`inc` is an action, not a host command".
- `/tmp/llp1089-prop.contract`, `cb()` then `m = m + 1`: `type-unknown-command`, "`cb` is an action prop: an action calls one only as its last statement". That is the §4 case "a prop call before the child's own writes", and `tail_call.rs:174`.

`sends::check` on the root does walk lifted actions, because they are appended to `expanded.root`. The type error stops compilation before that walk matters. `subst_stmts` also has no nested body to substitute: a command's name is copied through (`subst.rs:305–308`). A `Call` arm that does the same leaves the inlined statements with the child's own slot names.

**Fix.** Expand same-component calls on each component before `check_children`. Mark and expand prop and inject calls on the lifted actions before `check_root` typechecks those bodies. The child-scope check is the one that accepts a sibling call and a non-tail prop or inject call. The new `subst_stmts` arm substitutes `Call.body` (targets, derives, captures) and then the root walk sees the substituted body.

### 2. MATERIAL — D8

**Problem.** "The callee's parameters after the curried ones" includes the capture prefix on a lifted action. A same-component call records `curried = 0`.

**Evidence.** Lifting prepends `@capture:` parameters for every non-action prop and inject (`inline.rs:459–481`) and builds the parameter list as captures, then the authored parameters (`inline.rs:602–606`). A sibling `move(1)` has no curried prefix. Zipping the source argument at index 0 checks it against `@capture`, whose type is the prop's. `refine_params_from_view` (`component.rs:434`) never sees that call: it refines only handler attributes on view nodes (`:468–515`). `clipKey` calling an untyped `move(dr, dc)` is an action-body call, which is the §4 untyped-helper test. Handler refinement at `:515` does not visit it.

**Fix.** Refine and check source arguments against the callee's authored parameters: skip leading `@capture:` parameters, then skip the curried prefix. Do that before `check_body`, in a walk of action-body `Call`s as well as the view. On the lifted re-check, use that same cut; `lifted: true` today only skips the `let`-shadow check (`actions.rs:103`).

### 3. MINOR — D1, §3

**Problem.** The host command wins only if the expander can see `HOST_COMMANDS`. The expander is specified in `contract-syntax`, which depends on nothing.

**Evidence.** D1 classifies `name(args)` as a host command when `name` is in `HOST_COMMANDS` (`types/src/checks.rs:744`), then as a call. That list is `pub(super)`. `contract/syntax/Cargo.toml` has no dependencies (LLP 1004 D2). `expand` runs before `check` (`lib.rs:1217` then `:1225`). An expander that resolves "an action of this component" first turns Caltrain's `action setScheme` / `setScheme(scheme)` (`apps/caltrain/app.contract:109–110`) into `syntax-call-cycle`. A probe of that wrapper builds today (`[]`, exit 0).

**Fix.** Move `HOST_COMMANDS` into `contract-syntax` and consult it in `calls.rs` before same-component, prop, and inject lookup. The type checker keeps using that one list.

### 4. MINOR — D8, D9

**Problem.** "Lowering emits `body` in place" and "Lower expands `.call` in a fresh local scope" differ once a statement follows the call.

**Evidence.** Rust drops a block's `let`s at the end of that block (`contract/lower/src/stmts.rs:49–52`). Lean's `compileBlock` wraps the rest of the block in the `let`'s `dropLocal` (`semantics/Contract/Lower.lean:407–410`). A tail call is last in its block, so a nested block and a splice emit the same drops; existing plans stay byte-identical either way. A call with a later `let` does not: the splice keeps the callee local alive, so the later local's index moves. D9 says the lowering proof matches Rust.

**Fix.** Rust lowers `Call.body` as its own block, and the callee's locals drop before the next statement. That is what Lean's `Lower` matches. "In place" means those instructions stand where the call stood, with no call opcode.

### 5. MINOR — D3

**Problem.** The read walk counts every identifier in a `map`/`filter` arrow and in a `match` arm. Both binders hide a slot of the same spelling.

**Evidence.** D3 counts reads in `map`/`filter` arrows. An arrow's parameters are pushed onto the scope (`contract/types/src/lists.rs:88–95`; lowering at `contract/lower/src/expr.rs:589–595`). A `match` binding is pushed the same way (`actions.rs:272–274`), with no shadow check. A `let` cannot hide a slot (`type-let-shadow`). `map(xs, count => count + 1)` after another frame assigns state `count` is a read of the item. Counting `count` refuses a program whose two readings agree.

**Fix.** The walk skips names bound by the arrow, by `match`, and by `let`, the way `actions.rs`'s `names` does.

### 6. NIT — D8, D10, D5

**Problem.** Three specified strings are not recoverable from the fields that carry them.

**Evidence.** The arity example quotes `` `go=move(id)` ``. `Span` is a line and columns (`contract/syntax/src/lib.rs:41–49`); the type checker builds the message without the source. `authored`, `curried`, and `binding` supply the counts and the line. §4's byte fixture, "conditional dismiss, with a curried argument", is two tests in `tail_call.rs`: `VIEWER` (`close=dismiss`, then `close("swiped")` inside `if`, caller parameter `dy`) and `done=note("ada")` (`finish` has no parameters, so no `@c{k}`). `symbols` `fn stmts` (`symbols.rs:595`) is a separate match from `effects()`. Filling `writes` from the expanded action does not walk callee references, and a child's expanded name is `name#n` (`inline.rs:42`).

**Fix.** Store the binding text on the call, or print "curried at line N". Byte-compare `VIEWER` for `dy@c{k}`, and the curried `note("ada")` test for the capture `let`s. The `symbols` `Call` arm walks `body`; `--name` for a root action reads the expanded action of that name.
