# LLP 1017.003 direction review — Sol

**Reviewer:** Sol, independent direction panel
**Date:** 2026-09-09
**Verdict:** Proceed after adopting the dispositions below. Explicit component-instance ownership is the right direction. The RFC is not implementation-complete as written because the current bake has one value per resource declaration, timers cannot carry a child's lexical captures, and the pending/outbox model cannot fence an unmounted instance.

I reviewed the RFC against the current compiler, plan, runner, settlement, store, and bake paths without reading the other panel reviews.

## Main findings

1. **A component lifetime must be represented in the existing instance tree.** Attaching child effects to the nearest authored `each` is insufficient: a fixed child or a child under `when`/`match` has no row lifetime, and a child inside a row can unmount while the row survives. Add one nonvisual `scope` region at each use that owns state, a resource, a mutation, or a task. Keep view-only components inlined.

2. **The current bake representation cannot represent repeated component resources.** `resources.initial` and `resources.reader` are declaration-wide, and `contract::bake` reads one value back through `Runner::resource(name)` (`plan/tables/format.json`, `contract/cli/src/lib.rs`). A resource declaration realized under keyed rows needs distinct baked args, value, and store provenance per mounted instance. Reusing the first answer, or indexing only by args, violates D1/D2 when equal-argument siblings answer differently.

3. **Unmount fencing must cover both pending tickets and requests not yet handed to the host.** `Runner::forget` removes `pending` but leaves the matching `RequestOut` in `requests` (`runner/src/runner.rs`). That is already observable when a target is superseded before `take_requests`; component teardown would otherwise dispatch work after its owner died. Teardown must remove both by ticket. A pending target must be `(lifetime, declaration)`, not a declaration index alone.

4. **Tasks need an owned registration and live captures.** Current timers are all registered at boot, contain only `(interval_ms, action)`, and fire with empty frames and arguments (`plan/tables/format.json`, `runner/src/runner.rs::advance_timed`). Current child actions capture props by hidden handler arguments in `contract/syntax/src/inline.rs`; a timer cannot call such an action. A scoped timer needs owner, capture-argument code, next due time in the instance, and the instance frames at firing.

5. **Store provenance is per resource instance.** `store_readers`, `stale`, resource state, and kept-answer names are all declaration-wide today (`runner/src/runner.rs`, `runner/src/runner/settlement.rs`, `runner/src/runner/kept.rs`). Marking a whole declaration as a reader is safe but changes unrelated siblings and still lets their kept answers overwrite one another. Store invalidation and readiness must walk every live owned resource instance.

6. **The existing `Answer::Later` contract has no value for a never-before-seen instance to keep.** Bake can seed instances mounted in the baked first tree, but it cannot seed a key or conditional branch that did not exist then. The smallest complete rule is: a first mount may accept `Later` only when it has a matching baked snapshot; otherwise the source must answer `Now`, and the transaction is refused with the existing typed unavailable-data error. This is the scoped form of the current boot rule, not a new loading/suspense model. The RFC should state it.

## Answers to the panel questions

### 1. Is explicit lifetime ownership right, and is there a smaller complete implementation?

Yes. The smallest complete representation is a closed `RegionKind::Scope` with one arm and no visual node. It reuses the current region instance tree, frame stack, arm-root realization, and recursive destruction in `runner/src/instance.rs`. It should have a fresh monotonically allocated lifetime token each time it is realized.

Do not use the nearest authored keyed row as the component owner. That preserves keyed reorder but fails conditional removal inside the row, fixed uses, `match` arms, and nested component lifetimes. A synthetic singleton `each` could be made to work, but a distinct `scope` kind is smaller in semantic surface: it avoids fake list/key bytecode and lets plan validation require that owned declarations name an actual component scope.

The root remains the existing always-live owner. This change does not require a component table, runtime component lookup, or another reconciliation system.

### 2. Should every stateful child get a scope, or only effectful ones?

Every child with runtime-owned state should get one: any `state`, `resource`, `mutation`, or `task`. A component with only a view, substituted derives, or an action that owns no state/effect can retain current inlining.

Scoping only children that declare resources/mutations/tasks makes adding a resource change the lifetime of the component's pre-existing state. It also preserves the current bug where state under `when` survives removal unless that component happens to be effectful. This repository is pre-1.0 and explicitly rejects compatibility apparatus; use the simpler invariant that runtime-owned declarations share the component's mount lifetime.

This is a proposed correction to current behavior. Existing P4c lowering gives a child outside `each` a root slot and gives a child inside `each` a slot owned by the innermost authored row (`contract/syntax/src/inline.rs`, `contract/lower/src/lib.rs`, `llp/1017.000-contract-v1-1.spec.md`). It does not currently model conditional component lifetime.

### 3. Can existing row frames carry effects without a second tree?

Yes, if the frame points to one instance-owned cell rather than expanding the runner's global arrays. Extend the scope frame with an `Rc<RefCell<ScopeState>>` (or the equivalent) containing its token, owned slots, owned resource states and pending flags, and owned timer next-due values. The instance tree holds the strong reference. Handler and timer execution receive cloned frames. Pending requests hold the token plus a weak reference; they must not keep an unmounted scope alive.

`LoadSlot`/`StoreSlot` already resolve `slots.owner` through `Frame::row_of`, and row writes already carry the exact storage cell for rollback (`runner/src/vm.rs`). Generalize that lookup for `LoadResource`, `PendingResource`, mutation slots, `PendingMutation`, `Refresh`, and `Send`. Root-owned declarations continue through the current runner storage.

The global ticket counter, pending vector, and host request queue may remain runner-wide. They are scheduling indexes, not an ownership tree. Tree destruction is the ownership event; after each tree update, prune dead weak targets and their undrained `RequestOut`s.

### 4. What is the correct bake representation?

Keep the current root `resources.initial`/`reader` behavior for ownerless resources in this landing. Add `resources.owner: opt:regions` and a scoped snapshot table declared in `plan/tables/format.json`, with rows equivalent to:

```
resource: idx:resources
path: bytes       # canonical Value::List of enclosing authored each keys
args: bytes       # canonical Value::List
value: bytes      # the typed resource value
reader: bool      # this instance observed Store/external storage at bake
```

The resource id distinguishes static uses. The keyed path distinguishes repeated realizations of that static use; it must include every enclosing authored `each` key in outer-to-inner order. The stored args must equal the args evaluated in the live scope before a snapshot is accepted. This prevents a host/store-dependent prop change from taking a snapshot baked for different arguments. A runtime lifetime token must never be serialized or used for lookup.

The plan validator must decode these values, require primitive finite path keys, require a list for `path` and `args`, require the snapshot value to conform to the resource type, reject duplicate `(resource, path)` rows, and require each owned resource/slot/timer to name a `scope` region. A malformed plan must be refused during `Plan::validate`, before VM lookup.

`contract::bake` should boot the unbaked plan, enumerate mounted scope resources in deterministic tree order, and append one snapshot per mounted instance. Fixed sibling uses naturally have different resource ids; repeated keyed uses have different paths even when their args are equal. For store-reading scoped snapshots, a kept-answer key may include `(resource, baked path)`, but only for the finite paths present in the baked snapshot table. Do not create durable kept entries for arbitrary runtime keys. On a same-run unmount/remount, do not read the prior lifetime's kept answer.

Uncertainty to resolve in the LLP text, not by broadening implementation: a scoped instance absent from bake has no fallback for `Answer::Later`. Adopt the `Now unless matching snapshot` rule in finding 6. Adding authored loading values, suspension, or a new answer variant is a separate design.

### 5. What teardown, rollback, store, or pending edge is missing?

The required edges are:

- A lifetime token is fresh on every realization, including remove/reinsert of the same key. Ticket lookup checks both token and declaration. Late replies become ordinary unknown-ticket drops.
- Teardown removes pending entries, pending flags, timer registrations, staged refreshes, and undrained host requests for that token. Already taken host work may finish but cannot publish.
- Replacing resource args fences the older ticket for only that instance. Equal-name/equal-argument siblings remain independent.
- Mutation `Now` answers, mutation assignments, `Later` replies, and `pending(mutation)` resolve the mutation result slot through the owner frame. `plan/src/lib.rs::validate_mutation_slot` currently rejects every owned mutation slot and must instead permit a slot owned by the mutation's component scope while preserving the `option<T>` check.
- A task's tie order must be specified. Preserve the current plan-order rule, then break ties between realizations by lifetime allocation order: `(due_ms, timer row, lifetime token)`. Reordering a key keeps the token and next due time.
- Store reader/stale/revision state belongs to each resource realization. A store write requires settlement of all live root and scoped readers, in deterministic tree order, until their observed revision is current. A newly mounted synchronous resource may itself write the store, so repeat settlement/tree update to the existing bounded cycle refusal.
- Scoped refresh/send outcomes must capture their owner while the action frames are live. Bare declaration ids in `vm::Outcome` are insufficient.
- Preserve the current failure boundary rather than claiming stronger atomicity: failures before instance-tree mutation roll back the store and writes; a failure after tree mutation poisons the runner and requires restart, as `runner/src/runner.rs::update` does today. The RFC's “preserve rollback guarantees” should explicitly include this existing poison case.

### 6. Is deduplication correctly left to the data source?

Yes. The runner must call the source independently for each mounted resource realization whose own args/state require an answer. It must not memoize by `(source, args)`, because `DataSource::answer` may observe or mutate the Store and may depend on credentials or executor state (`runner/src/runner/source.rs`, `runner/src/store.rs`). A data source may explicitly share transport or cached values behind that seam. A parent may continue to own one resource and pass its value down.

## Concrete compiler hazards

Removing `type-child-resource` is only the first edit.

- `contract/syntax/src/inline.rs::expand` currently lifts only states/actions, substitutes derives, and records only the nearest `each` as owner. It must lift and rename resources, mutations, and tasks per static use and wrap the expanded body in its scope.
- `subst_stmts` currently leaves `Stmt::Send.target` and `Stmt::Refresh.target` unchanged. They must be renamed to the lifted declaration. The substitution map must also rewrite `pending(resource|mutation)` and derives that read an owned resource.
- Child actions close over props/injects through hidden parameters evaluated by handlers. Timers need the same capture expressions in `timers.args`; otherwise the lifted action has nonzero arity and the current timer call passes none.
- `ComponentTypes.sources` is currently per component, while lowering emits the expanded root's source table. Sources used by children must be merged and unified globally so two child components cannot bind one source name with incompatible signatures.
- `contract/lower/src/lib.rs` currently creates every resource, mutation, and timer as runner-global and lowers actions through root declaration lookup. Lowering needs owner ids before bodies, and text-leaf validation must treat a nonvisual scope as transparent just as it treats regions.
- The resource/derive settlement loop in `runner/src/runner/settlement.rs` uses empty frames and declaration-wide vectors. Root settlement must skip owned resources; scope settlement runs only that scope's resources with its live frame chain, while allowing reads from root and ancestor scopes.

## Smallest complete implementation plan

1. **Write focused failing tests first.** Add compiler/runner fixtures for a fixed child, a child under `when` and `match`, a child inside nested keyed `each`, remove/reinsert of the same key, and a nested child resource that controls whether another child exists. Add plan decode refusals for bad owners and duplicate/malformed snapshots.

2. **Make the closed plan changes.** In `plan/tables/format.json`, add `RegionKind::Scope`, resource ownership, timer ownership plus capture args, and scoped resource snapshots. Update semantic validation and `PlanBuilder`; do not hand-maintain generated rows.

3. **Preserve component boundaries only where lifetime exists.** Update syntax expansion/types/analyze/lowering to scope components with state/resource/mutation/task, lift and rename all owned declarations, merge source signatures, and remove `type-child-resource`. Leave view-only expansion unchanged.

4. **Generalize frame-owned state.** Add the scope cell and lifetime allocator in `runner/src/instance.rs`; route VM reads/writes/pending/send/refresh through the declaration owner. Keep the instance tree as the only strong owner.

5. **Make settlement and requests instance-aware.** Settle a scope before realizing dependent bindings/regions; use `(token, declaration)` request targets; prune dead pending and undrained requests; make store invalidation traverse live scopes. Keep current poison-on-post-tree-failure behavior explicit.

6. **Move timers into their owner.** Initialize at mount `now + interval`, evaluate capture args in current frames when due, order ties by timer row then token, and let tree destruction remove registrations.

7. **Bake mounted instances.** Export deterministic mounted resource snapshots from the bake runner, write them through the builder, accept only matching path+args on boot, and enforce the first-mount `Now unless snapshotted` rule.

8. **Run the required focused matrix, then the five existing checks and one real host consumer.** The key proofs are distinct sibling answers, reversed replies, conditional teardown, keyed reorder versus remove/reinsert, timer capture/order, mutation rollback/pending, store readiness, distinct baked instance values, and observable behavior through the existing agent operations. No new check, host ABI verb, cache layer, or general effect framework is needed.

## Disposition

Adopt D1–D5 with the scope and fencing details above. Amend D6 to define per-instance bake snapshots and the unsnapshotted first-mount rule. Amend D1 so every component with runtime-owned state receives the same mount boundary. With those changes, the proposal has a finite implementation: one new nonvisual region kind, owner metadata on existing declarations, one bake snapshot table, frame-owned state, and lifetime-qualified scheduling. It permits component-owned resources, mutations, and tasks with correct fixed, conditional, keyed, and nested lifetime without introducing shared caching or a second runtime tree.

## Round 2 — final panel disposition

After reading the Grok and Claude reviews and the shared discussion, I have no remaining direction blocker. Both reviewers now accept the all-stateful `Scope` boundary and path-keyed snapshots; implementation can proceed with the finite plan above.

I amend my Round 1 first-mount rule. A newly opened Fleet member is a normal late mount and may legitimately receive `Later`, so `Now` or a preexisting snapshot alone is too restrictive. Add an optional explicit resource fallback:

```exact
resource transcript = transcript(tab.id) as shape Transcript else loading_transcript(tab.id)
```

The `else` expression is typechecked as the declared shape and evaluated in the owner's live lexical environment when the first answer is `Later` and no settled value or matching snapshot exists. Pending remains true and the real request remains outstanding. With no `else`, retain the clear `Now`/matching-snapshot requirement and refusal. Do not infer null, a typed placeholder, or suspense behavior.

`resource_boot` rows must be keyed by declaration plus the full enclosing keyed path, require matching arguments, and carry the snapshot value and reader. If bake recorded the explicit fallback while the request was pending, the row must also be marked as a placeholder requiring launch. Otherwise boot would mistake fallback UI for a settled pure initial value and silently never fetch. A settled baked answer has no such marker. These rows are boot seeds only; there are no owned kept answers or cross-lifetime carry.

The remaining adopted details stand: ownership on resources and timers, mutation lifetime through its result slot, lifetime-qualified pending/outbox/timers, settlement during the existing tree walk, root/scoped store fixpoint, current post-walk poison boundary, deterministic timer ordering with live frames, root/shared animation, and additive `state.instances` accounting. This closes the panel.
