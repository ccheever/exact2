1. **blocker — Two planned collections can resolve to the same Figma collection.** [code.ts:104](/tmp/rv-e4-4/tools/figma-tamber/src/code.ts:104)

   With a two-mode limit, pull the fixture into the Black and Dim collections. Rename Black’s collection in Figma to `Tamber · dark-style=grey`, then add Grey contexts to the design. Preflight resolves Black by its stored ID and Grey by that same collection’s current name. Both entries retain the same object.

   Writing Grey subsequently overwrites Black’s variables and replaces its modes. The saved plan gives both entries the same collection ID, including references to modes already removed.

   **Fix:** reserve every surviving collection’s stored ID before resolving names. Require collection assignments to be one-to-one; a new tuple must never adopt another planned tuple’s collection.

2. **blocker — A parked default loses its context identity and can become another context.** [code.ts:127](/tmp/rv-e4-4/tools/figma-tamber/src/code.ts:127), [code.ts:150](/tmp/rv-e4-4/tools/figma-tamber/src/code.ts:150)

   Parking drops the original context from `contextIds`. On a later pull, the default ID goes to whichever context lacks an ID first.

   For example, remove both Black contexts from the fixture and make Dim Light the default. Black Light’s original mode is parked. Restore the Black contexts while retaining Dim Light as default: Black Dark occurs first among the missing contexts and receives Black Light’s parked ID. Black Light gets a new ID.

   **Fix:** persist the parked mode’s original context and ID separately from active contexts. Reserve that ID and reuse it only for its original context. Only a newly created collection’s unassigned default may take an arbitrary first context.

3. **should-fix — The two-step rename still targets occupied names.** [code.ts:134](/tmp/rv-e4-4/tools/figma-tamber/src/code.ts:134)
