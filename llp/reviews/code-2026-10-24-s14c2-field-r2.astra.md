1. **MAJOR — CSS comments can still defeat the mixed-rule refusal.**  
   [contract/lower/src/icon_svg.rs:131](contract/lower/src/icon_svg.rs:131)

   Pair an even-odd path with:
   ```xml
   <path fill-rule="evenodd"
         style="--note:'/*'; fill-rule:nonzero"
         d="M2 2H22V22H2Z M8 8H16V16H8Z"/>
   ```
   `uncommented()` treats the quoted `/*` as an unterminated comment and discards the real override. The linter accepts both paths as even-odd, although the second path is nonzero. CSS preserves comment-like text inside strings. [CSS string-token rules](https://www.w3.org/TR/css-syntax-3/#consume-string-token)

   The declaration scanner also misses escaped property names such as `fill-\72 ule:nonzero`. [CSS escaping](https://www.w3.org/TR/css-syntax-3/#escaping)

   **Fix:** tokenize declarations with string, escape and nesting awareness before resolving importance and inheritance. Add mixed-rule regressions for both examples.

2. **MAJOR — Compat misses even-odd sources in baked resource values.**  
   [bake/src/icon_rules.rs:68](bake/src/icon_rules.rs:68)

   `even_odd()` scans only `plan.icons` and `plan.strings`. A data source returning `symbol:icon||0 0 24 24|evenodd:…|` can supply a bound image without declaring an icon. Baking stores that answer in **`plan.data`**, through [set_resource_initial](plan/src/builder.rs:933), without interning its strings.

   Consequently, reading the shipped `app.plan` still produces no `iconFillRules` input. A TypeScript update can introduce this source while retaining compatibility with binaries that cannot interpret its marker. The shipped-plan test inserts an icon row, so it misses this case.

   **Fix:** recursively inspect decoded resource initial and placeholder values, including nested records, lists and options. Add a test that actually bakes a data-source answer and checks the resulting compatibility ID.

3. **MAJOR — Widget and activity plans do not contribute their fill-rule requirement.**  
   [bake/src/compat.rs:190](bake/src/compat.rs:190)

   The rule decision considers only the main plan. Entry plans are obtained afterward and shipped as `plans/<kind>.plan` by [widgets::emit](bake/src/widgets.rs:14).

   A plain `App` plus a widget component containing a literal even-odd icon therefore omits `iconFillRules` when that component is absent from the main render tree. Changing only the widget’s icon can retain the old cohort ID. This is a compat omission independent of the deferred Apple painting work.

   **Fix:** resolve or reuse `entries` before computing the requirement, then include every shipped entry plan. Test an even-odd icon used exclusively by a widget or activity.

4. **MAJOR — The hardened guard still misses ordinary aliases and JS readers.**  
   [contract/cli/tests/it/icon_path_readers.rs:84](contract/cli/tests/it/icon_path_readers.rs:84), [line 264](contract/cli/tests/it/icon_path_readers.rs:264)

   **Fix:** track aliases and operations across statements, or conservatively flag candidate accesses with explicit exemptions. Add these negative fixtures without relying on particular variable names.
