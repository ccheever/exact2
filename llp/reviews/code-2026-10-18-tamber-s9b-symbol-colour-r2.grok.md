# Review round 2, LLP 1121 stage 9 B (symbol images take their written colour), Grok 4.7 (xhigh)

**RIGHT WITH CHANGES.** Round 1 is in the tree and holds for the cases those notes named. Two holes are still live: an Apple tab face keeps a stale `symbolColorWritten` after the face fact changes, and the JS runtime ink mis-reads a mode boundary. `~/x2review/x2p4-s9b-plan.md` is not on disk. Shelf and the Bluesky clone are not in this tree, so those mover counts are unchecked.

1. **BLOCKING** — A tab face's ink is decided only while props are built, so the image keeps the word it already had when it becomes or stops being that face. `NodeRef::is_tab_face` (`kernel/src/node.rs:70`) is read at `host/apple/src/paragraph.rs:595` and `host/apple/src/content_region.rs:395`. `NodeArena::ink_said` (`kernel/src/arena/text_style.rs:265`) is only "parent is not a `Control` and `says(TextColor)`", and `defaults::changed` (`kernel/src/txn/defaults.rs:80`) repaints symbol images only when that flag flips. A child that stays in the tab is neither moved nor detached (`kernel/src/txn.rs:884`), and a role edit compares the child's `DefaultContext` (`kernel/src/txn/defaults.rs:42`) whose `tab` bit is the neutral tab (`aria-controls`), so the `inherited.rs` face never flips it. Move the sole symbol on or off a `role="tab"` under an equal written colour, add or remove the sibling that crosses one child, or clear `role="tab"` on a non-neutral tab: the image is not touched, and the segment either bakes the written colour (`.alwaysOriginal`) or the page glyph stays the unsaid tint. Putting the face into `ink_said` covers a move of the image itself and still misses a sibling-count change. Compare the emitted predicate on the image, and touch the previous and new sole child when a `role="tab"` node's count crosses 1 and when that role is set or cleared. Cover both directions in `kernel/tests/it/symbol_color.rs` and with an Apple props assertion.

2. **SHOULD-FIX** — A one-image radio is projected as a segment and still receives page ink. `is_tab_face` requires `role=="tab"` (`kernel/src/node.rs:72`). `SegmentsIOS.member` is `"radio"` for a radiogroup (`host/apple/Sources/ExactKit/IOS/SegmentsIOS.swift:207`), `segmentFace` turns one image child into `.image` (`host/apple/Sources/ExactKit/Accessibility.swift:521`), and that image is drawn `.alwaysOriginal` (`SegmentsIOS.swift:248`). The gate at `paragraph.rs:595` therefore sends `symbolColorWritten`, and the segment bakes the written colour. Exclude the same projected faces (one image child of a tab or of a radio) and invalidate them the same way as finding 1.

3. **SHOULD-FIX** — `inked` treats a mode boundary's rewritten `color` as the binding's own value. With modes on, a bound colour is `Sx` (`host/web-js/src/rows.rs:565`). On a `data-x-b` element a clear (`null`, `unset`, `inherit`, or `currentcolor`) returns null (`host/web-js/modes.js:140`), so the binding leaves no inline colour. `apply` then writes the ancestor channel inline when that channel's own bit is unset (`modes.js:86`); a bound colour never sets the bit (`host/web-js/src/modes.rs:322`). `inked` (`host/web-js/symbols.js:126`) sees that inline colour and returns `data-exact-ink === "1"`. `none` on a mode-pin or color-scheme boundary therefore keeps the symbol in `currentcolor` (the label, when nothing above is written) instead of the accent or the decision past it. `inherit` / `currentcolor` on an accent boundary (`data-x-b` all bits, so `apply` does not rewrite) leaves no inline colour, and a written clear is treated as unsaid. `modes` is emitted before `symbols` (`host/web-js/src/emit.rs:522`), so this order is stable. `host/web/tests/js-symbols.test.mjs:205` drives `S()` on elements with no `data-x-b`. Record the binding's own runtime provenance from `S`/`Sx` (value, `none`, or a CSS-wide clear) and have `inked` read that. A CSS-wide clear stays said; `none` stays absent. Add the `Sx` + `data-x-b` cases to that Chrome test.

4. **NIT** — The sole `aria-hidden` image of a tab is shown as a page glyph and still suppressed as a face. `segmentFace` returns nil when any child is `accessibilityElementsHidden` (`Accessibility.swift:519`), before the one-image check, so the glyph stays on the page. `is_tab_face` is still true, and the page symbol is sent no written colour. Make the emission predicate match `segmentFace`, and invalidate it with finding 1 if that hidden bit changes.
