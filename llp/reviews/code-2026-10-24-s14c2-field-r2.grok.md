## Findings

**MAJOR** — `contract/cli/tests/it/icon_path_readers.rs:77` and `:223` and `:242`. The scan still misses ordinary readers.

- A binding taken from the table in a later statement is invisible. `row_bindings` only looks at the statement that contains `.icons` (`:77–79`). `let icons = &plan.icons; for row in icons { plan.str(row.path) }` tracks `icons`, not `row`. The same is true of `icons.iter().for_each(|row| row.path)` on the next line, and of a helper that returns `&[IconsRow]`.
- The owner of `.path` is the alphanumeric run immediately before the dot (`:224`). `(row).path` and `(*i).path` see `)` and record an empty owner.
- `for IconsRow { path, .. } in &plan.icons` never mentions `.path`, so the destructured field is not a hit.
- The JavaScript half runs only when the file contains the literal `icon|` (`:242`). `path.startsWith("evenodd:")` and `path.slice(8)` on a line without `icon|` are ignored. `raw.split("|")` is ignored because `raw` is not in the receiver-name list (`:271`). A helper file that only receives an already-cut path is invisible.

No current product reader hits these. The guard is the check that is supposed to fail on the next one.

Fix: inside the function, keep walking `for` / `let` / closures whose receiver mentions a name already tracked. Treat `(`, `)`, `*`, `&`, and whitespace as transparent before `.path`. Flag an `IconsRow` pattern that binds `path`. Flag `startsWith("evenodd:")` and a slice or split on `:` even when the file has no `icon|`. Add each of those as a case in `the_scan_catches_each_bypass`.

**MINOR** — `host/web/tests/symbol-hole.test.mjs:96`. The glue.js flip does not exercise the host.

The comment at `:86` says the web host's `element.rs` attributes are swapped as a props batch. The glue.js branch (`:98`) deletes the old attribute itself and then asserts it is gone (`:123`). `refreshSymbols` does rebuild `fill-rule` from `data-symbol-nonzero`, and the pixel samples follow that. A host that left both attributes set would still pass: the painter prefers `data-symbol-nonzero` (`glue.js:385`) and would fill the hole. The `symbols.js` branch does call `draw`, so that half is real. `host/web/tests/it/icon_rule.rs` only checks the first paint.

Fix: for the glue.js case, call `applyProps` with the `set` and `clear` lists `host.rs:1417` would send when the new map omits the old attribute, and assert the DOM from that. Remove the harness `removeAttribute`.
