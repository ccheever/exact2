LAND WITH CHANGES

1. **MATERIAL** — A list inside a header, tablist, or Back control is still bar state, and a rows-only batch never re-projects it. `HeaderShape.init` walks every descendant of the route’s header (`NavigationBarIOS.swift:81-99`), `projectBack` resolves `navigationBack` anywhere in the route (`NavigationBarIOS.swift:545-550`), and `TabFace` reads each tab’s children (`NavigationTabsIOS.swift:50-55`). `onlyListRows` stops at the first `kind == "list"` ancestor (`ListRowsIOS.swift:21-24`, `29-35`) and `apply` then skips `navigation.sync` (`PresenterIOS.swift:954-956`). Concrete batch: route → `header` → `list` → heading; a later `paragraph` on that heading is rows-only, so `navigationItem.title` stays at the previous string. The same batch shape on a tab label or the Back control’s title leaves the tab item and `backButtonTitle` stale. A chat row does not hit this: its list is a sibling of the header, not under it. Fix: while walking, return false if `self` or an ancestor above that list is a `header`, a `tablist`/`tab`, or the node whose `id` is `navigationBack`.

2. **MATERIAL** — Children of a route owner that is a list, or that sits inside one, never update `logicalChildren`. Projection copies those children only from the batch inside `sync` (`NavigationIOS.swift:212-224`). The classifier treats that op as rows: `kind == "list"` (`ListRowsIOS.swift:32`) or `underList` when a `role="tabpanel"` is nested in a list (`ListRowsIOS.swift:33`). Both are legal (`contract/lower/src/routes.rs:241-244`). Concrete batch: unselected `list role="tabpanel"` gains a route (creates + that `children` op, no root `props`). Sync is skipped, so the new id never enters `logicalChildren`. The later tab switch is a `navigationKey` prop with no `children` op, and the new route never becomes a view controller. `content` / `frame` / `rank` on a list that is not an owner are not read by projection (the collapse scroller is chosen by sibling identity at `NavigationBarIOS.swift:576-589`; insets still move through `viewSafeAreaInsetsDidChange`). Fix: a `children` op whose id is `navigation.container` or already in `logicalChildren`, or whose node is under a list but is itself an owner, is not rows-only.

3. **MINOR** — `ListRowsIOSTests` never calls `apply`, so a reversed guard or a `syncOwed` that drops `nativeMoved` still passes. It also never places a flat leaf (`FlatLeaves.parent`), a `present` outside a list, a header-nested row, or a tabpanel `children` op. `syncOwed` itself matches the paths that used to depend on the next batch: `pendingSync`, `changing`, `windowless`, `nativeMoved` (`NavigationIOS.swift:136-139`, set at `723-724`, cleared only once `sync` is past the window check at `326-328`), plus a live `transitionCoordinator`. Window attach still syncs from `mounted()` (`NavigationIOS.swift:475-477`). Sheet dismiss still syncs from the route batch that sets `pendingSync`, then `modalDidDismiss`. Trait refresh still goes through `requestProjectionSync` (controls, segments, grouped lists), and those three still run on a rows-only `apply`; the idle-tick holes are not reopened. `.present` / `.collections` return true for every id (`ListRowsIOS.swift:31`), so a present-only frame of a tab badge (`TabFace.badgeText` reads `alpha`) also skips the bar until a later non-present op.

4. **NIT** — The two `isHidden` guards keep the same bit. `ControlHost` writes `cssVisibilityHidden` only when it differs (`ControlsIOS.swift:166`). `MenuHost` hides a popover only when it is showing (`MenusIOS.swift:144-145`); `NodeView.isHidden` already folds in `display: none`, so skipping a repeat write does not record `hostHidden`. tvOS uses the same skip; `menuKey.sync` and `focusGuides.sync` still run after it (`PresenterIOS.swift:957-960`). The new tests are `#if os(iOS)` only. Files stay under 1,500 lines (`PresenterIOS.swift` is 1,421).
