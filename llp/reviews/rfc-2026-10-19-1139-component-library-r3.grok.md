1. **BLOCKING — D1, "Ranges hold in every column."** A terminal scale cell is stored as `n ch` (`kernel/src/style/scale.rs` `css`, stage 11 B1). `cells::parse` and `Tamber::length` (`runner/src/runner/tamber.rs` `points`) turn `1ch` into `n * 8` px on every axis (`kernel/src/style/cells.rs`: `COLUMN = 8`, `ROW = 16`). The 16 px figure is `lh` and the later `Env::cell_spaces` rounding, which runs only for padding, margin, and gap, per axis, after the length exists (stage 11 C2: space.sm and space.md are 8 px and lay out as 0 rows down). A param has no axis, so "8 px across, 16 px down for a vertical row" cannot be applied to a range. `space.xs` and every terminal radius are 0 cells (B1's table); `radius.full` is 9999 px, and 0 on the terminal. "Never a ranged default" has no error id, so a range that includes both 0 and 9999 accepts it. **Fix:** check `ScaleValue::Cells(n)` as `n * 8` px, and a 0 cell as 0. Refuse `radius.full` as a ranged default with a named error. State separately that a padding or gap the range accepts can still lay out as 0 rows under `Env::cell_spaces`, and that D4's column check uses that rounding for `padding-*`, `row-gap`, and `column-gap`.

A folded arm that is the literal 0 on `padding-*` is allowed; any other non-positive value is refused. `add-token` is in the list only while it can still override a package or base name.
