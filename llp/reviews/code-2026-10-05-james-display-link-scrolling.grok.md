LAND WITH CHANGES

1. **MATERIAL** — Default-rate users are throttled to 60 Hz by any lower explicit vote. `FrameClock.rate` treats `CAFrameRateRange.default` as an abstention (`host/apple/Sources/ExactKit/IOS/FrameClockIOS.swift:49-56`). `OffsetDriver`, the navigation reveal, heavy leaves, and live SVG filters all register with that default (`CollectionIOS.swift:354-356`, `NavigationIOS.swift:691-693`, `HeavyLeavesIOS.swift:210-212`, `SvgFilterLive.swift:156-161`). Paint-only motion votes a hard maximum of 60 (`Frames.swift:92-95`). Those four used to own links with no range, so they tracked the display. On a 120 Hz phone, a breathing fade plus a smooth list correction now stays at 30–60: the correction’s scroll callbacks take the new painted-text early return (`ScrollPumpIOS.swift:131-134`) and never install the pump’s full-rate vote. The ease and the reveal then step at half the panel rate. Pass the same full-range vote the pump uses (`minimum: min(60, max)`, `maximum`/`preferred: screen max`) from those four call sites. Leave a timer-only `Frames` user on `.default`, which is what LLP 1061 D4 still requires.

2. **MATERIAL** — The additive press animation outlives the press and multiplies later transforms. `easePress` installs it under the key `"press"` (`PressFeedback.swift:141-151`) and nothing else removes it. `rebind` clears `press` and, only when the model is non-identity, sets `transform` to identity (`NodePoolIOS.swift:539-540`), so a release ease (model already at 1) keeps scaling the next row that reuses the view. A flight writes `transform` directly every frame (`FlightsIOS.swift:249`, `290-295`, `299`) while `applyTransform`’s flight branch replaces the model with the flight scale only (`PressFeedback.swift:197-200`). The animation stays additive, so the flying view is also scaled by the in-flight press factor. `layer.removeAnimation(forKey: "press")` in `rebind` and at flight start. On land, if `press` is still easing, rebuild the ease from `pressFactor` so the pivot matches the current origin.

3. **MINOR** — The new tests miss both defects. `testTheRateIsTheHighestAsked` only merges explicit ranges (`FrameClockIOSTests.swift:28-37`). `testThePressEasesOnTheRenderServerFromWhatShows` never applies a frame op, a flight, or a recycle while `"press"` is attached (`PressFeedbackIOSTests.swift:112-150`). `ScrollPumpIOSTests` never puts a row in `fillPending` after the scroll has stopped, nor calls `requestText` once the link is idle. A full-rate vote on the four call sites, and `removeAnimation` on rebind and flight start, should fail those cases if omitted.

4. **MINOR** — A non-shared `FrameClock` never invalidates its link. `testTheRateIsTheHighestAsked` returns with user `a` still registered and the link running at 30–60, then the clock deinits (`FrameClockIOSTests.swift:28-37`, `FrameClockIOS.swift:67-72`). The run loop keeps that link for the process. `deinit { link?.invalidate() }`.

5. **NIT** — `issues/20261002-scroll-efficiency.md` §5.3 still lists four link users. The clock now also drives `OffsetDriver` and the navigation reveal, and LLP 1061 D4 still says an idle app drops the link rather than pausing it (`Frames.swift:89-91`). Update both sentences.
