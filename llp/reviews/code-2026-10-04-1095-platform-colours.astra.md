**NOT READY.** I found a tvOS build regression, colour-reference loss, and several paths that retain incorrect or stale colours.

1. **High — tvOS selects AppKit code.** [SystemColor.swift:9](/Users/admin/.config/tuft/sessions/1791112488.305919/worktrees/exact2/host/apple/Sources/ExactKit/SystemColor.swift:9), [Affordances.swift:30](/Users/admin/.config/tuft/sessions/1791112488.305919/worktrees/exact2/host/apple/Sources/ExactKit/Affordances.swift:30). The new `#if os(iOS)` branches exclude tvOS. A tvOS build therefore imports unavailable AppKit and selects `controlAccentColor` on a UIKit colour type. **Fix:** extend the new UIKit guards to tvOS, matching main’s existing shared presenter.

2. **Medium — composite wire values lose `platform-color()` references.** [roles.rs:238](/Users/admin/.config/tuft/sessions/1791112488.305919/worktrees/exact2/kernel/src/style/roles.rs:238). Composite codecs serialize through `.css()`, which replaces a platform reference with its web colour or fallback. For example, a gradient containing `platform-color(ios systemOrangeColor, #010203)` decodes with a fixed `#010203` stop. Shadows, palettes and SVG paint have the same problem. **Fix:** separate lossless wire serialization from browser CSS emission; test composite round trips. The added direct `ColorValue` round-trip test does not cover this.

3. **Medium — only the first session refreshes after a colour report changes.** [colors.rs:35](/Users/admin/.config/tuft/sessions/1791112488.305919/worktrees/exact2/host/apple/src/colors.rs:35). `set_reported` compares against a process-wide table, but repainting is session-local. With two embedded sessions, the first contrast-change report updates the table; the second identical report returns false, leaving that session’s gradients, SVG and motion targets stale. **Fix:** track each session’s consumed report generation, or keep resolutions per session.

4. **Medium — accent reports depend on an incidental main-thread lookup.** [Bridge.swift:458](/Users/admin/.config/tuft/sessions/1791112488.305919/worktrees/exact2/host/apple/Sources/ExactKit/Bridge.swift:458), [SystemColor.swift:128](/Users/admin/.config/tuft/sessions/1791112488.305919/worktrees/exact2/host/apple/Sources/ExactKit/SystemColor.swift:128). `reportColors()` resolves on the owner thread, where `@tint` only reads `lastTint`. Unless another paint previously populated it on main, `AccentColor` and `Highlight` are omitted. A gradient can consequently stay fallback blue while its window’s tint is red. **Fix:** resolve the owning session’s tint on main through `Owner.callMain`, then submit the report.

5. **Medium — unstyled web symbols remain black.** [symbols.js:9](/Users/admin/.config/tuft/sessions/1791112488.305919/worktrees/exact2/host/web-js/symbols.js:9), [glue.js:358](/Users/admin/.config/tuft/sessions/1791112488.305919/worktrees/exact2/host/web/glue.js:358). Both web targets still register `--exact-tint` with `initial-value:#000`. An unstyled symbol emits no tint declaration, so changing the schema default does not give it `AccentColor`. **Fix:** implement the new symbol default in both web presentation paths while preserving authored tints.

6. **Medium — bound composite roles produce invalid browser CSS.** [style.rs:486](/Users/admin/.config/tuft/sessions/1791112488.305919/worktrees/exact2/host/web-js/src/style.rs:486). The JS mapper replaces whole-value roles and embedded WebKit aliases, but leaves `system-orange` inside a bound `linear-gradient(system-orange, #fff)` or shadow unchanged. The browser rejects the declaration, although the literal/native paths accept it. **Fix:** translate embedded role tokens using the supported composite grammar.

7. **Medium — inline colours freeze at batch decoding.** [BatchShapes.swift:240](/Users/admin/.config/tuft/sessions/1791112488.305919/worktrees/exact2/host/apple/Sources/ExactKit/BatchShapes.swift:240). Inline references become two RGBA snapshots and discard their names. Toggling Increased Contrast invalidates paragraph rendering, but `InlineText.run` reuses those snapshots; an unchanged inline `secondary-label` remains at its old contrast. **Fix:** retain references and resolve against the paragraph owner’s current traits, or explicitly regenerate affected runs.

8. **Medium — palette symbols retain old contrast colours.** [Affordances.swift:39](/Users/admin/.config/tuft/sessions/1791112488.305919/worktrees/exact2/host/apple/Sources/ExactKit/Affordances.swift:39). Palette colours are converted to fixed colours when constructing the symbol configuration, but the symbol cache key includes only dark/light appearance. A contrast or elevation change reapplies style without rebuilding the configuration. **Fix:** include the relevant traits or a colour-resolution generation in the key.

9. **Medium — macOS accent changes never invalidate cached resolutions.** [SystemColor.swift:47](/Users/admin/.config/tuft/sessions/1791112488.305919/worktrees/exact2/host/apple/Sources/ExactKit/SystemColor.swift:47). `invalidate()` has no callers, and no observer handles `NSColor.systemColorsDidChangeNotification`. Changing the system accent while appearance and contrast stay unchanged keeps cached `controlAccentColor` channels, including subsequent reports. **Fix:** observe system-colour changes, clear the cache, and refresh every affected session and view.

10. **Medium — direct resolution ignores a view’s contrast override.** [SystemColor.swift:59](/Users/admin/.config/tuft/sessions/1791112488.305919/worktrees/exact2/host/apple/Sources/ExactKit/SystemColor.swift:59). Contrast comes from global `DisplayPreferences`, not the requesting view. A subtree with `.accessibilityContrast = .high` under normal system contrast still receives normal colours despite its trait callback firing. **Fix:** pass the view’s actual contrast/appearance traits through resolution and cache keys.

11. **Medium — box-filter shadows miss colour-report refreshes.** [colors.rs:45](/Users/admin/.config/tuft/sessions/1791112488.305919/worktrees/exact2/host/apple/src/colors.rs:45). A box with `color="system-orange"` and `filter="drop-shadow(0px 2px 4px)"` resolves its shadow colour into filter bytes before the first report. Without a transition or gradient, subsequent reports never resend that style. **Fix:** include filters dependent on referenced `currentcolor` in report-driven regeneration.

12. **Medium — explicit filter colours contradict D1’s supported scope.** [filter.rs:652](/Users/admin/.config/tuft/sessions/1791112488.305919/worktrees/exact2/kernel/src/svg/filter.rs:652). `drop-shadow(... system-orange)` and `drop-shadow(... platform-color(...))` are refused because the parser and `FilterFn::DropShadow` still use fixed `Color`. **Fix:** carry `ColorValue` through this parser, serializer and resolver.
