## Review (verbatim)

### 1. Overall assessment

The field report is useful and largely accurate; every finding I spot-checked against the code holds, with a few numeric and mechanism errors. The RFC is weaker: its framing ("small, additive, with no new app-facing vocabulary") is not true of R1/R2/R3/R5 — R1 is a new data-seam API every forwarding source and both module ABIs must carry, R2 as written changes an accepted decision (LLP 1016 D5) and can reintroduce the very bug R1 fixes, R3 as written adds an unbounded queue LLP 1041 D2 forbids and relies on a timeout that does not exist, and R5 reverses an explicit security decision in ibex2 and LLP 1016 D6. The parity and script items (R7–R12) are close to ready; R6 has not established where its bug lives.

### 2. Strengths

- **Evidence-backed, severity-graded findings (1054 §2–§6)** with cost and existing coverage per item. Most claims check out: D3's journal lines exist (`runner/src/runner/lines.rs:51,80`); D5's refusal string and budget are real (`host/apple/src/executor_core.rs:18,156-159`); D7's exact-origin matching is real (`host/web/glue.js:869-879`, `vendor/ibex2/src/grant.rs:23-26`); L3's flex column is real (`contract/lower/src/tags.rs:107-112`); X1's Linux gap is real (`set_time` only on Apple/web: `host/apple/src/host.rs:785`, `host/web/src/host.rs:691`).
- **§7 "What worked, to keep"** protects the seam's single loop and the runner's commit order from accidental "fixes".
- **RFC "Not proposed"** routes items to existing owners (LLP 1036.001, issues, 1035.003) instead of re-specifying them.
- **R4** replaces a hand-kept comment with generated code for positional records; additive and consistent with "generated files are built, not committed" if emitted into `OUT_DIR`.
- **C2's reasoning** correctly keeps LLP 1016's explicit-promise rule (LLP 1041 §8.4 states "no independence is inferred from GET").
- **Cost section and implementer/date present**, per RULES §Scope.

### 3. Concerns

**1. MATERIAL — The doing-list bar is not addressed.** `rules/NOT-DOING.md` admits named consumers (Caltrain, Weird Castle's wordmark, the Markdown viewer, Fieldnotes, RealWorld, …); Bluesky is not one, and "Everything not required by those … does not exist." X2/X6/X5 already landed at `f115a0e6`, and R4, R5, C3, C4 are new capability justified only by Bluesky. *Resolve:* either ask Charlie to admit Bluesky as a consumer with a take (NOT-DOING format), or justify each R-item by an admitted consumer. RealWorld substantiates D2 and L8 directly — `apps/realworld/app.contract:129-134` threads `changeStamp`/`authStamp` through resources and hand-writes `emptyFeed()`/`emptyArticle()`/`emptyProfile()` — and the RFC never cites it.

**2. MATERIAL — R1 is a seam API change mis-costed at ~120 lines, and it hides dataflow.** `DataSource` (`runner/src/runner/source.rs:65-285`) has many forwarding implementations: `Storage<D>` (`data/host/src/lib.rs:126`), `Mixed` (`data/src/mixed.rs:517`), `Placed` (`data/src/placed.rs:383`), `Anonymous` (`host/render/src/source.rs:32`), `Swappable` (`logic/src/lib.rs:205`), the TypeScript `Module` (`js/src/lib.rs:885`, `js/web/src/lib.rs:344`), snapback4, `Composed`/`Seeded` (js/bake). A forwarder that does not override `changed()` defaults to empty and silently drops invalidations — the same class of bug R1 removes. Replaceable Rust modules cross an ABI (`rustAbi:3`, `scripts/rust.mjs:393`), so this is an ABI bump with a delivery-compatibility story; a worker-placed source answers off-thread, so its change list must travel back with the result; TypeScript sources get nothing, breaking LLP 1027.001's language parity. Semantically, "asks after every call … `parse`/`parse_for` for a reply" includes resource replies: a source whose resource `parse` names its own source re-asks → `Later` → parse → re-ask, a request loop (within one pass it can also trip `RunnerError::Cycle`, `settlement.rs`'s `passes > resources.len()+1` guard, refusing the commit). Alternatives are not weighed: the runner already re-asks store-reading resources on store revision (`settlement.rs:359-377`, `store.rs:199-230` — durable-write-backed, so unsuitable, but the RFC should say why); Contract already has `refresh r` in action bodies (`contract/lower/src/lib.rs:1075-1081`); a resource argument can read a mutation's slot, which fills when the reply lands. R1 also moves invalidation out of the Contract/plan, where `state` and the source map cannot see it. *Resolve:* consult `changed()` only after mutation `answer`/`parse` (or forbid self-marking), enumerate forwarders and the ABI change in design and cost, specify the TypeScript surface or declare R1 Rust-only and justify under 1027.001, and compare against a declared form (e.g. a Contract-visible "resource … refreshes after m") — probably a C-item.

**3. BLOCKER for R2 as written — keeping the in-flight request defeats R1, `refresh` and store invalidation.** The runner deliberately replaces a request on an equal-args re-ask ("so is one a re-ask with equal arguments replaced (a `refresh`)", `source.rs:262-264`); a forced re-ask is sent `cache: "reload"` (`RequestOut.forced`; `glue.js:699`). Scenario: a `send` POSTs a message, R1 marks `chats`, `chats`'s GET is already in flight (issued before the POST); the source answers an identical GET; R2 keeps the old ticket, whose reply lacks the message — D2 reintroduced intermittently. The same staleness applies to store-revision re-asks and to storage reads kept across a write on the ordered lane. R2's equality list (method, URL, headers, body, scheduling) omits `continuation`, `storage`, `surface`, `grants` (`runner/src/request.rs:62-82`); use `Request`'s derived `PartialEq` (answers open question 2). R2 amends LLP 1016 D5 ("the newest arguments win") without saying so. And `answer_for` has already run, so parking sources are affected: the TS `Module` parks by `(target, source, args)` (`js/src/lib.rs:106-110,766-780`); the old parked call is released only if the runner sets `forgot` and calls `forgotten`. *Resolve:* coalesce only when the re-ask was caused by an argument change and never when forced (refresh, R1 mark, store revision, `data_ready`); never coalesce storage/continuation requests; use whole-`Request` equality; keep `forgotten` firing and test each parking forwarder (TS native, TS web, `Mixed`, `Placed`); record as an amendment to 1016 D5.

**4. MATERIAL — R3 introduces an unbounded queue and relies on a timeout that doesn't exist.** LLP 1041 D2: "Bound every queue by count and bytes"; §8.4: the lane "adds no … larger queue"; the executor comment "there is no unbounded queue of overload failures" (`executor_core.rs:71-78`). "The count limit also queues" removes the 128 bound. "A wait longer than the host's request deadline fails as today's timeout does" — there is none (`executor_core.rs` has no deadline; LLP 1016 D4: "No timeout is promised"). The actual defect: `reservation` charges an independent job its full ceiling at admission (`executor_core.rs:477`, `if lane == 0 { bytes } else { limit }`), while `next_job` already charges the remainder at start and waits for bytes (`executor_core.rs:346-361`) — exactly the ordered-lane bug fixed for the Crew port's F2 (LLP 1041 §8.4). *Resolve:* charge independent jobs their request buffers at admission and let `next_job` wait; keep the 128-count refusal. A few lines, with documented precedent.

**5. MATERIAL — D5's arithmetic is wrong, so R3's proposed doc line would be wrong.** `limit = bytes + max(2 × max_response_bytes, 32 KiB) + 2 × 64 KiB` (`executor_core.rs:476`). An 8 MiB ceiling charges ≈16.1 MiB, so the *second* concurrent read is refused, not the fifth; "fifth refused" implies a ceiling of ≈3.1–3.9 MiB. "Reserves this much of a 32 MiB budget" understates the charge by ~2×. *Resolve:* correct D5 and the Confidence paragraph; document the real formula (or make it moot via concern 4).

**6. MATERIAL — R5 reverses a deliberate security decision and understates its reach; it belongs in the C-list.** ibex2: "Wildcards are deliberately absent: an origin pattern language is where per-origin grants quietly become all-origin grants" (`vendor/ibex2/src/grant.rs:23-26`); LLP 1016 D6 (Accepted): an origin "matched whole, never a prefix". The rule "two labels after `*`" admits `*.co.uk`, `*.github.io`, `*.vercel.app`, `*.workers.dev`, `*.s3.amazonaws.com` — attacker-registrable; grants are the exfiltration fence for kept secrets and for over-the-air updatable logic (`grantCeiling`, `scripts/app.mjs:802-805`; `logic/bake/src/main.rs:58-72`). Call sites are more than "three": ibex2, `glue.js` `granted()`, `module-glue.js:46-49` (`fetchEarly`), `glue.js:684` (`scopeValid` exact-text subset), and the deploy classifier and logic bake's exact-text ceiling checks; the "runner matcher" does not exist (`io_grants` only filters lines, `request.rs:20-27`). The wildcard also covers only Bluesky-hosted PDSes, not self-hosted ones, and the entryway workaround already works (S2). *Resolve:* move to C with a default of "no"; if admitted, specify public-suffix handling, IDN/trailing-dot/case normalization shared by Rust and JS parsers, subset semantics for scopes and ceilings, and that it is an upstream ibex change, not a vendored patch.

**7. MATERIAL — R6's diagnosis is unestablished.** Both Apple presenters report row height identically as the row view's kernel-computed `bounds.height` (`CollectionIOS.swift:56-58`, `CollectionMac.swift:238-240`); the web lays out in the DOM, not the kernel. If iOS is wrong, macOS and Linux likely are too, and the cause may be the kernel/Taffy (e.g. negative-margin collapse through the row root in block layout, or row origin placement), not "the iOS collection's row height". *Resolve:* dump frames for the same fixture on macOS and Linux first; place the fix in the kernel or in every native collection, declared against the web oracle.

**8. MINOR — R7/R8 simplify CSS.** R7: CSS `overflow: hidden` clips children to the *padding* box with inner radii (outer radius minus border width) and does not clip the element's own outer `box-shadow`; `cornerRadius + masksToBounds` on the node's own layer does both wrong. "As iOS already does" is true only for uniform radii (iOS sets `cornerRadius = 0` when `!oneRadius`, `BoxLayerIOS.swift:111-120`). R8: standard CSS `line-clamp` does not imply `overflow: hidden`; Exact's web host emits it explicitly (`host/web/src/css.rs:115`) — cite that as the parity target, and check Linux in the same fixture.

**9. MINOR — R9 puts wall-clock network waits into `clock settle`,** which exists to make the agent deterministic (NOT-DOING, the `clock` rationale). Prefer `screenshot` waiting for viewport images and leaving `settle` alone, or settle reporting rather than waiting.

**10. MINOR — R10 details.** Pre-flight probes on every build tax the dev loop; diagnose on failure. binaryen is not a hard prerequisite: a non-132 `wasm-split` builds unsplit with a note (`host/web/stages.mjs:29-39`), so O2's "133 refused" is inaccurate, and R10 must not turn a warning into a failure. Auto-`cargo fetch` should be `--locked` (builds are otherwise `--offline`). For O5, `EXACT_WEB_DIST` exists (`build.mjs:28-30`, `dev.mjs:55`, `agent.mjs:213`); having `scripts/app.mjs` give an outside app its own dist fixes the hazard, where a `serve.mjs` warning only reports it.

**11. MINOR — R12's offset default diverges from the web,** which uses the OS local zone; a zero offset unless `TZ` names a fixed offset is a deviation to declare. POSIX `TZ` signs are inverted (`UTC-5` is +5).

**12. MINOR — Accounting errors.** 32 open findings, not 30 (O5 + L10 + D8 + P4 + A5). L1 (the vocabulary reference) and X7 ("Charlie to confirm") appear nowhere in the RFC. "D8 … is small once R1 exists" is unsupported (R1 does not touch time arguments). `source.rs:251` still documents grants as "`net.fetch <url prefix>`", contradicting D6 as built.

**13. MINOR — C1's premise is false.** `button` fixes only `display: flex; flex-direction: column` (`tags.rs:107-112`); no `align-items: center` default exists anywhere (web `css.rs` included). Adding `justify-content: center` alone yields a vertically centered, horizontally stretched label; a bare `<button>` also has `text-align: center`. Adding `align-items: center` changes stretch for buttons that hold rows. The web-standard encoding is block + `text-align: center` + `align-content: center` (if the kernel supports it) or both flex properties; spell out which and which apps move.
