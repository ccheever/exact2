1. **MATERIAL — Modal completion can leave the previous style indefinitely.** [Appearance callbacks](host/apple/Sources/ExactKit/IOS/ModalIOS.swift:62) resolve before the completions clear `presenting` or `retiring` at lines 423 and 484, so [the transition guard](host/apple/Sources/ExactKit/IOS/StatusBarIOS.swift:22) rejects them. UIKit documents this ordering for [presentation](https://developer.apple.com/documentation/uikit/uiviewcontroller/present%28_%3Aanimated%3Acompletion%3A%29?language=objc) and [dismissal](https://developer.apple.com/documentation/uikit/uiviewcontroller/dismiss%28animated%3Acompletion%3A%29?language=objc). With unchanged viewport geometry, nothing subsequently resolves. **Fix:** resolve from completion after clearing transition bookkeeping, including drag/zoom completion and cancellation.

2. **MATERIAL — A noncovering sheet hides the underlying covering presentation from resolution.** [ModalIOS.swift:230](host/apple/Sources/ExactKit/IOS/ModalIOS.swift:230) examines only `layers.last`. A medium sheet above a fullscreen lightbox returns no covering route; the resolver then excludes the lightbox and selects the base screen. **Fix:** search presentations from top to bottom for the first covering layer.

3. **MATERIAL — Presentation scope excludes pushes within that presentation.** [StatusBarIOS.swift:53](host/apple/Sources/ExactKit/IOS/StatusBarIOS.swift:53) requires descent from the original boundary node. Pushed routes occupy separate [route controllers](host/apple/Sources/ExactKit/IOS/NavigationIOS.swift:359), so a fullscreen presentation’s pushed detail resolves `.default`; a medium sheet’s pushed detail can incorrectly enter the background scope. Unselected mounted tabs are also not explicitly excluded. **Fix:** resolve membership through the selected navigation stack and its committed top controller.

4. **MATERIAL — “Shows” mishandles both projections and CSS visibility.** [StatusBarIOS.swift:40](host/apple/Sources/ExactKit/IOS/StatusBarIOS.swift:40) admits a context-preview row after [UIKit reparents it](host/apple/Sources/ExactKit/IOS/ContextMenusIOS.swift:263); the next batch can let that preview control the bar. Conversely, checking every ancestor’s `cssVisibilityHidden` rejects a visible child of a hidden wrapper, contrary to [existing CSS semantics](host/apple/Sources/ExactKit/CssVisibility.swift:1). **Fix:** exclude lifted preview subtrees explicitly; check computed CSS visibility on the candidate, retaining ancestor checks for subtree hiding.

5. **MATERIAL — `settled: true` bypasses a newly started transition.** [NavigationIOS.swift:746](host/apple/Sources/ExactKit/IOS/NavigationIOS.swift:746) processes pending navigation before calling `resolveStatusBar(settled: true)`. If another push was queued during the first, this starts its animation and then bypasses its transition guard, exposing the next style mid-flight. **Fix:** ignore only the completing coordinator, never newly set `changing`/interactive flags.

6. **MATERIAL — `none` inherits ambient animation.** [StatusBarIOS.swift:30](host/apple/Sources/ExactKit/IOS/StatusBarIOS.swift:30) calls `apply()` directly. A viewport-dependent style flip during [keyboard resize animation](host/apple/Sources/ExactKit/IOS/PresenterIOS.swift:294) therefore animates despite `none`; UIKit explicitly [animates invalidations inside animation blocks](https://developer.apple.com/documentation/uikit/uiviewcontroller/setneedsstatusbarappearanceupdate%28%29?language=objc). **Fix:** use `UIView.performWithoutAnimation` for `none` and frozen execution.

7. **MINOR — The tests do not establish the required UIKit behavior.** [The fixture](host/apple/tests/ExactKitTests/StatusBarIOSTests.swift:13) has neither session nor root controller. The [“scroll threshold” test](host/apple/tests/ExactKitTests/StatusBarIOSTests.swift:86) injects props and checks cached values; removing every UIKit invalidation would still pass. **Fix:** drive a real scroll-bound state change, assert root and presented-controller updates within its apply, and cover native fade plus transition completion/cancellation.

8. **MINOR — “Any node” silently excludes inline text.** [Candidate lookup](host/apple/Sources/ExactKit/IOS/PresenterIOS.swift:59) returns only `NodeView`s, while [nested text remains viewless](host/apple/src/paragraph.rs:247). Its status-bar declaration never participates. **Fix:** index inline declarations and resolve their visibility/order through the paragraph owner.

9. **MINOR — Invalid runtime values are never logged.** [StatusBarIOS.swift:57](host/apple/Sources/ExactKit/IOS/StatusBarIOS.swift:57) silently filters invalid styles; line 65 silently treats invalid animations as `none`. **Fix:** diagnose changed invalid values while preserving D1’s unset fallback.
