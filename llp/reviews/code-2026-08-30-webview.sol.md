## Review (verbatim; the final message — the CLI's exploration transcript precedes it in the session rollout)

I’m using the LLP review guidance because this is an LLP-governed, mutually blind review. I’ll stay read-only, inspect only the capsule materials, and ground every finding in file-and-line evidence.
Overall, the schema/codec extension is orderly—new ordinals are appended, sandbox presence including `sandbox=""` is preserved, payload narrowing is consistent, and WebKit stays outside the presenter binary. The change is not ready to ship, however: Apple teardown contains a likely use-after-free, and several lifecycle, agent-parity, containment, and screenshot paths are not exercised by the green fixture smoke.

### HIGH

1. **Apple teardown leaves a live WebArm holding a dangling callback context.** `WKUserContentController` strongly retains registered handlers; because `WebArm` owns the controller and registers `self`, the cleanup in `deinit` cannot break that retain cycle. Destroy merely removes the manager entry and releases the original retained handle, while the callback was passed into the arm unretained. The detached WKWebView can therefore continue loading or messaging and invoke `takeUnretainedValue()` on a freed `WebCallbackBox`, causing a crash after leaving/re-entering the screen or destroying mid-load. Add an explicit arm `invalidate` operation that stops loading, removes both handlers, clears the delegate, and only then releases the handle; preferably register weak proxy handlers as well. ### MEDIUM

1. **Apple `src` updates are not generation-safe.** `generation` advances only when the whole wrapper is served, while ordinary `src` changes navigate the existing inner frame. Consequently, queued load/message callbacks from the previous document still satisfy the generation check and can mark the new URL loaded or dispatch its payload. There is a second race: `served` becomes true before the wrapper finishes loading; if the update script runs before `#exact-frame` exists, it returns `false`, but the completion handler re-serves only on an actual JavaScript error. A rapid source change can therefore leave the old guest mounted while `tree` reports the new `entry.src`. Re-serving per source epoch, or validating both the returned Boolean and a per-navigation generation, would close both paths. 2. **The Apple agent bridge can attach to a guest’s nested iframe instead of the guest document.** The private ready script is injected into every frame, and every non-main-frame callback overwrites `guestFrame`. 3. **Web guest input does not implement the API that this change documents.** The web carrier ignores `selector`, `x`, and `y` and always clicks the iframe center.
