## Review (verbatim)

The document is a coherent rule: two shapes, nine operations, agent mode never reads the machine. Rulings P1 / `substituted` / settle-at-once / seeded entropy are the right constraints. It is not yet a protocol siblings can implement. Ticket identity, the clock’s wait set, and the web answer path are still open, and D8 collides with the existing `--device` flag. First slice item 3 cannot be built from the text as written.

## Findings

### 1. BLOCKER — Command-shaped tickets are unspecified in the document that owns them

D3 says command-shaped requests (picker, share, document pickers) have no runner ticket, the host assigns a number, and collision with the runner’s sequence is “the spec’s (LLP 1069 §7, Open after the pass).” This RFC is that spec. `state.pending` is produced only from `Runner::pending()` (`runner/src/agent.rs:547-555`; tickets from `next_ticket` starting at 1, `runner/src/runner.rs:275,644` and `runner/src/runner/commit.rs:645-646`). Host-assigned numbers cannot appear in `state.pending`, cannot be classified for `clock settle`, and can alias a live fetch.

Cost already budgets “a `device` field on pending entries” on the runner, which only works if the runner issues the ticket.

**Resolve:** Every device hold, including command-shaped, takes a ticket from the runner (`hold_device` or equivalent on the existing counter). Hosts never pick numbers. Distinct ranges are unnecessary. Close survey open #1 here.

### 2. BLOCKER — Held device requests still sit in the clock’s wait set; Q3 only names `settle`

Touches ruling Q3.

On Apple, `pendingCount()` is `state.pending.length` (`Agent.swift:341-345`). `waitForReplies` spins while that is non-zero (`:357-364`). `clock settle` waits first (`:266`); `clock +N` waits before a due timer (`advanceStepped`, `:330`). On the web, every `request` op is pushed onto `inflight` (`glue.js:689-698`); `clock settle` waits on that set (`:1213,1230`).

If a held auth / `native.later` / synthetic device request is a pending runner ticket, `clock +N` and today’s settle loop wait up to twenty seconds for an answer only the agent can give. Q3 fixes settle’s *reason*; it does not remove those holds from `waitForReplies` / `inflight`. Mixed pending (network + device) is also unspecified: a single `reason: "device"` would skip the network wait 1012 §2 still requires.

**Resolve:** A held device request is listed in `pending` with `device:` and is **not** in-flight I/O. `waitForReplies` / `waitForInflight` ignore it. `clock +N` advances and fires app timers. `clock settle` still seeks motion, still waits for network, and returns at once with `reason: "device"` plus **all** remaining tickets (device and network) when any device hold exists. Touch Q3 only to write that full clock rule.

### 3. BLOCKER — D4 and D5 specify two incompatible web answer paths

D4: the agent answers with `type @t` / `tap @t`, `delivery: "substituted"`. D5: the web file picker is `Page.setInterceptFileChooserDialog` then `DOM.setFileInputFiles` on `Page.fileChooserOpened`, `delivery: "platform"`. 1069.002 D9 copies both.

`Page.fileChooserOpened` is a CDP event with a `backendNodeId`. It does not create a runner ticket or a `state.pending` row. `type @7` has nothing to address unless the driver invents a ticket (finding 1). If the glue never calls `showPicker()` under `?agent=1`, the CDP event never fires.

**Resolve:** Pick one web path in this document, and have siblings quote it.

- Glue always holds; CDP is unused in agent mode; `delivery: "substituted"` on every host.
- Or: glue still calls `showPicker()`; the driver enables intercept at launch, registers a runner ticket from the CDP event, and `type @t` performs `DOM.setFileInputFiles`; `delivery: "platform"` on web only, called out in D7.

Share, auth, and File System Access already take the first path in D5. Using that for `<input type=file>` as well is the smaller protocol.

### 4. BLOCKER — D8’s `--device real` collides with the physical-iPhone flag

`parseFlags` treats `--device` as a boolean that selects a paired phone (`scripts/agent-launch.mjs:16`; `scripts/agent.mjs:898,1408`; LLP 1012). D8 defines `EXACT_DEVICE=real` as “the driver’s `--device real`”. `agent.mjs ios --device real tree` already means “physical phone, then op `real`”.

**Resolve:** Follow the store precedent (`EXACT_STORE=real` is env-only, `host/apple/src/store.rs:27-29`). Consult `EXACT_DEVICE` only when `EXACT_AGENT=1` (or `?agent=1`). Do not add a `--device` value. If a CLI switch is required, give it a new name (`--os-ui` / `--device-ui`).

### 5. MATERIAL — `Page.setWebLifecycleState` is not a visibility substitute

D5 maps visibility to `Page.setWebLifecycleState`. That CDP method exists and is experimental; its `state` is `frozen` | `active` ([Chrome Page domain](https://chromedevtools.github.io/devtools-protocol/tot/Page/#method-setWebLifecycleState)). `document.visibilityState` is `visible` | `hidden` | `prerender`. Frozen pages pause timers and rAF. The web carrier runs `exact.agent` / `exact_advance` as page JS (`scripts/agent.mjs:291`; `glue.js:1207-1234`). Freezing the page can stall every later agent operation, including `prefer` to make it visible again.

1069.000 D6 copies this mapping and wants a hidden page to stop a 1 s tick under the agent clock.

**Resolve:** Visibility is a fact through `Runner::set_*` / `prefer page.visibility-state`, same as D2. Drop `Page.setWebLifecycleState` from D5, or keep it only under D8 for a human observing freeze, never as the agent fact.

### 6. MATERIAL — `Network.emulateNetworkConditions` `{offline}` severs host I/O

The method is real; `offline` is a required boolean, together with `latency`, `downloadThroughput`, and `uploadThroughput` ([Chrome Network domain](https://chromedevtools.github.io/devtools-protocol/tot/Network/#method-emulateNetworkConditions)). In Chromium it fails `fetch`, which is how the web host fulfills runner requests (`host/web/http-body.js:58`). `prefer online false` would then make `clock settle` wait on network until the 20 s bound.

**Resolve:** Online is a fact via `Runner::set_*`. If a CDP demo is wanted, name a method that only changes `navigator.onLine` (and pin the Chrome that has it), and keep host `fetch` alive.

The other D5 names are real and do what is claimed: `Emulation.setEmulatedMedia`, `Emulation.setLocaleOverride`, `Emulation.setTimezoneOverride`, `Browser.setPermission`, `Emulation.setGeolocationOverride`, `Page.setInterceptFileChooserDialog`, `DOM.setFileInputFiles`, `Page.fileChooserOpened`. Locale/zone already have a launch-parameter path (`host/web/navigation.js:533-545`); D5 should say CDP is additive to `exactTime`, or that `prefer place` is the only mid-run path.

### 7. MATERIAL — Landed `--time-zone` does not pin `exactTime().utcOffset`; first-slice “same state” fails

`--seed` / `--locale` / `--time-zone` exist (`scripts/agent-launch.mjs:17-19,28-37`; `LaunchPlace` in `Session.swift:24-33`; `host/linux/src/zone.rs:24-31`; `placeReporter` in `navigation.js:533-545`). The date still comes from the machine at the cited sites (`glue.js:1334` `Date.now()`, `Session.swift:837` `Date()`, `host/linux/src/app.rs:292` `SystemTime::now()`).

`utcOffset` is a separate `exactTime` field (`runner/src/time.rs:14-31,50-51`). Every host still samples the machine for it: `-new Date().getTimezoneOffset()` (`glue.js:1334`), `TimeZone.current.secondsFromGMT()` (`Session.swift:836-837`), `zone::local_offset_minutes()` (`host/linux/src/app.rs:298`, `zone.rs:5-16`). Two agent runs with `--time-zone UTC` on machines in different zones disagree on `state` and on any UI that reads `utcOffset`. §5 item 1 is held by “the same `state` and the same screenshots.” `--epoch` alone does not deliver that.

Display preferences are also still the machine’s until `prefer` is called (`DisplayPreferences.swift:26-32`; web `matchMedia` via `navigation.js:528-529`). D2’s “reads no device fact from the machine” and the r2 “where things stand” inventory (only the date) are incomplete.

**Resolve:** Derive `utcOffset` from the IANA zone under agent mode (`UTC` → `0`). List current machine leaks (offset, media, online, visibility) next to the date. Apply documented launch defaults for every fact D2 already names, or narrow the hold criterion.

### 8. MATERIAL — D7 is not enough for a sibling to build

D7 asks for shape, prefer/flag/default, pending name/args/tap/type/fixture, and CDP. Building also needs, in this document:

- Ticket allocation (finding 1) and `pending.name` for command-shaped rows (D3’s example uses `"name": "avatar"`; runner `name` is a resource/mutation).
- Cancel/supersede when the node unmounts or 1016 D5 forgets the ticket (`exact_request_active` is the existing pattern).
- Journal redaction: `type @t` of an auth callback URL carries `?code=`; D2 redacts secret *facts* only. 1069.006 D7 puts that URL on the wire.
- `native.later`: D5 holds it as `capability: "native"` and skips module code; D4 has no tap choice or `type` JSON shape.
- Permission state as a fact with no reserved source (survey open #3; D1 says facts are source fields).
- A request that fires after `EXACT_AGENT=1` and before the iOS outbound socket (1012 physical carrier).
- Delivery value per carrier if D5 keeps CDP `platform`.
- Fixture copy onto a physical phone (`devicectl copy` already exists for worlds; D4 is silent).

Streams of events are approximated by repeated `prefer` (`native.watch` is a pull on announce, 1016.002 D1). Background push is only “type the navigation root” plus scheduled delivery via `clock +N` (D6). A request whose answer is a stream has no shape. Say those three are out, so a sibling does not invent a third shape.

**Resolve:** Expand D7 with ticket/pending schema, unmount/forget, journal redaction, `native` answer form, permission source name, pre-attach holds, and an explicit “no stream / no background delivery” sentence. Close survey opens #2 and #3 here or name the owner LLP.

### 9. MATERIAL — Production isolation is asserted, not enforced

D2: “A production launch never reads the agent's values.” Web agent mode is `searchParams.has("agent")` in production glue (`glue.js:125,637`; `navigation.js:536`; `storage-environment.js:10`). There is no bake/trust gate. `?agent=1` on a shipped origin already freezes the clock and skips the store; under this rule it would also hold pick/share/auth/permission forever with no OS fallback and no timeout (D3: wait until the agent answers). Native `EXACT_AGENT=1` is an env var a macOS user can set.

**Resolve:** Production bakes ignore `?agent` / `EXACT_AGENT` (or honor them only when the driver set a launch token). Held requests in a non-driver process fall back to the OS or refuse by name. Keep the existing non-agent boot test.

### 10. MATERIAL — `tap @t <choice>` is not in the CLI grammar; the parser would drop the choice

First slice includes `tap @t cancel`. Current `tap` parsing (`scripts/agent.mjs:1424-1439`) passes only the first token as the target; `allow` / `deny` / `shared` / `cancel` are ignored unless they are wheel/hover/history/phase. `s.find` treats `/^\d+$/` as a view id (`:991`); `@7` would miss today, which is fine, but `tap @7 cancel` would not send `cancel`.

`type @7 …` works as leftover text (`typeArguments`, `:1217-1218`) once `@t` resolves.

**Resolve:** Add `tap @<ticket> <choice>` and wire `{"op":"tap","ticket":N,"choice":"cancel"}` to LLP 1012 §7’s grammar. Resolve `@N` before `find`. While a contact is down, `tap cancel` stays a phase; `tap @N cancel` is a ticket.

### 11. MATERIAL — `position` is both a pending request and auto-answered from a fact

D3 lists `position` in pending. D6: “`prefer`; a one-shot answered from the fact.” If `getCurrentPosition` never appears in pending, D7’s request paragraph does not apply. If it waits when no fact is set, say that.

**Resolve:** One-shot reads the current place fact when the agent has set one; otherwise it is a `position` hold answered by `type @t` or `prefer place`. Put that in D3/D6 and in D7 for the geolocation LLP.

### 12. MATERIAL — Cost claims the web carrier already knows these CDP calls

§4: “Web carrier: CDP calls it already knows.” The driver uses `Emulation.setEmulatedMedia` (`scripts/agent.mjs:328`). The rest of D5’s table is new. “No new check, script or file” and the nine-operation budget are otherwise aligned with `rules/RULES.md` / `rules/DEFERRED.md`.

**Resolve:** Drop that sentence. Name the new CDP calls as driver work in existing `agent.mjs`.

## Strengths worth keeping

- Two shapes (D1) plus entropy as the counted-read exception. That is the right bar for every sibling.
- P1: `prefer` stays the ninth operation; a new fact is a name, never a tenth (`§3`, `rules/DEFERRED.md` §Agent API).
- `tap` / `type` on `@ticket`, following 1038 D11, keeps the operation budget intact.
- `delivery: "substituted"` (ruling Q2) so a transcript cannot pass a fake picker off as PHPicker.
- Settle must not wait twenty seconds for an answer only the agent can give (ruling Q3); the *intent* is right once finding 2 is written down.
- `--answer` defaults to wait, never silent success (D4).
- Empty store in agent mode as the precedent for “read nothing from the machine” (1018 amendment).
- First slice order: date, seeded stream, pending/`@t`/settle reason, then `prefer` groups — with a runner test before any capability arm.
- D8 as an explicit, non-smoke path to the real OS surface, modeled on `EXACT_STORE=real`.
