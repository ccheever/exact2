NOT READY

1. **Major** — §3.1, §3.3, §8 stage 1. Under the agent clock, `perf frames` is `{"virtual": true}` and nothing else (`host/apple/Sources/ExactKit/Agent.swift:284`, `host/linux/src/agent.rs:159`, LLP 1079 D4 at `llp/1079-speed-hygiene-in-the-agents-hands.rfc.md:362-365`). The driver prints that as "no frame was presented" (`scripts/agent-inspect.mjs:300`). `FrameSampler.saveTrace` stores identity, proxies, plan, journal, frames, and perf, with no hook section (`FrameSampler.swift:220-241`). Stage 1 tells `smoke.mjs` to read a hook off a late frame it forced. There is no late record to attach `hooks:` to on an agent drive. **Resolve:** attribute hook time on a `perf hooks` read (a form of `perf`). Keep `perf frames` virtual under the agent. A person's wall-clock trace can carry late-frame `hooks`. Rewrite the stage 1 acceptance to a `perf hooks` span and a trace section from a development session.

2. **Major** — §2.4, §4.6, §8 stage 2. `context.frames` is specified as the host frame source (`FrameClockIOS`, rAF, Linux `frames.rs`), woken while a ticket is live, and also stepped by `clock +ms` so `clock +1000` yields 60 callbacks. The runner's frame tasks are `base + k·1000/60` (`runner/src/runner.rs:564-567`). `clock +ms` steps that clock. A hook's own `CADisplayLink` stays on the wall (§2.4). LLP 1079 D3 says the sampler must not keep the app frame source running (`llp/1079-speed-hygiene-in-the-agents-hands.rfc.md:269-273`), and D4 says several frame tasks can commit at one virtual instant, so a virtual frame count is ill-defined. The "frames only while something moves" citation of LLP 1009 D4 is a loose paraphrase of "the host owns the frame; nothing runs per frame unless something asked." **Resolve:** bind `frames` and `after` to the runner clock, the same source as `every(frame)`. State that `perf frames` stays `virtual: true` under the agent. Drop the display-link wake from the agent path.

3. **Major** — §2.2, §4.1, Q3. On a painting host the hook receives pointer and key events before Exact and may claim one so Exact sees a cancel. `rules/DEFERRED.md:522-525` refuses a gesture arena: the platform recognizes, and scroll always wins (LLP 1057 is a precedence table). On Linux, Exact is the hit-tester, so "claim, then cancel" is that arena. The overlay is described as the Canvas 2D list, clipped and replayed, and the paint walk must not call app code. The recording type a hook emits, clip, z-order, and which thread publishes the latest recording before paint are unspecified. `host/linux/src/android.rs:1-6` is a separate `ALooper` render thread. Desktop Linux paints on the host loop that would also run the hook, so "never the painter's" describes a thread split that host does not have. **Resolve:** the hook observes, or receives only events the existing precedence table already left to the app. Scroll and Exact's derived gestures stay uncancellable. Name the recording, clip, z-order, and the publish-before-paint handoff ("not inside the paint walk"). Q3 (b) is the buildable cut until that is written. Q3 (a) needs the constraint in the decision.

4. **Major** — §3.5, §3.6, §8 stage 3, Q1. Activation `tap <node>/<part>` runs the part closure (`delivery: hook`). Platform delivery posts a touch at the part frame (`delivery: platform`). Those exercise different code, so the agent drive and a finger diverge, and the D5 parity claim fails for that control. LLP 1012 says an agent never runs an action by name (`llp/1012-agent-api-v1.spec.md:315-316`). LLP 1075.003 §3.4 says a named action, when it comes, appears in `tree` and is a form of `tap` delivered as `recognized`, and that 1012 sentence is amended in the same decision or the case is refused (`llp/1075.003-native-platform-control-merged.plan.md:415-421`). A closure invoked by part id is that case, and it is not a Contract action. `tree` parts have no cap, while §3.6 says every list is bounded and says `truncated`. `scripts/agent-inspect.mjs:163` renders runner nodes and `hook=`; there is no parts wire. LLP 1080.000's aim resolver has no part frame, and its real-touch carrier is partial (held contacts stay unsupported). **Resolve:** recommend Q1 (b), or synthesize the same pointer event the platform path posts. If Charlie wants the closure, amend 1012 in Q1's decision and require the closure's only effect to be an authored act. Cap parts and `owns`, and say `truncated`.

5. **Major** — §4.3, §5, Q6. `nativeModules` is `Null` when the `modules` roster is empty (`bake/src/compat.rs:330-332`, `contract/cli/src/native.rs:16-18`). Hook words and data words are separate lists and are not digest inputs (`native.rs:36-43`). An app can ship hooks with empty `modules` tags (`scripts/app.mjs:561-563`). Putting hook words "into `nativeModules`" leaves that digest `Null`. The host still calls `element()` for a word the binary was not compiled with: `moduleElement` builds `ExactHookKey(word)` from the JSON string (`host/apple/modules/ExactNativeModule.swift:892`), and `ExactHookKey.init` accepts any string (`host/apple/data-keys.mjs:15`). The failure is the app's typed static, which does not exist. A Swift body change with no word-list change still does not move the id. `webAbi` stays 1. **Resolve:** specify the digest field for hook words, including the empty-roster case. Say what the runtime does when a delivered plan marks an unknown word. State that an implementation change with the same word list does not move the id.

6. **Major** — §4.4, §9. The section says Apple and Android cannot catch a crash in native code, including Kotlin's uncaught exceptions, and then says Kotlin and Rust hooks run inside `try`/`catch` and `catch_unwind` and are skipped for the session. Swift traps are not catchable. Kotlin exceptions are. Root `[profile.release]` sets `panic = "abort"` (`Cargo.toml:50`). `host-dev` inherits `release` (`Cargo.toml:110-111`), and `logic-dev` and `gpu-dev` set `panic = "abort"` (`Cargo.toml:129`, `:137`). `catch_unwind` does not catch those panics. `cargo test` uses `dev`, which does not abort, so the §9 test can pass while the binary an agent drives aborts. The breadcrumb is "a fixed slot the crash handler and the next launch can read." No such handler exists, and a memory word does not survive process death. **Resolve:** Swift and ObjC stay uncatchable; persist the breadcrumb in a file or a crash-report field and name the writer. Kotlin: catch, journal, skip for the session. Rust under `panic = "abort"`: do not claim `catch_unwind`. Pick one policy for "not called again" versus "next launch only."

7. **Major** — §2.5, §4.6. Acts are queued past the batch, and `clock settle` is specified to wait for them and for due `after` callbacks, "as it waits for a native `later`." Apple acts are `DispatchQueue.main.async` (`ElementHooks.swift:225`). The agent answers on the main thread (`host/apple/Sources/ExactKit/Mac/AgentMac.swift:52-59`). `settle` waits for runner requests and calls `settlePump` (`Agent.swift:526`, `:540-544`). Mac `settlePump` drains leaves, collections, and text (`PresenterMac.swift:489-504`). `nativeInFlight` is collection animation (`AgentMac.swift:67`). On Mac the idle loop returns as soon as that is clear (`Agent.swift:552-556`), so a `main.async` act queued on the command's own turn has not run. Web acts are microtasks (`hooks.js:35-38`). `inflight` covers the page-module promise and drops on `setTimeout` (`hooks.js:47-74`), not when the act returns. **Resolve:** name the pump and an in-flight count for hook acts and `after`, the same shape as runner requests, on each host. A settle that waits while already on the main thread has to spin that queue or it deadlocks.

8. **Minor** — §4.3. A plan reload ends hooked objects and builds them again, while app and window hooks hear `changed` because "the platform window survives." That can be true of an Apple `UIWindow`. The web dev loop reloads the page, so `app` hears `built` again. **Resolve:** state the reload moment per host.
