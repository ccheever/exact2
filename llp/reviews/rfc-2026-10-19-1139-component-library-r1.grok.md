VERDICT: RIGHT WITH CHANGES

1. **BLOCKING** — D3 (and the QuietCard example), against LLP 1121 D8 step 1. A class row is dropped when the node sets the same name (`contract/lower/src/class.rs`: the node’s own rows win). The component writes `background-color="param.fill"` on `surface` and `gap="space.sm"` on `body`, so the recipe’s `background-color` and `gap` do nothing. The clause “unless the row reads a param” is the opposite of that rule: a param read is still the node’s row. **Fix:** one order, the one Q2 recommends. A recipe row applies only when that part’s node does not set the row. Rewrite the example so every recipe row is one the component left unset. Delete the “unless” sentence. Leave D8 step 1 as it is.

2. **BLOCKING** — D3, against the `style`/`class` model (Contract grammar, `class.rs`, LLP 1122 D6). `style Name` takes a newline and then `attr=literal`, a `:state`, or `::placeholder`. `style QuietCard for Card` plus a nested `surface` block does not parse. A component use is `Card(title=post.title)`, not `Card class="QuietCard" title=post.title`, and `class` is not a prop. A class resolves only to a `style` in that same file (`lower-unknown-class`); two files may each declare `style Card`, and the style rung edits the node’s own file. An app recipe for a package component is necessarily cross-file, and part sections are a selector, which LLP 1121 §4 rules out. **Fix:** add the productions. `class=` is a reserved argument of a component use. A `style … for` is keyed by component identity plus name, looked up from the use’s file and that component’s package, with a collision rule. Its sections become namespaced rows on the component’s own `part=` nodes before nested uses are inlined, so a child’s parts are not the parent’s. A conditional class sets the same part rows on both sides. A plain `style` cannot be put on a library instance.

3. **BLOCKING** — D2 and D3, the slot rule. `display`, `visibility`, `height`, `overflow`, and `font-size` are already outside every group, so those foreclosure clauses never see a recipe that compiles. What a recipe can still do: `opacity` of `0%`, `0.0`, or a token that folds to 0; `color` of `transparent`, an alpha of 0, or a different name for the same colour (`param.fill` versus the token it defaults to); `font` set to a 0 size (`font` is in the `text` group, `font-size` is not); `border-width` or `padding` large enough to collapse a fixed, clipped part. The `text` group inherits into the caller’s children. Contract’s rule (`docs/contract-for-agents.md`) is that the fill keeps the caller’s variables and providers, not that inherited rows stop at `children`. “A recipe has no section for the caller’s children” has no syntax to refuse. “Places `children` once” is not a compiler rule: a second `children` node inlines the fill again (`contract/syntax/src/inline.rs`). **Fix:** one predicate on the slot part and every ancestor part, base rows and state rows, over folded used values: opacity 0, font size 0, a text colour that is transparent or equal to that part’s background, and a padding or border that leaves no content box given the component’s own size and overflow. Those rows are literals, not tokens or params, so a later app override cannot open the hole. A slot part does not take the `text` group. A second `children` is an error. Say which nested part is `slot: true` (the innermost).

4. **BLOCKING** — D7, against LLP 1121 §3 and D11 as amended by stage 11. Folding is one evaluator: every host gets the same bits. An unset base name is kept as written and never folded; `calc(space.md + 4px)` is `tamber-base-expression` (`tamber/src/check.rs`). `describe`/`resolve` have no per-column slot for a token; a base name is a separate `base` row (`docs/tamber-protocol.md`, *1.14*). `calc(var(--exact-space-md) * 2)` on the JS target is not a folded per-column constant. B2 names no schema-digest break. **Fix:** the value stays a residual expression. The kernel evaluates it in the process column; the JS target emits `calc(var(--exact-…))` of the stage 11 B2 variables. An app-set base folds to one length, as today, and a value edit of it is live. The first set, which turns a residual into a fold, is a rebuild (stage 11 B2’s structure change). Admit `min`/`max`/`clamp` or refuse them. The gate compares used px per column.

5. **BLOCKING** — D8, against D11 and the grammars. After `=`, the rest of a token line is CSS value text, so `renamed` is part of the value, not a flag. Meta is `name=value`. On a param, `renamed=` is refused (`syntax-param-attribute`; the admitted set is `range`, `step`, `control`, `options`, `label`, `help`, `group`, `priority`). Merge drops a package token the app defines, whole (`contract/lower/src/theme/packages.rs`). An app line `cards.pad = 20px` replaces the alias and does not follow the rename to `cards.padding`. **Fix:** a real alias production. Merge retargets an app line of the old name onto the new token before “the app wins,” warns `tamber-renamed` on the app’s line, and refuses the app setting both names. A renamed param is the same single token under the old full name, not a second param (`tamber-param-unused` must not fire).

6. **BLOCKING** — D1 and D5, the cascade and the wire, including what the server writes. “For a param the app hasn’t set” lists `set-param` as level 3. D5 then asks `describe` for `base`, `package`, `file`, and the override, which is four fields, and `file` is stage 11 A2’s source identity, not a value. `group` is already the editor group. Token `explain` takes a token; a node’s rows come back from `layout` and the selection join (LLP 1122 D5). `set-token` on a package token the app has no line for is refused, and the package file is left untouched (`contract/cli/tests/it/tamber_serve_packages.rs`). **Fix:** write the cascade that already folds. The app’s `set-param` wins, otherwise the default expression. That names a token. The first app override is `add-token` in the app design, later edits are `set-token`, and “Back to the package” is `remove-token` of that app line only. A bare base underneath is the host column unless the app sets the base. On *1.15*, `describe`’s component gains `parts: [{name, groups, slot}]` and `variants: [{prop, options}]`, and each param gains `base` and `package: {file, token}` beside the existing `set`. Part and recipe provenance go on the selection join. The writable set stays the app’s design and the app’s own `.contract` files (`tamber_contract.rs`). Package paths stay out of it, including a `component` block once B lifts `tamber-package-block`. The LLP 1122 D6 template, style, `add-param`, and `set-state` rungs are not offered when the source file is a package.

7. **BLOCKING** — D6, against LLP 1121 D9. A native control takes `accent-color` and control roles, never Exact paint, and a state part on one is `lower-state-target`. `lower-button-style-attr` refuses background, border, shadow, and typography on a native `button`. The `paint` group is those rows and does not include `accent-color`. D9’s Post button is a styled pressable because iOS prominent glass will not fade, but §5 E ships that Post button as a library control that “uses the platform’s control.” **Fix:** two forms. A native control is one part whose group is `control` (`accent-color` and control-role rows, no state parts). Anything that needs the faded press, including the Post button, is a styled pressable (`appearance="none"` or a box), as D9 already says. Params are written onto those rows by the component. The no-fork gate is a lint with a written denylist (no target test, no host-module argument), not “reads the platform.”

8. **BLOCKING** — D4, citing LLP 1122 D3. D3 pins scheme, mode, and build facts. It does not pin a prop. §4 adds no command. A variant is per-instance runtime data (D15), and the tool must not write a file. “Chooses on” is not a walk, so `disabled=(!enabled)` and an `if` can be marked as variants or missed. **Fix:** define a *1.15* preview command that sets the prop on the workbench copy only, or generate that copy outside the app. A prop of a closed option type or `bool` is a variant only when a style row of the component’s own view mentions it in `?:` or `match`.

9. **SHOULD-FIX** — D1. The opening rule says a literal colour, length, or radius is not a knob. `lower-library-literal` covers only spacing and radius rows, allows any zero, and does not look at param defaults, so `fill: color = "#1083fe"` and `padding="16px"` on a non-spacing miss both pass. **Fix:** warn on colour rows and on a param default that is a literal, and treat `0` and `0px` as the only allowed literal lengths.

10. **SHOULD-FIX** — D2. “A recipe never moves a part” is false of the groups as written: `space` is padding and gap, `text` includes `font` and `letter-spacing`, and `paint` includes `border-width`. **Fix:** say a recipe may change that part’s padding, gap, type, and border width, and may not set `display`, `position`, `width`, `height`, `flex*`, `overflow`, or `margin*`. Keep the border-width note in §6.

11. **SHOULD-FIX** — D2. `part` is not a reserved attribute, so `part=surface` is an unknown row unless lowering strips it. “Part” is already the `::placeholder` pseudo-element (`contract/syntax/src/parser/parts.rs`, LLP 1104), whose only row is `color`. **Fix:** `part=` is stripped and never emitted. Anatomy sections are not `::` parts. Placeholder stays that one pseudo-element.

12. **SHOULD-FIX** — D1’s example, against D15’s range check. `pad` defaults to `cards.pad`, which aliases unset `space.md`, with `range="0..40"`. D15 checks one folded px per app tuple. Today’s `0..40` happens to contain `space.md` and `radius.lg` in every column; a tighter range, or `radius.full`, does not. **Fix:** a ranged default that reaches an unset base lies in range in every scale column. Put that on B’s gate.
