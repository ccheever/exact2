The happy path is right. A fully visible row, switch, or detail button is aimed at the view UIKit draws, the covering check passes, and `realTap` accepts the landing because both `aim.hit` and `began.node` are the list owner. The Signal Clone refusal (`_UISystemBackgroundView covers its middle`) is fixed. Two edges still report `delivery: platform` for a touch that never reached the control.

1. **should-fix.** A half-clipped row whose center misses the port can succeed as a tap on an ancestor. `shown` treats any intersection as on-port (`GroupedListIOS.swift:142`), then `aim` uses that view's geometric middle (`TouchIOS.swift:160`). `UIView` hit-testing never reaches a cell whose center is outside the collection view. If that point falls in a parent's padding, the hit is the parent `NodeView`. `obscured` now takes the cell or accessory (`AgentIOS.swift:632`, called at `TouchIOS.swift:169`) and still allows any ancestor `NodeView` (`AgentIOS.swift:637`). `realTap` then compares `began.node` with `aim.hit` (`host/apple/touches.mjs:349`); both walk to that same ancestor, so the driver reports a platform tap. Host activation does not: it requires the cell's middle inside the collection view and a hit on the cell or a descendant (`GroupedListIOS.swift:159`). A full-bleed list fails closed (the overflow hits the viewport scroll view or a sibling and is refused). The same hole is open for an `x`/`y` override: `drag from` sends the hidden node's layout point, and after the collection view has scrolled on its own that point can sit on the ancestor. Those coordinates are absolute viewport points; leave them that way. **Fix:** when `v` is not a `NodeView`, require `hit === v || hit.isDescendant(of: v)`. Keep the ancestor clause for real nodes (a `pointer-events: none` child). Also refuse a grouped aim whose point lies outside the collection view's bounds, so the refusal stays the port error.

2. **should-fix.** A missing accessory should refuse, not aim at the cell. `shown` returns `list.accessory(row.view) ?? cell` for a toggle or detail target (`GroupedListIOS.swift:144`). `accessory` returns nil when the switch has no window (`GroupedListIOS.swift:378`) or the detail search finds no `UIControl` (`GroupedListIOS.swift:380`). The cell's middle selects the row when the row is pressable — a button can carry a switch or a detail button — or it does nothing. The landing check cannot tell the cell from the accessory; both resolve to the list owner. Host activation never substitutes the row (`GroupedListIOS.swift:173`). On tvOS the toggle case is not compiled (`GroupedListIOS.swift:377`), so every toggle aim takes this fallback; that is latent, because the platform runner is iOS-only, and the `#if` itself compiles. The detail search is fine: the smoke leg's state checks show the first control's middle fires the detail action on the simulator where it was run. **Fix:** if the requested node is the accessory target and `accessory` is nil, return `.some(nil)` and refuse with the switch or detail button not being on screen.

3. **nit.** The new test never aims. `testARealTouchAimsAtTheCellOrAccessoryUIKitDraws` (`GroupedListIOSTests.swift:154`) asserts `shown()` for a switch, a row, a non-drawn node, a detail control, and a fully scrolled-away row. It does not call `aim`, hit-test the returned control, or cover a partial intersection or a missing accessory. The smoke leg (`scripts/smoke-touch.mjs:87`) covers the visible switch, detail button, and row, and the info row is not pressable, so a cell fallback would fail that leg. It would not catch finding 1, or a pressable row whose detail control was missing. `llp/1084-native-grouped-lists.rfc.md:240` says the aim takes the view UIKit draws, as host activation does, and is refused when the cell is outside the port. The views and the dispatch node (the list's) are right. The refusals are not the same: activation occludes on the cell's middle, and it refuses a disabled row or control. Aim allowing a disabled control is the right finger semantics — a disabled switch still hit-tests, and UIKit declines — so the note should say that rather than claim parity. The fixture is already in `contract fmt` form: `header()` (`contract/syntax/src/fmt.rs:419`, width 100) would split `list` and `input`, and they are already split there, with the bare `switch` flag kept on the tag line. That is from the formatter rules; `contract fmt` was not executed.
