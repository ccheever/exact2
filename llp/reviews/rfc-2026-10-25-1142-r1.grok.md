## Concerns

**BLOCKING — D3 sends momentum at the scroll view the agent does not use.** `ChainingScrollView.appliesAtOnce` is `ExactEnv.agentMode` (`ChainingScrollView.swift:108`). A phased wheel with room then routes to `.here` (`:167`, `:206-209`), which clamps and calls `contentView.scroll(to:)` (`:302-310`). AppKit's rubber band and momentum run only for `.appKit`. That path is taken for a contained axis (`:195-200`), not for an ordinary list under the agent. `scrollWheel` does read `momentumPhase` (`:269-274`), and `AgentMouseMac.swift:80-85` sets `scrollWheelEventScrollPhase` only, so the field D3 wants is free. A synthesized stream aimed at a stock `NSScrollView`, which §5 names as the first probe, can succeed while every agent session still takes `.here`. The `NSClipView` clamp at `AgentMac.swift:215-218` is a separate, real limit on tests that set the origin through the clip view. Resolve this by rewriting D3 against `appliesAtOnce`: either the fling and the hold turn that switch off for the gesture and the probe is a `ChainingScrollView` in agent mode, or the driver times deltas through `.here` and the RFC stops claiming AppKit momentum. Also name the second gate on live frames: `FrameSampler.activity()` returns immediately while `session.clock != nil` (`FrameSampler.swift:115`), so clearing the virtual reply at `Agent.swift:383` still records nothing.

**MATERIAL — D1's phases are not a partition of the overrun, and several named intervals do not exist.** `overrun` is how far the main-thread turn ended past `targetTimestamp` (`FrameSampler.swift:46-48`), not the turn's duration. Summing whole-turn phase times and printing `other` as overrun minus that sum goes negative whenever the in-budget part of the turn is included. The sample print in §3 only works if the buckets are exclusive and cover the late portion alone. Nested signposts make that worse: `apply` (`PresenterMac.swift:1011`) wraps the batch, and anchor correction (`CollectionMac.swift:297-301`) sits in that batch with no interval of its own. `pump-collection` and `pump-text` (`PresenterMac.swift:546`, `:551`) are a later pump, not nested in `apply`. There is no signpost for kernel layout or for main-thread image decode. Raster decode runs on the raster worker (`RasterLoader.swift:231-242`). `text-raster-worker` runs on `RegionTextExecutor.queue` (`TextRasterIOS.swift:177-187`); `text-raster-urgent` and `text-draw` (`NodeViewIOS.swift:1446`) are the main-thread ones. The region-reader names are `reader-demand`, `reader-publish`, and `reader-draw` (`RegionReaderMac.swift:162`, `:275`, `:404`), not `publish` and `draw`. On the web, `loaf.script` and `loaf.styleLayout` (`host/web/frames.js:90-91`) exist only for long-animation-frame entries, which are frames over 50 ms (`frames.js:101`, LLP 1079 D4). A frame 17 ms past an 8.3 ms target gets no loaf, so mapping those fields onto `apply` and `layout` neither covers the reported gap nor means batch apply. Linux's record is paint time only (`frames.rs:26-32`). Resolve this by listing, per host, the function to wrap, charging the innermost phase only, defining `other` against that same window, dropping off-thread intervals, and leaving the web column empty below 50 ms unless a new timer is specified.

**MATERIAL — D4 replaces a string the driver already prints.** `state.failed` values are strings. The test runner interpolates them directly (`scripts/agent-test.mjs:433`, `:633`). `{why, count, first, last}` prints as `[object Object]` and breaks any snapshot of `state`. The runner also does not mark journal lines as failures: `release_failed` builds one string and calls `log` (`admission.rs:190-192`). `runner.rs:1134` is that generic `log`, not a failure site. Apple has no journal `Logger`; the existing ones are `com.exact.host` (the signposter) and `dev.exact` (`Wakes.swift:76`), not the proposed `com.exact.app`. Resolve this by adding `count`, `first`, and `last` without changing the type of the message the driver reads, naming the development predicate (`ExactEnv.releaseBuild` / `productionBake` in `BuildInfo.swift:114` and `Session.swift:35`; the Excord session was a person, so the gate cannot be `agentMode`), and saying how a host recognizes a failure line (a new flag from the runner, not a string search).

**MATERIAL — D5 does not say which process handles the signal, or where `--pid` finds the file.** The stderr line at `FrameSampler.swift:310` already exists on the Save Trace path. The macOS handler should follow the `SIGTERM` pattern: ignore in the signal handler, hop to the main queue (`ExactMac/main.swift:703-717`), then call `saveTrace` with no alert. The iOS simulator is a different binary. Its entry is `host/apple/Sources/ExactIOS/main.swift`, which installs no signal source. `kill -USR1` reaches the process and does nothing until that file handles it. After the save, the file is in the app's temporary directory, under the sandbox container for a bundled app, and the path is printed to stderr the driver does not have when a person launched the app. `trace --phone` works because it knows `tmp/trace-latest.json` inside the container (`agent-inspect.mjs:583-599`). `--pid` has no such rule. Resolve this by naming `ExactIOS/main.swift`, reusing `latestTrace`, and specifying the lookup (container `tmp/` for a simulator, a documented path for a Mac app).

**MATERIAL — D6's journal line needs a source location the runner does not have, and the threshold sentence is wrong.** Plan nodes do not carry file and line. The development map is what joins a site to `app.contract:<line>`, and a host or the runner must not read it (`rules/DEFERRED.md` lines 1323–1335). A lowering warning can use the AST span. A runtime journal line should carry the plan site, and `agent.mjs` should join it the way `perf` already does. "Half the display rate" is not 30 on this sampler: the period is `targetTimestamp − timestamp` (`FrameSampler.swift:18-20`), 8.33 ms on ProMotion, so half of 120 Hz is 60. A fixed 30 warns on a 120 Hz Mac for work that is not every frame. "While a scroller moved" is not a runner fact. `dispatch` (`runner/src/runner/event.rs:1085-1170`) has the view and the event while it runs, and it does not record the handler's plan site on the commit. The runtime key rule ("more than half its keys" while "length changes by fewer than that") does not say what "that" is, and a filter that rewrites keys at a stable length would warn. Resolve this by shipping `lower-key-position` first, adding the handler count to `perf` as a site id, deriving the rate from the measured period or dropping the "half the display rate" claim, and deleting the scroller clause and the file:line from the runner's line.

**MATERIAL — D7's port cannot be written into `app.json`.** `apps/excord/app.json:40` starts `fixture/server.ts` with no port, so the default is 4790. A hash of the checkout path is different in every worktree, so it cannot be committed there. The launcher that spawns `commands.server` has to export `EXACT_BACKEND_ORIGIN` and pass `--port` or `PORT`, and a server a person starts by hand has to use the same value or the baked app calls 4790 while the fixture listens elsewhere. A collision inside 4790–5789 is unspecified. The macOS XCTest idea is sound; the cost is unmeasured, as §9 says, and that measurement has to come before the lane grows. The build-exit pitfall line is worth doing: `host/web/build.mjs:104` already exits 1 on a failed JS build.

## Answers to Q1–Q6

**Q1.** The fixed phase list is a form of `perf`, on the same terms as LLP 1079's late line: durations beside the frame, with coverage stated, and no claim that a phase caused a commit. That holds only if the buckets are exclusive, host-named, and not attributed to app code. A stack sample on overrun is the flame chart and should stay refused. Confidence: high (0.8) on the distinction; the current arithmetic in §3 does not yet meet it.

**Q2.** Keep maps out of hosts and bakes. `--plan`, plus commit and checkout in `identity`, is the reading path LLP 1079 D5 already describes for a native trace. A development bundle that carries the map so the host can write it violates the rule DEFERRED states at lines 1323–1335. Confidence: high (0.9).

**Q3.** No badge. "No devtools UI" covers a LogBox-style overlay. The App Info line and the log forwarding do not need a ruling. Confidence: high (0.85).

**Q4.** Yes to the lowering warning `lower-key-position`. The handler-rate counter belongs on `perf`, joined to source by the driver. The runtime key-churn line and the "while a scroller moved" sentence should not ship as written. Confidence: medium (0.7).

**Q5.** Yes, after the Studio time is measured, and only if that time fits the lane. The gap is real: `scripts/async.mjs:174` is iOS only, which `QUEUE.md` around line 727 already records as intentional. Confidence: medium (0.65) that it should be added; low (0.4) on the cost, which nobody has measured.

**Q6.** No. A building marker in `QUEUE.md` will rot, and it would not have stopped the nucbox lane. Confidence: medium (0.7).
