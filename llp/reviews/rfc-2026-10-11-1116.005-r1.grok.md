## 1. Decisions

**D1 — RIGHT WITH CHANGE.** A second place on the web is a route. recipe-finder and event-rsvp lost because Back left the app, reload dropped the place, and nothing was linkable. habit-tracker won on a real `/add` route. GPT reads `navigation-stack` and still switches screens with `when`, then obeys compiler warnings, so a warning plus a vocab answer matches the diaries. The warning as written looks for a `header` in each arm. recipe-finder has no `header` and no `routes`: both arms are headings inside one `scroll` under a hand-built bar (`when showingDetail` / `else`). Key the warning off that shape, a state swap that replaces the page, and leave tabs, empty states, and error arms alone.

**D2 — RIGHT WITH CHANGE.** This is LLP 1115 on a field. An unsaid input in a grouped row is borderless in the cell on iOS and a visible field on the web and the Mac. `appearance="none"` stays the author's bare box. water-tracker lost on "18 px inputs read as plain text" because the docs teach that override, while `web-look` already promises a 36 px field. The host default never runs while start-here's first example, and the pitfall that says the fix is `appearance="none"`, keep teaching the override. Drop it in those places too.

**D3 — WRONG DIRECTION.** The grader note matches `web-look` ("an app bar, sticky on a page that scrolls"), and it did not decide a pair. recipe-finder lost on routes. tip-splitter won with the same inner scroller. Promoting the window-filling scroller to the document is the stopwatch bug on the web: the timer and buttons slid under the status bar, and Reset hit the status bar. recipe-finder is that shell (a fixed bar, `scroll flex=1`). Document scroll also splits layout from iOS (keyboard inset, large-title collapse, a composer or tab bar that must stay put), which LLP 1115 keeps as one box, and the RFC leaves the exception rule unnamed. Keep the shell. Restore each route's own scroll position on Back. That is event-rsvp's "detail opens scrolled partway down."

**D4 — RIGHT WITH CHANGE.** Text that changes or leaves has to repaint on that commit (stopwatch kept "3 laps" beside 00:00.00 after it had left the accessibility tree). The large title has to survive an error view replacing the list (chat-rooms). Stopwatch is an Expo loss. SwiftUI's third loss is grocery-list (empty section headers, a swipe row that clips), which this RFC does not cover and which is mostly the builder's. The same stopwatch grade has a second framework bug: once laps fill the screen, the page scrolls under the status bar. Cover that here. It is the constraint D3 must not violate.

**D5 — RIGHT WITH CHANGE.** A launch seed below 2^32 on every host is right for `%` and for `>>> 0`. It does not make trivia's mix exact. `seed * 2654435761 + round * 40503` is past 2^53 even for a 32-bit seed, and mulberry32 then keeps the low 32 of that already-rounded sum, so Play Again stays the same deck. The recipe they followed says to pass `round` so the source refreshes, and that "the argument itself is unused," which is why they invented the multiply. Show one mix, `Math.imul` and `>>> 0`, and drop the claim that ordinary arithmetic stays exact.

**D6 — RIGHT.** trivia's home shows "Trivia Quiz" as the large title and again as an `h2`. The author wrote the heading, so a warning is what LLP 1115 allows. It is a side note on a loss D5 decides, and it is cheap.

## 2. What the record still asks

D1 and D2 are the right answers to React's 2–5–1, and they match LLP 1115: a web user notices a missing URL, and a field that looks like text. They are not the whole 2–5–1. flashcards is builder scope (edit and delete), correctly left out. focus-timer is form chrome this RFC never names: a disabled Save that still looks like the primary button, no outline on the invalid field, Enter does not save. That loss is smaller than routing. D3 is not an answer to the 2–5–1.

The React token ratio is already visible, and D1 will not move it. Where GPT's command counts match, Exact2 is at or under parity (tip-splitter 32 vs 34 commands, event-rsvp 28 vs 32, habit-tracker 31 vs 27 and 1.09×). The ratio sits in three small apps: flashcards 27 vs 14 commands and 1.66×, focus-timer 24 vs 15 and 1.65×, recipe-finder 34 vs 23 and 2.29×. Fresh tokens are close (recipe-finder 91k vs 79k). The gap is cached context times extra commands. The diaries spend those commands after the app works: `verify` is green, then a hand-rolled Playwright script, more agent drives, and another screenshot pass. start-here says a clean `verify` is done, and also tells them to keep driving. React's one browser script is the tests and the screenshots. Fold the real-browser drive and the screenshots into that one report so a small web app stops near 15 commands. Vocab cut docs 22% and left steps flat because web-look, content-design, tests, and responsive-columns are still opened beside it. Round 8 measuring "where steps go after D1" waits on a change recipe-finder's diary already rules out: they read `navigation-stack` and never searched for routes. contacts (Muse, 79 vs 47 commands, 4.97M vs 1.96M) is a long loop, not that GPT floor.

## 3. Risks

D3 can make the goal worse: fixed chrome that scrolls away, and a web scroll model iOS does not share. D5 as written can ship and leave trivia red, so round 8 will treat a miss as "try another width." A D1 warning that fires on tabs adds route-learning turns. One that requires a `header` does nothing on the pair it is for. D2 and D6 stay inside author-wins. D4 should repaint the text that changed, not the tree.

## 4. Verdict

**READY WITH CHANGES.** Point D1's warning at the state-swapped page recipe-finder wrote. Drop `appearance="none"` from the required example. Replace D3 with per-route scroll restoration and keep fixed chrome fixed. Add stopwatch's under-the-status-bar scroll to D4. Make D5's recipe an `imul` mix. Put the verify-plus-browser-harness collapse on the list as the React token lever.
