# Design review: LLP 1108.001 r4, GPT-6 Astra

Reviewer: GPT-6 Astra (codex exec, xhigh, read-only), 2026-10-08, blind, on lane/media-slices-2-3 with r4 and the pre-r3 slice-2 draft in the tree. Same brief for both families.

NOT READY

1. **MAJOR — §§1.4/1.6: stalled rename still blocks the executor.** R4 moves writes and sync off-thread, but requires `rename()` under the executor’s shared state mutex. `renameat` remains a blocking filesystem call ([app_fs_unix.rs:78](/Users/ccheever/projects/exact2-wt-media23/vendor/ibex/crates/ibex2/src/stdlib/app_fs_unix.rs:78)); forgetting, completion and retirement all require that mutex ([executor_core.rs:394](/Users/ccheever/projects/exact2-wt-media23/host/apple/src/executor_core.rs:394), [:543](/Users/ccheever/projects/exact2-wt-media23/host/apple/src/executor_core.rs:543), [:475](/Users/ccheever/projects/exact2-wt-media23/host/apple/src/executor_core.rs:475)). A stalled rename can therefore block timeout delivery and the UI’s retirement path. Round-3 Astra #4/Grok #2 is only partially resolved. **Change:** decide publication with a short per-ticket state transition, release the shared mutex before filesystem calls, and explicitly define completion semantics once publication wins. Test a held rename alongside timeout, forget and another request’s completion.

2. **MAJOR — §2.2: wasm Blob reads need tracked host work.** Restoring `currentCall` after `blob.arrayBuffer()` does not keep its answer alive while the browser reads. With no fetch ticket or storage operation yet, the prelude fails the answer as “pending on nothing” ([prelude.js:1111](/Users/ccheever/projects/exact2-wt-media23/js/src/prelude.js:1111)); the realm then clears its host context ([module-glue.js:218](/Users/ccheever/projects/exact2-wt-media23/host/web/module-glue.js:218)). An in-memory probe of the proposed restore-and-send sequence reproduced that failure. This also affects directly awaiting browser Blob readers. **Change:** integrate asynchronous Blob operations with the existing `hostWork`/owner-delivery mechanism ([prelude.js:205](/Users/ccheever/projects/exact2-wt-media23/js/src/prelude.js:205), [storage.js:76](/Users/ccheever/projects/exact2-wt-media23/host/web/storage.js:76)). Test delayed reads, upload, abandonment and disposal in both iframe and worker realms.

3. **MAJOR — §§2.4/2.5: permanent UUID tombstones introduce an unbounded leak and increasingly expensive reloads.** Remembering every issued UUID forever retains memory even when every URL is revoked and every engine ends; the buffer quota cannot reclaim or limit it. Each replacement engine restarts the same stream ([js/src/lib.rs:311](/Users/ccheever/projects/exact2-wt-media23/js/src/lib.rs:311)), so redraws traverse the accumulated history. A probe using the repository’s generator ([storage-environment.js:40](/Users/ccheever/projects/exact2-wt-media23/host/web/storage-environment.js:40)) required 500,500 draws for 1,000 successive engines making one URL each, with zero live URLs. **Change:** use a bounded, non-repeating engine incarnation namespace combined with each engine’s generator, or another constant-space allocation scheme. Preserve stale-URL isolation without retaining every historical UUID; test churn and repeated reloads.

4. **MAJOR — §2.4: the bake refusal still permits compiling a device-dependent fallback.** The proposed error shape defers only when it escapes the answer ([js/src/lib.rs:675](/Users/ccheever/projects/exact2-wt-media23/js/src/lib.rs:675), [:700](/Users/ccheever/projects/exact2-wt-media23/js/src/lib.rs:700)). An answer that catches it and returns a placeholder produces an ordinary successful value; the probe confirmed this. Storage additionally records an external read **before** refusing ([door.rs:59](/Users/ccheever/projects/exact2-wt-media23/js/src/door.rs:59)), which the runner tracks independently ([settlement.rs:612](/Users/ccheever/projects/exact2-wt-media23/runner/src/runner/settlement.rs:612)). **Change:** require `createObjectURL` to record that device dependency before the bake check. Test caught and uncaught refusals. Round-3 Grok #4’s error-shape correction alone is insufficient.

5. **MINOR — §2.6: the older-video-arm fallback adds a forbidden compatibility branch.** The optional `exact_video_blobs` symbol explicitly preserves older arms, contrary to [rules/RULES.md:49](/Users/ccheever/projects/exact2-wt-media23/rules/RULES.md:49). The loader already validates required exports ([VideoModule.swift:36](/Users/ccheever/projects/exact2-wt-media23/host/apple/Sources/ExactKit/VideoModule.swift:36)). **Change:** update the arm and loader together and require the new export.

The status/header write gate, preserved refusal bodies, byte count and client publication split resolve parent Astra r4 #7 at the design level. The other earlier corrections are represented in r4. Charlie’s slice order and proposed bounds are respected; I found no additional boot-path or source-cap conflict. No files were modified.
