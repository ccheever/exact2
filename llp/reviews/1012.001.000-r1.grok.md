The findings are real, and stage 1 is the right work. The part that would make the implementation wrong is treating a directory-mtime walk as if it were a build receipt, and fixing the JS-target stylesheet reader only in the agent.

Spot-checks:

- **F1.** `openStdio` only checks that the binary exists (`scripts/agent.mjs` line 457). `builtAppMatches` checks that `dist/` is intact and names the app, not that any input is current. The macOS receipt omits `app.contract` on purpose: `completeBuild` skips the root build script's `rerun-if-changed` paths (`scripts/app.mjs` lines 821–825), and `caltrain-apple` does not `include_str!` the contract. Cargo's uplifted `<bin>.d` does include those paths and path-dependency sources, so the Linux half of D1 matches Cargo. This snapshot has no binary, so the "581 paths" count was not recounted.
- **F3.** `declared()` keeps a property only when a top-level `selectorText` is `.` + class. The emitter writes `.cN{…}` inside `#exact-root#exact-root{…}` (`emit.rs` lines 648–652). In current Chrome that inner rule's `selectorText` is `& .c22`, so the top-level test never matches. The same test in `flow.js` `classHeight` decides whether a paragraph's height is definite.
- **F4.** `accessibility_tree` ignores the request and asks the runner for `{"op":"tree"}` (`host/linux/src/agent.rs` lines 147 and 421). The runner honors `target` and `shallow`. Defaults are 420×900 on the web and 420×860 on macOS and Linux.
- **F5.** `clock()` reads `imageHold`, a module-level `let` the fixture never binds; `gpuInPlay` is injected, `imageHold` is not. `scripts/async.mjs` does not run `host/web/*.test.mjs`. The "31 pass, 4 fail" run was not repeated here: this machine's Bun is 1.3.12 and the tree refuses anything older than the pinned 1.4.2 before those tests start.

F2, F6, and F8 match the code (no APNG in `png.mjs`; the map has to come from the bake that produced the running plan; the header usage and the `main()` usage have already drifted). F7 belongs to LLP 1012.000.

## Per-decision verdict

**D1 — right with changes.** Refusing a stale Linux `<bin>.d` or a stale macOS receipt is the right refusal: a warning on stderr is what an agent skips, and a false pass is the harm. Hash every root build-script watch the receipt drops (`app.contract`, `app.json`, and the `data/`, shader, and asset paths that same `if` skips), the way `pendingBuildInputs` hashes. When `--plan` is set, the baked contract is not what is running; still refuse a stale host binary. The web check has to be a real input list on `.exact-build.json`, which the build already writes. Apply the same receipt check in `openIOS`; that launcher only checks that the bundle exists.

**D2 — right with changes.** A clock-sampled `screenshot` stays one of the nine operations: pixels of seeks, no input log, no replay, which is the line `DEFERRED` draws around session record/replay. The clock cannot go backwards, so the drive correctly ends at `over`. If a step stops short (a timer refusal or a request in flight), stop the film and return that error with the frames already taken. `png.mjs` encodes one IDAT today; the contact sheet fits that encoder.

**D3 — right with changes.** Walk nested rules and match `& .cN`, which is what Chrome returns. Use that same walk in `flow.js` `classHeight`. Otherwise inspection starts telling the truth while text-around-shapes still treats a class height as indefinite.

**D4 — right.** Forward the caller's `tree` request, then apply Linux's annotations. Pass a runner `error` through unchanged.

**D5 — right.** Bind `imageHold` as null in the fixture so the clock tests reach their assertions again. Leaving them off the async lane until Charlie says so is what `RULES` §Agents requires.

## Open questions

1. **Web staleness.** Refuse Linux and macOS from their own records. For the web, refuse when the app's own inputs differ, and refuse compiler inputs only once the marker lists them. A hard refuse on "newest mtime under `contract/`" will be bypassed with `--url`, which skips the check entirely.
2. **Sheet vs paths.** The contact sheet is the right single image for an agent to look at. Also write the frames and name their paths in the reply, at full resolution. A sheet of up to 240 full frames is too large to be the only artifact. Animated PNG remains the form a person plays; Linux still paints GIF frame 0, so film will not invent frames the host does not paint.
3. **Stage split.** Keep D6–D10 in stage 2. Pull `flow.js` into D3. Leave the 201 px vs 352 px `station-search` width out of D8: a shared viewport does not explain it, and a bare `input` keeps its intrinsic width at `display: block`, so the native hosts are the ones off the web rule. D8 should report authored and computed as two values. Rewriting computed `16px` into the runner's `16`, or leaving `font_family` as an index, fights "the web is the standard." D6's map beside the receipt in `target/`, out of the product, matches "never in a bake."

## Missed or overreaching

The input-width split is a host bug an agent will "verify" wrongly, and this RFC never names an owner for it. The web heuristic overreaches by claiming the same guarantee as a sha256 receipt. Nothing here adds an operation, a record/replay log, or a new gate.
