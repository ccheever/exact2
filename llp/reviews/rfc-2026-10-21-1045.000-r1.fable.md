**Overall assessment**

The shape is right. An atom as a span of the source, recognized by `exact-markdown` on every style, with faces keyed by source text, answers each of r3's findings (§7) with mechanisms that exist today: one crate (`markdown/editor/src/projection.rs`), one `contentEditable` field (`host/web/markup-editor.js:1-20`), r6's paragraph delegate (`MarkupHidden.swift:22-35`). The value stays the source (LLP 1045 D1). The reference citations I checked are accurate except two noted below. Six material changes are needed before a ruling: the press record borrows a DOM name, one caret rule has no visual meaning once the label is not source, the overlap between a link atom and the editor's existing hidden-destination run is unstated, two §10 questions rest on wrong facts, and inline math does not belong in this mechanism.

**Strengths**

**Concerns**

1. MATERIAL — D7, §7, Q6. `href`, `sourceStart`, `sourceEnd` on `MouseEvent`. The record is DOM's `MouseEvent` (contract/types/src/selection.rs:246-256: four modifier bools). DOM's `MouseEvent` has no `href`; an anchor's `href` is `event.target.href`. `event_record` maps `press` to `MouseEvent` by attribute, not by tag (selection.rs:69-79), so the change reaches every `press` in every app. This is r3's finding "DOM names given meanings the DOM's do not have" (1114.007 §0, line 20). Resolution: a separate record for a press on a `markup="markdown"` node, which needs a tag-aware `event_record` or a distinct event name. Say which in r2.

2. MATERIAL — D5 Caret. "Nearer edge; on a tie, its end" is copied from `composerChipEdge` (composer-rich.contract:35). That rule measures to the shown end `](` because today the label is shown source (:30-33). With a pill the label is not source, so "nearer" in source offsets means nothing to the person. On Apple (§4) the first unit is U+FFFC with the pill's advance and the rest are joiners with none (MarkupHidden.swift:22-35), so offsets start+1..end all draw at the right edge; a ↑ landing at start+1 would go to the start and jump left. The crate puts a caret after a `Prefix`/`LinkClose` cluster (projection.rs:211-229) and r6's `place` puts it after the run (MarkupHidden.swift:60-78). Resolution: one rule by drawn position: at start stays, strictly inside goes to end. Drop the tie-break.

3. MATERIAL — D1, D5, §4. A link atom and the existing hidden destination of the same link. The styler emits `links` (style.rs:100-110), `link_destinations` filters them (markdown/editor/src/lib.rs:39-50), the projection has `RunKind::LinkClose` (projection.rs:14), and Apple marks `.markupHidden`/`.markupOpener` from `l` (markup.rs:135-179; MarkupEditor.swift:132-139). r6's `rewrite` keeps a destination and its `[` through a replacement (MarkupHidden.swift:96-118), the opposite of D5's "replaces the range, atom included". The RFC says an atom is never inside another atom but not that an atom's link leaves `l`/`LinkClose`. Resolution: state that a link that is an atom is one `Atom` run from `[`/`![` to `)` and is not in `l`; the atom rules win in `place`, `rewrite`, `past`, `copyRange`.

4. MATERIAL — D1 ¶3, Q4. "This is the reference's own rule" holds for `$` (composer-rich-text-doc.ts:467-470 returns null for an unknown skill) but not for `@`: a mention segment is always a chip (:457-461) and the tokenizer has no face gate (composerInlineTokens.ts:65-96). What keeps a typed `@foo ` as text is the edit path: the only input rules are list, task, quote, rule and heading (ComposerPromptEditorTiptap.tsx:583-694, :879-930), and chips appear when the doc is rebuilt from the value (`buildDocJson`, :1141, :1601). Lines 1598-1606 show that rebuild, not a "stays text" rule. I did not confirm whether the parent's echo of a typed value triggers it. Resolution: restate the rationale: face-gating is the app's rule, and it keeps the reference's exclusions (`@scope/pkg`, `@name(`, `$5`: composerInlineTokens.ts:25-28, :36-42) out of the framework. Note that a typed and a picked `@x` share one key.

5. MATERIAL — D9, Q6 (second half). "`tap` has no point form outside `pinch`" is false. `tap <target> at <x> <y>` is a press at a point in the target on every carrier (llp/1012-agent-api-v1.spec.md:332-335; scripts/agent.mjs:4). Resolution: strike it; D9 says a drive presses an atom with `tap <field> at <x> <y>` from `state.atoms`' frame.

6. MATERIAL — D6, Q5. Inline math stretches "atom". Every defining property (caret, selection, deletion, press with `href`, link role, pill) is an editor or pill property. A math atom is reader-only (D3 refuses it on `textarea`), has no pill (D4), has role image (D8), and needs a field only it uses (`baseline`). It makes the styler's dialect depend on a per-node declaration (`$` is absent from `markdown/src` today, confirmed by grep) and adds an inline picture run to pieces, which carry text-run fields only (pieces.rs:36-60). Resolution: defer to a child RFC on inline replaced content in `text markup="markdown"`, which can also take inline images. `AtomFace` stays at four fields; stage 3 goes.

7. MINOR — D4. "The pill `NSTokenField` draws" and "`UISearchToken`": neither is reusable drawing in a TextKit 2 text view (NSTokenField's token is an `NSTextAttachmentCell`, TextKit 1; `UISearchToken` belongs to `UISearchTextField`; from Apple's API, not run here). Neither name appears under `host/apple/Sources`. The web has no platform token, so its unsaid look is the host's choice. Resolution: say these name the look to match, and say what the web pill is modeled on.

8. MINOR — §9, Q1, RULES. DEFERRED is binding and the RFC proposes no take; "Implementer: none yet" against RULES.md:57-59. Resolution: propose a take in Q1 (candidates: LLP 1045 D5's reveal-on-touch of the other native markers, or intrinsic `field-sizing: content` parity, behind atoms) and name the implementer at the ruling.

9. MINOR — D1 table. The reference and the clone require whitespace or a line start before a token and whitespace after it (composerInlineTokens.ts:24-27, :32-35; composer-source-chips.ts regexes), and `\p{Sc}` for a skill, not one `$`. The RFC's `prefix` ends at "the end of the source" and `relative` has no boundaries. Resolution: adopt the boundaries, or list the difference in §6 and gate `relative` by a face as a prefix token is.
