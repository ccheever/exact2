## Design (verbatim)

## 1. Summary

- Give every resource a typed zero placeholder unless its `else` clause supplies another.
- Add contextual `else empty(field=value, …)` for literal overrides, including nested records.
- Retain `else source(values…)` for computed placeholders and nonempty collections.
- Compile placeholders into the existing `#else` row structure, separately from the resource’s baked answer.
- Track placeholder provenance: it keeps `pending(r)` true and never becomes a kept, baked, or carried answer.

## 2. Surface

```ebnf
placeholder = "empty(" [field "=" value {"," field "=" value}] ")"
            | source_call

value       = string | number | "-" number | boolean
            | "none" | "some(" value ")"
            | "empty(" [field "=" value {"," field "=" value}] ")"
```

Omitting `else` means the typed equivalent of `else empty()`. Fields may be supplied only when the expected type is a record. `empty()` without fields works for every supported value type.

`empty` is a compiler form in placeholder position and inside its initializer. It is not a data source or a general expression constructor. Overrides accept literals, `none`, `some(…)`, and nested `empty(…)`; computation remains available through `else source(…)`.

This reuses the existing call grammar and `field=value` syntax. Both already parse today. [parser.rs:694](/Users/ccheever/projects/exact2/contract/syntax/src/parser.rs:694), [parser.rs:1249](/Users/ccheever/projects/exact2/contract/syntax/src/parser.rs:1249)

## 3. Semantics

| Type | Zero |
|---|---|
| `number` | Positive `0` |
| `string` | `""` |
| `bool` | `false` |
| `unit` | `Value::Unit`, distinct from `none` |
| `option<T>` | `none`; do not construct a `T` |
| `list<T>` | `[]`; do not construct an element |
| Record | Every field’s zero, recursively, in declaration order |

These values match the existing structural conformance rules, including finite numbers and positional record fields. [value.rs:108](/Users/ccheever/projects/exact2/plan/src/value.rs:108)

Runner-provided record types use their resolved fields too; there is no special empty object or field-name heuristic. This does not initialize or replace the live router. Runner-owned sources such as `exactViewport` continue supplying actual host facts synchronously. [routes.rs:52](/Users/ccheever/projects/exact2/contract/types/src/routes.rs:52), [runner.rs:1091](/Users/ccheever/projects/exact2/runner/src/runner.rs:1091)

Recursive shapes remain rejected, including recursion through lists or options. Action types and unresolved types remain invalid resource value types. [checks.rs:314](/Users/ccheever/projects/exact2/contract/types/src/checks.rs:314), [lower/lib.rs:616](/Users/ccheever/projects/exact2/contract/lower/src/lib.rs:616)

**Overrides and arguments.** Named overrides replace fields of the zero record; nested `empty(…)` receives its type from the containing field. `some(empty(…))` can explicitly populate an optional record. Nonempty lists and computed constants use an existing source factory.

Neither form captures the resource’s live arguments. `empty(id=homeFeed)` is rejected; `empty(id="discover")` is allowed. A placeholder requiring computation from constant arguments can remain `else emptyFeed("discover")`. State-dependent placeholders stay out of scope, consistent with the existing restriction. [component.rs:233](/Users/ccheever/projects/exact2/contract/types/src/component.rs:233)

**A value’s contents never determine whether it is an answer.** A source may genuinely answer with all zeros, `ready=false`, or `found=false`. That is still an answer. Conversely, an overridden placeholder remains pending even if it contains `ready=true`.

| Situation | Result |
|---|---|
| Boot, source ready | Reuse eligible real data or ask the source. If it answers `Later` without retained real data, display the placeholder and dispatch the request. |
| Module awaiting load | Display the placeholder with `pending=true`, `awaiting=true`, and no request ticket. `data_ready` asks the current arguments. |
| Refresh or changed arguments | Preserve the existing behavior of displaying the last real answer while requesting another. A placeholder never satisfies the answer cache. |
| Failed request, parser returns `Now(value)` | Publish that value as an answer and clear placeholder provenance—even if it equals the placeholder. |
| Parser returns `Later` | Keep displaying the prior value and continue pending. |
| Parsing or shape validation refuses | Preserve transactional refusal: restore the previous state/request and report the error. Do not convert failure into successful empty data or introduce retries. |
| Carried reload | Carry eligible real answers under existing identity, type, and argument rules. Reconstruct placeholders from the **new plan** and ask unanswered resources again. |

The existing implementation already retains values during requests, shapes failed outcomes through the source, and asks deferred resources at activation. [settlement.rs:489](/Users/ccheever/projects/exact2/runner/src/runner/settlement.rs:489), [commit.rs:669](/Users/ccheever/projects/exact2/runner/src/runner/commit.rs:669), [kept.rs:128](/Users/ccheever/projects/exact2/runner/src/runner/kept.rs:128)

**Inspection.** Preserve displayed values in `state.resources` and the actual-ticket list in `state.pending`. Add:

"resourceStatus": {

## 4. Implementation

**Syntax and authoring tools.** Keep the existing `Placeholder` and expression ASTs. Recognize `empty` contextually; its nested arguments already fit `Expr::NamedArg`, `Expr::Call`, and `Expr::Some`. Formatting retains the existing syntax. Update symbols so `empty` is not reported as an app source. [ast.rs:369](/Users/ccheever/projects/exact2/contract/syntax/src/ast.rs:369), [symbols.rs:498](/Users/ccheever/projects/exact2/contract/cli/src/symbols.rs:498)

**Types.** Add a small placeholder checker/materializer taking the expected `Ty` and resolved shapes. It constructs the canonical `Value`, validates overrides, and retains the result in checked component metadata. Run it for implicit defaults and explicit `empty(…)`. Never register `empty` in the source signature table. Existing source factories retain signature unification and the state-read restriction.

No resource-stage system is needed: every valid resource value type has a defined fallback. Lists and options keep their existing implicit behavior.

**Lower.** For a materialized placeholder, emit the existing helper row:

```text
name         = "<resource>#else"
source       = ""
args         = []
ty           = owner's type
initial      = encoded placeholder Value
initial_args = encoded Value::List([])
reader       = false
placeholder  = None
```

Point the owner’s `placeholder` column at it. Do **not** populate the owner’s `initial`. Omitted list/option placeholders need no helper row because their existing runner fallback suffices.

This extends the current lowering at one site; it does not add expression bytecode or a runtime constructor. [lower/lib.rs:463](/Users/ccheever/projects/exact2/contract/lower/src/lib.rs:463)

**Plan format.** Keep `resources.placeholder: opt:resources`. Document an empty `source` as a constant helper, permitted only for a row referenced as a placeholder. Validate that it has zero arguments, a conforming encoded value, encoded empty `initial_args`, no reader flag, and no placeholder of its own. Retain the existing same-type and non-self-reference checks. [format.json:143](/Users/ccheever/projects/exact2/plan/tables/format.json:143), [plan/lib.rs:257](/Users/ccheever/projects/exact2/plan/src/lib.rs:257)

No column or opcode is added. Updating the format declaration changes its digest; old readers reject the new semantics rather than interpreting them as an app call. The digest already covers the canonical JSON declaration. [plan/build.rs:243](/Users/ccheever/projects/exact2/plan/build.rs:243)

**Bake.** Preserve compiler-created constants. Continue answering source factories during bake; they must return a conforming `Now` value. A factory returning `Later` is refused even when its result type is a list or option—its own implicit empty must not conceal the mistake.

A baked helper is an immutable template from the bake’s empty-store evaluation. Runtime activation does not re-evaluate its factory. Ordinary resource store-reader behavior remains unchanged.

Replace the current ticket-name-only exclusion with a semantic eligibility check: the owner’s displayed placeholder is never compiled as its answer, including when it is awaiting a module without a ticket. Today bake checks `runner.pending()`, which contains tickets only. [cli/lib.rs:528](/Users/ccheever/projects/exact2/contract/cli/src/lib.rs:528)

**Runner.** Add `is_placeholder: bool` to `ResourceState`. This is necessary because settlement currently stores every displayed value there without distinguishing its origin. [runner.rs:180](/Users/ccheever/projects/exact2/runner/src/runner.rs:180), [settlement.rs:540](/Users/ccheever/projects/exact2/runner/src/runner/settlement.rs:540)

Use that provenance consistently:

- Set it when displaying either an explicit helper or an implicit list/option empty.
- Clear it on a real `Now` answer or eligible real-data adoption, regardless of value equality.
- Reuse a placeholder only to display it while matching work is already pending or awaiting activation; it cannot prevent the first query.
- Include it when deriving `pending(r)`, independently of ticket existence.
- Exclude it from answer persistence, bake output, carry, and document answers.
- Exclude helper templates themselves from carried answers; load them from the current plan even when a carried boot calls `settle(false)`.
- Never send constant helpers through `DataSource`, `adopt`, or `keep_answer`.

Keep the existing placeholder pointer lookup and settlement ordering. [settlement.rs:79](/Users/ccheever/projects/exact2/runner/src/runner/settlement.rs:79), [settlement.rs:353](/Users/ccheever/projects/exact2/runner/src/runner/settlement.rs:353)

Carry currently relies on pending/stale flags; the provenance check makes its exclusion explicit and independent of transient request bookkeeping. [runner.rs:440](/Users/ccheever/projects/exact2/runner/src/runner.rs:440)

**Diagnostics.** Report independent mistakes together using the existing diagnostic sink.

| ID | Example message |
|---|---|
| `type-placeholder-field` | `` `post`'s placeholder: `Profile` has no field `avater`. `` |
| `type-placeholder-duplicate` | `` `post.author.image` is supplied twice. `` |
| `type-placeholder-fields` | `` `empty` overrides use `field=value`; `Feed` received a positional argument. `` |
| `type-placeholder-type` | `` `post.author.found` expects `bool`, got `string`. `` |
| `type-placeholder-value` | `` `post.title` must be a literal, `some(...)`, or `empty(...)`; use `else source(values...)` for computation. `` |
| `type-placeholder-reads` | `` `feed`'s placeholder reads `homeFeed`: placeholders cannot read runtime state. `` |
| `bake-placeholder-later` | `` `feed`'s placeholder `emptyFeed` answers later; a placeholder must answer now. Use `else empty(...)` or a synchronous factory. `` |

Preserve `type-shape-recursive` and existing unrepresentable-type diagnostics. A missing `else` is no longer an error: its value is defined. Retain defensive runner refusals for unavailable or invalid factories, naming the owner.

**Existing factories.** `else source(…)` remains a supported feature, not a compatibility branch. Remove exports used solely to manufacture placeholders. Keep ordinary data helpers: RealWorld’s empty constants also shape real source results and failures, and Bluesky’s `empty` dispatch handles ordinary sources as well. [app.ts:81](/Users/ccheever/projects/exact2/apps/realworld/app.ts:81), [values.rs:207](/Users/ccheever/projects/bluesky-exact2/data/src/values.rs:207)

Neither Rust nor TypeScript needs code or generated source signatures for the common case.

## 5. Alternatives considered and why rejected

- **Only opt-in `else empty()`.** Leaves the missing-placeholder problem unless every potentially delayed resource gets a mandatory annotation. Without stage labels, implicit zeros provide defined behavior with less declaration churn.
- **Zero-only support.** Leaves three of RealWorld’s four factories because of avatar defaults and the nested author value.
- **General record expressions or defaults on shapes.** Expands expression typing and construction beyond placeholders, or makes a presentation choice apply to every use of a shape.
- **Live argument-dependent placeholders.** Adds dependencies and reevaluation rules without a demonstrated need; the cited feed ID is expressible as a literal.
- **Put generated zeros in the owner’s `initial`.** Makes a stand-in look like baked data and can suppress the first request.
- **Generate zeros in each data executor.** Requires Rust/TypeScript implementations or module readiness for something the compiler already knows.

## 6. Risks and open questions

Implicit scalar zeros are an intentional extension alongside record zeros. They satisfy structural types, not domain invariants: zero is not necessarily a sensible image ratio or route value. Views must still use `pending(r)` where absence matters.

Implicit helpers increase plan bytes and settlement row counts for records and scalars. Measure the two consumer plans; do not add interning or another runtime graph without evidence that the existing representation costs too much.

The important verification cases are: nested records/options/unit; runner-owned facts before module load; a real answer equal to its placeholder; awaiting without tickets during bake; failed outcomes and admission refusal; argument changes; repeated reload; and a reload that changes only a placeholder literal. Source factories returning `Later` need coverage for list and option results too.

For this design review, I ran the existing compiled six placeholder tests and four carry tests; all passed. Those verify current behavior, not the proposed changes. No files were modified.
