VERDICT: RIGHT WITH CHANGES

1. **[BLOCKING] [D3, §9 Q2](/tmp/rv-1139-r1/llp/1139-component-library.rfc.md:173): The param exception contradicts the stated composition rule.** Existing classes sit below authored rows regardless of whether those rows read params ([class.rs](/tmp/rv-1139-r1/contract/lower/src/class.rs:25)). Consequently, Card’s `background-color="param.fill"` defeats QuietCard’s background, and its authored `gap="space.sm"` defeats QuietCard’s gap. “Unless the row reads a param” introduces an unspecified exception; changing the param itself would affect every instance, contrary to per-instance recipe selection. **Fix:** specify one complete precedence table, including a part’s existing class, recipe, authored rows and every state after shorthand expansion. To preserve D8 unchanged, remove the exception and restrict recipes to rows the component leaves unset.

2. **[BLOCKING] [D3](/tmp/rv-1139-r1/llp/1139-component-library.rfc.md:180): The slot protection can be evaded through admitted values.** A slot ancestor taking `text` can receive `color="transparent"` or a zero-size `font` shorthand. Different token names can resolve to identical foreground and background colours. An opacity token can become zero in a `when` branch or a subsequent live edit. Keeping the caller’s variables and providers does not prevent inherited styling or ancestor opacity from hiding its content. **Fix:** define a conservative, mechanically enforceable invariant for slot ancestors, checking expanded rows, resolved dependencies and states. Recheck mutable dependencies during transactions and scrubs; reject values whose safety cannot be established.

3. **[BLOCKING] [D2](/tmp/rv-1139-r1/llp/1139-component-library.rfc.md:143): One content slot does not mean one `children` placement.** Contract expands the same fill separately at each placement, including placements in regions. The existing [child-state test](/tmp/rv-1139-r1/contract/cli/tests/it/child_state_lifetime.rs:370) explicitly exercises two copies. The singular “slot’s part” also leaves forwarded slots and multiple containing parts undefined. **Fix:** preserve Contract’s rule and represent every slot placement and its containing part ancestry. Alternatively, introduce an explicit restriction for library anatomy, with diagnostics, rather than describing it as an existing Contract rule.

4. **[BLOCKING] [D3](/tmp/rv-1139-r1/llp/1139-component-library.rfc.md:150): Recipe application lacks a compatible component-call grammar.** `Card class="QuietCard" title=…` is not a Contract component call; calls use parentheses. Existing `class` values are style identifiers or conditional choices, not strings. Merely moving `class` inside parentheses would make it a component argument, not existing element styling. See [component-use parsing](/tmp/rv-1139-r1/contract/syntax/src/parser/view.rs:170). **Fix:** specify a dedicated recipe annotation on component calls, its relationship to an ordinary prop named `class`, and identifier/conditional syntax. Resolve the target through the component’s declaring identity and import aliases before inlining, preserving existing style-name resolution.

5. **[BLOCKING] [D4–D5](/tmp/rv-1139-r1/llp/1139-component-library.rfc.md:224): Pinning a selected instance’s prop is new runtime functionality.** LLP 1122 D3 does not supply it. The existing [`pin` payload](/tmp/rv-1139-r1/docs/tamber-protocol.md:1178) contains scheme, contrast, modes and root font size. Component props are substituted during compilation, so there is no general runtime prop cell to overwrite. **Fix:** specify the development representation and protocol: build/plan-qualified instance address, declared prop and type, authorization, ownership, acknowledgements, disappearance/reload handling and disconnect/revoke cleanup. Define interactions with prop-derived state and application effects. Otherwise, limit variants to authored workbench controls instead of promising arbitrary instance pins.

6. **[BLOCKING] [D7, §4](/tmp/rv-1139-r1/llp/1139-component-library.rfc.md:253): Per-column arithmetic has no specified representation or wire encoding.** Current lengths are scalar px/rem/em or named references ([measure.rs](/tmp/rv-1139-r1/tamber/src/measure.rs:71)); live batches carry one value per app tuple, not per host column. The terminal also uses `ch`, making `calc(space.sm + 2px)` more than a numeric px fold. **Fix:** define the resulting value form, column selection, terminal unit policy, serialization, fallback and any format/schema changes. Cover native bindings, JS CSS and SVG attributes. Preserve base dependencies through folding so retention, `uses`, `bases`, edits and scrubs remain correct. Optional read fields alone do not specify this change.

7. **[BLOCKING] [D1](/tmp/rv-1139-r1/llp/1139-component-library.rfc.md:72): The advertised ranged defaults fail D15’s current rules.** `cards.pad = space.md` and `cards.corner = radius.lg` retain named references when the bases are unset. The [range checker](/tmp/rv-1139-r1/contract/lower/src/params.rs:349) accepts only `Length::Px`, so the illustrated sliders produce `tamber-range-unit`. D7 does not explicitly change bare-alias range checking. **Fix:** use token controls without ranges, or explicitly amend D15 to validate every relevant column and tuple, with a defined terminal-unit policy, while retaining the host reference.

8. **[BLOCKING] [D8, §6](/tmp/rv-1139-r1/llp/1139-component-library.rfc.md:265): Rename aliases violate the binding rules and do not provide the claimed behavior.** `cards.pad = cards.padding` makes the old name follow the new; an app override of `cards.pad` does not change readers of `cards.padding`. The bare `renamed` marker and param spelling lack canonicalization and conflict rules. Compatibility aliases also contradict [“Delete; don’t deprecate”](/tmp/rv-1139-r1/rules/RULES.md:49). The empty-part tombstone additionally violates D2’s requirement that every part have a node. **Fix:** remove the compatibility mechanism and update the private packages and consumers together. Any retained-alias exception needs an explicit ruling and complete semantics, including simultaneous old/new overrides and `when` branches.

9. **[BLOCKING] [§3, §5 B](/tmp/rv-1139-r1/llp/1139-component-library.rfc.md:281): Package-design components need an explicit identity and retention path.** Contract component params and `.tamber` declarations for non-Contract components are different cases. Currently, [`params::tokens`](/tmp/rv-1139-r1/contract/lower/src/params.rs:58) collects Contract declarations and the app design’s components; the package merger copies package tokens. Simply lifting `tamber-package-block` would not collect package-design components. **Fix:** preserve each package design’s declaring identity when collecting its components, reject identity collisions, and retain all non-Contract params and their dependency closures as D15 requires. Keep package `params` override blocks prohibited. Add a gate using a package-declared native component read only through generated bindings; the proposed Contract-component gate cannot catch this omission.

10. **[BLOCKING] [D5, §4](/tmp/rv-1139-r1/llp/1139-component-library.rfc.md:230): Anatomy inspection is not specified sufficiently to join or edit safely.** Existing [`explain`](/tmp/rv-1139-r1/docs/tamber-protocol.md:423) addresses a token, not a node. `{component, part, recipe:{style,file,line}}` supplies neither a node address nor per-row/state provenance. The current component IR also enumerates components through their params, omitting inspection-only components. **Fix:** define the node request or extend the existing selection response; carry declaring identities, part-to-site mappings and recipe origins through inlining. Record winning origins per row/state with source spans and digests, including conditional recipes and caller-owned slot content. Emit anatomy entries without params, and keep inspection metadata outside release artifacts.

11. **[SHOULD-FIX] [D2, D6](/tmp/rv-1139-r1/llp/1139-component-library.rfc.md:244): Native-control policy conflicts with the chosen PostButton consumer.** LLP 1121 D9 explicitly permits an authored pressable for PostButton’s faded-blue disabled appearance; the platform’s prominent button cannot provide it. D6’s unconditional native-control requirement removes that exception. Meanwhile, `paint` omits `accent-color`, the supported parameter D6 prioritizes. **Fix:** distinguish native controls from intentionally authored pressables, retain D9’s PostButton exception, and declare supported native-control styling explicitly. Apply D8’s target exclusions to native controls and grouped-list rows, not merely its row whitelist.

12. **[SHOULD-FIX] [D5, §4](/tmp/rv-1139-r1/llp/1139-component-library.rfc.md:237): The tool’s write destinations and nested recipe addresses are incomplete.** Existing style edits identify a style, row and optional state; two recipe parts can now write the same row. “C has no wire” leaves that ambiguity unresolved. “Back to the package” also conflates removing a param override with removing a package-token override; unsetting the former may still leave the latter active. **Fix:** add a part-qualified edit address or explicitly make recipe rows read-only in the tool. Keep param edits the default rung, make broader token edits explicit, and label each reset by the override it removes. Preserve the existing [package ownership guard](/tmp/rv-1139-r1/contract/cli/src/tamber_contract.rs:69) for every write path, including undo and compound operations.

13. **[SHOULD-FIX] [D2, §6](/tmp/rv-1139-r1/llp/1139-component-library.rfc.md:132): The permitted groups do move layout.** Padding, gaps, fonts, letter spacing and border widths can change geometry. Moving `border-width` from `paint` to `shape` does not change that behavior or make it host-dependent. **Fix:** replace “a recipe never moves a part” with the actual restriction on positioning and structural rows. Define group membership over canonical schema rows and shorthand expansions, retain the separate state-paint restriction, and account for permitted geometry changes in the slot invariant.

14. **[SHOULD-FIX] [§5](/tmp/rv-1139-r1/llp/1139-component-library.rfc.md:299): Several gates lack executable acceptance criteria.** First defining or removing a retained base token changes table structure and therefore rebuilds under the [current live protocol](/tmp/rv-1139-r1/docs/tamber-protocol.md:1043); B/B2 cannot promise unconditional live behavior. A source-text “no platform reads” check misses helper calls and indirect inputs. Screenshots and “still shows children” lack a fixed input/state matrix. **Fix:** specify expected live/rebuild cases, including first override, removal and changed dependencies; define the exact compiler-level platform-read restriction; name deterministic consumer fixtures, states, variants, mode tuples, host columns, baselines and comparison thresholds. Separate universal compiler invariants from finite visual tests.

15. **[SHOULD-FIX] [D1–D4](/tmp/rv-1139-r1/llp/1139-component-library.rfc.md:72): The examples contain additional unsupported spellings.** Contract’s closed string type is `enum<"primary", "quiet">`, not `"primary" | "quiet"` ([parser](/tmp/rv-1139-r1/contract/syntax/src/parser.rs:765)). `font="headline"` and the purported roles `background.secondary`/`text.secondary` are not the schema’s spellings. PostButton names undeclared parts. Component-valued leading/trailing props would require the render-prop facility §8 excludes. **Fix:** use the existing enum syntax and platform names, declare the parts, show a real `params` override block, and provide a runnable ListRow example using ordered slot children or ordinary data props.

16. **[SHOULD-FIX] [§5](/tmp/rv-1139-r1/llp/1139-component-library.rfc.md:301): The mandated “house process” conflicts with binding repository rules.** Required SIGNOFFS files and fixed review rounds conflict with [DEFERRED’s process restrictions](/tmp/rv-1139-r1/rules/DEFERRED.md:992). **Fix:** remove those mandates and retain owners, dependencies and concrete acceptance gates, unless an explicit applicable exception is recorded.
