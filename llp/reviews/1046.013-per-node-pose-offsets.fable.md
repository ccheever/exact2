# Review of LLP 1046.013 (per-node pose offsets), r1

**1. Verdict: READY WITH CHANGES.** The shape is right (presentation-only, palette path, CPU composition in `pack`, mark at the asset). Four things need fixing before code: the interpolation-history semantics, the presentation-column allocation, the composition frame (do not pay for it in the exporter), and the 17th-row panic.

**2. Agree**
- D1. `Gait` is literally Castle's `modelAnim = {phase, swing, air, lean, last}` (`pxmodel.js:660`); saving it and deriving offsets in `present` is the README's rule exactly, keeps `animation::step` the only `Pose` writer (`animation.rs:1098`), and keeps pins still under gait tuning.
- D4. Palette path, no new GPU path. `skin.wgsl` already interpolates local TRS and composes the hierarchy; `merge.rs` `animated_groups` keeps `avatar-0` at 2 draws (I checked the GLB: 20 nodes, 6 meshes, 2 opaque materials, 5+1); `cull.wgsl:70` bounds a skinned record by its palette, so offsets cull exactly and shadows follow. Composing on the CPU at both endpoints is trivially cheap and leaves the shader alone.
- D3 one predicate `Model::animated()` for the three gates; rejecting promote-on-first-use and parts-as-entities, for the reasons given.
- Deferring the saved procedural layer. The trigger is right.

**3. Would change**
**(a) Presentation-only: fine, but the smoothness claim is wrong as stated, and on the target device.** `present` runs at the last two ticks of an advance (`sim.rs:1203`), but the rows from T−1 are erased when T presents (`world/presentation.rs:16`), and the renderer feeds skins once per completed-tick feed (`models/poses.rs:19`, gated by `self.tick != w.tick()` in `world.rs`). So the renderer's "previous row" is its *last fed* row, not T−1 — same as `History::update_to` for `Offset` (`world/scene.rs:107`). On a Pixel 5 at 25–30 fps (castle-town README) every frame is a 2-tick advance: `Pose.previous/local` are (T−1, T) while the offset history is (T−2, T). For Castle's clip-less avatars this is a uniform lag, invisible; for "offsets over clips", which the RFC promises, the node and its parent interpolate over different intervals every frame. Alternative: say what the history is (last fed, current) and that `Offset` has the same semantics; or, the elegant fix, double-buffer presentation columns in the engine (`clear_presentation` swaps instead of erasing; `Present`/renderer read `previous`), which makes the sim's "last two ticks" comment true, fixes `Offset` as well, and removes the renderer-side history this RFC adds. Cost: 2× presentation memory, a World change outside this RFC. At minimum, write the truth into D1 and drop the 1−cos(π/10) argument, which assumes tick-exact endpoints.
Also write the cliff down: `Ik` runs before offsets (`finish` in `animation.rs`), so IK and `NodeOffsets` on one chain are incoherent, and `animation::socket` returns the un-swung hand. Agents will spawn things from `handR`; the engine README's "save the cause" section should say offsets are invisible to sockets.
**(b) Node-frame composition: keep it, but not by editing the asset.** The GLB's `armL`/`armR` rest at Rz(±16°) (nodes 9, 12). three.js `rotation.x = swing` with Euler XYZ yields Rx(swing)·Rz(16°): the swing axis is the torso's X. Node-frame gives Rz(16°)·Rx(swing): a swing plane tilted 16° — visible in the stride screenshots. D3's remedy (the exporter inserts a splay child) is a tell: the API fights the content, every ported model with a rotated part needs the same surgery, and `verify.mjs`'s node counts move. Node-frame is still the right default (additive layers post-multiply, `animation/layers.rs:149`; `Offset` is `local·offset`). Alternative: a per-row flag, "parent axes about the node's pivot": rotation `r′·r`, position `p + p′`, scale `s⊙s′`. Identical to node-frame on unrotated nodes, one branch in `pack`, matches three.js/Unity `localRotation` semantics, no asset edits. Cost: one bool per row and two rules in the doc. (The game could also conjugate by the rest rotation itself, but then it hard-codes a per-model constant.) Also define "parent frame" in Not-in-scope: the true affine pre-multiply `p′ + r′·p` rotates the leg about the hip's parent, which nobody wants.
**(c) The fixed row and "0 allocations" — the proof will fail against the engine as it is.** `erase_all` frees a page when its count reaches zero (`storage/raw.rs:349–356`); the next present re-allocates and zeroes it (`alloc_zeroed`, `raw.rs:59`). `PAGE = 512` (`storage.rs:23`) × ~1.5 KB = ~768 KB zeroed per page per present. Today's `Offset`/`Tint` pay 20 KB; `NodeOffsets` pays 40×. Fix in the engine: an `erase_all` that drops values and keeps pages (five lines, helps every presentation component). Also shrink the row: drop `scale` unless a use exists (Castle never scales parts), and the row is hash + 7 floats ≈ 36 B → ~600 B at 16 rows.
**(d) A 17th row must not panic.** A present panic leaves the guard armed and refuses a restore; a content-dependent crash (`Rig::model` marks every bone; the humanoid preset is ~12, a tail or fingers pass 16) is a field crash. Drop the row with a once-per-entity diagnostic, or make the capacity a const generic with 16 the default.
**(e) `NodeName`.** Fine; the 64-bit FNV in a `const fn` costs nothing. Two notes: `Data: Default + read` cannot produce a `&'static str` — define `NodeName::read` as an error ("presentation rows are not read") and say agent JSON is write-only; and ≤16 posable nodes per model means a sorted `[(u64,u32)]` scan beats a map. The real wart is two naming schemes for one node (`NodeMaterials` uses `String`, `scene.rs:537`); the RFC should name `NodeName` as the direction, not just defer.
**(f) The posable mark.** Right place. State the costs: `Node.posable` changes the `.model` format and every model's content identity (saves refuse by name), so everything rebakes; `tools/export.mjs` must write the extra; `rig::Rig::model` marking every bone is fine (already skinned).
**(g) Palette path / loss of static merge.** Right for avatar-0. Missing: the *blended* pass is CPU-visible by record sphere (`renderer/draw.rs:537`, `culling.rs:125`), and a posable-only model has no `Pose`, so `spatial.rs:147` gives rest bounds — a Blend part swung out of them pops. Castle's avatars are opaque; say the limit, or keep posable models' blended parts `KEEP_ALL`.
**(h) Upload at 30 vs 1,000.** At 30: 96 KB/tick, noise. At 1,000: `pack` copies every skinned record of every level (`skinning.rs:358` iterates `records`, not `job_records` filtered by `hidden`) and `poses.write` uploads the whole buffer (`:409`) — 3.2 MB/tick memcpy plus the staging copy, ~400 MB/s on shared LPDDR4x, likely 1–2 ms of the Pixel 5's frame before the 2,000 workgroups. The RFC's three cuts are right; the cheapest with no new semantics is "pack drawn levels only, write the dirty range". The 1,000 column should read as the trigger for that cut, not as a property of this design.

**4. What will bite an implementer**
- `World::insert` calls `leases.restructure()` per insert (`world.rs:591`); `insert_each` must walk the source column without a live `query()` guard, or every live query holds all its rows for the loop.
- `insert_each`'s closure gets `(Entity, &C)` only; Rivals-style presenters need `p.tick()`/`p.get` inside. Give it a read-only view, or the API is Castle-only.
- Sanitize the composed quaternion in `pack`: a NaN row poisons `cull.wgsl`'s `norm()` and the record vanishes; `Opacity` already does this for its channel.
- Bound the unmatched-row diagnostics (1,000 entities × 16 rows).
- Two records per avatar (merged group + torso) each compose the full row set: your 600/20,000 counts already include this; `pack` could compose once per entity and copy.
- Proof item 2's "order is clip, IK, offset" needs a clip-animated posable fixture; `skinned-fixture` has no posable nodes and castle-town has no clips.

Verdict: READY WITH CHANGES. Every disposition of my r1 findings holds on the code. One thing r2 added (D4's refusal of negative-determinant nodes) collides with the port's own content and must be resolved in the text before code.
F(a) rejected — holds: sim.rs:1205 presents at target − tick < 2, then :1233 calls after with left; the stock observer feeds at left < 2 (surface.rs:296-310), so a 2-tick advance feeds twice, after T−1's present and after T's. The feed reaches pack each time because world.rs:1057 gates on self.tick != w.tick() and :1135 advances it. Offset's History::update_to (world/scene.rs:107) shifts on the same next_tick, so its history is also (T−1, T). Double buffering not needed.
F(c) keep scale — holds: motion.js:18/225/347/363.
F(g) blended culling — holds: draw.rs:590 CPU-culls only record.skin.is_none(); sorting by rest centre is a stated limit.
F(b) flag deferred — holds: verify.mjs:87/90. The arm nodes already are pure groups (armL#9 mesh=undefined children=[10,11] in avatar-0.glb), so the exporter can pre-multiply Rz(±16°) into the two children's matrices without adding a node; N stays 20.
NEW (MATERIAL): D4 refuses a posable model when any node has a negative determinant. 15 of the 16 GLBs contain such nodes (Castle's mirror groups: an unnamed diag −1,1,1 node under head or torso wrapping the second eye, glint, cheek, leaf, from export.mjs:204-207). Refusing is correct today because the static merge rewinds a mirrored node (merge.rs:148-156), the animated merge does not (:192), and bind_pose decomposes to a negative scale (asset/pose.rs:48). Remedy (elegant): extend the animated merge's winding rule to rest-mirrored joints (same determinant() < 0 test on the joint's rest matrix, and whatever the lone-part rigid record uses), and refuse only shear. Parity is static because D3 drops offset rows with scale ≤ 0. The cofactor normal in model_vertex.wgsl already handles mirrored matrices.
D5 one span per instance — sound (skinning.rs add_merged, :287, skin.wgsl job.y + node*10; priming per template :374 — the shared span must OR over the instance's templates, as mark_fresh does).
D6 retained pages — sound; put a number in Cost: retention is per page ever touched, bounded by peak entity index; 1,000 avatars over 20k indices retain ~26 MB for this column; the sparse proof should report it.
Nit: a finite all-zero quaternion passes the non-finite check and Quat::normalize yields NaN; use try-normalize to identity.
