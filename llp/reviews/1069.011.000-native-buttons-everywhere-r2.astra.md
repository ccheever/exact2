1. **Blocker — D5’s macOS opening path runs before its promised revalidation.**

   r2 says to cancel the default action when the handler removes or retargets the invoker, while retaining the implicit opening performed by `Presenter.press`. Those instructions conflict. `onPress` applies its batch synchronously, then `Presenter.press` immediately calls `menus.pressed`. A handler changing `popovertarget` from A to B therefore schedules B before `invokeNative` can reject the changed relationship. The queued opening checks only that the two IDs still exist. An ancestor handler that is itself an invoker can also schedule its menu before the native child schedules another.

   **Evidence:** [Session.swift:668](/Users/ccheever/projects/exact2-wt-buttons2/host/apple/Sources/ExactKit/Session.swift:668), [PresenterMac.swift:684](/Users/ccheever/projects/exact2-wt-buttons2/host/apple/Sources/ExactKit/Mac/PresenterMac.swift:684), [MenusMac.swift:38](/Users/ccheever/projects/exact2-wt-buttons2/host/apple/Sources/ExactKit/Mac/MenusMac.swift:38), [MenusMac.swift:57](/Users/ccheever/projects/exact2-wt-buttons2/host/apple/Sources/ExactKit/Mac/MenusMac.swift:57).

   **Change:** Give native invocation an application-handler dispatch path without implicit menu opening. Capture the originating invoker and resolved target, dispatch once, revalidate them, then schedule exactly one default action. Revalidate again when the scheduled opening executes. Test retargeting, disabling, removal, and an ancestor that also invokes a menu.

2. **Blocker — D5’s iOS branches still prescribe different owners for the press.**

   The common routine promises nearest-ancestor handler resolution, but the specified existing deferred provider presses only the invoker’s own handler. `openConfirmation` does the same. Calling either after `invokeNative` has dispatched repeats an own-handler press; calling them directly misses an ancestor handler. Likewise, “the provider’s press and then `presentMenu`” needs protection against the uncached provider performing that press again during presentation.

   Merely naming `invokeNative` does not resolve these conflicting instructions. The existing native activation also performs focus and editing work that these menu helpers bypass.

   **Evidence:** [MenusIOS.swift:118](/Users/ccheever/projects/exact2-wt-buttons2/host/apple/Sources/ExactKit/IOS/MenusIOS.swift:118), [MenusIOS.swift:239](/Users/ccheever/projects/exact2-wt-buttons2/host/apple/Sources/ExactKit/IOS/MenusIOS.swift:239), [NativeButtonsIOS.swift:60](/Users/ccheever/projects/exact2-wt-buttons2/host/apple/Sources/ExactKit/IOS/NativeButtonsIOS.swift:60).

   **Change:** Separate invocation preparation—focus handling, target resolution, one dispatch and revalidation—from presentation and row extraction. Define how pointer-driven deferred resolution and programmatic opening share one prepared activation without redispatching. Make confirmation presentation consume that preparation too. Remove the copied 80-ms delay; the handler batch is synchronous. Test own, ancestor-only and absent handlers through both presentation kinds.

3. **Should-fix — Shortcuts and the iOS agent’s keyboard path remain outside the new activation contract.**

   D5 covers Enter/Space on the node and agent `tap`; D7 changes shortcut identity and faces. Neither explicitly repairs the independent shortcut and agent-key dispatch paths. Changing shortcut discovery to `isButton` while preserving its other eligibility rules still excludes handlerless native invokers. Both shortcut execution paths call `presenter.press` directly. The iOS agent likewise implements Enter/Space itself, requiring an own `press` handler and bypassing `NodeView.pressesBegan`.

   **Evidence:** [ShortcutsMac.swift:53](/Users/ccheever/projects/exact2-wt-buttons2/host/apple/Sources/ExactKit/Mac/ShortcutsMac.swift:53), [ShortcutsMac.swift:68](/Users/ccheever/projects/exact2-wt-buttons2/host/apple/Sources/ExactKit/Mac/ShortcutsMac.swift:68), [ShortcutsMac.swift:153](/Users/ccheever/projects/exact2-wt-buttons2/host/apple/Sources/ExactKit/Mac/ShortcutsMac.swift:153), [AgentIOS.swift:669](/Users/ccheever/projects/exact2-wt-buttons2/host/apple/Sources/ExactKit/IOS/AgentIOS.swift:669).

   **Change:** Explicitly include native invokers without an own handler in shortcut eligibility, and route shortcut execution and agent Enter/Space through the same invocation routine. Test both handlerless and ancestor-handler cases. Also state the agent-mode presentation: ordinary iOS menus currently receive no native attachment in that mode ([MenusIOS.swift:75](/Users/ccheever/projects/exact2-wt-buttons2/host/apple/Sources/ExactKit/IOS/MenusIOS.swift:75)).

4. **Should-fix — D8’s fresh `UIControl` does not establish a fresh callback lifetime for its reused `NodeView`.**

   Recreation fixes the reviewed switch/date state leakage. However, D8 retains the control’s node, unlike existing holes, which destroy the whole leaf node. An old native button’s action resolves `button.owner` at delivery time; that owner can now be the reused node under a new ID. Menu confirmation liveness similarly checks object identity through the node’s *current* ID. Neither check uses the incarnation that the pool already invalidates and replaces.

   Cleanup timing matters: `Presenter.release` currently has no control/menu retirement hook, and end-of-batch control cleanup is later than parking and possible taking. Its cleanup also omits `lastRange`.

   **Evidence:** [NodePoolIOS.swift:203](/Users/ccheever/projects/exact2-wt-buttons2/host/apple/Sources/ExactKit/IOS/NodePoolIOS.swift:203), [NodePoolIOS.swift:272](/Users/ccheever/projects/exact2-wt-buttons2/host/apple/Sources/ExactKit/IOS/NodePoolIOS.swift:272), [NodePoolIOS.swift:466](/Users/ccheever/projects/exact2-wt-buttons2/host/apple/Sources/ExactKit/IOS/NodePoolIOS.swift:466), [NativeButtonsIOS.swift:84](/Users/ccheever/projects/exact2-wt-buttons2/host/apple/Sources/ExactKit/IOS/NativeButtonsIOS.swift:84), [MenusIOS.swift:138](/Users/ccheever/projects/exact2-wt-buttons2/host/apple/Sources/ExactKit/IOS/MenusIOS.swift:138), [PresenterIOS.swift:822](/Users/ccheever/projects/exact2-wt-buttons2/host/apple/Sources/ExactKit/IOS/PresenterIOS.swift:822), [ControlsIOS.swift:102](/Users/ccheever/projects/exact2-wt-buttons2/host/apple/Sources/ExactKit/IOS/ControlsIOS.swift:102).

   **Change:** Specify an immediate retirement hook before rebinding: invalidate attachments and pending callbacks, detach actions and clear the old button’s owner, remove its control, and clear `controls`, `kinds`, `reported`, `menus` and `lastRange`. Require captured IDs/incarnations for deferred providers and confirmations. Preserve D8’s glass teardown through `syncGlassSlot`, then create and register the new control in the existing `controls.sync → menus.sync → glassGroups.reconcile` order. [GlassGroup.swift:263](/Users/ccheever/projects/exact2-wt-buttons2/host/apple/Sources/ExactKit/GlassGroup.swift:263), [PresenterIOS.swift:808](/Users/ccheever/projects/exact2-wt-buttons2/host/apple/Sources/ExactKit/IOS/PresenterIOS.swift:808).

   Also replace “not retired” with an explicit lifetime outcome: refusing `pool.retire` currently causes ordinary destruction, not retention ([PresenterIOS.swift:748](/Users/ccheever/projects/exact2-wt-buttons2/host/apple/Sources/ExactKit/IOS/PresenterIOS.swift:748)). Actual destruction must cancel presentation and invalidate completions; retaining an interaction requires the existing collection-pin mechanism. Test a retained old callback after take, glass-to-glass reuse, and destruction while presentation is pending.

5. **Should-fix — D6’s image-map addition does not make swipe-action discovery safe with native body buttons.**

   `actionView` searches every `UIButton` beneath the table, including the authored body, and matches by accessible label **or** image. A newly admitted native body button named “Archive” can therefore match the “Archive” swipe action. Two matches make the action unresolvable; when only the body matches, the agent can activate the body button while reporting activation of the swipe action. Recording the native symbol in `images` does not distinguish those owners.

   **Evidence:** [SwipeActionsIOS.swift:359](/Users/ccheever/projects/exact2-wt-buttons2/host/apple/Sources/ExactKit/IOS/SwipeActionsIOS.swift:359), [AgentIOS.swift:460](/Users/ccheever/projects/exact2-wt-buttons2/host/apple/Sources/ExactKit/IOS/AgentIOS.swift:460).

   **Change:** Exclude the authored carrier/body subtree, including hidden original action controls, from rendered-action discovery. Keep the image map for matching UIKit’s action presentation. Test matching body/action labels and symbols, including an unrevealed action.

6. **Should-fix — D1/D7 change existing custom shortcut titles despite promising to preserve custom projection behavior.**

   The universal textual fallback `title ?? label` reverses the current shortcut preference: custom shortcuts use `aria-label` first. A custom button showing “⋯” with `aria-label="More options"` would acquire “⋯” as its menu title when the shared face exposes its visible text as `title`.

   **Evidence:** r2’s D1/D7 at [RFC:29](/Users/ccheever/projects/exact2-wt-buttons2/llp/1069.011.000-native-buttons-everywhere.rfc.md:29) and [RFC:49](/Users/ccheever/projects/exact2-wt-buttons2/llp/1069.011.000-native-buttons-everywhere.rfc.md:49); existing behavior at [ShortcutsMac.swift:143](/Users/ccheever/projects/exact2-wt-buttons2/host/apple/Sources/ExactKit/Mac/ShortcutsMac.swift:143).

   **Change:** Preserve each custom projection’s existing label/title preference. Apply the new native textual fallback explicitly, or make the custom naming change an intentional decision with a regression test.

7. **Should-fix — D5’s iOS matrix overstates ordinary-menu `commandfor` support.**

   r2 lists `commandfor` alongside `popovertarget` for iOS menus. The existing implementation interprets `command` only for dialogs: `show-modal` and `close`. For a non-dialog target, `opens` ignores `command` and checks `popovertargetaction`; it therefore treats a `commandfor` source as opening regardless of its command.

   **Evidence:** [MenusIOS.swift:53](/Users/ccheever/projects/exact2-wt-buttons2/host/apple/Sources/ExactKit/IOS/MenusIOS.swift:53). The documented admitted subset is dialog confirmation, while general popover invoker commands remain outside that subset: [LLP 1021:150](/Users/ccheever/projects/exact2-wt-buttons2/llp/1021-menus.rfc.md:150), [LLP 1021:419](/Users/ccheever/projects/exact2-wt-buttons2/llp/1021-menus.rfc.md:419).

   **Change:** Narrow the matrix to ordinary menus through `popovertarget`, and the existing confirmation grammar through `commandfor` with `show-modal`/`close`. Refuse unsupported combinations explicitly, unless this RFC also defines and tests their command semantics.
