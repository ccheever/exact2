1. **MATERIAL.** A received file is stored under the sender's name. D3 (`llp/1133.024-share-browser-compose-print.rfc.md` lines 237–260), which line 260 calls "LLP 1114.006 D3, unchanged."

The path is `app:/tmp/shared/<id>/<name>`. `<name>` comes from another app. LLP 1114.006 D3 (lines 193–195) stored `app:/tmp/shared/<id>.<ext>` with an id from the launch seed and a counter. LLP 1069.002 D4 (line 883) does the same for picks: the path never contains the user's file name; that name is only `Picked.name`. A name containing `..` or a slash leaves `app:/tmp/shared/` and, if the extension uses it while writing `<group>/shares/<uuid>/`, leaves the inbox inside the App Group container that holds LLP 1126's update-store generations (LLP 1126 D8, lines 385–389). The opaque query token is sound: `sharedFiles` returns `[]` for a token the runner did not mint, so a forged location cannot invent files. The hole is the path.

**Resolution.** Name the bytes `app:/tmp/shared/<id>/<n>.<ext>` from the launch seed and a counter. Keep the sender's name only as `Picked.name`. When claiming the inbox, refuse a `share.json` name that is not a single safe path segment. Drop the "unchanged" sentence.

2. **MATERIAL.** The Mac share extension is specified as a class AppKit does not have. D4 steps 1–2 (lines 276–294) and the packaging note (lines 333–334); the macOS share-target row in §15.

`SLComposeServiceViewController` is the iOS and Mac Catalyst compose sheet. The archived App Extension Programming Guide gives iOS that system sheet and requires macOS to supply its own compose view (`NSViewController` adopting `NSExtensionRequestHandling`). This Mac host is AppKit. This RFC's own D12 (lines 565–568) records that, and so does LLP 1114.004 (line 202): Catalyst's Safari controller opens the default browser, and AppKit has neither that controller nor this compose class. One principal class cannot serve both hosts. The inbox, the App Group, and the Darwin notification still work on the Mac. The sheet does not.

**Resolution.** Keep `SLComposeServiceViewController` for iOS. For macOS, specify an AppKit `NSViewController` with the same Post and Cancel result and the same inbox write, under the same `com.apple.share-services` point. State that choice in §15.

5. **MATERIAL.** Android print replays the canvas op stream onto a software PDF canvas, and that replay calls `drawRenderNode`. D19 (lines 940–947) and stage 0 (lines 1186–1187), which probes this and names no fallback. Apple's painter has one (lines 931–939).

`Player.replay` draws structural ops with `Canvas.drawRenderNode`: native views (line 713), row nodes (line 864), picture slots (line 873), layers (line 879), and scroller groups (line 902). A frame of text is those row nodes (`ExactView`). `PrintedPdfDocument`'s page canvas is a software canvas, and `drawRenderNode` throws on a canvas that is not hardware-accelerated ("Software rendering doesn't support drawing RenderNodes"). **Resolution.** Paint an Android page the way D19 already paints a Windows page: rasterize, then `drawBitmap` into the PDF page. Vector text in the Android PDF waits on that interpreter, as it already does on Windows.
