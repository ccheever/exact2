1. **Treat this as a promising lever, with its token impact still to prove.** Removing unfamiliar rules and repair steps fits the goal. But diagnostics are not separate failed builds: I extracted 162 JSON errors in 73 compiler outputs across 80 builds, with the median error output around 31% through the command sequence. That weakens the premise that each error costs a separate late build. Rank changes by avoidable repair steps, lookups and re-sent tokens; estimate how much of the gap they could actually remove.

2. **Include knowledge builders successfully look up.** Compile errors reveal guesses that survived the documentation, not everything builders needed to learn. Stage 1’s extra lookups included tests, persistence, timers, composition and function signatures; colour aliases address only part of that demand. Trace those successful lookups too. Identify which knowledge each language change eliminates, then test removing that teaching. Otherwise builders can keep reading the same early documentation even when more guesses compile.

3. **Set a bounded naming policy before admitting aliases.** Keep CSS names authoritative where CSS supplies them, including `AccentColor`. Where CSS has no name, consider making the familiar platform spelling canonical instead of automatically retaining Exact’s abbreviation. For aliases retained on evidence, use the existing [schema authority](/Users/ccheever/projects/exact2/kernel/tables/schema.json): one role, one semantic implementation, consistent lookup/documentation, and equivalent lowering across hosts. A UIKit-shaped spelling must still resolve to each host’s role, preserving [LLP 1115](/Users/ccheever/projects/exact2/llp/1115-write-the-web-ship-the-platform.principle.md). Avoid routine canonical-spelling notes: they add context and can provoke unnecessary edits after a successful build.

4. **Separate harmless syntax acceptance from inferred behaviour.** Quoted numeric CSS literals and checked type annotations are strong candidates. An annotation should also supply the missing element type for `[]`, rather than merely agree with an independently inferred type. Inferring `key=x.id` is a different decision: an `id` field does not establish the intended identity, uniqueness or stability. Keep that explicit for this experiment, or evaluate it separately with state retention and reorder behaviour. Frequency of a guess is evidence of friction, not proof of its meaning.

5. **Make D2 preserve the intended presentation, especially native controls.** “Drop `buttonStyle`” can remove the error while abandoning the native button the builder wanted. Offer the concrete native-preserving edit alongside the authored-face alternative, and assess which builders choose. Likewise, moving a conditional header can affect its presence and spacing. Prefer semantic suggestions over unconditional nearest-name matching; something like `-exact-tint-background` may mean a subdued surface rather than the full accent. Successful repair must retain intent and “no tells.”

6. **Measure repair in the fast loop, not just initial errors.** First-pass compilation measures D1, but cannot demonstrate D2’s benefit: better diagnostics leave the initial error count unchanged. Give builders a bounded repair opportunity and measure tokens, lookups and attempts to a correct result. Include a small behavioural or structural check so deleting a feature, dropping native presentation, or accepting the wrong meaning cannot improve the score merely by making compilation succeed.

7. **Use the corpus for diagnosis and regression, with held-out validation.** Preserve real failed programs and run identical inputs against both compiler versions; separately generate fresh guesses to measure discoverability. Forty short screens drawn from the same specs risk overfitting and omit interactions involving components, data, tests and navigation. Include representative complete examples and held-out tasks, and distinguish the start-here-only experiment from the actual pattern/card workflow. Retain the graded end-to-end comparison by builder and platform as the adoption decision; corpus improvement alone cannot establish lower total tokens at equal quality.
