No critical findings. The [RFC](/Users/admin/Developer/observe-lab/exact2/llp/1132-shown-and-interactive.rfc.md) has these major and minor issues. External references were not fetched under the local-only constraint.

1. **Major — D1/D3: “has been shown” is insufficient.** A previously shown screen can become ready while unselected, covered by a modal, or superseded. Its parts likewise remain mounted. Conversely, a split’s non-top route can remain usable: [head.rs:109](/Users/admin/Developer/observe-lab/exact2/runner/src/head.rs:109) explicitly preserves that case. A sheet can leave its presenter visible while disabling interaction ([ModalIOS.swift:453](/Users/admin/Developer/observe-lab/exact2/host/apple/Sources/ExactKit/IOS/ModalIOS.swift:453)).  
   **Fix:** Require current presentation and input eligibility, separately from historical `shown`. Define cancellation/re-entry for tabs, covering layers, backgrounding and supersession. Use host presentation facts, including refusal, rather than treating `open` or an attempted command as presentation. Track eligible subjects independently; one “top” is insufficient for splits.

2. **Major — D1: launch completion is not derived from screen completion “as built.”** Apple’s launch independently settles its ledger and then marks the current screen interactive ([Launch.swift:336](/Users/admin/Developer/observe-lab/exact2/host/apple/Sources/ExactKit/Launch.swift:336)). Its initial-route path marks shown on `NextFrame` without checking appearance ([NavigationMarks.swift:210](/Users/admin/Developer/observe-lab/exact2/host/apple/Sources/ExactKit/NavigationMarks.swift:210)); only subsequent navigations use `routeAppeared` at line 275. A launch sheet delayed behind another presentation can therefore receive launch-derived marks before appearing. The Observe README explicitly admits this exception.  
   **Fix:** Separate the app’s first frame from the launch destination’s first frame. Preserve process-start timing across redirects, discard destinations replaced before presentation, and derive launch readiness from the actually eligible destination. Correct the “as built” claim.

3. **Major — D1/D5: parts lack a coherent lifetime and identity.** Starting every part at its parent’s visit makes a comments panel opened ten minutes later report ten minutes of loading. Remounting it under the same visit conflicts with “at most one” and “nothing is filled in later.” A part outside any screen inherits the process launch indefinitely. D5 identifies parts by `id`, but duplicate IDs are supported ([symbols.rs:271](/Users/admin/Developer/observe-lab/exact2/contract/cli/tests/it/symbols.rs:271)); D3’s example dialog has no ID although D5 requires one in its event.  
   **Fix:** Give each measured mount/open occurrence an internal identity and a defined start; use authored IDs as labels. Explicitly define ownership outside routes and for root-level dialogs.

4. **Major — D3: declaration override also appears to bypass fatal failures.** Its complete eligibility list contains shown, transition completion and the expression. “The ledger does not apply” removes the only specified poisoned-runner/activation checks, which D2 states only for launch. A true declaration can thus certify UI whose actions cannot commit. Existing navigation explicitly cancels on poisoning ([NavigationMarks.swift:354](/Users/admin/Developer/observe-lab/exact2/host/apple/Sources/ExactKit/NavigationMarks.swift:354)).  
   **Fix:** Make runtime viability and lifecycle cancellation unconditional prerequisites for every subject. Declarations override loading dependencies, not fatal execution failure.

5. **Major — D4: one `ChromeIndex` key cannot implement “any element.”** The index explicitly excludes text runs ([ChromeIndex.swift:1](/Users/admin/Developer/observe-lab/exact2/host/apple/Sources/ExactKit/ChromeIndex.swift:1)). Apple creates no individual native view for SVG children, option contents, inline runs or protected native content, and skips their ordinary property updates ([paragraph.rs:231](/Users/admin/Developer/observe-lab/exact2/host/apple/src/paragraph.rs:231), line 307). Their declarations would disappear from the proposed Swift index. Renewal also preserves `NodeKey` while requiring fresh per-mount state ([txn.rs:80](/Users/admin/Developer/observe-lab/exact2/kernel/src/txn.rs:80)); membership alone cannot reset first-passage history.  
   **Fix:** Maintain declaration facts from kernel receipts before native projection, propagate those facts to Swift, and reset occurrence state on `renewed` even when the boolean is unchanged.

6. **Major — D4: the JS target’s set does not retain readiness.** D4 specifies membership on mount/unmount, while the change table removes the attribute from the DOM. There is consequently no specified boolean to read. Ordinary bindings write DOM properties ([rt.js:687](/Users/admin/Developer/observe-lab/exact2/host/web-js/rt.js:687)); literal bindings skip dynamic emission ([emit.rs:1203](/Users/admin/Developer/observe-lab/exact2/host/web-js/src/emit.rs:1203)). A constant `interactive=(true)` needs handling too.  
   **Fix:** Specify one runtime entry containing occurrence identity and current boolean, initialized for constants and updated by the ordinary reactive effect, with scope cleanup. The Rust `touched` proposal covers value changes; the JS proposal must provide its equivalent.

7. **Major — D2/D6: app settlement is not subject interactivity, and the built claims differ across hosts.** D2 admits that unrelated covered-screen loading delays a ready layer. Its unchanged-tree requirement can also delay readiness during unrelated updates ([launch_marks.rs:123](/Users/admin/Developer/observe-lab/exact2/host/linux/src/launch_marks.rs:123)). Moreover, the JS host ignores resource failure status and unconditionally finishes as `settled` ([marks.js:148](/Users/admin/Developer/observe-lab/exact2/host/web-js/marks.js:148)); failed module loading can leave resources waiting indefinitely ([rt.js:533](/Users/admin/Developer/observe-lab/exact2/host/web-js/rt.js:533)). “Images never” also excludes canvas-image decoding only rhetorically: Apple counts it through `loadingCount` ([Canvas2DImage.swift:147](/Users/admin/Developer/observe-lab/exact2/host/apple/Sources/ExactSurfaces/Canvas2DImage.swift:147)).  
   **Fix:** Prefer no undeclared interactive mark, retaining app settlement as a separately named diagnostic. Otherwise document the approximation and host differences precisely, including image categories and failure outcomes.

8. **Major — D1/D5: Observe separation remains semantic, not merely lexical.** The framework permanently suppresses a screen’s later interactive measurements because Observe records one per screen—explicitly the rationale in [NavigationMarks.swift:5](/Users/admin/Developer/observe-lab/exact2/host/apple/Sources/ExactKit/NavigationMarks.swift:5). Renaming events preserves that service policy. D5’s migration inventory also omits Apple’s Observe-specific launch-duration formula ([Launch.swift:564](/Users/admin/Developer/observe-lab/exact2/host/apple/Sources/ExactKit/Launch.swift:564)) and framework `EXACT_OBSERVE_LOG` controls.  
   **Fix:** Emit general presentation-occurrence facts and let Observe deduplicate/classify them. Move its formulas and thresholds with its names. A single measured-scope mechanism, with launch as an aggregate, is simpler than four independent timing systems and automatic events for every popover.

9. **Major — D3: banning a root declaration unnecessarily limits application-defined readiness.** An app with routes cannot declare that its persistent shell or two visible panes together constitute key UI; it must accept “screen on top.” That contradicts the owner’s application-defined requirement and author precedence.  
   **Fix:** Allow an explicit launch/root predicate to override the default aggregate. Keep one expression per measured scope. Apply placement validation after component expansion, which lowering already receives ([lib.rs:7](/Users/admin/Developer/observe-lab/exact2/contract/lower/src/lib.rs:7)), rather than adding a separate component mechanism.

10. **Minor — D4: the cited O(depth) precedent is false.** `inactive` calls `unselected`, which scans stacks and invokes a descendant traversal in `tab_panels` ([head.rs:210](/Users/admin/Developer/observe-lab/exact2/runner/src/head.rs:210), line 255).  
    **Fix:** Use a plain parent-link walk for ownership and existing presentation notifications for eligibility. Benchmark the complete read path, holding subject count constant and varying tree width as well as depth.

11. **Minor — D3/§0: live predicates and completed reporters are conflated.** “True at mount makes … interactive when shown” conflicts with requiring truth at the eligible frame if it becomes false beforehand. The cited task/reporter completions are latched events; a reactive conjunction is not generally equivalent.  
    **Fix:** State that the predicate must be true at the first eligible presented frame; earlier transient truth does not count. Narrow the platform analogy.

12. **Minor — D1/D2/Q1: terminology promises more than the mechanism.** D1 says both times are presented frames, but D2 explicitly permits loop-turn timestamps. The web fallback timestamps a task after `requestAnimationFrame`, not a verified presentation ([marks.js:62](/Users/admin/Developer/observe-lab/exact2/host/web-js/marks.js:62)). The nonstandard `interactive` name also needs an explicit deviation ruling.  
    **Fix:** Distinguish frame estimates from readiness timestamps, and document that the approved attribute observes readiness without enabling or disabling interaction.
