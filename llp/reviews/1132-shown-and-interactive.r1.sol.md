No critical findings.

1. **Major — D1/D3: historical “shown” does not establish present usability.** A retained screen can have been shown previously while now hidden, covered, or unselected. A newly mounted part beneath it satisfies D1’s mounted-plus-subject-shown rule; its true declaration then produces TTI offscreen. A visible screen beneath a sheet can also be inert ([NavigationRulesTests.swift:161](/Users/admin/Developer/observe-lab/exact2/host/apple/tests/ExactKitTests/NavigationRulesTests.swift:161)). **Fix:** distinguish first-shown history from current presentation and input eligibility. Gate declared interactivity on current eligibility. Explicitly cancel pending attempts on supersession/backgrounding and define their restart on return.

2. **Major — D1: one router top cannot describe split-view screens.** The RFC promises times for each route, but existing timing tracks one top and one pending navigation ([NavigationMarks.swift:34](/Users/admin/Developer/observe-lab/exact2/host/apple/Sources/ExactKit/NavigationMarks.swift:34)). Meanwhile, [`beside_a_pane`](/Users/admin/Developer/observe-lab/exact2/runner/src/head.rs:118) deliberately treats the stack’s first route as live beside its selected detail. On a direct launch into detail, that visible list—and declared parts inside it—may never receive their own shown time. **Fix:** derive presentation eligibility from the host’s presented routes, including simultaneous panes, rather than exclusively from router-top changes.

3. **Major — D1/D3: the launch appearance claim is not “as built.”** Subsequent UIKit navigations wait for `routeAppeared` ([NavigationMarks.swift:269](/Users/admin/Developer/observe-lab/exact2/host/apple/Sources/ExactKit/NavigationMarks.swift:269)); launch routes instead become shown through an unconditional next-frame callback ([NavigationMarks.swift:210](/Users/admin/Developer/observe-lab/exact2/host/apple/Sources/ExactKit/NavigationMarks.swift:210)). Startup settlement also marks the current top interactive without consulting that appearance gate ([Launch.swift:360](/Users/admin/Developer/observe-lab/exact2/host/apple/Sources/ExactKit/Launch.swift:360)). A deferred launch sheet can therefore count before UIKit presents it. **Fix:** use the same presentation/transition eligibility for launch and navigation. Specify redirect collapsing through actual first presentation; a launch screen replaced before its frame must remain unshown.

4. **Major — D2: the default measures global settlement, not the subject’s key UI.** The runner enumerates resources globally ([outstanding.rs:74](/Users/admin/Developer/observe-lab/exact2/runner/src/runner/outstanding.rs:74)). D2 explicitly admits that an unrelated hidden-tab request delays a ready screen, and a loading page delays an independently usable dialog. A never-ending stream can prevent either time indefinitely. Labelling this `ledger` explains the approximation but does not make “nothing the subject shows is loading” accurate. **Fix:** the simpler default is no interactivity mark without a declaration, matching the RFC’s stated precedents. Keep settlement separately if a consumer needs it; avoid resource-to-view tracking.

5. **Major — D3: declaration bypass needs an explicit runtime-validity exception.** The exhaustive declared rule requires only prior showing, transition completion, and a true expression. Bypassing the ledger consequently also bypasses its poisoned-runtime protection. A retained `true` value cannot mean usable UI when every action fails. Existing navigation explicitly cancels for poison ([NavigationMarks.swift:354](/Users/admin/Developer/observe-lab/exact2/host/apple/Sources/ExactKit/NavigationMarks.swift:354)); web timing does likewise ([marks.js:139](/Users/admin/Developer/observe-lab/exact2/host/web-js/marks.js:139)). D2 mentions failure termination only for launch. **Fix:** specify terminal failure and poison handling for every subject, independent of whether readiness is declared.

6. **Major — D4: adding a ChromeIndex key misses legal Apple declarations.** ChromeIndex indexes native views; inline text, SVG elements, and native-control contents can have kernel identities without native views. Apple’s projection explicitly returns before creating such views ([paragraph.rs:231](/Users/admin/Developer/observe-lab/exact2/host/apple/src/paragraph.rs:231)). Paragraph runs are updated through a separate path ([InlineText.swift:148](/Users/admin/Developer/observe-lab/exact2/host/apple/Sources/ExactKit/InlineText.swift:148)). D3 nevertheless allows `interactive` on any element. **Fix:** track declarations before native projection and forward their timing metadata through existing batches. A ChromeIndex key alone is insufficient.

7. **Major — D4: membership alone does not define values or mount lifetimes.** The JS proposal stores declared elements but excludes the attribute from the DOM; it never specifies where the boolean lives or how changes update it. Literal bindings bypass dynamic emission ([emit.rs:1203](/Users/admin/Developer/observe-lab/exact2/host/web-js/src/emit.rs:1203)). Rust renewal can retain a node key while requiring completely fresh per-mount state ([txn.rs:80](/Users/admin/Developer/observe-lab/exact2/kernel/src/txn.rs:80)). **Fix:** specify registration for literals and reactive bindings, separate declaration presence from its boolean value, update values without remounting, and reset pending/first-passage state on renewal. Apply classification after component expansion ([lower/src/lib.rs:7](/Users/admin/Developer/observe-lab/exact2/contract/lower/src/lib.rs:7)).

8. **Major — D5: generic timing remains coupled to consumer installation, and the inventory is incomplete.** The web includes and installs timing only when a launch module supplies a web service ([build.mjs:340](/Users/admin/Developer/observe-lab/exact2/host/web-js/build.mjs:340)). Renaming events will still leave an app with declarations but no launch service without timing. Additional framework-owned Observe payloads include Linux’s `coldLaunchTime`/`timeToFirstRender`/`timeToInteractive` ([launch_marks.rs:498](/Users/admin/Developer/observe-lab/exact2/host/linux/src/launch_marks.rs:498)) and Apple’s constructor/delegate launch-time formula ([Launch.swift:564](/Users/admin/Developer/observe-lab/exact2/host/apple/Sources/ExactKit/Launch.swift:564)). **Fix:** make generic timing activation independent of Observe and explicitly move all consumer formulas/names into the module, retaining raw lifecycle facts.

9. **Minor — D1/D3/D5: subject identity is inconsistent.** D3’s example permits an unnamed `dialog open=(composing)`, but D5 requires a layer’s `id`. Parts outside any screen belong to launch, yet D5 requires their containing screen. Repeated mounts with the same authored ID also need distinct lifetimes. **Fix:** use existing runtime identity plus opening/mount lifetime for correlation; make authored IDs labels and permit a launch parent. This also removes the need for the part-ID compile error.

10. **Minor — D3: removing key UI is not answered by keeping its declaration mounted.** A screen expression waiting on an image remains false if that image is removed before its load event. Saying the screen’s declaration cannot disappear does not resolve that case. **Fix:** explicitly assign conditional membership to the author and show an expression such as `not showImage or imageReady`. Explain that child declarations measure independent parts and never aggregate automatically; remove the claimed equivalence with reporter-count approaches when reporters disappear.

11. **Minor — D4: the cited lookup is not O(depth).** [`inactive`](/Users/admin/Developer/observe-lab/exact2/runner/src/head.rs:86) calls `unselected` along the ancestor path; that invokes [`tab_panels`](/Users/admin/Developer/observe-lab/exact2/runner/src/head.rs:255), which traverses descendants. It also performs repeated path searches. **Fix:** specify a plain ancestor lookup over known subject boundaries, rather than reuse this visibility helper. Benchmark registration, renewal, and value updates as well as steady reads; the proposed read-only benchmark cannot establish the whole efficiency claim.

12. **Minor — D1/D2: frame-only definitions contradict the documented implementation.** D1 says both endpoints are presented frames, but D2 permits the instant work clears when nothing needs painting. Apple implements precisely that immediate branch ([Launch.swift:346](/Users/admin/Developer/observe-lab/exact2/host/apple/Sources/ExactKit/Launch.swift:346)). **Fix:** define interactivity as readiness of already-presented UI, waiting for presentation only when relevant UI changed, or consistently require another frame.
