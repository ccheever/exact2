## Overall assessment

This is a good RFC and a half-good plan. Building a coding harness in a day, with the transcript living in the terminal's own scrollback, is the result that matters. Charlie's reaction matches the mechanism: settled rows are printed once (`spike/host/terminal/src/term.rs:8-11`, `257-284`) and the live tail is the only thing redrawn. That is LLP 1101 D10, and it held.

The fourteen proposals are real findings, and the code matches most of them. The order does not. P1 is recommended as a host-only layout freeze whose "done when" is flat frame cost and flat memory (§3 P1). A freeze of that shape cannot do both. The data module copies every entry into the snapshot on each push (`spike/apps/harness/data/src/value.rs:111-126`), the view mounts every entry (`spike/apps/harness/terminal.contract:201-202`), and `compute_layout` runs on the whole root on every commit (`spike/host/terminal/src/host.rs:163-172`). Memory lives in those three places. Layout is only one of them.

Two things the plan ranks below P5 and P7 will change how the harness feels sooner, and they are smaller: diffing the live region (P3), and making the multiline prompt own its arrows. One thing the plan does not say is the actual cost model that makes P1 cheap: settle a finished line or block into scrollback immediately, and keep only the open tail in the tree.

I did not re-run the timings. The 6.9 MB binary, the 1–2 ms versus 600 ms–2.1 s layouts, the 70 MB and 166 MB residencies, the 4,133 scrollback rows, and the 43 KB plasma frame are claims about a run, not values in the tree. `replay.rs` is the tool those rows would have been counted with. It does not record 4,133.

## Strengths

- **§1 names the product in one rule, and the code is that rule.** A `role="log"` child's rows before the first `aria-busy` child are printed once, with trailing blanks stripped (`host.rs:265-294`, `grid.rs:202-214`). Busy entries are defined as still mutable, and the data module refuses to edit a settled one (`shapes.contract:37-38`, `state.rs:296-304`). Approvals, the key box, completions, and the prompt sit outside the log (`terminal.contract:199-262`), so they stay live. That split is why selection, copy, and tmux belong to the terminal. Inline mode turns mouse tracking off (`term.rs:31-32`). Full screen does not (`term.rs:28-30`).
- **The push path is the right stream.** Threads call `Native::changed("session")` (`state.rs:399-400`). The host wakes on a socket and re-reads the resource (`host.rs:127-140`, `term.rs:387-397`). Coalescing loses nothing when the snapshot is the whole text. The harness already proved that by not using ibex2 for tokens.
- **The seam and the vocabulary held.** `shapes.contract` is the contract the screen and the data crate share. The screen is ordinary tags: 380 lines, which is the "about 400" in the summary. The data crate has 40 `#[test]` functions, as the summary says. `preventDefault` does run before the host default (`keys.rs:137-149`). The compiler's `syntax-call-ambiguous` rule for host commands is already documented (`docs/contract-for-agents.md:356-358`).
- **The measurements are attached to the right question.** F2's warning, that a debug stall almost became a design conclusion against inline mode, is worth keeping even if the 300× factor is never reduced to one guilty check. F3's "a spinner rewrites the tail" is visible in the writer: every changed generation moves up, sends `\x1b[J`, and emits every live row (`term.rs:265-294`).
- **§4's grouping is sane**, and §5 asks the questions P1 actually depends on. Q1 and Q2 are the design. The rest of the plan should be rewritten around the answers, not left open while P1 is scheduled.

## Concerns

**High — P1(a) cannot meet its own done-when, and it is the recommended form.** Freezing printed children inside `compute_layout`, while the app still returns them, leaves three costs growing with history:

- `session()` builds a `Value` list of every entry on every announce (`value.rs:111-126`). A token push copies the whole transcript.
- The view mounts `EntryView` for every entry, and passes `tick` into all of them (`terminal.contract:87-88`, `201-202`). A busy turn bumps `tick` every 100 ms, so every historical row is a new prop even when its text does not use `tick`.
- The kernel still owns every node, and `after_commit` lays out every root (`host.rs:170-172`). `focusables`, `follow_ends`, and `images.load` walk that tree (`host.rs:373-400`, `487-509`, `image.rs:145-157`). `transcript()` is a fourth walk, but it runs from the inline writer (`term.rs:264`), not from `after_commit`. The "four walks in `after_commit`" sentence is a little stronger than the code.

Option (b) is the one that releases the tree. It needs an ack, or the host will drop a row it has not printed. Doing (a) first builds a Taffy special case you throw away once (b) exists. D7 does not require a host-side copy of scrollback: the terminal already has the bytes. Remembering a frozen height per retired child is a mirror. After SIGWINCH the emulator reflows those bytes and the host's `cursor_row` (`term.rs:248-268`) is no longer where the host thinks it is. The resize path lays out again and then issues cursor-up from that stale row (`term.rs:412-414`, then `265-269`). Q2 is that bug, not a preference.

What resolves it: make the done-when two numbers, tail layout time and retained kernel nodes, at `/stress 3000` during a 100 ms spinner. Meet it by retiring printed log children after the host has presented them, and by stopping the snapshot and the view from carrying those children. Answer Q2 in the same change: on resize, do not walk into scrollback, repaint only the live region from a cursor the host has just learned, and add a replay assertion that settled bytes are not emitted again.

**High — the prompt does not own vertical arrows, so §1's "keys as on the web" is only true of `preventDefault`.** `field_key` handles left, right, Home, End, and Enter (`keys.rs:72-133`). It does not handle ArrowUp or ArrowDown. Those fall through to `step_focus` (`keys.rs:181`). `onKey` claims them only for completion and for single-line history (`terminal.contract:140-156`). A draft that contains a newline does not claim ArrowUp, so the caret cannot move between lines, and focus leaves the field. Parent D6 says arrow keys belong to the focused field (`llp/1101-terminal-apps.rfc.md:223`). The sibling reviews already called the same binding on the todo fixture. This harness is the app where it is the whole interface. None of P1–P14 touches it.

What resolves it: in a textarea, ArrowUp and ArrowDown move the caret by line. ArrowUp on the first line recalls history. ArrowDown on the last line walks toward newer history. They do not call `step_focus`. Tab still moves focus. Add one headless drive: a two-line draft, ArrowUp, and the caret is on the first line with the same focus.

**Medium — P3 is right, and the sentence about `Grid::diff` will be implemented wrong if it is taken literally.** `diff` positions with absolute `CUP` (`grid.rs:248-271`). The inline live region is not at screen origin. An absolute cup paints the scrollback. The proposal does say "cursor moves relative to its top," so the intent is a relative diff. Say that `diff`'s byte sequences cannot be reused, and that a partial update must not send `\x1b[J`. Also say why it is urgent: the current full erase destroys a selection in the approval box or the prompt on every spinner tick. That is the user-visible bug. The 1.4 MB/s plasma figure is the case where a diff cannot help, because every cell changes.

What resolves it: one replay fixture. A one-cell spinner tick's bytes stay under a small bound and do not include the settled rows. A selection-sized assertion is "unchanged lines produce no writes."

**Medium — P4 adds a second streaming architecture beside the one that just worked.** ibex2 keeping the newest message is correct for snapshots and wrong for deltas. The harness already accumulates tokens below the seam and pushes a snapshot. A bounded lossless queue has to define what the UI does when the queue is full. That is a larger design than "medium," and no consumer in this RFC needs it.

What resolves it: delete the queue from this RFC. Add a pitfalls paragraph: token deltas are accumulated in the data module; the resource answers the text so far; coalescing is safe only for that shape. Keep a lossless mode on the ibex2 list, for a consumer that actually has unreproducible events.

**Medium — P6 proposes a view form the agent guide already lists, and misses the pyramid that is worse.** `docs/contract-for-agents.md:588` already names `else when` as a view form. `BlockView` is written as `else` plus a nested `when` (`terminal.contract:287-327`), which is a different tree. Actions are documented as nested too: "`else if c` is `else` around one nested `if`" (`contract-for-agents.md:347`). `onKey` is eight levels of that (`terminal.contract:131-179`). The guide's view `match` is exhaustive over options, not strings (`contract-for-agents.md:588`). String `match` is the feature that does not exist. `else when` may.

What resolves it: compile one flat `else when` chain before scheduling syntax work. If it compiles, rewrite `BlockView` and drop that half of P6. If the real gap is a nine-arm discriminant, add string `match` in views and in actions, with a default arm, and use it for `kind` and for `onKey`. Budget a semantics and difftest run. "Small–medium" is optimistic for a Contract form.

**Medium — P11's timer will eat real keystrokes and still miss the bug's shape.** The hazard is real. While an approval is up, the textarea is disabled (`terminal.contract:252`), disabled nodes leave `focusables` (`host.rs:384-386`), focus jumps to the first `autofocus` (`host.rs:183-188`), and `aria-keyshortcuts` on those buttons fire (`keys.rs:168-174`). The current buttons are `1`, `2`, and `3`/`Escape` (`terminal.contract:216-221`). The `y`/`n` story is no longer in the file. The loop applies every key from one read before waiting again (`term.rs:469-486`), so a key decoded in the same buffer as the key that opened the prompt is "typed ahead" with no clock involved. A 300 ms delay also drops a `1` the person pressed because they saw the prompt.

What resolves it: stamp each key with the generation read before it was dispatched. A shortcut arms only for keys read after the frame that showed its node. Do not sleep. Keep bare letters off transient prompts.

**Medium — P10 contradicts parent D5, and the spike does not negotiate.** D5 exposes color depth as the `color` media feature and explicitly leaves the image protocol off the fact table, because `img` falls back by itself (`llp/1101-terminal-apps.rfc.md:209-214`). There is no web name for "kitty versus half-blocks." The host does not query DA1 or the kitty protocol. `Protocol::detect` reads `EXACT_TERM_IMAGES`, `TMUX`, `TERM`, `KITTY_WINDOW_ID`, and `TERM_PROGRAM` (`image.rs:111-132`). tmux is always half-blocks, including when the outer terminal is kitty and passthrough is on. WezTerm is classified as iTerm (`image.rs:128`) while the kitty comment says WezTerm supports kitty (`image.rs:100`). Color is always `38;2` truecolor (`grid.rs:312-314`).

What resolves it: build D5's `color` fact and quantize to it. For images, expose one host source the harness can print, with a name that is not pretending to be a media feature. Override it with the existing `EXACT_TERM_IMAGES` switch. Do not block the harness on a capability probe.

**Medium — the harness is still written in the border unit LLP 1101.000 called a lie, and this plan never says so.** Every panel is `border="1px solid …"` (`terminal.contract:210`, `223`, `250`, `262`, `366`). The profile only checks attributes that lower to `AttrTarget::Styles` (`spike/contract/cli/src/terminal.rs:108-112`), so the shorthand skips the cell check. The kernel then turns any positive width into one cell under a process-wide flag (`cells.rs:34-39`, called from `border.rs:21`). P7 will lint `width: 100%` plus padding, which is already a candidate diagnostic in `docs/agent-pitfalls.md:81-89`. I did not find `width="100%"` on a bordered box in the current screen. The root is `width="100%"` with no border (`terminal.contract:199`). The banner trap is fixed in the source the RFC cites, or it was never this box.

What resolves it: point P7 at the existing pitfalls entry, add the new lint for a collapsing leading or trailing space, and let LLP 1101.000's border spelling land in this file. Do not invent a second box-model diagnostic.

**Low — P13 as written reopens D3.** The cell is two constants, 8 and 16 (`cells.rs:17-20`). The process-global state is a one-way `AtomicBool` that only changes border occupation (`cells.rs:24-28`). The harness gained nothing from that bool being global. Moving the constant into the kernel instance does not change layout, and a variable cell would break D3's "bake and runtime resolve the same way with no host input."

What resolves it: move the flag onto the kernel instance, default off, set by the terminal host. Leave `COLUMN` and `ROW` fixed.

**Low — `close` already means quit.** `take_commands` maps the command name `close` to `self.quit = true` (`host.rs:174-177`). The model row also uses `command="close"` as a dialog invoker (`terminal.contract:266`), which `invoke` handles from the attribute (`host.rs:527-556`) and does not send through that list. P5's `close(id)`, "dispatched like `close()`," collides with the quit command unless arguments distinguish them.

What resolves it: specify `showModal(id)`, `show(id)`, and `close(id)` as commands whose first argument is an id, and state that a no-argument `close()` remains quit. One terminal test and one Mac test open a dialog from an action and Escape closes it.

**Low — F12 and P12 match the code, and the cost is understated.** Paint always draws half-blocks (`paint.rs:464-471`). Protocol bytes are written only while printing settled rows (`term.rs:313-341`), using kitty `a=T` with no image id (`image.rs:175-191`). `\x1b[J` does not delete a kitty image. A live image needs an id, a delete, and a place on every move, including when settled rows push the live region down. iTerm2 staying on half-blocks is the right call.

3. **Reshape P1 around retirement, and settle finished blocks while the reply is still streaming.** The app already has the invariant that a non-busy entry never changes. ## Novel ideas

**Settle lines, not entries.** The settled unit in the RFC is a transcript child. That keeps a 200-line in-progress answer in the live region, where it is clipped to one screen and relaid out on every token. Treat a finished markdown block as the log child that gets printed, and keep a one-block busy tail. The harness can do this in its view model now, because `busy_entry` already guarantees a settled entry is immutable. Inline mode then matches a typewriter: what you have read is scrollback, and the kernel's tree is about a screen tall. P1, the scroll-during-stream problem, and most of the RSS growth fall out of that one split. A host-side mirror of those rows would fight D7. The terminal is the mirror.

**Spell the skip with `content-visibility`, if a kernel skip is still needed after retirement.** A printed log child with a frozen block-size is `content-visibility: hidden` plus a last-known size. That is a CSS name the web chat can use later. A terminal-only "do not lay this out" switch is a second layout policy. Retirement should make it unnecessary. If a profile says otherwise, the CSS name is the one to add.

**Paint settled prose with the markdown reader that already exists.** The guide says a `text` with `markup="markdown"` is the reader, and it is one node (`docs/contract-for-agents.md:816-817`). The terminal painter never looks at `markup`. `BlockView` builds a node per run per block (`terminal.contract:282-327`), which is why `/stress` hurts. One cell-level markdown paint path serves this harness and the LLP reader, the other consumer parent §9 already named. Keep the run tree for syntax-colored tool output and the open tail. Settled assistant prose does not need it.

**Ask the terminal where the cursor is after resize.** `CSI 6 n` is a device report, which this host's input parser is already shaped to receive. One report after SIGWINCH re-anchors the live region without reprinting history and without trusting `cursor_row` across an emulator reflow. That is the whole of Q2.

## Open questions

- **What is the settled unit?** An entry, a markdown block, or a line? This decides whether a long stream is readable, and it decides how big P1 is. I would settle finished blocks.
- **Who drops the bytes?** Does `session()` stop returning retired entries, or does the runner drop presented log children while the resource still returns them? The view still evaluates `each` over whatever the resource returns. Flat cost requires the view input to shrink. The model context (`State.history`, `state.rs:252`) stays either way.
- **After resize, what is the contract with the emulator?** Repaint the live region only, and let Ghostty, tmux, and Terminal.app reflow scrollback differently. Worth a written "we do not re-lay-out history" line, plus one recording per terminal that matters.
- **Does a fullscreen app with a `role="log"` stay fullscreen?** Yes. Inferring inline from the role will surprise the next todo-like app. The entry or the flag chooses. Parent D10's default remains full screen. This harness passes inline.
- **Q4 is already answered.** `rules/RULES.md` says the boot path compiles nothing. A dev binary may compile the entry. A binary someone runs compiles a baked plan. The 1 MB compiler in the shipping link is a spike convenience.
- **Does `else when` compile today?** If yes, P6 shrinks to a rewrite and, separately, a decision on string `match`.
