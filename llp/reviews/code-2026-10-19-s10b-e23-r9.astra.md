**One blocker remains.** The source-parser boundary and remote Astryx restriction hold by inspection, but a paired client can still exhaust the parent through subscription snapshots.

1. **blocker — Initial subscriptions and long polls bypass the outbound limit.** [scripts/tamber-server.mjs:533](/tmp/rv-e23-9/scripts/tamber-server.mjs:533), [570](/tmp/rv-e23-9/scripts/tamber-server.mjs:570)

   The new 8 MiB check applies only to subsequent `send()` calls. Both endpoints first serialize and write the entire held-proposal list. A propose client can retain 64 proposals with roughly 900 KiB reviews, then open slow-reading subscriptions: approximately 56 MiB per connection, multiplied across the remote listener’s 64 connections. No further event is needed, and the connection deadline is suspended while answering.

   **Fix:** bound all outbound paths, including initial snapshots and long-poll responses. Paginate or stream held proposals with backpressure before constructing a large aggregate string; enforce aggregate queued-byte limits too. Test subscribers that stop reading.

2. **should-fix — Admission ends before the import finishes; shutdown does not cancel queued imports.** [scripts/tamber-isolate.mjs:50](/tmp/rv-e23-9/scripts/tamber-isolate.mjs:50), [78](/tmp/rv-e23-9/scripts/tamber-isolate.mjs:78), [scripts/tamber-server.mjs:1123](/tmp/rv-e23-9/scripts/tamber-server.mjs:1123)

   The per-client count is released when planning ends, while `importHeld()` can still be awaiting `hold()`. Thus “two outstanding imports” does not cover whole requests. `stopImports()` kills only the current child: queued callbacks, or a design read already underway, can spawn another planner after `close()`. Disconnect and revocation likewise leave admitted work running. The global kill helper also lacks an exit-state check while `running` remains populated until `close`.

   **Fix:** associate admission with the whole import and its owning wire; cancel queued work on disconnect, revocation and shutdown, prevent subsequent spawning, and await active-child cleanup. Check recorded exit state before signaling.

3. **should-fix — The design-read timeout abandons unfinished I/O, and reads can be truncated.** [scripts/tamber-isolate.mjs:72](/tmp/rv-e23-9/scripts/tamber-isolate.mjs:72), [94](/tmp/rv-e23-9/scripts/tamber-isolate.mjs:94)

   The outer race now answers within two seconds, but does not cancel `designText()`. Releasing admission lets repeated attempts accumulate unfinished filesystem operations and cleanup. The single `file.read()` still treats a short read as EOF; a valid partial design can therefore be planned with the wrong digest, repeatedly rejecting a legitimate import.

   **Fix:** retain a separate bounded reader permit until I/O cleanup completes, while answering the client on time. Read until EOF or `max + 1`, and clear both timeout handles.

4. **should-fix — The design-identity answer does not resolve legitimate manifest changes.** [scripts/tamber-server.mjs:906](/tmp/rv-e23-9/scripts/tamber-server.mjs:906), [1111](/tmp/rv-e23-9/scripts/tamber-server.mjs:1111), [1484](/tmp/rv-e23-9/scripts/tamber-server.mjs:1484)

   After `app.json` changes from design A to B, the child plans B, while file-less operations still target the Rust serve’s startup design A. Holding computes its touched files and digest map using B. This can produce a proposal against A that cannot subsequently be accepted. The CLI now carries a digest, but rediscovers its path after planning.

   The commit’s “requires filesystem changes” answer limits the remote threat; it does not fix this ordinary development case.

   **Fix:** obtain the serve’s validated design identity and carry that exact path through planning, operations, marks and guards. Restart or explicitly reject a changed manifest identity.

5. **should-fix — Proposal and history limits count characters and omit part of the proposal.** [scripts/tamber-server.mjs:175](/tmp/rv-e23-9/scripts/tamber-server.mjs:175), [945](/tmp/rv-e23-9/scripts/tamber-server.mjs:945)

   `.length` measures UTF-16 code units, not bytes. Unicode diffs can exceed the advertised byte limits. The proposal check also excludes `ops`, `changed` and the remaining envelope, so it does not implement round 8’s complete-proposal cap.

   **Fix:** cap `Buffer.byteLength()` of the complete serialized proposal before retention or broadcasting, and use actual serialized bytes for event accounting.

6. **should-fix — Manifest reads still have an unbounded synchronous path.** [scripts/tamber-server.mjs:126](/tmp/rv-e23-9/scripts/tamber-server.mjs:126), [1037](/tmp/rv-e23-9/scripts/tamber-server.mjs:1037)

   `designPath()` rejects a stable FIFO or oversized manifest, but its separate `statSync`/`readFileSync` operations provide neither a descriptor-bound size limit nor a deadline. More directly, `designRel()`, reached by remotely available history/revert operations, retains the original unlimited synchronous read. A problematic local filesystem can still freeze the parent and its watchdog.

   **Fix:** use one bounded asynchronous manifest reader, validating and reading the same descriptor, and reuse the validated design identity.

7. **should-fix — Local source acquisition remains outside the promised bounds.** [scripts/tamber-isolate.mjs:168](/tmp/rv-e23-9/scripts/tamber-isolate.mjs:168)

   Astryx now correctly uses the watched planner. However, `sourcesOf()` still performs synchronous traversal and reads before that planner starts. Its byte count uses earlier metadata, directory traversal has no work/depth limit, and there is no acquisition deadline. Stalled regular-file I/O can still hang a legitimate local import.

   **Fix:** acquire sources inside the watched child, or use bounded descriptor reads that count actual bytes and cover traversal with an overall deadline.

8. **nit — Kept baselines remain uncapped and accept a symlink directory.** [contract/cli/src/tamber_export.rs:160](/tmp/rv-e23-9/contract/cli/src/tamber_export.rs:160)

   Grok G remains unchanged, though the watched child contains its cost. **Fix:** reject a symlink baseline directory and limit entries and total bytes read.
