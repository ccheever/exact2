## Findings

**should-fix: Public-host origins accept the cleartext origin, and a `:443` allow-host entry does not accept the browser's https origin — `scripts/tamber-remote.mjs:192`**

`remoteHandler` parses `Host` with the door scheme (`http`) and then allows that scheme or `https` when `publicName` says so:

```192:192:scripts/tamber-remote.mjs
      try { const o = new URL(req.headers.origin); same = (o.protocol === `${scheme}:` || (o.protocol === 'https:' && publicName(at.name))) && o.host === at.host; } catch { /* refused */ }
```

A page at `http://tamber.example.com` is a different origin from `https://tamber.example.com`, and this admits it. A different hostname still gets 403 (the `evil.example.com` case in the new test). `--allow-host name:443` does not admit the `Host: name` a browser sends for https, and an https origin omits `:443` while the http parse of `Host: name:443` keeps it, so `o.host === at.host` fails. That entry therefore accepts `http://name:443` and rejects `https://name`.

Fix: if the hostname is a public allow-host entry, require `https:` and compare with https default-port rules (port 443 omitted on both sides). Keep the door's `http` scheme for loopback names only. Ignore a `:port` suffix only for that https comparison; a `name:port` entry should admit that port alone. In `publicName` (`scripts/tamber-remote.mjs:300`), do not treat `localhost`, `127.0.0.1`, or `::1` as public, so `--allow-host 127.0.0.1` cannot turn on `https://127.0.0.1`.

Those requests are answered here, before the gate can return 421.

A direct browser fetch of this server still sends this port, so the Figma case is fine, and the local token is still refused (`access.remote` forces `local: false` in `handle`). ## The six checks

1. **Local token.** A null origin cannot read it or use it. `pluginOnLoopback` only runs for `Origin` exactly `null`, a peer of `127.0.0.1`, `::1`, or `::ffff:127.0.0.1`, and a `Host` whose WHATWG hostname is `localhost`, `127.0.0.1`, or `::1`, and only for the four wire paths. `/__tamber/token` is not one of them, gets no `Access-Control-Allow-Origin`, and falls through to the gate. `::ffff:127.0.0.1` is IPv4 loopback on a dual-stack socket; any other mapped address is absent from the list. Alternate spellings that canonicalize to `127.0.0.1` (`127.1`, a single decimal) are still loopback. A rebound DNS name does not canonicalize and is 421, which the new test covers. `data:`, `file://`, and a sandboxed iframe all show up as `Origin: null` and get the same remote principal: `handle` forces `local: false` whenever `access.remote` is set (`scripts/tamber-server.mjs:486`), and `principalOf` accepts the local token only when `access.local === true`. An extension origin such as `chrome-extension://…` is not `null`, so it stays on the gate.

2. **CORS.** The headers are the opaque origin, not a reflection and not `*`: `Access-Control-Allow-Origin: null`, `Vary: Origin`, no `Access-Control-Allow-Credentials`. The preflight is 204 with `POST`, `content-type, x-exact-tamber-token`, and `max-age` 600. Anything outside `WIRE` skips those headers. On the tunnel, a null origin on another path is 403 with no CORS. On the main port, that request falls through to the gate. A preflight for a path not in `WIRE` is not answered here.

3. **`--allow-host`.** Another hostname on the same tunnel is 404, and `https://evil.example.com` on the allowed host is 403. `https://127.0.0.1` is 403 for a normal public name. The holes are the cleartext origin and the `:443` comparison in finding 1, and a loopback name is https-allowed only if it is itself passed to `--allow-host`.

4. **Paired token from a sandboxed page.** Same table as any other remote client. `access.plugin` is never read. `read` can hello, describe, history, export, subscribe, and events. `propose` can also hold, import, revert, and drop its own. `pair-code`, `clients`, `revoke`, and every `write` method stay on the local token or a write token via `allows()`. The pair limiter keys on the socket peer, so every IPv4 loopback caller shares `127.0.0.1` (the user's own tool, the tunnel, and every null-origin page). `::1` is a second bucket. Five attempts a minute, and five failures burn every live code. Guessing a 50-bit code is not practical. The lumping is acceptable. With the flag on, any site's sandboxed iframe can spend that bucket; the lead put `/__tamber/pair` on this path, and the tunnel already collapsed every far-side client into `127.0.0.1`.

5. **Flag off.** The main port matches the previous behavior. The doors match for well-formed requests when `--allow-host` is absent. The 404-versus-403 difference is the nit above. `bun test scripts/tamber-remote.test.mjs`: 23 pass, 0 fail.
