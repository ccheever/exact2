## Review (verbatim)

**Build with named changes. Do not implement r1 unchanged.** The shared Rust scene and native raster fallback are sound directions. The blocking problems are reference semantics, loss of path information, text measurement, unsafe compositor lowering, filter processing, and the proposed universal SMIL-to-CSS translation.

This was a static audit confined to the checkout. I made no edits and ran no interpreters, builds, tests, browsers, or image tools. RFC line references below refer to [Draft r1](/Users/ccheever/projects/exact2-wt-svg2-review/llp/1055.000-completing-svg.rfc.md:1). Spec references identify the relevant normative sections; I did not fetch external specifications or independently reproduce current Chrome behavior.

**D1 — change: keep the shared resolver, define its intermediate stages.**  
*Lines 45–57.*

Sharing inheritance, references, geometry, and paint resolution removes real duplication: both [Apple’s walk](/Users/ccheever/projects/exact2-wt-svg2-review/host/apple/src/svg.rs:238) and [Linux’s walk](/Users/ccheever/projects/exact2-wt-svg2-review/host/linux/src/paint/svg.rs:83) independently compute paint and geometry.

However, “everything resolved” cannot be produced by a simple top-down inheritance walk:

- Group bounding boxes require descendant geometry.
- `transform-box: fill-box` and `stroke-box` require those boxes.
- Object-bounding-box paints, clips, masks, and filters depend on geometry.
- Text geometry requires host shaping.
- Animated geometry changes these dependencies.

Define explicit stages: computed style and instance construction; geometry and text measurement; bounding boxes; used transforms and resource coordinate systems; effect/compositing assembly. Cache those results with dependencies.

Also distinguish **computed values from used values**. An inherited font-relative length may already have become an absolute computed length; a percentage can retain its percentage until used on the descendant. Resolving every inherited length into pixels at the ancestor would be wrong.

Scene items need stable identities that distinguish multiple instances of the same authored node. They also need their authored event target, resource dependencies, and animation provenance. An affine and resolved color alone lose information needed for hit testing and later animation.

Relevant specification: SVG 2, [coordinate systems, units, and bounding boxes](https://www.w3.org/TR/SVG2/coords.html), and [use-element shadow trees](https://www.w3.org/TR/SVG2/struct.html#UseElement).

**D2 — change: islands are viable, but the host capability claims are too broad.**  
*Lines 59–71, 253–259.*

The shared raster crate is a reasonable way to implement effects consistently. Several mappings need additional machinery:

| Host | Concrete limit and required change |
|---|---|
| Apple | A `CGContext`-drawn gradient in a layer has raster backing. An animated shape mask does not make that backing remain sharp at arbitrary compositor zoom. Define redraw resolution and invalidation. |
| Apple | `CAShapeLayer` exposes solid fill and stroke colors. Gradient fill and gradient stroke need separate painted layers and masks, ordered according to `paint-order`, with element opacity applied to the combined result. |
| Apple | A layer has one `mask`. Independent clipping and masking, possibly around a filtered result, require correctly ordered wrapper layers or a combined raster operation. |
| Apple | `CTFontCreatePathForGlyph` cannot represent every rendered glyph, notably bitmap/color glyph content. Text needs a non-outline fallback. |
| Linux GPU | Vello’s clipping stack intersects clips. It does not by itself implement the union of differently ruled SVG clip children. Its drawing primitives also do not supply an SVG filter graph or SVG resource semantics. |
| Linux CPU | A tiny-skia mask is coverage data; SVG mask rendering, luminance conversion, coordinate systems, and regions remain exact2’s responsibility. The claimed general two-circle radial mapping, particularly nonzero `fr`, needs a demonstrated adapter for the pinned version. |

The checkout pins tiny-skia 0.12 and vello 0.10, but its SVG adapters currently use solid brushes. They provide no local evidence for the draft’s broader gradient promises.

“Re-rendered only when something inside it changes” is incorrect. An island can depend on an external resource, inherited style, target bbox, viewport, transform, device scale, font availability, image decoding, or backdrop.

Finally, specify the rendering sequence. Filtering, clipping, masking, group opacity, and blending are distinct operations with observable ordering. Follow [SVG’s rendering model](https://www.w3.org/TR/SVG2/render.html), [CSS Masking’s compositing model](https://www.w3.org/TR/css-masking-1/), and [Filter Effects’ rendering model](https://www.w3.org/TR/filter-effects-1/).

**D3 — reject the default lookup policy; change the reference machinery.**  
*Lines 73–80.*

An ordinary `<svg>` does **not** create an ID scope. “Own SVG first” is a product deviation, not SVG resolution, and duplicate IDs do not establish that Chrome is rendering incorrectly.

Prefer standard document/tree-scoped resolution. If Contract needs reusable local identifiers, introduce explicit component-level identifier hygiene that produces unique definitions and matching references. The proposed `x<svg-id>-<id>` scheme still collides when two component instances containing the same authored ID share one outer SVG.

Other corrections:

- **Missing masks:** a failed mask reference is not generally equivalent to `mask: none`. An invalid mask image contributes transparent black and can hide the element. Separate mask failure from invalid clip/filter behavior. See CSS Masking, [the `mask-image` property](https://www.w3.org/TR/css-masking-1/#the-mask-image).
- **`href` and `xlink:href`:** accept the legacy attribute, but give `href` precedence when both occur.
- **Grammar:** URL values include quoting, escaping, and URL resolution. Define support for external resources explicitly. Pattern template `href` is missing from the attribute list.
- **Cycles:** use resource-specific rules. A cyclic gradient template reference must not automatically erase usable local stops and attributes.
- **Index invalidation:** reparenting and reordering can change resolution without changing an ID. Inserting a previously missing target must invalidate unresolved references. Editing an unnamed descendant can change a named resource.
- **Compile-time refusal:** “ID not declared in the same file” rejects valid cross-file sprites and composed components. It also conflicts with D8’s document-wide sprite use.
- **Rewriting:** accessibility IDREF lists and fragment links must remain coherent, not merely paint URLs.

Relevant specification: SVG 2, [linking and URL references](https://www.w3.org/TR/SVG2/linking.html), and its [use-element shadow-tree rules](https://www.w3.org/TR/SVG2/struct.html#UseElement).

**D4 — change: several defaults and sizing statements need correction.**  
*Lines 82–89.*

The geometry-row migration is right, with these corrections:

- **`x` and `y` initially equal `0`.** `rx` and `ry` initially equal `auto`; only the radii have the paired fallback behavior. The parenthetical at line 84 wrongly groups all four.
- Unit resolution is property-specific. Ordinary SVG geometry percentages use the viewport; object-bounding-box resource coordinates use a different system; `textPath` percentages use path length.
- Preserve authored length/percentage structure where later viewport or font changes affect the result. The existing `f32` codecs for radii, stroke width, and dash offset cannot represent the proposed grammar.
- Include the absolute unit `q`. Define CSS math expressions and CSS-wide keywords. Refusing `vw`/`vh` for lack of a consumer is particularly weak when viewport dimensions are already available.
- **Intrinsic ratio is not always the viewBox ratio.** Absolute intrinsic width and height take precedence under SVG’s intrinsic-sizing algorithm.
- **The 300×150 default object size still participates in ratio-only sizing.** It is not used exclusively when both size and ratio are absent. Simply setting Taffy’s `aspect_ratio` does not replace the complete sizing algorithm.

Relevant specification: SVG 2 [geometry properties](https://www.w3.org/TR/SVG2/geometry.html), [intrinsic sizing](https://www.w3.org/TR/SVG2/coords.html#IntrinsicSizing), and CSS Images 3 [default sizing](https://www.w3.org/TR/css-images-3/#default-sizing).

Two first-slice issues also need explicit completion work:

1. [`dash_scale`](/Users/ccheever/projects/exact2-wt-svg2-review/kernel/src/svg/shape.rs:114) ignores `pathLength="0"`. SVG defines zero specially rather than treating it as an absent attribute; negative values are errors. See SVG 2, [the `pathLength` attribute](https://www.w3.org/TR/SVG2/paths.html#PathLengthAttribute).
2. [`view_box`](/Users/ccheever/projects/exact2-wt-svg2-review/kernel/src/svg/shape.rs:138) uses the points parser, which drops an odd trailing coordinate. A viewBox requires exactly four numbers; it cannot inherit points-list error recovery.

**D5 — change: the composition equation is useful, but the grammars and Apple lowering are incomplete.**  
*Lines 91–100.*

The stated order for individual transforms followed by `transform` is correct for the admitted 2D case before motion-path effects.

Required changes:

- Keep SVG transform-attribute parsing separate from CSS transform-property parsing. Unitless SVG angles and `rotate(a cx cy)` are not general CSS transform syntax. Convert the attribute into an equivalent representation while preserving the presentation-attribute cascade.
- The SVG origin exception is not universal. SVG elements without CSS layout boxes generally use `0 0`; an outer SVG with a CSS layout box follows the applicable CSS-box rules.
- Support nonuniform individual `scale`, percentage translations, and the stated reference boxes. The current schema has scalar `scale` and numeric two-component `translate`.
- Declare the 3D boundary explicitly. A single affine cannot represent the full CSS transform vocabulary.
- Define singular-transform behavior for painting and hit testing.
- Add CSS **`transform` animation**, which D15 currently omits.

The Apple layer pair can work, but only with a precise bounds, position, anchor, and origin convention. The required matrix is:

`T(origin) · T · R · S · M · T(-origin)`

An outer layer with an origin-adjusted transform and an inner layer carrying an unexplained `M` does not establish that equality. `transform.scale` is also uniform; radians, independent axis scales, overlapping animations, and changing reference boxes need explicit handling. Use ordered layer transforms or sampled fallback where equivalence is unproven.

For non-scaling stroke, preserve separate fill/paint and stroke coordinate systems. Baking the path into host coordinates must not accidentally move a user-space gradient, alter markers, or subsequently scale the supposedly unscaled stroke through a compositor transform.

Relevant specification: CSS Transforms 1, [SVG transform attributes](https://www.w3.org/TR/css-transforms-1/#svg-transform), and CSS Transforms 2, [individual transform properties](https://www.w3.org/TR/css-transforms-2/#individual-transforms).

**D6 — change: distinguish color interpolation, paint switching, and transition admission.**  
*Lines 102–111.*

Premultiplied sRGB is a reasonable explicitly bounded implementation for the legacy-color cases the RFC intends to match. It is not a complete color model for every CSS Color 4 syntax or SVG color-interpolation context.

Specify:

- Supported color syntaxes and their interpolation rules.
- SVG `color-interpolation`, separately from `color-interpolation-filters`.
- `currentColor` dependencies, including inherited animated color and resource-tree color.
- How native color values retain the information needed for those rules.

The strongest concrete contradiction is at line 109: a non-interpolable server/color pair switches discretely; animating a gradient layer’s opacity creates a crossfade. Those are different pictures. Also distinguish CSS animations from transitions: an ordinary transition does not automatically run for a discrete pair under the default transition behavior.

Core Animation accepting two `CGColor`s does not prove it matches the required color-space and alpha interpolation. Make that a lowering eligibility condition, backed by presentation-value fixtures.

The statement that label rerasterization is “well under a millisecond” is an unmeasured estimate in this audit. Measure it before making it a cost premise.

Relevant specification: CSS Color 4, [color interpolation](https://www.w3.org/TR/css-color-4/#interpolation); Web Animations, [animation types](https://www.w3.org/TR/web-animations-1/#animation-types); CSS Transitions 2, [transition behavior](https://www.w3.org/TR/css-transitions-2/#transition-behavior-property).

**D7 — change: retain the paint-server design, expand its semantics and fallback plan.**  
*Lines 113–119.*

Correct choices include non-inherited stop properties, monotonic stop offsets, object bounding boxes excluding stroke, and separate gradient transforms.

Missing requirements include:

- Coordinate defaults; `fx`/`fy` fallback to `cx`/`cy`; `fr`; and focal-circle constraints.
- Zero-stop, one-stop, coincident-stop, zero-vector, and zero-radius cases. A zero-length linear gradient uses its last stop; it is not a missing paint server.
- Template inheritance before defaults, and replacement of inherited stop children by local stop children.
- Stop style and `currentColor` resolution in the resource tree.
- Exact geometric bounds, including curve extrema, transformed child bounds, and text-specific bounds.
- Separate handling of a degenerate object bbox and an invalid URL reference.

**Repeating stops across an extent is not a general proof of exact radial repeat/reflect.** With moving centers and nonzero focal radius, extending the gradient parameter changes the circle family as well as stop positions. The Core Graphics adapter needs a mathematical construction or fallback for those cases.

SVG gradient interpolation also needs its own specified alpha/color behavior; do not silently reuse whichever premultiplication mode the color-animation implementation or backend gradient brush defaults to.

For patterns, specify `patternUnits`, `patternContentUnits`, their defaults, the override caused by `viewBox`, template inheritance, tile overflow, and transformed sampling. “Device scale times the transform’s scale” is insufficient for a general affine transform.

Relevant specification: SVG 2, [gradients and patterns](https://www.w3.org/TR/SVG2/pservers.html), and [bounding boxes](https://www.w3.org/TR/SVG2/coords.html#BoundingBoxes).

**D8 — change: instance scenes are appropriate, but animation and size semantics need precision.**  
*Lines 121–131.*

Inheritance from the `use` host, while preserving the referenced element’s own declarations, is the right direction.

Change these parts:

- Specify the `auto` and override rules for `use` width/height instead of blanket replacement by 100%.
- Preserve each shadow instance’s identity, inherited context, and reference scope.
- Distinguish CSS animation instances from SVG/SMIL animation behavior. “Every target animation gets the instance’s own start” is not a universal SVG rule.
- Define event handling inside the instance and retargeting across its boundary. Returning the `use` target to outside listeners does not fully describe event propagation.
- Keep referenced definitions available even though `defs` and `symbol` are not directly painted.

There is an implementation gap: the motion engine currently keys animations by an authored node identifier. Scene-only instances therefore need an explicit animation-context mechanism; the present architecture does not automatically provide independent instance effects.

Relevant specification: SVG 2 §5.6, [the `use` element](https://www.w3.org/TR/SVG2/struct.html#UseElement), especially shadow trees, style inheritance, and animation.

**D9 — change: preserve authored vertices before implementing markers.**  
*Line 135.*

The proposed source of marker vertices is insufficient. The current [path representation](/Users/ccheever/projects/exact2-wt-svg2-review/kernel/src/svg/path.rs:10) contains only moves, lines, cubics, and closes; [arc conversion](/Users/ccheever/projects/exact2-wt-svg2-review/kernel/src/svg/path.rs:305) can turn one authored arc into several cubics.

Those internal subdivision points are **not marker vertices**. An arc must not acquire additional `marker-mid` instances merely because the renderer approximated it.

Retain authored segment boundaries and tangent information. Implement the specified rules for:

- Zero-length segments and searching for usable incoming/outgoing directions.
- Opposing directions and angle bisectors.
- Multiple subpaths.
- Closed paths where start and end markers can coincide.
- Start/end markers at the path’s first/last vertices, rather than indiscriminately at every subpath boundary.

`context-fill` and `context-stroke` also need the referencing paint’s coordinate context, not merely a copied color or resource ID.

Relevant specification: SVG 2, [markers and marker orientation](https://www.w3.org/TR/SVG2/painting.html#MarkerElement).

**D10 — change: correct basic-shape reference boxes and mask semantics.**  
*Lines 137–147.*

Three significant corrections:

1. **A CSS basic-shape clip does not take its reference box from `transform-box`.** `clip-path` has its own geometry-box grammar and defaults, including mappings for SVG elements without CSS layout boxes.
2. **Clip children union before the result intersects the surrounding clip.** Successive backend clip pushes intersect; concatenating arbitrary child paths can also produce incorrect winding interactions. Implement an actual union representation or coverage mask. The current [GPU clip methods](/Users/ccheever/projects/exact2-wt-svg2-review/host/linux/src/gpu.rs:500) do not provide this abstraction.
3. **CSS mask longhands apply to SVG elements.** Calling them “HTML-box features” is factually wrong. Defer them explicitly if necessary.

The listed luminance coefficients are not the main problem. In a fixed color space, a weighted sum of premultiplied RGB is algebraically equivalent to luminance of straight RGB multiplied by alpha. The implementation must additionally honor the applicable `color-interpolation` behavior, perform nonlinear color conversion correctly, and avoid multiplying alpha twice.

Specify `maskContentUnits`, invalid-mask behavior, mask-region clipping, and how clips and masks combine without overwriting Apple’s single layer-mask slot.

Relevant specification: CSS Masking 1, [clipping paths](https://www.w3.org/TR/css-masking-1/#clipping-paths), [mask processing](https://www.w3.org/TR/css-masking-1/#mask-processing), and [SVG mask sources](https://www.w3.org/TR/css-masking-1/#svg-masks).

**D11 — change substantially: shaping and geometry need a richer interface.**  
*Lines 149–160.*

The existing [text measurement interface](/Users/ccheever/projects/exact2-wt-svg2-review/kernel/src/text.rs:229) returns width, height, and one baseline. It cannot return the glyph positions, character-cluster mapping, glyph-cell bounds, outlines, or baseline information this design requires.

A chunk’s advance alone cannot support per-character positioning, text-path placement, accurate text hit regions, or all text bounding-box calculations. Nor can a scene be fully resolved before Swift shapes its text and subsequently reports the result.

Define a synchronous shaping/geometry interface or an explicit staged resolution process. Its output must serve both vector painting and Rust islands containing text.

Other corrections:

- **`baseline-shift` does not use the `dominant-baseline` keyword set.** It uses shifts such as lengths/percentages and `sub`/`super`; specify the supported legacy syntax separately.
- `alignment-baseline` has its own grammar.
- Addressable characters are not interchangeable with glyphs. Handle whitespace processing, ligatures, combining characters, bidi, and nested positioning lists.
- `rotate` list repetition differs from position-list exhaustion.
- A text chunk may contain multiple fonts and paints; one undifferentiated path per chunk loses those boundaries.
- Provide a fallback for bitmap/color glyphs.
- `textPath` must account for `pathLength`, referenced coordinate systems, shaping, and the text-layout algorithm’s placement rules.

There is also a Contract ambiguity to resolve: text’s `x`, `y`, and `rotate` attributes are positioning lists, while identically named CSS properties have different roles.

Relevant specification: SVG 2, [text layout and positioning](https://www.w3.org/TR/SVG2/text.html), and CSS Inline Layout, [baseline alignment](https://www.w3.org/TR/css-inline-3/#baseline-alignment).

**D12 — change: image reuse is feasible; `contentsGravity` is insufficient.**  
*Lines 162–164.*

Reusing decoding and caching is sensible. Apple’s `contentsGravity` alone does not express all combinations of the nine SVG alignments with `meet`, `slice`, and `none`. Resolve the destination rectangle and clip explicitly.

Specify intrinsic sizing, `auto`, image orientation/rendering policy, and whether animated raster images remain animated through islands.

Deferring external SVG images can be a staging decision, but it leaves a significant part of ordinary SVG asset usage unsupported. The refusal should be coordinated with external `use` and other external SVG references, which also need document loading and resolution.

Relevant specification: SVG 2, [the `image` element](https://www.w3.org/TR/SVG2/embedded.html#ImageElement), and [preserveAspectRatio](https://www.w3.org/TR/SVG2/coords.html#PreserveAspectRatioAttribute).

**D13 — reject the permanent refusal as justified here.**  
*Lines 166–168.*

“No chart, icon or illustration needs it” is false. HTML labels in diagrams and charts are a common `foreignObject` use.

The claimed architectural necessity is also too strong. An embedded box subtree can have a native container under the SVG presentation; every SVG ancestor need not become a native view. Focus, transformed controls, clipping, and filters remain difficult, but that is a design problem requiring an explicit supported boundary.

Deferring `foreignObject` is reasonable. Permanently excluding it contradicts the binding admission of complete browser SVG unless the product scope is explicitly narrowed. Positioning an unrelated box over an SVG is not generally equivalent under nested transforms, clipping, scrolling, or accessibility.

Relevant specification: SVG 2, [the `foreignObject` element](https://www.w3.org/TR/SVG2/embedded.html#ForeignObjectElement).

**D14 — change substantially: filters need a typed graph with per-operation processing rules.**  
*Lines 170–182.*

A shared native filter implementation is viable. The described processing model is not sufficient.

- **Color conversion once per filter is wrong.** `color-interpolation-filters` can vary by primitive. Convert inputs as required at graph edges.
- **CSS filter functions operate in sRGB.** They cannot simply enter a chain using the SVG filter default of linearRGB.
- A universal premultiplied-buffer formulation is insufficient. Component transfer and color-matrix operations require their specified treatment of straight color and alpha.
- Define `filterUnits` and `primitiveUnits` defaults, input defaults, primitive-specific subregion calculation, named-result resolution, and invalid-input behavior.
- Boundaries and sampling matter: convolution edges, blur support, primitive clipping, displacement sampling, and pixel/user-coordinate transforms require explicit algorithms.
- `FillPaint` and `StrokePaint` are missing from the input inventory. Account explicitly for background-related legacy inputs.
- The primitive inventory omits supported modes and subelements, including nonseparable blend modes, component-transfer function elements/defaults, and external-image forms of `feImage`.

The blur threshold and assertion of matching Chrome are not established by a spec citation. Treat them as an implementation hypothesis to verify.

“About 1,000 lines” is not a credible implementation budget for the listed complete set. Turbulence, convolution, displacement, lighting, color conversion, region propagation, and graph execution are substantial individually.

Add intermediate precision, allocation limits, buffer lifetime/reuse, recursion limits, and tile/halo processing to the design. Those determine whether a modest SVG can cause native memory or frame-time problems.

Relevant specification: Filter Effects 1, [filter primitives](https://www.w3.org/TR/filter-effects-1/#FilterPrimitivesOverview), [`color-interpolation-filters`](https://www.w3.org/TR/filter-effects-1/#ColorInterpolationFiltersProperty), and [filter functions](https://www.w3.org/TR/filter-effects-1/#FilterFunctions).

**D15 — change: lowering must be conditional on dependencies, not only the property name.**  
*Lines 184–192.*

Fixing inherited animation and `display: none` cancellation is correct. The compositor strategy needs a more selective contract.

The engine currently has [one global lowered-property set](/Users/ccheever/projects/exact2-wt-svg2-review/motion/src/engine/animate.rs:132). The RFC needs **per-effect/per-instance eligibility**: the same property may be safely composited on one shape but require sampling on another.

Examples:

- A path animation changes bbox-dependent paints, masks, filters, markers, and calibrated dash lengths.
- Changing geometry position does not necessarily translate a `userSpaceOnUse` paint with it.
- An animated ancestor value must retain the ancestor’s phase when a descendant mounts. Copying the animation specification and restarting it on that descendant is wrong.
- Descendant declarations can block inheritance; inherited animation must not manufacture descendant animation events.

**`d` animation needs an authored path representation.** The current conversion to cubics loses command identity and arc parameters. Interpolating cubic approximations of endpoint arcs is generally different from interpolating the SVG arc parameters and constructing the intermediate arc. Core Animation path interpolation is suitable only for a proven compatible subset.

Add the omitted CSS `transform` animation and ordinary SVG animation targets such as stroke width, fill/stroke opacity, stop opacity, and dash arrays. Clarify attribute animation targets separately.

The first slice’s animated-radius/dash-calibration limit and easing “before flag” limit also need explicit closure. Broadening lowering while retaining those defects would make them harder to isolate.

Relevant specification: SVG 2, [path interpolation](https://www.w3.org/TR/SVG2/paths.html); CSS Transforms 1, [transform interpolation](https://www.w3.org/TR/css-transforms-1/#interpolation-of-transforms); CSS Animations 1, [animation lifecycle](https://www.w3.org/TR/css-animations-1/#animations).

**D16 — reject universal SMIL-to-CSS lowering.**  
*Lines 194–219.*

A restricted SMIL subset can compile to CSS. The proposed table does not describe a semantics-preserving translation of the admitted features.

| Mapping | Finding and required correction |
|---|---|
| `attributeName` → row | Contradicts the promise to animate `points`. It also excludes attribute targets such as line endpoints, `viewBox`, resource coordinates, and filter parameters. SMIL needs attribute targets beyond CSS properties. |
| `from` / `to` / `by` / `values` | `from + by` is only one case. A by-only animation is additive; to-only animation has underlying-value behavior. Define precedence and the SMIL sandwich model. |
| `keyTimes`, `calcMode` | Default to SMIL’s timing rules, not CSS’s default `ease`. Discrete values occupy intervals: three values without explicit times each occupy one third of the duration. Naively putting them at 0%, 50%, 100% with step-end intervals is wrong. |
| `paced` | Distances are type-specific and may depend on resolved units and current values. Literal text alone does not guarantee compile-time distances. `animateMotion` also has its own default pacing behavior. |
| `dur`, repeats | `repeatDur` constrains active duration together with `repeatCount` and end timing; it is not an unconditional replacement by a fractional count. Indefinite durations and omitted durations need representation. |
| `begin` | SVG timing uses a time container, not CSS effect creation time. The insertion-time rewrite is a semantic deviation. Offset-based `end` is missing even though only event/syncbase ends are refused. |
| `fill="freeze"` | Can map to forwards fill only after the correct active interval and final sampled value have been established. |
| `set` | A constant value applies throughout its active interval; it is not intrinsically an interpolating keyframe pair. Its duration can be indefinite. |
| `animateTransform` | Postmultiplication for additive transform animation is useful, but does not solve multiple-animation priority, replace/additive behavior, or live underlying transforms. |
| `animateMotion` | CSS motion paths introduce anchoring, reference-box, and composition rules. `offset-anchor`, `offset-position`, coordinate conversion, and matrix order must be reconciled explicitly. Three offset properties do not establish equivalence. |

Refusing additive animation for other types also conflicts with supporting by-only forms faithfully.

A CSS animation list does not reproduce SMIL’s entire animation sandwich and timing model. Synthesized CSS animations additionally raise questions about CSS animation events, cancellation, `display: none`, and interaction with authored CSS animations.

Keep native SMIL on the web and implement the admitted timing/value model natively, or publish a narrowly defined lowering subset with explicit refusals. The web agent clock can use SVG timing APIs such as `pauseAnimations()` and `setCurrentTime()`; WAAPI’s inability to enumerate SMIL does not force this translation.

Relevant specification: [SMIL Animation](https://www.w3.org/TR/smil-animation/), particularly values, calculation modes, timing, and the animation sandwich; SVG’s [animation elements](https://www.w3.org/TR/SVG11/animate.html); CSS Motion Path, [motion-path transforms](https://www.w3.org/TR/motion-1/).

**D17 — change: exact hit regions and accessibility cannot use the proposed shortcuts.**  
*Lines 221–231.*

Add the missing `pointer-events: bounding-box` value.

Distance to a flattened centerline with round joins is not equivalent to SVG stroke hit testing. It produces false positives beyond butt caps and misses parts of square caps and miter joins. Preserve the specified cap/join/miter behavior, non-scaling-stroke space, and degenerate-path rules.

Also specify:

- Transparent paint and opacity zero can remain hit-testable.
- Clip paths affect hit regions; mask transparency and filter pixels do not simply replace the geometric hit region.
- `overflow: visible` must not be defeated by always restricting hits to the SVG box.
- Text has text-specific hit regions.
- Native element targets need virtual dispatch identities, since they have no native views.
- Pointer capture, focus, keyboard activation, and `use` retargeting need contracts beyond hover.

The accessibility inclusion rule is too restrictive. A shape with a title or accessible name can merit exposure without an event handler or explicit role. Name/description precedence must include `aria-labelledby` and `aria-describedby`, not just a title child. An accessibility object also does not, by itself, implement `tabindex` keyboard focus.

Relevant specification: SVG 2, [pointer events](https://www.w3.org/TR/SVG2/interact.html#PointerEventsProperty); [SVG-AAM](https://www.w3.org/TR/svg-aam-1.0/); and [Accessible Name and Description Computation](https://www.w3.org/TR/accname-1.2/).

**D18 — change: boundary timers are appropriate, but the observable event model is missing.**  
*Lines 233–239.*

Avoiding per-frame polling for lowered animations is sound. Define:

- `animationName`, `elapsedTime`, bubbling, cancellation, and event ordering.
- Negative-delay start events.
- Zero-duration start/end behavior.
- No iteration event at a boundary that instead produces the final end event.
- Pauses and timing changes rescheduling timers.
- Cancellation on name removal, destruction, and `display: none`.
- Event behavior when the agent clock crosses several boundaries.

“Only while a handler is registered” must include listeners on ancestors: animation events bubble. A parent listener must receive a child’s iteration events even when the child has no local handler.
