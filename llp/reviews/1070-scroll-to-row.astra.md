# Review: scroll-to-row for virtualized lists (direction, before its sub-LLP of 1070)

**Reviewer:** Astra (codex gpt-6-astra, max), requested by Charlie, 2026-09-27
**Subject:** the design sketch in `QUEUE.md` ("Scroll-to-row for virtualized lists"), before it is written up
**Dispositions:** in the sub-LLP, when it is written after LLP 1070 stage 4. Point 0 below (1070 on main reads Draft with inner offsets resetting) is answered by the rulings commit on `feat/horizontal-lists`: Q1 as ruled, default-on keep.

**Verdict: go with named changes.** Key-based `scrollIntoView` is the right direction. Instance identity and long-distance smooth scrolling need firmer decisions before implementation.

I’m treating your accepted LLP 1070 behavior as authoritative; the checked-in document still says Draft and resets inner offsets ([1070:232](/Users/ccheever/projects/exact2/llp/1070-nested-and-horizontal-lists.rfc.md:232)).

1. **Medium — Keep the command imperative and keyed.** The index already supports key lookup and logarithmic prefix sums ([index.rs:273](/Users/ccheever/projects/exact2/runner/src/instance/collection/index.rs:273)). Indices belong inside the implementation. A bound position prop introduces persistent ownership and awkward repeated requests; anchor key + offset fits restoration. Scroll snap and `scroll-margin` influence landing geometry, not target selection. Fragment navigation can invoke this primitive after loading data; it also carries URL, `:target`, and focus semantics. `content-visibility:auto` retains DOM elements while skipping rendering work, so it does not replace bounded row lifetime. [HTML fragments](https://html.spec.whatwg.org/multipage/browsing-the-web.html#scroll-to-the-fragment), [CSS containment](https://drafts.csswg.org/css-contain-2/#content-visibility).

2. **High — Specify the action command and list address together.** Use the existing `name(args)` action-command form, specialized for runner-owned collection work; `send` and `refresh` remain data operations. Commands already execute after commit ([ast.rs:462](/Users/ccheever/projects/exact2/contract/syntax/src/ast.rs:462), [runner.rs:48](/Users/ccheever/projects/exact2/runner/src/runner.rs:48)). A recycled inner list needs a logical address: outer list instance → outer row key → inner declaration/component site plus intermediate eager-`each` keys → target key. LLP 1070 already identifies those distinguishing parts ([1070:243](/Users/ccheever/projects/exact2/llp/1070-nested-and-horizontal-lists.rfc.md:243)). A live `ViewId` or dynamically generated `testId` cannot address an unmounted inner list. Realize ancestors to resolve that address; avoid introducing general mutable reference objects.

3. **High — Complete the web option semantics.** Add `inline`, defaulting to `"nearest"`; horizontal centering uses `inline:"center"`, not `block:"center"`. Defaults should be `block:"start"`, `behavior:"auto"`, and ancestor scope `"all"`. Include `"instant"`: `"auto"` consults CSS `scroll-behavior`, which exact2 already exposes ([schema.json:2318](/Users/ccheever/projects/exact2/kernel/tables/schema.json:2318)). Support or explicitly scope out `container:"nearest"`. Ancestor alignment must use the actual target’s rectangle and include ordinary scrollers and the page—not merely center its outer row. Preserve 1070’s explicit horizontal RTL refusal until negative-offset handling is implemented ([1070:194](/Users/ccheever/projects/exact2/llp/1070-nested-and-horizontal-lists.rfc.md:194)). [CSSOM View](https://drafts.csswg.org/cssom-view/#dom-element-scrollintoview).

4. **High — Destination preparation does not solve smooth traversal.** A thousand-row animation exposes intermediate viewports. Building only the destination leaves gaps; retaining the whole route breaks O(window) lifetime. D1 owes jump destinations, while D3 withholds **known over-budget rows during user motion**, not every row ([1050.000:72](/Users/ccheever/projects/exact2/llp/1050.000-choosing-the-fill-tradeoff.rfc.md:72)). Programmatic animation needs an explicit classification: today the heavy-leaf hold checks only dragging/deceleration ([HeavyLeavesIOS.swift:114](/Users/ccheever/projects/exact2/host/apple/Sources/ExactKit/IOS/HeavyLeavesIOS.swift:114)). **Ship instant positioning first.** Gate smooth support on a bounded traversal/fill policy and a declared browser limitation where compositor scrolling cannot wait. Distinguish missing rows from 1068’s painted boxes with pending heavy leaves; neither may remain pending at settlement ([1068:589](/Users/ccheever/projects/exact2/llp/1068-recycling-heavy-views-in-list-rows.rfc.md:589)).

5. **High — Make positioning a bounded prepare–measure–commit operation.** Explicitly realize the target key and destination viewport, measure, then publish geometry and offset coherently. Preserve the currently displayed window while preparing a distant destination. The web has useful build-before-move machinery, but its hidden/partial fallback moves before filling ([collection-glue.js:227](/Users/ccheever/projects/exact2/host/web/collection-glue.js:227)); that cannot certify this command. Native `scrollIntoView()` becomes usable only after materialization. Define success as measured target alignment within a pixel tolerance, subject to clamping—not equality with an eager list’s absolute `scrollTop` while preceding heights remain estimated. Specify finite correction work and an explicit non-convergence result; the existing two-pass host budget is not a convergence proof ([Collection.swift:49](/Users/ccheever/projects/exact2/host/apple/Sources/ExactKit/Collection.swift:49)).

6. **High — Define request lifetime, mutation, and cancellation.** Missing/unloaded keys should produce an observable no-op/refusal; fetching belongs to app code. Reject ambiguous duplicate keys—the current collection disambiguates duplicates by occurrence ([mod.rs:413](/Users/ccheever/projects/exact2/runner/src/instance/collection/mod.rs:413)). Re-resolve surviving keys after insert/reorder; cancel on deletion, list destruction, newer conflicting requests, or user takeover. Do not apply ordinary anchor deletion fallback to an explicit target. Tag work with request and incarnation identity alongside existing revision/sequence/epoch checks ([mod.rs:757](/Users/ccheever/projects/exact2/runner/src/instance/collection/mod.rs:757)). Explicit targeting temporarily overrides restoration, reading anchors, and end-follow; cancellation must discard later corrections. For smooth motion, specify retargeting explicitly—reissuing native smooth scrolls can restart animation. The current iOS correction guard does not cover programmatic animation ([CollectionIOS.swift:66](/Users/ccheever/projects/exact2/host/apple/Sources/ExactKit/IOS/CollectionIOS.swift:66)).

7. **Medium — Specify the target box and CSS spacing.** Collections measure generated wrappers enclosing authored root margins ([views.rs:33](/Users/ccheever/projects/exact2/runner/src/instance/collection/views.rs:33)). Decide which box the command targets; I recommend the authored row root, with its `scroll-margin`, against each ancestor’s `scroll-padding`. Implement those CSS properties for sticky-header clearance instead of an API-specific header offset. Test oversized rows, already-visible `"nearest"`, zero-size targets, endpoint clamping, and snap-adjusted destinations. Scrolling alone should not change focus. Reduced-motion behavior should follow the existing producer preference policy, with explicit `"instant"` available ([DEFERRED.md:329](/Users/ccheever/projects/exact2/rules/DEFERRED.md:329)). [CSS scroll spacing and snapping](https://drafts.csswg.org/css-scroll-snap/#scroll-margin).

8. **Medium — Share the agent path without adding a tenth operation.** Use a `tap` form invoking the same runner command, with logical target addressing; current lookup only finds live nodes ([agent.mjs:897](/Users/ccheever/projects/exact2/scripts/agent.mjs:897)). The operation budget requires this ([DEFERRED.md:391](/Users/ccheever/projects/exact2/rules/DEFERRED.md:391)). Expose pending/completed/cancelled/refused status through `state`. Preserve deterministic immediate scrolling under the frozen agent clock—the existing native path already does that ([NodeViewIOS.swift:868](/Users/ccheever/projects/exact2/host/apple/Sources/ExactKit/IOS/NodeViewIOS.swift:868)). `clock settle` must drain nested realization, corrections, and held leaves; platform-timing tests must separately exercise actual smooth motion and interruption.

9. **Medium — Tighten staging and acceptance.** A short 1010 sub-LLP after 1070’s axis/nesting work makes sense. Record its implementer/date and reconcile 1070’s stale retention text. Explicit targeting should override the addressed inner list’s saved anchor and persist the resulting position; other inner lists retain theirs. Before switching Extra Heavy’s jump scenario, require the **full feed to remain supplied**, Chrome eager-versus-virtual target-rectangle parity, bounded mounted rows, and mutation/interruption cases. Include cold large jumps, first/last rows, variable sizes, nested restoration, and pending-heavy-content measurements—not merely a successful settled screenshot.
