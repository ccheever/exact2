## Blocking

- `tamber/src/import/dtcg/pen.rs:174` — Kind inference still treats author-named maps as pixel properties. `OPAQUE` is only `uniforms` (`pen.rs:67`). A script `inputs` value and a `metadata` value are bindings under the author's key (`inputs?: { [key: string]: … | Variable }` and `metadata?: { type, [key: string]: any }` in the Pencil schema). `inputs: { "gap": "$scale" }` sets `pixel` because the key is `gap`, and the label stays `gap` (`pen.rs:175-178` adds the parent only for a side, a gradient, or `uniforms`). The note says Pencil reads it as `gap`, and the token is proposed as `Npx`. The same for `width`, `padding`, `fontSize`, `strokeWidth`, `radius`, and `blur`. Treat `inputs` and `metadata` as opaque, the way `uniforms` already is.

## Should-fix

- `tamber/src/import/dtcg/pen.rs:171` — Every `$…` string is a use, including `id`, `name`, `ref`, `geometry`, `url`, `href`, `scriptUri`, `deviceId`, and `slot`, which are not variable bindings. A crafted `"id": "$gap"` on a real gap variable adds a non-pixel use, so the token imports as a unitless number. The note names `id`, but the proposal is still wrong.
- `tamber/src/import/dtcg/pen.rs:173` — `offset.x` / `offset.y` are pixels under any object key `offset`, not only an effect of type `shadow`. An unknown object `{ "offset": { "x": "$n" } }` imports as px, and the note says `offset.x`.
- `tamber/src/import/dtcg/pen.rs:346` — A duplicate name keeps its last value, but the kind walk still runs on every earlier definition when the last `type` is `number`. A discarded `"value": "$leading"` joins that number into the group, so the kept `16` used only as `gap` imports as a unitless number. Scan only the definition that stands.
