**Concerns**

1. **BLOCKER — The first wall-time report need not publish any labels.**

   D5 says the `wall` dependency fills initially blank labels, but [`set_time`](</private/tmp/claude-501/-Users-ccheever-projects-exact2/b6cc99c5-fa7f-4db0-8ab7-8757af067fe1/scratchpad/rv3/runner/src/runner/time.rs:68>) collects only declared `exactTime` resources. [`recommit`](</private/tmp/claude-501/-Users-ccheever-projects-exact2/b6cc99c5-fa7f-4db0-8ab7-8757af067fe1/scratchpad/rv3/runner/src/runner/settlement.rs:55>) returns without settlement when that list is empty.

   A relative-only view needs no `exactTime` resource under the proposed API. It can therefore remain blank with `label_due = ∞` and nothing scheduled. **Resolve:** make a changed wall fact commit when relative expressions depend on it, independently of resource declarations. Test initial publication with no resources, actions or authored timers.

2. **BLOCKER — Restoring an expired deadline after refusal creates an automatic retry loop.**

   [D5.7](</private/tmp/claude-501/-Users-ccheever-projects-exact2/b6cc99c5-fa7f-4db0-8ab7-8757af067fe1/scratchpad/rv3/llp/1054.000.003-dates-numbers-and-durations-in-the-roster.rfc.md:269>) restores the old deadline, while the existing advance machinery leaves the clock at its landed value. The restored deadline is consequently still due. The real [`timerWake`](</private/tmp/claude-501/-Users-ccheever-projects-exact2/b6cc99c5-fa7f-4db0-8ab7-8757af067fe1/scratchpad/rv3/host/web/timer-glue.js:4>) selects a frame for both that instant and subsequent frames; ordinary batch errors are logged without stopping scheduling (`host/web/glue.js:589`).

   This is reachable through an unrelated clock-dependent derive that persistently refuses after a boundary—for example, `now() >= 60000 ? 1 / 0 : 0`, which compiles. **Resolve:** specify how a failed label wake is disarmed or retried with a bound, while preserving transactional rollback. Test persistent refusal through the scheduler, not merely restored state.

3. **MATERIAL — “Fresh when remounted” is false with the current host clock plumbing.**

   [`Host::dispatch_at`](</private/tmp/claude-501/-Users-ccheever-projects-exact2/b6cc99c5-fa7f-4db0-8ab7-8757af067fe1/scratchpad/rv3/host/web/src/host.rs:538>) updates the host’s clock, then dispatches without advancing the runner’s clock. Replies behave similarly (`:1170`); Apple and Linux have the same separation. The web scheduler advances the runner only when a deadline is due.

   I exercised the actual scheduler: with no deadline, requesting a frame after an hour left the simulated runner clock at zero. Static-only labels can consequently remount using launch-time “now”; long-lived date labels also permit long idle intervals. **Resolve:** sample controlled elapsed time into the runner before relevant event, reply and mount evaluations, preserving agent-mode determinism and timer ordering. Price that plumbing instead of promising no host changes.

4. **MATERIAL — Static output depends on evaluation optimizations.**

   [D4](</private/tmp/claude-501/-Users-ccheever-projects-exact2/b6cc99c5-fa7f-4db0-8ab7-8757af067fe1/scratchpad/rv3/llp/1054.000.003-dates-numbers-and-durations-in-the-roster.rfc.md:203>) reads current time during evaluation but deliberately omits its clock dependency. Yet [`set_full_evaluation`](</private/tmp/claude-501/-Users-ccheever-projects-exact2/b6cc99c5-fa7f-4db0-8ab7-8757af067fe1/scratchpad/rv3/runner/src/runner.rs:1088>) is explicitly the reference that incremental evaluation must equal.

   After `clock +60000` and an unrelated action, full evaluation refreshes a static label while incremental evaluation retains it. A static call sharing an expression with a live call or `now()` can also update on clock changes. **Resolve:** give the sample time a semantic lifetime independent of whether an optimization skips evaluation, or make it an explicit input. Add full-versus-incremental and mixed static/live expression tests.

5. **MATERIAL — A label wake is an ordinary commit, with broader effects than D5 claims.**

   Advancing `now_ms` changes existing clock dependencies in [`Deps::changed`](</private/tmp/claude-501/-Users-ccheever-projects-exact2/b6cc99c5-fa7f-4db0-8ab7-8757af067fe1/scratchpad/rv3/runner/src/instance/deps.rs:350>) and settlement (`runner/src/runner/settlement.rs:202`). Therefore a label commit can re-evaluate unrelated `now()` derives and re-ask their resource dependants. “Re-evaluates the live labels and nothing else” and “No resource is asked again” are not general guarantees.

   The single generation also invalidates **every** live label at the earliest boundary, rather than each label only at its own boundary. Fifty minute labels distributed across fifty seconds produce fifty generations and 2,500 formatter evaluations per minute under D5’s algorithm. An existing timer can absorb an additional commit; it does not eliminate this work.

   **Resolve:** state these costs accurately. “At most one” describes an additional label commit per runner advance, not all label evaluations or necessarily an entire agent operation, whose request-aware loop may invoke advance repeatedly.

6. **MATERIAL — Virtualization has two omitted interactions.**

   A global label dependency dirties collection row bodies. [`Collection::update_data`](</private/tmp/claude-501/-Users-ccheever-projects-exact2/b6cc99c5-fa7f-4db0-8ab7-8757af067fe1/scratchpad/rv3/runner/src/instance/collection/mod.rs:266>) then ends reorder previews, invalidates measurement epochs and advances collection revisions—even when most formatted strings remain unchanged. Ordinary height invalidation is O(1), but mounted rows acquire new measurement identities and hosts do more work.

   Also, unmounted rows **do** evaluate during logical text copying: [`list_text`](</private/tmp/claude-501/-Users-ccheever-projects-exact2/b6cc99c5-fa7f-4db0-8ab7-8757af067fe1/scratchpad/rv3/runner/src/runner/lists.rs:60>) uses the ordinary `Env`, and `runner/src/instance/text.rs:225` realizes offscreen rows. A shared reporting `Cell` would let this read-only operation alter the deadline.

   **Resolve:** suppress deadline reporting for read-only projection as well as actions, and measure collection feedback costs. Test offscreen copying, unmounting the earliest label, remounting, and an active reorder across a label boundary.

7. **MATERIAL — The proposed byte measurement cannot establish its claims.**

   The proposed `/^exact_runner::format::/` expression cannot match [`metrics.mjs`’s owner string](</private/tmp/claude-501/-Users-ccheever-projects-exact2/b6cc99c5-fa7f-4db0-8ab7-8757af067fe1/scratchpad/rv3/scripts/metrics.mjs:797>), which is `exact_runner::format`. I reproduced that mismatch. Furthermore, the measurement loop selects only RealWorld, video-player and Caltrain (`:813`); if `"long"` is deferred, none exercises the capability.

   **Resolve:** correct the matcher, measure an actual formatting consumer, and report total raw/brotli deltas including the core deadline/dependency machinery. A module attribution row alone cannot demonstrate the proposed 1 KiB compressed penalty from unused entries. Qualify “Caltrain links nothing new” as a production-web body claim; native `ALL` retains the capability.

8. **MINOR — The examples’ compilation claims omit required scaffolding.**

   Both printed snippets produce `type-unknown` for `Time` and `Post`. Supplying shapes makes the “today” example compile to the claimed 1,091 bytes; supplying shapes and stand-in functions makes the proposed syntax compile too. See [the examples](</private/tmp/claude-501/-Users-ccheever-projects-exact2/b6cc99c5-fa7f-4db0-8ab7-8757af067fe1/scratchpad/rv3/llp/1054.000.003-dates-numbers-and-durations-in-the-roster.rfc.md:405>).

   **Resolve:** include the declarations or identify a complete fixture containing them. Describe the stand-in probe as syntax validation, not validation of the forthcoming formatter behavior.

9. **MINOR — Two numeric claims need precision.**

   D3’s “every input under 10⁹” overstates parity with Bluesky. Bun formats `1.25` as `1.2` and `-1` as `-1`; Bluesky floors the former and clamps the latter to zero ([`fmt.rs:203`](</Users/ccheever/projects/bluesky-exact2/data/src/fmt.rs:203>)). Say **nonnegative integer counts**.

   D1 specifies a shifted instant, while D7 says TimeClip first. With `epochMs = -0.5`, offset `+60`, clipping before shifting prints `1:00 AM`; shifting before clipping prints `12:59 AM` in Bun. **Resolve:** provide one exact operation order, including whether the zero sentinel is checked before clipping, and add these cross-boundary oracle cases.

**Suggestions**

- Retain the existing `timer_due_ms`/`advance` seam and the router-style capability link. No new opcode, plan field, agent operation, Cargo feature or blocking check is justified.
- Preserve `clock settle` as settlement of current work and motion; do not make it chase future recurring label deadlines. Test deterministic large jumps, fractional boundaries, New Year, and coexistence with request-producing timers.
- Make the actual Bluesky migration part of acceptance. Removing clock arguments also requires addressing startup guards such as [`reads.rs:205`](</Users/ccheever/projects/bluesky-exact2/data/src/reads.rs:205>) and [`chat.rs:130`](</Users/ccheever/projects/bluesky-exact2/data/src/chat.rs:130>), which currently gate fetching on known time. Verify cold loading and retained polling, alongside the “no feed query on label update” assertion.

The narrowed scope is consistent with RULES/DEFERRED and the admitted consumer. The declared English locale, fixed-offset limitation and Bluesky-specific future policy are explicit; the remaining web-parity issue is precise arithmetic semantics, not a need for additional speculative styles.

**Answers to r3’s open questions for Charlie**

1. **API/default:** Keep the required third argument for this slice. Updating behavior should remain separate from presentation style; `"narrow-second"` conflates them. Explain that `"minute"` sets minimum displayed precision, not a once-per-minute wake guarantee.
2. **Under a minute:** Prefer `"now"` with minute precision. Live seconds should be opt-in.
3. **Static:** Prefer a sample taken at mount and refreshed when its timestamp input changes or it remounts, with a defined response to wall-fact changes. That is useful and predictable; incidental evaluator cache behavior is not an adequate lifetime definition.
4. **RealWorld `"long"`:** Drop it unless its migration ships with this work and its capability cost is measured. The conditional fixture rule is appropriate.

**Verdict: BUILD WITH CHANGES.**
