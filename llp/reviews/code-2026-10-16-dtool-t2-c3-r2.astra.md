1. **High — Two tabs can share a scrub and corrupt redo.** [app.ts:409](/tmp/rv-dt-t2c-r2/apps/design-tool/app.ts:409), [app.ts:909](/tmp/rv-dt-t2c-r2/apps/design-tool/app.ts:909). Both tabs use `design-tool:<person>`. The server accepts an opening request without an ID as an update to that client’s existing scrub. If Ada previews red in tab A, then blue in tab B, A still considers red acknowledged and enables Keep. Keep writes blue, but A records red for redo. **Fix:** give independently operating tool instances distinct protocol ownership identities, or enforce one active instance per identity.

2. **Medium — Cancelling an opening scrub can cancel its replacement.** [app.ts:919](/tmp/rv-dt-t2c-r2/apps/design-tool/app.ts:919), [app.ts:413](/tmp/rv-dt-t2c-r2/apps/design-tool/app.ts:413). Cancel returns immediately when the opening ID is unknown, allowing another Scrub live. That second opening uses the same client and therefore updates the still-open server session. When the first response arrives, its cleanup cancels that shared ID, terminating the newly chosen scrub. The test waits for completion before restarting, avoiding this race. **Fix:** retain a closing state and await the opening response and cancellation acknowledgement before permitting another opening.

3. **Medium — A terminal event arriving before the opening response is lost.** [app.ts:1045](/tmp/rv-dt-t2c-r2/apps/design-tool/app.ts:1045), [app.ts:419](/tmp/rv-dt-t2c-r2/apps/design-tool/app.ts:419). The event fold requires an already-known `scrubbing.id`. Suppose the first preview succeeds, another write ends it, and the long poll delivers that end before the successful opening response reaches the tool. The end is ignored; the late response then installs the dead ID and reports ready. Subsequent unchanged polls send no frame, so “Previewing” can persist indefinitely. **Fix:** retain terminal events while opening and reconcile the returned ID against them before adopting the response.

4. **Medium — Changing the person breaks Keep and makes Cancel falsely report success.** [app.ts:904](/tmp/rv-dt-t2c-r2/apps/design-tool/app.ts:904), [app.ts:920](/tmp/rv-dt-t2c-r2/apps/design-tool/app.ts:920). Open as Ada, change the header name to Grace, then cancel. Frames remain bound to `s.client`, but cancellation uses the new `client`. The server rejects Grace’s cancellation of Ada’s scrub; the client suppresses “no such scrub,” drops its handle and claims restoration while the preview remains open. Keep similarly fails. **Fix:** use the session’s stored client for every terminal command and cancel that session before changing identity.

5. **Medium — Slider release is discarded while the final frame is pending.** [app.contract:515](/tmp/rv-dt-t2c-r2/apps/design-tool/app.contract:515). Drag and release before the last preview response arrives. `dialReleased` fails its readiness guard and records no release intent. When the response arrives, nothing writes; the preview eventually expires unless the user separately presses Keep. A quick track click naturally exercises this timing. **Fix:** latch the final value and release intent, drain the sender, then release once that value is acknowledged. Cancel or a server end must clear the intent.

6. **Medium — Opening refusals disappear instead of showing the server’s reason.** [app.ts:416](/tmp/rv-dt-t2c-r2/apps/design-tool/app.ts:416), [app.ts:427](/tmp/rv-dt-t2c-r2/apps/design-tool/app.ts:427). If another client already owns the scrub, the server returns its explanatory 409. `pump` stores that error, then calls `endScrub(s, '')`; `scrubState` subsequently returns `ok:true`, an empty error and an empty end message. The tool silently returns to Apply. Rebuild, stale-digest and preview failures during opening follow the same path. **Fix:** preserve and display the refusal after closing the local session.

7. **Medium — Returning to the last valid preview does not clear a rejected frame’s error.** [app.ts:407](/tmp/rv-dt-t2c-r2/apps/design-tool/app.ts:407), [app.ts:418](/tmp/rv-dt-t2c-r2/apps/design-tool/app.ts:418). Preview value A, enter an invalid value B, then restore A. Because A already equals `shown`, the pump sends nothing and never clears B’s error. The state becomes `ready:true, ok:false`, leaving Keep disabled for the valid preview. **Fix:** associate errors with the rejected operation and clear them when the draft returns to an acknowledged operation; handle terminal failures separately.

8. **Low — The stub tests still overstate value and undo coverage.** [tamber-stub.ts:41](/tmp/rv-dt-t2c-r2/apps/design-tool/stub/tamber-stub.ts:41), [app.test.contract:578](/tmp/rv-dt-t2c-r2/apps/design-tool/app.test.contract:578). Reusing `scrubSessions` improves lifecycle fidelity, but its canned planner ignores opening digests, preview records no value, and release/undo do not model design contents. The multi-value test checks controls and counters, so incorrect dial values or redo operations can pass. **Fix:** record previewed and released operations, model digest conflicts, and assert final values and undo/redo restoration. Add controlled response ordering for the races above.

Verdict: Request changes.
