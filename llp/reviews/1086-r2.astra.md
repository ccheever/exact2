D3’s memo/commit resets miss several of these and combine others: JS currently emits all resource arguments inside one callback ([`emit.rs:438`](/Users/ccheever/projects/exact2/.claude/worktrees/agent-ae5e6cce2a46e6a63/host/web-js/src/emit.rs:438)). Save and restore the enclosing context with `try/finally`: lazy memo evaluation can nest through [`rt.js:28`](/Users/ccheever/projects/exact2/.claude/worktrees/agent-ae5e6cce2a46e6a63/host/web-js/rt.js:28), so resetting one global counter loses the caller’s consumption. Inline `fn` bodies and map/filter callbacks retain their caller’s budget. Test separate arguments, repeated row keys, and nested lazy derives.

**MATERIAL — D3: an array-only extent cache cannot reproduce the runner’s composite bounds.** JS erases `Some`/`Unwrap` and emits records and lists as ordinary arrays ([`code.rs:285`](/Users/ccheever/projects/exact2/.claude/worktrees/agent-ae5e6cce2a46e6a63/host/web-js/src/code.rs:285), `:325`). Thus `[some(0)]` and `[0]` have identical JS representations but different runner node counts and depths. The runner checks `Some`, `Record` and `List` construction individually, including intermediate values that are subsequently discarded (`runner/src/vm.rs:552`, `:655`, `:667`). Merely moving roster functions and emitting `x_map`/`x_filter` does not cover these constructions.

**Fix:** Specify checked constructor emission and how option extents survive erasure—type-aware metadata or a representation change. Include `MAX_VALUE_DEPTH`, intermediate constructions and aggregate string bytes. The `3 × length` shortcut must apply to a sound aggregate upper bound; individually small strings can collectively exceed `MAX_VALUE_BYTES`.

**MATERIAL — D6: the fixed point omits two existing inference dependencies.** Untyped action parameters are inferred from handlers only after owned initializers ([`component.rs:202`](/Users/ccheever/projects/exact2/.claude/worktrees/agent-ae5e6cce2a46e6a63/contract/types/src/component.rs:202)). Consequently, the proposed loop cannot refine `items = []` from `action replaceItems(v) / items = v` when `v` acquires `list<Item>` through `press=replaceItems(sourceItems)`. It reaches strict dependent checks too early.

Only **owned** initializers are revisited, also leaving `state items = []; state other = items` incomplete after a typed action refines `items`. Both cases reproduce with `target/debug/contract build /dev/stdin --json`; the latter reports that nothing writes `other`.

**Fix:** Include lenient handler-parameter refinement and all dependent initializers in the fixed point, preserving the initializer’s restricted scope. Include parameter changes in convergence detection and its bound, and merge learned types rather than overwriting them with incomplete initializer types (`checks.rs:447`).

**Fix:** Include Apple focus eligibility changes. Test otherwise noninteractive boxes with zero, positive and negative values, programmatic focus, and dynamic changes. Explicit values must also override synthesized web defaults.
