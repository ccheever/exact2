**Errors**

1. **D6.3: the painter is “unhinted.”** The CPU rasterizer explicitly calls `.hint(true)`, including at the RFC’s cited commit, `fade920ee5`. Grayscale is accurate; unhinted is not. This weakens the stated diagnosis behind Q5. [catalog.rs:638](/Users/ccheever/projects/exact2-wt-review-1115004/host/linux/src/text/catalog.rs:638)

2. **D3.6: multiplying the root font size reproduces WinUI text scaling.** It does not: Microsoft documents nonuniform scaling across text sizes and requires containers to resize/reflow around enlarged text. The proposed mechanism also leaves authored pixel-sized text unchanged while enlarging non-text `rem` dimensions. Its equivalence to WinUI should be withdrawn and tested. [Microsoft: Accessible text](https://learn.microsoft.com/en-us/windows/apps/design/accessibility/accessible-text-requirements), [Text scaling](https://learn.microsoft.com/en-us/windows/apps/develop/input/text-scaling)

3. **D6.3: Windows uses ClearType wherever the person enables it.** This is too broad for the proposed transparent composition path. Rendering-surface alpha also affects the antialiasing choice; forcing ClearType can produce incorrect results. [Microsoft: ClearType and alpha modes](https://learn.microsoft.com/en-us/windows/win32/direct2d/supported-pixel-formats-and-alpha-modes#cleartype-and-alpha-modes)

4. **D11: S1 needs none of the missing Scroll/Grid/Table providers.** The Scroll exemption is incompatible with qualifying Shelf’s scrollable library as a normal UIA list: Microsoft requires the Scroll pattern when list items are scrollable. This bears directly on Q1’s first-consumer acceptance. [Shelf:250](/Users/ccheever/projects/exact2-wt-review-1115004/apps/shelf/app.contract:250), [Microsoft: List control requirements](https://learn.microsoft.com/en-us/windows/win32/winauto/uiauto-supportlistcontroltype#required-control-patterns-and-properties)
