## 3. Worth, item by item

- **D1, the failure capture: DO NOW, cut to what is missing.** `agent-test.mjs`'s `fail` (line 696) already reads `state` and peeks the logs at the failing step and folds resource failures, held and pending requests and clock hints into the failure line. What it does not keep: a picture, the target's `layout`, the log lines themselves, and the build id, all of which the agent reruns to get. Verify's `testEnd` (`verify.mjs:762`) takes a picture of every test's end, failed ones included, but after `clock settle`, so it is not the failing step's. The RFC should say this is a 100-line extension of `fail` plus a directory, not a subsystem.
- **D2, the real-time recording: DO NOW on the iOS simulator, DO LATER on Chrome, NEVER as a general recorder.** Two diaries asked for it. `xcrun simctl io <udid> recordVideo --codec h264 <file>` is an out-of-process recorder that exists today and does not touch the app's frame loop; the driver already shells to `simctl io screenshot` (`agent.mjs:656`). On Chrome the repository already uses `Page.startScreencast` (`host/web/tests/collection.mjs:299`), which delivers timestamped PNG frames, not a movie; that is enough for a contact sheet on real time and should be the web form, not an MP4 encoder. macOS needs ScreenCaptureKit and a Screen Recording grant (`AgentMac.swift:1141`); defer until a diary asks.
- **§5 focus and accessibility observations: DO LATER, as one `expect` form, or delete.** `tree` already carries the focused node and `tree --ax` the platform's tree. The Windows focus diary (`2026-10-27-windows-focus-and-rows.md`) was about a painted ring, found by screenshot, not by a missing observation. Nothing here needs a design; if D1 saves `tree` at the failing step it covers the sheet-closed-focus case the RFC imagines.
- **§5 human annotations anchored to a run: DO LATER, one flag.** `evidence.mjs note` exists (line 102). Adding `--run <id>` or `--capture <dir>` is a ten-line change that needs no RFC text beyond a sentence. Nobody in the diaries wrote a note that failed to find its run.
- **§5 attaching work, frame and stream observations: DELETE from §5; it is already a D1 bullet** ("Already collected work counts, frame reports or trace references"). Listing it twice makes the table look longer than the design.
- **§5 actual app audio: NEVER here.** No consumer; the RFC itself says it "needs its own design once a consumer is assigned". A row that says "design later" is not a proposal. Move it to one line in QUEUE.md.
- **§5 resource and failure diagnostics: DELETE.** Crash reports are already attached to a dead app's error (`agent.mjs:578`, `667`: `crashed(...)` folds the report in). Memory and CPU samples have no diary consumer. The row's content is "attach what the OS already wrote", which D1's crash bullet says.
- **§5 haptics and assistive-technology notes: DELETE.** Its content is "a person writes a note", which `evidence.mjs note --device` already is.

So the document is D1, a narrow D2, and two one-line follow-ups. §5 should go.

## 4. Oversights, by severity

1. **D2 collides with a DEFERRED entry the RFC does not cite.** `rules/DEFERRED.md:1591` (the design tool's admission, Charlie 2026-10-14) lists "captures of running apps" among what is "still refused". That entry is about the design tool's channel, and an agent's recording is a different thing, but the RFC must say so and ask for the entry to be narrowed, or a reader will refuse D2 on that line. Resolve: cite it in §6 and propose the exact narrowing.
2. **No implementer and no date.** `RULES.md` "A spec needs an implementer and a date, or it isn't written." The status line says both "remain unset". Resolve: name one (the parent's implementer built D1–D7 in a day) and a date, or mark the document a proposal awaiting assignment and keep it out of `llp/current/` until it has one.
3. **The budgets are invented.** 5 s collection deadline, 15 s per run, 20 MiB, 100 MiB, 30 s / 1080p / 30 fps / 100 MiB: none is derived from a measurement. The repository has the numbers: an iOS display capture is "about 1 s" (`agent.mjs:650`), a `state` reply is capped at `STATE_CAP` in the transcript (`agent-inspect.mjs:337`), verify keeps one PNG per screen. Resolve: keep one bound per kind, each with the measurement it came from, or say "the first implementation measures and sets them".
4. **D1 duplicates what `fail` already assembles, and the RFC does not read it.** §2 names the seam but §3 specifies "resource status and pending/failure summaries" as new content. Resolve: §3 should list only what `fail` does not keep (picture, `layout` of the target, the log lines, build id, directory), and say the failure line is unchanged.
5. **D2's web form should be CDP's screencast, not an MP4 pipeline.** The RFC writes a recorder design (queues, encoder backpressure, MP4 versus WebM, format refusal) for a target the repository already films frame-by-frame. Resolve: on the web, `Page.startScreencast` frames with their `metadata.timestamp`, written as a contact sheet or APNG as `screenshot over` already writes; MP4 only where the platform recorder makes one (`simctl io recordVideo`).
6. **Who reads the movie?** The agent reads text. The RFC says a reviewer "locates the visible defect in a short recording", which is a person. For the agent the useful artifact is frames at real timestamps it can read as a contact sheet beside `perf frames` late entries. Resolve: say the output for the agent is the sheet, the movie is for a person, and make the sheet the first slice.
7. **The clock rule is right but under-argued.** Refusing `clock settle` during capture is correct: settling lands replies and transitions, which changes the scene. Say that in one sentence instead of the paragraph of prohibitions.
8. **Length.** 283 lines, most of them "do not" clauses for cases nobody has hit. `AGENTS.md` "Writing": say what the reader needs and nothing more. Resolve: a revision at about a third of the length, with D1 as a bullet list of artifacts and D2 as two paragraphs.
