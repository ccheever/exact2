**RIGHT WITH CHANGES.** R2 corrects scheme ownership, per-use invalidation, ordinary dynamic-name pruning, `disabledStyled` compatibility, Android mappings and existing token names. Section 0 overstates closure for subtree modes, state composition, bindings and editor authentication.

1. **BLOCKER — D7: nested mode pins still cannot reliably restore the default tuple.**  
   [RFC:410](/Users/admin/x2theme/exact2/llp/1121-design-system.rfc.md:410) promises a whole slice, but emits only values differing from the default. With Dim as default, a Black parent and Dim child, the child emits no replacement and inherits Black. Removing token-to-token references does not prevent [custom-property inheritance](https://www.w3.org/TR/css-variables-1/#defining-variables). This leaves Astra’s finding 2/Grok’s finding 1 unresolved. **Fix:** emit defaults on **every boundary**, followed by tuple overrides, or emit complete slices. Recompute descendant boundaries’ inherited axes when an ancestor changes. Test a non-default parent with a default child.

2. **MAJOR — D7/§3: folding still changes modern colour semantics.**  
   [RFC:367](/Users/admin/x2theme/exact2/llp/1121-design-system.rfc.md:367) stores sRGB results as `Fixed`. But `color(srgb …)` is deliberately `Wide`, including colours within sRGB: [1100:160](/Users/admin/x2theme/exact2/llp/1100-color-spaces-and-hdr.rfc.md:160). The distinction controls precision and interpolation; [motion.rs:267](/Users/admin/x2theme/exact2/kernel/src/motion.rs:267) sends `Wide` endpoints through Oklab. Turning a literal into a token could therefore change its transition. **Fix:** preserve colour-space and modern/legacy semantics through folding, using LLP 1100’s representation and availability rules.

3. **MAJOR — D6/§5: omitting weight does not supply the promised platform typography today.**  
   [RFC:340](/Users/admin/x2theme/exact2/llp/1121-design-system.rfc.md:340) lowers a text-style token to `font-size` while leaving weight unsaid. The existing [relative resolver:83](/Users/admin/x2theme/exact2/kernel/src/txn/relative.rs:83) resolves size; today’s [font shorthand:303](/Users/admin/x2theme/exact2/contract/lower/src/shorthands.rs:303) separately supplies weight. A headline token can therefore inherit body weight. **Fix:** make LLP 1115.000 D12.2’s implicit weight/leading implementation a prerequisite, and specify authored masks and clearing for each projected longhand. Also preserve D12.3: [Bold Text applies even to authored system-font weights](/Users/admin/x2theme/exact2/llp/1115.000-no-tells-on-every-host.rfc.md:567), while bundled fonts remain unchanged.

4. **MAJOR — D7/D12: pruning removes tokens used exclusively through generated bindings.**  
   [RFC:375](/Users/admin/x2theme/exact2/llp/1121-design-system.rfc.md:375) roots retention in plan references; [D11:554](/Users/admin/x2theme/exact2/llp/1121-design-system.rfc.md:554) explicitly keeps only tokens a plan references. A token used solely by `ExactDesign(session).color(.surfaceCard)` in a native module can disappear, leaving the advertised live accessor with only a fallback. This is a new hole beyond the repaired dynamic-string case. **Fix:** include exported binding tokens in the retention roots, conservatively retaining all externally accessible tokens unless an explicit export set bounds them.

5. **MAJOR — D12: binding context and observation remain incomplete.**  
   [RFC:567](/Users/admin/x2theme/exact2/llp/1121-design-system.rfc.md:567) gives Swift/Kotlin a session but no node or mode context. Two views in the same session and identical OS traits can sit beneath different `-exact-mode` pins; a trait-only colour provider cannot distinguish them. [RFC:579](/Users/admin/x2theme/exact2/llp/1121-design-system.rfc.md:579) also omits root-size, Dynamic Type and subtree-pin changes from font observation. **Fix:** define a contextual design handle containing the owning node/view and resolution inputs, with subscriptions covering every dependency. Stable names fix only the identity half of Astra’s finding 9.

6. **MAJOR — D8: simultaneous-state precedence is only partly specified.**  
   [RFC:462](/Users/admin/x2theme/exact2/llp/1121-design-system.rfc.md:462) orders host overlays, but gives no order between `:checked` and `:disabled`, nor between class state parts, node state parts and ordinary authored rows. A checked, disabled toggle with two background declarations still has no defined answer. **Fix:** specify those merge rules and a complete per-property state order before lowering. Include class changes and base changes while pressed in the acceptance gate. Astra’s finding 6 remains open.

7. **MAJOR — D8: host-owned colour overlays lack inherited-paint semantics.**  
   [RFC:453](/Users/admin/x2theme/exact2/llp/1121-design-system.rfc.md:453) applies active/hover colours outside the runner. D7’s cited inheritance mechanism, however, runs through [kernel commits](/Users/admin/x2theme/exact2/kernel/src/txn.rs:1330); native text already carries [resolved inherited rows](/Users/admin/x2theme/exact2/host/apple/Sources/ExactKit/TextRunPaint.swift:1). Overlaying a container’s colour alone does not recolour its descendant text or `currentcolor` consumers. **Fix:** define host-side presentation inheritance, override boundaries and text-cache invalidation, or initially exclude inherited colour from host overlays. Test nested text, inline runs and SVG.

8. **MAJOR — D13: the capability’s bootstrap is not authenticated.**  
   [RFC:615](/Users/admin/x2theme/exact2/llp/1121-design-system.rfc.md:615) gives the capability to “the editor it serves” without restricting who receives that editor’s credential. The existing gate admits unauthenticated LAN GETs and POSTs; the read-only probe confirmed this. Supplying the secret in that public response restores the original vulnerability. **Fix:** restrict credential bootstrap to verified local access, as [local-install.mjs:89](/Users/admin/x2theme/exact2/host/web/local-install.mjs:89) does, or require explicit remote pairing. Keep credentials out of publicly readable editor responses. Astra’s finding 11 is only partially fixed.

9. **MAJOR — D8/D13: `set-state` cannot always be a table-only update.**  
   [D8:453](/Users/admin/x2theme/exact2/llp/1121-design-system.rfc.md:453) compiles disabled/checked parts into conditional bindings, whereas [D13:596](/Users/admin/x2theme/exact2/llp/1121-design-system.rfc.md:596) promises to update “the state look.” Changing a disabled literal or token name changes that compiled binding; it does not identify an existing token-table value to replace. **Fix:** either give all state declarations stable data entries selected by bindings, or route runner-known state edits through ordinary rebuild/reload. Their write precondition must also cover the edited `.contract` file, not just the design digest.

10. **MAJOR — D13: incremental publication lacks recovery and watcher coordination.**  
    [RFC:605](/Users/admin/x2theme/exact2/llp/1121-design-system.rfc.md:605) tags patches with the plan digest and **new** design digest, but no required previous design digest. A reconnecting session can miss an earlier token change and accept a later unrelated patch against the same plan. Moreover, writing the source currently triggers the [JS dev loop’s rebuild/reload watcher](/Users/admin/x2theme/exact2/host/web-js/dev.mjs:109). **Fix:** require base/new design identities, publish a full snapshot on connection or mismatch, and coordinate accepted source writes with the watcher so a successful swap does not also reload.

11. **MAJOR — D14: the DTCG mapping does not specify arbitrary cross-axis values.**  
    [RFC:643](/Users/admin/x2theme/exact2/llp/1121-design-system.rfc.md:643) maps each axis to an independent modifier, while D5 permits joint conditions. DTCG uses [ordered, last-wins overlays](https://www.designtokens.org/tr/2025.10/resolver/#ordering); independently assigning a token cannot represent every joint table—for example, alternating black/white across two binary axes. **Fix:** specify a composite-tuple export or generated helper/alias encoding. Validate every exported tuple against Exact’s folded table; an unchanged re-import alone does not prove exported semantics. The updated standards citation fixes only part of Astra’s finding 13.

12. **MINOR — §0/§5: ownership remains deferred, not fixed.**  
    [RFC:16](/Users/admin/x2theme/exact2/llp/1121-design-system.rfc.md:16) still names no implementer. Requiring one before a stage starts is a gate, not the assignment required by [RULES:58](/Users/admin/x2theme/exact2/rules/RULES.md:58). **Fix:** assign an owner and implementation date to the first accepted slice; leave subsequent stages explicitly unaccepted until assigned.
