1. **SHOULD-FIX** — `host/web-js/said.js:18`. The word is sampled only from the capture `pointerover` listener. A bound fill whose alpha changes while the pointer is already over the button keeps the wash from entry until the pointer leaves and comes back. A pressable with `background-color=(on ? "#2f6b3f" : "transparent")` is hovered, so `:hover` is already showing; the click writes the new inline color through `css()` and `pointerover` does not fire again. An opaque fill that just appeared keeps the 4% quaternary wash, and a fill that just cleared keeps the 12% ink wash. The same stickiness applies to a bound `light-dark()` or `var(--token)` when a scheme or mode change crosses alpha under a resting pointer, and to a motion or transition frame that crosses alpha after entry. Opaque-to-opaque toggles stay right, which is why interaction-gallery can stay at 0: its `theme.wash` / `theme.page` / `theme.card` branches are all painted fills. A button already under the cursor when the module evaluates (no later boundary event) waits the same way. **Fix:** keep the `pointerover` sample, and call `sayFill` again for the hovered `button:not([data-button-style])` from the `background-color` write in `css()` / `Sm()` and when the scheme or mode tuple changes.

2. **SHOULD-FIX** — `host/web-js/said.js:11`. If the inline longhand is missing, `sayFill` returns and leaves `data-exact-said` alone. That correctly preserves a class fill `element.rs` marked at compile time. When the inline longhand is removed, put that snapshot back (drop the attribute if there was none) and keep the other words. Run that from `css()`'s removal path as well as from `pointerover`, so a clear under a resting pointer updates the wash in the same frame.

Checked and holding:

- **Same-event hover.** The listener runs in the `pointerover` task. Style and paint run in the rendering steps after that task, so the first painted `:hover` frame sees the updated attribute. `neutral.css:87-90` changes `background-image` only, so a `getComputedStyle` flush while `:hover` is already matched still reports the author fill.
- **Touch and pen.** `pointerover` fires for every pointer type, including touch contact and pen. The wash itself is inside `@media (hover: hover)` and requires `:hover`, so a touch-only phone never shows it.
- **Keyboard.** Focus does not match `:hover`. The ink wash is not a focus style; the ring is separate. Leaving the word unchanged on focus is right.
- **light-dark.** A class fill stays on `element.rs`'s rule (`host/web/src/element.rs:1214-1215`): the word is set when either scheme is opaque, and the early return leaves it there across a scheme change. A bound `light-dark()` is inline, and `getComputedStyle` is the current scheme only, which is the right sample at entry. It goes stale only for the duration in finding 1.
- **SSR / no document.** The listener is installed only when `document.addEventListener` exists. The Bun render document's listener is a no-op, and `sayFill` does not run during render.
- **Class fill, no inline longhand.** `element.rs` still owns that word, including a static token or `light-dark()`. `sayFill` does not re-read it.
- **Alpha.** Computed sRGB is `rgb(R, G, B)` when opaque and `rgba(R, G, B, A)` otherwise; modern spaces keep a trailing `/ alpha`. Opaque `rgb()` no longer treats the blue channel as alpha. `transparent` from `getComputedStyle` arrives as `rgba(0, 0, 0, 0)`.
- **Pressable.** `button:not([data-button-style])` is the pressable button. Platform controls carry `data-button-style` and are skipped. Adoption keeps a bound row inline, so a `css()` skip on an adopted page still has a longhand to read at entry.

No test covers an alpha that crosses zero while the pointer stays, or a bound fill removed with `removeProperty`. Gallery conformance does not reach either path.
