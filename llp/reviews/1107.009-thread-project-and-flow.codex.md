## Ownership checked

Settings writes re-read permissions and config or shell before dispatch. Explicit
empty permissions deny writes. The common endpoint captures focused/fleet transport
generation and checks it before and after replies. Rename checks the captured
environment/project/path membership before fan-out; its post-ID settingsCall also
rejects a changed endpoint. Partial writes retain actual server results and report
failed environments. They do not synthesize renamed project records or report full
success after a partial save.

Plan Mode hydration updates only the shared device preference. Send reads actual
mobile preferences, validates draft/model identity, stages effective Build when
the preference or provider disables Plan, then captures the admitted identity.
The existing sender and pending reconciliation retain write ownership. The native
guard releases only at an actual orchestration write, allowing successful launch
to select the new thread.

New-task flow owns a session, route visit and selected draft identity. readyVisit
is cleared before projection and granted only on the ready branch. Ordinary
actions require that ready owner; project selection and preparation are the
explicit exceptions. Direct settings children prepare their actual staged model
session before exposing controls. An already-dispatched checkout stays tracked
until its answer settles and cannot patch a replacement draft. App answer guards
check ownership around native awaits, and model responses carry requestRoute.
The catalog readiness correction waits for a connected focused shell that has not
loaded, and for unsynchronized background environments. Known invalid identities
settle back to the chooser.

## 2026-10-07 native day-picker follow-up

I reviewed the subsequently added T3MobileThreadPreferences.swift, its Contract
binding and days-native validation. This supersedes the earlier observation that
iOS still used the inline field. The inline field now remains only as the
nonnative fallback. No native build, simulator drive or Swift compiler ran in this
review.

The picker captures scope, initial value and a unique open ID. Scope, value,
disabled or appearance-prop changes call close before adopting new props. Close
invalidates the open ID before dismissing and detaches presentation delegates.
Destroy also marks the instance inactive. Done, Cancel and dismissal callbacks
capture the owner weakly and refuse a replaced or destroyed instance. Cancel and
outside dismissal emit nothing; Done emits only a changed value after matching
the captured scope/initial value. The TypeScript command then validates that JSON
and refuses a freshly loaded reference value different from the captured initial
value. Native code retains no Exact answer, transport handle or server writer.

The responder-chain presenter is a local variable, not stored by the native
instance. The owned hosting controller and dismissal delegate have weak callbacks
back to the instance. Old callbacks cannot close or submit a new popover because
they also compare the open ID. Source inspection found no remaining stale-Done,
Cancel, destroy or controller-retention defect in this bounded path.

P2 found and corrected during review: the first implementation resolved static
colors from button.traitCollection during factory setProps, before window
attachment, and had no later system-scheme refresh. It could preserve a light
palette in a system-dark window or open popover. The author replaced this with
dynamic UIColor providers that capture only immutable light/dark role values.
Forced appearance remains on the button and controller. I inspected that source
correction; system-theme behavior has not been driven on a device.

The SwiftUI content matches the pinned iOS source's 1–90 choices, singular/plural
labels, Cancel/Done, 180-point wheel, 240-point content width, 12-point padding and
24-point button spacing. The UIKit tinted trigger differs from the source SwiftUI
bordered button, and compact popover adaptation/actual geometry remain unverified.
LLP1107.009 now states those limits and the native/fallback distinction.
