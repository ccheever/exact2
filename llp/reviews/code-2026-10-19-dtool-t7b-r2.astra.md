**There are blockers. Round 1 is only partly closed.** This was a static review: no files changed, builds performed, or test suites run.

The rewrite fixes overlapping passes, supplies `plan` on holds, respects explicit null digests, and adds ordinary States → Grid cleanup. Per-tile origins, the gateway’s four-copy cap, the `app` notice, and serving fallback paths in the stub are present. The remaining findings are:

1. **BLOCKER — Value equality still does not establish ownership.** [grid.ts:112](/tmp/rv-dt-t7b2/apps/design-tool/grid.ts:112). Tool A pins a copy light; tool B subsequently pins it light too. A’s cleanup sees equal JSON and sends unconditional `pin:null`, removing B’s pin. Holds have the same problem. Conversely, if A’s successful pin response arrives before its builds event, cleanup can see the preceding value and discard A’s duty without clearing the pin. Round 1’s ownership and acknowledgement findings remain. Track acknowledged revisions/ownership and make release conditional at the server.

2. **BLOCKER — Commands can cross a server restart.** [grid.ts:103](/tmp/rv-dt-t7b2/apps/design-tool/grid.ts:103), [wire.ts:109](/tmp/rv-dt-t7b2/apps/design-tool/wire.ts:109). Grid commands omit the wire’s `bound` argument. An old cleanup request can therefore acquire the restarted server’s token and retry against a reconnecting build with the same ID. It can clear a pin created in the new run before a later grid pass notices the changed epoch. Bind each command and cleanup obligation to its originating run; clearing maps at the next pass is insufficient.

3. **BLOCKER — States consumes its hold attempt before reaching the selected screen.** [grid.ts:179](/tmp/rv-dt-t7b2/apps/design-tool/grid.ts:179). Select a control at `/post/3` in One copy, then open States. New copies start at `/`; the pass sends their holds before sending navigation. A copy that processes the hold first reports `gone` because that site/instance is not mounted. After navigation succeeds, `asked` prevents another attempt, leaving the state unapplied. Wait for the selected location before consuming the hold attempt.

4. **SHOULD-FIX — A mismatched plan does not release an existing hold.** [grid.ts:156](/tmp/rv-dt-t7b2/apps/design-tool/grid.ts:156), [grid.ts:182](/tmp/rv-dt-t7b2/apps/design-tool/grid.ts:182). Cleanup retains a hold whenever the tile has a nonempty state, regardless of plan compatibility. After a copy rebuilds, the server may replay its hold onto the corresponding site; the grid merely displays the mismatch warning and leaves that hold active. If replay changes the site number, later cleanup also mistakes the changed hold value for another client’s. This contradicts round 1’s recorded disposition. Determine whether a hold is wanted from its plan and address, not just `t.state`.

5. **SHOULD-FIX — “Select the view again” cannot re-arm the same hold.** [grid.ts:181](/tmp/rv-dt-t7b2/apps/design-tool/grid.ts:181). After real input or a disabled node releases a hold, select the same view again. `shown.e` updates, but the `asked` key remains identical: build, site, instance, plan and state. No new request is sent, despite the tile’s instruction. Failed sends also consume that key permanently. Include a genuine selection generation and distinguish an unsuccessful send from an applied hold subsequently released.

6. **SHOULD-FIX — Host-reported navigation failures never trigger fallback.** [grid.ts:192](/tmp/rv-dt-t7b2/apps/design-tool/grid.ts:192), [app.ts:1078](/tmp/rv-dt-t7b2/apps/design-tool/app.ts:1078). The server acknowledges dispatch before the app attempts navigation. A JS build advertises `navigate` even when its page has no router; it subsequently reports `unsupported`. The grid handles only an immediate HTTP refusal, so it leaves `sentTo` pending and never reloads. The later event becomes caption text only. Consume the host’s refusal and retire the pending navigation before applying the fallback.

7. **SHOULD-FIX — Navigation acknowledgements survive Mirror off incorrectly.** [grid.ts:159](/tmp/rv-dt-t7b2/apps/design-tool/grid.ts:159). Send copy 2 to `/a`, turn Mirror off before arrival is observed, then move that copy to `/b` while mirroring is off. Acknowledgements are processed only inside `grid && mirror`, so `/a` remains pending. When Mirror is enabled again, copy 2’s `/b`—and subsequent moves—cannot lead because `sentTo.has(id)` suppresses them. Retire acknowledgements independently of whether mirroring is enabled, and reset obsolete pending state on policy changes.

8. **SHOULD-FIX — A stale page’s word can acquire the replacement page’s binding.** [grid.ts:46](/tmp/rv-dt-t7b2/apps/design-tool/grid.ts:46), [grid.ts:148](/tmp/rv-dt-t7b2/apps/design-tool/grid.ts:148). `srcs` records the desired URL before the returned tiles update the actual iframe. During a same-origin fallback reload, an old document’s delayed registration can arrive in that interval. Its source still matches the frame’s WindowProxy and its origin matches, so the listener stamps the old ID with the **new** `src`. While that build remains listed, it qualifies for commands. Source/origin checks do not prove document freshness; this also affects the gateway’s shared origin. Bind registration to the actual document generation.

9. **SHOULD-FIX — Serialization still executes superseded view requests.** [grid.ts:213](/tmp/rv-dt-t7b2/apps/design-tool/grid.ts:213). Each queued pass retains its original arguments, and an executing pass never checks whether newer intent superseded it. If a pin request is delayed and the person disables Mirror or chooses One copy, the old pass resumes and can issue its remaining holds and navigations before cleanup runs. Serialization fixes overlapping writes, but not round 1’s obsolete-write scenario. Coalesce queued desired state and check supersession after awaits.

10. **SHOULD-FIX — A failed hello is mistaken for a new server run.** [grid.ts:124](/tmp/rv-dt-t7b2/apps/design-tool/grid.ts:124), [app.ts:623](/tmp/rv-dt-t7b2/apps/design-tool/app.ts:623). A transient hello failure returns `epoch: ''`; the grid treats that as a changed run and clears all ownership duties. On recovery, existing pins can equal the desired pins, so no request recreates ownership. Choosing One copy then leaves them behind. Forget duties only after observing a successful, authoritative change of run.

11. **SHOULD-FIX — The tests still miss the lifecycle and protocol claims.** [app.test.contract:1953](/tmp/rv-dt-t7b2/apps/design-tool/app.test.contract:1953), [tamber-stub.ts:243](/tmp/rv-dt-t7b2/apps/design-tool/stub/tamber-stub.ts:243). Reverse registration checks only eventual pins; States checks state words while the stub ignores `plan`; navigation succeeds synchronously or fails immediately; fixed copy IDs never unregister. Removing the hold’s `plan`, using a common origin for every tile, or mishandling asynchronous navigation refusal would escape these assertions. The fallback-path and hold-cleanup assertions are improvements, but coverage needs delayed responses/events, document replacement, ownership replacement, and exact hold payloads.

12. **NIT — The compiler test’s exclusivity comment remains false.** [vocab.rs:1187](/tmp/rv-dt-t7b2/contract/cli/tests/it/vocab.rs:1187). It says every tag except iframe and radio refuses `name`, but native buttons still return before that restriction at [controls.rs:78](/tmp/rv-dt-t7b2/contract/lower/src/controls.rs:78). The exception predates T7b; narrow the new comment. I found no new regression in the iframe-specific lowering change.
