1. should-fix. A native button's title runs past its box on Linux, and the web's truncation rule does not apply to the element the host emits.

Evidence: `host/linux/src/paint/control.rs` builds the title paragraph with no width and draws it at a centered origin (`button_control`, around lines 343–359). Nothing clips that draw to the button. `host/web/src/element.rs` emits a block `text` node as a `div` (the `span` branch is only an inline run, lines 263–278). `host/web/index.html` line 50 truncates `button[data-button-style] > span`. The face title is a `div`, so that rule matches nothing. The button's `overflow: hidden` (line 49) can hard-clip once a width is set; the ellipsis the plan requires is not what is drawn. `kernel/src/node.rs` `lays_out_children` leaves a control's children unlaid-out, which is why the title is ordinary DOM inside the button rather than a kernel text box.

Failing input:

```

  text "Send message now"
```

On Linux the glyphs continue past the 48-wide box and paint over whatever is beside it. On the web the title is a `div`, so it does not ellipsize.

Fix: on Linux, ellipsize the title to the button's width and clip the draw to that box. On the web, point the truncation rule at the element actually emitted (`div`) and set `min-width: 0` on it so `text-overflow: ellipsis` can take effect inside the flex row.

3. should-fix. The native-button style allowlist accepts `display`, `direction`, and `pointer-events`. `pointer-events="none"` still receives a press on Apple and on Linux.

Evidence: `contract/lower/src/controls.rs` `NATIVE_ROWS` includes `StyleId::Display` (line 428), `StyleId::Direction` (line 432), and `StyleId::PointerEvents` (line 441). D6's allowlist is the whole rule, and inner layout rows are refused. `display` overrides the fixed `display: flex` (`native_tag`, lines 354–357), so the web face stops being a row. `direction` reverses that row in the browser; Apple places the symbol from `face.leading` in `configureNative` and does not read direction. Apple hit testing (`NodeViewIOS.swift` `hitTest`, around 670–702) and the Linux hit path (`host/linux/src/presenter.rs` `hit`, and `display_frame.rs` `allows`) consult hidden, inert, and `display: none`. They do not consult `pointer-events`. The web writes the property into CSS, so the browser drops the click.

Failing input:

```

  text "Go"
```

A click does nothing on the web. The same click fires `press` on iOS, macOS, and Linux. `display="grid"` and `direction="rtl"` compile as well and change the web face relative to the UIButton and NSButton.

Fix: remove `Display`, `Direction`, and `PointerEvents` from `NATIVE_ROWS`. Keep the fixed `display: flex`.

4. should-fix. A `tablist` whose `role` is a choice is not treated as a tablist, so a native button inside it compiles.

One arm `tablist` and the other something else stays a ternary. `lib.rs` lines 995–997 pushes that context onto every descendant.

Failing input:


This compiles. When `busy` is true the button is inside a tablist. `row role="tablist"` is refused, which the contract test covers (`contract/cli/tests/it/native_buttons.rs` lines 221–224). The choice is the hole.

Fix: treat an ancestor as a tablist when any arm of `literals(role)` is `"tablist"`.
