3. **MATERIAL — Earlier results can still become Timeout.** [executor_async.rs:1276](/Users/admin/x2p2/apps/exact2-core/host/apple/src/executor_async.rs:1276) only queues outcomes; [875](/Users/admin/x2p2/apps/exact2-core/host/apple/src/executor_async.rs:875) lets the timer claim the transition before the finisher applies an already-queued success or refusal. 4. **MATERIAL — Late redirect events permanently consume places.** [executor_async.rs:708](/Users/admin/x2p2/apps/exact2-core/host/apple/src/executor_async.rs:708) accepts `Hop` without validating its run. If timeout cleanup precedes this event, selection reserves a place, but the finished `FetchTask::hop` returns without another completion to release it. Reject stale/terminal hops both when applying and selecting them.

5. **BLOCKING — Retirement can still strand a reader.** [executor_async.rs:545](/Users/admin/x2p2/apps/exact2-core/host/apple/src/executor_async.rs:545) installs file state and a decision sender without checking retirement or whether the run survived. This can happen after retirement/disposal cleared them; the reader then waits at [568](/Users/admin/x2p2/apps/exact2-core/host/apple/src/executor_async.rs:568) while its events are discarded. Validate and register the live run atomically before arming/spawning.

6. **MATERIAL — Upload release remains incorrect.** [executor_async.rs:835](/Users/admin/x2p2/apps/exact2-core/host/apple/src/executor_async.rs:835) marks a buffer live before constructing its release-notifying `Upload`. Separately, [1169](/Users/admin/x2p2/apps/exact2-core/host/apple/src/executor_async.rs:1169) waits for the entire request, retaining uploads across body-dropping redirects. Create the tracked buffer before queueing; track the last body-carrying hop separately.
