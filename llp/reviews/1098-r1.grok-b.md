## MATERIAL

### 1. D6 — artwork is resolved on the wrong line, for a route bug this host does not have

**Section:** D6; §1 “A relative artwork `src` resolves against the page.”

**Problem:** `update()` publishes `el.exactMedia.props` (`media-glue.js:43`). Those props are the raw batch. Adding `mediaArtwork` to the `src`/`poster` line writes a DOM attribute and leaves the prop the glue reads unchanged. The §1 failure (a relative URL joining the route) happens on a page with no `<base>`. Exact pages set `<base href="/">`, and a relative `assets/art.png` then resolves at the asset root.

**Evidence:** `applyProps` calls `syncMedia(el, set, clear)` before the attribute loop (`glue.js:405`, `glue.js:24–28`). Line 443 only `setAttribute`s. `localAssetURL` (`glue.js:185–199`) returns the original string except for a dev asset card and a root-absolute `/assets|deck|shaders/` path under a release base (`glue.js:197–198`). On the JS target, `rel()` (`rt.js:551–552`) is that release rewrite alone; `h()` applies it to the attribute and then `media(e, attrs)` copies the raw attrs (`rt.js:558–561`, `media.js:39–44`). Only a dynamic prop goes through `rel` into `mediaProp` (`rt.js:621–627`).

Chrome, page `http://127.0.0.1:8765/show/x`:

- no `<base>`: `assets/art.png` reads back as `http://127.0.0.1:8765/show/assets/art.png`
- `<base href="/">` (`host/web/index.html:5`, `host/web-js/build.mjs:395`): the same relative URL reads back as `http://127.0.0.1:8765/assets/art.png`
- release base `/.exact/root/web/releases/<64 hex>/` (`scripts/deploy.mjs:1173–1176`): the relative URL stays under the release; `/assets/art.png` jumps to the origin root
- `app:/art.png` is stored as `app:/art.png`

Putting `mediaArtwork` on the `app:/` branch of line 443 would also run `appSource` and publish an object URL, which contradicts D1.

**Fix:** Resolve inside `media-glue.js`. Have both targets expose the wasm resolver (`exact.assetURL` is already `localAssetURL`, `glue.js:1417`); the JS target has no equivalent. Skip `app:/` in the glue and set `artworkError`. Leave `glue.js` at 1,499 lines. Restate §1: with exact’s `<base>`, a relative URL is already the app root; the resolver exists for dev cards and for root-absolute paths on a published release.

### 2. D6 — the JS target refuses the six events before `media.js` can hear them

**Section:** D6 “The JS target”; D11.

**Problem:** Adding the six names to `MEDIA_EVENTS` (`media.js:14`) never runs for an app that binds them. The JS emitter rejects every `EventKind` outside its match, and the app’s JS build fails.

**Evidence:** `host/web-js/src/emit.rs:1194–1250` lists `Play` through `Volumechange` and then:

```1245:1249:host/web-js/src/emit.rs

    return Err(format!(
        "node {i}: the `{}` event is not in the JS target",
```

### 6. D10 — the grammar cannot parse the RFC’s own steps

**Section:** D10 EBNF; §5; §9.

**Problem:** The EBNF says the action is an `IDENT` and the seconds are optional. Every example and the §5 tests quote the action (`tap "audio" mediasession "seekto" 600`), and the prose says `seekto` without seconds is a parse error.

**Fix:** EBNF: `"tap" STRING "mediasession" STRING [ NUMBER ]`, with `NUMBER` required if and only if the action is `seekto`. Parse the action with `str_lit` in the arm beside `into`.

### 8. D7 — the AVKit flag does not exist on tvOS, and podcast’s iOS player has no controller to set it on

**Section:** D7 “AVKit’s own publication”; §1.

**Problem:** The same `NowPlaying.swift` / `VideoArm.swift` build is the tvOS arm. Assigning `updatesNowPlayingInfoCenter` there does not compile. On iOS, an `audio` without `controls` never creates an `AVPlayerViewController`, so the flag is unreachable and Now Playing is the coordinator alone.

**Evidence:** The property is `API_UNAVAILABLE(tvos)` (`AVPlayerViewController.h:139`). `configurePresentation` (`VideoArm.swift:381–420`) builds a controller only when `controls` is set (or a video asks for PiP or fullscreen); otherwise it uses `VideoLayerView`. Podcast’s `audio` has no `controls` (`app.contract:458`). macOS always has an `AVPlayerView` (`VideoArm.swift:62`).

**Fix:** Set the flag under `#if os(macOS)` on `presentation`, and under `#if os(iOS)` on `controller?`. State that an iOS audio layer publishes only through `MPNowPlayingInfoCenter`. When the last claimant leaves, assign `true` again; the property stays `false` until something writes it.

### 9. D7 — play, pause, and toggle have no session handler to be “enabled while the owner handles it”

**Section:** D7 “Commands.”

**Problem:** The sentence “Each is enabled with a target only while the owner handles it” sits after both the play/pause commands and the six. `play` and `pause` are element operations (D3), not session events. An implementer who enables the play key only when the element binds `play` hides the lock-screen control for podcast, which drives the element with `paused=` (`app.contract:459`).

**Fix:** `play`, `pause`, and `togglePlayPause` stay enabled for the owner. `togglePlayPause` calls `play()` when `timeControlStatus` is paused and `pause()` otherwise (`VideoArm.swift:341–344`). The six stay enabled only while the owner handles them.
