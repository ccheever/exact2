I'll review the design for implementation feasibility on every host, starting with the RFC, the project rules, and the kanban evidence.The RFC's host and runner claims need to be checked against the reorder code, geometry codec, and the kanban diaries.The runner and every host still implement one vertical list with one token. The RFC's session, geometry v2, hold, ghost, and three-browser exit do not meet that code, so an implementer cannot land stage 1 without breaking the five checks or inventing the host protocol.

1. **MATERIAL** — §3 D4–D6, §4 stage 1. The session does not fit the one-list reorder API, and the JS target is a second copy of that API.
   **Problem:** `reorder_owner` is one `NodeKey`. `ReorderToken.list` is that list. `begin_reorder`, `preview_reorder`, `drop_reorder`, `has_reorder`, and `reorder_frame` all edit and dispatch that one collection. `drop_reorder` fires `reorderdrop` on `token.list`. `Offsets::at` in `runner/src/instance/collection/reorder.rs` only shifts rows between a source index and `before` inside the same index. A foreign list has no source index, so `Incoming { key, extent }` needs different offset math (shift everything at and after the gap by the ghost's main-axis extent; collapse the source list's slot). The document names the session and does not say whether the token stays the source, how one call updates two previews, or how the drop is dispatched on the target. `host/web-js/reorder.js` reimplements preview, owner, and drop in JS and does not call the Rust runner. `arrange.js` checks the same geometry keys. A stage 1 runner change that the JS copy does not share makes wasm and JS disagree in conformance.
   **Evidence:** `runner/src/runner/reorder.rs` (`reorder_owner`, `preview_reorder` at 123–144, `drop_reorder` at 148–165). `Offsets` at `reorder.rs` 293–310. `host/web-js/reorder.js` `ReorderOwner`, `previewDrop`, `$reorderdrop(drop[0], drop[1])`. `host/web-js/arrange.js` imports `arrangeController` from the copied `motion-glue.js` and decodes `scrollTop` / `portHeight`.
   **Fix:** Specify the token as the source identity for the whole gesture. Add the calls a host already has a place to make: one preview call that writes `Outgoing` on the source and `Incoming` on the target in one commit, and a drop that dispatches the target list. Define the incoming and outgoing offset numbers. State that `reorder.js` and `arrange.js` implement that same session in stage 2, and that stage 1 leaves the synchronous within-list path observationally unchanged so `reorder.contract` still matches.

2. **MATERIAL** — §3 D4, §4, §6 stage 1. Geometry v2 is three wires, and stage 1 omits the ones the five checks compile.
   **Problem:** Renaming `scroll_top` / `port_height` and deleting v1 does not describe the packets hosts actually send. There are three. The 68-byte `ReorderGeometry` v1 (`u32` version, identities, five `f64`s, length asserted 68). The wasm motion packet, wire v3, a fixed 176-byte header: version 3, op, nine `u64`s, a count, a `u32` that must be 0, then `scrollTop`, `portWidth`, `portHeight`, `rowWidth`, `totalExtent`, `contentY`, and the hold. The JS target's plain object (`GEOMETRY` in `reorder.js` and `arrange.js`), which never uses those bytes. Apple does not encode the 68-byte packet either. `reorder_begin` / `reorder_move` / `reorder_end` take a vertical `scrollTop` and `dy`, and `arrange_sample` builds `Value::new(base.x, base.y + dy + scroll_delta)`. Linux computes content y from `visual.y`. The collection already stores the main axis in those vertical names (`g.offset`, `g.port_main`). Adding `axis` shifts every fixed offset unless it occupies the spare `u32`. Stage 1 lists Apple and Linux encoders and not `host/web/src/reorder_drag.rs`, `motion-glue.js`, or `apps/exact-live/data/tests/it/arrange.rs`. `host/web` and `apps/exact-live/data` are default members, so `cargo test` fails the five checks on the field rename. `preview_reorder`'s coordinate is still `content_y`, and the Apple FFI is still vertical, so a row list has no place to pass a main-axis sample until someone invents it.
   **Evidence:** `runner/src/instance/collection/reorder_api.rs` 97–147. `runner/tests/it/reorder_codec.rs` asserts `wire.len() == 68`. `host/web/motion-glue.js` `motionBytes` (offsets 0, 4, 80, 88, 176). `host/web/src/reorder_drag.rs` `Input::decode` (176-byte header, padding `u32` must be 0). `host/apple/src/arrange.rs` `reorder_begin` / `arrange_sample` 221–265. `host/apple/Sources/ExactKit/ReorderHold.swift` `reorderMove(_:dy:scrollTop:…)`. `host/linux/src/presenter/arrange.rs` 238–242. `apps/exact-live/data/tests/it/arrange.rs` 244.
   **Fix:** Keep the 176-byte layout. Put `axis` in the spare `u32`. Map the existing floats onto `scroll_main` and `port_main`. Put `reorder_drag.rs`, `motion-glue.js`, `reorder.js`, `arrange.js`, and the exact-live test in stage 1 so vertical reorder still compiles. Name the main-axis sample that replaces `content_y`, `dy`, and `scrollTop` on a row list, and say stage 3 is when Apple and Linux send it.

3. **MATERIAL** — §3 D7. The hold contradicts the terminal, rebase, and finish sequence every host runs, and nothing wakes the 1 s deadline.
   **Problem:** Today the drop commit ends the preview. `end_preview` sets `terminal`, and `preview_offsets` then returns none, so every wrapper target goes to 0 in that same commit. The host then captures, rebases, releases the hold with velocity, and calls `finish_reorder` when the spring settles. Web phases are `active`, `terminalizing`, `settling`. Apple phases are `Active`, `Committing`, `Settling`. A hold that keeps the gap means this commit must not zero targets and must not release the hold. The document says the drop "ends the preview, as today" and that the gap stays. For a synchronous state update the key is already in place before `drop_reorder` returns, which is the only way `reorder.contract` stays green without host changes. For a `send`, the answer arrives on a later commit, and no current pump is running then: web's `requestAnimationFrame` loop runs only while the edge band is scrolling, and Apple's `Timer` runs only inside `updateEdge`. A still ghost never reaches 1 s.
   **Evidence:** `runner/src/instance/collection/reorder.rs` `preview_drop` / `end_preview` / `preview_offsets` (137–172, 240–242). `host/web/src/reorder_drag.rs` `reorder_terminal` then `reorder_rebase` (`end_hold` Release). `host/web/motion-glue.js` `terminal` at 994–1011 and `edges` at 1030–1044. `ReorderHold.swift` `updateEdge` at 209–216.
   **Fix:** Specify two endings of `drop_reorder`. If the dragged key is already in the target before `before` in that commit, end the preview as today so current hosts stay correct. Otherwise return a `holding` phase, keep `Incoming` / `Outgoing` targets, and do not release the hold. Name the host signal for the three endings (spring onto the new row, fade, spring home). Arm the 1 s deadline on the session clock with an explicit one-shot the host already uses for timers, started at the drop.

4. **MATERIAL** — §3 D4. The nested-list edit cites the wrong function, and that function does not enter mounted rows. The outer pin has no owner.
   **Problem:** `traversal.rs:540–548` builds the inner-site set for a plan walk. The reorder editor is `edit_walk` at 633–677. On a node that owns a collection it returns only when `c.view == view`, and the comment says nested collections are forbidden. It never walks `collection.mounted`. Inner lists live on those mounted rows. `find_collection_mut` (400–404) already does walk them. Frames for a nested edit have to include the outer row frame, the way the `Active::Rows` arm pushes `row.frame`. `begin_preview` also requires `geometry.interaction_view == Some(handle)` on that collection, and the host acquires that pin before `begin_reorder`. "Pin its outer row" needs a second pin on the outer list, reported as that list's interaction, or the board's window recycles the source column and `reconcile_reorder` cancels the drag.
   **Evidence:** `runner/src/instance/collection/traversal.rs` 540–560, 633–650, 392–407. `add_children` at 4–10 only stacks rows `inner.may_hold`. `reorder.rs` `begin_preview` 75–80. LLP 1070 §4.7 cited the same assumption when the editor lived near line 545.
   **Fix:** Change `edit_walk` to descend `collection.mounted` the way `find_collection_mut` does, pushing each outer row's frame. State that the host's interaction lease on the inner grip is paired with an interaction pin on the outer row for the whole gesture, released in `finish_reorder`.

5. **MATERIAL** — §3 D6. Nested autoscroll cannot follow DOM ancestors once the ghost leaves the scroll tree.
   **Problem:** "The innermost scroller under the ghost's centre, then each enclosing one" is read as a parent walk. A row list and a plain `scroll` beside it scroll on the other axis. The grip stays in the source list, so walking from the grip finds the source scroller, not the target under the ghost.
   **Evidence:** `host/web/motion-glue.js` `edgeRange` / `edges` 1024–1043. `ReorderHold.swift` `ReorderEdge.direction(offset:height:)` 36–44. D5's three detached ghosts.
   **Fix:** Hit-test the ghost centre against scrollport viewport boxes, innermost first, then each geometrically containing scroller that can still move on its axis. Keep each host's band and speed, measured on that scroller's axis. Re-certify the gap from the lists' boxes after those scrolls, on the source and the target.
