`host/web-js/rt.js:1150` now settles the load promise on the first of two calls: a `requestAnimationFrame` that queues a zero-delay timer (the old after-paint path), or `setTimeout(r, 1000)`. Calling the promise resolve twice is a no-op. On a visible page the frame runs in the rendering steps before the next timer task, so the zero-delay timer fulfills the promise and `import("./input-glue.js")` runs once; the one-second call lands later and starts nothing. That is the whole double-resolve story.

**After paint.** The import is still the body of the `.then`, so it does not run inside the frame callback. A visible page paints, then loads the glue, same as before. The one-second timer wins only when no frame has been delivered for a second. That is the offscreen cross-origin iframe: Chrome does not hand it animation frames, and it clamps timers to about one second, so this timer fires on that clamp. There is no paint sitting behind the parse of `input-glue.js` in that state. `createInputHandlers` only attaches listeners and publishes `exact.hold` (`host/web/input-glue.js:351` fires `exact-hold`). The first `arrive()` records the stack and returns (`host/web/input-glue.js:594-595`), so a glue that comes up late does not move focus on first sight.

**A page that never paints, the agent clock, `inflight`, `__exactRender`.** The render host sets `__exactRender` and `input()` returns at `rt.js:1145` before the timer and before `inflight.n++`. A headless render still does not load the glue. On a visible page that is still about one frame plus the import.
