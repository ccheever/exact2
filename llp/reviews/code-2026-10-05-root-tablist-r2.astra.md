1. [NavigationIOS.swift:108](/tmp/x24/host/apple/Sources/ExactKit/IOS/NavigationIOS.swift:108) — **must-fix:** The new tracking survives its tab container. Neither `retireTabs()` nor the handoff to an app-owned container clears `tablistRoot` or `tablistHidBar`. After rebuilding tabs while retaining the same root, an ordinary projection can see neither a change nor an arrival and skip hiding the new bar. After a reset, stale `tablistHidBar == true` can instead undo a new container hook’s hide. **Fix:** clear both fields whenever Exact’s tab container retires or is replaced; test rebuilding with a hidden retained root and a fresh hook-hidden container.

2. [NavigationIOS.swift:733](/tmp/x24/host/apple/Sources/ExactKit/IOS/NavigationIOS.swift:733) — **must-fix:** Settlement can overwrite a freshly executed route hook. If root metadata changes during a pop, `pendingSync` runs `prepareRoutes`, including that root’s updated hook. A hook that shows the bar then immediately loses to `settleTablist(... settled: true)`, even though it ran after the projected defaults. The same ordering is possible through the synchronous Back dispatch. **Fix:** consume the arrival reconciliation before route hooks in the settling projection, and avoid repeating it afterward. Add a test with a hook update queued during the pop.

3. [NavigationTitleIOS.swift:358](/tmp/x24/host/apple/Sources/ExactKit/IOS/NavigationTitleIOS.swift:358) — **should-fix:** `tablistHidBar` becomes true even when Exact issued no hide. Start with a hook-hidden bar, hide the authored tablist, then show it: Exact reveals the hook’s bar because it claimed ownership of the existing hide. That contradicts the stated “shows only if Exact hid it” rule. **Fix:** acquire ownership when Exact actually performs the hide, preserving existing ownership where applicable; cover this hide/show cycle.
