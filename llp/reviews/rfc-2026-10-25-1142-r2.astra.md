**Concerns**

1. **BLOCKING — D3 still measures different scheduling, and its clock contract contradicts the existing operation.**

   Changing `ChainingScrollView.appliesAtOnce` addresses routing, but the normal post-scroll slice still explicitly refuses agent mode. The existing wheel path also calls `settlePump()`, which synchronously drains work that ordinary scrolling schedules over time. Neither requirement is addressed in §5. [PresenterMac.swift:459](/Users/ccheever/projects/exact2-wt-review-1142/host/apple/Sources/ExactKit/Mac/PresenterMac.swift:459), [PresenterMac.swift:518](/Users/ccheever/projects/exact2-wt-review-1142/host/apple/Sources/ExactKit/Mac/PresenterMac.swift:518), [AgentMac.swift:717](/Users/ccheever/projects/exact2-wt-review-1142/host/apple/Sources/ExactKit/Mac/AgentMac.swift:717)

   There is also a new contradiction: r2 freezes the runner clock during scrolling, then promises `live.from/to` “as LLP 1079 returns them.” LLP 1079 defines those fields as the runner clock advanced by the live window, and the driver assigns `s.now = r.live.to`. Returning wall timestamps would desynchronize the driver; returning unchanged logical timestamps would give this operation different semantics. [r2:216](/Users/ccheever/projects/exact2-wt-review-1142/llp/1142-what-a-development-build-tells-an-agent.rfc.md:216), [1079:381](/Users/ccheever/projects/exact2-wt-review-1142/llp/1079-speed-hygiene-in-the-agents-hands.rfc.md:381), [agent.mjs:792](/Users/ccheever/projects/exact2-wt-review-1142/scripts/agent.mjs:792)

   **Resolve:** specify one scoped native-input/live mode covering routing, normal pumping, settlement suppression, and clock semantics. Define how sampling is acknowledged before input starts, how a gesture outlasting the requested window behaves, and how cancellation restores the process-global routing switch and releases a hold. The proposed fling can last longer than the example’s 1,500 ms window. Merely saying the driver runs operations “inside the window” leaves the essential protocol to the implementer.

2. **MATERIAL — §2 permits production collection while claiming development-only diagnostics.**

   The named Apple predicate is accurate: `FrameSampler.measured` excludes production bakes, while `atBoot` separately controls eager collection. But r2 explicitly leaves runner counts and alert queues populated in production, merely undrained. Bounded storage is still collection and allocation; withholding output does not satisfy the stated admission rule. [r2:137](/Users/ccheever/projects/exact2-wt-review-1142/llp/1142-what-a-development-build-tells-an-agent.rfc.md:137), [FrameSampler.swift:22](/Users/ccheever/projects/exact2-wt-review-1142/host/apple/Sources/ExactKit/FrameSampler.swift:22)

   LLP 1079 specifies production collection off, with an empty counter table. It also distinguishes admission from starting measurement at the first request. [1079:176](/Users/ccheever/projects/exact2-wt-review-1142/llp/1079-speed-hygiene-in-the-agents-hands.rfc.md:176)

   **Resolve:** gate the new runner counters and alert queue at collection, preserving existing ordinary failure handling. State separately when phases and handler counts begin in a non-production release build, and whether failure totals deliberately begin at boot. This is the unresolved portion of Astra’s admission finding.

3. **MATERIAL — D2 still labels loaded-plan provenance with the native bundle’s build identity.**

   The named Info.plist stamps exist, including separate app-repository commit and dirty fields. That factual correction is sound. [buildinfo.mjs:65](/Users/ccheever/projects/exact2-wt-review-1142/host/apple/buildinfo.mjs:65)

   However, the Mac executable can boot an alternate plan without rebuilding and can subsequently load development revisions. [ExactMac/main.swift:731](/Users/ccheever/projects/exact2-wt-review-1142/host/apple/Sources/ExactMac/main.swift:731), [ExactMac/main.swift:755](/Users/ccheever/projects/exact2-wt-review-1142/host/apple/Sources/ExactMac/main.swift:755), [r2:192](/Users/ccheever/projects/exact2-wt-review-1142/llp/1142-what-a-development-build-tells-an-agent.rfc.md:192)

Specify what `--out` does when no map matches: it must report an unsymbolized copy or fail explicitly, rather than promise portability. Also retain the app repository’s dirty flag, not just its commit.

4. **MATERIAL — D4 does not finish the delivery contract, and omits the web JS execution path.**

   This is an existing case, not a hypothetical extension: the Mac entry point maintains multiple document windows with separate sessions, while `saveTrace()` exports one session. One `trace-pid-<pid>.json` does not say which session to save; exporting each session to that name would overwrite earlier exports.    **Resolve:** choose and document session selection, or export a process manifest pointing to separate session traces. Include session identity and an export generation in the result; validate them alongside freshness. Probe the proposed temporary-directory discovery with independently launched Mac and simulator apps before treating it as established.

   The new documentation sentence also appears to promise `trace --pid` for Linux, although D5 specifies its marker and output convention only for Apple. Qualify the sentence or include the Linux implementation. 6. **MATERIAL — D6 retains the false rebuild claim and an ambiguous counter.**

   The warning still says that insertion/removal gives following rows new keys “and [they] are rebuilt.” For position-only keys, inserting at the front can reuse existing keys for different records and create just the additional trailing instance. The identity hazard is real; universal rebuilding is not. Adding “if” before insertion does not resolve Astra’s original objection. [r2:282](/Users/ccheever/projects/exact2-wt-review-1142/llp/1142-what-a-development-build-tells-an-agent.rfc.md:282)

   Separately, “committed a change” could mean successful action execution, changed logical state, or a nonempty kernel receipt. Those differ. Even the cited dispatch path can return `Ok(CommitReceipt::default())` without finding a handler. [event.rs:1190](/Users/ccheever/projects/exact2-wt-review-1142/runner/src/runner/event.rs:1190)

   **Resolve:** warn that position-dependent keys can associate retained state with different records or cause remounts. Define the dispatch counting point and the exact commit criterion, including no-ops, effects-only actions, failures, aggregation across instances, and reset behavior. Use the existing `perf` lifetime and subtree conventions where applicable.

An empty ring is also unspecified. Conversely, ring eviction requires distinguishing lost measurements from genuinely unattributed time. [r2:152](/Users/ccheever/projects/exact2-wt-review-1142/llp/1142-what-a-development-build-tells-an-agent.rfc.md:152)

   **Resolve:** track recording start and the eviction boundary separately from the oldest activity. Define treatment of an open segment at sampling time. Name the concrete layout entry points—the table still says only “the host’s kernel layout calls”—and verify their execution thread before wrapping them. [r2:165](/Users/ccheever/projects/exact2-wt-review-1142/llp/1142-what-a-development-build-tells-an-agent.rfc.md:165)
