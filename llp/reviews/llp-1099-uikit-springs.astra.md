NEEDS REWORK

1. **[BLOCKING] D2 is undefined for accepted inputs.** [RFC:104](llp/1099-uikit-springs.rfc.md:104) accepts every ζ > 0, but its zero-velocity formula gives **W = −23025.85 at ζ = 0.0001**; no positive root exists there. At ζ = u = 0.05, the initial Newton derivative is zero: [fit.mjs:32](motion/tests/fixtures/uikit-springs/fit.mjs:32) breaks, unlike D2’s specified twelve steps. Define the supported domain, zero-velocity branch, zero-derivative and non-finite outcomes, and validation of resolved coefficients. Route the new logarithm through pinned deterministic math.

2. **[BLOCKING] f32 rounding is consequential.** Contrary to [RFC:267](llp/1099-uikit-springs.rfc.md:267), running `durationW(.05,.05)` gives **5**, while rounding both arguments with `Math.fround` gives **1.299146441×10⁹**; the curves differ by approximately one whole move. Text parsing currently retains f64 ([parse.rs:269](motion/src/parse.rs:269)), whereas wire decoding uses f32 ([codec.rs:289](kernel/src/wire/codec.rs:289)). Specify one canonical precision at every ingress and build path, then recompute the fixtures under it; alternatively preserve f64 in the new tag. Quantizing only the wire breaks parity.

3. **[BLOCKING] The proposed final frame does not implement a snap.** [RFC:255](llp/1099-uikit-springs.rfc.md:255) retains linear interpolation to a final target frame; today’s [frame representation](motion/src/engine.rs:198) has evenly spaced values without explicit offsets. Using the measured reply-icon coefficients, interpolation across the final 240 Hz interval differs from the physical curve by **0.38677 moves at 197.917 ms**. Carry explicit offsets and encode the left-limit value and target at the same terminal offset. Likewise, `99.99%, 100%` in line 256 is a ramp: the CSS example needs two **100%** stops. [CSS easing semantics](https://www.w3.org/TR/css-easing-2/#linear-easing-function-output) support that distinction.

4. **[BLOCKING] `composite: 'add'` does not implement D5 for scale.** [RFC:223](llp/1099-uikit-springs.rfc.md:223) defines arithmetic residual sums, but [RFC:255](llp/1099-uikit-springs.rfc.md:255) delegates each component to CSS addition. CSS scale addition multiplies: the [WPT scale-composition fixture](https://github.com/web-platform-tests/wpt/blob/master/css/css-transforms/animation/scale-composition.html) expects underlying 2 plus effect 3 to produce 6. LLP 1063’s additive **translate** is insufficient precedent. Lower the summed scale into one absolute track, or specify and test a numeric composition mechanism.

5. **[MATERIAL] Fixed-rate sampling cannot meet the stated browser tolerance.** For the measured `100ms, ζ=.01, v=0` spring ([report:2](motion/tests/fixtures/uikit-springs/ios-27.0.txt:2)), I computed **1.368 moves** of interpolation error between 240 Hz samples, excluding the end snap. [LLP 1002:88](llp/1002-motion-v1.rfc.md:88) already makes interpolation error frequency- and amplitude-dependent. Replace D6’s blanket 10⁻³ promise with adaptive sampling and a defined resource limit, or explicitly bound supported parameters. Test between sample times; matching stored frames cannot catch this.

6. **[MATERIAL] D5’s restart equivalence excludes the proposed overdamped branch.** The textbook linearity argument is sound for equal normalized coefficients, before cuts, with the same actual injected velocity. But [D4](llp/1099-uikit-springs.rfc.md:191) gives negative-bounce components initial velocity `(v + 2ζω)Δ`. At `400ms, bounce −.5, v=0`, each new component injects **62.83185Δ units/s**, despite [D5:220](llp/1099-uikit-springs.rfc.md:220) describing only `vΔ`. Thus even zero authored velocity does not equal today’s velocity-preserving restart. Qualify the proof and distinguish the API velocity parameter from the actual derivative throughout retargeting and handoff.

7. **[MATERIAL] Velocity handoff and zero distance need executable rules.** [RFC:242](llp/1099-uikit-springs.rfc.md:242) does not say how authored velocity combines with gesture release velocity, especially when components have different or zero distances. Moreover, today’s ordinary interruption **cancels** when presentation equals the new target ([engine.rs:444](motion/src/engine.rs:444)); the explicit zero-distance velocity exception belongs to [hold release](motion/src/engine/hold.rs:326). Define velocity precedence for restart, additive retarget, opacity, release and cancel; distinguish unchanged model targets from zero presentation displacement. Add unequal-axis and zero-distance cases.

8. **[MATERIAL] D3’s critical end equation does not uniquely specify an end.** [RFC:166](llp/1099-uikit-springs.rfc.md:166) permits arbitrary velocity, but its absolute-value equation can have three roots. The supplied [bisection](motion/tests/fixtures/uikit-springs/fit.mjs:65), at ω=1 and v=1.23649, returns **3.99808 s**, although displacement subsequently reaches **0.00126794** at 5.22851 s. Specify the root, bracketing and tolerance; if “settling” means remaining inside the threshold, select the last crossing. Keep UIKit’s animation duration distinct from CA’s getter: [report:2531](motion/tests/fixtures/uikit-springs/ios-27.0.txt:2531) reports **0.58792069 versus 0.6 s**.

9. **[MATERIAL] The duration grammar leaves delayed springs unresolved.** [D1:89](llp/1099-uikit-springs.rfc.md:89) refuses a second duration, while [parse.rs:63](motion/src/parse.rs:63) always treats the first outer time as duration. Existing delayed springs use `0s spring(...) 100ms` ([holds.rs:222](host/web/tests/it/holds.rs:222)). Preserve `0s` as the no-override placeholder and define that spelling for intrinsic-duration springs. Scope the ζ>1 clamp explicitly to the duration form; response currently contradicts that blanket rule. The unit-dispatched syntax needs no fully labelled replacement, but Q4’s prefix should follow [LLP 1081’s requested rename](llp/1081-names-exact-invents.rfc.md:4).

10. **[MATERIAL] The band warning has no reproducible predicate.** [RFC:393](llp/1099-uikit-springs.rfc.md:393) leaves interpolation, margins, unmeasured ζ and out-of-grid velocities unspecified. Linear interpolation of the displayed ζ=.05 and .1 bounds yields **[.07,.13] at ζ=.06**, missing Signal’s u=.16. The dimensionless reduction is sound for normalized velocity and scale-free dynamics; it does not establish a universal band or prove that tuning cannot improve reconstruction. Define and test a conservative predicate before accepting Q1’s warning recommendation. Also provide a non-fatal diagnostic path: today’s [BadTransition generation](kernel/build.rs:1306) returns an error, not a warning.

11. **[MATERIAL] Conformance must separate parameter fitting from renderer fitting.** [RFC:522](llp/1099-uikit-springs.rfc.md:522) requires every U curve to match within 10⁻⁴, while the authored Signal duration spelling misses by **0.0595**. Feeding measured coefficients tests D4 successfully but bypasses D2. Specify those as separate tests, plus authored-string→wire→host tests using canonical precision. Check `end−ε`, `end`, and `end+ε`, delayed retargets and the 60 s boundary. Explicitly include the omitted CA ≥critical and SwiftUI-rendering tasks from §4.6 in stage 0. Older-runtime probing also needs availability guards: [probe.sh:13](motion/tests/fixtures/uikit-springs/probe/probe.sh:13) currently requires iOS 18.

12. **[MATERIAL] Several accuracy statements compare the wrong quantities.** Running the fit confirms **98.2%/99.2%**, the underdamped CA settling fit, and the S-curve residuals. Independent recomputation, however, gives worst zero-velocity relative errors **5.99×10⁻⁸ in W and 1.20×10⁻⁷ in stiffness** ([report:1955](motion/tests/fixtures/uikit-springs/ios-27.0.txt:1955)). SwiftUI versus UIKit stiffness differs by **5.37×10⁻⁸**; [fit.mjs:142](motion/tests/fixtures/uikit-springs/fit.mjs:142) instead compares SwiftUI against the formula. Only **56/60 damping values** are bit-equal. The reply icon’s **1.724** sample is at 190 ms; D4’s left limit at 200 ms is **1.77290**. Correct the metrics and replace universal “exact” claims with measured tolerances. Q2/Q5 are defensible as an explicitly pinned **27.0** choice; “iOS 17 and later” is unmeasured.

13. **[MATERIAL] Q3’s rationale confuses absolute and relative rest.** [RFC:169](llp/1099-uikit-springs.rfc.md:169) claims either ending leaves ≤10⁻³ of the move. A move of 0.0005 units already satisfies today’s absolute rest test, leaving **100% of the move** before snapping. The [10 s cap](motion/src/spring.rs:145) also permits much larger residuals: allowed `spring(100,0,1)` has unit residual **|cos(100)|≈0.8623** there. Keeping existing physical-spring semantics is defensible, but document the normalized-error and cap exceptions instead of claiming equivalent drawing.
