1. **High — Releasing another slider commits the original scrub.** [app.contract:528](/tmp/rv-dt-t2c-r3/apps/design-tool/app.contract:528), [app.ts:929](/tmp/rv-dt-t2c-r3/apps/design-tool/app.ts:929). Open a scrub on `hue`, then drag `warmth`. Its input changes `editTarget`, and `scrubFrame` correctly reports “another edit.” But `dialReleased` checks the current draft’s target, so it still calls `releaseScrub`. The mismatched identity merely skips updating `s.want`; execution continues and writes the old `hue` preview. This can happen even though `warmth` is rebuild-class and never offered a scrub. **Fix:** reject a release whose full edit identity differs from the session’s, and cancel or explicitly block switching controls during a scrub.

2. **Medium — The release value remains mutable while Keep drains the sender.** [app.ts:917](/tmp/rv-dt-t2c-r3/apps/design-tool/app.ts:917), [app.ts:929](/tmp/rv-dt-t2c-r3/apps/design-tool/app.ts:929). Release a slider at B while B’s frame is pending, then begin another drag to C before its response arrives. `releaseScrub` waits on the shared pump, while the new resource call replaces `s.want` with C. The pump previews C, and the pending release writes C—even while that second drag remains held. Comparing `shown` with mutable `want` does not preserve the released value. **Fix:** latch an immutable release operation and prevent subsequent frames from changing it, or invalidate the release when another gesture begins.

3. **Medium — Slider release during opening is still discarded.** [app.contract:528](/tmp/rv-dt-t2c-r3/apps/design-tool/app.contract:528). Press Scrub live, then drag and release before the opening response arrives. The panel exists through `scrubWant`, but `scrub.live` retains its previous false value until `scrubFrame` finishes. Consequently, `dialReleased` records nothing. Once the responses arrive, the value remains a preview until Keep or the idle timeout. **Fix:** latch release against the pending session’s identity as well as an acknowledged session, then drain and release it. Add a delayed-opening slider test; the current delayed-opening test only exercises Cancel.

4. **Medium — Resource re-entry bypasses the closing fence.** [app.ts:909](/tmp/rv-dt-t2c-r3/apps/design-tool/app.ts:909). A new session is assigned to `scrubbing` before awaiting `closing`, but only the call that increments `scrubAsked` waits. After an event gap starts closing an old, in-flight scrub, choose Scrub live again and move the control while closure is pending. The next `scrubFrame` skips that opening branch and calls `pump` immediately. Its request omits an ID, so the server can attach it to the old same-client scrub; the old cancellation then terminates the replacement. **Fix:** make the opening barrier part of the session/sender, enforced on every route into `pump`, and preserve that barrier through cancellation of a waiting session.

5. **Medium — Ended IDs from an old server run terminate fresh scrubs.** [app.ts:425](/tmp/rv-dt-t2c-r3/apps/design-tool/app.ts:425), [app.ts:1051](/tmp/rv-dt-t2c-r3/apps/design-tool/app.ts:1051). `endedIds` survives epoch changes, whereas the server restarts its counter at `scrub-1`. Let `scrub-1` expire, restart the server, then explicitly start another scrub. Its successful `scrub-1` response matches the old terminal record, so the tool drops the new session without cancelling it and displays the old end reason while the server previews. **Fix:** scope terminal records to the server token/epoch. The [stub restart](/tmp/rv-dt-t2c-r3/apps/design-tool/stub/tamber-stub.ts:187) should recreate its session manager: `lost()` currently retains the counter, masking this case. Test opening again after restart.

6. **Medium — Cancellation failures are reported as successful restoration.** [app.ts:447](/tmp/rv-dt-t2c-r3/apps/design-tool/app.ts:447), [app.ts:953](/tmp/rv-dt-t2c-r3/apps/design-tool/app.ts:953). `closeScrub` discards the cancellation result, and `cancelScrub` always returns success. If the request fails before reaching the server, the preview remains active, but the tool drops its handle, says committed values were restored, and permits reopening. That reopening can join the uncancelled session with its original digests. **Fix:** propagate cancellation errors and retain enough closing state to retry; release the fence only after confirmed cancellation or a definitive server end/restart.

Verdict: Request changes — release binding, closure fencing, and restart handling still have correctness bugs.
