**READY WITH CHANGES.**

The spine is right: the Canvas host is the app host, Material is painted, and the operating system is used for input, scrolling, insets, Back and accessibility. Several decisions cannot be built as written because they contradict each other, the principle, or the code.

### Decisions

**D1 — RIGHT.** Painting Material is the platform's look. The operating system owns the IME, fling, insets, Back, haptics, accessibility, the system font and dialogs. Amending LLP 1104 D7 for Android only is right.

**D2 — RIGHT WITH CHANGE.** Bring the reader in as `host/android/` before any Kotlin work. `apps/shelf` has no `linux/` crate. Drop "ahead of Views and Compose on cold start." LLP 1076 §7 gives that ordering low confidence, and `QUEUE.md` records the Views first frame at 11 ms while this host waits 31–46 ms on HWUI pipelines. The Canvas host is still the app host because an `ANativeWindow` cannot take an `EditText`, TalkBack or an `EdgeEffect`. "Real Views sit in one hierarchy" is draw-only: the reader puts `Natives` under `ExactView`, and `ExactView` consumes every touch, so hosted views get no input (`android-reader.md` §7). S0 has to make those views hit-testable or D8 has nowhere to land.

**D3 — RIGHT WITH CHANGE.** The swapchain host already calls `set_safe_area` once at boot (`host/linux/src/android.rs:452-456`). The Canvas `start` passes only size, scale, directory and `live`, and sets `EXACT_FONT=Roboto` (`host/linux/src/canvas/jni.rs:73-89`). `Preferences` (`runner/src/viewport.rs:170-190`) has reduced motion, contrast and dark. It has no locale, layout direction, 12/24-hour clock or bold text. Locale is `LANG` at process start (`host/linux/src/zone.rs:111-119`). Add those doors or take them out of this call. The reader's `configChanges` omits night mode, font scale, locale and density, so the activity is recreated and `start` runs again with no guard (`android-reader.md` §6). The session has to survive that. Edge-to-edge also has to set status-bar and navigation-bar icon appearance. The reader's root is white and sets no `WindowInsetsController`.

**D4 — RIGHT WITH CHANGE.** `roles::set_reported` is the right colour door (`host/apple/src/colors.rs:48`). `ButtonFace → secondaryContainer` and `ButtonText → primary` cannot paint D9's four emphases: a filled button is `primary` / `onPrimary`, a tonal button is `secondaryContainer`, a text button is `primary`. There is no type-ramp door. `textStyles` is one Apple ramp indexed by root (`kernel/tables/schema.json:4215-4219`). Reporting Material sizes and also setting the root to 16 sp times font scale either runs them through that ramp or scales twice. Android 14's font scale is non-linear per style, which is why a static table was refused. The report has to be the already-converted px size and line height. The root is that body size. The kernel must not index those numbers with `textStyleBodies`. Line height changes layout and is still `normal` on other hosts, so say that it is a per-host layout input. `placeholder` and `-exact-secondary-label` are both `onSurfaceVariant`. Tertiary and `GrayText` are both disabled-content grey. `quaternary-label` is missing. Keeping Apple's system hues ships `#007aff` on a Material surface. Map them, or leave them out of this wave. The painter has to read `AccentColor` and stop using the `#0075ff` literal.

**D5 — RIGHT WITH CHANGE.** A queue the reader drains matches a host with no JNI upcalls (`android-reader.md` §8). Picker and share results still return as downcalls. Field measurement (D8) is synchronous during layout. A drain after the frame is too late. Keep notifications in the "what works" list or take them out of the preamble.

**D6 — RIGHT WITH CHANGE.** `host_back` pops only when the id is the selected top, the depth is at least 2, and there is no navigate handler (`runner/src/runner/router.rs:686-705`). It does not close a sheet. `CanvasHost::back` presses any node whose `id` is `"back"` (`host/linux/src/canvas/keys.rs:50-66`), which is not the authored back control. Press that control when it exists. Otherwise call `host_back` with the selected visit id. Otherwise disable the callback and finish. Predictive progress waits until a route transition exists.

**D7 — RIGHT WITH CHANGE.** Reader-owned `OverScroller` and `EdgeEffect` are new work. The bench path translates the feed's `RenderNode` on the UI thread and Rust catches up (`android-reader.md` §2). Keep that. Telling the presenter an offset and waiting for a new frame drops the reason this host is fast. Do not replace the shared 4 px `SLOP` (`motion/src/gesture.rs:17`). Android supplies `scaledTouchSlop`. Desktop Linux keeps 4. Nested hand-off includes child `EditText`s and real sheets. A second pointer cancels today (`android-reader.md` §3).

**D8 — RIGHT WITH CHANGE.** A real `EditText` matches iOS, where a field is a `UITextField` (`host/apple/Sources/ExactKit/IOS/NativeFieldsIOS.swift`), and it answers LLP 1076 §7 question 4. iOS measures with the same class that draws. This reader shapes in Rust and draws glyphs (`android-reader.md` §7). Without a synchronous measure from that `EditText` into the kernel, the caret, handles and magnifier miss the glyphs. That measure is not D5. "Real whether or not focused" is right. Leaving LLP 1085 out of this document leaves the field's text engine unset. D8 is that decision for inputs.

**D9 — RIGHT WITH CHANGE.** A build-time Android look keeps the desktop pins (`presenter/control.rs:8-19` is 13×13, 38×22, 129×16). 48 dp is the hit target. Material's checkbox glyph is about 18 dp, and the button is 40 dp tall. A 48 dp layout box is the wrong tell and reflows every row. Button colours follow the D4 split. Inherited colour stays off the spinner, field, tab selection, swipe actions and bar items, which is LLP 1115 D4. Real date and time dialogs agree with D1.

**D10 — RIGHT WITH CHANGE.** Split it. Projecting a route header, a root tab list and list rows is the gap that makes an LLP 1115 D7 app look unstyled, and it can be built headless. `HeaderShape` is Swift (`host/apple/Sources/ExactKit/IOS/NavigationBarIOS.swift:27`), not a shared rule. One classifier both hosts read, or the bars will disagree. A painted top layer shared with desktop Linux contradicts D1. On Android an alert, a dropdown and a modal sheet are real windows. The presenter can paint their content. A painted sheet cannot nest-scroll with D7. Move swipe actions, pull-to-refresh, detents, scroll-to-dismiss and context menus out of this decision.

**D11 — RIGHT WITH CHANGE.** Last, and a gate before any app is called supported. Real `EditText`s and real dialogs own their accessibility nodes. The provider skips them.

**D12 — RIGHT.** `back` as an arrow is the one glyph the app bar needs. The rest of the Material Symbols set can wait.

### Missing

- Launch is a white, light-only splash (`android-reader.md` §1). §4 excludes it, and it shows on every cold start in dark mode.
- System back-gesture insets against `SWIPE_EDGE` (20 px, `motion/src/gesture.rs:13`). An authored swipe will fight predictive back.
- Keyboard and D-pad focus movement. D7.3 only hides the ring. Tab, arrows and Escape still have no path.
- `pointer` and `hover` stay at the fine/hover defaults, so a phone reports a mouse.
- `labelLarge` and `labelMedium` tracking. Material's label styles are not default tracking.

### Order

S0, then the settings that have doors, locale and direction, surviving configuration change, D4's colours, D6 without predictive back, D7.2–D7.3, and the D5 queue for links, share, clipboard and haptics. Pull a minimal D10 (the refused dialogs, the app bar) ahead of the full D9 catalog and ahead of D8. The stage table currently holds that Rust work behind reader stages the prose says it does not need.

Cut from the first commitment: the full control catalog beyond buttons and ripple, D10's swipe/refresh/detent bundle, the full symbol set, predictive back, and the type ramp until the kernel takes a reported size and line height without the Apple table.
