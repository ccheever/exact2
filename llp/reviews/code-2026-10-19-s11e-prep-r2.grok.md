## Blocking

**1. The package-file probe is satisfied by "no such file."** `scripts/stage11-gate.mjs:353-360`

The op names `../../packages/cards/cards.tamber`. The server compares that string to snapshot names (`app.tamber`) and answers `` `../../packages/cards/cards.tamber` is no file of this design `` (`tamber/src/session.rs:274-284`, echoed by `contract/cli/src/tamber_serve.rs:996`). `refusedOutside` is `/outside|package|not the app/i` against the whole error JSON, so the path's own `packages` matches. That item drops out of `pending`. `untouched()` only re-reads the two real package files, so this never checks a package path the server actually has. As soon as `add-token space.lg` is refused with `set-token` in the message (and `cards.fill` writes the app line), `server-writes` PASSes with the package-file guard untested. The `../` depth is also one short of `packages/` (`served-<pid>` is `target/stage11-gate/served-<pid>`, line 121), but the server never resolves it as a filesystem path, so correcting the slashes does not fix the check.

Fix: keep this subcheck pending until `hello`/`describe` lists the package file under the name the server uses (`@exact/cards/cards.tamber`, RFC D11). Match a diagnostic id that the request path cannot satisfy. Assert those bytes, and that no sibling file appeared.

**2. The live line reads layouts the agent took before the edit, and the race flag cannot fire.** `scripts/stage11-gate.mjs:173-213`

`agent.mjs` is given every command at spawn (line 174): `layout`, two `clock +3000 real`, `layout`, the same settle, `layout`. `clock +3000 real` is about 3s of wall time (`scripts/agent.mjs:1216-1221`); `clock data` waits on in-flight requests, not a rebuild. The queue only delays the gate's read of stdout. The agent captures the next layout on its own clock, which starts when it prints the previous layout — before this script has sent the edit. `remove-token` of a kept `space.md` is a structure change and rebuilds (`host/web/dev.mjs:570` and `:1260`). That rebuild is longer than the ~6s of clocks already running, so layout 3 is taken while padding is still 28. The line then FAILs `back === 16` on a correct return to 16. The flag at line 196 compares `edits.length` to `replies.length` before `onLayout` pushes the reply, and each earlier layout has already pushed both, so `raced` stays false.

Fix: do not issue the next `layout` until the edit has returned and the dev log has gone quiet; after `remove-token`, wait for the reload, then measure. Make the race flag compare capture time to edit completion.

## Should-fix

**3. "No reload" is the absence of two strings.** `scripts/stage11-gate.mjs:206-213`

This host logs a value edit as `batch ready … no plan` (`host/web/dev.mjs:558`) and a plan rebuild as `plan ready … pushed to N pages` (`:570`). The gate's regex is only `reloaded seq=` or `N pages reloading`. `reloaded seq=` is printed only when the page beacons and `pending` has that seq (`dev.mjs:1436-1442`). Silence in the set-token window still PASSes, and `pushed to` does not count as a reload. The evidence text looks for `no reload`, which this process does not log.

Fix: PASS the set-token window only if it contains `no plan`, and FAIL it on `plan ready` or `pushed to`.

**4. Stopping the dev loop leaves the release compiler.** `scripts/stage11-gate.mjs:92-96`, spawn at `:160`

`stop` SIGTERMs the process group and returns after 10s with no SIGKILL. `host/web/dev.mjs` does not handle SIGTERM; `killCompiler` (`:969-978`) runs only from `stop()` (`:989`), and the signal handlers that call it are in `dev-startup.mjs`, which the gate does not spawn. The compiler is `detached: true` (`dev.mjs:535`), so it survives the node process. `freePort` (`:83-88`) also closes the socket before the child binds; a stolen `--port` makes `dev.mjs` exit (`:49-53`), so that case FAILs rather than attaching to another server. The quiet loop (`:167-171`) opens the page after 60s even if the log never settled.

Fix: escalate to SIGKILL after the 10s for the process the gate owns, and shut the dev loop down through a path that runs `killCompiler`. Re-check the log is quiet before the first layout, and do not proceed on the 60s cap.

**5. Nothing fails if the fixtures stop being private.** `scripts/stage11-gate.mjs:263-400`

`packages/cards/package.json` and `packages/notes/package.json` are `"private": true`, and `bun.lock` only adds those two `workspace:*` entries. No line reads either fact. The id list in `scripts/stage11-gate.test.mjs:37` has the same hole. Dropping `"private"` or adding a publish of `@exact/cards` / `@exact/notes` leaves the gate green.

Fix: add a line that requires `"private": true` on both packages and fails if a publish script or workflow names them.

**6. The tool line will pass on a substring once any matching test exists.** `scripts/stage11-gate.mjs:364-370`

Today it correctly WAITS: no `test('…')` in `scripts/design-tool.test.mjs` matches the filter. When one does, `bun test -t` joins those titles with `|`, and the pass count is the first unanchored `(\d+) pass`, not those tests.

Fix: name the exact tests and require the filtered run's own summary.

**7. `describe.ok.tokens` is not where package rows are, so the A2 wait cannot clear.** `scripts/stage11-gate.mjs:324-330` and `:346`

`describe` returns package tokens on `meta.tokens`, a name-to-meta map (`contract/cli/src/tamber_base.rs:137-180`). There is no `ok.tokens` array with `package` and `file`. RFC D11 names a package token `<package>/<file>#<token>`. `packaged` stays false after that lands, `server-rows` keeps waiting, and `server-writes` keeps treating a real miss as WAITS-ON because `a2` never becomes true. `endsWith('cards.tamber')` would also accept a suffix.

Fix: look up `@exact/cards/cards.tamber#cards.pad` on the object `describe` actually returns, and treat "A2 is in" as that identity being present.
