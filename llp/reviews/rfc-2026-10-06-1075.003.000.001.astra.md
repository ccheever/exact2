---

The direction is workable, and the ten-operation agent API and native-language boundary are preserved. However, lifecycle, delivery, measurement and input contracts need substantive changes before implementation. The inventory is mostly accurate. Review was read-only; no builds were run.

NOT READY

1. **Major — §2.1, §4.1: teardown ordering contradicts the cited design.**  
   Hooks do run inside batches and resets: `ended` must remove additions before views enter the reuse pool. [ElementHooks.swift:86](host/apple/Sources/ExactKit/ElementHooks.swift:86) and [1075.003.000:503](llp/1075.003.000-hooks-on-every-host.rfc.md:503) explicitly require this. Deferring all moments until afterward breaks that invariant. Preserve synchronous teardown inside the protected batch/reset, while deferring acts; distinguish it from post-batch `built`/`changed`.

2. **Major — §4.3, §8 stage 5, Q6: changing the compatibility ID does not prevent incompatible delivery.**  
   The classifier explicitly says ID equality decides neither binary nor bundle admission; it checks artifact requirements against authenticated cohort capabilities. [scripts/app.mjs:1328](scripts/app.mjs:1328). Plan requirements currently omit hooks. [receipt.rs:463](bake/src/receipt.rs:463). Add hook requirements and cohort capabilities through that path, including modules with no native-view tags. Test rejection against an old cohort. Q6’s objective is sound; its proposed mechanism is insufficient.

3. **Major — §2.1, §2.4, §4.2–4.3: scope ownership is not specified sufficiently to guarantee lifetime safety.**  
   Modules are per session, and two sessions already share one physical window. [ExactHostMac/main.swift:48](host/apple/Sources/ExactHostMac/main.swift:48). Meanwhile, `context` is module-wide, yet tickets supposedly belong automatically to the calling node. [ExactNativeModule.swift:79](host/apple/modules/ExactNativeModule.swift:79). Define session versus process/window ownership, scoped registration tokens, detach/reparent behavior, and generation checks for callbacks surviving reload. Specify root-data `changed` ordering too; it is absent from the moments table.

4. **Major — §2.4, §3.1–3.3, §8 stages 1–2: logical frames and measured frames are conflated.**  
   LLP 1079 uses wall-clock observations and returns only `{"virtual":true}` under agent timing. [1079:307](llp/1079-speed-hygiene-in-the-agents-hands.rfc.md:307), [1079:362](llp/1079-speed-hygiene-in-the-agents-hands.rfc.md:362). A logical 60 Hz hook meter cannot diagnose physical jank; the proposed default-agent busy-loop smoke cannot establish a late physical frame. Linux’s `frames.rs` is a sampler, not the scheduler. Specify virtual callback ordering, timer/act interleaving, limits, and sequence meaning using [1073:74](llp/1073-every-frame.rfc.md:74). Separate logical spans from wall-time attribution and add an explicit physical-clock test.

5. **Major — §3.3, Save Trace: “since last read” violates the perf contract.**  
   LLP 1079 requires reads to change nothing; driver-side differences carry plan/incarnation identity, and percentiles describe a bounded window with dropped counts. [1079:234](llp/1079-speed-hygiene-in-the-agents-hands.rfc.md:234), [1079:356](llp/1079-speed-hygiene-in-the-agents-hands.rfc.md:356). Otherwise another reader—or Save Trace—changes subsequent results. Specify cumulative counters, non-destructive timing windows, identity/reset rules, and coherent trace capture.

6. **Major — §3.5, §8 stage 3, Q1: parts lack the input-target contract needed for trustworthy taps.**  
   A declared rectangle and closure do not establish that the native control is reachable or received input. LLP 1012 requires platform hit-testing on web/macOS; LLP 1080 requires side-effect-free aim, obstruction checks and session/incarnation validation. [1012:259](llp/1012-agent-api-v1.spec.md:259), [1080.000:270](llp/1080.000-real-touches-on-ios.rfc.md:270). Define those checks for parts, stale-target refusal, actual delivery evidence and explicit activation capability. Do not silently fall back when a platform carrier fails. The macOS activation-only acceptance test is insufficient. Prefer Q1(b) until this is specified.

7. **Major — §3.4–3.5: ownership attribution and AX joins have no identity mechanism.**  
   `owns(kind, sentence)` supplies neither a platform object nor a region; `ExactPart` supplies no view/AX reference. These cannot establish precise owned-object counts, moving geometry or AX ownership. `seal.frame` is also typically local, whereas agent geometry includes scroll and presentation transforms. [1012:247](llp/1012-agent-api-v1.spec.md:247). AX joins use actual ownership, not matching strings. [1080.002:174](llp/1080.002-the-accessibility-tree-in-the-agents-hands.rfc.md:174). Specify weak object bindings, coordinate conversion and update rules; distinguish declarations from observations. The claimed existing recognizer audit is absent: [ElementHooks.swift:191](host/apple/Sources/ExactKit/ElementHooks.swift:191).

8. **Major — §2.2, Q3: the painting overlay needs a protocol, not merely the Canvas list format.**  
   Existing Canvas lists mutate persistent pixels, state, paths and resources; they carry lifetime, size-generation and sequence information. [1056:46](llp/1056-canvas-2d.rfc.md:46). Replaying “the latest recording” is ambiguous and can repeat blending or lose prior state. Specify replacement versus incremental recordings, resizing, invalidation, clipping/stacking, resource lifetime and backpressure. Also define pointer-stream ownership and cancellation; offering each event before Exact does not itself preserve scroll/gesture precedence.

9. **Major — §3.2, §3.6, §4.1: diagnostics are not yet demonstrably bounded.**  
   Limits on metric names do not bound samples, unfinished spans, log bytes, rejected-name bookkeeping, queued cross-thread records or parts/regions. Percentiles lack a retention algorithm; the lock-free ring lacks capacity and overflow semantics. “Refused once by name” can itself accumulate unlimited names. Specify byte/object limits, dropped counters, timestamp capture, retirement behavior and trace-request coalescing. Add overflow/concurrency tests and a measurable overhead acceptance threshold rather than “within noise.”

10. **Major — §4.4, §9: Rust recovery will not work in the shipped profiles, and disabling calls is not cleanup.**  
    Release uses `panic = "abort"`; `host-dev` inherits it. [Cargo.toml:45](Cargo.toml:45), [Cargo.toml:110](Cargo.toml:110). `catch_unwind` tests under another profile would give false confidence. Also, a throwing hook may already have installed recognizers, callbacks or reusable-view additions; suppressing future calls can suppress teardown. Specify the actual panic policy and a safe failure lifecycle, then test production-equivalent behavior and partial mutations.

11. **Major — §4.4: the next-launch crash breadcrumb is underspecified.**  
    A fixed in-memory slot alone does not survive termination. The proposal also omits clearing/restoring it after successful or nested calls, and distinguishing crashes from normal termination or unrelated later failures. Without that, “ended inside hook” can falsely blame the last hook. Specify crash-safe persistence, session/call identity and validity rules; test genuine process termination. Qualify the “one store” cost claim.

12. **Major — §2.6: module-load failure is not equivalent to hooks being disabled.**  
    The same module supplies native views and calls. Missing factories leave unavailable empty boxes, not behaviorally equivalent controls. [1024:206](llp/1024-native-modules.rfc.md:206). Separate hook-only disabling from whole-module failure, define their respective diagnostics, and state the author’s fallback obligation. A fixture reaching equivalent states cannot establish that arbitrary module-dependent apps survive failed loading.

13. **Major — §2.5, §3.2, §4.5, Q5: privacy and production gating conflict.**  
    Automatically journaling `input "…"` records passwords and other field contents, contrary to existing protected-value handling. [1080.002:281](llp/1080.002-the-accessibility-tree-in-the-agents-hands.rfc.md:281). Log the operation/target without the value by default. Also reconcile production diagnostics in §3.2 with §4.5’s development-gate claim and LLP 1079’s production collection-off rule. [1079:173](llp/1079-speed-hygiene-in-the-agents-hands.rfc.md:173). Q5 should separate counters, payload logs and crash breadcrumbs; disabling diagnostics need not remove crash attribution.

14. **Major — §5, §8: packaging work and platform validation are understated.**  
    Windows has its own entry point, window lifecycle and frame loop; it cannot inherit all hooks merely through a generated Linux entry file. [windows/lib.rs:9](host/windows/src/lib.rs:9), [windows/window.rs:195](host/windows/src/window.rs:195). Specify that adapter and a running Windows test. Web discovery/scanning currently accepts only `index.js`, then copies the module directory unchanged. [web-js/build.mjs:86](host/web-js/build.mjs:86), [web-js/build.mjs:508](host/web-js/build.mjs:508). Make TypeScript support explicit new work. Define how per-platform hook availability is known; the global word list does not reveal which words each implementation handles.

15. **Minor — §1.1, §4.1, §4.5: correct several factual claims.**  
    Module construction is eagerly prepared after first draw, before `dataReady`, rather than waiting for the first view/call/hook. [Session.swift:1167](host/apple/Sources/ExactKit/Session.swift:1167). Internal logging is not inaccessible to app sources compiled into the same Swift module. [ExactNativeModule.swift:158](host/apple/modules/ExactNativeModule.swift:158), [build.mjs:1077](host/apple/build.mjs:1077). The thread check silently returns, rather than asserting. [NativeHooks.swift:60](host/apple/Sources/ExactKit/NativeHooks.swift:60). Static web distributions do not automatically receive grant-derived policy headers. [1069.008:241](llp/1069.008-permissions-from-grants.rfc.md:241).

16. **Minor — §10: the decision questions need sharper boundaries.**  
    Q2 is sound with the targeting and redaction fixes above. Q4 should leave Android’s shape provisional: its cited research explicitly includes hybrid rendering, which does not fit a host-wide object/painting dichotomy. [1076:201](llp/1076-android-rendering-choices.research.md:201). Add an explicit ruling on node-scoped frame subscriptions relative to the deferred per-node-frame restriction, rather than implicitly broadening it. [DEFERRED.md:556](rules/DEFERRED.md:556). Any exception should state its boundary and required take or waiver.

R2 substantially improves r1: synchronous teardown, non-destructive perf reads, production gating, Rust abort handling, and the delivery-classifier approach are corrected. However, several r1 findings remain only partially resolved, and the revision introduces lifecycle and clock contradictions. Review was read-only; no builds were run.

NOT READY

1. **Major — §2.4: callbacks observe the wrong virtual instant (r1 A4/G2 incomplete).**  
   RFC lines 329–341 replay ticks and `after` callbacks only after the seek’s commits, against its final state. Thus `clock +1000` differs from smaller seeks: earlier callbacks see later data, `context.now()` is already advanced, and callback-created timers/acts cannot interleave correctly. This conflicts with `llp/1073-every-frame.rfc.md:79`. **Resolve:** yield at each due callback, apply that instant’s commits, run callbacks and drain eligible acts before advancing; test seek partition equivalence, chained `after`, cancellation and `frame.seq`.

2. **Major — §2.1, §2.7: the teardown correction overgeneralizes container ordering.**  
   RFC lines 175–182 and 427 prohibit every built/changed hook inside a batch. Existing container hooks supply construction decisions synchronously: `showsBar` in `NavigationBarIOS.swift:384`, and the returned tab container in `NavigationTabsIOS.swift:114`. Initial installation runs inside the batch (`PresenterIOS.swift:783`). LLP 1075.003 explicitly requires these hooks before child layout (`…merged.plan.md:351`). **Resolve:** preserve the container-specific moments; distinguish them from post-batch element hooks and queued acts.

3. **Major — §2.5, Q2: agent `type` is not a usable cross-platform hook entry.**  
   Web typing uses driver-side CDP `Input.insertText` (`scripts/agent.mjs:491`), unavailable to a production page module. On iOS, the entry makes the authored field first responder (`IOS/AgentIOS.swift:849`), potentially stealing focus from the motivating native search controller. **Resolve:** specify a production editing primitive, its focus/composition semantics, and the browser implementation; share appropriate validation with agent typing. Test actual native-search forwarding.

4. **Major — §2.6 versus §4.3, Q6: optional platform hooks become mandatory delivery requirements.**  
   RFC lines 414–418 allow a hook without counterparts, but lines 674–680 require every marked word in every target cohort. An Apple-only hook therefore blocks updates to a hook-less Linux cohort, including unrelated updates. **Resolve:** distinguish intentional platform fallback from a missing required implementation, and derive requirements accordingly. Test both cases.

5. **Major — §5: handled-word capabilities lack a reliable build-time extraction mechanism (A14 incomplete).**  
   Bun’s cited scan discovers export **names**, not the values of `export const hooks` (`host/web-js/build.mjs:92`). Apple’s existing roster probe executes a macOS build even for iOS and can fall back to the manifest (`host/apple/build.mjs:1080`); that cannot establish an iOS-specific computed `class var hooks`. **Resolve:** define target-authentic, statically extractable declarations or artifact metadata, including cross-compilation and empty rosters. Do not silently substitute the global manifest list.

6. **Major — §2.1.1: session count does not establish window ownership (A3 incomplete).**  
   RFC line 197 grants whole-window styling whenever only one session uses it. A single embedded Exact view may still share its window with native UI; the sample host already contains an embedder-owned table and window (`ExactHostMac/main.swift:38`, `:61`). **Resolve:** make exclusive window ownership an explicit embedder grant, defaulting to restricted access. Also define process-wide appearance ownership and attachment changes.

7. **Major — §2.5: sixteen settle rounds do not bound a FIFO drain (G7 incomplete).**  
   RFC lines 375–387 specify neither queue capacity nor a per-drain work limit. A changed hook can enqueue a click whose commit invokes the hook again; draining until empty never reaches the round limit. Web microtasks can similarly starve the event loop. **Resolve:** bound queued items/bytes and work per pump, defer newly queued work to a later bounded round, and define overflow/refusal behavior. Test self-enqueuing acts.

8. **Major — §3.2–§3.6: observability remains incompletely bounded (A9/G16 incomplete).**  
   Metric quotas are concrete, but `owns` registrations and descriptions have no limits; appearance regions can accumulate indefinitely. Parts have an output truncation threshold, not a registration/field-byte bound. Cross-thread records have an entry count without a byte bound, and the recognizer walk has no traversal budget. **Resolve:** specify storage, field, traversal and whole-reply limits, with deterministic overflow policies and tests.

9. **Major — §4.4: the persisted breadcrumb is unsafe across sessions (A11 incomplete).**  
   RFC lines 699–706 prescribe one `hook-breadcrumb` file mapped at session start and truncated at session end. Non-agent module temporary directories are shared by sessions (`NativeModule.swift:462`); ending one session can erase another’s evidence and invalidate its live mapping. Stack overflow and interrupted record publication are also unspecified. **Resolve:** define process-owned or isolated mappings, atomic validity publication, overflow handling and cleanup ownership; test two sessions and termination during push/pop.

10. **Major — §3.5, Q1: landing evidence does not identify the intended part (A6 incomplete).**  
    A pre-input aim plus the touched view’s class cannot distinguish two same-class parts under one node, or a replacement between aim and delivery. Existing `TouchLog.landing` reports node/class/session, not hook-part identity (`IOS/TouchIOS.swift:54`), and explicitly does not observe recognizer outcomes (`:5`). **Resolve:** carry a part binding token through aim and actual dispatch verification, reject mismatches, and specify any new recognizer instrumentation. Test replacement and obstruction after aiming.

11. **Minor — §3.5: absent accessibility exposure is not “unnamed interactive.”**  
    RFC lines 578–581 assign that finding to a view exposing no AX element. LLP 1080.002 defines it only for an **exposed** interactive element with an empty name (`…accessibility-tree-in-the-agents-hands.rfc.md:294`). **Resolve:** report the part as unjoined/not exposed with coverage information; preserve the four existing findings unless explicitly amended.

12. **Minor — §3.1–§3.3: per-word timing cannot answer per-site perf queries.**  
    RFC line 449 aggregates by word/moment, while line 518 promises hook time on each plan site. Two sites using `hook="avatar"` cannot be separated afterward. **Resolve:** retain site identity in automatic measurements across node retirement, define inclusive/exclusive timing, and specify aggregation into `perf <target>`.

13. **Minor — §2.2.1: overlay publication lacks an explicit repaint trigger.**  
    RFC lines 265–269 publish for the “next paint,” but do not require waking an idle presenter or invalidating after image resolution. A hook-only visual update may remain invisible until unrelated activity. **Resolve:** define dirtying, frame scheduling and asynchronous resource invalidation; test `draw` and `clear` while the Contract app is idle.

14. **Minor — §1.2: “No app line reaches the journal” is false.**  
    RFC line 134 contradicts its corrected §1.1 inventory. App Swift shares `ExactAppModules` and can call the internal logger (`ExactNativeModule.swift:255`; `NativeHooks.swift:77`; `build.mjs:1077`). **Resolve:** say there is no public, supported diagnostics API. Also correct the static `Permissions-Policy` citation in §4.5: that discussion is LLP 1069.008 **D6**, not D4.

15. **Minor — §8–§9: tvOS remains outside the proposed validation.**  
    The RFC promises the expanded Apple surface on tvOS, acknowledges no module test there, and then specifies only iOS/macOS/web acceptance. **Resolve:** add a tvOS fixture build-and-launch exercising supported scopes, lifecycle and diagnostics, with explicit unsupported input behavior. Name the implementer when implementation is approved.
