## Findings

1. **should-fix.** A wasm worker abort that rides a turn result is discarded with that result, and nothing else can see it. `finish` moves every pending door-22 ticket into the result and empties the array (`host/web/module-worker.js:135`). The worker realm has no `aborted` method (`host/web/module-glue.js:464-481`), so `call`'s `'aborted'` op returns an empty list (`host/web/module-glue.js:517`). `Module::take_aborted` polls the realm only for `Placement::Main` (`js/web/src/lib.rs:835-843`). A superseded or forgotten continuation never reaches `step`: `fulfill_now` logs the reply and returns before parse (`runner/src/runner/commit.rs:1200-1205`). `note_aborted` therefore never runs, and a still-pending fetch of another target keeps its connection. Native placement closed this with a side channel that is filled before `reply.send` (`data/src/placed.rs:397-404`); the wasm worker has no equivalent. The page realm is safer only for tickets still in the array: `finish` and `realm.aborted` both `splice(0)` the same array (`host/web/module-glue.js:230`, `:382`), and a second sighting is a no-op because `note_aborted` has already swap-removed that ticket (`js/web/src/lib.rs:175-178`).

2. **should-fix.** The web host hears aborts after it has stopped answering them, and it does not schedule another pass. `Host::complete` drains `take_aborted_answer` and only then calls `take_requests` (`host/web/src/host.rs:1020-1024`). `take_requests` is what hears (`runner/src/runner/commit.rs:945-946` → `background.rs:130-131`). If that hear fills `module_aborts` and `immediate` is empty, the loop breaks (`host.rs:1031-1032`). `explicit_aborts` is filled only inside `take_aborted_answer` (`runner/src/runner/admission.rs:140`), so this batch emits no `abort` (`host.rs:1050-1051`). Apple and Linux wake after that same collection (`host/apple/src/abi.rs:311-315`, `host/linux/src/presenter.rs:862-866`); the web host does not. The next entry, if it is that fetch's own reply, removes the pending row before `complete` (`host/web/src/host.rs:1291-1296`, `commit.rs:1228`) and `take_aborted_answer` skips a ticket that is no longer pending (`admission.rs:137-138`). The body is committed and the cancel is never sent.

3. **should-fix.** The server render runs the same executor and never settles an abort. `settle` hands requests out and fulfills replies (`host/render/src/lib.rs:793-810`). `hand_out` calls `take_requests`, which hears into `module_aborts` (`lib.rs:855-858`), and then neither takes an abort answer nor cancels. Nothing in `host/render` calls `has_module_aborts`, `take_aborted_answer`, or `cancel`. An aborted fetch stays in flight until the real reply or the render deadline, and the answer does not resume at the abort.

4. **nit.** `Module::unload` clears `parked` and `host.requests` and leaves `host.aborted` (`js/src/lib.rs:705-707`; the drain is `lib.rs:761-768`). A new engine starts `nextTicket` at 1 (`js/src/prelude.js:435`). `activate_for_validation` unloads and reactivates that same object (`js/src/source.rs:180-187`), so a door-22 ticket still in the vec can name a new fetch that reused the number. A live reload does not use this path: `replacement` builds a new `Module` (`js/src/source.rs:190-201`), and a host that still has pending work is refused (`host/apple/src/abi.rs:707-708`).

5. **nit.** WebSocket lookup calls `off_thread(signal, None, …)` (`vendor/ibex/crates/ibex2/src/transport/websocket.rs:417-420`). The deadline checks in `Pool::run` (`lookup.rs:140-145` and `:181-182`) therefore do not run for it. Abort still returns the caller at once (`websocket.rs:424-425`). An unaborted hung `getaddrinfo` blocks that connect and holds one of the four helpers until the OS call returns. Fetch passes a deadline (`rustls_http.rs` resolver).

## (a) Identity, loss, wake

Clean for identity. `hear_aborted` binds `(Target, module fetch)` to the runner ticket only while that pending row has the same target, `fetch == Some(fetch)`, no continuation, and no stream (`admission.rs:104-116`). `take_aborted_answer` delivers a ticket that is still pending and leaves it out of `explicit_aborts` otherwise (`admission.rs:134-149`). The regression test fulfills the real reply first and requires the fallback fetch to be untouched (`js/tests/it/abort.rs:189-208`).

A re-ask of the same target removes the old pending row before inserting the new one (`commit.rs:854-859`). Two targets with equal arguments are two keys; the native and wasm keys both start with the target. Within one engine `nextTicket` only increments. A new module is a new `HostState`, so a reset counter does not see the old abort list. `hear_aborted` uses `find` against one pending row per target.

Apple `emit` and the Linux presenter (Android uses that presenter) hear during `take_requests` and notify when `has_module_aborts` is set. That wake is in place. The holes that remain are findings 1–3: the worker result that is never parsed, the web batch that hears and then stops, and the render loop that hears and never answers.

## (b) Worker placement

Clean on the native owner. After each turn the owner takes aborts and extends the `Arc<Mutex<…>>` before `reply.send` (`data/src/placed.rs:397-404`). `Placed::take_aborted` drains that mutex while an owner exists, and drains the inner source when there is no owner (`528-534`). The discarded-reply test reads `[(Mutation(0), 7)]` after the reply is dropped (`1009-1022`). The envelope carries `Request.fetch` only. `wasm32` refuses this placement (`643-646`). A moved source whose `inner` is gone cannot be replaced (`909-911`). A built replacement is a new `Placed` with a new mutex (`210-228`); dropping the old one closes the channel and does not wait (`916-920`). A swap while requests are pending is refused unless the session is let go (`host/apple/src/abi.rs:707-708`), so the old mutex is not required to feed the new module. `Job::Forgotten` does not record door 22; let-go is the host forget path.

## (c) wasm

Page double delivery is clean, including a mapper. `message()` returns `finish()`, which splices (`module-glue.js:396-404`), and that result goes through `step` → `note_aborted` (`js/web/src/lib.rs:287-323`, `:359`). A background round does not splice its own return (`module-glue.js:308-323`); those tickets stay for `realm.aborted` (`:382`), which `take_aborted` polls on the main placement. `unindex` runs on page finish and forget and on worker finish and forget (`module-glue.js:244`, `:409-421`; `module-worker.js:144`, `:155`). An untargeted key (`[null, …]`) does not parse as a target (`js/web/src/lib.rs:184-190`). The open hole is finding 1.

## (d) ibex2 lookup

Clean. The deadline and the abort are checked before `*count += 1` (`lookup.rs:140-146`) and again before a `Found` answer is accepted (`:180-182`). An answer that arrives after `expired()` is `TimedOut`. `Slot`'s `Drop` frees the pool once and sends `Message::Ended` only if the helper did not already take the sender (`51-57`). Spawn failure drops that same slot (`164-169`). A panic drops it too and the parent sees `Failed("the lookup ended without an answer")`. `waiting` is incremented only when the waiter observed a full pool, and decremented once on the way out (`121-137`). `AbortSignal::abort` releases the signal lock before callbacks, and the lookup callback takes the count lock only to `notify_all`, so the condvar wait cannot deadlock with abort. Fetch maps `Aborted` / `TimedOut` / `Failed` onward. The tests cover a passed deadline that starts no lookup, a fifth waiter that observes `waiting() == 1`, and a panicking lookup that returns the helper. Finding 5 is the websocket caller passing no deadline.

## (e) Executor, ordered lane, streams, compatibility, docs

Clean.

Explicit cancel of a queued non-work job decrements `counts`, streams, and bytes once and removes the job (`host/apple/src/executor_core.rs:700-708`). A running exchange is marked forgotten and its transport is claimed; the count is released once when it ends, in `complete` (`1068-1077`) or in async `settle` (`1098-1101`). `physical` then adjusts bytes only (`1158-1176`). `cancel` on an empty slice returns immediately (`683-686`). Calling `cancel` and then `forget` does not decrement twice: the queued job is already gone, and a running job is only marked forgotten.

The ordered lane stays occupied until that end. `ordered_idle` is `counts[0] == 0` (`784-785`), not the length of the deque. `ordered.retain` removes the ticket at cancel (`748`) so a later drain cannot `pop_front` it. A forgotten settle does not pop. The next ordered job waits on the count, which matches the docs: the app's logical slot is free when the fetch rejects, and the host's connections, per-origin places, and ordered lane return when the transport ends (`docs/reference.md:1028-1045`).

Streams are excluded in the prelude (`js/src/prelude.js:563-564`), in `hear_aborted` (`admission.rs:108-109`), and in the executor (`exchange` is unset for a stream, `executor_core.rs:1041`; async `cancel` requires `!run.stream`). Continuations, timers, yields, and the waiting park use tickets `0` and `u64::MAX-1` downward and store `fetch: None`. A module-wide re-park does not match `parked.ticket == abort ticket`.

`TYPESCRIPT_RUNTIME` is 5, with the comment that an older prelude would leave the request running and drop the reply, a 429 included (`bake/src/compat.rs:38-50`). The reference names runtime 5 and the capacity caveat in the same paragraph (`docs/reference.md:1042-1045`). `dev-gallery.test.mjs` is not in `1df7ab7829..7fb398f447`.
