The direction is sound, but D3 and D5 undershoot the goal: Exact2 should make polished apps cheaper to produce, beyond explaining how builders can improve them.

1. **D1 — RIGHT WITH CHANGE.** Fix both regressions. Explicitly constrain the inset change to native safe-area integration; “a scroller’s content box excludes its inset” must not become a new universal layout rule. Preserve CSS sizing and authored overrides while making native content comfortably visible. Judge the result against a hand-built screen, rather than copying the web’s margin numbers as authority.

2. **D2 — RIGHT WITH CHANGE.** Teach the complete save lifecycle: retain input and keep the form open until success, show refusal where the person is editing, and clear stale errors after recovery. The current [navigation recipe](/Users/ccheever/projects/exact2/docs/recipes/navigation-stack.md) immediately navigates back after sending, so correcting draft clearing alone leaves the same failure elsewhere. Also change “a create or edit form is a sheet” to guidance for substantial creation flows. Chat composers, quick-add fields, and desktop editing need other arrangements.

3. **D3 — RIGHT WITH CHANGE.** The distinction between controls and content is correct, but another recipe is insufficient. “Deliberate design is allowed” already appears in the core, yet [weather](/Users/ccheever/bakeoff/rounds/r2/grades/weather/grade.md) still loses despite stronger native presentation. Ship a small, opt-in set of reusable Contract components or compositions: summary/stat displays, primary-and-secondary row content, comparative bars, and empty states. Give them good spacing, role colours, accessible type, and sensible narrow/wide arrangements. Authors choose the composition and retain control. Validate actual screens; compiling and passing `no-tells` cannot establish visual quality.

4. **D4 — RIGHT.** Both changes repair missing affordances with little additional author knowledge. Back completes the router’s existing promise, and visibly actionable links are basic web presentation. Keep these defaults subordinate to authored presentation and preserve normal browser navigation. This is a strong example of improving quality without increasing application code or required reading.

5. **D5 — RIGHT WITH CHANGE.** Cover those questions, but make precise retrieval the objective rather than the number of recipes. Extend the existing `contract vocab` approach to functions and declarations: one requested operation, its signature, a minimal example, and relevant constraints. Avoid requiring an entire function catalogue for `slice`. In the [19-pair anatomy](/Users/ccheever/bakeoff/rounds/r2/findings.md), recipes already contribute about 300 KB of reading versus 250 KB from long guides. Moving material between files does not necessarily reduce total context or lookup turns.

The larger missing levers are:

- **Reusable working patterns instead of repeated reconstruction.** Make the common list/detail/create flow and read/write/error lifecycle available as maintained, selectable starting patterns using existing mechanisms. Move the core’s complete CRUD/storage tutorial behind that selection and keep required reading focused on essential rules and choosing a pattern. This attacks both repeated boilerplate and the larger input cost: everything learned early is replayed through later turns. The evidence supports prioritizing this experiment; it does not yet quantify its savings relative to D5.
- **Screen structure and adaptation as part of D3.** A hero card cannot fix a stretched phone interface. [Contacts](/Users/ccheever/bakeoff/rounds/r2/grades/contacts/grade.md) loses partly to a desktop list/detail arrangement; habit-tracker’s desktop creation page is mostly empty. Include an explicit adaptive composition alongside the content examples. The framework should supply reusable choices without silently centring every page or changing bare CSS defaults.
- **Close the remaining observed behavior gap.** [Chat rooms](/Users/ccheever/bakeoff/rounds/r2/grades/chat-rooms/grade.md) opens long conversations short of the newest message. Investigate whether the documented scroll behavior fails and fix it if confirmed. That is a concrete quality loss omitted from the decisions.

The main risks are replacing “design nothing” with another universal scaffold, making every edit modal, and growing mandatory reading while claiming token savings. Literal authored design must remain valid under **author > platform > CSS default**; `no-tells` should not become a prohibition on it.

**Overall: READY WITH CHANGES:** bound D1’s layout scope; broaden D2 to save completion and qualify sheet guidance; add reusable, adaptive content compositions to D3; make D5 reduce total reading and lookup turns. Round 3 should report, by stack, how often Exact2 is **simultaneously cheaper, faster, and preferred**, keeping backend comparisons separate.
