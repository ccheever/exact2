## Findings

1. **MAJOR** — `aria-labelledby` targets are read and not recorded. `recordReads` stores only `popovertarget` and `commandfor`, and only on buttons (`ToolbarReadsMac.swift:147`). `authoredLabel` resolves `accessibilityLabelledBy` through `chrome.named` and reads that node's label or `accessibleText` (`Accessibility.swift:41`). The bar uses that for the status readout's overflow and accessibility name (`ToolbarMac.swift:601`), the segments group's name (`HeaderMac.swift:218`), the search item's name (`HeaderMac.swift:283`), and the lent search field's accessibility label (`NativeFieldsMac.swift:243`). The referenced node usually sits outside the header and popover subtrees. A paragraph or props change on it fails `concerns` and leaves `BarInputs` alone, so the overflow name and VoiceOver name stay at the last present. Storing the id string would still miss a text change on the resolved node; the invocation path subtrees its target, and this path does not. Changing `accessibilityLabelledBy` on the bar node itself is a hit, because that node is already in the set. `BarReadsMacTests` never moves an external label.

2. **MAJOR** — The shadow does not compare everything the bar shows, and its present repairs the live bar. `shadowCheck` (`ToolbarReadsMac.swift:191`) snapshots, calls real `sync()` (which presents and rewrites `reads` and `inputs`), then restores only `presents`. `present()` does not consult `BarReads`, so a field the snapshot includes still fails the test when it changes. `shadowState` (`:211`) omits the search item's label, placeholder, and enabled bit, the segments group's label and the tab titles (the segments line at `:218` is ids, selection, and enabled only), `backgroundTintColor` (`ToolbarMac.swift:376`), and the accessibility enabled bit (`syncAccessibility` is skipped while shadowing, `ToolbarMac.swift:709`). Search and segments items are not in `items`, so the item loop never sees their names. Under XCTest the live bar is updated anyway; `testARowFillOutsideTheBarsReadsDoesNotPresentIt` asserts the present counter, which was restored. A missed search or segments name is corrected in the test process and stays stale in release. The same hole covers prominent accent tint: `NSColor.systemColorsDidChangeNotification` (`Session.swift:548`) re-reports colors and calls `systemColorsChanged` without syncing the toolbar, and `backgroundTintColor` is absent from the snapshot, so a report batch that touches no read node both leaves the tint stale in release and hides the change under the guard. The guard is absent from release builds.

3. **MINOR** — A `present` opacity on a painted header child is ignored (`ToolbarReadsMac.swift:89`) while `MacBarFace` folds `child.alphaValue` into the item image (`BarFaceMac.swift:68`). That alpha is applied from the opacity present op (`PresenterMac.swift:1268`). The item image keeps the alpha from the last real present. The shadow's image hash would fail such a skipped batch; the reported zero mismatches mean the suite never skipped one. A style op that sets opacity still presents.

4. **NIT** — `unplaced` (`ToolbarReadsMac.swift:65`) presents on any props, style, paragraph, or children op aimed at a viewless node this batch did not create, whether or not the bar read it. That keeps viewless bar content correct and is one pass over the batch. A props update on a viewless node elsewhere in the page still presents the bar. The measured transcript fill does not hit it.
