**MATERIAL findings**

1. **A refused open can release the current owner’s SQLite locks.**  
   [js/src/native_storage.rs:111](/private/tmp/claude-501/-Users-ccheever-projects-exact2/3075bb39-112b-4b60-a056-edc166a1f89f/scratchpad/laneA/capsule/js/src/native_storage.rs:111) calls `resolve_sqlite` before checking the reservation. On Unix, `AppDirectories::sqlite_path` opens and drops the existing database file (`vendor/ibex/crates/ibex2/src/stdlib/app_fs_unix.rs:398`). Closing that descriptor releases the process’s POSIX locks on that file, including locks held by the other SQLite library. The reverse order has the same defect: `sqlite_abi.rs:173` resolves the path before calling `Reserving::open`.

   Consequently, returning the expected refusal still permits the corruption mechanism this reservation is meant to prevent. **Fix:** resolve and validate the filename without opening and closing the database, and check/reserve it before any database-descriptor operation. Add a regression that verifies an existing owner’s locks survive a refused open. The current fixture’s ordinary `File` and string assertions cannot detect this.

2. **The registry distinguishes names that identify the same file.**  
   [js/src/native_storage.rs:48](/private/tmp/claude-501/-Users-ccheever-projects-exact2/3075bb39-112b-4b60-a056-edc166a1f89f/scratchpad/laneA/capsule/js/src/native_storage.rs:48) canonicalizes only the parent, then appends the filename unchanged. On a case-insensitive filesystem, `vault.sqlite` and `VAULT.sqlite` therefore get different registry entries while opening the same database. With `sqlite.open app:/data`, both are admitted. Hard-linked filenames likewise bypass the exclusion; the resolver accepts regular files without rejecting hard links.

   **Fix:** make reservation identity follow the actual file, including aliases, while preserving exclusion before a new file exists. Cover case aliases and hard links in both opening orders. Parent canonicalization correctly handles `/tmp` versus `/private/tmp`, but does not solve these cases.

3. **Rust data sources bypass the reservation entirely.**  
   [data/host/src/native.rs:128](/private/tmp/claude-501/-Users-ccheever-projects-exact2/3075bb39-112b-4b60-a056-edc166a1f89f/scratchpad/laneA/capsule/data/host/src/native.rs:128) opens the bare `ibex2_sqlite::SqliteProvider`. Only the TypeScript storage session installs `Reserving`. This is reachable in a mixed app: `data/src/mixed.rs:945` supplies both sources with the same storage roots. A Rust storage request can consequently open a file held by the native module; a concurrent Rust connection is also invisible to `NativeStorage::sqlite`.

   **Fix:** have the Rust storage path participate in the same reservation before touching the database, and test mixed-source exclusion. The implementer’s open question is a merge blocker: the safety requirement concerns the file and process, regardless of the source language.

4. **Dependency changes can leave the generated factory stale or bypass `bake-native-twice`.**  
   [contract/cli/src/native/slot.rs:40](/private/tmp/claude-501/-Users-ccheever-projects-exact2/3075bb39-112b-4b60-a056-edc166a1f89f/scratchpad/laneA/capsule/contract/cli/src/native/slot.rs:40) skips declarations without `native` before registering a watch. It also never watches the dependency’s `package.json`, although that file selects the declaration.

   For example, build with native package A and plain package B, neither imported by TypeScript. Add `native` to B’s declaration without changing the app manifest. If A is encountered first, `nativePackage` still returns A, the shell stamp stays unchanged, and the bake has no watch on B’s declaration: the next build can succeed without issuing `bake-native-twice`. Changing A’s export to another retained declaration can similarly preserve the old factory.

   **Fix:** watch every package manifest and declaration consulted during selection, including negative results, so dependency changes rerun selection. Add incremental-build coverage; the current test only invokes the selector afresh.
