READY WITH CHANGES

Round 1 is resolved. The arriver keeps `slot.bounds.size`, `FlightScale.of` scales from that layout size, an interrupted flight captures the clip (on macOS the unscaled clip, so an unlayered content view still yields the shown box), place-went stands the view at the clip’s top left at its own size, and `applyTransform` puts `FlightLook.scale` back after AppKit clears the layer transform in `layout`, `updateLayer`, and `draw`. The new tests reach those paths. Hit-testing still ends at the flight layer, the clip, and the slot. An iOS anchor that is off-centre stays top-aligned because position is `anchor × layout × scale`. The macOS layer-backed anchor stays `(0, 0)`, the top left of a flipped view, so the scale grows down and right. A second interruption takes the same clip snapshot. `forgetFlight` and `resetFlights` drop the clip, and the reduced-motion guard returns before a clip is created. Two should-fixes are new.

1. **should-fix** — `PaintOrder.swift:111`, `FlightsIOS.swift:262`, `FlightsMac.swift:234`. `rankChildren` assigns a `zPosition` only to a `NodeView` or a `paintForeground` child. The clip is neither, so it stays at `zPosition` 0 while the node’s rank is applied only among the clip’s own children. A sublayer `zPosition` orders layers inside the clip. Sibling flights see the clip at 0, so two cards, or a card beside an image that is a direct child of the flight layer, stack by subview order and ignore `z-index`. The flight layer’s own `setPaintForeground` is unchanged, so the layer stays above the document plane. Rank a `FlightClip` from the contained node’s `paintRank`, in the same dense space as those image flights, and when that rank changes refresh the flight layer (the clip’s superview) as well as the clip. Leave the node’s own `zPosition` so its filter picture stays with it.

2. **should-fix** — `FlightsMac.swift:261`, `NodeViewMac.swift:738`. `showFlight` sets the view’s frame to the full layout size at the clip origin and scales only the layer. `accessibilityFrame()` uses that view frame: with no canvas placement it falls through to AppKit, and `drawnRect` converts through view frames, which ignore the layer scale. VoiceOver therefore gets the unscaled card, hanging out of the shown box. iOS already sets `accessibilityElementsHidden` at lift (`FlightsIOS.swift:251`) and restores it on land. On macOS, save `isAccessibilityHidden()` at lift, call `setAccessibilityHidden(true)` (the same call the exit path uses), and restore the saved value on land and on the place-went path.
