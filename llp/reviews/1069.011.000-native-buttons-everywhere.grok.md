## Findings

1. Blocker. Tab and segment projection still decide from child views, and a native button has none.

`TabBarFace` requires exactly two child views, a `symbol:` image and a paragraph (`SegmentsIOS.swift:39-48`). `segmentFace` returns an image only for exactly one image child, and a title only when the children are non-empty paragraphs (`Accessibility.swift:44-50`). A native button's children are not views (`paragraph.rs:8-23`, `309-311`), so both initializers return nil, `tabs()` never sees `kind == "control"` (`SegmentsIOS.swift:91-95`, `SegmentsMac.swift:33-37`), and the tablist stays authored. The D10 test that requires a tab bar and segments then fails. `SegmentFace.image` holds a `NodeView` (`Accessibility.swift:36`) that the segment code snapshots (`SegmentsIOS.swift:110-127`, `SegmentsMac.swift:87-99`). A native symbol has no such view. `buttonFace` returns a platform symbol name (`commands.rs:154-161`), which is what `UIImage(systemName:)` and `NSImage(systemSymbolName:)` take.

`accessibleText` for a native button reads `nativeTitle`, the control's last written title (`Accessibility.swift:12-13`, `NativeButtonsIOS.swift:43`). `segments.sync` runs before `controls.sync` (`PresenterIOS.swift:808-809`, `PresenterMac.swift:964-965`), so that title is empty on the creating batch. The face has to be `presenter.buttonFace`, the kernel read, which does not wait for the control.

LLP 1059 D3 tints the selected tab-bar item from the selected symbol's `tint-color` (`SegmentsIOS.swift:48`, `217`; `llp/1059-tab-bar-projection.rfc.md:39-41`). A native button refuses that row (LLP 1069.011 D6). Its tint is `accent-color` (`NativeButtonsIOS.swift:120`, `138`).

Change the plan. `TabBarFace` is built from `pressFace`: a symbol and a title, nothing else. Tint is the image child's `tint-color` for a custom tab and `accent-color` for a native one, defaulting to the label color. `SegmentFace` gains a symbol case drawn with `systemName` / `systemSymbolName`. A custom image segment keeps the snapshot of its image view, including a raster. A native tab whose `aria-label` differs from its visible title stays authored, which is the guard at `Accessibility.swift:47-49`. A symbol plus a title is a tab bar on iOS only. macOS has no tab bar (`SegmentsMac.swift` projects only `NSSegmentedControl`), so that face stays authored there, as a custom tab does today. Say that in D4 so the macOS test does not expect a tab bar.

2. Blocker. D5's invoker path opens the menu twice on macOS, and on iOS it turns a confirmation into a menu.

`activateNative` dispatches `presenter.press` on the resolved target, which may be an ancestor (`NativeButtonsMac.swift:62-98`). `press` already calls `menus.pressed` (`PresenterMac.swift:684-688`), and that looks up the invoker by the id that was pressed (`MenusMac.swift:51-67`). Adding "then open the menu" in the button action pops a second menu when the target is the button, and opens nothing when the target is an ancestor or when there is no `press` handler (`activateNative` returns at line 96 before `press`). iOS menus are not opened by `press`. An overlay button carries the menu (`MenusIOS.swift:106-130`), and its deferred element presses the invoker's own id (line 122). A confirmation invoker is a different overlay: `showsMenuAsPrimaryAction = false`, and the action calls `openConfirmation` (`MenusIOS.swift:89-104`, `248`). `openConfirmation` already presses the invoker once (line 248). Putting `UIButton.menu` on every native invoker shows a menu instead of the alert, and leaving `primaryActionTriggered` attached (`NativeButtonsIOS.swift:84`) presses again if UIKit still sends it.

Change D5. Menu opening stays `MenuHost.pressed(invokerId)`. When the native button's own handler is the press target, `activateNative`'s existing `press` is the one open. When there is no press target, the action calls `menus.pressed(self.id)` and does not dispatch. When the press target is an ancestor, dispatch that press and also call `menus.pressed(self.id)`. Do not pop a menu anywhere else. On iOS, a native invoker of an ordinary popover gets the deferred menu on its `NativeButtonIOS`, `showsMenuAsPrimaryAction = true`, no overlay, and the primary action is removed while it is an invoker. The deferred element presses the invoker's id once, as the overlay does. A confirmation invoker does not get a menu. Its primary action calls `openConfirmation` and does not also run `activateNative`. When `popovertarget` or `commandfor` goes away, the next `menus.sync` clears `menu` and `showsMenuAsPrimaryAction` and puts `activateNative` back. `menus.sync` already runs after `controls.sync` (`PresenterIOS.swift:809-810`), so the control exists. The "one menu, one press" test is a real click. Agent mode never tracks an `NSMenu` (`MenusMac.swift:28-31`) and on iOS leaves the popover painted.

Rows: `items(of:)` and `menu(of:)` already take any direct subview with `press`, not `kind == "button"` (`MenusIOS.swift:290`, `MenusMac.swift:76`). Do not add an `isButton` filter there. That would drop non-button press rows that work today. Do switch the confirmation filter (`MenusIOS.swift:251-254`) to `isButton`. `title(of:)` walks child views (`MenusIOS.swift:308-314`, `MenusMac.swift:98-104`) and is empty for a native row, so it reads `pressFace`. Set `UIAction.image` / `NSMenuItem.image` only for a native row. A custom row stays text-only.

3. Blocker. A native button in a swipe row's body eats the swipe.

The parent RFC just taught the list scroller to cancel a touch in a `NativeButtonIOS`, because UIKit does not cancel a `UIControl` (`ScrollViewIOS.swift:29-34`). The swipe table is a plain `UITableView` (`SwipeActionsIOS.swift:179`), so it keeps the default and will not cancel that button. A pan that starts on the button never becomes the row's swipe. Custom body buttons are `NodeView`s, so the table cancels them.

Change D6. The swipe table overrides `touchesShouldCancel(in:)` the same way, naming `NativeButtonIOS`. The action's own control stays hidden (`SwipeActionsIOS.swift:263`) and the `UIContextualAction` remains the thing that runs `presenter.press` (line 319).

Also spell the action's look, because `label()` does not see a native title. It reads the node's `accessibilityLabel` (`SwipeActionsIOS.swift:103`), and the native button sets that label on the control (`NativeButtonsIOS.swift:140`), not on the node. The eligibility check then rejects a title-only action (`SwipeActionsIOS.swift:79`) and the whole row falls back. Use `pressFace`: accessibility label, or the title. A symbol becomes `UIImage(systemName:)` of the face's symbol (already the Apple name, `commands.rs:154-161`), with no title string, matching the custom "image, or else title" split (`SwipeActionsIOS.swift:323-339`). A custom action keeps the snapshot, including its transform (lines 326-328). Color: a native action with `accent-color` uses it. With no accent, a non-destructive action sets system blue, and a destructive action leaves `backgroundColor` unset so UIKit keeps red. The custom path sets system blue even on a destructive action (line 321). Do not copy that onto native actions.

4. Blocker. D8's pool reuses the wrong control and keeps the previous row's state.

`rules/DEFERRED.md:332-335` binds this: a reused view is indistinguishable from a new element, and state that must survive scrolling lives in keyed data.

The shape is built twice, from different data. Park walks views (`NodePoolIOS.swift:209-216`). Take walks create ops (`NodePoolIOS.swift:372-387`), and `createdNodes` stores kind and image source only (lines 332-337), not `type` or role. `kind` for every control is `"control"` (`host.rs:1398-1399`). `ControlKinds.kind` maps both a switch and a checkbox, and also `type=file`, through the same default (`ControlKinds.swift:12-19`): unknown types become checkbox. A shape token of `"control"` or of the `type` prop pools a `UISwitch` row with a checkbox row, and a file row with a checkbox row. Record `ControlKinds.kind` only after giving `file` its own token. Write it from the create op's props on take and from the view on park. A control emits no child views (`paragraph.rs:309-311`), so the face's `text` and `image` are not part of either shape. Keep it that way.

`recyclable` treats `pressed` as "a gesture is in progress" (`NodePoolIOS.swift:313`). A native button never sets `pressed` (LLP 1069.011 D4: nothing sets `pressed`). A `UISwitch`, `UISlider`, or `UIButton` can be tracking with `pressed` false. Parking then rebinds that same `UIControl` under the finger, and the touch-up runs `activateNative` on the new id (`NativeButtonsIOS.swift:84`, owner is the reused view). A tracking control, `isTracking` or `isTouchInside`, makes the row ineligible, on the control as well as the node.

These writes do not clear the old row:

- Switch and checkbox update `isOn` only when `checked` is present (`ControlsIOS.swift:119-128`). An omitted `checked` leaves the previous row on.
- A date picker sets its date only when `value` parses (`DatesIOS.swift:25-27`). An omitted `value` leaves the previous date. `datePickerMode` is set in `makeDate` (line 14) and never again, so a date picker reused as a time picker stays a date picker unless the shape keeps them apart.
- A slider does rewrite its value (`RangeIOS.swift:22-23`), unless it is tracking, in which case it skips the write. `lastRange` is keyed by id (line 35) and must be dropped with the old id.
- A select rebuilds its menu only when the cache misses (`ValueControlsIOS.swift:29-36`). The closure captures the id. A cache reset is enough for the menu, and the select's button is a plain `UIButton`, not a `NativeButtonIOS`. Adopting across those classes is wrong.
- `configureNative` returns immediately when `written` matches (`NativeButtonsIOS.swift:126`). `menu` and `showsMenuAsPrimaryAction` are not in `Written`. A reused invoker keeps the previous row's menu and does not press.

`controls.sync` deletes any control whose id is no longer live, and removes it from the superview (`ControlsIOS.swift:102-106`). That sync runs at the end of the batch (`PresenterIOS.swift:809`), after `retire`. The handoff onto `parkedControl` has to happen inside `recycle`, removing the id from `controls`, `kinds`, `reported`, `menus`, and `lastRange` without `removeFromSuperview`. `reported` is private (`ControlsIOS.swift:69`). `control(for:)` (`ControlsIOS.swift:78-90`) adopts `parkedControl` only when the class and `ControlKinds.kind` match, then sets `tag`, `owner`, and nil `written`. A mismatch removes the parked control and makes a new one. `drop` and a memory warning already remove the root (`NodePoolIOS.swift:143-149`). Nil `parkedControl` there.

A glass button's control sits in the slot, which `children()` already treats as the node's own (`NodePoolIOS.swift:181`). `recycle` tears down materials and glass groups (`NodePoolIOS.swift:441-444`) and does not touch the slot. Clear `isGlass` and call `syncGlassSlot` so the control moves back onto the node before the slot is removed (`GlassGroup.swift:263-271`). After that move the control is a direct subview, so `children()` must treat the node's control as its own or the next park fails. `glassGroups.reconcile` runs after `controls.sync` (`PresenterIOS.swift:809-811`), so the taken row builds a new slot around the adopted control.

Change D8 to that, and change Q3's answer to: select, range, date, time, and datetime-local stay out of the pool in this slice. Button, switch, and checkbox join, with omitted `checked` written as off, and a tracking control blocking the park.

5. Should-fix. The attribute refusal is one match arm. Lifting "the contexts" can lift the wrong attributes.

`button_context` refuses ancestors (`controls.rs:370-400`). `check_native_button` refuses a single list on the button itself: `popovertarget`, `commandfor`, `href`, `action`, `aria-keyshortcuts`, the `swipe*` attributes, `popover`, and `toolbarPlacement` (`controls.rs:508-514`), plus any role other than the literal `button` (`522-526`). The ancestor context sticks for the whole subtree (`lib.rs:1014-1018`).

Lift on the button: `toolbarPlacement`, `popovertarget`, `commandfor`, `aria-keyshortcuts`, and a role that is a literal or a choice among `button`, `tab`, `menuitem`, `menuitemcheckbox`, and `menuitemradio`, each arm checked the way `buttonStyle` is. An authored role already overrides the fixed `button` role. Fixed props are pushed first and the last binding wins (`lib.rs:778-783`, `924-947`; `tags.rs:632`).

Keep refused on the button: `href`, `action`, `popover` (a native button is not a popover), `swipeContent`, `swipeLeading`, `swipeTrailing`, `swipeIndicator` (a native button is not a swipe row; the row carries those), any other role, and `type` other than `button`. Keep the ancestor refusals for `canvas` and for inside a native button (`controls.rs:377-382`). The face grammar would also reject a nested button, but the error would become `lower-button-content`. Keep the context error.

A popover refusal that is simply deleted admits a native button nested inside a menu row. The host only projects direct subviews (`MenusIOS.swift:289`, `MenusMac.swift:75`), and the popover is hidden (`MenusIOS.swift:78`), so that button compiles and never appears. Allow a native button whose context is the popover's direct child. When that child is lowered, its descendants get "inside a menu row" and stay refused. `lib.rs` has room for that (1386 lines). `controls.rs` is 851.

`contextmenu` stays refused (`controls.rs:583-588`). A projected segment's long-press calls it (`SegmentsIOS.swift:73`). A native tab cannot declare it, so the long-press does nothing. Either admit `contextmenu` on a native button, or say in D4 that a native tab has no context menu.

6. Should-fix. D3 points at an owed list LLP 1075.003 does not have.

Put one sentence there: those buttons are read through this RFC's `pressFace` / `isButton`, and a prominent `buttonStyle` maps to `UIBarButtonItem.style = .prominent` the way D2 maps `NSToolbarItem`. 7. Should-fix. The confirmation alert tints from `text_color`, which a native button cannot set.

`openConfirmation` sets the alert tint from `action.color("text_color", .systemBlue)` (`MenusIOS.swift:263`). A native action has no `text_color`. Use `accent-color` for a native action, and keep `text_color` for a custom one.

8. Nit. Linux dialog invokers are already refused without the walk change, and `host.rs` is at the line cap.

Stop at a native button the same way: it is an invoker when it has `popovertarget`, and it is not one when it does not, even if a parent `Pressable` does. `commandfor` is already refused for whatever node is pressed (`host.rs:747-756`). The web needs no host change: a native button is already `<button>` (`element.rs:419`), `popovertarget`, `commandfor`, `role`, and `aria-selected` are already emitted (`element.rs:696`, `782-787`), and an implicit `role="button"` is stripped only when the role is `button` (`element.rs:891-902`), so `role="tab"` remains.

Cut select, range, date, time, and datetime-local from row reuse in this slice. The plan's own Q3 rule, applied to the code, puts them out. Button, switch, and checkbox are enough to retire D13 for the control people will actually put in a list row.

Cut the custom-invoker fix (question 2).

Cut the idea that one `pressFace` replaces every image path. It should return the label, title, and symbol. Toolbar rasters, segment snapshots, and swipe snapshots stay the custom projections' own code. Native symbols are `systemName` images at those three call sites.

Keep the header projection cut. One sentence in 1075.003 is the whole of D3.
