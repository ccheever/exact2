I'll review the design-system RFC against the architecture it cites, starting with the draft and the decisions it depends on.The draft is 761 lines. Next I’ll check its decisions against the colour, precedence, motion, and schema documents it cites.**WRONG.** Named tokens as plan data, with the platform as the default and Dim as an app axis, matches LLP 1095 and LLP 1115. The draft's resolution pipeline does not. It assigns scheme and `rem` to the wrong side of the host/kernel split, and several decisions describe APIs and shorthands this tree does not have. The reach-ruling citation (LLP 1095 §5 item 6), the `NSSwitch` limit, the 76-symbol count, and the Facet import refusal are accurate.

## BLOCKER

**1. D2, D5, and D7 put scheme selection in the kernel and subtree modes in `:root` selectors.**
D7 (`llp/1121-design-system.rfc.md:325`, `:341`) says the kernel resolves each reference against the node's mode vector, and the web switches tokens with `:root[data-x-dark-style="dim"]` while `-exact-mode` only sets the data attribute on a subtree. LLP 1034 D2 (`llp/1034-scheme-aware-colour.rfc.md:82`) forbids the kernel from flattening `light-dark()`: the web host must emit the function so the browser resolves it per element against inherited `color-scheme`. LLP 1095 D1 and D5 (`llp/1095-platform-colours.rfc.md:105`, `:380`) keep scheme, contrast, iOS level, and material in the host's trait set; the kernel uses a host report or the fallback pair. A custom property set on `:root` is inherited as a specified value, so a data attribute on a descendant does not change it. The JS target has no kernel at runtime (`kernel/src/style/relative.rs:8-11`), so a kernel mode vector does not exist there.
Fix: the plan stores, per token, one value per app-axis combination, and that value stays a `ColorValue` (`LightDark`, `Role`, `Platform`, mix, wide). The kernel selects the app-axis slice only. Scheme, contrast, level, and material stay inside the value for the host, as they do today. On the web, emit `light-dark()` and role variables (LLP 1095 D11, including `prefers-contrast` and `forced-colors`). For an app axis, set the custom properties on the element that pins the mode, from that slice. Do not pre-flatten scheme into the kernel.

**2. D3, D6, and D7 send lengths and type through a font shorthand and a host `rem` resolver that do not exist.**
D3 (`:185`) says `font` sets five rows the way `font="-exact-footnote"` does today. The shorthand is four longhands, `FontStyle`, `FontWeight`, `FontSize`, `LineHeight`, and it accepts only a platform text style (`contract/lower/src/shorthands.rs:32`, `:285-298`). Family is not in it. D7 (`:317`) and D2 (`:152-154`) say hosts resolve `rem` and text styles. The kernel resolves both at the end of the commit, `rem` against the root size and `em` against the element's own font size, and stores pixels (`kernel/src/style/relative.rs:1-20`). `em` has no meaning in a shared table if it is folded at build. `calc(1rem * 0.9375)` (`:294`) is the open gap in `QUEUE.md:397`: inside `calc()`, the kernel still takes only `px`. An authored weight on a type token also writes a weight the text style currently leaves unsaid, so Bold Text (LLP 1115.000 D12.3) does not apply.
Fix: a length token lowers to today's dimension or relative-length side table. `rem`, `em`, text styles, and `-exact-hairline` stay kernel residuals. Forbid `em` in a token unless it remains that residual. Do not treat `calc(rem)` as legal until `QUEUE.md:397` is built. A type token lowers to the four longhands plus `font-family`. Keep `font` as the text-style shorthand. Leave weight and line-height unsaid when the token is a text style, so the platform weight and Bold Text still apply.

**3. D3, D7, and §3 invent a colour codec the tree already outgrew, and they widen LLP 1095 D10.**
D7 (`:319-320`) says `ColorValue` gains nothing beyond D1's `Ref(u16)`. On main there is no `Ref`. The enum is `Fixed`, `LightDark`, `Role(u8)`, `Platform(u16)`, `Wide(u16)`, `Moving`, and `Profiled` (`kernel/src/style.rs:695-714`). §3 (`:596-597`) quantises every mix to 8-bit sRGB. LLP 1100 D2 (`llp/1100-color-spaces-and-hdr.rfc.md:149`) stores the space on the value, which is what `Wide` and `Profiled` are. The expression subset adds `oklch` relative colour, channel `calc()`, and `contrast-color()` (`:182`, `:594-597`). LLP 1095 D10 (`llp/1095-platform-colours.rfc.md:635-642`) refuses those until the wide row is the wire, and admits `color-mix` only in `srgb` and `oklab`. D7's fallback is one value for the default modes (`:313`). D1's fallback is a light/dark pair, which is what Linux and headless use. One `domain` on the token (`:313`) contradicts D3, where a `number` is paint or layout depending on the row (`:184`). Keyframe colours still refuse references (`llp/1095-platform-colours.rfc.md:442`); the draft never says so.
Fix: colour tokens are rows in the plan table the reach branch is adding, pointing at the existing `ColorValue` variants. Mixes stay inside D10's subset and LLP 1100's wide value. Keep the fallback a pair. Record the invalidation domain on each use, not on the token. Repeat D6's keyframe refusal, and run a mode change through the same `transition` path as a trait change (LLP 1095 D6).

## MAJOR

**4. D1 misstates precedence.** `llp/1121-design-system.rfc.md:110-112` inserts "the design" between the author and the platform, and puts accessibility above the author's row. LLP 1115 (`llp/1115-write-the-web-ship-the-platform.principle.md:16-24`) is: accessibility where a hand-built app would apply it, then the author, then the platform, then CSS. Increase Contrast moves roles, not an authored hex. Bold Text weights the system font only. A token named by a row is an authored value.
Fix: drop the extra tier. Say a design supplies the app's authored defaults; a row on the node wins; accessibility beats either only where LLP 1115.000 D12.3 already says it does.

**5. D5 and D6 treat `setMode` as `setScheme`, and invent a root-size spelling that is already queued.** `setScheme` tells the host which appearance to present (LLP 1034 D3). It is not re-resolved inside the runner commit. D5 (`:275-276`) says `setMode` has that reach and is re-resolved in the action's commit. `setRootFontSize` is the command that relayouts in the commit (`docs/contract-grammar.md:1576`), and it does not persist (LLP 1069.000 D3). While an app size stands, later Dynamic Type updates are stored and do not relayout (`runner/src/runner/root_font.rs:55`). `QUEUE.md:396` already asks for `setRootFontSize("125%")` and a first frame that has the stored size. D6's `setRootFontSize(scale=1.125)` (`:297`) matches neither the positional command nor that spelling. Q6 (`:749`) reopens a decision the grammar already states.
Fix: `setMode` selects the app-axis slice for the window. Scheme stays `setScheme`. Cite LLP 1069.000 D3. Use the queued percentage form if the scale ships in stage 2, and keep persistence as the separate first-frame question in `QUEUE.md:396`.

**6. D5 and D7 never define the mode key.** `values: [(mode mask, value)]` (`:313`) is a bitset. `density` has three values (`:251`), so a bit per axis cannot represent it. "Most specific `when`" (`:263`) is undefined once `light-dark()` inside the value and a `when contrast=more` both speak. The 64-combination cap (`:284`) has no encoding. Specificity has to be compiled away: each token stores disjoint rows keyed by the app-axis tuple, `under scheme=dark` drops the combinations where the axis does not apply, and `light-dark()` stays inside the value rather than becoming another `when`.

**7. D7's token-to-node index misses how colour is actually invalidated.** The index is "nodes whose rows read the token, built at mount" (`:327-328`). Inherited `color` and `currentcolor` have no row on the child (`kernel/src/style.rs:322-323`). Text colour is cached; LLP 1034 D2 requires `invalidateText` on an appearance change, and a paint-domain mark does not do that. A mode change with `transition` set has to ease (LLP 1095 D6), which the stage 2 gate (`:669-670`) describes as a same-frame repaint.
Fix: index every node whose computed colour holds the reference, invalidate text caches when a colour token changes, and let `transition` ease the swap.

**8. D8 amends LLP 1061 D1 by citing the wrong precedent.** `::placeholder` admits `color` only (`docs/contract-grammar.md:131-136`). Any other part is `syntax-part`. LLP 1061 D1 (`llp/1061-press-feel-and-reduced-motion.rfc.md:56-57`) rejected an `active` block as a selector system. The host's press is not CSS `:active`: it is the innermost node with a `press` handler (`:119`), eased on `cubic-bezier(.16, 1, .3, 1)` (`:68`, `:111`), and it is kept under Reduce Motion. The draft's "120 ms ease" (`:385`) is a different curve, and it never says what Reduce Motion does. On the Mac the unsaid press darkens the ink; it does not dim (LLP 1115.000 D6). A list row's press is the cell highlight (D16), not this dim. `[aria-selected]` is an attribute selector, which §4 says the RFC does not add. The disabled rule already landed as a heuristic in `contract/lower/src/disabled_look.rs`, not as a part.
Fix: if Q8 is accepted, the part is a grammar production whose `:active` means the existing press tracking, including the agent clock's unsmoothed press. State Reduce Motion (feedback stays, a colour fade snaps). Exclude native controls and list cells. Keep `:disabled` as the mark that heuristic already writes.

**9. D9's control table does not match the hosts.** Switches, sliders, and progress already take the node's `accent-color` (`host/apple/Sources/ExactGroupedLists/GroupedListIOS.swift:901`, `host/apple/Sources/ExactKit/IOS/RangeIOS.swift:23`, `host/linux/src/paint/control.rs:155`). The draft does not say whether `switch-on` wins over that row. `NSSwitch` really has no tint (`host/apple/Sources/ExactKit/Mac/ControlsMac.swift:158`), and a Mac progress indicator has no tint either (`host/apple/Sources/ExactKit/Mac/ProgressMac.swift:1-12`). There is no Compose `SwitchColors` in `host/android`. Linux, the terminal, and Windows are absent, and Linux paints its own controls. LLP 1095 §3 makes a new role a curated schema change and a new host binary.
Fix: extend the existing `accent-color` path where it already reaches. Add a control role only for a parameter `accent-color` cannot name, with a column per host that ships, `none` where the platform has no parameter. Drop the Compose API names.

**10. D10 rebuilds a symbol table that already draws on the web.** `kernel/tables/schema.json:4554` gives each of the 76 roles an SVG path. `symbol:sf/<name>` is the reserved opaque Apple name, which is the Bluesky hole. `-exact-symbol-rendering` already has monochrome, hierarchical, palette, and multicolor. A token flag of `multicolor` (`:453`) drops the middle two. Turning the 76 roles into tokens changes every working `symbol="back"`.
Fix: keep the role table. An icon token is the checked form for a name that is not a role: SF Symbol, Material name, SVG fallback. `symbol:sf/…` with no token fails the build and names the target. Rendering stays the existing row.

**11. D11 contradicts D1, and the package link is unspecified.** D1 (`:120-121`, `:126-127`) says an app with no `.design` is byte-identical and rejects a Facet-like default brand. D11 (`:468`) then ships Facet's 4 px `space.s1…s24` scale as Exact's base, while the platform's metrics are the schema's `rem` rows (`kernel/tables/schema.json` `_metrics`, for example `tabbar-height` at `3.5rem`). D7 (`:312`) puts one row per token from the IR, so a base that is always linked is not an empty table. "A name two packages both declare is refused unless the app sets it" (`:476`) has no merge rule for `when` clauses, dials, or axes. Q4 reopens the decision D11 already writes.
Fix: until Q4 is answered, the base is roles, text styles, and the existing metric names. App and package files contribute rows only for names a plan references. Specify the merge: package names are prefixed, the app file replaces a package token by full name, and two unprefixed definitions are a compile error.

**12. §5 and §6 understate the wire break and the stage 2 cut.** "One schema digest change" (`:695`) covers the new row forms. State looks (stage 3), `controlRoles`, and any symbol-wire change are further digest breaks. LLP 1030 D3a means every native host binary moves on each one. The stage 2 gate (`:664-670`) measures web, iOS, and Mac. The JS target, Linux, Android, and the terminal still have to read the new rows. D7 also rewrites the colour table the reach branch is building, which the introduction says is not redesigned here.
Fix: stage 2 is colour tokens and app axes on the reach branch's table, after that table has landed. Lengths, type, state parts, control roles, and icons are later RFCs with their own digest. The gate names every host that must load the new plan.
