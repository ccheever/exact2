1. **BLOCKER** — `describe.targets` is stringified and run through a hardcoded map, so the ruled shape shows no shipped columns. `apps/design-tool/base.ts:11`, `base.ts:30`, `base.ts:57`.

Theme2's `targets` entries are `{target, column}` (`~/x2theme/stage11-brief.md`, the 16:32 addition), and the tool is not supposed to hardcode a target-to-column map. `targetsOf` does `said.map(String)` whenever the field is an array, and `baseColumns` then looks those strings up in `DRAWS` (`web` → `neutral`, `macos` → `mac`, …). `String({target:"web", column:"neutral"})` is `"[object Object]"`, which is not in `DRAWS`, so `ships` is empty. Every column fails `c.ships` and sits behind "Other platforms" (`app.contract:1720`). "Set for this app" then starts from column 0 (iOS), not the column the app ships. A server that omits `targets` still falls back to the icons' `draws` keys, and a missing `base` still yields no base rows (`app.ts:143`, `base.ts:57`). The stub sends `targets: ['ios', 'macos', 'web']` (`stub/tamber-stub.ts:279`), and the stage 11 test asserts that string shape (`app.test.contract:1839`), so this stays green.

2. **SHOULD-FIX** — A base name never opens read-only, and `explain`'s `kind: 'base'` body throws in the branch read. `apps/design-tool/app.ts:739`, `app.contract:1721`.

A base row with no override is synthesized with `cells: []` (`app.ts:666`). Its platform lines are plain text, not `selectCell` controls, so the grid cannot open one. The inspector can: "Open space.md" calls `editFromSelection`. `explain` for that name is `{kind:'base', name, base}` with no `whens`, `value`, `names`, or `dials` (the brief, and the stub at `tamber-stub.ts:292`). `loadBranch` calls `branchOf(..., x.whens)` before it looks at `x.kind`, and `branchOf` does `whens.map` (`branches.ts:42`). The read throws, and the read-only copy at `app.ts:751` never runs. The name is also absent from `snap.kinds` (only `ir.tokens` are recorded), so a guarded read would still present it as `color`. A package cell does open read-only; the test covers that path only.

3. **SHOULD-FIX** — "Set for this app" is always `add-token`, and a package row has no "already has a line" state. `apps/design-tool/app.contract:1171`, `base.ts:48`, `app.ts:751`.

For a base name this is safe. `radius.md` with `override` set is one row in "Base scale (Exact)", `source` is `'app'`, the button is hidden (`app.contract:1725`), the cells are that token's (the stub's `12px`), and the branch editor is editable, so a change goes out as `set-token`. "Back to the base" is `remove-token` of the app's line. A package row is `source: 'package'` whenever `t.package` is set, with empty `over` / `back`. The button stays, and `setForApp` always sets `editKind = "add-token"`. There is no `set-token` arm. If `reading.measure` still carries `package` and `file` after `app.tamber` has a line for it (the brief puts those fields on the package row, and there is no package `override`), the button is shown on a name the app already sets, the proposal is `add-token`, and the branch stays read-only because `explain.package` is set, so the existing line cannot be edited as `set-token` either. There is no "Back to the package".

4. **SHOULD-FIX** — Those ops follow the file picker, so a package `.tamber` can be the file they write. `apps/design-tool/app.ts:164`, `app.contract:1651`.

`opOf` adds `file` whenever the open file is non-empty. The picker lists every hello file that is not a `.contract`, which will include `reading.tamber` once package designs are served. "Set for this app" and "Back to the base" do not force the app design. With the app's design open (`file == ""`) the op correctly omits `file`. With `reading.tamber` selected, "Set for this app" on `reading.measure` proposes `{op:'add-token', name:'reading.measure', file:'reading.tamber'}`.

5. **NIT** — The branch editor's confirm-remove control is not tied to `readOnly`. `apps/design-tool/app.contract:1832`.

Pin, the part fields, the value field, "Only this mode", rename, and the Remove opener are all `disabled` when `branch.readOnly != ""`. `confirm-remove-yes` is only `disabled=(not canPropose)`, and `removeToken` does not check `readOnly`. The opener being disabled is what keeps the dialog shut. At read scope, "Set for this app" and "Back to the base" are greyed (`not canPropose`); at propose they stay enabled and Apply holds the edit. That part matches T6.
