## Overall assessment

The document carefully separates source adaptation from supported-device behavior.
Its draft/answer ownership description matches the inspected adapter. Keep Draft.
Two low-severity wording corrections would make the lifetime guarantees precise.

## Strengths

- Controller reuse records the one cancellation adaptation and preserves the source
  state machine, text/revision guards and selection semantics.
- Draft and selection explains why edit-then-revert requires synchronous observation.
  The adapter captures the shared slot and invalidates stale caret revisions while
  preserving the user's current thread selection.
- Answer lifetime names temporary native/storage handles, drainage and separate Cancel
  ownership. It also records the missing immediate native reply-cancellation callback.
- Native transcription uses the actual supported SpeechAnalyzer path and preserves
  unsupported-device refusal. No substitute transcript or network backend is implied.
- Verification explicitly excludes real microphone use and distinguishes SDK source
  checks and a Hermes probe from native launch or interruption behavior.

## Concerns

1. P3: Answer lifetime calls mobileVoiceSnapshot pure. It calls
   mobileVoiceObserveDraft, which can advance the observed text revision, invalidate
   a staged caret and notify the observer. Describe it as a synchronous no-I/O
   projection with draft observation, rather than a pure function. This is a wording
   correction; the observation itself supports the intended stale-result guard.

2. P3: the statement that no native callback survives an answer needs a qualifier.
   No answer-bound JavaScript callback or native handle should survive, but the
   module-owned AVAudioRecorder delegate and native meter timer necessarily span
   answers while recording. Native lifetime describes those correctly. Say
   answer-bound callbacks/handles so these two sections do not appear contradictory.

## Suggestions and open questions

Keep the runtime-question/approval exclusion and missing native cancellation hook
explicit. Event sequence ordering, background during asset preparation, microphone
permission changes and selection restoration on iPad still need supported-device
proof. A native source typecheck cannot settle those questions.

## Recommended next step

Apply the two wording corrections and retain Draft. Do not promote inferred native
behavior to observed until the permitted device drive supplies evidence. This review
changes no status, adds no overlay and does not stand in for another model family.
