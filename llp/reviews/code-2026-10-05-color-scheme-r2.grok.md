NOT READY

1. **must-fix** — The first view report of a subtree scheme snaps away the colour transition that the commit just started. `kernel/src/motion/paint.rs:264` (`first`) and `:269` (`paint_adopt` with the raw report, applied with `snap`). `paint_sync` already resolves `light-dark()` through `appearance()` and starts the transition. `set_view_scheme` then treats a view that was not yet in the map as a first report: `apply` removes the property (`:133`) and `Engine::observe` settles it with no transition, because a property the engine has never seen does not move. Every box now carries the row, so each one reports, and the jump hits the whole subtree every time its scheme begins to differ from the session (including dark, then back to the session, then dark again). A bound `normal` does re-dirty descendants: it clears the row (`StyleValue::unsets` → `ClearStyle` → `propagate_inherited`), and the row itself is not a motion property. Fix: adopt with `appearance()` (computed `color-scheme`, then the report, then the session), and pass `snap: false` when `color_scheme_dark()` is `Some`. Keep `set_node_dark` so keyframes follow. Add a test that toggles a bound `color-scheme` between `dark` and `normal` under a transition on `background-color` and expects the halfway colour.

2. **must-fix** — `scheme` records the appearance descendants still have, then the real reports sit unflushed. `host/apple/Sources/ExactKit/Session.swift:1288`. It is called from the root trait callback (`IOS/ExactViewIOS.swift:100`, `Mac/ExactViewMac.swift:225`) while that view’s traits are new and subviews have not been updated yet. The loop reads those stale `drawsDark` values, and because they differ from the new session it stores an explicit override for the old appearance. `runtime.scheme` has already run by the time `apply` flushes the queue (`:1007`). Descendant callbacks then `noteAppearance` the real value into `pendingViewDark`, and nothing flushes that until a later batch. Paint motion keeps the old half: a session that has just gone dark still resolves `light-dark()` and keyframes as light. `reportColors()` (`:1288`) is itself an `apply`, so any note already queued is flushed before `runtime.scheme`, ahead of the scheme. Fix: do not snapshot `drawsDark` inside `scheme`. Let each node view queue `noteAppearance` from its own trait callback, skip the `pendingViewDark` flush inside the `reportColors` apply, and flush once on the next main-queue turn after `runtime.scheme`, when the trait walk has finished.

3. **must-fix** — Linux paints a lifted row and an open select menu in the session scheme. `host/linux/src/paint.rs:781` (`paint_ghost`) and `:783` (`menu`) run after the root walk has restored `painter.dark`. `host/linux/src/host.rs:606` puts a scheme on `Presented.dark` only when that node’s own mask has the row, and `paint/lift.rs:139` starts the ghost walk at the wrapper. A row dragged out of a `color-scheme="dark"` column has no bit of its own, so it paints light while the app is light. The menu uses that same restored `self.dark` (`paint/control.rs:189`) and resolves its accent with `brush.dark` (`presenter/control.rs:251`). In-tree carrying holds: roots start from the session, and placed, spatial, and list-lifted children copy `painter.dark` while the ancestor carry is still active. Hit-testing is unchanged: boxes are recorded from geometry, and the ghost drops its boxes. Fix: before the ghost walk and the menu, set `dark` from the nearest ancestor with `color_scheme_dark() == Some`, otherwise the session. Extend the pinned test with a reorder ghost (or a select menu) inside the dark sheet.

4. **should-fix** — Every box under a scheme stops being a flat leaf. `host/apple/Sources/ExactKit/Prepared.swift:85`. `color_scheme` is not in `FlatPaint.inert`, so `FlatPaint` returns nil and `FlatLeaves` promotes the leaf to a view (`IOS/FlatLeavesIOS.swift:129`). A fixed fill does not depend on the scheme. Fix: add `color_scheme` to `inert`. Nested `light` and removal already hold: a child that sets `light` has that override from create, before it is inserted; an inherited child keeps an explicit override until its own later style op clears the key to `.unspecified` / `nil`.

Round 1 is otherwise in. Inline runs and SVG elements are refused at compile time. A bound `normal` clears the row, and the JS target removes the property unless the value is `light` or `dark`. `appearance()` ranks the computed scheme above a view report for `paint_sync` / `paint_resync`. The Apple tests still only style the ancestor and rely on UIKit inheritance; they never give the child the computed key the host now sends, and they never call `scheme`.
