**Verdict:** SOUND WITH CHANGES

1. **Prove the cache fit before committing to the full rewrite.** [§4:115](/Users/ccheever/projects/exact2-wt-parley-plan/llp/1085.000-parley-in-place-of-cosmic-text.plan.md:115) assumes Parley preserves Exact’s shared-shape, separate-width arrangement. Parley 0.11.1 instead owns shaping and line data together in [cloneable vectors](https://raw.githubusercontent.com/linebender/parley/v0.11.1/parley/src/layout/data.rs), and [justification mutates cluster advances](https://raw.githubusercontent.com/linebender/parley/v0.11.1/parley/src/layout/alignment.rs). Keeping several immutable widths therefore needs copying or an additional storage arrangement. This could substantially change both predicted wins. **Resolve:** start with a small integration proving simultaneous width snapshots and worker handoff; measure copying, peak allocations, and retained `LayoutContext` scratch before tackling all the gaps.

2. **Preserving the font cache is missing implementation work, not straightforward wiring.** Today [font_cache.rs:26](/Users/ccheever/projects/exact2-wt-parley-plan/host/linux/src/text/font_cache.rs:26) restores face metadata and weight-axis ranges without reopening every font. Fontique’s proposed [`register_fonts` path](https://docs.rs/fontique/latest/src/fontique/collection/mod.rs.html#702-738) takes font bytes, retains their blob, and parses them; it cannot simply consume that cached listing. A naïve adapter could restore the expensive startup work recently removed and increase font residency. **Resolve:** explicitly design cached metadata registration with lazy font loading, and validate startup with both an empty and populated font cache early. G8’s matching cleanup does not cover this dependency.

3. **The proposed intrinsic-sizing shortcut has a known correctness gap.** [§4:116](/Users/ccheever/projects/exact2-wt-parley-plan/llp/1085.000-parley-in-place-of-cosmic-text.plan.md:116) replaces intrinsic measurement with `calculate_content_widths`, whose [documentation explicitly warns about mixed-direction text](https://docs.rs/parley/latest/parley/layout/struct.Layout.html#method.calculate_content_widths). Correct line starts at four supplied widths do not establish correct intrinsic widths; wrong answers can change the containing flex/grid layout. **Resolve:** include Chrome comparisons for mixed-direction min/max-content sizing and preserve the existing whitespace and indent requirements. Treat any necessary compensation or upstream fix as an explicit gap before crediting the shortcut’s performance.

4. **Windows is an affected shipping surface missing from the plan.** [host/windows/Cargo.toml:10](/Users/ccheever/projects/exact2-wt-parley-plan/host/windows/Cargo.toml:10) depends on `exact-linux`, and cosmic-text currently selects a [Windows-specific fallback implementation](/Users/ccheever/projects/exact2-wt-parley-plan/vendor/cosmic-text/src/font/fallback/mod.rs:25). Moving only `unix.rs`’s fallback list and validating Linux/Android can regress Windows when this lands. **Resolve:** preserve its discovery and fallback behavior and add a bounded Windows validation covering ordinary text, emoji/CJK, and resize.

5. **The landing rule leaves the two principal benefits insufficiently protected.** [§6:192](/Users/ccheever/projects/exact2-wt-parley-plan/llp/1085.000-parley-in-place-of-cosmic-text.plan.md:192) prohibits regressions in scroll, start, size, and build—but omits memory and re-layout. Literally, a same-surface result with 25% less text memory and much slower re-layout could qualify for “Land”; “Mixed” only describes cross-surface tradeoffs. Also, deterministic binary growth has no measurement noise, so P6’s ±0.2 MB prediction conflicts with that landing condition. **Resolve:** protect both primary metrics, classify material tradeoffs explicitly, and give size a numerical allowance. Define text memory to include the engine’s retained scratch and caches, rather than relying solely on Exact’s existing partial residency counter.

- **MINOR:** The research’s three-patch baseline is stale: [EXACT-PATCHES.md:58](/Users/ccheever/projects/exact2-wt-parley-plan/vendor/cosmic-text/EXACT-PATCHES.md:58) adds soft-hyphen rendering, text indentation, and cached weight-axis metadata; explicitly reconcile these during inventory.
- **MINOR:** Android’s rotation-to-first-frame measurement cannot alone test P2’s prediction about text’s share; record text CPU alongside total rotation latency.
- **MINOR:** The Rust gate should inspect build dependencies and build scripts too; [`cargo tree -e normal`](https://doc.rust-lang.org/cargo/commands/cargo-tree.html#tree-options) excludes build dependencies, and crate names alone cannot establish implementation language.

The direction is sound and the experiment is worth running for memory, re-layout, and parity. The cheaper cosmic-text changes remain sensible fallbacks, but would not establish Parley’s integrated benefits. §3 correctly identifies an available Rust text stack and distinguishes Android’s platform painting boundary; no C/C++ text-engine port is required. I would proceed after the early storage/catalog checks and the decision-rule changes above.
