NEEDS REWORK

Round-2 dispositions are in the r3 text, and a fresh `fit.mjs` run matches the §4 census (2,412/2,457 and 6,960/7,014 within 10⁻⁵, 100/100 misses inside the band, 27 refusals, settling-duration residual 2.2·10⁻¹⁶, bounce-end residual 1.79·10⁻⁴, icon curve gap 0.0595). The dimensionless reduction holds. Q2–Q7 are defensible. The gaps below are what an implementer still cannot resolve from this draft.

1. **BLOCKING** — The web step size is undefined for a release at zero or tiny distance. D6 sets `h = min(0.25 s, √(8 · 5·10⁻⁴ · |Δ| / M))` and checks the 16,384-frame cap at parse (`llp/1099-uikit-springs.rfc.md:451-466`). A release velocity is in property units and is applied as the actual derivative (`:379-387`); it is not known at parse. At Δ = 0 the formula gives h = 0, and D5 still starts that component (`:398-406`, `motion/src/engine/hold.rs:328`). `SpringConfig::sample` already integrates a zero displacement with a nonzero velocity (`motion/src/spring.rs:102-140`); `transition.rs:427` skips a component only when both are zero. For a duration spring of 1 s at ζ = 0.8 (ω ≈ 8.99) released at 5,000 pt/s from Δ = 0.01 pt, the tolerance is 5·10⁻⁶ while the travel is about 900 pt, so h ≈ 2.3·10⁻⁵ s and the 1 s end needs about 43,000 frames. The parse check, using the authored velocity in moves per second, accepts the spelling. Fix: size the tolerance to the displacement amplitude, `max(|Δ|, |v_actual|/ω)`, give the Δ = 0 limit explicitly, re-check the frame bound at release on every host, and state the refusal that applies when the bound trips. Add a web-frame fixture for an exact zero-distance release and a small-Δ, high-velocity release.

2. **MATERIAL** — `lower-spring-uikit-band` has no success-path consumer. Literals inside the band, including Signal's icon (curve gap 0.06), are accepted with that warning (`:640-647`). The kernel maps a transition failure to `BadTransition` and nothing else (`kernel/build.rs:1306`); the compiler reports diagnostics only when compilation fails (`contract/cli/src/build.rs:59-93`, `contract/cli/src/symbols.rs:912`). Q1's recommendation is that this warning is what an author sees. Fix: specify a diagnostic that a successful compile still emits into the agent report, or refuse in-band literals.

3. **MATERIAL** — Height is specified as a residual played with `composite: 'add'`, "as LLP 1063 D6 already does" (`:436`). LLP 1063 D6 adds a translate residual; a size change is a stand-in painted with absolute keyframes (`llp/1063-presence-and-layout-motion.rfc.md:141-146`). Today's height path is a replace sample clamped with `Math.max(0, value[0])` (`host/web/motion-glue.js:98`). A negative residual that passes through that clamp becomes 0. Fix: keep height on the replace-absolute track with translate, scale, rotate, and opacity, or specify a box whose used value stays the residual through composition.

4. **MATERIAL** — Paint retargets are specified twice. D5 attaches additive components to every duration or bounce spring (`:342-344`). D1 admits `background-color spring(400ms, 0.8)` and refuses only an authored velocity on paint (`:163-164`). §5 and LLP 1062 D3 play paint as one `linear()` from rest and interrupt it as CSS (`:700-701`, `llp/1062-paint-motion-and-stagger.rfc.md:72-79`, D6 at `:437`). One `linear()` is a single replace curve; the re-bake that sums components is specified for compositor properties (`:435`). §8 has no paint duration-form retarget. Fix: exclude paint from the D5 component list — CSS replace from the presented color, no carried velocity — and add that case to §8.

5. **MATERIAL** — The last-crossing oracle does not match its inputs. D3 and §8.1 say ω = 1, v = 1.2262 → 5.4216 (`:270-271`, `:776-777`). `criticalSettle(1, 1.2262)` returns 5.454495. The input that returns 5.421647 is v = 1.2261769259289865, whose first lobe is 4.14285. The lobe-and-bisection procedure in `fit.mjs:69-81` is the right one, including v ≤ ω. Fix: print 1.2261769259289865 beside 5.421647, and 5.454495 beside 1.2262.

6. **MINOR** — Determinism cites a `ln` the pinned profile does not have. D2 sends `exp`, `ln`, and `sqrt` through pinned libm under LLP 1003 §7 (`:244-245`). `motion/src/math.rs:13-36` pins `exp`, `sin`, and `cos` at libm 0.2.16 and implements `sqrt` as IEEE `x.sqrt()`; there is no `ln`. LLP 1003 §7 lists those four and not `ln` (`llp/1003-motion-v1.spec.md:226-227`). The amend list is §1, §4, and §5 (`:13-18`). The v = 0 closed form and the underdamped end `T = ln((1+|B|)/ε)/(ζω)` both need `ln`. Fix: amend LLP 1003 §7 to add `ln` via libm 0.2.16, and state that `sqrt` stays the IEEE intrinsic.

7. **MINOR** — The v = 0 Newton procedure leaves the 10⁻⁵ gate as ζ approaches 1 from below. D2 says that for ζ' < 1 the twelve-step procedure reaches the closed form within that gate, and implementations use the closed form (`:213-215`). Relative error against `durationW0` is 0 through ζ = 0.9999, 6.2·10⁻⁹ at ζ = 0.999999, 0.027 at ζ = 0.999999999, and 0.167 at ζ = 1 − 10⁻¹². ζ = 1 matches the separate constant 9.233413476451585. The specified result is the closed form. Fix: limit the "within 10⁻⁵" sentence to ζ ≤ 0.999999, which covers every measured row.
