# Code review: Linux non-modal popover follows HTML, round 2 (astra)

- **Family:** OpenAI. GPT-6 Astra via `codex exec`, reasoning effort max, read-only sandbox, a throwaway worktree at `/tmp/dt3-rv-b2`.
- **Method:** one brief (sha256 `fd9744e48664e21c48e33879d710f5a8f03db1c7c0dd1613d13e0c422c4cc05a`), shared by both reviewers, blind to the other review. The author (Claude, dtool3) is not a reviewer.
- **Transcription:** the final message, unedited.

1. **MAJOR — Popover frames use the wrong coordinate contract.** [alert.rs:537](/tmp/dt3-rv-b2/host/linux/src/presenter/alert.rs:537) reports the placed **border box**, but [shown_at](/tmp/dt3-rv-b2/runner/src/geometry.rs:711) interprets a block root’s rectangle as its **block allocation**, including margins. For a 100px-wide popover with a 20px left margin painted at x=80, the runner computes x≈96.67 and width≈83.33. `frame()` and point reads therefore disagree with painting. Report the block allocation and compensate for the root’s offset. The new geometry tests omit margins.

2. **MAJOR — Global `tabindex` sorting undoes the popover focus scope.** [typing.rs:528](/tmp/dt3-rv-b2/host/linux/src/presenter/typing.rs:528) splices the subtree, then line 541 globally sorts every stop by `tabindex`. With a default-tabindex invoker, an inside button at `tabindex=1`, and a following page button, the resulting order is `inside → invoker → after`: Tab from the invoker skips its popover. Sort each scope before flattening it after its owner, as [HTML specifies](https://html.spec.whatwg.org/multipage/interaction.html#flattened-tabindex-ordered-focus-navigation-scope). The added test uses only default tabindex values.

3. **MAJOR — A clipped ancestor can still remove the entire popover from accessibility.** [access.rs:1087](/tmp/dt3-rv-b2/host/linux/src/presenter/access.rs:1087) now reaches nonmodal popovers only through the page walk. An offscreen or fully clipped scroller fails `access_emit`, causing [an early return](/tmp/dt3-rv-b2/host/linux/src/presenter/access.rs:846) before the popover-root clip reset executes. Put the existing fixture’s scroller below the viewport while keeping its external invoker visible: the popover paints onscreen, but its controls disappear from the accessibility tree. The current guard keeps the ancestor visible and misses this path.

4. **MAJOR — A dialog popover without focusable descendants leaves focus outside.** [alert.rs:270](/tmp/dt3-rv-b2/host/linux/src/presenter/alert.rs:270) falls back to the dialog only when `self.focus` is `None`. Opening a text-only `dialog popover` preserves the focused invoker; `move_focus_in` finds no stops and leaves it unchanged, so the fallback never runs. [Dialog focusing steps](https://html.spec.whatwg.org/multipage/interactive-elements.html#dialog-focusing-steps) select the dialog when no delegate exists. The new dialog test covers only a dialog containing buttons.

5. **MAJOR — Light-dismiss exemption includes non-popover commands.** [alert.rs:792](/tmp/dt3-rv-b2/host/linux/src/presenter/alert.rs:792) exempts every `Invocation` targeting the open box, including `Close` and `ShowModal`. An external `commandfor="menu" command="close"` button targeting an open dialog popover consequently neither light-dismisses nor closes it: `follow_invocation` accepts `Close` only for modal presentations. HTML’s [light-dismiss targeting](https://html.spec.whatwg.org/multipage/popover.html#popover-light-dismiss) exempts eligible popover commands, not arbitrary commands sharing the target. Add this alongside the second-toggle-button regression test.

6. **MINOR — An internal invoker moves the popover to the end of Tab order.** [alert.rs:776](/tmp/dt3-rv-b2/host/linux/src/presenter/alert.rs:776) cannot find an invoker inside its own popover after removing that subtree, so it appends the subtree after every page control. A programmatic opening with an internal source therefore changes ordinary document order. Internal invokers should not establish this scope; [Chromium explicitly excludes them](https://bugzilla.mozilla.org/show_bug.cgi?id=2065427). The no-invoker path already preserves tree order.

7. **MINOR — Manual popovers still consume Escape.** [alert.rs:646](/tmp/dt3-rv-b2/host/linux/src/presenter/alert.rs:646) routes Escape through `alert_key` for manual popovers. Although `alert_close_request` returns false, `alert_key` returns true, preventing the page shortcut/default path. This is observable with a programmatically opened manual popover, no focused element, and a page Escape shortcut. Manual Back coverage does not prove Escape forwarding.

8. **MINOR — An unfocused popover receives keyboard events intended for the page.** The newly preserved `None` focus exposes [events.rs:494](/tmp/dt3-rv-b2/host/linux/src/presenter/events.rs:494), which unconditionally falls back to `alert_root()` before the page root. Open a non-dialog popover programmatically without autofocus: its key handlers now receive keys despite never gaining focus, and can prevent Tab into the page. Restrict that fallback to modal boxes and add a no-focus keyboard test.

`report_top_layer` itself only updates runner geometry; I found no synchronous recursion through that call. No files changed. `git diff --check` passed; Cargo and Chrome tests were not rerun.
