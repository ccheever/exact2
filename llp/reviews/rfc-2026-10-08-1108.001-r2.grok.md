# Design review: LLP 1108.001 r2, Grok

Reviewer: Grok 4.7 (xhigh, read-only), 2026-10-08, blind, on lane/media-slices-2-3 at c33872252 (r2). Same brief as Astra's.

Note: its remark that the round-1 Grok file held only a header was true when it read it; the file was truncated by the recorder and has since been restored from the review's output.

NOT READY

The §1.3 write gate (2xx, and every `when` header, else the body stays readable and the path is untouched) is the admission parent §0.3 asks for (`llp/1108-media-from-snapback.rfc.md:145-147`). It is not yet a buildable client, and slice 3 is not buildable as specified. `llp/reviews/rfc-2026-10-08-1108.001-r1.grok.md` is only the four-line header, so those nine items were checked against §5's paraphrase. Astra's r1 items the text does close: `fetchEarly` (§1.2), IndexedDB under `mutate`, the staging name and Drop-unlink, the inline stream body, the declared wasm byte surfacing, the video bridge, acquisitions, and `blob.js`.

1. **BLOCKER** — §1.6 (lines 185–188) reads a not-written body with `json()` or `text()` and hands the core `{status, body}`. Parent D2 (`llp/1108-media-from-snapback.rfc.md:232-233`, `:241`, `:249`) says bytes never enter the core and `{status, body}` is a refusal's JSON. The client's `when` is `accept-ranges: bytes`. A `416` JSON body is that arm. A `200` with `accept-ranges: none` is the image (parent §0.3, lines 142–144; D5 lines 464–467): `json()` throws (`js/src/prelude.js:575`), `text()` is the photo (`prelude.js:574`), and `{status, body}` carries no `accept-ranges`, so the core cannot tell a spent view from a failed save. §1.3 (lines 98–101) already keeps that body in memory for a later `blob()`. Change: forward status and the four media headers, and drop the bytes. Keep `{status, body}` for a JSON refusal. The core treats `200` + `accept-ranges: none` as the spent once-view (`E_ASSET_ONCE_UNSUPPORTED` until slice 3) and `416` + `E_ASSET_RANGE` as unspent.

2. **MAJOR** — §1.3 says each `when` header "matches" and does not say how. `SaveTo::admits` (`runner/src/request.rs:141-148`) requires the whole combined value, trimmed, ASCII case-insensitive. `saveAdmits` (`host/web/http-body.js:277-279`) splits on commas and admits a list member, so `accept-ranges: none, bytes` writes on the web and not natively. Change: pin full-value equality in §1.3 and make `saveAdmits` use it. `Headers.get` already returns the combined value.

3. **MAJOR** — §1.4 (lines 127–131) compares `content-length` whenever `content-encoding` is absent or `identity`. On a cross-origin fetch the coding is hidden unless exposed and `content-length` is safelisted, so a hidden gzip length is treated as the decoded size. Snapback is cross-origin. The page code already skips that compare for this reason (`http-body.js:281-284`). URLSession copies `allHeaderFields` verbatim (`vendor/ibex/crates/ibex2/src/transport/darwin_http.mm:404-405`) while the body is decoded, so "skip when Content-Encoding is present" is the native case. Change: on the web, compare only when `content-encoding` is exposed and is absent or `identity`; otherwise trust the browser's framing. Natively, compare only when the kept headers and the delivered bytes are the same representation. Test a cross-origin gzip whose coding is not in `Access-Control-Expose-Headers`.

4. **MAJOR** — §1.5 (lines 154–158) and the §5 row say `outcome_from` splits at the first colon and cannot carry `:exact-saved`, so the page sends a `saved` field. On this checkout `outcome_from` already accepts a leading colon (`host/web/src/host.rs:81-86`), `http-body.js:251` puts `:exact-saved: N` in the header text, and `fulfill` / `fulfill_at` take only that text (`host/web/src/abi.rs:568-583`, `host.rs:1273-1289`). There is no `saved` argument. Change: keep the leading-colon line and delete the `saved` field, including the §3 test that `outcome_from` turns `saved` into the pair. Or add a `saved` argument through `fulfill` and `fulfill_at` and keep the pseudo-header out of the header text.

5. **MAJOR** — §2.4 (lines 305–306) and §2.6 (line 401) give every host `blob:<app id>/<uuid>` and resolve it by "origin". `URL.origin` of `blob:com.interview.app/<uuid>` is `"null"`; the app id sits in the pathname. The browser's `URL.createObjectURL` mints `blob:<serialized origin>/<uuid>` and will not load a hand-built app-id URL. §2.2 and §2.6 (lines 234–235, 369–371) say both web executors use the browser's Blob and URL; `localAssetURL` returns that string (`host/web/glue.js:187-201`), and `symbols.js` has no `blob:` branch. Change: the app-id form is Hermes and native only. Web `createObjectURL` is the browser's, and image/video pass that string through. Parse the native form from the pathname. State the deviation from the URL standard (an opaque origin).

6. **MAJOR** — §2.4 (lines 310–315) cites LLP 1069.005 D2b and then uses a process-wide counter `00000000-0000-4000-8000-<12 hex>`. D2b (`llp/1069.005-web-crypto-in-sources.rfc.md:253-277`) is a per-executor ChaCha20 stream through `crypto.randomUUID`, reset when the executor is created; seed 1's first TypeScript UUID is `deb201fb-035c-4c32-bbbf-3da08991a485`. A counter that survives reloads and is shared by every engine does not replay one drive and interleaves two engines. Change: under an agent drive, mint blob UUIDs from that host-side stream, or name blob URLs as a different generator and say what a drive may assert.

7. **MAJOR** — §2.3–§2.6 name `exact_blob_acquire` and a process-wide `Arc` store and no lock. Callers are the Hermes thread, a GC finalizer (§2.3 line 269), `RasterLoader.decode` (`host/apple/Sources/ExactKit/RasterLoader.swift:196-220`), and the resource-loader queue (`host/apple/videoarm/VideoArm.swift:374-387`). `new Blob` from `ArrayBuffer` parts is not specified as a copy (§2.3 lines 273–274; those copies are reads out). §2.6 (lines 373–377) releases in the `Data` deallocator and again once the bitmap exists. `RasterLoader.acquire` (`RasterLoader.swift:102-106`) returns a `byName` hit before `open`. `js/src/shim.cc` has no `setExternalMemoryPressure` call site. Change: one mutex; construction copies bytes out of JS buffers; acquire clones the `Arc` under the lock and the buffer is immutable; one release (the `Data` deallocator) after `CGImageSource` has finished; a revoke drops the `byName` entry or the hit re-checks the store. Name the JSI method on the Hermes this repo links, with a fallback if it is absent. Keep the 64 MiB `encodedLimit` (`RasterInput.swift:44`) on a memory-backed blob.

8. **MINOR** — §1.7 says `TYPESCRIPT_RUNTIME` goes from 1 to 2. The checkout is already 2, and the comment assigns 2 to `exactSaveTo` (`bake/src/compat.rs:39-42`). §2.7's bump to 3 is right only while 2 stays the save bump. Say that.

No apparatus, boot-path, or cap violation. Parent D5's "until the process ends" (`llp/1108-media-from-snapback.rfc.md:444`) against §2.4's "until that engine ends" is a tightening; record it in D5 when slice 3 lands.
