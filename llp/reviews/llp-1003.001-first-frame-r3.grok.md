NEEDS REWORK

Round 2’s pending-on-the-curve model holds, and these are closed against the code: the separate `pending` field (D1), exit `played` versus `exit_end` (D3, `presence.rs:136`), flight `curve_start` plus `land_after` (D3, `flights.rs:107-117`), filter re-seek while `"h"` is set (`SvgFilterLive.swift:132-138`, `:296-298`), boot reading a bridge latch before `sync.apply` (`host.rs:452-524`), and cancel-versus-fling (D6). Three load-bearing holes from rounds 1–2 are still open.

1. **P1 — A frame task seeks the input clock to `targetTimestamp`, so the next wall-time input is refused.** `Frames.tick` calls `runtime.frame(frameNow)` before `tick(s.now())` whenever frame tasks exist (`Frames.swift:64-74`, `Session.swift:1200`). `Runner::frame` stamps those receipts at the target (`runner/src/runner/commit.rs:228-256`). `Host::frame` stores that in `now_ms` (`host.rs:911-919`), and `commit_tree` then `engine.advance`s to each `at_ms` and finally to `now_ms` (`host.rs:1264-1268`, `:1299`). `Engine::now` is then one interval ahead of the wall. `begin_hold` / `end_hold` / the transform holds return `ClockWentBackwards` (`hold.rs:212-214`, `:346`), a transform packet is refused (`transform_drag_wire.rs:81-83`), and a height sample fails the equality check (`height_drag.rs:156`). D5’s “`tick` advances `now`” never runs: that `advance(wall)` is already behind the engine. **Fix:** `Engine::now` moves only for input, holds, releases, and timer receipts at a time ≤ wall. `Host::frame` still moves the runner and `Host::now_ms` (LLP 1073). Those curves stay pending until this callback’s `present_frame`.

2. **P1 — The same commit’s final `advance` drops a lowered pending play, so the link never starts.** `schedule_animations` keeps a node only when `live && sampled` (`animate.rs:176-186`). `advance_animations` removes it otherwise (`animate.rs:368-376`). `commit_tree` applies the play and then advances (`host.rs:1271`, `:1299`) before `quiescent()` is copied into `motion` (`host.rs:1164-1166`). A lowered play is not sampled, so one commit that only starts one reports `motion: false`. `present_frame` never runs, and the `"h"` spec stays at `speed` 0. **Fix:** a pending play occupies `animating` until `present_frame`, lowered or not; `advance_animations` must not retire it. §5’s quiescence check has to `advance` once after scheduling.

3. **P1 — Births inside a tick and commits between frames are the same clock state.** After `present_frame`, `shown == frame` and wall `< shown`, so the sampling time is `shown`. A later commit, still before the next callback, has that same `begin == shown`. “Already started” cannot be derived from `max(now, shown)`. Treating `begin <= shown` as started makes the between-frame curve start at the previous frame (the §1 jump). Leaving it pending makes a height, resize, or arrange curve show local zero twice (`host.rs:1113-1114`, `resize.rs:27-46`, `arrange.rs:434-444`). **Fix:** drop the birth-site exception. Latch the tick’s frame and call an idempotent `present_frame` at the start of `Host::present` while the latch is set, so tick, `arrange_settle`, resize, and height all start curves born since the last present before the batch is sealed. Clear the latch when `tick` returns. Between frames the latch is unset and curves stay pending.

4. **P2 — A pending clock origin is not sticky, and a pause or an unbind escapes it.** `join_clocks` resets the origin whenever `!busy` (`clock.rs:99-115`). Pending members are defined not to be busy, so a second idle join stores a new origin and the first member’s `boundary` start is left behind. An authored pause is busy, so a join before the frame takes D8’s “already running” path, is not pending, and is not shifted when the origin moves. Unbind is not the last write: it resumes from the drag’s local time and then `join_clock_node` (`timeline.rs:85-98`) overwrites that start. **Fix:** a pending origin is unchanged until the frame; every join until then enrolls and is pending, including after a pause. Pause counts as busy only once the origin has started. Unbind’s resume is pending only when `join_clock_node` does not claim the play; a running clock wins, a pending origin wins over the drag local time.

5. **P2 — Pause, path interruption, and clock join still sample `Engine::now`.** `set_animations` captures `now - start` (`animate.rs:75`, `:105-108`). After a tick, wall `< shown` and a started play’s `start` is the frame, so the hold is negative and the next `frame` paints behind what was presented. `observe_path` does the same with `self.now` (`path.rs:68-72`). `join_clocks` calls `boundary` at `self.now` (`clock.rs:84`, `:145`), so a new member of a running clock joins behind the phase already shown. **Fix:** one sampling time, `max(now, shown)`, for those three as well as `advance`, `observe`, and `frame`. Velocity tracking and `ClockWentBackwards` stay on the input `now`. `AnimationPlay::local` has to use that sampling time for a play that is running; naming `frame` does not reach it while `local` closes over `self.now` (`animate.rs:37-38`, `:266-269`).

6. **P2 — Turning the latch off does not replace a prepared host’s stored batch.** `prepare_plan_carried` keeps the boot batch beside the candidate (`abi.rs:773-784`). D7 starts the candidate’s engine and returns a batch for Swift to apply to the live presenter. `commit_plan` still installs the stored batch, whose specs are `"h":0`, onto curves already started. **Fix:** regenerating the prepared batch when the latch changes, and committing that batch.

7. **P2 — A missed target disagrees for as long as `tickInFlight` drops callbacks, not one frame.** `Frames.tick` sends no tick while one is in flight (`Frames.swift:72`, `Session.swift:597-600`). CA’s `beginTime` is the captured target (`SvgScene.swift:197`), so it keeps moving across the skipped vsyncs while sampled values stay on the in-flight batch. The starts are not re-armed, so the next tick that is sampled and applied on time matches again. **Fix:** say that in D4. The Swift test should drop two callbacks, not delay one batch by one frame.

8. **P3 — “An easing’s slope at local zero” is not what `sample` returns.** The central difference clamps the left side (`transition.rs:350-355`), so a linear easing at `t = 0` reports half its chord slope. Every interrupt before the frame inherits that. **Fix:** name `Running::sample`’s velocity, or take the slope from inside the interval.

**Q1.** Yes. `advance`, `observe`, begin, and `frame` are specified at the sampling time. Pause/resume (`animate.rs:105-108`), `observe_path` (`path.rs:68`), `join_clocks` (`clock.rs:145`), and `local` (`animate.rs:37-38`) still read `Engine::now` and can paint behind `shown`.

**Q2.** Yes. It lasts until the next on-time applied tick. `tickInFlight` can skip several vsyncs. It does not last the rest of the curve, and a lowered-only play has no sampled twin after the link stops.

**Q3.** No. A resume and an unbind both then hit `join_clock` / `join_clock_node` (`animate.rs:169`, `timeline.rs:98`). A running clock must clear pending. A pending origin must take the joiner. The drag local time survives only when the node is on neither.

**Q4.** No wrong curve. Velocity is zero (`hold.rs:341-343`); kernel commits pass `None` (`kernel/src/motion.rs:493`). The view sits on the held value for the commit plus up to one interval, then returns. That is the §1 delay as a pause. Keep the cancel pending.

**Simpler.** One sampling time and one idempotent `present_frame` at the start of `present` while a tick latch is set. That removes D5’s “born already started” special case and covers every early return. The per-curve pending bit, the input clock, and the held spec stay.
