**SHOULD-FIX.** The client shell now matches the wasm host's 100 ms barrier, and that is the right side to change. Two boot-order holes are still real.

1. **SHOULD-FIX — On a rendered page the gate runs after `font-display: optional` has already failed.** `host/web-js/build.mjs:427`. A rendered document paints its text before the module: the capture script imports `app.js` on first paint, and activation treats a boot earlier than that paint as a failure (`host/web-js/conform.mjs:615`). `optional` has a zero swap period, so a face that misses that paint stays on the fallback for the page view. Adoption reuses those nodes (`rt.js` `adopt`). Calling `FontFace.load()` inside the module cannot undo it. The non-preloaded weights (one variable file, one face per weight, `no-store`) are the ones that miss. The agent path can still win, because `?agent=1` imports at `DOMContentLoaded`, often during Chrome's preload block, which is why a conform drive can go green while a reader still sees fallback widths. `fonts-boot.test.mjs` only builds the empty shell, so it never sees this.

2. **SHOULD-FIX — Work that used to follow a synchronous `start()` now races ahead of it.** `host/web-js/build.mjs:436` and `:438`. `go(start)` returns before `start`. The else branch still schedules `requestAnimationFrame(() => setTimeout(load))` immediately, so when fonts take longer than a frame the Rust module installs first and the first commit asks it live. The baked snapshot was supposed to stand, not pending, until that load (`rt.js:526`). `wait || mixed` is fine: font fetches start at once and `go(start)` runs after `load()`. Container hatches have the same shape. Two animation frames are about 32 ms, inside the 100 ms wait, and `containers()` then does `globalThis.exact.onProject = project` (`hatches.js:669`). On the client shell nothing creates `exact` until `start()`, so that throws and the hatches never attach. A rendered page is safe only because the capture script already created `exact`.

The test does what it claims for the empty shell: three weights reach `loaded` before the first node, canvas and DOM widths agree, a 2 s font is cut at about 100 ms (`≥ 95`, `< 1000` against a 2 s body), and a page with no faces records no loads. Those bounds are not flaky. `suiteBrowser()` is the lane's Playwright Chromium. It does not cover a painted document, a failed face, or the Rust and hatch ordering. No declared face still calls `start()` synchronously. A rejected `load()` is swallowed and does not hold past the race. Stray `document.fonts` entries can delay boot by at most 100 ms. Early taps are read inside `start()`, so the wait keeps them. The 100 ms cap matches `prepareFonts` and is acceptable. Deduping preloads would not fix this: with `no-store`, each face is its own fetch, and only one of them consumes the preload.
