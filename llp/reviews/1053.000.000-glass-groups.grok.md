## Findings

**Blocker. The group view is a new non-node between a node and its children, and the scroll, clip, and pool code only understand NodeViews, the material view, and the clip box.**

`container` is `scroll ?? overlay ?? glass content ?? clipBox ?? self` (`NodeViewIOS.swift` line 522, `NodeViewMac.swift` line 521). D2 says `container` becomes the group content view and the group view is inserted as the first subview of whatever `container` is now. That fights the next style pass:

- Creating a scroll moves only direct `NodeView` subviews. On iOS it reads `subviews`, not `container` (`NodeViewIOS.swift` lines 1095–1104). On macOS teardown puts those NodeViews back on `overlay ?? materialContent ?? self` and then removes the scroll (`NodeViewMac.swift` lines 1054–1062). A group view is not a NodeView, so it stays inside the scroll and is removed with it, children included.
- `syncClipBox` does the same move from `subviews` (`host/apple/Sources/ExactKit/BoxShadow.swift` lines 140–145).
- `fitScroll` sizes the scroll's content, not an inner wrapper (`NodeViewIOS.swift` lines 1172–1174). A group view sized to the node's bounds with the material's autoresizing mask (`NodeViewIOS.swift` line 914) is the viewport, not the content. Children are positioned in content coordinates (`PresenterIOS.swift` lines 877–881).
- The pool parks a row only when every platform subview is the glyph, the material, or the clip box (`NodePoolIOS.swift` lines 44–47 and 175–190). A group view or an isolation wrapper fails that test, `children` returns nil, and the row is destroyed instead of reset. `recycle` never sees it. `list(holding:)` also requires the row's superview to be the list's `ScrollView` (lines 171–173). Rows wrapped by a group on the list itself stop qualifying. There is no macOS pool (`NodePoolIOS.swift` is iOS-only), so the macOS "pooled view resets" test in §4.5 has nothing to run.

Change the plan. Spell the precedence: the group content view is the child container only when it is the innermost wrapper, and it sits inside the scroll document view, the canvas overlay, and the clip box, in that order. `syncScroll`, `syncClipBox`, and `updateMaterial` move children from the current container and put the group view back inside the new scroll or clip box. On a scrolling node the group view's frame is the content size, updated from `fitScroll`. Extend `own` with the group view and the isolation wrapper, and teach `list(holding:)` to walk those views to the scroll. Reset them in `recycle` the way the material is dropped (lines 441–443). Drop the macOS pool test.

**Blocker. A bound `glassGroup` fails the JS web build, which is the web that ships.**

`element.rs` matches every `PropId` (`host/web/src/element.rs` line 549). A `continue` arm is required or the wasm host does not compile. That arm is not enough. A bound prop is emitted by `prop_name` (`host/web-js/src/emit.rs` lines 1151–1153). A prop the document template does not write has no DOM name and the build returns an error (`host/web-js/src/style.rs` lines 405–409). The static path's default is the opposite: an unknown prop becomes an attribute (`emit.rs` line 864). The plan allows a bound value and says the web writes nothing (`D1`, §4.4).

Change the plan. Name both files. The static arm skips the attribute. The binding emits no `P(...)` call and does not call `prop_name`. Pixels stay unchanged. Do not add it to `contains_absolute` (`contract/lower/src/tags.rs` lines 77–80) or to the web stacking set (`host/web/src/layers.rs` lines 87–89). Frames are parent-relative (`llp/1074-css-taffy-lacks.rfc.md` line 141), and a group view that fills the node at the origin does not need to be a containing block. State that the group view and its content view do not clip (`clipsToBounds` false, no mask), so an absolute child that sticks out still paints.

**Blocker. D6 refuses the wrong pair, and only in one direction.**

The effect view is built for `backgroundMaterial` or for `backdrop-filter` (`Backdrop.swift` lines 127–129 and 145–157). D6 refuses only `glassGroup` together with `backgroundMaterial`. A node with `backdrop-filter` and `glassGroup` still gets two owners of that view. The runtime sentence covers a bound material on a group node and not a bound `glassGroup` on a material node, and it does not say the group returns when the material clears.

Change the plan. Refuse both on one element, including `backdrop-filter`, with the same "put the group on the parent" message. At run time, a material view wins while it exists and the group is restored when it clears. Log once.

**Should-fix. D4's path is nodes, so it misses the views that actually sit between a group and its glass.**

The group's own `UIScrollView` is not a node (`NodeViewIOS.swift` lines 1090–1097). It sits between the group node and the glass once D2 inserts the container into `container`. Row 11's scroll is between the group and the glass. Row 13's honored opacity is the group view and above. Those are different nestings, and only the second one is "the container is inside the clip." The plan treats them as one rule.

Change the plan. Add one measured row: the container view is a subview of the scroll view, half the glass scrolled out. If that scroll clips, say so, and keep the group node excluded. If it does not, a group may not be a scroll container: Contract refuses `glassGroup` on a node whose overflow scrolls, and glass inside any scroll stays isolated. Also walk views, not only nodes, so the canvas overlay's alpha is on the path. Re-evaluate only when the condition flips across clear, not on every opacity tick. Opacity arrives as a `present` op, not as style (`host/apple/src/style.rs` lines 11–13; `PresenterIOS.swift` line 777; `PresenterMac.swift` line 937).

**Should-fix. Every reparent must keep the first responder, on both platforms.**

D4 saves it only for the macOS isolate move. Setting the prop, clearing it, and macOS rejoin also move views. Removing a view that holds the field resigns it. The consumer is the composer. Collection reorder already documents that a detach clears AppKit's first responder (`host/apple/Sources/ExactKit/Mac/CollectionMac.swift` lines 222–225). iOS `updateMaterial` already detaches children while it rebuilds the effect (`NodeViewIOS.swift` lines 906–919). The group path has to be stricter than that, because the composer is focused while an ancestor fades.

Change the plan. One helper for every move: record the first responder, move, restore if it was inside. iOS included.

**Should-fix. The end-of-batch material reorder will fight the wrapper.**

After every batch the presenter does `sendSubviewToBack(material)` (`PresenterIOS.swift` line 802). That call does nothing when the material is not a direct subview, which is the wrapped case. The wrapper is what has to stay behind the node's own siblings (the field is a sibling of the effect, added in `init`). `updateMaterial` inserts the effect at index 0 of `self`, not of `container` (line 915).

Change the plan. The install helper inserts the wrapper at the back of the node. `sendSubviewToBack` targets the wrapper. It must not pull the material view out of the wrapper.

**Should-fix. Say where a bound negative number is clamped, and what the agent reports.**

Literals can be refused in `check_prop_value` next to the material check (`values.rs` lines 483–496). A bound value is not a literal (`numeric_literal`, lines 20–25). The kernel stores the authored float (`kernel/build.rs` lines 316–345 generates the prop; it should not special-case this one). The Apple host clamps a non-finite or negative value to 0 when it sets `spacing`, the same parse as `scrollLeft` (`NodeViewIOS.swift` line 945). `native.glassGroup.spacing` is the applied value. Prop id 216 is the next free id (`schema.json` line 574 is 215). Put the `@ref` on the row, as the neighbors do.

**Should-fix. Navigation, swipe, and exit need one sentence each so the implementer does not "fix" them.**

- Routes stay in the navigation controller, not in the group content view (`NavigationIOS.swift` lines 61–64 and 131). A `glassGroup` on the navigation owner does not group the routes. - Swipe takes the top view under the scroll and moves it into the cell, then puts it back (`SwipeActionsIOS.swift` lines 202–203 and 232–259). If that top view is the group view, the whole group moves together. `placeChildren` must not pull those children back to the old container mid-swipe.
- Exit brings the leaving view to the front of its superview (`PresenceIOS.swift` line 29). Inside a group that does not change glass paint order (D5). Say that.

**Should-fix. Stored fields have nowhere to live if the node files only gain call sites.**

That file is 1470 lines of the 1500 cap, so the new stored properties are a handful of lines and the behavior stays in `GlassGroup.swift`. `NodeViewIOS.swift` is 1437. The hit-test case is a call, and it has to keep the visible-overflow bypass (`NodeViewIOS.swift` lines 691–699): the effect view's own bounds check hides children that paint outside the box.
