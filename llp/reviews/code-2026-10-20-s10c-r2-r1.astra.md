**Blocking**

- [docs/tamber-protocol.md:247](/tmp/rv-r2-1/docs/tamber-protocol.md:247): **BYO DNS does not eliminate relay impersonation.** Because those names reach the relay’s port 443, its operator can obtain individual-host certificates using [TLS-ALPN-01](https://letsencrypt.org/docs/challenge-types/#tls-alpn-01). Local DNS-01 issuance does not prevent that. Require effective developer-controlled CAA restrictions or retain the stated browser trust limitation.

- [scripts/tamber-acme.mjs:64](/tmp/rv-r2-1/scripts/tamber-acme.mjs:64): **Server-provided URLs and redirects are unrestricted.** Directory endpoints, authorization URLs and certificate URLs can target HTTP or internal services. Validate every destination and redirect against explicitly trusted HTTPS origins.

- [scripts/tamber-acme.mjs:96](/tmp/rv-r2-1/scripts/tamber-acme.mjs:96), [scripts/tamber-relay.mjs:93](/tmp/rv-r2-1/scripts/tamber-relay.mjs:93): **Authorization names are neither validated nor matched to the requested names.** A malicious ACME response can inject CRLF into the authenticated relay handshake or direct the local DNS hook to publish/delete unrelated records. Validate syntax and requested-domain membership before either path.

- [scripts/tamber-acme.mjs:82](/tmp/rv-r2-1/scripts/tamber-acme.mjs:82): **`patience` does not bound network operations.** It is checked only after `fetch()` and body consumption complete. Requests have no abort deadline, and JSON/certificate/error bodies have no byte limit, allowing stalled issuance or memory exhaustion.

- [scripts/tamber-acme.mjs:110](/tmp/rv-r2-1/scripts/tamber-acme.mjs:110): **Wildcard validation accepts a certificate for only `x.acct.relay.test`.** Replacing `*` with `x` proves coverage of one hostname. The cache repeats this mistake, and installation never rechecks the actual session names. Fresh certificates also bypass validity-date checks. Validate before caching and activation.

- [scripts/tamber-remote.mjs:444](/tmp/rv-r2-1/scripts/tamber-remote.mjs:444): **Shared-cache renewal leaves other apps serving expired certificates.** When another process renews, `get()` returns the fresh certificate with `renewed: false`; this process consequently never swaps its context. Adopt changed cached certificates regardless of which process renewed them.
