NOT READY

1. **must-fix** — `vendor/taffy/src/compute/flexbox.rs:1039` — The new probe treats “resolved cross size is `None`” as “cross size is auto”. Sizing keywords resolve to `None` (`Dimension::maybe_resolve`), so `width: min-content`, `max-content`, `fit-content()`, and `stretch` get a definite fit-content width for the height probe. The used width does not. `determine_hypothetical_cross_size` only substitutes fit-content when `size_style.width.is_auto()` (`flexbox.rs:2000`). A column item `width: min-content; flex-wrap: wrap` with three 80×10 boxes in a 200-wide column is measured at fit-content 200 (two lines, height 20) and then laid out at min-content 80 (three lines). The lines overflow. Before this patch the child’s own `width` keyword was still in force during the height measure, so the two widths matched. Require `child.size_style.cross(dir).is_auto()` in addition to `provisional_cross_removed.cross(dir).is_none()`, and add a `min-content` / `max-content` case next to the new tests in `kernel/tests/it/browser_flex.rs`.

2. **should-fix** — `vendor/taffy/src/compute/flexbox.rs:1041` — §9.2 step E’s own example is a preferred aspect ratio, not only a block-axis main size. `aspect_ratio.is_none()` leaves a wrapping flex item with `aspect-ratio` on the old path: its height is still the single-line sum, then the used width is the narrower fit-content width. The same bailout is at `flexbox.rs:2000`, so dropping it only here would make the base size and the used cross size disagree. Remove the aspect-ratio exclusion in both places and keep the ratio transfer on that fit-content size (it is definite when the available cross size is). Leaves stay excluded: a text or image leaf already wraps or takes its intrinsic size from the available cross space, and it has no child flex line to sum.

3. **should-fix** — `vendor/taffy/src/compute/flexbox.rs:1039` — `!dir.is_row()` is narrower than “a cross size is needed”. A `flex-wrap: wrap` column in a row with a definite height and `align-items: flex-start` still has no known main size, so `collect_flex_lines` (`flexbox.rs:1273`) keeps one line and the row grows to the sum of the items instead of `min(max-content, max(min-content, available height))`. Run the same probe for an item whose own main axis is the parent’s cross axis and that actually wraps (multi-line flex), and pass that fit-content size in as the known main size. Ordinary row items, whose inline size does not depend on the block size, should stay as they are. A column that itself wraps does not need a separate path: for `align-items: flex-start` the used width is the same fit-content width just measured, and for stretch the line width and the available width only differ when both are at least the max-content width, so the line count does not change.

4. **nit** — `vendor/taffy/src/compute/flexbox.rs:1037` and `vendor/taffy/EXACT-PATCHES.md:854` — The two intrinsic measures run before the definite flex-basis break (`flexbox.rs:1099`). An item with a definite height and a specified `min-height` never reads them. Move the probe to just before step E and the automatic-minimum measure. The patch note’s “one failing before” is wrong for this mechanism: all four wrapping-box cases take the one-line height without the known cross size. The text comment’s “300 wide” (`kernel/tests/it/browser_flex.rs:467`) is 29 × 16 × 0.6 = 278.4; the 200×36 assertion is still right (two 18px lines).

Clamp order, box-sizing, and margins are consistent with CSS 2.1 §10.4 and with `determine_hypothetical_cross_size`. `min_size` / `max_size` are border-box (content-box padding and border are added in `generate_anonymous_flex_items`), the same box as `measure_child_size`. Available space is the margin box; the probe subtracts `cross_axis_margin_sum` before the formula, then `maybe_clamp` applies max-cross and then min-cross (min wins). Pre-clamping available by min/max does not change that result. Percentage min/max cross sizes are already resolved against the column’s inner size. Under a min-content or max-content available cross size the probe correctly does not run (fit-content would be that constraint). The layout-cache key includes the new known width, so the height measure does not reuse a max-content-width entry.
