## Should-fix

1. **An icon param's `winning` is not what `resolve` returns.** `components` always walks (`contract/cli/src/tamber_params.rs:488-494`), including `kind: "icon"`. `resolve` returns first when the name is in `folding.icons` and its tuples have no `level` or `name` (`contract/cli/src/tamber_base.rs:213-217`). The walker also stops on an icon name (`icon.star` is not a theme token, a base, or a role) and keeps the line that wrote it (`contract/cli/src/tamber_levels.rs:179-184`), so the step is `default` or `app-param` with the param's full name. `docs/tamber-protocol.md:416-418` says this array is what `resolve`'s tuples say. Attach the same step on that icon return, or the sentence is false.

2. **`winning` walks once per tuple per param on every `describe`.** `set` does not depend on the tuple, and each call runs `params::resolve` → `folds`, which clones every param (`contract/cli/src/tamber_levels.rs:88-94`, `contract/lower/src/params.rs:186-199` and `:591`). An unset param scans every `params` line. With `P` params, `L` lines, and `T` tuples (`MAX_TUPLES` is 64) that is `P × T × L` full clones, on top of the fold `components` already repeats (`tamber_params.rs:402`). One walk is enough when no line on the chain has a `when`; reuse that step for the other tuples.

3. **The new tests do not lock the cases above or the non-library rule.** `describe_lists_…` (`contract/cli/tests/it/tamber_describe_library.rs:59`) has one tuple, no icon param, and no `when`. `Card` has params, so deleting the gate in `tamber_base.rs:123` still lists `Badge`. `an_app_with_no_library_lists_no_parts` (`:157-175`) builds an app with no params and no library component, so `components` is absent and `all(…)` is true on an empty list. Parts are added only when `d.library` is set (`tamber_params.rs:508`), which is a private package that ships a design (`contract/cli/src/sources/library.rs:40-41`). A local file with parts, or a public package with parts, is untested; so is "only a param-less library component."
