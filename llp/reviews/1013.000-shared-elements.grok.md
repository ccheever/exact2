## Must-fix

**1. A round trip never starts.** D2 flies only when the destination declares `layout-transition`. The example puts `Hero` only on the viewer image (`llp/1013.000-shared-elements-native-first.rfc.md:57-69`, `:102-112`). On close the card is the destination and has no row (`apps/interaction-gallery/app.contract:308`), so reverse, Photos return, and drag-dismiss do not run. Both ends need the curve, or the curve has to come from either side.

**2. D1 and D8 contradict.** A name must be unique among live nodes, and a second holder is dropped (`rfc:90-93`). Fullscreen routes stay mounted (`llp/1035.001-native-interaction-ownership.rfc.md:563-566`), and Messages already has both the conversation and the details route live with `navigationSource="contact-photo"` (`apps/messages-legacy/contact-details.contract:24-25`). D8 needs that same pair resident at once (`rfc:291-303`). UIKit resolves the source later, from the preceding route, by HTML id (`host/apple/Sources/ExactKit/IOS/ModalIOS.swift:281-295`). A unique style name cannot replace that lookup. Deleting `navigationSource` removes the case that works.

**3. The kernel cannot compute the handoff geometry, and `Property::Layout` is the wrong motion.** `CommitReceipt` is produced at apply, before `compute_layout` (`kernel/src/kernel.rs:440-447`). `layout_box` is parent-relative and returns `None` unless that node itself declares `layout-transition` (`kernel/src/motion.rs:311-344`). A created node is not seeded (`kernel/src/motion/layout.rs:23-41`). The first `observe` of a property snaps with no transition (`motion/src/engine.rs:376-404`). Presented boxes and hold velocity live in the host presenter and the engine, not the kernel. Seeding window boxes into a parent-space `Layout` spring interpolates two coordinate spaces. Reading the slot every frame (`rfc:145-150`) retargets that spring continuously. CSS Transitions retargeting does not track a moving rect. UIKit zoom does, because it maps progress onto a rect it re-asks for. D7 then refuses a progress value (`rfc:285-289`).

**4. `contentsGravity` does not morph the crop.** It is not an animatable `CALayer` property. D4 says Core Animation interpolates it, and also that the crop is the destination's `object-fit` for the whole flight (`rfc:169-175`). Those conflict, and neither is what Photos does. At frame 0 a `contain` image inside the thumbnail box is letterboxed, not the card's `cover` crop. The fixture only compares boxes (`rfc:360-364`), so it will not catch the jump. The animatable piece is `contentsRect` (or the zoom transition's own rect), from the source crop to the destination fit.

**5. The gallery leaver is not an exit ghost.** An exit requires a parent that survives the batch (`kernel/src/txn.rs:885-906`); exits whose parent was destroyed are dropped (`:855-857`). Photos mode is `when/else`: opening destroys the grid, closing destroys the viewer (`app.contract:191-202`). The named image is inside that subtree, so it is not in `CommitReceipt::exits` and `PresenceIOS` will not keep it (`host/apple/Sources/ExactKit/IOS/PresenceIOS.swift:1-6`). D5 (`rfc:180-184`) points at a path that does not see this node. The view has to be pulled out before the ancestor is removed. Linux cannot keep it either way (`host/linux/src/presence.rs:1-14`).

**6. Drag-to-dismiss is not a hold handing velocity to a layout flight.** `drag-timeline` progress is the source's presented **translate** (`llp/1057.003-gesture-timelines.rfc.md:90-93`), not whatever moves the view. In the gallery the hold is on `viewer-transform`, the image is a child, and release does not close: it writes `panY = 900` (`app.contract:421-430`, `:454-458`). The backdrop is inside the viewer arm, so it is destroyed with the close. A layout spring on the card does not feed `--dismiss`. Release velocity is in translate units on the parent, not `Property::Layout` on the image.

## Should-fix

**Scroll-into-view ownership is split wrong.** An authored `scrollIntoView` in the same action does join the state write in one kernel batch: commands are queued, then `tree.update` runs, then the request, then one `apply` (`runner/src/runner/commit.rs:614-627`, `runner/src/runner/lists.rs:44-57`). Case 3's "B exists when the kernel computes the handoff" is true for that command. Case 2 cannot be: `handoffs` exist only after `apply`, so the runner cannot issue them inside that commit. Case 1 is new host work. `scrollIntoView` resolves a virtualized list id and refuses anything else (`runner/src/instance/collection/into_view.rs:453-461`); ordinary scrollers are deliberately not moved (`llp/1070.000-scroll-into-view.rfc.md:48`). The gallery scroller is `scroll testId="photos-scroll"`, not a virtualized list (`app.contract:195-202`). `scrollIntoView("photos", open)` does not target it. Corrections continue for several reports (`into_view.rs:234-307`); a spring that "follows" them is the must-fix 3 bug. Photos scrolls first, then lands. Wait until the offset has converged, then start one curve.

**Reduced motion is not a producer rewrite.** `prefersReducedMotion` is a viewport fact the app reads (`runner/src/viewport.rs:162-170`). Nothing clears `transition` or `layout-transition`. Calendar still sets `layout-transition` while branching only `transition` (`examples/ios/calendar/app.contract:1153`). D11's one-line fix (`rfc:349-353`) has nowhere to go. Suppress the flight in the host when the preference is set, the way UIKit's zoom already crossfades.

**Hit-testing and accessibility disagree with the lift.** The flight layer is above route content and the live view receives input (`rfc:137-156`), while VoiceOver is pinned to the final slot. Reparenting moves the accessibility element. `1041` requires hit-testing to follow what is drawn (`llp/1041-graceful-overload.rfc.md:545`). Fixture 7 (`rfc:380-381`) says the viewer's Close control, a sibling above the image (`app.contract:436`), still receives the tap at mid-flight. It does not if the shown box covers it. Empty flight-layer space must pass hits through, and the overlap case has to be specified.

**Surface rows do not already interpolate.** There is no radius property on the engine (`motion/src/property.rs:34-88`). The surface layer copies the node's own radius with implicit actions disabled (`host/apple/Sources/ExactKit/Surface.swift:55-59`, `:113-118`). Cross-node radius is new work. Name the rows.

**Web view transitions will fight presence and the second call.** `presence-glue.js` already turns an `exit` op into an absolute ghost (`host/web/presence-glue.js:283-309`). A leaver with `exit-animation` would ghost and be snapshotted. A duplicate name aborts the document transition, not one pair. `startViewTransition` while one is active throws until `skipTransition` has cleared it. D9's same-turn skip-and-start (`rfc:329-330`) needs that sequencing. `motion-glue.js:85` does emit `linear()` for timeline springs. That part is real. The group's animation still has no release velocity, which D9 admits.

## Consider

- Drop the leaver ghost (D5). If the arriving image is in the source rect at frame 0 with the source crop, a second copy only doubles the photo. It also deletes the nested-destroy problem.
- v1 shared elements should be replaced elements only. The box-with-children rule is `1063` D6: children stay at final size while the surface changes (`llp/1063-presence-and-layout-motion.rfc.md:117-130`). That is a poor hero.
- `ModalIOS` presents with `animated: !ExactEnv.agentFreezes` (`ModalIOS.swift:302`). `scripts/agent.mjs` will not see D8's zoom. Fixture 8 has to stay a physical case.
- `1081` is still a draft and wants `layout-transition` / `spring()` spelled `-exact-`. The new attribute already follows that. The example does not.

## Better design

Keep the split Charlie ruled: names, live view on native, `startViewTransition` on the web, UIKit zoom across routes.

Make the native flight a host-owned sample of B's curve, `shown = interpolate(from_window_rect, to_window_rect, progress)`, plus a `contentsRect` from A's crop to B's fit. Sample the from-rect from the presentation layer before teardown. Do not write it into `Property::Layout`. Scroll until `1070` reports done, then start that one curve. Interrupt by sampling the shown rect and its velocity into a new curve. Leave `navigationSource` in place until a name is allowed on exactly one retained outgoing node and one incoming node. That is the zoom pair, not a duplicate-name error.

## Risk and staging

The risky part is D4+D5+D7: reparent a live view, chase a moving slot with a spring, ghost a nested destroy, and keep a translate timeline attached. That is the part that cannot be implemented as written.

Cut the ghost, the per-frame chase, and drag-coupled dismiss. Stage what is left:

1. Within-route leave/arrive of a replaced element, after scroll has settled, one fixed window rect, web `startViewTransition`.
2. iOS zoom, still keyed by `navigationSource`.
3. Interrupt and retarget from the shown rect.
4. Drag-to-dismiss only once a progress source exists. The gallery's current dismiss is the translate spring to `panY = 900`, and it should stay that until then.
