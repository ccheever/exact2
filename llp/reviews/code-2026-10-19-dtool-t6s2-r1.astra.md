**One BLOCKER found: pairing can send a previous session’s credential to a different server.**

1. **BLOCKER — Credentials are bound to a token, but not its origin or session.** [wire.ts:93](/tmp/rv-dt-t6s2/apps/design-tool/wire.ts:93) accepts an old `bound` token and sends it to the mutable `base`; pairing replaces that base at [line 128](/tmp/rv-dt-t6s2/apps/design-tool/wire.ts:128). After local use, let hello fail and pair with a different, CORS-permissive door granting write. The changed client can trigger [loadScope](/tmp/rv-dt-t6s2/apps/design-tool/app.ts:1163) before the new poll replaces `heldToken`, sending the **local token** to that door. A [review made before pairing](/tmp/rv-dt-t6s2/apps/design-tool/app.ts:772) carries the same unsafe binding. An outstanding `askToken()` can also overwrite the newly paired token. Bind credentials and reviews to an origin and session generation; reject old bindings and obsolete asynchronous completions.

2. **SHOULD-FIX — Dropping another client’s proposal can still be sent above scope.** [wire.ts:35](/tmp/rv-dt-t6s2/apps/design-tool/wire.ts:35) implements inspect’s dynamic scope rule but treats every drop as `propose`. The [server requires write for another owner’s proposal](/tmp/rv-dt-t6s2/scripts/tamber-pairing.mjs:78). A propose client can edit another client’s mapped import value: [editImport](/tmp/rv-dt-t6s2/apps/design-tool/app.ts:1307) creates a replacement and then sends the forbidden drop at line 1312, despite the separate Drop button being disabled. The server contains this with 403, but T6’s “never sent” guarantee fails. Check ownership before sending, including this indirect path.

3. **SHOULD-FIX — Mid-write revocation is not consistently terminal in the tool.** A paired 401 becomes `GONE` with `reply: {}` at [wire.ts:102](/tmp/rv-dt-t6s2/apps/design-tool/wire.ts:102). During Keep, [app.ts:870](/tmp/rv-dt-t6s2/apps/design-tool/app.ts:870) interprets that as a missing response, restores the scrub, and tells the user to keep or cancel again. Cancel similarly restores it at line 891. Separately, a late 200 still returns success after another request has set `gone`. Preserve any already-dispatched write’s actual outcome, but report revocation and retire the session instead of presenting retryable connection loss. Subsequent calls are blocked by the wire; the lifecycle and displayed outcome are wrong.

4. **SHOULD-FIX — A paired tool frames the viewer’s loopback app.** [loadHello](/tmp/rv-dt-t6s2/apps/design-tool/app.ts:623) applies `pageOf` regardless of locality. The [real server](/tmp/rv-dt-t6s2/scripts/tamber-server.mjs:692) supplies its dev-loop page to paired clients too. If that page is `http://127.0.0.1:8080`, the resulting iframe targets `http://localhost:8080` on the **viewer’s machine**. It can show an unrelated local service or fail. D12 explicitly requires no remote canvas until the authenticated gateway exists. Suppress this page/frame for paired sessions. The [stub’s paired hello](/tmp/rv-dt-t6s2/apps/design-tool/stub/tamber-stub.ts:182) returns null and masks the mismatch.

5. **SHOULD-FIX — The advertised pairing flow fails from another origin.** [The form instructions](/tmp/rv-dt-t6s2/apps/design-tool/app.contract:1287) say to accept the certificate and return here to enter the address and code. However, [pairWith](/tmp/rv-dt-t6s2/apps/design-tool/wire.ts:124) makes a cross-origin JSON POST, and [B’s Origin check](/tmp/rv-dt-t6s2/scripts/tamber-remote.mjs:149) correctly rejects that origin, including its preflight. Accepting the certificate does not change this. A page served by the door itself works; a tool opened elsewhere does not. Direct the user to the destination’s `/__tamber/tool/` before collecting its code, preserving B’s restriction. The stub’s wildcard CORS conceals this failure.

6. **SHOULD-FIX — The stub still lets a revoked client finish a pending scrub release.** [Stub revocation](/tmp/rv-dt-t6s2/apps/design-tool/stub/tamber-stub.ts:147) removes presence and build ownership but never ends `scrubs`; [its scrub configuration](/tmp/rv-dt-t6s2/apps/design-tool/stub/tamber-stub.ts:64) also omits `allowed`, whose default is true. With a delayed preview, start release and revoke while release waits: the scrub survives and its eventual write is allowed. The [real server’s revoke callback](/tmp/rv-dt-t6s2/scripts/tamber-server.mjs:626) ends absent clients’ scrubs. Round-1 finding 5 remains partially unresolved; mirror both cancellation and the release-time authorization check.

7. **SHOULD-FIX — Stub expiry cleanup requires the expired client to return.** [who()](/tmp/rv-dt-t6s2/apps/design-tool/stub/tamber-stub.ts:128) expires only the token being presented and returns immediately for local requests. Pair a client, establish its pins/inspect ownership, then stop its requests: after twelve hours, local Clients reads still list it and its ownership remains. The real implementation has expiry timers and a global sweep. Expired-code rejection and expired-token authentication are fixed, but round-1 finding 4’s expiry event/list/cleanup behavior remains incomplete.

8. **SHOULD-FIX — Read/propose clients cannot recover cached inspector selections.** When event history has rolled over, the first poll returns `missed` without selections. [waitChanges](/tmp/rv-dt-t6s2/apps/design-tool/app.ts:1082) reloads hello/builds, but never obtains the server’s cached selections. The only [refresh call](/tmp/rv-dt-t6s2/apps/design-tool/app.ts:1341) requires an existing selection and ignores `reply.ok.selections`. A newly paired reader therefore sees no selection despite the server retaining one, and cannot toggle Inspect to recover it. Seed and resynchronize selections through read-only `inspect refresh`, consuming its reply.

9. **SHOULD-FIX — Read-scope editing controls remain enabled.** [DialControl](/tmp/rv-dt-t6s2/apps/design-tool/app.contract:1967) has no disabled prop; its sliders, steppers and fields remain editable. The same applies to [branch edits, Rename/Remove/Add](/tmp/rv-dt-t6s2/apps/design-tool/app.contract:1701), Param Reset and mapped import values. A read client can change a draft and receive a scope refusal despite the page saying edits are greyed. The wire prevents the forbidden request, so this is a UI correctness issue. Pass `canPropose` through these controls and guard submit actions too.

10. **SHOULD-FIX — “Pin a value” is incorrectly restricted to write.** [app.contract:1664](/tmp/rv-dt-t6s2/apps/design-tool/app.contract:1664) disables this button for propose clients. Its [action](/tmp/rv-dt-t6s2/apps/design-tool/app.contract:1082) only opens the literal-value editor; it does not issue the protocol’s write-scoped `pin` command. A propose client should be able to draft that override and hold it for review. Gate this editor with `canPropose`.

The [new scheme-wide grants](/tmp/rv-dt-t6s2/apps/design-tool/app.ts:32) permit every HTTP/HTTPS origin, including LAN services; current fetch sites use either the fixed local API or the validated pairing origin. Finding 1 is the missing credential-to-origin boundary. Local-only methods remain denied to paired clients, and inspect refresh does not toggle builds below write.
