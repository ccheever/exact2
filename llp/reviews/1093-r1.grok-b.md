As written, the second pass, the scroll extent, `column-gap`, the balancer bound, and the host files that would hold the work do not.

1. **MATERIAL** — §D5. Writing the balanced height into the engine style and laying out again resolves percentage heights that Chrome leaves indefinite.
   Chrome 154, `column-count:2; column-fill:balance; width:400px; column-gap:0`, a `height:50%` child beside a `height:100px` sibling: the percentage box is 18px tall and the container is 59px. The same `height:50%` in a fixed `height:200px` multicol is 100px. Taffy resolves a child's percentage against `parent_size.height` once that height is known (`vendor/taffy/src/compute/block.rs:970-976`). A second pass that stores a definite height turns the 18px box into about half of 59. `measure_auto_height` then puts the arena style back, height still `auto`, and lays out again (`kernel/src/kernel/geometry.rs:57-75`), so a style mutation is not a stable used height either.
   **Fix:** Leave `height: auto` on the style. After the cut, overwrite the container's layout-output height with H and relayout ancestors only. Add the percentage child to the Chrome fixtures.

2. **MATERIAL** — §D1, §D7. Overflow columns never become the scrollable overflow the hosts publish.
   Chrome 154, six `white-space:pre` lines at 20px, `column-width:80px; column-gap:10px; height:40px; width:80px; column-fill:auto`. `overflow:hidden` reports `scrollWidth` 260 and `scrollHeight` 40. `overflow:auto` reports `scrollWidth` 530 and `scrollHeight` 25, because the scrollbar leaves one line per column. Publication stores Taffy's flow-thread overflow (`kernel/src/layout/publication.rs:92-97`). Apple and Linux start the scroll extent from that and only grow it (`host/apple/src/host.rs:1344-1351`, `host/linux/src/paint.rs:1439-1445`), so the chapter stays about 120px tall.
   **Fix:** After the cut, set the multicol container's content size to the fragmented extent: width through the last overflow column, height H. The flow-thread height must not remain in that field.

3. **MATERIAL** — §1. `column-gap: normal` is not a value of the existing row, and its used value is not 0.
   `kernel/tables/schema.json:2195-2199` stores `column_gap` as an `f32` defaulting to 0. Chrome 154's computed value is the keyword `normal`. The used gap is 1em of the multicol element's own font (font-size 40px gives a 40px gap; a 16px multicol inside a 40px parent gives 16px). Flex and grid with that same initial value use a 0 gap.
   **Fix:** Keep the stored default at 0. An unset bit on a multicol container computes to 1em of that element's `font-size`. An authored 0 stays 0. The web emits nothing when the bit is unset.

4. **MATERIAL** — §D5, §3. The balancer is not bounded by N−1 walks.
   The RFC says balancing reruns the cut at most N−1 times. Blink stretches by the least space shortage and repeats until the content fits or the max height is hit. Its own comment on the older balancer says this is typically no more than the column count (`column_balancer.h`), and `StretchColumnBlockSize` adds `minimal_space_shortage` with no N−1 stop. When the shortage is one line, each pass moves one line.
   **Fix:** Repeat while the cut reports a positive shortage and H is under its max, and stop when H does not grow. Cost the 400-paragraph probe as one walk per line moved.

5. **MATERIAL** — §D2. The patch, as specified, does not establish a block formatting context.
   §D1 requires an independent formatting context. Taffy sets `establishes_new_bfc` only for a scroll container, `align-content`, or `contain` (`vendor/taffy/src/compute/block.rs:516-532`). Chrome 154 keeps a first child's `margin-top:30px` inside the multicol: the child's top is 30px below the container's top.
   **Fix:** The patch sets that flag for a multicol container before margin collapsing. It substitutes W for the children's available width and percentage basis only after the container's content width U is known. An auto width follows §D10 item 4 and does not solve W from U.

6. **MATERIAL** — §6, §D8. The files named for the work are already on the 1,500-line cap.
   `wc -l`: `host/linux/src/paint.rs` 1498, `host/linux/src/presenter.rs` 1488 (`layout_json` and `hit`), `host/apple/src/abi.rs` 1496 (`Hooks`), `NodeViewMac.swift` 1480, `NodeViewIOS.swift` 1479. `override func hitTest` lives in the class body (`NodeViewMac.swift:668`, `NodeViewIOS.swift:722`). The RFC accounts for `kernel/src/layout.rs` at 1,492 and for no other file.
   **Fix:** Put Linux fragment painting, the `layout` reply, and fragment hit-testing in new files, called from the existing functions. Put `exact_set_lines` in `host/apple/src/abi/exports.rs` (586 lines). Bump `EXACT_ABI_VERSION` in `host/apple/include/exact.h:33`. Name those splits in §6.

7. **MATERIAL** — §D7, §D8, §D12. Stage 1 Linux has no fragment record to read, and it hit-tests the union.
   Linux paints sticky from `kernel.sticky_constraint` (`host/linux/src/paint.rs:1325-1333`). It does not consume the Apple batch. `hit` and `tap` use the painted box (`host/linux/src/presenter.rs:1127-1156`), and `tap` uses the box center. §D7's union is what `getBoundingClientRect` returns. Chrome's client rects for a 3-line paragraph in a 40px-tall column are `200×40` at x=0 and `200×20` at x=220, so the bounding union is `420×40` and covers the gap. §6 puts fragment hit testing on Apple in stage 2.
   **Fix:** Store fragments on the kernel and read them the way Linux reads sticky. Stage 1 `hit` and `tap` accept a point only inside a fragment. The Apple `fragments` op is the presenter encoding of that record.

8. **MATERIAL** — §D6, §8 Q3. A host `lines()` answer fragments one-node Markdown. Markdown splitting waits.
   §D6 tells each host to return bottoms from the paragraph it just built. The empty default is what makes a paragraph monolithic. Apple expands Markdown before layout and keeps `lineBottoms` on that paragraph (`host/apple/Sources/ExactKit/Text.swift:1298-1301` and `1083`). §8 Q3 says a Markdown node stays monolithic until its viewer asks.
   **Fix:** The kernel skips `lines` when `paragraph.markup` is Markdown.

9. **MINOR** — §D5. `column-fill: auto` with `height: auto` is a single column as tall as the content.
   Chrome 154, `column-count:3; column-fill:auto; width:300px` and six 20px blocks: the container is `300×120` and every block is at x=0. The balance second pass would distribute them.
   **Fix:** State that result. Run the second pass only for `column-fill: balance`.

10. **MINOR** — §D8. Selection treats the node as one content box.
    `TextSelectionMac.swift:293-310` subtracts `contentBox()` and calls `lineIndex`. A point in a later fragment has a y in the union frame, which is not that line's content y.
    **Fix:** Choose the fragment that contains the point, invert its `(dx, dy)` into content coordinates, then use the existing line index. Do the same on iOS.

11. **MINOR** — §6 stage 2, §D11. The reader port still settles on a timer.
    §D11 and §8 Q2 leave the 100ms timer. Stage 2 deletes the line-grid page height and does not name a resize event. The decision is that the event lands before stage 2.
    **Fix:** Stage 2's reader reads `frame()` from that event and deletes the timer. The event's API stays in its own document. This document names the call site.

12. **NIT** — §D2. The regression named for an unchanged container is gone.
    `vendor/taffy/EXACT-PATCHES.md` Patch 7 says the emulated-callback differential was removed. What remains is the 512-tree incremental-versus-fresh comparison.
    **Fix:** Cite that comparison.

13. **NIT** — §D6. The ABI version is not in `measure.rs`.

    **Fix:** Name `exact.h`.
