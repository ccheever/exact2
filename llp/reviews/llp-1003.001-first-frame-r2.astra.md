NEEDS REWORK

1. **P1 — Late asynchronous delivery still breaks phase agreement.** D4’s claim that both executors are “late together” is false. The batch contains values sampled at target F, but CA’s absolute `beginTime=F` makes it display positive elapsed time when delivered after F ([Session.swift:597](host/apple/Sources/ExactKit/Session.swift:597), [SvgScene.swift:197](host/apple/Sources/ExactKit/SvgScene.swift:197)). The target is a [submission deadline](https://developer.apple.com/documentation/quartzcore/optimizing-iphone-and-ipad-apps-to-support-promotion-displays), not confirmation of presentation. **Fix:** specify an atomic activation/submission boundary and missed-target policy; rearm pending starts without replaying timers/tasks. Test a deliberately delayed batch containing both sampled and lowered motion.

2. **P1 — D5’s future engine clock breaks input and release semantics.** An engine sampled at 116 ms rejects a valid 110 ms transform input ([transform_drag.rs:203](host/apple/src/transform_drag.rs:203)). Clamping timestamps also defeats height tracking’s equality check ([height_drag.rs:156](host/apple/src/height_drag.rs:156)). Moreover, velocity-bearing `observe` starts at `engine.now`; `Change` carries no release timestamp ([engine.rs:36](motion/src/engine.rs:36), [engine.rs:445](motion/src/engine.rs:445)). **Fix:** separate input timestamps from presentation time; preserve raw times for velocity and release origins. Include the engine in the agent takeover floor, currently only wall/runner ([Agent.swift:492](host/apple/Sources/ExactKit/Agent.swift:492)).

3. **P1 — A pending clock cannot be treated as an already-running busy clock.** A joins an idle clock and becomes pending; B joins before the frame. A’s hold makes the clock “busy,” exempting B, then D8 shifts only A/origin and breaks their phase agreement ([clock.rs:109](motion/src/engine/clock.rs:109)). Existing joining also skips every held play ([clock.rs:142](motion/src/engine/clock.rs:142)). **Fix:** represent a pending origin explicitly; enroll subsequent joiners until activation, distinguish authored pauses, and track actual membership through departures and transfers.

4. **P2 — Play ownership remains underspecified.** D1 includes newly added paused plays; D2 unconditionally clears their hold, potentially starting an authored pause ([animate.rs:125](motion/src/engine/animate.rs:125)). Drag unbinding independently resumes plays without passing through `set_animations` ([timeline.rs:85](motion/src/engine/timeline.rs:85)); binding overwrites every play’s hold, including appended exits ([timeline.rs:158](motion/src/engine/timeline.rs:158)). **Fix:** define explicit transitions among pending, authored pause, drag ownership and running; specify exit ownership and both directions of timeline transfer.

5. **P2 — Height layout is not the last source of curves in a tick.** After `present`, `finish` runs resize handlers whose commits can create and present more curves ([host.rs:1153](host/apple/src/host.rs:1153), [resize.rs:39](host/apple/src/resize.rs:39)). The arrange-settle early return also bypasses the proposed ordinary start step ([host.rs:1113](host/apple/src/host.rs:1113)). **Fix:** carry frame context through these paths and activate after their final curve births. Test resize-handler and arrange-completion motion.

6. **P2 — Activation needs scheduling and presenter updates, including on takeover.** Pending holds fail `live`/scheduling and `spatial` checks ([animate.rs:176](motion/src/engine/animate.rs:176), [engine.rs:674](motion/src/engine.rs:674)). Native emission visits only dirty roots/boxes ([svg.rs:201](host/apple/src/svg.rs:201)). An engine-only flag change leaves cached `"h"` authoritative even under an agent clock ([SvgScene.swift:178](host/apple/Sources/ExactKit/SvgScene.swift:178)); `take` returns without another batch. **Fix:** one activation helper must reschedule sampled plays, preserve pending spatial demand, dirty every affected lowering path, and emit/apply the replacement batch when disabling the flag.

7. **P2 — D7 names the wrong boot/reload seam.** Immediately after runtime creation there is no `Host` to configure ([abi.rs:121](host/apple/src/abi.rs:121)). Reload reuses the runtime and prepares another Host, including its initial batch ([Session.swift:865](host/apple/Sources/ExactKit/Session.swift:865), [abi.rs:753](host/apple/src/abi.rs:753)). **Fix:** persist the setting in `Bridge`, inject it before every Host’s initial motion sync, and propagate changes to prepared candidates. Test boot and reload.

8. **P2 — Shared spec serialization does not guarantee a held renderer.** Filtered SVG’s offscreen branch intentionally leaves animations running, setting their start from wall time ([SvgScene.swift:189](host/apple/Sources/ExactKit/SvgScene.swift:189)). `CARenderer` samples at a later wall-time read ([SvgFilterLive.swift:317](host/apple/Sources/ExactKit/SvgFilterLive.swift:317)). Pending local time can therefore advance. **Fix:** evaluate held tracks at one explicit renderer instant, or materialize their held values. Add a filtered-SVG test; inspecting `"h"` alone is insufficient.

9. **P2 — Pending exit deadlines collide with the enqueue sentinel.** `Leaving.end == None` currently means “call `play_exit`,” so using it for “enqueued but pending” can append exits again on each intervening commit ([presence.rs:134](host/apple/src/presence.rs:134)). **Fix:** separate enqueue state/play identity from optional deadline; test multiple commits before activation.

10. **P3 — Correct two semantic claims.** D3’s “zero for an easing” disagrees with the derivative returned at zero by, for example, linear easing ([transition.rs:350](motion/src/transition.rs:350)). D8’s `observe_settled` exemption applies only to idle properties; live ones delegate to ordinary observation ([engine.rs:516](motion/src/engine.rs:516)). **Fix:** specify the actual initial sample/velocity and exempt only changes that genuinely create no curve.
