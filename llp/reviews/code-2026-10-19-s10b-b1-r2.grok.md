## Should-fix

**Pre-handshake sockets are neither timed out nor counted.** `scripts/tamber-remote.mjs:148-173`. `limit()` sets `maxConnections = 64` and `handshakeTimeout`, then arms the socket timer only on `secureConnection`. On this Bun, `node:https` does not emit `connection` for a raw TCP client, and it does not enforce either property. A silent TCP client was still open at 1.7s with the timer at 350ms. Seventy stalled TCP clients all stayed open past a cap of 64, and a further TLS `GET` still returned 200. A server with `maxConnections = 1` accepted a second in-flight TLS request. Trickled non-TLS bytes are cut, so only the silent accept path is open.

Own the accept socket. Listen with `node:net`, count there, destroy anything over 64, and destroy any socket that has not finished the handshake within `timeoutMs`. One `timeout` listener, armed before TLS.

**The idle timer drops for the whole time a handler is reading the body.** `scripts/tamber-remote.mjs:151-153`. `request` fires when the headers are complete, and that is when `setTimeout(0)` runs. A handler that waits on the body stayed up past 1.6s against a 350ms cap, both with a stalled body and with a body trickled a byte at a time. Today's production paths 404 on `access.remote` before `body()` (`scripts/tamber-server.mjs:491`), and that response rearms the timer, so a stalled body on those routes is cut at about the cap. Pairing will read the body. Clear the timer on `req`'s `end`, and rearm it on `res`'s `finish`. A 900ms response against a 350ms cap already returns 200 once the body has ended, so a long poll and the events stream stay intact.

**`addPort` builds the request URL from the caller's Host and does not admit it.** `scripts/tamber-remote.mjs:187-191`. Origin-form is required, so `GET http://x/page`, `//`, and a backslash are 404. `GET /page` with `Host: evil.example` is 200, and the handler receives `https://evil.example/page`. Cookies are left in place, which the comment says is intentional for the canvas gateway. Nothing calls `addPort` yet. Parse against the listener's own host, and admit that host the same way `remoteHandler` does (`scripts/tamber-remote.mjs:120-123`).

**`tamber serve` leaves the plaintext listener up if the remote port is taken.** `scripts/tamber-server.mjs:1057-1060`. `listen()` binds first and only closes that server inside its signal handler (`:1038`). The catch calls `tamber.close()` and `process.exit(1)`. `tamber.close()` waits on the design child for up to about 7 seconds, and during that wait the plaintext server is still answering, including `GET /__tamber/token` from loopback. Have `listen()` return a closer and call it in that catch before `tamber.close()`. The JS dev loop already does this: `host/web-js/dev.mjs:1012` and `:1028` close the HTTP server, then the wire, and exit 1.

## Nit

**`setTimeout(ms, cb)` stacks a new `timeout` listener on every rearm.** `scripts/tamber-remote.mjs:150` and `:153`. `setTimeout(0)` disables the timer and leaves the old listeners. The official test prints `MaxListenersExceededWarning` at 11 listeners. Install one `timeout` listener that destroys the socket, and call `setTimeout(ms)` / `setTimeout(0)` with no callback.

**The wasm dev loop's `stop` never closes its HTTP server.** `host/web/dev.mjs:980-989`, used on remote-bind failure at `:1495`. It closes the design server and the remote doors, then exits. The process does exit. The JS loop's `stop` is the one that calls `server.close()`.

**A Host that canonicalizes to an allowlisted address is admitted with no Origin.** `scripts/tamber-remote.mjs:120-123`. `2130706433`, `0x7f000001`, `127.1`, and `127.0.0.1.` all become `127.0.0.1` inside `new URL`, so they reach the wire. The same request with an Origin is 403, because the Origin's host is the canonical name and the raw Host is not. A browser on a non-443 port sends the port, and a non-browser can omit Origin anyway. Compare the canonical hostname on both sides if you want one spelling.

**The Origin check compares the raw Host to the parsed Origin host.** `scripts/tamber-remote.mjs:126`. `Host: [0:0:0:0:0:0:0:1]:port` is admitted (canonical `::1`), then `Origin: https://[::1]:port` is 403. It fails closed. A browser that canonicalizes before navigating still matches.

**The flag parser rejects a dotted IPv4-mapped address, and binding `::` does not list IPv6 interfaces.** `scripts/tamber-remote.mjs:78` and `:86-91`. `[::ffff:127.0.0.1]:7443` fails the regex (the dots); `[::ffff:7f00:1]:7443` is accepted. `remoteNames('::')` is `localhost`, `127.0.0.1`, and `::`. `0.0.0.0` does enumerate non-internal IPv4. That is a name-coverage gap, and the Host check still 404s anything outside that list.

**The timeout test's name overclaims, and several probes are absent.** `scripts/tamber-remote.test.mjs:205-221` cuts a header that never finishes and checks that a 600ms answer returns 200. It does not leave a connection idle after a finished response. Idle-after-response does work; I measured it at about the cap. Also untested: a silent TCP client, a handler blocked in the body, `addPort` with a foreign Host, a live `::1` listener, `Origin: null`, a tool symlink, and a decimal Host. The cases the suite does claim are real. Plaintext returns zero bytes containing `HTTP/` and the wire is not called (`:114-117`). Both cookie spellings are gone from `rawHeaders` and `headersDistinct` (`:22-23`, `:124-126`). The `//`, `///`, and backslash 404s go through `node:https` `path` and are not rewritten by the client (`:130-132`); the same targets on a raw TLS socket also 404 with the wire uncalled.
