1. **High — Cancel can leave the opening scrub active.** [app.ts:850](/tmp/rv-dt-t2c/apps/design-tool/app.ts:850), [app.ts:874](/tmp/rv-dt-t2c/apps/design-tool/app.ts:874). Start a scrub and press Cancel before its first response arrives. `scrubbed` is still null, so Cancel sends nothing and reports that committed values were restored. The opening request subsequently previews and installs its ID despite `scrubbing=false`. Dropping the resource’s reply does not prevent this module-level assignment. Likewise, an old `ended` response can clear a newer handle. **Fix:** track an opening/closing generation, freeze its opening review and token, cancel any session returned after cancellation, and fence every completion against its generation and ID.

2. **High — Keep can write one operation and record another for redo.** [app.ts:839](/tmp/rv-dt-t2c/apps/design-tool/app.ts:839), [app.ts:861](/tmp/rv-dt-t2c/apps/design-tool/app.ts:861). Scrub a token’s colour, then use its Rename control. The non-scrubbable draft returns `ok:true` with the existing scrub ID, enabling Keep. The server writes the last colour preview, but the tool records the rename operation in the undo entry. Undo restores the colour; Redo renames the token. Clearing a value has the same mismatch. Selecting another cell also hides the scrub controls without cancelling the session. **Fix:** bind the session to its file, operation, target and branch; cancel or require another explicit choice when those change. Record the acknowledged operation actually released, and disable Keep for an unmatched draft.

3. **High — A server restart can silently reopen the scrub on the new server.** [app.ts:970](/tmp/rv-dt-t2c/apps/design-tool/app.ts:970), [app.contract:426](/tmp/rv-dt-t2c/apps/design-tool/app.contract:426). An epoch change clears `scrubbed` but leaves Contract’s `scrubbing=true`. The epoch refreshes the proposal; its new `review` then triggers `scrubFrame`, which opens a new session using the new server’s token and digests. If another app now occupies the port and accepts that target, its running copies receive the old draft without a new scrub choice. **Fix:** terminate the gesture and publish its end on an epoch change. Require an explicit start against a fresh review.

4. **Medium — An old end notification stops the next scrub.** [app.contract:466](/tmp/rv-dt-t2c/apps/design-tool/app.contract:466), [app.contract:559](/tmp/rv-dt-t2c/apps/design-tool/app.contract:559). After an idle or competing-write end, `changes.scrubEndKey` remains populated. Starting again sets `scrubbing=true`, immediately rearming the timer for that previous end. It can stop the new scrub before its opening response arrives, without cancelling it. Clearing module-level `scrubEnd` later does not clear the cached `changes` resource. **Fix:** consume end notifications once and match them to the active gesture/session. The stub test restarts without advancing this timer before Keep, masking the failure.

5. **Medium — Missed events can leave “Previewing” displayed indefinitely.** [app.ts:976](/tmp/rv-dt-t2c/apps/design-tool/app.ts:976), [app.ts:989](/tmp/rv-dt-t2c/apps/design-tool/app.ts:989). Scrub cleanup depends entirely on receiving its terminal event. If a backgrounded tool misses enough build/status events to evict the idle notification, the server returns `missed:true` with no events. The tool retains the expired ID and successful scrub resource, although the server has restored committed values. **Fix:** reconcile active scrubs on an event gap; with the existing wire, conservatively cancel the bound ID, accept “no such scrub” as ended, and require a new explicit start.

6. **Medium — The requested scrub gesture is not implemented.** [app.contract:559](/tmp/rv-dt-t2c/apps/design-tool/app.contract:559), [app.contract:1129](/tmp/rv-dt-t2c/apps/design-tool/app.contract:1129). “Scrub live” starts a persistent mode, and only Keep releases it. The slider still listens to `change`, so dragging sends no intermediate values until release. A user can therefore drag, release, and later lose the preview to the 30-second timeout instead of committing once. This differs from the brief and D6’s gesture lifetime. **Fix:** retain explicit opt-in, then bind opening to press, frames to continuous input, release to one write, and Escape/cancellation to restoration.

7. **Medium — The integration test does not prove preview delivery or undo restoration.** [design-tool.test.mjs:798](/tmp/rv-dt-t2c/scripts/design-tool.test.mjs:798), [design-tool.test.mjs:841](/tmp/rv-dt-t2c/scripts/design-tool.test.mjs:841). It reads the server’s `/__dev/design` snapshot, while the “unchanged plan” assertion compares JS-host plan fields that are always `null`. Removing the frame’s live-batch application could still pass these checks. The drive also never invokes Undo; it only checks the count. **Fix:** observe the frame’s reported design digest or rendered value before, during and after cancellation, establish a pre-scrub reload baseline, and actually undo and compare original bytes. Replace fixed real-clock pauses with those observable conditions, as `docs/testing.md` requires.

8. **Low — The scrub stub accepts requests the real server rejects.** [tamber-stub.ts:68](/tmp/rv-dt-t2c/apps/design-tool/stub/tamber-stub.ts:68). It ignores `request.scrub`, opening digests and client presence, and has no automatic idle expiry or delayed/coalesced replies. For example, a late frame naming an ended scrub opens another session in the stub; the real server returns 409. **Fix:** reproduce these protocol checks and terminal behavior, preferably using `scrubSessions` with fake I/O, and make delayed replies controllable for lifecycle tests.

Verdict: Request changes.
