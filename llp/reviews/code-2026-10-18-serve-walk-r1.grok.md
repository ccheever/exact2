1. **Blocking** — `contract/cli/src/tamber_serve.rs:434-436` (walk freshness). A consulted path whose device and inode changed is still treated as fresh when `std::fs::read` returns the same bytes. `stamp` follows symlinks (`metadata` at `tamber_serve.rs:180`), and package resolution records the link path on purpose (`contract/cli/src/resolve.rs:285-287` and `:334-337`): relinking `node_modules/<pkg>` at another directory changes what `use` resolves without editing either tree. If `package.json` and the entry file match byte for byte, the check stops there. Transitive sources stay at the old canonical paths, so the next `resolve` / `propose` keeps the old params, the old owned-file list, and the old synthetic key. The previous code ran `source_graph` on every request, and that new file set was the key. **Fix:** same inode and same digest may skip a rewalk; a different `(dev, inode)`, or a stamp that appeared or disappeared, must rewalk even when the bytes match.

4. **Blocking** — `contract/cli/src/tamber_serve.rs:423-431` and `contract/cli/src/tamber_contract.rs:52-73`. Retargeting an existing `node_modules/pkg` symlink, or adding `@scope/pkg` under an `@scope` directory that is already listed, changes which files are the app’s without a new top-level name. Adding or removing `"name"` in a vendored `package.json` that no `use` consulted does the same, and it changes param identities (`home` in `contract/cli/src/sources.rs:229-242`). Previously `owned` and read-path `params_of` re-read those inputs every request. **Fix:** record each entry’s canonical target, including `@scope/*`, and stamp every `package.json` `owned` / `home` reads.
