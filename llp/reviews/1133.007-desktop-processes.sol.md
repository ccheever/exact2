**Reviewer:** codex gpt-6.1-sol, reasoning effort ultra (confirmed in the run log), run 2026-10-22 by Claude (Opus 5.5) for Daehyeon Mun, read-only (`codex exec -s read-only`) on an export of `daee3d11bb` with `llp/reviews/` left out; it could read the T3 Code clone and the reference app on disk. Blind: no other review existed. Not redacted (the document holds no secrets). Scope given: the ceiling test and tier boundaries, the D9 checklist, the platform claims, the design against the runner, executor and hosts, security and the system-binary decision, stage feasibility and the consumer, the questions for the ruling. The RFC was LLP 1133.005 when reviewed and was renumbered afterwards, so both reviews cite `llp/1133.005-desktop-processes.rfc.md`. A second family (Grok) was not run: its CLI is not signed in on this machine. The text below is the reviewer's final message, unedited except that absolute export paths in its links are shortened to `RFC:<line>`.

VERDICT: NOT READY

1. **MATERIAL — The executor binding and admission route remain unspecified.** RFC:515–525 says adding an executor implementation enables ordinary module binding. Existing bindings generate one-options-object Promise calls serialized as JSON (`js/bake/src/typescript.mjs:1032–1053`); native streams are expressly refused (`host/apple/src/executor_core.rs:1099–1106`). Neither represents the proposed mapper callback, binary data and opaque child handle. **Resolve:** specify the declaration, generated binding and executor request protocol, including common admission, source-scoped grants, origin, substitution and release. The D5 vocabulary exception is reasonable; it does not itself define this route.

2. **MATERIAL — Process exit is confused with completion of output.** RFC:227–244 ends the stream at `exit` while promising lossless output. Stdio can remain open after exit, which is why Node distinguishes [`exit` and `close`](https://nodejs.org/api/child_process.html#event-close). The clone explicitly drains both pipes, bounded at five seconds, before finalizing or restarting (`T3LocalBackendManager.swift:323–335`). **Resolve:** separate exit, pipe EOF and final completion; flush decoders and accepted chunks before completion or restart. Define the bound when descendants retain pipe handles.

3. **MATERIAL — Restart and kill need an incarnation-aware lifecycle.** RFC:308–310 reuses a handle across restarts, but existing staged operations address only the stream ticket (`runner/src/request.rs:562–573`). A delayed write, `end` or signal needs a defined relationship to the replacement child. Separately, RFC:245 calls `child.kill` a release, while RFC:251–253 says it is not. **Resolve:** address staged operations, probes and escalation timers to an incarnation; reject stale operations and reset stdin state. Distinguish signalling from release, including restart suppression and whether nonterminating signals receive any escalation.

4. **MATERIAL — Streaming stdin lacks a progress protocol.** RFC:232–240 provides per-turn quotas but no transport-wide buffering contract or writable notification. A quiet child that consumes several MiB before producing output cannot be fed reliably through mapper events alone. D7 also imposes transport bounds and cumulative per-answer bounds, not merely per-turn bounds (`llp/1016.000-answers-that-keep-coming.rfc.md:236–242,381–390`). **Resolve:** define bounded stdin buffering with acknowledgements, `drain`, or an awaitable write mechanism that preserves commit staging. Include large streaming stdin in the ceiling test.

5. **MATERIAL — The secret-field guarantee misses existing text-bearing channels.** RFC:438–442 sanitizes ordinary event `value`, but existing `beforeinput` carries both replacement text and the prior value (`host/apple/Sources/ExactKit/FieldInput.swift:69–81`). Web `beforeinput`, selection and ancestor keyboard handlers expose text too (`host/web-js/rt.js:926,931,1132–1137`). **Resolve:** specify redaction or refusal across every text-bearing event and read, including ancestor handlers, paste, selection, IME and replacement paths. Define the new `length` payload, which current `InputEvent` lacks (`contract/types/src/selection.rs:173–183`), and drive these cases on each field target.

6. **MATERIAL — Held secrets need an explicit volatile storage contract.** RFC:432–448 reuses `store.get/set/forget` while excluding persistence and carry. Today `Store::set` produces durable writes, and `snapshot` carries stored values (`runner/src/store.rs:386–399,464–470`; `runner/src/runner.rs:714`); the web persists writes to localStorage (`host/web-js/rt.js:385–393`). **Resolve:** define the volatile provider/tier, exclusion from snapshots and durable writes, conflicting `secret.keep`/`secret.hold` names, source-scoped access, and field synchronization with committed `set/forget`.

7. **MATERIAL — Tool-origin execution can trigger the system UI that the parent forbids.** RFC:530–540 permits every operation from tools because none opens a prompt. Yet RFC:595–600 expressly allows children to trigger app-attributed protected-file prompts. Free arguments and arbitrary programs can also open UI. This conflicts with parent D6 rule 3 and its refusal of tool-opened prompts (`llp/1133-the-standard-library.rfc.md:349–356,557–560`). **Resolve:** define an enforceable origin policy for these indirect effects, or explicitly request an amendment. “Spawn itself has no prompt” does not settle it.

8. **MATERIAL — Scratch `home:` does not isolate real SSH execution.** RFC:604–622 runs real children by default while claiming the drive never reads the person's `~/.ssh`. Framework path remapping cannot constrain external programs. [OpenSSH uses the passwd home directory](https://github.com/openssh/openssh-portable/blob/master/ssh.c#L550); changing `HOME` alone is insufficient. The clone currently requires an agent SSH substitute and supplies isolated configuration (`T3Ssh.swift:52–55,344–348`). **Resolve:** require appropriate doubles or actual child isolation, or narrow the guarantee and retain explicit configuration, identity and agent isolation in consumer drives.

9. **MATERIAL — The claimed Swift deletions require additional capabilities.** RFC:736–744 overstates what stages 0–2 free:
   - Runtime installation reads bundle resources and uses an interprocess lock and symlink/mode validation (`T3LocalRuntime.swift:73–105,179–201`). Bundle resources currently require native `Bundle.main.resourceURL` access (`docs/reference.md:718–724`).
   - Askpass requires an executable 0700 helper (`T3SshAuth.swift:39–47`), while RFC:686–690 defers the host helper and treats `chmod` only as a possible launcher follow-up.
   - Editor discovery checks executability throughout arbitrary PATH directories (`T3RemoteEditors.swift:109–131`). Existing `stat` exposes no executable-access result (`vendor/ibex/crates/ibex2/src/stdlib/fs.rs:324–333`).

   **Resolve:** admit or name these dependencies and provide concrete migrations, or narrow the deletion table and 3,882-line claim.

10. **MATERIAL — Readiness cannot reproduce the SSH tunnel behavior.** RFC:311–316 accepts only 2xx and repeats timeout rounds. The tunnel accepts any status below 500 and fails after twenty seconds (`T3Ssh.swift:422–432,555–567`). A healthy endpoint returning 401 or 404 never becomes ready. **Resolve:** provide a success-status policy and timeout action, or demonstrate another supported implementation of that consumer behavior.

11. **MATERIAL — Linux crash cleanup is weaker than the table implies.** RFC:467–472 uses `PR_SET_PDEATHSIG` as crash cleanup. It targets the immediate child, is cleared in forked descendants, depends on the creating thread, and needs installation-race handling. [Linux documentation](https://man7.org/linux/man-pages/man2/PR_SET_PDEATHSIG.2const.html). Process groups also do not contain descendants that deliberately leave them. **Resolve:** state the precise cleanup boundary and implement the parent recheck/thread-lifetime requirements. Also specify the platform setup needed for descriptor closure and signal-mask reset; those guarantees do not follow from plain Rust `Command` alone.

12. **MATERIAL — The ceiling test is incomplete.** RFC:554–574 omits ordinary file-backed/merged stdio, suspend/resume and Windows verbatim argument handling. Tier 1 permits only pipe/ignore and excludes `SIGSTOP`/`SIGCONT`; tier 3 offers nothing. The priority row claims tier 2 coverage, but D10 provides no Linux priority control. These are established [Node options](https://nodejs.org/api/child_process.html#optionsstdio) and [Foundation operations](https://developer.apple.com/documentation/foundation/process/resume%28%29). **Resolve:** reach each through a tier or name its intentional exclusion and reason. Mark listed-but-deferred tier-2 features as deferred, rather than counting them as reached.

13. **MATERIAL — Stage 0 cannot yet deliver its promised substitute-first drive.** RFC:659–669 puts substitutes in stage 0 but process execution in stage 1; its substitute is another executable using that transport. It also leaves agent-clock behavior for restart, readiness and timeouts undefined. **Resolve:** provide a synthetic event substitute, or move enough execution machinery into stage 0 to make the drive runnable. Specify clock behavior and failure injection. Launch flags and `state` forms preserve the existing operation count.

14. **MINOR — Finish the declarations, examples and ruling text.** RFC:479–487 lacks D9-required platform links and precedence explanations. Further corrections:
   - RFC:401 compares login-PATH lookup to Node, although [Node honors `options.env.PATH`](https://nodejs.org/api/child_process.html); declare the deviation.
   - RFC:343–349 omits the clone's Nushell handling (`T3LocalShellEnvironment.swift:36–50`) and a reliable Linux fallback.
   - RFC:199–203 passes the bootstrap envelope through resource arguments, although it contains secrets (`T3LocalBackendManager.swift:51–58`). Build it inside data code.
   - Q1's claim that extension arguments inherently become Contract values is inaccurate; data-code `native.later` already sends request-body bytes (`js/src/prelude.js:1257–1263`). Retain the valid ordered-stream objection.
   - Q7's waiver text says the held-secret field is absent outside desktops, contradicting stage 2's web/iOS scope. Add Expose's missing target cell. Keep binary cost explicitly pending measurement.

The resource-owned process lifetime, executor ownership, commit-staged input and lossless receive backpressure are sound foundations. Named environment grants, explicit executable targets and post-first-pixel capture address real consumer needs. The grant discussion correctly avoids claiming to sandbox child behavior, and Windows' native-drive requirement is appropriate. Most D9 headings are present, but the contracts above prevent the checklist and consumer-completion claims from being considered satisfied. No files were edited.

## r2 (2026-10-22)

**Reviewer:** codex gpt-6.1-sol, reasoning effort ultra (confirmed in the run log), a fresh session, read-only on an export of `c9226c1b40` with `llp/reviews/` left out. The r1 artifact was not in the export; r2's own §16 summarised r1's findings, so this round knew what r1 had raised. The text below is the reviewer's final message, unedited.

VERDICT: NOT READY

1. **MATERIAL — Process-group cleanup fails when the leader exits first.** `llp/1133.005-desktop-processes.rfc.md:570` validates leftovers using the leader’s PID and start time, but `:575` promises cleanup of surviving group members. Linux’s parent-death signal kills only the direct child; ordinary grandchildren can survive after that identity disappears. The same identity problem exists on macOS. Also, ending escalation with the incarnation (`:355`) can cancel the promised group `SIGKILL` after the leader closes. Define cleanup ownership that survives leader exit, reconcile configurable grace with the five-second quit limit (`:569`), and drive a surviving grandchild. [Linux documents the parent-death limitations.](https://man7.org/linux/man-pages/man2/PR_SET_PDEATHSIG.2const.html)

2. **MATERIAL — Launch-only origin checks do not enforce the claimed UI boundary.** The RFC permits mutations to write retained child handles (`llp/1133.005-desktop-processes.rfc.md:255`) and signal them (`:286`), while checking origins only for new launches and initial environment capture (`:672`). A foreground-spawned shell can subsequently receive a tool-origin command that opens UI or accesses a protected directory. Thus `:743` overstates the protection. Carry origins into process operations and define their admission policy, or explicitly narrow the parent guarantee and present that amendment in Q8.

3. **MATERIAL — The agent substitute’s system-program restriction is bypassed by permitted descendants.** Real `bundle:`, `home:` and `app:` executables run by default (`llp/1133.005-desktop-processes.rfc.md:747`), and their descendants require no grant (`:487`). Such a program can invoke the real SSH executable and use the person’s actual home. The assertion that the preceding rule prevents unisolated real children (`:776`) therefore does not hold. Require explicit real execution for all executable targets, or state the trusted-code boundary clearly and remove the isolation implication.

4. **MATERIAL — Held-secret delivery across executor boundaries is missing.** D8 excludes held secrets from snapshots (`llp/1133.005-desktop-processes.rfc.md:515`) while promising access through `store.get` (`:534`). However, the module ABI supplies secrets through `Store::snapshot()` and reconstructs a mirror (`logic/abi/src/lib.rs:121`, `:598`); web wasm/worker dispatch also serializes that snapshot (`js/web/src/lib.rs:671`). Native main-thread TypeScript has a direct store door (`js/src/door.rs:32`), but these other callers do not. Specify a grant-scoped, volatile transfer distinct from durable snapshots and carry, and include those callers in the stage-2 drive.

5. **MATERIAL — `wx` does not replace the consumer’s installation lock.** `llp/1133.005-desktop-processes.rfc.md:463` and `:914` claim an exclusive-create lock shared by applications using `~/.t3`. The clone opens `.install.lock`, acquires `flock`, then unlocks and closes without deleting the file (`examples/t3-code/modules/apple/T3LocalRuntime.swift:100` in the clone checkout). Consequently, `wx` fails after an ordinary previous launch and does not observe an active advisory lock. Add compatible advisory locking, or specify a replacement protocol covering contention, ownership and crash recovery. [Node’s `wx` semantics](https://nodejs.org/api/fs.html#file-system-flags) and [Apple’s `flock` semantics](https://developer.apple.com/library/archive/documentation/System/Conceptual/ManPages_iPhoneOS/man2/flock.2.html) are different.

6. **MATERIAL — The runtime integrity checks cannot be preserved by the proposed filesystem additions.** The deletion claim says `stat` checks symlinks and modes (`llp/1133.005-desktop-processes.rfc.md:914`). The clone actually requires `lstat`, the link target, and incremental SHA-256 checks (`examples/t3-code/modules/apple/T3LocalRuntime.swift:167`, `:185`). Existing `stat` follows links (`vendor/ibex/crates/ibex2/src/stdlib/fs.rs:399`), and D6a adds neither `lstat` nor `readlink`. The archive is 81,251,357 bytes (`examples/t3-code/server-runtime/runtime-pin.json:10`), exceeding the existing raw `readFile` limit of approximately 12 MiB (`vendor/ibex/crates/ibex2/src/stdlib/fs.rs:30`). Add non-following metadata, link reads and a bounded hashing route, explicitly name suitable helper programs, or retain this native code and reduce the deletion claim.

7. **MATERIAL — Mapper appends do not provide the claimed output-redirection fallback.** `llp/1133.005-desktop-processes.rfc.md:706` proposes `storage.fs.appendFile`, but mappers cannot await (`docs/reference.md:1088`; `js/src/prelude.js:1404`). Storage has a separate queue that rejects after 256 waiting operations (`js/src/prelude.js:909`), while pipe backpressure tracks only the receive queue (`llp/1133.005-desktop-processes.rfc.md:275`). A fast producer can overrun disk writes. Separate pipes also cannot reproduce shared-descriptor stdout/stderr ordering. Define native redirection or a bounded asynchronous sink with completion and failure semantics; otherwise explicitly exclude these capabilities without claiming equivalence.

8. **MATERIAL — The planned acceptance drives do not satisfy the consumer requirement.** Stages 0–2 use fixtures; the real consumer is deferred to a later app PR (`llp/1133.005-desktop-processes.rfc.md:819`, `:845`). Parent D9.11 and D10 require the consumer drive before acceptance (`llp/1133-the-standard-library.rfc.md:483`, `:507`). Moreover, the clone explicitly has no Linux build (`examples/t3-code/README.md:21`). Add an explicit macOS T3 acceptance gate and name a real Linux consumer, or qualify Linux’s acceptance scope until that drive exists.

9. **MINOR — The secret-field matrix remains incomplete.** The blanket prohibition on textual events is clear, but the table omits `selectionchange` (`llp/1133.005-desktop-processes.rfc.md:526`), which currently carries full field text on web and Apple (`host/web-js/rt.js:958`; `host/apple/Sources/ExactKit/FieldSelections.swift:347`). Stage 2 does not exercise it (`llp/1133.005-desktop-processes.rfc.md:836`). Also decide whether `setRangeText` may write a secret field: it exists on all four initial targets (`docs/contract-for-agents.md:3339`), despite “only the person writes it” (`llp/1133.005-desktop-processes.rfc.md:538`). Add both cases to the rules and drive.

10. **MINOR — The macOS QoS implementation cannot accept all declared values.** `llp/1133.005-desktop-processes.rfc.md:585` proposes four QoS classes through `posix_spawnattr_set_qos_class_np`; Apple permits only utility and background and returns `EINVAL` otherwise. Restrict the values or specify a verified alternative. The link labelled `Process.qualityOfService` also points to `Operation`. [Apple’s declaration states the restriction.](https://github.com/apple-oss-distributions/libpthread/blob/main/include/pthread/spawn.h#L49-L53)

11. **MINOR — Windows executable discovery needs a batch-file boundary.** The RFC uses `PATHEXT` to identify executables (`llp/1133.005-desktop-processes.rfc.md:460`) and promises PATH resolution (`:475`), but selects `CreateProcessW` (`:563`) while refusing shell execution. Common `.cmd` and `.bat` launchers require a command interpreter. Specify discovery and spawn behavior for them and name the restriction in the ceiling test. [Microsoft](https://learn.microsoft.com/en-us/windows/win32/api/processthreadsapi/nf-processthreadsapi-createprocessw) and [Node](https://nodejs.org/api/child_process.html#spawning-bat-and-cmd-files-on-windows) document this boundary.

12. **MINOR — Cancellation of an awaited one-shot is unreached and unnamed.** `execFile` has neither Node’s `signal` option nor a returned handle (`llp/1133.005-desktop-processes.rfc.md:313`), and the ceiling table omits cancelling an in-flight invocation (`:690`). Add an explicit cancellation route or declare the omission and its reason. [Node supports aborting `execFile`.](https://nodejs.org/api/child_process.html#child_processexecfilefile-args-options-callback)

13. **MINOR — The supervision example changes consumer behavior.** The example uses `"on-failure"` (`llp/1133.005-desktop-processes.rfc.md:335`), excluding exit zero under its definition (`:342`). The clone restarts every unexpected exit except 78 (`examples/t3-code/modules/apple/T3LocalBackendManager.swift:363`); the reference does likewise (`apps/desktop/src/backend/DesktopBackendManager.ts:859` in the reference checkout). Use `"always"` for this consumer and drive an unexpected zero exit.

14. **MINOR — Mode bits do not reproduce the editor probe.** `llp/1133.005-desktop-processes.rfc.md:460` and `:916` substitute `mode & 0o111`. The clone checks that the candidate is not a directory and is executable by the current user (`examples/t3-code/modules/apple/T3RemoteEditors.swift:129`). Mode bits alone miss ownership-class selection, ACLs and mount restrictions. Provide an executable-access predicate or a suitable direct-candidate form of `execPath`.

15. **MINOR — Two parent-checklist details need explicit answers.** The declaration exposes `available` but no permission-state fact (`llp/1133.005-desktop-processes.rfc.md:621`), although parent D7 requires one (`llp/1133-the-standard-library.rfc.md:405`). Declare it or explicitly justify replacing it with static grant admission. Android is also labelled `absent` despite acknowledging executable support and merely lacking a consumer (`llp/1133.005-desktop-processes.rfc.md:790`); parent D8 calls that `later` (`llp/1133-the-standard-library.rfc.md:428`).

16. **MINOR — Q2 and Q3 need fairer descriptions.** Free arguments and unchecked descendants already allow arbitrary local execution through SSH’s `ProxyCommand` (`llp/1133.005-desktop-processes.rfc.md:483`), so refusing shell command lines is an API restriction, not an authority boundary. Make that explicit in Q2/security. Q3 describes manifest services as necessarily starting before initialization (`:876`), although a manifest could declare services started after initialization. Present that alternative without the unnecessary timing assumption. [OpenSSH documents `ProxyCommand` execution.](https://man.openbsd.org/ssh_config#ProxyCommand)

The central design is sound: executor vocabulary is justified by the parent’s data-capability exception, and the request, grant narrowing, staged operations and forget path fit existing machinery. r2 substantially improves incarnation identity, stdin bounds, readiness and `exit`/`close`. Most D9 items are answered; deferred cost measurement is honestly gated before acceptance, and the 3,882-line total is accurate. The remaining issues above prevent §16’s claim that all earlier findings are resolved from holding. No files were edited.
