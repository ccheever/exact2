**There are blockers.** This was a static review; no files changed, builds performed, or test suites run.

1. **BLOCKER — Superseded grid reads continue writing.** [grid.ts:78](/tmp/rv-dt-t7b/apps/design-tool/grid.ts:78), [app.contract:755](/tmp/rv-dt-t7b/apps/design-tool/app.contract:755). While a pin is awaiting its response, switch to One copy. Cleanup cannot see that unfinished pin; the old `loadGrid` then records it and continues issuing commands for its old tiles. Additionally, `sending.has(id)` returns success without sending anything, so overlapping cleanup or navigation can be silently discarded. Writes need generation checks and serialization that preserves the latest desired command.

2. **BLOCKER — Holds are not qualified by the selection’s plan.** [grid.ts:149](/tmp/rv-dt-t7b/apps/design-tool/grid.ts:149). The local digest comparison uses a captured build record, but the request omits `plan`. If a rebuild lands between that snapshot and the hold—especially during the preceding awaited pin—the server defaults to the receiving build’s **new** digest and applies the old site number there. Send the selection’s digest with the hold. Also, [app.ts:375](/tmp/rv-dt-t7b/apps/design-tool/app.ts:375) incorrectly preserves the old digest when the server explicitly reports `null`.

3. **BLOCKER — View transitions leave effects behind.** [grid.ts:120](/tmp/rv-dt-t7b/apps/design-tool/grid.ts:120), [grid.ts:148](/tmp/rv-dt-t7b/apps/design-tool/grid.ts:148). Switching States → Grid retains the first four build IDs in `mine`, and the Grid branch never clears their holds. The mode grid therefore retains pressed, hovered and focused states. Separately, Grid → States without a valid selection returns at line 109 before cleaning up any grid pins. Reconcile effects against the desired view even when its tile list is empty.

4. **BLOCKER — Cleanup forgets effects it has not cleared.** [grid.ts:84](/tmp/rv-dt-t7b/apps/design-tool/grid.ts:84). `handBack` deletes tracking before checking whether the build exists or whether the request succeeds. Disconnect a copy briefly, then choose One copy: its tracking disappears without a clear request. The server retains pins across disconnection and can replay them when that ID reconnects while this tool remains present. Failed clear requests are likewise forgotten. Retain cleanup obligations until acknowledged or invalidated by the server session ending.

5. **BLOCKER — Refused holds create a continuous write/event loop.** [grid.ts:152](/tmp/rv-dt-t7b/apps/design-tool/grid.ts:152), [app.contract:755](/tmp/rv-dt-t7b/apps/design-tool/app.contract:755). Select a disabled control or an instance absent from a copy. The host lets the hold go; the resulting event clears `holding.hold`; `changes.answer` immediately reruns `loadGrid`, which sends the same hold again. This repeats at event/request speed, without waiting for the one-second timer. Remember refusals for the current selection/build/state and retry only after a relevant change.

6. **SHOULD-FIX — Copy registrations outlive their frames and pages.** [grid.ts:44](/tmp/rv-dt-t7b/apps/design-tool/grid.ts:44), [grid.ts:90](/tmp/rv-dt-t7b/apps/design-tool/grid.ts:90), [grid.ts:119](/tmp/rv-dt-t7b/apps/design-tool/grid.ts:119). `copies` is never cleared or associated with a frame generation. Replace the grid page while an old build is still listed: the replacement tile can report ready and receive commands addressed to the previous document before its own registration arrives. Expire registrations with the corresponding frame/page lifetime and require the replacement’s own word.

7. **SHOULD-FIX — Old navigation acknowledgements suppress later user navigation.** [grid.ts:131](/tmp/rv-dt-t7b/apps/design-tool/grid.ts:131), [grid.ts:160](/tmp/rv-dt-t7b/apps/design-tool/grid.ts:160). Move copy 1 to `/a`, causing copy 2 to receive `/a`. Move copy 2 to `/b`, then use Back there to return to `/a`. Its old `sentTo=/a` causes that real move to be treated as an echo, and the tool sends it back to `/b`. Consume acknowledgements when observed; failed or skipped sends must not remain permanently recorded as delivered targets.

8. **SHOULD-FIX — Turning Mirror navigation off still moves copies.** [grid.ts:127](/tmp/rv-dt-t7b/apps/design-tool/grid.ts:127), [grid.ts:159](/tmp/rv-dt-t7b/apps/design-tool/grid.ts:159). The toggle gates leader detection, but leaves `place` populated and does not gate navigation sends. After establishing a leader, disable mirroring and navigate that leader elsewhere: it can be sent back to the retained location. Gate sends by the active view’s navigation policy and reset obsolete mirror state.

9. **SHOULD-FIX — A fresh selection of the same address does not replace the frozen selection.** [grid.ts:106](/tmp/rv-dt-t7b/apps/design-tool/grid.ts:106). The key contains only build, site, instance and plan. Select the same view again after its app changes theme or location, without rebuilding: the fresh selection passes `!sel.stale`, but States retains the earlier facts and screen. Distinguish a new user selection from refresh reports of the frozen selection.

10. **SHOULD-FIX — Cleanup can erase another tool’s newer pin or hold.** [grid.ts:85](/tmp/rv-dt-t7b/apps/design-tool/grid.ts:85), [grid.ts:123](/tmp/rv-dt-t7b/apps/design-tool/grid.ts:123). Tool A records a grid pin; tool B subsequently pins that build; A closes its grid before reconciling B’s change. A sends unconditional `pin:null`, clearing B’s current pin. The stored values are never checked, and ownership/revision is not retained. Cleanup should release only the effect the grid still owns.
