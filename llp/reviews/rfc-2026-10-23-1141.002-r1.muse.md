Verdict: READY WITH CHANGES — direction is right and evidence-led, but the all-apps `tabs` migration (§3 D2) and two borrowed words (D1, D4) need tightening before staging.

## Strengths

- Refuses inference (§1, §3 D1). Shelf/Harmony refutation is decisive: a filter field is not a search destination. Matches [LLP 1115](/Users/ccheever/projects/exact2-wt-review-1141x/llp/1115-write-the-web-ship-the-platform.principle.md:13) author > platform.
- Keeps `role="tab"` (§3 D1). Correct ARIA call: a `tablist` may own only `tab`s; `role="search"` would break web arrow-key order and announce a landmark. Rejecting the panel-landmark route because panels build late is grounded in [tabs.rs](/Users/ccheever/projects/exact2-wt-review-1141x/runner/src/instance/tabs.rs:1).
- Puts search knowledge in the kernel from frame one (§3 D1). [bars.rs `root_tabs`](/Users/ccheever/projects/exact2-wt-review-1141x/kernel/src/bars.rs:511) already resolves tabs/panels in tab order; `search: Option<usize>` is the minimal extension and every host benefits.
- No new word for activation (§3 D3). Reusing `autofocus` via 1141.001 D6 avoids vocabulary invention.
- Stage 0 measures UIKit alone first (§4), including the honest escape hatch: if the `.search` system item on the `viewControllers` path proves equal, drop the migration. That is the right falsification test, given GPT's crash and in-pill failure (§1).

## Concerns

**BLOCKING — §3 D2, §4 stage 2: migrating every tab app to `tabs` is under-specified.** Current code eagerly builds stacks, held stacks, hatches and replay in [NavigationTabsIOS.swift `installTabs`/`syncTabs`](/Users/ccheever/projects/exact2-wt-review-1141x/host/apple/Sources/ExactKit/IOS/NavigationTabsIOS.swift:62). `UITab.viewControllerProvider` is lazy; how it composes with held stacks, `askTabContainer`/`replayTabs`, reshape, iPad floating/sidebar modes, the More overflow (>5 tabs), and tvOS (same `#if os(iOS) || os(tvOS)` file, yet D2 table says tvOS stays ordinary) is unstated. Resolve: stage 0 must include held-tab, hatch, >5-tab, iPad and tvOS probes; stage 2 needs a fixture matrix, not "driven once."

**MAJOR — §3 D2: `UITab` face mapping is asserted, not shown.** `title`/`image`/`identifier` are plausible; `badgeValue` and `isEnabled` on `UITab` itself need verification — today they live on `tabBarItem` in [NavigationTabsIOS.swift `syncItems`](/Users/ccheever/projects/exact2-wt-review-1141x/host/apple/Sources/ExactKit/IOS/NavigationTabsIOS.swift:274). Resolve: stage-0 API checklist; if badge/enablement stay on the provider's controller, say so.

**MAJOR — §3 D4: `field-sizing="content"` overloads a sizing property with a presentation.** On web/Android/Linux it literally sizes the field; on iOS 26 it becomes a button. An author sizing a field gets a different control. This cuts against "names stay CSS" in [tags.rs](/Users/ccheever/projects/exact2-wt-review-1141x/contract/lower/src/tags.rs:4). Resolve: prefer an Exact attribute beside `buttonStyle`/`listStyle` (see Q2), or explicitly document the dual meaning and test authored-width interactions.

**MAJOR — §3 D1/D3: which field is "the" search field is ambiguous.** Header projection takes the first `input type="search"` ([bars.rs](/Users/ccheever/projects/exact2-wt-review-1141x/kernel/src/bars.rs:177)). Pushed routes inside the search tab can also carry header search; the RFC does not say UIKit ignores them, nor what happens before the lazy panel first builds its root route. Resolve: state root-route-only binding and add a first-selection test.

**MAJOR — §3 D6/§4: agent and accessibility coverage is thin.** `tree` placement strings and `back`-cancels-search are good, but there is no VoiceOver test (pinned image-only tab, focus on activation/cancel-return), no Dynamic Type/AX-size check, and XCUITest exposure of a `UITab` button is deferred entirely to stage 0. Resolve: add AX XCTests and make stage 0 report the exact element type/identifier found.

**MINOR — §2/§3 D3: availability guards need naming.** The RFC correctly dates `UITab`/`UISearchTab` to iOS 18 and `.integrated*`/`automaticallyActivatesSearch` to iOS 26 (§2), consistent with [Package.swift](/Users/ccheever/projects/exact2-wt-review-1141x/host/apple/Package.swift:104) iOS 17 minimum. D3/D4 should still state the `#available` guard at each use site, including iOS 18–25 `UISearchTab` without auto-activation.

**MINOR — §3 D1: plumbing is missing.** No `rel` prop exists in the attribute table yet; the RFC omits schema/prop creation and the compatibility-id consequence. Resolve: one line naming the prop and whether lowering can truly distinguish a root tablist today.

## Open questions

1. **`rel` vs `role`:** Keep `rel="search"` (85). It is the only candidate that means search to the web and leaves ARIA correct. Accept validator noise; do not require `link role="tab"` (changes press semantics) or rewrite `role` in the DOM (one silent lie in the contract).
2. **`field-sizing`:** Pick an Exact attribute instead (70). Reserve `field-sizing` for sizing. Platform-inferred minimizing when unsaid: no (80) — minimizing hides the field; that is author intent, not an unsaid default.
3. **Root header at rest:** Let stage 0 decide, but pre-commit the threshold: any first-frame hidden-vs-shown difference triggers the stage-4 early assignment (75).
4. **Mac:** Keep the sidebar row until the SwiftUI reference is built; adopt the sidebar-top field only if `sidebarAdaptable` shows it without losing the row's label/order (60).
5. **tvOS:** Ordinary tab is right for now (85). File the `UISearchContainerViewController` gap; do not block iOS on it.
6. **iPad virtual keyboard:** Follow UIKit/HIG — do not auto-activate with only a virtual keyboard if UIKit does not (70). Verify in stage 0 with hardware-keyboard-connected and disconnected cases.
7. **Hatches:** Log line is not enough (65). Pre-1.0 "delete; don't deprecate" argues for handing `UITab`s from `tabContainer` with a loud log for `viewControllers` setters, plus one hatch XCTEST.

## Missing

Second-search-tab behaviour on hosts other than iOS (order, warning surfacing); search-tab deep-link/`navigationKey` interaction; selected search tab tint/badge inheritance; and a regression drive for Shelf/Harmony proving their filter fields did not become search tabs.
