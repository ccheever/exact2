1. **BLOCKING — Upload release can deadlock.** [fetch_async.rs:288](/Users/admin/x2p2/apps/exact2-http/vendor/ibex/crates/ibex2/src/stdlib/fetch_async.rs:288) drops the upload under the task mutex; its destructor invokes `released()`. On grant refusal, a release callback that aborts the same signal re-enters that mutex and hangs. The redirect path also drops resources under lock. Take uploads/exchanges out under lock, then destroy them after unlocking; add a reentrant-release test.

2. **MATERIAL — Terminal transitions race.** [fetch_async.rs:272](/Users/admin/x2p2/apps/exact2-http/vendor/ibex/crates/ibex2/src/stdlib/fetch_async.rs:272) cancels before recording `Aborted`, allowing the cancellation’s `end` to win. Conversely, [end:410](/Users/admin/x2p2/apps/exact2-http/vendor/ibex/crates/ibex2/src/stdlib/fetch_async.rs:410) calls `hop_ended` before recording success; a reentrant abort replaces an already-completed response. Commit the terminal decision under the mutex before cancellation or event callbacks. Test both orderings.

3. **MATERIAL — Physical completion misses cleanup.** [fetch_async.rs:412](/Users/admin/x2p2/apps/exact2-http/vendor/ibex/crates/ibex2/src/stdlib/fetch_async.rs:412) returns for an already-terminal fetch before releasing its exchange and partial response. Retaining `FetchTask` therefore retains stopped uploads and response buffers. Also, [line 330](/Users/admin/x2p2/apps/exact2-http/vendor/ibex/crates/ibex2/src/stdlib/fetch_async.rs:330) can install an already-ended redirect exchange while `next_hop` is deferred. Track physical completion separately; always detach completed-hop resources and reject handles returned after that hop ended.

4. **MATERIAL — Callback guarantees are not implemented.** [darwin_async.rs:93](/Users/admin/x2p2/apps/exact2-http/vendor/ibex/crates/ibex2/src/transport/darwin_async.rs:93) creates a thread for invalid input, bypassing lane serialization and permitting callbacks before `start` returns. Native queued failures and `[task resume]` likewise have no return barrier ([darwin_task.mm:223](/Users/admin/x2p2/apps/exact2-http/vendor/ibex/crates/ibex2/src/transport/darwin_task.mm:223)). Introduce an explicit install/activate handoff and deliver refusals on the lane queue.

5. **MATERIAL — Late metrics lose their origin.** [fetch_async.rs:451](/Users/admin/x2p2/apps/exact2-http/vendor/ibex/crates/ibex2/src/stdlib/fetch_async.rs:451) forwards metrics without a hop identifier or origin. After A redirects to B, a late A report cannot be attributed correctly through `FetchEvents`, as D2 requires. Capture the admitted origin in each `HopSink` and include it in metric events.

6. **MINOR — Queued time starts at creation, not resume.** [darwin_task.mm:132](/Users/admin/x2p2/apps/exact2-http/vendor/ibex/crates/ibex2/src/transport/darwin_task.mm:132) subtracts `taskInterval.startDate`, which Apple defines as task instantiation time. Record a timestamp immediately before `resume` and subtract that. [Apple documentation](https://developer.apple.com/documentation/foundation/urlsessiontaskmetrics/taskinterval?changes=_4&language=objc).

7. **MINOR — Required cases remain unpinned.** [fetch_async_tests.rs:60](/Users/admin/x2p2/apps/exact2-http/vendor/ibex/crates/ibex2/src/stdlib/fetch_async_tests.rs:60) never defers `next_hop`; Darwin coverage never exercises concurrent exchanges on one lane. Add skipped-hop-wait aborts, no-body exemptions, header-count boundaries, Manual/Error/MAX_REDIRECTS, late/missing-metrics cleanup, and cookie/cache/reuse cases.
