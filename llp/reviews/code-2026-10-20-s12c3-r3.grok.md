## SHOULD-FIX

**A percentage beside a token still passes as spacing.** `over` (`contract/lower/src/anatomy/library.rs:150-152`) treats any word that parses as `f64` after stripping one `%` as a factor. `calc(50%)` and `min(100%, 100%)` are refused, because a function needs a knob. `padding="calc(100% - space.md)"` and `gap="min(100%, space.md)"` pass: `100%` is skipped and `space.md` supplies the knob. In `color-mix` that skip is the share (`40%`). In `calc`, `min`, `max`, and `clamp` a `%` is a length, and D1's only literal lengths are `0` and `0px`. `min(8px, space.md)` is still refused.

**A function tracks `displayMode` one call deep.** `fns` (`contract/lower/src/anatomy/platform.rs:37-50`) marks a parameter only when that function's own body member-reads it. `viewport` (`:206`) is false for a call. `fn pass(v: Viewport): Viewport = v` then `text pass(vp).displayMode`, or `derive v = pass(vp)` then `v.displayMode`, ships. So does `fn outer(v) = inner(v)` when `fn inner(v) = v.displayMode` and the view calls `outer(vp)`. `fn mode(v) = v.displayMode` then `mode(vp)` is refused, which is the case `library_rules.rs:308` covers.

**A `match` binding is not held.** `viewport` (`platform.rs:204`) ors the two arm expressions and ignores `var`. `held` (`:123-174`) gathers resources, injects, states, derives, and `let`s. `match some(vp) { case some(x) => x.displayMode, case none => "" }` ships, in a view and in an action. A ternary of the viewport is tracked.

**`held` is one name set for the whole component.** The fixed point (`platform.rs:164-174`) adds a name when any binding of that name may be the viewport, and leaves it there for every read. An action `let item = vp` makes every `item.displayMode` a host read, including the view's prop `item`, which D6 leaves as the app's data. `library_rules.rs:319-323` passes only when no such `let` exists. A second action's `let mode = item` is refused when another action has `let mode = vp`. A `for` variable that reuses the resource's name is refused the same way, because the resource name is held for the whole component (`:124-128`).

**`type` is still one string.** `text` (`library.rs:403-410`) returns only `Expr::Str`, and the input arm (`:526-529`) uses `"text"` otherwise. Roles go through `theme::leaves` (`:486-500`). `type=(flag ? "checkbox" : "text")` is checked as text, so the checkbox arm ships without `checked`. `type=(kind == "check" ? "checkbox" : "radio")` with `checked` and `aria-label` is refused for a missing `value`.
