# Review round 2, LLP 1121 stage 9 A2 (Apple's control faces draw icon paths), Grok 4.7 (xhigh)

**RIGHT WITH CHANGES.** Round 1’s blocking fixes are in the source: Mac tint uses `sourceIn` (`FaceSymbol.swift:81`), grouped path cells reserve the standard symbol slot, take the label/destructive/disabled tint, and redraw on Dynamic Type (`GroupedListIOS.swift:892`, `:918`, `:1258`), an unsaid iOS button path takes the title foreground or the glass ink (`ButtonConfigurationIOS.swift:276`), a symbol-only button uses the size UIKit resolves (`ButtonConfigurationIOS.swift:73`, `:252`), and the agent symbol is `icon.reply` via `symbolIcon` and `FaceSymbol.observed` (`button.rs:49`, `NativeButtonsIOS.swift:307`, `NativeButtonsMac.swift:312`, `SidebarMac.swift:286`). The token stays out of test ids, accessibility labels, `.fill` selection, and grouped observation. The grouped svg-only leading icon becomes a standard cell (`kernel/src/grouped.rs:218`, `:413`), which is what the ruling asks for. File caps are under 1499 (`NavigationBarIOS.swift` ends at 1462). Suites were not run.

1. **SHOULD-FIX** — `host/apple/Sources/ExactKit/IOS/SegmentsIOS.swift:379` and `host/apple/Sources/ExactKit/IOS/NavigationTabsIOS.swift:244`. A tab-bar path is baked at `FaceSymbol.tabBarPoints` (23 compact, 17 regular; unspecified also yields 23, `FaceSymbol.swift:96`) and then left there. The in-page bar rebuilds only when the title or the symbol token changes, so a later compact↔regular change (iPad split, iPhone Plus landscape) keeps the old em. The root bar puts the size class in its signature, but `syncItems` runs only from `installTabs` (before `tabController` exists, so the first image uses `UITraitCollection.current`) and from `syncTabs` on a navigation batch (`NavigationIOS.swift:488`). A size-class change does not start a batch, and `SystemColor.resolvesDifferently` ignores it, so nothing calls `syncItems` again. UIKit resizes an SF Symbol on that change; the path bitmap does not. `FaceSymbolIOSTests.swift:140` asserts the compact constant, so it stays green if `project` ignores the bar’s traits. **Fix:** put the horizontal size class (or the point size) into the in-page rebuild key, and register both bars for `UITraitHorizontalSizeClass` so a change rebuilds the path images. Read the root bar’s traits from the tab bar after it is in the window, not from `UITraitCollection.current` on the first call.

2. **SHOULD-FIX** — `host/apple/Sources/ExactKit/IOS/SegmentsIOS.swift:252`. A symbol segment’s path is rasterized once at `FaceSymbol.defaultPoints` (the current body size) and cached by name and label only (`size` is stored as `-1,-1` and never compared). `FaceSymbol.image` applies `points` only to paths; an SF Symbol is an unconfigured symbol image and follows the control’s content size when UIKit draws it. A Dynamic Type change does not miss the cache, and `ExactSegmentedControl` never registers for `UITraitPreferredContentSizeCategory`. Grouped cells already redraw (`GroupedListIOS.swift:1262`). **Fix:** key that cache on the point size (or the content-size category) and register the control for content-size changes, then call `setImage` again at `UIFont.preferredFont(forTextStyle: .body, compatibleWith: control.traitCollection).pointSize`.

3. **NIT** — `host/apple/tests/ExactKitTests/FaceSymbolTests.swift:251`. The comment still says the agent reads `""` for the sidebar path. The assertion at line 319 expects `icon.reply`, which matches the ruling. **Fix:** change the comment to say the agent reads the icon’s name.
