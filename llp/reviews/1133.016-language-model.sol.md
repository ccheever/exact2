1. **MATERIAL** — D6, [lines 448–451](llp/1133.016-language-model.rfc.md#L448); D14, lines 841–842: **the Apple implementation requires an API unavailable on its supported OS floor.** Accounting and eviction depend on `tokenCount(for:)`, but every overload in the installed SDK requires iOS/macOS 26.4; unlike `contextSize`, it is not back-deployed. Apple’s [Foundation Models updates](https://developer.apple.com/documentation/updates/foundationmodels) corroborates its introduction with 26.4. Decide whether to raise the supported floor or specify different accounting and eviction behavior for 26.0–26.3. An availability guard alone cannot preserve the promised behavior.

2. **MATERIAL** — D11, [line 738](llp/1133.016-language-model.rfc.md#L738); D9, lines 613–618; §12, lines 1163–1164: **`apple.toolCallingMode="required"` has no declared successful exit.** [Apple explicitly requires](https://developer.apple.com/documentation/foundationmodels/expanding-generation-with-tool-calling) either throwing from the tool or dynamically changing the mode; otherwise tool calling continues. Here, handler failures and timeouts become model-visible errors and generation continues, while dynamic profiles are excluded and no session hatch exposes a mode transition. Defer `required`, or provide an explicit termination or mode-transition mechanism.

3. **MATERIAL** — D7, [lines 482–490](llp/1133.016-language-model.rfc.md#L482); D9, lines 637–642; D2, lines 218–219: **the context window does not bound the accumulated response.** The web implementation repeatedly prompts through tool rounds, evicting earlier context, while `toolCalls` retains every call’s complete arguments and result. The handler timeout bounds one invocation, and the nesting limit bounds depth; neither bounds sequential rounds. Consequently, inference work and polled snapshots can grow without limit, eventually exceeding the existing native binding’s 1 MiB response ceiling. Decide a total tool-round budget, a byte-bounded tool-history representation, and terminal behavior when either limit is reached. The constants can remain implementation work.

4. **MATERIAL** — D3, [lines 257–259](llp/1133.016-language-model.rfc.md#L257); D6, lines 411–423; D13, lines 799–804: **completed responses cannot be reclaimed independently of their conversation.** Every finished response remains readable until its model session ends, and Agents keeps a session per conversation. Evicting transcript turns therefore leaves their response text and tool results retained indefinitely. The inherited `release(name, args)` releases readers; `dispose(ids)` handles undelivered replies. Neither retires delivered responses. Decide explicit response disposal or bounded retention semantics. An implementation cannot reclaim them while honoring the stated lifetime.

5. **MINOR** — D5, [lines 341–351](llp/1133.016-language-model.rfc.md#L341): **`modelNotReady` does not establish that a download is underway.** Apple’s [availability example](https://developer.apple.com/documentation/foundationmodels/systemlanguagemodel) includes downloading and other system reasons. Mapping all such cases to `downloading` turns uncertain readiness into a false fact and makes the consumer display download progress where no download may exist. Preserve `unavailable` with `model-not-ready`, or explicitly distinguish uncertain readiness from a confirmed download.

VERDICT: NOT READY
