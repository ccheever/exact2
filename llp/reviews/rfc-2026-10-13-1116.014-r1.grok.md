Verdict: RETHINK

1. **Accepting these guesses does not reach the token gap.** The gap is cached context re-sent every step, and LLP 1116.013 showed the bytes are the opening fetch: stage 1 shrank that text and tokens stayed at 1.03× because builders fetched the same knowledge by name (test, persist, color, data, compose, timer, signatures). LLP 1116.012's extra steps against React are mostly those lookups (+8.3), with builds only +1.5. On the same 80 builds, `contract vocab` commands that name color are about 0.4 a build and a few percent of doc re-send; start-here, the card, recipes, and the other lookups are the rest. Color is one name in that list. **Change:** account this table in MB-steps, the way LLP 1116.013 did, and retarget the decision at the opening fetch. Keep a repair-only claim only if that accounting says the repair slice is the gap.

2. **A second spelling is the decision LLP 1081 and `rules/RULES.md` ("Delete; don't deprecate") already closed.** Names the author writes stay CSS (LLP 1115); Exact gets one `-exact-` name; a real browser spelling stays in the schema's alias column. `-apple-system-grouped-background` already resolves to `grouped-background`. The guesses are blends (`-exact-system-grouped-background`, `-exact-tint`), which are neither UIKit's identifiers nor CSS. `-exact-tint` is a second spelling of `AccentColor`, beside the property `-exact-tint-color` and the author spelling `--exact-tint` that LLP 1081 forbids. "The rest of UIKit's `system…Color` family" is an open Apple tier, which LLP 1081 D4 declined, and LLP 1115.001's Android builders will guess Material names the same way. LLP 1104 D4's familiar path is a behavior (the common reset), not a second vocabulary. **Change:** add no author aliases. An unknown color fails with the one canonical name.

3. **Several rows called certain would compile a different meaning, and that meaning can be a tell.** `-exact-tint-background` is as plausibly `Highlight` (tint at low alpha) as `AccentColor`. `-exact-system-fill` is the rename LLP 1081 rejected in favor of `-exact-fill`, and the spelling test still refuses `-apple-system-fill`; `secondarySystemFillColor` is also `ButtonFace`. `-exact-system-background` is `systemBackgroundColor` on iOS for both `Canvas` and `-exact-background`, which differ on the Mac. `each` with no `key` keyed by `x.id` picks an identity the author did not write (wrong row state is visible). `empty()` already means "the shape's zero" only on a resource's `else`; the failure outside that is "`empty` is not in the stdlib," so widening it gives one word two positions. A quoted number on a length (`width="100"`) silently becomes pixels, against the quoting rule start-here exists to teach. **Change:** leave all of these as errors that name the edit. The one harmless acceptance is a type annotation that equals the inferred type, and it is too small to be the RFC.

4. **The guess corpus measures a population and a number that will pick the wrong decision.** It gives the model only start-here and scores errors per screen on one shot. Builders who hit these 166 errors had already read the card and the recipes; a cold model invents a wider set. D2 cannot move that score, because the first guess still fails, so the corpus will rank aliases as the win and the diagnostic as nothing. A guess that compiles to the wrong screen scores as clean. Rerunning two models after every docs edit pushes the answers back into start-here, which stage 1 showed does not stick, and spends the builder models to judge a string a fixture can check. **Change:** the fast loop is a frozen fixture of the observed failures, compiled with no model. Judge a diagnostic by whether the next command is still a lookup. Anything that changes meaning waits for the graded comparison, and a compile of a different meaning fails the fixture.

5. **Naming the rewrite is the lever that matches the rules, and the current color error does not do it.** `role_hint` fires for a bare role (`grouped-background` → `-exact-grouped-background`) and a wrong `-exact-` name gets a grammar paragraph of several hundred characters with no nearest role. `buttonStyle` on a custom face already says both "remove it to keep the native button" and `appearance="none"`, which is why that lookup survives. The header error states the rule and omits the edit (a changing header is a `header` with a `when` inside it). This is LLP 1116.013 D3, deferred there, applied to this table. **Change:** one line, the edit, the canonical name, before any rule. Ship that on its own and measure repair lookups and extra builds in a real build.

6. **An alias that "notes" the canonical name keeps two spellings in circulation.** A note that prints is re-sent on every later build of a file that still contains the alias. A note that does not fail leaves the alias in the file, so the next step teaches it. Vocab, the card, patterns, computed-style readback (`var(--exact-<role>, …)`), and the spelling test (LLP 1081 D8, `no_old_spelling_is_accepted_by_any_table`) all assume one emitted spelling. Documenting both grows the early text stage 1 just cut; documenting one while accepting the other is the drift. **Change:** the canonical name is the only spelling in source, docs, readback, and the conformance walk.

7. **The knowledge stage 1 measured is still outside this RFC.** Test, persist, data, compose, timer, and the signatures are Exact's protocols. A React or SwiftUI builder cannot guess them as a synonym of a role they already know, which is the only case where "make the guess compile" could remove a fetch. **Change:** say so in the claim. Either the next decision is about that fetch, or this RFC stops presenting repair sugar as the token lever.
