## 0. The short version

The direction is right and the RFC's semantics (D1–D6) are the ones I would
choose. Two things are missing, and one of them is a decision the RFC must
make before code:

1. **A child resource has no value at mount when its source answers
   `Later`.** LLP 1016 D3's keep-previous rule has nothing to keep for a
   fresh instance, and the root's escape ("declare boot arguments the source
   answers now") does not exist for a prop-driven child. The motivating
   consumer hits this on its first component: Fleet's `fleetUsages`,
   `fleetUsage`, and `fleetTranscript` all answer `Later` once the source is
   active (`crates/data/src/lib.rs:190–207`). D2's "typed placeholders" does
   not answer it — the bake's placeholder is per declaration and cannot be
   computed for an instance that is not mounted at bake. §2.1 gives the three
   possible rules; I recommend the `else` fallback LLP 1016 §4 deferred.
2. **Owned-resource settlement necessarily runs inside the instance walk**,
   and the walk is not transactional: today any error there poisons the
   runner (`runner.rs`, `update`). A source refusal or shape mismatch on a
   child resource — a clean rollback at the root — would become a restart.
   §2.2 gives the options; the cheapest sound one is to keep poison for
   genuine source bugs and make sure `Later` is never one of them (point 1).

Everything else is a matter of doing the P4c pattern again, carefully:
a fourth region kind for the scope, `owner` columns, a handle on the `Frame`,
and reconciliation of tickets and timers against the tree after every commit.
Small, complete, no second tree, no Aquifer. Estimate at the end.

## 1. The six questions

**Q1 — Explicit lifetime ownership; is there a smaller implementation?**
Yes to ownership. The identity rule D1 states (an allocation, never a path or
a key alone) is what `Row` already is: the instance tree keys rows and drops
them, and P4c hung state on that. The smaller implementation is not a
different model but the same one with fewer new concepts than the RFC's item
list suggests:

- One new `RegionKind::Scope` (one arm, no subject, no key): the compiler
  wraps an effectful use's inlined view in it. It is transparent to layout
  (a region's roots are its parent's children — `instance.rs`, `roots_of`),
  it nests wherever a `when`/`match`/`each` arm nests, and a `Row` reuse by
  key reuses the scope inside it. The RFC's alternative — a synthetic
  single-row `each` over a constant list — works for identity but evaluates a
  fake subject every update and cannot be validated as "this is a scope";
  the kind is ~30 lines in `format.json`, `validate_semantics`, and
  `RegionInst`.
- `owner: opt:regions` on `resources`, `mutations`, and `timers` (slots have
  it). Validation: an owner is a `Scope` region; a mutation's slot owner
  equals the mutation's owner (`validate_mutation_slot` today refuses any
  owner).
- The scope's runtime state travels the way row slots do: `Frame` gains one
  field, an `Rc<RefCell<ScopeState>>` beside `row`, and `LoadResource`,
  `PendingResource`, `PendingMutation`, `Refresh`, `Send` take the owner
  branch `LoadSlot` and `StoreSlot` already have (`vm.rs`, `Frame::row_of`).
  No registry of instances; the tree is the registry.
- Two runner-wide lists keyed by `(plan index, scope id)`: pending requests
  (there already, `Target` gains a scope) and live timers (a `Vec` today,
  becomes root entries plus scope entries).

That is the whole shape. What cannot be made smaller is that owned resources
settle in the walk (Q3), and the walk's lack of rollback is the one
structural cost (§2.2).

**Q2 — Every stateful child, or only effectful ones?** Only effectful ones,
now. Reasons: (a) P4c's singleton child state is a root slot carried by name
across a dev reload (`instance.rs` test: `n__1` is in `carry().slots`), and
giving every stateful child a scope would end that — a dev-loop regression
for Counter-shaped components with no consumer asking for it; (b) row-owned
state already has an owner, so nothing is gained there. But name the cliff
this creates: **adding a `resource`, `mutation`, or `task` to a child moves
its `state` from carried-by-name to restart-on-reload.** D1 says this in the
positive ("state belonging to an effectful child lives in its scope too");
say it as the cliff in 1017.000 P4c's amendment so an author who loses a
draft on reload knows why. The alternative — scopes for all — is the
cleaner rule and the right one *if* Charlie ever revisits 1017 §8.4 (no
instance carry); it is not this cut's.

**Q3 — Can row frames carry owned effects without a second tree?** Yes, and
they must: an owned resource's arguments read the item, the bound, the props
(substituted expressions over the use site's scope), and the scope's own
slots, all of which exist only in the frames at the site. `settle` today
evaluates every resource argument with `frames: &[]`
(`runner/settlement.rs`, the `Env` in the resource loop) before `update`
realizes anything. So owned resources settle *during* `RegionInst::update`
for their scope — at mount and on every re-evaluation — not in `settle`.
That is the honest consequence of D2 and the RFC's item 4 should say it
plainly ("settle resources in a scope's actual environment before
publishing dependent view bindings" is this). What it costs: the seam
(`DataSource::answer`, the `Store`, `store_readers`, `keep_answer`) must be
reachable from `Update`, which today borrows an immutable `Env`; `Update`
gains a `&mut dyn` seam handle or becomes generic over `D`. Not a second
tree — a second *place* where the seam is called. The frames themselves need
no change beyond the handle field.

**Q4 — Bake representation for per-instance values.** Content-addressed
answers, not ordinals. A new table `answers { resource: idx:resources, args:
bytes, value: bytes }`, one row per distinct `(declaration, arguments)` the
bake's first frame settled, consumed at boot exactly as `resources.initial`
is: a scope mounting in the boot frame whose evaluated arguments equal an
entry takes it, else queries. This is the "unchanged arguments reuse" rule
applied to compiled data. Why not the alternatives:

- *Allocation ordinal* (the n-th scope of declaration d): deterministic when
  boot's first frame equals bake's, and wrong when it does not — a
  `boot_stored` snapshot that flips a `when` shifts every ordinal after it,
  and instance k shows instance k+1's data. The RFC's own D6 sentence
  ("cannot use the first instance's answer for all other instances") is a
  weaker form of this hazard; arguments are the only safe key.
- *No compiled data for children*: a Rust source answers at boot anyway, so
  this costs nothing there; a TypeScript source is not ready at boot (LLP
  1027 D4), and a child mounted in the first frame would then have nothing
  to show — the same hole as §2.1, on the first frame.

Provenance: `resources.reader` stays per declaration; if any instance's
answer read the store at bake, the declaration is a reader, and every
instance's compiled answer is a placeholder asked again at `data_ready`.
`initial` can stay for root resources this cut (an entry with the root's
boot arguments is the same thing; unify later or now, the implementer's
call). `FORMAT_DIGEST` changes and every host re-bakes, as P4c did.

**Q5 — What edge is missing?** §2, all of it. The three that would ship
wrong if not decided: mount with `Later` (§2.1), settlement-in-walk rollback
(§2.2), and timer actions needing their hidden capture arguments (§2.5).

**Q6 — Cross-instance deduplication at the source: right boundary?** Yes,
and Fleet already does it that way: `fleetUsages` keeps a `usage_cache` and
one `usage_pending` id in the data crate and answers `Now` from the cache or
`Later` for the next id (`lib.rs:190–199`). A runner cache keyed by
`(source, args)` would be wrong for exactly the reasons D2 gives (store,
clock, seed, credentials are arguments only when declared — LLP 1027.000),
and the existing per-target "unchanged arguments reuse" is the dedup that
is safe. What the RFC should add is the *cost statement* 1017.000 P4c made
("a row must not open N requests"): N mounted instances with a `Later`
resource are N tickets, N host requests, and N things `clock settle` waits
for. That is now the author's choice, and `state.pending` shows it.

## 2. Hazards, by the RFC's own list

### 2.1 Resource settlement at mount: `Later` with nothing to keep

Today: at boot, `Later` with no compiled value and no carried value refuses
the boot (`settlement.rs`, `DataError::Unavailable("answers later at
boot…")`) and bake refuses it as a build error (LLP 1016 D3). After boot, a
resource always has a previous value. A child mounted later has neither.

The RFC does not decide this. The choices:

1. **Refuse the mount.** Same rule as boot: the source answers `Now` for a
   fresh instance's arguments, or the mount is a data refusal. Honest, zero
   syntax — and unusable for Fleet: `AccountUsage(account=…)` with a real
   account is `Later` by design once the source is active. Authors would
   route around it by passing an "empty" sentinel prop and flipping it a
   commit later, which is 0102's race by another name.
2. **Retype child resources as `option<T>`.** Rejected for the root in LLP
   1016 (retypes every read site); the same reason applies.
3. **An explicit fallback on the declaration** — `resource usage =
   fleetUsage(account) as shape list<Choice> else []` — evaluated in the
   instance's environment when the source answers `Later` and there is no
   previous value; the resource is then pending over that value exactly as
   a root resource is pending over its compiled value. LLP 1016 §4 deferred
   this because the first consumer did not need it; this consumer does. It
   is not async syntax (the RFC's stated exclusion): it is a value. ~40
   lines (parser, one unify in `checks.rs`, an `initial`-style code column
   on `resources`, one branch in the mount path), and it also gives the
   root a way to stop encoding boot arguments as sentinels. Refuse a child
   `Later` with no `else` at mount (option 1) so nothing is silent.

Recommendation: 3. If Charlie wants zero syntax in this cut, 1 with the
Fleet consequence written down — and then the "downstream proof" in item 5
cannot be the usage component.

### 2.2 Settlement inside the walk is not transactional

`run_action_inner` rolls back slots, row writes, commands, and pending flags
when `settle` refuses, and the kernel is untouched. `update` cannot: a
failure after the tree began to change poisons (`runner.rs`, `update` →
`poison`; LLP 1005 §6 "the remaining way there is a duplicate `each` key from
a data source"). Owned resources add three new ways to fail inside the
walk: a source refusal (`DataError`), a shape mismatch, and `Later` without
a value (§2.1). The first two are source bugs at the root today and roll
back; in the walk they restart the app.

Options, cheapest first:

- **Accept poison for the two source-bug cases; eliminate the third by
  §2.1.** Zero structural change. State it in D6 beside the duplicate-key
  sentence. This is what I would ship first.
- **Make `update` transactional by snapshot.** `Tree`, `NodeInst`,
  `RegionInst`, `Row`, `Frame` are all derivable `Clone` (values are `Rc`);
  clone before `tree.update`, restore on `Err`, and extend the action path's
  rollback (slots, row undo, commands, pending) to cover update failures
  too. Then `Poisoned` remains only for `Kernel::apply` refusing a batch.
  Cost: one tree clone per commit — on the 10,000-row scaling fixture (LLP
  1005 §8, 6.47 ms edit) that is a measurable number the implementer must
  take before choosing it. Scope state behind an `Rc` handle is *shared* by
  the clone, so it needs its own undo list either way (§2.4).
- **A dry pre-pass** that decides the instance set and settles new scopes
  before mutating. Rejected: region subjects can depend on values that
  scopes being mounted in the same pass produce (the RFC's own test:
  "synchronous resources determining whether further children exist"), so
  the pre-pass becomes the walk.

Whichever is chosen, `refresh` on an owned resource and an argument change
on a live scope both re-query *inside the walk*, so the store-write case in
§2.6 and the poison rule here apply to re-settlement as well as mount.

### 2.3 Instance identity and conditional teardown

Realized as a `Scope` region, identity falls out of the tree: inside `when`
or `match`, switching arms destroys the roots and the scope with them
(`RegionInst::switch` → `destroy_all`); re-entering realizes a new one.
Inside `each`, the row's reuse-by-key reuses the scope; removal drops it; the
same key reinserted later is a new `Row` and a new scope. Reorder is a
reuse. All of D1's sentences hold with no new mechanism — this is the
argument for Q1.

Two things to get right:

- **Scope ids.** Allocate from `Ids` (monotonic, never reused) at realize.
  The lifetime token D5 wants is this id; a ticket plus a scope id is the
  fence.
- **Destroy must be observable to the runner in the same commit.** `Child`
  drops are silent today (`destroy` pushes a `DestroyView` op and the Rust
  value drops). Add `dropped_scopes: Vec<ScopeId>` to `Update`, pushed when a
  scope's instance is destroyed; after `update` succeeds, the runner forgets
  every pending request and every timer registration whose scope is in that
  list (one journal line each, as `forget` writes today). This is D5's
  "cleanup must leave no live runner registration solely because a
  component once existed" as a mechanism rather than a promise. Test it
  with a late reply after a `when` flip: the ticket is gone, the reply is
  dropped, nothing parses.

`find(view)` reconstructs frames per level by cloning (`instance.rs`,
`RegionInst::find`); a scope adds one frame per effectful use on that path.
Fine, but the frame handle must be an `Rc`, not a clone of the state.

### 2.4 Mutations and rollback

- The mutation's `option<T>` slot becomes a slot owned by the scope, read
  and written through `Frame::row_of` like any row slot. `Send` must capture
  the scope handle at eval time as `StoreSlot` captures the row
  (`Outcome.row_writes` carries the `RowSlots`; `sends` needs the same), so
  the request is enqueued under `Target::Mutation(m, scope)`.
- `pending_mut` becomes per scope. Today the action path snapshots
  `pending_mut` as a `Vec` and restores it on a settle refusal; the scope's
  flags live behind the handle, so the rollback is an undo list of
  `(handle, old ScopeState)` for every scope the commit touched — the
  `row_undo` pattern, one level up. Do the same in `fulfill_inner`, which
  today saves `self.resources` wholesale.
- A reply for a live scope's *current* ticket writes the scope's slot; for a
  forgotten ticket or a dead scope it is dropped (D3). "A new instance with
  the same list key cannot inherit it" is true by construction: new `Row`,
  new scope id, and the old ticket was forgotten at destroy.
- An assignment to an owned mutation's slot forgets its ticket (as today) —
  the assignment carries the scope through the frames, so the target is
  known.
- `validate_mutation_slot` flips from "no owner" to "same owner as the
  mutation"; a decoded plan that disagrees is `PlanError::MutationSlotOwned`
  as today, and a frames mismatch at runtime is `Trap::BadScope`, never a
  panic.

### 2.5 Timer environments

Three things the RFC does not say that the code requires:

- **The action's hidden capture parameters.** The inliner closure-converts
  a child's props and injects into hidden action parameters
  (`inline.rs`, `@capture:{n}:{i}`), which a *handler* supplies as curried
  arguments evaluated at the node site at dispatch. A timer has no node
  site. So `timers` gains `args: range:args` — the capture expressions, as
  `handlers.args` — evaluated in the scope's frames at fire time. That is
  also what makes D4's "fires in that instance's live lexical environment"
  true: nothing is captured at registration. Validate `args.len ==
  action.params.len` in `validate_semantics`.
- **Frames at fire time come from the live tree, not from registration.**
  `Frame.item` is a snapshot of the row's item at the last update; storing
  frames with the registration would read a stale item. Add
  `Tree::find_scope(id) -> Option<Vec<Frame>>` (the shape of `find(view)`)
  and resolve it in `advance_timed` before `run_action(action, args,
  &frames)`. A scope that is gone at fire time (cannot happen if
  reconciliation is in-commit, but the code should not assume it) is a
  journal line and a skipped fire, not a trap.
- **Ordering and mount-in-seek.** Deterministic order is `(next_ms, plan
  timer index, scope id)`. A timer's own commit can mount a scope whose
  timer is due before the seek target; the loop re-selects the earliest
  registration each iteration, so it fires on the way — test it ("mounting
  timers late"). `TIMER_FIRE_LIMIT` and `ClockDidNotAdvance` apply per
  registration unchanged.

And one cost the motivating consumer should hear before it moves anything:
Fleet's `Working` indicator ticks at 100 ms from *one* root timer that bumps
`frame`, and every row follows in one commit. Per-instance timers would make
that N commits per 100 ms, each a full `update` walk (LLP 1005 §8: the
evaluation walk is not incremental). Owned timers are for a card's own
refresh cadence (`usagePoll` at five minutes); the animation clock should
stay at the root, and a shared clock passed as a prop is the design, not a
workaround. Say this in the RFC so the "downstream proof" is the usage
component, not the indicator.

### 2.6 Store readiness and invalidation

- `store_readers`, `stale`, and `store_revision` are per declaration or per
  root state today. Per scope: `store_revision` and `stale` on the scope's
  `ResourceState`; `store_readers` stays per declaration (conservative:
  any instance reading the store makes the declaration a reader, which is
  what bake needs).
- `data_ready` → `recommit(stale)` re-asks by resource index through
  `refresh_next` and `settle`. For scopes, `recommit` must mark stale scope
  resources "forced" and run `update`, where the walk re-queries them. Same
  for `set_delivery` (root only today; keep it root only — the delivery
  source is the runner's).
- The root's re-loop when a later resource's `answer` bumps the store
  revision after an earlier reader settled (`settle`, `stale_store_reader`)
  has no equivalent in the walk. A scope later in tree order whose source
  writes the store leaves an earlier scope's reader at an old revision. The
  small answer: after the walk, if the store revision moved during it, walk
  once more (bounded, like the root's pass count); ops are deltas against
  `last`, so a second pass in the same batch is safe — but a scope created
  in pass one and destroyed in pass two yields `CreateView` then
  `DestroyView` in one batch, which the kernel must accept. Test that
  specific batch. If it cannot, refuse store writes from `answer` during a
  walk in this cut and say so.
- `keep_answer` (LLP 1027 D4) keys kept answers by resource name; per
  instance the arguments are in the encoding already, so the key can stay
  the name and the value the *last* instance's — which is wrong for two
  instances. Either skip kept answers for owned resources this cut (the
  compiled `answers` entries cover the first frame for arguments the bake
  saw) or key by `(name, args)` under the 8 KB cap. Skip is smaller.

### 2.7 Compiler and plan

- The type pass checks a child's resource arguments in the child's own
  scope (`check_component`, no owners), then the expanded root's lifted
  declarations in the root's declaration scope — which has no region
  frames, so a lifted argument that reads an `each` item is
  `type-unknown-name`. Row-slot initializers solved this with
  `each_scopes[tag]` in lowering and `infer_owned_state_initializers` in
  types; owned resource and timer arguments need the same per scope tag.
- Two owned resources of one child that depend on each other: the root
  settles by fixpoint; the walk should not. Order them at compile time (the
  inliner already does this for derives, `resolved_derives`) and refuse a
  cycle (`type-resource-cycle`); the runner then settles a scope's
  resources in plan order, no retry loop.
- `Runner::resource(name)`, `carry()`, and `agent::state` iterate
  `plan.resources`; each must skip owned rows as they skip owned slots.
- `runner/src/runner.rs` is at 1,400 of 1,500 lines. Move timers and the
  request list out (`runner/timers.rs`, `runner/requests.rs`) as a no-op
  commit *before* the feature lands, or the cap check fails mid-lane.
- The reject fixture `type-child-resource` (`contract/corpus/rejects.txt:157`)
  goes; `contract/analyze/src/lib.rs:67–69` and `contract/types/src/lib.rs:
  888–910` with it. Delete, don't deprecate.

### 2.8 Agent observability without a ninth operation

`state` shows root slots, derives, resources, and pending tickets by name.
Owned declarations are per instance and invisible today (row slots are
skipped). Add one key to the `state` reply — `"instances": [{"scope": id,
"region": r, "slots": {…}, "resources": {…}, "pending": [{…}]}]` — and
journal lines that name the scope (`request 7 (usage@3)`, `timer 2 (tick@3)
→ epoch …`, `forget request 7 (usage@3): scope 3 destroyed`). No new
operation; `expect state` can grow `instance` addressing later if a test
needs it.

## 3. A small complete implementation

In the order it can land with the five checks green after each step.

1. **Split `runner.rs`** (timers, requests) — no behavior change.
2. **Plan**: `RegionKind::Scope`; `owner: opt:regions` on `resources`,
   `mutations`, `timers`; `args: range:args` on `timers`; the `answers`
   table; the `else` code column on `resources` (if §2.1 option 3);
   `validate_semantics` for all of it; `FORMAT_DIGEST` moves.
   `plan/tests/format.rs`: every malformed ownership is a typed refusal.
3. **Runner, scope state**: `ScopeState { id, resources: Vec<Option<
   ResourceState>>, pending_res, pending_mut, mutation slots via the row
   map }` behind an `Rc<RefCell>` on the `Frame`; `RegionInst` realizes and
   drops a `Scope`; `vm.rs` owner branches for `LoadResource`,
   `PendingResource`, `PendingMutation`, `Send`, `Refresh`; `Update` carries
   the seam handle, `dropped_scopes`, `mounted_timers`, and an undo list;
   settlement of owned resources in `RegionInst::update` (mount, argument
   change, forced); reconciliation after `update`; `fulfill` by `(ticket,
   scope)`; `advance_timed` over root and scope registrations with
   `find_scope`. Rollback as §2.4. Poison rule as §2.2, written in D6.
4. **Compiler**: the inliner wraps an effectful use in a `Scope` node and
   lifts its resources, mutations, and tasks with owner tags and the use
   site's scope; types and lowering check and lower their arguments in that
   scope; timer capture arguments; compile-time resource order; the
   refusals deleted.
5. **Bake**: write `answers` from every scope the first frame mounted;
   `reader` per declaration as now; never `advance`.
6. **Agent**: `state.instances`, journal lines.
7. **Fleet**: move `accountUsage`/`usagePoll` into an `AccountUsage(account)`
   child — the proof — leaving the indicator's clock at the root.

Estimate: plan ~120 lines, runner ~450 (scope state 150, walk settlement
150, timers 80, reconciliation and fulfill 70), compiler ~250, bake ~40,
agent ~40, tests ~300. Roughly 1,200 lines against P4c's 430; the walk
settlement and its rollback are the difference and are not optional.

**Tests to add to the RFC's list** (each names a behavior above): a late
reply after a `when` flip is dropped; a scope timer whose action unmounts
its own scope fires once; a timer mounted by an earlier timer's commit
inside one seek fires in that seek; a child `Later` at mount with `else`
shows the fallback and is pending, without `else` is refused; two instances
with equal arguments produce two tickets; bake writes one `answers` entry
per distinct argument list and boot takes it only when arguments match; a
`boot_stored` snapshot that changes the first frame's instance set still
gives every instance its own arguments' answer; a store write from a later
scope's `answer` re-answers an earlier scope's reader in the same commit;
`state.instances` lists a mounted scope and drops it after unmount; and a
count — commits per second of clock with N mounted 100 ms timers — recorded
once so the cost in §2.5 is a number.

## 4. Findings

- **Direction: right.** Ownership by mounted instance, realized as a region
  the tree already knows how to create, reuse by key, and drop. No second
  state system; the frame carries a handle, as it carries row slots.
- **Decide before code: the mount-time value of a child resource whose
  source answers `Later`.** Fleet's usage and transcript sources are that
  case. Recommend `as shape T else <expr>`; otherwise refuse at mount and
  drop the usage component as the proof.
- **Owned resources settle inside the instance walk, which cannot roll
  back.** Either accept poison for source bugs there (and write it into D6),
  or make `update` transactional by cloning the tree and measure the cost on
  the 10,000-row fixture first.
- **Timers need their capture arguments and live frames.** `timers.args`
  in the plan; frames resolved from the tree at fire time; order by `(due,
  timer, scope)`.
- **Reconcile in-commit.** Destroyed scopes are reported by the walk; the
  runner forgets their tickets and timers before the commit returns. The
  ticket plus scope id is the fence D5 asks for.
- **Bake by arguments, not ordinals.** An `answers` table keyed by
  `(resource, args)`; `reader` per declaration; used at boot only.
- **Only effectful children get a scope now**, and the RFC should name the
  cliff: adding an effect to a child ends reload carry for its state.
- **Keep Fleet's animation clock at the root.** Per-instance timers are for
  a card's own cadence; N instances at 100 ms are N full-walk commits per
  tick.
- **Housekeeping the cap forces:** split `runner.rs` first; delete the
  child-resource refusal and its fixture; skip owned rows in `resource()`,
  `carry()`, and `state`.

## Round 2 — shared discussion (2026-09-09, after reading the Sol and Grok artifacts)

Responses to the six lead dispositions.

**(1) Scope for every child that owns state, resource, mutation, or task.**
I argued effectful-only to keep singleton-child reload carry; Grok argued
the same. I concede to Sol. The decisive point is one I under-weighted: P4c
today gives a `when`-guarded stateful singleton a root slot that survives
unmount, so "leaving an arm destroys it and re-entering starts it again"
(1017 §5 P4c) is already false for that case. One rule fixes that and
removes the resource-addition cliff. The price is real and should be
written, not implied: a dev reload restarts every stateful child's state,
and the `instance.rs` assertion that `n__1` carries flips to the opposite.
That is 1017 §8.4's ruling applied consistently, not a new trade.

**(2) `as shape T else <expr>`.** Accepted as proposed. Against Grok's
alternative (pending with no value, `pending(x)` true, `LoadResource`
traps): a trap in the else-arm during the walk is the poison class §2.2
describes, and Grok's own mitigation (settle before realizing the
instance's nodes) still leaves an unconditional read as a restart. A typed
value evaluated in the live environment has no trap class. Against Sol's
"Now unless snapshotted": correct as the refusal rule when no fallback is
written, and the disposition keeps it. Fleet's late-mounted usage card
needs the fallback.

**(3) Snapshot rows keyed by declaration plus full enclosing keyed path,
with args match.** I proposed args-only; Sol is right that equal-argument
siblings can differ, and Fleet is the evidence: `fleetUsages` mutates
`usage_pending` per call, so two equal-argument answers at bake are not the
same answer. My ordinal objection does not apply to a path key, since a
path is a lookup key rather than an allocation order, and the args-equality
gate covers a store-dependent prop change. Accepted. Agreed with both
families that owned answers are neither kept nor carried in this cut.

**(4) Ownership columns.** Accepted. Defining a mutation's owner as its
result slot's owner is one fewer column and the validator has what it
needs: slot owner is a `Scope` region, `option<T>` check unchanged. Timer
`args` for the hidden captures: all three reviews found it; keep it.

**(5) Settlement in the walk; pre-walk rollback preserved; poison for
post-walk source bugs.** This is my first option and I hold to it. Two
pins for the implementer: settle a newly mounted scope before realizing its
kernel nodes (Grok), so a no-fallback `Later` refuses with nothing created;
and the store fixpoint over live scopes must be tested for the batch a
second pass produces (a scope created in pass one and destroyed in pass
two yields create and destroy of one view in one batch). Bounded by the
existing cycle count.

**(6) Timers and pruning.** Accepted in full. `has_timers` from the plan
table (Grok) is the right call for hosts that check once at boot. Ordering
by `(due, plan index, lifetime id)` is deterministic and cheaper than
Grok's key path. Pruning undrained `RequestOut`s on supersede and unmount
(Sol) fixes a latent case: `forget` drops the pending entry but the queued
request still ships.
Animation clock stays at the root; the proof is the account-usage periodic
task. `state.instances` additive; no ninth operation.
