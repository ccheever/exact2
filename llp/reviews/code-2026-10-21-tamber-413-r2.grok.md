1. **Early remote refusal.** An over-limit body resolves `null` on the next microtask, before `ready`. `Promise.race` at `scripts/tamber-server.mjs:536` therefore writes the 413 and returns without waiting out a cold start. A `ready` that is already rejected still loses that race to the already-fulfilled `null`, so the 413 is still written. If `ready` rejects while the body is still in flight, `handle` throws the same way `await ready` did before.
2. **`undefined` during `ready`, and an empty body.** A client that leaves resolves `undefined`. `undefined === null` is false, so the handler falls through, and `scripts/tamber-server.mjs:541` returns without a 413. An empty body is `''`, which is also not `null`. The `''` from `ready.then(() => '')` is only the race sentinel; the handler still uses `await early` as the body.
3. **Pairing.** `scripts/tamber-server.mjs:657` uses `?? ''`, so both `null` and `undefined` stay a 400. An over-limit body has already gone through `refuseBody`, so that 400 is a lingering close.
4. **GET/HEAD through `forward`.** `scripts/tamber-server.mjs:1427` runs every method through `readBody`. A GET or HEAD with no body ends as an empty `Buffer` (`== null` is false) and is omitted from `fetch`. An over-limit `Content-Length` is a 413 and opens nothing upstream. Subscribe and long-poll are still a finite body, then a streamed response; `res` `'close'` still aborts that `fetch`.
5. **Socket close and the stand-in.** The timer is cleared from `req.socket` (else `res.socket`) at `scripts/tamber-request.mjs:16`, and again on `'end'`. On this repo's Bun 1.4.2 server, `req.socket` is the real `NodeHTTPServerSocket` passed into `IncomingMessage`. `FakeSocket` is only created when that argument is missing, and the parser shim is `socket.parser`, which this code does not listen to. Request and response `'close'` stay off the timer because those fire before the answer is out.
6. **Abuse.** A declared over-limit body is refused before it is buffered. A chunked one drops its chunks at the limit (`scripts/tamber-request.mjs:37`). After the answer, further bytes are discarded and `req.destroy()` runs at 5 seconds, or sooner on `'end'`. The timer is `unref`'d. Listeners die with the request.
7. **Tests and the lane.** `scripts/async.mjs:114` registers `tamber-body-limit`. The unit test at `scripts/tamber-body-limit.test.mjs:125` really does sleep about 11 seconds (4.5 + 1 + 5.5). Both waits share the timer queue with the 5 second fallback, so a stall runs the earlier deadline first: still not destroyed at the 4.5 second check, destroyed by the 5.5 second check, and still not destroyed when `'close'` cleared the timer. Headers-only, GET-with-an-over-limit-length, and the `--via` loop are covered separately.
