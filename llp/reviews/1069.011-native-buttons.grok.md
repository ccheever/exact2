## §5

1. A literal `appearance="auto"` after class merge, plus a fixed `appearance: none`, is the right switch. A new tag invents a component, which `rules/DEFERRED.md` and LLP 1069.001 D1 already refuse for HTML elements that exist. A different attribute would leave CSS. Refusing a bound `appearance` is right, and the refusal has to see the merged expression, including a ternary that class merge synthesizes when the two styles disagree or one omits the row (`contract/lower/src/class.rs:52-64`, `contract/lower/src/lib.rs:667-677` and `918-919`). `Expr::None` clears to the kernel default, and `Appearance` defaults to `auto` (`kernel/tables/schema.json:1632-1637`), which replaces the fixed `none` (`lib.rs:792-798`). The node's own `appearance="none"` wins over a class's `auto`. Switching native and custom is `when`, two nodes. Node type is chosen at compile time (`lib.rs:699-702`).

2. Lowering to `Control` changes `kind` from `"button"` to `"control"` (`host/apple/src/host.rs:1398-1399`). What that breaks, beyond the plan's refusal list: the chrome index never visits the node; iOS `tap` treats every `UIButton` as an unopenable menu and `type` chooses a select option; macOS `activate` only clicks a popup; Linux toggles it as a checkbox, paints a checkbox, and `type` sets a value; the node view still presses, labels, and draws a focus ring wherever the platform control does not cover the box; hardware-keyboard focus is lost because only `kind == "button"` becomes first responder; autofocus targets the node; a virtualized row that gains a platform subview leaves the pool; a tab in a tab list silently misses the segment bar; a toolbar child that is no longer `kind == "button"` drops the whole toolbar. Swipe actions key off `swipeContent`, not button kind. Header buttons are not special-cased in this tree and are exactly what LLP 1075.003 (not on this branch) plans to project.

3. One text and one `symbol:` image, with `when`/`match`, is the right v1 model once the "neither" sentence is fixed. `each` is refused because the count is not static, by walking `Node::Each`, not by a tag check. Raster images and a subtitle stay refused. The children are data on Apple and Linux and real DOM on the web, the same split `select`/`option` already has. The fixed `flex-direction: column` fights leading/trailing on the web.

4. Making `buttonStyle` legal inside a `style` is the right fix, checked at the use site, with both-sides-or-neither for a conditional class. That rule is right for a prop, which has no kernel default, and it is the wrong rule for `appearance`, where `none` means `auto`. `backgroundMaterial` and `glassGroup` stay unstyleable in this plan.

5. Default `bordered` is right: the web is the standard (`rules/RULES.md:51-53`) and a browser button is bordered. The macOS mapping is an unmeasured sketch (§2 is iOS 27 only) and belongs in the generated table, one row per name, `~` for stand-ins. The web look for `bordered` follows the checkbox `appearance: auto` precedent. The other looks stay stated approximations. Symbol-only glass is a circle (34.33 pt), not the classic 47.

6. Nothing here contradicts 1075.003 Q1–Q6, and that document is not in this branch (commit `b2af79eca` only), so this plan cannot treat it as a landed ruling. The collisions that matter are write-only-on-change, header buttons that a future bar presses, the first frame, and keeping UIKit names out of Contract.
