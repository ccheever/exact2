## Strengths

The child RFC correctly drops the parent’s universal Wasmtime path and the coupling of dev reload to release engine choice. Starting native, replacing a whole bounded module, and carrying host Store/slots/clock is the right grain: no function patching, no new registry, no live object graph.

Platform choice is coherent. `dlopen` of uniquely named cdylibs is the practical macOS/Linux mechanism. Browser Wasm is mandatory. Pulley-without-JIT is the only serious physical-iPhone story that does not generate executable ARM. Unique paths, no overwrite of mapped files, constructors that do no work, no module threads/escaping callbacks, and a measured retention cap with an explicit host restart are the right retirement posture.

Reuse of LLP 1027 D5 prepare/commit, disposable validation, latest-edit-wins, and “changed logic invalidates resource answers” is the smallest path to a working loop. §6 is unusually honest that the warm numbers are a query-only Wasm compile probe, not e2e swap.

## Concerns

**1. HIGH — §3 C/Wasm inventory is not the live `DataSource` seam.**
The proposed surface is identity, grants, activation, answer/parse, destruction. The trait also has `bind(&Plan)`, `ready`, `configure_storage(PathBuf, …)`, `continuation` → `Box<dyn FnOnce>`, and `answer`/`parse` taking `&mut Store`. `replacement` returns `Self` and takes `module: Vec<u8>`.

A bytes/C interface is sufficient only if the host adapter implements `DataSource` and the module never sees Rust types, paths, trait objects, or allocator ownership. As written, the inventory is a subset. Remedy before loaders: a method-by-method map (host adapter vs module export). V1 module capability should be explicit: encoded `Value` in/out, `app_id`/`grants`/`revision`, activate (no-op work), answer/parse, destroy. `bind` consumes plan bytes already on the host. `configure_storage` stays host-side.

**2. HIGH — Store and continuations will pin or smuggle native lifetime if they cross the ABI as they do today.**
`answer`/`parse` mutate `Store` in-process. That cannot be `&mut Store` through C or Wasm. Either host imports (`store_get`/`store_set` with bounded bytes) or a snapshot in and write-set out. Validation must use a throwaway store, matching `activate_for_validation`.

`continuation` returning a `Send` closure is an escaping callback into the old image. §4 says retire only after callbacks/worker refs are gone; §3 says pass tokens, not closures. Those must be the same rule in v1: the module returns request tokens; the host owns workers. An old closure must not run after commit. Until file/continuation sources have host adapters, they are not in the replaceable crate — otherwise “one module = the whole data crate” contradicts “those sources remain binary-bound” (§1 vs §3).

**3. MEDIUM — Verification overclaims failed-candidate recovery for native (§3, §7).**
Withholding grants/storage is real for the request protocol and for Wasm. Native code can still crash, hang, or hit the OS. “Invalid candidate preserves all sessions” is true for ABI/grant/state refusal, not for a native SIGSEGV during prepare. Remedy: split the test list. Wasm: malformed/looping fails inside executor budgets. Native: interface refusal preserves sessions; a candidate crash is process-fatal until you later isolate (out of scope). Do not ship UX copy that implies TypeScript-class recovery on `dlopen` code.

**4. MEDIUM — Unbounded retention is handled in policy, not yet in a contract (§4, §8).**
The cap+restart rule is the right one; without a number it is easy to “forget” mapped dylibs and unique files. `dlclose` not making memory go away is normal. Remedy: the macOS/simulator probe returns a hard cap (count or bytes of retained images plus unpublished files). Hit the cap → diagnostic and host restart. Delete superseded artifacts that were never mapped. Do not treat `dlclose` success as proof of reclamation.

**5. MEDIUM — 0.5–1 s save-to-visible is an aspiration, not a supported e2e figure (§6).**
Medians of 398–455 ms (opt 0/1) and 885 ms (web opt-z) are warm `cargo` of a query-only Wasm wrapper, five samples, no bake/pair/fetch/validate/carry/present, no cdylib link, no Pulley encode, no dual-target. Connected macOS+phone implies a native build and a Wasm/Pulley build. Remedy: keep p50 < 1 s as a goal; gate on instrumentation (phase timestamps, ≥20 real edits/surface, cold separate). Parallelize per connected target. Do not fail the architecture if first e2e p50 is ~1.5 s. The 100 ms restart budget staying separate is correct.

**6. LOW/MEASURE — Native-until-edited identity is sound; the identity function is not (§5).**
Wasm bytes cannot prove native identity (parent D4). Include sources, lockfile, build scripts, profile, target. Embedded vs reload profile will differ, so a revert without a host rebuild should stay on `loaded-native` unless inputs match the embedded baseline. That is correct. Specify the identity tuple before wiring “return to embedded.” Expose executor via existing `state`/`logs` as proposed.

**7. LOW/MEASURE — Physical-iOS Pulley is plausible as a dev-only adapter, not a given (§2, §7).**
Precompile on the desktop, link interpreter only, no Cranelift/Winch, no ARM JIT — conceptually right. Wasmtime iOS is Tier 3; mmap/threads/signals/size are the real risk. A development composition that carries Wasmtime while release stays native is the right split. If Pulley misses the board-style budget, wasmi is a comparison, not a redesign. Simulator native remains a probe, not a promise.

## Better alternative (not recommended)

Wasm-everywhere (including macOS) would collapse loaders and unload risk. Tradeoff: you give up native-until-edited speed, which is the point. Out-of-process native logic would make replacement and crash isolation easy and would destroy in-process query latency. Stay in-process; cap and restart when the OS will not unload.

## Open questions vs established defects

Established: ABI inventory < live trait; Store/`continuation` cannot cross as typed today; native crash ≠ session-preserving validation; e2e 1 s is unmeasured.
Hypotheses to measure: `dlopen`/signing/library validation; whether mappings shrink; simulator native vs Pulley fallback; Pulley latency/UI on device vs native; Wasmtime embed cost.

Also still open, as the RFC says: trusted-producer transport before any network-fed native load; exact `Value` encoding; module declaration shape.

## Next step

Do not start the full loop. Smallest decisive experiment: on macOS, from a running host, `dlopen` uniquely named Caltrain cdylibs through a query-only C ABI, swap ≥20 times, check answers, and record RSS/mapped files after intended retirement. That decides whether native replacement is a bounded reload or “restart the host every N edits.” Immediately after (or in parallel on a device build), run the same Rust data cases native vs Pulley on a physical iPhone for answer equality and frame impact.

Ship the ABI map and v1 capability cut (no closures, no paths, Store via host) as a page of RFC before those probes so the probe exercises the real boundary, not the 1026 query wrapper. Then implement one app, one module, web Wasm + macOS native + device Pulley, reusing 1027 prepare/commit.

The direction is worth implementing after those limited changes.
