1. **MATERIAL — D7 treats the session clock and the canvas input clock as one clock.** D7 (lines 450–454) stamps every sample a caller sees, including a canvas `at_ms`, on the session clock, and says that clock is the host input clock on every host. The sentence it cites (`game/README.md:397–399`) only says that `clock +N` and a 60 Hz panel fire the same ticks. On the live web host they are different clocks. The session clock is `performance.now() - t0` (`host/web/glue.js:171`). `exact.now` is installed only under the agent (`glue.js:1416`). Live frames use the paced `requestAnimationFrame` timestamp (`host/web/gpu-glue.js:182`, `424–426`), and keys and pointers are stamped `event.timeStamp` (`gpu-glue.js:574`). Both of those are time since the time origin. The offset is `t0`, constant, and typically hundreds of milliseconds. The engine maps a stamp into the frame with `(host_us - last).clamp(0, gap)` (`game/engine/src/sim.rs:729–740`); the live clamp only pulls future stamps back to `now` (`sim.rs:693–700`). A sensor stamp behind the frame clock by more than one frame lands at offset 0, so the samples D6 counted on — a 100 Hz gyroscope arriving as two distinct times inside a 60 Hz frame (`D6`, lines 400–405) — share one world instant. Tilt-to-move can still see the latest vector, so drive 7 can pass while gyroscope aiming, the reason D6 refused the Contract path (lines 437–439), does not. Apple’s live path is aligned: input and `ExactEnv.wall()` share `CACurrentMediaTime`. Android canvas input is `SystemClock.uptimeMillis()` (`host/android/canvas/.../ExactView.kt:228`); `SensorEvent.timestamp` is `elapsedRealtimeNanos`. An offset measured at acquisition is valid only if canvas samples are converted into the input clock. **Decision:** stamp canvas `at_ms` on the host input clock the queue already uses, and keep the session clock for Contract polls. Drop the claim that they are the same clock.
