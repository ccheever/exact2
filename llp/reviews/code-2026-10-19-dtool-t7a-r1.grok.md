## Findings

1. **SHOULD-FIX** — The path wait gives up by forcing the requested URL onto the history entry, which strips an agent session and can disagree with the router.
   `host/web/dev.js:481-482` and the same loop in `host/web-js/dev.mjs:712` wait up to a second for `location.pathname + location.search` to equal the parsed path, then unconditionally `history.replaceState(history.state, "", to + hash)` whenever the fragment differs. `host/web/navigation.js:129-137` (`historyURL`, used from `commit` at `navigation.js:220` and `:240`) appends `agent`, `seed`, `locale`, `timeZone`, `epoch`, `storage`, and `failFetch` from the document's launch URL whenever `AGENT_ADMITTED` is set (`navigation.js:2`) and that launch URL has `agent` (`navigation.js:1078`). The bar therefore never equals `to`.
   Open the dev page at `http://127.0.0.1:PORT/?agent=1&seed=1` and send `navigate` to `/post/7#c`. The router writes `/post/7?agent=1&seed=1`. The `pushState` hook (`dev.js:459`) reports that URL, with no fragment, on the next turn. About a second later `replaceState` writes `/post/7#c` and drops the agent query. A reload then comes up without the agent adapter, because the JS page copies those keys from the current search (`host/web-js/dev.mjs:702`). The same call with no fragment skips `replaceState` (the hash already matches), so the status stays `/post/7?agent=1&seed=1` and a client waiting for `/post/7` never arrives. The "already here" check makes this worse: `history.state.url` is the route path without the agent query (`dev.js:474`), so a fragment-only command on the current route skips the router and still falls into the same wait.
   The same fallback overwrites a real redirect. If the root `navigate` handler commits `/login` for `/post/7`, the timeout `replaceState` puts `/post/7` on that entry while `history.state.url` stays `/login`.
   Design-tool copies frame `src=${base}/` with no agent query, so their wait matches on the same turn and one status includes the fragment. `pushState` inside `go` / `goTo` is synchronous, and `due` (`dev.js:441-451`, `dev.mjs:711`) folds the following hash `replaceState` into that one status.

2. **SHOULD-FIX** — A path the regex accepts normalizes to a `//` pathname, and the hash step then throws with no `unsupported`.
   `LOCATION` (`scripts/tamber-builds.mjs:64`) rejects a scheme, a host, `//`, `/\`, a backslash, whitespace, and C0/DEL. It accepts `/foo/..//evil.example/x` and `/%2e%2e//evil.example`. `new URL(location, location.origin)` keeps the page origin and yields pathname `//evil.example/x` (also `//evil.example`). `%2F%2F`, `%5C%5C`, and the Unicode slashes stay percent-encoded on that same origin.
   On a page whose router does not claim that path, `dev.js:475` (and `goTo` at `host/web-js/router.js:199-200`) answers `unsupported` before touching history. Send `/foo/..//evil.example/x#frag` when the document is already on pathname `//evil.example/x`, or when `history.state.url` is that string (`dev.js:474`). The hash differs, so `dev.js:482` calls `history.replaceState(state, "", "//evil.example/x#frag")`. A leading `//` is scheme-relative. The history API throws `SecurityError` and the document stays on its origin. `command()` catches that at `dev.js:873` (`dev.mjs:712` does the same) and posts nothing. The server has already answered `{navigated: true}` (`scripts/tamber-builds.mjs:604`). `historyURL` itself is safe: it prefixes `location.origin`, so a router `pushState` of this path remains `http://<page-host>//evil.example`.

3. **NIT** — A stale `navigate` refusal is journaled before it is dropped. `scripts/tamber-builds.mjs:438` logs `build …: unsupported navigate` for every such report. The seq check at `:453-455` then returns 204 and sends no event. A late refusal of seq 1, after seq 2 was sent, still prints that line. The event is not stored on the build (`b.unsupported` is untouched; `shown` at `:169` stays null) and is not replayed.

4. **NIT** — Two frames given the same `window.name` share one build id. The key is read once (`host/web/dev.js:366`, `host/web-js/dev.mjs:706`) and the page never writes `window.name`. Nothing in this repo assigns `window.name`. A name the app sets still survives reload, so the next load reads `exact.dev.build:<new name>`, mints a new id, and leaves the old key's id behind. On a joint reload of two frames with the same name, both read the same stored id. The `BroadcastChannel('exact.dev.build')` who-check (`dev.js:372-376`) finds nobody: the previous documents are gone, and a channel does not deliver to its sender. The second `register` clears the first stream's build (`scripts/tamber-builds.mjs:370`). Distinct names do not collide, because the message is `who:<id>` and the ids differ. A duplicated tab still splits, provided the original answers within 60 ms; that timer is the pre-existing one.

5. **NIT** — `here()` (`dev.js:457`, `dev.mjs:707`) turns a bar the app itself wrote into `location: null` when the address contains a space, a backslash, or is longer than 2048 characters. The server stores that null (`scripts/tamber-builds.mjs:413`), so the leader's location disappears. U+202E is allowed by `LOCATION` and is not escaped by the journal's `JSON.stringify` (`tamber-builds.mjs:603`), so a write client can visually reorder `navigated … to "…"`.

6. **NIT** — The new tests prove the claims they assert, and they leave the two bugs above unmeasured. `scripts/tamber-builds.test.mjs:708-750` covers the listed bad locations, a missing capability, one frame, status `location`, a stale seq, `only` on the event object, `list().unsupported === null`, `clear()` sending nothing, no replay, and a polled queue that keeps `/b`. It does not pass `/foo/..//evil.example`. `scripts/tamber-pairing-server.test.mjs:372-393` covers propose → 403, write but absent → 409, a missing build, bad locations, ios → 409 `unsupported: "navigate"` with no frame, the journal line, and the frame. `only` is enforced for subscribers at `scripts/tamber-server.mjs:179` and for the events poll at `:572`; neither new test subscribes a second client. `scripts/dev-copies.test.mjs` (not executed here) checks three distinct ids from the dev origin, reload stability, an in-place JS route to `/post/7?from=grid#c` with taps and `window.__mark` kept, a wasm fragment `/#c`, and `/nowhere` → a detail containing `no route` while that frame stays at `/`. The other two copies are both `/`, so that assertion does not depend on registration order. The wasm loop never takes a real route step (the comment at `:46-50` says so). `free()` (`:43`) binds port 0 and then the dev loop binds it again. The JS string `"this page has no router"` (`dev.mjs:712`) is unreachable in a dev build: `host/web-js/build.mjs:427` always sets `exact.goTo`.

## What holds

The in-place route step is the link step. Both pages use the same "already here" test (`pathname + search`, or `history.state.url`), the same root check (`navigationBack` and a `navigate` handler), then `exact.navigate(to)` or `exact.go` / `goTo` (`host/web/input-glue.js:112-119`, `host/web-js/router.js:179-183` and `:198-203`). Already here is a success. A fragment alone skips the router and `replaceState`s the hash onto the current entry, which is how the no-router theme fixture moves `/#c`; a plain link click to a fragment is left to the browser (`input-glue.js:115`, `router.js:180`), so that click pushes an entry and scrolls, while the command sets the fragment on the entry it has. A link `press` handler is not replayed. A missing route answers `unsupported` rather than letting the browser load another document. `goTo` and `historyURL` receive a path; `historyURL` prefixes `location.origin`.

Status hooks wrap `pushState` and `replaceState` and listen for `popstate` and `hashchange` (`dev.js:458-461`). `replaceState` does not fire `hashchange`. An unchanged fact string is not posted. The vm contexts in `host/web/tests/dev-scheduler.test.mjs` have no `history` and no `pathname`; `here()` returns null, the wrapper is skipped, and `framed` is false. Those tests assert report kinds, not `location`.

`navigated` is `id → {client, seq}` (`tamber-builds.mjs:156`). A refusal whose revision is not that seq is 204 with no event (`:453-455`). The matching one is deleted and sent with `only: n.client` (`:457`). `clear` does not send a navigate frame (`:608-619`). Register replays none (`:380-390`). Scope is `write` (`scripts/tamber-pairing.mjs:50`, `scripts/tamber-server.mjs:670` then `:722`, `apps/design-tool/wire.ts:30`), the client must be present (`tamber-builds.mjs:628`), and the journal line names that client (`:603`). A paired token overwrites `request.client` (`tamber-server.mjs:534`).

`postMessage` runs only after a successful register and sends `{type: 'exact-build', id}` (`dev.js:919`, `dev.mjs:714`). The nonce, token, and design are not in it. A report still needs the stream nonce. A popup (`parent === self`) does not post. A nested frame posts to its parent, not to `top`, so `event.source` stays that nested window. The generated `here()` regex in `dev.mjs:707` is the server's `LOCATION`.
