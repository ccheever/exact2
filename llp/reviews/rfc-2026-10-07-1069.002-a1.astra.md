Two issues block implementing A1 as written.

1. **Blocker — timeout can reject the call before it replaces `to`.** [A1.4, line 183](/private/tmp/imgrv/wt-d1/llp/1069.002-media-picker.rfc.md:183)

   Checking 20 seconds only before each trial does not keep the operation inside the continuation’s 30 seconds. A final trial can start at 19 seconds, finish at 35, and write its result. Meanwhile, [the continuation](/private/tmp/imgrv/wt-d1/js/src/storage.rs:100) has failed, and [the prelude](/private/tmp/imgrv/wt-d1/js/src/prelude.js:1373) rejects the head and advances the queue. The old operation can then overwrite a subsequent write. This violates both ordering and “on any failure `to` is left as it was.”

   **Fix:** coordinate timeout and final replacement through one operation-owned terminal state. An operation reported failed must lose permission to commit; checking elapsed time before encoding alone is insufficient. Include input reading and final writing in that coordination. Test a stalled final encode followed by another write to the same destination.

2. **Blocker — the web pixel limit is checked after the allocation it should prevent.** [A1.5, line 192](/private/tmp/imgrv/wt-d1/llp/1069.002-media-picker.rfc.md:192)

   “Header before decoding” conflicts with checking dimensions after `createImageBitmap`. A highly compressible 9000×9000 PNG can fit comfortably under 64 MiB encoded while requiring roughly 324 MB for one decoded RGBA bitmap. The browser can exhaust memory before returning dimensions, instead of reporting `too-large`.

   **Fix:** inspect bounded image headers before calling the decoder, with explicit handling for every admitted format and refusal when dimensions cannot safely be established. Recheck decoded dimensions afterward. Test that oversized headers never reach `createImageBitmap`; a post-decode rejection test does not establish this guarantee.

3. **Should-fix — the native memory formula is not an ImageIO guarantee.** [A1.5, line 194](/private/tmp/imgrv/wt-d1/llp/1069.002-media-picker.rfc.md:194)

   `2 × 4 × w × h`, plus one encoded trial, omits thumbnail bit depth, row alignment, codec scratch/cache allocations, and the retained best JPEG while another trial is encoded. Subsampling JPEG/HEIC does not establish that bound for the other promised inputs. The existing [RasterDecodePlan](/private/tmp/imgrv/wt-d1/host/apple/Sources/ExactKit/RasterImage.swift:246) explicitly distinguishes its reservation policy from opaque codec RSS and allows wider staging pixels. It also [handles ImageIO rounding a side upward](/private/tmp/imgrv/wt-d1/host/apple/Sources/ExactKit/RasterImage.swift:347).

   **Fix:** specify a conservative allocation policy and distinguish controlled allocations from codec internals. Account for both retained and trial output, disable unnecessary source caching, and release intermediates between sizes. Qualify large PNG/TIFF/WebP/GIF inputs alongside JPEG/HEIC. Keep the proposed exact `w × h` drawing step; it resolves thumbnail rounding for output dimensions.

4. **Should-fix — specify the options snapshot and native wire representation.** [A1.3, line 161](/private/tmp/imgrv/wt-d1/llp/1069.002-media-picker.rfc.md:161)

   Adding an entry to `fs_methods` does not transport this signature: Ibex’s [argument converter](/private/tmp/imgrv/wt-d1/vendor/ibex/crates/ibex2/src/bindings/install.cc:118) stringifies ordinary objects, so the options arrive as `"[object Object]"`. Records also need an explicit result conversion, as `stat` does today. Separately, [storageCall](/private/tmp/imgrv/wt-d1/js/src/prelude.js:959) only shallow-copies arguments: changing `options.maxBytes` while the call waits would change native behavior, whereas the web snapshots arguments.

   **Fix:** validate and capture scalar options before queue insertion, define opcode 121’s arguments and result encoding, and reconstruct the public record. Test mutated options behind a held operation, invalid inputs rejecting without entering the queue, and all returned fields.

5. **Should-fix — valid options produce zero-sized images.** [A1.2, line 114](/private/tmp/imgrv/wt-d1/llp/1069.002-media-picker.rfc.md:114)

   For a 64×48 image and `maxDimension: 1`, the algorithm requests 1×0. For a 1×1 image whose first two trials miss, the next dimension becomes zero. Those cases reach invalid canvas/Core Graphics operations rather than the specified search outcome.

   **Fix:** explicitly define a one-pixel minimum for each output axis and stop shrinking when dimensions cannot decrease, returning `unfit` when necessary. Declare this small deviation from the reference for the generalized option range. Add tiny-image and extreme-aspect-ratio cases.

6. **Should-fix — “no metadata” and colour preservation need a precise contract.** [A1.3, lines 163–164](/private/tmp/imgrv/wt-d1/llp/1069.002-media-picker.rfc.md:163)

   Apple keeps the drawn image’s profile, while the specified web context defaults to sRGB. A saturated Display P3 photo therefore retains its gamut natively but loses it on the web. “Canvas output carries no metadata” is also too strong: the standard specifies resolution metadata and colour-profile serialization. [HTML canvas specification](https://html.spec.whatwg.org/multipage/canvas.html#serialising-bitmaps-to-a-file)

   **Fix:** say that source EXIF/GPS/IPTC/XMP metadata is discarded, while encoder-generated colour/density information is permitted. Choose an explicit output colour policy—sRGB everywhere is straightforward—or declare the platform difference. Test P3 and non-RGB inputs, including the intended SDR conversion of HDR sources.

7. **Should-fix — the tests do not establish the promised host and failure coverage.** [A1.7, line 219](/private/tmp/imgrv/wt-d1/llp/1069.002-media-picker.rfc.md:219)

   Direct Chrome `createFileSystem` tests bypass the default JS target’s facade, the prelude-backed realm, and worker placement. One concrete worker trap is the timeout clock: [the prelude replaces both `Date.now` and `performance.now`](/private/tmp/imgrv/wt-d1/js/src/prelude.js:106), so a lazily loaded helper cannot capture either normally. Use a trusted clock captured before hardening.

   Also, line 240 expects `unsupported` everywhere except macOS, contradicting the promised iOS Rust path. Codec-only simulator tests would miss an absent iOS binding installation.

   **Fix:** exercise the public call through each web carrier and an iOS TS/Rust storage path. Include grant denial before source reads, `from === to`, write/timeout failure preserving an existing destination, and `doc:/`/Windows-native refusals before their existing special dispatch paths. Test orientation **pixels**, not merely swapped dimensions; add HEIC/WebP/GIF coverage.

   Current [Safari](https://webkit.org/blog/13966/webkit-features-in-safari-16-4/) and [Firefox](https://www.firefox.com/en-US/firefox/105.0/releasenotes/) support worker 2D OffscreenCanvas. Still define `unsupported` for missing worker capabilities and test null contexts, rejected encodes, null `toBlob` results, and PNG fallback. Preserve the JPEG MIME check already proposed.

8. **Nit — Exact patch 8 is occupied.** [A1.3, line 161](/private/tmp/imgrv/wt-d1/llp/1069.002-media-picker.rfc.md:161)

   [EXACT-PATCHES.md:125](/private/tmp/imgrv/wt-d1/vendor/ibex/EXACT-PATCHES.md:125) assigns patch 8 to Android Hermes support. Reusing it makes vendor replay references ambiguous. Choose the next unused patch identifier. Opcode 121 itself is available.

9. **Nit — the result is not structurally a `Picked`.** [A1.1, line 92](/private/tmp/imgrv/wt-d1/llp/1069.002-media-picker.rfc.md:92)

   `Picked` also requires `name`. Assigning `CompressedImage` where a complete `Picked` is expected therefore fails. Keep the lean result, but describe it as sharing the image fields and show callers preserving the original name when needed.

The `fs` placement, caller-named destination, grant pair, and single host-owned search fit the existing architecture.
