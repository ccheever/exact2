VERDICT: RIGHT WITH CHANGES

1. **[BLOCKING] D1, D4, D5 — Define which components receive the library rules.** There is no precise distinction between public library components, helpers and `Gallery`. Under D1’s description, `Gallery` itself qualifies, making “places every library component” recursive. D4 also requires `children` exactly once without conditioning that requirement on a declared `slot`, excluding ordinary slotless controls. **Fix:** define the eligible declaration set, explicitly exclude gallery fixtures, and require exactly one placement only for components declaring a slot; require zero otherwise. [Draft](/tmp/rv-1139-r4/llp/1139-component-library.rfc.md:237)

2. **[BLOCKING] D2–D3 — Omitting `part=` bypasses anatomy checking.** Groups govern only class rows brought to a part’s node. Removing the node’s `part=` and corresponding declaration leaves the same class unrestricted. An unmarked sibling can therefore acquire positioning and cover the slot without violating any anatomy declaration check. This does not enforce LLP 1121 stage 12’s “a recipe styles parts.” **Fix:** require every library-owned node receiving class rows to declare a checked part, preserving the exclusion for caller-authored slot content. [Draft](/tmp/rv-1139-r4/llp/1139-component-library.rfc.md:196)

3. **[BLOCKING] D4 — The deny-list misses equivalent ways to disappear.** `opacity=-1` is a valid numeric style value, belongs to `paint`, and escapes the literal `opacity: 0` prohibition; the Linux painter clamps it to zero. Similarly, an allowed text recipe can set inherited `font-size=0`. These are effects of permitted recipe rows, beyond the stated examples of outside clipping and occlusion. **Fix:** validate effective property semantics, including opacity ≤ 0 and zero inherited text sizing, and add compiler, transaction and scrub refusal cases. Reconcile the remaining limitation explicitly with LLP 1121’s slot guarantee. [Draft](/tmp/rv-1139-r4/llp/1139-component-library.rfc.md:246), [painter](/tmp/rv-1139-r4/host/linux/src/paint/region.rs:264)

4. **[BLOCKING] D5, §5(D) — Gallery retention requires a new live-delivery design.** The gallery deliberately retains components and tokens absent from the app’s plan. Existing batches and snapshots apply only to builds with the same token-table shape, and the dev loop maintains one snapshot and broadcasts it. Merely registering the gallery “like any other” build cannot deliver edits to these differing tables. **Fix:** specify per-entry retention, projected batches, snapshots and rebuild decisions, keyed to each build’s plan/shape. Keep gallery retention out of release builds. [Draft](/tmp/rv-1139-r4/llp/1139-component-library.rfc.md:276), [protocol](/tmp/rv-1139-r4/docs/tamber-protocol.md:1104), [dev loop](/tmp/rv-1139-r4/host/web/dev.mjs:234)

5. **[BLOCKING] D5, §5(B/D) — Gallery compilation and server ownership are unspecified.** The server currently discovers params from the consuming app’s `app.contract`; gallery-only declarations will not automatically become editable through `set-param`. Changing the server root to the package would also change the ownership boundary that protects package files. **Fix:** keep the consuming app as the sole design/write owner, add gallery graphs as read-only inputs, preserve package identities, and specify an app-owned location for generated artifacts. Add refusal tests for package-addressed writes and restoration operations while a gallery is open. Happy-path before/after hashes alone do not establish this boundary. [Draft](/tmp/rv-1139-r4/llp/1139-component-library.rfc.md:283), [discovery](/tmp/rv-1139-r4/contract/cli/src/tamber_walk.rs:257), [ownership guard](/tmp/rv-1139-r4/contract/cli/src/tamber_contract.rs:75)

6. **[SHOULD-FIX] D4–D5, §4 — The new IR and wire need concrete semantics.** `parts[].slot` is undefined, and “the slot chain’s rows and dependency closure” specifies neither addressing nor representations for state layers, conditional branches and unset values. Existing conditional classes explicitly produce `none` where one branch lacks a row. The single cascade `level` is also ambiguous: `param.pad → cards.pad → space.md`, with an app override of `space.md`, involves both a package declaration and an app value. **Fix:** provide typed records and representative JSON, define unset/default handling and source freshness, and separate the editable declaration’s owner from the resolved value’s provenance. [Draft](/tmp/rv-1139-r4/llp/1139-component-library.rfc.md:255), [conditional-class semantics](/tmp/rv-1139-r4/contract/lower/src/class.rs:20)

7. **[SHOULD-FIX] D1, §5(C) — `lower-library-literal` has spelling and expression loopholes.** The colour list includes `border-color` but omits its longhands. Thus `border-left-color="#f00"` falls outside the written rule; expanding shorthands before checking makes the omission more consequential. The rule also does not say whether it checks literal leaves of conditional node expressions. **Fix:** define the restricted properties by canonical row IDs, check shorthand expansions and every value-producing branch, and distinguish permitted references/zero values from hard-coded literals. [Draft](/tmp/rv-1139-r4/llp/1139-component-library.rfc.md:127), [shorthand expansion](/tmp/rv-1139-r4/contract/lower/src/shorthands.rs:10)

8. **[SHOULD-FIX] D6 — The role test does not establish native-control use.** A radio inside a radiogroup is exempt even when the group has `appearance="none"` or vertical orientation; the Apple presenters explicitly exclude those groups from native segmentation. Conversely, the literal wording rejects an actual native input carrying a redundant `role="checkbox"`. **Fix:** check the element’s native-control classification and the segmented control’s actual eligibility rules, rather than treating role spelling and ancestry as proof. Define handling of computed roles too. [Draft](/tmp/rv-1139-r4/llp/1139-component-library.rfc.md:308), [UIKit eligibility](/tmp/rv-1139-r4/host/apple/Sources/ExactKit/IOS/SegmentsIOS.swift:456)

9. **[SHOULD-FIX] D5 retention, §5(B) — Preserve D7/D15’s additional retention roots explicitly.** “An app’s release keeps only what the app’s own sources reach” is narrower than the governing rules unless “reach” includes unconditional role overrides, computed-name retention, generated bindings/`exports`, and `.tamber` component declarations. A native component’s params must survive without a Contract row naming them. **Fix:** state that gallery roots are additional preview/check roots while release retention remains exactly D7 plus D15, including package-declared native params and their closures. [Draft](/tmp/rv-1139-r4/llp/1139-component-library.rfc.md:283), [existing native-param roots](/tmp/rv-1139-r4/contract/lower/src/theme.rs:311)

10. **[SHOULD-FIX] D4, §5 “The slot, rendered” — The pixel oracle can pass an invisible marker.** A nonzero layout rectangle containing pixels different from the cell background does not establish that the marker rendered. An opaque covering sibling with another colour satisfies both conditions. The gate also never requires held-state checks. **Fix:** compare otherwise identical renders with two distinct marker contents and require the expected marker-dependent pixel change; check exact marker cells on terminal. Exercise declared states and identify the combinations the gate covers. [Draft](/tmp/rv-1139-r4/llp/1139-component-library.rfc.md:262)

11. **[SHOULD-FIX] §5 restyling/gallery gates — Box differences are not a general styling oracle.** Changing `cards.surface` should change pixels without moving boxes. A radius change may also preserve every box. Terminal spacing changes can legitimately quantize identically—for example, 16 px and 17 px both round to the same whole cells. **Fix:** give each tested edit a property-specific expected result: resolved values and paint for colour, corner measurements for radius, and quantized geometry for spacing. Assert expected restoration after removal instead of universally requiring different boxes. [Draft](/tmp/rv-1139-r4/llp/1139-component-library.rfc.md:428)

12. **[SHOULD-FIX] §5 “The consumer, no visual change” — The rectangle allowance can exempt the entire component.** Limiting each rectangle to 10% permits ten rectangles collectively covering 100%. **Fix:** cap the union of all exempt pixels intersecting each component instance, counting overlaps once, and report the cumulative coverage mechanically. [Draft](/tmp/rv-1139-r4/llp/1139-component-library.rfc.md:421)

13. **[SHOULD-FIX] D8 — The rename guarantee misses names whose package provenance disappears.** D15 permits short overrides such as `Card.pad`. After renaming `Card`, that spelling no longer identifies a package component and can fall back to the app’s unknown-param warning. Likewise, removing or renaming a package namespace leaves an old `cards.pad` line indistinguishable from an app-owned token. **Fix:** require canonical package identities for package-param overrides, and limit the guaranteed token-rename detection to namespaces still linked unless additional ownership information is recorded. Add tests for component and package renames, not only token removal within an unchanged namespace. [Draft](/tmp/rv-1139-r4/llp/1139-component-library.rfc.md:354), [current unknown-param handling](/tmp/rv-1139-r4/contract/lower/src/params.rs:495)
