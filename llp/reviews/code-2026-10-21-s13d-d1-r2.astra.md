The round-1 fixes look correct. **One blocker and two major issues remain.**

1. **Blocker — [rows.rs:98](contract/lower/src/theme/rows.rs:98): cached font metadata can falsely refuse an accepted write.** Warm retention with an automatically weighted font backed by a static 400 face, then replace its file with a variable font supporting 700. Changing a type token from `400 1rem "F"` to `700 1rem "F"` still checks the cached 400-only `DeclaredFont` and refuses. A fresh build reads the new font’s range and accepts. Font assets are absent from the source key guarding this cache. **Fix:** include declared font-file identities/digests in cache invalidation, rebuilding or skipping stale font contexts.

2. **Major — [scan.rs:182](contract/lower/src/theme/scan.rs:182): folded grouped-list labels produce diagnostics at discarded spans.** In a grouped-list header/footer, put identical `font="body"` attributes on both `if/else` text arms. Changing `body` from a type token to a family makes the checker report both arms, with the `else` arm first. Lowering’s `grouped::messages::fold_label` collapses them into one text retaining the `then` attribute’s span. The checker therefore reports a location the build never diagnoses. **Fix:** reuse that fold during scanning, or conservatively omit affected label subtrees; compare complete diagnostic locations in a regression test.

3. **Major — [scan.rs:173](contract/lower/src/theme/scan.rs:173): native-module font rows still count as previously passed.** For `my-view font="body"`, changing `body` from a type token to a family produces `tamber-kind` here. Build lowering instead emits `lower-native-attr` and skips font validation altogether, both before and after the edit. This violates diagnostic parity and the “not judged never passed” rule. **Fix:** exclude rows rejected or bypassed by lowering’s native-module guards using the same guard functions.
