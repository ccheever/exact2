**CLEAN.** The host rule matches the approved plan: a session that holds the selection brings its own copy into view, scrolls nothing when that copy is not shown, and uses the first shown copy only when it does not hold one.

`Inspect.revealing` (`host/apple/Sources/ExactKit/Inspect.swift:165`) is the only copy of the rule. It holds when `selected` matches the outline's plan, the site is in the outline, and `sessions[was.session] == was.generation`. The copy is then `session` plus node id plus `shown`. Anything else returns nil, so another session's view with the same id, a hidden or missing id, or a later shown copy is not used. Both hosts call that function and keep the old "own click scrolls nothing" guard (`InspectIOS.swift:108`, `InspectMac.swift:249`). iOS does not reimplement the choice.

The iOS `shown` walk is the right scroll predicate. A bar stand-in is `isHidden` in the content (`NavigationBarIOS.swift:846`), so it is in `copies` with `shown: false`. A held selection of that node scrolls nothing, including not to another copy. `reveal` is only called for a view that is actually in the hierarchy; scrolling the hidden content view would move the feed to that view's layout slot. `place()` still outlines the bar. A recycled or collapsed row is the same path: hidden or gone from the window, so nil.

A move's landing node is the new selection. `select` stores its id and site before the report is sent, and the server outlines that report's source, which includes that site. On the main-queue stream (`PlanURL.swift:236`, delegate queue `.main`), `selected` is written before `reportSelected`, so the outline that answers the report sees the landing id. If that view is not mounted, the id is absent from `copies` and the scroll is nil.

The JS page treats a restored selection as not holding a copy. After reload, `install` sets `el: null` (`host/web-js/inspect-dev.js:645`). `holds` requires `was.el` (`inspect-dev.js:500`), so the outline takes `found[0]`. A live element that is detached or not in `found` still resolves to null, so a removed row does not jump to another copy. The wasm page keys the same choice by plan, `exact.generation`, and site, then the view id (`host/web/dev.js:826`). One page is one session. Wasm commands are serialized on `designing`; the JS page is not, but the outline for a report cannot arrive before `inspecting.selected` is set, because that write happens before `env.report`.
