## MAJOR

**1. `host/web-js/symbols.js:30-43` — `iconForm` paints a path `Icon::of_row` refuses.**

`known = rule === ""` treats a leading colon as a successful nonzero strip. `":M0 0h1Z".split(/:(.*)/s)` yields rule `""` and path `M0 0h1Z`, and `draw` (`symbols.js:42`) sets `data-symbol-nonzero`. `Icon::of_row` (`kernel/src/replaced.rs:185-188`) returns `None` for any colon whose rule is not exactly `evenodd` with a non-empty remainder, so the wasm host draws nothing. A literal `symbol:icon|…|:M…|` is a real source (the Linux hole test compiles that form). An unknown rule such as `winding:M0` returns an empty path but still returns the viewBox and `evenOdd` 0, so `draw` sets `data-symbol-nonzero`. `host/web/tests/symbol-hole.test.mjs:71-76` locks that in as `['', false, true]` while the comment at `symbols.js:29` says an unknown rule draws nothing and mirrors `Icon::parse`. `split("|")` is also not `splitn(4, '|')`.

Fix: same four-field split as `Icon::parse`. No colon means nonzero. Only `evenodd` plus a non-empty remainder strips and sets even-odd. Any other colon clears path, viewBox, fill, `data-symbol-nonzero`, and `data-symbol-evenodd`. Assert `:M0`, `evenodd:`, `winding:M0`, and `evenodd:evenodd:M0` against `Icon::parse`, and sample the leading-colon case so it stays blank.

**2. `contract/cli/tests/it/icon_path_readers.rs:73-99` and `:129-131` — the guard stays green on the readers it was added to catch.**

`reads_row_path` requires the argument’s first dotted field to be `path`, so `let p = i.path; s(p.0)` is invisible. Indexing the string table (`plan.strings.get(i.path.0 as usize)`) matches neither `s(` nor `.str(`. `splits_source` misses `indexOf` / `slice` / `substring`, and it matches `.split("|")` only in a file that also contains the literal `"icon|"`. The exemption is any of the previous four lines containing `Icon::of_row(`, so this raw read is allowed:

```rust

let raw = s(i.path.0);
```

`the_scan_catches_a_reader` (`:161-183`) only checks strings the patterns already match. No current production reader slips through besides the allowlisted Apple `icon_name` comparison.

Fix: flag a `.path` field copied into a local that is later passed to `s` / `.str`, flag a string-id load of a path, and flag `indexOf` / `slice` / `substring` on an icon form. Exempt only the arguments of the `Icon::of_row` call, not the next four lines. Add those snippets as fixtures the test must reject.
