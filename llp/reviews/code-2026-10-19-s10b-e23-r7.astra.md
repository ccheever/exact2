**No blocker found.** The unbounded stdout and planner backlog findings are addressed, but several round-1 fixes remain incomplete.

1. **should-fix — The design read can still wedge every import.** [scripts/tamber-isolate.mjs:64](/tmp/rv-e23-7/scripts/tamber-isolate.mjs:64)

   `open(real, 'r')` happens before checking whether the file is regular and before starting any deadline. Replacing the design with a FIFO without a writer leaves this promise—and the global import queue—pending indefinitely. The event loop remains responsive. The size check also precedes an unrestricted `readFile`; growth between them can exceed 4 MiB. Replacing the validated path before `open` can bypass containment.

   **Fix:** open without following links and without blocking on FIFOs, validate the opened descriptor, read at most `designBytes + 1`, and cover the entire read with a deadline. These cases require filesystem changes, not merely an HTTP source.

2. **should-fix — Marks still reads all kept baselines in the shared serve.** [contract/cli/src/tamber_serve.rs:644](/tmp/rv-e23-7/contract/cli/src/tamber_serve.rs:644)

   Every marks request calls `kept()`, which reads all matching files into memory without a total byte limit. The marks branch returns before using them. Large or slow baseline files therefore still cost the shared serve, outside the import watchdog.

   **Fix:** remove this read and pass an empty slice, or call a dedicated marks function. Keep baseline loading exclusively in the watched child.

3. **should-fix — The digest guard does not preserve design identity or absence.** [scripts/tamber-server.mjs:1108](/tmp/rv-e23-7/scripts/tamber-server.mjs:1108), [scripts/tamber-server.mjs:1112](/tmp/rv-e23-7/scripts/tamber-server.mjs:1112)

   The path is rediscovered separately for planning and holding; the Rust serve retains its original design target. After a manifest change from `a.tamber` to `b.tamber`, planning can read B and supply B’s digest while default operations still target A. Also, `digest: null` drops the guard entirely: a design that appears during planning is accepted without requiring a replan.

   **Fix:** bind planning to the serve’s validated design path, carry that exact path with its digest, and represent absence explicitly—or refuse imports while the design is missing.

4. **should-fix — Local imports still contain unwatched work.** [scripts/tamber-server.mjs:1457](/tmp/rv-e23-7/scripts/tamber-server.mjs:1457), [scripts/tamber-isolate.mjs:129](/tmp/rv-e23-7/scripts/tamber-isolate.mjs:129)

   Other CLI imports synchronously load their sources before entering `planAlone`. A 256-file count does not bound bytes or prevent a single FIFO from hanging.

   **Fix:** route resolved Astryx JSON through the watched planner too, and perform bounded, regular-file source reads before retaining CLI input.

5. **should-fix — RSS accounting still excludes descendants.** [scripts/tamber-isolate.mjs:26](/tmp/rv-e23-7/scripts/tamber-isolate.mjs:26), [scripts/tamber-isolate.mjs:38](/tmp/rv-e23-7/scripts/tamber-isolate.mjs:38)

   Cargo can replace itself with the final planner, but its compilation children remain outside this PID-only sample. The Linux address-space limit applies per process, not to the aggregate tree. Group killing at ten seconds does not enforce the memory threshold during those seconds.

   **Fix:** require a prepared executable for admission, or account for the complete process group. This portion of both prior memory findings remains unresolved.

6. **should-fix — A kill releases the concurrency slot before termination is confirmed.** [scripts/tamber-isolate.mjs:89](/tmp/rv-e23-7/scripts/tamber-isolate.mjs:89)

   Immediate settlement fixes the old response hang. However, a process whose exit is delayed by kernel I/O can remain alive after `finish()` clears monitoring and advances the queue. Repeated failures can accumulate processes despite the “one at a time” claim.

   **Fix:** answer promptly, but retain the active-process permit until exit is confirmed. Refuse further imports while termination remains outstanding; close stdin and cancel the outstanding probe during cleanup.

7. **should-fix — The queue has no actual waiting deadline or client isolation.** [scripts/tamber-isolate.mjs:53](/tmp/rv-e23-7/scripts/tamber-isolate.mjs:53)

   `waitMs` is checked only when the preceding job finishes. An accepted request can wait roughly 39 seconds under ordinary ten-second jobs, or indefinitely behind the blocked design read above. One authenticated client can occupy all slots and keep replenishing them. Disconnect, revocation, and server shutdown do not cancel queued imports.

   **Fix:** use independently expiring queue entries, a per-principal allowance, and cancellation tied to request/server lifetime. The global depth cap fixes unlimited backlog retention, but not these remaining starvation cases.

8. **should-fix — The “2 MiB” output cap counts UTF-16 units.** [scripts/tamber-isolate.mjs:111](/tmp/rv-e23-7/scripts/tamber-isolate.mjs:111)

   `out.length` is not a byte count. A DTCG filename containing repeated three-byte characters, repeated across unmapped rows, can produce nearly 6 MiB of UTF-8 output below this threshold. This remains bounded, but exceeds the documented retention limit.

   **Fix:** count bytes before appending while preserving streaming UTF-8 decoding. Also enforce the intended size limit on the complete proposal before retaining or broadcasting it.
