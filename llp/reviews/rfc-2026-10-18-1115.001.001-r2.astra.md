The remaining **material concerns** are:

1. **Text masking makes r2 less discriminating than r1.** D5.2 removes text-colour probes, while D5.3 masks entire text line boxes. A label painted in the wrong colour—or made invisible inside an otherwise unchanged filled control—can retain its layout and accessibility information and pass every applicable static comparison. **Change:** retain a calibrated text-appearance check, at least on the phone: coverage-aware colour/opacity measurements and glyph-image comparison with bounded rasterization tolerance. Add wrong-colour and invisible-label defects to O1. Whole-line masking must not qualify text appearance.

2. **The phone’s field geometry still comes from the wrong engine.** D4 recognizes that the phone uses `EditText`, but D5.1 obtains Exact’s text boxes from its paragraph. The implementation records the actual `FieldText` drawing in `Fields.kt`; Rust paragraph metrics do not measure that drawing. **Change:** obtain hosted-field line boxes, baselines and line counts from the actual `EditText` layout, transformed through its padding, scrolling and clipping. Use Exact paragraphs only for text they actually draw.

3. **Calibration can erase the sensitivity O1 demonstrated.** D4 derives thresholds from surrogate discrepancies without a maximum acceptable error. O1’s detection test precedes those thresholds, and D5.3 explicitly cannot fail yet. A later generous threshold could pass every earlier planted defect. **Change:** require independently captured valid specimens to pass **and** planted defects to fail using the final calibrated thresholds. If both cannot hold, make that observable phone-only. Treat systematic rendering differences separately from capture noise; do not automatically turn them into tolerated defects.

4. **“Matched” still lacks reproducible evidence and sufficient coverage.** D1/D7 omit the resolved UI/Foundation/ripple dependencies and complete environment fingerprint. D7 still lacks wrapped text, actual RTL-script content and reduced-motion cases. **Change:** attach dependency and environment fingerprints—including Android build, runtime/native-renderer versions, fonts and capture mode—to the result; require those specimens where applicable. D8 must review implementation/dependency changes even when token values stay unchanged.

5. **Behavioral comparisons remain underdefined.** Reading both accessibility trees through the same API does not define equivalent nodes, labels, states or actions. “A frame of slack” likewise needs an input timestamp and captured-frame timestamps. **Change:** specify specimen-based node correspondence, normalization, action arguments/outcomes, modal focus restoration and touch-target observations; compare phone motion against elapsed time from the recorded input.

**Nonmaterial follow-ups:** name O1’s implementer/date; give the complete warm job a budget and owner; explicitly fail the asynchronous job on regressions while keeping landing nonblocking. Make adopting Expressive an explicit bump decision.

**O1 is now the right first implementation slice, as a provisional instrument.** The five components and planted defects are a useful bounded start. Its completion must not imply fidelity: fix text coverage, distinguish provisional detection from qualification, and require O2 to repeat the detection tests with final thresholds before S2 uses the oracle to declare matches.
