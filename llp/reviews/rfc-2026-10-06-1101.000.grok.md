## Overall assessment

LLP 1101.000 is a good evidence note and a half-good plan. G1–G5 are real, and they are the result that matters: a terminal entry can be ordinary Contract, the logic does not know it is a terminal, and the edit loop is a text diff. P1 (axis check) and P9 (text screenshots first) should land. P2 should land only after it stops treating CSS `medium` as the heavy box. P3, P4, and P6 are worth doing later, smaller and more specified than they are here. P5 (`Row`, `Tabs`, `Panel`) is the wrong next step. P7's scroll half looks wrong against the current compiler. P8 is the right deferral, and the parent RFC still claims the feature exists.

The fixture is a 90-line list with three rows. It can prove the vocabulary. It cannot prove lists, wrapping, or focus. Those are the LLP reader's problems, and that is the consumer LLP 1101 §9 already named.

## Strengths

- **The bet is confirmed with the file, not a sketch.** §1 G1 matches `spike/apps/todo/terminal.contract`: lines 5–37 are a shape, state, `derive`, and actions, and the view starts at line 39. Nothing above the view is terminal-specific.
- **The loop claim is the best idea in the document.** §1 G2 and P9 follow from a host that prints a grid. The fixture test already treats that grid as the assertion (`spike/host/terminal/tests/todo.rs:13–29`). That is a real advantage over every pixel host.
- **Cells are honest, and the profile catches the rows it was built to catch.** G3 and G5 match the code. `1ch` is 8 px and `1lh` is 16 (`spike/kernel/src/style/cells.rs:18–20`). The profile test refuses `padding=16`, `box-shadow`, `font-size`, `margin="1lh 2px"`, and `canvas` as five errors (`spike/contract/cli/src/terminal.rs:213–226`).
- **C1's table is true.** With the box top on a row boundary, `padding-top` of `1ch` (8 px) is half a row and `round` of 0.5 goes away from zero, so it becomes 1 row. `2ch` is exactly 1 row. `3ch` is 1.5 and becomes 2. `padding-left="1lh"` is 16/8 = 2 columns (`paint.rs:56–69`). The prose undersells the result: `padding="1ch"` does not stay "half a row." After the snap it is a blank row on top and bottom.
- **C2 is a real hole, and the mechanism is as described.** `border` is `AttrTarget::Shorthand` (`contract/lower/src/tags.rs:788–789`), and the profile ignores anything that is not `AttrTarget::Styles` (`terminal.rs:110–112`). `border_width_*` and the radii are `quantize` in the spike schema, so the cell check never sees them. Any positive width then becomes one cell (`cells.rs:34–39`). The painter calls the border heavy when the written width is at least 3 (`paint.rs:193–203`). The fixture's `border="1px solid #5f87af"` and `border-radius=4` (`terminal.contract:57–58`) are exactly the lie D3 forbade for lengths, and the test expects the light rounded box that lie produces (`tests/todo.rs:26–28`).
- **Refusing bare integers is the right call** (§3, "Not proposed"), for the reason LLP 1101 D3 gives: a terminal source stays a legal page, and `padding=1` stays 1 px. LLP 1101 Q2 is already axis-aware ("lowers to `ch`/`lh` by axis"). This note describes Q2 as verbosity-only. The rejection still stands. The reason to write down is source meaning, not character count.
- **P8's split is right.** Reverse video is implemented and is the only focus paint (`paint.rs:174–176`). `:focus-visible` does not exist in the compiler. Caltrain's handler-and-state pattern is a cross-surface question. Keeping it out of this RFC is correct.
- **The note stays exploratory.** Status, implementer "none yet," and "nothing moves off DEFERRED" match LLP 1101 and `rules/DEFERRED.md` ("no TUI host"). That restraint is part of why the document is good.

## Concerns

**High — P5 walks back LLP 1101 D2 on the evidence of one list.** D2 said a terminal package of `Panel` / `List` forks the vocabulary, and that `exact:terminal` ships only what a consumer uses. §3 P5 adds `Row`, `Tabs`, and `Panel` because the fixture repeats a button's flex styles (`terminal.contract:64–67`) and a selected-tab look (`terminal.contract:45–53`). That repetition is real. A component kit is the exact1 answer anyway: `llp/exact1-0368-tui-target.rfc.md:170–187` required `Row`, `Panel`, `Tabs`, `List`, `StatusBar`, and `KeyHelp` as the vocabulary. Once `Row` exists, agents will write `Row` instead of `button`, and the "same vocabulary" claim becomes a kit with HTML underneath. The one thing the fixture cannot say in CSS is a title drawn into the top edge. That is Q2, and HTML already names it `fieldset` / `legend`.

What resolves it: delete `Row` and `Tabs` from the proposal. Leave `exact:terminal` unbuilt until a second app has a need that is not a CSS shorthand. Answer Q2 by admitting `fieldset` and `legend`, and draw the legend into the border in the painter.

**High — the focus model contradicts LLP 1101 D6, and this plan does not touch it.** D6 says arrow keys belong to the focused list, scroll, or field. The spike binds `ArrowDown` to the same focus walk as Tab (`spike/host/terminal/src/host.rs:399–402`). Every row is a Tab stop (`terminal.contract:62`). Reverse video then has to mean both "focused control" and "cursor row" (C5, P8). Three todos hide this. A reader or a real list will not. `tabindex` already exists (`contract/lower/src/tags.rs:625–627`) and the host never reads it. `autofocus` parses (`contract/syntax/src/parser.rs:1313`) and the host never reads it (`host.rs` starts `focus: None`).

What resolves it: add a decision to this RFC. A `list` (or a scroll of options) is one Tab stop. Arrows move a cursor inside it. Tab moves between regions (filters, list, field). Reverse video paints the cursor row. `autofocus` focuses on boot. Amend LLP 1101 D6 so it describes the host that exists, including the `:focus-visible` sentence, which is not true today.

**Medium — P2 canonizes the lie it is trying to kill.** CSS `medium` lowers to `3px` and `thin` to `1px` (`contract/lower/src/shorthands.rs:137–141`). The schema default for border width is 3. The painter treats width ≥ 3 as heavy `━┃`, and it drops rounding whenever the border is heavy (`paint.rs:205–213`). So `border-style=solid` with no width is the loud box, and the fixture had to write `1px` to get the ordinary one. P2 then makes `thin` the spelling of every normal panel and `medium` a trap. §4 of the parent already said "`medium` = heavy." The spike falsified that choice. The author reached for the light line.

What resolves it: in a terminal entry, a drawn single border is light. Heavy is an explicit word (`double`, or keep `thick` and refuse it if you want only two weights — pick one and use it only for heavy). `border-radius` accepts `0` and `1ch` only. Radius together with a heavy border is `terminal-length`, not a silent drop. Check the shorthand string and the longhands. The longhands are `quantize`, so a check that lives only in the `cell` arm will not see `border-width=1`.

**Medium — P1 is the right check and will miss the fixture's own tags unless the spec says how.** `row` and `column` set `flex-direction` as fixed styles, not attributes (`contract/lower/src/tags.rs:69–78`). P1 says a one-value `gap` follows "a literal" direction, and otherwise both units pass. An implementer who looks only at a `flex-direction` attribute will accept `row gap="2lh"`, which is the bug, and will also fail to explain why line 44's `gap="2ch"` passes. The walker also skips `style` declarations (`terminal.rs:186–190` walks component views only; `File::styles` is a separate list at `contract/syntax/src/ast.rs:40`) and skips every expression that is not a number, a string, or a ternary (`terminal.rs:92–105`). `padding-top=pad` and `class=Pad` with `padding=16` in a style block both sail through. A one-value `gap` on a wrapping container sets both axes (`row-gap` is vertical). The proposal assumes `nowrap`.

What resolves it: state that tag-implied `flex-direction` counts as a literal. Walk `style` blocks. For a non-literal length, refuse it in a `cell` row unless it is `0`, `auto`, a percentage, or a `ch`/`lh` string. On `flex-wrap` other than `nowrap`, a one-value `gap` must be legal for both axes or it is `terminal-axis`.

**Medium — P3 is the right control and the wrong size and verb.** Checkbox, radio, range, date, and file are already Contract controls (`contract/syntax/src/ast.rs:1121–1132`). The terminal profile does not refuse `input`. The painter records a `Control` as a hit and draws nothing for it (`paint.rs:108–119`). "Admit the checkbox" is already done. What is missing is paint, size, and the event. Linux toggles with `input` then `change` carrying a bool (`host/linux/src/presenter/control.rs:73–75`). The spike turns Space into `press` (`host.rs:403–407`). A checkbox with no kernel min-size collapses, because the glyphs `[x]` exist only in the painter. `accent-color` has no `terminal` key in the spike schema diff, so the profile would refuse it until someone marks it `quantize`. The other control kinds would keep painting as empty focusable holes, which is the silent degradation D2 forbids.

What resolves it: refuse every control kind the host does not draw. Draw checkbox and radio at a fixed 3×1 cells (`[x]` / `(•)`). Space and Enter dispatch the Linux events. Say what happens to the row: it stops being a button, and the `checked` prop is the tree's answer. `aria-checked` already exists (`tags.rs:611`) if you want the tree to say checked before the host can draw the control.

**Medium — P4 does not replace the footer it deletes.** The footer's useful content is host behavior: Tab, Enter, `n`, `1`/`2`/`3` (`terminal.contract:84`). An overlay of `aria-keyshortcuts` plus accessible name misses Tab, arrows, Enter, Esc, and Ctrl-C. The spike's `shortcut()` also does not know an accessible name. It matches the property and returns the first hit, including a zero-size one (`host.rs:292–302`). `focusables()` filters empty rects. `shortcut()` does not. There is no compiler check for two bindings of the same key, which LLP 1101 D6 already required.

What resolves it: the overlay lists host keys and the app's shortcuts. An app shortcut wins, so the LLP reader can take `?` for search. Paint the overlay into the grid so `screenshot out.txt` shows it. Skip clipped and zero-size hits. Add the duplicate-key bake error in the same change.

**Medium — P6's derived floor will be wrong.** LLP 1101 D1's authored `minimumColumns` / `minimumRows` is the right screen. "Until `app.json` exists, derive a floor from the root's min-content size" is a second policy. Min-content of this list is either enormous (the longest title, if nowrap has not applied yet) or nothing (flex items may shrink). The empty border at 60×6 (C7) is the bug. An inferred number is a new way to get it.

What resolves it: pass `60×16` on the command line until `app.json` exists. Below that, paint the host's own "make the window larger" screen into the grid. Add the 60×6 case next to `tests/todo.rs`. Do not read min-content.

**Medium — C6's scroll sentence does not match the lint, so P7's QUEUE line is aimed at the wrong bug.** I did not re-run the compiler. I read the lint that has been in tree since 2026-10-04, before the spike. `flex=1` counts as a bound by itself (`contract/lower/src/values.rs:1120–1132`), and `contract/cli/tests/it/collection_bounds.rs:197–208` compiles `flex="1"` inside a column with no height. `flex-grow` is never read. `min-height=0` is accepted when the parent column is already bounded (`values.rs:1138–1152`). The fixture's tree is that case: a root `column` with `height="100%"`, a panel with `min-height=0`, then the scroll. In that tree, `scroll flex-grow=1 min-height=0` does not trip `lower-scroll-unbounded`. The real asymmetry is narrower: `flex-grow=1` without a bounded parent is refused, and `flex=1` is accepted even then.

What resolves it: compile both spellings in the fixture's tree before adding a QUEUE line. If they both pass, delete that half of C6. Keep the `light-dark()` half.

**Medium — the painter rewraps, and the next consumer is a wrapping reader.** LLP 1101 D3 says the kernel owns wrapping and the painter never rewraps. The spike measures with `wrap` (`measure.rs:160–176`) and wraps again at the snapped content width (`paint.rs:300`). Snap can move that width by a column. The todo lines are short, so the fixture cannot see it. The LLP reader will.

What resolves it: record it in this RFC as a known spike gap, ahead of any component work. The painter should draw the kernel's line boxes.

**Low — a few smaller mismatches.**

- The summary says the first three proposals are compiler checks of a few dozen lines. P1 is. P2 is the profile plus the painter. P3 is host drawing, measurement, and events.
- `cells::set_terminal` is a process-wide one-way flag (`cells.rs:22–29`). Fine for a dedicated binary. Say so, so nobody calls it from a test process that also lays out GUI fixtures.
- The profile still admits `border-style` values the shorthand lowerer refuses (`shorthands.rs:117–126` allows solid and inset only) and that `border_widths` turns into no border unless the style is solid or inset (`spike/kernel/src/style/border.rs:17–19`). Dashed cannot be written today. When it can, the painter will drop it. That is a parent-§4 gap, not a reason to block P2.
- `docs/contract-for-agents.md:1429` lists `light-dark(a, b)` as a colour spelling and does not show the quotes. That is why C6 happened. P7 updates `docs/agent-pitfalls.md` and leaves the guide that agents read first (`CLAUDE.md`) pointing at the trap.

## Suggestions

Ranked by value for cost.

1. **P1, specified as above.** Highest value, smallest honest change. It makes the trap in C1 a compile error and lets LLP 1101 Q2 stay closed. Include tag-implied direction, style blocks, and non-literal lengths.
2. **P2 with light as the ordinary border, `1ch` as the only nonzero radius, and heavy as one explicit word.** Rewrite the fixture's lines 57–58 in that spelling and keep the `╭` golden. Amend LLP 1101 §4's "`medium` = heavy" in the same revision.
3. **One list cursor, not a component kit.** Roving focus inside the list, arrows move it, Tab changes region, `autofocus` on boot. This changes the feel of every terminal app more than `Row` does, and the keys are already being intercepted for the wrong job.
4. **Refuse undrawn controls at bake, then draw checkbox and radio.** One profile arm for `input type`. No empty focus stops. Do the drawing in a follow-up if the refusal lands first. The refusal is the D2 property. The glyphs can wait a day.
5. **P6 as an explicit `60×16` floor and a 60×6 golden.** Drop min-content inference.
6. **P4 with host keys, app-shortcut precedence, and the duplicate-key error.** Then delete the hand-written footer.
7. **P7, colour half only.** Put the quoted form in `docs/contract-for-agents.md` and `docs/agent-pitfalls.md`. Quote the diagnostic the compiler already emits (`contract/lower/src/values.rs:380`).
8. **Amend LLP 1101 D6 in this revision.** Reverse video is the focus indicator. `:focus-visible` is not implemented. Arrows will belong to the focused list once suggestion 3 exists. Until then the parent should not claim they do.
9. **P9 when `scripts/agent.mjs terminal` exists.** One line in that guide. Do not write the guide before the command (`rules/RULES.md`: a spec with no implementer is how the corpus grew).
10. **Painter uses the kernel's line breaks** before anyone ports the LLP reader. Not a P-number for the todo. A recorded gap so it is not rediscovered as a wrapping bug.

Take away: `Row`, `Tabs`, `Panel`, the min-content floor, and the scroll QUEUE line.

## Novel ideas

**Make the list a listbox, in the ARIA sense, and let that be the terminal's one new behavior.** One Tab stop, a cursor index the host owns, arrows move it, Space or Enter activates the row, reverse video on the cursor only. The web already has this pattern (`listbox` / `option`, roving tabindex). Exact does not need a `List` component to get it. The host keys are the behavior. Contract keeps `button` or `option` rows. This is the difference between "a web page drawn with box characters" and "a terminal app," and the spike currently does the former (`host.rs:399–402`).

**Use `fieldset` and `legend` for the titled box, and stop there.** `╭─ Tasks ───╮` is `legend` text painted over the top border, clipped out of the border run. No `Panel` import, no title prop, and the web draws the same elements as a real fieldset. Q2 is the whole of `exact:terminal` until a second app asks for something else.

**Give the terminal entry a declared UA sheet for two properties, the way D6 already declares reverse video.** A terminal button is `text-align: start`. A single-line row is `white-space: nowrap`. Those are the lines C3 pays on every row (`terminal.contract:64–71`), and `docs/contract-for-agents.md:599–603` already tells GUI authors to override the button default by hand. The button default is Exact's own UA sheet (`tags.rs:120–122`), not a CSS law. Name the terminal sheet next to the reverse-video deviation. The web layout oracle (LLP 1101 §5, stage 3, not a gate) compares author lengths, not UA chrome. This removes the reason `Row` exists without a second vocabulary.

**Author interaction in the terminal entry first, even when the app will have a GUI.** The failed experiment was projecting a GUI into cells (LLP 1101 §1). The other direction is useful for agents and is not a projection: shared state, two hand-written views, and the terminal view is the one whose screen diffs. Focus order, keys, empty states, and overflow show up in `print` in one command (`§1 G2`). The GUI entry stays the visual one. I would not build tooling for this. I would write it into the terminal authoring guide as the recommended order, once P1 and P2 make the terminal file honest.

## Open questions

- **UA sheet or author CSS?** Does a terminal entry get declared deviations for button alignment, nowrap, and a light default border, or must every difference be written on the node? This decides whether P5's `Row` has a reason to exist. I would allow the sheet.
- **What is one Tab stop?** Per control, as the spike does, or per list, with a cursor inside? I would do per list for anything that is a set of peer rows, and per control for filters, fields, and dialogs.
- **`fieldset`/`legend` now, or only when a second screen has a titled box?** I would specify the painting rule now, in a paragraph, and build it when the LLP reader or a settings screen needs it.
- **Which border word means heavy, and is the CSS default light?** I would make every ordinary solid border light and pick one explicit heavy spelling.
- **Does `?` belong to the host?** Only when the app has not bound it. The reader will want it.
- **Who implements, and does any of this take "no TUI host" off `rules/DEFERRED.md`?** None of P1–P9 should. The parent already says the take is Charlie's and still open (LLP 1101 §9.2). P1 and P2 can live on `terminal-spike` without that decision. `exact:terminal` should not.
- **Is the scroll lint actually red on this tree?** One compile answers it. I expect no.
