**Concerns**

1. **Material. `back` is already a Contract function.** `back(router)` is a router expression (`/Users/daehyeonmun/orca/workspaces/exact2/fw-browser-shell-rfc/docs/contract-grammar.md:874`; recognised at `/Users/daehyeonmun/orca/workspaces/exact2/fw-browser-shell-rfc/contract/lower/src/warnings/root_replace.rs:372`, `("back", [r]) => self.is_slot(r)`). D3 adds `back(id)` to `HOST_COMMANDS`, where "a statement naming one is the command, never a call" and a same-named action is refused as ambiguous (`/Users/daehyeonmun/orca/workspaces/exact2/fw-browser-shell-rfc/contract/syntax/src/lib.rs:91-99`). `stop` is also an existing handler name (`/Users/daehyeonmun/orca/workspaces/exact2/fw-browser-shell-rfc/contract/lower/src/tags.rs:441`, the media session), so a component with `action stop` could not call `stop(id)`. Resolve: state how the compiler tells `nav = back(nav)` from `back("tab-3")`, and the rule for `stop`; or choose names that do not collide and declare the deviation.

2. **Material. The partitioned guest inherits the direct guest's self-post interception.** D1 says the guest "keeps §10's direct rules" and "has no bridge". The arm injects a document-start script into every main-frame document that captures any `message` event whose `source` is the window itself, calls `stopImmediatePropagation()`, and forwards the data to the app (`WebArm.swift:266-270`). A page's own `window.postMessage` to itself is a common idiom (setImmediate polyfills, schedulers). In a browser shell every site a tab visits gets this script. That is a tell and a compatibility break, and page data reaches the app's `message=` from the committed origin. Also, the `exact-app` scheme handler is registered on every web view (`WebArm.swift:246-247`) and answers while `assetPage != nil` (`:82`), which a direct guest's self-navigation does not clear (`:678-686` sets only `revoked`). Resolve: a partitioned frame gets no `message=` and no `postMessage` target (refused at compile time, as `sandbox` is), no document-start script in the page's documents except the agent's bridge, and no `exact-app` handler (or `partition` with a bundled `src` is refused). Say which exact1 finding each rule keeps out.

3. **Material. The web subset is stated two ways, and `navigate`'s URL policy is unstated.** The Summary says "`navigate` and `reload` for any guest" (§Summary, line 37-39). §10's table says a cross-origin guest gets `navigate` only (line 546). A parent cannot call a cross-origin frame's `location.reload()`; re-setting `src` reloads the authored `src`, not the current URL. Pick one. Separately, the web host admits a frame `src` only through a scheme allowlist so a `javascript:` URL never runs in the app's origin (`/Users/daehyeonmun/orca/workspaces/exact2/fw-browser-shell-rfc/host/web-js/rt.js:684`, `/Users/daehyeonmun/orca/workspaces/exact2/fw-browser-shell-rfc/host/web/navigation.js:690`). `navigate(id, url)` takes an address field's text (§1) and the RFC does not say it passes the same policy on every host, Apple's `load(URLRequest)` included. Resolve: one web-subset statement, and `navigate` takes `src`'s URL policy on every host.

4. **Material. The host table does not use LLP 1133 D8's words.** D8 requires each cell to be the platform API, `absent`, or `later`. The table writes "refused" for every Android cell and "absent" for Windows. Android's `WebView` is top-level today (`Natives.kt:513-519`: bare `loadUrl`, pooled views), so "refused" for D1 topology misdescribes what happens; and Android has the APIs (`WebViewClient`, `WebChromeClient.onCreateWindow`, `onJsAlert`, `onShowFileChooser`, `DownloadListener`, the `androidx.webkit` Profile API, `WebSettings` darkening and zoom). Windows has WebView2. Both are `later`, with the API named. Linux alone is `absent` (LLP 1020 D5). Resolve: rewrite the table in D8's words.

5. **Material. The ceiling test counts the oracle's rows, not the framework's common uses.** LLP 1133 D9 item 4 asks for "the common uses of each platform's framework". §10 counts §1.1's seventeen rows. Uses of `WKWebView` a hand-built browser shell reaches that no tier or §13 names: element fullscreen (`WKPreferences.isElementFullscreenEnabled`, `WKWebView.fullscreenState`); `allowsBackForwardNavigationGestures` (an iOS tell; the clone sets it false, `T3BrowserSession.swift:89`); `javaScriptCanOpenWindowsAutomatically` (the clone sets it false, `:76`; D5 states no gesture rule for scripted popups); `inactiveSchedulingPolicy` (the clone sets `.throttle`, `:78`; D1's "keeps running" while hidden depends on it); `interactionState` (a tab's session restore across launches); `allowsLinkPreview`, `allowsInlineMediaPlayback` and `mediaTypesRequiringUserActionForPlayback` (iOS: a video leaves the tab without them); `preferredContentMode` (iPad desktop or mobile); `estimatedProgress`; `createPDF`; `themeColor`. Resolve: run the ceiling test over `WKWebView`'s API, put each use in a tier or in §13 with its reason, and list the unsaid defaults with their HIG source (D9 item 5).

6. **Material. Guest fullscreen is dropped without a word.** The oracle allows `fullscreen` so a page fills its own webview (`BrowserSession.ts:37-40`). The clone implements it in `T3BrowserSession+Links.swift:18-20,120` and following. §12 deletes `+Links.swift` at stage 2, and D5 has no fullscreen row. A hand-built WKWebView browser enables element fullscreen; with it off, a video's fullscreen button does nothing. Resolve: a D5 row for guest fullscreen (the platform's whole-screen fullscreen, as Safari has it, or the tab-filling one the oracle has), and its tell-test judgement.

7. **Minor. `navigate`'s record is mapped by attribute name, not by tag.** `event_record(attr)` keys on the attribute (`/Users/daehyeonmun/orca/workspaces/exact2/fw-browser-shell-rfc/contract/types/src/selection.rs:69-95`), and `navigate` on the root is "zero or one location string" (`contract-grammar.md:1307`). D2 reuses `navigate=` on `iframe` with a `NavigateEvent`. Resolve: state the type pass branches by tag for `navigate`, or use a name that does not collide.

8. **Minor. `partition` couples two concepts.** Electron's `<webview>` is top-level with or without `partition` (the default session). D1 ties top-level to naming a partition, so there is no spelling for a top-level guest in the default store. Q1 should name this and say why it is acceptable now.

9. **Minor. D5's scope and gate are unclear.** It does not say whether popups, dialogs, file inputs and downloads apply to every `iframe` or to partitioned ones only; §8 uses `windowopen=` on a sandboxed frame, so presumably every frame. And the `new-window` row opens a platform window with no gate, while the text says "a frame that never asked for popups opens none". Resolve: name the frames D5 covers and the gate for `new-window`.

10. **Minor. `windowopen`'s precedent.** Chrome's `<webview>` tag has `newwindow` with `windowOpenDisposition`; BiDi's `browsingContext.contextCreated` fires after the fact. Name the nearest precedent or adopt `newwindow`.

11. **Minor. `pending`'s shape and 1069.007's table.** D3 of LLP 1069.007 writes entries as `device: {capability, args}` with a declared inspection summary, and keeps a capability-name table (`/Users/daehyeonmun/orca/workspaces/exact2/fw-browser-shell-rfc/llp/1069.007-device-capabilities-in-the-agents-hands.rfc.md:311-321`). The RFC writes `{capability: "dialog", args}`, adds no rows for `dialog` and `download`, and does not say which capability a guest's file input uses (`pick`?). D7 requires the amendment.

12. **Minor. The Summary table misstates two rows.** Downloads are "nothing" in the Summary but D5 adds a `download=` event. `prompt` is answered here but returns null in the oracle and the clone; record it as a declared difference from the oracle.

13. **Minor. `captureScreenshot` is Contract-only, but T3's agent runs in data code.** The oracle's automation ops include `snapshot` beside `click` and `evaluate` (`/Users/daehyeonmun/orca/workspaces/exact2/t3code-oracle/packages/contracts/src/previewAutomation.ts:28-40`). Also say the app reads the file under its own `fs.read` grant (`/Users/daehyeonmun/orca/workspaces/exact2/fw-browser-shell-rfc/runner/src/share.rs:228-230`).

14. **Minor. Occlusion and hidden painting.** The clone disables WebKit's occlusion detection under the agent because a covered window stops painting (`T3BrowserSession.swift:92-94`, a private selector). D7 and D8 under the agent should name this as a stage-1 measurement.

15. **Minor. Tier 3's ownership list is thin.** `WKWebViewConfiguration` choices (data store, preferences, `applicationNameForUserAgent`) are fixed at construction; LLP 1133 D3 calls that a before-construction hatch moment. Say whether there is one and what the app may change.

16. **Minor. `zoom` on `<iframe>` is measured on Chrome only.** The web cell says "CSS itself"; the conformance runs include Firefox and WebKit. Say whether their behaviour is measured or declared.

17. **Minor. `error: "crashed"` has no web name.** Declare the deviation (Electron: `render-process-gone`).
