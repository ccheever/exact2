1. **blocker — Linux’s limit setup can prevent every planner from starting.** [scripts/tamber-isolate.mjs:33](/tmp/rv-e23-8/scripts/tamber-isolate.mjs:33)

   With the usual unlimited soft address-space limit, lowering only the hard limit first fails because the soft limit exceeds the proposed hard limit. The `&&` chain never executes the planner; the failure is generally reported as a costly-source 413.

   **Fix:** set both limits together with `ulimit -v ${kb}`, or lower the soft limit before the hard limit. Test the actual Linux launch path. Round 2’s “soft only” premise was incorrect for the default `ulimit -v` invocation.

2. **blocker — Successful imports can still exhaust the parent through a slow subscription.** [scripts/tamber-server.mjs:176](/tmp/rv-e23-8/scripts/tamber-server.mjs:176), [scripts/tamber-remote.mjs:202](/tmp/rv-e23-8/scripts/tamber-remote.mjs:202)

   A paired client can subscribe, stop reading, and repeatedly submit successful imports through another connection. Every proposal is written to the subscription without respecting `res.write()` backpressure. The remote connection deadline is suspended while that stream is answered. Held-proposal and event-history eviction do not remove queued socket writes, so parent memory can grow independently of the child’s limits.

   **Fix:** enforce a bounded outbound queue per subscriber and disconnect slow readers when it fills. Test repeated imports against a subscription that stops consuming.

3. **should-fix — The complete proposal still has no byte cap.** [scripts/tamber-server.mjs:941](/tmp/rv-e23-8/scripts/tamber-server.mjs:941), [tamber/src/session.rs:499](/tmp/rv-e23-8/tamber/src/session.rs:499)

   The 2 MiB child-output cap is fixed, but the subsequent shared-serve proposal adds an uncapped diff. Two changes near opposite ends of a permitted, nearly 4 MiB design can produce roughly 8 MiB of diff: `file_diff` includes the intervening text on both sides. Repeated proposals retain these strings in event history even after holds are evicted. This leaves round 2’s request to cap the **complete proposal** unresolved.

   **Fix:** cap the final serialized proposal before retaining or broadcasting it, and bound event retention by bytes as well as count.

4. **should-fix — Planning and holding still do not share the serve’s design identity; CLI imports discard the digest.** [scripts/tamber-server.mjs:1106](/tmp/rv-e23-8/scripts/tamber-server.mjs:1106), [scripts/tamber-server.mjs:995](/tmp/rv-e23-8/scripts/tamber-server.mjs:995), [scripts/tamber-server.mjs:1477](/tmp/rv-e23-8/scripts/tamber-server.mjs:1477)

   Computing `target` once fixes rediscovery within an HTTP import, but it still comes from the current manifest. Rust retains its startup design, and operations without `file` target that design. After the manifest changes from A to B, the child can plan against B while `propose` operates on A. Rust permits missing digests during proposal planning, so B’s digest does not guard A. Remark also rediscovers the manifest path.

   Separately, `importTheme` receives the child’s digest but posts `propose` without `files`, allowing intervening design changes—and missing-design planning—to bypass this protection.

   **Fix:** bind planning, marks, operations and guards to the serve’s validated design identity. Carry that identity and digest through CLI proposals too, and refuse absence there.

5. **should-fix — The design’s two-second deadline does not cover the whole read.** [scripts/tamber-isolate.mjs:77](/tmp/rv-e23-8/scripts/tamber-isolate.mjs:77), [scripts/tamber-isolate.mjs:84](/tmp/rv-e23-8/scripts/tamber-isolate.mjs:84), [scripts/tamber-isolate.mjs:88](/tmp/rv-e23-8/scripts/tamber-isolate.mjs:88)

   `realpath`, `open` and `stat` precede the deadline. After a read timeout, `finally` still awaits `file.close()`, which can wait for outstanding I/O. A stalled filesystem operation can therefore retain the active turn indefinitely. The parent also still synchronously reads `app.json` through `designPath`; a FIFO there blocks the event loop.

   **Fix:** cover acquisition, validation and reading with one deadline; settle the response independently of stalled cleanup while retaining a bounded reader permit. Remove the synchronous manifest read from import admission. Read in a bounded loop: one `file.read` is not guaranteed to reach EOF.

6. **should-fix — `O_NOFOLLOW` does not close the ancestor-directory race.** [scripts/tamber-isolate.mjs:77](/tmp/rv-e23-8/scripts/tamber-isolate.mjs:77)

   After containment is checked by `realpath`, an intermediate directory can be replaced with a symlink before `open`. `O_NOFOLLOW` protects only the final component, so the opened regular file can be outside the app. This requires filesystem modification; the HTTP source cannot directly select the path.

   **Fix:** anchor traversal to an opened app-directory descriptor and reject symlinks in every component. The outside-symlink test does not exercise this race.
