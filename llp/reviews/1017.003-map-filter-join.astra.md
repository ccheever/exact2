- **BLOCKER — D3: binding traps poison the runner.** A trap during tree evaluation calls `poison()`; subsequent actions fail. The checkpoint then restores only the store, not the complete previous state. This includes a newly mounted virtualized row exceeding the iteration cap. The promised recoverable, whole-commit refusal requires additional transaction work. Bake does fail, but its error currently lacks binding attribution. - **MATERIAL — D5: specify callback control-flow regions precisely.** Permit a jump to **exactly `end`**: a trailing ternary already generates that jump. Require properly nested body intervals, prohibit crossing their boundaries, and process callback completion before decoding the instruction at `end`. Nested callbacks can share the same end offset and must unwind correctly. Existing validation checks only forward, instruction-aligned targets. Evidence: [lower/expr.rs:328](/Users/ccheever/projects/exact2-wt-listmap/contract/lower/src/expr.rs:328), [plan/build.rs:763](/Users/ccheever/projects/exact2-wt-listmap/plan/build.rs:763). - **MATERIAL — D5: “leaves one value” is insufficient isolation.** Save operand-stack and locals bases; prohibit consuming caller operands or dropping callback parameters/caller locals; require exactly one additional result and balanced temporary locals. Checking final lengths alone can miss destruction and replacement of caller values. Use an explicit callback-frame stack, retaining absolute PCs and one evaluation counter. A `fn` inside a callback works with the existing local counter; recursively calling the current `eval` would reset its locals. ## Dispositions (author, r2)

1. **BLOCKER, D3 poisoning — accepted as a correction, not as new work.** Checked: a trap while the tree updates calls `poison()` (`runner/src/runner/lists.rs`), as it does for every existing binding trap. r2's D3 now says so, with the journal line, and that a trap in a derive or an action body refuses only that commit. Making tree traps recoverable is transaction work for every trap and is listed under §Refused; the cap follows the policy the other value bounds already have. The bake message is the trap and its pc, as r2 now says (no binding name). The boot test asserts `Instance(Trap(IterationLimit))`.
2. **D5 control-flow regions — accepted; already so in the implementation.** The generated `check_code` refuses a jump from inside a body past its end, a jump from outside strictly into a body, and crossed bodies; landing on `end` from outside is allowed. The VM finishes callbacks at `end` before decoding, innermost first, in a loop, so shared ends unwind. Tests: `plan/tests/format.rs` `a_callback_body_is_entered_and_left_only_at_its_ends`; nested and trailing-ternary cases run in `contract/cli/tests/it/lists.rs`.
3. **D5 isolation — accepted.** A body now runs on an operand stack of its own (the caller's is set aside in the callback frame and restored after), must leave exactly one value, and `DropLocal` below its two bound locals is `Malformed`. The explicit callback stack, absolute pcs and one step counter were already the design. Test: `a_callback_body_cannot_touch_what_its_caller_holds`.
4. **D6 scope edges — accepted; the rule was already conservative, now stated.** A shifted read landing on frame 0 sets every field (`Reads::union`), inner masks are never ORed into an outer frame, and leaving a scope restores the outer mask. Match-bound values: kept precise rather than coarse — an arm's frame holds only `bound`, and `LoadBound 0 → Field k` is the same pattern over the same comparison; a non-record or differently sized value marks every field. The incremental-equals-full test's synthetic app now has map/filter/join in a plain and a virtualized row, and the runner test covers both a plain `each` and a virtualized list.
5. **D6 refine one term — accepted; so implemented.** `changed_outside` refines only the innermost-frame term at shift 0; root inputs, outer frames, row-slot writes, opaque reads and `full` are unchanged; keys (shift 1) are not refined; `equivalent` per field keeps signed zero. Actual-change detection stays `changed_outside`, used identically in both modes. Separating D6 into its own landing: declined; it is small, general, and the consumer's test needs it; r2 says it could land alone.
6. **D3/D4 fuel and work — accepted.** The bound is now 65,536 *list steps*: a callback run or an item `join` prints. Map/filter extents are checked as each value is kept. `join` overflow is `StringTooLong`. The "under a frame" claim is removed; the 256 × 256 example is corrected to 255 × 256. r2 states that other linear operations in a body cost what they cost today, within the value bounds.
7. **D1/D2/D4 binders — accepted; implemented, with the fixtures asked for.** Substitution (`subst.rs`), derive resolution (`derives.rs`: freshened, and a callback body is a "sometimes" part), sharing (`share.rs`: not strict, bound inside), free names, the call graph (`checks.rs`), `symbols.rs`, and `reads_state` all treat arrows as binders. Tests: a prop naming a callback's parameter, recursion through a callback, a call repeated inside a callback bound inside it, an empty filtered list.
8. **MINOR, D7 and Why — accepted.** D7 now says the retained-binding path refuses `Unsupported` and ordinary dispatch is unaffected. §Why now says about 80 rows per tick and 5,000 baked strings, and the port drops the data source's `Vec<f64>`.
