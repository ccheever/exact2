VERDICT: RIGHT WITH CHANGES

1. **[BLOCKING] D4 — Non-style attributes can close the slot.** A slot holder can have `popover="auto"` without any forbidden style row, leaving its children hidden until invoked. `inert=true` and `aria-hidden=true` similarly remove interaction or accessibility. These are [props, not style rows](/tmp/rv-1139-r3/contract/lower/src/tags.rs:670), so the proposed allow-list misses them. **Fix:** constrain slot-chain tags and props as well as styles; explicitly reject visibility, interaction and accessibility suppression, with refusal tests.

2. **[BLOCKING] D2, D4, §6 — A sibling can cover the entire slot.** D2 exempts node attributes from group restrictions outside the slot chain, and §6 expressly permits sized sibling decoration. An absolutely positioned sibling can therefore cover the fill, with a recipe supplying its opaque background through an allowed `paint` row. The fill remains present and every chain check passes. Classes on unnamed nodes also escape the group checks. **Fix:** require recipe applications to target declared parts and extend the conservative content-preservation rules to owned siblings, including overlapping positioning, negative margins and stacking. Add an opaque-sibling counterexample to the gate.

3. **[BLOCKING] D4.3–5, D5, §4 — Scrub validation is weaker than compile validation, and its input format is unspecified.** Compile-time checks require a provably positive value across tuples and columns; the server rule only rejects **zero**. Negative values and unevaluable residuals are uncovered. This matters because the [current scrub fast path](/tmp/rv-1139-r3/contract/cli/src/tamber_scrub.rs:16) postpones additional checks until verification. “Rows and dependency closure” also does not specify how to preserve variant conditions, literal-zero exceptions or dependencies exposed by an unset. **Fix:** define a concrete constraint IR and one validator used before every preview batch and commit. Specify candidate dependency recomputation, source-digest invalidation and failure behavior.

4. **[BLOCKING] D5, §5 D–E — The gallery needs an entry-point, retention and ownership design.** Registering another build does not make its component set part of the server’s model: [param discovery](/tmp/rv-1139-r3/contract/cli/src/tamber_walk.rs:254) and [retention discovery](/tmp/rv-1139-r3/contract/cli/src/tamber_serve.rs:370) currently start from `app.contract`. A component used only by the gallery can therefore need params and tokens absent from the app’s retained plan. Conversely, treating the package gallery as a new app root risks changing declaring identities and writable-file ownership. **Fix:** specify separate consuming-app and gallery-entry identities, per-entry retention/maps and live-or-rebuild handling. Keep all overrides, journal and undo writes in the consuming app; keep package files read-only. Test gallery-only components, bounded exports and attempted package writes.

5. **[BLOCKING] D1 — Terminal range conversion contradicts stage 11 as built.** The draft converts a terminal cell to 16 px for a vertical row. The scale actually emits [`n ch`](/tmp/rv-1139-r3/kernel/src/style/scale.rs:62), which means 8 px per unit on either axis. Spacing then undergoes [axis-specific rounding](/tmp/rv-1139-r3/kernel/src/style/cells.rs:31): terminal `space.md` is 8 px, and vertical padding resolves to **zero rows**, not 16 px. A param also has no inherent axis and may serve several rows or native bindings. **Fix:** keep D15 ranges in the token’s actual px value; evaluate any layout-space constraint separately at each use through the kernel’s conversion and rounding rules.

6. **[BLOCKING] D8 — Renames do not reliably fail the build.** An app’s old `cards.pad = 12px` remains a valid app token after the package renames its token; it can simply become unused. Unknown param overrides are explicitly [warnings in LLP 1121’s as-built specification](/tmp/rv-1139-r3/llp/1121-tamber.rfc.md:3338), implemented by [`params::unknown`](/tmp/rv-1139-r3/contract/lower/src/params.rs:495). Thus the claimed `tamber-unknown-token` protection does not exist for either important stale-override case. **Fix:** either introduce an explicit, approved stale-library-override validation rule, or replace the build-failure promise with a mandatory rename audit covering every consumer. Test token, param and declaring-file renames.

7. **[BLOCKING] D2, D6 — Native-first is not enforced by the listed predicates.** A library can implement `view role="switch" ...` with paint/shape parts and a hand-drawn thumb. No `control` group is present to reject, and the compiler’s [control classification](/tmp/rv-1139-r3/contract/lower/src/controls.rs:54) primarily recognizes control tags/types. The listed anatomy checks therefore do not establish D9’s prohibition on look-alike controls. **Fix:** define enforcement over semantic control roles and every conditional alternative, require their admitted native implementation, and explicitly delimit the authored-button exception. Add a custom-switch refusal test.

8. **[SHOULD-FIX] D3, §5 C — “Same-file styles” is not today’s complete class model.** Contract supports importing and re-exporting styles; an [existing test imports `Muted` and applies it through `class`](/tmp/rv-1139-r3/contract/cli/tests/it/use.rs:379). A file-local ownership scan would miss another component applying an imported alias of a param-bearing style. Also, [param-use checking currently walks component views](/tmp/rv-1139-r3/contract/lower/src/params/rewrite.rs:615), so style-only reads need explicit integration. **Fix:** describe recipe locality as a new library restriction, preserve ordinary style imports, and determine ownership by resolved declaration identity across the source graph. Add positive style-only retention tests and negative imported/re-exported second-owner tests.

9. **[SHOULD-FIX] D2–D4, §5 — Define where anatomy checks run in composition.** The rules discuss authored attributes/classes, but the gate rejects any forbidden row carried by a chain node. The example’s `column` nodes themselves acquire [`display:flex` and `flex-direction:column`](/tmp/rv-1139-r3/contract/lower/src/tags.rs:70). Conditional classes also [supply `none` where one branch omits a row](/tmp/rv-1139-r3/contract/lower/src/class.rs:61). The draft does not settle treatment of those generated values. **Fix:** specify check order relative to import resolution, shorthand expansion, class merging, state lowering and slot inlining; distinguish authored rows from admitted tag defaults; define omitted-branch behavior. Keep caller-owned fill outside library ownership checks.

10. **[SHOULD-FIX] D1 — The literal prohibition has spelling-dependent holes.** Its colour list names `border-color` but omits `border-top-color` and the other longhands, although D2 expressly admits them. The treatment of compound shorthands and literal leaves inside conditional values is also unstated. **Fix:** define the restricted canonical row set and inspect every reachable value leaf after shorthand expansion, including state rows. Test equivalent shorthand/longhand spellings and conditional literals.

11. **[SHOULD-FIX] D1, D5, §4 — A single “winning level” lacks defined semantics.** For `param.pad → cards.pad → space.md`, the package supplies the alias while the app may supply the base value. An expression can have several differently owned inputs. The proposed `{level, name}` does not say which ownership it reports or identify the winning `when` branch required by [LLP 1122 D6](/tmp/rv-1139-r3/llp/1122-design-tool.rfc.md:426). **Fix:** distinguish the selected definition and branch from its dependency provenance; specify the serialized fields and reset target. Include mixed-source expressions and mode-specific overrides in protocol fixtures.

12. **[SHOULD-FIX] D5–D6, §5 — Several gates can pass without proving their claim.** Unlimited rectangles, each covering at most 10%, can collectively mask an entire component. “Per-platform variants of one component” has no mechanical predicate. Gallery membership is undefined for helpers and `Gallery` itself, and components with no variant props have no stated cell rule. Finally, unconditional gallery “live” delivery conflicts with closure-based rebuild classification. **Fix:** cap the **union** of excluded pixels per component; distinguish the enumerated platform-read checks from human review; define the gallery component set and one baseline cell for zero-variant components; require live delivery only for edits classified live, with explicit rebuild cases.
