# Review round 3, LLP 1121 stage 8 E2 (Apple) + E3 (Linux/Android) held states, Astra (gpt-6-astra, max)

**RIGHT WITH CHANGES**

1. **BLOCKING — Native holds are not scoped to their stream.** [Inspect.swift:176](/tmp/rv-s8e23-r3/host/apple/Sources/ExactKit/Inspect.swift:176) sends old hold callbacks through the current connection; [build_channel.rs:330](/tmp/rv-s8e23-r3/host/linux/src/build_channel.rs:330) similarly retries queued reports with the new nonce. Both hosts retain ended revisions across reconnects unless a lower revision arrives. A restarted server can reuse a revision: an old release can then clear its new hold, or an old ended entry can suppress it. **Fix:** mirror E1’s stream/epoch guards, clear ended revisions on a new stream, and discard old hold reports. Test reconnects with equal revision numbers and delayed releases.

2. **BLOCKING — Mac table-row clicks bypass hold release.** [ExactViewMac.swift:281](/tmp/rv-s8e23-r3/host/apple/Sources/ExactKit/Mac/ExactViewMac.swift:281) uses ordinary hit testing, but `TableRowCell.hitTest` deliberately returns the table for pressable rows. The hook therefore misses the held row, and `pressRow` invokes its action without releasing the hold. [HoverMac.swift:29](/tmp/rv-s8e23-r3/host/apple/Sources/ExactKit/Mac/HoverMac.swift:29) has the same mismatch: it initializes `over` to false, so subsequent movement within the row incorrectly releases held hover. **Fix:** use the existing `TableRowCell.whatIsThere` hit-test path in both places. Test actual table clicks and movement within a held row.

3. **BLOCKING — Android’s native text fields bypass the input hooks.** [hosted.rs:487](/tmp/rv-s8e23-r3/host/linux/src/presenter/hosted.rs:487) receives native field edits directly; these never traverse the new `typing.rs` hook. Field touches likewise go to `EditText` without traversing `pointer_pressed_with`. Focus a field, hold its `focus-visible`, then type or tap within it: focus remains unchanged and the hold survives. **Fix:** connect hosted field touch-down, edit/composition and key/action entry points to `hold_input`, after validating the field generation. Test through the hosted-field APIs.

4. **SHOULD-FIX — iOS textarea backspace still leaves a hold active.** [TextAreaIOS.swift:180](/tmp/rv-s8e23-r3/host/apple/Sources/ExactKit/IOS/TextAreaIOS.swift:180) calls only `supersedePress` and `nativeEdit`; neither releases held state. Unlike insertion and composition, software-keyboard deletion never calls `heldKey`. **Fix:** call `heldKey(at: owner)` before deletion, including deletion that changes no text. Test `TextArea.deleteBackward()` while the focused textarea has a hold.

5. **SHOULD-FIX — iOS agent taps release against the requested ID before resolving the actual tap.** [AgentIOS.swift:541](/tmp/rv-s8e23-r3/host/apple/Sources/ExactKit/IOS/AgentIOS.swift:541) misses a held child when `tap parent at […]` lands on that child. The later one-shot delivery has no hold hook. Conversely, a tap subsequently rejected as obscured or offscreen has already released the hold. **Fix:** release against the validated final hit immediately before input delivery, covering early host-activation paths. Assert successful delivery and action execution in tests; [HeldStateTests.swift:426](/tmp/rv-s8e23-r3/host/apple/Tests/ExactKitTests/HeldStateTests.swift:426) currently discards the tap reply and can pass on a rejected tap.

6. **SHOULD-FIX — Linux’s native pressed appearance disappears during an unrelated contact.** [feedback.rs:57](/tmp/rv-s8e23-r3/host/linux/src/presenter/feedback.rs:57) chooses `contact.or(held)`. Hold ordinary button A active, then press sibling B: A loses its native pressed appearance even though its hold remains live. Applying A’s hold while B is already down has the same problem. **Fix:** represent physical and held feedback separately and compose them per painted node. Test both orderings with buttons that have press handlers and no authored D7 rows.
