**RIGHT WITH CHANGES.** Round 1 is fixed. The path-rule unit tests pass (`bun test scripts/tamber-paths.test.mjs`, 2/2). The cargo remote suite was not run.

Round 1's three blockers are gone. A subscribe or long poll while the design server is down scrubs `down` for a non-local client (`scripts/tamber-server.mjs:550` and `:599`); the SSE `down` event goes through `forRemote`. Whole-reply replacement and the Rust backstop are gone: `scrubbedMessages` rewrites only a `message` inside an `error` or a `down` event, longest match first, at a whole-path boundary (`scripts/tamber-paths.mjs:50-72`). Linked-package `file` fields go through one rule in `tamber_uses::shown` (`contract/cli/src/tamber_uses.rs:558`) and `pathName`, including a package outside the app and the home directory. Local `hello.app` stays the absolute directory (`scripts/tamber-server.mjs:740`). Outline names both the client's location and the map node with `pathName` before comparing (`scripts/tamber-server.mjs:816-817`). A client-sent `file` is accepted only when it equals a snapshot key of the app's own `.contract` (`contract/cli/src/tamber_contract.rs:531`, `:779`); `../`, a package path, and anything else are refused and no file outside the app is read back. Pair-code doors are `{origin, fingerprint}` or `{origin, tunnel: true}` (`scripts/tamber-remote.mjs:332`).

1. **SHOULD-FIX** — A compile failure of a file outside the app and the home directory still sends that absolute path to a non-local client. `resolve` puts `path.display()` in the refusal (`contract/cli/src/resolve.rs:157`, `:283-302`, `:366`). `sources.rs:756` copies that string into `CompileError.message`, and `sources.rs:793` does the same for an unreadable `use` target. `uses` and `explain` return it as `the app does not build: …` (`contract/cli/src/tamber_serve.rs:845`, `:850`, `:866`; `contract/cli/src/tamber_explain.rs:263`, `:268`), and a transaction's diagnostics send `e.message` raw (`contract/cli/src/tamber_contract.rs:703`). `messageScrubber` only rewrites the app directory and the home directory, so a linked package under `/var/folders/…` (the case the remote test constructs) is left intact. `llp/1121-tamber.rfc.md:4646-4647` says no message names such a directory; these do. **Fix:** name that path with `shown` (or leave it out; the diagnostic `file` field already goes through `shown`) everywhere a refusal string is built from `path.display()`. Add a remote assertion that an unreadable `@acme/linked` contract outside the home directory produces a `uses`/`explain` error containing neither that directory nor the home directory, and correct the RFC sentence.

2. **NIT** — The subscribe snapshot is sent raw (`scripts/tamber-server.mjs:551`): no `namedPaths`, no `forRemote`. A long poll scrubs messages but takes `proposals: held()` from the pre-`namedPaths` copy (`:592`, `:939`). Events stored by `send` are already named, and a proposal that was planned only carries snapshot-relative `file` strings, so this does not leak on the paths covered above. **Fix:** run `namedPaths` on that snapshot, and `forRemote` on the subscribe frame, the same way `send` does.

3. **NIT** — `export`'s `baseline` uses `strip_prefix(&self.dir).unwrap_or(&kept)` (`contract/cli/src/tamber_serve.rs:784`). The key is not `file` and the value sits in `ok`, so neither namer nor scrubber sees it. `keep` writes under the canonical app directory, so the prefix matches in the normal case. **Fix:** name it with `shown` and drop the `unwrap_or`.
