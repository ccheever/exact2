# Quick review: Swift packages in the arm cache (1ed590a38d), Grok

**RIGHT WITH CHANGES**

The module-arm key matches what `placePackages` compiles. It hashes the build triple, the SDK name and path, `swiftc --version`, the module name (the `.o` filename), the package Swift text, and the composed adapter (`composed` is in `moduleSources`). `packageDir` is initialized at `host/apple/build.mjs:993`, before `arm`. `placePackages` is reached only from a cache miss whose arguments contain that directory. The web, video, sound, and MIDI arms do not, and the module and probe calls sit after its definition at `1094`, so there is no temporal dead zone. `.replace(packageDir, '<packages>')` rewrites this build's temp directory only. The simulator probe, the route that records the roster, repeats that same simulator triple and SDK. `placed` is set on one thread before any `await`.

1. **BLOCKING** — `host/apple/build.mjs:998` and `:1099`. Packages are compiled for the build target, and only on a miss. The objects are `…-ios…-simulator` (`1099`; `iphoneos` on `--device`). That link fails, and a failed arm is not published (`1002–1006`), so the next warm build misses again and calls `placePackages` again. The commit message's "arm's own target" and "the package compile no longer runs" describe a compiler other than `:1099`. The same miss repeats for tvOS, whose only route is the macOS probe (`1111`, `1116`) while objects are built for tvOS.
