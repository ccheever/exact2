## Should-fix

**Cookie survives on the request the wire receives — `scripts/tamber-remote.mjs:99`**

`delete req.headers.cookie` clears only the parsed map. On Bun 1.4.2 the same request still has the tossed cookie in both other views: `req.rawHeaders` contained `x-exact-tamber-token=abc`, and `req.headersDistinct.cookie` was `['x-exact-tamber-token=abc']`, while `req.headers.cookie` was absent. `tamberServer`’s handle reads `req.headers` only, so a canvas on the same host and another port cannot present that cookie as the token today. The next reader that scans `rawHeaders` or `headersDistinct` (pairing is the obvious one) will see it. The test at `scripts/tamber-remote.test.mjs:79` only asserts `req.headers.cookie`.

Strip every `Cookie` pair out of `req.rawHeaders` first, then `delete req.headers.cookie` and `delete req.headersDistinct?.cookie`. Assert all three are empty in the test.

**`headersTimeout` and `requestTimeout` are not enforced on Bun 1.4.2 — `scripts/tamber-remote.mjs:119`**

The properties stick (`headersTimeout` reads back as set; the default socket `timeout` is `0`), and `maxConnections` is real: a second connection with `maxConnections = 1` got `ECONNRESET`. The two timers are not. A client that paused 1s mid-headers with `headersTimeout` 400 still received `200`. A body withheld for 1s with `requestTimeout` 400 still received `got:5`. A handler that waited 1.5s after a finished request also completed, so these timers do not cut `/__tamber/events` (25s long poll) or the `/__tamber/subscribe` stream. They also do not reap a slow client. Sixty-four half-open connections fill the cap and hold the port.

Arm a socket timeout on `connection`, and clear it on the request’s `end` (headers and body are in, the long poll and the event stream may stay up):

```js
server.on('connection', (socket) => {
  socket.setTimeout(10_000, () => socket.destroy());
});
// inside the handler, once the body has arrived:
req.on('end', () => req.socket?.setTimeout(0));
```

**About 1 in 256 certificate builds throw, and the dev loop exits — `scripts/tamber-remote.mjs:41`**

`serial[0] &= 0x7f` keeps the integer non-negative, and `int()` then leaves a leading `0x00` in place. When the next byte is also below `0x80`, that is non-minimal DER. `new X509Certificate(cert)` throws `OPENSSL_internal:INVALID_INTEGER` (forced vector `00 11 …` throws; `00 81 …` and `01 …` parse). `openRemote` does not catch it, so `host/web/dev.mjs:1495`, `host/web-js/dev.mjs:1029`, and `scripts/tamber-server.mjs:1057` take the bind-failure path and the process exits. An all-zero serial throws the same way.

Regenerate while `serial[0] === 0`, and make `int()` drop leading zeros that are not a sign pad. Add a test that builds a few hundred certificates.

**An IPv6 bind is admitted and logged, and it is missing from the certificate — `scripts/tamber-remote.mjs:39` and `:145`**

`isIP(n) !== 4` becomes `null`, so the SAN keeps only `localhost` and `127.0.0.1`. `remoteNames('::1')` still contains `::1`, and `admits` uses that list, so `Host: [::1]:port` is served (`peer` `::1`, `local: false`). The line printed for humans is `https://::1:65369` (no brackets). `info().origin` is the valid `https://[::1]:65369`. A client that checks the name against the URL will reject the cert; the fingerprint still matches the cert that was sent.

Encode IPv6 as a 16-byte `iPAddress` (`0x87`). Bracket every colon-bearing name in the `say()` line the same way `origin` is built.

**A mixed-case DNS name never matches the Host header — `scripts/tamber-remote.mjs:64`, `:100`, and `:139`**

`remoteArgs` keeps the argv spelling (`i` on the regexp). The handler lowercases `Host`, then `admits` does a case-sensitive `names.includes`. `--remote MyBox.local:7443` puts `MyBox.local` in the certificate and the allowlist; a browser sends `mybox.local` and gets 404. `localhost` still works because it is inserted in lowercase.

Lowercase the host in `remoteArgs` and compare lowercased names.

**Failure exits skip the cleanup the signal path does**

- No design: `host/web/dev.mjs:1494` and `host/web-js/dev.mjs:1028` call `stop()`, and both `stop()` implementations end in `process.exit(0)` (`host/web/dev.mjs:988`, `host/web-js/dev.mjs:1018`). The refusal is a successful exit. On the wasm loop the banner has already been printed and the HTTP server is accepting.
- Port taken: those two catches and `scripts/tamber-server.mjs:1057` call `process.exit(1)` without `tamber.close()`. The design child is `detached`, so it drops `.exact/tamber.lock` only after it sees stdin EOF, and this path does not wait. `serveAlone` also skips the `listen()` stop handler that would have closed both servers.

Exit `2` for a missing design after closing the listeners. On `EADDRINUSE`, `await tamber.close()` and close the HTTP server, then exit `1`. `tamber serve` already returns `1` when the app has no design, before it listens.

## Nit

The wire handler rejects a request-target that does not start with `/`. The canvas port parses `GET http://other/path` with `new URL` and hands that URL to `handler`. Nothing calls `addPort` yet. Reject non-origin-form targets there too.

## What held

The fingerprint is SHA-256 of that DER (same bytes as `openssl dgst -sha256`), printed in Node’s colon-separated form. `minVersion: 'TLSv1.2'` rejects TLS 1.0 and 1.1. The private key stays in the closure; the log line is the fingerprint only.
