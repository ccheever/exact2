# Round 1 (Grok 4.7, xhigh, on r1 c166d914d)

**Verdict: NEEDS REWORK**

---

### (1) LLP 1099, Zoom, press, CA commit

1099’s springs are engine-sampled on Apple (`llp/1099-uikit-springs.rfc.md:615`). There is no `CASpringAnimation`. Zoom (`navigationSource`) and `PressFeedback` are UIKit/CA and are not engine curves. Those three are not shifted twice.

The collision is the lowered CSS executor, which **is** an engine curve **and** a CA animation committed at the batch:

- iOS box keyframes (`translate` / `scale` / `rotate` / `background-color`) — `host/apple/src/svg.rs:39-51`, LLP 1055.001
- SVG tracks on iOS and macOS — `host/apple/src/svg_lower.rs:249-253`, `SvgScene.swift:197` (`beginTime = t0 + start + delay`)

`present()` emits those specs in the commit batch (`presence.rs:379`). `CssAnimations.apply` adds them immediately (`SvgScene.swift:106-107`). Core Animation’s transaction commits at the end of that run-loop turn.

D4 then waits for `Host::tick` to re-emit a shifted spec (`llp/1003.001-motion-starts-at-the-first-frame.rfc.md:113-124`). That tick is later, and often a main-queue hop later (`Session.swift:447`, `593-596`; `Frames.swift:68-73`). The first vsync can already show the unshifted `beginTime`. Replacing the animation then jumps CA back toward 0. Engine `start` and CA local time diverge.

1099’s future CA mapping (`llp/1099-uikit-springs.rfc.md:615`, “permitted, not built”) is the same trap.

---

### (2) D6 — right for one case, not complete

D6 is right for a **same-key** LLP 1003 restart: the user never saw the pending curve, so the replacement must start from `from` at rest (`engine.rs:453-501` samples at `self.now` today).

It is incomplete for the rest of Q2.

**`Engine::advance` still walks pending curves.** `commit_tree` seeks to each receipt, then to `now_ms` (`host.rs:1263-1299`). `end_hold` seeks first (`hold.rs:346`). A second commit on **another** key, or a release on another property, samples the pending curve at wall time, `present()` emits that mid-curve value (`host.rs:1331`), and the later `start_pending` puts `start` back at the frame. First vsync can show a flash, then 0.

**Play records cannot express D6.** D1 keys plays as `(node, start)` (`rfc.md:79-81`). D6 wants a matched pending play to keep its record and a new play on the same node to be independent. One `(node, start)` slot cannot hold both. `set_animations` matching is by name (`animate.rs:93-128`); the pending table must follow that, plus row index.

**Lowered spec emitted twice before a frame.** First commit writes `s: play.start` and CA starts. A second commit that **matches** leaves `box_sent` equal, so nothing is re-emitted (`svg.rs:247-254`). A second commit that **drops or replaces** emits a new spec, still at commit time. Tick’s third spec is the first one that could carry the shift, and it can arrive after a vsync. D6 does not say “do not hand CA a spec until `start_pending`”, which is the rule that actually works.

**1099 additive retargets.** Two UIKit-spelling springs in the same gap are two components with two begins (`llp/1099-uikit-springs.rfc.md:405-408`). D6’s “sample at begin, start a new curve from `from`” is the restart form. Under 1099 both components should start at the first frame.

---

### (3) Progress 0 at the first presented frame

For the measured lightbox open, p = 0 at the first presented frame is the right default. “One interval since the commit” puts commit duration and phase back into the first sample, which is the bug in §1 (`rfc.md:12-34`, `51-69`).

It is **not** the same for every curve kind:

| Kind | First presented sample after this RFC |
|---|---|
| Easing / spring transition, delay ≥ 0 | `from` (true p = 0). Delay is kept (`transition.rs:306`, `331-337`). |
| Negative delay | Already into the curve at observe `now`. D6’s “`from` at rest” is false (`transition.rs:334` vs `306`). |
| Flight | First-seen 0, then 0→1000 (`flights.rs:98-106`). First frame progress 0. Right. |
| New play / exit | Local 0. Right **if** the spec is not already running on CA. |
| Clock-joined new timeline | `join_clocks` pins origin at commit `now` (`clock.rs:113-115`, `145`). D3 forbids shifting. First frame is already into the phase. |
| Drag-bound play | Held to the source (`timeline.rs:158-173`). Correctly unshifted. |
| Release / authored velocity | Spring at t = 0 is still `from` (`transition.rs:371-384`). One still frame after lift, then the fling. |

Reanimated’s lightbox sets the value **inside** rAF, so that frame **is** t = 0. A gesture release is not that path. One rule that includes `end_hold` (`rfc.md:77-78`, `hold.rs:363-364`) makes a flung photo sit for a frame.

CA-like “first frame = one interval” is the wrong default for opens. Velocity-carrying starts should keep the release instant (or the last presented frame) as t = 0, so the first displayed sample already includes `v·Δt`.

### (4) Everything else

**Holds / releases.** `end_hold` must not call `advance` through other pending curves (`hold.rs:346`). Releases should be exempt from the still first frame, or the first tick should sample elapsed `now − release`.

**Settle / display link.** `quiescent()` is `running` ∪ `animating` (`engine.rs:657-659`). Lowered plays are not in `animating` (`animate.rs:156-166`, LLP 1055.001:72-74). A commit that only starts box/SVG keyframes leaves `batch.motion` false (`Session.swift:1016`, `Frames.swift:68`). `start_pending` never runs. D4’s re-emission has no tick. Pending records must keep the link awake, **or** specs must wait until the curve is started.

**Layout-transition first-seen.** Unchanged and correct: first observe takes the box (`engine.rs:419-422`, `layout.rs:167-174`); `seed_layout` makes a gained row animate its next move (`presence.rs:164-172`). That animation is an engine `Running` and does get the shift.

**LLP 1073 frame tasks.** `Host::frame` then `Host::tick` in one display-link callback (`Frames.swift:62-73`) is the “shift is zero” case, **if** both use the same instant. They do not: frame tasks use `targetTimestamp` (`Frames.swift:48`, `llp/1073-every-frame.rfc.md:56-57`); motion tick uses `s.now()` = wall (`Session.swift:575`, `86-87`). `start_pending` must use the same effective now `Host::tick` already maxes (`host.rs:1108`).

**Timers.** A timer fired **inside** that callback, then `tick`, can still present mid-curve in the advance batch and p = 0 in the tick batch (`host.rs:1263-1299` then `1107-1110`). Same run loop, last write wins for model values. A timer **outside** the link is the between-frames path and hits the D6 `advance` hole.

**Agent.** Flag default-off is right for fixtures. D5 turns it off at `presentFrames(false)` (`Agent.swift:604`). Takeover is earlier (`Agent.swift:482-488`) and `clock take` / `clock land` never reach `advanceStepped`. `Host::tick` is also the agent’s seek tick (`Agent.swift:530`). The flag is the only gate; it has to go off at takeover, not only at `presentFrames(false)`.

**macOS.** Same `Session`, same rule (`rfc.md:136`). macOS **samples** box transforms (1055.001:32) and **lowers** SVG. Press is `PressClock`, not the engine (`PressFeedback.swift:314-344`). The CA race is SVG-only there. `PressFeedback.unseen` (`PressFeedback.swift:35-36`) is the same “never presented” test D6 wants.

**Signal clone.** Onset-aligned traces will move by under a frame **for engine-sampled curves**. Lowered CA that already started at commit will not match those traces until emission is deferred.

**Determinism.** With the flag off, the engine is still a seek. With it on, samples are a function of `(begin, first frame time)` and stay closed-form. Do not read `CACurrentMediaTime` in the engine. Host tests that boot `Session` with `clock == nil` **will** change; D5’s “every existing host test keeps today’s timing” is only true for tests that never turn the flag on.

**Q4 (per-node shift).** Flight nodes are dedicated (`flights.rs:91-117`). Shifting `lands_at` by that node’s Δ is fine; recomputing from the Layout curve’s start is safer. Exits share the motion node with other plays (`presence.rs:134-142`, `animate.rs:269-276`). `Vec<(u64, f64)>` cannot name two begins on one node. After `start_pending`, re-read `start + end_time` (and flight `lands_at`) from the engine.

## Findings

### 1. [P1] Defer lowered CA specs until the curve is started — `llp/1003.001-motion-starts-at-the-first-frame.rfc.md:113`

D4 commits a spec at the tap (`presence.rs:379`, `svg_lower.rs:253`, `SvgScene.swift:197`) and hopes a later tick replaces it before vsync. On the input path, and on the async tick path (`Session.swift:593-596`), CA has already started. Engine sample and CA local time then disagree. Hold the layer at the underlying value (or `speed = 0`, `timeOffset = 0`, which `SvgScene.swift:178-195` already implements) until `start_pending`, then emit once with the shifted `start`.

### 2. [P1] Pending curves must not move until started — `motion/src/engine.rs:533`

D6 only covers same-key retarget. `Engine::advance` (`engine.rs:536-551`), `commit_tree` (`host.rs:1263-1299`), and `end_hold` (`hold.rs:346`) sample pending curves at wall `now`. A second commit in the gap presents mid-curve (`host.rs:1331`); `start_pending` then snaps back to 0. Invariant: while a record exists, `sample` / interrupt / `frame` use the begin instant (`from`, at rest for delay ≥ 0).

### 3. [P1] Lowered-only commits never see `start_pending` — `motion/src/engine.rs:657`

Lowered plays do not occupy `animating` (`animate.rs:156-166`). `quiescent()` is then true, `frames.motion` stays false (`Session.swift:1016`), the display link does not run (`Frames.swift:68`). D4’s re-emit has no tick. Pending records must keep the link (or finding 1 makes the tick unnecessary because the first display-driven `tick`/`frame` is scheduled another way).

### 4. [P1] Do not still-frame a release — `llp/1003.001-motion-starts-at-the-first-frame.rfc.md:41`

`end_hold` starts a spring with release velocity (`hold.rs:363-364`). Shifting t = 0 to the next vsync shows `from` with v unused (`transition.rs:371-384`). Lightbox open wants p = 0; a fling wants the first displayed sample to include `v·Δt`. Split the rule: author-triggered curves start at the first presented frame; velocity-carrying starts keep the release (or last presented frame) as t = 0.

### 5. [P2] Play pending keys are too coarse; exit ends cannot be per-node — `llp/1003.001-motion-starts-at-the-first-frame.rfc.md:79`

Running keys `(node, property)` are right. Plays keyed `(node, start)` cannot implement D6’s matched-vs-new split (`animate.rs:93-128`). `start_pending`’s `Vec<(u64, f64)>` cannot move an exit’s end (`presence.rs:142`) when that node also has an older pending transition. Key plays like `set_animations` does; after the shift, re-read play/exit ends and flight `lands_at` from the engine.

### 6. [P2] 1099 additive retargets vs D6 — `llp/1003.001-motion-starts-at-the-first-frame.rfc.md:138`

When 1099’s component list exists, two springs in the gap are two begins (`llp/1099-uikit-springs.rfc.md:405-408`). D6 restart-from-`from` drops the first component. Both begins shift to the first frame; D6’s restart wording applies only to LLP 1003 restart forms.

### 7. [P2] Idle clock-timeline origin stays at commit — `motion/src/engine/clock.rs:113`

D3 correctly refuses to shift a join onto a **busy** clock. A new timeline sets `origin = now` at commit (`clock.rs:113-115`) and then D3 leaves it there. First presented frame is already into the cycle. Shift the origin (and those first members) when the clock was idle.

### 8. [P2] Pin the frame instant; turn the flag off at takeover — `host/apple/Sources/ExactKit/Frames.swift:48`

LLP 1073’s frame time is `targetTimestamp` (`Frames.swift:48`). Motion tick uses wall (`Frames.swift:72`, `Session.swift:575`). `start_pending` must use the same maxed now as `Host::tick` (`host.rs:1108`). D5 must clear the flag at clock takeover (`Agent.swift:482-488`), not only at `presentFrames(false)` (`Agent.swift:604`), because `Host::tick` is also the agent seek (`Agent.swift:530`).

### 9. [P3] D6’s “`from` at rest” is only for delay ≥ 0 — `motion/src/transition.rs:306`

Negative delay sets `start < begin`. Sample at begin is already into the curve (`transition.rs:341-348`). State that, and keep the skip into the curve when shifting.

---

## Answers to the RFC’s questions

- **Q1.** Zoom, press, and 1099’s **current** Apple path are not double-shifted. Lowered CSS (and any future `CASpringAnimation` executor) **can** start twice and lose sync unless specs wait until `start_pending`.
- **Q2.** D6 is right for same-key restart retargets and for dropped vs matched plays in the abstract. It is not complete: pending + `advance`, play keying, CA emission, 1099 components.
- **Q3.** p = 0 at the first presented frame is the right default for the measured open/close. It is the wrong first sample for velocity-carrying releases. Do not claim one rule for every curve kind.
- **Q4.** Re-read shifted ends from the engine. Per-node Δ is enough for a flight node; it is not enough for exits.

**Tests to add** (beyond §5): second commit on another key in the gap; lowered-only play with `motion == false`; CA spec identity across two commits then one tick; `end_hold` with a pending fade on the same node; idle `clock()` join; `clock take` with a pending curve; frame task at `targetTimestamp` vs tick wall; Signal/Bluesky recordings that include a lowered box animation, not only the flight.
