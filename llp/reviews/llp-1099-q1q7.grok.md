**Q1 — RFC recommendation.** Confidence 86.

The 100 misses among the 9,474 measured calls are two different failures. 73 are real roots of the other basin, already inside the `|g| ≤ 0.1ε` gate, with curve error up to 1.85 of the move (0.06 on Signal’s reply icon). 27 fail the root test: four `(ζ, u)` pairs, repeated across durations. The fallback runs only on those 27, so the large errors still ship.

“Nearest real root” is also the wrong substitute on the 27. For `u > 0` the settle equation has up to three positive roots, split by the kink at `W = u/ζ′` where `B = 0`. When the twelve steps diverge, the iterate is enormous (`ζ = 0.2`, `u = 0.5` → `W ≈ 2.86×10¹⁶`). The roots are about 2.48, 2.52 and 26.1; UIKit took 2.48; both absolute and log distance take 26.1, and the curve is 1.43 of the move off. The same thing happens at `ζ = 0.8`, `u = 3.2`. On the sweep, log-nearest matched UIKit’s `W` on none of the 27. Adjacent samples already flip which root UIKit returns, and on 24 of the 54 distinct miss pairs UIKit’s own `W` fails the root gate: its answer is an unconverged iterate, so a cleaned-up root moves away from it.

A hold release never enters this solver under D5, and D6 already keeps a gesture from being refused. The fling only hits the band if a dynamic duration string carries it, or if Q7 re-solves. A dynamic string in the band claims a UIKit match at a point where twelve steps from 5 is not a reproducible function, and the kernel has no warning channel. A silent wrong-basin curve is the worse failure.

Rule: keep D2 and §4.3. Accept the twelve-step result only when it is finite, in `(0, 10⁴]`, and `|g| ≤ 0.1ε`. Inside `u > 0` and `0.6 ≤ u/ζ′ ≤ 8`, rewrite an accepted literal to the resolved `end spring(k, c, 1, velocity v)` and refuse a dynamic string. Do not substitute another root.

**Q7 — RFC recommendation.** Confidence 82.

A duration spring already completes at the authored `d`. Injecting the release velocity changes the path and the snap at `d`. The completion time moves only for the bounce form, whose end depends on velocity and which this alternative leaves alone.

Re-solving does not make dismisses match frame for frame. For `spring(400ms, 0.8)` the band is a normalized velocity of about 1.2–16 per second, a normal flick. There the solve is the same chaotic map as Q1, so with that fallback the curve can still be about a move off UIKit.

The velocity the engine has is a per-axis derivative in property units. UIKit’s scalar is `v/Δ`, which is undefined at `Δ = 0`, and D5 is required to start a component there. Rows X do not re-solve per axis either: `(1, 5)` and `(5, 1)` share the `v = 1` stiffness and store each axis’s own `initialVelocity`. A per-axis `uᵢ = vᵢ d / Δᵢ` would put a different `k` on each axis and a discontinuity at `Δ = 0`. The duration form clamps `ζ` to 1, so this re-solve never meets the overdamped quirk. Extending it to bounce would: that branch’s derivative is `v + 2ζω`, and it cannot carry an arbitrary release at zero distance. D5’s textbook branch is what makes the release velocity the derivative on screen.

A port that wants UIKit’s per-call re-solve passes one scalar as the duration form’s velocity on a new transition. That string is under Q1: reproduced outside the band, refused inside it.

Rule: on release, keep the authored `k`, `c` and end. The new component’s actual initial derivative is the release velocity, per axis, in property units, including at zero distance. Do not form `u` from `Δ`. Bounce coefficients and the textbook branch stay as D5.
