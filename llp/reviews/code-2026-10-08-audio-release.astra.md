- **Blocker — deactivating live players can stop the video.** [AudioSession.swift:47](/private/tmp/bsky4-rv/wt-au/host/apple/Sources/ExactKit/AudioSession.swift:47), [VideoModule.swift:259](/private/tmp/bsky4-rv/wt-au/host/apple/Sources/ExactKit/VideoModule.swift:259). On re-mute, release runs **before** `module.update` applies the mute; invalidation similarly releases before destroying the player. Apple documents that deactivation with running audio objects stops them and deactivates the session even when it reports `isBusy`. The comment’s fallback assumption is false. Since neither `paused` nor `src` changed, the arm need not restart playback. Fix: coordinate deactivation with the arm’s I/O lifecycle and preserve intended muted playback; merely swallowing the error or moving release after the mute is insufficient. Add a test asserting that playback time keeps advancing after re-mute. [Apple’s API contract](https://developer.apple.com/documentation/avfaudio/avaudiosession/setactive%28_%3Aoptions%3A%29).

- **Blocker — a surviving Now Playing claim loses its required category.** [VideoModule.swift:259](/private/tmp/bsky4-rv/wt-au/host/apple/Sources/ExactKit/VideoModule.swift:259). Play a podcast with metadata, then mute it or clear its source while keeping the element mounted—for example, between episodes. `NowPlaying` retains ownership and remote commands, but this predicate releases the last holder and switches to `.ambient`. A mixable category is ineligible for Now Playing; declaring background audio does not fix that. Count Now Playing ownership as an independent playback requirement and release it when ownership ends. A paused, **unmuted player with a source** already retains its hold correctly. [Apple’s eligibility requirements](https://developer.apple.com/videos/play/wwdc2022/110338/).

- **Should-fix — failed acquisition still commits ownership.** [AudioSession.swift:33](/private/tmp/bsky4-rv/wt-au/host/apple/Sources/ExactKit/AudioSession.swift:33), [VideoModule.swift:140](/private/tmp/bsky4-rv/wt-au/host/apple/Sources/ExactKit/VideoModule.swift:140). If canvas activation throws, its permanent token remains despite activation failing. Remove that canvas, later play and re-mute a video: the stale token prevents fallback forever. Video acquisition also marks `holdsSession` before success, suppressing retries. Commit new tokens and the local flag only after success, or roll them back on failure; keep failed attempts retryable.

The ordinary accounting balances deinit, repeated invalidation, source removal and rapid authored mute changes. Fullscreen shares the player and holder. Current production callers serialize these changes on main; agent mode skips acquisition, and `.ambient` is available on tvOS. Existing interruption/route-resume limitations are unchanged.
