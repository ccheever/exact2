## Findings

1. **HIGH —** `host/apple/macos/Sources/ExactMac/Presenter.swift:287`. After mapping through each placed child’s inverse, `hitTest` always `return super.hitTest(point)`. `super` hit-tests the overlay’s subviews by their kernel frames. Every stack child still occupies its column cell in that overlay, so a press *outside every placed quad but inside the canvas* — the question this review was asked — lands on whichever card AppKit would have hit in the untransformed column, not on the canvas/sky. The same path keeps departed cards tappable: `stack.rs:418` only shoves the homography (`homography[2] += 100_000`), which makes the inverse miss; it does not take the view out of `super.hitTest`. That is the opposite of “skipping the box AppKit would test” (the comment at `:272`, LLP 1014 D5). Fix: if any direct child has a placement, do not fall through to `super` for those views — return the canvas (or `nil`) on a miss, and skip placed subviews when calling through. `tests/stack.rs` cannot catch this; it never instantiates `NodeView`.

2. **HIGH —** `gpu/src/lib.rs:411`. On a size change `Module::texture` allocates a fresh `previous` and never writes it (`:429–434`). `GlassSurface` then samples that view whenever `fade < 1` (`glass.rs:152–163`, `glass.wgsl` `mix(prev, cur, u.fade)`). After the first upload `generation != 0`, so a capture that also changes size after ≥ `CONTINUOUS_MS` of quiet (a window resize following idle is the normal case; live-resize frames are *not* quiet) sets `fade_start = now` and the next compose is a 320 ms blend from uninitialized GPU memory. Same-size updates copy correctly; this path does not. Zero the new previous, or force `fade_start = NEG_INFINITY` when the previous texture was just created.

3. **MEDIUM —** `host/apple/macos/Sources/ExactMac/Agent.swift:146`. `clock` applies runner/motion batches and returns. It never calls `Canvases.tick`. Glass is the *presented* root (`glass.rs:220` always returns `true`); its `now_ms` and fade only move in `Canvases.tick` (`Gpu.swift:357`) on the display link (`main.swift:54`). Nested stack springs move in `render`/`readback`, and `tick` recaptures a nested wanter only when `now != readAt` (`Gpu.swift:367`) — so at a frozen agent clock they stay put after the first readback (`dt = 0` on that first call, `stack.rs:399`). Consequences, all in the files: (a) `clock settle` asks `Exact.settle()` (CSS transitions only) and will report settled while the deck is still at `stacked(index)` (`stack.rs:359`); (b) spec §1b’s “screenshot after `clock +400` shows the new children” is not implied by `clock` itself; (c) web glue *does* park rAF under the agent clock (`host/web/gpu-glue.js:42`) and re-render on `clock` — macOS does not. The smoke already `sleep(150)` “one frame of the surface after its first capture” (`scripts/smoke.mjs:217`), which is the same hole. FLAG: I did not run the agent, so I cannot show a stale PNG, only that present is not on the `clock` call. Fix: after applying the batch, `canvases.tick(now: landed)` (and the nested capture it schedules) before returning, matching the web “one render per clock”.

4. **MEDIUM —** `host/apple/macos/Sources/ExactMac/Presenter.swift:291`. `accessibilityFrame` maps only when *this* node has `placement`. Direct cards get a mapped box; descendants do not. `local` and `Agent.box` both walk `placedAncestor`. VoiceOver on the countdown text inside a fanned card reports the kernel column. Use the same `placedAncestor` path as `Agent.box`.

5. **MEDIUM —** `host/apple/macos/Sources/ExactMac/Gpu.swift:370`. `Canvases.tick` recaptures a through-canvas whenever the first responder is under the overlay, with no `paintedThisTurn` / `needsCapture` check. `apply` already captured that turn (D4 a). A `type` into an input under the sky therefore captures the full window twice in one display-link turn (5–8 ms each at 840×1720). D4(d) still wants every *frame* while editing; it does not want twice on the keystroke’s turn. Honor `paintedThisTurn` here as `repaintThrough` already does.

6. **MEDIUM —** `gpu/src/native.rs:285`. `gpu_placement` does `*(out as *mut [f32; 10])` with no null check and no length. `gpu_child` / `gpu_texture` / `gpu_readback` (`:268`, `:297`, `:309`) `from_raw_parts` the host pointer before any length/size check — a 0 pointer with `len > 0` is UB (Rust also requires a non-null data pointer for `len == 0`). Everything else the brief named is handled: unknown id and no device return 1; `width == 0 || height == 0` is refused (`lib.rs:296`, `:394`); `placement` past `children_count` is `None` → 0; `readback`/`render` before `bind` do nothing. Check `out.is_null()` (and the byte pointers) and return 0/1. FLAG: the well-behaved presenter always passes a 10-float buffer; this is the misbehaving-host rule, not a crash I reproduced.

7. **LOW —** `llp/1014.000-canvas-children-v1.spec.md:303`. §5 still lists “Transforms and per-child textures (LLP 1014 D5); nested canvases …” as not in v1. §1a/§1b transcribe both as built; the RFC’s D5 note and `QUEUE.md`’s canvas line already say they landed.
