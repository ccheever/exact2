The float prop is a reasonable API. The main problems are in view ownership and D4’s promise to preserve opacity and clipping.

I reviewed commit `b1c1d4a52` without modifying files. I treated §2 as the measurement record and did not locate or rerun its probes.

Answers to §5, in order:

1. **Keep per-glass isolation for the first implementation**, limited to ordinary live views. Partitioning at a fading ancestor could preserve merging among siblings that fade together, but would require broader child-container changes. Per-glass isolation still needs the animation, lifecycle, and focus changes below.
2. **The proposed conditions are incomplete.** Account for Core Animation opacity, host-created masks, AppKit backdrop clipping, and capture boundaries. Filters and captured canvases need an explicit supported behavior; inserting another container does not establish that their captured pixels are correct. `mix-blend-mode` is already SVG-only, so this should not expand box blending support. [1001-kernel-v1.spec.md:414](/Users/ccheever/projects/exact2-wt-glassgroup/llp/1001-kernel-v1.spec.md:414)
3. **Declare paint order; omit an automatic overlap detector.** Also specify hit behavior: group infrastructure must introduce no independent hit target, and the merged bridge between shapes must not invent button geometry. Overlapping painted controls need a documented hit-order caveat.
4. **Keep the float**, in logical points, with absence disabling the group and zero remaining an enabled group. CSS lengths would add grammar without a corresponding CSS property. The existing schema/generator already supports this type; runtime validation needs tightening. [kernel/build.rs:403](/Users/ccheever/projects/exact2-wt-glassgroup/kernel/build.rs:403)
5. **Yes:** the proposed wrapping can disrupt scroll/clip transitions, flat leaves, pooling, canvas placement, navigation ownership, and focused editors. Modal geometry must continue using the existing deferred replay path. The findings below identify the changes needed.

Findings:

1. **blocker — The `opacity` presenter hook misses CSS opacity animations.**

   A box’s opacity keyframes are lowered to Core Animation; the engine explicitly does not sample them every frame. They arrive as `animations` ops and install layer animations, bypassing the proposed `present(opacity)` check. Reading `UIView.alpha` or `NSView.alphaValue` also does not establish the current animated presentation opacity. [host/apple/src/svg.rs:9](/Users/ccheever/projects/exact2-wt-glassgroup/host/apple/src/svg.rs:9), [SvgScene.swift:602](/Users/ccheever/projects/exact2-wt-glassgroup/host/apple/Sources/ExactKit/SvgScene.swift:602)

   **Change:** add the Rust animation-lowering path to §4. To retain D4’s exact “isolated while opacity < 1” behavior, sample affected opacity animations through the existing engine mechanism and reconsider eligibility when group membership changes. The existing `set_node_sampled` mechanism supports this switch. Test transitions, keyframes, paused animations, fill modes, and adding a group during an animation. [svg_lower.rs:285](/Users/ccheever/projects/exact2-wt-glassgroup/host/apple/src/svg_lower.rs:285), [animate.rs:180](/Users/ccheever/projects/exact2-wt-glassgroup/motion/src/engine/animate.rs:180)

2. **blocker — D2 needs a defined container hierarchy, not just another `container` return case.**

   UIKit’s scroll creation/removal moves direct `NodeView` subviews. `syncClipBox` does likewise. After D2 introduces a group wrapper, those children are no longer direct subviews: a scroll transition can leave the group outside the scroller or remove its hierarchy with the old scroller. AppKit also has explicit destinations that bypass a future group. [NodeViewIOS.swift:1095](/Users/ccheever/projects/exact2-wt-glassgroup/host/apple/Sources/ExactKit/IOS/NodeViewIOS.swift:1095), [BoxShadow.swift:130](/Users/ccheever/projects/exact2-wt-glassgroup/host/apple/Sources/ExactKit/BoxShadow.swift:130), [NodeViewMac.swift:1059](/Users/ccheever/projects/exact2-wt-glassgroup/host/apple/Sources/ExactKit/Mac/NodeViewMac.swift:1059)

   **Change:** distinguish the base child container, the group’s content container, and the outer material/background view. Specify reconciliation for group, material, scroll, and clip-box changes together. Preserve child coordinates and sibling order, and define group sizing in scroll-content coordinates, including nonzero scroll offsets. Keep the scroll/document machinery as its current owner.

   Material ordering needs the same treatment: UIKit currently sends `materialView` behind siblings on the node itself; that is no longer the correct ordering operation when the material sits inside an isolation wrapper. [PresenterIOS.swift:792](/Users/ccheever/projects/exact2-wt-glassgroup/host/apple/Sources/ExactKit/IOS/PresenterIOS.swift:792)

3. **blocker — “Any element” breaks the canvas’s direct-child contract.**

   Canvas capture enumerates `overlay.subviews` as `NodeView`s, uploads them by index, and reads placements back using that same enumeration. D2 moves those nodes beneath a non-node group view, so the enumeration becomes empty. Hit testing and placement coordinate conversion also depend on the existing overlay relationship. [GpuIOS.swift:341](/Users/ccheever/projects/exact2-wt-glassgroup/host/apple/Sources/ExactKit/IOS/GpuIOS.swift:341), [GpuIOS.swift:371](/Users/ccheever/projects/exact2-wt-glassgroup/host/apple/Sources/ExactKit/IOS/GpuIOS.swift:371), [NodeViewIOS.swift:644](/Users/ccheever/projects/exact2-wt-glassgroup/host/apple/Sources/ExactKit/IOS/NodeViewIOS.swift:644)

   The overlay additionally sets its own alpha to zero outside presenter opacity ops. Thus a path walk over authored nodes misses a real visibility boundary. [GpuIOS.swift:453](/Users/ccheever/projects/exact2-wt-glassgroup/host/apple/Sources/ExactKit/IOS/GpuIOS.swift:453)

   **Change:** cut grouping within sampled canvas content from the first release, with an explicit diagnostic and a rule preventing membership from crossing that capture boundary. Keep ordinary glass controls outside the sampled canvas. Supporting this later requires preserving child identities, placement indices, hit geometry, accessibility, and captured glass pixels—not merely finding descendant nodes recursively.

4. **should-fix — D4 conflates clipping with effects that replace a subtree’s pixels.**

   `clip-path` becomes a layer mask. Layout transitions install another mask and can turn `clipsToBounds` off while that mask stands in. AppKit backdrop blur enables clipping even with visible overflow. Meanwhile `BoxFilter` hides the original subtree and displays a filtered bitmap rendered from its layer. These are distinct mechanisms. [ClipPath.swift:35](/Users/ccheever/projects/exact2-wt-glassgroup/host/apple/Sources/ExactKit/ClipPath.swift:35), [Surface.swift:144](/Users/ccheever/projects/exact2-wt-glassgroup/host/apple/Sources/ExactKit/Surface.swift:144), [Backdrop.swift:197](/Users/ccheever/projects/exact2-wt-glassgroup/host/apple/Sources/ExactKit/Backdrop.swift:197), [BoxFilter.swift:77](/Users/ccheever/projects/exact2-wt-glassgroup/host/apple/Sources/ExactKit/BoxFilter.swift:77)

   **Change:** enumerate the host-owned clipping mechanisms D4 supports and their invalidation points. Treat bitmap filters as capture boundaries with an explicit limitation or fallback. Add composited tests for `clip-path`, backdrop-induced clipping, and layout-transition masks before claiming that isolation preserves them. §2’s rectangular clipping result alone does not establish those cases.

5. **blocker — Suppressing the web attribute breaks bound props on the default JS target.**

   The JS emitter resolves a prop’s DOM name by projecting a sample through the web host. If `element.rs` emits nothing, that lookup fails with “prop … has no DOM name.” The existing fallback emits `data-<name>`. [host/web-js/src/emit.rs:1151](/Users/ccheever/projects/exact2-wt-glassgroup/host/web-js/src/emit.rs:1151), [host/web-js/src/style.rs:376](/Users/ccheever/projects/exact2-wt-glassgroup/host/web-js/src/style.rs:376), [element.rs:698](/Users/ccheever/projects/exact2-wt-glassgroup/host/web/src/element.rs:698)

   **Change:** delete §4’s “writes no attribute” requirement and retain the harmless `data-glassgroup` fallback. Alternatively, explicitly implement ignored-prop handling in the JS compiler. Verify literal, bound, updated, and cleared values through the default web build. “Nothing drawn” does not require “nothing emitted.”

6. **should-fix — Moving view children leaves flat leaves behind.**

   UIKit flat leaves are `CALayer`s, including combined runs, attached to `parent.container.layer`. They move only when their parent is marked dirty and `FlatLeaves.flush()` rebuilds their placement. A group prop change can change the container without any children op. Clearing the old group can therefore remove flat paint with it. [FlatLeavesIOS.swift:189](/Users/ccheever/projects/exact2-wt-glassgroup/host/apple/Sources/ExactKit/IOS/FlatLeavesIOS.swift:189), [FlatLeavesIOS.swift:219](/Users/ccheever/projects/exact2-wt-glassgroup/host/apple/Sources/ExactKit/IOS/FlatLeavesIOS.swift:219), [PresenterIOS.swift:710](/Users/ccheever/projects/exact2-wt-glassgroup/host/apple/Sources/ExactKit/IOS/PresenterIOS.swift:710)

   **Change:** make every child-container replacement invalidate flat-leaf placement. Test a parent containing interleaved flat leaves and view children while its group is added and cleared using props alone. Do not solve this by disabling flattening throughout grouped subtrees.

7. **should-fix — Pool reset alone does not preserve reuse.**

   `NodePool.children` accepts only specific owned infrastructure views. A new group or isolation wrapper fails that whitelist before reset is reached. A group directly on a collection also breaks `list(holding:)`, which requires the row’s immediate parent to be the list’s `ScrollView`; inner-card parking separately enumerates raw scroll subviews. [NodePoolIOS.swift:170](/Users/ccheever/projects/exact2-wt-glassgroup/host/apple/Sources/ExactKit/IOS/NodePoolIOS.swift:170), [NodePoolIOS.swift:178](/Users/ccheever/projects/exact2-wt-glassgroup/host/apple/Sources/ExactKit/IOS/NodePoolIOS.swift:178), [NodePoolIOS.swift:256](/Users/ccheever/projects/exact2-wt-glassgroup/host/apple/Sources/ExactKit/IOS/NodePoolIOS.swift:256)

   **Change:** cover eligibility, logical-child traversal, collection ownership, parking, reset, rebind, and eviction. Destroy group/isolation effects at park and recreate them for the new incarnation; clear old membership and presenter indexes. This follows the existing material contract that reused rows receive fresh effects. [1068-recycling-heavy-views-in-list-rows.rfc.md:514](/Users/ccheever/projects/exact2-wt-glassgroup/llp/1068-recycling-heavy-views-in-list-rows.rfc.md:514)

8. **should-fix — Membership must follow physical containment and drawing lifetime.**

   UIKit moves routes into controller views, and mounts navigation views directly on the root, bypassing `root.container`. A root carrying `glassGroup` therefore would not necessarily contain its logical route descendants. Modal presentation moves those hierarchies again. Separately, exit animations retain visible views after removing them from live maps and indexes. [NavigationIOS.swift:15](/Users/ccheever/projects/exact2-wt-glassgroup/host/apple/Sources/ExactKit/IOS/NavigationIOS.swift:15), [NavigationIOS.swift:121](/Users/ccheever/projects/exact2-wt-glassgroup/host/apple/Sources/ExactKit/IOS/NavigationIOS.swift:121), [ModalIOS.swift:231](/Users/ccheever/projects/exact2-wt-glassgroup/host/apple/Sources/ExactKit/IOS/ModalIOS.swift:231), [PresenceIOS.swift:17](/Users/ccheever/projects/exact2-wt-glassgroup/host/apple/Sources/ExactKit/IOS/PresenceIOS.swift:17)

   **Change:** define membership from the actual mounted group views. Invalidate descendants when any containing ancestor moves, not only when the glass node itself moves. Handle retained exits and modal-retiring views until they stop drawing. Initially require groups inside route content rather than promising grouping across controller ownership boundaries.

   Group geometry must also follow modal-deferred frame replay; do not add a separate eager sizing path. [ModalIOS.swift:181](/Users/ccheever/projects/exact2-wt-glassgroup/host/apple/Sources/ExactKit/IOS/ModalIOS.swift:181)

9. **should-fix — Both group and isolation wrappers need explicit hit semantics.**

   UIKit deliberately bypasses the glass effect’s normal bounds check to keep visible-overflow children hittable, and ignores node alpha for CSS hit participation. That special case currently requires `materialView` to be a direct child. An isolation wrapper hides it from that check. [NodeViewIOS.swift:679](/Users/ccheever/projects/exact2-wt-glassgroup/host/apple/Sources/ExactKit/IOS/NodeViewIOS.swift:679)

   Simply using `PlainView` is insufficient: its hit test rejects points outside its bounds. AppKit’s existing material content also deliberately avoids becoming its own hit target. [ScrollViewIOS.swift:9](/Users/ccheever/projects/exact2-wt-glassgroup/host/apple/Sources/ExactKit/IOS/ScrollViewIOS.swift:9), [NodeViewMac.swift:16](/Users/ccheever/projects/exact2-wt-glassgroup/host/apple/Sources/ExactKit/Mac/NodeViewMac.swift:16)

   **Change:** specify transparent hit routing for every added wrapper. Test overflow, opacity zero, hidden/inert ancestors, empty group space, the merged bridge, and scroll-versus-press arbitration. Preserve the platform glass recognizers’ ancestry.

10. **should-fix — Saving a descendant first responder is not a complete focus-preservation strategy.**

    A material’s content contains authored child nodes, including editors, so moving the material moves those editors too. The AppKit collection code explicitly avoids detaching views because doing so clears first responder. Existing focus detection handles an `NSTextField` through `currentEditor()`, separately from ordinary descendant views. [NodeViewMac.swift:553](/Users/ccheever/projects/exact2-wt-glassgroup/host/apple/Sources/ExactKit/Mac/NodeViewMac.swift:553), [CollectionMac.swift:222](/Users/ccheever/projects/exact2-wt-glassgroup/host/apple/Sources/ExactKit/Mac/CollectionMac.swift:222), [AgentMac.swift:99](/Users/ccheever/projects/exact2-wt-glassgroup/host/apple/Sources/ExactKit/Mac/AgentMac.swift:99)

    **Change:** cover logical editor ownership, field editors, selection, marked text, and focus/blur delivery. Reparent only when isolation state changes. Test a focused input and textarea through isolate/rejoin and group add/remove on both platforms. The planned iOS manual composer test does not validate the macOS reparenting strategy.

11. **should-fix — Runtime spacing validation is underspecified.**

    A float’s schema kind does not enforce finiteness. The runner accepts any numeric float, and the Apple bridge narrows it from `f64` to `f32` before stringifying it. Thus even a finite authored number can become infinity before reaching Swift. “Clamped at 0” does not resolve this.     **Change:** specify a finite representable range, reject out-of-range literals, clamp finite negative bound values to zero, and disable the group with a once-only diagnostic for nonfinite/overflowed runtime values.
