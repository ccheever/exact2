## Review (verbatim)

NOT READY — the presentation boundary is sound, but the storage assumptions and mobile cost model need correction before implementation.

I agree with saving `Gait` and deriving cosmetic offsets in `present`. That follows [engine/README.md](/Users/ccheever/projects/exact2/game/engine/README.md:304) and [LLP 1046.008](/Users/ccheever/projects/exact2/llp/1046.008-game-presentation-seams.plan.md:291). `Pose` already owns saved local history, and `animation::step` commits it after sampling, layers and IK. Adding a second writer would complicate that ownership. Gameplay-relevant procedural animation should eventually enter that pipeline before IK; this cosmetic feature need not solve it.

Keeping imported nodes out of the entity graph, interpolating local TRS, and reusing the existing palette path are also good decisions. They fit [asset/pose.rs](/Users/ccheever/projects/exact2/game/engine/src/asset/pose.rs:5) and the explicit animation model in [game/README.md](/Users/ccheever/projects/exact2/game/README.md:187).

The changes I would require:

1. **Fix the allocation premise before choosing the fixed component layout.** Presentation clearing calls `storage.clear()`, which erases every row and frees each emptied page. Reinsertion allocates zeroed pages of **512 component slots**. Thus the proposed inline array does **not** produce zero warm allocations. Using the RFC’s 1.5 KB estimate, one occupied page costs roughly 0.75 MB—even for one avatar. Sparse entity IDs amplify this. There is also a temporary `Vec` in presentation clearing. See [world/presentation.rs](/Users/ccheever/projects/exact2/game/engine/src/world/presentation.rs:19), [storage/raw.rs](/Users/ccheever/projects/exact2/game/engine/src/storage/raw.rs:307), and [storage.rs](/Users/ccheever/projects/exact2/game/engine/src/storage.rs:23).

   **Alternative:** retain presentation backing pages and clearing scratch while logically removing all rows. Then qualify the 16-row layout using both clustered and sparse avatar IDs. Sixteen is an acceptable explicit initial bound, not an allocation argument. **Cost:** retained memory and a focused storage change. `Present::insert_each` is a reasonable convenience, but must traverse and write disjoint columns without collecting entities; benchmark the whole clear/present/feed cycle, not just its closure.

2. **Keep node-frame composition, but stop claiming broader equivalence.** `local·offset` matches `Offset`; changing the default to parent-frame for Castle would make two “offset” APIs disagree. However, additive layers translate in the parent frame: `base.position + delta`, unlike the RFC’s rotated/scaled displacement ([animation/layers.rs](/Users/ccheever/projects/exact2/game/engine/src/animation/layers.rs:141)). Castle directly replaces Euler channels and torso Y (Castle's `pxmodel.js:690`); moving arm splay into children is a legitimate export conversion, not proof of general equivalence.

   **Alternative:** explicitly define node-frame TRS semantics and qualify rotated, scaled rest poses. Reject unsupported authored shear when promoting a formerly static model: `Node.transform` preserves shear, but `bind_pose` decomposes it. Also specify the nonuniform-scale approximation instead of calling it an affine product. **Cost:** validation and some asset normalization; no new shader.

3. **Make names authoritative and hashes an accelerator.** Rejecting collisions between two asset nodes does not catch an unmatched requested name whose hash collides with one valid node. The string is already carried.

   **Alternative:** compare the actual name after a hash match; use string identity for duplicate-row replacement too. Preserve the same naming semantics as `NodeMaterials` ([scene.rs](/Users/ccheever/projects/exact2/game/engine/src/scene.rs:511)). **Cost:** short string comparisons, negligible beside packing and composition. No global interning registry is justified.

4. **Keep the explicit `posable` mark, with an honest render contract.** Selecting representation at preparation avoids mid-session promotion and preserves the static fast path for ordinary assets. But one marked node promotes the entire model, including instances that never receive offsets. Name the shared predicate `requires_palette()` rather than `animated()`; simulated bounds intentionally retain a different predicate.

   The change does **not** necessarily lose material merging: [models/merge.rs](/Users/ccheever/projects/exact2/game/render/src/models/merge.rs:18) still merges animated rigid parts. It loses static pretransformation and zero-weight-buffer rendering. **Alternative:** accept whole-model promotion for these small avatars, require genuinely static distant assets, and defer mixed static/dynamic subtree partitioning. **Cost:** palette and vertex work on every promoted part; avoiding that later requires ancestor-aware partitioning.

5. **Own pose uploads per instance/model, not per material record.** The RFC correctly identifies existing duplication in [skinning.rs](/Users/ccheever/projects/exact2/game/render/src/skinning.rs:289), but should not extend it unquestioningly.

   | At 60 fed ticks/s | 30 avatars | 1,000 avatars |
   |---|---:|---:|
   | Current proposed upload | 96 KB/tick; 5.76 MB/s | 3.2 MB/tick; 192 MB/s |
   | One shared pose copy | 48 KB/tick; 2.88 MB/s | 1.6 MB/tick; 96 MB/s |

   **Alternative:** let both draw jobs reference one pose span per entity/model. **Cost:** offset mapping and invalidation changes; the shader already accepts a pose offset. This does not eliminate duplicated hierarchy computation.

   Thirty looks plausible, not proven. At 1,000, static far LOD skips compute dispatches but still packs/uploads near-level poses. The suggested future 8× reduction is not established: sparse-node uploads need retained base poses and correct ancestor handling, and do not benefit arbitrary clips equally.

6. **Replace optimistic GPU accounting with measured work.** [skin.wgsl](/Users/ccheever/projects/exact2/game/render/src/shaders/skin.wgsl:25) composes the whole hierarchy serially on one lane per job. Merged rigid vertices execute the generic four-influence blend and inverse-transpose calculation ([model_vertex.wgsl](/Users/ccheever/projects/exact2/game/render/src/shaders/model_vertex.wgsl:15)). “One palette matrix” describes useful influences, not guaranteed memory traffic.

   **Alternative:** measure Pixel 5 and a named iPad model at 30 and 1,000, with shadows, all-near, far-LOD and offscreen populations. Report CPU packing, allocations, upload bytes, skinning, culling and geometry time. **Cost:** additional benchmark cases. Do not assert fixed binning/tile traffic from source inspection.

Missing details that will bite:

- **History lifecycle:** retain a removed row through its transition to identity; shift history once per tick, not per record/feed. Cover same-tick re-presents, visibility, generation reuse, model replacement, LOD arrival and attachments created without `Pose`. Share endpoint composition between packing and [socket chains](/Users/ccheever/projects/exact2/game/render/src/world/scene.rs:852).
- **Culling is conservative, not exact.** It unions the whole mesh sphere transformed by every palette joint ([cull.wgsl](/Users/ccheever/projects/exact2/game/render/src/shaders/cull.wgsl:70); [LLP 1046.003](/Users/ccheever/projects/exact2/llp/1046.003-game-engine-as-built.explainer.md:1094)). Promotion can worsen rejection.
- **Arbitrary `Transform` needs limits:** negative node scale is not included in current winding selection; translucent sorting ignores palette motion. Define restrictions or extend those paths.
- **`NodeName` needs a `Data` design:** `Presentation` derives reading/writing too; existing implementations do not support `&'static str`. Preserve readable diagnostics without leaking dynamically read strings.

These are source-based findings; I ran no builds or device measurements and changed no files.

### Review (verbatim)

READY WITH CHANGES — the disputed r1 rejections hold; retained-memory policy and rotation sanitization need tightening.

- **F(a), interpolation history: rejection holds.** `present` runs for each of the final two ticks before the observer callback ([sim.rs:1205](/Users/ccheever/projects/exact2/game/engine/src/sim.rs:1205), [sim.rs:1233](/Users/ccheever/projects/exact2/game/engine/src/sim.rs:1233)). The stock observer feeds both when `left < 2` ([surface.rs:296](/Users/ccheever/projects/exact2/game/render/src/surface.rs:296)). Thus a two-tick advance supplies T−1 and T, despite clearing presentation between them. Double-buffered engine columns are unnecessary for this contract.

- **F(c), dropping scale: rejection holds.** Castle explicitly multiplies part scale for waves and blinks (Castle's `motion.js:347`, Castle's `motion.js:363`). Keeping scale has a concrete consumer.

- **F(g), translucent popping: rejection holds.** CPU frustum rejection requires `record.skin.is_none()` ([draw.rs:590](/Users/ccheever/projects/exact2/game/render/src/renderer/draw.rs:590)); palette records bypass it. Sorting still uses the undeformed mesh centre ([draw.rs:581](/Users/ccheever/projects/exact2/game/render/src/renderer/draw.rs:581)), accurately identified as a separate limitation.

- **F(b), parent-axes flag: deferral holds for these avatars.** Moving the splay beneath an unrotated swing pivot gives the required `Rx·Rz` composition. The conversion must move the existing children—including hand anchors—beneath that splay child. The verifier checks anchor-name existence and world-space triangles, not node counts ([verify.mjs:87](/Users/ccheever/projects/exact2/game/games/castle-town/tools/verify.mjs:87)). However, it does not establish socket-frame equivalence: the named arm pivot itself changes orientation. That qualification does not justify adding another runtime composition mode now.

- **A5/F(h), remaining upload optimizations: deferral is reasonable pending the promised measurements.** D5’s shared span is sound: shader jobs independently address pose input and palette output ([skin.wgsl:26](/Users/ccheever/projects/exact2/game/render/src/shaders/skin.wgsl:26)). Different material/skin jobs can share locals while retaining their own palettes. Hidden-level packing remains real work: `pack` traverses every record, whereas visibility filters dispatch separately ([skinning.rs:358](/Users/ccheever/projects/exact2/game/render/src/skinning.rs:358), [skinning.rs:386](/Users/ccheever/projects/exact2/game/render/src/skinning.rs:386)). I found no material architectural problem introduced by sharing the span.

Two changes need tightening:

1. **D6 needs a reclamation policy and retained-memory measurement.** Keeping pages through clearing removes churn, but retaining every historically touched page indefinitely is a different commitment ([r2:239](/Users/ccheever/projects/exact2/llp/1046.013-per-node-pose-offsets.rfc.md:239)). Storage indexes pages by entity index ([raw.rs:321](/Users/ccheever/projects/exact2/game/engine/src/storage/raw.rs:321)); at the RFC’s size, 1,000 avatars occupying distinct pages retain roughly **650 MB**, and pages can remain after offsets disappear. The sparse proof currently checks allocations, not retained bytes. Specify bounded reuse or reclamation for pages remaining empty after presentation, and measure residency through sparse populations and churn.

2. **The new limits do not fully sanitize rotations.** A zero quaternion is finite and passes D3’s listed rejection rules, but cannot be normalized ([r2:150](/Users/ccheever/projects/exact2/llp/1046.013-per-node-pose-offsets.rfc.md:150)). CPU attachment interpolation normalizes directly ([skinning.rs:13](/Users/ccheever/projects/exact2/game/render/src/skinning.rs:13)), so this can propagate NaNs. Explicitly drop non-normalizable rotations and check composed endpoints remain finite; finite inputs alone do not prevent arithmetic overflow.
