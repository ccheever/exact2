LAND WITH CHANGES

1. **MATERIAL** — A cancelled sheet drag or zoom dismiss never re-resolves, so a batch that lands during the gesture leaves the bar on the pre-gesture style. `modals.inTransition` is true while `isBeingDismissed` is (`ModalIOS.swift:195-197`), and `resolveStatusBar` returns immediately (`StatusBarIOS.swift:22-23`). A completed drag or zoom does resolve: `presentationControllerDidDismiss` goes through `closeTop` into `drainRetired`, which clears `retiring` and then resolves (`ModalIOS.swift:527-541`, `487-493`). A cancel does not. `viewDidAppear` is the reappearance after a cancelled interactive dismissal (`ModalIOS.swift:64-68`) and does not resolve; zoom's `appeared` only clears `ZoomLanding.interactive` (`ModalIOS.swift:170`, `374`). Concrete input: a large sheet (or zoom) showing `light-content`, the user pulls to dismiss, and the batch that sets the header to `dark-content` is applied while `isBeingDismissed` is set. The header updates; the bar does not. The user lets go. Nothing calls `resolveStatusBar` again, so the root and the `ModalController` keep returning `.lightContent` until some later full `apply`. Pops, tab changes, and cancelled back swipes do re-resolve (`NavigationIOS.swift:743-770`). **Fix:** from `viewDidAppear`, when `presenting` is already false and `isBeingDismissed` is false, call `resolveStatusBar()`. The first appearance still no-ops (`presenting` / `isBeingPresented`), and the present completion stays the success path. If `isBeingDismissed` is still true inside that `viewDidAppear`, resolve from the interactive coordinator's completion when `context.isCancelled`.

2. **MINOR** — The tests would stay green for a wrong scope, a missed transition end, and a missing UIKit re-read. `testAScrollThresholdFlipChangesTheBarInItsOwnBatch` (`StatusBarIOSTests.swift:100-126`) does pin that `onStatusBar` runs before `apply` returns and that the stored style changed. `reread` increments inside the test's own hook, and `preferredStatusBarStyle` is read by the test, so deleting `setNeedsStatusBarAppearanceUpdate` still passes. `testTheSheetDelegateHearsADetentDrag` only checks that the selector exists; an empty method passes. Nothing presents a controller, cancels a drag, or resolves a push inside a covering presentation. **Fix:** one test whose root and presented controller count reads of `preferredStatusBarStyle` during the flipping `apply`; one cancelled interactive dismiss whose intervening props batch is visible on the controller after the gesture ends.
