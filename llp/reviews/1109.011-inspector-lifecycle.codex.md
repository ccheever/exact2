## Overall assessment

Two concrete source-lifetime discrepancies were found and corrected by the model author. The revised model preserves callback registration separately from actual renderer mounting and restarts inactive completion deadlines when the source effect dependencies change. No additional actionable issue was found in the bounded model review. Keep Draft and the existing native proof limitations.

## Strengths

- Snapshot decodes and projects committed JSON without allocating tokens, advancing deadlines, reading transport or issuing writes. Only explicit transitions adopt focus and allocate owner tokens.
- Role, registration, inactive exit and prewarm ownership are distinct. An old close callback cannot clear a reopened registration or a later exit of the same content.
- Focus ownership includes route, kind, environment, thread, generation and cwd. Source route-mode reset, Files reveal and Review reveal remain separate from permission or data readiness.
- Renderer replacement preserves visited modes and an existing same-mode prewarm clock only when the same stack remains mounted. Actual unmount clears visited/prewarm state; remount begins fresh child state.
- Root supplies actual role/column support rather than retaining a prior role to force a column behind an overlay.

## Findings and disposition

1. **P2, corrected — unsupported layout dropped the callback lease.** Initial transition code cleared registration when columnSupported became false. In pinned `AdaptiveWorkspaceLayout.tsx`, workspaceInspector retains the renderer until onClosed; in `workspace-inspector-pane.tsx`, hooks and the close effect are outside the conditional Animated.View. Unsupported width therefore unmounts the child renderer but retains the active/inactive callback lease. Quick resupport can remount outgoing content before closure. Revised code projects mounted=false, clears child visited/prewarm state, and retains the actual lease. Parent adapter projects empty native owner/zero column while keeping captured serialized content for a surviving lease.

2. **P2, corrected — width/resizing changes reused an obsolete close deadline.** Pinned `workspace-inspector-pane.tsx` close effect depends on inspectorWidth and resizing as well as visibility. Inactive null-to-width or width changes restart withTiming-to-zero and its onClosed callback. Revised input carries columnWidth and resizing; committed prior values detect an actual change and allocate a new exitToken/deadline. Old callbacks/deadlines cannot remove this restarted exit. Unsupported width normalizes to zero. New tests cover quick resupport, inactive width changes and resizing.
