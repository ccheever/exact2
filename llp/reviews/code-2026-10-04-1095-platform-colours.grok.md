## Correctness

**1. High.** `host/web/glue.js:358` and `host/web-js/symbols.js:9`. An unstyled symbol is black on the web. Both stylesheets register `@property --exact-tint` with `inherits:false; initial-value:#000`, and every `img[data-symbol-path]` paints `background-color: var(--exact-tint)`. The host emits `--exact-tint` only when the tint row is set (`host/web/src/element.rs:199`). The schema default is `AccentColor` (`kernel/tables/schema.json:2486`), and D8 says an untinted symbol is the platform tint: UIKit's inherited `tintColor` on iOS, `controlAccentColor` on macOS, CSS `AccentColor` on the web (`llp/1086-platform-colours.rfc.md:455`). Apple does that by leaving `symbolTint` nil when the row is absent or is `@tint` (`host/apple/Sources/ExactKit/Affordances.swift:23`). On the web, `image "symbol:checkmark"` with no `tint-color` is `#000`. Rasters stay untinted, because the rule is limited to `img[data-symbol-path]` and the raster template still requires the mask bit. Set the symbol rule to `var(--exact-tint, AccentColor)` and the `@property` initial value to `AccentColor`. Leave rasters alone.

**2. Medium.** `host/linux/src/paint.rs:53` and `host/linux/src/paint/svg.rs:100`. An unstyled Linux symbol uses `CanvasText`, not `AccentColor`'s fallback. `image_tint` returns `None` unless the tint bit is set, and `symbol` then paints `node.text_color()`. That is `#000000` / `#ffffff`. D8 says a host with no system colour uses the role's own fallback pair (`llp/1086-platform-colours.rfc.md:467`). `AccentColor`'s pair is `#007aff` / `#0a84ff` (`schema.json:3451`). A checkmark with no `tint-color` is black in light mode. When the tint bit is absent, paint `style.tint_color` (the schema default) for symbols only. Keep the mask-bit check for rasters.

**3. Medium.** `host/apple/Sources/ExactKit/SystemColor.swift:47` and `:60`. Accent and selection colours go stale, and `AccentColor` is not the view's tint. D5 says accent and selection changes post `NSColor.systemColorsDidChangeNotification` and that the host observes it (`llp/1086-platform-colours.rfc.md:389`). Nothing calls `SystemColor.invalidate()`, and the cache key is `(name, dark, contrast, elevated)`. Change the accent in System Settings: `controlAccentColor`, `selectedTextBackgroundColor`, and any kernel-resolved `AccentColor` (a gradient, an SVG scene, paint motion, `tint-color="AccentColor"`) stay on the old colour until appearance or contrast changes the key. `tint()` (`SystemColor.swift:128`) also reads the key window's `tintColor`, or `systemBlue` when there is no key window, and does not store that result in `resolved`. A second window's `AccentColor` gradient follows the key window. Inherited `@tint` symbols still follow the view's live `tintColor`. Observe the notification (and an iOS window-tint change), call `invalidate()`, and report colours again. Resolve `@tint` from the view's window.

**4. Medium.** `host/apple/Sources/ExactKit/Affordances.swift:39`. Hierarchical and palette symbols ignore Increased Contrast and elevation. `symbolLookKey` is rendering mode, palette JSON, variable value, the tint row, and `drawsDark`. `updateSymbol` rebuilds the image only when that key changes (`host/apple/Sources/ExactKit/IOS/NodeViewIOS.swift:427`, `host/apple/Sources/ExactKit/Mac/NodeSymbolMac.swift:23`). Hierarchical and palette colours are baked in `symbolConfiguration` (`Affordances.swift:46`). Monochrome still assigns `tintColor` / `contentTintColor` on every call, so that path follows contrast when `applyStyle` runs. Turn on Increase Contrast with `symbol-rendering="palette"` or hierarchical and `system-orange`: the glyph stays at the normal-contrast orange. D5 names this look key as a site that has to carry the trait set. Put contrast and elevated level in the key.

**5. Medium.** `host/apple/Sources/ExactKit/SystemColor.swift:85`. `platform-color()` lookup can crash on a non-object class method. `lookup` requires `class_getClassMethod` and two arguments (the receiver and `_cmd`), then calls `perform` and `takeUnretainedValue` before `as? Native`. D3 requires a class method, zero user arguments, an object return, and `isKindOfClass:` a colour (`llp/1086-platform-colours.rfc.md:298`). §9 says that check is what shipped. A method that matches `[a-z][A-Za-z0-9]*Color` and returns a number or a struct never reaches the cast. I did not find a public `UIColor` or `NSColor` `*Color` method that returns a non-object, so this is not a crash on today's shipping selectors. Check `method_copyReturnType` for `@` before `perform`, and use the fallback otherwise.

**6. Medium.** `kernel/src/style.rs:699` and `kernel/src/style.rs:495`. The runtime accepts `platform-color()` from data. D3 says the function is literal-only, Contract refuses it in dynamic values, and the runtime parser does not accept it (`llp/1086-platform-colours.rfc.md:287`). `parse_light_dark` tries a role, then `platform-color(`, then a pair, and `StyleValue::color_value` is what dynamic text uses (`runner/src/bridge.rs:98` into `set_dynamic`). `roles.rs:126` says Contract refuses it. The Contract error text lists it as a valid colour (`contract/lower/src/values.rs:134`). There is no `lower-platform-color-literal` lint. §9 already marks that lint unbuilt. A bound value can name any legal selector or `named:…`, which is the input to finding 5. The intern table is process-global, capped at 1024, and never shrinks (`roles.rs:126`). At the cap, `parse_platform` returns the fallback and drops the name. Reject `platform-color(` in dynamic `set_dynamic`, and add the lint. The same process-global `REPORTED` map is what §9 calls one table per process. Appearance is part of the key and contrast is process-wide (`DisplayPreferences.agentContrast`), so two sessions do not swap contrast. A second session's `reportColors` still replaces the whole map.

**7. Low.** `SystemColor.swift:38` and `:65`. One failed lookup blacklists the name for every trait set. `refused` is filled when lookup or `rgba` fails, `invalidate` does not clear it, and `invalidate` has no callers. A `named:` asset that is not loaded yet, or one `getRed` / `usingColorSpace` failure, keeps the fallback after the asset or the colour space would succeed. Key the refusal by the trait key, or refuse only when lookup fails, and clear it from `invalidate`.

**8. Low.** `host/apple/Sources/ExactKit/Session.swift:785`, `:1121`, and `:1183`. The first colour report can animate from system blue to the window tint. Boot calls `tellTime` → `tellPreferences` → `reportColors` before the view's `scheme(dark:)`. With no key window, `@tint` is `systemBlue` (`SystemColor.swift:132`). `colors_changed` does nothing until `self.dark` is set (`kernel/src/motion/paint.rs:209`), so that first report only fills the table. `scheme` then sets the scheme and reports again. If the window tint differs, the second report re-targets paint motion with `first=false`. A node with `transition` on a colour that is `AccentColor` eases from system blue to the app tint at startup. Skip `@tint` until a window exists, or treat the first report after `scheme` as the non-motion correction.

**9. Low.** `kernel/src/style/roles.rs:30` and `host/apple/src/abi/colors.rs:42`. A bad role id wraps onto another role's fallback. `role_of` uses `% COLOR_ROLES.len()`. Wire decode rejects an id past the table (`kernel/src/wire/codec.rs:216`). A host report only checks that the id fits in `u8`, then `set_reported` stores it. `resolve` prefers the report, so a bad id still paints what the host sent. After a later report drops that id, fallback wraps onto a different role. Reject a role id that is not `< COLOR_ROLES.len()` in `parse_report`.
