I'll check the RFC's load-bearing claims against the repository, starting with the rules that bind the design and the Excord, trace, and perf code they depend on.The benchmark does not record the fling it exists to judge, and the warning does not match the lists that janked.

**1. The frame sampler is idle during the glide of a list that is already built.**

`FrameSampler` starts its display link only from a runner batch (`batch` calls `activity`) and stops it 500 ms after the last one. A tick does not keep the segment alive. `activity` is refreshed only when `session.frames.link` is running. `ScrollPump` states the other half: a screen painted up front scrolls with no follow-up pass and asks for no frames.

Excord's member list is that screen. `scroll testId="members"` wraps `MemberList`'s `for` over `loadMembers`, with no `scroll=` handler and no collection, so a fling applies no batch. The link is already stopped by the time the finger moves, and the trace diff has no frames for the glide. The same gap hides the hover work from `4d404187a7`, which ran inside the scroll callback. The window also opens after the first frame, so the cost of building every row — the DM list in `268396d49f`, which the app itself says took seconds to open — sits outside the diff.

This is the measurement. A fully built scroller is the jank the document is trying to see, and this sampler is defined to be quiet then.

Hold one sampler segment open from the baseline until deceleration ends, on a wall-clock arm rather than on batch activity. Count the frames in which the list is built as well as the glide. Treat an empty window as a failed run.

**2. As specified, the run never gets a wall-clock fling onto Excord's transcript.**

A plain `build.mjs --ios --run` sets neither `EXACT_AGENT` nor `EXACT_AGENT_SOCKET`, and aiming a `testId` is a `tap` with `aim` on that socket. The transcript is not the launch screen. The fixture tests open it by tapping through the directory. `landed` in `agent.mjs` sends `clock land` after every input. With the default agent timing the clock is already 0 from launch, so `activity()` never starts the link. With platform timing, that first clock operation sets `session.clock` and stops the sampler. The drag `openTouches` can send today also inserts the resting steps in `Synthesizer.path`, which are there so UIKit's velocity is 0 at the lift. The still-waypoint shape that kept a glide (measured around 520 pt/s) is not what that call sends.

The first app in the plan cannot be measured by the procedure in the plan. The clock rule the document is trying to respect is also what shuts the sampler off as soon as the driver navigates.

Launch with the socket and platform timing, resolve the target and walk to the channel with `aim`, and do not send `clock`. Play the still-waypoint drag that keeps UIKit's velocity. Take both traces while that wall clock is still in force.

**3. The warning's growth test excludes the lists this document is about, and the channel list does not page on `scrolled`.**

The member list is one resource, fetched whole, repeated by `for r in rows` inside a plain `scroll`. Nothing in the contract concats, pushes, or pages it. The decision says a list fetched once and never grown is not warned, so this list is silent. It is also the list the Excord section calls the warning's case. The DM window grows by `dmsShownCount = … + 100` on a button, not by `concat` or `push`. The channel list is `list id="channels"` with no `scroll=`. `scroll=scrolled` is on `list id="transcript"`, which is already `virtualized=true`. That handler pages the message window. The reach-lead issue describes the same handler.

The compile-time half is justified as catching the lists that became the DM list and the member list. The predicate drops both, and the Excord section goes looking for a scroll handler the channel list does not have.

Warn when a non-virtualized `scroll` or `list` repeats a collection whose length is not a short literal: a resource, a prop fed by one, or a slice window. That is the member list and the channel list. Leave the transcript's `scrolled` as the paging handler it is. Once a fling is actually on the trace, the frame record can say whether those writes cost a frame.
