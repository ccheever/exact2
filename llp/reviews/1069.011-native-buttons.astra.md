`1075.003` is absent from this worktree. For that comparison, I read the [copy in the sibling `exact2` checkout](/Users/ccheever/projects/exact2/llp/1075.003-native-platform-control-merged.plan.md:1); it is a Draft, not evidence committed with this plan.

My answers to §5 are:

1. **Keep the literal `appearance="auto"` switch.** It expresses the requested opt-in without inventing another tag. Refusing a runtime switch is reasonable because it changes the node’s representation and child layout. Evaluate it after class merging and node overrides; identical `auto` values in both class arms already collapse to a literal. Declare the ordinary button’s fixed `none` as proposed. [class.rs:29](/Users/ccheever/projects/exact2-wt-native-button/contract/lower/src/class.rs:29), [DEFERRED.md:291](/Users/ccheever/projects/exact2-wt-native-button/rules/DEFERRED.md:291).

2. **`Control` is the right sizing abstraction, but it does not preserve `Pressable` behavior automatically.** Focus, keyboard input, focus retention, accessibility naming, projection ownership, agent activation and row recycling need explicit integration. Refusing `press-scale` is sensible; the platform should own its highlight. Findings 1 and 4–11 detail the regressions.

3. **Keep one title and one symbol for this slice.** Defer raster images and subtitles. Clarify conditional cardinality, icon-only accessibility, permitted child attributes and text flattening. Those restrictions are a scope choice, not a claim that platform buttons cannot display raster images.

4. **Schema-declared `styleable` props are the right mechanism.** The conditional-class rule is a reasonable initial restriction, but it is insufficient for value validation. “Props have no `none`” should be described as a compiler restriction: the runtime already has `ClearProp`. Finding 9 explains the necessary changes.

5. **`bordered` is a reasonable explicit default.** Its justification should be product policy, rather than a universal claim about browser appearance. The macOS mappings need a complete table and verification; the web proposal needs actual layout, colour and capability plumbing, not only selectors.

6. **There is no necessary conflict with 1075.003, but the ownership boundary needs stating.** This feature is a bounded, authored control projection; it need not wait for hooks or inherit their unresolved API promises. The sibling draft keeps actions on authored controls and says Exact must not overwrite app-owned configuration. State that this feature’s button configuration is Exact-owned, and leave future hook access separate. [1075.003:334](/Users/ccheever/projects/exact2/llp/1075.003-native-platform-control-merged.plan.md:334), [1075.003:370](/Users/ccheever/projects/exact2/llp/1075.003-native-platform-control-merged.plan.md:370).

The findings follow.

1. **Blocker — “Focus and keys: the platform’s” does not preserve Exact’s focus contract.**

   iOS Tab navigation enumerates `NodeView`s and focuses `textArea ?? field ?? node`; it never selects a hosted control. A plain `control` with only a `press` handler cannot become first responder. Focus/blur dispatch and collection pin updates also live on the wrapper. macOS programmatic focus similarly targets the wrapper. [PresenterIOS.swift:364](/Users/ccheever/projects/exact2-wt-native-button/host/apple/Sources/ExactKit/IOS/PresenterIOS.swift:364), [NodeViewIOS.swift:247](/Users/ccheever/projects/exact2-wt-native-button/host/apple/Sources/ExactKit/IOS/NodeViewIOS.swift:247), [PresenterMac.swift:589](/Users/ccheever/projects/exact2-wt-native-button/host/apple/Sources/ExactKit/Mac/PresenterMac.swift:589).

   **Change:** Specify one logical focus owner and its native responder adapter, covering Tab/Shift-Tab, `tabIndex`, autofocus, `focus()`/`blur()`, focus events, rings and collection pins. Preserve `retainFocus` and editor-blur behavior currently implemented in [NodeViewIOS.swift:1343](/Users/ccheever/projects/exact2-wt-native-button/host/apple/Sources/ExactKit/IOS/NodeViewIOS.swift:1343). Require real keyboard tests: the agent currently dispatches Enter/Space even if `becomeFirstResponder()` fails, so that test alone can falsely pass. [AgentIOS.swift:665](/Users/ccheever/projects/exact2-wt-native-button/host/apple/Sources/ExactKit/IOS/AgentIOS.swift:665).

2. **Blocker — D7’s “children emitted as today” cannot produce D4’s native face consistently.**

   Ordinary buttons carry fixed `display:flex; flex-direction:column`. Their title spans receive `display:block`, and images are globally block elements. Resetting the outer button with `all:revert` does not normalize its children. Moreover, D4 ignores authored typography and colour on native hosts while D7 preserves the web declarations. The JS target usually emits static declarations through classes, not inline as D7 claims. [tags.rs:252](/Users/ccheever/projects/exact2-wt-native-button/contract/lower/src/tags.rs:252), [element.rs:27](/Users/ccheever/projects/exact2-wt-native-button/host/web/src/element.rs:27), [index.html:78](/Users/ccheever/projects/exact2-wt-native-button/host/web/index.html:78), [emit.rs:987](/Users/ccheever/projects/exact2-wt-native-button/host/web-js/src/emit.rs:987).

   **Change:** Define the native tag’s fixed rows explicitly, removing the custom button’s column layout. Specify the DOM face layout, leading/trailing placement, spacing and centering. Separate resetting native chrome from the authored outer box, including `box-sizing`. Resolve typography consistently: honor supported declarations, refuse unsupported declarations, or document the unavoidable deviation in LLP 1001. Logging an ignored declaration does not resolve the cross-host disagreement required by [CLAUDE.md:9](/Users/ccheever/projects/exact2-wt-native-button/CLAUDE.md:9).

3. **Blocker — The glass pass and `ControlHost.sync` would compete for ownership of the button’s parent.**

   Both control hosts unconditionally move a control back under its `NodeView` when it has another superview. The isolation pass moves the glass body into a slot/container and subsequently assumes it remains there. Merely generalizing “material view” to “glass body” lets the next control sync undo isolation; the existing slot may then prevent reconciliation from reinstalling it. [ControlsIOS.swift:114](/Users/ccheever/projects/exact2-wt-native-button/host/apple/Sources/ExactKit/IOS/ControlsIOS.swift:114), [ControlsMac.swift:73](/Users/ccheever/projects/exact2-wt-native-button/host/apple/Sources/ExactKit/Mac/ControlsMac.swift:73), [GlassGroup.swift:272](/Users/ccheever/projects/exact2-wt-native-button/host/apple/Sources/ExactKit/GlassGroup.swift:272).

   D6 also leaves simultaneous native glass and `backgroundMaterial` undefined. The proposed Messages compose consumer already carries `backgroundMaterial="glass"`. Existing group conflicts recognize materials, not native button glass. [app.contract:566](/Users/ccheever/projects/exact2-wt-native-button/apps/messages/app.contract:566), [GlassGroup.swift:101](/Users/ccheever/projects/exact2-wt-native-button/host/apple/Sources/ExactKit/GlassGroup.swift:101).

   **Change:** Define a shared mounting destination and glass-body lifecycle used by both passes, including frame coordinates, style changes, removal and focus preservation. For this slice, refuse same-node material/filter/group combinations on native buttons and put the group on the parent; remove the consumer’s old material. Test isolation across consecutive batches, glass-to-plain changes, clipping, fading and group removal.

4. **Blocker — Reusing the agent’s control activation path weakens button visibility checks.**

   iOS control activation checks window membership, enabled state and inertness, but not hidden ancestors or occlusion. It executes before both the swipe-action availability check and ordinary hit testing. macOS also takes the control shortcut before ordinary hit testing, although it checks hidden ancestors. A native button could therefore activate underneath another view; an authored swipe action could bypass the requirement that its projected action be revealed. [ControlsIOS.swift:159](/Users/ccheever/projects/exact2-wt-native-button/host/apple/Sources/ExactKit/IOS/ControlsIOS.swift:159), [AgentIOS.swift:443](/Users/ccheever/projects/exact2-wt-native-button/host/apple/Sources/ExactKit/IOS/AgentIOS.swift:443), [AgentMac.swift:412](/Users/ccheever/projects/exact2-wt-native-button/host/apple/Sources/ExactKit/Mac/AgentMac.swift:412).

   **Change:** Resolve the active presentation owner before dispatch, then apply that presentation’s visibility and hit checks. Standalone buttons must reject hidden, clipped-away, occluded, disabled and inert targets. Preserve the existing delivery distinction between host activation and synthesized contact, and test exactly one `press`.

5. **Should-fix — A measured leaf does not make its children projection-free data.**

   Apple suppresses creation and updates specifically for `option` descendants. Other children still acquire mirrors/views, while `emit_children` refuses to attach any `Control` children. Linux’s paint walk still traverses children after painting a control. The parent RFC explicitly records that suppressing option projection was necessary. [paragraph.rs:182](/Users/ccheever/projects/exact2-wt-native-button/host/apple/src/paragraph.rs:182), [paragraph.rs:289](/Users/ccheever/projects/exact2-wt-native-button/host/apple/src/paragraph.rs:289), [paint.rs:1099](/Users/ccheever/projects/exact2-wt-native-button/host/linux/src/paint.rs:1099), [1069.001:432](/Users/ccheever/projects/exact2-wt-native-button/llp/1069.001-form-controls.rfc.md:432).

   This also affects naming: Apple’s `accessibleText` walks mounted child `NodeView`s, so the wrapper’s agent-accessible name loses its title when those children disappear. [Accessibility.swift:10](/Users/ccheever/projects/exact2-wt-native-button/host/apple/Sources/ExactKit/Accessibility.swift:10).

   **Change:** Add one kernel `ButtonFace` reader, analogous to `select_choices`, and make the Apple ABI serialize it. Suppress face-child view projection on Apple and ordinary child painting on Linux while retaining logical identities. Use the semantic face for accessibility and agent naming, with explicit refresh on title, symbol and conditional-child changes.

6. **Should-fix — The existing control pipeline has several “everything else is select/checkbox” branches.**

   Both `ControlKinds.indexed` and `ChromeIndex.values` need `type:button`; changing `ControlKinds.kind` alone does not make the host discover buttons. On iOS, configuration, typing, observation and unsupported-menu reporting identify a select by `UIButton`. Linux consumes a generic control press as a checkbox toggle before ordinary `press` dispatch. [ControlKinds.swift:8](/Users/ccheever/projects/exact2-wt-native-button/host/apple/Sources/ExactKit/ControlKinds.swift:8), [ChromeIndex.swift:14](/Users/ccheever/projects/exact2-wt-native-button/host/apple/Sources/ExactKit/ChromeIndex.swift:14), [ValueControlsIOS.swift:23](/Users/ccheever/projects/exact2-wt-native-button/host/apple/Sources/ExactKit/IOS/ValueControlsIOS.swift:23), [surface_controls.rs:512](/Users/ccheever/projects/exact2-wt-native-button/host/linux/src/surface_controls.rs:512).

   **Change:** Expand §4 into an explicit kind-dispatch change covering discovery, creation, configuration, measurement, activation, value typing and observation on both Apple hosts. Distinguish select from button by logical kind, not widget class. On Linux, route buttons to ordinary press handling and reject value typing. Add regressions proving selects remain selects and buttons never emit `input`/`change`.

7. **Should-fix — A “fixed” `type="button"` does not seal the control kind.**

   Fixed props precede authored props, and the lowerer deliberately makes the last binding win. An authored `type="checkbox"` or bound `type` could therefore overwrite the proposed discriminator. `select` avoids this by explicitly refusing authored `type`. [lib.rs:799](/Users/ccheever/projects/exact2-wt-native-button/contract/lower/src/lib.rs:799), [lib.rs:918](/Users/ccheever/projects/exact2-wt-native-button/contract/lower/src/lib.rs:918), [controls.rs:20](/Users/ccheever/projects/exact2-wt-native-button/contract/lower/src/controls.rs:20).

   **Change:** For native buttons, accept only an absent `type` or literal `"button"` and reject every other literal or expression. Add this to D3’s refusals and test it after class expansion.

8. **Should-fix — D4 does not yet define a closed content grammar.**

   “Neither [text nor image] … unless … a symbol” is contradictory, and does not clearly require a label for symbol-only buttons. `when`/`match` also need cardinality rules across complete reachable faces, rather than checks of individual branches. Existing symbol validation examines only a directly literal source. [1069.011:63](/Users/ccheever/projects/exact2-wt-native-button/llp/1069.011-native-buttons.rfc.md:63), [values.rs:509](/Users/ccheever/projects/exact2-wt-native-button/contract/lower/src/values.rs:509).

   **Change:** State that every admitted face contains a title, a symbol, or both; symbol-only faces require an accessible label. Define text-run flattening, whitespace, allowed child attributes and the treatment of child visibility. Refuse actionable descendants. Restrict symbol sources to validated literals or finite validated alternatives for this slice. Make the content diagnostic take precedence over the existing generic empty-button check at [lib.rs:758](/Users/ccheever/projects/exact2-wt-native-button/contract/lower/src/lib.rs:758).

9. **Should-fix — Conditional styleable props can bypass current literal validation.**

   Class merging transforms differing literals into `Expr::Ternary`. Material-name validation only checks `Expr::Str`; glass spacing validation only checks a numeric literal. Thus “both arms contain the prop” does not prevent invalid names or spacing from becoming runtime values. Node overrides already suppress class rows and must continue to do so before the presence rule runs. [class.rs:48](/Users/ccheever/projects/exact2-wt-native-button/contract/lower/src/class.rs:48), [values.rs:482](/Users/ccheever/projects/exact2-wt-native-button/contract/lower/src/values.rs:482).

   **Change:** Generate the styleability predicate from schema metadata, recursively validate the effective expression’s literal alternatives, and define the fallback for an unknown computed `buttonStyle`. Keep the both-arms rule as an explicit first-slice restriction. Do not present clearing as impossible: `ClearProp` already exists, although an intentional optional-prop path would need to avoid the current invalid-value journal entry. [instance.rs:798](/Users/ccheever/projects/exact2-wt-native-button/runner/src/instance.rs:798).

10. **Should-fix — Refusing menu invokers, tabs and toolbar items does not cover other projections.**

    A native button can still be a menu action: menu rows are selected by their `press` handler, but their titles are extracted from child `NodeView`s. Swipe actions similarly obtain their image from a child view. Those children cease to exist as mounted face views under D4. Toolbar membership is determined by the parent declaration, so checking only the button’s own props is insufficient. [MenusIOS.swift:287](/Users/ccheever/projects/exact2-wt-native-button/host/apple/Sources/ExactKit/IOS/MenusIOS.swift:287), [MenusIOS.swift:308](/Users/ccheever/projects/exact2-wt-native-button/host/apple/Sources/ExactKit/IOS/MenusIOS.swift:308), [SwipeActionsIOS.swift:313](/Users/ccheever/projects/exact2-wt-native-button/host/apple/Sources/ExactKit/IOS/SwipeActionsIOS.swift:313), [ToolbarMac.swift:133](/Users/ccheever/projects/exact2-wt-native-button/host/apple/Sources/ExactKit/Mac/ToolbarMac.swift:133).

    **Change:** List supported projection contexts explicitly. Either adapt these consumers to the semantic face and one activation owner, or refuse them. I would exclude menu and swipe-action projections from this slice, alongside tabs and toolbars, and make contextual refusals inspect ancestors and references.

11. **Should-fix — One native button currently makes its entire list row unpoolable.**

    `control` appears in neither the reusable-kind set nor the fresh-heavy-leaf set. Recursive shape construction therefore rejects the whole row. Merely adding it to reusable kinds also fails because the hosted `UIButton` is an unrecognized subview. [NodePoolIOS.swift:86](/Users/ccheever/projects/exact2-wt-native-button/host/apple/Sources/ExactKit/IOS/NodePoolIOS.swift:86), [NodePoolIOS.swift:178](/Users/ccheever/projects/exact2-wt-native-button/host/apple/Sources/ExactKit/IOS/NodePoolIOS.swift:178), [NodePoolIOS.swift:203](/Users/ccheever/projects/exact2-wt-native-button/host/apple/Sources/ExactKit/IOS/NodePoolIOS.swift:203).

    **Change:** Treat native controls as fresh leaves that the surrounding row pools around. Do not add native widget-state reuse in this feature. Verify park/take behavior, stale action cleanup, glass cleanup and focus pinning; reused rows must remain indistinguishable from new elements. [DEFERRED.md:332](/Users/ccheever/projects/exact2-wt-native-button/rules/DEFERRED.md:332).

12. **Should-fix — D5 needs a constrained-size policy, including macOS.**

    Both Apple hosts currently center controls at their natural height; only sliders fill the available width. D5 explicitly changes filling on iOS but leaves macOS ambiguous. The kernel measurement closure substitutes known dimensions into a single intrinsic size; it does not remeasure height under a narrower available width. [ControlsIOS.swift:129](/Users/ccheever/projects/exact2-wt-native-button/host/apple/Sources/ExactKit/IOS/ControlsIOS.swift:129), [ControlsMac.swift:85](/Users/ccheever/projects/exact2-wt-native-button/host/apple/Sources/ExactKit/Mac/ControlsMac.swift:85), [layout.rs:908](/Users/ccheever/projects/exact2-wt-native-button/kernel/src/layout.rs:908).

    **Change:** Specify the control frame on both Apple platforms and what happens to a long title in a constrained box: wrapping, truncation or clipping. Keep natural-size reporting independent of the assigned frame. Add explicit width/height, min/max, padding, border and both box-sizing cases to acceptance, plus title and Dynamic Type changes. The parent RFC makes authored box geometry the parity requirement. [1069.001:157](/Users/ccheever/projects/exact2-wt-native-button/llp/1069.001-form-controls.rfc.md:157).

13. **Should-fix — The proposed web looks lack their colour and material data paths.**

    `accent-color` is emitted as the CSS property; it is not an existing custom property that other declarations can consume. Symbol masks use `--exact-tint`, registered as non-inherited with a black default, so setting a filled button’s text white does not make its symbol white. Material variables are emitted only for `BackgroundMaterial`, and their capability is linked only when used. [css.rs:415](/Users/ccheever/projects/exact2-wt-native-button/host/web/src/css.rs:415), [symbols.js:9](/Users/ccheever/projects/exact2-wt-native-button/host/web-js/symbols.js:9), [element.rs:85](/Users/ccheever/projects/exact2-wt-native-button/host/web/src/element.rs:85), [1053.000:82](/Users/ccheever/projects/exact2-wt-native-button/llp/1053.000-backdrop-filter.rfc.md:82).

    **Change:** Specify static and dynamic accent resolution, including inheritance, `auto`, light/dark colours and symbol tint. Extend capability selection for glass button styles without charging unused apps for the material table. Emit the default style marker even when `buttonStyle` is absent. Verify conditional `buttonStyle` on the JS target: its dynamic prop-name probe constructs a bare node without the button’s `type`, so a type-dependent attribute mapping can fail. [style.rs:376](/Users/ccheever/projects/exact2-wt-native-button/host/web-js/src/style.rs:376).

14. **Nit — The fallback logging policy copies a stale materials-table comment.**

    D2 proposes logging known stand-ins once. The accepted materials policy explicitly makes known stand-ins silent and reports `{name, drawn, standIn}`; only unknown computed names are logged. The schema comment still says otherwise. [1053.000:29](/Users/ccheever/projects/exact2-wt-native-button/llp/1053.000-backdrop-filter.rfc.md:29), [schema.json:3082](/Users/ccheever/projects/exact2-wt-native-button/kernel/tables/schema.json:3082).

    **Change:** Follow the accepted policy. Make the button table enumerate every mapping and OS fallback, and expose requested versus actually drawn style in `native.control`. A requested `"glass"` alone cannot establish whether the control actually draws glass or a bordered fallback.

I would cut the future bare-button-default discussion, raster images, subtitles, additional menu/toolbar/tab/swipe projections, native widget-state pooling, and any dependency on 1075’s hooks from this implementation. I would also remove routine warnings for known approximations. Keep the opt-in, bounded face, schema table, styleable props and existing agent operations; add the integration and behavioral acceptance cases above before building.
