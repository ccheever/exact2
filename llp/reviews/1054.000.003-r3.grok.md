## Assessment

r3 does what §0 claims against the tree: the D8 seam matches the router (`RunnerLinks` function pointer, `ALL` at bake and native boot, web `Linked` + `admit`), `calendarDiff`/`formatDuration`/`integer` are gone, compact uses `trunc` + `signDisplay: "negative"`, TimeClip and `""` for non-finite input are consistent, and Bluesky’s admitted call sites now cover the four remaining entries. The live-label design is the right shape for this runner — one `label_due` chained into `timer_due_ms`, two extra dep bits beside the clock, agent `clock +N` driving it, hosts already scheduling on that due — and Charlie’s static/live/granularity request is actually designed, not bolted on. The spec still underspecifies the four-place dep invariant, names the wrong commit primitive for a timer-less wake, and couples `"static"` to the minute spelling; those are the changes to make before building. Quoted `Intl` strings match Bun 1.4.2 / ICU 78.1 (U+0020 in `1:02 PM`, compact `999K`/`1B`, DurationFormat `42s`/`5m`/`3h`/`6d`).

## Concerns

### MATERIAL — Label wake must call `commit_again`, and `until_request` has to define when that step runs
`recommit` returns `Ok(None)` when `which` is empty (`runner/src/runner/settlement.rs:50-58`). A clock jump with no authored timer that then calls `recommit([], …)` never updates the tree, so `"minute"` labels stay frozen until something else commits. The existing primitive that settles and updates with nothing asked is `commit_again` (`settlement.rs:63-79`). `advance_until_request` (`commit.rs:145-147, 283-286`) also breaks out of the same loop the extra step is supposed to follow; if that step still runs and a live call sits in resource arguments, the follow-up settle can drop the request the stop was meant to preserve (LLP 1016 D5).

**Resolve:** After the timer loop, call `commit_again(vec![], "labels")` only when `label_due <= landed` *and* the advance did not already stop for a send. Name `commit_again` in D5. A crossed deadline on a request-stopping advance is absorbed by the reply commit, which already settle-bumps.

### MATERIAL — `Input` / `Seen` / `Settled` / `Layout` are a four-place invariant D5 does not name
Today `Layout::width` is `clock() + 1` (`deps.rs:72-77`), `inputs()` maps every bit at or after clock to `Input::Clock` (`deps.rs:272-280`), `unchanged` compares only `now_ms` for that input (`settlement.rs:202`), and `changed` / `Seen` only snapshot `now_ms` (`deps.rs:350-352, 419-427`). Adding `wall` and `labels` after the clock bit without new `Input` variants makes live calls look clock-dirty on every 250 ms Bluesky `settle` (`app.contract:499-500`). That re-evaluates every mounted label four times a second, which is the cost D5 exists to avoid. The tests as written count label *commits*, which stay quiet if the timer commit itself re-evals.

**Resolve:** Add `Input::Wall` and `Input::Labels`, extend `Seen` and `Settled`, and compare them the way `Clock` is compared. Add a test that `advance(250)` with `label_due` at 60_000 does not re-evaluate live label sites (a derive whose body is one `formatRelativeTime` call is enough: `derives_evaluated` stays 0 after the checkpoint reset in `commit.rs:34`).

### MATERIAL — `"static"` is defined as “minute spelling, no `labels` bit,” which collapses Charlie’s two axes
D4 puts `"minute"` and `"static"` in one column, so a 42 s-old static label is `now` and stays `now` until remount or `thenMs`/`wall` change. Charlie asked for static-vs-updating *and* granularity. Remount-refresh itself is well-defined and matches LLP 1068 (a row that scrolls back in is a new instance; only mounted rows eval and report). The missing sentence is whether static is a snapshot of the *true* delta (including `42s`) or a cheap untimed `now`/`5m`/`3h`.

**Resolve:** Either state that `"static"` always uses the minute table (frozen seconds refused until a caller), or make update orthogonal to spelling: `"static"` means “do not read `labels`,” and the unit table is the second-column one when the author wants a frozen `42s`.

### MATERIAL — D5’s mode scan is load-bearing and specified as “the literal before the Call”
D9 is an AST check (precedent `path()`, `contract/types/src/routes.rs:158-163`). Lowering of an inlined `fn` (`contract/lower/src/expr.rs:216-257`) does emit `Str "minute"` immediately before `Call`, so a previous-instruction scan works for the examples. `uses()` today never walks `Call` at all (`runner/src/uses.rs:116-179`); D8’s “one pass of `vm::instructions` over `plan.code`” is new and must walk each body’s range, because `instructions` stops at the first malformed opcode (`vm.rs:412-425`). A missed `"static"` marks a live call, and a missed `"minute"` never wakes.

**Resolve:** Specify: D9’s literal lowers to `Opcode::Str` immediately before `Call`; the deps scan looks that instruction up in the string pool; `uses()` unions `Call` of the three capability names over every code range. Test a wrapper `fn ago(t: number): string = formatRelativeTime(t, "narrow", "minute")` (inlined) as live, and a `"static"` call as silent under `clock +3600000`.

### MATERIAL — Label machinery is core and counts against `WEB_CORE_KIB`
D5’s deadline, two dep bits, settle bump, and extra advance step live in the runner even when `label_due` stays `∞`. Bodies are the linked `format` capability; the wake path is not. Video-player’s ceiling is 240 KiB brotli (`scripts/metrics.mjs:755-756`). The RFC says those ceilings stay the gates.

**Resolve:** Measure video-player / RealWorld core in the landing change. If D5 pushes a ceiling, raise it in the same PR with the reason, as `metrics.mjs` already requires.

### MINOR — Env-site list is wrong in one slot and incomplete in another
D8 lists `canvas2d.rs:665` as a runner `Env`. That literal is canvas-2D’s `Env` (`canvas`, `text`, `images`). Runner `Env` literals are `runner.rs:1152` (the helper used by actions *and* `Update::new`), `settlement.rs:276` and `:346`, `instance.rs:381` (spread), three `vm.rs` tests, and `instance/collection/tests.rs:96`. Action eval goes through `self.env` (`commit.rs:387-388`). If that helper always carries the label `Cell`, actions report dues D5 said they would not.

**Resolve:** Thread `format` / `wall` / the cell through the helper for settle and tree update; pass a dead cell from `run_action_inner`.

### MINOR — Printed examples omit the `shape`s that make the byte counts true
As pasted, both snippets fail `type-unknown` on `Time` and `Post`. With those shapes, the “today” program is exactly `1 slot, 1 derive, 2 resources, 1091 bytes`. The r3 stand-in (correct `fn f(…): string =` syntax, empty bodies) is 1193 bytes, not 1170. `style` as a parameter name is refused (`syntax-expected-name`); `fn formatClockTime` is refused (`contract-fn-shadows-roster` at `contract/types/src/lib.rs:961-971`). The r2 `when` bug is gone.

**Resolve:** Paste the shapes in the RFC. Recount the r3 stand-in.

### MINOR — A few citations and one consumer fact are stale
- `settlement.rs:266` is the `unchanged(…)` *call*; the clock arm is `:202`.
- Bake boot is `contract/cli/src/lib.rs:526` (`Runner::boot` → `RunnerLinks::ALL` at `runner.rs:422-423`).
- Bluesky’s `every(30000, tick)` writes `ticks`, which nothing reads. The minute clock is `floor(now() / 60000)` and already moves because `every(250, settle)` commits. Harmless for D5 (that 250 ms timer absorbs label wakes, as the RFC says).
- Motivation quotes `Sep 26, 2026 at 1:02 AM` from Bluesky’s comment; Bluesky’s own test and Intl for `2026-09-26T13:02:00Z` are `1:02 PM` (`fmt.rs:273-274`; Bun prints U+0020).

### MINOR — Year-1 oracle row
`Date.UTC(1, 0, 1)` is 1901. `Date.parse("0001-01-01T00:00:00.000Z")` formats as `Jan 1, 1`. The Rust table should use civil-from-days / that ISO parse.

## Suggestions

- Name `commit_again`, `Input::Wall` / `Input::Labels`, `Seen`, `Settled`, and `Layout::{wall,labels}` in D5 the way D8 names `RunnerLinks.format`.
- Compiler: refuse `formatRelativeTime` in resource arguments (the footgun D5 only documents). The whole point of this RFC is that feeds stop taking a clock.
- Scan `timer_due_ms` in tests rather than computing unrounded boundaries; D5 rounds due times up to a whole second.
- Put `format` on `Capability::ALL` and in `web_linked`’s no-export arm (`logic.rs:130`) in the same change; a missing match arm will not compile.
- Keep `formatTime` in core replacing `formatClockTime` in place in `format.json` so later stdlib wire ids move only as far as the one digest bump already requires.
- Driven Bluesky test is the right fixture (`EXACT_APP_DIR`, `clock +60000`, no `query` for a feed). Keep the 250 ms `settle` timer in that drive; removing it is 1058’s problem.

## Answers to r3’s open questions

1. **Keep the third argument.** Roster arity is fixed, so `"minute"` will be written anyway; `"narrow-second"` mixes spelling with update policy. The compiler already has to see a literal for D5’s scan.
2. **`"minute"` is the right default.** It matches Charlie’s “probably not” on live seconds and is what an “ago” column claims. Bluesky’s port currently prints `42s` (`fmt.rs:131-132`, test at `:250`). If the feed should keep that, those five `ago` sites pass `"second"`; everything else can stay `"minute"`. Do not make `"second"` the roster default for a few feed rows.
3. **Remount-refresh is the right `"static"`.** Per-row freeze until data changes needs state D5 is right to refuse, and it fights LLP 1068. Say so in D4, and decide the spelling question in the MATERIAL item above (minute table vs true-delta snapshot).
4. **Drop `"long"` until RealWorld migrates in the same change.** `apps/realworld/app.ts:23-25` is already `September 26, 2026`, which is `dateStyle: "long"` in `en-US`, but the fixture rule is a call site in Contract. Adding the style for a TypeScript helper that does not move is the r2 fixture miss again.
