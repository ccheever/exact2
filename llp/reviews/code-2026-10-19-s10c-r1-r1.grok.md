## Blocking

**Rejected `CLIENT` lines bypass the 64-socket guard and the backoff, and each one sends the bearer token again.** `scripts/tamber-relay.mjs:134-140` marks the control connection handed and calls `fill()` before `client()` runs. `scripts/tamber-remote.mjs:351` then destroys any SNI other than the tool name, including the canvas name this commit is supposed to leave closed. `down()` only backs off when `handed` is still false (`scripts/tamber-relay.mjs:110-112`), so the reject path never waits. A local relay sending `CLIENT other.example …` produced **1408 outbound TLS handshakes in 400 ms**, each one writing `authorization: Bearer …` (`scripts/tamber-relay.mjs:117`). `close()` does stop it. The same loop happens with an honest relay: the canvas name is published in Certificate Transparency, and every connection to it is a rejected SNI. A `READY` also sets `wait = 250` (`scripts/tamber-relay.mjs:129`), so a relay that greets and then drops never backs off past 250 ms either.

## Should-fix

- **Relay-supplied strings are not bounded or sanitized, and they reach logs and the admitted origin.** The 1024-byte cap runs only on the leftover buffer (`scripts/tamber-relay.mjs:143`). A line that already contains `\n` is taken whole: a probe got a **5012-character** `READY` name and an address of `1.2.3.4\rINJECTED`. That name becomes the origin, the `Host` allow-list, and the peer (`scripts/tamber-remote.mjs:342`, `scripts/tamber-remote.mjs:359-361`). The address is `access.reported` and is logged, CR included, 64 characters at `scripts/tamber-server.mjs:652`. The peer is logged in full on pair and on burn (`scripts/tamber-server.mjs:461`, `scripts/tamber-server.mjs:652`). A greeting `REFUSED` logs 200 characters of the reason (`scripts/tamber-relay.mjs:126`), so a relay that echoes the bearer token puts it in the log.

- **`REFUSED` after `READY` does not revoke the session.** It is handled as a bad `CLIENT` and destroys only that socket (`scripts/tamber-relay.mjs:133`). `stop()` runs only when `REFUSED` is the greeting (`scripts/tamber-relay.mjs:126-127`). The other pooled streams stay up, and the connector dials again.

- **A control connection has no deadline.** The token is sent on `secureConnect` (`scripts/tamber-relay.mjs:116`). A relay that finishes TLS and then sends nothing holds the pool slot until process exit. The 1024-byte cap covers only a header that keeps growing.

- **`--allow-plugin-origin` is wired to the relay door.** `scripts/tamber-remote.mjs:342` passes `plugin`. The `--remote` TLS door does not (`scripts/tamber-remote.mjs:304`). With the flag, `Origin: null` gets CORS on the public name. `docs/tamber-protocol.md:203-210` says a sandboxed page is never answered on the TLS door.

- **The relay private key is read with no mode check** (`scripts/tamber-relay.mjs:56`). The token file is refused unless mode is owner-only (`scripts/tamber-relay.mjs:52`).

- **The canvas gate trusts the relay’s `CLIENT` SNI, not the ClientHello.** A lying relay can label a canvas connection with the tool name. TLS is then terminated and the real `Host` is answered (404), which is an answer. An honest relay is closed, and the test covers that path.

## Nits

- The pairing bucket is safe against a client-chosen peer. `admit` uses `startsWith('relay:')` (`scripts/tamber-pairing.mjs:252`). The relay door sets `relay:${tool}` itself; other doors use `socket.remoteAddress`. `reported` is not the peer. The local token stays unused: `access.local` is false, and `/__tamber/token` is not in `WIRE`.
- The client-facing TLS socket is as strict as `--remote` on this runtime. `createSecureContext({ minVersion: 'TLSv1.2' })` plus `TLSSocket` (`scripts/tamber-remote.mjs:343`, `scripts/tamber-remote.mjs:352`). A probe negotiated TLS 1.3, selected no ALPN, and completed with no client certificate. Neither door sets ALPN. Plain HTTP after `CLIENT` did not reach the wire. A certificate for the wrong name failed with `ERR_TLS_CERT_ALTNAME_INVALID` and the token was not sent. There is no insecure flag.
- A `CLIENT` line in the same chunk as `READY` is dropped when names come from the relay: `client()` runs synchronously (`scripts/tamber-relay.mjs:140`) and `names` is assigned in the `ready` microtask (`scripts/tamber-remote.mjs:359`).
- The tests would fail if TLS were skipped, the token were sent to a bad certificate, or the relay shared the direct pairing bucket. They would still pass with the redial storm, the line-length bypass, and a `reported` value containing CR.

Checked and holding: WebPKI on the outbound dial, token not placed in a URL, cookies stripped in `remoteHandler`, and `close()` stops further dials.
