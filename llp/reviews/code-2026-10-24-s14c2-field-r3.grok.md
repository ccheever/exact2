## MAJOR

**`all` still overrides `fill-rule` and the lint records the other rule.** `contract/lower/src/icon_svg.rs:156`

`style_refused` (`icon_svg.rs:136`) only rejects quotes, backslashes, comments, braces, and `@`. `property` then reads a declaration only when its name is the property it was asked for. `all` is a plain declaration, so both let it through, and a presentation `fill-rule` (or an inherited one) wins in the linter.

```xml
<svg viewBox="0 0 24 24"><path fill-rule="evenodd" style="all:initial" d="M0 0h4v4H0Z M1 1h2v2H1Z"/></svg>
```

```xml
<svg viewBox="0 0 24 24" fill-rule="evenodd"><g style="all:initial"><path d="M0 0h4v4H0Z"/></g></svg>
```

Both are accepted as even-odd templates. In CSS, `all:initial` resets `fill-rule` to `nonzero`, and `all:inherit` / `all:unset` take the parent's rule; the style attribute beats the presentation attribute. The same is true of `fill-rule:evenodd; all:initial`. `fill-rule:initial` itself is already refused (`icon_svg.rs:327`); this is the shorthand that skips that check. The shipped marker and `iconFillRules` then follow the wrong rule.

Fix: when walking declarations, refuse a name that is `all` (any case) with the existing `FIX_STYLE`.

**An even-odd template with no SF Symbol is sent to Apple as no path.** `host/apple/src/icon_path.rs:16`

`commands` drops any symbol whose `even_odd` is set:

```16:16:host/apple/src/icon_path.rs
    let path = exact_kernel::symbol_path(name).filter(|p| p.filled && !p.even_odd)?;
```

`symbol:icon||0 0 24 24|evenodd:M…|icons/ring.svg` has an empty SF name, so the first guard does not return, and the filter then returns `None`. Linux (`host/linux/src/raster.rs:760`) and the web mask draw that path even-odd. The build still accepts the template for Apple (`contract/lower/src/icons.rs:87`), and `push_json` writes no `symbolPath`. The face is blank. This is separate from the known `icon_name` / `i.path.0` break.

Fix: send the path and a fill rule Swift already understands (`eoFill` / `.evenOdd`), or refuse the icon at build for Apple targets. Do not return `None`.
