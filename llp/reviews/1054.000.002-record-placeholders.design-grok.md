## Design (verbatim)

I'll read the rules, the LLP map, and the record-placeholder RFC first, then check the placeholder implementation and the RealWorld and Bluesky consumers against the code.The RFC is a placeholder-shape problem, not a new data source. Next I’ll read D6 and the settlement, type-check, and lowering code that already implement placeholders.## 1. Summary

Every resource whose type is a plan value gets the structural zero as its stand-in, the way a list already shows `[]` and an option already shows `none`. While that stand-in is up, `pending(r)` is true, the value is not stored as `initial`, it is not kept, and it is not carried. A few non-zero fields are a same-line patch, `else empty { image="/assets/default-avatar.svg" }`, compiled to the existing `<name>#else` row. Anything computed stays `else source(args)`. No record literals, no shape defaults, no new request path.

## 2. Surface

A resource is still one line. After `as shape T`, `else` is optional:

```
resource name = source(args) as shape T
resource name = source(args) as shape T else empty
resource name = source(args) as shape T else empty { path=literal, path.field=literal }
resource name = source(args) as shape T else source(literals)
```

`else empty` and `else empty { }` are the zero. A patch is `name=value`, the same spelling as a named argument (`contract/syntax/src/parser.rs:1264` rejects `name: value`). A path is field names separated by `.`. A value is a literal: string, number (a leading `-` on a number is part of it), `true`, `false`, `none`, or `some` of one of those. `else empty(` is still a source call named `empty`, because `(` is what a call has today (`parser.rs:713`).

RealWorld (`apps/realworld/app.contract:129`) becomes:

```
resource me = currentUser() as shape User
resource tags = popularTags(current.name == "home" or current.name == "tag") as shape list<string>
resource feed = articles(listKind, current.params.tag, listName, page, me.username) as shape Feed
resource post = article(slug, me.username) as shape Article
resource thread = comments(slug, me.username) as shape list<Comment>
resource person = profile(listName, me.username) as shape Profile else empty { image="/assets/default-avatar.svg" }
```

`person.image` is the one stand-in the view draws with no `found` gate (`app.contract:1077`). `me.avatar` is drawn only inside `when me.signedIn` (`app.contract:338`), and the zero `signedIn` is false, so `me` needs no patch. The logged-out user is still `currentUser`'s answer, the constant in `app.ts:73`. `post` is gated by `when not post.found` (`app.contract:917`). `emptyFeed` (`app.ts:77`) is already the zero.

In `app.ts`, delete the four placeholder keys `anonymous`, `emptyFeed`, `emptyArticle`, `emptyProfile` (`app.ts:145`). Keep the constants. `articles`, `article`, `profile`, and `currentUser` return them as answers.

Bluesky's seven clauses (`app.contract:49`, `:91`, `:102`, `:113`, `:114`, `:125`, `:133`) delete `else emptySession()` and the rest. Each arm in `data/src/values.rs:207` is the zero when called the way the contract calls it (`else emptySearch()` passes no arguments, so `query` is `""`). `homeFeeds` and `authorFeeds` are `list<Feed>` (`app.contract:76`, `:89`) and already show `[]`. `emptyFeed` (`values.rs:211`) is not a resource clause. It echoes argument 0 and sets `more: true` on a `Feed`, and nothing in `app.contract` names that source. Drop the `empty*` arms and the `source.starts_with("empty")` fast path (`data/src/lib.rs:272`). A future record that needs `more: true` while pending writes `else empty { more=true }`.

## 3. Semantics

The zero is one function of the plan type. Shapes are finite trees (`type-shape-recursive`, `contract/types/src/checks.rs:360`). The walk uses the decode depth cap of 64 (`plan/src/value.rs:200`) and returns nothing past it.

| Type | Zero |
|---|---|
| `number` | `0` |
| `bool` | `false` |
| `string` | `""` |
| `unit` | unit |
| `option<T>` | `none` |
| `list<T>` | `[]` |
| record | each field's zero, declaration order |

A nested record is a record of zeros. `Article.author` is a `Profile` whose `found` is false and whose `image` is `""`, not `none`. A list field is `[]`. The element type is not built, so a `list<Post>` does not construct Bluesky's `Post` (`shapes.contract:74`). An option field is `none`. The inner value is not built.

Lists and options do not change. Their zero is the value `placeholder` already returns (`runner/src/runner/settlement.rs:86`). A declared `else source()` on a list still replaces `[]`.

A patch replaces leaves of that zero. `author.image="/assets/default-avatar.svg"` leaves `author.found` false. The patched value is fixed for the launch. It does not read state and does not copy the resource's arguments. That is the same rule as `type-placeholder-reads` (`contract/types/src/component.rs:233`): a placeholder is answered once. Bluesky never passed a live feed id. `else emptyFeed(id)` is not in the contract, and `else emptySearch(activeQuery)` would be `type-placeholder-reads` because `activeQuery` is a derive.

The stand-in is chosen only when nothing else applies. The order already in settlement stays:

1. A kept value for these arguments shows, and the request stays in flight (`settlement.rs:489`, LLP 1016 D3). A refresh does not flash back to zero.
2. A compiled `initial` whose `initial_args` match is the bake's answer. It stands. `pending` is false (`settlement.rs:401`).
3. Otherwise the stand-in shows and `pending(r)` is true.

A baked answer and a stand-in can be the same bytes. `pending(r)` is the difference, as it already is for `[]`. The stand-in is not written to `resources.initial`, not passed to `keep_answer` (that runs only on `Answer::Now`, `settlement.rs:477`, and on fulfill), and not carried.

`pending(r)` reads `pending_res` (`runner/src/vm.rs:676`). After the pass, that flag is the in-flight tickets plus the awaiting rows (`runner/src/runner/commit.rs:596`). The agent `state` operation prints the resource's current value under `resources`, field names included (`runner/src/agent.rs:509`), and lists `pending` only for tickets (`agent.rs:522`, `commit.rs:645`). While a module has not loaded there is no ticket, so `state.pending` omits the name and `pending(r)` is still true. That split already exists. This design does not add a field to `state`.

Runner-owned sources (`exactDelivery`, `exactViewport`, `exactSurface`, `exactTime`, `plan/src/lib.rs:564`) answer in `query` before the stand-in branch (`runner/src/runner.rs:1097`) and are excluded from the awaiting branch (`settlement.rs:439`). Their zeros, when they answer zero, are answers. `pending(time)` stays false when `epochAtZero` is 0. Bluesky's clock test stays `time.epochAtZero > 0`.

**Boot, before the first answer.** The source returns `Later`, nothing is kept, and no `initial` matches. The stand-in shows, `pending_res` is set, and the request is enqueued (`settlement.rs:512`). The stand-in does not swallow that request. If the bake already answered these arguments, step 2 applies and no request goes out.

**Awaiting module.** `data.ready()` is false and the source is not runner-owned (`settlement.rs:435`, LLP 1027 D4). With no applicable `initial`, the stand-in shows, `stale` and `awaiting` are set, and nothing is asked. `data_ready` asks the current arguments (`runner/src/runner/kept.rs:128`). A matching baked answer still stands, including a store reader's empty-store `initial` (`format.json:1009`, the adoption branch above the stand-in). That reader value is the bake's data. The structural zero is used when that `initial` is absent.

**Failed request.** `fulfill` asks the source to parse the outcome (`commit.rs:707`, LLP 1016 D4). `Answer::Now` replaces the stand-in and clears pending. RealWorld and Bluesky already shape a failure into a record with `ready` or `found` and a message. The stand-in is not a failure screen. `Answer::Later` keeps the current value and sends one more request. A parse error restores the checkpoint taken before the ticket was removed (`commit.rs:680`), so the stand-in and the ticket remain.

**Carried reload.** `carry` drops a resource that is pending or stale (`runner/src/runner.rs:440`). A stand-in is one of those, so the next boot does not see it as an answer and issues the first request again, unless a baked `initial` applies. A settled answer whose name, source, and shape still match is carried (`runner.rs:646`) and reused. A document checkpoint uses the same split (`runner/src/runner/checkpoint.rs:98`): runner-owned rows are omitted, stale rows are pending, and a value is an answer only when `pending_res` is false.

## 4. Implementation

**Syntax** (`contract/syntax`). `Placeholder` becomes an enum: `Source { source, args, span }` as today, and `Empty { fields, span }` where each field is a path of idents plus an `Expr`. The parser, after `else`, takes `empty` not followed by `(` as `Empty`, then an optional `{ path=expr, ... }` on the same line. `else source(` is unchanged. `spans.rs` moves `Placeholder` from the struct list to the enum list. `fmt` stays source-preserving. It needs no new break rule. A long resource line is already one line.

**Types** (`contract/types`). `Source` keeps `type-placeholder-reads` and `record_source`. `Empty` does not record a source. Each patch is rejected if it contains a name, a call, or a template hole. The expression is then inferred in an empty scope and unified with the field type. A path walks record fields only. A step through a list or an option is an error. The resource type must be a record when the brace list is non-empty. Bare `else empty` on a list, an option, a string, a number, a bool, or unit is accepted and means the zero.

**Lower** (`contract/lower`). `Source` still appends `<name>#else` (`contract/lower/src/lib.rs:470`). `Empty` with no patches lowers nothing. The runner builds the zero. `Empty` with patches builds `Value::zero`, writes the leaves, and appends `<name>#else` whose source is `exactPlaceholder`, whose arguments are empty, whose type is the resource's type, and whose `initial` is the patched value. `PlanBuilder::resource` already pairs a non-empty `initial` and empty arguments with an empty `initial_args` list (`plan/src/builder.rs:389`). The row is not entered in the seam's source table, so it does not appear in the TypeScript `SourceMap`.

**Plan.** `Value::zero(plan, ty) -> Option<Value>` lives in `plan/src/value.rs` beside `conforms`. Both the runner and lower already depend on `exact-plan`. `runner_owned_source` gains `exactPlaceholder`. The `resources.placeholder` comment (`format.json:174`) is updated: `None` means the zero of the type, and a row is a declared `else source()` or a patched `else empty { ... }`. The codec does not change, so `formatVersion` stays 5. The digest hashes the file (`plan/build.rs:247`), so the comment change invalidates baked plans and they rebuild. Plan validation of a placeholder row is already "another row, same type, no placeholder of its own" (`plan/src/lib.rs:257`) and accepts this row.

**Bake** (`contract/cli/src/lib.rs:545`). Skip `initial` when the resource is pending after boot, not only when it holds a ticket. Expose `Runner::resource_pending(name)`, which reads `pending_res` after `sync_pending_flags`. The reader flag is still set first. A stand-in shown because the bake's source was not ready has no ticket today (`commit.rs:645`), and writing it as `initial` would make the next boot treat it as an answer (`settlement.rs:401`). A source that answered `Now` is not pending, and its value is still compiled. That includes a zero the source really returned.

**Runner.** `placeholder`'s `None` arm calls `Value::zero` instead of matching list and option (`settlement.rs:82`). The declared-row arm is unchanged. `query` answers `exactPlaceholder` from `initial`, or from `Value::zero` if `initial` is empty, and does not call the data source. `adopt` skips that source name so the app is not told about it. No other branch changes. Kept value, then `initial`, then stand-in. Awaiting and `Later` already set `pending_res`.

**Diagnostics.**

| Id | When | Message |
|---|---|---|
| `syntax-placeholder` | `else` is not `empty` and not a call | `` `else` needs `empty`, `empty { field=value }`, or `source(arguments)` `` |
| `type-placeholder-value` | a patch is not a literal | `` `person`'s placeholder sets `image` from `me.avatar`: a patch is a literal, `none`, or `some` of one `` |
| `type-placeholder-field` | unknown field, or a step through a non-record | `` `post`'s placeholder sets `author.image`, and `author` is `option<Profile>` `` |
| `type-placeholder-type` | literal does not unify | `` `person`'s placeholder sets `image` to a number, and `image` is a string `` |
| `type-placeholder-dup` | one path twice | `` `person`'s placeholder sets `image` twice `` |
| `type-placeholder-shape` | braces on a non-record | `` `tags`'s placeholder sets `n`, and a list has no fields `` |
| `type-placeholder-reads` | unchanged | a source placeholder's argument reads state |

The boot refusal `declare a placeholder, resource {name} = … else source()` (`settlement.rs:109`) remains for a zero that could not be built (depth) and for a placeholder row whose own source answers later (`settlement.rs:105`, the message `a placeholder answers now`). A normal record, string, number, or bool no longer refuses. `contract/cli/tests/it/placeholder.rs:195` changes from "boot refuses" to "boot shows `{id:"", title:""}` and `pending(post)`". The corpus's `else emptyPost()` and the "placeholder answers later" test stay.

**Existing `else source()`.** It compiles, bakes, and runs as it does now. The compiler does not rewrite it and does not warn. Delete a clause when the source returns the zero. Rewrite it to `else empty { ... }` when the difference is literals. Keep it when the value is computed from constant arguments. RealWorld and Bluesky, as above, are deletions plus one patch. Their answer-side constants stay.

## 5. Alternatives considered and why rejected

**Opt-in `else empty` on every record.** This keeps a line on all seven Bluesky resources and on RealWorld's `me`, `feed`, and `post`, and it keeps the boot refusal for anyone who forgets the line. Lists and options are already implicit (`settlement.rs:86`). The refusal exists because a record had nothing defined (`1048.003` D6). The zero defines it. Constraint 5 allows that in place of the refusal.

**A `<name>#else` row for every record, holding the zero.** That reuses the row, and it adds a resource, a bake adoption, and an agent-state entry per record. Bluesky would gain seven rows whose value is the zero the runner can build from the type. Rows stay for the case that is not the zero: a patch, or `else source()`.

**Shape field defaults.** Contract does not construct records. A default would affect only the stand-in, while reading like a default of every answer. The data crate would still hand-build values. No second use.

**Record literals in Contract.** A general `{ image: "..." }` value needs an expression form, inference, and VM construction, for one constant the lowerer can already write into `initial` with `PlanBuilder::data`. The patch spelling matches named arguments and stops there.

**Copying a live argument into the stand-in** (`id` from the resource's arguments, `emptyFeed`'s feed id). Those arguments read state. D6 forbids that, and the value would change when the arguments change, so it cannot be the baked row. The port does not declare this case.

**Leaving non-zero fields on `else source()`.** RealWorld's profile image is on screen during pending (`app.contract:1077`). One literal patch removes that source key. A source function for one string is the boilerplate this RFC is for.

**A new `stand_in` bytes column.** The placeholder row's `initial` is already that column. A new codec is a format change for a path that exists.

## 6. Risks and open questions

A view that treats `ready: false`, `""`, or `0` as a finished empty result will show that during pending unless it also reads `pending(r)`. Bluesky's screens branch on `.ready`, which the zero leaves false. RealWorld passes `loading=pending(feed)` and `pending(post)`. A record with neither a flag nor `pending(r)` shows blank fields. That is the same record the hand-written empties returned, now produced without a source.

`Article.author.found` on the stand-in becomes false. Today's `emptyArticle` sets it true by reusing `author()` (`app.ts:63`, `:78`). The article page and the editor do not read `author` while `found` is false. The editor's title, description, and body are `""` in both values.

String, number, and bool resources are included, because the zero function is the whole rule and `meAvatar`, `unread`, `theme`, and `hasNew` are those types. They change only in the case that refuses today: `Later`, nothing kept, no matching `initial`. They then show `""`, `0`, or `false` with `pending` true. Narrowing the arm back to records, lists, and options is a few lines if that refusal should keep teaching on scalars.

A source that answers `Now` is an answer even when its arguments are stand-ins. `pending` does not travel through it. `loads` already computes from `homeFeeds` while that list is `[]`.

`state.pending` still omits an awaiting stand-in that has no ticket. `pending(r)` does not. Changing the agent JSON would invent a ticket-less entry. Left as it is.

`exactPlaceholder` must not reach the app. `query` returns the constant, and `adopt` skips the name. A later edit that sends the name to `answer` would surface an unknown source at boot.

The `format.json` comment changes `FORMAT_DIGEST`. Old plans fail the digest check and rebuild. `formatVersion` stays 5.

The deferred compile error in D6 ("waits for stage labels") should not be added for types that have a zero. A placeholder source that answers later still refuses at boot.
