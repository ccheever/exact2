- **should-fix — The guard mishandles early responses and pipelining.** [scripts/tamber-remote.mjs:175](/tmp/rv-b-3/scripts/tamber-remote.mjs:175).
  An early 404 can finish before its request body ends: `finish` arms the next deadline, then that request’s later `end` cancels it. The next keep-alive request gets no new absolute deadline. Unread input is drained after an early response in [Bun’s implementation](https://github.com/oven-sh/bun/blob/744846f84/src/js/node/_http_server.ts#L2996-L3032).

  Conversely, pipeline two complete requests, with the second awaiting a long poll or holding SSE open. Both request `end` events clear the timer; the first response’s `finish` then rearms it and cuts the second response after ten seconds.

  **Fix:** track the current receive deadline and outstanding responses per connection. An earlier request must not cancel a later deadline, and a completed response must not start an idle timer while another complete request is being answered. Add both event-ordering regressions on TLS and tunnel listeners; the current delayed-response test always consumes the body first.

- **should-fix — Unexpected IPv6 bind failures are silently accepted.** [scripts/tamber-remote.mjs:229](/tmp/rv-b-3/scripts/tamber-remote.mjs:229).
  Every error except `EADDRINUSE` is treated as absent IPv6, including permission or resource failures. Startup can announce success without reserving `::1` even when IPv6 exists.
  **Fix:** ignore only errors establishing that IPv6 loopback is unavailable; close partial listeners and rethrow other failures with the flag/address diagnostic.

- **should-fix — The earlier wasm shutdown finding remains.** [host/web/dev.mjs:985](/tmp/rv-b-3/host/web/dev.mjs:985).
  Remote-bind failure calls `stop()`, which awaits children without closing the main HTTP listener. It continues serving throughout cleanup, potentially for seconds.
  **Fix:** stop the main listener, its IPv6 companion, and accepted connections before awaiting children; preserve the existing failure exit code.
