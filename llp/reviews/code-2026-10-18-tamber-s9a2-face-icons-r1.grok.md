# Review round 1, LLP 1121 stage 9 A2 (Apple's control faces draw icon paths), Grok 4.7 (xhigh)

**RIGHT WITH CHANGES.** The token, the host JSON, and the face sites that already tint a template image are sound. An unsaid svg-only icon on an iOS button is not tinted as an SF Symbol is, which breaks the ruling this commit is there to implement.

1. **BLOCKING** `host/apple/Sources/ExactKit/IOS/ButtonConfigurationIOS.swift:234`. An unsaid path is installed at line 228 and then skipped by the tint block. That block runs only when the symbol's `tint_color` is `@tint` or a resolved colour (`follows || own != nil`). With no author tint, `config.image` stays the black `alwaysTemplate` bitmap and never gets `imageColorTransformer`, the glass `symbolInk` path, or the disabled `withTintColor`. UIKit applies `baseForegroundColor` only to symbol images (LLP 1069.011.001 D14: absent a tint, the symbol takes the title's colour). The comment at 231 says a glass configuration ignores a template image's configuration colour and therefore draws the symbol through `NativeButtonIOS.Ink` — and that path is inside the same guard. A plain, bordered, or gray button keeps a black glyph (missing in dark mode, not greyed when disabled or when `tintAdjustmentMode` is dimmed). A filled button keeps black instead of white. A glass button never enters `Ink`. An authored symbol tint does go through the block and is fine.

    Fix: when `FaceSymbol.isPath` and there is no authored symbol colour, still tint. Non-glass, set `imageColorTransformer` to return the proposed colour UIKit passes in (the title foreground: white on `filled` / `borderedProminent` / `prominentGlass` / `prominentClearGlass`, the label otherwise, including the greyed colour when disabled or dimmed). Do not substitute `button.tintColor`; that is the accent. Glass must take the existing `Ink` path, but pass that same foreground as `Ink.color`. `Ink.drawn` uses `color ?? button.tintColor`, so `nil` would paint the accent, and an unsaid glass symbol is the label colour. Keep today's `withTintColor(resolved)` only for a disabled button that has an authored colour.

2. **SHOULD-FIX** `host/apple/Sources/ExactGroupedLists/GroupedListIOS.swift:884`. The standard cell sets `c.image` to the template and sets `imageProperties.tintColor` only for an authored symbol tint (889), a destructive row (911), or a disabled row (917). A symbol image is tinted with the label when `tintColor` is nil; a non-symbol template is not. A normal Reply row therefore does not follow the label the way the `bell` row does. Destructive and disabled rows are fine because they assign a colour.

    Fix: after the title colour and the destructive/disabled assignments, if `row.symbol` is a path and `imageProperties.tintColor` is still nil, set it to the same label colour the title uses when the author gave none (`ThemeRoles.color("label", …)`, falling back to `.label`). Do not copy an action row's accent title colour onto the image; an untinted symbol stays the label there.

3. **SHOULD-FIX** `host/apple/Sources/ExactKit/IOS/NativeButtonsIOS.swift:307`, `host/apple/Sources/ExactKit/Mac/NativeButtonsMac.swift:312`, `host/apple/Sources/ExactKit/Mac/SidebarMac.swift:286`. `ButtonFace.symbol` and `TabFace.base` now hold `icon-path:<viewBox>|<commands>`. These three reports publish that string as `native.control.symbol` (LLP 1069.011 D10, the platform name or `""`) and as `state.window.sidebar` rows' `symbol`. The command string can be the whole SVG path. Page-image `native.symbol.name` still reads `symbolName` and is fine. Cache keys that embed the token (bar source, toolbar item, tab signature, back-button source) are invalidation keys and should keep it.

    Fix: at those three observation sites, report `""` / `NSNull` when `FaceSymbol.isPath`. Leave the token on the face for drawing and equality.

4. **SHOULD-FIX** `host/apple/Sources/ExactKit/IOS/ButtonConfigurationIOS.swift:218`. A symbol-only button sets `preferredSymbolConfigurationForImage = nil` so UIKit sizes the SF Symbol from the body style and `buttonSize` (the comment cites LLP 1116.019 D1: the title label's font is a fixed 17). `symbolPoints` is only `UIFont.preferredFont(forTextStyle: .body).pointSize`, and line 228 rasterizes the path at that size. A `control_size` of `large`, `small`, or `mini` with no title leaves the path at body size while the symbol grows or shrinks. With a title, `symbolPoints` follows the resolved title font, and an authored symbol `font_size` is honoured. Mac already uses `NSFont.systemFontSize(for: controlSize)` in `ButtonConfigurationMac.swift:100`.

    Fix: when the path is drawn and the symbol configuration is nil, take the side from the image UIKit resolves for a symbol under that same configuration and `buttonSize` (assign a placeholder `UIImage(systemName:)`, read its size, then replace `config.image`). Do not hard-code body point size.

5. **SHOULD-FIX** `host/apple/tests/ExactKitTests/FaceSymbolTests.swift:147` and `:227`. The messages say the button and the cell tint the path as a symbol. Both assertions check `renderingMode == .alwaysTemplate` (and a width). The same flag is what the bar, tab, segment, and toolbar tests call "tinted" (`:75`, `:93`, `:114`, `:138`, `:164`, `:181`, `:197`). None sample a pixel, set a dark trait, disable the control, or select a tab. The Mac button test (`:203`) only checks `isTemplate == false` after an authored tint, so a blank `sourceAtop` result in `FaceSymbol.tinted` (`FaceSymbol.swift:69`) would still pass. That is why findings 1 and 2 are green.

    Fix: for an unsaid iOS path button, assert the resolved image colour under the default traits, a dark trait collection, and `isEnabled = false`, including a glass style and a filled style (white ink). For the grouped cell, assert `imageProperties.tintColor` is the label colour when no symbol tint is authored, and still red or tertiary-label for destructive and disabled. One `control_size=large` symbol-only button should compare the path's side to the symbol UIKit resolves, not to body point size.

Checked and holding: the `icon-path:` split (viewBox may contain spaces; commands contain no `|`); `.fill` is not stripped or appended for a path (`TabFace.swift:37`, `NavigationTabsIOS.swift:249`); root-tab test ids skip the token (`NavigationTabsIOS.swift:241`); menu, swipe, and segment accessibility names stay the host label; `sf` still wins and emits no `symbolPath`; custom grouped rows clear `icon`, and no app contract uses an svg-only icon in a grouped list, so the standard-cell switch does not restyle an existing list; release and plan bytes are unchanged; chips, readouts, badges, the title attachment, bar items, tab items, and Mac template images (`isTemplate` left true, `contentTintColor` set) do tint; the title glyph's `y = (capHeight - height) / 2` is the right attachment offset; no touched file exceeds 1499 lines (`NavigationBarIOS.swift` ends at 1462). Tab 25 and toolbar 17 match the sizes the commit names for controls that size a symbol themselves and draw an image as-is.
