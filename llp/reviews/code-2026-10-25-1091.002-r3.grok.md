## MAJOR — A deferred method check uses every component the file belongs to

`contract/cli/src/sources/members.rs:263`

The parser defers every `syntax-method-form` and `syntax-method-shadowed` call in a file once that file has a members block or any `members` line (`contract/syntax/src/parser.rs:344`). `splice_members` then unions the actions of every component the file is a host or a part of, and applies that one set to every deferred call in the file.

A members file may also declare its own component (D2). This file is only a part of `App`, but `Card`'s calls are judged by `App`'s actions:

```contract
members App
  action trim
    let x = 1

component Card
  view
    text "  hi  ".trim()
    text trim("  hi  ")
```

`Card` has no action `trim`. `"  hi  ".trim()` is the built-in and should compile. It is refused with `syntax-method-shadowed`. `trim("  hi  ")` is the free spelling the grammar refuses (`syntax-method-form`). It is kept, and the type checker accepts it as the roster function `trim(string) -> string` (`plan/tables/format.json:1512`). Before this commit the block's action was not in `file.components`, so the free call was refused and the method call was allowed.

The same union hits a file that is in two assemblies: a `members App` block plus a component of its own that has a `members` line. `App`'s actions and that component's actions become one set for every call in the file.

A host file's other components are a different case. After the splice they share a file with the pasted action, and the one-file parser is file-global, so they match that program.

Fix: remember which component, or which members block, each deferred call sits in. Decide a block's calls from the component that lists the file, and a component's calls from that component after its own splice. Leave a file-level `fn` or shape on the parser's existing check against this file's own declarations.

## MAJOR — One family lets a call reach another file's shape or `fn`

`contract/cli/src/sources.rs:1065`, `contract/cli/src/sources/members.rs:229`

`families` unions every members edge, and `unique_names` then ignores bindings from the same family. That keeps the round-2 case working: a shape `Item` in the host, beside a state `Item`, stays `Item` when a members file merely holds that state. `taken` still gives two shapes of the same name two program-unique names.

It also skips a declaration that lives only in the members file. The host binds `Item`, so the shape is not renamed:

```contract
component App
  state Item = 0
  state item = Item(value=1)
  members "./more.contract"
  view
    text item.value.toString()
```

```contract
shape Item
  value: number
members App
  state extra = 0
```

`Item(value=1)` is not rewritten: the state `Item` is local, and this file does not see the shape (`contract/syntax/src/scope.rs:921`). The merged program still has `shape Item`. `is_record_call` (`contract/types/src/lib.rs:847`) builds that record, and the view reads `item.value`. The one-file paste has no such shape, so the same call is an unknown function. D4 and D5 both say this call stays in the host file.

`families` is also transitive across components. A host file with two `members` lines puts both members files in one family, so a shape in the second component's file is visible to a binding in the first.

Fix: keep the exemption for a declaration in the host file, which is what a single file would contain. Still rename a `fn` or shape in a members file when any other file binds that name. Do not union two components' files just because one source file hosts both.

The single-unit path does not drop a deferred refusal. A members block in the only file is `contract-members-unlisted` in `prepare_members`, and a `members` line loads another unit or fails, both before the fast path at `contract/cli/src/sources.rs:837`. On the compile path, `parse_source_partial` keeps `File.deferred` and `splice_members` still decides it. `contract sources` skips that decision when the parse already failed, because `graph` does not call `scope`; the build still reports it.

**Verdict: NOT READY.**
