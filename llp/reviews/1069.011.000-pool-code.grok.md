Commit `1f2ad227` adds `"control"` to `NodePool.leaves` and covers it with `testARowPoolsAroundItsControlsWhichAreBuiltFresh`. A list row that holds switches, checkboxes, selects, sliders, dates, or native buttons now parks and is taken like any other row. Each control is a hole: its `NodeView` and its `UIControl` are destroyed at park and built fresh at take. Nothing of a control is carried into the next row.

D8 in `llp/1069.011.000-native-buttons-everywhere.rfc.md` (line 49) is the bar. The hole token is `control*`. The control's type does not matter because the node is new. Face children are not views. An open select menu, a date calendar, or a control under a finger is destroyed the same way an unpooled row is destroyed today.

The batch order makes that safe. The kernel's `DestroyView` walks `arena.subtree` preorder, root first (`kernel/src/arena.rs` 382–394, `kernel/src/txn.rs` 560–587). `commit_tree` emits every destroy, then every create, then every children op (`host/apple/src/host.rs` 1181–1223). The row root is the first destroy, so `retire` runs while the control nodes are still in the tree. `park` releases each control before it recycles the rest (`NodePoolIOS.swift` 267–279). View ids are never reused (`runner/src/instance/collection/api.rs` 20).

State keyed by the old id

`ControlHost.sync` runs at the end of `Presenter.apply`, after the op loop and before `menus.sync` and `glassGroups.reconcile` (`PresenterIOS.swift` 808–811). Owners come from the chrome index. `release` has already called `chrome.forget` (`PresenterIOS.swift` 833), so a parked control is not an owner. The cleanup drops `controls`, `reported`, `kinds`, and `menus` for that id (`ControlsIOS.swift` 102–107). The new row's id is absent from those maps, so `control(for:)` builds a new `UIControl` (`ControlsIOS.swift` 78–94).

A switch or checkbox action returns when `presenter.views[id]` is nil (`ControlsIOS.swift` 160–162). A select menu's `UIAction` closes over the id it was built with and `chose` returns on the same check (`ValueControlsIOS.swift` 32–36, 65–66). `menus[newId]` starts empty, so the next select builds its menu from `selectOptions` for the new id (`ValueControlsIOS.swift` 28–31). A date callback requires both `views[id]` and `kinds[id]` (`DatesIOS.swift` 30–32). A slider reports only through `reported`, which also requires `views[id]` (`RangeIOS.swift` 28–31). A native button's action holds the node weakly and `activateNative` returns when `presenter` is nil (`NativeButtonsIOS.swift` 81–84, 60–61). The test presses the old button after the take and the press list stays `[22]` (`NodePoolIOSTests.swift` 333–336).

`lastRange` is the one map the cleanup does not clear (`ControlsIOS.swift` 102–107; `reset` at 195–200 also skips it). `rangeReleased` clears it only when the view is still mapped (`RangeIOS.swift` 40–42). Park clears `views[id]` inside `release` and only then calls `removeFromSuperview` (`NodePoolIOS.swift` 271–272, `PresenterIOS.swift` 822–835), so a touch-cancel that arrives as the slider leaves the window finds no view and leaves `lastRange[oldId]` set. The next row's slider is a new id and reads `lastRange` only under that id (`RangeIOS.swift` 35–36). The same window exists when a row is destroyed outright, because that path clears the view map before removing the view too (`PresenterIOS.swift` 755–756).

The intrinsic publish is the same shape. `sync` enqueues sizes only for live owners and hops to the next turn with no second liveness check (`ControlsIOS.swift` 151–157). A size queued on an earlier turn can arrive after the id is gone. `Kernel::set_intrinsic_size` refuses an unknown view (`kernel/src/kernel/intrinsic.rs` 18–20). The next control has a new id, so that late size cannot size it. A fully destroyed row has the same race.

Glass follows the node. The slot is a subview of the control node (`GlassGroup.swift` 291–300). Park removes that node. `forget` nils `presenter` and does not touch the registry (`NodeViewIOS.swift` 448–469). The registry is a weak hash table (`GlassGroup.swift` 26–27). `nativeGlassBody` needs a live presenter (`NativeButtonsIOS.swift` 47–49), so a forgotten node has no glass body unless it also has a material. `reconcileGlass` then returns immediately (`GlassGroup.swift` 283–284). A detached node with a material takes `glassPath`'s empty walk (`GlassGroup.swift` 126–146) and only clears a slot effect. `configureNative` registers the new button and `glassGroups.reconcile` builds that button's slot on the new node (`NativeButtonsIOS.swift` 147–150, `PresenterIOS.swift` 811).

Menus and the file picker do not bridge the hole. A menu or confirmation overlay is a `UIButton` on its invoker (`MenusIOS.swift` 90–114). On a non-leaf that subview makes `children` return nil (`NodePoolIOS.swift` 182–194), so an invoker row still does not park. A native button is not an invoker (D9). On a control the overlay is not a `NodeView`, so the leaf check allows the hole (`NodePoolIOS.swift` 207–211`), and `removeFromSuperview` takes the overlay with the node. `MenuHost.sync` then drops any overlay whose id is no longer live (`MenusIOS.swift` 132–135). The file picker's `open` set is keyed by view id for `input type=file` (`Picker.swift` 44), which is kind `input`, already a hole.

An exit never reaches the pool. `beginExit` holds the members and `controls.sync` keeps a leaving control mounted (`ControlsIOS.swift` 100–102, `PresenceIOS.swift` 17–30). The host's destroy calls `endExit` and continues before `retire` (`PresenterIOS.swift` 748–752).

Face and options are read after the node exists

`controls.sync` runs after every create in the batch. `configureNative` reads `buttonFace(owner.id)` and `configureValue` reads `selectOptions(owner.id)` for a node already in `views` (`NativeButtonsIOS.swift` 121, `ValueControlsIOS.swift` 28). Both closures read the kernel (`Session.swift` 683–684). The kernel has already committed that id (`host.rs` 1198–1206). A parked id is not an owner, so those reads are not made for it. `syncAccessibility` runs after `controls.sync` (`PresenterIOS.swift` 815), so `nativeTitle` sees the new `UIButton`.

Shape

Park and take both spell a childless control as `control*` (`NodePoolIOS.swift` 207–211 and 380–383). The type is not in the token, so a switch row and a button row with the same other structure share a parked tree. That is D8. The shared views are the non-controls. `recycle` clears props that own platform views, and `rebind` sets `props` to empty before the create op writes the new row's props and handlers (`NodePoolIOS.swift` 426–448, 470–486, `PresenterIOS.swift` 698–704). The control itself is a nil slot in the parked tree and is never claimed (`NodePoolIOS.swift` 406–408).

Child order is part of the string, so `view(text()control*)` and `view(control*text())` are different keys, and `input*` does not match `control*`. Take refuses a control whose children op is non-empty (`NodePoolIOS.swift` 381). Park refuses a control that has a `NodeView` subview (`NodePoolIOS.swift` 209`). The two sides agree for every control the host actually builds. A disagreement would miss the reuse. The new row would be built from scratch.

Parent and order at take

A hole's id is not put in `claims`, so `take` returns nil and the create op allocates `NodeView(id:kind:presenter:)` (`PresenterIOS.swift` 698–699). `placeChildren` then inserts that view at the index the children op names (`PresenterIOS.swift` 840–856). Creates run before children ops, so the reused parent is already in `views`. The old control has already been removed. The UIControl is added later, inside the new node, at `controlMount` (`ControlsIOS.swift` 117–118, `NativeButtonsIOS.swift` 40`). Sibling order among `NodeView`s follows the children op. The existing heavy-leaf test checks that order for the other hole kinds (`NodePoolIOSTests.swift` 284). This hole uses the same placement.

What a control node contains

`emit_children` returns immediately for `NodeType::Control` (`host/apple/src/paragraph.rs` 308–311), so the batch has no children op for a control. `option_part` skips a select's option text and every descendant of a native button (`paragraph.rs` 11–30, 194–198), so those kernel children never become views. The hole's platform subviews — the `UIControl`, a glass slot, a material — are not `NodeView`s, and the leaf check counts only `NodeView`s. Flat leaves parent only `view` and `button` (`FlatLeavesIOS.swift` 58), and `createdNodes` omits them from the shape (`NodePoolIOS.swift` 336–346). A control row therefore has the empty hole a heavy leaf is required to have.

Rows that have no controls

`leaves.contains` is true only for kind `control` (`NodePoolIOS.swift` 95, 207, 244, 374, 380). A row whose nodes are views, text, images, buttons, scrolls, svgs, or the older heavy leaves takes the same branches as before. A control that is itself the row root is refused by `retire` because its kind is now in `leaves` (`NodePoolIOS.swift` 244`). Before this commit `shape` already rejected it, because `control` is not in `kinds` (`NodePoolIOS.swift` 86, 213). Either way that root is destroyed in full. `leavesDropped` gains a `"control"` count only when a control leaf is actually dropped.

`idle` still ignores `UIControl` tracking, a `UIButton` menu, and a compact date picker's internal responder (`NodePoolIOS.swift` 323–327). D8 says park matches destroy there, and it does: the leaf goes through `presenter.release` plus `forget`, and every callback is guarded on the old id. `retire` still refuses a row root that a dismissing modal is keeping (`NodePoolIOS.swift` 245, `ModalIOS.swift` 167–171), which is the case where the row sits inside the retiring route. The agent looks up `presenter.views` and then `controls.activate` (`AgentIOS.swift` 447–452). After `sync`, the old id has neither a view nor a control.
