I found no correctness regression introduced by `1f2ad2275`. The teardown audit did uncover two existing bugs, both present in its parent commit:

1. **Interrupted slider input leaves state behind.** [ControlsIOS.swift:102](/Users/ccheever/projects/exact2-wt-buttons2/host/apple/Sources/ExactKit/IOS/ControlsIOS.swift:102) removes `controls`, `reported`, `kinds`, and `menus`, but omits `lastRange`; [reset():195](/Users/ccheever/projects/exact2-wt-buttons2/host/apple/Sources/ExactKit/IOS/ControlsIOS.swift:195) omits it too. A slider’s `input` action can remove its row after [rangeMoved():34](/Users/ccheever/projects/exact2-wt-buttons2/host/apple/Sources/ExactKit/IOS/RangeIOS.swift:34) records the value. Subsequent release/cancellation returns at the live-node guard before clearing that entry. Repeating this retains dead ids indefinitely. Ordinary row reuse assigns fresh ids, so it does **not** suppress the next row’s input; a runtime restart reusing ids can.
   
   **Fix:** Clear `lastRange[id]` during control removal and replacement, clear the dictionary in `reset()`, and clear it before the liveness guard in `rangeReleased`.

2. **Queued intrinsic sizes can report destroyed ids.** [ControlsIOS.swift:157](/Users/ccheever/projects/exact2-wt-buttons2/host/apple/Sources/ExactKit/IOS/ControlsIOS.swift:157) captures numeric ids and sizes in an asynchronous closure without validating their lifetime. Create a control, destroy its row in another batch before that closure executes, then drain the main queue: the old size still reaches `onIntrinsic`. [host.rs:905](/Users/ccheever/projects/exact2-wt-buttons2/host/apple/src/host.rs:905) submits it to the kernel, which returns `UnknownView` for the dead id.
   
   **Fix:** Queue measurements with weak owner references and lifetime tokens, following [PresenterIOS.swift:574](/Users/ccheever/projects/exact2-wt-buttons2/host/apple/Sources/ExactKit/IOS/PresenterIOS.swift:574), and validate at actual delivery, including after any `whenIdle` deferral.

The change itself preserves the important boundaries: `control*` is a typed hole; controls receive fresh nodes and platform controls; the batch’s children operation restores parent and sibling order. Select options and native-button faces are omitted from Apple view creation, so they cannot misalign the pool’s preorder mapping. Configuration runs after node creation. Glass registrations are weak, and the detached control node and its slot never become the next row’s objects. I found no changed execution path for an app without controls in list rows.

It does not cover either lifetime bug above, changed control types, or open presentations. This was a static audit; I did not rerun UIKit tests or modify files.
