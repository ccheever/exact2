**Verdict:** SOUND WITH CHANGES

1. **The land rule can reject a good swap, or pass without checking the bug it names.** G5 only moves Khmer U+200B. On the width-0 opportunity set in LLP 1085 F3, plain Parley is also worse on Myanmar (559 missing / 97 extra against cosmic-text's 552 / 0) and Thai (1,130 / 7 against 1,130 / 0). `complex-scripts` is out of scope and still leaves about 100 extra Myanmar breaks (1085 F3; `rules/DEFERRED.md` lines 137–139). The in-repo corpus drives `exact-textflow`'s own breaker (`textflow/src/walker.rs` line 5, `unicode_linebreak`), which this plan keeps, so that test will not move. The 1,758 / 2,183 figures are the engine comparison from `~/bench/dioxus/q5`. §6 requires both "Chrome agreement at least main's" and "no script worse in the corpus" (`1085.000` lines 129–130 and 190). Resolve it by making the veto rendered line starts against Chrome, per script, at the F3 widths, and by using the width-0 set only to accept the Khmer fix. Waive or schedule the leftover Myanmar and Thai extras in §6 before stage 1.

2. **Main has behavior the gap list never schedules, and one of them is a predicted Android start failure.** `vendor/cosmic-text/EXACT-PATCHES.md` records six patches. LLP 1085 and G1–G8 cover the first three. Soft hyphen is now host behavior (`EXACT-PATCHES.md` lines 58–69, `host/linux/src/text/css_tests.rs` around line 289). The phone font cache pushes already-parsed face info and `wght` ranges so launch does not open roughly 300 files (`host/linux/src/text/font_cache.rs` lines 1–8 and 51; the weight-axis patch at `EXACT-PATCHES.md` lines 71–79). fontique 0.11.1 only offers `register_fonts(Blob)` and `load_fonts_from_paths`, both of which read and parse. P4 says boot moves only through G8 (`1085.000` line 77). §6 drops the branch on a start regression. Add the soft hyphen and a no-reparse catalog to the gap list. `Layout::set_text_indent` already exists in Parley 0.11.1, so map the existing indent through it (`shaping.rs` line 330) rather than discovering the CSS test later.

3. **Replacing the width-zero wrap with `calculate_content_widths` can regress mixed-direction layout without failing the parity matrix.** Parley 0.11.1 documents that this method may return wrong bounds for mixed-direction text, and that it is recomputed on every call (https://docs.rs/parley/0.11.1/parley/layout/struct.Layout.html). The plan adopts it as the min- and max-content path (`1085.000` line 116). F3 and the LLP 1053 cases are fixed-width line starts, so a wrong intrinsic width on an RTL or mixed run would still look like a pass. Keep the current width-zero measurement for those paragraphs until the new method matches main on them.

4. **The result that can kill the branch is cheap to learn before the rewrite.** LLP 1085's own order is: settle base direction, font admission, and the untraced Devanagari advance, then switch (1085 lines 384–398). The plan rewrites the host in stage 1 (about 5,100 lines, 1085 F7) and only then gives G4 and G5 three rounds (`1085.000` lines 152–157 and 135). A miss there is a Drop after the phones. Run those patches, plus the soft hyphen and the residual script extras, in the existing `~/bench/dioxus/q5` harness first. Start stage 1 only if that bench meets the revised parity bar.

MINOR:
- Android "re-layout" is rotation's config-change-to-first-frame (`1085.000` line 179), a full activity restart, so P2's "text work down by about half" cannot show up there. The Linux resize sweep is the measurement that can decide it.
- G3 puts ellipsis and `line-clamp` in `exact-textflow`, but ordinary paragraphs already clamp through cosmic-text's `Ellipsize` (`shaping.rs` lines 310–316, `text.rs` lines 370–384, `css_tests.rs` line 179). The flow walker already clamps. The F4 accept cases are the right bar, on the ordinary path.
- Keep the host line box on the face's ascent, descent, and gap (`shaping.rs` `line_box`, around line 569). Parley's own `MetricsRelative(1.0)` height is the 22 px against Chrome's 24 px case (1085 F4).

The direction is right: one Rust engine behind the measurer seam, judged on Chrome breaks, memory, and re-layout, with scroll treated as a non-goal. §3 is right. exact2 is already pure Rust (harfrust, skrifa, swash, fontdb's Rust `fontconfig-parser`), Parley stays that way if its default `system` feature stays off (`yeslogic-fontconfig-sys` on Linux), `Layout<B>` is `Send` when the brush is, and Android's Skia `drawGlyphs` and Expose's FreeType stack are correctly left out. What needs to change is the parity veto, the gap list relative to today's patches, and proving the blockers in the bench that already exists before rewriting the host.
