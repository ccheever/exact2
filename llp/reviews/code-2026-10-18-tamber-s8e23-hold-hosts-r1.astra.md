# Review round 1, LLP 1121 stage 8 E2 (Apple) + E3 (Linux/Android) held states, Astra (gpt-6-astra, max)

**RIGHT WITH CHANGES — the blocking findings need fixing before landing.**

1. **BLOCKING — Apple misses required input-driven releases.** [HeldState.swift:88](/tmp/rv-s8e23-r1/host/apple/Sources/ExactKit/HeldState.swift:88) only receives state-specific appearance changes. Pointer-down does not end a hold; Mac keyboard activation dispatches `press` without changing `pressed`; iOS focus transitions never call `heldInput`. Mac hover tracking also excludes nodes without authored hover rows. These holds remain active after qualifying input. **Fix:** clear the applicable hold at real pointer/key dispatch and actual focus/pointer boundary transitions, including input within the held subtree, independently of whether appearance flags change.

2. **BLOCKING — Apple conflates held state with physical interaction state.** [HeldState.swift:42](/tmp/rv-s8e23-r1/host/apple/Sources/ExactKit/HeldState.swift:42) clears `pressed` and look flags unconditionally. Mouse-down → hold active → clear hold → mouse-up loses the click because `MouseEventsMac` requires `pressed` to dispatch it. Conversely, a contact already down when a hold arrives releases the hold through [PressFeedback.swift:107](/tmp/rv-s8e23-r1/host/apple/Sources/ExactKit/PressFeedback.swift:107), contrary to E1’s takeover behavior. Clearing a held hover/focus also erases an existing physical look. **Fix:** track forced state separately, compose it with physical state, and preserve contact/action tracking. Test both orders of real press and hold.

3. **BLOCKING — Apple’s generation swap does not reliably release silently and rehold.** [Session.swift:304](/tmp/rv-s8e23-r1/host/apple/Sources/ExactKit/Session.swift:304) sets `swapping`, but the actual replacement calls `presenter.reset()`, whose teardown does not generally call `holdGone()`. With an existing iOS press contact, `forget()` cancels it, changes `pressed`, and reports `input`; `heldInput` ignores `swapping`. That live-revision report ends the server hold and clears the saved frame. Retained old views can also prevent `rehold()` from running. **Fix:** explicitly release the old hold unsaid before resetting presenters, preserve its frame, and reapply after replacement. The new generation test only sends `.destroy`; test the actual reset/rehold path.

4. **BLOCKING — Apple rejects valid rendered child sites before resolving their press owner.** [Inspect.swift:191](/tmp/rv-s8e23-r1/host/apple/Sources/ExactKit/Inspect.swift:191) requires `presenter.views[id]`. Flat leaves and inline text have logical sites but no corresponding `NodeView`, so holding active on such a child reports `gone` even when its ancestor handles presses. `holdTap` has the same restriction. The test fixture explicitly adds `testId` to prevent flattening. **Fix:** resolve site/instance and press ancestry through the logical tree before finding the presentation; support flat and inline targets. Add fixtures that retain those optimizations.

5. **SHOULD-FIX — Both hosts omit held rows from the originally requested child.** [HeldState.swift:99](/tmp/rv-s8e23-r1/host/apple/Sources/ExactKit/HeldState.swift:99) and [held.rs:314](/tmp/rv-s8e23-r1/host/linux/src/presenter/held.rs:314) answer only for the resolved press owner. Selecting a label and holding active therefore leaves that selection/layout without the parent’s held press rows. E1 explicitly answers for both the requested element and its resolved owner. **Fix:** retain both identities and return the owner’s D7 rows for either. Reverse the Linux test’s assertion that the child has no held metadata.

6. **SHOULD-FIX — Apple ignores disabled ancestors.** [HeldState.swift:70](/tmp/rv-s8e23-r1/host/apple/Sources/ExactKit/HeldState.swift:70) checks only the resolved view’s own `disabled` property; [PressPaint.swift:97](/tmp/rv-s8e23-r1/host/apple/Sources/ExactKit/PressPaint.swift:97) likewise checks only that view during updates. A hover/focus hold on a child beneath a disabled parent is accepted, and disabling that parent does not release it. E1 and Linux check ancestors. **Fix:** check the relevant ancestry on application and reconcile an existing hold when ancestor disabled properties change.

7. **SHOULD-FIX — Linux/Android can retain pressed paint after clearing a hold outside the node.** [held.rs:97](/tmp/rv-s8e23-r1/host/linux/src/presenter/held.rs:97) preserves paint whenever `contact_press()` names the held node. That helper returns the contact’s original press target even after its pointer moves outside. Reproduce with down inside → hold active → move outside → clear hold: the hold ends, but pressed paint remains until another move/release. **Fix:** preserve paint only when the live contact is currently pressing inside its stored press bounds; otherwise release through the normal easing path.
