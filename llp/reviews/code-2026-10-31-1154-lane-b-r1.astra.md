## MATERIAL findings

1. **The cached bytes actually linked are not verified.** [scripts/package-libraries.mjs:121](/private/tmp/claude-501/-Users-ccheever-projects-exact2/3075bb39-112b-4b60-a056-edc166a1f89f/scratchpad/laneB/capsule/scripts/package-libraries.mjs:121) checks only whether `placed` exists. The hash check at line 102 covers the downloaded file, which is separate from the copied `.so` or extracted framework. Changing `<hash>/<target>/libvault.so` leaves the checked download untouched; subsequent builds link and ship the changed bytes. Apple likewise signs an altered cached framework. **Fix:** verify the derived view against the checked download before reuse, rebuilding it atomically when necessary. Add corruption cases for the actual link inputs; the current test corrupts only the downloaded file.

2. **An xcframework can select bytes outside the verified archive.** [scripts/package-libraries.mjs:70](/private/tmp/claude-501/-Users-ccheever-projects-exact2/3075bb39-112b-4b60-a056-edc166a1f89f/scratchpad/laneB/capsule/scripts/package-libraries.mjs:70) resolves `LibraryIdentifier` without containment checks. For example, an absolute identifier selects an existing framework elsewhere on the machine, which line 147 copies into the cache. The install-name check does not establish that those bytes came from the hashed zip. Preserved symlinks can also escape the extracted tree. **Fix:** validate archive paths and symlinks, require the selected slice to remain inside the extracted xcframework, and require framework links to remain inside the framework while allowing its normal internal version links.

3. **Native-library lookup runs during web bakes.** [js/bake/src/lib.rs:68](/private/tmp/claude-501/-Users-ccheever-projects-exact2/3075bb39-112b-4b60-a056-edc166a1f89f/scratchpad/laneB/capsule/js/bake/src/lib.rs:68) calls `library::link` regardless of `platform`. A package declaring the RFC’s native targets therefore fails for `wasm32-unknown-unknown`. This affects `host/web/build.mjs --bake`, which deployment invokes even when the published page uses the JS target. The integration test’s ordinary `web-build` bypasses this path. **Fix:** exclude web bakes from native-library lookup and linking; cover deployment’s web bake as well as the JS build.

4. **Deployment bypasses the fetch and verification step.** [scripts/app.mjs:1251](/private/tmp/claude-501/-Users-ccheever-projects-exact2/3075bb39-112b-4b60-a056-edc166a1f89f/scratchpad/laneB/capsule/scripts/app.mjs:1251) provides no library preparation in `buildBake`. `scripts/deploy.mjs:690` invokes it directly, bypassing both new `prepareLibrary` callers. Independently of finding 3, a native deployment bake fails on a cold cache; with a warm cache, Rust checks only existence and skips even the downloaded-file hash check. The source snapshot does not carry this cache. **Fix:** invoke library preparation from the shared pre-Cargo fetch path used by deployment, reading the declaration from the materialized snapshot.

5. **Widget and Live Activity builds omit the library from the shared runtime’s link.** [host/apple/build.mjs:1228](/private/tmp/claude-501/-Users-ccheever-projects-exact2/3075bb39-112b-4b60-a056-edc166a1f89f/scratchpad/laneB/capsule/host/apple/build.mjs:1228) adds the framework only to the final executable links. Earlier, line 1018 calls `sharedWidgetCore`; `widgets.mjs:178` links `ExactCore` against the force-loaded Rust archive without the package framework. A shim referencing its C symbols fails there before the final link. That framework’s reuse digest also omits the library. **Fix:** pass the library’s link inputs and identity into the shared-core build and its reuse calculation.

6. **Mixed TypeScript/Rust apps never emit the library’s Rust link directives.** [js/bake/src/lib.rs:100](/private/tmp/claude-501/-Users-ccheever-projects-exact2/3075bb39-112b-4b60-a056-edc166a1f89f/scratchpad/laneB/capsule/js/bake/src/lib.rs:100) and `build_mixed_with` at line 109 call `build_sources` directly. The new hook exists only in `build`. A mixed Linux app can successfully fetch the library, then fail with unresolved shim symbols because Cargo receives neither its search path nor `-l`. **Fix:** invoke the hook from every applicable native Cargo entrypoint, retaining the web exclusion described above.

7. **`--embed` produces an incomplete artifact.** [host/apple/build.mjs:964](/private/tmp/claude-501/-Users-ccheever-projects-exact2/3075bb39-112b-4b60-a056-edc166a1f89f/scratchpad/laneB/capsule/host/apple/build.mjs:964) copies the Rust archive and existing dependencies but never includes the package framework or communicates its required link inputs. `embedOnly` returns at line 985 before bundle placement. A consumer cannot link and package this archive using the emitted artifact alone. **Fix:** carry the package framework and its link requirements in the embed output.

8. **Linux runtime library names are assumed rather than checked.** [scripts/package-libraries.mjs:126](/private/tmp/claude-501/-Users-ccheever-projects-exact2/3075bb39-112b-4b60-a056-edc166a1f89f/scratchpad/laneB/capsule/scripts/package-libraries.mjs:126) copies any accepted library to `lib<link>.so`. If its `DT_SONAME` is `libvault.so.1`, the executable records that name, but packaging supplies only `libvault.so`. An absolute SONAME similarly records a machine-specific dependency that `$ORIGIN` cannot repair. The fixture explicitly supplies the expected SONAME, hiding this case. **Fix:** validate a present SONAME against the carried filename and refuse mismatches by package and target before linking.
