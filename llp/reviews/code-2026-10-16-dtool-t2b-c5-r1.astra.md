1. **High — Token editability does not fail closed.** [scripts/tamber-inspect.mjs:48](/tmp/rv-dt-t2b5/scripts/tamber-inspect.mjs:48) takes the first referenced token and eventually offers it without requiring `source === "authored"`, `origin === "own"`, or a directly specified token. The theme fixture’s `linear-gradient(90deg, accent.fill, surface.card)` therefore offers editing `accent.fill`; a synthetic `color-mix(...)` can offer an expression as a token name. Missing map origins also pass. **Fix:** positively establish an own authored row whose specified value names one declared token; otherwise return a reason and token links.

2. **High — Changing the design file does not invalidate editability.** [scripts/tamber-inspect.mjs:68](/tmp/rv-dt-t2b5/scripts/tamber-inspect.mjs:68) checks only the node’s file and component call-site files. Although the compiler now records the `.tamber` digest, the join never checks it. Delete a referenced token or introduce a design compile error while leaving Contract files unchanged: the old page and its latest status still agree, and the selection remains editable against an incompatible design. **Fix:** validate the design snapshot backing the reported applied digest, including its source-file digests. Account explicitly for successful live batches and scrub previews instead of blindly comparing every selection with the original bake’s design.

3. **Medium — Maps and outline sites are not resolved per running build.** [host/web/dev.mjs:359](/tmp/rv-dt-t2b5/host/web/dev.mjs:359) supplies only the current map or a disk fallback; [scripts/tamber-builds.mjs:323](/tmp/rv-dt-t2b5/scripts/tamber-builds.mjs:323) broadcasts that map’s sites and digest unchanged. With two pages on different generations, the older page loses its source join and ignores the newer page’s outline. Its existing marks are actually cleared before the digest rejection. The initial baked plan’s map is also unavailable through this lookup when it differs from the resident compiler’s plan. **Fix:** resolve retained plan/map pairs for each build, including the initial bake, and translate source locations separately for each recipient. Verify the pair before using a disk map or clearing existing outlines.

4. **Medium — A lost status report causes an endless refresh loop.** [scripts/tamber-server.mjs:189](/tmp/rv-dt-t2b5/scripts/tamber-server.mjs:189) sends another refresh on every mismatch. The page discards failed status POSTs and records `channel.told` before delivery; refresh sends only another selection. If a status after a pin or batch never reaches the server, every subsequent selection produces another 409 and refresh indefinitely. **Fix:** refresh status before resending the selection, and allow only a bounded outstanding refresh until the compared status changes. Test an undelivered status, not merely a manually corrected next report.

5. **Medium — Outline lookup performs quadratic work on the page’s main thread.** [host/web/dev.js:611](/tmp/rv-dt-t2b5/host/web/dev.js:611) requests a complete node explanation for every mounted view. Each explanation calls `site_of()` and `modes_of_view()`, which search the instance tree, and serializes rows that outline never uses. A large mounted feed therefore incurs roughly quadratic traversal work on every selection. **Fix:** obtain view/site associations through the existing index or one instance-tree traversal; request full explanations only for selected nodes.

6. **Medium — Scrolling immediately invalidates the outline boxes.** [host/web/dev.js:618](/tmp/rv-dt-t2b5/host/web/dev.js:618) measures all rectangles and creates fixed overlays before calling `scrollIntoView()`. Selecting an offscreen use scrolls its element into view while leaving its outline at the previous viewport coordinates. Resize and subsequent layout changes likewise leave detached boxes. **Fix:** scroll first, then measure; update or invalidate marks when their geometry changes.

7. **Low — Boundary token links are always discarded.** [scripts/tamber-inspect.mjs:48](/tmp/rv-dt-t2b5/scripts/tamber-inspect.mjs:48) sets `token` to null whenever `implied` is true, then returns that null as the boundary row’s link. Selecting a preview boundary with an implied `text.primary` row therefore cannot expose the promised token link. **Fix:** retain token identity independently of whether the row is editable. Also test actual inherited reports: the runner currently omits their token metadata, whereas the unit fixture supplies it manually.

8. **Medium — Outline omits D4’s command authorization and ownership.** [scripts/tamber-server.mjs:491](/tmp/rv-dt-t2b5/scripts/tamber-server.mjs:491) drops `scope`, and the outline channel accepts no client owner or journal attribution. A present `read`/`propose` client can issue outlines; client B can replace outlines while A owns inspect, then disconnect without clearing B’s marks. **Fix:** require write scope, record the issuing client, journal the command, and clear its outlines on owner removal without clearing a newer owner’s command.

9. **Low — The tests do not establish “every copy outlined.”** [scripts/tamber-server.test.mjs:448](/tmp/rv-dt-t2b5/scripts/tamber-server.test.mjs:448) checks only a minimum number of overlay elements. Incorrect, invisible, or misplaced overlays satisfy those assertions. The unit test claiming delivery to every build registers only one build and duplicates the server callback. Waiting for the compiler’s log also does not establish which generation the page accepted. **Fix:** assert exact target identities and rectangle alignment, include repeated instances and two different running plans, and wait for the page’s reported generation.
