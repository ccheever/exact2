Nothing blocking. On a real pointer move or focus move, Chrome, Firefox, and Safari update `:hover` and `:focus-visible` before `pointerover` / `pointerout` / `focusin` / `focusout`, and they start transitions only at the next style recalc. `snap` forces that recalc with transitions off, so those edges do snap. The holes are edges that never produce those events, and edges the new predicate treats as “still inside.”

1. **Should-fix** — `host/web/input-glue.js:435`. Moving focus between a looked element and a descendant does not snap. `el.contains(relatedTarget)` is true for both `focusout` (card → inner field) and `focusin` (field → card), so the loop breaks. `:focus-visible` does not propagate, so the card’s look still changes and eases on its own `transition`. Hover-into-a-child is different and should not snap. Split the predicate: for focus, snap a looked element when it gains or loses `:focus-visible`, including when `relatedTarget` stays inside it.

2. **Should-fix** — `host/web/input-glue.js:435`. A popover or `showModal` dialog under a looked ancestor is in the top layer. Ancestors stop matching `:hover`, but pointer events still walk the DOM and `contains(relatedTarget)` stays true, so the ancestor’s look eases out (and eases back in on the way out). Same loop: if the pointer event says the node is still inside but it does not match `:hover`, snap it anyway. Nodes parented outside `root` (the reorder ghost is, on `document.body`) never reach this listener; app sheets stay under `root` and are heard. A looked node inside a shadow tree is also missed: the listener is outside the shadow, so `target` is retargeted to the host and `parentElement` never enters the shadow. The app tree is light DOM, so that is latent.

3. **Should-fix** — `host/web/input-glue.js:439`. Hover can change with no `pointerover` / `pointerout`. Scroll under a still pointer: Chrome and Safari generally show `:hover` and then fire pointer events (so the snap can still win); Firefox fires `mouseover` / `mouseout` only ([pointerevents#529](https://github.com/w3c/pointerevents/issues/529)), so the look eases. Layout that moves a node under a still pointer, and a node inserted under the pointer, update `:hover` in Chrome and Safari with no pointer event at all. Touch on a phone never applies these rules (`@media (hover: hover)`); a touch screen on a hover-capable machine can stick `:hover` after `pointerup` with no later `pointerout`. Also listen for `mouseover` / `mouseout` (Firefox scroll). For insert and layout, keep the last pointer point and on `scroll` (capture) plus a mutation/frame after DOM edits, snap looked nodes whose `:hover` set changed via `elementFromPoint`.

4. **Should-fix** — `host/web/input-glue.js:439`. `:focus-visible` can turn on for an already-focused node when the modality flips to keyboard (mouse-focused button, then a key that does not move focus). No `focusin` / `focusout`. In Chrome the flag flips in the key’s default action, after listeners, so a `keydown` handler that snaps immediately flushes too early. Queue a microtask from capture `keydown` and snap `document.activeElement` only on the transition into `:focus-visible` (every key would otherwise cancel in-flight transitions).

5. **Should-fix** — `host/web/input-glue.js:338` (called from `:436`). `snap` assigns `el.style.transition` and forces a style flush. That commits every transitioning property on that node to its underlying value, not only the look’s. Mid-press, an author `transition` that is timing opacity or background (the press rule changes those used values) jumps. The press scale WAAPI (`--exact-press-factor` in `showPress`) is not a CSS transition and keeps running. The press paint WAAPI is cancelled and replaced: `style` is in the paint observer’s attribute filter (`input-glue.js:282`), so the microtask runs `repaint`, which `animation.cancel()`s and starts a new paint from the current `--exact-press-paint` over the remaining time. Easing restarts; it does not drop the press. `:active` is not what this host paints with (`data-exact-painting` is). Fix: drive the flush from a stylesheet `[data-exact-snap] { transition: none !important }` toggled by an attribute the paint observer does not watch, so the paint animation is left alone. That still cancels CSS transitions on the node; preserving unrelated ones means freezing their current computed values across the flush, not blanking `transition`.

6. **Nit** — `host/web/input-glue.js:338`. The write-back of the captured `style.transition` is safe on this path: `change` is empty, and `getComputedStyle` does not apply a host style op. A `cssText` replace that did land inside the flush (motion’s `style()` sets the whole attribute) would be overwritten by the stale shorthand, and the shorthand setter would also drop an inline `!important` the host does not emit today. The held listener (`:426`) already snaps that node before `lookEdges`, so a held hover/focus edge flushes twice. Harmless.

7. **Nit** — `host/web/input-glue.js:432`. Every `pointerover` / `pointerout` / `focusin` / `focusout` walks to the containment ancestor and, for each `data-view`, calls `getElementById("exact-looks")` and `Map.has`. `getComputedStyle` runs only for looked edges, once each, so nested looks force one layout per edge. Hoist the map once per event and set `transition: none` on every edge, then flush once.

8. **Nit** — `host/web/tests/looks.test.mjs:86`. The Chrome hover enter/leave checks are real: one frame of a 400ms linear transition is not `rgb(255, 255, 0)` / `0.80`, and a base change left on `transition: none` would be black by 100ms. They only cover Chrome (`chromium()`), only hover, and only `pointer` events from `mouseMoved`. `:94` stays yellow even if the inner move snaps anyway. Nothing covers focus, scroll, or a press in flight. A stalled frame longer than 400ms would also go yellow without the snap.

`exactRules` keys are not a bug. The batch writes `id` as a JSON number (`glue.js:615`, `u32`), `attach` stores `String(id)`, and `Number(dataset.view)` matches. `u32` is inside the safe integer range. The test’s `Map([[11, '']])` is the same key type. Nested looked elements are both snapped: the walk does not stop until an ancestor contains `relatedTarget`.
