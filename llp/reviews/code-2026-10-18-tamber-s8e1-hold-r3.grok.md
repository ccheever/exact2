1. **BLOCKING — A generation-overtaken wasm hold is applied on the new plan and can report `gone` before the status replay.** `host/web/dev.js:706-708`, `host/web/dev.js:696-698`, `host/web/dev.js:239`, `host/web/glue.js:1333`, `host/web/glue.js:1365`, `scripts/tamber-builds.mjs:380-382`, `scripts/tamber-builds.mjs:193-195`.

   `hold()` samples `generations` only after the glue wait (`dev.js:701`), then takes the digest from `await planDigest()`. `boot` bumps `exact.generation` and installs the new runner before `await flowLoading` / `textflow.settle()` (`glue.js:1333`, `glue.js:1365`), while `swaps` is still 1 and `applied()` has not run. `planDigest()` therefore re-reads `ask({op:'sites'})` and returns the new plan. The overtake branch stores `{frame, digest}` of that new digest and, because `swaps` is still set, returns unsaid. `apply`'s `finally` then drops `swaps`, and `applied()` (`dev.js:239`) calls `knownPlan(newSha)`, `status()`, and `rehold()`. `rehold` commands the kept frame whenever `planDigest() === kept.digest` (`dev.js:696-698`), which is now true, so the old `{site, instance}` is resolved on the new tree.

   The same store happens when the swap finishes inside `await planDigest()` itself: `gen` is the old count, `swaps` is already 0, and the branch calls `rehold()` directly with the post-`knownPlan` digest. The re-commanded `hold()` samples `generations` after the increment, skips the overtake branch, and reports `{kind:'held', state:null, reason:'gone', revision}` for the revision `holdSent` still names. `status()` only calls `report` after `facts()` (`dev.js:399`), so that `gone` is queued first. `held` deletes the hold and closes the revision (`tamber-builds.mjs:380-382`). The status's `replayHold` (`always` false) then returns because the record is gone (`tamber-builds.mjs:193-195`). Correspondence never runs. A same-plan swap is fine; a different plan loses the hold, or paints the old site number when that number exists on the new plan.

   **Fix:** before the glue wait and before `planDigest()`, capture `generations` and the digest already cached for that generation (`planDigestOf === exact.generation ? planDigestNow : null`). After both awaits, if `holdLatest !== frame`, return. If `swaps` is set or `generations` moved: when the live digest is still that pre-wait digest, store `{frame, digest: pre}` and `rehold()` only once `swaps` is 0. When the digest changed, return without writing `channel.hold` and without reporting. Leave correspondence to `applied()`'s `status()`.

2. **SHOULD-FIX — A JS plan mismatch refuses the hold by name, so the reloaded page has nothing to replay.** `host/web-js/inspect-dev.js:31`, `host/web-js/inspect-dev.js:465-469`, `scripts/tamber-builds.mjs:389-396`, `host/web-js/dev.mjs:593`.
