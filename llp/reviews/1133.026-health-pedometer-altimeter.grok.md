## The diff

**MATERIAL. IN-DELTA.** `state` treats a denied history permission as a denied health read.

History is a new Android permission that "appears in `types`" (D5, around 414–420). `state` is `denied` if any of those reads is `denied` (around 353–358). `READ_HEALTH_DATA_HISTORY` is not a data type. **Failing scenario.** The app sets `android.readHealthDataHistory=true` and requests steps and history. The person grants steps and cancels history until it is `permanentlyDenied`. Health Connect will return the last thirty days of steps. `healthStatus.state` is `denied`. A screen that follows `state`, the same way geolocation's recipe follows `state`, shows the recovery and never draws those steps.

**Decision.** `history` stays out of the rollup. `state` is `prompt` when a data type would still show the sheet, `granted` when every data type is granted, and `denied` when every data type is denied. History's own `HealthTypeStatus.read` is where that denial shows.

**MATERIAL. IN-DELTA.** The new gate keys off `type` while tier 2 replaces `type`.

`"permissionBy": {"type": "health.{}"}` admits `healthStatistics` on `health.steps` and the other three closed names. D10 says `apple.quantityType` and `android.recordType` beat `type` (around 575 and 587). The request's `read` enum is only `steps|distance|activeEnergy|workouts`, so a heart-rate identifier cannot be asked, and there is no `health.*` permission for it. r1's per-value key would have opened a state for whatever string was passed. This closed list does not.

**Failing scenario.** The call is `healthStatistics(type="steps", apple.quantityType="HKQuantityTypeIdentifierHeartRate", ...)`. Steps are granted, so admission proceeds. The query is heart rate, which was never requested. HealthKit returns no samples and no error. D6's `NotAllowedError` with `requestHealthAuthorization` does not fire, which is the silent empty that rule exists to prevent. On Android the same call reaches Health Connect without a runner state for `READ_HEART_RATE`.

**Decision.** The permission is the type actually queried, after the tier 2 override. The bake derives a permission for every literal tier 2 identifier the app writes, and `read` accepts those literals. A statistics call whose effective type is still `prompt` fails `NotAllowedError`.
