1. **must-fix** — `host/apple/Sources/ExactKit/Mac/FlightsMac.swift:224` (cleared by `host/apple/Sources/ExactKit/Mac/NavigationMac.swift:104`). The flying view is hidden from accessibility only until later in the same `apply`. `flightsBatchApplied()` runs, then `navigation.sync` (`PresenterMac.swift:1062`). A flight batch also creates, styles, and reparents the arriver, so that view is in `touched`, and a new arriver is in `reparented`, whose descendants are walked. `refreshInputGates` then sets `accessibilityHidden` from inert, visibility, and the aria prop only. The view now lives under `FlightClip` / `FlightLayer`, so that gate is false and the lift's `setAccessibilityHidden(true)` is overwritten before the frame is shown. Children are never hidden, and their AppKit frames ignore the layer scale, which is why the hide exists. Land's saved restore does not cover the frames in between. The new tests never call `apply` or `refreshInputGates`, so they stay green.

   **Fix:** Treat a node as hidden when it or an ancestor `isFlying`, in `refreshInputGates` (so this write stops clearing it, including descendants and the field / text area that loop already touches). Override `NodeView.isAccessibilityHidden()` with the same check so a descendant the gate does not visit stays hidden without storing `true` on it. After `landFlight` has dropped the flight and put the view back, run `refreshInputGates` on that view and its descendant nodes so a `true` stored during the flight does not stick. Add a test that lifts through `Presenter.apply` (a create, a style, and a child) and asserts the card and the child stay hidden, then asserts land restores the previous value.
