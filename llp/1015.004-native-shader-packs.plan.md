# LLP 1015.004 — Native game shader packs

Status: approved for implementation by parent review. Implementer: Codex Windows owner,
2026-10-04. User authorized reviewed engine papercut fixes. No working-set entry
or new blocking gate.

## Reproduction

Skirmish's authored `Fog` hook compiles and advertises one shader interface.
The direct GPU fixture registers its WGSL and passes. The actual Windows app
restores enabled sight and creates its hook resources, but reports `ready:false`
with `Skirmish fog: Unable to find entry point 'vs'`. Its image stays fully lit.

The Windows packager copies EXE/DLL/assets/deck but omits `copyShaders`.
The shared native `Surfaces::Abi` never calls the existing `gpu_shader` ABI.
Reflected `module()` consequently receives empty source. Native readback creates
device-free surface ownership using `create_headless`, which intentionally
allows absent shaders, then renders it without the ordinary `create` shader
readiness check. This is independent of audio, restore and the shader's name.

## Bounded correction

1. Windows packages the complete flat declared shader inventory through existing
   `copyShaders`, including preludes and its filesystem gate, into executable-
   relative `shaders/`. No checkout-relative runtime paths. Its completed package
   receipt observes WGSL bytes as well as executables. Remove only stale files
   inside that owned shader output, never authored roots or unrelated artifacts.
2. The shared native presenter loads primary runtime shaders through the existing
   `Assets` resolver and the compatibility shader roster before surface creation.
   Read/UTF-8/size/name failures identify the shader. Entry-zero bytes must match
   the baked asset size/SHA; selected-generation bytes use their existing verified
   resolver without entry-zero fallback. Validate every candidate using
   `gpu_shader_validate` before replacing the module's namespace with the existing
   clear/register ABI. The successful registration precedes any bind/readback.
   Named modules retain their existing separately compiled shader policy; missing
   runtime source there refuses at readback rather than implying support.
3. An already loaded primary module may see assets during an ordinary native plan
   reload. Compare the candidate byte digests; unchanged packs do no GPU work.
   Validate the whole changed pack before namespace mutation; rejected packs retain
   the prior registry and report refusal. Registering an accepted complete pack
   advances the existing shader generation, which readback already forwards into
   hook pipeline replacement. This does not add a new live-update transport.
4. `Module::readback` checks the registry's shader readiness before any render or
   readback allocation and refuses by name. `create_headless` remains valid with
   no device and no shader text for deterministic logic/proof operation. Shaderless
   games require no new runtime files or symbols. A surface blocked on shader
   readiness cannot report a successful image through the rendered path.

No new GPU ABI, shader reflection format, fog gameplay permission, save format or
platform target. The native loader uses existing bounded asset limits. Runtime
shader validation remains the module's interface authority; the host never guesses
shader entry points or normalizes invalid source.

  an actual fresh Windows process launched from unrelated cwd restores fog before
