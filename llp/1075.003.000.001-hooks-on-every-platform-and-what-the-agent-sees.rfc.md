## Summary

Charlie, 2026-10-06: "Can we write up an RFC for adding hooks to every
platform. They might make sense on Mac and Android and Linux and web too. We
also might want to be able to add stuff into your hooks code that gives agents
visibility into what's going on in them."

Hooks already reach further than one platform. iOS has the container hooks and
`element`; macOS has `element` and the window toolbar; the web's JS target has
`element` and the container hooks (§1). What is missing is: hooks above the
node (the app and its windows), a frame clock a hook can share with the agent,
Linux, an Android shape, and any way for hook code to say what it is doing.
The Signal clone shows each gap (§1.3).

- **D1. One model, four scopes, on every host.** A hook attaches to the
  **app** (`app`: lifecycle, appearance, its windows), a **window**
  (`window`, `windowEnded`), a **container** (as built), or a **node**
  (`element`, by `hook="word"`, as built). Same names in Swift, Kotlin, Rust
  and JavaScript. Nothing else in 1075.003.000 changes.
- **D2. Two kinds of host, one handle.** On an *object host* (Apple, the web,
  an Android host that makes Views) the handle carries the platform object. On
  a *painting host* (Linux, Windows, an Android host that paints) it carries
  the node's box, an overlay to draw into and the input that lands there.
  Every handle has the same `frame`, `data`, moments and acts.
- **D3. Hooks share Exact's clock.** `context.frames` ticks with the session's
  frame clock, `context.after` waits on the session's clock, and both follow
  `clock +ms` and `clock settle` under the agent. A hook's own display link or
  timer still runs on the wall, and the agent cannot step it.
- **D4. Into Contract only through what a person could do.** A hook reads
  only declared `data-*` words. It writes only by acting on authored nodes:
  `click`, `focus`, `blur`, and a new `input(value)`, the agent's `type`.
  Topics stay the data path. There is no `dispatch`, and no state read or
  write. Each act is journaled and lands between batches.
- **D5. The app works without its hooks.** The module loads after first
  pixel, so the first frame never has hooks. A host without hooks, a module
  that fails to load, or a development switch `EXACT_HOOKS=off` leaves an app
  whose behaviour runs on authored paths. A hook may add looks and gestures;
  anything that changes state stands for an authored control.
- **D6. Hook code can make itself observable.** `context.diagnostics` gives
  hook code `log`, `count`, `measure` and `publish`. Exact also times every
  hook call by itself. The results show in `logs`, `state.hooks`, a new
  `perf hooks` form, the late frames of `perf frames`, and Save Trace.
- **D7. The agent is told what it cannot see.** A hook declares a
  **hook-owned region** (`element.owns(…)`, `window.owns(…)`), and `tree`
  shows it. LLP 1080.001's opaque interiors then name their owner. A hook may
  also declare **parts**, the controls it drew. They appear under their node
  in `tree`, and `tap` reaches them (§10 Q1).
- **D8. Safety: the main thread, handles that end, crashes that leave a
  name.** A hook runs on the main thread, never inside a batch. A handle does
  nothing once its object ends. A crash inside a hook names the hook at the
  next launch. Hooks hold no grant the app lacks, and `hooks` joins the
  compatibility id.
- **D9. Build and scaffold.** `modules/<platform>/` per platform, as today.
  `exact.mjs hook <word>` declares a word and writes one stub per platform the
  app builds. Android is specified here and built with its host, which
  `DEFERRED.md` still holds.

Six questions for Charlie are in §10, each with a recommendation.

### 1.2 What the agent sees of them today

- `tree` prints `hook="word"` on the node on every host
  (`scripts/agent-inspect.mjs:138`, `:163`).
- `state.hooks`, per word, gives live nodes, reusable nodes, what each gave up,
  and calls by moment (`ElementHooks.swift:165-184`; the web's
  `exact.hookStats`, `hooks.js:24-26`, `agent.js:394`).
- The journal names each call. In a list row only the first of each moment is
  journaled (`ElementHooks.swift:137-151`, `hooks.js:19`, `:44`).
- **What a hook did is invisible.** No app line reaches the journal. On the
  web, `console.*` is captured as host lines (`scripts/agent.mjs:217`). No
  counter, no timing, nothing in `perf` or Save Trace
  (`FrameSampler.swift:215-265`), and no time measured for the calls
  themselves.
- **What a hook drew is opaque.** LLP 1080.001 counts a hooked node's,
  module's or platform kind's interior as `opaque`, unjudged and unnamed
  (1080.001 D3, and its r2 disposition 10).
- **What a hook drew cannot be driven.** A hook-made control stands for an
  authored one and calls its `click()` (1075.003 §3.4). The named action for a
  control with no counterpart was left to "its first case".

## 2. The model

### 2.1 Scopes and moments (D1)

A hook belongs to one of four scopes. Each moment runs on the main thread,
after the batch that caused it, never inside it (1075.003.000 §7.7).

| Scope | Hook | Moments | Handle carries |
|---|---|---|---|
| App | `app(_:)` | **built** once the module connects; **changed** when visibility, colour scheme, contrast or reduced motion change (the facts `exactPage()` and `prefer` already name, LLP 1069.000) | `ExactApp`: the platform application object, `visibility`, `colorScheme`, `windows` |
| Window | `window(_:)`, `windowEnded(_:)` | **built** for each window or scene the session draws in (replayed at connect), **changed** on a size class or safe-area change, **ended** | `ExactWindow`: the `UIWindow`/`UIWindowScene`, `NSWindow`, the document, or the painting host's surface; its `frame` |
| Container | `navigation`, `route`, `routeEnded`, `tabs`, `tabContainer`, `toolbar` | as built (1075.003 §3.2, 1075.003.000 §3.7) | as built |
| Node | `element`, `elementEnded` | built, changed (`data-*`), ended, as built | `ExactElement`, as built, plus §2.2 |

- **No hook runs before first pixel.** The app and window hooks run when the
  module connects, the turn after first draw, as every hook does today. So the
  first frame is always the hook-less app (D5). A hook that wants the launch
  screen tinted sets the tint in the host's manifest (`theme_color`), not in
  a hook.
- **Appearance is the app hook's.** Tint, bar appearance and the window's
  colour are set in `app` and `window`, and set again on `changed`. They
  follow the facts Exact already tracks, so a hook never polls the trait
  collection. What Contract authors (`accent-color`, `color-scheme`) is still
  Exact's to write (§2.3).
- **No per-frame moment.** A hook that wants frames asks for them (§2.4).

### 2.2 Two kinds of host, one handle (D2)

Every node and window handle has:
- `frame`: in window coordinates, the box Exact laid out, read-only;
- `data`, `hook`, `id`, `isNew`, `isLive`;
- `click()`, `focus()`, `blur()`, `input(_:)` (§2.5);
- `owns(_:)` and `parts` (§3.4, §3.5).

What it carries beyond that depends on the host:

| | Object host: Apple, web, an Android host of Views | Painting host: Linux, Windows, an Android host that paints |
|---|---|---|
| `view`, `platform` | the node's view and the kind's object, as built | nil |
| `overlay` | nil: the hook adds subviews or sublayers to `view` | a drawing the hook records, painted over the node's box after Exact's paint, clipped to the box (2D paths, fills, strokes, images and text, in the Canvas 2D list format `exact-canvas` already records and the Linux painter already replays, LLP 1056) |
| `input` | the platform's own gestures and events on `view` | the pointer and key events that land in the box, given to the hook before Exact's handling. The hook may claim one (Exact then sees a cancel), under LLP 1057's precedence |
| `window` | `UIWindow`, `NSWindow`, the document | the host's surface and its input |

- **The painting host's overlay is a recording, not a callback inside the
  paint.** A hook records into `overlay` at its moments or at a frame
  (§2.4), and the painter replays the latest recording. Exact's paint walk
  never calls app code, so a hook cannot stall or reenter the painter.
- **Linux gets hooks it can use.** A hooked node's overlay and input, the
  window's surface, `app`, and the frame clock. It still has no native
  objects, and the journal says so once, as today.
- **Android follows whichever renderer LLP 1076 picks.** If the host makes a
  View per node, it is an object host. If it paints (as
  `host/linux/src/android.rs` does), it is a painting host, with the
  `Activity` and `Window` on `app` and `window` either way. The names are
  fixed here. The code lands with the host, which `DEFERRED.md` holds.
- **The web's wasm target stays without hooks.** It builds games, whose render
  hooks are LLP 1046.006.000's, and conformance.

### 2.3 What a hook may touch

1075.003.000 §3.6's one rule extends to the new scopes: **Exact owns every
platform property an authored row or attribute writes; the app owns the
rest.**

| Area | The app may | Exact keeps |
|---|---|---|
| A node's view | add interactions, gestures, subviews, sublayers above Exact's; on a painting host, draw in `overlay` | frame, transform, alpha, hidden, its paint and its subviews, the gestures and accessibility it derives (as built) |
| Gestures | add recognizers to a node's view or the window, under LLP 1057's precedence; declare them (§3.4) | the gestures Exact derives from authored handlers; the dev menu's own gesture |
| Appearance, tint | set tint, bar appearance, window background, `overrideUserInterfaceStyle`, in `app`/`window`/containers | what `accent-color`, `color-scheme`, `theme_color` and authored rows set |
| The frame clock | subscribe (§2.4); run its own display link at its own cost | the session's clock, the frame source, `perf frames` |
| App events | observe visibility and the device facts (§2.1); observe the platform's own notifications directly | the facts' values as Contract sees them; the session's lifetime |
| Windows | style a window, add a toolbar item after Exact's, set a window's title bar look | which windows exist, their content view, their frames where Contract sets them |

The development check of 1075.003 §3.5 covers the new handles where Exact
records a last write (a window's background, the tint `accent-color` writes).
It journals a difference once and gates nothing.

### 2.4 The frame clock (D3)

```swift
// Swift
let ticket = context.frames { frame in … }     // frame.now: the session clock, ms; frame.seq
ticket.stop()
context.after(800) { … }                        // the session clock, not the wall
```

```js
// the page module
const stop = exact.frames(frame => { … });
exact.after(800, () => { … });
```

- **One frame source.** `frames` runs on the frame source the host already
  has: `FrameClockIOS`, the web's rAF loop, Linux's `frames.rs`. It wakes the
  source only while a ticket is live (LLP 1009 D4: frames only while something moves), and `frame.seq` is the
  commit sequence the frame presents (LLP 1079 D3).
- **Under the agent** the source steps with `clock +ms`, and `clock settle`
  runs `after` callbacks whose time has come. So the Signal frame meter,
  rebuilt on `frames`, measures the drive the agent made. The meter becomes
  mostly redundant with `perf frames`, which is the point.
- **Wall time is still available.** A hook that runs its own `CADisplayLink`
  or `DispatchQueue.asyncAfter` gets the wall. The agent cannot step it, and
  §4.5 says what that costs.
- **`context.now()` is unchanged**: the session's clock, the agent's under
  the agent (`ExactNativeModule.swift:98`).

### 2.5 Talking to the Contract app (D4)

**Into a hook:**
- **`data-*` words**, declared in `app.json` `data`, on a hooked node, a
  route or (new) the root. Rooted words reach `app` as `app.data`. This is how
  a hook reads state: the Contract projects what it wants the hook to know
  into a word, and the hook hears `changed`.
- **Facts** the host already tracks (§2.1).
- Nothing else. No hook reads the runner's state, a resource, or another
  node's props.

**Out of a hook:**
- **Acts on authored nodes**, as a person would: `click()`, `focus()`,
  `blur()`, and new, `input(value)`. `input` sets an authored field's value as
  the agent's `type` does, with its input event, and is refused by name on a
  node that is not an editable field. It answers the Signal search case.
- **Topics**, unchanged: `context.changed(topic)` asks every
  `native.watch(topic)` again, and the source asks back with `native.call` or
  `native.later` (LLP 1016.002, 1067.000).
- **No `dispatch(action)`, no state write, no emitted event that bypasses an
  authored handler.** Contract's handlers decide what happens. This is 1075.003
  §3.4's rule, kept.

**Determinism:**
- Every act is queued and runs after the batch being applied: on Apple on the
  main queue's next turn, on the web in a microtask (`ElementHooks.swift:221-225`,
  `hooks.js:36-39`), on Linux at the loop's next turn.
- Every act is a journal line `hook <word> #<id>: input "…" (delivery: hook)`,
  so `logs` reads it in order with the commits around it.
- Under the agent an act queued by a hook is in flight until it lands, and
  `clock settle` waits for it, as it waits for a native `later`.
- An act from a handle that has ended does nothing and is journaled
  (as built).

### 2.6 The app works without hooks, and parity (D5)

- **The first frame is hook-less** on every host (§2.1).
- **The hook-less app is the standard.** A host with no hooks (the wasm
  target), a module that fails to load (`state.native` names why), or
  `EXACT_HOOKS=off` in a development build runs the app with no hook called.
  The development switch is the test (§9): a smoke run with hooks off must
  reach the same states, by the same authored controls.
- **Looks may differ, behaviour may not.** A hook may change how a platform
  looks and feels: tint, a material, a gesture that is a shortcut. Anything
  that changes the app's state goes through an authored node (§2.5), so the
  web, the agent and the hook-less app reach it.
- **Parity is per platform, not lowest common denominator** (Charlie,
  2026-09-27). A hook on one platform needs no twin on the others. The
  journal says once per word which platforms' modules define the hook, and
  `state.hooks` lists them.

### 2.7 Refused

- **Native property names in Contract** (`DEFERRED.md`; 1035.006 12.08). Kept.
- **A hook that runs before first pixel**, or anywhere on the boot path
  (`RULES.md`).
- **A hook that writes Contract state**, dispatches an action by name, or
  reads the runner's state.
- **A hook inside a batch or inside the painter's walk.**
- **JavaScript above the data seam on native** (`DEFERRED.md` §Authoring
  models). Native hooks are Swift, Kotlin or Rust. The TypeScript experiment
  of 1075.003 §3.10 is unchanged and adopts nothing.
- **A hook on the wasm target**, and **a per-frame journal line**.
- **An eleventh agent operation.** Everything in §3 is a form of `tree`,
  `state`, `logs`, `perf` or `tap`.
- **Platform-suffixed route overrides** (`DEFERRED.md`). A hook configures
  what Exact built; it never replaces a route's authored tree.

## 3. What the agent sees (D6, D7)

### 3.1 What Exact measures by itself

With no app code:
- **Every hook call is timed** on the main thread while measuring is on, which
  is development trust (LLP 1079 D1). Calls, total ms and the worst call go
  per word and moment for nodes, and per hook for the other scopes.
- **A late frame names the hooks that ran in it.** A `perf frames` late
  record gains `hooks: [{ hook: "element avatar", calls: 12, ms: 9.8 }]` for
  the hook calls between its frame's start and its present. The join is by
  time window with stated coverage, as the record already joins commits by
  `seq` (1079 D3). It is not a causal trace.
- **Frame-clock tickets are counted**: live tickets per hook, and ms per
  tick.

### 3.2 What hook code adds: `context.diagnostics`

```swift
let d = context.diagnostics                       // also element.diagnostics, scoped to its word
d.log("swipe began at \(x)")                      // a journal line
d.count("swipes")                                 // a counter, +1
d.count("frames.over20", by: n)
let span = d.begin("swipe")  …  span.end()        // a timed span on the session clock
d.measure("swipe.worst", ms: worst)               // a sample of a named timing
d.publish("lastSwipe", ["worst": worst, "over20": n])   // a snapshot, JSON
```

```js
// the page module: e.diagnostics for a node, exact.diagnostics for the module
exact.diagnostics.count("swipes");
```

```rust
// Linux: ctx.diagnostics().count("swipes", 1);
```

- **Names** follow `data-*`'s rule: lowercase words, digits and `-`, with
  `.` to group. A bad name is refused by name in the journal, once.
- **Bounded.** `log` is rate-limited per hook: the first 20 lines of a
  second, then one `… N more`. A hook in a list row journals its first call
  per moment, as built, and counts the rest. At most 64 counters, 64 timings
  and 16 snapshots of 4 KB each per module. The excess is refused once by
  name.
- **Cheap when nobody is looking.** In production trust `log` goes to the
  platform log only (`os_log`, the console, stderr). `count`, `measure` and
  `begin`/`end` are a few stores into a fixed table, and `publish` keeps the
  latest value. Nothing is sent anywhere. Save Trace stays development-only
  (LLP 1079 D5).
- **Namespaced.** Every line and name is prefixed with the hook's scope
  (`hook element avatar: …`, `hook module: …`), so an agent can always tell
  hook output from Exact's.

### 3.3 Where it shows

| Read | What it gains |
|---|---|
| `logs` | `d.log` lines, every act (§2.5), refusals, the crash breadcrumb (§4.4) |
| `state.hooks` | per word or scope, as today, plus `platforms`, `owns` (§3.4), `parts` (§3.5), counters and published snapshots |
| `perf hooks` (a form of `perf`, 1079 D7: "a new measurement is a form of `perf`") | per hook: calls, total and worst main-thread ms, frame tickets, timings (count, p50, p95, max) and spans, over the window since the last read, tagged with `seq` like every `perf` read |
| `perf frames` | late frames' `hooks` (§3.1), and spans that overlap them |
| `perf <target>` | on a hooked site's row, its hook calls and ms |
| Save Trace, `agent.mjs trace <file>` | a `hooks` section: `state.hooks` and `perf hooks` at the moment of saving. A hook may ask for a save, `context.diagnostics.saveTrace()`, development only, so the Signal clone's Settings row needs no responder-chain call |

### 3.4 Hook-owned regions

A hook says what it owns that the agent cannot read:

```swift
element.owns(.subviews, "a title view: avatar, name, verified seal")
element.owns(.gesture, "long press: reaction picker")
window.owns(.gesture, "three fingers held 0.8 s: dev menu")
app.owns(.appearance, "tab bar tint: label")
```

- The kinds are `subviews` (or `overlay` on a painting host), `gesture`,
  `appearance` and `layer`, each with a sentence for the agent.
- **`tree`** shows them on the node or at the root as `owns: [{ by: "element
  title", kind: "subviews", what: "…", frame }]`.
- **LLP 1080.001** names the owner of an `opaque` interior where a hook
  declared one: `opaque: 85 (hook title 12, module 40, platform 33)`. An
  undeclared one stays plainly `opaque`.
- **A gesture a hook added and did not declare** is visible to the
  development check. It already walks a hooked node's view, and it counts its
  recognizers that are not Exact's. It journals once: `hook element avatar
  added a UILongPressGestureRecognizer it did not declare`.
- **Screenshots are unchanged.** Pixels are pixels. `tree` gives each region's
  frame, so the agent knows which pixels in a screenshot belong to which hook.

### 3.5 Hook parts: driving what a hook drew

A part is a control a hook drew, declared with what the agent needs to find
and press it:

```swift
element.parts = [ExactPart(id: "seal", role: "button", label: "Verified",
                           frame: seal.frame) { route.element("safety-number")?.click() }]
```

- **`tree`** lists parts under their node as `part`, with `id`, `role`,
  `label` and `frame`. They are not plan nodes, and `layout` refuses them by
  name.
- **`tap <node>/<part>`** reaches a part. With a real-touch carrier (LLP
  1080.000, `delivery: platform`) it is a touch at the part's frame, which
  the hook's own recognizer receives as a finger's. Under activation delivery
  the host runs the part's closure, reported `delivery: hook`.
- **The closure must act on an authored node** (§2.5). A part is a second way
  to reach a handler, never a new one.
- **1080.002** reads a part's platform accessibility element if the hook made
  one, keyed to the part's id. An unnamed interactive part is the existing
  finding.

This is what 1075.003 §3.4 left to "its first case", made narrower: no action
by name, a tap at a declared place, delivered as a finger where one can be.
§10 Q1 asks Charlie.

### 3.6 With LLP 1079 and LLP 1080

- **1079.** `perf hooks` is a form of `perf`, not an operation. The trace file
  gains a section, not a format. Times stay observations with their proxy
  named (1079 D6). Counts from `d.count` repeat when the inputs are
  controlled, as runner counts do.
- **1080.000.** Real touches reach hook gestures and parts unchanged.
  Activation delivery reaches parts through their closures.
- **1080.001.** Hook-owned regions attribute `opaque`. A hook's own subviews
  stay unjudged: Exact does not own that subview list.
- **1080.002.** `tree --ax` already reads what the platform exposes, hook UI
  included. Parts join it by id.
- **1080's constraints hold.** There is no new operation. Every list is
  bounded and says `truncated`. A painting host's part has no accessibility
  element and reports `unavailable`.

## 4. Safety (D8)

### 4.1 Threads

- **Every hook runs on the main thread** (Apple, and the UI thread on
  Android). On the web it runs on the page's thread. On Linux it runs on the
  host's loop thread, never the painter's.
- **Never inside a batch, a reset or the painter.** Acts are queued past them
  (§2.5).
- **Never on the owner thread** (LLP 1072). A hook cannot reach a runtime, so
  it cannot reenter the owner.
- **`diagnostics` is callable from any thread.** Lines and counters from
  another thread go through a lock-free ring that the main thread drains. A
  handle's other members stay main-thread only, and Apple asserts it in
  development (`hookSession`'s existing check, `NativeHooks.swift:62-65`).

### 4.2 Lifetime

- **A handle lives while its object does.** After `ended` (or
  `windowEnded`), `view`, `platform` and `overlay` are nil, and acts do
  nothing and are journaled (as built for nodes, 1075.003.000 §7.7).
- **Frame tickets and `after` callbacks** belong to the scope that made them.
  They stop when it ends: a node's at `elementEnded`, the module's at the
  session's end. A ticket left running past its node is impossible by
  construction, not by check.
- **Parts and owned regions** go with their node.

### 4.3 Reload and delivered updates

- **A plan reload** ends every hooked object and builds again (LLP 1024 D6).
  The app and window hooks hear `changed`, not a rebuild, because the
  platform's window survives a reload.
- **A hook edit** is a native change: a rebuild and a restart on Apple,
  Android and Linux (1024 D6, LLP 1030), and a page reload on the web. That
  does not change here.
- **A gap to close: `hooks` and `data` are not in the compatibility id.**
  `nativeModules` carries the roster's tags (`bake/src/compat.rs:330`), but
  not the hook or data words. So a delivered plan can mark a node with a word
  the installed module was compiled without, and its `ExactHookKey` never
  matches. Proposed: the declared `hooks` words join `nativeModules` in the
  id, so a new word is a new binary stream. `data` words do not join it: a
  hook ignores a word it does not read. §10 Q6.

### 4.4 Crashes in hook code

- **Apple and Android cannot catch a crash in native code.** Swift traps and
  Kotlin's uncaught exceptions end the process. So the host leaves a
  breadcrumb. Before each hook call it writes the hook's name into a fixed
  slot that the crash handler and the next launch can read. At the next
  launch the journal's first line is `the last run ended inside hook element
  avatar (built)`, and `state.native.lastCrash` carries it. That costs one
  store per call.
- **Kotlin and Rust hooks are called inside a catch** (`try`/`catch`,
  `catch_unwind`). A panic or exception is journaled with the hook's name.
  The hook that threw is not called again this session, and the app goes on
  without it, hook-less (§2.6).
- **The web** already catches and journals a throw (`hooks.js`, `call`). It
  gains the same not-called-again rule.
- **No automatic disable across launches.** A crash loop in a development
  build is fixed by `EXACT_HOOKS=off`, which the breadcrumb line names.

### 4.5 Privacy and capabilities

- **Hooks hold no grant the app lacks.** The context gives a hook no token,
  keychain item, resource, fetch, or another session's data. Its directories
  are the module's own (`ExactModuleContext.data`, `cache`, `temporary`), and
  a scratch tree under the agent.
- **Native hooks are declared, not enforced** (LLP 1069.008 D3): in-process
  native code can call any platform API. The OS enforces the device
  permissions, through the keys the app's `device.*` grants put in the binary.
  A hook that uses the camera without the grant fails at the OS, as a module
  does. The documentation says this plainly. Exact makes no claim to sandbox
  native code.
- **On the web, the page's own policies hold.** A page-module hook runs under
  the CSP and `Permissions-Policy` the bake derives from the grants (LLP 1048
  D11, 1069.008 D4), like any page script.
- **Under the agent a hook substitutes, as modules do.** `context.agent` is
  true. A hook that reaches a device (the photo library, haptics, the
  pasteboard) answers from a substitute, never the OS (LLP 1069.007). It never
  prompts.
- **Diagnostics are the app's own data.** They stay in the journal, the
  trace file and the platform log, under the same development gate as the
  rest (§3.2). They are never uploaded.

### 4.6 Determinism under the agent clock

- **Repeatable:** the moments (ordered by batches), acts (journaled,
  settled), `context.now`, `frames` and `after` (stepped), `d.count` (when
  the inputs are controlled), and UIKit animation a hook starts (frozen under
  agent timing, `Session.swift:65-72`, like Exact's own).
- **Not repeatable, and named:** a hook's own display link, wall timers,
  `Date()`, `CACurrentMediaTime()` and threads. The documentation lists them.
  `perf hooks` marks a hook that holds a display link the host did not give it
  only where the host can see one (a `CADisplayLink` on the node's view is not
  visible to Exact; one asked through `frames` is).
- **`clock settle`** waits for queued acts and due `after` callbacks. It does
  not wait for a hook's own timers, which it cannot see.

## 5. Build, packaging, scaffolding (D9)

| Platform | Files | Built by | Into | Loaded |
|---|---|---|---|---|
| iOS, iPadOS, tvOS, macOS | `modules/apple/*.swift` (or `<platform>/modules`), one `ExactModule` subclass | `host/apple/build.mjs`, with `ExactNativeModule.swift` and the generated keys | `libexact_modules.dylib` | `dlopen` the turn after first draw (as built) |
| Web | `modules/web/index.js`, the page module, or `index.ts` (Rolldown strips the types, and the export scan reads TS) | `host/web-js/build.mjs` | the page module, and `hooks.js` only for a plan that marks a node or a module that exports a hook (as built) | after first paint (as built) |
| Linux, Windows | `modules/linux/*.rs`, one type that implements `exact_linux::Hooks` (default methods do nothing), named once: `pub type ExactHooks = App;` | the app's own Linux crate: the generated `entry.rs` `include!`s the module and passes it to the host at boot | the app's binary, statically: no `dlopen`, no C table, no cargo feature on a core crate | the host calls `app` after first present |
| Android | `modules/android/*.kt`, one `ExactModule` subclass, the same names | the Android host's Gradle build, when it exists | the app's APK | after first frame |

- **One declaration authority.** `app.json` `hooks` and `data` stay the word
  lists. Each platform gets typed keys: `ExactHookKey` and `ExactDataKey` in
  Swift and Kotlin, a `HookKey` enum in Rust, and a frozen object in
  JavaScript (`exact.hooks.avatar`), whose misuse the build reads from the
  export scan where it can.
- **The ABI grows by size.** `app`, `window`, `windowEnded`, `frames`,
  `after`, `diagnostics` and `parts` take new module-table and
  host-table entries past 184 and 48. An older module's shorter table still
  loads with none of them (1075.003 §3.9).
- **`bun scripts/exact.mjs hook <word> [--app | --window]`** adds the word to
  `app.json` `hooks` (for a node) and writes one stub per platform the app
  declares under `host`. Each stub implements the hook's moments and its end,
  declares an owned region, and has one `d.log`. Each says what the hook gives
  up on that platform (1075.003.000 §3.5). An app with no module gets one
  file per platform with the module's boilerplate (`let exactModule = …`). It
  is the only new verb, and it writes files that the app owns.
- **The agent's documentation.** The app template's `AGENTS.md` (LLP 1086)
  gains a section on hooks: the verb, the rule of §2.5, `EXACT_HOOKS=off`, and
  how to read `perf hooks` and `owns`.

## 6. Alternatives

- **Hooks in TypeScript on every platform** (one language, bound to native
  objects). This is 1075.003 §3.10's experiment. It is refused here because it
  runs JavaScript in the tree on native, and its thread and lifetime questions
  are open. It would give the same handles to the same scopes. Nothing in this
  design forecloses it.
- **An event bus from hooks into Contract** (`dispatch(action, payload)`).
  Simpler for authors and wrong for parity: the web, the agent and the
  hook-less app could not reach what a hook dispatched. Acts on authored
  nodes keep one path.
- **Agent visibility by scraping:** read the platform's view tree and
  accessibility tree and guess. 1080.001 and 1080.002 already do the
  platform's part. They cannot say *whose* a view is or *why* it is there, and
  only the hook knows that.
- **Exposing the platform's own tracing** (`os_signpost`, `console.time`,
  Perfetto) instead of `diagnostics`. Instruments and Chrome still work, and a
  hook may use them. They do not reach `perf`, `state` or the trace file on
  every host, and they would give the agent four formats to read.
- **Linux: the C ABI and `dlopen`, as the GPU module.** That matters only if
  hooks must be delivered apart from the binary, which a native change never
  is (LLP 1030). Static linking is simpler, and the app's Linux crate already
  exists.
- **No painting-host hooks; Linux keeps "none".** That is honest, but it
  leaves Linux, Windows and a painted Android with no app-level escape hatch.
  The overlay is a bounded one: it records draws Exact already knows how to
  paint.

## 7. Risks

- **The escape hatch becomes the road** (1075.003.000 §5). Hooks on every
  scope invite more native code. The mitigations: the hook-less smoke (§9), the
  journal, `perf hooks` and `owns`, which make a heavy hook visible.
- **Diagnostics become a second telemetry system.** They are capped, kept in
  memory, development-gated for the trace, never uploaded, and refused past
  their bounds. Production telemetry is EAS Observe's (LLP 1079 D7).
- **Declared regions and parts can lie.** A hook can declare a part at the
  wrong frame. A real-touch `tap` then misses, and the drive fails loudly,
  which is the right failure. The development check compares a part's frame
  with its view's when the part names a view.
- **The overlay drifts into a second canvas API.** It is limited to the Canvas 2D list
  format `exact-canvas` already records, clipped to the box, and replayed. Anything
  more is a `canvas` node.
- **The ABI grows by six entries.** Each lands with its fixture case, or is
  not added.
- **Android's shape is written before its host.** If LLP 1076 picks a
  renderer that fits neither column of §2.2, the Android row is revised with
  the host's RFC. The names stay.

## 8. Stages

Each stage lands with its fixture cases in `apps/native-fixture`, its tests in
existing binaries, and an amendment to this document's as-built section.

1. **Diagnostics and timing on the hosts that have hooks** (Apple, web JS).
   Exact times every call; `context.diagnostics`; `state.hooks` gains
   counters and snapshots; `perf hooks`; late frames' `hooks`; Save Trace's
   `hooks` section and `saveTrace()`. The crash breadcrumb and the web's
   not-called-again rule. *Acceptance:* `smoke.mjs <ios|macos|web> --app
   native-fixture` reads a `d.log` line, a counter, a span in `perf hooks`, a
   hook named in a late frame it forced (a 30 ms busy loop on a debug button),
   and the trace's section. The Signal frame meter, ported to the fixture,
   reports through `publish`.
2. **App and window scopes, and the frame clock** (Apple, web JS). `app`,
   `window`, `windowEnded`; rooted `data-*`; `frames`, `after`; `input(value)`.
   *Acceptance:* the fixture tints its window per colour scheme on every
   host. A frame ticket counts frames that `clock +1000` steps (60 at 60 Hz,
   under the agent). `input` types into an authored field, and the commit
   shows it.
3. **Owned regions and parts.** `owns`, `parts`, the undeclared-gesture line,
   1080.001's attribution, `tap <node>/<part>` (if Q1 rules it).
   *Acceptance:* the fixture's hooked dot declares a long-press region and a
   drawn part. `tree` shows both, and `tap dot/part` runs the authored
   handler under activation delivery on iOS and macOS, and under platform
   delivery where 1080.000's carrier runs.
4. **Linux.** `exact_linux::Hooks`, `modules/linux/`, the overlay and input,
   `app`, `window`, `frames`, `diagnostics`. *Acceptance:* `smoke.mjs linux
   --app native-fixture` sees the dot's overlay in a screenshot, its claimed
   press, the module's counter, and `perf hooks`. Windows inherits it with no
   code of its own, which one Windows build checks.
5. **The compatibility id** (§4.3), with Q6, in any stage.
6. **The `hook` verb and the template's `AGENTS.md`**, after stage 2.
7. **Android**, with the Android host and its own RFC, under §2.2's names.

## 9. Test plan

- **The fixture is the contract** (1075.003 §3.9). `apps/native-fixture`
  gains a module per platform that exercises every scope, the frame clock,
  every diagnostics call, an owned region and a part.
- **UIKit XCTests** (in the async lane for `host/apple`) cover the
  breadcrumb, the timing of a call, ticket lifetime across `elementEnded` and
  a reload, `input` on a non-field (refused), and acts queued past a batch.
- **Web**: the JS target's tests, plus `smoke.mjs web --app native-fixture`.
  The cores of Caltrain, RealWorld and video-player stay byte-identical, so a
  plan that marks nothing pays nothing (link by use, as built).
- **Linux**: `cargo test -p exact-linux --lib --tests` covers the overlay
  replay, input claim, `catch_unwind` and the not-called-again rule.
  `smoke.mjs linux` drives the fixture.
- **Hook-less parity**: `smoke.mjs <host> --app native-fixture` with
  `EXACT_HOOKS=off` reaches every state the hooked run reaches, by authored
  controls. This is the D5 test, and it runs where the smoke runs, not in the
  gate.
- **Determinism**: two agent drives of the same steps under the agent clock
  give identical `d.count` values, frame ticket counts and act journal lines.
- **Cost**: stage 1 repeats 1075.003.000.000's interleaved series on the
  Extra Heavy feed with every row's avatar hooked, the hook calling `d.count`
  and `d.log`, against the hook empty. The documentation quotes it. Expected:
  within noise, since the call itself was.

## 10. Questions for Charlie

### Q1 — Driving what a hook drew

**Recommended (a):** parts (§3.5). The agent taps a declared part, as a real
touch where the carrier exists and through its closure otherwise. The closure
must act on an authored node. This amends LLP 1012's "an agent never runs an
action by name" only so far as a part's closure stands in for a finger. *(b):*
keep today's rule: a hook-made control calls an authored one, and the agent
taps that. That is simpler, but the agent never exercises the hook's own
control. *(c):* no parts at all, regions only.

### Q2 — `input(value)` on an authored field

**Recommended: yes.** It is the agent's `type`, given to a hook, so a native
search field or a picker can feed an authored field (the Signal case).
Refused: a general `setValue` on any node, or a state write.

### Q3 — Linux and the painting hosts

**Recommended (a):** the overlay and input (§2.2), plus the app, window and
frame hooks. *(b):* only app, window and frame hooks, so a node stays "shown
and never called". *(c):* none, as today.

### Q4 — Android now or with its host

**Recommended:** fix the names and the two-column shape now (§2.2, §5), and
build nothing until the Android host exists. `DEFERRED.md` still holds
Android, and this RFC does not move it.

### Q5 — Diagnostics in production builds

**Recommended:** they run, capped, in memory. `log` goes to the platform log.
Nothing leaves the device, and Save Trace stays development-only. *(b):*
compile them to nothing in production. That is cheaper, but a person's
`os_log` loses the lines and the crash breadcrumb loses its context.

### Q6 — `hooks` in the compatibility id

**Recommended: yes** (§4.3). A delivered plan should not mark a node with a
word its binary's module was compiled without.
