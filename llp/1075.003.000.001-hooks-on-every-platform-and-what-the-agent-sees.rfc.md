## Summary

Charlie, 2026-10-06: "Can we write up an RFC for adding hooks to every
platform. They might make sense on Mac and Android and Linux and web too. We
also might want to be able to add stuff into your hooks code that gives agents
visibility into what's going on in them."

Hooks already reach further than one platform. iOS has the container hooks and
`element`; macOS has `element` and the window toolbar; the web's JS target has
`element` and the container hooks (§1). Several things are still missing:
hooks above the node (the app and its windows), a frame clock a hook shares
with the agent, Linux and Windows, an Android shape, and any way for hook
code to say what it is doing. The Signal clone runs into each gap (§1.3).

- **D1. One model, four scopes.** A hook attaches to the **app** (`app`:
  lifecycle and appearance), a **window** (`window`, `windowEnded`), a
  **container** (as built) or a **node** (`element`, by `hook="word"`, as
  built). The names are the same in Swift, Kotlin, Rust and JavaScript. The
  module stays one per session (LLP 1067.000), and so does each handle.
- **D2. Two kinds of host, one handle.** On an *object host* (Apple, the web)
  a handle carries the platform object. On a *painting host* (Linux, Windows)
  it carries the node's box, an overlay the hook replaces whole, and the input
  that lands there, to observe only. Android's shape stays provisional until
  its renderer is chosen.
- **D3. Hooks share the session's clock.** `context.frames` ticks at the
  instants LLP 1073's frame tasks fire: presented frames on the wall, and the
  virtual 60 Hz display under the agent. `context.after` waits on the session
  clock. Both are logical time, for behaviour. Measured time stays LLP 1079's,
  and under the agent `perf frames` stays `virtual`.
- **D4. Into Contract only through what a person could do.** A hook reads
  only declared `data-*` words. It writes only by acting on authored nodes:
  `click`, `focus`, `blur`, and a new `input(text)` that goes through the
  agent's own `type` path. Topics stay the data path. There is no `dispatch`,
  and no state read or write. Every act is journaled without its value,
  counted in flight, and lands between batches. `clock settle` waits for it.
- **D5. The app works without its hooks.** No hook runs before first pixel.
  `EXACT_HOOKS=off` turns hooks off in a development build and leaves the
  module's views and calls alone. With hooks off, the app's Contract state is
  reachable through authored acts. A hook-only surface that changes no
  Contract state (a dev-menu shortcut, a frame meter) is allowed if it is
  declared.
- **D6. Hook code can make itself observable.** `context.diagnostics`
  (`log`, `count`, `measure`, `begin`/`end`, `publish`) is bounded and
  development-only, like `perf`. Exact also times every hook call itself.
  Reads are cumulative and change nothing. Results show in `logs`,
  `state.hooks`, a `perf hooks` form, a person's late frames (on wall time
  only), and Save Trace.
- **D7. The agent is told what it cannot see.** A hook binds an owned region
  to a platform object it made (`owns(view:…)`). The host observes the
  object's frame and life, and `tree` shows both the declaration and what the
  host observed. 1080.001's opaque interiors name their owner. A hook may
  also declare **parts** bound to a view. They show in `tree` and join
  `tree --ax`. Whether `tap` may reach them is §10 Q1, and the
  recommendation is real platform input only, never a closure.
- **D8. Safety.** Teardown runs synchronously inside the batch, as built.
  Built and changed run after it. Callbacks carry the session's incarnation,
  and stale ones are dropped. A crash leaves a persisted breadcrumb. A Kotlin
  or JavaScript throw is caught, and its hook still gets its teardown. Hooks
  hold no grant the app lacks. A plan that marks a word the installed module
  does not handle is a binary change, through 1030 D3's classifier.
- **D9. Build and scaffold.** `modules/<platform>/` per platform. Windows gets
  its own adapter. The web stays `index.js`. `exact.mjs hook <word>` writes
  one stub per platform the app builds. Android is named here and built with
  its host, which `DEFERRED.md` still holds.

Six questions for Charlie are in §10, each with a recommendation.

### 1.2 What the agent sees of them today

- `tree` prints `hook="word"` on the node on every host
  (`scripts/agent-inspect.mjs:138`, `:163`).
- `state.hooks`, per word, gives live nodes and calls by moment. Apple adds
  reusable nodes and what each gave up (`ElementHooks.swift:165-184`). The
  web's `exact.hookStats` leaves `reusable` at 0 and `lost` empty, which fits
  "gives up nothing" there (`hooks.js:24-26`, `agent.js:394`).
- The journal names each call. In a list row only the first of each moment is
  journaled (`ElementHooks.swift:120-123`, `hooks.js:44`).
- **What a hook did is invisible.** No app line reaches the journal. On the
  web, `console.*` is captured as host lines (`scripts/agent.mjs:217`). No
  counter, no timing, and nothing in `perf`. Save Trace carries identity,
  proxies, plan, journal, frames and `perf`, and no hooks
  (`FrameSampler.swift:220-241`). The calls themselves are not timed.
- **What a hook drew is opaque.** LLP 1080.001 counts a hooked node's,
  module's or platform kind's interior as `opaque`, unjudged and unnamed
  (1080.001 D3).
- **What a hook drew cannot be driven.** A hook-made control stands for an
  authored one and calls its `click()` (1075.003 §3.4). The named action, for
  a control with no counterpart, was left to "its first case", which must
  amend LLP 1012 or be refused.

## 2. The model

### 2.1 Scopes and moments (D1)

The module is one instance per session (LLP 1067.000). Each handle below
belongs to that session.

| Scope | Hook | Moments | Handle carries |
|---|---|---|---|
| App | `app(_:)` | **built** when the module connects; **changed** when visibility, colour scheme, contrast or reduced motion change (the facts `exactPage()` and `prefer` name, LLP 1069.000), or when a root `data-*` word changes | `ExactApp`: the platform application object, those facts, root `data` |
| Window | `window(_:)`, `windowEnded(_:)` | **built** for each surface the session presents into (replayed at connect); **changed** on a size or safe-area change; **ended** before the session leaves the surface | `ExactWindow`: the `UIWindowScene` and `UIWindow`, the `NSWindow`, the document, or the painting host's surface; its `frame`; `shared` (§2.1.1) |
| Container | `navigation`, `route`, `routeEnded`, `tabs`, `tabContainer`, `toolbar` | as built (1075.003 §3.2, 1075.003.000 §3.7) | as built |
| Node | `element`, `elementEnded` | built, changed (`data-*`), ended, as built | `ExactElement`, as built, plus §2.2 |

**When each moment runs.** This is the order 1075.003.000 §7.7 settled, for
every scope:
- **Ended runs synchronously, inside the batch or reset that removes the
  object**, before its view or surface goes. That is how `reusable` works, and
  how a hook removes a recognizer before its view is reused. Acts asked for in
  an ended moment are queued like any other (§2.5).
- **Built and changed run after the batch**, in the order the batch built
  them: the app, then windows, then containers, then nodes.
- **No hook runs before first pixel.** The module is prepared and connected
  the turn after first draw. So the first frame is the hook-less app on every
  host (D5). A hook that wants the launch tinted uses `theme_color`.
- **Under the agent, hooks run.** They are journaled, and their effects are
  governed by §2.4 and §4.6.

#### 2.1.1 Two sessions, one surface

macOS's sample host embeds two sessions in one window
(`ExactHostMac/main.swift:48`). Each session's module hears `window` for the
window it presents into, with `shared = true`. A hook on a shared window may
style only what it owns through `owns` (§3.4). The window's title bar,
toolbar and background are the embedder's, and the development check
journals a write to them from a shared window's hook. An app that is the
window's only session has `shared = false` and the whole of §2.3's row.

#### 2.1.2 Ownership of what a hook registers

Everything a hook registers belongs to a scope and carries that scope's
**incarnation** (the session's plan generation):
- `context.frames`, `context.after` and the module's diagnostics belong to
  the session. They end at the session's end and at a plan reload.
- `element.owns`, `element.parts` and an element's diagnostics belong to the
  node. They end at `elementEnded`. A reused view's (§1.1, `reusable`) are
  cleared by the host before the next node's `element`.
- `window.owns` belongs to the window and ends at `windowEnded`.
- A callback registered under an earlier incarnation is dropped and
  journaled once (`hook frames: a ticket from before the reload was dropped`).
  A handle cannot outlive its object in a way that reaches the next object.

There is no node-scoped frame ticket. LLP 1073 admits frame tasks at the
root only (`DEFERRED.md`, "one root task form"), and the session scope keeps
hooks inside that line.

### 2.2 Two kinds of host, one handle (D2)

Every node and window handle has:
- `frame`: in window coordinates, the box Exact laid out, read-only, current
  as of the last batch;
- `data`, `hook`, `id`, `isNew`, `isLive`;
- `click()`, `focus()`, `blur()`, `input(_:)` (§2.5);
- `owns(…)` and `parts` (§3.4, §3.5).

| | Object host: Apple, web | Painting host: Linux, Windows |
|---|---|---|
| `view`, `platform` | the node's view and the kind's object, as built | nil |
| `overlay` | nil: the hook adds subviews or sublayers to `view` | §2.2.1 |
| Input | the platform's own gestures and events on `view`, under LLP 1057's precedence | `observe(input:)`: the pointer and key events that land in the box, after Exact has handled them, read-only (§2.2.2) |
| `window` | `UIWindow`, `NSWindow`, the document | the host's surface |

- **Linux and Windows get hooks they can use:** the overlay, observed
  input, the app and window hooks, the frame clock and diagnostics. They
  still have no native objects, and the journal says so once, as today.
- **Android stays provisional** (§10 Q4). LLP 1076 includes hybrids, where
  some nodes are Views and the rest are painted, so a host-wide split may not
  fit. If it fits neither column, the per-node answer is: a node that is a
  View gets `view`, and a painted node gets `overlay`. The scope names and
  moments are fixed; the handle's members are revised in the Android host's
  RFC.
- **The web's wasm target stays without hooks.** It builds games, whose
  render hooks are LLP 1046.006.000's, and conformance.

#### 2.2.1 The overlay on a painting host

The overlay is a protocol, not a canvas:
- **A recording replaces the last one whole.** `overlay.draw { list in … }`
  records a fresh Canvas 2D list (LLP 1056's ops, its list format) against
  the box's current size, and publishes it. It has no persistent pixels, no
  carried state, and no incremental append. Nothing blends twice, and
  nothing depends on an earlier recording. `overlay.clear()` publishes the
  empty list.
- **Size.** A recording carries the box size it was recorded at. When the
  box's size changes, the host drops the recording, and the hook hears
  `changed` with the new `frame` and records again. A stale size is never
  stretched.
- **Clip and order.** Clipped to the node's border box, painted after the
  node's own paint and its descendants, and below the next sibling. The
  overlay is the node's top-most content, and it never paints outside the
  node.
- **Resources.** Images in a recording are named by the app's asset URLs and
  resolved through the host's image cache. A recording owns nothing that
  outlives it.
- **Threads and handoff.** On Linux and Windows the hook runs on the host
  loop's thread, between turns. A publish swaps a pointer that the painter
  reads at the start of its next paint. One recording is pending at a time,
  and the latest wins. The paint walk never calls hook code, and a hook never
  sees a half-painted frame.
- **Bounds.** A recording is at most 4,096 ops and 256 KB. A larger one is
  refused by name, and the last good one stays.

#### 2.2.2 Input on a painting host: observe only

Exact is the hit-tester on Linux and Windows. A hook that could claim an
event would make Exact's dispatch a negotiation, which is the gesture arena
`DEFERRED.md` refuses. So a hook only observes: it gets each pointer and key
event in its box after Exact's dispatch, with `handled` saying whether an
authored handler or a scroll took it. To act, it uses §2.5's acts. Claiming
input on a painting host is out of scope here and would need its own LLP and
a ruling on the arena.

### 2.3 What a hook may touch

1075.003.000 §3.6's one rule extends to the new scopes: **Exact owns every
platform property an authored row or attribute writes; the app owns the
rest.**

| Area | The app may | Exact keeps |
|---|---|---|
| A node's view | add interactions, gestures, subviews, sublayers above Exact's; on a painting host, publish an `overlay` | frame, transform, alpha, hidden, its paint and its subviews, the gestures and accessibility it derives (as built) |
| Gestures | add recognizers to a node's view or (unshared) window, under LLP 1057's precedence; declare them (§3.4) | the gestures Exact derives from authored handlers; scroll; the dev menu's own gesture |
| Appearance, tint | set tint, bar appearance, window background, `overrideUserInterfaceStyle`, in `app`, `window` (unshared) and containers | what `accent-color`, `color-scheme`, `theme_color` and authored rows set |
| Logical time | `context.frames`, `context.after` (§2.4) | the session clock, the frame source, the runner's frame tasks |
| Measured time | its own display link, at its own cost, reported through `measure` (§3.2) | `perf frames` and its sampler |
| App events | observe the facts of §2.1; observe the platform's own notifications | the facts' values as Contract sees them; the session's lifetime |
| Windows | style an unshared window, add a toolbar item after Exact's, set a title bar's look | which windows exist, their content view, frames that Contract sets |

The development check of 1075.003 §3.5 covers the new handles where Exact
records a last write (a window's background, the tint `accent-color` writes,
a shared window's chrome). It journals a difference once and gates nothing.

### 2.4 The frame clock: logical time (D3)

```swift
// Swift
let ticket = context.frames { frame in … }     // frame.now: session clock, ms; frame.seq: the commit it follows
ticket.stop()
context.after(800) { … }                        // the session clock
```

```js
// the page module
const stop = exact.frames(frame => { … });
exact.after(800, () => { … });
```

`frames` and `after` are logical time. They are for behaviour that must keep
step with the app, such as a hook-drawn indicator that follows an animation.
They are not for measuring the display, which §3 covers.

- **The same instants as LLP 1073's frame tasks.** While a ticket is live the
  host registers a frame interest with the runner, as a root frame task does.
  The source then runs (1073 D2), and a ticket fires at each frame after that
  frame's tasks and timers, in registration order, with `frame.now` the
  frame's time.
- **On the wall** that is each presented frame.
- **Under the agent** it is 1073 D3's virtual display: `clock +1000` passes
  sixty instants on every host, bit for bit. The runner's seek returns the
  virtual instants it passed while an interest is registered. The host then
  calls each ticket once per instant, in time order, after the seek's
  commits are applied, so a tick sees its own `frame.now` and the state as of
  the end of the seek. Ticks count against the seek's `TimerFireLimit` like
  frame tasks.
- **`after`** fires at its due time on the session clock. Under the agent, a
  seek runs the callbacks that came due, in time order, with ties broken by
  registration. They run after the seek's commits, interleaved with ticks by
  time.
- **Acts** asked for from a tick or an `after` callback are queued (§2.5).
  They land at the next batch boundary, after the seek. A tick never applies
  a batch.
- **`perf frames` stays as LLP 1079 built it:** wall-clock observations, and
  `{"virtual": true}` under the agent (1079 D4). A ticket does not keep the
  frame sampler running (1079 D3).
- **`context.now()` is unchanged**: the session clock
  (`ExactNativeModule.swift:98`).

A hook's own `CADisplayLink`, `requestAnimationFrame` loop or wall timer is
the wall. The agent cannot step it, and §4.6 says what that costs.

### 2.5 Talking to the Contract app (D4)

**Into a hook:**
- **`data-*` words**, declared in `app.json` `data`, on a hooked node, a
  route or (new) the root. A root word reaches `app` as `app.data`, and its
  change is a `changed` moment on `app`. This is how a hook reads state: the
  Contract projects what the hook should know into a word.
- **Facts** the host already tracks (§2.1).
- Nothing else. No hook reads the runner's state, a resource, or another
  node's props.

**Out of a hook:**
- **Acts on authored nodes**, as a person would: `click()`, `focus()`,
  `blur()`, and new, `input(text)`. `input` enters text into an authored
  editable field by **the same host entry the agent's `type` uses**, so
  filters, `maxlength`, input events and composition rules are one code
  path. It is refused by name on a node that is not an editable field.
- **Topics**, unchanged: `context.changed(topic)` re-asks every
  `native.watch(topic)`, and the source asks back with `native.call` or
  `native.later` (LLP 1016.002, 1067.000).
- **No `dispatch(action)`, no state write, no event that bypasses an authored
  handler.** That is 1075.003 §3.4's rule, kept.

**Every act is queued, counted and journaled:**
- **One FIFO per session**, owned by the host. Apple's acts move from
  `DispatchQueue.main.async` (`ElementHooks.swift:225`) into it. It is
  drained at the main queue's next turn, as today, and also by the agent's
  settle pump (below). The web keeps its microtask (`hooks.js:36-39`), and
  Linux and Windows drain at the loop's next turn.
- **In flight.** The FIFO's length, plus due `after` callbacks, plus (on the
  web) the page module's load, is the host's `hookInFlight` count. A queued
  act counts until it has run, not until it was scheduled.
- **`clock settle`** waits for `hookInFlight` to reach zero, as it waits for
  runner requests. On Apple the settle loop runs on the main thread
  (`Agent.swift:526-556`), so it drains the FIFO itself in its pump step
  (`settlePump`) rather than waiting on a queue it is blocking. The same
  bound applies: 16 rounds, then `reason: "hooks"`.
- **The journal** gets `hook element search #q: input (5 chars, delivery:
  hook)`. It records the length, never the text, and nothing at all for a
  `type=password` field beyond `input (protected)` (1080.002's protected
  values).
- **An act from an ended handle** does nothing and is journaled, as built.

### 2.6 The app works without hooks, and parity (D5)

- **The first frame is hook-less** on every host (§2.1).
- **`EXACT_HOOKS=off`** (development builds only, dropped with `EXACT_AGENT*`
  in production trust) connects no hooks. The module still loads, and its
  views and calls work. It is a different state from **a module that failed
  to load**. There the views are unavailable boxes and the calls fail
  (LLP 1024 D2, `state.native`), and the author's obligations are 1024's,
  unchanged. This RFC promises nothing about an app whose module is
  missing.
- **What "works" means.** With hooks off, every Contract state the hooked app
  reaches is reached by authored acts (`tap`, `type`), as the smoke drives
  them. The test is the fixture's (§9), not a promise about every app.
- **Looks may differ, behaviour may not.** A hook may change how a platform
  looks and feels. Anything that changes Contract state goes through an
  authored node (§2.5).
- **A hook-only surface is allowed when it changes no Contract state and is
  declared.** A dev-menu shortcut, a frame meter or a haptic is declared with
  `owns` (§3.4), and needs no authored stand-in. `state.hooks` lists these
  surfaces, so the agent knows they exist.
- **Parity is per platform** (Charlie, 2026-09-27: allow what a platform
  supports). A hook on one platform needs no twin on the others. Each
  module reports the words it handles on its own host (§5), and the journal
  and `state.hooks` name the current host's. A host cannot see another
  platform's module, and does not claim to.

### 2.7 Refused

- **Native property names in Contract** (`DEFERRED.md`; 1035.006 12.08).
- **A hook that runs before first pixel**, or anywhere on the boot path
  (`RULES.md`).
- **A hook that writes Contract state**, dispatches an action, or reads the
  runner's state.
- **A built or changed moment inside a batch**, and any hook inside the
  painter's walk.
- **Claiming input on a painting host** (the gesture arena).
- **A node-scoped frame ticket** (LLP 1073's root-only rule).
- **A tap that runs hook code by name** (§3.5; LLP 1012).
- **JavaScript above the data seam on native** (`DEFERRED.md` §Authoring
  models). Native hooks are Swift, Kotlin or Rust. 1075.003 §3.10's
  TypeScript experiment is unchanged and adopts nothing.
- **A hook on the wasm target**, and a per-frame journal line.
- **An eleventh agent operation.** Everything in §3 is a form of `tree`,
  `state`, `logs` or `perf`, and §3.5's driving, if ruled, is a form of
  `tap`.
- **Platform-suffixed route overrides.** A hook configures what Exact built.
  It never replaces a route's authored tree.

## 3. What the agent sees (D6, D7)

### 3.1 What Exact measures by itself

All of this is collected only while measuring is on: development trust,
under LLP 1079 D1's switch. In production it is not collected.
- **Every hook call is timed** on the main (or loop) thread: calls, total
  ms and the worst call, per word and moment for nodes and per hook for the
  other scopes. Cumulative counters, as `perf`'s are.
- **A person's late frames name the hooks that ran in them.** On wall time
  (a development session, Save Trace, `perf frames live`), a late frame's
  record gains `hooks: [{ hook: "element avatar", calls: 12, ms: 9.8 }]`: the
  hook calls whose start fell in its frame window. The join is by window
  with stated coverage, as frame records join commits by `seq` (1079 D3). It
  is not a causal trace. Under the agent there are no late frames
  (`virtual`), and hook time is read from `perf hooks` instead.
- **Frame tickets** count their live tickets and ms per tick.

### 3.2 What hook code adds: `context.diagnostics`

```swift
let d = context.diagnostics                       // element.diagnostics is scoped to its word
d.log("swipe began at \(x)")                      // a journal line
d.count("swipes")                                 // a counter, +1
d.count("frames.over20", by: n)
let span = d.begin("swipe")  …  span.end()        // a span on the session clock
d.measure("swipe.worst", ms: worst)               // one sample of a named, measured timing
d.publish("lastswipe", ["worst": worst, "over20": n])   // a snapshot, JSON
```

```js
exact.diagnostics.count("swipes");   // e.diagnostics for a node
```

```rust
ctx.diagnostics().count("swipes", 1);   // Linux, Windows
```

- **Development only, like `perf`** (LLP 1079 D1). In production every call
  is an early return on one flag, with no storage and no platform log. The
  crash breadcrumb (§4.4) is separate and always on. §10 Q5 asks whether
  Charlie wants more than that in production.
- **Names** follow `data-*`'s rule: lowercase letters, digits and `-`, with
  `.` to group, at most 64 bytes. A bad name increments one `rejected`
  counter per module. The first 8 distinct bad names are journaled, and the
  rest are only counted.
- **Bounds, per module, all fixed at connect:**

| Kind | Bound | Over the bound |
|---|---|---|
| Counter | 64 names, `u64` cumulative | `rejected` +1 |
| Timing (`measure`, spans) | 64 names; per name a cumulative count, sum and max, plus a ring of the last 256 samples | the ring overwrites, and its `dropped` counts what it lost |
| Open spans | 32 at once | `begin` returns an inert span, `rejected` +1 |
| A span still open when its scope ends | closed as `abandoned` and counted, not timed | — |
| Snapshot (`publish`) | 16 names, 4 KB of JSON each, the latest kept | refused, `rejected` +1 |
| `log` | 256 bytes a line; 20 lines per second of **session clock** per hook, then one `… N more` | truncated with `…`; counted |
| Cross-thread records | a 1,024-entry ring the owning thread drains each turn | overwritten, `dropped` +1 |
| `saveTrace()` | at most once a second of wall time | coalesced into the pending one |

- **Repeatable under the agent.** Counters, spans on the session clock and
  `log`'s rate limit all use the session clock, so two identical drives give
  identical `logs`, counts and spans. `measure` samples are the hook's own
  measurements, which may be wall time, and are marked `measured`.
- **Namespaced.** Every line and name is prefixed with its scope (`hook
  element avatar: …`, `hook module: …`).
- **Cost.** A `count` is a bounds check and an add into a fixed table. §9 sets
  a measured threshold.

### 3.3 Where it shows

| Read | What it gains |
|---|---|
| `logs` | `d.log` lines, every act (§2.5), refusals, the crash breadcrumb (§4.4) |
| `state.hooks` | per word or scope, as today, plus `platform` (the words this host's module handles), `owns` (§3.4), `parts` (§3.5), hook-only surfaces (§2.6), counters and published snapshots. Bounded lists, with `truncated` |
| `perf hooks` (a form of `perf`: "a new measurement is a form of `perf`", 1079 D7) | per hook: cumulative calls, total and worst ms, frame tickets, counters, and per timing its cumulative count, sum and max and its ring's p50, p95 and max with `samples` and `dropped`. Tagged with `seq`, the plan digest and the incarnation, like every `perf` read |
| `perf frames` | on wall time only, late frames' `hooks` (§3.1) |
| `perf <target>` | on a hooked site's row, its hook calls and ms |
| Save Trace, `agent.mjs trace <file>` | a `hooks` section: `state.hooks` and `perf hooks`, captured in the same main-thread turn as the trace's journal, frames and `perf`, so the sections agree. `context.diagnostics.saveTrace()` asks for one, development only, so the Signal clone's Settings row needs no responder-chain call |

**Reads change nothing** (1079 D2). Every count is cumulative from the
incarnation's start. A difference is two reads that the driver subtracts,
and it refuses to subtract across a changed incarnation or plan digest, as
`perf <target> during` already does. A reader, Save Trace, or a second agent
leaves the next read unchanged. A reload starts a new incarnation and resets
the counters, and the reply says so.

### 3.4 Hook-owned regions

A region is a declaration bound to an object the hook made. The host then
observes that object:

```swift
let title = TitleView(…); route.controller.navigationItem.titleView = title
route.owns(view: title, "title view: avatar, name, verified seal")
element.owns(recognizer: longPress, "long press: reaction picker")
window.owns(recognizer: threeFinger, "three fingers held 0.8 s: dev menu", surface: true)
app.owns(appearance: "tab bar tint: label")
```

- **Bindings are weak.** A region names a view or layer, a gesture
  recognizer, or (for `appearance`) nothing. It ends when its object
  deallocates, leaves the hierarchy, or its scope ends. `surface: true` marks
  a hook-only surface (§2.6).
- **`tree` shows both halves**, distinguished: `owns: [{ by: "route
  conversation", kind: "view", what: "…", observed: { live: true, frame,
  class: "TitleView" } }]`. `what` is the hook's sentence. `observed` is
  what the host saw, with `frame` converted to window coordinates by the
  same conversion 1012 §1's geometry uses (scroll and presentation transforms
  included), at read time. A region whose object is gone shows `observed:
  { live: false }` once, then drops.
- **On a painting host**, `owns(overlay:)` binds the node's overlay, and
  `observed.frame` is the node's box.
- **LLP 1080.001** attributes an `opaque` interior by object identity, not by
  sentence. A view under a region's bound view counts as that region's:
  `opaque: 85 (hook "title view" 12, module 40, platform 33)`. An unbound
  interior stays plainly `opaque`.
- **Undeclared gestures, as new work.** The development check walks a hooked
  node's view and an unshared window, and counts recognizers that are neither
  Exact's nor bound by a region. It journals once: `hook element avatar added
  a UILongPressGestureRecognizer it did not declare`. Today's check compares
  only the scroll, field and text properties Exact recorded
  (`ElementHooks.swift:191-204`). The walk is added in stage 3.
- **Screenshots are unchanged.** `observed.frame` tells the agent which
  pixels belong to which hook.

### 3.5 Hook parts: what a hook drew, named

A part is a control a hook drew, bound to a view:

```swift
element.parts = [ExactPart(id: "seal", view: sealButton, role: "button", label: "Verified")]
```

- **`tree`** lists parts under their node, as `part`, with `id`, `role`,
  `label` and the observed, converted `frame`, with `truncated` past 32 per
  node. They are not plan nodes, and `layout` refuses them by name.
- **`tree --ax`** joins a part through its bound view's own accessibility
  element, which is ownership, not a string match (1080.002). A part whose
  view exposes no accessibility element is the existing "unnamed
  interactive" finding.
- **There is no closure.** A part does nothing when the agent names it. What
  the bound control does when touched is the hook's own code, which must act
  on an authored node (§2.5).

**Driving a part** is §10 Q1. Recommended: `tap <node>/<part>` only as real
platform input, with no activation fallback.
- **The aim.** The host resolves the part to its bound view, then runs the
  same side-effect-free aim 1080.000 runs for a node: the session and
  incarnation match, the view is live and in the window, the converted
  frame's centre hit-tests to the bound view or a descendant (not covered),
  and nothing is mid-transition. A failed aim is refused by name (`part seal:
  covered by UIDimmingView`). A stale part is refused.
- **Delivery.** iOS uses 1080.000's real-touch carrier (`delivery:
  platform`). macOS and the web dispatch a synthesized pointer event at the
  aimed point through the platform's own hit-testing, as 1012 §1's `tap`
  does there. Where no real carrier exists (a phone without 1080.000's
  runner, a painting host), the reply is `unsupported`. It never falls back.
- **Evidence.** The reply carries what the platform reported (the touched
  view's class, whether a recognizer began). A tap that reached nothing says
  so.
- **No action by name.** Every path is a touch at a place, which 1012
  already allows. So this does not amend 1012's sentence. 1075.003 §3.4's
  "named action" placeholder is closed by refusal.

### 3.6 With LLP 1079 and LLP 1080

- **1079.** `perf hooks` is a form of `perf`, not an operation, and its reads
  change nothing. Save Trace gains a section, not a format. Times stay
  observations with their proxy named (1079 D6). `perf frames` keeps
  `virtual` under the agent. Collection stays development-only.
- **1080.000.** Real touches reach hook gestures and, if Q1 rules it,
  parts, through the existing aim.
- **1080.001.** Regions attribute `opaque` by identity. A hook's own subviews
  stay unjudged, because Exact does not own that subview list.
- **1080.002.** Parts join `tree --ax` by ownership. Hook UI the platform
  exposes is already read.
- **1080's constraints hold.** No new operation. Every list is bounded and
  says `truncated`. A painting host's part has no accessibility element and
  reports `unavailable`.

## 4. Safety (D8)

### 4.1 Threads

- **Every hook runs on the main thread** on Apple (and the UI thread on
  Android). On the web it runs on the page's thread, and on Linux and Windows
  on the host loop's thread, between turns.
- **Ended runs inside the batch or reset that removes the object**,
  synchronously (§2.1). Built and changed run after it. No hook applies a
  batch: acts are queued (§2.5).
- **Never on the owner thread** (LLP 1072). A hook cannot reach a runtime,
  so it cannot reenter the owner.
- **The painter never calls hook code** (§2.2.1).
- **Only `diagnostics` may be called from any thread.** Such calls go
  through the cross-thread ring (§3.2). A handle's other members are
  main-thread only. The guard that returns silently today
  (`NativeHooks.swift:61`) becomes, in development builds, a journal line
  naming the member and the thread, and still returns.

### 4.2 Lifetime

- **A handle lives while its object does.** After its ended moment, `view`,
  `platform` and `overlay` are nil, and acts do nothing and are journaled (as
  built for nodes, 1075.003.000 §7.7).
- **Registrations carry their scope's incarnation** (§2.1.2). A ticket, an
  `after`, a region or a part from an earlier incarnation is dropped, and the
  drop is journaled once.
- **A reused view** (iOS `reusable`) has its regions and parts cleared by the
  host before the next node's `element`. Its next hook decides again.

### 4.3 Reload and delivered updates

**A plan reload, per host:**
- **Apple, Linux, Windows:** every hooked node, route and container ends and
  is built again (LLP 1024 D6). The platform window survives, so `window` and
  `app` hear `changed`. Registrations from the old incarnation are dropped.
- **The web:** the dev loop reloads the page. Everything is built again,
  `app` included.

**A hook edit** is a native change: a rebuild and restart on Apple, Linux and
Windows, and a page reload on the web (1024 D6, LLP 1030).

**A delivered plan that marks a word the installed module does not handle**
is a real gap today:
- A word is not a plan requirement (`bake/src/receipt.rs:450-480`), and the
  hook words are not in the compatibility inputs (`bake/src/compat.rs:330-332`,
  which is `null` for an empty roster even when an app has hooks).
- On Apple the host builds `ExactHookKey(word)` from the plan's string
  (`ExactNativeModule.swift:892`; `data-keys.mjs:15` accepts any string), so
  the module is called with a key its code never compiled.

The proposal:
- **The plan's requirements gain `hooks`:** the sorted words the plan marks.
- **The cohort's capabilities gain `hooks`:** the words the installed module
  handles. Each platform's build writes them from what the module declares
  (§5), not from `app.json`. An empty roster still records them.
- **`classifyArtifacts` (`scripts/app.mjs:1328-1345`)** checks that every
  required word is in the cohort's set, as it checks `surfaceCalls` and
  `gpuSurfaces`. A missing word makes the plan a binary change, named
  (`plan: hooks.avatar (not handled by the installed module)`). This uses 1030
  D3's path, where compatibility-id equality decides nothing.
- **At run time**, a plan word the module does not report is never called.
  The journal says so once per word, and `state.hooks` lists it under
  `unhandled`. This also covers a development build whose module lags its
  plan.
- **A change to a hook's body with the same words moves nothing.** It is a
  binary change because the module changed, which the binary's own digest
  already covers.

### 4.4 Crashes in hook code

**Swift and Objective-C cannot be caught, and neither can Rust.** A Swift
trap or an Objective-C exception ends the process. Rust panics abort in every
shipped profile: `[profile.release]` sets `panic = "abort"`
(`Cargo.toml:50`), `host-dev` inherits it (`Cargo.toml:110-111`), and
`logic-dev`/`gpu-dev` set it (`Cargo.toml:129`, `:137`). No `catch_unwind`
is claimed. For all three, the host leaves a breadcrumb:
- **Persisted.** A 4 KB file, `hook-breadcrumb`, in the app's temporary
  directory. It is `mmap`ed shared at session start, so a write reaches the
  page cache with no syscall, and the kernel keeps the page if the process
  dies.
- **Written around each call.** Before a hook call the host pushes a record
  (hook scope and word, moment, session id, incarnation, a call sequence) onto
  a stack 8 deep, which allows for nested calls. After the call it pops the
  record. A clean session end and a clean exit truncate the file.
- **Read at the next launch.** A non-empty stack means the last run ended
  (crash, kill or jetsam) while those calls were open. The journal's first
  line says `the last run ended while inside hook element avatar (built, call
  4127)`, and `state.native.lastEnd` carries it. The wording is "ended
  while inside", not "crashed in": another thread may have been the cause,
  and the line says that.
- **Cost.** Two stores of about 40 bytes into a mapped page per call, with
  no syscall. §9 measures it with the rest.

**Kotlin and JavaScript can be caught.** Android's Kotlin hooks (when they
exist) are called inside `try`/`catch`, and the web already catches a throw
and journals it (`hooks.js`, `call`). After a throw:
- the throw is journaled with the hook's name;
- that hook's built and changed moments are not called again this session;
- **its ended moments still are**, so a hook that installed a recognizer or
  a reusable-view addition before throwing still gets to remove it. A throw
  in an ended moment is journaled, and teardown of the next object goes on.

**No automatic disable across launches.** A crash loop in a development build
is broken with `EXACT_HOOKS=off`, which the breadcrumb line names.

### 4.5 Privacy and capabilities

- **Hooks hold no grant the app lacks.** The context gives a hook no token,
  keychain item, resource, fetch, or other session's data. Its directories
  are the module's own (`ExactModuleContext.data`, `cache`, `temporary`), and
  a scratch tree under the agent.
- **Native hooks are declared, not enforced** (LLP 1069.008 D3). In-process
  native code can call any platform API. The OS enforces device permissions,
  through the keys the app's `device.*` grants put in the binary. A hook that
  uses the camera without the grant fails at the OS. The documentation says
  so, and Exact makes no claim to sandbox native code.
- **On the web, policies hold where they are served.** A page-module hook is
  held to the CSP and `Permissions-Policy` that Exact's render server derives
  from the grants (LLP 1048 D11, 1069.008 D4), like any page script. A static
  dist gets no `Permissions-Policy` and says so in its reach table (1069.008
  D4). There a hook is held to nothing more than the page is.
- **Under the agent a hook substitutes, as modules do.** `context.agent` is
  true. A hook that reaches a device answers from a substitute, never the OS
  (LLP 1069.007), and never prompts.
- **Typed text is not journaled** (§2.5). Diagnostics are development-only
  (§3.2) and never uploaded. The breadcrumb holds names and numbers only.

### 4.6 Determinism under the agent clock

- **Repeatable:** the moments (ordered by batches), acts (FIFO, settled),
  `context.now`, `frames` and `after` (the virtual display), counters, spans,
  `log` with its session-clock limit, and UIKit animation a hook starts
  (frozen under agent timing, `Session.swift:65-72`, like Exact's own).
- **Not repeatable, and named in the documentation:** a hook's own display
  link, wall timers, `Date()`, `CACurrentMediaTime()`, its own threads, and
  `measure` samples taken from them.
- **`clock settle`** waits for acts and due `after` callbacks (§2.5). It does
  not wait for a hook's own timers, which it cannot see. `perf hooks`
  promises a mark only for a `frames` ticket, never for a display link the
  host did not issue.

| Platform | Files | Built by | Into | First hook call |
|---|---|---|---|---|
| iOS, iPadOS, tvOS, macOS | `modules/apple/*.swift` (or `<platform>/modules`), one `ExactModule` subclass | `host/apple/build.mjs`, with `ExactNativeModule.swift` and the generated keys | `libexact_modules.dylib` | after first draw, at connect (as built) |
| Web | `modules/web/index.js`, the page module | `host/web-js/build.mjs` | the page module, and `hooks.js` only where linked by use (as built; the byte-identical cores check it, §9) | after first paint (as built) |
| Linux | `modules/linux/*.rs`, one type that implements `exact_linux::Hooks` (every method has a default that does nothing), named once: `pub type ExactHooks = App;` | the app's own Linux crate: the generated `entry.rs` `include!`s the files | the app's binary, statically: no `dlopen`, no C table, no cargo feature on a core crate | the host constructs the value with `ExactHooks::default()` after first present, then calls `app` |
| Windows | the same `modules/linux/*.rs` (the trait is the presenter's) | `exact-windows` gains an adapter. Its own entry (`src/lib.rs`) takes the hooks value. Its window loop (`src/window.rs`) calls the window moments and its frame loop calls ticks, and the overlay and observed input go through the shared presenter | the Windows binary | after first present |
| Android | `modules/android/*.kt`, one `ExactModule` subclass, the same names | the Android host's build, when it exists | the APK | after first frame |

- **No hook code runs before first present on any host.** On Linux and
  Windows nothing in `modules/linux` is constructed before then. The generated
  entry holds only the type, and the host makes the value.
- **Each module says which words it handles:**
  - Swift: `override class var hooks: Set<ExactHookKey>`. The default is
    every word that `app.json` declares, so today's apps change nothing.
  - Kotlin: the same.
  - Rust: `const HOOKS: &[HookKey]`.
  - The web: `export const hooks = [...]`, which the build reads with the
    export scan it already does (`build.mjs:84-94`). Without it, the module
    handles every declared word.

  The build writes these as the cohort's `hooks` capability (§4.3) and
  `state.hooks.platform`.
- **Typed keys** stay generated from `app.json`: `ExactHookKey`/`ExactDataKey`
  in Swift and Kotlin, and a `HookKey` enum in Rust. The web reads plain
  strings.
- **The web stays `index.js`.** The export scan reads only that file
  (`build.mjs:86-91`), and the build copies the module directory unchanged
  (`build.mjs:508`). A TypeScript page module would be separate work, not
  part of this RFC.
- **The ABI grows by size.** New module-table entries: `app`, `window`,
  `windowEnded`, the handled-words list. New host-table entries: `frames`,
  `after`, `diagnostics` (one entry for the call table), `owns`, `parts`,
  `input`, the breadcrumb's push and pop. That is four module entries and
  seven host entries past 184 and 48. An older module's shorter table still
  loads with none of them (1075.003 §3.9). The overlay has no Apple entry.
- **`bun scripts/exact.mjs hook <word> [--app | --window]`** (new apparatus,
  for Charlie's approval) adds the word to `app.json` `hooks` (for a node).
  It writes one stub per platform the app declares under `host`: the hook's
  moments, its ended moment undoing what built added, a region, and one
  `d.log`. Each stub says what the hook gives up on that platform
  (1075.003.000 §3.5). An app with no module gets each platform's
  boilerplate. The files it writes are the app's.
- **The template's `AGENTS.md`** (LLP 1086) gains a short section on hooks:
  the verb, §2.5's rule, `EXACT_HOOKS=off`, `perf hooks`, `owns`.

## 6. Alternatives

- **Hooks in TypeScript on every platform.** This is 1075.003 §3.10's
  experiment. It is refused here because it runs JavaScript in the tree on
  native, and its thread and lifetime questions are open. Nothing in this
  design forecloses it.
- **An event bus from hooks into Contract** (`dispatch(action, payload)`).
  Simpler for authors, and wrong for parity: the web, the agent and the
  hook-less app could not reach what a hook dispatched.
- **Agent visibility by scraping** the platform's view and accessibility
  trees. 1080.001 and 1080.002 already do the platform's part, but they
  cannot say *whose* a view is or *why* it is there.
- **The platform's own tracing** (`os_signpost`, `console.time`, Perfetto)
  instead of `diagnostics`. A hook may still use it. It does not reach
  `perf`, `state` or the trace file on every host.
- **A logical frame clock driven by the display link even under the agent.**
  Rejected: under the agent there is no display, and 1073 D3 already defines
  the virtual one.
- **Activation delivery for parts through a closure.** Rejected (§3.5). It
  exercises different code from a finger and is an action by name.
- **Claiming input on painting hosts.** Rejected for now (§2.2.2): it is the
  gesture arena.
- **Linux through a C ABI and `dlopen`.** That only matters if hooks ship
  apart from the binary, and a native change never does.
- **No painting-host hooks.** That is honest, but it leaves Linux and Windows
  with no escape hatch at all. The overlay is bounded: it replaces a whole
  recording in a format the painter already replays.

## 7. Risks

- **The escape hatch becomes the road** (1075.003.000 §5). The hook-less smoke
  (§9), the journal, `perf hooks` and `owns` make a heavy hook visible.
- **Diagnostics become telemetry.** They are development-only, capped, never
  uploaded, and refused past their bounds.
- **Regions and parts can be wrong.** They are bound to objects, and the
  host reports what it observes beside what was declared. A part that is
  covered fails the aim, by name.
- **The overlay drifts into a canvas API.** It is limited to whole-recording
  replacement, clipped to the box, with fixed bounds. Anything more is a
  `canvas` node.
- **The settle pump grows.** Draining hook acts inside settle on Apple adds a
  path through which app code runs during an agent read. It is the same code
  that would run on the next turn, in the same order.
- **The ABI grows by eleven entries.** Each lands with its fixture case, or
  is not added.
- **Windows needs real adapter work**, not just a re-export. Stage 4 sizes it
  and tests a running Windows binary.
- **Android's shape is provisional.** Its host's RFC may revise the handle.

## 8. Stages

Each stage lands with its fixture cases in `apps/native-fixture`, its tests in
existing binaries, and an amendment to this document's as-built section.

1. **Diagnostics, timing, the breadcrumb, the delivery gap** (Apple, web JS).
   Exact times every call; `context.diagnostics` with §3.2's bounds;
   `state.hooks`'s new fields; `perf hooks`; Save Trace's `hooks` section and
   `saveTrace()`; the late-frame `hooks` on wall time; the breadcrumb; the web's
   throw rule with teardown kept; the handled-words list; §4.3's requirement,
   capability and classifier check.
   *Acceptance, under the agent:* `smoke.mjs <ios|macos|web> --app
   native-fixture` reads a `d.log` line, a counter, a span and the fixture
   hook's call time in `perf hooks`, and two drives agree on every count. The
   classifier refuses a plan with an unhandled word against the fixture's
   older cohort.
   *Acceptance, on the wall* (a development session, no agent clock): a
   debug button's hook busy-waits 30 ms. Save Trace's `frames` then has a late
   frame naming that hook, and its `hooks` section matches `perf hooks`.
   *Acceptance, the breadcrumb:* an XCTest launches a fixture build whose hook
   calls `abort()`, relaunches, and reads the line.
2. **App and window scopes, the frame clock, `input`, the settle pump**
   (Apple, web JS). `app`, `window`, `windowEnded`, `shared`; root `data-*`;

   *Acceptance:* the fixture tints its window per colour scheme on every
   host. A frame ticket counts exactly 60 ticks for `clock +1000` under the

   the commit shows it, and the journal holds the length, not the text.
   `clock settle` returns only after a hook's queued `click` has committed.

## 9. Test plan

- **The fixture is the contract** (1075.003 §3.9). `apps/native-fixture`
  gains a module per platform that exercises every scope, the frame clock,
  every diagnostics call and its bounds, a region and a part.
- **UIKit XCTests** (the async lane for `host/apple`) cover: the breadcrumb
  across a real `abort()` and relaunch; nested-call breadcrumbs; ended still
  synchronous inside the batch, with a recognizer removed before the pool
  reuses the row; a dropped stale-incarnation ticket; `input` on a non-field
  (refused); the FIFO drained by settle on the main thread with no deadlock;
  diagnostics overflow (every bound in §3.2's table hit, `dropped` and
  `rejected` exact); concurrent `count` from four threads summing exactly.
- **Web**: the JS target's tests; `smoke.mjs web --app native-fixture`; a
  throw in `element` followed by its `elementEnded` still being called. The
  cores of Caltrain, RealWorld and video-player stay byte-identical, so a
  plan that marks nothing pays nothing (link by use).
- **Linux**: `cargo test -p exact-linux --lib --tests` covers overlay
  replacement, the resize drop, clipping, the op and byte bounds, observed
  input after dispatch, and the ticks at virtual instants. It does not claim
  to test panic recovery, which the shipped profiles abort. `smoke.mjs linux`
  drives the fixture.
- **Windows**: the fixture's Windows build, run on a Windows machine, as
  stage 4 says.
- **Hook-less parity**: `smoke.mjs <host> --app native-fixture` with
  `EXACT_HOOKS=off` reaches every Contract state the hooked run reaches, by
  authored `tap` and `type`. The fixture's hook-only surfaces are declared,
  and the smoke checks that they are listed. This runs where the smoke runs,
  not in the gate.
- **Determinism**: two agent drives of the same steps give identical
  counters, spans, tick counts, `logs` and act lines.
- **Cost, with a threshold**: stage 1 repeats 1075.003.000.000's interleaved
  series on the Extra Heavy feed. Every row's avatar is hooked with
  `reusable` set, and its hook calls `d.count` twice and `d.log` once
  (journal suppressed in rows after the first). It is compared against the
  same hook empty, in a development build with measuring on. Pass: CPU and
  main ms/s within +3% and fps within 1 on the iPhone 13 Pro Max, medians
  of 3 rotated rounds. A production build also runs the series, with every
  diagnostics call a flag check, and must match the empty hook within noise.

## 10. Questions for Charlie

### Q1 — Driving what a hook drew

**Recommended (a):** parts are visible in `tree` and `tree --ax`, and `tap
<node>/<part>` reaches one only as real platform input after 1080.000's aim:
a touch on iOS, a pointer event through hit-testing on macOS and the web,
`unsupported` elsewhere. There is no closure and no action by name, so LLP
1012 is unchanged. *(b):* parts are visible but not tappable, and a hook-made
control is driven by tapping the authored control it stands for (today's
rule). *(c):* no parts, regions only.

### Q2 — `input(text)` on an authored field

**Recommended: yes**, through the agent's own `type` entry, queued like
`click`, journaled without its text. It answers the Signal search case.
Refused: a general `setValue` on any node, or a state write.

### Q3 — Linux and Windows

**Recommended (a):** the overlay protocol (§2.2.1) and observed input
(§2.2.2), plus the app, window and frame hooks. *(b):* only the app, window
and frame hooks, so a node stays "shown and never called". *(c):* none, as
today. Claiming input is out under every option.

### Q4 — Android

**Recommended:** fix the scope names and moments now, and keep the handle's
members provisional (§2.2), because LLP 1076 leaves hybrids open. Build
nothing until the Android host exists. `DEFERRED.md` still holds Android,
and this RFC does not move it.

### Q5 — Diagnostics in production

**Recommended (a):** development-only, like `perf` (LLP 1079 D1): in
production every call is a flag check, and only the crash breadcrumb stays
on. *(b):* counters and snapshots on in production, kept in memory, and `log`
to the platform log. This amends 1079 D1. It would let a person's phone carry
context into a crash report, but `os_log` is gathered by sysdiagnose, so "it
never leaves the device" would be false.

### Q6 — Unhandled words in a delivered plan

**Recommended: yes** to §4.3: `hooks` as a plan requirement and a cohort
capability, checked by `classifyArtifacts`, and never called at run time when
unhandled. The alternative, putting the words in the compatibility id, does
not stop a delivery, because id equality decides nothing (1030 D3).
