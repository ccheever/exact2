# LLP 1016.002: Changes the device announces

**Type:** RFC
**Status:** Implemented 2026-09-26
**Systems:** Store (`observe_topic`), Runner (`watching`, `changed`, `listen`, `apply_announced`), the `Native` handle (`on_changed`, `changed`), TypeScript (`native.watch`), `NativeModule::changes`, the Swift seam (`ExactNative.changed`), the web page module (`connect({ changed })`), Apple, Linux and web hosts, the worker envelope
**Author:** Claude (Opus 5.5) for Seth Webster
**Date:** 2026-09-26
**Related:** LLP 1016.000 (answers that keep coming, Draft; its network half is untouched); LLP 1067 (long native calls, the page module); LLP 1018 D4 (a device read makes an answer the device's); grnl's FRICTION.md M6

## Summary

An answer that calls `native.watch("meter")` depends on the device topic
`meter`. When native code announces the topic, from any thread, the runner
asks again exactly the resources whose current answers watch it, one
commit per topic. The announcing code differs by platform:

- Swift: `ExactNative.changed("meter")`.
- A Rust module: through the `Changed` hook `NativeModule::changes` hands it.
- The web page module: through `connect({ changed })`.

Nothing is polled. Announcements that arrive before the host applies them
coalesce, because the re-ask reads the latest state.

## Motivation

grnl polled on an 80 ms Contract task for three things: the voice meter
while recording, the capture pipeline's step, and a correction's progress.
The device knew when each of them changed; the view could not be told.

## Design

- **D1 — Push invalidates; the answer stays a pull.** A topic carries no
  value. The source answers again with whatever the device holds now. That
  keeps every rule an answer already follows: shapes, pending, stores,
  worker turns. A producer faster than frames costs one re-ask per host
  wake.
  - *Rejected (for now):* LLP 1016.000's value streams. They remain the
    design for network sources (SSE, sockets), where the value is only in
    the message.
- **D2 — The answer names its topics.** `native.watch(topic)` records the
  topic on the store for the answer being made, so it is found with no
  declaration in Contract.
  - A fresh answer replaces the resource's topics, and its reply's parse
    may add more.
  - Watching counts as a device read, so the bake does not compile it.
  - The worker envelope carries the topics back from the owner.
- **D3 — The runner owns the queue.** `Runner::listen(wake)` registers with
  the source's `Native` handle.
  - An announcement queues its topic, deduplicated, and calls the host's
    waker: the executor's `notify` on Apple and Linux.
  - The host's next pump applies the queue before its replies.
  - On the web the page module announces into the wasm directly
    (`exact_changed`), after input is ready.
