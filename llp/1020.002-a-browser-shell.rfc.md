## Summary

T3 Code's Browser panel is a browser inside a desktop app: tabs of real web
pages, each with its own back and forward, kept alive while hidden, with
saved logins per profile, light or dark on request, zoom, screenshots,
recordings and an agent that drives the page. In the reference it is an
Electron `<webview>` per tab. In the clone it is 4,813 lines of app-owned
Swift over `WKWebView`. LLP 1020 refused everything such a product needs
until a product needed it. This RFC is that product's request.

It adds to the `iframe` element:

| Need | What the author writes | Where the name comes from |
|---|---|---|
| a guest that is a top-level page with its own storage | `iframe src=u partition="persist:work"` | Electron's `<webview partition>`; the web has no name |
| what the guest is showing | `navigate=`, `currententrychange=`, `navigatesuccess=`, `navigateerror=`, each with a `FrameNavigation` record | the Navigation API's events and fields, seen from outside (D2) |
| moving it | `navigate(id, url)`, `traverseHistory(id, -1)`, `reload(id, ignoreCache=)`, `stopLoading(id)` | the Navigation API; WebDriver BiDi; WebKit and Android (D3) |
| clearing a profile | `await clearSiteData("persist:work", ["cookies", "storage"])` in data code | the Clear Site Data header's types |
| a popup | `newwindow=`: a tab is the app's to open; a scripted window is the platform's popup | Chrome's `<webview>` event; Electron's dispositions |
| `alert`, `confirm`, `prompt`, a file input, a download's destination, element fullscreen | nothing: the platform's sheet, panel or fullscreen; a `download=` event to list downloads | the platform (LLP 1115) |
| light or dark, zoom | `color-scheme`, `zoom` on the `iframe` | CSS, as Chrome applies them to a frame (measured, D6) |
| a picture of the page into the app's files | `captureScreenshot(id, "app:/tmp/a.png", clip=)` | WebDriver BiDi's `browsingContext.captureScreenshot` |
| a PDF | `iframe src="app:/cache/a.pdf"`, shown by PDFKit on Apple | the platform's viewer |
| script, input and prompts for an agent | data code, under the grant `browser.automation` | WebDriver BiDi's `script.evaluate`, `input.performActions`, `browsingContext.handleUserPrompt` |

macOS and iOS get all of it. The web gets a subset the app can detect,
because a page can see into a frame only of its own origin (§11).
Android and Windows are `later`, Linux is `absent` (LLP 1020 D5).
Recording rides on screen capture (B10). Cookie import from other browsers
is a declared difference: dropped.

## 1. Why now

LLP 1020 §5 wrote down when each refused piece returns. Two of its
triggers are met by one product:

- **"`top` topology — never, absent a product that is a browser shell."**
  T3's Browser panel is a browser shell. It is Electron-only in the
  reference: `apps/web/src/browser/ElectronBrowserHost.tsx:116` returns
  `null` when not in Electron, and the web build shows "This tab is open in
  the T3 Code desktop app." (`apps/web/src/components/preview/PreviewView.tsx:1025-1039`).
- **"Navigation policy, verdicts, popups, the 13-op controller — the first
  product need to intercept guest navigation."** The panel's back and
  forward buttons, its address field, its tab-opening links and its OAuth
  popups each need it.

Without these the clone keeps its own browser in Swift
(`modules/apple/T3Browser*.swift`, 4,813 lines over 15 files, plus
`T3ShellWebView` 106 and `T3WebInspection` 42): a capability that one
app's native module has, on one host, where LLP 1133 makes capabilities
exact2's, with a visible absence elsewhere. Every other desktop app that
shows a web page it does not own (a docs pane, a preview, an OAuth window)
meets the same wall.

## 3. Design: the guest

### D1 — `partition` makes a guest a page of its own

```
for t in tabs
  iframe id=("tab-" + t.id) src=t.url partition=(t.incognito ? "incognito-" + env : "persist:" + env + "-" + t.profile)
         display=(t.id == shown ? "block" : "none")
         navigatesuccess=landed currententrychange=moved newwindow=opened
```

An `iframe` with a `partition` is a **top-level browsing context** on
every native host: the web view's own document, never a wrapper's child.
This is Electron's `<webview>`, whose guest is its own top-level page with
its own session, and it is LLP 1020's `top` topology, admitted for this
case only. It is required, not chosen:

- **Sites refuse to be framed.** On 2026-10-21 `github.com` sent
  `x-frame-options: deny`, and `www.google.com` and `developer.apple.com`
  sent `SAMEORIGIN` (`curl -sI`). As a frame's child (today's iOS wrapper
  for every remote page, and macOS's for a sandboxed one) none of them
  loads.
- **WebKit partitions a frame's storage by the top page's site.** LLP
  1020.001 measured it on iOS: under a wrapper at another origin, a framed
  page's `localStorage` and IndexedDB did not survive a relaunch. A saved
  login in a framed page is the wrapper's, not the site's.

A partitioned guest is exactly as privileged as a page in a browser tab,
and has no way to the app that a browser tab lacks. Four rules hold that,
each closing a path from the guest to the app:

| Rule | Checked | The path it closes |
|---|---|---|
| `sandbox` with `partition` is refused | compile time, `lower-iframe-partition-sandbox`; at run time a frame whose computed values carry both does not load: it shows `about:blank` and fires `navigateerror` (`NotSupportedError`). The `sandbox` is never dropped | a native top page emulating a frame's `sandbox`: the fail-open class of LLP 1020 §3.3 (WebKit cannot sandbox a top-level network load, §10) |
| `message=` on a partitioned frame, and `postMessage` to one, are refused | compile time, `lower-iframe-partition-message`; at run time a post is dropped and logged, and no bridge script is installed | the guest's data reaching the app's actions; and the document-start script that takes a direct guest's self-posts (`WebArm.swift:262-270`), which would change every site's own `window.postMessage` |
| No script in the page's world, and no host script that changes page behaviour | the arm installs, for a partitioned web view, only scripts in its own content worlds that read (title, icons), and the agent's bridge under agent mode; none listens to the page's events | a host script a site can observe or break |
| No `exact-app` scheme handler, and a bundled or `app:/` `src` refused | compile time for a literal; at run time the frame shows `about:blank` and fires `navigateerror` | a remote page reading the app's assets through the scheme a bundled page left registered (`WebArm.swift:82`) |

Every message handler and the `exact-app` scheme handler check the
`WKWebView` instance they serve, beside its document and origin, so a popup
(D5), which WebKit builds from a copy of its opener's configuration, is
never taken for the guest and never served the app's assets (the clone
guards its handlers the same way, `T3BrowserFavicon.swift:40,84`).

**A partition is a name.** `persist:` and then 1 to 64 of
`[A-Za-z0-9._-]` persists across launches; the same form without
`persist:` lives in memory until the session ends, whether or not a frame
still uses it, as Electron's in-memory partitions live until the app
quits. Every frame that names one partition shares its cookies and
storage. A frame without `partition` is today's frame, in the default
store. Changing a mounted frame's `partition` replaces its web view: a new
document at its current `src`, the old one's state gone, `load` again, as
a changed `src` navigates.

**Apple:** a persistent partition is
`WKWebsiteDataStore(forIdentifier:)` with a UUID derived from the app's
bundle id and the name (macOS 14, iOS 17: the deployment targets,
`host/apple/Package.swift:104`); an in-memory one is
`WKWebsiteDataStore.nonPersistent()`, one per name, held by the arm for the
session. Under the agent every partition is in memory, as the clone does
(`T3BrowserSessions.swift:86`), so a drive never reads or writes a person's
saved logins.

**Web:** the guest is the `<iframe>` itself, and `partition` cannot be
honoured: the web has no such attribute, and the browser partitions by
top-level site. So the absence is visible before any frame mounts: the
reserved source `exactPage` (LLP 1069.000, `runner/src/page.rs`, beside
`canShare`; `prefer` sets it under the agent) gains a field
`iframePartition`, `true` on Apple and `false` on the web, so an app chooses its fallback before it loads a page; the reference's
web build shows "This tab is open in the T3 Code desktop app." The records a
frame fires carry the same value as `partitioned`. A site that refuses
framing shows the browser's refusal.

**Hidden tabs.** A mounted frame under `display: none` keeps its document,
as an `<iframe>` does in Chrome. On Apple the arm keeps the web view in
the window's view tree, hidden. A web view it has to detach is kept
running by `WKPreferences.inactiveSchedulingPolicy = .throttle` (macOS 14,
iOS 17; it applies "when idle and detached from all windows",
`WKPreferences.h`), as the clone sets it (`T3BrowserSession.swift:77-78`).
Whether a hidden web view paints (for D7 and D8), and how the arm keeps it
painting without the clone's private occlusion selector
(`T3BrowserSession.swift:92-94,198-204`), is stage 1's first measurement.
An app keeps a tab alive by keeping it mounted and closes it by
unmounting it: the clone's registry (`T3BrowserSessions`) and parking
window (`T3BrowserCapture.swift:79-148`) become the app's `for` loop over
its tabs.

**Unsaid, as Safari has them:** the page draws its own background
(WebKit's default, where framed guests are clear today,
`WebArm.swift:289-300`); a scripted `window.open` without a person's
gesture is blocked (`WKPreferences.javaScriptCanOpenWindowsAutomatically =
false`; its default is `NO` on iOS and `YES` on macOS, `WKPreferences.h`;
the clone sets it, `T3BrowserSession.swift:76`); on iOS
`allowsInlineMediaPlayback = true`, so a page's `playsinline` video plays
in the tab.

### D2 — What the guest shows: events with the Navigation API's names

```
shape FrameNavigation
  url: string            // navigation.currentEntry.url: the committed URL
  destination: string    // NavigateEvent.destination.url while one is in flight; "" otherwise
  navigationId: number   // one navigation's events share it (WebDriver BiDi's navigation id)
  navigationType: string // "push" | "replace" | "reload" | "traverse" (NavigationType)
  title: string          // document.title
  icons: string[]        // the page's <link rel~=icon> hrefs in document order, then /favicon.ico
  canGoBack: bool        // navigation.canGoBack
  canGoForward: bool     // navigation.canGoForward
  loading: bool          // navigation.transition !== null
  partitioned: bool      // the host honours `partition` (false on the web)
  controller: string     // "person" | "agent" (D9; "person" without it)
  error: string          // navigateerror only: a DOMException name, or "crashed"
  message: string        // navigateerror only: the platform's code and text
  recovering: bool       // navigateerror "crashed" only: another reload attempt follows
```

`FrameNavigation` is a state record, not the Navigation API's
`NavigateEvent`: it reports the guest from outside, across documents, as
WebDriver BiDi's `browsingContext` events do, and its fields take the
Navigation API's names where the API has the value. An action takes it as
it takes a `PointerEvent` (`action moved(e: FrameNavigation)`). The record
for `navigate=` is chosen by tag: on an `iframe` a `FrameNavigation`, on
the navigation root its location string as now. `event_record` keys by
attribute today (`selection.rs:69-95`), and its four consumers (analysis's
arity, the view's handler types, the runner's `Event::record`, the JS
target's trailing argument, `selection.rs:62-68`) all take the tag with
it.

**The sequence** (Apple; the web's subset in §11):

| What happens | Events, in order | Record |
|---|---|---|
| a link, a script, `navigate(id, url)`, a form | `navigate` | `destination` set, `loading: true` |
| a server redirect | `navigate` again, same `navigationId` | `destination` the new URL |
| the new document commits | `currententrychange` | `url` the committed URL, `destination` "" |
| it finishes loading (`didFinish`) | `navigatesuccess` | `loading: false` |
| a same-document navigation (a fragment, `pushState`) | `navigate`, `currententrychange`, `navigatesuccess` together | `navigationType` push or replace |
| `traverseHistory` or a back gesture | as a navigation, `navigationType: "traverse"` | |
| a traversal with no entry | `navigateerror` | `error: "InvalidStateError"` |
| a failure before or after commit (`didFailProvisionalNavigation`, `didFail`) | `navigateerror` | `loading: false`, `url` the last committed one |
| `stopLoading` | `navigateerror` | `error: "AbortError"`, as the Navigation API fires it for a stopped navigation; nothing follows |
| a new navigation replacing one in flight | `navigateerror` for the old `navigationId`, then the new one's `navigate` | `error: "AbortError"`, as for a superseded navigation |
| the frame's `partition` changes (D1) | `navigateerror` (`AbortError`) for any navigation in flight, then the new web view's sequence from its `src` | |
| a title or icon change with no navigation | `currententrychange` | `url` unchanged |
| a refused command (§11's web subset) | `navigateerror` | `error: "NotSupportedError"` |
| the content process dies | `navigateerror` for a navigation in flight, or alone if none | `error: "crashed"`, `recovering: true` |
| each recovery, after 250, 500 and 1,000 ms | a new navigation (`navigationType: "reload"`, its own `navigationId`) of the failed or pending `destination`, else the committed `url`, else `src` on a first load that never committed (the clone's order, `T3BrowserSession.swift:346`; today's arm re-serves `src`, `WebArm.swift:664-670`) | |
| the third recovery attempt within 30 s fails (the fourth death) | `navigateerror`, in place of the row above | `error: "crashed"`, `recovering: false`; no further attempt until `reload`, as the clone allows three (`T3BrowserSession.swift:435-447`) |

Every navigation ends in `navigatesuccess` or `navigateerror`, so an app
that shows `loading` never keeps it. `load` still fires for every
document, as LLP 1020 D1 has it.

**Declared deviations:** the record is not `NavigateEvent` (above);
`navigatesuccess` fires at each document's load, where the Navigation API's
fires inside one document and a cross-document navigation ends that
document first; a title or icon change fires `currententrychange`, since
the web has no event for either (Electron's are `page-title-updated` and
`page-favicon-updated`); `"crashed"` has no web name (Electron's is
`render-process-gone`).

- **Icons are URLs**, candidates in order, as Electron's
  `page-favicon-updated` gives them. The arm reads them in its own content
  world. The app picks one and shows it with `img`; the clone's fetcher
  and 32×32 redraw (`T3BrowserFavicon.swift`, 169) become an `img` whose
  `error=` moves to the next candidate.
- **No progress.** Neither the oracle nor the clone reports one
  (`estimatedProgress` is left out, §9).

`src` keeps iframe semantics: setting it navigates, and the guest's own
navigation does not rewrite it. An app that keeps the address in its state
reads it from `currententrychange`.

### D3 — Moving it: four commands

| Command | Name from | Apple | Why not the obvious name |
|---|---|---|---|
| `navigate(id, url)` | `navigation.navigate(url)` | `load(URLRequest)` | |
| `traverseHistory(id, delta)` | WebDriver BiDi's `browsingContext.traverseHistory`; `history.go(delta)`'s meaning | `goToBackForwardListItem` on `backForwardList.item(at: delta)` | `back(router)` and `go(router, location)` are Contract functions (`docs/contract-grammar.md:874-876`) |
| `reload(id)`, `reload(id, ignoreCache=true)` | `navigation.reload()`; BiDi's `ignoreCache` | `reload()`; `reloadFromOrigin()` | |
| `stopLoading(id)` | `WKWebView.stopLoading()`, Android's `WebView.stopLoading()`: the name the platforms share (LLP 1133 D1); the web's is `window.stop()`, a window's method, not a frame element's | `stopLoading()` | a bare `stop` would read as the window's, and as the media session's handler name (`tags.rs:441`) |

- `navigate`'s URL passes a scheme policy on every host, so an address
  field's `javascript:` is refused by name, not run. On Apple it takes
  `http`, `https` and `about:blank`; another web-less scheme (`mailto:`)
  goes to D5's external-scheme rule, and `javascript:`, `file:`, `data:`
  and `blob:` are refused. On the web it is `src`'s list, `navigable`
  (`host/web-js/rt.js:684`, `host/web/navigation.js:690`).
- `reload()` with no argument stays the development host's reboot, as
  `close()` stays the window's beside `close(id)`.
- `ignoreCache` on Apple is `reloadFromOrigin()`, which performs "end-to-end
  revalidation using cache-validating conditionals if possible"
  (`WKWebView.h`); Electron's `reloadIgnoringCache` bypasses the cache. A
  declared difference: the result is fresh, the transfer may be smaller.
- A command whose `id` names no mounted `iframe` is refused at compile time
  when the id is a literal, and logged when computed, as `postMessage` is.

A command may share a name with a handler, as `load` is both
(`tags.rs:476`, `lib.rs:113`); an action of the same name in the component
is then ambiguous and refused (`lib.rs:91-99`), as it is for `load`.

These are elements' methods, so they join `HOST_COMMANDS` as
`requestFullscreen` and `showModal` did. LLP 1133 D6 says `HOST_COMMANDS`
"stops growing" for module names, and D5 keeps a tag's vocabulary in the
compiler; §12 Q7 rules that reading.

### D4 — Storage: `clearSiteData`

```ts
import { clearSiteData } from "@exact/browser";

await clearSiteData("persist:work", ["cookies", "storage"]);
```

The clone clears from TypeScript (`src/browser/browser-profiles.ts:146-151`),
and clearing is asynchronous, so it is a data-code binding (LLP 1133 D6)
whose promise settles when the platform says the clear is done.

The type names are the Clear Site Data header's
([W3C Clear Site Data](https://www.w3.org/TR/clear-site-data/)); the scope
is not: the header clears one origin, this clears a whole partition across
origins (a declared deviation).

| Type | Apple `WKWebsiteDataStore.removeData(ofTypes:modifiedSince: .distantPast)` |
|---|---|
| `"cookies"` | `WKWebsiteDataTypeCookies` |
| `"storage"` | local and session storage, IndexedDB, service worker registrations, file system |
| `"cache"` | disk, memory and fetch caches |
| `"*"` | all of the above |

- **Completion.** The promise resolves in WebKit's completion handler and
  rejects with `NotSupportedError` where clearing is not offered, or
  `NotFoundError` for a partition this session has never named.
- **Concurrent writes.** WebKit removes data by modification date
  (`modifiedSince: .distantPast`, `WKWebsiteDataStore.h`) and promises
  nothing about a page writing while it runs. So a page open in that
  partition may keep or re-create data; an app that needs a clean profile
  unmounts its frames, clears, then mounts them again.
- The oracle's "clear cookies" is `"cookies", "storage"`; its "clear cache"
  is `"cache"`. Deleting a persistent store's files
  (`WKWebsiteDataStore.remove(forIdentifier:)`) is not offered.
- **Web:** rejects with `NotSupportedError`; a page cannot clear another
  origin's data.

**Cookie import from other browsers is dropped**, a declared difference.
It reads another app's Keychain item and files under Full Disk Access
(`T3BrowserImportIO.swift`, 372 lines; the reference's `BrowserImport/*`),
and has no meaning on the web, iOS or Linux. Nothing replaces it; a person
signs in again in the clone.

## 4. Design: policy

LLP 1020 §5: "when this returns, it returns as policy data, not a default".
What the author leaves unsaid is the platform's (LLP 1115). D5 applies to
every `iframe` on Apple, partitioned or not: the arm becomes each web
view's `WKUIDelegate`.

### D5 — New windows, dialogs, files, downloads, fullscreen, permissions

**New windows.** WebKit asks `createWebViewWith` with a navigation action;
Electron's `setWindowOpenHandler` gets a disposition. `newwindow` is
Chrome's `<webview>` event for the same moment
([Chrome Apps `webview`](https://developer.chrome.com/docs/apps/reference/webviewTag),
`newwindow` with `windowOpenDisposition`); its payload is `{url,
disposition}` with Electron's disposition names. A frame asks for popups by
handling `newwindow=`.

The rows are checked in order; the first that matches decides.

| Request | `newwindow=` handled | not handled |
|---|---|---|
| sandboxed frame without `allow-popups` | WebKit blocks it; nothing reaches the arm | same |
| scripted, with no person's gesture | blocked (D1's unsaid default) | same |
| `about:blank` or an empty URL | refused, as both do | same |
| a URL that is not http(s), whatever the disposition | the external-scheme rule below; never `newwindow`, as both implementations classify the scheme first (`+Links.swift:74`; `Manager.ts:490`) | same |
| `new-window` (`window.open` with features, ⇧-click) | the platform's popup opens: a window (macOS) or a sheet (iOS) holding the web view WebKit configured, in the same partition, so `window.opener` and its `postMessage` work (OAuth); `newwindow` fires to say so; it closes on `window.close()`; its own popups are refused (one level, as both have it) | refused |
| a tab disposition with a POST body | loads in the frame itself, since a new tab cannot repost; the clone (`T3BrowserSession.swift:379-383`, `+Links.swift:72`) and the oracle (`Manager.ts:484-496`) do the same | same |
| `foreground-tab`, `background-tab` (`target=_blank`, ⌘-click, middle click, `window.open` without features) | `newwindow` fires; nothing opens; the app opens a tab or calls `openURL` | refused |

A frame with no handler opens nothing, as LLP 1020's frames open nothing
today.

**What a popup carries.** WebKit hands `createWebViewWith` "a copy of
webView.configuration" and requires the returned view to use it
(`WKUIDelegate.h`). The copy is changed before the view is made, as the
clone builds its popup from it (`T3BrowserSession.swift:459`): it gets a
fresh `userContentController` with none of the opener's scripts, so the
popup's own `window.postMessage` reaches its own listeners; and the
`exact-app` handler refuses it (D1), so a popup from a bundled page cannot
navigate itself to `exact-app://app/…` and read the app's assets. It keeps
the data store, so it shares the opener's partition and cookies, which
OAuth needs.

**Dialogs.** `alert`, `confirm` and `prompt` show the platform's own: an
`NSAlert` sheet on the window (macOS), a `UIAlertController` (iOS), titled
with the guest's origin so that a person can tell the page's words from the
app's. `prompt` is answered: a declared difference from the oracle and the
clone, which answer null. `beforeunload` is WebKit's default.

**File inputs** show the platform's open panel (`runOpenPanelWith` on
macOS; on iOS the delegate exists from 18.4, and without it WebKit "will
match the file upload behavior of Safari", `WKUIDelegate.h`).

**Downloads.** A response WebKit cannot show, or one marked
`Content-Disposition: attachment`, becomes a `WKDownload`. Unsaid, it asks
where to save with the platform's save panel (an `NSSavePanel` sheet; on
iOS the export picker). The frame fires `download` with `{url,
suggestedFilename, state, path}` as it starts, finishes (with `path`) or
fails, so the app can list it.

**Fullscreen.** `WKPreferences.isElementFullscreenEnabled = true` (macOS
12.3, iOS 15.4): a page's `requestFullscreen()` takes the screen, as in
Safari, and a video's fullscreen button works. The oracle and the clone
fill the tab instead (`apps/desktop/src/window/DesktopWindow.ts:513-532`;
`+Links.swift:122-191`).
By the tell test the platform's answer wins (LLP 1115); the tab-filling
form stays possible as a page script under D9. A declared difference from
the oracle, §12 Q6.

**Permissions** a guest asks for are denied, as LLP 1020 §5's `allow`
entry keeps them, with the mechanism named per API, because omitting a
delegate is not denial:

| Permission | Mechanism | From |
|---|---|---|
| camera, microphone | `requestMediaCapturePermissionFor` answers `.deny`; omitted, WebKit prompts (`WKUIDelegate.h`) | macOS 12, iOS 15 |
| geolocation | `requestGeolocationPermissionFor` answers `.deny` | macOS 27, iOS 27 (`WKUIDelegate.h`). Below it WebKit asks the app's own location authorization, for which an app without a `device.geolocation` grant has no usage string; stage 2 measures what a guest sees there |
| device motion and orientation | `requestDeviceOrientationAndMotionPermission` answers `.deny` | iOS 15 |
| notifications | `WKWebView` has no Notification API (the clone records it, `T3BrowserSession.swift:17-21`) | every version |
| clipboard read | WebKit's own paste confirmation, a person's choice per read (the same record); not a denial, a declared limit | every version |

So denial is guaranteed for camera and microphone everywhere, for motion on
iOS, for notifications, and for geolocation from macOS and iOS 27. Below 27, an app that holds
`device.geolocation` exposes WebKit's own geolocation prompt to its guests:
a declared limit, as is clipboard read's confirmation. If stage 2 finds a
guest obtaining any other permission, that row becomes a declared limit in
this table before the stage lands; the stage does not ship claiming a
denial it cannot enforce.
The oracle allows clipboard read and geolocation; §12 Q8 rules not to
match it, a declared difference. A popup inherits its opener's answers.

**External schemes** (`mailto:`, `slack:`): the platform's confirmation
(an `NSAlert` sheet), then `openURL`, as the clone does
(`+Links.swift:92-118`).

**DevTools:** `isInspectable` in development builds, as the arm already
sets it (`WebArm.swift:255-259`). Safari's Web Inspector is the platform's
DevTools; there is no `openDevTools`.

## 5. Design: appearance

### D6 — `color-scheme` and `zoom` on the frame

Chrome 155, headless, measured on 2026-10-21 (a frame posting
`matchMedia('(prefers-color-scheme: dark)').matches`, `innerWidth` and
`devicePixelRatio` to its parent):

| Frame style | Under a light page preference | Under a dark one | `innerWidth`, `devicePixelRatio` |
|---|---|---|---|
| none | light | dark | 400, 1 |
| `color-scheme: dark` | dark | dark | 400, 1 |
| `color-scheme: light` | light | light | 400, 1 |
| `zoom: 1.5`, `width: 400px` | — | — | 400, 1.5 (the box is 600 px) |
| `zoom: 1.5`, `width: 100%` of 400 px | — | — | 267, 1.5 (the box stays 400 px) |

So in Chrome `color-scheme` on an `iframe` is the guest's
`prefers-color-scheme`, and `zoom` on an `iframe` is page zoom: the guest's
CSS pixels grow, and a frame sized by its container keeps its size. Both
are what the oracle does by CDP and `setZoomFactor`. Firefox and WebKit are
not measured yet; the conformance runs at stage 1 (`conform-firefox`,
`conform-webkit`) record them, and a difference becomes a declared one.

- **`color-scheme`** already exists and is inherited. On Apple the arm sets
  the web view's `appearance` (`.aqua`, `.darkAqua`, or `nil` to follow)
  on macOS and `overrideUserInterfaceStyle` on iOS from the frame's
  computed value. The node view's appearance may already reach the web
  view as a subview (`ColorScheme.swift`); stage 1 measures what the guest
  sees and sets it explicitly if not.
- **`zoom`** is admitted on `iframe` only. On a leaf, CSS `zoom` multiplies
  the element's own absolute lengths and zooms its content; the kernel
  does the first, the host the second (`pageZoom` on Apple; the property
  itself on the web). Stage 1 measures the guest's `innerWidth` and
  `devicePixelRatio` on Apple against the table above. `zoom` on any other
  element stays refused by name. The steps (the oracle's and the clone's
  0.25 to 5.0) are the app's.

## 6. Design: pictures

### D7 — A picture of the guest into an `app:/` file

```
captureScreenshot("tab-3", "app:/tmp/shot.png")
captureScreenshot("tab-3", "app:/tmp/crop.png", clip=rect)
```

WebDriver BiDi's `browsingContext.captureScreenshot`
([W3C WebDriver BiDi](https://w3c.github.io/webdriver-bidi/#command-browsingContext-captureScreenshot))
takes a context, an optional `clip` and an image format, and returns the
PNG. Here it writes the file, and the frame fires `capture` with `{path,
width, height}` or `{path, error}` when it is done; `path` ties the answer
to its request. A declared deviation, because the app's data code reads
files, not base64 strings. The app reads the file under its own `fs.read`
grant, as for any `app:/` file.

- **Coordinates.** `clip` is `{x, y, width, height}` in the guest's CSS
  pixels relative to its viewport (BiDi's box clip with `origin:
  "viewport"`), so a rect from `getBoundingClientRect()` is a valid clip.
  That rect is in the layout viewport; after a pinch zoom and a pan the
  visible part is the visual viewport, displaced and scaled from it
  (`UIScrollView.h`: zooming "adjusts both offset and scale").
  `WKSnapshotConfiguration.rect` is "in view coordinates"
  (`WKSnapshotConfiguration.h`): the web view's points, y down. So at
  capture the arm reads `window.visualViewport`'s `offsetLeft`,
  `offsetTop` and `scale` in its own content world and converts each edge
  as `(css − offset) × scale × pageZoom`, then adds the web view's top
  obscured inset on iOS. This is one formula on both platforms, whatever
  zooms the view (`magnification` on macOS, the scroll view on iOS). A
  clip outside the visual viewport is cut to it; an empty one is an error.
  Stage 3 asserts it on both with a clip around a known element after a
  pinch to 1.5 and a pan to a nonzero offset.
- **Size.** The PNG is the clip's size in view points times the screen's
  backing scale (`snapshotWidth` unset).
- **Apple:** `takeSnapshot` with `afterScreenUpdates`, encoded off the main
  thread, written under the `app:/` roots LLP 1069.002 D7 allows; three
  tries 120 ms apart, as the oracle and the clone do.
- **Web:** `NotSupportedError`. No web API gives a parent page a frame's
  pixels without screen capture.
- **Other elements:** a non-`iframe` id rejects with `NotSupportedError`.
  A picture of any element waits for a consumer (§12 Q9).
- **No grant.** The file is in the app's own space and the pixels are the
  app's window's.

### D8 — Recording: the frame as a screen-capture source

The oracle records a tab by answering `getDisplayMedia` with the guest
frame as the source and recording that stream with `MediaRecorder`
(`Manager.ts:3082-3221`). The web's names for "this element, not the
screen" are Element Capture's
([`RestrictionTarget.fromElement`](https://screen-share.github.io/element-capture/)).
So recording a frame is screen capture (B10) with an element target, and
belongs to B10's RFC. This RFC fixes only what B10 inherits:

- On Apple a frame's pictures come from `takeSnapshot` at the requested
  rate (the clone's way, `T3BrowserRecorder.swift:193-253`), so recording
  one's own frame asks for no Screen Recording permission.
- A hidden frame that records keeps painting (D1's measurement).
- The drawn cursor and key badges are the app's: a page script under D9
  (the clone's `browser-recording.js`) and a compositor in data code.

Until B10 lands, the clone keeps `T3BrowserRecorder` (712 lines).

## 7. Design: automation

### D9 — Script, input and prompts under `browser.automation`

T3's agent drives the page: snapshot, click, type, press, scroll, evaluate,
wait for (`packages/contracts/src/previewAutomation.ts:28-58`). The
planning is already TypeScript (`browser-automation-plan.ts`); the clone's
Swift only runs scripts, sends input and settles prompts and downloads for
an agent-driven page. §12 Q5 admits it, in production builds that hold
the grant. The rest of this RFC does not need it.

**Three things stay apart:**

| | Who | What it changes |
|---|---|---|
| The agent's substitute (development drives, LLP 1069.007) | `scripts/agent.mjs` | dialogs, file inputs and save panels are tickets; partitions are in memory; a production bake reaches none of it (§10) |
| Automation authority | the app's data code, holding `browser.automation` | the calls below, in any build the grant is in (§12 Q5) |
| Control of one frame | whoever acted last | after an automation call that acts (all but reads and screenshots, as the clone counts, `T3BrowserAutomation.swift:56,405-407`), the frame is agent-controlled until a person's pointer or key input reaches it (`T3BrowserSessions.swift:47-67`); the record's `controller` says which |

**The surface is data code's,** because the caller is: an asynchronous
binding (LLP 1133 D6) taking the frame's `id`, named after WebDriver BiDi,
the W3C protocol for driving a browser:

```ts
import { evaluate, performActions } from "@exact/browser-automation";

const title = await evaluate("tab-3", "document.title", { sandbox: "t3", awaitPromise: true });
await performActions("tab-3", [{ type: "pointer", id: "mouse", actions: [
  { type: "pointerMove", x: 40, y: 12 }, { type: "pointerDown", button: 0 }, { type: "pointerUp", button: 0 } ] }]);
```

| Call | BiDi | Apple |
|---|---|---|
| `evaluate(id, expression, {sandbox?, awaitPromise?})`, `callFunction(id, fn, args, …)` | `script.evaluate`, `script.callFunction` | `callAsyncJavaScript` in `WKContentWorld.world(name: sandbox)`, or `.page` without one |
| `addPreloadScript(id, fn, {sandbox?})`, `removePreloadScript` | `script.addPreloadScript` | a `WKUserScript` at document start, main frame, in that world (the clone's diagnostics and annotate overlay) |
| `performActions(id, sources)`, `releaseActions(id)` | `input.performActions`, `input.releaseActions` | `pointer` (`pointerMove`, `pointerDown`, `pointerUp`), `key` (`keyDown`, `keyUp`), `wheel` (`scroll`), `pause`; per source `id`, pressed buttons and keys kept until released |
| `handleUserPrompt(id, {accept, userText?})` | `browsingContext.handleUserPrompt` | answers the open dialog of an agent-controlled frame, which then shows no sheet and fires `userpromptopened` with `{type, message}` |
| `setDownloadBehavior(id, {destination})` | `browser.setDownloadBehavior` | an agent-controlled frame's downloads go to that `app:/` folder with no panel |
| `captureScreenshot(id, path, {clip?})` | `browsingContext.captureScreenshot` | D7, writing the `app:/` `path` and resolving with `{path, width, height}` |

- **Results** are JSON, at most 64 KB (the clone's limit), not BiDi's
  `RemoteValue`: a declared deviation. An exception rejects with its
  message.
- **Ending.** When its frame unmounts, every pending call rejects with
  `NotFoundError` and the input state is released. When a person takes the
  frame back, a pending `performActions` rejects with `AbortError`, pressed
  keys and buttons are released, and an open prompt is shown to the person
  as D5's sheet. A navigation ends nothing: BiDi keeps input state across
  it, and a pending `evaluate` in the old document rejects with
  `AbortError`.
- **Focus.** For trusted input the arm makes the web view first responder
  and gives it back to the previous responder after the action, as the
  clone does (`T3BrowserAutomationInput.swift:48-59`).
- **Controller changes** fire `currententrychange` with the same `url`, as
  a title change does.
- **Trusted input.** macOS: `NSEvent`s sent to the web view's own
  responder methods, in-process, as the clone does
  (`T3BrowserAutomationInput.swift:15-59`), not posted to the OS, which
  LLP 1020 §3.3 found never reaches WebKit; whether the page sees
  `isTrusted: true` is measured at the build. iOS: no public way to make a
  `UITouch`, so input is script-dispatched, `isTrusted: false`, declared.
  Web: a same-origin guest's page world only; `sandbox` and trusted input
  are `NotSupportedError`.
- **Without the grant** every call rejects with `NotAllowedError`. The
  grant derives no manifest key.
- **The agent's own bridge** (LLP 1020 D4) is unchanged and needs no grant.

## 8. Design: PDF

### D10 — A local PDF in a frame is the platform's viewer

An unpartitioned, unsandboxed `iframe` whose `src` is a local PDF (an
`app:/` file, or a file under `assets/`) is shown on Apple by PDFKit's
`PDFView`, with
`autoScales` and continuous pages, as the clone's preview does
(`T3MediaPreview.swift:192-209`). PDFKit is Apple's framework for showing
a PDF in an app ([PDFKit](https://developer.apple.com/documentation/pdfkit));
WebKit's PDF view is the one Safari shows. Which of the two a person reads
as the platform's in an app's pane is the tell test (LLP 1115), judged at
stage 3 against a hand-built `PDFView` and against the frame as it is now.

| | A PDF frame |
|---|---|
| `load`, `error` | as for any `app:/` source |
| `#page=N` | opens at that page (Adobe's PDF open parameters) |
| D2's events, D3's commands, D9 | not a browsing context: no events; commands `NotSupportedError` |
| `sandbox` | a sandboxed PDF frame stays WebKit's, which applies the sandbox to the file's response (`WebArm.swift:433`); `PDFView` cannot enforce navigation or popup restrictions |
| `zoom` | multiplies `PDFView`'s automatic scale |
| `color-scheme` | `PDFView`'s own appearance |
| D7 | draws the view in-process, no remote layers |
| a link in the PDF | not `PDFView`'s default, which opens the URL (`PDFView.h`): the arm takes the click; an http(s) link is a `foreground-tab` request under D5's table, and another scheme takes D5's external-scheme confirmation |
| a `src` change to or from HTML | the view is replaced; `load` again |
| tier 3 | the hatch hands the `PDFView` |
| the agent | `tree` shows `{pdf: true, pages}` |

- **Partitioned frames, sandboxed frames and remote PDFs stay WebKit's.** Reading a remote
  PDF natively would change cookies and redirects (LLP 1020 §10's reason
  against fetching a sandboxed page); a browser shell that navigates to a
  PDF shows WebKit's viewer, as Safari does.
- **Web:** Chrome's PDF viewer, unsandboxed, as now.
- **The arm loads PDFKit**, so an app with no `iframe` pays nothing.
- **Declared difference:** the clone keeps a short document at the top
  (`T3MediaPreview.swift:375`); `autoScales` alone does not. It is an
  acceptance case at stage 3.

The clone's HTML preview becomes an `iframe` of the file under
`sandbox="allow-scripts allow-forms allow-popups allow-modals"` with
`newwindow=` calling `openURL`, as the oracle's files panel frames it.

**Tier 2** (LLP 1133 D2), words the consumer sets today:

|---|---|---|---|

## 10. What a person and the agent see

**Disclosure.** `tree` shows a frame's `FrameNavigation` record (URL,
title, loading, `controller`) and its `partition` name. It never shows
cookies or storage. `pending` shows a dialog's type and text and a
download's file name.

**Substitute** (LLP 1069.007 D7). Navigation is not a request: the agent
loads real pages, from a fixture served by `dev.mjs` or the network. Three
requests are held as tickets, answered by `tap` and `type`, and retired
when their frame unmounts:

| Request | `capability` in `pending` | `args` | Answers |
|---|---|---|---|
| `alert`, `confirm`, `prompt` | `dialog` (a new row in LLP 1069.007 D3's table) | `{type, message, origin}` | `tap @t ok`, `tap @t cancel`; `type @t <text>` for `prompt` |

Partitions are in memory. A production bake reaches none of the
substitute; automation in production is D9's.

**Why `navigate` does not cancel.** The Navigation API lets a page
`intercept()` its own navigation, and Electron's `will-navigate` lets the
host `preventDefault()` one. Neither the oracle nor the clone vetoes a
tab's navigation; each only refuses non-web schemes in the main frame
(`T3BrowserSession.swift:225-247`), which D5's external-scheme rule covers.
If a product needs a veto, the shape exists: `preventDefault()` in the
`navigate` action, as a `key` or `beforeunload` action has it. Until then
it stays out, because WebKit's policy callback would wait on the runner's
turn.

## 12. Rulings (Daehyeon Mun, 2026-10-23)

Q3's take replaces the candidate r4 offered, and Q9 is narrower than r4
proposed; the others follow r4's recommendations and arguments.

- **Q1 — `partition` as the key for a top-level guest.** Electron's
  `<webview>` is top-level with or without a partition (the default
  session); here there is no spelling for a top-level guest in the default
  store. **Ruled:** accepted. Every tab of the consumer names a partition,
  and an unpartitioned top-level guest would share the app's own web
  storage.
- **Q2 — `sandbox` and `message` with `partition`.** **Ruled:** both are
  refused (D1). WebKit cannot sandbox a top-level load, and a message
  bridge would change every site's own `postMessage`.
- **Q3 — The `rules/DEFERRED.md` trade.** This moves `top` topology (for a
  partitioned frame), navigation policy (D5) and the controller (D2, D3)
  off "What stays no". r4 offered the clone's adoption as the take, but
  deleting app Swift is the change's result, not a doing-list item.
  **Ruled:** a take. `QUEUE.md`'s "Web view rows: memory against SwiftUI"
  (LLP 1020 §10) moves to Later; the record is DEFERRED's webview entry.
- **Q4 — The web.** **Ruled:** a partitioned frame is an ordinary
  `<iframe>` there, and `exactPage().iframePartition` is `false`. The fact
  is readable before any frame mounts, so the clone shows the oracle's web
  message ("This tab is open in the T3 Code desktop app.").
- **Q5 — D9's automation.** **Ruled:** admitted under
  `browser.automation`, in production builds, as stage 4. The oracle ships
  its agent to people, and without D9 the clone keeps 1,595 lines of
  automation Swift. Whether macOS input arrives with `isTrusted: true` is
  measured at the build; iOS input is untrusted, declared.
- **Q6 — Fullscreen.** **Ruled:** the platform's whole-screen fullscreen
  (LLP 1115). It is the default for every app, and a Mac user would notice
  the oracle's tab-filling form. For the clone it is a known difference.
- **Q7 — `HOST_COMMANDS`.** **Ruled:** the element methods (`navigate`,
  `traverseHistory`, `reload(id)`, `stopLoading`, `captureScreenshot`)
  join `HOST_COMMANDS`. `iframe` is a kernel tag, so its vocabulary is the
  compiler's (LLP 1133 D5); LLP 1133 D6's "stops growing" applies to
  module sends.
- **Q8 — Guest permissions.** **Ruled:** deny all (LLP 1020 §5 keeps
  `allow` and a permission broker out). Clipboard reads already go through
  WebKit's own per-read confirmation, and below macOS and iOS 27
  geolocation cannot be enforced either way. A known difference from the
  oracle; stage 2 measures each row, and a row it cannot enforce becomes a
  declared limit.
- **Q9 — `captureScreenshot`'s scope.** **Ruled:** `iframe` only. The
  consumer asks only for guest pictures; a picture of any element waits
  for a consumer, such as the device stream's save panel, which stays in
  Swift (LLP 1133.003 §12).
- **Q10 — D9's names.** **Ruled:** WebDriver BiDi's, the W3C standard
  (LLP 1133 D1), with an isolated realm as `sandbox`.
- **Q11 — Cookie import.** **Ruled:** dropped, as ruled on 2026-10-21. A
  person signs in again.
- **Q12 — The working set.** **Ruled:** this RFC stays out of
  `llp/current/`, which holds its 15 documents; nothing leaves.
