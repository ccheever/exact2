## Summary

T3 Code's Browser panel is a browser inside a desktop app: tabs of real web
pages, each with its own back and forward, kept alive while hidden, with
saved logins per profile, light or dark on request, zoom, screenshots,
recordings and an agent that drives the page. In the reference it is an
Electron `<webview>` per tab. In the clone it is 4,813 lines of app-owned
Swift over `WKWebView`. LLP 1020 refused everything such a product needs
until a product needed it. This RFC is that product's request.

It adds to the `iframe` element, by the web's names where the web has them:

| Need | What the author writes | Where the name comes from |
|---|---|---|
| a guest that is a top-level page with its own storage | `iframe src=u partition="persist:work"` | Electron's `<webview partition>`; the web has no name |
| what the guest is showing | `navigate=`, `navigatesuccess=`, `navigateerror=`, `currententrychange=` events with a `NavigateEvent` record | the Navigation API |
| moving it | `navigate(id, url)`, `back(id)`, `forward(id)`, `reload(id, ignoreCache=)`, `stop(id)` | the Navigation API; `window.stop()`; WebDriver BiDi's `ignoreCache` |
| clearing a profile | `clearSiteData(partition, "cookies", "storage", "cache")` | the Clear Site Data header's types |
| a popup | `windowopen=` event for tabs; the platform's popup window for scripted windows | Electron's dispositions |
| `alert`, `confirm`, `prompt`, a file input, a download | nothing: the platform's sheet and panel | the platform (LLP 1115) |
| light or dark, zoom | `color-scheme`, `zoom` on the `iframe` | CSS, as Chrome applies them to a frame (measured, D6) |
| a picture of the page into the app's files | `captureScreenshot(id, "app:/tmp/a.png", clip=)` | WebDriver BiDi's `browsingContext.captureScreenshot` |
| a PDF | `iframe src="app:/cache/a.pdf"`, shown by PDFKit on Apple | the platform's viewer |
| script and trusted input for an agent | data code, under the grant `browser.automation`, ruled separately | WebDriver BiDi's `script.evaluate` and `input.performActions` |

macOS and iOS get all of it. The web gets the subset the browser allows a
parent page: CSS `color-scheme` and `zoom`, `navigate` and `reload` for any
guest, the rest for a same-origin guest only, each refusal by name.
Android, Linux and Windows refuse with `NotSupportedError`. Recording rides
on screen capture (B10). Cookie import from other browsers is a declared
difference: dropped.

## 1. Why now

LLP 1020 §5 wrote down when each refused piece returns. Two of its
triggers are met by one product:

- **"`top` topology — never, absent a product that is a browser shell."**
  T3's Browser panel is a browser shell. It is Electron-only in the
  reference: `apps/web/src/browser/ElectronBrowserHost.tsx:116` returns
  `null` when not in Electron.
- **"Navigation policy, verdicts, popups, the 13-op controller — the first
  product need to intercept guest navigation."** The panel's back and
  forward buttons, its address field, its tab-opening links and its OAuth
  popups each need it.

Without these the clone keeps its own browser in Swift
(`modules/apple/T3Browser*.swift`, 4,813 lines over 15 files, plus
`T3ShellWebView` 106 and `T3WebInspection` 42): a capability that only
one app's native module has, on one host, where LLP 1133 makes
capabilities exact2's, with a visible absence elsewhere. Every other
desktop app that shows a web page it does not own (a docs pane, a preview,
an OAuth window) meets the same wall.

## 3. Design: the guest

### D1 — `partition` makes a guest a page of its own

```
iframe id=("tab-" + t.id) src=t.url partition=(t.incognito ? "incognito" : "persist:" + t.profile)
       navigatesuccess=landed currententrychange=moved windowopen=opened
```

An `iframe` with a `partition` is a **top-level browsing context** on every
native host: the web view's own document, never a wrapper's child. This is
Electron's `<webview>`, whose guest is its own top-level page with its own
session, and it is LLP 1020's `top` topology, admitted for this case only.
It is required, not chosen:

- **Sites refuse to be framed.** On 2026-10-21 `github.com` sent
  `x-frame-options: deny`, and `www.google.com` and `developer.apple.com`
  sent `SAMEORIGIN` (`curl -sI`). As a frame's child (today's iOS wrapper
  for every remote page, and macOS's for a sandboxed one) none of them
  loads.
- **WebKit partitions a frame's storage by the top page's site.** LLP
  1020.001 measured it on iOS: under a wrapper at another origin, a framed
  page's `localStorage` and IndexedDB did not survive a relaunch. A saved
  login in a framed page is the wrapper's, not the site's.

What keeps exact1's findings from returning (they all lived in `top`, where
a native top page emulated a frame's `sandbox`):

- **`sandbox` and `partition` together are refused** at compile time
  (`lower-iframe-partition-sandbox`). Nothing is emulated: a partitioned
  guest is exactly as privileged as a page in a browser tab, and a
  sandboxed guest stays the frame LLP 1020 built. A product that wants both
  (a sandboxed page with its own storage) has no use yet.
- **The guest has no bridge.** The page world gets nothing; the
  `message` event and `postMessage` keep §10's direct rules (a post to
  `parent` is taken from the committed origin until the guest navigates).
- **Navigation is the guest's**, as a tab's is. D4's policy is about new
  windows and dialogs, not about vetoing the guest's own navigation;
  `navigate` events report, they do not cancel (§9).

A `partition` is a name: `persist:` and then 1 to 64 of `[A-Za-z0-9._-]`
persists; the same name without `persist:` lives in memory for as long as
the session runs. Every frame that names one partition shares its cookies
and storage, as Electron's do. A frame without `partition` is today's
frame, in the default store.

**Apple:** a persistent partition is
`WKWebsiteDataStore(forIdentifier:)` with a UUID derived from the app's
bundle id and the name (macOS 14, iOS 17: the deployment targets,
`host/apple/Package.swift:104`); an in-memory one is
`WKWebsiteDataStore.nonPersistent()`, one per name, kept while any frame
uses it. Under the agent every partition is in memory, as the clone does
(`T3BrowserSessions.swift:86`), so a drive never reads or writes a person's
saved logins.

**Web:** the guest is the `<iframe>` itself. `partition` is inert (the web
has no such attribute; the browser's own storage partitioning by top-level
site applies), and a site that refuses framing shows the browser's refusal.
This is the web subset of §7: a local dev server, the main thing T3 shows,
frames fine.

**Kept while hidden.** A mounted frame under `display: none` keeps its
document and keeps running, as an `<iframe>` does in Chrome. The Apple arm
must hold the web view while its node is hidden; whether it does now is
the first thing stage 1 measures. An app keeps a tab alive by keeping it
mounted, and closes it by unmounting it: the clone's registry
(`T3BrowserSessions`) and parking window (`T3BrowserCapture.swift:79-148`)
become the app's `for` loop over its tabs.

### D2 — What the guest shows: the Navigation API's events

Four events with the Navigation API's names
([HTML, the Navigation API](https://html.spec.whatwg.org/multipage/nav-history-apis.html#navigation-api)),
each carrying one record. `navigate=` is already the navigation root's
event (`contract/lower/src/tags.rs:511`); on an `iframe` it is the
guest's.

| Event | Fires | Navigation API |
|---|---|---|
| `navigate` | a navigation of the guest's top page starts (a link, a script, a command, a redirect) | `navigate` |
| `currententrychange` | the guest's current URL changes: a commit, a same-document navigation, a traversal | `currententrychange` |
| `navigatesuccess` | the page finishes loading (WebKit's `didFinish`) | `navigatesuccess` |
| `navigateerror` | the navigation fails (`didFail`, `didFailProvisionalNavigation`) or a command is refused | `navigateerror` |

```
shape NavigateEvent
  url: string                  // navigation.currentEntry.url
  title: string                // document.title
  icon: string                 // the page's first <link rel~=icon> href, resolved; "" when none
  canGoBack: bool              // navigation.canGoBack
  canGoForward: bool           // navigation.canGoForward
  loading: bool                // navigation.transition !== null
  navigationType: string       // "push" | "replace" | "reload" | "traverse"
  error: string                // navigateerror only: the error's name
  message: string              // navigateerror only
```

An action takes it as it takes a `PointerEvent`: `action moved(e:
NavigateEvent)`. Two declared deviations:

- **Seen from outside, across documents.** The Navigation API's events fire
  inside one document, and a cross-document navigation ends that document
  before `navigatesuccess` could fire. Here the embedder sees the guest's
  whole life, as WebDriver BiDi's `browsingContext` events do, so
  `navigatesuccess` fires at each document's load. The names and the
  fields are the API's; the timing is the browsing context's.
- **Title and icon.** A title or icon change with no navigation fires
  `currententrychange` again with the same URL. The web has no event for
  either, and Electron's `page-title-updated` and `page-favicon-updated`
  would be two more names for one record.

- **`icon` is a URL, not bytes.** Electron reports URLs
  (`page-favicon-updated`); the app shows it with `img src=e.icon`. The
  clone's favicon fetcher and 32×32 redraw (`T3BrowserFavicon.swift`, 169)
  become an `img`.
- **`error`** is WebKit's error mapped to a name the web uses where one
  exists, with the platform's own code in `message`. A cancelled load (a
  new navigation replacing one in flight) is not a failure and fires
  nothing, as the clone has it (`T3BrowserSession.swift:290-338`). The clone's Chromium `ERR_*` names are
  T3's to keep in TypeScript.
- **No progress.** Neither the oracle nor the clone reports one.
- **`load` is unchanged**: it still fires for every document, as LLP 1020
  D1 has it.
- **A crashed guest** keeps LLP 1020 D2's silent reload. When three
  reloads in 30 s fail (the oracle's and the clone's limit), it fires
  `navigateerror` with `error: "crashed"` and stays down until `reload`.
  This is LLP 1020 §5's process-death return, as data on an existing
  event.

`src` keeps iframe semantics: setting it navigates, and the guest's own
navigation does not rewrite it. An app that keeps the address in its state
reads it from `currententrychange`.

### D3 — Moving it: five commands

By the Navigation API's method names, each with the frame's `id` first, as
`fastSeek(id, s)` and `showModal(id)` take theirs:

| Command | Web | Apple |
|---|---|---|
| `navigate(id, url)` | `navigation.navigate(url)` | `load(URLRequest)` |
| `back(id)`, `forward(id)` | `navigation.back()`, `forward()` | `goBack()`, `goForward()` |
| `reload(id)` | `navigation.reload()` | `reload()` |
| `reload(id, ignoreCache=true)` | none: refused | `reloadFromOrigin()` |
| `stop(id)` | `window.stop()` | `stopLoading()` |

- `reload()` with no argument stays the development host's reboot, as
  `close()` stays the window's beside `close(id)`.
- `ignoreCache` is WebDriver BiDi's name for the same option
  (`browsingContext.reload`), and Electron's `reloadIgnoringCache`; the
  Navigation API has none. A declared deviation.
- A command whose `id` names no mounted `iframe` is refused at compile time
  when the id is a literal, and logged when computed, as `postMessage` is.
- A refused command (D7's web subset) fires `navigateerror` with `error:
  "NotSupportedError"`.

The names are elements' methods, so they join `HOST_COMMANDS` as
`requestFullscreen` and `showModal` did. LLP 1133 D6's "which stops growing"
is about modules; D5 keeps a tag's vocabulary in the compiler.

### D4 — Storage: `clearSiteData`

```
clearSiteData("persist:work", "cookies", "storage")
clearSiteData("persist:work", "*")
```

The types are the Clear Site Data header's
([W3C Clear Site Data](https://www.w3.org/TR/clear-site-data/)):

| Type | Apple `WKWebsiteDataStore.removeData(ofTypes:)` |
|---|---|
| `"cookies"` | `WKWebsiteDataTypeCookies` |
| `"storage"` | local and session storage, IndexedDB, service worker registrations, file system |
| `"cache"` | disk, memory and fetch caches |
| `"*"` | all of the above; a persistent store is then removed (`WKWebsiteDataStore.remove(forIdentifier:)`) once no frame uses it |

The oracle's "clear cookies" is `"cookies", "storage"`; its "clear cache"
is `"cache"`. On the web it is refused: a page cannot clear another
origin's data.

**Cookie import from other browsers is dropped**, a declared difference.
It reads another app's Keychain item and files under
Full Disk Access (`T3BrowserImportIO.swift`, 372 lines; the reference's
`BrowserImport/*`), and has no meaning on the web, iOS or Linux. Nothing
replaces it; a person signs in again in the clone.

## 4. Design: policy

LLP 1020 §5: "when this returns, it returns as policy data, not a default".
What the author leaves unsaid is the platform's (LLP 1115).

### D5 — New windows, dialogs, files, permissions

**New windows.** WebKit asks `createWebViewWith` with a navigation action;
Electron's `setWindowOpenHandler` gets a disposition. The disposition
decides:

| Disposition (Electron's names) | When | What happens |
|---|---|---|
| `foreground-tab`, `background-tab` | `target=_blank`, ⌘-click, middle click, `window.open` without features | the frame fires `windowopen` with `{url, disposition}`; nothing opens. The app opens a tab (another `iframe`) or calls `openURL`. |
| `new-window` | `window.open` with features, ⇧-click | the platform's popup: a window (macOS) or a sheet (iOS) holding the web view WebKit configured, in the same partition, so `window.opener` and its `postMessage` work (OAuth). It closes on `window.close()`. Its own popups are refused, one level, as in the oracle and the clone. |
| `about:blank` or empty URL, a POST body | | refused, as both do |

`windowopen` is a declared deviation (the web has no event a parent sees);
its payload is `{url, disposition}`. A frame with no `windowopen=` handler
refuses tab dispositions, so a frame that never asked for popups opens
none, as LLP 1020's frames open none today.

**Dialogs.** `alert`, `confirm` and `prompt` show the platform's own: an
`NSAlert` sheet on the window (macOS), a `UIAlertController` (iOS), titled
with the guest's origin so that a person can tell the page's words from the
app's. `prompt` is answered, which
the clone does not do. Under the agent each is a request ticket (LLP
1069.007 D1): `pending` shows `{capability: "dialog", args: {type,
message}}`, `tap @t ok` or `tap @t cancel` answers it, `type @t text`
answers a `prompt`. `beforeunload` is WebKit's default.

**File inputs** in the guest show the platform's open panel
(`runOpenPanelWith` on macOS; iOS's own picker). Under the agent they are
tickets the same way.

**Downloads.** A response WebKit cannot show, or one marked
`Content-Disposition: attachment`, becomes a `WKDownload`. Unsaid, it asks
where to save with the platform's save panel (`NSSavePanel` as a sheet; on
iOS the export picker). The frame fires `download` with `{url, suggestedFilename,
state}` as it starts, finishes or fails, so the app can list it. Under the
agent the file is written to `app:/tmp/downloads/` and the event carries
its path. The clone's "agent-driven page saves to the artifact folder"
(`T3BrowserCapture.swift:248-318`) is then T3's TypeScript moving that file.

**Permissions** a guest asks for (camera, microphone, geolocation,
notifications, clipboard read) are denied, as LLP 1020 §5's `allow` entry
keeps them, and as the clone has it. The oracle allows clipboard read and
geolocation; that difference stays until a consumer names a need (§9).

**External schemes** (`mailto:`, `slack:`): the platform's confirmation
(an `NSAlert` sheet), then `openURL`, as the clone does
(`+Links.swift:92-118`).

**DevTools:** `isInspectable` in development builds, as the arm already
sets it (`WebArm.swift:255-259`) and the clone does. Safari's Web Inspector
is the platform's DevTools; there is no `openDevTools`.

## 5. Design: appearance

### D6 — `color-scheme` and `zoom` on the frame

Chrome 155, headless, measured on 2026-10-21 (a frame posting
`matchMedia('(prefers-color-scheme: dark)').matches`, `innerWidth` and
`devicePixelRatio` to its parent):

| Frame style | Under a light page preference | Under a dark one | `innerWidth`, `devicePixelRatio` |
|---|---|---|---|
| none | light | dark | 400, 1 |
| `color-scheme: dark` | dark | dark | 400, 1 |
| `color-scheme: light` | light | light | 400, 1 |
| `zoom: 2`, `width: 400px` | — | — | 400, 2 (the box is 800 px) |
| `zoom: 1.5`, `width: 100%` of 400 px | — | — | 267, 1.5 (the box stays 400 px) |

So in Chrome `color-scheme` on an `iframe` is the guest's
`prefers-color-scheme`, and `zoom` on an `iframe` is page zoom: the guest's
CSS pixels grow, and a frame sized by its container keeps its size. Both
are what the oracle does by CDP and `setZoomFactor`.

- **`color-scheme`** already exists and is inherited. On Apple the arm sets
  the web view's `appearance` (`.aqua`, `.darkAqua`, or `nil` to follow)
  on macOS and `overrideUserInterfaceStyle` on iOS from the frame's
  computed value. The node view's appearance may already reach the web
  view as a subview (`ColorScheme.swift`); stage 1 measures what the guest
  sees and sets it explicitly if not.
- **`zoom`** is admitted on `iframe` only. On a leaf, CSS `zoom` multiplies
  the element's own absolute lengths and zooms its content; the kernel
  does the first, the host the second (`pageZoom` on Apple; the property
  itself on the web). `zoom` on any other element stays refused by name.
  The steps (the oracle's and the clone's 0.25 to 5.0) are the app's.

### D7 — A picture of the guest into an `app:/` file

```
captureScreenshot("tab-3", "app:/tmp/shot.png")
captureScreenshot("tab-3", "app:/tmp/crop.png", clip=rect)
```

WebDriver BiDi's `browsingContext.captureScreenshot`
([W3C WebDriver BiDi](https://w3c.github.io/webdriver-bidi/#command-browsingContext-captureScreenshot))
takes a context, an optional `clip` box and an image format, and returns
the PNG. Here it writes the file instead, and the frame fires
`capture` with `{path, width, height}` (or `{error}`) when it is written.
`clip` is a box in the guest's CSS pixels (`{x, y, width, height}`). A
declared deviation, because the app's data code reads files, not base64
strings.

- **Apple:** `takeSnapshot` with `WKSnapshotConfiguration.rect` and
  `afterScreenUpdates`, encoded off the main thread, written under the
  `app:/` roots LLP 1069.002 D7 allows. Retries as the oracle and the clone
  do (three, 120 ms apart).
- **Web:** refused (`NotSupportedError`). No web API gives a parent page
  a frame's pixels without screen capture.
- **Other elements:** `captureScreenshot` on a non-`iframe` id draws the
  element as `share(files=["#id"])` does. It is in this RFC because the
  app needs both with one name; `share`'s picture stays as it is.
- **No grant.** The file is in the app's own space and the pixels are the
  app's window's.

### D8 — Recording: the frame as a screen-capture source

The oracle records a tab by answering `getDisplayMedia` with the guest
frame as the source and recording that stream with `MediaRecorder`
(`Manager.ts:3082-3221`). The web's names for "this element, not the
screen" are Element Capture's
([`RestrictionTarget.fromElement`](https://screen-share.github.io/element-capture/)).
So recording a frame is screen capture (B10) with an element target, and
belongs to B10's RFC, not this one. This RFC fixes only what B10 inherits:

- On Apple a frame's frames come from `takeSnapshot` at the requested rate
  (the clone's way, `T3BrowserRecorder.swift:193-253`), so recording one's
  own frame asks for no Screen Recording permission.
- A hidden frame that is recording keeps painting: the host keeps its web
  view in a window, off screen if need be, as the clone parks it
  (`T3BrowserCapture.swift:79-148`) and the oracle keeps it at
  `zIndex: -1`.
- The drawn cursor and key badges are the app's: a page script under D9
  (the clone's `browser-recording.js`) and a compositor in data code.

Until B10 lands, the clone keeps `T3BrowserRecorder` (712 lines).

## 7. Design: automation, ruled separately

### D9 — Script and trusted input under `browser.automation`

T3's agent drives the page: snapshot, click, type, press, scroll, evaluate,
wait for (`packages/contracts/src/previewAutomation.ts:28-58`). The
planning is already TypeScript (`browser-automation-plan.ts`); the clone's
Swift only runs scripts and sends input. That is the part this decision
admits or refuses, and it is not needed by the rest of this RFC.

- **The grant:** `browser.automation` in a data source's `grants`, a new
  family beside `device.*` and `auth.*` (`runner/src/grants.rs:111-122`).
  Without it every call below refuses. It derives no manifest key.
- **The surface is data code's**, because the caller is: an asynchronous
  binding (LLP 1133 D6) taking the frame's `id`, named after WebDriver
  BiDi, the W3C protocol for driving a browser:

  ```ts
  import { evaluate, performActions } from "@exact/browser-automation";

  const r = await evaluate("tab-3", "document.title", { sandbox: "t3", awaitPromise: true });
  await performActions("tab-3", [{ type: "pointer", actions: [
    { type: "pointerMove", x: 40, y: 12 }, { type: "pointerDown", button: 0 }, { type: "pointerUp", button: 0 } ] }]);
  ```

  `evaluate`'s `sandbox` is BiDi's word for an isolated world; omitted, the
  script runs in the page's world. Results are JSON, at most 64 KB (the
  clone's limit). Playwright's injected script and the annotate overlay
  are page assets the app passes as script text.
- **Trusted input:**
  - macOS: `NSEvent`s sent to the web view's own responder methods
    (`mouseDown`, `keyDown`), as the clone does in-process
    (`T3BrowserAutomationInput.swift:15-59`), not posted to the OS, which
    LLP 1020 §3.3 found never reaches WebKit. Whether the page sees
    `isTrusted: true` is measured at the build.
  - iOS: there is no public way to make a `UITouch`, so input is
    script-dispatched (`isTrusted: false`), declared.
  - Web: a same-origin guest's page world only; `sandbox` and trusted
    input are refused.
- **The agent's own bridge** (LLP 1020 D4) is unchanged and needs no grant.

The questions for this ruling are §11's Q6–Q8.

## 8. Design: PDF

### D10 — A PDF in a frame is the platform's viewer

An `iframe` whose document is `application/pdf` from a local source (an
`app:/` file, or a file under `assets/`) is shown on Apple by PDFKit's
`PDFView`, not by WebKit, with `autoScales` and continuous pages, as the
clone's preview does (`T3MediaPreview.swift:192-209`). PDFKit is Apple's
framework for showing a PDF in an app
([PDFKit](https://developer.apple.com/documentation/pdfkit)); WebKit's PDF
view is the one Safari shows. Which of the two a person reads as the
platform's in an app's pane is the tell test (LLP 1115), judged at stage 3
against a hand-built `PDFView` and against the frame as it is now.

- `load` fires when the document opens; `error` when it cannot be read, as
  for any `app:/` source. A `#page=N` fragment (the PDF Open Parameters
  Chrome follows) opens at that page.
- **Remote PDFs stay WebKit's.** Reading the bytes natively would change
  cookies and redirects (LLP 1020 §10's reason against fetching a sandboxed
  page). A browser shell that navigates to a PDF shows WebKit's viewer,
  which is what Safari shows.
- **The agent:** `tree` shows `{pdf: true, pages}`; `screenshot` draws the
  view in-process (no remote layers).
- **Web:** Chrome's PDF viewer, unsandboxed, as now.
- **The arm loads PDFKit**, so an app with no `iframe` pays nothing.

The clone's HTML preview becomes an `iframe` of the file under `sandbox="allow-scripts
allow-forms allow-popups allow-modals"` with `windowopen=` calling
`openURL`, as the oracle's files panel frames it.

## 9. What a person and the agent see

**Disclosure.** `tree` shows a frame's `NavigateEvent` record (URL, title,
loading), its `partition` name, and, under D9's grant, nothing more. It
never shows cookies or storage. `pending` shows a dialog's text and a
download's file name.

**Substitute** (LLP 1069.007 D7). Navigation is not a request: the agent
loads real pages, from a fixture served by `dev.mjs` or the network. Dialogs,
file inputs and save panels are requests: held as tickets, answered by
`tap` and `type`, gone when their frame unmounts. Partitions are in memory.
A production bake reaches none of the substitute.

**Why `navigate` does not cancel.** The Navigation API lets a page
`intercept()` its own navigation, and Electron's `will-navigate` lets the
host `preventDefault()` one. Neither the oracle nor the clone vetoes a
tab's navigation; each only refuses non-web schemes in the main frame
(`T3BrowserSession.swift:225-247`), which D5's external-scheme rule covers.
If a product needs a veto, the shape exists: `preventDefault()` in the
`navigate` action, as a `key` or `beforeunload` action has it
(`contract/syntax/src/lib.rs`, `preventDefault`). Until then it stays
out, because WebKit's policy callback would wait on the runner's turn.

### Cost

- **Nothing before first pixel, nothing without an `iframe`.** Everything on
  Apple is in the web arm, which loads at the first `iframe` commit (LLP
  1020 D3); PDFKit is linked by the arm alone.
- **Web:** the commands and events add to the JS target's runtime
  (`host/web-js`); stage 1 measures the bytes against its size.
- **The schema and compiler:** two props (`partition`, `zoom`), seven events
  (`navigate`, `currententrychange`, `navigatesuccess`, `navigateerror`,
  `windowopen`, `download`, `capture`), six new commands and a `reload(id)`
  form, one grant family.

### LLP 1133 D9's checklist

The `iframe` is exact2's vocabulary (LLP 1133 D5: a tag the kernel lays

1. **Tier 1:** the Navigation API, CSS, Clear Site Data, WebDriver BiDi;

5. **Unsaid defaults:** D5, each the platform's sheet or panel.
6. **Packaging:** exact2's vocabulary (a tag), except D9, a data-code
   binding.
7. **Callers:** Contract for D1–D8 and D10; data code for D9. Nothing is
   `sync`.
8. **Targets:** the table above.
9. **Grant and substitute:** §9; `browser.automation` for D9 only.
10. **Cost:** above.
11. **Consumer:** the T3 clone's Browser panel, driven on macOS.
12. **What stays out:** §13.

## 11. Open questions for a ruling

- **Q1 — `partition` or a separate attribute for the top-level guest?**
  D1 ties "a page of its own" to naming a partition, as Electron's
  `<webview>` is always one. The alternative is a frame-topology attribute
  beside it. Recommended: `partition`, one word for one concept.
- **Q2 — `sandbox` with `partition`: refuse (recommended) or allow on the
  wrapper?**
- **Q3 — The `rules/DEFERRED.md` trade.** This moves `top` topology (for a
  partitioned frame), navigation policy (D5) and the controller (D2, D3) off
  "What stays no". The rule wants a take or a waiver. This RFC does not
  choose one.
- **Q4 — `windowopen` as an event, or `allowpopups` as Electron spells it?**
  Recommended: the event, since the app decides where a tab opens.
- **Q5 — Guest permissions.** Deny all (recommended, LLP 1020 §5) or match
  the oracle's clipboard read and geolocation?
- **Q6 — Admit D9's automation at all**, under `browser.automation`?
  Without it, the clone keeps its automation Swift (1,595 lines) until
  this question is answered.
- **Q7 — D9's names:** WebDriver BiDi's (recommended: a W3C standard, with
  an isolated realm as `sandbox`), or CDP's, which the oracle speaks
  (`Runtime.evaluate`, `Input.dispatchMouseEvent`).
- **Q8 — May a production build hold `browser.automation`?** T3 ships its
  agent to people, so it needs one. The alternative is development builds
  only.
- **Q9 — `captureScreenshot` on any element**, or on `iframe` only?
  Recommended: any element, one name.
- **Q10 — Cookie import:** dropped, a declared difference.
- **Q11 — The working set.** `llp/current/` holds its 15 documents
  (`rules/RULES.md`'s budget), so this RFC is not linked there. Entering it
  means one leaves.
