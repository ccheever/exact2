## Summary

Contract was used enough to have a record: 420 files and 43,629 lines in exact1, 26 files and 1,751 lines of Coterie on Snapback, seven full builds of the same social messenger by four model families under a frozen test harness, and now two apps on exact2. The record is consistent. The core — `state`/`derive`/`action` with declared `writes`, keyed `each`, `testId` as a first-class name, one source for every host — was praised by every author, human and model, and nobody hit a grammar wall. The hours went elsewhere: to **quiet failures** the compiler did not model (layout and navigation), to **time** (stale captures, remounts, races the author had to discipline by hand), to **composition** (prop-drilling, no layout, no local state), to the **escape hatch** ("three files and a generator run to do what a React component does inline"), and, in exact1, to **governance** that grew faster than the language (a 1,979-line spec with twenty-two open issues and seven pending "Edition-2 fold obligations"; 103 of exact1's 527 LLP files name Contract in the title).

exact2 already answered half of it by construction — no JavaScript, no generator, no sidecar, arguments evaluated at dispatch, a baked first frame, one kernel table, a fixture per construct, an eight-operation agent API. This document proposes the other half as nine small moves, in order of leverage: the kernel's table becomes the compiler's value checker, with three layout refusals and a measured lint at bake (P1); actions can branch (P2); a mutation is `send` and a query is `refresh`ed — decided in LLP 1016 today (P3); a component owns its state, a layout takes children, and a theme is provided rather than passed (P4); the escape is a pure `fn` written in Contract (P5); named styles (P6); tests in the language, compiled to the eight agent operations (P7); `use` for components across files (P8); the words are the web's, finished (P9). The same question was put blind to Grok 4.6 and GPT-5.6 Sol (LLP 1017.001, 1017.002); r2 folds them — three independent no's on JSX, six moves agreed, three that moved this document, five forks for one panel round; r3 folds the panel (§10): every fork settled but the naming rule that was never the panel's, and §8 is now Charlie's list. Every move is measured by the same instrument: an agent builds an app from a brief on the real hosts, and the number to drive to zero is the failure the harness found that no diagnostic did.

## 1. The record

### 1.1 What was built

- **exact1** (`~/projects/exact`, main worktree): 420 `.contract` files, 43,629 lines; 33 `.contract-meta.ts` sidecars (one restates 36 `pure(...)` signatures and 9 shapes); the largest single file a 4,608-line route (`open-pencil/index.contract`) and a 4,135-line canvas; 50 Facet components written in Contract; a ~220K-line compiler package of which the compiler proper is ~22K (parser 4,280, inference 4,517, analysis 9,330; LLP 1004 §1); a 549-line diagnostic-code table. The language spec, LLP 0508, is 1,979 lines, "one version, one flag, one migration," with a v1 migration census of **278 rejection sites in 39 of 64 files, 75% of them at two boundary seams** (`prop-annotation` 120, `shape` 90; LLP 0532 §1.1).
- **Coterie** (`~/projects/snapback/demos/coterie`): the Exact/Contract twin of Clique, the React Native social messenger. 26 `.contract` files, 1,751 lines, against a 3,595-line RN reference kit — and 3,456 + 2,119 lines of provider adapters plus 1,349 generated. Built by hand first (diary 0086, 2026-08-15..24), then six times in the 2026-08-17 matrix by Sol, Grok, and Opus under explicit and familiar Snapback profiles (diaries 0094/0095/0098/0099/0102/0103), each timed, costed, and driven by a frozen `sm-*` choreography in two browsers.
- **exact2**: `apps/caltrain/app.contract`, 264 lines plus a 282-line Rust data crate; Weird Castle, 99 lines (`~/projects/weird-castle/app.contract`). Language as LLP 1006 §2: root-only state, inlined components, closed types, `option<T>` as the only absence, `when`/`match`/keyed `each`, actions of assignments and commands, `resource … as shape T` over a Rust data source, 11 roster functions, 27 reject fixtures, an 8–13 ms dev loop.

### 1.2 What it cost

The matrix (`record.md`; N=1 per cell, machine load shared, calibration not claim): every Coterie lane reached M1–M3 green — 1.4 to 3.75 hours, $39 to $116 — and **35 of 36 milestone cells across both apps were green; the one red was an Exact defect** (SPA links detaching mid-route under the choreography, 0095). In aggregate Coterie was *faster in wall than Clique and costlier in tokens* (Coterie Explicit 26,380 s / $216 vs Clique Explicit 35,338 s / $193; Familiar 22,916 s / $165 vs 36,461 s / $233). Contract source was shorter than React in every twin measured — Coterie 1,751 vs 3,595; Shindig ≈420 vs ≈640; the blog 324 lines of Contract against 4,156 of TypeScript — and the todo field report still concluded "**React was faster and less error-prone for me to build**," which LLP 0532 §1.2 named exactly: "Contract can be shorter than React in the view file and still take longer to author… The core Contract forms were not the dominant complaint. The correction loop around them was."

Where the loop went, in the authors' words: "A good refusal collapsed a loop; a silent lifecycle state or packaging seam created a bisection session" (Snapback LLP 0277). "The compiler is strict about the things it models (`writes` lists, `each` keys, expression purity) and mute about layout and navigation semantics, which is where I actually lost time" (0102). "The language is thinner than the problem" (0098). "I did not miss JSX as syntax. I missed the escape hatches" (0099). "The current hard part is confidence: authors and agents spend too much time discovering what is valid, running the compiler to learn one issue at a time" (exact1 LLP 0234). exact1 planned to measure this (0532 §6's bakeoff, 0237's 480-build matrix) and never did: the evidence file is "A RECORD OF ABSENCE," and "the M1 number was never published."

## 2. What went wrong, consistently

Seven clusters. Each cites at least three independent authors; the parenthetical says whether exact2 already answers it.

### 2.1 Quiet failures — the compiler is strict about what it models and mute about the rest

`height=` on a `scroll` did not bound it, so the region grew with its content, never scrolled, and `scrollend` never fired — pagination "quietly did not exist until I measured `clientHeight` in a probe"; `maxHeight=` worked (0102; 0103 found the cause, `flex: 1 1 0%`). `link href="/?tab=global"` navigated without its query string; `navigate({to, search})` carried it — "neither is documented, and both fail quietly… the compiler happily accepted the attrs" (0102). A single-row query was typed as an object and delivered as `[row]`; a mutation's typed result was the inner payload and the action received the envelope — "at exactly the abstraction boundary that is supposed to eliminate ambiguity" (0094, 0098). Authored `start`/`end` alignment silently substituted at runtime (0094). A video as a data URL crossed a 16-bit protocol string limit and was truncated (0094). A zero-argument `pure` helper was a cached constant (0098). "A button with only a `label` and no explicit size is invisible… a silent zero-size trap that an agent will hit every time. Severity: high" (exact1 valet diary 0003). The same class in exact2 today: `width=true` compiles and fails at first frame (LLP 1006 §8); a root-level `when` compiles and bakes and fails at boot in every host's `build.rs` (`QUEUE.md`); a `scroll` with no bounded height is CSS's own behaviour — it grows — and nothing says so.

### 2.2 The escape hatch tax

When the language did not have it — computed member access, a scroll-to-key, a DOM effect, a file input — the answer was "put it in a TS module and declare a `.contract-meta.ts` sidecar. That is the right architecture; it is also three files and a generator run to do what a React component does inline" (0103; `scrollToMessage(id)` shipped marked `opaque()`). "13 imports → 13 hand-written descriptor entries" (todo report). The sidecar "restates 32 signatures tsc already knows" (0251 F4). The web's controlled input snapped back to the last rendered value, `pressSequentially` was invisible to `change=`, and "the workaround that finally worked was not a better action. It was a capture-phase listener in the provider, which is an admission that the authoring model does not yet cover the thing the frozen choreography actually does" (0098). exact1's formal answer — RFC 0518's three island lanes with an empty whitelist, `cursor` plus budgeted widening for dynamic access — was more governance. (exact2: D4 removed JavaScript entirely; the escape is now a Rust data crate for data and *a roster entry in `plan/tables/format.json` and `runner/src/stdlib.rs`* for a formatter — the sidecar problem moved into the framework's own crates. A Weird Castle price string needs a compiler change.)

### 2.3 Time — where the hours actually went

Action arguments were snapshotted at render, so the second click of a like sent `set` again with a stale boolean (0099). Feed tabs as route links remounted the route and cleared the draft the harness had just typed — "Contract had trained me to assume state just persists" (0103); "In React I would have solved the same problem with a layout route and a stable component instance in minutes" (0095). State initialized from router search saw the default snapshot too early; deriving it reactively remounted the controls (0095). Hydrating a form from a query inside `task … when [dep]` raced the typing; the fix was "derive from the live cell and keep a `draft` override," undocumented (0102). Every route-owned write after an `await` needed a hand-built reducer with a generation counter so a stale completion could not publish into a successor draft (0086 M3 and its review; 0102; 0103) — "the single reducer made the race tests deterministic," and every author built it again. No observable "delivered at least once" on an async region, so tests synthesized a debug node (0102). A clock threshold is not a revision, so typing expiry lived in the browser (0095, 0103). "Create conversation on first send, then use its id cannot live in the view layer" (0017); "one subscription per query name, args fixed at boot… event selection became a full navigation" (0015, 0016). (exact2: handler arguments are evaluated at dispatch — LLP 1005 §6 — so 0099's bug cannot occur; `pending(resource)` and `clock settle` are LLP 1016's answer to the marker; the reload carries state. Still open: actions cannot branch, so Enter-to-submit is impossible — `QUEUE.md` §2 — and how a mutation is written is LLP 1016 §4's open question.)

### 2.4 Composition — prop-drilling, no layout, no local state

`CoterieMessageBubble` takes 22 props; the chat route passes them on one line. Caltrain's `Content` takes **31 props, written twice** because the `when skyOn`/`else` arms each call it; `StationRow` duplicates its whole subtree for `hot`. "Every Coterie route repeats the same provider query and primary-navigation wiring… the first place I would look for a paved Contract layout example" (0086; Snapback 0279 #16). "Theme is prop-drilled through every signature; no context/provide-inject" (0251 F8). "All Aboard is a 219-line app deliberately written as one component because splitting it hit `event_unknown_action`" (0277 G5). "The same 8-attr padding/radius/border block repeated on ~10 buttons… a real token and readability tax" (0277 G6); Contract's two screens ran 208 lines against React's 185 + 41 of stylesheet (0016). The curried-on-event, eager-on-prop rule toggled every feed card's like during render (0086; 0279 #6). (exact2: only the root holds state, LLP 1006 §2; per-instance state and inlining-budget are "not in v1"; the `action` prop type exists and inlining resolves currying — but nothing flows down without a prop.)

### 2.5 The generated seam — the best idea and the most frequent defect site

"The provider seam is the best idea here… my `.contract` routes cannot reach Snapback even if I want them to" (0102); "the part I would take to any stack" (0103); "Four steps where Convex has one… it is the ratio you want" (0102). And: `LogoutResult`/`CreatePostResult` collided with the generator's own alias and the binding module failed to parse with no validation (0086, 0103); a mutation parameter typed as an object emitted a multi-line type inside a single-quoted string (0102); regeneration widened `string | null` to `string` (0086); no typed page envelope, so `nextCursor` rode on every row; no ephemeral descriptors; the error envelope dropped `code`; a single-table subscription forced no-op invalidation writes (0086; 0279's P0/P1 bands). Snapback LLP 0277 F9: "Each item is small; the sum was the largest discoverable-only tax in the Coterie program." (exact2: there is no generator — a hand-written Rust data crate, `shape` validated at the seam, bake boots the runner so a missing source fails at build. LLP 1016 keeps that: answer now or hand back a request; failure is data. This cluster is closed by construction; the lesson is to keep it closed — no TypeScript in the seam, no second description of a shape.)

### 2.6 Vocabulary and the uncanny valley

Attribute names were a React Native/CSS hybrid — `numberOfLines`, `nativeId`, `secureTextEntry`, `keyboardType`, `resizeMode`, alignment enums that required `flex-start` natively (0086) — and the expression language looked like JavaScript with "deliberately different rules: Option-only `??`, flattened optional projection, Option-scoped truthiness rejection, aggregate equality rejection, exact shapes, contextual `some` and `none`" (0532 §1.4). "Agents often think JSX = React" (0477); the guide grew a "what not to hand-roll" section: no braces, no quotes around attrs, no semicolons, "don't invent syntax — copy the corpus." `use` meant import at file scope and behaviour-instantiation inside a component (0003). A hyphenated attribute failed compile "for reasons that have nothing to do with HTML" (0098). (exact2: the web is the standard — `size`→`font_size`, `gap`→`row_gap`+`column_gap`, `flex=n` is CSS `flex: n`; residue remains: `secureTextEntry`, `keyboardType` — `QUEUE.md` §3 — and `label` for `aria-label`.)

### 2.7 Governance instead of language

LLP 0508 §13 lists 22 open issues, seven of them "Edition-2 fold obligations" for accepted amendments — `staticDependencies` (0521), ActionSegments with a per-segment transaction law (0535), a `form` grammar (0539), island lanes (0518), localization opt-outs (0536), progressive-delivery annotations (0537), capability imports (0499) — each specified before an app needed it. The tree-syntax bakeoff (0256) was run and shelved on evidence; the authoring bakeoff (0532 §6) was specified and never run. The `contract` block "runs at a fraction of its promised depth" — `change` outcomes, dynamic `count`, `when`, `action … writes`, `derive … depends` all `return null` in the emitter (0277 G2); its selector strings are literals and nothing quantifies over `each` rows (issue 2026-08-10); its diagnostics pointed thirteen lines below the offender (0015). Fix-it arrays were "emitted empty for every closed-type rejection" (0523 §2.1). (exact2: `rules/DEFERRED.md` §Process, LLP 1004 D6 — "a construct with no fixture does not exist" — and D3's "pre-1.0 there is no compatibility" are the answer; this document is held to them.)

## 3. What worked — keep it

Every author, unprompted: **`testId` as a first-class name** ("the frozen contract IDs dropped straight in" — 0102; "you emit the identifiers the choreography will click" — 0099). **`writes` declared and checked** ("twice it caught me assigning to state I had not declared" — 0103). **`derive`** ("better than `useMemo`… half the bugs I have shipped in React are stale closures and missing deps; that entire category does not exist here" — 0102). **Keyed `each`** mandatory. **The primary-argument sugar** (`text "Coffee"`, `button "Post" press=submit` — "genuinely nicer than `<Text>Coffee</Text>`" — 0103). **The `async` region with `loading`/`error`/`empty`/`ready` arms** ("the compiler refusing to let me render a state I did not author… I did not write a single loading boolean" — 0103; exact2 has no such region — LLP 1016 D3 chose stale-while-revalidate plus `pending()`, which is the web's model; §8 asks whether the arms are wanted back as sugar over it). **One route, one file.** **Pure helpers as a separate, testable thing** — "a genuinely good split" (0102): the split is right and the ceremony is wrong. **Diagnostics of design-review grade** — LLP 0278's "this action mutates a table no query in this file reads, so its UI effect cannot be observed" was "the single best diagnostic I hit all milestone… a design review in a compiler message" (0102); "duplicate handles, missing `mutates`, hyphenated attrs, write-set mismatches died in the compiler instead of in production" (0098). **Named refusals over corrupted data** ("the platform surfaced almost all of it as a named refusal" — 0102). And the seam that cannot be bypassed — the reason to choose the stack at all: "I would take it for a system that already has a frozen presentation contract and a requirement that two devices agree" (0099).

## 4. What exact2 already answers

By construction, before this document: no JavaScript anywhere and no generator, so §2.5 cannot recur (LLP 1004 D4); handler arguments evaluated at dispatch (§2.3's stale capture; LLP 1005 §6); the first frame is compiled data (bake); one declaration authority for the vocabulary (`kernel/tables/schema.json`) and one for the plan (`format.json`), so a name the kernel does not know is `lower-unknown-attr` at compile time; a stable id, a span, and a reject fixture per diagnostic — 27 today — and an accept fixture proven on the runner per construct (D6); the eight-operation agent API with the clock in the agent's hands (`clock settle` waits for motion, timers, and — under 1016 — requests; `state` lists what is pending), which is the "delivered at least once" marker 0102 built by hand; the reload carries state; CSS names and CSS defaults, with each deviation declared (LLP 1001 §1). What remains is §5.

## 5. The shape — r2, synthesized from the first draft and the two blind answers (§9)

Nine moves, in order of leverage, numbered as the first draft was so that `QUEUE.md`, §9, and the two sub-LLPs still point at the right thing. Where the three answers agreed, the move is stated as settled; where they did not, the fork is named **F1–F5** and the recommended arm is stated with its reason. The panel (§10) then settled every fork but F2 — the naming rule, never its to settle — and the arms stand as recommended, sharpened where §10 says. Nothing here adds a runtime concept the web lacks, and every cost is an estimate against the crates as they are (LLP 1006 §1: 4,381 compiler lines; LLP 1005).

**P1 — No quiet failures** *(all three agree; closes §2.1).* (a) `contract-lower` checks every attribute value against its `schema.json` row and refuses `width=true`, `align="start"`, `justify="middle"` with the row's own vocabulary in the message — generated from the table like everything else (~150 lines). (b) The compiler refuses what the runner refuses: a region at the root (`lower-root-region`), a handler on a tag that has none, an action prop's arity at the use site (LLP 1006 §8's two circle-backs). (c) Three layout refusals, conservative, in the compiler: `lower-scroll-unbounded` — a `scroll` with no `height`, `maxHeight`, or `flex` on its path; `lower-zero-size` — a pressable with no children and no definite size (valet 0003); `lower-root-region`. (d) The measured lint at bake for what only layout can see: bake already lays out the first frame on `Kernel::with_monospace()` (`contract/cli/src/lib.rs`); after it, at 390×844, a `scroll` whose main-axis size equals its content's and a pressable with zero area are `bake-scroll-unbounded` / `bake-zero-size` with the node's line. Both compile-time and bake-time, because the first is cheap and the second is true. ~350 lines.

**P2 — Actions branch** *(all three agree; closes `QUEUE.md` §2–3).* `if … else …` and `match` as statements in an action body over the same closed expressions; still assignments, commands, and P3's statements; no loops, no `let`, no `await` (the road every Coterie author rebuilt by hand and exact1 formalized as ActionSegments, LLP 0535 — out). The VM has the jumps (LLP 1005 §4): parse and lower, a reject fixture for a write inside a branch not in `writes`. ~150 lines. **F3 — Enter.** Grok proposes a `submit` handler on `input` (the web's `submit` event, no payload); the first draft and Sol reach Enter through `key=` plus `if k == "Enter"`. *Recommended: `submit`, and P2 anyway.* The reason is a host fact, not taste: inside a text field on macOS and iOS, `key` sees editing commands only (LLP 1008 §5's declared deviation), so an Enter that arrives through `key=` is a web-only Enter; `submit` is one event kind on every host and `input`'s own semantics. ~40 lines per host, one `EventKind`.

**P3 — A mutation is `send`; a query is `refresh`ed** *(decided in LLP 1016, Accepted 2026-08-30; all three concur).* `mutation session as shape Session` is an `option<T>` slot, `none` at boot, never queried at bake; `send session = login(who, password)` snapshots the arguments and makes one request; `refresh name` re-requests a resource whose arguments did not change; the reply is data, the view routes on it, fulfilment runs no action. Weird Castle's `attempt` and `submitted*` slots go and a password no longer lives in `state`. From Sol: an action declares what it sends and refreshes as it declares what it writes — `action submit sends session`, `action back refreshes bricks` — and the analyzer checks it (`analyze-send-not-declared`), the same discipline as `writes` that "twice caught me" (0103). Clearing a mutation is assignment, `session = none` (Grok), not a fourth statement. Cost: 1016's ~250 lines plus ~60 in `analyze`.

**P4 — Composition: instances, slots, provide** *(revised; closes §2.4).* The first draft's "a child reads the root's names" is withdrawn: both blind answers declined it for the same reason — hidden data flow is the class §2.1 is about — and reached the same alternative independently. (a) **Provide/inject as compiler-filled props.** A component declares `inject theme: Palette`; a use site or an ancestor writes `provide theme = palette`; the compiler fills the prop at inlining, a consumer with no provider on some path is `analyze-missing-provide`, the nearest provider wins, and what is provided is a closed value or an action reference — never a writable cell. 0251 F8's theme drilling and Caltrain's 31-prop `Content` go, with no runtime lookup and nothing hidden from the type checker. ~120 lines. (b) **A default slot.** A component declares `slot` and writes `children` in its view; the nodes indented under a use fill it — the web's `<slot>`. Grok's `SkyPage` collapses Caltrain's duplicated `when skyOn`/`else` into one call; every Coterie route's repeated header (0086) becomes `Shell(selected="chats")` with its content beneath. Named slots wait for an app. ~120 lines, inlining only. (c) **Per-instance state, now.** A child may hold `state`, `derive`, and `action`; a local slot's live identity is its declaration plus which use plus the enclosing `each` keys (Sol's rule; Grok stores an `each` child's slots on the keyed row — the same thing at the row; the instance tree already keys rows, LLP 1005 §6); leaving an arm destroys it and re-entering starts it again; a keyed reorder keeps it. A dev reload carries root slots by name as today (`rules/DEFERRED.md` §Runtime) and restarts instance slots — carrying them by address would be identity matching, which that rule forbids (the panel, both families; r2 had said otherwise). Child actions write only their own slots and reach the parent through action props, whose arity is checked at the use (P1b). Only the root holds `resource`, `mutation`, and `task` — a row must not open N requests (Sol). Hover lives in `StationRow`; the reaction picker in the bubble; the tab on the feed route that a remount kept clearing (0103). The first draft deferred this to Weird Castle's deck; both blind answers, independently, said now, and named the trade — so it is taken here: per-instance *state* comes off LLP 1006 §8's not-in-v1 list, and general `task … when [dep]` (0102's race), per-instance resources and mutations, and `await` go onto DEFERRED in the same step. ~300 lines in the runner, ~150 in `lower`.

**P5 — The escape is written in Contract** *(revised; closes §2.2). F1 — three spellings.* The first draft declared `pure name(params): type` in Contract and implemented it in Rust; Grok has the data crate export pure functions into the roster table (declared in `format.json`, calls roster-checked) with no line in the `.contract` file; Sol writes `fn` *in Contract* — pure, expression-only, monomorphic, non-recursive, compiled to plan bytecode — so a price string, a palette choice, or a projection needs no Rust, no roster edit, no sidecar, and the corpus tests it like any construct. *Recommended: Sol's `fn`*, bounded hard: one expression, no loops, no recursion, no lists built by iteration; anything heavier — sorting, geodistance, the schedule — is the data crate's, as LLP 1004 D4 says. The reason: the file then says what it calls *and* what it does, in one language, and the expression assembler (`expr.rs`) already exists; the cost is one `fns` table and a `CallFn` opcode (~150 lines). The risk is the one the record names — an expression language growing into a programming language — and the bound is the guard; the first `fn` that wants a loop is evidence for the data crate, not for `fn`. The roster keeps `length`, `toString`, `now`.

**P6 — Named styles** *(all three agree; closes 0277 G6).* `style Card` at file scope holds attribute rows; a node applies it by name and its own attributes win; not an open object — an unknown row is refused at the declaration. The compiler merges rows at lowering; the kernel sees rows as today; no runtime. ~100 lines.

**P7 — Tests in the language, compiled to the eight operations** *(revised; from Sol, closes §2.7's second evaluator).* The `contract` block — parsed and compiled to nothing today, "a fraction of its promised depth" in exact1 — is replaced by a top-level `test "bad login"` whose statements are the agent API's own verbs — `tap testId="login"`, `type testId="who" "alice"`, `clock settle` — and `expect` lines that read their replies (`expect tree has testId="login-error"`, `expect state password == ""`; `expect` is test grammar, not an operation), compiled to the script `smoke.mjs` already runs on every host through `scripts/agent.mjs`. A test executes or it does not exist; there is no second evaluator and no ninth operation (LLP 1012; `rules/DEFERRED.md`). Grok's compiled `has node testId` is one `expect` line. ~200 lines in the driver, plus the verbs' grammar.

**P8 — `use Name from "./file.contract"`, components, shapes, styles, and `fn`s only** *(all three agree).* One keyword, one meaning; never TypeScript, never a behaviour. The inliner reads the file; a plan is still one file's worth of tables. ~100 lines.

**P9 — The words are the web's. F2 — how far.** *Charlie's, not the panel's; decided 2026-08-30 — the literal CSS names (§8.1).* The first draft swept the RN residue (`secureTextEntry` → `type="password"`, `keyboardType` → `inputmode`, `nativeId` → `id`).
