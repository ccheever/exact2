## 1. Purpose and authorization

A public framework needs ordinary controls before a particular in-repository app
happens to demand each one. A settings screen, appointment form, searchable list,
or attachment flow is a legitimate consumer. Methodically work through Apple's
UI capabilities, implement useful Exact capabilities, and explicitly choose an
alternative or deferral for the rest. Completeness means covering user needs,
not exporting every Apple class, initializer, style, or modifier.

Charlie requested this grouped, ordered LLP and a way to implement and hand-check
items one at a time. Writing the plan is authorized. This does not claim that all
items are implemented, manually accepted, required for the first public release,
or authorized for immediate implementation. In particular, existing exclusions
such as camera, video, pager, general native-view loading, and additional tooling
are not silently removed by appearing below. When a slice is selected, record its
consumer and the required scope trade in the owning LLP/rules. Do not make the
whole catalog a prerequisite for shipping the current apps.

This extends LLP 1035 from repairing current applications to preparing public
coverage. It does not supersede that program's semantic or ownership decisions.
The concrete future trade proposed here is to prioritize the common-control
examples in groups 01–06 over further decorative showcase work; admitting that
implementation is a separate step from recording this plan.

## 2. Scope, sources, and what “all” means

The checklist covers the public UI families relevant to ordinary macOS and iOS/
iPadOS apps: controls, containers, presentations, document/media workflows,
specialized views, and decisions about mechanisms Exact should not duplicate.
Custom and third-party views make a literally exhaustive list impossible. This
is a dated capability inventory, not a claim to enumerate every SDK symbol.
New SDK capabilities are added to the matching family when needed, not made into
one wrapper per symbol. watchOS, tvOS, visionOS, CarPlay, and private APIs are not
new target platforms in this plan.

Current package deployment declarations are macOS 14 and iOS 17
([Package.swift](../host/apple/Package.swift)). Keep those distinct from the OS
used to inspect an example. Each selected item must record actual availability;
an Apple API mentioned below is a candidate, not a guarantee on both platforms
or on the minimum OS. Older-OS behavior can be a supported alternative or an
explicit unavailable result. A simulator cannot prove camera, purchases, system
account, translation execution, or physical input behavior it does not support.

Catalog references, consulted 2026-09-17–18:

- [UIKit views and controls](https://developer.apple.com/documentation/uikit/views-and-controls) and [UIKit Catalog](https://developer.apple.com/documentation/uikit/uikit-catalog-creating-and-customizing-views-and-controls).
- [AppKit views and controls](https://developer.apple.com/documentation/appkit/views-and-controls).
- SwiftUI [controls and indicators](https://developer.apple.com/documentation/swiftui/controls-and-indicators), [text input and output](https://developer.apple.com/documentation/swiftui/text-input-and-output), and [menus and commands](https://developer.apple.com/documentation/swiftui/menus-and-commands).
- SwiftUI integration through [UIHostingController](https://developer.apple.com/documentation/swiftui/uihostingcontroller) and [NSHostingView](https://developer.apple.com/documentation/swiftui/nshostingview). Hosting controller containment is part of support, not just attaching its view.
- Specialized references accompany the relevant groups. Apple names identify things to evaluate; the use cases, order, and acceptance exercises below are Exact proposals.

## 3. How to knock out one item

### Disposition and progress are different

Choose one disposition per capability; platform-specific implementations may differ:

| Disposition | What we deliver |
|---|---|
| Native | Exact semantics projected into an appropriate native control or controller. |
| Compose | A reusable Exact composition and an example proving the behavior. |
| Operation | A request, cancellation/failure, and result; the host owns temporary system UI. |
| Module | An optional specialized component with a bounded view/renderer and lifecycle. |
| Defer | An explicit gap and a concrete return trigger. This is not supported coverage. |
| Alternative | Deliberately do not expose this mechanism; demonstrate the supported alternative and name its limits. |

The starting labels below are an audit of the current tree, **not acceptance**:
`E` = related implementation exists, often only a subset; `P` = documented
prototype; `W` = uncommitted implementation; `N` = needs evaluation, no complete
implementation established by this audit. Suggested dispositions are provisional.
Existing code does not entitle an item to a checked box.

Use each checkbox for **reviewed disposition**. For Native/Compose/Operation/Module,
checking it requires the agreed manual acceptance. A checked Defer/Alternative
means a reviewed decision, not implemented coverage. Keep those totals separate
when reporting release coverage. All boxes start unchecked.

### The loop

1. Pick the next unchecked item. State the actual user task and the smallest
   complete behavior. Confirm its dependencies and scope admission. Prefer an
   existing app; otherwise use a compact realistic example, not a widget with no
   surrounding task. Name the implementer and date when implementation begins.
2. Decide value/event semantics, state ownership, commit versus cancel, layout
   ownership, and per-platform disposition before choosing the Apple class.
   Reuse HTML/CSS/ARIA names where they fit. Do not expose SwiftUI binding/state
   machinery as a second application model. Kernel-owned layout stays authoritative;
   specialized internals may own layout inside their assigned box.
3. Implement only that slice, or write the alternative/deferral and its reason.
   Record macOS, iPhone, iPad, web, and Linux behavior explicitly. An unavailable
   host is visible and explained; an empty box or inert button is not a fallback.
4. Run the relevant automated checks and the row's manual exercise in an ordinary
   app. Inspect native presentation with real mouse/touch/keyboard input. The
   agent's painted menu alternative or `host-activation` does not prove a native
   menu, swipe, or sheet gesture. Use the existing eight agent operations for
   observations and repeatable setup; no ninth operation or new gate is proposed.
5. Leave the item ready for Charlie's hand check. Record what was actually tested,
   then check it only when the review happened. Three fix rounds still means stop,
   report the remaining defect, and leave it unaccepted.

Append a short receipt **under the item**, not in a second tracking system:

> Disposition: …; progress: selected / implemented / awaiting hand check / reviewed.
> Example and revision: …; launch command and starting state: ….
> Hosts/OS/devices checked: …; expected/observed result: …; evidence link: ….
> Reviewer/date: …; remaining limits or deferral return trigger: ….

### Shared hand check, applied to every relevant item

Run the row-specific exercise plus these applicable checks. Mark irrelevant checks
N/A with a reason rather than manufacturing interactions a control does not have.

- **Value and action:** initial state; user change; programmatic change; disabled
  and read-only where meaningful; empty/error/boundary state. Actions fire once,
  programmatic synchronization does not echo, and cancellation preserves the value.
- **Input and access:** real pointer/touch and keyboard; visible focus; correct
  accessible name, role, value, and disabled state; VoiceOver activation/adjustment.
  A visual imitation without the same interaction is not accepted as equivalent.
- **Appearance and fit:** light/dark; narrow and wide layouts; long localized text;
  right-to-left; large text/zoom where supported; minimum and current supported OS
  behavior. Explicitly distinguish fixed CSS font sizes from native Dynamic Type.
- **Ownership and lifetime:** update while focused/open; move away and return;
  remove/reload while an operation is pending; cancel an interactive presentation.
  No duplicate callback, stale mutation, lost draft, or unexpected sibling scroll.
  Exercise two embedded sessions for features that own window/controller/system UI.
- **Platform truth:** inspect macOS and iOS separately, with iPhone/iPad adaptation
  for presentations; exercise the web behavior and the Linux disposition. Record
  unchecked platforms honestly. UI correctness does not require identical pixels.

Do the deeper gesture/large-data checks only for items that use them. This plan
adds no blocking check, registry, code generator, or review ceremony. Source and
runtime changes use the existing five checks; long native sweeps stay asynchronous.

## 4. Order and example flows

Work within a group from top to bottom. Complete or explicitly defer a prerequisite
before its dependent item. A deferral does not prohibit independent later work.
Groups 01–06 are the proposed common-control baseline to review before calling the
public UI offering broadly useful; they are not yet a ratified release gate.

| Order | Group | Example that makes the items work together | Main dependencies |
|---|---|---|---|
| 01 | Content and appearance | A readable detail screen | Existing host/layout/text |
| 02 | Actions and simple choices | Settings and preferences | 01 |
| 03 | Text, search, and forms | Account/profile form | 01–02 |
| 04 | Structured value selection | Appointment and reminder editor | 02–03 |
| 05 | Status and feedback | Import task with progress and retry | 01–03 |
| 06 | Menus and commands | Document actions | 02–03 |
| 07 | Navigation and presentation | Inbox → detail → edit/cancel | 03, 06 |
| 08 | Collections and organization | Searchable library with selection | 03, 06–07; LLP 1010/1041 |
| 09 | Documents and transfers | Open, edit, export, share | 03, 06–08 |
| 10 | Media and specialized views | Attachments and previews | 07–09; module seam if needed |
| 11 | System/domain workflows | One real flow per admitted capability | 07, 09 |
| 12 | Extension and deliberate alternatives | Prove one custom view and the boundary | First admitted specialized consumer |

One small control gallery would provide breadth; the flows above provide depth.
If admitted for implementation, use one ordinary example app with sections and
existing build/drive scripts, not twelve apps or a devtools product. Give each
example a reset and a visible value/action result. Record its entry/launch beside
the row once it exists. This document does not pretend that gallery exists today.
Reuse Fieldnotes, Caltrain, Messages, Markdown, and Weird Castle where they already
exercise the task. Start with **01.01, 02.01–02.04, and 03.01** for a settings slice,
then return to the numbered order. Move group 12's extension work immediately ahead
of the first selected item that actually needs it; do not build a universal loader
as a prerequisite for an ordinary checkbox.

## 5. Ordered checklist

### 01 — Content and appearance

- [ ] **01.01 — Labels, headings, and formatted inline text.** `E · Compose`. Apple: UILabel/NSTextField labels, SwiftUI Text/Label; Exact currently uses CoreText. Show a title, explanatory text, and an icon label. Check wrapping, selection policy, baseline, link boundaries, and long text without changing the surrounding layout contract.
- [ ] **01.02 — Images and asynchronous image states.** `E · Compose/native renderer`. Apple: UIImageView/NSImageView, Image/AsyncImage. Open a detail image, replace its source, and force a failed load; verify fit/crop, intrinsic sizing, placeholder, accessible alternative, and no stale image after reuse.
- [ ] **01.03 — System symbols and icon-only actions.** `E · Native`. Existing semantic symbol roles, not arbitrary Apple names. Compare several weights/sizes and disabled tint; verify the icon-only button keeps its accessible name and hit target and that other hosts have an explicit rendering.
- [ ] **01.04 — Dividers, groups, sections, and labeled values.** `E/N · Compose`. Apple: NSBox, Divider, GroupBox, Section, LabeledContent. Group account settings with explanatory footers; check reading/focus order and alignment after labels grow. Do not equate a painted line with semantic grouping.
- [ ] **01.05 — Blur, vibrancy, and glass.** `E · Native`. Existing ultra-thin/glass subset; UIVisualEffectView/NSVisualEffectView/NSGlassEffectView. Put controls over scrolling content; switch appearance and reduced transparency, change/remove the material, and verify legibility and unchanged input ownership. Additional effects need an explicit reason.
- [ ] **01.06 — Text scale and system appearance adaptation.** `N · Native facts + Compose`. Dynamic Type, accessibility contrast, system appearance. Enlarge system text while a form is open; establish which authored sizes adapt and which remain CSS-fixed. Check unclipped content, scrolling, and focus rather than claiming automatic scaling today.
- [ ] **01.07 — Tooltips, help, and enlarged content.** `N · Native/Compose`. AppKit tooltips, SwiftUI help/HelpLink, UIKit large-content viewer where available. Explain an unfamiliar icon with mouse, keyboard, and touch-accessibility paths; no essential information may exist only on hover.

### 02 — Actions and simple choices

- [ ] **02.01 — Standard action buttons.** `E · Compose/Native decision`. UIButton/NSButton/Button. Save once using click, touch, Space, and Return where appropriate; disable during the action. Compare plain, prominent/default, destructive, text, and icon variants without silently replacing every custom pressable.
- [ ] **02.02 — Switches.** `N · Native`. UISwitch/NSSwitch/Toggle. Turn notifications on/off, then change the value programmatically; check one user event, disabled behavior, accessible on/off value, and no layout jump.
- [ ] **02.03 — Checkboxes, including mixed state.** `N · Native/Compose`. NSButton checkbox/Toggle styles; iOS needs a deliberate presentation. Select one permission and then some/all permissions; check label activation, mixed-state semantics, keyboard, and consistency between parent and children.
- [ ] **02.04 — Radio groups.** `N · Native/Compose`. NSButton radio/Picker styles. Choose one delivery method; check exclusivity, arrow-key navigation, disabled choices, empty/required policy, and programmatic selection.
- [ ] **02.05 — Segmented choices and tabs.** `E · Native`. UISegmentedControl/NSSegmentedControl. Switch a library filter using text and image segments; remove the selected option and resize. Specify when the semantics are tabs versus a value picker; do not mislabel every exclusive choice as navigation.
- [ ] **02.06 — Sliders.** `N · Native`. UISlider/NSSlider/Slider. Adjust volume with drag, keyboard, and VoiceOver; verify endpoints, step policy, continuous versus committed events, and programmatic updates while dragging.
- [ ] **02.07 — Steppers and bounded quantities.** `N · Native`. UIStepper/NSStepper/Stepper. Change a ticket quantity; hold to repeat, reach both bounds, and type into a paired field. Check one shared value and no overflow or duplicate increment.
- [ ] **02.08 — Ratings and level selection.** `N · Native/Compose`. NSLevelIndicator and accessible composed choices. Rate a document, clear the rating, and show read-only capacity; distinguish interactive rating from a meter and announce the scale.
- [ ] **02.09 — Links and external destinations.** `E · Compose/Operation`. Link and host URL opening. Open an internal route and an external URL; check keyboard activation, rejected destinations, history, and return without accidentally mutating app state.
- [ ] **02.10 — Split buttons, repeat buttons, and disclosure actions.** `N · Native/Compose`. NSComboButton, button menus/repeat behavior. Run the default export versus choosing another format; ensure the primary action, menu opening, and held-repeat policy cannot trigger each other accidentally.

### 03 — Text, search, and forms

- [ ] **03.01 — Single-line text entry.** `E · Native`. UITextField/NSTextField/TextField. Edit a profile name; replace a selection, submit, clear, and update from app state. Check placeholder, read-only/disabled distinctions, undo, and retained caret through unrelated updates.
- [ ] **03.02 — Password and secure entry.** `E · Native`. Secure UITextField/NSSecureTextField/SecureField. Enter a password, toggle reveal if offered, and submit; check no unintended logging, correct selection/value preservation, and the declared autofill behavior.
- [ ] **03.03 — Multiline plain-text editing.** `E · Native`. UITextView/NSTextView/TextEditor. Write a note with newlines; grow to its height limit and scroll. Check Enter versus submit, placeholder, line height, selection, and draft preservation after a surrounding rerender.
- [ ] **03.04 — Read-only selection and the system edit menu.** `E · Native/Compose`. Native editor selection; AppKit reader selection has a separate implementation. Select/copy text across lines, invoke available system actions, dismiss, and resume editing elsewhere. Do not count text drawn by CoreText as automatically having native selection.
- [ ] **03.05 — Keyboard hints, composition, and text services.** `E · Native`. Input mode, correction, capitalization, spelling, IME, dictation. Enter composed/non-Latin text and emoji; change adjacent app state mid-composition. Verify committed text once, appropriate keyboard, and no forced responder reset.
- [ ] **03.06 — Autofill, content purpose, and password-manager interaction.** `N · Native`. Platform text-content types and web autocomplete semantics. Fill an account/address form; inspect field mapping, one-time-code handling where available, and behavior when autofill is unavailable. Use appropriate devices and sample credentials.
- [ ] **03.07 — Search field and cancellation.** `E/N · Native/Compose`. Existing input can express queries; dedicated UISearchBar/UISearchController/NSSearchField/searchable integration is not established. Filter a list, clear, cancel, and return; define whether cancellation restores the previous query and selection.
- [ ] **03.08 — Suggestions, completions, and editable combo boxes.** `N · Native/Compose`. NSComboBox, text-input suggestions, accessible combobox pattern. Choose a station by typing; test no matches, stale async responses, keyboard selection, Escape, and text that is not a listed option.
- [ ] **03.09 — Tokens and multiple recipients.** `N · Native/Compose`. UISearchToken/NSTokenField. Add two recipients, paste a list, edit/remove one token, and handle an invalid address; check focus movement and whether free text has been committed.
- [ ] **03.10 — Validation and form submission.** `N · Compose`. Labels, required/invalid state, inline messages, default action. Submit an incomplete form; announce/focus the first error, preserve entered values, correct it, and submit once. Native field validity and app business validation must not disagree.
- [ ] **03.11 — Undo/redo, clipboard, and find/replace.** `E/N · Native/Operation`. Native editors supply some behavior; a general app contract is not established. Make two edits, undo/redo, paste multiline text, then replace a match; check command availability and the intended undo grouping across focus changes.
- [ ] **03.12 — Rich text and writing tools.** `N · Module/Native`. Attributed text editing and platform formatting/writing tools where available. Bold a selection, insert a link, undo, save, and reopen; specify the persisted format and selection model. Plain textarea support does not satisfy this row.

### 04 — Structured value selection

- [ ] **04.01 — Single-choice menus and pickers.** `N · Native`. UIPickerView/NSPopUpButton/Picker. Choose a time zone from a labeled set; verify stable option IDs, disabled options, keyboard behavior, and replacement of the option list while open.
- [ ] **04.02 — Multiple-choice pickers.** `N · Compose/Native`. Multi-selection list/checklist. Choose export fields, select all, and cancel; verify whether edits are live or transactional and preserve choices when filtering the list.
- [ ] **04.03 — Date-only values.** `N · Native`. UIDatePicker/NSDatePicker/DatePicker. Enter a birthday, change time zone, and reopen it; the calendar date must not shift. Check leap day, min/max bounds, clearing, locale, and supported calendar policy.
- [ ] **04.04 — Time and date-time values.** `N · Native`. Date-picker variants. Schedule an appointment; distinguish a local wall time from an instant. Test 12/24-hour display, time-zone changes, and daylight-saving gap/overlap behavior with a declared resolution policy.
- [ ] **04.05 — Calendars, multiple dates, and date ranges.** `N · Native/Compose`. UICalendarView/MultiDatePicker and composed range selection. Choose travel dates; test reversed endpoints, excluded days, month boundaries, keyboard access, and cancel without committing half a range.
- [ ] **04.06 — Durations and countdown values.** `N · Native/Compose`. UIDatePicker countdown mode or numeric fields. Set a reminder duration; verify units, zero, bounds, and round trips without converting a duration into a date/time-zone value.
- [ ] **04.07 — Color selection.** `N · Native/Operation`. UIColorWell/UIColorPickerViewController, NSColorWell/NSColorPanel, ColorPicker. Change an annotation color and cancel; define color space and alpha, verify round trips, and keep two sessions from sharing unintended selection state.
- [ ] **04.08 — Font selection.** `N · Operation`. UIFontPickerViewController/NSFontPanel. Select an editor font and cancel; decide system versus app-bundled font policy, unavailable faces, permitted traits, and the web/Linux alternative without promising arbitrary fonts on every host.

### 05 — Status and feedback

- [ ] **05.01 — Determinate progress.** `N · Native/Compose`. UIProgressView/NSProgressIndicator/ProgressView. Import a file from 0 to completion, including a revised total; show an accessible value and distinguish completion from failure.
- [ ] **05.02 — Indeterminate activity.** `N · Native/Compose`. UIActivityIndicatorView/NSProgressIndicator/ProgressView. Start a task whose total is unknown, cancel, and retry; ensure activity stops and hidden/offscreen indicators do not create unnecessary frame work.
- [ ] **05.03 — Gauges and read-only meters.** `N · Native/Compose`. Gauge/NSLevelIndicator. Show storage usage at empty, normal, and exceeded capacity; communicate the range and warning without color alone.
- [ ] **05.04 — Empty, unavailable, loading, and error content.** `N · Compose`. ContentUnavailableView/UIContentUnavailableView concepts. Search with no results, disconnect, retry, and succeed; distinguish no data from pending/error and preserve a usable next action.
- [ ] **05.05 — Inline banners and transient messages.** `N · Compose`. No universal Apple toast wrapper is assumed. Save a note, show an undoable notice, and trigger another; check announcements, duration policy, focus retention, and accessibility without stealing the keyboard.
- [ ] **05.06 — Badges and counts.** `N · Compose/Native`. Tab/list badges. Show zero, one, and a large unread count; distinguish count from decoration and announce updates without repeatedly interrupting reading.
- [ ] **05.07 — Haptics and interaction feedback.** `E/N · Operation`. Existing gestures use UIKit feedback; general feedback requests are not established. Cross a slider threshold and perform a successful action; verify one appropriate response, no fake support on unavailable hardware, and no dependence on haptics alone.
- [ ] **05.08 — Refresh affordances.** `N · Native/Compose`. UIRefreshControl/AppKit refresh support where available. Pull to refresh and invoke the keyboard/button equivalent; check one pending request, success/failure, preserved scroll position, and return to an idle indicator.

### 06 — Menus and commands

- [ ] **06.01 — Pull-down action menus.** `E · Native`. UIMenu/UIAction/NSMenu from menu-shaped popovers. Open, choose, reopen, and dismiss; verify current labels, enabled state, checked choices, separators, and exactly one action under ordinary native presentation.
- [ ] **06.02 — Submenus and grouped choices.** `N · Native`. Nested menus and radio/check groups. Choose an export format inside a submenu; test keyboard traversal, changed availability while open, and checkmark consistency. Existing flat-menu support is insufficient.
- [ ] **06.03 — Context menus and previews.** `E/N · Native/Compose`. Current authored context surfaces are not a general UIContextMenuInteraction wrapper. Right-click/long-press an item, preview, act, and cancel; retain the correct target after list updates and do not also trigger its primary action.
- [ ] **06.04 — Application menu bar and command validation.** `E · Native`. NSMenu/NSMenuItem, SwiftUI Commands concepts. Open two documents/sessions and switch focus; File/Edit commands must target the active owner, show current enabled state, and not cross into another session.
- [ ] **06.05 — Keyboard shortcuts and default/cancel actions.** `E · Native/Compose`. Existing aria-keyshortcuts and responder routing. Use Save, Return, and Escape with an editor and a sheet open; resolve conflicts by ownership, and do not dispatch a hidden route's action.
- [ ] **06.06 — Window and content toolbars.** `E/N · Native/Compose`. NSToolbar exists; UIToolbar/UIBarButtonItem and other placements need evaluation. Resize until items overflow, activate overflow commands, and switch routes; preserve action identity, accessibility, and containing-app ownership.
- [ ] **06.07 — Edit, rename, paste, and help commands.** `N · Compose/Operation`. EditButton/RenameButton/PasteButton/HelpLink concepts. Rename a selected file, cancel, then paste where permitted; command names must route to actual behavior rather than become independent special button tags.
- [ ] **06.08 — Palette and multi-action menu content.** `N · Native/Compose`. Menu selection palettes and non-dismissing action policies where available. Apply several formatting choices; define which actions close the menu and prove keyboard/focus behavior before supporting arbitrary rich content.

### 07 — Navigation and presentation

- [ ] **07.01 — Push/pop and Back.** `E · Native/Compose`. Existing iOS UINavigationController and route projection. Open detail, begin Back and cancel, then complete it; verify route, draft, focus, and scroll state agree. AppKit/web use their declared route behavior.
- [ ] **07.02 — Native titles, navigation bars, and large-title collapse.** `P · Native`. UINavigationBar/navigation items; existing host hides the bar. Scroll an inbox through title collapse, search, push/pop, and return from a sheet; no inset jump or duplicated authored header. Prototype measurements are not shipping support.
- [ ] **07.03 — Application tab bars.** `N · Native/Compose`. UITabBarController/UITabBar/TabView and desktop equivalents. Switch between three sections with independent history; preserve intended state, badges, keyboard selection, and overflow/adaptive behavior. A segmented tablist is not automatically a tab bar.
- [ ] **07.04 — Split views, sidebars, and inspectors.** `N · Native/Compose`. UISplitViewController/NSSplitViewController/NavigationSplitView/inspector. Select an item wide, collapse to narrow, go Back, then widen; preserve selection and avoid simultaneous native/kernel ownership of the same geometry.
- [ ] **07.05 — Alert and confirmation dialogs.** `E · Native/Operation`. Existing iOS one-action confirmation subset; UIAlertController/NSAlert. Delete an item, cancel, then confirm; test Escape, outside input exclusion, destructive/default roles, and the macOS implementation gap. Expand grammar only with defined semantics.
- [ ] **07.06 — Sheets and transactional forms.** `E · Native`. Existing iOS modal routes; AppKit sheet ownership needs evaluation. Edit a draft, attempt dismissal, discard or return, then save. Verify focus restoration, keyboard viewport, and one result delivered to the presenting owner.
- [ ] **07.07 — Detents and interactive sheet resizing.** `E/N · Native/Compose`. Existing bounded detent behavior and LLP 1041 sheet work are distinct mechanisms. Drag between admitted sizes with nested scrolling and the keyboard open; reverse/cancel and inspect geometry. Do not assume arbitrary native detent binding already exists.
- [ ] **07.08 — Rich anchored popovers.** `N · Native/Compose`. UIPopoverPresentationController/NSPopover. Open a small editable inspector near an edge; resize, show the keyboard, dismiss, and reopen. Check anchoring, adaptation, focus, clipping, and touch order, not just a matching rectangle.
- [ ] **07.09 — Fullscreen covers and source-linked transitions.** `E · Native`. Existing iOS fullscreen/source zoom subset. Open an attachment from a cell, remove/recycle the source, and dismiss; resolve a live source or a safe fallback and preserve the underlying route.
- [ ] **07.10 — Utility panels and detached tools.** `W · Native/Compose`. Current floatingPanel work uses NSPanel and in-page iOS/web dragging. Move, edit, pick a menu item, close/reopen, and reload while the main document remains live. Verify correct owning-window coordinates and unchanged session identity.
- [ ] **07.11 — Paging and page indicators.** `N · Native/Compose; excluded pending admission`. UIPageViewController/NSPageController/UIPageControl/TabView paging. Move through onboarding with swipe and buttons; test first/last page, focus, scroll arbitration, and saved page. Decorative dots alone do not satisfy paging.
- [ ] **07.12 — Windows, settings windows, and scenes.** `E/N · Native host integration`. ExactKit embeds sessions, but arbitrary app-authored window creation is not established. Open two documents and settings, close one, and quit; define session lifetime, active commands, restoration, and which capabilities remain containing-app responsibilities.

### 08 — Collections and organization

- [ ] **08.01 — Lists and row identity.** `E · Compose/Native decision`. Existing Exact lists/windowing; UITableView/NSTableView/List are candidates, not automatic replacements. Browse a long history, prepend data, and update a visible row; preserve anchor, focus, selection, and bounded mounted views.
- [ ] **08.02 — Sectioned/grouped lists and index navigation.** `N · Compose/Native`. Sections, headers, footers, section index. Browse contacts by letter; collapse/filter sections and check headings, sticky behavior if promised, and correct jump targets after data changes.
- [ ] **08.03 — Single and multiple row selection.** `E/N · Compose/Native`. Select, Shift-select, toggle selection, filter, and delete; distinguish selected data from focused row and define whether hidden selections remain. Touch selection mode and desktop modifiers need separate hand checks.
- [ ] **08.04 — Leading/trailing swipe actions.** `E · Native/Compose`. Existing iOS UITableViewCell/UIContextualAction projection. Partially reveal, cancel, fully swipe, and choose an action; check destructive policy, scroll arbitration, stale rows, and a keyboard/accessibility equivalent.
- [ ] **08.05 — Reordering and drag handles.** `E/N · Compose/Native`. LLP 1041 has a bounded reorder consumer. Move a row beyond the visible window, cancel another move, and receive a concurrent update; commit stable item IDs once and keep drag state out of recycled rows.
- [ ] **08.06 — Data tables and sortable columns.** `N · Native/Compose`. NSTableView/SwiftUI Table. Sort a file table, resize/hide a column, select rows, and edit a cell if admitted; preserve identity and accessible row/column relationships.
- [ ] **08.07 — Trees, outlines, and disclosure.** `N · Native/Compose`. NSOutlineView/OutlineGroup/DisclosureGroup. Expand a project tree, select a descendant, collapse its parent, and refresh; define focus/selection and loading behavior for removed or lazy children.
- [ ] **08.08 — Collection grids and thumbnails.** `N · Native/Compose`. UICollectionView/NSCollectionView/Lazy grids. Resize a photo library while thumbnails load; keep item identity, keyboard navigation, scroll anchor, and decoded-image budget independent of total item count.
- [ ] **08.09 — Breadcrumbs and column browsers.** `N · Native/Compose`. NSPathControl/NSBrowser. Navigate a deep folder, use an ancestor menu, and replace the underlying location; keep the displayed path and selection consistent without requiring a filesystem-specific core widget.
- [ ] **08.10 — Rule and predicate builders.** `N · Compose/Module`. NSRuleEditor/NSPredicateEditor. Build “sender is Alice AND unread,” change nesting, save/reopen, and cancel. Persist a portable query model, not an opaque platform predicate; defer if ordinary filter controls suffice.

### 09 — Documents and transfers

- [ ] **09.01 — Open/import files and folders.** `E/N · Operation`. Existing macOS NSOpenPanel/file_handlers; UIDocumentPickerViewController/fileImporter candidates. Select an allowed file, cancel, deny access, and reopen later; define ownership of returned handles, type filters, multiple selection, and access lifetime.
- [ ] **09.02 — Save/export and destination selection.** `N · Operation; file-input scope must be reconciled`. NSSavePanel/document export/fileExporter. Export a note, cancel, replace a file, and handle write failure; preserve the original and distinguish choosing a destination from completing the write.
- [ ] **09.03 — Document opening and recent documents.** `E/N · Native host integration`. Existing Finder/Open With delivery; NSDocument/UIDocumentBrowserViewController are broader candidates. Open from the OS while running and while closed, reopen a recent item, then try a missing file; route to the correct session.
- [ ] **09.04 — Share sheets and services.** `N · Operation`. UIActivityViewController/NSSharingServicePicker/ShareLink. Share text and a file, cancel, and return; keep temporary content alive for the operation and avoid claiming that opening a share target proves delivery.
- [ ] **09.05 — Clipboard actions and drag/drop transfers.** `E/N · Operation/Native`. Existing text copying is narrower than typed data transfer. Drag an image/file between apps, reject an unsupported type, and cancel; define copy/move, asynchronous loading, permissions, and failure without losing the source.
- [ ] **09.06 — Quick Look previews.** `N · Operation/Module`. [Quick Look](https://developer.apple.com/documentation/quicklook). Preview a supported attachment, switch items, delete the source, and close; retain required resources and return focus to the correct item. Record platform differences in preview/edit capabilities.
- [ ] **09.07 — PDF reading and thumbnails.** `N · Module`. [PDFKit](https://developer.apple.com/documentation/pdfkit), PDFView/PDFThumbnailView. Open a multipage PDF, zoom, search/select text, navigate a thumbnail, and reopen; check page position, accessibility, and memory with a large document.
- [ ] **09.08 — PDF markup and forms.** `N · Module`. PDFKit annotation/form facilities. Annotate or fill a field, undo, save a copy, and reopen it; establish persisted bytes and supported form types. A PDF renderer alone does not imply editing support.
- [ ] **09.09 — Printing and print configuration.** `N · Operation`. UIPrintInteractionController/NSPrintOperation. Preview/print selected pages, cancel, and simulate an unavailable destination; preserve document state and separate successful submission from physical printing.
- [ ] **09.10 — Document change protection and recovery.** `N · Compose/Native host integration`. Dirty state, close confirmation, autosave/recovery policy. Edit, close/cancel, force a failed save, and reopen after interruption; never infer “saved” from a dismissed sheet. Choose policy rather than wrapping an entire document architecture by default.

### 10 — Media and specialized views

- [ ] **10.01 — Embedded web content.** `E · Module`. Existing iframe/WKWebView. Load a deck, navigate within the admitted policy, exchange a message, fail loading, and remove/reopen; check focus, isolation, resources, and explicit unsupported host behavior. Extra browser controls remain separate scope.
- [ ] **10.02 — Photo/video selection.** `N · Operation/Module`. [PhotosPicker](https://developer.apple.com/documentation/photosui/photospicker)/PHPickerViewController. Select one/many assets, cancel, wait for remote loading, and encounter a failed asset; preserve order and report partial failure without hanging the form.
- [ ] **10.03 — Photo viewing, zoom, and image editing.** `E/N · Compose/Module`. Bounded LLP 1041 photo interaction exists; general crop/rotate/export does not follow from it. Zoom/pan, return to fit, rotate/crop if admitted, cancel, and export; define orientation, image quality, and gesture ownership.
- [ ] **10.04 — Video playback and presentation.** `N · Module; excluded pending admission`. [AVKit](https://developer.apple.com/documentation/avkit). Play, pause, seek, change source, enter/exit fullscreen, and interrupt playback; define captions, audio policy, background/Picture in Picture scope, and no hidden continuing player.
- [ ] **10.05 — Audio playback, recording, and route controls.** `N · Operation/Module`. [AVFAudio](https://developer.apple.com/documentation/avfaudio) and system media routing. Play or record a memo, deny permission, unplug/change output, and interrupt; distinguish app-owned controls from system route UI and retain only the intended recording.
- [ ] **10.06 — Camera capture and live preview.** `N · Module/Operation; excluded pending admission`. [AVFoundation capture](https://developer.apple.com/documentation/avfoundation/capture-setup). Capture/retake/cancel, deny permission, background, and reopen on hardware; camera resources must stop when their owner goes away.
- [ ] **10.07 — Document, barcode, and text scanning.** `N · Operation/Module; camera scope applies`. [VisionKit](https://developer.apple.com/documentation/visionkit). Scan two pages or a code, correct/retry, cancel, and handle unsupported hardware; separate recognition results from preview frames and persistent permission policy.
- [ ] **10.08 — Maps and location presentation.** `N · Module`. [MKMapView](https://developer.apple.com/documentation/mapkit/mkmapview)/SwiftUI Map. Pan/zoom, select an annotation, update the data, deny location, and go offline; separate map display from location permission and preserve the declared camera ownership.
- [ ] **10.09 — Drawing and Pencil tools.** `N · Module`. [PencilKit](https://developer.apple.com/documentation/pencilkit/pkcanvasview). Draw with touch/Pencil, erase, undo, change tools, save/reopen; test nested scrolling, tool palette ownership, and a portable/documented persistence choice on real supported hardware.
- [ ] **10.10 — Charts and data visualization.** `N · Compose/Module`. [Swift Charts](https://developer.apple.com/documentation/charts). Inspect a time series, select a point, change the range, and show missing data; preserve units, accessible values, and useful web/Linux presentation. A chart screenshot is not an interactive chart.
- [ ] **10.11 — GPU, 2D/3D, and live rendered content.** `E/N · Module`. Existing Metal-backed canvas; specialized [RealityKit](https://developer.apple.com/documentation/realitykit) content requires its own scope. Resize, occlude, remove, and reopen a surface; check resources, screenshots, frame demand, and input within a kernel-owned box.
- [ ] **10.12 — Terminals, code editors, and third-party native views.** `N · Module`. Choose one actual component as the first general native-view consumer. Type, select, resize, change focus, remove/reopen, and exercise its external-resource lifetime; do not assume a terminal process or editor undo stack survives reload without a contract.

### 11 — System and domain workflows

These are useful catalog dispositions, not a requirement that Exact become a
wrapper for every Apple service. Select a real workflow and public API, check its
platform/device availability, and keep its credentials/data model out of the view
kernel. None is accepted merely because a system sheet can be presented.

- [ ] **11.01 — Translation.** `E/P · Operation`. Existing native text-selection path plus a SwiftUI translationPresentation prototype. Invoke direct translation for selected app text, cancel first-use consent, translate on supported hardware, and close; retain source text, draft, and focus. Conversation translation is a separate product behavior.
- [ ] **11.02 — Authentication and biometric prompts.** `N · Operation`. [AuthenticationServices](https://developer.apple.com/documentation/authenticationservices)/[LocalAuthentication](https://developer.apple.com/documentation/localauthentication). Sign in, cancel, fail, and return from external/system UI; deliver once to the live owner. Credentials/session policy is not a view wrapper.
- [ ] **11.03 — Contact selection and editing.** `N · Operation`. [ContactsUI](https://developer.apple.com/documentation/contactsui). Pick a recipient, cancel, restrict/deny access, and handle a removed contact; return the agreed fields/identifier without importing the whole contact database implicitly.
- [ ] **11.04 — Calendar/event editing.** `N · Operation`. [EventKitUI](https://developer.apple.com/documentation/eventkitui). Add an appointment, change calendars, cancel, and deny access; distinguish an edited draft from a saved event and preserve date/time semantics from group 04.
- [ ] **11.05 — Mail and message composition.** `N · Operation`. [MessageUI](https://developer.apple.com/documentation/messageui) where supported; platform alternatives elsewhere. Prefill a recipient/attachment, cancel, and handle no configured service; report the platform's actual result without claiming message delivery.
- [ ] **11.06 — Payments and wallet presentation.** `N · Operation`. [PassKit](https://developer.apple.com/documentation/passkit). Use an appropriate test environment to exercise supported/unsupported setup, cancel, success, and failure; bind result to one purchase and separate presentation from business fulfillment.
- [ ] **11.07 — Purchases and subscriptions.** `N · Operation/Module`. [StoreKit](https://developer.apple.com/documentation/storekit) views and purchase operations. Inspect an offer, cancel, encounter pending/failure, and restore; separate UI dismissal, transaction state, and entitlement updates. No live purchase is needed for a hand check.
- [ ] **11.08 — Tips, onboarding assistance, and system settings links.** `N · Compose/Operation`. [TipKit](https://developer.apple.com/documentation/tipkit), SettingsLink where available. Show/dismiss a contextual tip, open settings, and return; avoid repeat interruption and preserve the user's place. Prefer a normal help flow where the platform facility is absent.
- [ ] **11.09 — Games and collaboration system UI.** `N · Defer/Operation`. [GameKit](https://developer.apple.com/documentation/gamekit), [GroupActivities](https://developer.apple.com/documentation/groupactivities). Only admit with a game/collaboration consumer; check join, cancellation, participant change, and session end. Return trigger: an app needs that actual system workflow, not a generic networking demo.
- [ ] **11.10 — App extensions and system surfaces.** `N · Defer/Alternative`. Widgets, Live Activities, notification actions, menu-bar items, Dock integration, Quick Look/share extensions. Decide each requested surface in the containing-app packaging layer; verify launch/action/termination there. These are not arbitrary views mounted inside Exact and do not create new target platforms by implication.

### 12 — Extension mechanisms and deliberate alternatives

- [ ] **12.01 — App-owned native leaf component.** `N · Module`. LLP 1024 is a proposal, despite NativeView's schema entry. Prove create/update/resize/destroy, event identity, focus, accessibility, unavailable-host result, packaging, and reload with the first real specialized consumer. Keep optional code outside core features and before-first-pixel imports.
- [ ] **12.02 — SwiftUI-hosted component.** `N · Module/Native`. UIHostingController/NSHostingView. Embed a bounded stateful control that presents its own system UI; update from Exact, dismiss, reparent, and destroy. Preserve controller containment, environment, and one committed state owner; a hosting view alone is insufficient.
- [ ] **12.03 — Native container with Exact children.** `N · Defer/Native`. A split/container/toolbar integration may need child projection rather than a leaf ABI. Prove mount order, layout ownership, focus, and removal with a concrete consumer. Do not silently make every module a container or add a second tree reconciler.
- [ ] **12.04 — Stacks, grids, spacers, and layout readers.** `E/N · Alternative`. UIStackView/NSStackView, H/V/ZStack, Grid, Spacer, GeometryReader. Build the equivalent responsive form using Exact's CSS model, documenting gaps. Do not duplicate Apple's layout engine; missing CSS capabilities remain genuine Exact work, not a claim that all compositions already exist.
- [ ] **12.05 — Shapes, gradients, effects, and animation APIs.** `E/N · Alternative/Module`. SwiftUI Shape/Canvas/effects and Apple animation APIs. Reproduce the needed visual with existing styles, images, motion, or canvas; test reduced motion, hit testing, and capture. Keep current gradient/layout-animation scope exclusions explicit.
- [ ] **12.06 — State wrappers, bindings, and platform application roots.** `N · Alternative`. SwiftUI State/Binding/Environment/App/Scene and UIKit/AppKit app ownership. Demonstrate Exact state driving an embedded component and the host owning its window. Export the capability, not a second application runtime or a platform property for every internal state variable.
- [ ] **12.07 — Legacy, private, and platform-only catalog entries.** `N · Alternative/Defer`. Evaluate NSCell/NSMatrix-era mechanisms, niche deprecated controls, Touch Bar, platform-specific content viewers, and attribution-only views by an actual need. Prefer supported modern equivalents; private APIs are not candidates. Record each newly requested exception instead of hiding it in “other.”
- [ ] **12.08 — General native styling escape hatch.** `N · Alternative`. Arbitrary native property setters and wholesale SwiftUI modifier forwarding. Style a representative control through the admitted Exact semantics; document unsupported customization. Add a justified semantic property or optional component when needed rather than an uninspectable native object bag.

## 7. Public-release review and remaining decisions

After each group, run its small integrated flow: controls must work together,
not just in isolated cells. Before publishing coverage, enumerate the supported
items and OS/platform limits from their receipts. In particular:

- Common controls should have a usable, documented authoring path; an optional
  Apple-native style is not a reason to make the web authoring model unusable.
- A partial capability is named narrowly: “single-action confirmation on iOS,”
  not “dialogs”; “selectable plain text,” not “rich text editor.”
- Count implemented/hand-checked coverage separately from reviewed deferrals.
  Do not advertise the whole checklist as supported because every row has a decision.
- Recheck affected receipts when their implementation changes. Do not rerun every
  manual case after an unrelated edit or introduce a second release gate system.

Decisions to make when beginning implementation: the first public-release subset;
whether to admit the single ordinary gallery app; actual baseline/current OS and
device availability for checks; first native-module consumer if any; and each
excluded feature's consumer/take when it is selected. These choices do not block
reading or using this ordered checklist, and no API design for unselected rows is
required in advance.
