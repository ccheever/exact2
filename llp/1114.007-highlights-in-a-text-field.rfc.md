# LLP 1114.007: Decorations over a textarea's plain string

**Type:** RFC
**Status:** Approved design, 2026-10-18; implementation in progress.
**Implementer:** Codex, 2026-10-18.
**Systems:** Contract syntax and lowering; kernel schema; runner field commands and geometry;
Apple, web, Linux, Windows, Android and terminal hosts.
**Related:** LLP 1045 D1/D5, LLP 1008 §5, LLP 1069.001, LLP 1115.

## 1. Scope

A `textarea` keeps a plain string. The app computes named decorations over that string;
the host lays them out and draws them. Decorations admit inline styling, block styling,
hidden source markers and atomic chips. The app owns its grammar and editing commands.
This replaces this RFC's paint-only `highlight` proposal with one capability.

The consumers are T3 Code's Markdown composer and Bluesky's coloured mentions, links and tags.
A field without decorations keeps its current editing and boot costs. No app-owned native
module or rich value type is introduced.

## 2. Authoring

```text
decoration mention color="#1083fe"
decoration heading font-size="1.25rem" font-weight=600 line-height=1.3 margin="1.25rem 0 0.5rem"
decoration quote border-left="2px solid #888" padding-left="0.8rem"

component Composer
  props
    draft: string
    draftDecorations: TextDecorations
  view
    textarea id="composer" value=draft decorations=draftDecorations
```

A producer constructs the record with the built-in shapes, naming every field:

```text
TextDecorations(value="hello @alice",
  spans=[TextDecorationSpan(name="mention", start=6, end=12)],
  blocks=[], hidden=[], atoms=[])
```

The other constructors are `TextDecorationBlock(name, start, end, marker)`,
`TextDecorationHidden(start, end, reveal)`, `TextDecorationAtom(name, start, end, label)`
and `TextDecorationRange(start, end)`; constructor arguments use `field=value` as above.
Use an empty marker string for no marker and `none` for no reveal interval.

A `decoration` is scoped and imported like a style declaration. Its properties use CSS names.
The compiler checks the supported property set instead of silently accepting arbitrary layout.
The declaration supplies appearance; it does not detect text or own editing rules.

`decorations` is a record containing the source `value` and these lists:

| List | Record | Meaning |
|---|---|---|
| `spans` | `{name, start, end}` | Inline font, colour, background and text decoration. |
| `blocks` | `{name, start, end, marker?}` | Whole-line spacing, padding, border, background, radius, font and line height. |
| `hidden` | `{start, end, reveal?}` | Source characters with zero advance, omitted from accessibility. |
| `atoms` | `{name, start, end, label}` | A labelled chip that selects and moves as one unit. |

Offsets are UTF-16 code units, matching field selection and JavaScript string offsets.
For example, `hello @alice` may carry `{value: "hello @alice", spans:
[{name: "mention", start: 6, end: 12}], blocks: [], hidden: [], atoms: []}`.

Inline declarations accept font properties, `color`, `background-color` and `text-decoration`.
Block declarations additionally accept block margins, left padding and border, `border-radius`
and `line-height`. Block markers are bullet, source number, checked/unchecked checkbox or rule.
A checkbox emits `toggle`; the app edits its plain source through the normal editing path.
Its `ToggleEvent` has `oldState`/`newState` (`checked` or `unchecked`) and UTF-16 `start`/`end`
for the source marker. Ordinary popover toggles retain `open`/`closed` and report -1 for
both offsets. Host dispatch kind 50 accepts `checked,unchecked,start,end` in addition to
its existing `open,closed` form.

A hidden range may name a reveal interval. When selection touches that interval, the host shows
the source dimmed immediately, without waiting for the data module. Each hidden boundary remains
a caret stop. Atomic ranges are selected and replaced whole. Neither changes the stored source.

Unknown names paint nothing and log once. Clamp ranges to the source length; empty ranges draw
nothing. Later named ranges take precedence where they overlap. Decoration updates never make
an undo entry or change the field's value.

`input` and `textarea markup="markdown"` refuse `decorations`: this capability applies to plain
multiline fields, while the existing Markdown editor retains its own grammar and styling owner.

## 3. Freshness, composition and undo

Each record names the exact source it describes. Equal ranges for a different string therefore
still make a new binding value. When its `value` equals the current field text, the record is
authoritative. Otherwise it is provisional until the app sends its next record.

Reconcile the two strings at their common prefix and suffix. Boundaries before the changed span
stay; boundaries after it move by the length difference; boundaries within replaced text move
to the replacement's start. Use shared Rust rules and table tests for these offsets. Provisional
hidden and atomic ranges that intersect the edit are revealed as ordinary source until fresh
metadata arrives, so stale metadata cannot hide or absorb new typing.

Do not apply decoration changes during IME composition. Apply them after composition ends,
preserving the committed text and selection. Restyling resets typing attributes to the base so
style does not bleed into new ordinary text. Style changes add no undo entry.

`setRangeText(id, text, "undo")`, or
`setRangeText(id, text, start, end, selectionMode, "undo")`, requests an explicit undo mode.
This mode on `setRangeText` makes one undo step for an app edit. Its existing default
keeps its current behaviour. The host delivers the existing single replacement input event;
undo/redo must restore both the source and selection, and decoration updates remain outside it.
This mode is an explicit extension to DOM's method, as LLP 1069.001 records for its input event.

## 4. Geometry

`rangeFrame(id, start, end)` reads a field range in the same viewport coordinate space as
`frame(id)`. It is an action-time geometry read, not a reactive subscription. It returns Geometry
with the existing unavailable/provisional conventions. This places a language picker or chip
popover beside the selected source. It does not expose a layout tree or general text metrics.

## 5. Hosts

| Host | Implementation and boundary |
|---|---|
| macOS | TextKit 2 storage and paragraph attributes, marker/frame/chip drawing, hidden-source caret stops and accessibility. Generalize the existing Markdown host code. Hidden markers are admitted here. |
| iOS/tvOS | The same shared rules and TextKit 2 path. Hidden markers remain visible until the required phone proof covers caret movement, selection gestures and accessibility. |
| Web JS/wasm | Load the shared contentEditable line renderer on demand for layout decorations. A paint-only record may use the field's Custom Highlight/OpaqueRange path when available. Both paths preserve the plain source. |
| Linux/Windows | Apply inline spans as text runs. Block layout, hidden ranges and atoms are declared host differences until supported. |
| Android/terminal | Ignore decoration paint as a declared difference; preserve ordinary editing and source. |

On Linux and Windows, spans affect glyph metrics and inline paint. Their font, colour,
background and text-decoration rows use the same source projection for intrinsic sizing,
wrapping, paint and caret geometry. Blocks do not change paragraph layout or draw markers;
block-only rows, including `line-height`, do not affect spans. Unknown aliases paint nothing
on these hosts and currently emit no warning, unlike Apple and web.
Hidden ranges remain visible and accessible; atoms remain their ordinary editable source
instead of labels or one-step selections. No checkbox toggle is generated. Android and
terminal ignore every decoration category, including spans, and retain their normal source
display, accessibility and editing. These differences do not change the record's source value.

An app without decorated or Markdown fields loads none of the optional editor machinery.
On the web, use the platform's editing, selection and composition where possible; structural
app edits use the shared source mapping and undo path. No mirror textarea or editor dependency
is admitted.

## 6. Agent and acceptance

No grant, timer or new agent operation is needed. `tree` shows the record; `state` reports applied
ranges and whether they are authoritative or provisional; `screenshot` shows the result.

Verify these behaviours through shared tests and actual host drives:

- An equal range list for `@alice` then `@carol` still refreshes because the source differs.
- Typing before, inside and after a range reconciles correctly, including astral characters.
- Stale hidden/atomic metadata reveals edited source until a matching record arrives.
- Heading, quote, list, task and fenced-code layouts preserve the source byte for byte.
- Caret movement crosses hidden/style boundaries in both directions; selection and accessibility
  exclude hidden source and treat a chip as one unit.
- Composition is not restyled mid-edit. Plain typing after styled text uses the base attributes.
- An app replacement is one undo step only when requested; undo/redo restores source and selection.
- `rangeFrame` follows wrapping, scrolling, removal and an unavailable field without polling.
- Removing decorations restores the ordinary field without losing source or selection.

## 7. Admission

The five rulings approved on 2026-10-18 admit layout decorations in this control, hidden markers
on macOS with the iOS proof boundary above, the two web rendering paths and undoable app edits.
LLP 1045's string value and TextKit 2 requirements remain. The prior paint-only RFC is folded
into this implementation; it does not become a second declaration or attribute.

## 8. Shared implementation boundary

The core slice defines the declarations, built-in records, kernel reconciliation, producer
serialization and action-time geometry/undo signatures. Host adoption and live acceptance
remain pending; accepting a Contract program does not yet establish decorated rendering.

At the producer/host boundary `decorations` is named JSON with the fields above. Missing
lists or malformed records are refused as a whole. Offsets are finite numbers, truncated
and clamped to unsigned UTF-16 offsets. Blocks always serialize `marker` as a vocabulary
string or `null`; hidden ranges serialize `reveal` as a range object or `null`.

The compiler emits the internal `decorationStyles` prop as a JSON object from visible
declaration aliases to ordered `[kernelStyleId, literalValue]` rows. CSS shorthands expand
to longhands; each id is from `kernel/tables/schema.json`, and font-family literals resolve
to plan font-stack ids. Values retain the existing style codec's string/number representation.
Only declarations visible to the field's source file enter its table. Apps write neither this
internal prop nor style ids. Hosts resolve relative lengths and platform colours in the
field's normal font and theme context.
