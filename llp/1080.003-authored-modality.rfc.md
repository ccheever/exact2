## 1. The gap

An app draws full-screen overlays as root children after the tab container, because content inside a route draws under the native bars (docs/agent-pitfalls.md). Signal Clone does this for its call screen, message menu, chat menu and delete sheet. Sighted users see only the overlay. VoiceOver still reaches everything underneath: the chat list, the swipe actions and the native tab and navigation bars. `axe describe-ui` over the call screen listed some twenty "Mute" buttons from the chat list behind it.

The kernel already has a prop for this (`accessibilityModal`, id 32), and `tree --ax` already reports platform modality (LLP 1080.002 D7, D8). No Contract attribute reached the prop, though, and no host acted on it. `inert` on the panels is not a substitute. It hides the authored content but not the tab controller's native bars, which live outside any node the app owns.

## 2. Decisions

**D1. `aria-modal` is an attribute on any element, lowered to `accessibilityModal`, a bool.** It takes a literal or an expression, like `inert`. ARIA defines it for `dialog` and `alertdialog`, and the web honours it there. An author should therefore write `role="dialog"` beside it. The compiler does not require that, because the native hosts act on the prop alone.

**D2. On iOS, the prop is `accessibilityViewIsModal`, while the view is exposed.** UIKit's documented rule then hides the view's siblings from VoiceOver.
- After each batch, `syncModal` decides which views are modal. A view qualifies while its prop is true and it is attached, displayed (no `display: none` on it or an ancestor), not hidden, not inert, and not leaving.
- UIKit's rule also hides one modal sibling from another. So of the views that qualify under one parent, only the frontmost is modal: highest `zPosition` first, then later in subview order.
- When the set changes, VoiceOver moves into the newest modal view, or back to the screen when there is none. The trigger can be a mount, a show, a hide, a removal, an exit or a cleared prop. The move is `.screenChanged` with that view, or with nil.
- A view that starts its exit is no longer modal, and a reused view starts unmodal.
- The native bars are hidden only when the overlay is a direct child of the root's container. The tab container's view is mounted there (`NavigationTabsIOS.swift`). The container is the root view unless the root scrolls, has a clip box (a clipped box with a shadow), a material or a glass group. In those cases the overlay sits in a wrapper, and the bars are siblings of the wrapper. A route-local dialog never hides the bars, because its route view lives in a route controller.

**D3. macOS: DEFERRED.** AppKit has no sibling rule. Filtering a parent's flattened `accessibilityChildren()` was tried, and both reviews of r1 found it unsound. It drops cells and scroll-wrapped modals, keeps a leaving or undisplayed modal, picks by subview order rather than paint order, and leaves `tree --ax`'s `modal` unreported. The macOS host therefore does not act on the prop yet. A correct version returns the modal view itself from the nearest ancestor that AppKit flattens, and reports it in `AgentAccessibility`'s `modal`. That needs its own tests with native controls and scroll parents.

**D4. On the web, the prop is the DOM's `aria-modal`.** The browser and the screen reader own what follows from it (LLP 1007 §2: the browser owns exclusion).

**D5. No new kernel prop, no digest change, no runtime change.** Plans baked before this change still load. A plan that uses the attribute needs a compiler with D1.

## 3. Proofs

- `contract/cli/tests/it/aria.rs`: `aria-modal` lowers and follows state, true and then false after a press.
- `host/web/tests/it/host.rs`: the boot batch carries `"aria-modal":"true"` beside `"role":"dialog"`.
- `AccessibilityTreeIOSTests.testAriaModalIsUIKitsModalViewWhileExposed`:
  - The prop sets `accessibilityViewIsModal`, and `tree --ax` reports the view as the modal and hides its siblings.
  - VoiceOver's target follows: the box while modal, nil after false.
  - `display: none` turns modality off and `display: flex` turns it back on.
  - Of two modal siblings only the front one is modal.
  - An exiting modal hides nothing, and the one left behind is modal again.
  - Clearing the prop exposes the siblings.
- On the simulator, under the agent: Signal Clone's call screen with `role="dialog" aria-modal=true`. `tree --ax` lists the call screen's 8 elements, "modal by accessibilityViewIsModal". The agent paints its own bars, so this does not show the native bars hidden. That rests on UIKit's rule and the overlay's placement (D2). VoiceOver on a phone is owed.

## 4. Not in this document

- Focus containment for keyboards (Tab cycling) on macOS and the web. The web's `<dialog>` with `showModal` already does that, and `aria-modal` alone never has.
- Escape to dismiss. Apps bind `key` themselves.
- `accessibilityPerformEscape` on iOS, the two-finger scrub. It belongs with the app's close action, and would be a separate `escape` handler mapping.
