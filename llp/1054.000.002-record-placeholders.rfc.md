# LLP 1054.000.002: Record placeholders without a data source

**Type:** RFC
**Status:** Draft
**Systems:** Contract language (resource declarations, values), compiler (type check, lowering), plan (a resource's placeholder), bake, runner (settlement's placeholder and pending rules)
**Author:** Claude (Opus 5.5) for Charlie Cheever
**Date:** 2026-09-26
**Related:** LLP 1054 L8 (the finding); LLP 1054.000 C3 (the question); LLP 1048.003 D6 (placeholders as built); LLP 1016 D3 (a resource keeps its value while a request is out); LLP 1027 D4 (before a module loads); LLP 1018 D4 (store readers are not compiled data); design inputs `llp/reviews/1054.000.002-record-placeholders.design-{claude,astra,grok}.md`


**Ruled (Charlie, 2026-09-27, after the review of PR #47; amends D4 as merged at a5f03a59):**
- A failed request never relabels the standing value. The runner keeps the value's own arguments and marks the failed arguments, so a request that fails every time isn't asked again until its arguments change or a `refresh` (built 2026-09-27).
- After a failure, a placeholder stays a placeholder, marked failed. It never becomes the answer.
- Contract reads the failure with `failed(x)`, beside `pending(x)`, so a view can say "couldn't load" instead of showing an empty or stale result as real. This follows the web's data libraries (React Query's `isError` beside kept data).

## Summary

A resource of record shape whose first answer comes later must declare
`else source(args)`. The app's data crate or module must then implement that
source only to hand back an "empty" record. The Bluesky port wrote eight of
these, and RealWorld wrote three. This RFC states the problem and the
constraints. Three designs were commissioned independently (Claude, GPT-6
Astra at maximum effort, Grok 4.7 at xhigh). §Design is the synthesis, and
§Decision records what was built.

## Motivation

As built (LLP 1048.003 D6, `runner/src/runner/settlement.rs` `placeholder`):

- A list resource shows `[]` and an option `none` while nothing is kept for
  its arguments and its source has not answered. `pending(r)` is true.
- A record, a string, a number or a bool has no empty value. Without an
  `else`, boot refuses: "answers later, with nothing kept for these
  arguments: declare a placeholder, `resource r = … else source()`".
- `else source(args)` compiles to a resource row of its own,
  `<name>#else`. Its arguments are values; reading state is
  `type-placeholder-reads`. The bake answers it once, and the answer is
  compiled into the plan. The source must answer now.
- Contract has no record values of its own. A record comes only from a
  source, so a placeholder costs a source in Rust or TypeScript.

What the consumers actually wrote:

- **Bluesky** (`data/src/values.rs` `empty`): `emptySession`, `emptyFeed`,
  `emptyNotes`, `emptySearch`, `emptyExplore`, `emptyPeople`,
  `emptyConvos`, `emptyLoads`. Most are all-zero. `emptyFeed` is not: it
  takes an argument (the feed id) and sets `more: true`. Records carry a
  `ready: bool` or `found: bool` that the placeholder leaves `false`, and
  the view reads it.
- **RealWorld** (`apps/realworld/app.ts`): `anonymous` (a `User` whose
  `avatar` is a default image URL, not `""`), `emptyFeed`, `emptyArticle`
  (a nested `author` record), `emptyProfile` (`image` is the default
  avatar URL).

So a placeholder is *mostly* the zero value, *sometimes* has a few non-zero
fields, and *occasionally* depends on a constant argument.

## Constraints every design must meet

1. **A placeholder is never an answer.** While it shows, `pending(r)` is
   true. It is never kept as the resource's answer for its arguments. It is
   never carried across a reload as an answer, and it never stops the first
   real request. A compiled baked answer, which is data, stays distinct
   from a placeholder, which is a stand-in.
2. **Shape conformance.** The value conforms to the resource's type,
   including nested records, lists, options, `unit` and runner-owned shapes.
3. **No new runtime machinery without need.** The runner already shows a
   placeholder row's value (LLP 1048.003 D6). A design that reuses that path
   costs less than one that adds a new one.
4. **The web is the standard only where it applies.** There is no CSS
   analogue; follow Contract's existing grammar and diagnostics style.
5. **Refusal stays helpful.** A resource that truly has nothing to show must
   still be refused at compile time, or it must show something defined.
   The current boot refusal names the fix.
6. **Both languages.** A Rust crate and a TypeScript module need no code for
   the common case. The design must also say what happens to the existing
   `else source()` placeholders.
7. **When it shows.** At boot before the first answer, while a TypeScript
   module has not loaded (`awaiting`), after a failed request, and after a
   reload that carries state. Each is defined.
8. **Cost.** Grammar, type check, lowering, plan format, bake and runner
   changes are named, with the diagnostics a mistake gets.

## Questions the designs answer

- Implicit (every record resource gets a zero placeholder), opt-in
  (`else empty` or similar), or something richer (record values in
  Contract; field defaults in `shape`)?
- How are the non-zero fields (`more: true`, a default avatar URL) and the
  argument-dependent ones (`emptyFeed(id)`) expressed, or are they left to
  `else source()`?
- What is "zero" for each type, and for a nested record?
- Does anything change for lists and options, which already have an
  implicit empty value?
- What do `pending(r)` and `state` show while the placeholder is up?

## Inputs

- **Claude** (`design-claude.md`, written before reading the others): opt-in
  `else empty` and `else { field: value }`; a constant in a new
  `resources.placeholder_value` column; a missing placeholder still refused.
- **Astra** (`design-astra.md`): implicit zero for every resource without
  `else`; `else empty(field=value, …)` reusing the call and named-argument
  grammar; the constant in the existing `#else` helper row with an empty
  source; and a **provenance flag** on the runner's resource state, because
  today a displayed placeholder is stored exactly like an answer and could be
  reused, carried or baked as one.
- **Grok 4.7 xhigh** (`design-grok.md`): received after the synthesis
  was built. It was run blind, in worktrees from before it. It converges on
  every decision taken. Implicit zero for every type without `else` makes
  it two of three designs. It has the same zero table, no source or
  signature for `empty`, and a literal-only patch surface. It independently
  finds the bake bug Astra found: a placeholder shown before a module is
  ready, with no ticket, would be compiled as the answer. Its differences
  are small and not taken:
  - `else empty { author.image="…" }` with dotted paths, where we have
    `else empty(author=empty(image="…"))`. That's the same power, and ours
    needs no new syntax.
  - The patched value in a `#else` row answered by a runner-owned
    `exactPlaceholder` source, where we use a column.
  - No provenance flag. It relies on the pending/stale flags, which D4's
    flag makes independent of request bookkeeping.

  It also noted that RealWorld's `me` and `post` need no patch, because
  their views gate on `signedIn`/`found`. The migration keeps the patches
  anyway, so the values shown are exactly the old ones. And it caught one
  leftover in the Bluesky data crate: a fast path for sources named
  `empty…`, now removed.

## Design

The synthesis. Where the first two agreed (zero values per type; overrides of
literals, `none`, `some(…)` and nested records; `else source()` stays for
computed placeholders; no live arguments), that is the design. Where they
differed:

**D1 — A resource without `else` gets its type's zero, pending.** From Astra.
Without stage labels, the missing-placeholder refusal happens at *boot* on a
device, not at compile time; a defined, pending value is better than a
refused boot, and the port's and RealWorld's records already carry
`ready`/`found` for views to read. This extends the rule lists and options
already follow. The zero of `number` is `0`, `string` `""`, `bool` `false`,
`unit` `()`, `option<T>` `none`, `list<T>` `[]`, a record every field's zero
in order.

**D2 — `else empty(field=value, …)` for the non-zero fields.** From Astra's
surface (it is the call grammar Contract already parses); from mine, bare
`else empty()` is the same as omitting `else`, spelled out. A value is a
literal (`-` allowed before a number), `true`/`false`, `none`, `some(v)`, or
a nested `empty(…)` for a record field. RealWorld's
`else anonymous()` becomes `else empty(avatar="/assets/default-avatar.svg")`.

**D3 — The constant rides the resource's row.** From mine: the compiler builds
the whole `Value` and stores it in a new `resources.placeholder_value` column
(empty bytes: none). Astra's helper row would need the settlement loop to
treat an empty-source row specially; a column needs one lookup in
`placeholder()`. An implicit zero is not stored at all: the runner computes it
from the type, as it already does for lists and options.

**D4 — A placeholder is never an answer.** From Astra. The runner's
`ResourceState` gains `placeholder: bool`, set when settlement shows a
placeholder (a declared row, a constant, or a zero) and cleared by any real
answer, even one equal to it. A placeholder state is reused only while a
request is in flight or the source is awaited; otherwise the resource is
asked again. It is never carried across a reload, never compiled by the bake
as the resource's answer, and never kept.

**D5 — Diagnostics** (Astra's, reported together): `type-placeholder-field`
(no such field), `type-placeholder-duplicate`, `type-placeholder-fields`
(positional argument, or fields on a non-record), `type-placeholder-type`,
`type-placeholder-value` (not a constant: "use `else source(…)` for
computation"). `type-placeholder-reads` stays for `else source(…)`.

**Not taken:** Astra's `resourceStatus` in the agent's `state` (the
`pending` list and values already show it; revisit if a drive needs it);
refusing a list/option `else source()` that answers later at bake (existing
behaviour, separate).


## Decision

Built 2026-09-26 by Claude (Opus 5.5) on main, D1–D5 as above:

- `contract/types/src/placeholder.rs`: `zero` and `materialize` (the check
  and the constant, one pure function), called by the type check
  (`component.rs`) and by lowering (`lower/src/lib.rs`). `empty` is not a
  source: no signature, no `#else` row, and `contract symbols` skips it.
- `plan/tables/format.json`: `resources.placeholder_value: bytes`.
- Runner (`settlement.rs`): `placeholder()` gives a declared row's value, the
  constant, or the type's zero, but no zero for a row that is itself a
  declared `else source()` (one that answers later is still refused, by its
  owner's name). `ResourceState.placeholder` marks what is shown. A
  placeholder is reused only while its request is in flight or its source is
  awaited, never carried, and never compiled by the bake
  (`Runner::resource_is_placeholder`).
- Tests: `contract/cli/tests/it/placeholder.rs` covers the zero shown
  pending, `empty(…)` with overrides and each diagnostic, nesting, and a
  placeholder shown before the source is ready never compiled. That last
  test failed before the bake change, the bug Astra found. The mutation,
  router and carry tests that pinned the old refusal now pin the new
  behaviour.
- Consumers: RealWorld drops four placeholder sources (`anonymous`,
  `emptyFeed`, `emptyArticle`, `emptyProfile`; the constants stay, as real
  answers), so its plan has 6 resource rows instead of 10. Bluesky drops
  seven (`emptySession` … `emptyConvos`) and the unused `emptyFeed`: 20 rows
  instead of 27. Bluesky was driven on the web (signed out, live network;
  and the demo account) and on macOS. RealWorld was type-checked against
  `app.ts`, but its bake needs Hermes, which this Mac lacks.
- Size: Caltrain's `app.wasm` is 710 KiB against 708 KiB without this change.

A behaviour change to note: a resource whose source is not ready (a
TypeScript module not yet loaded) and that has no compiled value now shows
its zero and is asked at `data_ready`. Before, it was asked anyway, which
for a real module failed with "the engine is not loaded".
