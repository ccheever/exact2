## Summary

On iOS a box's `@keyframes` on `translate`, `scale`, `rotate` and
`background-color` go to Core Animation as opacity's already did, so a
shimmer or a playhead no longer keeps the display link awake. What Core
Animation cannot play as CSS does stays sampled by the engine.

## 1. Why the key paths are CSS

UIKit anchors a view's layer at its centre, CSS's initial `transform-origin`.
Probed on a live layer: a non-additive animation on
`transform.translation.x`/`.y`, `transform.rotation.z` or `transform.scale`
replaces that one component of the layer's transform and keeps the others,
composed translate, then rotate, then scale — exactly the individual
transform properties, where an animation replaces its property's value.
Each interpolates its component linearly under the segment's cubic, as CSS
interpolates by computed value; a rotation's angle is a scalar, so 0 → 360°
turns once. Translate goes as two tracks (one per axis), rotate in radians.
`steps()` and `linear()` become sub-keyframes, a colour interval is sampled
every sixteenth (LLP 1055.000 D6's treatment), as before.

AppKit anchors a layer at its corner, so macOS samples all four.

## 2. When it lowers

A box's animation of any of the four lowers when (`svg_lower::box_eligible`):

- a transform: its `transform-origin` is the centre; no `layout-transition`
  moves it; neither it nor anything under it has a handler — Core Animation
  moves the presentation and UIKit hit-tests the model, where a browser
  hit-tests what it shows;
- a background colour: no side has a border that paints and there is no
  `background-image` (else the view draws its box in `draw(_:)`), and every
  colour in the track, the row's own where a 0% or 100% keyframe leaves it
  out, has one alpha (Core Animation interpolates unpremultiplied).

Otherwise every animation on that node is sampled. An SVG element's
transform is its scene's, and is sampled. `color` is sampled: text is a
raster. Eligibility is decided when the node's `animation` row changes, as
LLP 1055.000 D15's is.

## 3. Not built

- **Transitions** of these properties are still sampled; they are finite, so
  they wake the display link only while they run.
- A pressed box's `press-scale` and a scale animation on the same box: the
  box takes input, so it is sampled; nothing composes the two in Core
  Animation.
- Eligibility is not revisited when a border, handler or origin changes
  under a running animation.

## 4. Held by

- `host/apple/src/box_motion_tests.rs`: the specs for each property (keys,
  radians, the y track), each refusal sampled (corner origin, a pressable
  box, a box holding a button, a bordered colour, two alphas, an SVG
  element), no frames kept and no `present` ops for the lowered ones, macOS
  unchanged.
- `bun scripts/smoke.mjs motion`: the gallery's keyframes (a sweep, a pulse,
  a spin, a colour, `steps(4)`, a three-stop tour, a corner origin, a paused
  one) against Chrome at seven clock times, a held spec seeked by the
  agent's clock. 2026-09-27: iOS mean |Δ| 0.25/255.
- The display link, 2026-09-27, iPad Pro 13" (M5) simulator, the gallery's
  shimmer page (36 bars sweeping forever), idle 10 s after 3 s: lowered, the
  app's CPU 0.01 s and no `Frames.tick` in a 3 s `sample`; the same build
  with box lowering off, 0.36 s and `Frames.tick` in 22 samples. Core
  Animation's work is the render server's, not measured here.
