## Summary

Speech is two capabilities the web puts in one specification: the device
speaks text aloud, and the device turns spoken audio into text. exact2 gives
each its own package, because they share no object, no permission and no
dependency (D1):

- **`@exact/speech-synthesis`** speaks: the Web Speech API's
  `speechSynthesis.speak(new SpeechSynthesisUtterance(…))`, `cancel`,
  `pause`, `resume`, `getVoices`, with the queue's progress (the `boundary`
  event's `charIndex`) as a live value and each utterance's outcome kept by
  its id. Below it, `AVSpeechSynthesizer` and Android's `TextToSpeech`. It
  asks for no permission. Its sound is a claim on the host's one audio
  session, beside sounds (LLP 1096), players (LLP 1098) and captures (LLP
  1133.009 D7).
- **`@exact/speech-recognition`** listens: the Web Speech API's
  `SpeechRecognition`, in the specification's two forms, on an audio track
  that `@exact/media-capture` opened (`start(audioTrack)`) or on the
  microphone (`start()`), and, where the platform can, on a recorded file.
  Below it, the Speech framework (`SpeechAnalyzer` with `SpeechTranscriber`
  on iOS and macOS 26 and later, `SFSpeechRecognizer` before) and Android's
  `SpeechRecognizer`. Its results are a live value that numbers every final
  result; the whole transcript goes to a file the app names.

```
use getUserMedia, MediaStream from "@exact/media-capture"
use startSpeechRecognition, stopSpeechRecognition, speechRecognitionState,
  SpeechRecognitionInfo, SpeechRecognitionState
  from "@exact/speech-recognition"

state trackId = ""
state recognitionId = ""
mutation opened as shape MediaStream then listen
mutation started as shape SpeechRecognitionInfo then begun
mutation heard as shape SpeechRecognitionInfo then filed
resource words = speechRecognitionState(recognition=recognitionId)
  as shape SpeechRecognitionState else empty()

action open
  send opened = getUserMedia(audio=true)
action listen
  match opened
    case some(s)
      trackId = s.tracks[0].id
      send started = startSpeechRecognition(track=trackId, continuous=true,
        interimResults=true, processLocally=true,
        transcript="app:/data/notes/today.json")
    case none
      trackId = ""
action begun
  match started
    case some(r)
      recognitionId = r.id
    case none
      recognitionId = ""
action done
  send heard = stopSpeechRecognition(recognition=recognitionId)
```

```ts
import { cancelSpeech, speak } from "@exact/speech-synthesis";

// Replace whatever is being read; each speak answers its utterance's id at once.
await cancelSpeech();
const ids = [];
for (const text of paragraphs) ids.push((await speak({ text, audioSessionType: "playback" })).id);
return { ids };
```

Tier 2 reaches the Speech framework's engines, presets, punctuation and
custom language models, `AVSpeechSynthesizer`'s voices, Personal Voice and
SSML; Android's recognition services, biasing strings and silence lengths,
and the TTS engine. Tier 3 hands the app's Swift the synthesizer, each
utterance, and each recognition's analyzer or request before it starts;
its Kotlin the `TextToSpeech` after it initializes and each
`RecognizerIntent` before `startListening`.

Three things are decided here that reach beyond this module (D4, D8, D12):

- **Recognition opens no capture of its own beside media capture's.** It
  consumes a `@exact/media-capture` track's samples where the platform's
  recognizer takes audio (Apple always; desktop Chrome; Android services
  known to read a supplied audio source), holding the track's lease like a
  recorder, so a recorder and a live transcript share one capture, one
  decision and one indicator. Where the recognizer can only open the
  microphone itself (Safari, Chrome on Android, other Android services),
  `start()` takes the device **exclusively** from `@exact/media-capture`
  for its length, and only while no other consumer in the process uses
  that device.
- **Spoken audio is a claim on the host's audio session** with a type
  named after the W3C Audio Session draft: `transient` (a prompt that ducks
  other apps' audio), `transient-solo` (one that interrupts it), or
  `playback` (reading aloud, which interrupts it and may continue in the
  background). The owner never reconfigures the session under a live engine
  or player to serve a claim. On Android, where the host has no owner
  today, the owner is built here as the one holder of audio focus.
- **Results are a value, and the durable record is a file.** A
  recognition's state numbers its final results and keeps the latest
  window of them with the interim one, so a reader that skips answers can
  tell; the complete transcript is written to a path the app names, since
  a long session's text is unbounded and a module reply is not.

The consumers are two small features that apps in the repo lack and their
platforms' own apps have: the recorder shows a take's transcript as it
records and keeps it with the take, and transcribes an older take on
request; the Markdown reader reads a document aloud and marks the word
being spoken (§10).

## 1. What exists

**Nothing speaks or listens.** No host, runner command or app synthesises
or recognises speech. `rules/DEFERRED.md`'s LLP 1096 entry keeps
"synthesis" out of sounds; that is sound synthesis (oscillators, effects),
not speech, and this module moves nothing of it (§14 question 7).

**The grant exists.** `device.speech-recognition` is a row of
`runner/src/device.rs` (LLP 1069.008), deriving
`NSSpeechRecognitionUsageDescription` on iOS and macOS, with no web or
Android column; its comment records the web's deviation ("its speech API is
gated by `microphone`").

**What this builds on.** LLP 1133.009 decides the microphone:
`@exact/media-capture` is the only package that opens an input, one capture
per device for the process, a session's tracks as leases on it held while
the track has a consumer (D3, D6); handles are provisional until the runner
delivers the answer that carries them (D6); the host's audio-session owner
composes claims and is reachable from every package's context (D7, D10 item
5); a capture start is refused to a tool invocation and a wake in every
state (D9); a writable path may be checked out to a handle for its life
(D10 item 4); the runner tells an implementation when a source's argument
group loses its last reader (D10 item 12). LLP 1133.008 decides that a
lease is taken at the first consumer with the origin of the commit that
made it one (D3), and that under the agent the runner admits and the
implementation answers (D8 item 9). This RFC uses all of it unchanged and
adds what speech needs (D12).

## 2. Two packages

### D1 — Synthesis and recognition are separate packages

The Web Speech API is one document with two interfaces that share nothing:
`SpeechSynthesis` is a window attribute with a queue, `SpeechRecognition` a
constructor whose instances take a track. Their platform frameworks are
different (AVFAudio and Speech; `android.speech.tts` and `android.speech`),
synthesis asks for no permission while recognition asks for one or two, and
only recognition depends on `@exact/media-capture`.

One package would make an app that only speaks (the Markdown reader) depend
directly on `@exact/media-capture`, since LLP 1133.001 D4 lets no transitive
package carry native code, and link the Speech framework and the capture's
engine code for nothing. Two packages keep an app's dependencies, binary
and permissions to what it uses (LLP 1047.001). The roster's one row
(LLP 1133.000 §3.5) names the module; this RFC amends it to name both
packages (§11).

## 3. Synthesis

### D2 — Tier 1: `speechSynthesis`'s names

| Name | Kind | Web | Contract | Data code |
|---|---|---|---|---|
| `speak(text=, …)` | send; answers at once | `speechSynthesis.speak(new SpeechSynthesisUtterance(text))` with its attributes | `send u = speak(text=…)` | `await speak({text})` |
| `cancelSpeech()` | send, answers nothing | `speechSynthesis.cancel()` | `cancelSpeech()` | `await cancelSpeech()` |
| `pauseSpeech()`, `resumeSpeech()` | sends, answer nothing | `pause()`, `resume()` | statements | `await pauseSpeech()` |
| `speechSynthesisState()` | live source; a fact; `sync` where the host has `call` | `speaking`, `pending`, `paused`, and the current utterance's `boundary` | `resource s = speechSynthesisState()` | `await speechSynthesisState()` |
| `speechUtterance(utterance=)` | live source; a fact | one utterance's `start`, `end` and `error` | `resource u = speechUtterance(utterance=id)` | `await speechUtterance({utterance})` |
| `speechSynthesisVoices()` | live source; a fact; `sync` where the host has `call` | `getVoices()`, read again at `voiceschanged` | `resource v = speechSynthesisVoices()` | `await speechSynthesisVoices()` |

`speak`'s options are `SpeechSynthesisUtterance`'s attributes: `text`,
`lang` (BCP 47), `voice` (a `voiceURI` from `speechSynthesisVoices()`),
`volume` (0 to 1), `rate` (1 is the voice's normal rate), `pitch` (0 to 2),
and one shared word, `audioSessionType` (D4).

**Values:**

| Shape | Fields |
|---|---|
| `SpeechSynthesisVoice` | `voiceURI`, `name`, `lang`, `localService`, `default`; `apple`, `android` result words (D5) |
| `SpeechUtteranceInfo` | `id` |
| `SpeechSynthesisState` | `available`; `speaking`, `pending`, `paused` as the specification defines them; `utterance: option<string>`, the id being spoken; `charIndex`, `charLength`, `name` (`word`, `sentence`, a mark's name, or `""`) and `elapsedTime` of its last `boundary` or `mark`; `queue: string[]`, the ids not yet spoken |
| `SpeechUtterance` | `id`, `state` (`queued`, `speaking`, `paused`, `ended`), `outcome: option<enum<end|error>>`, `error: option<SpeechSynthesisErrorCode>` |

**Errors** are the specification's `SpeechSynthesisErrorCode`s, in an
utterance's `error` (`canceled`, `interrupted`, `audio-busy`,
`audio-hardware`, `network`, `synthesis-unavailable`, `synthesis-failed`,
`language-unavailable`, `voice-unavailable`, `text-too-long`,
`invalid-argument`, `not-allowed`). A send that cannot queue at all fails
with the `DOMException` name LLP 1133.006 D8 item 2 answers
(`NotSupportedError` where the target has no implementation,
`NotAllowedError` for D10's foreground rule).

**Declared deviations,** each because an event is not a value:

- **An utterance is an id,** and its id is a handle (LLP 1133.009 D10 item
  10). A reply the runner drops (a superseded mutation, the session ending)
  cancels that utterance: one still queued never speaks; one already
  speaking is interrupted. Words already heard cannot be taken back, so
  an app that replaces what is being read says so with `cancelSpeech()`
  before it queues, as the consumer does (§10).
- **Events are fields.** `start`, `end`, `pause`, `resume` and `error` are
  each utterance's `state`, `outcome` and `error`, kept by its id until the
  session ends (a few dozen bytes each), so no outcome is lost however many
  utterances end between two reads. `boundary` and `mark` are the queue
  state's `charIndex`, `charLength`, `name` and `elapsedTime`, the last
  one reached: a reader marking the word being spoken needs only that, so
  coalescing loses nothing it shows.
- **SSML** (the specification lets `text` be an SSML document) is not
  tier 1: browsers speak it as text or not at all, and the platforms take
  it only through their own entries (Apple's
  `AVSpeechUtterance(ssmlRepresentation:)`, iOS 16). `apple.ssml=true` is
  tier 2 (D5); everything else speaks `text` as plain text (§12).
- **Android's pause** (below, D3) resumes from the last boundary reached,
  not from the sample where it paused.

A `TextToSpeech` binds its engine asynchronously
([`OnInitListener`](https://developer.android.com/reference/android/speech/tts/TextToSpeech.OnInitListener));
the Android implementation makes it at the module's first name and holds
utterances spoken before initialization in its own queue, in order. It
gives the engine one utterance at a time, so its own queue, not the
engine's, is what `cancelSpeech`, `pauseSpeech` and a dropped handle act

### D4 — Spoken audio is a claim on the host's audio session

LLP 1096 D8 made one owner of the process's audio session, and LLP
1133.009 D7 made a capture one more claim the owner composes. Speech is a
third kind of claim, held from the queue's first utterance starting until
the queue is empty (or `cancelSpeech`), with a type the author may write on
`speak` as the shared word `audioSessionType`. Its values are the W3C Audio
Session draft's types for spoken output, whose meanings it takes:
`transient` ("such as a notification ping. They usually should play on top
of playback audio"), `transient-solo` ("such as driving directions",
which "pause/mute all other audio and play exclusively"), and `playback`
("podcasts, etc.", which "should not mix with other playback audio")
([Audio Session §3.1](https://w3c.github.io/audio-session/)). The draft sets
one type for a page; a claim per queue is a declared deviation, since a
reader that speaks a document and a game that speaks a prompt are different
uses in one app. **A queue's type is fixed when it starts speaking:** the
strongest type among the utterances queued by then (`playback` over
`transient-solo` over `transient`); an utterance of another type queued
later speaks under it, and the type is chosen again only when the queue
has emptied.

| Type | Apple (iOS, tvOS) | Android | Web |
|---|---|---|---|
| `transient` | `.playback`, mode [`.voicePrompt`](https://developer.apple.com/documentation/avfaudio/avaudiosession/mode-swift.struct/voiceprompt), options `.mixWithOthers`, `.duckOthers` and `.interruptSpokenAudioAndMixWithOthers`: other apps' music ducks and their spoken audio pauses, as a navigation prompt has it | focus `AUDIOFOCUS_GAIN_TRANSIENT_MAY_DUCK`; `USAGE_MEDIA`, `CONTENT_TYPE_SPEECH` | `navigator.audioSession.type = "transient"` where it exists |
| `transient-solo` | `.playback`, `.default`, no options: not mixable, so other apps' audio is interrupted for its length | `AUDIOFOCUS_GAIN_TRANSIENT`, the same attributes | `"transient-solo"` |
| `playback` | `.playback`, mode [`.spokenAudio`](https://developer.apple.com/documentation/avfaudio/avaudiosession/mode-swift.struct/spokenaudio), no options | `AUDIOFOCUS_GAIN`, the same attributes | `"playback"` |

All three are `.playback`, which plays with the Silent switch set, as a
voice prompt must ([`playback`](https://developer.apple.com/documentation/avfaudio/avaudiosession/category-swift.struct/playback)).
`.duckOthers` and `.interruptSpokenAudioAndMixWithOthers` each set
`.mixWithOthers` themselves
([`duckOthers`](https://developer.apple.com/documentation/avfaudio/avaudiosession/categoryoptions-swift.struct/duckothers),
[`interruptSpokenAudioAndMixWithOthers`](https://developer.apple.com/documentation/avfaudio/avaudiosession/categoryoptions-swift.struct/interruptspokenaudioandmixwithothers)),
which is why `transient-solo` takes neither: any of the three makes the
session mixable, and the type means exclusive. Ducking "ends when you
deactivate the session", and Apple says not to "duck the audio of other
apps for more than a few seconds", so `transient` is for prompts; reading
aloud is `playback`. The Mac has no session: the queue plays.

**Composition: speech never reconfigures a live engine or player.** A
category, mode or option change stops a running `AVAudioEngine` (LLP
1133.009 D7) and cuts a player. So the owner sets a speech claim's
configuration only while nothing else in the process holds the session (no
capture, no sound-arm engine, no player). While something does, speech
plays in the session as it is: under a capture's `.playAndRecord`, under a
`playback` app's non-mixable `.playback`, or under an `ambient` app's
session with sounds running, and a development build journals the type it
could not apply. A sound or video started during speech plays under the
speech claim's configuration, which is `.playback` in every case. When the
last speech claim ends and nothing else holds the session, the owner gives
it up with `.notifyOthersOnDeactivation`, so audio a prompt ducked or
interrupted returns; this includes an `ambient` app, whose session the
owner today leaves active (`AudioSession.release`). When something else
still holds it, the owner sets the other claim's configuration back only
if nothing live would be cut, and otherwise leaves it until that claim
ends; since ducking ends only at deactivation, a sound or player that
starts during a `transient` prompt keeps other apps ducked until it ends
too, which stage 2 measures and the journal names.

**Android** has the same three types as focus requests through the owner
(D12 item 2), with `USAGE_MEDIA` and `CONTENT_TYPE_SPEECH`, which the
system's automatic ducking spares ("automatic ducking is not performed
when the user is listening to speech content"), and the guide's rule for
spoken content, which "should pause rather than duck"
([Manage audio focus](https://developer.android.com/media/optimize/audio-focus)).
So `AUDIOFOCUS_LOSS_TRANSIENT` and `…_CAN_DUCK` pause the queue and resume
it when focus returns; `AUDIOFOCUS_LOSS` pauses it until `resumeSpeech`. A
capture claim holds `AUDIOFOCUS_GAIN` for its length, and speech under it
requests nothing. An app targeting API 35 "cannot request audio focus
unless it's the top app or running a foreground service" (the same page),
which is D10's foreground rule for starting speech.

**Interruptions** on Apple (a call, Siri) are the owner's to observe (LLP
1133.009 D7): the speaking utterance pauses, `paused` reads true, and the
queue resumes only by `resumeSpeech`, as a player resumes only when the app
asks; Android resumes after a transient loss by itself, as its guide asks,
a declared difference. A route change that removes headphones pauses a
`playback` queue, as Apple asks of a player when the old route was
headphones ([Responding to audio route changes](https://developer.apple.com/documentation/avfaudio/responding-to-audio-route-changes)).

**The background.** On iOS a `playback` claim with `audio` in
`host.ios.backgroundModes` keeps speaking when the app leaves the
foreground, through LLP 1133.009 D7's widened `playsInBackground`, which
gains this claim beside `.playback` and a background capture. On Android a
`playback` queue pauses when the activity stops, until the roster's
`foreground-service` module exists. A `transient` or `transient-solo` queue
is canceled at the background on every target, each utterance ending
`interrupted`: a prompt the person can no longer see the reason for is a
tell. Now Playing for a `playback` queue (LLP 1098's media session) is out
until a consumer asks (§12).

**Who plays it.** On Apple the synthesizer plays with
[`usesApplicationAudioSession`](https://developer.apple.com/documentation/avfaudio/avspeechsynthesizer/usesapplicationaudiosession)
true, under the owner's claim; set false, "the system creates a separate
audio session to automatically manage speech, interruptions, and mixing and
ducking", which would put a second owner beside LLP 1096 D8's. Whether the
synthesizer activates or deactivates the application's session by itself is
not documented; stage 2 measures it and amends this paragraph, the owner
having activated the session for the claim before `speak` reaches the
synthesizer. *Rejected:* rendering speech into buffers
(`write(_:toBufferCallback:toMarkerCallback:)`, iOS 17) and playing them
through the sound arm's engine. A hand-built app speaks with `speak(_:)`,
the platform's own route handling (AirPlay, the call uplink) comes with it,
and the buffer path's interaction with Personal Voice and assistive
settings is not documented; it stays tier 3 for an app that wants the
buffers (D5, D15).

### D6 — Objects and lifetimes for synthesis

- **One queue per session.** Each session has its own synthesizer and
  queue, as each document has its own `speechSynthesis`. Two sessions
  speaking at once are heard together, under one process claim whose type
  is the first queue's (D4).
- **An utterance belongs to its session** once delivered (D2's handle
  rule), and to nothing narrower: it outlives the answer and the mutation
  that queued it. `cancelSpeech` and the session's end cancel the queue;
  each queued utterance ends `canceled`, the speaking one `interrupted`.
- **`destroy`** (LLP 1133.009 D10 item 1) stops the synthesizer
  (`stopSpeaking(at: .immediate)`, `TextToSpeech.stop()` and, on the
  process's last session, `shutdown()`) and releases the claim.
- **Threads.** Every entry is on the main thread. Apple's delegate is
  called on the queue the synthesizer chooses; the implementation hops to
  main. Android's `UtteranceProgressListener` is called on a binder thread;
  the implementation posts to the main looper.

**Values:**

| Shape | Fields |
|---|---|
| `SpeechRecognitionInfo` | `id`, `leavesDevice` (true when this recognition's engine may send audio off the device, D9), `finalCount`, `transcript: option<string>` (the path, once written) |
| `SpeechRecognitionAlternative` | `transcript`, `confidence` (0 to 1) |
| `SpeechRecognitionResult` | `index` (0 for the recognition's first final result, counting up), `alternatives: SpeechRecognitionAlternative[]` (at most `maxAlternatives`, best first), `start: option<number>`, `end: option<number>` (milliseconds into the recognised audio, where the platform reports them) |
| `SpeechRecognitionState` | `id`, `state` (`starting`, `listening`, `stopping`, `ended`), `audio`, `sound`, `speech` (bools: between the `…start` and `…end` events), `results: SpeechRecognitionResult[]` (the last `history` final results, oldest first; default 20, at most 200), `finalCount`, `interim: option<SpeechRecognitionResult>`, `leavesDevice`, `error: option<SpeechRecognitionErrorCode>`, `message: option<string>` |

**Errors** are the specification's `SpeechRecognitionErrorCode`s in the
state's `error` (`no-speech`, `aborted`, `audio-capture`, `network`,
`not-allowed`, `service-not-allowed`, `language-not-supported`,
`phrases-not-supported`), and a send that cannot start fails with a
`DOMException` name: `InvalidStateError` for a track that is not a live
audio track (the specification's own rule for `start(audioTrack)`),
`NotAllowedError` for D10 and D11, `NotReadableError` for D8's exclusive
hold, `NotSupportedError` for an input `inputs` does not list or a target
with no recognizer.

**Declared deviations:**

- **A file is a source.** The web has no transcription of a file; Apple
  (`SFSpeechURLRecognitionRequest`, `SpeechAnalyzer(inputAudioFile:…)`) and
  an Android service that reads a supplied audio source do. `path=` is a
  shared word for it, in the specification's style, with its own entry in
  `inputs`.
- **Objects are ids,** and a recognition's id is a handle (LLP 1133.009 D10
  item 10): a reply the runner drops aborts the recognition.
- **Events are the state's fields.** `audiostart` … `audioend` are `audio`,
  `sound` and `speech`; `result` is `results`, `finalCount` and `interim`;
  `nomatch` is a final result with no alternatives; `error` and `end` are
  `error` and `state` `ended`, which is sticky until the session ends.
  Final results are numbered, so a reader that sees `finalCount` 12 and a
  window ending at index 11 has missed nothing, and one whose last read
  ended at index 3 and now sees the window starting at 5 knows two went by
  unseen (finals arrive seconds apart, so a window of 20 covers any reader
  that keeps up with commits). No event protocol is needed (LLP 1133 D6
  rule 7).
- **The whole transcript is a file.** A continuous recognition is
  unbounded, and a module reply is capped (1 MiB,
  `js/bake/src/typescript.mjs`, `runner/src/request.rs`). So the state
  carries only the window, `stopSpeechRecognition` answers the recognition's
  `SpeechRecognitionInfo`, and every final result goes, as it arrives, to
  the `transcript=` path: a JSON Lines file, one `SpeechRecognitionResult`
  a line, checked out to the recognition's handle for its life (LLP
  1133.009 D10 item 4) and finished when it ends, however it ends. A
  recognition with no `transcript=` keeps only its window, which is enough
  for a command or a dictated field.
- **`speechRecognitionAvailability`** is the static `available()` as a live
  source, re-asked when an install changes it.

### D8 — Three inputs, and what each target takes

The specification's two forms are two contracts, and exact2 keeps them
apart: **consuming a track's samples**, and **taking the microphone**.

**`track=` consumes samples.** A recognition on a track is one of that
track's consumers, as LLP 1133.009 D6 counts a recorder that is not
inactive: it holds the track's lease, so a track whose only consumer is a
recognition keeps the capture open, and the capture's device, processing
and constraints are the track's. Starting one is a capture start (D10).

**`microphone=true` takes the microphone.** Where the target takes
samples, it is the same as a track the implementation opens for itself
through `@exact/media-capture` with `getUserMedia(audio=true)`'s defaults
and ends with the recognition: one capture, one lease. Where the
recognizer can only open the microphone itself, `@exact/media-capture`
grants an **exclusive hold** on the default input device (D12 item 4):

- it is admitted only while no lease on that device in any session of the
  process has a consumer, and fails `NotReadableError` otherwise; while it
  lasts, `@exact/media-capture` opens no capture of the device, a
  `getUserMedia(audio=…)` whose consumer would start on it fails
  `NotReadableError`, and a track waiting for its first consumer stays
  `idle`;
- the platform recognizer then opens its own input, under the same
  platform permission (`microphone` in the browser, `RECORD_AUDIO`), from
  the platform's default device: an app cannot choose the input there, and
  the status says so (`inputs` has no `track`);
- the hold ends with the recognition.

**`path=` transcribes a file,** where `inputs` lists `file`. It opens no
device.

| Target | `track` | `microphone` | `file` |
|---|---|---|---|
| iOS, macOS 26 and later | the track's buffers as `AnalyzerInput`s on the `AsyncStream` a `SpeechAnalyzer` reads, converted with `AnalyzerInputConverter` ([SpeechAnalyzer](https://developer.apple.com/documentation/speech/speechanalyzer)) | through a track | `SpeechAnalyzer(inputAudioFile:…)` |
| iOS, macOS before 26 | appended to an [`SFSpeechAudioBufferRecognitionRequest`](https://developer.apple.com/documentation/speech/sfspeechaudiobufferrecognitionrequest) | through a track | `SFSpeechURLRecognitionRequest` |
| web, desktop Chrome 135 and later | `start(audioTrack)` with the page's `MediaStreamTrack` (MDN: Chrome 135; not Chrome on Android, Safari or Firefox) | through a track | absent |
| web, Safari and Chrome on Android | absent | `start()`, an exclusive hold | absent |
| Android 13 (API 33) and later, a qualified service | PCM written to a pipe passed as [`EXTRA_AUDIO_SOURCE`](https://developer.android.com/reference/android/speech/RecognizerIntent#EXTRA_AUDIO_SOURCE) with its channel count, encoding and sample rate | through a track | the file decoded (`MediaExtractor`, `MediaCodec`) into the same pipe |
| Android, any other service or API level | absent | `startListening` with no audio source, an exclusive hold | absent |

**A qualified Android service.** `EXTRA_AUDIO_SOURCE` says: "If this extra
is not set or the recognizer does not support this feature, the recognizer
will open the mic for audio", and no call reports support beforehand. A
service that ignores it opens a second capture, which Android's capture
policy resolves by silencing one client ([Sharing audio
input](https://developer.android.com/media/platform/sharing-audio-input)):
probing at run time would silence the recorder it meant to share with, or
open the room's microphone for a file a tool asked to transcribe. So the
Android implementation never probes. It carries a list of qualified
services (a package, a minimum version, and whether it is the on-device
recognizer of `createOnDeviceSpeechRecognizer`), and `inputs` lists
`track` and `file` only for the service a recognition would use and only
when the list names it. Stage 4 builds the list on devices where the app
is the only capture client, registering an `AudioRecordingCallback`
([`AudioManager`](https://developer.android.com/reference/android/media/AudioManager#registerAudioRecordingCallback(android.media.AudioManager.AudioRecordingCallback,%20android.os.Handler)))
to see whether the service opened its own capture while fed a known
recording; a service is added by a release of the package, never learnt on
a person's device.

So an app reads `inputs` and chooses: the recorder shows a live transcript
where `track` is listed, a Transcribe button where `file` is, and neither
where the target only has `microphone` (§10).

### D10 — Who may start, and the foreground

LLP 1133.009 D9's rule, unchanged: a **capture start** is refused to a tool
invocation and to a wake in every permission state, granted included
(`NotAllowedError`, `person-required`), and refused to any caller while the
app is not in the foreground. For this module the capture starts are
`startSpeechRecognition` with `track=` (it takes the track's lease) or
`microphone=true` (it takes a lease or an exclusive hold). They are
declared `"origin": "app", "foreground": true`. A tool may stop, abort and
read; a tool's `stopSpeechRecognition` answers the recognition's info, and
its transcript file is the app's data.

**A file is not a capture.** `startSpeechRecognition(path=…)` opens no
device, so it is admitted under LLP 1133.002 D12's table: a tool may
transcribe a take the app already has while the state is `granted`, and
fails `person-required` when it would prompt. The app should still say
whether the audio leaves the device (`leavesDevice`); the recorder asks for
local recognition, so a tool's transcription of a take stays on the device
or fails `service-not-allowed`.

**Recognition is a foreground activity.** Every recognition is declared
`"foreground": true` to start, and **leaving the foreground ends it**: a
track or microphone recognition is aborted (its window and transcript file
kept, `error` `aborted`) even when the capture under it is allowed to run
on in the background (LLP 1133.009 D8), and a file recognition ends the
same way, its finals so far in its file. Recognition in the background is
out (§12); this is the rule that keeps it out.

**Synthesis.** Speaking opens no device and shows no system UI, so any
origin may speak while the app is in the foreground, a tool's included.
`speak` and `resumeSpeech` are declared `"foreground": true`: a wake cannot
start speech (iOS gives a background app no new non-mixable session, and
Android's API 35 refuses focus to an app that is not the top app), while a
`playback` queue already speaking continues in the background where D4
says it does. `apple.requestPersonalVoiceAuthorization` shows a system
prompt and is a request, admitted as LLP 1133.002 D12 says.

**Not delegable now.** As LLP 1133.009 D9 says of a capture, recognition on
a live microphone records the room; until LLP 1133.002 D12's delegation
exists and says otherwise, no agent may start one without the person. A
voice is not a presence check (LLP 1133.010 D12), and nothing here treats
recognised speech as proof of who spoke.

## 5. Permission

### D11 — LLP 1133.002 §4 for recognition; none for synthesis

**Declare.** `device.speech-recognition <purposeKey>` gates every
recognition name, and `device.microphone` (LLP 1133.009 D9) gates the
inputs that capture, and on Android every input, since `SpeechRecognizer`
needs `RECORD_AUDIO` "to use this class":

| Target | `track=`, `microphone=true` | `path=` |
|---|---|---|
| iOS, macOS | `device.microphone` and `device.speech-recognition` | `device.speech-recognition` |
| Android | `device.microphone` and `device.speech-recognition` | the same |
| web | `device.microphone` and `device.speech-recognition` | (absent) |

`device.speech-recognition` derives, on iOS and macOS,
`NSSpeechRecognitionUsageDescription`, required "regardless of whether you
set `requiresOnDeviceRecognition` to true or false", without which "your
app will crash when it calls `requestAuthorization(_:)`" ([Apple](https://developer.apple.com/documentation/speech/asking-permission-to-use-speech-recognition));
on Android, `<queries>` for `android.speech.RecognitionService`, which apps
targeting API 30 need to reach a recognition service
([`createSpeechRecognizer`](https://developer.android.com/reference/android/speech/SpeechRecognizer#createSpeechRecognizer(android.content.Context)));
on the web, nothing (the row's recorded deviation). The declaration states
the table as grants per argument and per target (D12 item 5), so the bake
refuses a missing line by name (`grant-missing`) for an app and for a
third party's implementation alike.

Synthesis declares no grant. Its Android implementation declares
`<queries>` for `android.intent.action.TTS_SERVICE`, which "apps targeting
Android 11 that use text-to-speech should declare"
([TextToSpeech](https://developer.android.com/reference/android/speech/tts/TextToSpeech)),
in its `exact.json` (D12 item 3), derived when the package is used.

**Read.** `speechRecognitionStatus().state` is the decision a recognition
on this target still needs beyond the microphone's:

| Target | `state` |
|---|---|
| Apple 26 and later, the `SpeechAnalyzer` engines | `granted`: they are not `SFSpeechRecognizer`, whose server-bound process alone the authorization covers (below) |
| Apple before 26, or `apple.engine="sfSpeechRecognizer"` | `SFSpeechRecognizer.authorizationStatus()`: `notDetermined` → `prompt`, `authorized` → `granted`, `denied` and `restricted` → `denied` (`restricted` is tier 2) |
| Android | `microphoneStatus().state` (LLP 1133.009 D9): `RECORD_AUDIO` is the only decision, for a file too |
| web, `start(audioTrack)` | `granted`: it "does not request microphone permission" |
| web, `start()` | `unknown`: the browser's recognizer may ask by its own policy, and the Permissions API has no name for it |

Apple's article says the server-bound process "only applies to speech
recognition using `SFSpeechRecognizer`. `SpeechAnalyzer` transcriber modules
don't send audio data of the user's voice to Apple's servers". So on 26 the
implementation does not call `requestAuthorization` for the `SpeechAnalyzer`
engines, and asking an app on 26 to explain a server it never uses is not
the prompt the person sees. If stage 2 finds a transcriber failing for want
of authorization, that engine alone asks, and this table is amended.

**Ask.** A recognition while its decisions read `prompt` asks them in LLP
1133.002 D9's queue, the microphone's first (through `@exact/media-capture`'s
permission, which `getUserMedia` already took for a track): on Apple before
26, `SFSpeechRecognizer.requestAuthorization`; on Android, `RECORD_AUDIO`
through the microphone decision, before `startListening`, for a file too.
Explain and recover as LLP 1133.002 D11 says, with `openURL("app-settings:")`.

**Personal Voice** (synthesis, tier 2) is a permission of its own, read in
`apple.personalVoiceAuthorizationStatus` and asked by
`apple.requestPersonalVoiceAuthorization`; a Personal Voice is listed in
`speechSynthesisVoices()` only once authorized.

   abandons audio focus for the process, with the same claim API: a
   capture claim requests `AUDIOFOCUS_GAIN`, the speech types as D4 says,
   and a focus change reaches each holder as D4 says. Recording's Android
   capture (LLP 1133.009 stage 4) and sounds' later Android arm use it
   rather than each requesting focus.
3. **Manifest queries from an implementation.** An Android implementation's
   `exact.json` declares the `<queries>` intents it needs (`"queries":
   ["android.intent.action.TTS_SERVICE"]`), merged into the manifest when
   the package is bound, as geolocation's Apple implementation declares an
   Info.plist dictionary. A grant's Android column may name queries too
   (`device.speech-recognition`'s, D11).
4. **An exclusive hold on a device** (D8): `@exact/media-capture` gains
   `holdDevice(kind:, origin:)`, admitted as a capture start, which succeeds
   only while no lease on that device in any session has a consumer, opens
   nothing itself, refuses every consumer start on the device
   `NotReadableError` while held, and is released with the recognition.
   This amends LLP 1133.009 D3 and D6.
5. **Grants and origins conditioned on an argument's presence and the
   target** (`"grants": {"path": {"android": …}}`, `"origin": {"when":
   {"track": "present"}, …}`), beside LLP 1133.009 D10 item 8's condition
   on a value and item 9's grants per argument, so one send is a capture
   start with `track=` and not with `path=`, and needs the microphone line
   for a file on Android alone.

Each is apparatus under `rules/RULES.md` and lands with this ruling (§14
question 6).

### D17 — Cost

An app that does not import a package links none of it: no Speech
framework, no `NSSpeechRecognitionUsageDescription`, no `<queries>`, no
page code (LLP 1047.001). The synthesis package links AVFAudio, which the
sound arm links already, and no Speech. Nothing is made before the first
name is asked, so nothing runs before first pixel. Stage 2 records each
Apple implementation's size; stage 4 what the two Android implementations
add to an APK.

**Commit rate.** Interim results arrive several times a second, and each
announcement re-asks the state's readers with the window. The
implementation coalesces announcements to one per 100 ms of the session
clock and one per boundary for synthesis. LLP 1133.009 D13's budget, 2 ms
of main-thread time per update, is measured there for a small level value;
a state carrying a window of 20 results with alternatives is a larger
payload, so stage 0 measures it on the live clock against the same budget,
with a reader that falls behind, and lowers the default `history` if it
does not fit.

## 9. The substitute

**Each implementation is its own substitute** (LLP 1133.008 D8 item 9):
under the agent the runner admits each call and holds the permission
ticket, and the implementation runs, told so, speaks nothing, opens no
recognizer and calls no hatch. The declared `permission`
(`speech-recognition`) is the runner's, so `prefer
permission.speech-recognition`, `--permission speech-recognition=…` and
tickets work as geolocation's do. Its default is the target's (D11):
`prompt` on Apple before 26, the microphone's on Android, `granted`
elsewhere; the target's restrictions hold under the agent (LLP 1133.002
D15), `inputs` among them.

**Synthesis, on the session clock.** An utterance is spoken at 170 words a
minute times `rate`: each whitespace-separated word takes
`60000 / (170 × rate)` ms (352.9 ms at rate 1), a `word` boundary is
reached at each word's start, and `end` after the last. So at `clock
+1000` the third word is being spoken on every host. Voices are two:
"Agent voice" (`en-US`, the default) and one for the app's base locale.
`prefer extension speech-synthesis.fail="synthesis-failed"` makes the next
utterance end with that error.

**Recognition, from a phrase.** The agent's track (LLP 1133.009 §10) is a
tone, which no recognizer could hear. So a recognition hears what a drive
says it hears: `prefer extension speech-recognition.heard="pick up milk"`
delivers, from the moment it is set, one word as an interim result every
300 ms of the session clock and a final result 500 ms after the last word,
with confidence 0.9 and times on the session clock, each final appended to
the `transcript=` file. A non-continuous recognition then ends; a
continuous one waits for the next phrase. With no phrase, a non-continuous
recognition ends `no-speech` after 8 s. A `path=` recognition answers the
phrase preferred at its start as one final result, at once.
`prefer extension speech-recognition.speechRecognitionStatus={"inputs":["microphone"]}`
makes the target one that takes only the microphone (D8), so a drive tests
each branch on one host, and `{"local": false}` makes `processLocally=true`
fail `service-not-allowed`.

**Disclosure:** `state.extensions` lists each session's queue, each
utterance's state, the claim and its type, each recognition with its input
(track, microphone lease or hold, path), its results count, its transcript
path and each answer's origin.

**Production:** none of it.

## 11. What this amends

- **LLP 1133.009 D3, D6:** a recognition is a track consumer; a device may
  be held exclusively for a recognizer that opens it itself (D8, D12 item
  4).
- **LLP 1133.009 D7 and LLP 1096 D8:** the owner composes speech claims of
  three types, never reconfigures the session under a live engine or
  player, and gives an idle session up with
  `.notifyOthersOnDeactivation`, an `ambient` app's included (D4);
  `playsInBackground` includes a `playback` speech claim; the Android host
  gains an owner as audio focus, a capture claim requesting
  `AUDIOFOCUS_GAIN` (D12 item 2).
- **LLP 1133.009 D10 items 8 and 9:** origins and grants conditioned on an
  argument's presence and the target (D12 item 5).
- **LLP 1069.008:** `device.speech-recognition` gains an Android column
  (`<queries>` for `RecognitionService`); a grant column may name queries
  (D12 item 3).
- **LLP 1133.000 §3.5:** the row names two packages,
  `SpeechAnalyzer`/`SpeechTranscriber` and `SFSpeechRecognizer`,
  `TextToSpeech` and `SpeechRecognizer`; its "tier 2 must reach" becomes

## 14. Questions for the ruling

1. **Two packages (D1),** `@exact/speech-synthesis` and
   `@exact/speech-recognition`, as the roster's one module "speech"?
