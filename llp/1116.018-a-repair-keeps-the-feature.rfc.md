## 0. Summary

A builder who meets a refusal edits until the app compiles. LLP 1116.016 §7 had a GPT judge compare each
screen's first contract with its repaired one: about a quarter of repairs kept only part of the feature (GPT 11 of
45 under either compiler; Muse 13 of 32 and 18 of 33). What went is what a user sees: a save-failure message, a
running timer, an order, a heading, a status line.

Two causes. Some refusals marked a gap in the language: `failed()` refused a mutation, and the builder deleted
the failure message; admitting it (`90e28f1d2`) was the fix. The rest named no edit, or an edit that compiles but
means less, and the easiest repair deleted what did not fit.

**The standard: a loss is first a question about the language; a refusal that stays names an edit that keeps
what the form was for, or says plainly what is lost or where it moves; and the edit is tested.**

| | What changes | Kind |
|---|---|---|
| D1 | The standard for a refusal's message | standard |
| D2 | Every edit a message names compiles; where it claims the same behaviour, the runner shows it | test |
| D3 | The refusals the corpus shows losing behaviour, each fixed | messages, one attribute |
| D4 | The judge finds losses for a person to read; it is not a gate | measure |

## D1. The standard for a refusal's message

A refusal leads with the edit, in one line (LLP 1116.014 D1). The edit keeps what the form was for, by one of:

- **the same behaviour in Contract's form** (`timer t interval=1000 running=on tick=step` → `task stepTimer when
  on` with `every(1000, step)` under it);
- **the behaviour moved, named where the view reads it** (an order: `resource tasks = loadTasksByDueDate()`);
- **what is lost, said plainly**, where Contract has no equivalent and a host gap or a guarantee is the reason.

Before a loss row is fixed with a message, the RFC that fixes it asks whether the language lacks the form; if it
does, admitting the form is the fix and the message is deleted.

## D2. The edits are tested

- **Every edit a message names compiles.** LLP 1116.014 D2's fixture (`diagnostic_edits.rs`: what the builder
  wrote, how the message leads, the edits that must build) holds every refusal this RFC touches, and every
  refusal a later change touches joins it: a ratchet, not a census of all 330 ids at once.
- **Where a message claims the same behaviour, the runner shows it.** For the loss rows whose edit claims it (the
  timer, the footer chain), a case runs the edit in the runner through the states that matter (the clock moved,
  each branch's condition), with the expected values written from the feature.

## D3. The losses, fixed

The table in §1. `aria-atomic` is admitted as a property on every element, emitted by the web hosts; the native
hosts already announce a live region's whole text, which is `aria-atomic="true"`, and declare that
`aria-atomic="false"` is announced whole too (LLP 1001).

## D4. The judge as triage

`repair.py` and `repair_judge.py` stay the way to find what repairs lose. Their output is a list for a person to
read, not a stop rule: each partial verdict and a sample of the whole ones.
