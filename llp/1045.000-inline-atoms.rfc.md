## 1. Summary

An **atom** is a span of a Markdown source that the styler shows as one pill: a label
that is not its source, an optional icon, and a tooltip. A caret cannot stand inside it,
a selection takes it whole, Backspace removes it whole, and a press on it is a `press`
with its `href`. The value stays the Markdown string (LLP 1045 D1): an atom is a way of
drawing and editing source, not a value type.

An app declares which spans are atoms by their source form:

- a **link** (or image link) whose destination has a scheme the app names:
  `[Assistant quote](t3-citation://v1/…)`, `[main.rs](t3-context://v1/thread/7)`;
- a **prefix token**: a character the app names (`@`, `$`) at the start of a word, up to
  the next whitespace, with a quoted form (`@"a path with spaces"`);
- a **relative file link** whose text is the last segment of its destination
  (`[main.rs](src/main.rs)`);
- in the reader only, **inline math** between `$` delimiters, drawn as a picture the app
  supplies.

The one `markdown/editor` crate recognizes the spans from the source every time it
styles, so there is no list of offsets to keep in step with the text. The app supplies a
face for each atom (label, icon, tooltip) keyed by the atom's source text, not by its
position. Web, macOS and iOS draw atoms in the editor and the reader. Linux, Windows and
Android show the source in the editor and the label as link text in the reader, as
declared differences.

T3 Code is the consumer. Its composer chips and its transcript's `AssistantCitationChip`
are atoms in its reference; the clone draws them today as a "References" row below the
field and keeps them whole with app rules (#882, §8).

## 2. Motivation

Reference paths below are under `apps/web/src/` of T3 Code at `74541bab17`; clone paths
are under `examples/t3-code/` at `3e0c90e7b5`.

The reference T3 Code's composer is Tiptap 3 (ProseMirror). Its four chip nodes
(`composer-mention`, `composer-skill`, `composer-citation`, `composer-context-reference`)
are each `inline: true, atom: true, selectable: true`
(`components/ComposerPromptEditorTiptap.tsx:238-259, 299-321, 376-398,
501-524` at `74541bab17`). Each serializes to Markdown source, not to its label
(`composer-rich-text-doc.ts:827-841`). The person sees a pill with an icon
and a short label (a basename, a skill name, a quote cut at 64 characters); the source
behind a citation is a percent-encoded URL that can run to thousands of characters.

The clone's composer is LLP 1045's editor (`textarea markup="markdown"`). On the web it
hides `](destination)`; since r6, Apple does too. What it cannot do is draw a label that
is not the link text, keep the label out of editing, or deliver a press. So the clone
shows each reference twice: as link text in the field, and as a button in a References
row below it (`src/composer/composer-chip-controls.contract:20-53`).
And it keeps each reference whole with its own rules, in Contract and TypeScript, over
`setSelectionRange`, `setRangeText` and `beforeinput` (#882, §8). Every app with
mentions or tags would write those rules again, and each would differ in its corners.

LLP 1114.007 r3 removed atoms from `decorations` after three blind reviews found a second
editor beside LLP 1045's, hidden-range editing left to each browser, and app-supplied
offsets that go stale over new text. It sent chips here: "Hidden source, chips and block
layout in a plain field: LLP 1045's editor" (§8), and `QUEUE.md` says "Chips would need
their own RFC". This is that RFC. §7 answers each of r3's findings.

## 3. Design

### D1. An atom is a span of the source, recognized by the styler

The styler (`exact_markdown::style`) gains one output: `atoms`, a list of
`Atom { range, kind, source }`, where `range` is UTF-16 (LLP 1045 D2), `kind` is the
declaring `atom` name, and `source` is the substring. It is computed from the source and
the field's declared kinds on every `style`, as the hidden and replaced ranges are. The
host keeps no atom state between styles.

A span is an atom only where its form would otherwise be inline text: never inside a code
span, a fenced block or a thematic break (the clone's `sourceChips` excludes these,
`src/composer/composer-source-session.ts:146-148`), never inside another atom, and never across a line
break. Where two forms overlap, a link wins over a prefix token (the reference's rule,
`composer-editor-mentions.ts:78-95`), then the earlier start.

The forms, each declared by an `atom` (D3):

| Form | Matches | Ends | Default label |
|---|---|---|---|
| `link="<scheme>:"` | `[text](dest)` or `![text](dest)` where `dest` begins with the scheme (ASCII case-insensitive, as URL schemes compare) | the link's `)` | the link text |
| `link="relative"` | `[text](dest)` where `dest` has no scheme (a drive letter `C:` is not one) and `text` equals the last path segment of `dest`, percent-decoded | the link's `)` | the link text |
| `prefix="<c>"` | `c` at the source's start or after whitespace, then one or more non-whitespace code points, or `c"…"` with backslash escapes | the next whitespace, or the end of the source | the token without `c` |
| `math="dollar"` (reader only) | `$…$` by remark-math's `singleDollarTextMath` rules: no space inside either delimiter, not a number (`$5`), no line break | the closing `$` | the TeX source |

A prefix token is an atom only when the app has given it a face (D2). This is the
reference's own rule: a `$name` is a chip only when the provider has a skill of that
name (`composer-rich-text-doc.ts:456-478`), and a typed `@foo ` stays text until a menu
pick or a paste makes it one (`components/ComposerPromptEditorTiptap.tsx:1598-1606`). Link forms are
atoms whether or not a face has arrived; a missing face shows the default label.

The reader's dialect gains `$` math only on a node that declares a `math` kind. Elsewhere
`$` stays literal, as LLP 1045 D2's dialect has it.

### D2. The app supplies faces, keyed by source text

`atomFaces` takes a list of `AtomFace(source, label, icon, title)`:

- `source`: the atom's whole source substring, the key. Two atoms with equal source share
  a face.
- `label`: the text drawn in the pill and read by assistive technology. Empty takes D1's
  default.
- `icon`: an image source, as `image` takes one (an asset, a symbol role, `symbol:sf/…`,
  an `app:/` file, a `data:` URL; `docs/contract-for-agents.md` "Images"). Empty draws
  none. For a math atom it is the picture of the formula (D6).
- `title`: the tooltip, and the accessible description. Empty has none.

A face keyed by source cannot go stale: new text is a new key. A face that arrives after
the keystroke that made its atom changes the drawing a moment later and never the source
(LLP 1114.007 D3's lateness, without its offset reconciliation). A face whose source
matches no atom is ignored.

Faces are measured: a label changes the pill's width. The measurement key of LLP 1045 D3
gains the faces record.

### D3. Contract: an `atom` declaration, `atoms`, `atomFaces`

```text
atom citation link="t3-citation:"
atom context link="t3-context:"
atom file link="relative"
atom mention prefix="@"
atom skill prefix="$" background-color="light-dark(#efe7ff, #2c2340)"
atom equation math="dollar"

component Composer
  view
    textarea id="composer" value=draft input=edit press=chipPressed
      markup="markdown" atoms="citation context file mention skill" atomFaces=faces

component Reply
  view
    text body markup="markdown" atoms="citation equation" atomFaces=replyFaces press=citationPressed
```

`atom <name>` is a top-level declaration, scoped and imported like `style` and
`decoration`. It takes exactly one form attribute from D1's table and, optionally,
`color` and `background-color`, the paint `decoration` already admits. Any other
property is a compile error (`lower-atom-style`): the pill's metrics (padding, radius,
height, icon size) are the platform's (D4), because a property that moved them would be
a second layout model inside the editor.

`atoms` on a `text` or `textarea` with `markup="markdown"` lists the kinds visible in
the file. It is refused elsewhere (`lower-atom-field`), and a `math` kind on a `textarea`
is refused (`lower-atom-math-editor`), since the reference's composer keeps math as text.
A name with no visible declaration is a compile error. `atomFaces` takes an
`AtomFace[]`; without it every atom shows its default label.

The kernel gains three str props on `Text` and `TextInput`: `atoms` (the declared forms,
as a compiled table), `atomStyles` (the paint rows, as `decorationStyles` carries
`decoration`'s) and `atomFaces` (the record as named JSON). `atoms` and `atomFaces` are
measured; `atomStyles` is paint only. They go in `kernel/tables/schema.json`.

### D4. What an atom looks like

Unsaid, an atom is the platform's token: on macOS the pill `NSTokenField` draws, on iOS
the one `UISearchToken` draws, and on the web the host's stylesheet rule for the island,
with the same metrics and Chrome as the oracle. Its text is the field's font at the
field's size; its height is the line's text height, so a pill never changes the line
height of a line of plain text. `color` and `background-color` from the kind's
declaration win (author > platform, LLP 1115). The icon is square, as tall as the text's
cap height, before the label.

Inline formats around an atom apply to its label: `**[x](t3-citation:…)**` draws a
bold label. A range that covers an atom draws the atom selected, in the platform's
selection colour, as the reference highlights a chip in a range
(`components/ComposerPromptEditorTiptap.tsx:731-741`).

### D5. Editing at an atom: one set of rules, in the crate

The rules are the crate's, as LLP 1045's other editing rules are. The web runs them in
`exact-markdown-editor`; Apple applies them over the styler's marks, as it applies r6's
destination rules today (LLP 1045 D5 r6). Each rule names where the reference or the
clone has it.

- **Caret.** No offset strictly inside an atom is a caret position. A caret the app or
  the person sets inside one goes to the nearer edge; on a tie, its end (the clone's
  `composerChipEdge`, `src/composer/composer-rich.contract:35`).
- **Arrows.** An unmodified ← or → at an atom's edge crosses it in one step (the
  reference's `handleKeyDown`, `components/ComposerPromptEditorTiptap.tsx:1199-1243`). ⇧ with an
  arrow extends a range over it whole. ⌥ (word) movement treats it as one word. ↑ and ↓
  are the platform's line movement; a caret that lands inside one goes to the nearer edge.
- **Selection.** A range end inside an atom goes to the atom's outer edge, so a range
  holds an atom whole or not at all (`composerChipEdge`). A double-click on an atom
  selects it. A press on it in the editor selects it (D7), as a click on ProseMirror's
  `selectable` atom makes a node selection.
- **Deletion.** Backspace with a caret at an atom's end, or Delete at its start, removes
  the atom's whole source in one edit (the clone's `composerChipDeletion`,
  `src/composer/composer-source-chips.ts:109-117`). ⌥⌫ and ⌥⌦ remove it and the spaces between it and
  the caret, stopping at a line break (`composerChipWordDeletion`, `:121-129`). ⌃H and ⌃D
  are Backspace and Delete. Deleting a range that holds an atom removes it with the range.
  The reference's own Backspace at a chip is the browser's deletion of a
  `contenteditable=false` node, which Chrome removes whole; that is read from the code,
  not driven (the stage 1 drive compares it).
- **Typing and replacement.** Text typed, pasted, dropped or put by autocorrect over a
  range that holds an atom replaces the range, atom included. Since a caret is never
  inside one, typing at its edge inserts outside it. A character typed directly after a
  prefix token, with no space between, extends the token's source (`@foo` becomes
  `@foox`), which is then a new key: it shows as text until the app gives it a face. This
  is what the reference's serialization makes of the same keystrokes.
- **Undo.** Each atom deletion is one undo step; undo brings back the source and with it
  the atom and its face. On the web it is a crate history step; on Apple, native
  replacement in a group of its own, as `setRangeText` is (LLP 1045 D5).
- **Input methods.** A composition cannot begin inside an atom. One that begins over a
  range holding an atom first deletes the range, then composes (r6's rule for a range
  holding a destination). Text being composed is not recognized: a prefix token typed
  through an input method becomes an atom after the composition ends. No atom is
  restyled while marked text exists (LLP 1045 D1).
- **Copy, cut, plain copy.** A copy takes the atoms' source (LLP 1045 D1; the reference
  writes the source to `text/plain`, `components/ComposerPromptEditorTiptap.tsx:1783-1809`). Cut is
  one undo step. ⌘⇧C (LLP 1045 D1's plain copy) writes each atom's label.
- **Paste.** Pasted text is source; a pasted link form is an atom at once, and a pasted
  prefix token is one when the app gives it a face. The reference parses pasted text the
  same way (`components/ComposerPromptEditorTiptap.tsx:1388-1468`).
- **Commands.** `format` applies around an atom as around any text. `link` with a
  selection that is exactly one atom is in `MarkdownSelection.unavailable`.
  `MarkdownSelection.link` reports a link atom's destination when the selection is in or
  is it, as it does for a link now.
- **Not the editor's.** The trailing space the reference adds when a menu inserts a chip
  (`components/chat/ChatComposer.tsx:1016-1025`) is the app's `setRangeText`. Menus (`@`, `$`, `/`) and
  their keys are the app's.

`setSelectionRange`, `setRangeText`, `rangeFrame`, `input`, `beforeinput` and
`selectionchange` keep source offsets (LLP 1045 D6 r5). `beforeinput` comes first: an app
that cancels a Backspace at an atom keeps the atom.

### D6. Reading: atoms and inline math in `text markup="markdown"`

The reader draws an atom as the editor does, with no caret. `pieces` (LLP 1045 D4) gains
one piece kind, an inline box with the atom's kind, label, icon, title, `href` and source
range, measured and painted by the code that measures and paints the other pieces.

**Inline math** is an atom of a `math` kind. Its face's `icon` is the formula's picture
and its `label` the fallback text. The picture is the app's: T3 Code's data module turns
TeX into an SVG `data:` URL (a TeX-to-SVG renderer from npm, LLP 1027) and supplies it as
the face; native hosts draw SVG image sources since LLP 1011.001. The picture's natural
size sets the box. Its baseline sits on the text's baseline, lowered by the formula's
depth below it, which needs one more field on `AtomFace`, `baseline`, in ems (§10 Q5). Until
the face arrives, or when the renderer fails, the atom shows its TeX source as text, as
the reference shows the source when KaTeX throws (`components/chat/MarkdownMath.tsx:5-59`).

Display math (`$$…$$`, a ` ```math ` fence) is a block, not an inline atom. It stays out
of this RFC and can be a figure segment (LLP 1045 D9) or the Mermaid route (one web view
per block) in the app.

### D7. A press on an atom is a `press` with its `href`

A click or tap on an atom fires the `text`'s or `textarea`'s `press`, as a click on an
`<a>` inside the element bubbles to it. The `MouseEvent` an action may take gains:

- `href`: the destination of the link the press is in (a link atom's destination, as
  `HTMLAnchorElement.href` gives it; a prefix or math atom's source), `""` elsewhere;
- `sourceStart`, `sourceEnd`: the pressed atom's source range in UTF-16, `-1` elsewhere.

`rangeFrame(id, sourceStart, sourceEnd)` answers the pill's box on a `textarea`, as it
answers any range (LLP 1114.007 D7), and gains the same answer on a `text
markup="markdown"`, so a popover anchors to the pill. The press never navigates: a
declared scheme is the app's. In the editor the press first selects the atom (D5).

An atom is not a tab stop, as the reference's chips are not
(`components/ComposerPromptEditorTiptap.tsx:1245-1246`). Assistive technology activates it as a
link (D8), which is the same `press`.

### D8. Accessibility: atoms are elements in text order

- **Value.** The field's accessible value reads each atom as its label, in place of its
  source, as r6's VoiceOver value omits link destinations
  (`host/apple/Sources/ExactKit/MarkdownLink.swift:89-99`).
- **Elements.** Each atom is an accessibility element with the link role, named by its
  label, described by its title, at its pill's frame, in source order among the field's
  other elements. Web: the atom's island is an element with `role="link"`,
  `aria-label` and `aria-description` inside the `role="textbox"`. macOS: an
  `NSAccessibilityElement` child of the text view with `NSAccessibilityLinkRole`. iOS: a
  `UIAccessibilityElement` with the `.link` trait in the text view's
  `accessibilityElements`. Activating it is D7's press.
- **Icons** are not read (the reference's are `aria-hidden`,
  `components/ComposerPromptEditorTiptap.tsx:752`). A math atom is named by its label (the TeX, or
  the app's spoken form) with the role image: the reference names it "Inline equation"
  with KaTeX's MathML beside it, which no native host here reads (§6).

### D9. The agent

No new operation. `state.atoms` reports, per field and per `text`, each atom's kind,
source range, label and frame. `tree` shows the three props as the app set them. `type`
drives editing as today, so a drive asserts the rules by keys and reads `state`. A press
on an atom is driven by its frame (§10 Q6).

## 6. Known differences from the reference

- The pill's metrics are the platform's; the reference's are its Tailwind classes. Colours
  can match through the declaration; padding and radius cannot (Q2).
- A chip with a second control inside it (the citation's pencil button,
  `components/chat/AssistantCitationChip.tsx:147-238`) is one press target here. The app opens the comment
  from the press or from a popover. ⇧Tab to the pencil
  (`components/ComposerPromptEditorTiptap.tsx:1247-1270`) is dropped.
- iOS shows no tooltip (`title` is web and macOS only).
- Inline math has no MathML for screen readers, and its glyphs are the app's renderer's,
  not KaTeX's.
- Linux, Windows and Android editors show the source.

## 7. What r3's reviews found, and where this design stands

| r3 finding | Here |
|---|---|
| A second Markdown editor with different caret and hiding rules | One editor and one crate (LLP 1045); atoms are a run kind of its projection and a set of its rules. |
| A `<textarea>` replaced by a `div` in Safari and Firefox | Not this field: the Markdown editor is already `contentEditable` on the web (LLP 1045 D5). Plain textareas and `decorations` are untouched. |
| Hidden-range editing left to each browser | The crate decides every atom edit; the browser only types plain text outside atoms. |
| Prefix/suffix reconciliation leaves stale metadata over new text | Atoms are recognized from the source on every style. Faces are keyed by source text, so no offset is ever carried across an edit. |
| DOM names given meanings the DOM's do not have | `href` on the press is the anchor's `href`. New names (`atom`, `atoms`, `atomFaces`, `sourceStart`) are new, not borrowed. |
| No approval on record | §9: this RFC asks for the ruling before a build. |

## 9. What a ruling moves

`rules/DEFERRED.md`'s LLP 1045 entry ("no rich value type, collaboration or HTML paste
import") gains a record: inline atoms in LLP 1045's editor and reader, by this RFC, for
T3 Code's composer and transcript, the value still the source. It needs a take or a

## 10. Open questions for a ruling

1. **Admission.** Admit atoms with a take or a waiver? What is taken off, if a take?
2. **Styling.** Colours only, with the platform's metrics (D3, D4)? Or also `padding`
   and `border-radius`, which change layout inside the editor?
3. **The `relative` form.** Is "a relative link whose text is its last path segment" a
   framework form, or should the app write file mentions under a declared scheme? The
   reference's source is `[name](path)`, which a provider reads as a Markdown link.
4. **Prefix tokens gated by faces.** A prefix token is an atom only when the app names
   it (D1), as in the reference. Or should every matching token be an atom?
5. **Math.** Include inline math now (D6), with the picture the app's and a `baseline`
   field on `AtomFace`? Or defer it to its own child RFC?
6. **The press record.** `href`, `sourceStart` and `sourceEnd` on `MouseEvent` (D7), or a
   separate record for a press on an atom? And the driver's form for pressing an atom by
   its frame (`tap` has no point form outside `pinch`).
7. **Host coverage.** Web, macOS and iOS first; Linux, Windows and Android show the
   source in the editor, declared (the audit's D7)?
