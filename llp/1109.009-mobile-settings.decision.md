## Context

[observed] The mobile oracle is T3 Code at `365aa87982`. Its Settings scope can
select several environments and one logical project. The desktop clone's shared
transport, permission checks and data helpers remain the mobile app's data owner.
A selected logical project can have a different physical project ID in each
environment. Usage has its own environment filter and pooled account limits.
Scheduled Tasks retains an editable draft across nested model and branch routes.

[observed] LLP 1109.004 covers the Home grouping and initial device preferences;
LLP 1109.003 covers transport and credentials. Neither defines these scoped
server writes, retained task drafts or pooled usage accounts. This child records
the choices implemented in M8. It does not accept the implementation or claim
that the screens match the oracle.

## Scoped server settings

[observed] [root-presentation.ts](../examples/t3-code/mobile/root-presentation.ts)
projects Settings scope from the existing saved environments and shared fleet.
Environment-wide scope uses `members: null`. A project scope contains the exact
physical project members; an unavailable project produces an empty member list
and never broadens to environment-wide writes. The selected environment list for
Provider accounts is independent of whether that project exists on each server.

[observed] [settings-server.ts](../examples/t3-code/mobile/settings-server.ts)
and [settings-provider.ts](../examples/t3-code/mobile/settings-provider.ts) keep
the shared RPC and current-permission checks. Multi-environment saves report
partial failures by environment. Provider preparation reads catalogs and actual
auth state; typing, choosing a pending option and reveal changes use synchronous
projection. Provider auth events pass through the existing shared native reader
before acknowledgement. No second transport event drain is introduced.

## Scheduled draft

[observed] [settings-scheduled.ts](../examples/t3-code/mobile/settings-scheduled.ts)
uses the shared live-environment and task-stream helpers. The editor captures its
actual environment, project and task identity. Edit saves require the task still
to exist. The mobile upsert keeps the source's webhook schedule, signature and
runtime values, which the adopted desktop draft helper does not fully represent.
New tasks set `creationSource: mobile`; existing tasks retain their source. This
is an app-local payload adaptation, not a shared-protocol change.

[observed] Nested model and branch routes edit that same draft. Branch responses
are checked against the current query and draft before updating the list. Save
locks the draft before awaiting a real reply, retains it on failure, and closes
only after success. Delete, webhook rotation and dirty close require the native
confirmation associated with the captured target. The time picker returns a
local clock time; the mobileScheduleInput validator owns its payload.

## Offline cache storage

[observed] The app-owned `T3MobileClientCache` implementation uses a
separate SQLite database under `data/mobile-client-cache`. It serializes local
operations, uses bound SQL parameters and counts serialized UTF-8 payload bytes.
Its five record kinds are shell, thread, server-config, vcs-refs and project-favicon.
The module bridge admits requests on a serial queue and opens the database lazily.
No preference, draft, credential, attachment or delivery-journal store is included.
Standalone native storage validation passes. Focused and fleet snapshot consumers
are installed in the production mobile refresh, and Client Storage reads this store.

[observed] Persisted scope tickets reject writes captured before a matching clear
or removal, including after restart. Inspection and deletion share that store's
transaction owner. This is an app adaptation: the pinned source has no global
snapshot-cache epoch. Source favicon and VCS owners have additional invalidation
rules. VCS observation now wraps actual mobile requests; favicon rendering now consumes its app-owned query and image owners.

[observed] `mobile-client-cache-codec.ts` uses an explicitly different app format1,
not the source's schema3 envelope. The shared active shell already omits archived
rows and the wire shell version. At the pinned source, server ShellStream emits an
empty archivedThreads array and the Archive screen uses a separate live bounded
query; envelope fidelity alone does not establish a cold-offline Archive requirement. The codec preserves its retained rows and each
thread's committed projection, sequence and history boundary. Config removes
published themes and usage-limit sources as the pinned source does. Existing
shared validators are partial; source-derived fixture tests are not an executed
upstream schema differential.

[observed] `mobile-client-cache-sync.ts` runs after shared reducers in the mobile
subtype's awaited refresh. It captures immutable live snapshots after obtaining a
native ticket. Offline restoration commits all decoded display objects together,
after checking the selected environment, origin, generation, thread, revision,
current saved catalog and clear revision. An abandoned answer propagates without
another native call. Cached objects carry no connection, synchronization or scope
authority. The installed status hook removes those exact objects before connected
synchronization, so they cannot make the shared client skip a fresh snapshot.
Offline local selection reconciles cache ownership before reading a row; background
selection uses the native saved-environment operation and its returned status.
Neither path fabricates a synchronized fleet entry. Cached model/mode presentation
uses the existing staged-choice precedence. Selection rechecks its exact owner
after awaits, including a newer tap, catalog replacement and cache clear.

[observed] `mobile-client-cache-fleet.ts` runs background shell/config persistence
and separate offline display records. It never installs cached data into a live
fleet entry or changes synchronization. A connected entry suppresses its cached
view even when synchronization failed. Disabled environments keep stored data;
Home excludes them, matching the source's enabled-environment aggregates.
Forgotten, replaced or ambiguous saved identities invalidate retained and pending

Payload wrappers bind disk records to the normalized saved home, independently

discarded conditionally. A snapshot/generation barrier prevents old live objects
from repopulating a replacement catalog incarnation.

[observed] `mobile-vcs-cache.ts` admits only the unfiltered initial limit100 list.
Filtered or paginated reads remain live-only. It captures a ticket before the
live read, invalidates all VCS rows for the environment after ref mutations, and
blocks persisted reads after a failed clear until recovery succeeds. A live
error never falls back to cache. Its string codec matches the source's trimming
transform; the stored cwd key stays exact. Thirty-three comparisons against the
actual pinned decoder cover whitespace, null, missing and nonstring values.
The mobile subtype observes actual shared requests through its public request

adapters do not request notification permission, alter preferences, create tokens,
or call a native bridge. The configured source branch remains missing, including
