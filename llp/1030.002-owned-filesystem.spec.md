## Decision and scope

Charlie approved this narrow Rust primitive on 2026-09-04 after reviewing its
purpose and cost. Codex implements it on that date. It closes the remaining
check-then-open race in directory origins and the shared static-source policy.
The crate is build/publish tooling; no app links it and no boot uses it.
The current overlay archives the completed 1027.000 implementation link; its
document remains authoritative and reachable through LLP 1027.

## D1 — Owned directories, no followed user links

`exact-filesystem` opens the root from `/` one component at a time with
`openat(O_DIRECTORY | O_NOFOLLOW)`. Every subsequent component is relative to
an owned directory descriptor, including previously nonexistent write parents.
Files are opened with `O_NOFOLLOW`, checked regular, and read through that fd.
Listings use the directory descriptor. Rust bakes call the same directory walk
as a library; JavaScript tools use its executable. Asset inventory retains one
file's bytes at a time and hashes them in the bake, with no subprocess or base64
round trip. Pure Contract compilation remains portable; the owned-directory
asset bake runs on macOS or Linux. Served responses read through the same
primitive after route admission, closing their check/read gap too. Copying captures a whole source tree in
one helper invocation before writing its private candidate. Web bake, live dev,
and both Apple package outputs use that same primitive through `serve.mjs`.

The fixed macOS `/var`, `/tmp`, and `/etc` system prefixes map directly to their
`/private` spelling; this does not resolve any mutable user symlink. All other
symlinks, including dangling roots and final files, fail closed. A symlink
replacement cannot redirect an operation to its target. A renamed, already
opened directory remains the owned object: it can receive the write after being
renamed, rather than the replacement path. Detected stream-directory detachment
refuses the operation. This is not a snapshot of an arbitrarily edited tree.

## D2 — Complete writes and last-good candidates

A write creates an exclusive random sibling, writes and syncs it, then renames
through the same parent descriptor. Immutable writes use an exclusive hard link;
an existing name must have exactly the intended bytes. Links are never followed.
The private temporary name is removed through its parent on refusal.

Static copies reject links or read failures before their caller commits the
candidate. Live validators read those captured candidate bytes; a refused shader
or symlink leaves the previous served bytes and the dev process intact. Existing
whole-tree replacement and deletion semantics remain the caller's responsibility.
The primitive does not replace the separately landed deploy source snapshot.
Static watch notifications naming an ancestor of a configured tree reconcile
that whole tree: replacing `gpu` also replaces the `gpu/shaders` candidate.
This mapping does not guarantee that the OS delivers every watch notification.

Cargo bakes watch a missing optional static root's nearest existing ancestor,
so an unchanged absence stays warm and first creation still rebakes. If that
recursive watch would include a known Cargo, helper or bake output, or its
subtree contains links, they retain the conservative missing-root watch instead.
Those layouts still rebuild while the root is absent. Asset reads retain the
same owned-directory gate.

Development generations are reconstructible cache entries. Retention writes each
complete immutable file under one OS lock and writes the envelope last, without
file or directory fsync. Ordinary server/process restarts retain old URLs through
the OS filesystem cache. OS crashes or power loss may lose or reorder recent
writes; missing, malformed, truncated or digest-mismatched cached payloads are
refused. A lost historical iframe/resource URL can require an explicit app/page
reload; reconnecting with an identical generation does not guarantee its repair.
Signed publication and generic writes/stream heads retain their file-and-directory
syncs. This change does not alter app SQLite, files or secrets.

Quota accounting assumes an adapter-owned immutable cache. A fresh server,
missing or malformed completion, changed publisher token, or preceding failure
counts retained regular-file bytes through owned directories. An immediately
preceding successful holder may reuse the helper-computed total from the existing
lock file by presenting only its random completion token, never a byte count.
Acquisition invalidates the record before writes; successful completion records
the new token and a fixed-width count including the record itself. Untouched
historical corruption is discovered on verified reads or the next full scan,
rather than on every retention. Every new write still uses owned nofollow handles.
The envelope remains last. Quota refusal never removes an
older namespace. The server admits only envelope-declared files and verifies
their size and digest through owned reads, including after process restart.

## D3 — A held lock, never an age or PID lease

Each stream has a permanent `.lock` inode, opened without following links and
held with nonblocking `flock` by a helper for the entire publish callback. The
kernel releases it on helper exit. Neither age nor local/remote PID guesses can
steal it. A random acquisition token and the inode identity are verified for
operations, including immediately before head commit. The live acquisition token
is not fsynced: it is not recovery state, and process exit or reboot releases the OS lock. Release closes the owned
handle and never deletes a successor's named lock. An externally replaced lock
causes the former publisher to refuse subsequent operations.

`putHead` always acquires this lock, including standalone calls. The helper
stages and syncs the candidate, verifies ownership and compares the prior head's
digest immediately before rename. Generic `put` refuses stream heads and locks; the digest-named web release
envelope is permitted only as an immutable write. The web inventory pointer
uses the same guarded head operation.
This serializes all adapter publishers, including publishers with different host
identities. It is not a filesystem-wide digest CAS against arbitrary direct
writers bypassing the adapter. Shared volumes must provide working `flock`
semantics; an OS lock error fails closed. This is not a distributed lock service.

The tooling bridge separately serializes helper compilation and capture under a
local build claim. It launches digest-named captured bytes, so another Cargo
profile cannot replace an executable already selected by a caller. Stale build
claims require verifying that their recorded owner exited; they are not stream
locks and are never stolen automatically. A helper's unexplained exit reports
status and signal and never retries a filesystem operation that may have written.

Warm tooling starts reuse captured helper bytes after checking their digest and
hashing the complete helper and registry-package source trees, workspace manifest
and lock, toolchain versions and recorded build environment. A closure must match
before and after a Cargo build before it can be reused; the first observation only
seeds that comparison. Changed bytes invalidate even if size and timestamps were
preserved. Custom Cargo configuration, wrappers and additional local dependencies
fall back to Cargo. The mutable Cargo output is never the cached executable.
Up to eight verified environments share one unchanged source closure; build-script
callers do not evict an interactive caller's capture. Unsupported configurations
still invoke Cargo every time without discarding those independently validated
captures. A changed source closure discards all of its old environment entries.

HTTP reads share a resident helper. Its process and output streams gain a
liveness reference only on the transition from idle to pending reads, and lose
it after the last reply. Repeating `stderr.ref()` for concurrent reads can keep
Bun alive after all answers arrive; reference transitions are idempotent.

## Verification

The helper tests atomically exchange an intermediate real directory and an
outside-pointing symlink while reading, listing, writing, capturing static trees,
and acquiring/committing heads. Outside bytes never enter a candidate or receive
a write. Deterministic tests replace the parent after opening it and replace a
lock while its previous owner is alive. The existing caps suite covers live
symlink edits, invalid shaders, deletion/read races, both Apple static outputs,
all origin verbs and linked boundaries, old live locks, host identity changes,
lock replacement and reusability, and changed-head refusal.
The tooling fixture also replaces Cargo's helper output between callers and
checks that the first caller retains its executable and failed writes run once.
The resident-read fixture completes three concurrent bursts of large reads in a
child process and requires natural exit after the final reply.
