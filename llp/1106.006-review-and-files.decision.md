## Ownership

[inferred] [review-data.ts](../examples/t3-code/mobile/review-data.ts) owns section selection, disclosure, viewed state, line selection and cached screen projection. The shared T3Client remains the request owner. Shared diff.ts parses patches; diff-lazy.ts supplies source identity, per-file request payloads, patch adoption and retry; diff-comments.ts creates selected-line records. There is no second transport or event reducer. The mobile adapter reads ready checkpoint entities directly because desktop turnSummaries deliberately includes other statuses and deduplicates by run.

[observed] [review-owner.ts](../examples/t3-code/mobile/review-owner.ts) captures origin, environment, project, thread, generation, thread epoch and workspace. Reads check that identity before and after the native response. Actions require the snapshot owner, including a delayed comment Save. Shared cancellation errors propagate as cancellation. Newer files requests also supersede older requests for the same owner, preventing a delayed search authorization from replacing the current query.

[observed] [file-data.ts](../examples/t3-code/mobile/file-data.ts) reuses ensureTree, filesLocal and ensureFile from shared/r4-surfaces-files.ts. Those functions own projects.listEntries, projects.searchEntries and projects.readFile. The source search clamps its trimmed query to256 characters and asks for200 results. A fresh session check precedes access to cached host files; explicit permissions, including an empty array, take precedence over legacy scopes. Denied access hides cached text and tree entries.

[inferred] Shared composer-editor owns the context records placed on outbound messages. Review Save calls addReviewCommentChip through a mobile adapter for editorInsert/editorEdit. That adapter uses mobileDraftChanged, whose shared reducer runs synchronously before persistence. The current plain input appends the reference to its owned draft; it does not claim native caret insertion or rich chips. Save adds context to the draft, not a server comment or an immediate message. A subsequent normal Send owns dispatch. Remove uses the same shared record/reference removal path.

## Alternatives and consequences

[inferred] Reusing desktop DiffPanel presentation would change checkpoint eligibility, expansion, whitespace and lazy-loading behavior. Forking a mobile protocol client would split server and draft ownership. App-local projection over the existing reader/parser provides the narrower boundary, but shared parser limitations remain visible.

[observed] M6 is preparation, not acceptance. Missing evidence or implementation includes full native build and interaction validation, native screenshot parity, synchronized horizontal panning, whole-document native selection, exact hunk context and word-diff highlights, mobile comment attachment controls and rich context chips, complete media/browser file previews, native header menu fidelity, appearance-driven code sizing, and native transition/gesture behavior. Portable Markdown is used for Markdown files. Viewed/comment cards are functional projections whose native geometry is unverified. Root's interactive modal-back cleanup and scroll commands require integration checks.

## Manual viewport selection

[observed] [T3MobileReviewViewport.swift](../examples/t3-code/mobile/modules/apple/T3MobileReviewViewport.swift)
observes the public hooked list scroll view and mounted row bounds. It adds a target
to the existing pan recognizer and observes content offset without replacing the
scroll delegate. Each row carries its original file path, including comment rows
whose action path is a context identifier. Ending a hook removes its binding and
observations; the hook opts into row reuse.

[observed] A user pan admits viewport samples, including deceleration. The native
bridge coalesces pending samples on the main queue and emits only file changes.
The adjusted top means All files. If virtualization has not mounted the row at the
visible edge, sampling waits for a row or content-size update. Programmatic scrolls
without a user pan do not emit. Route, focus or navigation-revision changes reset
tracking, preserving the explicit destination during an animated file jump.

[observed] The root passes the report through its existing Review action. The
adapter checks owner, route visit, section, navigation revision and actual file
membership before changing selection. Refresh and explicit file selection advance
the navigation revision before asynchronous work. Passive viewport reports neither
navigate nor clear comments. They request the visible file and next two through
the existing lazy queue without awaiting network work or retrying failed patches.
The existing root task remains the patch read owner.

[observed] Combined root compilation, generated Answer typechecking, 540 mobile
tests, 71 neutral resource shape checks and a 120-handler exact-result audit pass.
Independent adapter review is [recorded here](reviews/1106.006-review-viewport.codex.md).
The actual iOS17 Swift API source check passes. Extracted native tracking and
coordinator bodies pass geometry and lifecycle witnesses; the latter use narrow
UIKit/Exact stubs and do not exercise real virtualization. The native implementation still requires a permitted full build and actual scrolling
on iPhone and iPad. These source checks establish no UIKit timing or pixel parity.

[observed] Real pairing and thread opening now work. Activating the Review navigation item aborts in UIKit while Exact configures the initially empty section select. The crash stack contains `UIMenu.establishInitialDefaultSingleSelection`, `UIButton.setMenu` and `ControlHost.configureValue`. Local gap008 records the reproduction and proposed framework fix.

[decision] Mount the section picker only while sections exist. Loading, error and empty content remain visible without a nonfunctional picker. The app does not alter Exact's native control code. The full native build passes. A subsequent native bar activation opens Review without crashing, and Back returns to Thread. The delayed data read then reports missing host-file permissions, tracked separately in the mobile pairing adapter. Diff rendering and viewport selection remain unverified.
