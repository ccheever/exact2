## Ownership

[inferred] [review-data.ts](../examples/t3-code/mobile/review-data.ts) owns section selection, disclosure, viewed state, line selection and cached screen projection. The shared T3Client remains the request owner. Shared diff.ts parses patches; diff-lazy.ts supplies source identity, per-file request payloads, patch adoption and retry; diff-comments.ts creates selected-line records. There is no second transport or event reducer. The mobile adapter reads ready checkpoint entities directly because desktop turnSummaries deliberately includes other statuses and deduplicates by run.

[observed] [review-owner.ts](../examples/t3-code/mobile/review-owner.ts) captures origin, environment, project, thread, generation, thread epoch and workspace. Reads check that identity before and after the native response. Actions require the snapshot owner, including a delayed comment Save. Shared cancellation errors propagate as cancellation. Newer files requests also supersede older requests for the same owner, preventing a delayed search authorization from replacing the current query.

[observed] [file-data.ts](../examples/t3-code/mobile/file-data.ts) reuses ensureTree, filesLocal and ensureFile from shared/r4-surfaces-files.ts. Those functions own projects.listEntries, projects.searchEntries and projects.readFile. The source search clamps its trimmed query to256 characters and asks for200 results. A fresh session check precedes access to cached host files; explicit permissions, including an empty array, take precedence over legacy scopes. Denied access hides cached text and tree entries.

[inferred] Shared composer-editor owns the context records placed on outbound messages. Review Save calls addReviewCommentChip through a mobile adapter for editorInsert/editorEdit. That adapter uses mobileDraftChanged, whose shared reducer runs synchronously before persistence. The current plain input appends the reference to its owned draft; it does not claim native caret insertion or rich chips. Save adds context to the draft, not a server comment or an immediate message. A subsequent normal Send owns dispatch. Remove uses the same shared record/reference removal path.

## Mobile presentation

[observed] [file-tree-model.ts](../examples/t3-code/mobile/file-tree-model.ts) preserves the pinned mobile fileTree.ts bodies, replacing only the ProjectEntry type and the search-ranking import with local/shared equivalents. It preserves directory rows, ancestor visibility during search, case-insensitive numeric sorting, and fuzzy word matching. The adapter merges only loaded directories reachable from the root, plus actual search results.

[observed] [review-model.ts](../examples/t3-code/mobile/review-model.ts) projects the shared parsed patch into mobile stacked rows and applies the source suppression thresholds. It uses the existing mobile TextMate theme adapter for full-side syntax state. Source text normalizes CR/LF, expands tabs to four spaces and retains the final blank line. An initial line is clamped and exposed as a row key for root scrolling.

[observed] [review-colors.ts](../examples/t3-code/mobile/review-colors.ts) uses the twelve previously extracted theme files and the pinned native diff colors. Contract components draw file headers, gutters, code rows, notices, source previews, tree rows and the comment composer. Review uses the native contextmenu gesture for range-start; the next line tap selects its end. An ordinary line tap opens the one-line comment sheet. UIKit's existing NodeViewIOS installs that long-press recognizer from the handler; native interaction still requires verification.

[observed] The current snapshot cache holds only the latest projection for each live review state and preserves row/token objects across unrelated app revisions. Inactive routes return an empty constant before parsing or highlighting. No native answer handle or pending promise is cached.

## Root seam

[observed] ReviewSnapshot/ReviewResult/ReviewColors are declared in review-shapes.contract. FileTreeSnapshot/FileTreeResult are in file-tree.contract; FileSnapshot is in file-view.contract. Root supplies headers, section/file menus, search debounce, navigation, modal lifecycle, wrap/preview choice and refresh. ReviewView reports action(op,path,lineIndex). File navigation uses actual paths, never an inferred server result. A changed-file pick exposes selectedPath and can scroll the virtualized review-diff list to key `file:<path>`.

[observed] Parent Contract imports are refused with contract-use-path. [file-icons.contract](../examples/t3-code/mobile/file-icons.contract) therefore contains the existing FileTypeIcon component with unchanged body, source SHA-256 and GAP001 marker. Its desktop Pierre icon geometry is reused; an exhaustive mobile icon-asset comparison is pending. Shared and framework source remain unchanged.

## Alternatives and consequences

[inferred] Reusing desktop DiffPanel presentation would change checkpoint eligibility, expansion, whitespace and lazy-loading behavior. Forking a mobile protocol client would split server and draft ownership. App-local projection over the existing reader/parser provides the narrower boundary, but shared parser limitations remain visible.

[observed] M6 is preparation, not acceptance. Missing evidence or implementation includes combined/native Contract validation, native screenshot parity, synchronized horizontal panning, whole-document native selection, exact hunk context and word-diff highlights, mobile comment attachment controls and rich context chips, complete media/browser file previews, native header menu fidelity, appearance-driven code sizing, and native transition/gesture behavior. Portable Markdown is used for Markdown files. Viewed/comment cards are functional projections whose native geometry is unverified. Root's interactive modal-back cleanup and scroll commands require integration checks.

## Validation

[observed] Scoped Bun tests exercise real shared request payloads with fixture transports, permission downgrade, stale workspace/search responses, checkpoint eligibility, lazy order/counts, source text normalization, actual outbound comment context and removal. Strict TypeScript and the bake capture/ambient validator pass for the new adapter entry points. These checks do not contact a live server or prove native rendering.

[observed] The isolated Contract loop stopped after three attempts: a typed-state error in its harness, unsupported default prop syntax in new components, then a harness import crossing the app directory. The first two were corrected; the file-icon ancestor import was localized afterward. No fourth attempt ran, so final Contract compilation remains unknown. Full native and combined root retries remain stopped under the existing human retry decision.


## Navigator selection follow-up

[observed] ReviewFileNavigator at the pinned mobile source is a flat list. Its projection is rendered in the responsive inspector described by LLP1106.011. File selection now clears comment selection, expands the chosen file and emits an owned scroll target. The highlighted inspector row can clear selection and return to the first diff row. Marking viewed collapses a file; marking unviewed leaves it collapsed.

[observed] Lazy selection returns its navigation result before patch reads. The snapshot exposes only the missing paths already requested by the existing shared lazy-patch owner. An explicit root task reads that queue for its captured section. A failed patch remains an error until an explicit retry; it does not keep the root task running. Review replies now carry the originating route visit, and the root checks that plus the workspace owner before navigation or feedback. Selection and queue regression tests pass; native list scroll behavior remains unverified.
