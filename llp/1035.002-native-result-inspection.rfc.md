## Summary

Select a node and answer five questions without LLDB: what did the author
ask for, what value won, why did it win, where is the node actually
painted, and what native state is affecting it. The answers extend the
three reads LLP 1012 already has — `tree`, `layout`, `state` — as **forms**
of those operations. There is no `inspect` operation, no devtools UI, and no
second state model: everything reported is an observation of the runner's
memory or the host's view hierarchy, tagged with the identity the runner
already stamps on `tree` (`epoch`, `incarnation`).

Today `layout` takes no target and reports `{id, x, y, w, h}` per node in
one space; `state` reports slots, derives, resources, pending requests and
store names; `tree` reports props by name and handlers. No reply names a
value's source, a coordinate space, a clip chain, the focused editor, the
keyboard's frame, the selected route or a transition's phase, and only
`tree` carries `epoch`/`incarnation`. Diagnosing the Messages heading
colour meant reading the arena and the presenter's dictionary in a
debugger; diagnosing the sheet's offset meant adding a window offset by
hand.

Decisions: **`layout <node>` is a form that explains one node** (D1),
**`state` gains focus, keyboard and navigation sections** (D2), **every
reply is tagged and a stale node is refused** (D3), **coordinate spaces are
named and missing ones are absent** (D4), **a value's source is one of five
kinds** (D5), **development source locations are a compiler-emitted map the
driver joins** (D6, the one DEFERRED amendment), and **reads are bounded
and opt-in** (D7).

## 1. Motivation — what the reads carry today

From `runner/src/agent.rs` and the three host agents:

- `tree` (`agent.rs:50-127`): `epoch`, `incarnation`, `clock`, `roots`,
  nodes in preorder with `id`, `parent`, `depth`, `type`, `props`,
  `handlers`, `children`. No style rows, no plan site.
- `layout` (`AgentIOS.swift:114-144`, `AgentMac.swift:28-101`,
  `glue.js:913-930`): `clock`, `viewport`, `env`, every mounted node's box
  in the viewport space — the web's `getBoundingClientRect`, transforms and
  scroll offsets folded in, two decimals — plus `sx`/`sy` on scroll
  containers and `ox`/`oy` under overscroll. No target argument
  (`agent.mjs:537-542` fetches `tree` again to join `type`/`testId`). No
  window, screen or capture space; no clip chain; no hidden/inert flag.
- `state` (`agent.rs:132-201`): `clock`, `slots`, `derives`, `resources`,
  `pending`, `store` (names), `delivery`. No focus, route, keyboard or
  transition.
- Identity: only `tree` echoes `epoch`/`incarnation`; no reply carries the
  session label, a wall-clock stamp or a coordinate-space name.

What the runner has and does not report: the own `StyleMask` (authored
presence) and the rows (LLP 1001 §2); the plan node each view was
instantiated from and the keyed instance it belongs to (the runner keeps
both to evaluate bindings); whether a row is bound by an expression
(`bindings.kind`, `plan/tables/format.json`). What the hosts have and do
not report: the native view class and its controller, the sheet, the
effect view, the first responder, the keyboard's frame and guide, the
navigation stack and the transition coordinator's state.

## 2. Decisions

### D1 — `layout <node>` explains one node

CLI `layout <target>`; wire `{"op":"layout","id":V}`. The reply is the
ordinary `layout` reply plus one `node` object for that view:

```
node
  id, type, testId, site (plan node index), instance (keyed path)
  style: { <row>: { value, source, from?, applied? } … }   — every own row and every inherited row
  props: { <name>: value … }                                — own props, as tree
  space:
    viewport { x, y, w, h }          — LLP 1012's space, unchanged
    parent   { x, y, w, h }          — the kernel's parent-relative frame
    local    { w, h, padding, border } — the used box
    window   { x, y, w, h }?         — UIKit/AppKit window points (absent on web/linux)
    screen   { x, y, w, h }?         — device points (absent on web/macOS)
    capture  { scale }               — pixels per point of a screenshot
  transform?  { translate, rotate, scale }   — the presentation values in force
  scroll: [ { id, sx, sy } … ]      — the enclosing scroll containers, outermost first
  clip:   [ { id, kind } … ]        — enclosing "overflow" and "clip-path" clippers
  visible: { hidden, inert, inViewport, clipped }
  native: { view, controller?, presentation?, effect?, editor? }   — host observations
  observed: { clock, wall }
  truncated?: [ "style" … ]
```

The runner answers `style`, `props`, `site`, `instance` and the parent
frame from its memory (the rows, the own mask, D5's sources); the host
answers the spaces, transform, scroll and clip chains, visibility and
`native`. The driver merges and renders it as a block under the ordinary
layout listing (LLP 1012 §7's rule: the rendering is part of the
interface; one `render`). `layout` with no target is unchanged.

### D2 — `state` gains three host sections

Appended to the runner's reply by the host, per session:

```
focus:      { logical: id|null, editor: id|null, responder: "UITextView"|…|null,
              pending: { target, reason, since }|null }
keyboard:   { visible, frame { x, y, w, h } (viewport space), overlap, guide,
              policy: "resizes-content"|"resizes-visual", interactive }
navigation: { route: key, stack: [ key … ], presentation: "modal"|null, closedby,
              transition: { interactive, phase: "idle"|"in-progress"|"cancelled"|"completed" } }
```

Web: `focus.logical` from `document.activeElement`'s view id, `keyboard`
from `visualViewport` where the browser exposes it and from the `env`
overlap otherwise, `navigation` from the root's props and the DOM's
`inert` state; `transition.phase` is `idle` (the browser has no
interactive pop). Linux: the sections present with `unavailable: true`
rather than absent, so a reader can tell "no keyboard" from "no report".
Observations only: nothing here is writable.

### D3 — Every reply is tagged, and a stale node is refused

Every reply carries `epoch`, `incarnation`, `clock` and — on the sample
hosts — `session`. A `layout <node>` or any targeted read whose `id` is
not a live view in the current incarnation is refused with
`{"error":"stale node #V (incarnation I)"}`; the driver's target
resolution (`tree` → id) is already per call, and the refusal closes the
window between. Native snapshots are taken on the UI thread with no action
run between the runner's part and the host's part; when a reply spans two
epochs (host I/O landed between), `spanned: true` says so and the caller
re-reads. No snapshot tokens, no refs, no identity envelope beyond these
three numbers (LLP 1012 §6).

### D4 — Coordinate spaces are named; a space the host cannot observe is absent

`viewport` is LLP 1012's space and stays the only space the ordinary
`layout` listing uses. `window` and `screen` are the platform's — UIKit's
window and screen points, AppKit's window points (y-down, converted) —
present only where the host has them. `capture.scale` is the pixels-per-
point of `screenshot`. During an animation the host reports the model
frame in `viewport` and, when it can read the presentation layer, the
observed frame as `presented { x, y, w, h }` beside it; it never
fabricates one from the model. If a driver maps a Simulator window onto the
desktop (1035.003 D3), that mapping is the driver's and is reported by the
driver as `desktop`, never by the host as a device coordinate.

### D5 — A value's source is one of five kinds

For each reported row: `authored` (the own mask has it, from a literal or a
class expansion), `dynamic` (the own mask has it and the plan binds it by
expression — `bindings.kind`), `inherited` (not in the own mask; `from`
names the ancestor whose own row won; 1035.000 D1's `computed`), `initial`
(no ancestor has it; the schema default), and `applied: "unsupported"`
beside any of these when the host has no mapping for the row (a material
on Linux, `clip-path` on Linux). A CSS initial value is never reported as
authored; a host fallback is never reported as an implementation. For a
`light-dark()` pair the reply carries the pair and `resolved: { scheme,
value }` from the painting host.

### D6 — Development source locations are a compiler-emitted map the driver joins

`tree` and `layout <node>` report `site` — the plan node index — and
`instance` — the keyed instance path (`each` keys from the root). Both are
in the runner's memory; no source text, no spans, no plan change. The
compiler emits, on request (`contract build --map`) and always in the dev
loop, `<plan>.map.json`: the plan's digest and, per plan node, `{file,
line, col, component, chain: [{component, file, line, col} …]}` — the
declaration and the component instantiation sites the inliner expanded.
The driver reads the map beside the plan, refuses one whose digest is not
the running plan's (`map is stale: rebuilt 14:02, running 13:58`), and
renders `@ app.contract:412 (Bubble ← Messages app.contract:459)` after a
node. The map never ships in a bake, is never read by a host, and holds no
source text, evaluation history or dataflow. Its format is 1035.005 D3's.

`rules/DEFERRED.md` §Agent API today excludes "contract witness /
dataflow / source-map / bindings". Before this slice is implemented that
line is amended to admit this bounded map (LLP 1035 §5 names the take);
the witness, dataflow and general provenance explorer stay excluded.
Slices 1 and 2 need no amendment.

### D7 — Reads are bounded, opt-in, and never carry private text into geometry

A targeted read is one node (a subtree form is not in this slice; it
returns `truncated` when a later slice adds it). `state`'s new sections
are fixed-size. An editor's text and selection appear only in `state`
(where the value already appears as a slot) — never in `layout <node>`'s
`native.editor`, which names the editor's class and first-responder
status only. The trusted development carriers are reused (LLP 1012 §4);
nothing new listens. Reply size and latency are measured on Messages and
the two-session host and printed by `metrics.mjs`; regressions ride the
existing tests; no new blocking check.

The source-map identity request adds only `planDigest` to the inner node (80
JSON bytes), and computes SHA-256 once per immutable runner plan on demand.
The first mapped read still allocates and encodes O(plan bytes); subsequent
reads reuse the digest. The discarded full-plan-hex prototype added 90–330 KB
on Caltrain, Messages and Exact Live and is not retained. Use
`bun scripts/metrics.mjs --inspection <host> --app <name> [--session <label>]`
after building to report actual carrier first/repeated latency and reply size;
`--json` keeps the samples' summaries and plan digest. This measures carrier
round trips, not CPU or physical presentation. Source-map fetching is separate.

## 3. What this deliberately does not add

A ninth operation; a devtools UI; a views layer or server (LLP 1012 §6); a
writable state model; a general provenance graph, dataflow trace or
witness; source text in any reply; a snapshot/ref envelope; a subtree dump
in slice 1; a `desktop` space reported by a host.

## 4. Landing order

1. **Slice 1 (this implementer):** D1 without `native`'s presentation
   fields, D3, D4's `viewport`/`parent`/`local`/`window`/`capture`, D5,
   `site`/`instance` from D6 (the runner's part; no map yet), the
   `render` block and its transcript fixture sample. Proof: `layout
   inbox-title` on the Messages dark launch reports `text_color: {value:
   light-dark(…), source: inherited, from: #1, resolved: {dark, #ffffff}}`;
   `layout new-message-sheet` reports the sheet's `window` box offset from
   its `viewport` box; a stale id refuses; the same read on the
   two-session host reports session b's view offset from the window origin.
2. **Slice 2:** D2's three sections on Apple and the web, `native`'s
   presentation fields, `presented` frames, the clip and scroll chains;
   proof through 1035.001's matrix (held sheet, cancelled Back, pending
   focus).
3. **Slice 3 (after the amendment):** D6's map emitted by the compiler and
   joined by the driver; proof: the three authoring edits of 1035.005 §3.

## 5. Open questions

- Should `layout <node>` on the web report the browser's *computed* style
  for the inherited rows as a parity check against the runner's
  `computed`? Leaning: yes, as `browser: value` beside `value` — the
  oracle in the reply.
- `instance` for a node outside any `each` is the empty path; for a node
  inside two nested `each`es it is two keys. Is the keyed path enough to
  find the instance in `state`? It is how the runner names row slots.
