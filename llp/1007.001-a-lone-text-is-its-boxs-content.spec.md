# LLP 1007.001: A lone plain text is its box's content on the web

**Type:** Spec
**Status:** Built (2026-10-02)
**Systems:** the web hosts' element projection (`host/web/src/element.rs` `folds`, `contents`): the live wasm host, the document writer (the render host's pages), the JS target's build (`host/web/src/template.rs` `parts_with`, `host/web-js/src/style.rs`); the agent's boxes on the web (`host/web/navigation.js` `viewBox`). No kernel, plan, Contract or native-host change.
**Author:** Claude (Opus 5.5) for Charlie Cheever
**Date:** 2026-10-02
**Related:** LLP 1007 §1 (a node is an element); LLP 1071.000 §6 (the grid's two extra boxes a row, where this was found); LLP 1012 (the agent's tree and layout); LLP 1074 D2 (paint isolation, which reads elements' paint facts).

## 1. Why

A kernel `Text` is an element on the web: a `<div data-exact-text>`, a `<span>`
inside a button. A button whose only child is its label is two boxes where a
hand-written page has one: the grid benchmark's rows made 24 layout nodes to
Solid's 22 (10,000 rows: 240,022 against 220,018), each one style-recalculated
and laid out at every create and append.

## 2. The rule

A `Text` **folds** into its parent's content when, in the tree as it stands:

- it is its parent's only child, and the parent is a box or a button (`View`,
  `Pressable`);
- it has no style row, no prop but its text, and no handler;
- it is no inline run (a `Text` inside a `Text` is one already);
- the parent has no `text-overflow` or `line-clamp`, which would reach the
  text once it is the parent's own inline content;
- the parent lays out one anonymous child as a block would: it is a block,
  or a flex column that stretches and starts its items (`align-items`
  normal or stretch, `justify-content` normal or start);
- a button that is a flex box has its content's height: no `height`,
  `min-height` or `aspect-ratio`, not absolutely positioned, not growing in
  a flex column, and not stretched across a flex row (its `align-self`, or
  its row's `align-items`, is neither normal nor stretch). A `<button>` that
  is a block centers its line boxes in its height, and no `align-content`
  moves them (Chrome, measured), so a taller button would carry its label
  from the top to the middle. Conformance's `rowsmore` caught this: a
  48-point button's label dropped 15 pixels.

Nothing of its own could show or hear anything, so nothing is lost by its
having no box.

## 3. How it projects

The element stays. It gets `display: contents` (and no `display: block`), so
it makes no box, and the parent, if it is a flex column, is written
`display: block`. A flex box wraps loose text in an anonymous item of its
own, so the text alone would trade one box for another; a block holds the
text as its own line boxes. For the parents above the two lay out alike: the
one item of a stretching, starting flex column is a full-width block at the
top, which is where a block's lines are — the same line boxes, the same
inherited font and colour. Measured on the grid's page (1,000 rows), Chrome's
layout tree goes from 24,086 objects to 22,073; `display: contents` alone
left it at 24,086. So:

- **Every host's tree is unchanged.** The kernel has its `Text` node, the
  runner its bindings; native hosts draw as before. The web keeps the element,
  so the runtime writes its text where it did, region anchors around it stay,
  and the agent's tree (built from elements on the JS target, from the
  kernel on the wasm host) has the node.
- **Styling:** the text has no rows of its own; it inherits from the parent as
  it did.
- **Hit testing:** the text has no handler; a press lands on the parent, which
  is where the text's press went before.
- **Accessibility:** the parent's accessible name is its text, as before;
  a `span` with `display: contents` is generic.
- **The agent's boxes:** an element with no box reports a zero rectangle, so
  the web hosts report a folded text's box as the anonymous block's
  (`viewBox`): its line boxes along the main axis, the parent's content box
  across it where the parent stretches its items. Both web hosts use the one
  function, so their layout compares as before.

## 4. Who decides

- **The live wasm host:** from the kernel tree at create and update, and again
  for a box's text children whenever its children change (`Host::refold`): a
  sibling that arrives takes the fold back. A button's fold reads its
  parent's rows, so a box's button children and their texts are refolded
  with it.
- **The document writer:** each child as it writes it, from its parent's facts.
  The host's first batch takes the projection's CSS, so the two agree.
- **The JS target's build:** from the template tree, only for a text the
  template holds whole — no bound row or prop but its text, no handler, not a
  repeated row (an `each` row's copies would join one anonymous block), and
  under a button only where neither the button nor its parent has a bound
  style row. A
  region's arms are all the parent's children in the template, so a text with
  a sibling in any arm doesn't fold.
