## Summary

In phase 1b, the runtime loads when the page is idle, and adopts the server's DOM
when its canonical document matches (LLP 1048.000 D6).

Phase 2 adds two things:
- **When the runtime loads becomes a per-page choice:**
  - when idle;
  - when visible;
  - on first interaction, with that event replayed with its semantics;
  - never.
- **Navigation between rendered routes** reuses their answers when their
  identity matches.

## 1. Decisions (proposed)

D1–D3 and D6 moved to LLP 1048.000 in r3. The remaining numbers are kept so that
references stay stable.

**D4 — Activation policies.** The route's `activate=` (LLP 1048.003 D5), or the
default:

| Policy | When the runtime loads and adopts | Default for |
|---|---|---|
| `idle` | After `requestIdleCallback` following load, or at the first interaction | pages needing a runtime (phase 1b) |
| `visible` | When an element needing the runtime enters the viewport | — |
| `interaction` | On the first interaction with an element that has handlers; the event is replayed (D5) | — |
| `never` | Never: no glue, no wasm, no checkpoint | pages needing no runtime |

- **What needs the runtime:** a page needs it if it has handlers, timers,
  pending sources, or host capabilities that need runtime work (canvas surfaces,
  virtualized collections). The renderer marks elements needing it with
  `data-exact-on`.
- **Why no `eager`:** a preloaded runtime would compete with the page's images
  and fonts. It returns only if a measurement shows `idle` is too late for some
  page.
- **What comes first:** LLP 1047's byte budget lands before `interaction`.

**D5 — Semantic replay.** Before adoption, the boot glue records events as the
live glue would interpret them:
- `press` from `click` (phase 1b already replays presses);
- `change` from `input`, with IME composition respected;
- `submit` from Enter, with the composition check;
- focus and blur.

It records them against view ids. After adoption they replay in order through
`exact_dispatch`, exactly once. Text typed before adoption is already in the
live input and replays as one `change`. Selection is preserved.

- **Before the boot glue runs** (Charlie, 2026-09-23: "yes, allow the tiny
  capture script"): a small inline host script in the served document records
  press-type events — click, and Enter or Space on elements needing the
  runtime — against their elements from first parse, and the boot glue takes
  them over. It is host code that records taps and holds no app logic; the
  startup check allows exactly this snippet in served pages, pinned by hash and
  byte-counted, and the server's CSP admits it by hash (LLP 1048.000 D6).

- **On a mismatch,** targets remap by instance path. An event whose target no
  longer exists is dropped and journaled.
- **If activation fails** (the wasm fails to load, or boot is refused), the
  document stays usable as HTML: links still work, and the failure is reported.
- **Controls stay enabled.** The document never marks controls disabled while
  activation is pending: screen readers would announce them as disabled, and
  replay covers them.

**D7 — Navigation data.**
- **Reuse.** When the router navigates in-app, a published answer is reused only
  if its source, arguments, logic identity, freshness and principal all match.
  Interview asks for arrays of parameters from its retained navigation stack
  (`app.contract` ~208), so a direct visit and an in-app visit can differ in
  arguments. A miss asks the source.
- **Build-stage answers** come from the destination's published checkpoint.
- **Request-stage answers** come from the server's data endpoint,
  `GET <location>?__exact=data`.
  - It has its own URL and content type, and is never negotiated on the HTML URL
    (no `Vary: Accept`).
  - An anonymous answer is cached like its page. A personal one is
    `private, no-store` (LLP 1048.002).
- **Prefetch** fires on hover over a same-origin link, and at idle for visible
  links. It is bounded in count and bytes.

**D8 — Static-only sites.** `never` pages may emit Speculation Rules
(`prerender`, `moderate`) and opt in to cross-document view transitions.

**D9 — Native hosts are unchanged.** They boot from the baked plan with no
network wait.

## 2. Verification (when specified)

- **Replay.** A click, typed text (including IME composition), a checkbox and a
  submit before adoption produce the same state as the same events after it,
  under `interaction` and `idle`. Nothing replays twice.
- **Cost.** Time to interactive and bytes before interaction, for `idle`,
  `interaction` and `never`. `never` pages transfer no wasm, glue or checkpoint.
- **Navigation.** Matching answers are reused, mismatched ones are asked again,
  and prefetch stays within its bounds.

Equality before and after adoption, and host-state restoration, are verified in
phase 1b (LLP 1048.000 §4).

## 3. To settle before this becomes a spec

1. The replay protocol's full event set: IME, submit, focus, and what a `form`
   does before the runtime starts. A `form` does nothing before the runtime
   starts. Whether a GET form may navigate without it is decided against
   DEFERRED's refusal of progressive forms, when someone proposes one.
2. The freshness and principal fields of an answer's identity for navigation
   reuse, shared with LLP 1048.002.
3. Prefetch bounds.
