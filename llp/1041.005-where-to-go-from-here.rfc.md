**Systems:** `game/` and the core seams it uses; the bench and the twins; the scoring process
**Author:** Claude (Fable 5.1) for Charlie Cheever

**Related:** LLP 1041 (the analysis), 1041.000 (Lanterns — the consumer this plan serves), 1041.003 (as built), 1041.004 (what the first experiments taught — the evidence for every choice here); `game/diaries/001-scores.md`; `rules/NOT-DOING.md`

## Summary

Keep the architecture; stop adding features for one pass; make the engine smaller
and structurally honest in the five places the whole-engine review named; then
rebuild the comparison game from scratch with a fresh builder and score it again.
**The re-score is the gate**: above the twins' 29 of 30, continue to assets,
skeletons and Lanterns; below it, this document is reopened with a number in hand
rather than a feeling. The alternatives (embed an engine; game logic in
TypeScript) are recorded with why they lose today and what would make one of them
worth an experiment.

## 1. The judgement this rests on

Three independent reviewers of three different scopes said the same thing: the
model is right (a world as a guest in a canvas; one `Data`; fixed ticks with GPU
interpolation; a tick that calls functions; the app's eight operations), and the
adapters around it are where the cost is. The score of 19 was earned by the
adapters — the HUD bus, the loop, the crates per game, the missing save form — and
each of those has since been replaced. Nothing found so far argues for a restart;
a restart would reproduce roughly four fifths of the code and lose the reviewed
seams, the cross-host pins and the instruments.

## 3. The gate

After C1–C5: **delete `game/games/beacons`, and have a fresh builder make it again
from the same brief**, with the same rules as the twins had; the same two judges
score all three diaries blind. Also run the feel probe in a quiet window with the
display unlocked, so Feel is a verified row for all three engines.

- **≥ 29 of 30, Feel verified better than both twins:** proceed to §4.
- **Below 29:** stop, and reopen this document with the judges' three changes and
  the alternatives in §5 weighed against them. No new features until then.

## 4. After the gate (LLP 1041.000's slices, with what each needs)

1. **Assets (S2):** the `assets` seam on `Surface`; a baker (glTF, textures, mips)
   that never ships; `Mesh::asset` drawing every mesh node through C5's instance
   record; textured PBR; the loading rule ("a world does not tick until its declared
   assets arrived"). Non-game reading: LLP 1030 D8's bytes to any module.
2. **Skeletons (S3):** clips, a 1-D blend space, a state machine as data, IK, events
   as journal lines; skinning on the GPU interpolated per **local** pose before
   hierarchy composition; a pinned pose as the test.
3. **Audio integration:** the `Player` inside `WorldSurface` after `Player::sync`
   is slimmed; agent sessions never execute playback; the Apple callback fix.
4. **Particles as emitters** (saved seed and parameters, their own instance
   buffer), never as entities unless gameplay needs them.
5. **Sprites/2D:** an orthographic projection choice; opaque/cutout/blended
   materials with an ordered translucent path; signed scale resolved.
6. **In-world UI:** the existing placement seam for a Contract child on an entity
   plane, with a hidden outcome for clipped placements; the browser half.
7. **Linux headless (D7)** by separating surface ownership from a presentation
   target; **iOS driven** once the machine's Xcode license is accepted.
8. **Lanterns** (S4–S6): the lantern springs and point lights, dusk to night,
   the signpost, the level as delivered data, a physical phone.

Each slice ends driven by a script in the eight operations, and each is followed
by the same builder/two-reviewer round. Every third slice gets the whole-engine
question again.

## 5. Alternatives, recorded

- **Embed an existing engine as the world executor.** Bevy (15+ MB of wasm, over a
  thousand crates, no cross-platform determinism, a scheduler philosophy that
  conflicts with "a tick is a function"), Godot (a 40 MB web export; determinism and
  agent inspection would be bolted on), three.js (web only). Each fails at least two
  of small, deterministic, every host, agent-native. Not pursued.
- **Game logic in TypeScript on Hermes**, the way exact2 runs data sources. The best
  authoring loop and the most exact2-shaped option; loses on throughput (hundreds of
  thousands of entities, a 60 Hz physics world). **Worth one measured experiment**
  after the gate: the same `Data`/agent/publication contract with a TS `tick` for a
  Beacons-sized game, scored by the same judges. If it wins on Small and Direct
  without losing Repeatable, small games could be written that way and large ones
  in Rust, on one engine.
- **Standard crates instead of the hand-rolled ECS and `Data`** (hecs + serde +
  bincode). Would have saved days; loses canonical iteration order, page uploads
  and by-name dev-carry — the three properties determinism and the dev loop rest
  on. Not pursued.

## 7. What is not planned

Networking; an editor GUI (the agent's reads and the dev loop are the editor); a
scheduler or plugin system; a second physics engine; any feature whose only
consumer is a benchmark.
