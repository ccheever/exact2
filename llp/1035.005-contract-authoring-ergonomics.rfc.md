## Summary

Contract stays easy to navigate when an app stops fitting on one screen:
find a component's definition and its call sites, follow an action from a
caller's binding to the callee's parameter, change a style, and land on
the declaration behind a painted node — without scanning 800-character
lines by eye. More syntax is the last remedy, not the first.

The compiler today has four subcommands (`build`, `test`, `compat`,
`types`), point diagnostics (`file:line:col [id] message`, no end
column), an AST with spans but **no comments** (the lexer drops them at
`lexer.rs:72,132`), **no printer**, and a plan with no source information
of any kind. Messages is 726 lines: 189 lines over 120 characters, 88 over
200, two bubble declarations of 829 and 841 characters, a root component
with 32 states, 43 actions and 11 derives, one child component with 16
props (7 values, 9 actions) bound at one 522-character call site, 113
`light-dark()` literals over 21 distinct pairs, and **zero** named styles,
`fn`s or `class=` uses — the ergonomics LLP 1017 landed are unused there.
And an `action`-typed prop has unknown arity, so a caller's binding is
never checked against the callee's use (`analyze/src/lib.rs:296-321`).

Decisions, in the order §1 gives them: **a formatter on the existing
parser, with trivia kept and one continuation rule** (D1), **compiler-
owned symbols and end-spanned diagnostics that name both sides of an
action prop** (D2), **the node-to-declaration map shared with 1035.002**
(D3), **refactoring at named responsibilities with the tools that exist**
(D4), and **artwork out of the source through 1035.004 and the asset row**
(D5).

## 1. Priority within this slice

1. Make existing source readable: formatting and navigation.
2. Connect compiler and runtime diagnostics to declarations.
3. Remove repetition with the constructs that exist (`style`, `fn`,
   `provide`/`inject`, `slot`) and 1035.004's roles.
4. Propose new syntax only for friction that remains, demonstrated in
   source.

## 2. Decisions

### D1 — `contract fmt`: the existing parser, trivia kept, one continuation rule

**Trivia.** The lexer keeps `//` comments and blank-line groups as tokens;
the parser attaches a leading comment group to the declaration or node
that follows it and a trailing comment to the node on its line
(`Node`/`Decl` gain `comments: Comments`). Nothing else in the AST
changes; the four passes ignore trivia. Messages has two comments; the
corpus has more; none may be lost.

**The printer** lives in `contract-syntax` (`fmt.rs`) and emits canonical
form: two-space indentation as the grammar already requires; one space
between attributes; attribute order as written (never reordered — order
is meaning for duplicate rows, LLP 1017.000 P6); string literals as
written; expressions re-spaced by precedence. A declaration that would
exceed **100 columns** breaks to one attribute per continuation line; a
component use whose arguments exceed it breaks to one argument per line
inside its parentheses (the lexer already ignores newlines inside
brackets, `lexer.rs:5-6,76,211-227` — legal today, untested, unused).

**The continuation rule** (the one grammar change): *an element's
attribute list may continue on the following lines, each indented deeper
than the element's line and beginning with `name=`; a child begins with a
tag or component name and never with `name=`.* One-token lookahead
(`ident` then `=`) decides; a tag name is never followed by `=`, so it is
unambiguous. `syntax-continuation-indent` refuses a continuation at the
element's own depth. Written into LLP 1006 §2 at acceptance.

```
button press=select(message.id, message.body, message.outgoing)
  retainFocus=true
  swiperight=openReplies(message.replyRoot)
  touch-action="pan-right pan-y"
  id=`bubble-${message.id}` testId=`bubble-${message.id}`
  max-width="75%" min-width=48 …
  text message.body font-size=17 …        ← a child: begins with a tag
```

**Proof:** `parse(fmt(src))` equals `parse(src)` up to spans and trivia
placement; `fmt(fmt(src)) == fmt(src)`; `compile(src).encode() ==
compile(fmt(src)).encode()` byte for byte (the corpus's own idiom,
`corpus.rs:204-213`) over the 17 corpus files, Messages, Caltrain and
Fieldnotes. `contract fmt --check` exits non-zero on a difference and is
**not** one of the five checks; nothing rewrites an author's file
unasked (the dev loop does not format on save).

`--check` emits separate unified hunks with three context lines, preserving
unchanged lines between nearby edits. Three-line anchors are indexed by their
position, so repeated lines do not require a quadratic edit table; the diff is
valid but does not promise the smallest possible edit sequence. Final-newline
changes retain the standard marker. Formatting and read-only behavior are unchanged.
In a formatted Messages source with two distant spacing edits, the check output
shrinks from 3,143 lines / 161,735 bytes to 20 lines / 842 bytes. Applying that
patch reproduces `fmt --stdout` exactly; Caltrain and Fieldnotes pass the same
two-edit check, alongside 500 generated patch applications.

The formatter shares each top-level token vector with the parser, removing two
redundant whole-file tokenization passes. It finds syntax spans in the existing
per-line token lists rather than building another whole-file index; the previous
ordinary token can still be on another line. Token-spelling comparison and parsing
of the formatted result both run. Across 53 inputs, output and refusals are
identical; all 17 application plans, maps and symbol graphs also match.
Removing the duplicate index reduces Messages formatting from 50,935 to 49,357
allocation/reallocation requests and from 7,098,610 to 6,635,170 requested bytes.
Against the token-sharing implementation, paired debug CLI medians on this Mac
were 31.0 → 25.5 ms for Messages, 12.3 → 11.1 ms for Caltrain, 11.8 → 10.3 ms
for Fieldnotes, and 105.0 → 64.8 ms for a 5,000-function fixture.

### D2 — `contract symbols`, end-spanned diagnostics, and both sides of an action prop

`Span` gains `end_col` (`{line, col, end_col}`); every identifier the
parser reads records it. `contract symbols <file>` prints JSON:

```
{ "definitions": [ { "kind": "component|prop|inject|state|derive|action|resource|source|style|fn|shape|font|id",
                     "name", "file", "line", "col", "end_col", "component"?, "writes"? } … ],
  "references":  [ { "kind", "name", "file", "line", "col", "end_col", "to": <definition index> } … ] }
```

An `action` definition carries `writes`, the states and mutations its body
assigns or sends through every branch, in slot order (router state, states,
then mutations, each as declared): inferred, since an action declares none (LLP
1035.005.000 D1, 2026-10-02). It is the review aid the deleted clause was;
references carry no `writes`.

References include `id` uses — `navigationBack="back"`, `contextTarget`,
`popovertarget`, `focus("id")` — so a Back control is findable from its
policy. `contract build --json` prints diagnostics as `{id, message,
file, line, col, end_col, related: [{file, line, col, end_col, note}]}`
and bake-time refusals (`bake-*`, today `id` and `message` only,
`lib.rs:40-45`) gain the offending node's span through D3's map.

**The arity gap closes.** An `action` prop's arity is inferred from the
component's own invocations of it (`cancelNewMessage()` in a handler —
zero; `selectRecipient(id)` — one string) and checked at every use site's
binding; a mismatch is `analyze-action-arity` with two `related` spans:
the prop's declaration and the caller's binding. This is LLP 1017 P1's
rule ("no quiet failures") reaching the one place it does not yet.

Navigation JSON is serialized directly from the resolved graph, without a
second tree of JSON objects and copied names and filenames. Definition and
reference ordering, optional fields and original source ranges are unchanged.

Named-declaration lookups borrow kind/component/owner/name keys. Locals and
parameters resolve through the lexical stack, IDs through their multi-target
index, and `testId`/`provide` retain declarations without unused lookup entries.
All definitions and reference edges remain in the output. In warmed Messages
queries, this removes 7,677 allocation/reallocation requests (about 6.9%) and
117,228 requested bytes. Paired debug CLI medians were 29.3 → 28.5 ms for the
full graph and 23.2 → 21.4 ms for `--name selectRecipient`; the 5,000-function
fixture was 87.7 → 80.1 ms. These measurements cover query work on this Mac.
All 17 full application graphs (including external Weird Castle) and 126
focused queries are byte-identical to the previous index implementation.

`contract symbols <file> --name <exact-name>` selects all declarations with that
case-sensitive name and their incoming references. Repeated names in different
scopes remain distinct; `to` indexes the returned definitions. No match returns
empty arrays. Import/type validation still covers the whole source graph, and
unfiltered output is unchanged. The serializer omits unselected records directly
instead of constructing and filtering a full JSON response.
On the measured Messages checkout, `--name selectRecipient` returns two
definitions and three references in 1,071 bytes versus the full 505,261 bytes.
The debug CLI median is 19.1 ms for that query versus 25.7 ms for its full graph;
this reduces navigation response work, not application rendering time.

Declared font families participate in the same graph: their quoted names retain
exact source ranges, and literal `font-family` uses on elements or named styles
resolve to the declaration, including fonts brought in by component/style
imports. Generic families and unrelated string literals produce no font edge.
A font-only source is queryable without loading font assets; asset validation
remains part of building the executable plan.
Typetour exposes both families and all 27 literal uses, and Reflow exposes its
bundled family and use. All 16 application plans and their node maps remain
byte-identical; existing non-font definitions and reference targets are unchanged.

Unknown attributes now suggest a spelling when exactly one accepted attribute
is one insertion, deletion, replacement or adjacent transposition away. Candidates
are checked through the existing lowering table, not a second vocabulary. Named
styles consider only style attributes; explicit old-to-CSS spelling hints retain
priority. Only ASCII names of 3–64 bytes are searched; ambiguous or unrelated
spellings receive no hint. The diagnostic id and original source range remain unchanged,
and the invalid spelling is still refused in both JSON and human output. This
reduces a typo-repair search without adding aliases or changing valid plan bytes.

Unknown record-field errors list the shape's declared field names in declaration
order, using the same checked shape map as member resolution. Empty shapes are
identified explicitly. Human and JSON diagnostics retain the stable id and the
original member-name range, including through imports. The message provides
valid field names; it does not imply they all have the type the surrounding
expression needs.

Missing component-prop refusals list every omitted prop for that use, in the
component's declaration order, through one helper shared by expansion and the
type checker. Already supplied props and lexical `inject` names are excluded.
The existing `syntax-missing-prop` / `type-missing-prop` IDs and original call-site
ranges remain unchanged; single-missing-prop messages keep their previous text.
This is one call's missing interface, not aggregation of every error in the file.
The real Messages `ContactNameField()` now exposes all five missing names together;
its repaired plan and all 18 app/fixture plans are byte-identical.

Unknown enum literals now list the row's accepted quoted spellings in the
`lower-attr-value` message. `StyleId::enum_names` is generated from the same kernel
schema as enum parsing, so the compiler maintains no second value vocabulary.
Human and JSON output keep the diagnostic id and original source range; existing
narrower authoring refusals such as `wrap-flow` keep their own message.
Enum `"auto"` literals now stay text during validation, matching the runtime;
the previous dimension conversion wrongly refused `align-self`, overscroll,
scrollbar-width and touch-action literals that the kernel already accepts.
Dimension `"auto"` handling and its refusals remain unchanged. Tests repair node
and named-style errors using the listed choices, boot each result and check the
actual kernel row. Existing accepted repairs and all 17 application plans,
including external Weird Castle, produce byte-identical plans.

An editor adapter is not a prerequisite: the JSON is enough for a
`compile_commands`-style integration, and whether an LSP is justified is
decided after these queries exist (LLP 1006 §8 keeps the LSP out).

Windows qualification, 2026-10-04: the diagnostic's optional resolved path is
immutable and stored as `Option<Box<Path>>`. This removes unused path-buffer
capacity from each by-value `CompileError`, reducing its 64-bit size from 128
to 120 bytes without suppressing the large-result lint. Public Rust callers
constructing this field convert owned `PathBuf` values with `into_boxed_path`;
borrowed access remains `as_deref()`. JSON, display, original ranges and related
locations retain their existing meaning. Native CLI fixtures use legal Windows
Unicode/space filenames and escaped source-string paths; Unix keeps the quoted
filename case. Existing diagnostic and source-map suites must pass on Windows,
with strict all-target clippy and Unix compilation checks as compatibility evidence.
The Windows CLI executes on an explicitly sized 8 MiB worker stack because its
default 1 MiB main stack overflows on a valid 256-site debug compilation. This
is an entrypoint budget, not a change to the 256-site language limit: the existing
CLI regression must accept 256 and diagnose 400/800 as `syntax-view-depth`.
The worker returns the same exit code and resumes an unwinding panic on main.
Qualification: the Windows CLI integration suite passes 607 tests with its two
existing opt-in cases ignored; the 256/400/800 regression passes. Strict clippy
passes for every Contract target on Windows and cross-compiles on Linux; caps
passes. The error-size regression enforces less than 128 bytes.

### D3 — The node-to-declaration map, shared with 1035.002

`contract build --map` writes `<plan>.map.json` beside the plan; the dev
loop writes it on every restart. Keyed by the plan's digest; per plan node
`{file, line, col, end_col, component, chain: [{component, file, line,
col} …], bindings: [{row, origin: "own" | "class:<Name>"}]}` — the
declaration, the instantiation sites the inliner expanded (the `hot__3`
renames resolved back), and for each bound row whether it came from the
node or from a named style, so 1035.002's `authored` can say which. Per
slot, action and derive `{file, line, col}` too, so a journal line
(`press view 12 (openStations)`) can be rendered with its source. The
compiler supplies all of it; nothing is reverse-engineered from runtime
text, `testId`s or generated-code shape. Not in the plan, not on the boot
path, refused when stale (the digest). `rules/DEFERRED.md` §Agent API is
amended for this bounded map before slice 3 (LLP 1035 §5 names the take);
a dataflow or provenance explorer stays out.

**Compiler implementation (2026-09-20):** `build --map -o <plan>` emits the
separate JSON map; the mapped library calls preserve the exact source snapshot.
`contract --help` and `contract build --help` expose the map option and its
required output path. Every subcommand accepts `--help` and `-h` alone, prints its
usage to stdout, and returns exit status zero without reading or writing source files.
Malformed `test` and `compat` invocations return usage and exit status two before
reading their inputs; extra operands, unknown options and repeated compatibility
options are refused.
The mapped checker records component instances and lifted declaration owners;
slot fills retain their caller's origin. Lowering records the winning style
origin with each deduplicated binding. Each location resolves its own
`Span.source_id`, including imported calls and declarations. The map's digest
names final encoded bytes, including after a bake. Measured layout refusals
carry a plan-node site; `SourceMap::bake_error` resolves its declaration and
call chain into the existing structured diagnostic. Non-node bake failures do
not invent a location. The ordinary compiler skips provenance collection; map JSON is serialized directly
without an intermediate object tree. Plan bytes are unchanged.

**Development producers (2026-09-20):** resident Contract, TypeScript and portable
Rust builds emit maps keyed by the final baked bytes. Captured TypeScript trees
relocate source filenames to their original app-relative paths; compile and
mapped bake refusals report those original files. The dev envelope's separate
`dev.sourceMap` card retains the map beside its immutable generation. It is
excluded from assets, module receipts, static builds and production publication.
A missing or mismatched map does not prevent a valid app reload.

**Runtime inspection (2026-09-20):** targeted `layout` can request `plan:true`.
The runner returns `planDigest` beside that same node's site, from a SHA-256 of
its immutable plan's canonical encoding. A per-runner lazy cache avoids hashing
at boot or on ordinary reads; the first request takes O(plan bytes) temporary
work, later requests and added wire size are constant. Accepted replacement
constructs a fresh cache; rejected candidates retain the old one. No plan bytes
or source maps enter the geometry reply. The driver discovers maps beside a
named plan or through the dev envelope, validates HTTP cards, and joins only
against the inner node's digest. It uses that node's own testId, refusing a
selector changed during inspection instead of relabeling from a later tree.
Four recent map digests are retained; absence, mismatch or malformed location
leaves geometry inspectable and source unavailable. Declaration and component
caller locations and winning own/dynamic style origins appear in JSON and the
transcript. Inherited rows keep their ancestor attribution. Matching bytes prove
a *compatible* source map, not an original authored revision: comments and
formatting can change the map without changing the plan. A fresh driver cannot
recover an older map merely from a latest manifest after a refused reload.
Local discovery reads and hashes the file on each targeted inspection, but
reuses its decoded map when the bytes are unchanged. File size and timestamps
are not freshness evidence: a same-size formatting edit still updates locations
even when its timestamp is restored. Missing or malformed files retain the
recent compatible maps, as before.

### D4 — Refactoring at named responsibilities, with what exists

Candidates in Messages, not a mandate: conversation header, recipient row,
composer, message bubble (twice today: `:459` and `:521` are one
declaration duplicated across the main and focused threads), reaction
controls, the typing indicator (also twice). Each keeps its actions and
state ownership explicit — a prop per value, a prop per action — and the
multi-line use form (D1) makes a 16-argument call legible. Before any new
construct: a `style` per surface colour role removes most of the 113
`light-dark()` literals (21 pairs → 21 `style` declarations, `class=`
where used); `provide accent = …` reaches every component through
`inject` (P4a) where a pair is truly global; `fn` for the three-line
conditionals repeated in derives. No opaque prop bag, no ambient
context, no implicit action propagation: the explicit interface stays and
D2 makes it navigable. No style-precedence system to abbreviate
declarations; a later reuse construct keeps CSS names and shows the
winning declaration through D3's `origin`.

**First Messages refactoring (2026-09-20):** shared data shapes, the new-message
sheet, message presentation parts, and contact fields now live in named Contract
files. Both thread views call one typing-indicator declaration; their caller
still owns placement and the accessible label. Extracted files use `contract
fmt`. Compiler folding of literal string templates removes the ID concatenation
introduced by the shared prefix prop. The complete compiled Messages plan is
byte-identical to the pre-refactoring plan (128,409 bytes), including all actions,
bindings, nodes and regions. The main state owner remains dense; shared surface
styles and further responsibility extraction remain work to do.

**Shared colour roles (2026-09-20):** six styles in `palette.contract` supply
53 static colour declarations on 52 nodes across the main screen, new-message sheet,
contact details and new-contact form. Each consumer imports the roles it uses;
`PrimaryText`, `AccentText`, `PrimaryIcon`, `PrimaryFill`, `PageSurface` and
`PageCanvas` retain CSS property names and their existing `light-dark()` pairs.
Source-map binding origins now name the shared role. State, action bindings and
conditional colour expressions retain their existing owners. Normalized plan
comparison resolves string/code offsets and compares each node's unique bindings;
all expressions and other plan tables are identical. Baseline and candidate
browser drives cover six scenes in both light and dark mode, including
mute/block, message creation, and contact draft keep/discard/save. All twelve
computed colour/geometry snapshots match, and live source maps identify the
shared roles for page, input and icon colours.

**Contact details (2026-09-20):** the details screen is a formatted
`ContactDetails` component with explicit route, conversation, artwork and action
props. The caller binds the mute action to its current thread. Nine grouped
surfaces share `ContactGroupSurface`; no state or durable mutation moved into
the component. Extraction alone keeps the 128,409-byte plan identical. Adding
the named style changes string-pool order and moves one unique color binding
on each of nine nodes; decoded comparison preserves every expression and all
other plan tables after those order/offset differences are normalized. A real
browser drive opens Maya's details, toggles and restores mute, blocks/unblocks,
and closes back to the conversation. Main source is 910 lines; further
responsibility extraction remains before formatting that entire file.

**New-contact form (2026-09-20):** `NewContactSheet` owns the formatted
presentation and seven surfaces share `ContactFormSurface`. Its caller still
owns all draft values, row visibility, navigation and save/discard actions;
every value and action crosses an explicit prop. Extraction alone is
byte-identical; the shared style preserves all decoded plan tables and
expressions after normalizing unique binding order and code/string offsets.
Baseline and candidate browser drives edit each field, remove/re-add phone and
email rows, keep/discard a draft, reopen and save a contact. Both finish at the
same saved contact; the filled and saved screenshots are byte-identical. Main
source is 866 lines; the form is 368 formatted lines.

**Shared bubbles (2026-09-20):** main and focused reply transcripts now call
one formatted `MessageBubble` for the reaction side slots, balloon, tail, swipe
indicator and selectable body. Twelve explicit props carry message data, IDs,
visibility, artwork and already-bound actions. No wrapper or state owner is
added. Both source-map sites resolve padding to the same declaration while
retaining their distinct caller locations. The complete 128,409-byte compiled
plan is identical. Baseline and candidate browser drives cover double-click
reactions, badge reopening, context-menu text selection, sending a reply,
reply reactions and message selection; all five captured PNGs are identical.
A held rightward swipe fails on both versions, including a fresh baseline
session. Its pointer-capture trace is a separate queued host issue, not a
claimed gesture verification for this extraction.

### D5 — Artwork leaves the source through 1035.004 and the asset row

Standard roles become `image "symbol:…"` (six now). The remaining
application-specific shapes — bubble tails, the reply arrow, the person
silhouette, the laugh badge — stay as `clip-path` derives until a path
asset has a home: an SVG-path asset row (LLP 1030 stage 1's asset row
carries files; a `path` asset is a text file the compiler validates with
`clip.rs` and the hosts consume as they consume the inline value). That
is a small explicit proposal when a third app needs it; growing inline
path strings is refused meanwhile.

## 3. Validation on three authoring tasks

Before and after slices 1–3, on the current Messages source, recording the
navigation steps and the ambiguities that remain:

1. **Change the incoming-bubble padding** — find both bubble declarations
   (`:459`, `:521`), change `padding-left` on the incoming branch only,
   see it on the phone and the web.
2. **Follow recipient selection** — from the sheet's `selectRecipient`
   binding to the root's action, its `send` to the data source, and the
   `recipients` resource that changes.
3. **Locate a heading from a dark-mode screenshot** — from pixels to
   `layout <node>` (1035.002) to `app.contract:352`'s declaration and its
   component chain.

A second app (Fieldnotes or Caltrain) repeats the three so the result is
not tuned to Messages' file layout. Success: fewer manual searches, less
incidental vector and wiring detail on screen, and a legible data/action
boundary; a shorter file alone is not success if responsibility or
precedence became harder to find. The edited apps are verified with the
existing driver.

## 4. Landing order

1. **Slice 1 (this implementer):** D1 — trivia in the lexer, the
   continuation rule in the parser with its refusal, the printer,
   `contract fmt [--check]`, the three proofs over the corpus and the
   three apps; corpus files reformatted only if byte-identical plans
   result. Then the multi-line form used at Messages' one call site.
2. **Slice 2:** D2 — `end_col`, `contract symbols`, `build --json`, the
   action-prop arity check with its corpus reject fixture.
3. **Slice 3 (after the amendment):** D3 — the map, with 1035.002 slice 3
   as its consumer and the bake-time spans as its first payoff.
4. **Slice 4 (Codex):** D4's Messages refactor and D5's replacements
   through 1035.004, measured by §3.

## 5. What this deliberately does not add

A new authoring model or a React tier (`rules/DEFERRED.md`); arbitrary
expressions above the data seam; generics; implicit action propagation;
a visual editor; an LSP before the queries exist; a style-precedence
system; source text in the plan; a sixth check (`fmt --check` is a
command, not a gate); format-on-save.

## 6. Open questions

- Should the printer break at 100 columns or at the first attribute that
  is an expression? Leaning: 100, the rule a reader can predict.
- A `test` block's steps (P7) are source too; the printer formats them
  with the same rule.
- Should `contract symbols` also emit the *used* CSS row for each style
  attribute (the kernel row name), so an editor can link `padding-left`
  to LLP 1001's table? Cheap, and it answers "is this name real" without
  compiling.

**Decided (Charlie, 2026-09-10, on the recommendations):** D1's continuation
rule is admitted, `name=` as the discriminator, 100 columns the break; D2's
action-prop arity check is a refusal under P1; D5's `path` asset waits for a
third app; D3's map is unblocked by the DEFERRED amendment of the same
date. Slices 1–3 were implemented on the authoring branches from this date;
that statement did not mean they were integrated into `origin/main`.

**Recovery (2026-09-20):** D1 is selectively recovered against the current
compiler. Its printer preserves source tokens and intervening trivia rather
than reconstructing literals/comments from the AST: the lexer exposes exact
token end columns, and the parser identifies safe wrapping boundaries. Existing
physical breaks remain; strings, numeric spellings, template interiors and
opaque `contract` bodies stay verbatim. This fixes the older printer's comment,
blank-group, overflowing-number and opaque-body losses. The current routes,
viewport, collection, pan and button-label behavior is retained. D2 and D3 are
still separate recovery work; no unrelated game-branch history is merged.

**Source-location foundation (2026-09-20):** `Span` now owns the lexer's
exclusive end byte column and a compilation-local file identity. Imports keep
that identity through parsing, expansion and all compiler passes; returned
diagnostics own the resolved filename, including nested template expressions
with their original byte columns. The loader caches unmerged source ASTs and
keeps cycle detection separate from cache membership. The formatter consumes
the same token ranges. Existing duplicate-import line/column equivalence and
path containment remain unchanged. This is part of D2/D3 recovery, not a claim
that symbols, structured diagnostics, action-prop arity or maps have landed.

**Navigation recovery (2026-09-20):** `contract symbols <file>` now emits
definitions and references from the build's contained import loader and type
checker. The parser retains otherwise-discarded identifier ranges in its
`NameSpans` index, including nested templates; no source text is rescanned to
guess names. The query includes local bindings, parameters, typed shape fields,
providers, tasks, routes and literal `testId`s beside D2's listed kinds.
`component` and `owner` distinguish declaration scopes. Shared shape/function/
style files need no app root. Primitive types and router operations follow the
type checker's namespaces; built-in `path()` links route names. Repeated literal
IDs produce one reference edge per matching declaration. Dynamic IDs have no
static target; provider-to-injection chains remain the contextual map's work.
The query is read-only, reports syntax/import/type errors with original file
locations, and produces no plan or bake. Structured diagnostics, action-prop
related locations and D3 maps remain separate work.

**Structured diagnostics (2026-09-20):** `contract build --json` emits one
JSON array on stdout, empty on success. Each refusal has D2's fields and the
original source's byte range; import, syntax, type, analysis, lowering, manifest,
argument and output-write failures use this protocol. The compiler still returns
the first refusal, and `related` remains empty until the action-prop diagnostic
work supplies both sides. Plan bytes and bake behavior are unchanged. D3's
node-to-source map and bake-time source locations remain unfinished.

**Action-interface diagnostics (2026-09-20):** D2 now infers compatible action
parameter counts from handlers, propagates them through forwarded/partially
bound props and lexical providers, and reports `analyze-action-arity` with the
invocation, interface declaration and binding. Provider requirements cross
components that do not themselves inject the name; inner providers shadow outer
ones, and slot fills retain the caller's context. `navigate` keeps its allowed
zero-or-one parameter range; analysis and lowering share event payload arity.
Unused action parameters remain unconstrained, while contradictory uses in an
unused component are refused. Related locations resolve their own source IDs,
including across imports, and appear in both JSON and human diagnostics.
Concrete prop/inject arity mismatches were already rejected during lowering;
this change adds interface consistency and useful related locations. D3's map
and bake-time source locations remain unfinished.
