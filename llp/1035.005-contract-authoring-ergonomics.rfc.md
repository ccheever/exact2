## Summary

Contract stays easy to navigate when an app stops fitting on one screen:
find a component's definition and its call sites, follow an action from a
caller's binding to the callee's parameter, change a style, and land on
the declaration behind a painted node — without scanning 800-character
lines by eye. More syntax is the last remedy, not the first.

The compiler today has four subcommands (`build`, `test`, `compat`,
`types`), point diagnostics (`file:line:col [id] message`, no end
column), an AST with spans but **no comments** (the lexer drops them at
`lexer.rs:72,132`), **no printer**, and a plan with no source information
of any kind. Messages is 726 lines: 189 lines over 120 characters, 88 over
200, two bubble declarations of 829 and 841 characters, a root component
with 32 states, 43 actions and 11 derives, one child component with 16
props (7 values, 9 actions) bound at one 522-character call site, 113
`light-dark()` literals over 21 distinct pairs, and **zero** named styles,
`fn`s or `class=` uses — the ergonomics LLP 1017 landed are unused there.
And an `action`-typed prop has unknown arity, so a caller's binding is
never checked against the callee's use (`analyze/src/lib.rs:296-321`).

Decisions, in the order §1 gives them: **a formatter on the existing
parser, with trivia kept and one continuation rule** (D1), **compiler-
owned symbols and end-spanned diagnostics that name both sides of an
action prop** (D2), **the node-to-declaration map shared with 1035.002**
(D3), **refactoring at named responsibilities with the tools that exist**
(D4), and **artwork out of the source through 1035.004 and the asset row**
(D5).

## 1. Priority within this slice

1. Make existing source readable: formatting and navigation.
2. Connect compiler and runtime diagnostics to declarations.
3. Remove repetition with the constructs that exist (`style`, `fn`,
   `provide`/`inject`, `slot`) and 1035.004's roles.
4. Propose new syntax only for friction that remains, demonstrated in
   source.

## 2. Decisions

### D1 — `contract fmt`: the existing parser, trivia kept, one continuation rule

**Trivia.** The lexer keeps `//` comments and blank-line groups as tokens;
the parser attaches a leading comment group to the declaration or node
that follows it and a trailing comment to the node on its line
(`Node`/`Decl` gain `comments: Comments`). Nothing else in the AST
changes; the four passes ignore trivia. Messages has two comments; the
corpus has more; none may be lost.

**The printer** lives in `contract-syntax` (`fmt.rs`) and emits canonical
form: two-space indentation as the grammar already requires; one space
between attributes; attribute order as written (never reordered — order
is meaning for duplicate rows, LLP 1017.000 P6); string literals as
written; expressions re-spaced by precedence. A declaration that would
exceed **100 columns** breaks to one attribute per continuation line; a
component use whose arguments exceed it breaks to one argument per line
inside its parentheses (the lexer already ignores newlines inside
brackets, `lexer.rs:5-6,76,211-227` — legal today, untested, unused).

**The continuation rule** (the one grammar change): *an element's
attribute list may continue on the following lines, each indented deeper
than the element's line and beginning with `name=`; a child begins with a
tag or component name and never with `name=`.* One-token lookahead
(`ident` then `=`) decides; a tag name is never followed by `=`, so it is
unambiguous. `syntax-continuation-indent` refuses a continuation at the
element's own depth. Written into LLP 1006 §2 at acceptance.

```
button press=select(message.id, message.body, message.outgoing)
  retainFocus=true
  swiperight=openReplies(message.replyRoot)
  touch-action="pan-right pan-y"
  id=`bubble-${message.id}` testId=`bubble-${message.id}`
  max-width="75%" min-width=48 …
  text message.body font-size=17 …        ← a child: begins with a tag
```

**Proof:** `parse(fmt(src))` equals `parse(src)` up to spans and trivia
placement; `fmt(fmt(src)) == fmt(src)`; `compile(src).encode() ==
compile(fmt(src)).encode()` byte for byte (the corpus's own idiom,
`corpus.rs:204-213`) over the 17 corpus files, Messages, Caltrain and
Fieldnotes. `contract fmt --check` exits non-zero on a difference and is
**not** one of the five checks; nothing rewrites an author's file
unasked (the dev loop does not format on save).

### D2 — `contract symbols`, end-spanned diagnostics, and both sides of an action prop

`Span` gains `end_col` (`{line, col, end_col}`); every identifier the
parser reads records it. `contract symbols <file>` prints JSON:

```
{ "definitions": [ { "kind": "component|prop|inject|state|derive|action|resource|source|style|fn|shape|id",
                     "name", "file", "line", "col", "end_col", "component"? } … ],
  "references":  [ { "kind", "name", "file", "line", "col", "end_col", "to": <definition index> } … ] }
```

References include `id` uses — `navigationBack="back"`, `contextTarget`,
`popovertarget`, `focus("id")` — so a Back control is findable from its
policy. `contract build --json` prints diagnostics as `{id, message,
file, line, col, end_col, related: [{file, line, col, end_col, note}]}`
and bake-time refusals (`bake-*`, today `id` and `message` only,
`lib.rs:40-45`) gain the offending node's span through D3's map.

**The arity gap closes.** An `action` prop's arity is inferred from the
component's own invocations of it (`cancelNewMessage()` in a handler —
zero; `selectRecipient(id)` — one string) and checked at every use site's
binding; a mismatch is `analyze-action-arity` with two `related` spans:
the prop's declaration and the caller's binding. This is LLP 1017 P1's
rule ("no quiet failures") reaching the one place it does not yet.

An editor adapter is not a prerequisite: the JSON is enough for a
`compile_commands`-style integration, and whether an LSP is justified is
decided after these queries exist (LLP 1006 §8 keeps the LSP out).

### D3 — The node-to-declaration map, shared with 1035.002

`contract build --map` writes `<plan>.map.json` beside the plan; the dev
loop writes it on every restart. Keyed by the plan's digest; per plan node
`{file, line, col, end_col, component, chain: [{component, file, line,
col} …], bindings: [{row, origin: "own" | "class:<Name>"}]}` — the
declaration, the instantiation sites the inliner expanded (the `hot__3`
renames resolved back), and for each bound row whether it came from the
node or from a named style, so 1035.002's `authored` can say which. Per
slot, action and derive `{file, line, col}` too, so a journal line
(`press view 12 (openStations)`) can be rendered with its source. The
compiler supplies all of it; nothing is reverse-engineered from runtime
text, `testId`s or generated-code shape. Not in the plan, not on the boot
path, refused when stale (the digest). `rules/NOT-DOING.md` §Agent API is
amended for this bounded map before slice 3 (LLP 1035 §5 names the take);
a dataflow or provenance explorer stays out.

### D4 — Refactoring at named responsibilities, with what exists

Candidates in Messages, not a mandate: conversation header, recipient row,
composer, message bubble (twice today: `:459` and `:521` are one
declaration duplicated across the main and focused threads), reaction
controls, the typing indicator (also twice). Each keeps its actions and
state ownership explicit — a prop per value, a prop per action — and the
multi-line use form (D1) makes a 16-argument call legible. Before any new
construct: a `style` per surface colour role removes most of the 113
`light-dark()` literals (21 pairs → 21 `style` declarations, `class=`
where used); `provide accent = …` reaches every component through
`inject` (P4a) where a pair is truly global; `fn` for the three-line
conditionals repeated in derives. No opaque prop bag, no ambient
context, no implicit action propagation: the explicit interface stays and
D2 makes it navigable. No style-precedence system to abbreviate
declarations; a later reuse construct keeps CSS names and shows the
winning declaration through D3's `origin`.

### D5 — Artwork leaves the source through 1035.004 and the asset row

Standard roles become `image "symbol:…"` (six now). The remaining
application-specific shapes — bubble tails, the reply arrow, the person
silhouette, the laugh badge — stay as `clip-path` derives until a path
asset has a home: an SVG-path asset row (LLP 1030 stage 1's asset row
carries files; a `path` asset is a text file the compiler validates with
`clip.rs` and the hosts consume as they consume the inline value). That
is a small explicit proposal when a third app needs it; growing inline
path strings is refused meanwhile.

## 3. Validation on three authoring tasks

Before and after slices 1–3, on the current Messages source, recording the
navigation steps and the ambiguities that remain:

1. **Change the incoming-bubble padding** — find both bubble declarations
   (`:459`, `:521`), change `padding-left` on the incoming branch only,
   see it on the phone and the web.
2. **Follow recipient selection** — from the sheet's `selectRecipient`
   binding to the root's action, its `send` to the data source, and the
   `recipients` resource that changes.
3. **Locate a heading from a dark-mode screenshot** — from pixels to
   `layout <node>` (1035.002) to `app.contract:352`'s declaration and its
   component chain.

A second app (Fieldnotes or Caltrain) repeats the three so the result is
not tuned to Messages' file layout. Success: fewer manual searches, less
incidental vector and wiring detail on screen, and a legible data/action
boundary; a shorter file alone is not success if responsibility or
precedence became harder to find. The edited apps are verified with the
existing driver.

## 4. Landing order

1. **Slice 1 (this implementer):** D1 — trivia in the lexer, the
   continuation rule in the parser with its refusal, the printer,
   `contract fmt [--check]`, the three proofs over the corpus and the
   three apps; corpus files reformatted only if byte-identical plans
   result. Then the multi-line form used at Messages' one call site.
2. **Slice 2:** D2 — `end_col`, `contract symbols`, `build --json`, the
   action-prop arity check with its corpus reject fixture.
3. **Slice 3 (after the amendment):** D3 — the map, with 1035.002 slice 3
   as its consumer and the bake-time spans as its first payoff.
4. **Slice 4 (Codex):** D4's Messages refactor and D5's replacements
   through 1035.004, measured by §3.

## 5. What this deliberately does not add

A new authoring model or a React tier (`rules/NOT-DOING.md`); arbitrary
expressions above the data seam; generics; implicit action propagation;
a visual editor; an LSP before the queries exist; a style-precedence
system; source text in the plan; a sixth check (`fmt --check` is a
command, not a gate); format-on-save.

## 6. Open questions

- Should the printer break at 100 columns or at the first attribute that
  is an expression? Leaning: 100, the rule a reader can predict.
- A `test` block's steps (P7) are source too; the printer formats them
  with the same rule.
- Should `contract symbols` also emit the *used* CSS row for each style
  attribute (the kernel row name), so an editor can link `padding-left`
  to LLP 1001's table? Cheap, and it answers "is this name real" without
  compiling.

## 7. Acceptance questions for Charlie

1. The continuation rule (D1) — accept as the one grammar change, with
   `name=` as the discriminator?
2. The action-prop arity check (D2) — accept as a refusal (a program that
   compiles today may stop compiling), consistent with P1?
3. The `path` asset (D5) — write it now for Messages' tails, or wait for
   a third app?

**Decided (Charlie, 2026-09-10, on the recommendations):** D1's continuation
rule is admitted, `name=` as the discriminator, 100 columns the break; D2's
action-prop arity check is a refusal under P1; D5's `path` asset waits for a
third app; D3's map is unblocked by the NOT-DOING amendment of the same
date. Slices 1–3 were implemented on the authoring branches from this date;
that statement did not mean they were integrated into `origin/main`.

**Recovery (2026-09-20):** D1 is selectively recovered against the current
compiler. Its printer preserves source tokens and intervening trivia rather
than reconstructing literals/comments from the AST: the lexer exposes exact
token end columns, and the parser identifies safe wrapping boundaries. Existing
physical breaks remain; strings, numeric spellings, template interiors and
opaque `contract` bodies stay verbatim. This fixes the older printer's comment,
blank-group, overflowing-number and opaque-body losses. The current routes,
viewport, collection, pan and button-label behavior is retained. D2 and D3 are
still separate recovery work; no unrelated game-branch history is merged.

**Source-location foundation (2026-09-20):** `Span` now owns the lexer's
exclusive end byte column and a compilation-local file identity. Imports keep
that identity through parsing, expansion and all compiler passes; returned
diagnostics own the resolved filename, including nested template expressions
with their original byte columns. The loader caches unmerged source ASTs and
keeps cycle detection separate from cache membership. The formatter consumes
the same token ranges. Existing duplicate-import line/column equivalence and
path containment remain unchanged. This is part of D2/D3 recovery, not a claim
that symbols, structured diagnostics, action-prop arity or maps have landed.
