## Summary

Finish 1035.000 D10's line-height repair as an independently shippable slice:
numbers are ratios, explicit pixel lengths remain lengths, and `normal` is
distinct from zero. Remove the unrelated clip-path fixture from its landing
dependency; clipping remains in 1035.000. This is a refinement of that proposal,
not a second owner of text inheritance. Implementation evidence and remaining limits are recorded below.

## 1. Reproduced, including the web half

A temporary Rust probe compiled and baked Contract against this checkout,
booted its runner and measured one `font-size=16` text node:

| Authored value | Current web declaration | Current reference measurer |
|---|---|---|
| `line-height=1.62` | `line-height:1.62px` | 1.62-point line |
| `line-height=0` | `line-height:0px` | 19.2-point natural line |
| `line-height="normal"` or `"24px"` | Compiler refuses: expected number | Not reached |

The schema row is `f32`, `TextStyle` and the Apple C measurement interface use
zero for natural height, and `host/web/src/css.rs` appends `px` to this numeric
row. Changing only a native measurer would preserve a compiler/web defect.

Plain Chrome 152 on the same day computed 25.92px for `font-size:16px;
line-height:1.62`, and an inheriting 20px child computed 32.4px. Explicit `0`
produced a zero-height line. These are separate browser and kernel observations,
not a claim of cross-engine glyph equality.

## 2. One typed row, resolved at the right point

Admit three forms using Contract's existing number/string/binding grammar:

| Authoring | Row value | Used native value |
|---|---|---|
| `line-height=1.62` | `Number(1.62)` | Multiply by the receiving element's computed font size |
| `line-height="26px"` | `Length(26)` | 26 logical points |
| `line-height="normal"` | `Normal` | The host font's natural metrics |

An absent own row inherits; explicit `normal` stops an ancestor's override.
Numbers inherit as numbers and fixed lengths as lengths. Zero is valid for a
number or length and never selects `normal`. Reject negative/nonfinite values
and unsupported units rather than guessing. These meanings follow
[CSS line-height](https://www.w3.org/TR/CSS22/visudet.html#propdef-line-height).
Percentages and font-relative length strings stay explicitly unsupported in
this slice; percentages cannot later be implemented as an alias for a ratio,
because they inherit a resolved length.

Change bit 72's codec in `kernel/tables/schema.json`; extend `kernel/build.rs`
to generate its default (`Normal`), row access, dynamic conversion, wire
encoding/decoding, patch and clear. Do not add a second style row for the unit.
The schema digest changes, so old plans/frames are refused by the existing
identity checks and native hosts are rebuilt. No old-number-means-points mode.

Keep the tagged value through authored/computed style, export and the agent's
existing row inspection. Resolve a ratio after inheritance, at the existing
kernel-to-text projection, using each receiving run's font size. The measurement
request and Apple batch/C ABI must distinguish `Normal` from an explicit used
length of zero; update their existing version/identity declarations together.
Swift painting, native editors and Linux's paragraph cache consume the same
resolved geometry. Delete the `> 0`/zero-as-normal tests along this path.
The browser receives `1.62`, `26px` or `normal` from the typed row and lets CSS
resolve it; it never receives a native computed length in place of a ratio.

Mixed-size inline runs also need their paragraph's minimum line box, including
when all child runs are smaller. Preserve the paragraph font/line-height input
in the existing measurement request if the flattened runs omit it. Resolve
each run separately; multiplying once at the ancestor is not sufficient.
Measure and paint with the same inputs. This does not reopen 1035.000 D6's
declared baseline rounding investigation.

## 3. Replace existing absolute authoring in the same change

Inventory every authored numeric line height in app sources, corpus fixtures,
tests and the maintained external consumer. Preserve intentional absolute
spacing with `"26px"`; a dynamic absolute value uses an existing interpolated
string such as `` line-height=`${height}px` ``. Convert the readers' proportional
prose to a ratio where that is its design, without changing heading/code spacing
by accident. Internal Rust callers that intended 26 points construct
`Length(26)` explicitly. Document the corrected property where its current
syntax is documented; no migration layer or separate guide.

This uses no new Contract syntax and does not preempt 1035.005's formatter and
navigation priority. It deletes the existing semantic exception and magic
sentinel rather than establishing a general CSS-unit expression system.

## 4. Acceptance

Use a literal HTML/CSS counterpart as oracle, not just Exact-on-web. The fast
compiler/kernel/web tests must cover all three kinds, zero, refusal, wire
round-trip, clear-to-inherit and a dynamic change between kinds. A 16px parent
with ratio 1.5 and a 20px child must give that child 30px; an explicit 24px
ancestor stays 24px. Change both font sizes, override/clear the child row,
reparent it, remove/recreate it and reload the plan. This catches stale text
measurement even when the inherited ratio itself has not changed.

Drive Markdown and LLP on web and Apple with the same declared font; include
mixed-size runs and an editor, inspect computed rows and line boxes, and save
native pixels. Sweep Linux through its existing text tests and driver. Allow
0.02 logical units for explicit line-box geometry at the driver's precision;
do not demand identical antialiasing or equal natural metrics from different
fonts. Run the existing five checks with `EXACT_UPDATE_TRUST=development` and
report the reader remeasure cost through existing metrics. Remove F2's `queue/`
line and transcribe the new codec/host interfaces only after this proof.

## Implementation evidence (2026-09-11)

Implemented on the assigned line-height lane: one generated typed row; Contract
literal/dynamic parsing; ratio resolution after inheritance; paragraph strut;
web CSS and row inspection; Apple ABI v5, Swift line boxes and textarea styles;
Linux paragraph baseline cache shared by its raster/GPU painters. Existing
numeric absolute authoring is explicit px; reader prose is 1.625. The maintained
Weird Castle source was inspected without edits and has no active line-height
values requiring conversion. Percent/em strings remain refused.

Compiler/kernel/web tests cover kinds, zero, refusal, wire round trips, clears,
font changes, reparenting, removal/recreation and plan reload. The C seam has a
zero-versus-normal flag regression. Swift's 42 tests and Linux's six text tests
pass, including smaller-run struts and mixed-font baseline extents. A literal
Chrome 152 CSS counterpart and driven web/macOS/iOS plans agree: 20px at 1.5
is 30px, changing the receiving font to 24px gives 36px, fixed 24px stays 24px,
zero is zero, and a 20px paragraph with 8px children retains its 30px box.
Native editor typing and native pixels were checked. A clamped emoji/fallback
case retains exactly 36.25px for two 18.125px lines, matching literal CSS;
normal uses the shaped fallback face's metrics. Markdown app-only smokes
pass web/macOS/iOS; LLP passes web/macOS. Temporary copies of both readers also
ran with the declared DejaVu face on web and macOS, without changing app fonts.
Linux's Caltrain app-only smoke also passes all three Contract tests. Screenshots
and driver output are retained as `/tmp/line-height-*` artifacts.

The mixed 20/40px DejaVu case under fixed 20px line-height measures 26.92px in
CoreText (26.923828 in Linux) versus 27px in Chrome: the existing D6 font-metric
rounding investigation remains open. Single-font explicit boxes and the
smaller-run minimum retain the 0.02 tolerance. Baseline painting's existing
pixel snapping is unchanged; this slice does not claim identical glyph pixels
or broaden Linux's existing inline-colour rendering support.

All five checks were run with development trust: workspace build, Clippy,
formatting, caps and boot pass. The full workspace test run completed with one
unrelated `exact-js` storage failure (`unload_invalidates_continuations_and_configuration_survives_reload`,
expected `again`, observed `cancel`); its isolated rerun passed, and no JS code
was changed. The initial Linux zero test exposed cosmic-text's zero-pitch
scrolling loop; its correction retains positive internal shaping pitches while
cached CSS geometry uses the original length, and the targeted regression passes.

The existing Markdown metrics command completed and reported a 171.4ms
navigation-to-content sample and 11.17ms browser layout work. It explicitly
reports no Markdown native metrics or dev executable, so it yields no native
remeasure cost; that absence is not a zero-cost result. Integrated reader
remeasure numbers belong to the concurrent reader lane's real-reader probe.
The reserved iOS simulator was returned to its initial Shutdown state.

The final shared fallback-font refinement passes Swift's 42-test suite, Linux's
six text tests, and targeted Apple/Linux Clippy with all targets and warnings
denied. These final runs complete the lane's checks; integrated verification
remains the shipping lane's responsibility.

Integrated review found two additional cases, corrected in the lane follow-up:
CoreText may coalesce same-font spans with different authored line heights, so
measurement now includes every authored span intersecting each shaped run.
Both native engines preserve fractional extents when an explicit descendant
determines a line's ascent or descent, while retaining normal rounding when
the normal strut dominates. Swift's 44 tests pass, including reversed span
order and a colour-only split; Linux's seven text tests pass. The new fractional
case is 60.25px under a normal 16px parent, with a separate 10px-child regression
for the dominating normal strut. Targeted Linux Clippy, formatting and caps pass;
the D6 metric-rounding investigation remains unchanged.
