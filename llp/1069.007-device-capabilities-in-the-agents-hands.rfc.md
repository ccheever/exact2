## Summary

The survey (LLP 1069 §4 B1) claimed that exact2 can make every device
capability drivable by an agent, and that Expo can't. This RFC states the
rule that makes it true and says which operation carries each case.

**The rule.** A device capability is admitted in one of two shapes, and
each has a substitute under agent mode:

- **A fact:** reduced motion, locale, zone, online, visibility, a
  permission's state, a watched position. The host reports it and the
  runner re-answers the readers in one commit (LLP 1039's shape). In agent
  mode the value comes from the driver, never from the machine.
- **A request:** pick a file, share, sign in, ask permission, get one
  position. The host answers it later. In agent mode the host never shows
  the OS's surface; the request waits in `state.pending` as a runner ticket
  until the agent answers it, or a fixture the driver named answers it.

A host API that shows system UI with no request, or reads a device value
that is not a fact, can't be substituted, so it can't be tested. It gets a
redesign. The rule covers latest-value facts and one-shot requests; event
streams, a request answered by a stream, and background or cold-start
delivery are not carried yet (Not in this RFC).

**The operations.** `prefer` sets a fact (ruled, §3). `tap` and `type`
answer a request, addressing it by ticket (`@7`), as `type` on the
navigation root addresses a location (LLP 1038 D11). No operation is added.

**Where things stand (r3):**

- **Landed the same day** (93546bef, c7f2014b): `--seed`, `--locale` and
  `--time-zone` on every host, defaults 1, `en-US`, `UTC`
  (`scripts/agent-launch.mjs`, `host/web/navigation.js` `placeReporter`,
  `Session.swift`, `host/linux/src/zone.rs`).
- **The date and the UTC offset,** since 2026-09-27: `--epoch` (1027.000.000
  D3) on every host, default 2026-01-01T00:00:00Z, and the offset of the
  agent's `--time-zone` at that instant, never the machine's.
- **Still the machine's under the agent:** display preferences until the
  first `prefer` (`DisplayPreferences.swift`, the web's `matchMedia`); and
  the offset is not recomputed when the virtual date crosses a DST change.
- **Unanswerable:** `state.pending` lists requests but gives the agent no
  way to answer one.
- **Not gated for production:** the web glue enters agent mode on any
  `agent` query parameter (`glue.js:125`, `searchParams.has`), in every
  bake (D2).

These are the first slice (§5).

## 1. Why this is worth a rule

In an Expo app, device capabilities are tested through the platform:

- **Permission dialogs** belong to SpringBoard or the Android system UI.
  XCUITest reaches them with `addUIInterruptionMonitor`; Maestro and Detox
  pre-grant with `simctl privacy`. None works on the web, on macOS, or on a
  phone in the same form.
- **Location** is `simctl location`, an emulator console command, or
  Maestro's `setLocation`: simulator-only and per-platform.
- **Push** is `simctl push` with a payload file, with no Android or web
  equivalent in the same script.
- **The photo picker** runs out of process; a test seeds the library with
  `simctl addmedia` and taps through another process's UI.
- **Waiting** is on wall time, with timeouts: the flake LLP 1012 §2
  removed from everything the runner owns.

exact2 already has the pieces that make this unnecessary: the runner does
no I/O (LLP 1016 D1), so every answer crosses one seam the host controls;
the clock is the agent's; `state` reports what is pending; and the store is
empty in agent mode (LLP 1018 amendment), the precedent for "agent mode
reads nothing from the machine". The rule extends that to the device.

What it does not test is the OS's surface itself: that PHPicker opens, or
that a permission string reads well. D8 keeps a way to see the real thing.

## 2. Decisions

### D1 — Two shapes: a fact or a request

Every capability declares its shape before it is built:

| shape | carried by | agent mode |
|---|---|---|
| fact | a reserved source's fields (`exactViewport`, `exactTime`, `exactPage`), re-answered by a `Runner::set_*` in one commit | the value comes from the driver, at launch and through `prefer` (D2) |
| request | an HTTP-shaped request (LLP 1016; `exact-native:`, LLP 1067; `exact-auth:`, LLP 1069.006), or a **command-shaped** request whose answer returns as an event on a node (LLP 1069.002's picker) or only to the journal (LLP 1069.003's share). Held, either is a runner ticket (D3) | the host holds it for the agent (D3) or answers it from a fixture (D4) |

A capability can have both. A permission's state is a fact (`granted`,
`denied`, `prompt`, the Permissions API's names); asking for it is a
request. A watched position is a fact; `getCurrentPosition` is a request a
substitute answers from that fact when one is set (D3).

**Entropy is the one input that is neither** (LLP 1069.005): a read the
store counts, drawn per call. Its substitute is a stream seeded by
`--seed` (LLP 1069.005 D2b).

*Rejected:* an agent operation per capability (`location`, `permission`,
`pick`): the old repo's route to eighty wire names.

### D2 — Facts come from the driver; `prefer` sets them mid-run

Under `?agent=1` / `EXACT_AGENT=1`, a host reads no device fact from the
machine.

**Only where agent mode is admitted.** A production bake ignores the agent
parameter and variable: no clock, store, fact or request substitute, and
no seeded entropy, can be reached by adding `?agent=1` to a shipped origin
or setting `EXACT_AGENT=1` for a shipped binary. Today the web glue admits
any `agent` query parameter in every bake (`glue.js:125`), and the Apple
and Linux hosts read the variable unconditionally (`Session.swift:41`,
`host/linux/src/app.rs:210`). The test is a production artifact launched
*with* the agent parameters, asserting the machine's facts, OS entropy and
a real request path. Which baked property decides "production" is for
Charlie (after review, 1).

**At launch,** the driver passes every fact with a documented default, so
screenshots match on every machine:

| flag | default | status |
|---|---|---|
| `--seed`, `--locale`, `--time-zone` | `1`, `en-US`, `UTC` | built (93546bef) |
| `--epoch` | `2026-01-01T00:00:00Z` | built (1027.000.000 D3) |
| the UTC offset | derived from `--time-zone` and the virtual date, never the machine's; recomputed when either changes, DST included | built at launch; the recompute on a DST crossing is owed (§5) |
| display preferences (`prefers-reduced-motion`, `-reduced-transparency`, `-color-scheme`, `-contrast`) | `no-preference`, `no-preference`, `light`, `no-preference`, applied at launch rather than on the first `prefer` | owed (§5) |
| one flag per other `prefer` name (`--online false`) | the defaults in each capability's LLP | with each capability |
| `--permission <name>=<state>` | `prompt` | with the first permissioned capability |

**Mid-run, `prefer`** (ruled, §3) changes one or more facts. It calls the
same `Runner::set_*` the host's own observer calls, so the path tested is
the path shipped: one commit, the readers re-answered. Its forms:

- **CLI:** `prefer <name> <value> […]`, pairs, each name a web name.
- **Wire:** names grouped by where they land. `media` stays as built
  (`{"op":"prefer","media":{"prefers-reduced-motion":"reduce"}}`, LLP 1012
  §1); beside it, `page`, `place` and `permission`.

| group | names | owner |
|---|---|---|
| `media` | `prefers-reduced-motion`, `prefers-reduced-transparency`, `prefers-color-scheme` (built); `prefers-contrast` | LLP 1061 D5, LLP 1069.000 D1 |
| `page` | `visibility-state`, `online`, `can-share`, `root-font-size` | LLP 1069.000 D2, D3; LLP 1069.003 D5 |
| `place` | `locale`, `time-zone` | LLP 1060, 1027.000.000 |
| `permission` | `permission.<name>` (`permission.geolocation denied`), `<name>` the Permissions API's, as in `device.<name>` grants | LLP 1069.008 |

The seed is launch-only; the date is `clock`'s.

- **The reply** gives every group as the runner now holds it, so the agent
  reads what took effect. Today `prefer` requires a `media` object and
  replies with the host-reported media (`Agent.swift:236`,
  `host/linux/src/agent.rs:239`); the other groups are the change.
- **`state`** gains `device{…}`: the facts' current values, beside `store`.
  A secret-shaped fact, such as a push token, shows its presence only.

### D3 — A device request waits for the agent

In agent mode a request-shaped capability's arm does not call the OS. It
holds the request and reports it.

**Every hold is a runner ticket.** An HTTP-shaped request already has one.
A command-shaped request (the picker, share, the document pickers) takes
one from the runner's own counter when the host holds it (a `hold` entry
point beside `fulfill`); the host never numbers a request. So `state.pending`,
produced only from `Runner::pending()` (`runner/src/agent.rs:547`), lists
every hold, and no host number can alias a fetch. Tickets restart with a
runner (`runner/src/runner.rs:644`); a reload drops every hold, as it drops
every request (LLP 1016).

**A hold's lifetime:**

- It ends exactly once: answered, cancelled by the agent, answered by a
  fixture, or retired. The host validates and consumes a live hold in one
  step before it delivers the answer; a second answer, or an answer to a
  retired hold, is refused by name (`not pending: @7`), as driver
  resolution refuses a stale view id.
- It is retired when the runner forgets the ticket (superseded, or its
  resource gone, LLP 1016 D5), when a command-shaped request's node is
  removed, and when the session ends. The journal says `retired`.
- An answer that takes host work (copying a fixture file in) is checked
  again when that work finishes; a hold retired meanwhile discards it.
- A request made before the driver attaches is held like any other: holds
  and fixtures are installed before any capability arm can reach the OS,
  and the driver's attach does not wait on them.

**`state.pending`** entries gain `device: {capability, args}`, for example
`{"name": "avatar", "ticket": 7, "device": {"capability": "pick", "args":
{"id": "avatar-file", "accept": ["image/*"], "multiple": false}}}`. For a
command-shaped hold, `name` is the requesting node's id. `args` is an
**inspection summary** each capability declares (D7), not the app's raw
arguments: enough for a test to check that the app asked for the right
thing, and never a credential. An authorization URL can carry an
`id_token_hint`; a native request body can carry a token.

**The clock.** A held device request is listed in `pending` but is not
I/O in flight:

- The wait loops that count pending tickets (Apple's `pendingCount` and
  `waitForReplies`, `Agent.swift:341–364`; the web's `inflight`,
  `glue.js:689` and `:1213`; Linux's `host/linux/src/agent.rs:493`) skip
  holds.
- **`clock +N`** advances and fires the app's due timers without waiting
  on a hold. It fires no timeout the host doesn't own: an app that wants a
  timeout on a picker authors a timer, and that timer fires.
- **`clock settle`** (ruled) never waits on a hold. It still seeks motion
  and still waits for network requests (1012 §2). If a hold remains, it
  returns `settled: false, reason: "device"` with every remaining ticket,
  device and network. A fixture answer ready in the same commit is drained
  first.

**The journal** gets `device pick 7 held (agent)`, then `device pick 7
answered: 1 item`, `… cancelled` or `… retired`. It shows the capability's
summary of an answer, never the value (D4).

**The capability names** in `pending`, one per sibling:

| `capability` | LLP | shape |
|---|---|---|
| `pick` | 1069.002 | command-shaped |
| `share` | 1069.003 | command-shaped, journal only |
| `auth` | 1069.006 | HTTP-shaped (`exact-auth:`) |
| `open-file`, `open-directory`, `save-file`, `export` | 1069.010 D2, D3 | command-shaped |
| `permission` | 1069.008, and any capability that asks | request, then fact |
| `position` | survey §5 #14 | answered from the place fact when the agent set one; otherwise a hold |
| `native` | LLP 1067 `native.later` | HTTP-shaped (`exact-native:`); out of the first slice (D5) |

### D4 — Answering is `tap` or `type` on the ticket

A pending device request is a target. The CLI writes it `@7`; the wire form
is `{"ticket": 7}` in place of `id`. The driver resolves `@N` before any
view lookup.

- **`tap @7 <choice>`** answers a request whose surface is a choice. The
  wire form is `{"op":"tap","ticket":7,"choice":"cancel"}`; the CLI's `tap`
  grammar gains the choice after an `@` target (today it passes only the
  first word, `scripts/agent.mjs:1424`). While a contact is down, `tap
  cancel` stays the contact's phase; `tap @7 cancel` is the ticket. The
  choices:
  - `allow` or `deny` for a permission (which also sets the fact);
  - `shared` for a share;
  - `cancel` for any request (a picker dismissed, a share sheet closed, a
    sign-in abandoned), which the app sees as the platform's own
    cancellation: HTML's `cancel` event on a picker, 499 on an
    `exact-auth:` request, `share: dismissed` in the journal.
- **`type @7 <value>`** answers a request whose surface produces a value,
  validated against the capability's result shape:
  - `pick`, `open-file`, `open-directory`: fixture paths on the driver's
    machine, copied in or minted into handles as the real picker's result
    would be (onto a physical phone, as `devicectl copy` already moves
    worlds);
  - `save-file`, `export`: the chosen name;
  - `auth`: the callback URL;
  - `position`: a position.

This is `tap` and `type` addressing something other than a view, as LLP
1038 D11 did for the navigation root: a target form, no operation. Each
answer carries `delivery: "substituted"` (ruled) on every host, web
included (D5), so a transcript never passes a substituted answer off as a
real one. LLP 1012 §1 lists `platform`, `recognized`, `activation` and
`unsupported`; the driver also emits `presenter` and `browser-viewport`
(`scripts/agent.mjs:1008`, `:289`), which 1012 should list beside it.

**A credential is never echoed.** Where the value is a credential (the
`auth` callback carries a code), the reply, the journal and any validation
error say what was answered (`callback accepted`), not the value.

**Fixtures instead of the agent.** `--answer <capability>=<value>` at
launch answers each request of that capability as it is held:
`--answer pick=fixtures/cat.jpg`, `--answer share=shared`,
`--answer auth=<callback URL>`. A smoke that isn't about the picker then
doesn't stop at it. Fixture answers take the same host path as `type @t`,
consume the hold the same way, and journal the same lines; they land in
the commit after the one that made the request, so an agent answer to a
fixture-answered ticket is refused as not pending. With no fixture the
request waits (D3). The default is never a silent success. A fixture
needing a value from the request (auth's `state`) takes it from the
request body, never from the store (LLP 1069.006 D1).

### D5 — Where the substitute lives, per carrier

**Requests are held by the host on every carrier.** On the web the glue
holds them in agent mode, as the Apple and Linux arms do, and the driver
answers through the page: the file picker, the share sheet, the auth
popup, permission prompts, and the File System Access pickers of LLP
1069.010. CDP answers no request: `Browser.setPermission` sets a
permission's state and creates no prompt to hold, and a file chooser
intercepted through CDP has no ticket and no way to deliver a late
`cancel`. One lifecycle (D3), one `delivery` value (D4).

**Facts on the web** use the browser's own override where it changes only
the reading, so the app's real code path runs:

| fact | CDP |
|---|---|
| display preferences, contrast | `Emulation.setEmulatedMedia` (what `prefer` uses) |
| locale, zone | `Emulation.setLocaleOverride`, `Emulation.setTimezoneOverride`, *in addition to* the glue's `placeReporter` (`navigation.js:533`), which reads the launch parameters and is what re-answers `exactTime` and the place fact |
| permission state | `Browser.setPermission` |
| position | `Emulation.setGeolocationOverride` |

**Visibility and online are not CDP.** `Page.setWebLifecycleState` takes
`frozen` or `active`; freezing hides and suspends the page the driver's
own operations run in. `Network.emulateNetworkConditions` with `offline`
fails the fetches the web host fulfils requests with
(`host/web/http-body.js:58`), which a native `prefer online false` does
not. Both facts go through `Runner::set_*`, as on every host.

Seed, locale and zone come from the page's agent parameters (built); the
date still comes from `Date.now()` (§5).

**Apple and Linux** have no override API. The capability arm checks agent
mode and never reaches UIKit, AppKit or the OS: no PHPicker, no
`UIActivityViewController`, no `ASWebAuthenticationSession`, no
`CLLocationManager`. The check sits once at the top of each arm, as
`ExactEnv.agentMode` already gates the session's timers
(`Session.swift:809`). The simulator's own tools (`simctl location`,
`privacy`, `push`) are not used: simulator-only, and not on the agent's
clock.

**A native module** (LLP 1067, 1016.002) is not one branch. In the default
native agent configuration the module reports itself unavailable
(`js/src/lib.rs:247`) and `native.later` falls back to a synchronous
`native.call` (`js/src/prelude.js:305`), so no hold appears; and a
`native.watch` re-answer needs a value from somewhere once the module
doesn't run. The substitute has to specify availability, synchronous
reads, topic values and later requests together, through the existing
seam. That is an amendment to LLP 1067, out of the first slice; until it
lands, a module's Swift or page code runs in agent mode only under D8.

|---|---|---|
| preferences, contrast, scheme, visibility, online, `canShare`, root font size (1069.000) | fact | launch flags; `prefer` |
| locale, zone, seed (1060, 1027.000.000) | fact | `--locale`, `--time-zone`, `--seed` (built); `prefer locale …` mid-run |
| form controls (1069.001) | UI, not device | `tap` / `type` on the control's node |
| file picker (1069.002) | request, command-shaped | `type @t fixtures/a.jpg`, `tap @t cancel`; `--answer pick=…` |
| share (1069.003) | request, command-shaped | `tap @t shared`, `tap @t cancel`; `--answer share=shared` |
| SSE / WebSocket (1069.004) | network, not device | a local server the smoke starts; `pending` shows the open stream |
| entropy (1069.005) | a counted read | the stream from `--seed` (1069.005 D2b) |
| auth session (1069.006) | request | `type @t "<callback URL>"`, `tap @t cancel`; `--answer auth=…` |
| permission (1069.008) | request, then fact | `tap @t allow` / `deny`; `--permission name=state`; `prefer permission.<name> denied` to revoke |

| scheduled notification (survey §5 #9) | request, then a fact (the schedule) | `state.device.scheduled`; `clock +N` past its time delivers it |

### D7 — What a capability LLP must say

Every sibling, and every later capability LLP, carries a **Substitute**
paragraph with:

1. The shape (D1).
2. For a fact: the `prefer` name and group, the launch flag and the
   default, and the reserved source's field that carries it.
3. For a request: the `capability` name in `pending`, its `args` summary,
   the value `type` accepts, the choices `tap` accepts, and the fixture
   form.
4. **Disclosure:** what `pending`'s `args`, the `prefer` reply, answer
   replies, validation errors and journal lines may show. A credential
   (code, token, key) shows its presence only.
5. **Lifetime:** when a hold is retired besides the runner forgetting it
   (its node removed, a second invocation), and what the app sees.
6. The web carrier's CDP override for a fact, if one changes only the
   reading.

A capability whose surface is a stream, a sequence of events that must
each arrive, or background or cold-start delivery doesn't fit D1 yet; its
LLP says so and waits for a rule (Not in this RFC). A capability LLP
without this paragraph isn't ready to build.

### D8 — The real surface, on purpose

`EXACT_DEVICE=real` turns substitution off, following `EXACT_STORE=real`
(`host/apple/src/store.rs:27`): the OS's dialogs and sheets appear, the
machine's facts are read, entropy comes from the OS, and `delivery` says
`platform`. It is consulted only in agent mode and is set only through the
environment: the driver's `--device` already means "a physical iPhone"
(`scripts/agent-launch.mjs:16`), and gets no value. It is for a person, or
a check that a string or a sheet looks right. No smoke uses it.

## 3. `prefer` sets every fact (ruled: P1)

`prefer` was built as a ninth operation for display preferences (LLP 1061
D5). The question was whether the operation that sets them also sets every
other device fact, and at what cost to the operation count. Ruled P1:
`prefer` stays the ninth and is general. A new fact is a new `prefer` name,
never a new operation (`rules/DEFERRED.md` §Agent API; LLP 1012 §1). It
keeps its name: it is built, and `rules/DEFERRED.md` names it.

*Rejected:*

- **P2, fold into `clock`** (`clock set online=false`): `clock` gains a
  second verb.
- **P3, `type @device {…}`**: "type" reads oddly for "go offline".
- **P4, launch values only**: a fact changing mid-run, the path most likely
  to break (the re-answer commit, a caching reader, motion started before
  the preference flipped), couldn't be tested.

## 4. What this costs

- **Runner:** a `hold` that issues a ticket for a command-shaped request, a
  `device` field on pending entries, a `device` section in `state`,
  `settle`'s new reason. No new request type.
- **Every host's agent loop:** holds leave the wait set (D3).
- **Driver:** the ticket target form and `tap`'s choice, `--answer`, and
  launch flags as each capability lands. The CDP calls beyond
  `Emulation.setEmulatedMedia` (`scripts/agent.mjs:328`) are new driver
  work. `agent.mjs` is at 1,459 lines and `glue.js` at 1,472 of the 1,500
  cap, so the first slice moves code out of each before it adds to them.
- **Production gate:** the bake property of D2, on each host.
- **Apple and Linux:** one agent-mode branch at the top of each capability
  arm, written with the arm. The native-module substitute is more (D5).
- **No new check,** script or file.

## 5. First slice

1. **The launch facts:** `--epoch` and the zone's offset are built
   (2026-09-27); left are the offset's recompute across a DST change and
   display preferences applied at launch. Held by: two runs of the smoke
   with the same flags, on machines with different zones and accessibility
   settings, give the same `state` and the same screenshots.
2. **The random stream:** `getRandomValues` and `randomUUID` under the
   agent draw from `--seed` (LLP 1069.005 D2b). LLP 1069.005 pins the
   generator, the seed's encoding, the stream's scope (per executor or
   shared) and what a reload does, so an ID carried across a reload is not
   minted again. Held by: two runs mint the same UUIDs; a reload does not
   repeat a carried one; the same vectors on every host.
3. **The production gate** (D2): a production artifact launched with the
   agent parameters behaves as a production launch.
4. **Holds:** the runner's `hold`; `pending` entries gain `device`; holds
   leave the wait loops; `clock settle`'s `reason: "device"`; the `@t`
   target and `tap @t <choice>`; `delivery: "substituted"`. No capability
   is admitted yet, so the test is a runner test with a synthetic device
   request, plus a driver test: a held request, a due app timer and an
   unfinished fetch together, through `clock +N` and `clock settle`.
5. **`prefer`'s groups:** the wire's `page`, `place` and `permission`
   objects, empty until 1069.000 and 1069.008 fill them.

Each capability sibling brings its own substitute (D7).

## Not in this RFC

- **Recording and replaying a session.** ✕ in `rules/DEFERRED.md` §Agent
  API. Substituted inputs keep it possible (LLP 1069.009).
- **Testing the OS surface itself.** D8.
- **Streams, lossless event sequences and background delivery.** A watched
  position or a `native.watch` topic is a latest value, which `prefer`
  sets. Two identical notifications, every partial result of a streaming
  request, and a notification that launches the app cold are not carried;
  a capability that needs them waits for a rule.
- **The native-module substitute** (D5): an LLP 1067 amendment.
- **Pasteboard reads.** Listed among the agent operations not shipping. A
  clipboard-read capability would be a request under D1 and need no
  operation.

## Decided

1. §3: P1. `prefer` is the ninth operation and sets every device fact.
2. D4: a substituted answer carries `delivery: "substituted"`.
3. D3: `clock settle` returns at once on a held device request.
4. §5: the first slice includes the repeatable random stream.
