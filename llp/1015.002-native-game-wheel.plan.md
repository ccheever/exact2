# LLP 1015.002 — Native game wheel delivery

Status: implemented and qualified on Windows and Chrome. Implementer: Codex Windows owner,
2026-10-04. The user authorized fixing encountered engine gaps after LLP review.

## Reproduction and contract

The real Frontier terrain drive on exact2 `f8e433495` sends
`s.tap('world', {wheel:[0,3000]})` at 640×480, 800×600 and 1280×720. Chrome changes
`Battle.zoom` from 22 to the game's limit 48; Windows remains at 22. Both the
Windows `MouseWheel` event and the native agent call `Presenter::wheel_at`, which
only scrolls UI containers/page. `gpu_input` already accepts a `wheel` message;
the engine already accumulates and expires wheel deltas per tick. No new game
input API, ABI, save field, or zoom rule is required.

The browser is the routing oracle: `gpu-glue.js` receives the event only when its
target is the input canvas/host itself, prevents scrolling, and sends one wheel
message. Focus alone does not steal a wheel over an overlaid control. Pointer
capture does not redirect wheel targeting. Native should follow the current
painted hit, respecting clipping, hidden/inert and pointer-events. A child HUD
control or an overlaid scroller retains its normal UI behavior; a non-input GPU
canvas retains the existing scrolling fallback.

## Bounded implementation

1. Before UI scrolling in `wheel_at`, resolve a direct, live, input-capable GPU
   surface under the logical viewport point. Do not use an ancestor-input search
   that would let a plain HUD child leak wheel events to its game. Do not fall
   back to the keyboard focus or a captured pointer. A pointer-events:none
   overlay naturally allows the actual canvas hit through.
2. Send one existing `{t:"wheel",dx,dy,x,y,at}` message. Coordinates are relative
   to the surface; deltas are logical/CSS pixels and are not scaled again in
   Presenter. A consumed surface event never also scrolls an ancestor/page,
   including when the GPU ABI rejects it: retain/report the existing surface
   error rather than redirecting failed input to another owner.
3. A wheel reaching a game must not cancel a held game pointer or control action:
   the browser preserves it. Preserve the existing wheel takeover for UI
   gestures; when wheel targets UI during a held game contact, leave that game's
   contact intact and let its eventual up/cancel resolve normally. No synthetic
   key/pointer releases or focus changes accompany game wheel input.
4. Preserve Windows' existing sign and units: line deltas become 40 logical
   pixels per line, physical pixel deltas divide by display scale once. Extract
   this small conversion only if needed to test 1×/2× and fractional deltas.
   This is not a claim that every physical mouse's detent equals a Chrome detent.
   Refuse nonfinite agent deltas and avoid any routing/mutation for invalid or
   zero device samples. Add no epsilon, clamp, or per-game normalization.

## Review accepted before implementation

Parent independently approved this proposal, 2026-10-04: direct current hit,
relative logical coordinates, one delivery, no scrolling fallback after consumed
or failed ABI delivery; preserve held game contacts/actions. Invalid/nonfinite
samples must mutate neither UI nor game. Keep HUD/scroller and capture/focus
regression coverage, and qualify real native maximum zoom plus browser/overlay
drives without making a physical latency claim.
