## Draft and selection

[inferred] [voice-data.ts](../examples/t3-code/mobile/voice-data.ts) captures the existing shared draft slot, connection identity, text revision and editor selection. Moving to another thread keeps that target. Completion writes that slot synchronously and calls shared client.persist without changing current thread/project selection. Changing connection identity refuses the old target. Root must call mobileVoiceObserveDraft synchronously after mutations that can clear or change drafts; [draft.ts](../examples/t3-code/mobile/draft.ts) does so immediately after the shared reducer starts, before any await. This detects an edit followed by a revert, which a final text comparison alone misses.

[inferred] Voice is unavailable while the current composer is answering a runtime question or approval. The adapter does not represent those answer slots yet and must not write an ordinary draft as though it answered one. This is a recorded implementation limit, not a claim that the pinned app forbids every such case.

[inferred] [T3MobileVoiceEditor.swift](../examples/t3-code/mobile/modules/apple/T3MobileVoiceEditor.swift) reads the mounted UITextView selectedRange through the existing Exact element hook. Start checks draft identity and text around that native read. Completion stages a selection for the captured owner and exact resulting text. A later hook applies it only when both match and its revision is current, then consumes it once. A later observed draft edit invalidates the selection token even if the text is reverted. Starting a new dictation also clears the previous pending token, so replacing the observation target cannot leave an old caret valid. Root assigns the owner only to the top active composer, so retained hidden editors cannot consume another route's selection. It does not replace Exact's delegate, text binding or focus owner. Root uses readonly while the visible target's voice phase blocks editing, and gates every Send entry point by the same state.

## Answer lifetime

[inferred] The persistent copied controller contains data and dependency functions. Each awaited mobileVoiceAction creates a temporary scope holding that answer's native/storage handles. Recorder start, deletion, publication and persistence are drained before the scope is cleared in finally. The target's commit function resolves the current scope when called; it does not retain Start's storage or native handle for Stop. Cancel during preparation/transcription invalidates the controller and requests native cancellation; the original answer remains responsible for settling its operation.

[inferred] mobileVoiceStatus reads native status and registers its watch. Its one control exception is a background event during an in-flight preparing scope: it invalidates that controller operation immediately; cleanup stays with that active answer. Native recorder completion, interruption and background events have monotonic sequence IDs. A separate root task invokes reconcile once for a new session/event pair, with its condition waiting until Start/Stop and Cancel mutations are no longer pending. The adapter also reconciles an already-observed event after draining its active scope. This prevents a background event during recorder startup from being lost as a busy reply. The synchronous, no-I/O mobileVoiceSnapshot projects status and controller data and observes the current draft revision and caret; its root resource must depend on the native status, including meter samples, and shared draft changes. Native state publication allows preparing/transcribing UI to update before the pending action finishes. No answer-bound TypeScript timer, native handle or JavaScript callback survives its answer. The module-owned recorder delegate and meter timer span answers until native cleanup. Abandoned answers invalidate the controller before its ordinary error handler runs. Root uses independent Cancel and operation mutations, disables Finish until startup drains, and prevents an overlapping operation from superseding Start.

## Native lifetime

[inferred] [T3MobileVoice.swift](../examples/t3-code/mobile/modules/apple/T3MobileVoice.swift) creates AVAudioRecorder lazily after permission and transcription preparation. Its settings match Expo HIGH_QUALITY: AAC/M4A,44100Hz, two channels,128000bit/s and maximum encoder quality. It uses exclusive play-and-record audio, an80ms meter timer and a native300second recording limit. It restores the preceding idle-timer-disabled value, explicitly deactivates audio to resume other apps, and deletes its temporary file on cleanup. Background preparation/recording, interruptions, encoding errors, cancel and module destroy stop capture. Agent mode refuses microphone activity, permission prompts and settings launches. Simulator capability is unavailable.

[inferred] Module registration is app-local: construct T3MobileVoice(agent:changed:), forward mobileVoice requests to perform(_:reply:), forward the editor hook and call destroy when the module closes. The source grant device.microphone purpose.microphone with the pinned text "Allow T3 Code to use your microphone for voice input." supplies NSMicrophoneUsageDescription through Exact's existing bake. SpeechAnalyzer uses no SFSpeech authorization path. Root/module/manifest integration belongs to the parent.
