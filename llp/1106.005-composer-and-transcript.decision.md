## Settings ownership

[inferred] [composer-settings.ts](../examples/t3-code/mobile/composer-settings.ts) owns only sheet presentation state: pending model/options, provider disclosure overrides, busy/error state and the sheet's draft/generation identity. Search/filter/legacy visibility are root inputs. Server config remains the catalog authority; shared provider availability/locks govern mutations. Mobile-specific catalog grouping, favorites-first stable ordering, simple visible-text search and hidden prompt-injected effort choices follow the pinned mobile source.

[observed] Save validates current catalog membership, permissions and the sheet's original applied selection. It places staged options into existing shared option memory and invokes the ordinary model command, whose single model-selection payload includes all options. A running turn uses shared next-turn staging. Cancel discards the pending sheet choice. Options for the already-applied model and runtime choices use existing commands immediately, matching the source's distinction. If the newly selected provider cannot support the current runtime, a compatible runtime command follows; those two server operations are not atomic, and a refusal leaves the sheet open with its error.

[observed] Favorites and model-option memory continue using shared local preferences. The unified mobile preference file supplies follow-up behavior before the shared send operation. [composer-behavior.ts](../examples/t3-code/mobile/composer-behavior.ts) reapplies that mobile setting after shared device presentation loads desktop preferences, and passes the actual primary/alternate intent through the existing composerSendIntent seam. Providers that cannot steer use queue. The shared dispatcher still owns payloads, permissions, pending operations and results. Environment, origin, project, thread, draft, generation, thread epoch and model/runtime identity are checked after preferences and before/after each native await preceding the first orchestration write. Once that write begins, shared pending reconciliation owns its outcome and a successful launch may select its new thread. An independent reproduction of a selection change during devicePresentation now dispatches nothing and preserves both drafts.

[observed] The stable composer textarea binds the pinned hardware-key chords through existing Contract keydown events. Enter/Meta+Enter follow the mobile Enter preference; alternate send uses Meta+Enter or Shift+Meta+Enter. Software Return remains a newline. Seven tests cover all queue/steer and primary/alternate combinations, unsupported steering, owner changes and desktop keybinding independence. Strict TypeScript passes. Hardware keyboard interaction, iPad command titles, long-press follow-up menus, haptics and rich input still require implementation or native evidence.

## New task ownership

[inferred] [new-task.ts](../examples/t3-code/mobile/new-task.ts) projects synchronized focused/fleet shells and uses JSON-encoded environment/project identity pairs for project picks. Selected project drafts remain in shared environment/project slots. [draft.ts](../examples/t3-code/mobile/draft.ts) calls the shared composerOps draft reducer synchronously before its first await, then persists through the existing serialized native queue. The full shared command path awaits presentation before reduction and can cross project ownership; mobile bypasses that preamble for text input. A delayed-input/project-switch regression covers this boundary. Shared environment-run-on moves the same logical project's draft between machines. A project on another live environment connects and synchronizes that actual environment before opening its project draft.

[observed] Branch resources read the authenticated session and actual VCS catalog. Checkout permission uses explicit permissions when present, including an empty list. A worktree base selection records shared draft context; checking out another local branch uses the real shared VCS command. Selecting the current branch requires no redundant checkout. Shared branch paging receives the actual Contract reachend event and performs its pending next-page read within the awaited root answer.

[inferred] New task Send invokes the existing shared send/launch path. The shared client allocates identifiers, persists pending operations, checks draft/model ownership before dispatch and reconciles uncertain writes. The adapter returns submitted=true only after a new actual thread identity is available for the same environment/project/generation. Root navigates on that result, never on a tap or predicted thread id. An uncertain launch retains the shared pending entry and original draft.

## Root seam

[observed] [composer-shapes.contract](../examples/t3-code/mobile/composer-shapes.contract) declares ComposerSettingsSnapshot, ComposerActionResult, NewTaskSnapshot, NewTaskResult, NewTaskPreparation and ComposerColors. Model/settings and new-task components consume those shapes, and delegate headers/search, routing, attachments and settings-page presentation to root. NewTaskResult returns environmentId,projectId,threadId and submitted. Root scopes branch reads to route, query, readiness and draft owner changes, rather than each keystroke. Thread selection replies carry their requesting route identity and cannot navigate over a newer route. The shared client remains the sole protocol mutation owner; test-native replies appear only in unit fixtures.

## Alternatives and consequences

[inferred] A second mobile client/reducer would split draft/submission ownership. Using desktop picker rendering directly would lose the source's staged Save behavior and catalog presentation. The selected approach keeps shared protocol ownership and app-local mobile presentation, at the cost of explicit adapters and some shared desktop constraints (for example, stricter writable admission).

[observed] The checkpoint still lacks full native parity evidence, rich composer chips/selection, picker search toolbar/filter header integration, native media/voice, offline outbox, no-project creation UI, logical project grouping in the new-task chooser, exact provider-unavailable/default retention behavior, source-specific tool rendering, and large-catalog virtualization. The latter is currently ordinary scrolling: Exact's virtualized list requires one direct each, while these preparation components include header content. No framework workaround was added. Root integration is written but its combined Contract compile is paused at the retry decision. Native validation remains required.

[observed] Focused tests exercise staged Save/Cancel, stale catalog/permission refusal, shared option payloads, project draft isolation, branch permissions, ownership changes before dispatch, confirmed launch identity and uncertain launch retention. Contract checks reached the three-round stop with a final numeric-text conversion correction awaiting the parent’s permitted next validation. Strict TypeScript passes. Validation state must be updated only from the actual integrated checks.

## Media presentation

[observed] [media-preview.ts](../examples/t3-code/mobile/media-preview.ts) resolves only an attachment present in the selected shared transcript or current composer draft. Transcript previews reauthorize through the existing `assets.createUrl` RPC when opened, then retain that first signed URL for the route instance. A changed environment/thread/generation refuses late authorization. Composer previews pass an owned draft UUID; filesystem paths and bytes stay below the native seam. Share repeats the ownership check before presenting. Failed native decoding can invalidate the presentation cache before an explicit retry.

[observed] Pinned mobile iOS uses Quick Look for native image/document previews and AVKit for videos. The app-local `T3MobileMedia*` files adapt those pinned implementations with existing native-view lifetime hooks. Quick Look owns zoom, document controls and its share action. AVKit owns playback controls, pauses on background, and restores the preceding audio-session category when still applicable. Native file/share operations lease original-byte copies; removing a draft does not delete an already-open lease. A separate share uses UIActivityViewController and retains its own copy through dismissal. Removing the presenter view cancels loading and dismisses its viewer; completion includes the request identity so root can reject late navigation.

[observed] The updated base 80eccbe's X29/#115 fix covers bundled PDF iframes. Its gap map still excludes app-file video/iframe and a dedicated PDF viewer; it does not replace these pinned mobile Quick Look/AVKit controls. This slice introduces no framework change or shared protocol fork. Source thumbnail transition anchors and iPad share-anchor geometry remain unimplemented; the system presentation fallback is used. Pinned AttachmentFileScreen's text/Markdown/table rendered/source modes remain separate from its native file-viewer action. Native interaction/parity has not been demonstrated.
