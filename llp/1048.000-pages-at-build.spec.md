**Type:** Spec
**Status:** Draft
**Systems:** Build (`contract::bake` and a render step beside it; `host/web/build.mjs`); web host (`host/web/src`: a page serializer sharing `Host::create`'s mapping; `glue.js` replace-on-boot); Router (route enumeration); serving (`dist/` layout, `host/web/serve.mjs`)
**Author:** Claude (Opus 5.5) for Charlie Cheever
**Implementer:** assigned by Charlie at phase 1 kickoff
**Date:** 2026-09-23
**Related:** LLP 1048 (parent: D1, D2, D8–D11), 1048.003 (head, document scrolling, semantic elements), 1048.001 (adoption replaces §2 D6), 1038 (the routes table), 1023 (the envelope link), 1007 §7 (building), 1047 (runtime size)

## Summary

Phase 1 of LLP 1048. At build, every enumerated route of an app renders to a real
HTML document: its first frame, its head and its links. The page paints when the
HTML arrives. When the runtime boots, it builds the same tree and swaps it in
once (adoption, LLP 1048.001, removes the swap). The output is a portable
`dist/`.

## 1. What renders

- **Pages.** Every route in the routes table without parameters. Parameterized
  routes render the locations the app enumerates (D2). An app without a router
  renders `/`.
- **Inputs.** `Runner::boot` at the route's location (path and query) with the
  build data source (the one `contract::bake` already uses,
  `contract/cli/src/lib.rs` ~494), the page viewport (D4), the build clock (D5)
  and an empty store (LLP 1018 D4 — bake already sees no one's session).
- **The first batch.** Produced by the web host code (`exact-web` compiled
  natively), exactly as `exact_boot` produces it in the browser.

## 2. Decisions

**D1 — The serializer shares the host's mapping.** `exact_web::page::render`
lives beside `Host::create` (`host/web/src/host.rs` ~874) and uses the same
`tag_for` (~1050), `props_for` (~1142) and `css.rs`.
- Elements keep their `data-view` ids.
- Text and attribute values are escaped per the HTML spec.
- Inline style is the same `cssText` the live host sets.
- Canvas nodes render as their sized element; the surface arrives with the
  runtime.
- `iframe` keeps `src`; images and videos use the hashed asset URLs.
- Markdown markup nodes render the spans that `renderMarkup` builds
  (`navigation.js` ~1413). That logic moves into Rust, so the live host and the
  renderer share it.

**D2 — Enumeration.** A parameterized route lists its pages through a
build-provenance source named on the route (LLP 1048.003 D5, `pages=`), which
answers a list of locations. A route with no list renders nothing at build;
its URLs fall through to `404.html`, which boots the runtime at the requested
location (D8).

**D3 — The batch is the page (LLP 1048 D1).** Before rendering is trusted,
every DOM effect `glue.js` applies outside ops at first paint moves into the
batch, or into Rust that the serializer runs:
- router projection (`navigation.project`: inactive routes hidden and inert);
- `refreshSymbols` (symbol images);
- `prepareContexts`;
- list and selection sync.

The async parity check (§4) guards this invariant for every app.

**D4 — The page viewport.** Pages render at the manifest's
`web.pageViewport`. The default is 390×844, the bake's `LINT_VIEWPORT`: phones
are where first paint matters most, and search engines index mobile-first. A
layout that branches on `exactViewport()` is right for that width only. Media
variants (LLP 1048.003 D3) are how a document is right at every width; until an
app uses them, the swap on boot corrects wider screens.

**D5 — The build clock.** `now()` reads the build time. Content that reads the
clock is corrected when the runtime boots (it is request- or client-provenance
content, LLP 1048 D3). Phase 1 renders the build-time value.

**D6 — Replace on boot (phase 1 only).** The runtime boots as today. The glue
builds the new tree off-document and replaces `#exact-root`'s children in one
frame. The trees are equal, so nothing visibly changes. When the root is the
document scroller (LLP 1048.003 D4), window scroll survives. LLP 1048.001
replaces this with adoption.

**D7 — The head.** Each page's `<head>` holds:
- `<title>`, `description`, `canonical`, OpenGraph and Twitter tags (`og:title`,
  `og:description`, `og:image`, `og:url`, `twitter:card`) and `robots`, from
  the active `head` element (LLP 1048.003 D1);
- `<html lang>` from the manifest;
- `@font-face` declarations and font preloads (LLP 1019);
- the envelope `<link rel=alternate>` (LLP 1023);
- `modulepreload`/`preload` for the glue and the wasm (from the web lane,
  2026-09-23).

`build.mjs` writes the head today by string replacement (~147–151); that moves
into the renderer.

**D8 — `dist/`.**
- `dist/index.html` for `/` and `dist/<location>/index.html` for every other
  rendered location (trailing-slash directories, which every static host
  serves).
- `dist/404.html`: the router's not-found route rendered if one exists,
  otherwise the runtime shell booting at the requested URL.
- `dist/sitemap.xml`: every rendered location, absolute against the manifest's
  origin.
- `dist/robots.txt` (allow, plus the sitemap line).
- Content-hashed assets, with precompressed `.br` and `.gz` siblings.

`serve.mjs` serves a rendered directory before its SPA fallback (~563–566); the
fallback remains for locations that weren't rendered.

**D9 — Where it runs: at build and per request, from one native binary.**
Charlie ruled the server target a native Rust binary (2026-09-23). The renderer
is a library over `exact-web` compiled natively, with two callers:
- **The build:** a render step after `bake`, called by `host/web/build.mjs`, for
  every enumerated location.
- **The server:** a native binary that serves `dist/` and renders a requested
  location per request — the same call, with the same empty store and no cache.
  This is what Interview's data-driven routes need in phase 1
  (LLP 1048 §10). Caching, holes and streaming come in LLP 1048.002.

A request render reads only public sources: those that don't consult the store,
through the host's fetch with no credentials. Anything that reads the store (a
session, drafts) renders its logged-out state, and the runtime corrects it on
boot.

The dev server calls the same renderer on each page load, so the dev loop shows
real pages too; its restart path is unchanged.

**D10 — Links.** Links in a rendered page are real `<a href>` and work without
the runtime. The web lane's same-origin interception (2026-09-23) routes them in
the app once the runtime is up.

## 3. Not in phase 1

Adoption, activation policies, route payloads and navigation prefetch (LLP
1048.001); provenance holes, request rendering and streaming (LLP 1048.002);
media variants and required placeholders (LLP 1048.003 part B).

## 4. Verification

- **Parity** (async lane): for every app and rendered location, the file's
  `#exact-root` equals the live DOM after the first batch in headless Chrome at
  that URL. Compare normalized tags, attributes, text and inline style. A
  difference names the view id, element and attribute.
- **Units:** escaping, head, sitemap and enumeration fixtures in `exact-web`'s
  tests.
- **Web vitals:** first contentful paint at 150 ms RTT and 6 Mbit/s for the
  website trial's pages. Today it is 2.26 s; the target is HTML arrival plus
  style.
- **Rules:** `bun scripts/boot.mjs` stays green; no app JavaScript runs before
  first pixel; `dist/` serves correctly from a plain static file server.
