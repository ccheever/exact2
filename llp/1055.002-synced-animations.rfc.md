# LLP 1055.002: Synced animations — loops that share a phase

**Type:** RFC
**Status:** Draft for review, built on `feat/clock-timelines` (2026-10-03): D1–D6 built and tested; D7 and D8 proposed, not built. Needs Charlie's ruling (§7).
**Systems:** Contract (a `timeline` declaration; `animation-timeline` taking it), Kernel (the `animation-timeline` row's `clock(<ident>)`), Motion (`exact-motion`: a synced play's start), Web host (`startTime` on the browser's animation), Apple host (none beyond the start it already receives), Linux host (none)
**Author:** Claude (Opus 5.5) for ide@expo.io
**Date:** 2026-10-02 (revised 2026-10-03, as built)
**Implementer:** Claude (Opus 5.5), 2026-10-03
**Related:** LLP 1055 D5 (`@keyframes` and `animation`; when an animation starts), LLP 1055 D7 and 1055.001 (lowered and sampled executors; a box's opacity in Core Animation), LLP 1057.003 D1, D4 (`animation-timeline`, named timelines and `timeline-scope`), LLP 1002 D3 (seek, not wait), LLP 1001 (declared deviations), LLP 1047 (pay for what you use)

## Summary

Two looping animations started at different moments stay out of step for as
long as they run. In the Lexy port, tapping Lock and then Start leaves
"Unlocking" and "Starting" pulsing out of phase, a few hundred milliseconds
apart. Loading indicators have the same problem: three skeletons that appear
one after another shimmer out of step. They should pulse together.

**This RFC proposes a clock timeline:**
- It's declared in Contract (`timeline Pending`) and shared by importing
  it with `use`; two different declarations of one name are a compile
  error, never one shared phase.
- An animation joins it with `animation-timeline=Pending`.
- Every animation on one timeline lines up to one shared phase.
- A timeline is one number, its origin. Nothing ticks for it. Each host
  plays a synced animation exactly as it plays any other, but from a
  different start time.

The rules, each argued in §4:
- A lone animation on an idle timeline starts at its first keyframe, as CSS
  would.
- An animation that joins a busy timeline picks up the phase already in
  progress.
- A finite animation always ends on a cycle boundary, where it would
  normally end. When it joins late, its start is cut short, never its end.

## 1. The problem

LLP 1055 D5: "An animation starts when its name appears in a node's row".
`exact-motion` records `start: now` (`motion/src/engine/animate.rs`). Every
executor plays from that start:
- Apple sets `beginTime = t0 + start` (`SvgScene.swift`'s `CssAnimations`).
- The browser starts a CSS animation when the style applies.
- Linux samples `now - start` each frame.

So an animation's phase is set by when it mounted. That's correct CSS, and
it's what an author wants for one-off motion. It's wrong for animations that
mean "this is still going on". In that case the meaning is shared, so the
rhythm should be too.

The consumer is Lexy (`exact/lexy` in the Lexy repo):
- `status.contract`'s `pending` pulse (0.4 → 1, 800 ms, `infinite
  alternate`) on the lock and engine words;
- `specs.contract`'s `skeletonPulse`;
- the refreshing note's `spin`.

## 2. What other systems do

| System | How things are synced | Scoped by |
|---|---|---|
| CSS | No sync property. The usual tricks are a negative `animation-delay` of `-(now mod duration)`, or setting the animation's `startTime` through Web Animations | — |
| Web Animations | `startTime` on a shared `DocumentTimeline`. `new DocumentTimeline({ originTime })` makes a timeline with its own origin | the object |
| Core Animation | `beginTime` rounded down to a whole number of periods, or one shared epoch | — |
| Jetpack Compose | One `rememberInfiniteTransition` moved up to a parent and read by every indicator | the object (variable scope) |
| Flutter | One `AnimationController` shared; the shimmer cookbook recipe paints every skeleton from one ancestor gradient so they shimmer together | the object |
| Reanimated | One shared value driven by `withRepeat` | the object |
| SwiftUI | `TimelineView(.animation)` computing the value from the date: a wall clock | — |
| CSS Modules | `@keyframes` names are local to the file and renamed at build time; `:global()` opts out | the file |
| CSS scroll-driven animations | Named timelines are visible in the declaring subtree; `timeline-scope` widens that | the tree |

Two lessons:
- **Sync means working out the phase from a shared origin instead of from
  the instance's own start.** Every mechanism above does that.
- **The frameworks that scope sync well do it by identity, not by string.**
  You share a phase by holding the same clock. Compose, Flutter and
  Reanimated pay for that with a per-frame tick. This design keeps the
  identity and drops the tick.

## 3. Design

### D1. A `timeline` declaration

```
// spinner-lib/pulse.contract
timeline Pending

keyframes pending
  from opacity=0.4
  to opacity=1
```

- A top-level `timeline Name` declares a clock timeline. It takes no
  arguments.
- It is imported with `use`, like a `fn` or a component:
  `use Pending from "./spinner-lib/pulse.contract"`.
- Contract's `use` merges a file's declarations into one namespace; nothing
  is module-scoped today. A timeline joins that namespace with one
  difference from a `fn`: two files' `timeline Pending` are refused at `use`
  (`contract-use-duplicate`) even though their text is identical, where two
  identical `fn`s merge. So two libraries' timelines of one name meet as a
  compile error, never as one silently shared phase. (True module scope
  would be a change to all of Contract; see D7.)
- The timeline's id is its name. The plan needs no table: the row's text
  carries it (D2).

### D2. Joining it: `animation-timeline`

```
text "Unlocking" animation="pending 800ms ease-in-out infinite alternate" animation-timeline=Pending
```

- `animation-timeline` already exists (LLP 1057.003 D1): `auto |
  <dashed-ident>`, where a dashed ident is a tree-scoped drag timeline.
- This adds a third value, `clock(<ident>)`. In Contract it's written as the
  bare name; `contract_syntax::resolve_clock_timelines` rewrites
  `animation-timeline=Name` (on an element or in a `style`) into the literal
  `"clock(Name)"` before types and lowering, so neither knows clock
  timelines exist. A `style` naming no timeline is refused
  (`contract-timeline-unknown`). A computed value (a ternary choosing
  between timelines) is not taken in v1.
- The rewrite runs on the merged file in `sources::load`, so every entry
  point that reads it (compile, `contract symbols`, the Lean backend) sees
  the clock. On an element, a name the component binds (a prop, `inject`,
  `state`, `derive`, `resource`, `mutation`, `action`, or an `each`/`match`
  binder in scope)
  shadows a timeline of that name, as it shadows any other name: the ident
  stays a binding.
- The kernel row (`AnimationTimeline`) gains `clock()` and `name()`; the
  tree-scoped lookup only ever sees `name()`, so a clock never goes through
  it (1057.003 D4), and a `--name` keeps meaning exactly what it did.
- The row is one value per node, as it already was: every animation on the
  node joins the timeline. (CSS's `animation-timeline` is a list matched to
  `animation-name`; 1057.003 took a single value, and so does this.)
- An infinite animation is allowed on a clock (the lowering's
  `lower-timeline-endless` refusal is for drag timelines only).
- **Declared deviation (LLP 1001):** CSS has no clock timeline value. The
  web never puts `clock(...)` in a CSS property; it carries it as
  `--exact-animation-clock` and sets the start itself (D5).

### D3. The origin: set when the timeline goes from idle to busy

Each timeline has one number, its **origin**, in engine time:
- **Idle:** no animation on it is live (none attached; every finite one has
  ended). The next animation to join sets `origin = now`.
- **Busy:** an animation that joins keeps the origin. A paused member counts
  as live: it will resume on the timeline.

The engine stores each node's clock and each timeline's origin, nothing
else (`motion/src/engine/clock.rs`). "Busy" is a scan, when a play starts or
resumes, of the plays on nodes whose clock is that timeline. It never runs
per frame.

### D4. A synced play's start

For an animation with duration `d`, joining at `now`:

```
period = d × (direction is alternate or alternate-reverse ? 2 : 1)
start  = now − ((now − origin) mod period)
```

- `start` is the most recent cycle boundary on the timeline at or before
  `now`. A play on an idle timeline gets `start = now = origin`, which is
  CSS's behaviour exactly.
- `animation-delay` is kept and counted from `start`, as it is from an
  unsynced start. So a delay offsets an animation from its peers on purpose
  (staggered dots), and the stagger is shared too.
- Iterations count from `start`. With an iteration count of `n`, the play
  ends at `start + delay + n × d`, which is a cycle boundary. It ends on the
  same keyframe and in the same direction as an unsynced play would.
- **What this costs a late joiner, stated in the docs:** a synced
  animation with iteration count `n` may show between `n − 1` and `n`
  iterations (between `n − 2` and `n` for `alternate`, whose cycle is two
  iterations). It shows exactly `n` only when it starts on a boundary or on
  an idle timeline. The start is cut short, never the end.

### D5. Per host

None of these does any work per frame for a timeline.

- **Engine (`exact-motion`).** `AnimationPlay.start` is set by D4 instead of
  `now`. Everything after that (phases, fill, direction, sampling) is the
  existing LLP 1055 D5 timing model, unchanged. Under an agent-owned clock,
  the origin and starts are engine time, so tests stay deterministic and
  `clock settle` works as it does now.
- **Apple.** No new code. A lowered animation already gets
  `beginTime = t0 + start` from the engine's start (the `s` field,
  `svg_lower.rs`). Core Animation keeps playing it on the compositor;
  `batch.motion` stays false for a lowered infinite pulse (LLP 1055 D7,
  1055.001).
- **Kernel.** `MotionSync` carries each created or touched node's clock
  (`clocks`) and applies it before the node's animations, so the engine
  knows the timeline when a play starts.
- **Web.** The browser starts the CSS animation when the style applies.
  After each commit, `animationClocks` (`host/web/navigation.js`) sets each
  newly started or resumed `CSSAnimation`'s `startTime` once, to D4's start
  on `document.timeline`; it keeps its own origin and members per clock,
  as the engine does. Both web paths use it: the wasm path from `glue.js`,
  the JS target through `rt.js` (emitted only when a node can be on a
  clock). Under the agent clock, each agent's `register` takes the start
  from it instead. `motion-glue.js` already set `startTime` for drag
  followers, so the pattern was in the codebase.
- **Linux.** It samples `now − start` each frame for every animation
  already; only `start` differs.

### D6. Pause, removal, remount

- **Pause:** `animation-play-state: paused` holds a synced play like any
  other. **Resume rejoins the timeline's phase** (D4, at the resume time),
  rather than continuing from where it was held. A resumed indicator that
  ran out of step would defeat the point. The cost is a jump at resume,
  which is acceptable for a looping indicator.
- **Removal:** removing the name detaches the play (D3's bookkeeping).
  Adding it back joins again under D4.
- **A remounted or recycled node** (iOS `NodePoolIOS`, a list row scrolled
  back) is a new play: it rejoins the phase.
- **Timeline-bound plays** (1057.003) are not affected. A row names one
  timeline per animation, a drag one or a clock, not both.
- **Moving onto a clock:** a node whose row changes to `clock(Name)`, or
  whose drag timeline is unbound while it is on one, puts its running plays
  on that clock's phase as new ones would join (D4); a play it kept would
  otherwise hold the timeline busy out of phase. On an idle timeline that
  sets a new origin, now, even when all its plays are paused. An ended play
  stays ended.
- **Within a commit** the engine joins once every row is applied
  (`MotionSync::apply` holds the joins, `Engine::join_clocks` makes them).
  A member another node's row ended in the same commit is gone, as it is on
  the web, where `sync` runs after the DOM commit; a drag-bound play is not
  a member; a join reads the timing its row ends the commit with. So the
  start does not depend on the order the commit's nodes were applied in. A
  resumed play was a member while paused and keeps the origin it rejoins; a
  new one is not a member until it joins.

### D7. Keyframes names become module-scoped (proposed, not built)

- Today `keyframes` names are global across every loaded file
  (`contract/cli/src/sources.rs`: "CSS `@keyframes` are global by name").
  Two files that declare the same name are refused at compile time
  (`lower-keyframes-duplicate`). So two libraries that each ship a `pulse`
  can't be loaded into one app.
- Like CSS Modules, a `keyframes` name becomes local to its file and is
  imported with `use`.
- The plan's `keyframes` table stores the file-qualified id. The web host
  emits it as a generated name (`@keyframes` text unchanged), so the
  browser never sees a collision.
- This stands without D1–D6. Not built: `animation-name` is resolved at run
  time from text that can be computed, so per-file names are a runner
  change too, and it is really the question of module scope for all of
  Contract (fns and components merge the same way).

### D8. Defaults for loading indicators (proposed, not built)

- The CSS default stays: `animation-timeline` is `auto`, and an animation
  that names no timeline plays from its own start.
- The standard library declares one app-wide timeline,
  `use Activity from "exact:motion"`, for indicators that should all keep
  one rhythm.
- A component library's spinner or skeleton names `Activity` by default, so
  "synced by default" lives in the indicator, where the intent is, and not
  in the engine.
- Not built: Contract has no built-in modules. Until it does, an app
  declares its own (Lexy's `timeline Activity` in `model.contract`).

## 4. Decisions, and what they were chosen over

**Sync keyed by the keyframes name** (`keyframes pending synced`).
- Rejected.
- Keyframes names are global. Two libraries' `pending` would share a phase they
  never agreed to, or be refused outright.
- Sync is about a family of indicators, not a set of frames. Two different
  keyframes (a pulse and a shimmer) may want one rhythm.

**CSS's tree-scoped named timelines** (`--pending` with `timeline-scope`).
- Rejected.
- The indicators that should agree are in unrelated subtrees: a card's lock
  word, a sheet's spinner, another tab's skeleton.
- Sharing would need `timeline-scope` at the root, which makes the name
  global again.
- These timelines have no source node to be scoped under.

**One global sync switch** (every opted-in animation's phase from engine
time zero).
- Rejected.
- There's no isolation: a library can't keep its own rhythm.
- With a fixed zero, a lone indicator starts mid-cycle. D3's idle-to-busy
  origin lets a lone one start at its first keyframe.

**A shared clock that ticks** (the Compose and Flutter model: one driver
per frame, read by every follower).
- Rejected.
- It costs work every frame, and on Apple it would take lowered animations
  off the compositor and keep the display link awake (LLP 1047; LLP 1055 D7
  `quiescent()`).
- An origin gives the same result for free.

**Synced by default for every infinite animation.**
- Rejected.
- It changes CSS behaviour for every app, and one-off infinite motion (a
  breathing ring that marks a new row) is meant to be in its own phase.
- Defaults belong to indicator components (D8).

**A finite animation counted from the origin** (`start = origin`).
- Rejected.
- An animation joining a minute late would already be past its end and
  would show its fill straight away.

**`n` full iterations counted from the join** (keep the phase, end
`n × d` after joining).
- Rejected.
- It ends mid-cycle, partway between keyframes, not where the animation
  normally ends. Cutting the start short (D4) keeps the end where an author
  expects it.

**Round up to the next boundary** (wait, then play exactly `n`).
- Rejected.
- It holds the first keyframe for up to one period before anything moves.
  For a loading indicator that reads as lag at the moment it matters most.

**Align `alternate` to single iterations** (a tighter `n − 1` to `n` range).
- Rejected.
- The join could start on a reverse pass. With `forwards` fill, the end
  keyframe would then depend on the join time.
- A cycle of two iterations keeps the first pass forward and the end state
  fixed. The cost is the wider range.

**On the web, a computed negative `animation-delay`** instead of
`startTime`.
- Kept only as a fallback.
- The delay is fixed when the style is written, and the browser applies it
  later, so it's off by however long that takes.
- `startTime` is exact and is set once.

**Resume continues from the held time.**
- Rejected for synced plays (D6).
- It's CSS for an unsynced play. For a synced one it would leave the resumed
  indicator out of step for good.

## 5. Verification

**Tests in the branch**
- `motion/tests/it/clock.rs` (7): a lone play starts now and a joiner takes
  its phase, two nodes sampled equal across 20 s; off a clock, starts are
  their own; a finite joiner ends on a cycle boundary; a timeline left idle
  starts over; a paused member keeps it busy and a resume rejoins; mixed
  durations meet at common boundaries; removing a node forgets its clock.
- `kernel/src/timeline.rs`: the row's grammar (`clock( Pending )`, and
  refusals of `clock()`, `clock(--a)`, `clock(1a)`, `clock(a b)`).
- `contract/cli/tests/it/clock_timeline.rs` (4): the row and the
  `MotionSync` clocks from an element and a `style`; a `style` naming no
  timeline; a timeline declared twice in a file; import by name, and two
  files' `timeline Pending` refused at `use`.
- `host/web/tests/clocks.test.mjs` (headless Chromium over CDP; skipped
  without `CHROME`): two pulses mounted 300 ms apart within 1 ms of one
  phase; an unclocked animation keeps its own; a lone one starts near 0; a
  3-iteration `alternate` joiner starts on the 1600 ms boundary and ends at
  2400 ms; and `animation-play-state` still pauses and resumes after
  `startTime` is set, back in phase.

**Driven in an app (Lexy, iOS 27 simulator)**
- Agent clock: Unlock, then Start 300 ms later. Sampled every 100 ms over
  1600 ms, the two words' normalized opacity matched in every frame (largest
  difference 0.01) and both peaked 800 ms after Unlock began; unsynced,
  Start would have peaked 300 ms later.
- Real clock (UIKit, no agent), Start confirmed about 10 s after Unlock: 25
  screenshots, troughs and peaks together in every one.
- A lone pending word starts at its first keyframe; after the timeline goes
  idle, the next one starts at its first keyframe again.

**Driven on the web**
- Lexy on the wasm path (`build.mjs lexy-web --wasm`), Unlock then Start
  about 300 ms apart. Under the agent clock, the two words had the same
  opacity at every step, 400 to 1200 ms: 0.7, 0.92, 1, 0.92, 0.7. On the
  real clock, both animations had one `startTime` in Chromium (5330.4 ms;
  3386.7 ms via Playwright) and in WebKit 26.6 (2304 ms), and the same phase
  at every sample.
- A fixture app on both the JS target and the wasm path, on the real clock
  in Chromium and WebKit and on the agent clock in Chromium, with the same
  numbers on both builds:
  - a joiner shares the lone pulse's start; an unsynced pulse keeps its own;
  - pause gives `paused`, and resume rejoins the phase;
  - a spinner and a skeleton on one timeline share a start, and the
    timeline takes a new origin after it goes idle;
  - a finite `3 alternate` joiner starts on the 1600 ms boundary and ends
    at 2400 ms.
- Lexy itself doesn't build for the JS target (`x_formatDate` has no export
  in `rt.js`, a gap unrelated to clocks); its `web-build` is `--wasm`.

**Not verified**
- Firefox: Playwright's Firefox won't start on the build machine ("Could
  not find profile folder").
- A conformance fixture for the strict lane: one was tried
  (`interaction-gallery` data), but its page background differs between the
  JS build and the wasm oracle, so every screenshot differs (state, tree and
  layout all matched). It was left out rather than added failing.
- macOS and Linux driven in an app (both play the engine's start with no
  new code; covered by the engine tests only).
- Core Animation across backgrounding (a lowered synced pulse still in phase
  with a newly joined one after the app returns).

**Known gaps (reviews, not fixed)**
- Under the web agent clock, an author's pause and resume of an animation
  already registered is not tracked (the adapter's `held` is set once, as on
  main for every animation, LLP 1055 D10), so a resumed synced animation
  does not rejoin there. The real clock does (`animationClocks.sync`).
- Under the JS target's agent, a timer crossed by one seek registers its
  joiner before older finite members are sought, so a member that ended
  inside the jump can still count as busy for it.
- Two `animation` rows for one node inside one held commit (the engine's
  `hold_clock_joins` API, which no kernel path does with differing rows)
  record the first row's play indices: a reorder between them can join the
  wrong play.
- `contract symbols` accepts a program with timelines but has no
  definition or reference for a timeline: navigation from
  `animation-timeline=Pending` to `timeline Pending` is not there yet.

The native same-commit ordering gap round 1 left open was fixed in round 2
(D6, "Within a commit").

## 7. For review

What a ruling is needed on, in order of consequence:

1. **The deviation itself:** `clock(<ident>)` as a third
   `animation-timeline` value (D2), declared in LLP 1001, with the web
   setting `startTime` from script.
2. **Resume rejoins** (D6) rather than CSS's continue-from-held.
3. **Finite joiners show between `n − 1` and `n` iterations** (`n − 2` and
   `n` for `alternate`), cut at the start, never the end (D4).
4. **Names:** a clock's name joins Contract's single merged namespace, with
   identical declarations from two files refused rather than merged (D1).
   D7 (module-scoped keyframes) and D8 (a built-in `Activity`) wait on module
   scope and built-in modules.

**What the branch touches:** `motion/src/engine/clock.rs` (new) and
`animate.rs`; `kernel/src/timeline.rs`, `timeline/lookup.rs`, `motion.rs`;
`contract/syntax` (the declaration, `clock.rs`, the style-literal
exception), `contract/cli/src/sources.rs` (the `use` rule),
`contract/lower/src/svg.rs` (a clock is not timeline-bound); `host/web`
(`navigation.js`, `glue.js`, `src/css.rs`) and `host/web-js` (`rt.js`,
