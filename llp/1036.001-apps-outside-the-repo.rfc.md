# LLP 1036.001: Apps outside the repository

**Type:** RFC
**Status:** Draft
**Systems:** App resolution (`scripts/app.mjs` `resolveApp`), Apple build (`host/apple/build.mjs`, Hermes provisioning in `js/build.rs`), Web build (`host/web/build.mjs`'s root cargo calls), the root workspace (`Cargo.toml`, `Cargo.lock`, `snapback4/`), Scaffolding (`game/new.mjs`), Tooling pins (`package.json`, `rust-toolchain.toml`)
**Author:** Claude (Opus 5.5) for Charlie Cheever
**Date:** 2026-09-24
**Related:** LLP 1007 §7 ("An app outside this repo": its own cargo workspace, "exact2's profiles and the Taffy patch copied"); LLP 1036 F5 (script surface weight; deletion pressure per addition); LLP 1036.000 (app-owned Apple builds); LLP 1029 D1 (what the template scaffolds; Draft, no implementer); LLP 1027 D6 (the iOS lean Hermes recipe); `rules/NOT-DOING.md` (2026-09-23: Messages taken off as the Snapback4 consumer); `game/Cargo.toml` (the precedent for a workspace outside the root members)

## Summary

An app outside this repository consumes exact2 by path. Today its author
copies exact2's Cargo profiles, both crates.io patches, the toolchain file,
and a small `lib.rs`/`build.rs` by hand (LLP 1007 §7). Nothing checks the
copies. A TypeScript app on iOS also needs about 30 minutes of manual
Hermes provisioning, and the root lockfile pins a private git repository
that fails offline builds. This RFC proposes three things. Profiles are
**injected** by the scripts, so nothing is copied. Patches and the toolchain
are **generated** once by a `new` verb and **validated** on every run. The
two root-level blockers get owners: the private Snapback pin leaves the root
workspace, and Hermes provisioning moves into `host/apple/build.mjs`.

## Motivation

The Crew port report (2026-09-24), items D1–D4:

- **D1: the Bun pin.** `scripts/app.mjs` refused Bun 1.3.11 against the
  1.4.2 pin, and a private 1.4.2 was not enough on its own. Build steps start
  `bun` by name under Cargo, so they found the global Bun again. Commit
  f1fe9aac now puts the Bun running the scripts first on PATH
  (`scripts/app.mjs:141-151`) and names a side-by-side install in the
  refusal. Still open: outside apps run these scripts under Node too
  (`~/projects/weird-castle/exact.mjs:46` spawns `node`), while
  `host/web/dev.mjs:940` calls `Bun.TOML` (f1fe9aac's own profile check
  matches a table header instead, so it runs under Node). Which runtime an
  outside app uses is undecided (Q1).
- **D2: the private git dependency.** The root `Cargo.toml:20-25` pins
  `snapback4-{core,device,lang}` from `https://github.com/expo/snapback.git`
  for `snapback4/` and Messages' Snapback client. Messages' Apple, Linux and
  web crates depend on it. Every web build runs cargo in the root with
  `--locked --offline` (`host/web/build.mjs:98,105`, for the Markdown editor
  and text flow), so every app's web build needs that private source in
  Cargo's cache, including apps that never use Snapback. Yet NOT-DOING
  (2026-09-23) took Messages off as the Snapback4 consumer; Interview is the
  consumer, and it pins the Snapback repository itself
  (`~/projects/interview/apple/Cargo.toml:15,20`).
- **D3: Hermes provisioning.** `js/build.rs` expects `../ibex` beside the
  checkout (`js/build.rs:53`). It wants a full `build-hermes.sh --vanilla`
  (headers, macOS VM and `hermesc`, about 20 minutes) and, for iOS, two lean
  CMake builds under the *checkout's* `target/hermes-ios`
  (`js/build.rs:71-73`). The recipe for those exists only as prose in LLP
  1027 (lines 751-785). The pins disagree: the `js/build.rs` header says
  Hermes `6badada7…` (`js/build.rs:17-18`, matching ibex's receipt), while
  LLP 1027:758-759 says `e3371863…`, "updated 2026-09-19".
- **D4: no scaffold.** Seth copied `[profile.apple-dev]`, `[profile.release]`
  and the build-overrides, the Taffy patch, `rust-toolchain.toml`,
  `Cargo.lock`, a 13-line `lib.rs` and `build.rs`, and hard-coded a relative
  path to exact2. The list has grown. The root now patches **cosmic-text**
  too (`Cargo.toml:36-37`). Weird Castle patches only Taffy, so its lock
  resolves crates.io cosmic-text 0.19.0 for its Linux host
  (`~/projects/weird-castle/Cargo.lock:271-273`): it silently builds
  different text code. And since 4cfbf599 every non-production Apple build
  asks for `--profile apple-dev`, which Weird Castle never declared. f1fe9aac
  falls back to `release` with a hint (`host/apple/build.mjs:494-498`).

## Design

### D1 — Profiles are injected; nothing copies them

A profile is build policy the scripts own. `scripts/app.mjs` already passes
Cargo settings with `--config` (`wasmRemapFlags`, `scripts/app.mjs:124-137`).
When the app's workspace is not the root, the scripts read the root's
`[profile.*]` tables and pass each as `--config profile.<name>.<key>=<value>`.
An app's own declaration of the same profile, where present, is overridden,
so it cannot drift. Cargo reads `[profile]` from configuration, custom
profiles included; confirm that on the pinned toolchain (1.97.0) before
building on it. f1fe9aac's `release` fallback is then deleted.

*Rejected:* injecting `[patch.crates-io]` the same way. A patch changes what
the lockfile resolves. Plain `cargo test` in the app (no scripts) would
resolve a different graph than the scripts' `--locked` builds, and one of
the two would fail.

### D2 — Patches and the toolchain are generated once, validated every run

A `new` verb creates an outside app from a template. It generalises
`game/new.mjs` (42 lines, already works outside the repo) rather than adding
a script. It writes `Cargo.toml` with the root's `[patch.crates-io]` rewritten
to paths through the exact2 checkout, `rust-toolchain.toml` with the root's
channel, the host crates' `lib.rs`/`build.rs`, and an `exact.mjs` like
Weird Castle's. `resolveApp` (`scripts/app.mjs:203`) then compares the app
workspace's patch table and toolchain channel with the root's on every run
and refuses on a mismatch. The refusal names the missing or different entry
and prints the exact block to paste. A new root patch (cosmic-text's
arrival) then fails every outside app up front, naming itself, instead of
building different code.

*Rejected:* validation alone. It turns "fails deep in cargo" into "fails
early", but the first build still starts from hand copies.

### D3 — The exact2 checkout is named once

Weird Castle's convention stands: `EXACT2`, defaulting to `../exact2`
(`~/projects/weird-castle/exact.mjs:21`). The generated `exact.mjs` uses it,
and the generated `Cargo.toml` paths are written relative to it. A moved
checkout means re-running `new --update`, which rewrites only the generated
blocks.

### D4 — The private Snapback pin leaves the root workspace

`snapback4/` gets its own workspace, like `game/` ("its own workspace,
absent from the root `members`", `game/Cargo.toml:1-3`), carrying the three
git pins. Interview keeps depending on it by path. Messages' Snapback client
(`apps/messages/{apple,linux,web}` and its `snapback-*.ts`) is removed, as
the 2026-09-23 ruling implies. After that, no root cargo command needs a
private source.

*Rejected:* a cargo feature on the Messages crates. CLAUDE.md forbids
optional capability as a feature, and the lockfile would still pin the
repository.

### D5 — Hermes provisions itself, once per machine

When `host/apple/build.mjs --ios` builds an app with an `app.ts` and the
target's lean archives are missing, it builds them. It uses ibex's pristine
source cache (`~/.cache/exact/hermes/hermes-src`) and host-compiler import
(`build_host_hermesc/ImportHostCompilers.cmake`, used by ibex's
`scripts/build-hermes.sh` at lines 412 and 516), and builds only that
platform's three targets. The default archive root moves from
`<checkout>/target/hermes-ios` to a per-pin directory under
`~/.cache/exact/hermes/`, so every worktree and outside app shares one
build. The pin lives in one place, the `js/build.rs` header, and LLP 1027
cites it rather than restating it. `EXACT_HERMES_IOS_DIR` still overrides.

*Rejected:* a new `provision-hermes` script. It is a fifteenth driver
(LLP 1036 F5), and the build that needs the archives is the one that knows
they are missing.

## Cost and what it touches

- `scripts/app.mjs`: profile injection (≈15 lines) and validation (≈30).
- `game/new.mjs` becomes the general `new`, with an `app` template beside
  the game one.
- `snapback4/Cargo.toml` becomes a workspace root. The root `Cargo.toml`
  drops three workspace dependencies and a member. Messages loses its
  Snapback client (about ten files).
- `host/apple/build.mjs` gains the lean-archive build. `js/build.rs` changes
  its default root. LLP 1027 D6 loses its restated pin.
- LLP 1007 §7's "profiles and the Taffy patch copied" becomes "generated and
  checked".

## Open questions for Charlie

1. **Runtime for outside apps.** Bun only (weird-castle's `exact.mjs` moves
   to `bun`, and every script may use `Bun.*`), or Node too (every `Bun.*`
   call in the scripts needs a fallback)? Today it is both, inconsistently.
   **Ruled (Charlie, 2026-09-25): Bun only.** The trigger was
   `scripts/filesystem.mjs` importing `bun:ffi` for `flock`, which Node cannot
   load. weird-castle's `exact.mjs` now spawns `bun`; Node fallbacks and the
   comments that say Node runs these scripts can go.
2. **The Bun minimum.** The pin moved 1.3.12 → 1.4.2 in a bulk commit with no
   stated need. Is 1.4.2 a floor you want outside apps held to, or should the
   floor be the lowest version the scripts actually need?
3. **Snapback.** Remove Messages' client (D4 as written), or move Messages
   into the new Snapback workspace so it keeps working?
4. **Hermes.** Should D5 first try ibex's `download-hermes.sh` prebuilt
   bundle path, if it can serve the vanilla lean archives?
