## Summary

An agent's drive should be something it can **trust**, and should show it
**what moved**. Three changes do most of that, and none adds an operation:

1. The driver **refuses a build its own record shows is stale**, and says
   when it could not check (D1).
2. `screenshot` gains a **film form** that steps the clock between frames. It
   writes a contact sheet an agent can look at, or an animated PNG a person can
   play, and keeps every frame (D2).
3. The hosts' answers are **brought back to one answer**: the JS target's
   authored rows, Linux's targeted `tree`, and the glue tests that pin the
   clock (D3–D5).

Stage 2 (D6–D10) lists what needs a decision or a larger change first.

## 0. What the reviews changed

- **D7 is deduplication only.** Universal JSON forms would grow the API

## Stage 1 — built with this document

### D1 — A carrier refuses a build its own record shows is stale

Before launch, each desktop carrier asks the build what it was made from. When
an input changed, the carrier refuses. The refusal names up to three inputs and
gives the command that rebuilds:

```
linux build is stale: apps/caltrain/app.contract changed since
target/release/caltrain-linux was built; run cargo build --release -p caltrain-linux
```

Each rule reads a record the build already makes. These are detectors: passing
one is not proof of freshness.

| carrier | record | rule | on a change |
|---|---|---|---|
| Linux | Cargo's dep-info, `<bin>.d` | a listed source newer than the binary, or gone (Cargo's own rule); a build script's generated output is skipped, since another build can rewrite it with other variables without a source changing (the web build reruns Caltrain's Linux build script for its render pass), and its sources are listed themselves | refuse |
| macOS, sample host, iOS simulator | the bundle's `receipt.json` | `pendingBuildInputs` (sha256 per Rust and Swift input, ~150 ms); then, by mtime against the receipt, the app's own files the receipt leaves out on purpose, outside its `apple/`, `linux/`, `web/` crates, and the Rust archive's dep-info (`lib<crate>.d`), which names what built it — the compiler and the bake — where the receipt names only what it links | refuse |
| web, built `dist/` | the build marker's mtime | the app's own files, outside its `apple/` and `linux/` crates | refuse |
| web, built `dist/` | the build marker's mtime | the roots the target's build reads (`host/web-js/`, `contract/`, `plan/`, `kernel/tables/`, `host/web/*`; the wasm target: the runner, kernel, motion, num, host crates) | warn: `may be stale (unverified)` |

- `EXACT_LINUX_BIN` or `EXACT_MAC_BIN` names the binary: the carrier prints
  `freshness unchecked` and launches it.
- A served web page (`--url`) is its server's concern. A native `--url` still
  launches a local binary, so that binary is still checked.
- `--plan` replaces the baked plan but not the host binary, which is still
  checked.
- A phone (`--device`) has its own install step and is not checked.
- No new flag and no environment switch.

*Rejected:* building on demand inside the driver. A cold macOS build is three
minutes, and `agent.mjs macos tree` would sometimes take three minutes without
saying why. Also rejected: a warning where the evidence is exact, because the
harm is a false pass, and a warning is what agents skip.

### D2 — `screenshot <path> over <ms> every <ms>`: film on the agent's clock

```
screenshot motion.png over 600 every 50     # a contact sheet: 13 frames in a grid
screenshot motion.apng over 600 every 50    # an animated PNG, 50 ms a frame
```

The driver takes a frame, moves the clock by `every`, and repeats. Frames fall
at 0, `every`, 2·`every` … ≤ `over`, and the clock lands at the last frame.
Each frame is the carrier's ordinary `screenshot`, so every carrier has film.
The frames are assembled with `scripts/png.mjs`:

- **the sheet** (any path but `.apng`): at most 6 columns, a 1 px gray gap,
  read left to right, shrunk by a whole factor until it is at most 2,048 px
  wide. This is what an agent looks at;
- **the animated PNG** (`.apng`): each frame shown `every` ms, looping. A
  viewer without APNG shows the first frame;
- **the frames**: kept at full size in `<path>.frames/`, named
  `<i>-<clock>ms.png`.

The reply is one `screenshot` reply with `frames`, `every`, `over`, `at` (each
frame's clock), `dir`, `form` (`sheet` or `animated`), `w`, `h` and the tags.

Limits and failures:

- `every ≥ 1`, at most 240 frames and 64 M decoded pixels, and one frame size
  throughout;
- refused under `--timing platform`;
- the frames must be 8-bit non-interlaced PNG (`png.mjs`). Web, macOS and
  Linux produce that; iOS is unverified;
- a failed step (a timer's refusal at `clock`, a capture error) stops the film.
  The frames already taken are written, and the error names them.

This is a form of `screenshot`, not a tenth operation. It is not record/replay
(DEFERRED): nothing is recorded but pixels, and nothing replays. Film shows
what the agent's clock drives. Host I/O (an image decoding, a video playing)
still moves on its own, as LLP 1012 §2 says.

### D3 — Nested class rules are read where they are

The JS target nests every class rule inside `#exact-root#exact-root { & .cN {
… } }`. Two readers matched only top-level `.cN`. Both now walk nested rules
and match `.cN` or `& .cN`:

- `host/web-js/agent.js` `declared()`: `layout <node>` reports `authored` and
  `dynamic` rows again;
- `host/web-js/flow.js` `classHeight`: a class's static `height` makes a
  paragraph's height definite again, for text around shapes.

The rows keep the browser's own names and values; D8 is how they meet the
runner's.

### D4 — Linux answers `tree` as asked

`accessibility_tree` forwards the request (target, `shallow`) to the runner,
passes a refusal through unchanged, and annotates what comes back. A test
covers the subtree, `shallow`, the whole tree, and three refusals (a missing
target, `shallow` without one, a non-boolean `shallow`).

### D5 — The glue's clock tests pass, and test what broke them

The `host/web/agent.test.mjs` fixture binds `imageHold` as null (no animated
image loaded), so the four clock tests reach their assertions again. A fifth
test holds an animated image's `ready()` and checks that `clock` answers only
after it lands.

## Stage 2 — proposed, each waiting on the decision named

- **D1b — The web build records its inputs.** `.exact-build.json` gains the
  inputs the JS (or wasm) build read, by digest, as the Apple receipt has them.
  The web's warning then becomes a refusal on exact evidence. *Decision:* none
  beyond review; it changes one build marker's shape (`builtAppMatches` ignores
  extra fields).
- **D6 — Source maps from the bake** (F6). *Ruled and built for the runner's hosts; §Decisions.* A development bake writes
  `app.plan.map.json` beside its receipt, in `target/`, never in the product.
  The driver finds it through the receipt, and the digest in the reply decides
  compatibility as today. On the JS target this also needs `site` (from the
  node's `data-s`) and the plan's digest. *Decision:* that a development bake
  writes one more file. DEFERRED admits the map "never in a bake"; this puts it
  beside one.
- **D7 — One grammar table** (F8). The CLI's forms are declared once (words,
  argument parsing, one usage line), and `main()` and both usage texts come
  from it. No new forms. *Decision:* none; it removes a second copy.
- **D8 — Rows as two values, one vocabulary of names** (F4). The JS target
  reports each row under the runner's name, with the authored value and the
  browser's computed value side by side. The runner names `font_family` rather
  than giving an index. The conformance run then compares `layout <node>`
  between hosts by meaning. The page's view numbering and the listing's
  rounding follow the runner's. The viewport is ruled and built (900; §Decisions).
- **D9 — The glue tests in the async lane** (F5). *Ruled and built; §Decisions.* The six `host/web/*.test.mjs`
  files (174 tests, ~7 s) join `scripts/async.mjs`, not the five checks.
  *Decision:* Charlie's. It adds a step to a lane (RULES §Agents).
- **D10 — LLP 1012 back to a reference** (F8). The iOS crash investigation and
  its evidence paths move to `issues/`, and LLP 1012's Summary returns to the
  operations, keeping one line with a link. *Decision:* none; it edits a
  Draft.
- **Not proposed here:** a platform accessibility read (what VoiceOver or
  AT-SPI receives) as a form of `tree`. It is the right next observation, but it
  needs four host implementations and a DEFERRED line ("accessibility audit" is
  refused; a read is not an audit), so it earns its own RFC. Attached sessions
  stay LLP 1012.000's.

## Decisions (Charlie, 2026-09-30)

On the three stage-2 questions put to him ("1. 900 seems fine. 2. ok rec fine.
3. k rec good."):

- **D8's viewport: 900.** Every desktop carrier (web, macOS, Linux) drives at
  420×900 unless a drive names a size (`scripts/agent.mjs` `VIEWPORT`). A phone
  or simulator stays its device's size. The conformance run's own 900 for the
  Linux host (`WEB_SIZE` in `host/web-js/conform.mjs`) is gone. The host
  binaries' own defaults outside the agent are unchanged. The rest of D8 (rows
  as two values, `font_family` by name, the page's view numbering and rounding)
  is still stage 2.
- **D9: the glue tests join the async lane.** `scripts/async.mjs` runs the six
  files by name as its `glue` step (174 tests, 5.5 s), and names each failing
  test in what it files.
- **D6: a development bake leaves its source map beside its plan.** Built as
  follows:
  - `bake/src/receipt.rs` `source_map` compiles the app's contract again and,
    when its nodes are the baked plan's, writes `OUT_DIR/app.plan.map.json`,
    keyed by the baked plan's digest. It writes only at `development` trust,
    never inside a product, and a map that cannot be made is absent rather than
    a failed build.
  - `scripts/app.mjs` copies the map into the bake output as
    `<platform>-<target>.plan.map.json`.
  - The driver gathers every map it can find (the Linux binary's through its
    dep-info, each platform's in the bake output), and the reply's
    `planDigest` picks the one that describes the running plan
    (`sourceMapReaders`).
  - The JS target's half, the same day
    (`issues/closed/20260930-web-js-node-source.md`): a development JS build
    (`host/web-js/build.mjs` without `--production`) passes `--sites` to the
    emitter. Each element then carries `data-site`, its plan node, set on
    creation and on adopting a rendered page alike, and the contract it
    compiled leaves `app.plan.map.json` beside `dist/app.plan`. The page's
    `layout <node>` reports the site, and the driver stamps the digest of the
    plan it serves. A production build has neither: the bytes on every node
    are a development cost only. Caltrain's `change-station` is site 24 on
    every host, `app.contract:223:13`.

## What this does not change

The nine operations, the clock rules, the transcript form of existing replies,
the smoke's assertions, and the five checks. Film's reply is a `screenshot`
reply, one JSON line as the others are (LLP 1012 §7).
