## Summary

The vocabulary a document needs, specified once and meaning the same thing on
every host, following CSS and HTML.

- **Part A** (phase 1): a `head` element, semantic elements, document scrolling,
  route policy fields.
- **Part B** (phase 2): media variants and required placeholders.

The web lane already lowers heading levels to `h1`–`h6` and sets `lang`
(2026-09-23). This LLP gives authors the rest.

## Part A

**D1 — `head` is an element.**
`head title=… description=… image=… canonical=… robots=…`, placed anywhere in
a route's view. It is not visual and takes no space. The innermost active
`head` wins, field by field. The values are ordinary expressions, so an article
page can say `head title=post.title description=post.summary`.

Per host:
- **Web:** the page renderer writes it into `<head>` (LLP 1048.000 D7), and the
  host keeps `document.title` and the meta tags in sync at runtime.
- **macOS:** `title` is the window title.
- **iOS:** `title` is the scene title (the app switcher, iPad windows).
- **Linux:** `title` is the window title.

In the kernel it is a new node type with string props, carried like any other
node and excluded from layout (schema entry).

**D2 — Semantic elements.** New tags, each an HTML element on the web and a role
or trait natively:
- blocks: `p`, `ul`, `ol`, `li`, `blockquote`, `pre`, `figure`, `figcaption`,
  `form`, `label`, `h1`–`h6`;
- inline runs inside `text`: `strong`, `em`, `code`.

Rules:
- **Layout is unchanged.** Each element's defaults are a bare `div`'s (the
  kernel's), and the web host resets the browser's defaults for these elements
  (margins, padding, list style, font) in `index.html`'s reset block. Choosing
  `p` over `column` changes meaning, not layout. Authors style them like any
  node.
- **Lists.** `ul`/`ol` require `li` children (a compile error otherwise). List
  markers are opt-in (`list-style-type`), as the reset removes them.
- **Forms.** `label for=<id>` associates with an input by `id` (the kernel has an
  `id` prop). `form submit=action` gives Enter-to-submit and a submit button
  with the semantics the web gives them. There is no navigation and no action
  URL — a submit is an event, not a request.
- **Native accessibility.** Headings, lists, list items, block quotes and
  figures map to their AppKit, UIKit and Linux accessibility roles.

**D3 — see Part B.**

**D4 — Document scrolling.** When a view's root is a full-size `scroll`, it
becomes the document on the web: `html`/`body` scroll instead of an inner
`div[data-scroll]`, so printing, `#id` anchors, text fragments, scroll
restoration and the mobile browser's collapsing toolbar all work. Native is
unchanged; the root scroll is the window's. An explicit `scroll document=false`
keeps today's inner scroller for app-shell layouts that need it.

**D5 — Route policy fields.** A route declaration (LLP 1038 D2) gains optional
fields:
- `render=build|cached|request|client` (LLP 1048 D2);
- `activate=eager|idle|visible|interaction|never` (LLP 1048.001 D4);
- `pages=<source call>` for parameterized routes (LLP 1048.000 D2);
- `revalidate=<seconds>` for `cached` (LLP 1048.002 §5).

Each has an inferred default, so most routes declare none.

## Part B

**D3 — Media variants.** A style row can vary with media conditions, as in CSS:
`min-width`/`max-width` (in px), `orientation`, `hover`, `pointer`,
`prefers-reduced-motion`, `prefers-contrast` and `print`. (`prefers-color-scheme`
is already covered by `light-dark()`.) Variants are declared on a `style` class:

```
style Grid
  display="flex" flex-wrap="wrap" gap=24
  media "(max-width: 640px)"
    flex-direction="column" gap=12
```

- **Web:** emitted as real `@media` rules in a generated stylesheet for classes
  with variants. Elements carry their class; the unconditional rows stay inline.
  One rendered HTML file is then right at every width (LLP 1048.000 D4).
- **Native:** style resolution evaluates the conditions against facts the
  system already holds — the runner's viewport (LLP 1039) and the kernel's
  `Env` — picks the matching rows, and re-resolves when those facts change. A
  variant's rows are ordinary rows, so layout is the kernel's as always.
- **Compiler:** conditions are parsed and checked against a fixed grammar (a
  subset of Media Queries 4, listed in the spec's corpus). An unknown feature is
  an error, not a silent no-op.
- **Why here:** this is the responsive mechanism for documents, instead of
  branching on `exactViewport()` in the runner — which remains for layouts that
  truly differ in structure.

**D6 — Required placeholders.** A resource whose source provenance is later than
`build` (LLP 1048 D3) needs a placeholder, the value it shows while pending:
`resource cart = cart(user) as shape Cart else emptyCart()`. Shapes with an
empty value (lists, options) have an implicit one. A missing placeholder is a
compile error naming the resource, so a boot never refuses an unanswerable
resource (LLP 1048 D6).

## Verification

- **Corpus:** a fixture per element, attribute and media feature, compiled and
  booted, with a rejection fixture per new diagnostic.
- **Parity:** every semantic element lays out identically to `column`/`row`
  equivalents on web and native (kernel vs Chrome, as in the 2026-09-22 kernel
  parity harness). Media variants resolve identically on web (`@media`) and
  native (kernel) at 375, 768 and 1280 px.
- **Accessibility:** the CDP tree shows headings, lists, list items, figures and
  labelled form controls. The macOS/iOS accessibility attributes show their
  roles.
- **Titles and print:** the window title follows `head title` on macOS and iOS.
  Printing a document-scrolling page produces every page, not the first
  viewport.
