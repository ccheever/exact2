## Summary

The vocabulary a document needs, meaning the same thing on every host and
following HTML and CSS — including their defaults.

- **Part A (phase 1):** a `head` element, semantic elements, document scrolling,
  route policy fields, and width variants.
- **Part B (phase 2):** the remaining media features and required placeholders.

## Part A

**D1 — `head` is an element.**
`head title=… description=… image=… canonical=… robots=…` goes anywhere in a
route's view. It isn't visual and takes no space. The innermost active `head`
wins, field by field. Values are ordinary expressions:
`head title=post.title description=post.summary`.

Per host:
- **Web:** the document's `<head>` (LLP 1048.000 D3), kept in sync with
  `document.title` and the meta tags at runtime.
- **macOS:** `title` is the window title.
- **iOS:** `title` is the scene title.
- **Linux:** `title` is the window title.

In the kernel it's a new node type with string props, excluded from layout.

**D2 — Semantic elements, with their HTML defaults.** New tags, each an HTML
element on the web and a role or trait natively:
- **Blocks:** `p`, `ul`, `ol`, `li`, `blockquote`, `pre`, `figure`,
  `figcaption`, `form`, `h1`–`h6`.
- **Inline:** `label`, and `strong`, `em` and `code` as runs inside text.

Rules:
- **Defaults are HTML's.** A bare node keeps a bare `div`'s defaults, but a
  declared semantic element takes its element's defaults from the HTML UA
  stylesheet: `p` and `blockquote` margins, list indentation and markers,
  `li` as `display: list-item`, `pre`'s monospace and preserved whitespace,
  `strong`'s weight, `em`'s italics, `h1`–`h6` sizes and margins, `label` as
  inline. The kernel schema carries these as default rows per tag, so every host
  renders them the same way. The web host doesn't reset them. Authors override
  them like any row.
- **Content models.** Children follow HTML's content models where the parser
  would otherwise restructure them. `p` holds only inline runs; `ul` and `ol`
  hold only `li`. A violation is a compile error naming the node.
- **Forms.** `label for=<id>` associates with an input by `id`. `form submit=`
  gives Enter-to-submit and a submit button with the semantics the web gives
  them. A submit is an event, not a request. What a `form` does before the
  runtime starts is LLP 1048.001 §4.3.
- **Native.** Headings, lists, list items, block quotes, figures and labels map
  to their AppKit, UIKit and Linux accessibility roles; native layout uses the
  same default rows.
- **Deviations.** Where a native host cannot reproduce a default exactly
  (marker glyphs, for example), the deviation is declared in LLP 1001 §1, not
  left implicit.

**D3 — Width variants (phase 1); other media features (part B).** A style class
can vary its rows by media condition, as CSS does:

```
style Grid
  display="flex" flex-wrap="wrap" gap=24
  media "(max-width: 640px)"
    flex-direction="column" gap=12
```

- **One cascade.**
  - On the web, a class's base rows and its variants go in one generated
    stylesheet, in declaration order. Elements carry their class, so a variant
    overrides its class's base rows as `@media` does.
  - Inline style carries only a node's own authored rows and bindings. They win
    over class rows, as inline style wins in CSS.
  - Natively, style resolution applies the same order: class base rows, then
    matching variants, then the node's own rows.
  - r1's example would have put base rows inline, where no `@media` rule could
    override them.
- **Structure.** A variant can't change the tree, but it can set `display`. For
  structural switches — Interview's tabs versus rail — both structures render,
  and variants choose which is displayed. That makes one document right at every
  width.
- **Facts.**
  - Width and height come from the runner's viewport (LLP 1039).
  - `orientation` derives from them.
  - `hover`, `pointer`, `prefers-reduced-motion` and `prefers-contrast` are new
    facts each host reports, as the viewport is reported today.
  - `print` applies on the web; native hosts ignore it.
- **Grammar.** Conditions are checked against a fixed subset of Media Queries 4,
  listed in the corpus. An unknown feature is a compile error.
- **Phasing.** Phase 1 ships width conditions (`min-width`, `max-width`),
  because Interview's layout needs them; part B adds the rest.

**D4 — Document scrolling, explicitly.** `scroll document` marks a view's scroll
container as the document on the web: `html` and `body` scroll instead of an
inner `div[data-scroll]`. That makes printing, `#id` anchors, text fragments,
scroll restoration and the mobile browser's collapsing toolbar work.

It is explicit, not inferred, because layouts like Interview's scroll inside a
height-constrained container (`app.contract` ~637). A heuristic would miss them,
or change app shells that need an inner scroller. Natively, the document scroll
container is the window's.

**D5 — Route policy fields.** A route declaration (LLP 1038 D2) gains optional
fields:
- `render=build|cached|request|client` (LLP 1048 D2);
- `activate=eager|idle|visible|interaction|never` (LLP 1048.001 D4);
- `pages=<source call>` for parameterized routes (LLP 1048.000 D2);
- `revalidate=<seconds>` for `cached` (LLP 1048.002 §5).

Each has an inferred default, so most routes declare none.

## Part B

**D6 — Required placeholders.** A resource whose source's stage is later than
`build` (LLP 1048 D3) needs a placeholder — the value it shows while pending:
`resource cart = cart(user) as shape Cart else emptyCart()`. Shapes with an empty
value (lists, options) have an implicit one. A missing placeholder is a compile
error naming the resource, so a boot never refuses an unanswerable resource.

**D3 (continued)** — `orientation`, `hover`, `pointer`,
`prefers-reduced-motion`, `prefers-contrast` and `print` conditions.

## Verification

- **Corpus:** a fixture per element, attribute and media feature, compiled and
  booted, plus a rejection fixture per new diagnostic (content models, unknown
  media features).
- **Defaults:** every semantic element's default rows lay out identically in the
  kernel and in Chrome, using the 2026-09-22 kernel-vs-Chrome parity harness.
  Declared deviations are listed.
- **Cascade:** width variants resolve identically on the web (`@media`) and
  natively at 375, 768 and 1280 px, including a node whose own inline row must
  win over a variant.
- **Accessibility:** the CDP tree shows headings, lists, list items, figures and
  labelled controls, and the macOS/iOS accessibility attributes show their
  roles.
- **Titles and print:** the window title follows `head title` on macOS and iOS.
  Printing a `scroll document` page produces every page, not only the first
  viewport.
