## Context

[confirmed] The supplied handoff requires upstream mobile pin365aa87982's V2 thread grouping and desktop clone client reuse. Native Home and thread selection have been driven. This document does not assert full screen parity or milestone completion.

[observed] The shared shell, fleet, sidebar capabilities, settlement, snooze and sorting functions already describe thread state. Upstream mobile presents that state with different section ordering, labels, typography and collapsed shelves. Its use-thread-list-v2-shelf-preferences persists shelf booleans on the device.

## Decision

[inferred] Project the shared shell into mobile rows without mutating it or creating another reducer. [home.ts](../examples/t3-code/mobile/home.ts) consumes the focused shell and synchronized fleet shells. Render keys include the environment and thread identities; action IDs preserve the shared client's fleet routing. Capabilities are evaluated per environment.

[observed] Rows appear in pinned, active, working, snoozed and settled order. Working is off until enabled in loaded preferences. Shelves are initially collapsed; a selected thread remains visible in a collapsed or paged shelf. Settled starts with10 rows and grows by25. Mobile uses Goal for an active working goal, Done for unseen completion, and elapsed labels beginning with <1m. Query results retain environment ownership.

[inferred] [home-state.ts](../examples/t3-code/mobile/home-state.ts) exposes exactly the Contract resource shape rather than returning internal projection fields. Root owns the elapsed clock, search state, pagination, selection commands and refresh dependencies. All native/client requests remain root resources or mutations.

[observed] [T3MobilePreferences.swift](../examples/t3-code/mobile/modules/apple/T3MobilePreferences.swift) now owns `mobile-preferences.json` for both Home shelves and mobile Settings. Its `mobileHomePreferences` and `mobileToggleShelf` operations preserve the four Home booleans and existing response shape. Appearance, keyboard, follow-up and project-grouping patches use the same serialized owner and atomic write. A malformed file fails visibly rather than overwriting saved state. Agent launches use the existing app-scoped scratch storage boundary. [confirmed] The implementation session selected replacement without a legacy migration because the previous Home-only store was unshipped and had not been launched outside temporary tests. These are mobile presentation preferences, separate from shared protocol preferences. The new helper has been typechecked; its persistence and runtime consumers still need driven verification.

## Rendering

[observed] [home.contract](../examples/t3-code/mobile/home.contract) uses a virtualized list and explicit mobile text roles from1107.002. Its list is the route's scroll surface. Collection padding-bottom is refused by the current compiler; bottom clearance is applied to the last measured row. The source native toolbar and safe-area-dependent clearance are still being integrated. A temporary root toolbar and120-point clearance are not parity implementations.

[inferred] The native toolbar may use UIKit through the existing app module API, with selections sent to authored actions. It must not own a separate thread model or navigation stack. Both phone and iPad controls consume the same project/environment projection.

## Alternatives

[inferred] A second mobile reducer would duplicate protocol and event ownership. Direct desktop sidebar rendering would preserve desktop labels, spacing and shelf behavior. Both conflict with the handoff; a mobile projection over the shared model keeps their ownership separate.

## Move up/down

[observed] Pinned `threadOrder.ts`, `threadListV2.ts:230–270` and `useThreadListActions.ts:582–751` plan adjacent moves against the full cross-environment pinned or active section. Search and project/environment filters do not change neighbors. Archived and subagent threads are excluded; settlement and snooze membership use each environment's capabilities. Queued messages keep a settled thread in its card section. Working beta disables active ordering while pinned ordering remains available.

[decision] [home-order.ts](../examples/t3-code/mobile/home-order.ts) reuses the shared fractional-key planner and computes all row availability once per section. A serializable client-owned pending order keeps the requested display order until commands finish and every assigned key appears in the canonical shell. Membership, anchor or unrelated key changes cancel the hold. Applying the pending order after filtering preserves the full section's relative positions. No timer, request, subscription or second shell reducer belongs to this helper.

[observed] [home-actions.ts](../examples/t3-code/mobile/home-actions.ts) captures the current Home/sidebar route, endpoint origins and generations, then reads fresh operation grants for every required environment before the first write. Each assignment allocates its command ID through that environment's existing bridge. Commands execute in order. A later refusal preserves earlier canonical writes and cancels the display hold. An uncertain transport outcome blocks another Move until the exact requested key appears, or the thread disappears from the connected original environment. Existing row locks and uncertain ordinary-action guards also apply. Root's action signature and closed result shape stay unchanged.

[observed] [home-state.ts](../examples/t3-code/mobile/home-state.ts) supplies the prepared order to Home and each projected menu. Move up/down use the source titles, symbols and disabled boundaries before the Pin item. The sidebar native menu receives those same items as JSON; it does not generate a second action list.

[observed] The Home controller/projection suite passes 47 tests and 274 assertions. Strict TypeScript checks pass. A separate executed comparison imports the actual pinned section, planner, availability and pending-order functions and passes 13,898 cases. These checks cover filtered neighbors, capability changes, all-environment grant denial, sequential partial success, both ACK/shell arrival orders, route departure, changed generation, origin isolation and unknown-write suppression. Evidence and exact source references are in `.context/t3-code-ios/home-operations/move/README.md`. Parent native phone Move down and Move up change actual server keys and restore the requested row order. On iPad, Move down through the new sidebar menu preserves the selected workspace and its unsent draft. The initial keyless section requires the source planner to assign keys to all three rows. AX, screenshots and before/after shell reads are under the same receipt directory. This establishes ordinary adjacent moves, not Arrange or swipe parity.

[observed] The projection accepts and tests queued-thread keys, but the production mobile offline outbox owner is still deferred. Server run queues and queued edits do not substitute for that source input. Wire the actual outbox keys when that flow is implemented.

## Visible sidebar row menus

[observed] The ordinary installed iPad app displays the persistent sidebar through the public tabContainer. Authored contextPopover still refuses that pane as an inactive navigation route. Physical long presses selected the row rather than showing its menu. GAP007 records the source eligibility check and native evidence; the app does not change host navigation or menu rules.

[decision] [T3MobileHomeMenus.swift](../examples/t3-code/mobile/modules/apple/T3MobileHomeMenus.swift) adds UIContextMenuInteraction to the existing sidebar row through the public ExactElement hatch. It builds UIMenu from the existing HomeMenuItem projection, including time subtitles, checks, disabled children and destructive actions. Each leaf retains the original authored action target resolved through ExactRoute.element(id).click. The root remains the command owner. Phone Home keeps its authored contextPopover. No private host types or alternate transport are used.

[observed] Immutable configuration, opening token, public route identity, row liveness and current sidebar visibility guard menu admission and callbacks. Configuration changes and hide/end dismiss the open menu. Teardown removes only the interactions and recognizers recorded when installing the native interaction before allowing row reuse. Actual Swift typechecking and21 decoder/cleanup checks pass; the cleanup model does not prove UIKit recycling. Independent review found no additional blocker.

[observed] Normal iPad native checks open the menu on an unselected thread while retaining the other selected workspace. Move down dispatches the existing root operation and preserves its draft. Snooze shows separate muted time subtitles. The final installed build opens the menu after sidebar hide/show and dispatches Rename; Cancel returns to the same workspace and draft. Ordinary short taps still open a thread. Receipts are `.context/t3-code-ios/sidebar-home-menus/`. Actual large-list recycling, held-menu route/reconnect changes, resize and complete light/dark pixel acceptance remain open. This hook also installs in agent sessions; no authored sidebar fallback or performance parity is claimed.
