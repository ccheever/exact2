## Summary

Restart Contract as a visibly non-JavaScript plan language: keep the indentation tree, `derive`, checked `writes`, mandatory keys, primary arguments, `testId`, closed values, and the compiled first frame; add real component instances with local state, typed slots, compile-time context, named styles, action branching, and executable tests over the eight-operation agent API. Split reactive reads from occurrences: `query` re-evaluates from arguments; `mutation` runs only at an explicit `send`. Actions remain synchronous reducers and never `await`. Small pure helpers are written in Contract; all other application computation crosses the one Rust data seam. CSS names and values are exact, aliases are deleted, and the compiler checks them before bake.

Contract should **not** look like React/JSX: borrow React’s useful composition expectations and the web’s true vocabulary, but do not borrow syntax that falsely promises JavaScript, hooks, closures, DOM refs, or arbitrary effects.

## The shape

### Surface

One route remains one `.contract` file. `use` imports only Contract declarations; JavaScript and TypeScript are not importable.

```text
file      := { use | enum | shape | data | context | fn | style | component | test }
component := "component" Name ["(" params ")"] NEWLINE INDENT member* view DEDENT
member    := state | derive | query | mutation | action | timer | provide
action    := "action" Name ["(" params ")"] effect-row NEWLINE INDENT stmt+ DEDENT
effect-row:= ["writes" names] ["sends" names] ["resets" names] ["refreshes" names]
stmt      := assignment | if | match | action-call | send | reset | refresh | command
node      := tag | component-call | when | match | each | status
```

The tree keeps indentation and primary-argument sugar:

```contract
text "Coffee" font-size=15
button "Post" press=submit testId="post"
each message in messages key=message.id
  MessageRow(message=message)
```

Tags remain the small kernel-facing set. CSS attributes use CSS spellings:
`font-size`, `background-color`, `border-radius`, `align-items`,
`box-sizing`. `size`, `background`, `radius`, `align`, React Native names,
and duplicate camel-case aliases do not exist. `testId` is the one deliberate
application-level name.

The schema table supplies each attribute’s type and default. `"100%"` is a
length, `"#ffffff"` is a color, and `true` is neither; `width=true` is therefore
a compile rejection. Dynamic CSS values must retain the corresponding closed
type.

Expressions are deliberately not JavaScript:

- `bool`, `number`, `string`, enums, shapes, `list<T>`, `option<T>`, and typed action references.
- Boolean-only conditions; no truthiness.
- `and`, `or`, and `not`; no `&&`, `||`, or `!`.
- `if … then … else …` and exhaustive `match`.
- No `null`, `undefined`, `?.`, `??`, ternary operator, implicit conversion, or open object.
- Equality is structural over closed values.
- String interpolation is `"Zone {station.zone}"`.
- Indexing that may miss returns `option<T>`.
- Non-finite arithmetic is a named, transactional refusal.

A top-level `fn` is pure, monomorphic, non-recursive, expression-only, and
compiled to plan bytecode. It covers price strings, palette selection, and
small projections without a roster edit or sidecar. Sorting, geodistance,
storage, network access, and other application computation remain data-source
work.

### Reactivity and effects

`state` is mutable storage. `derive` is a pure, automatically tracked
calculation. Dependencies are never authored.

Every component may own `state`, `derive`, and `action`. A local slot’s identity
is its declaration plus the component call address and enclosing `each` keys.
Leaving an arm destroys that instance; re-entering starts it again. Reordering
a keyed row retains it. Dev reload carries it only when qualified name, type,
call address, and keys still match.

Only an application root may own `query`, `mutation`, and `timer`. This prevents
a row component from silently opening N requests.

Actions are synchronous atomic reducers. They may branch and match, but never
loop or `await`. Handler arguments are evaluated at dispatch, as in LLP 1005.
Nested action calls join the same transaction. Authored writes, sends, resets,
and refreshes are checked; reads, calls, commands, and ambient inputs are
derived transitively.

A timer has one form:

```contract
timer ticker every 1000 -> tick
```

There is no general mount task or dependency-watching effect.

### Data

One block declares the application-facing seam once:

```contract
data
  query stations(Location) -> list<Station>
  mutation login(string, string) -> Session
```

Rust implements the names and returns closed plan values. Contract is the type
authority; bake and the runner validate every answer against it. There is no
generator, TypeScript declaration, or metadata sidecar.

A `query` is keyed by its current arguments. Argument change or explicit
`refresh queryName` requests it once. It retains its compiled or last value
while pending. Bake requires every initial query to answer synchronously; a
`Later` answer is a build refusal.

A `mutation name: T` owns an initially absent result. `send name = source(args)`
is an occurrence: equal arguments still send twice, it never runs at bake or
because state exists, and reload never replays it. `value(name)` is
`option<T>`; `pending(name)` is boolean. The newest fulfilment is accepted,
although every send already issued remains an occurrence. `reset name` clears
the result and forgets its ticket.

Network failure remains data shaped by the Rust source. No completion callback
runs. Query chaining observes the settled value normally. `refresh` remains
separate from mutation invalidation.

`status` is the exhaustive view form. Queries require `pending value` and
`ready value`; mutations require `idle`, `pending previous`, and `ready value`.
Ordinary expressions may ignore status when stale-while-revalidate is intended.

### Composition

Props have complete types, including action arity. Slots are typed view
parameters; an indented child fills the default slot, and named `slot` arms
fill named slots.

A declared context is a compile-time hidden prop, not a runtime global:

```contract
context Theme: ThemeValues
provide Theme = theme
```

A consumer names the context it reads. Missing or ambiguous providers reject.
Context may carry closed values and action references, but not writable cells.

A named `style` is a checked set of kernel rows. At a use site, named style
rows apply first and inline rows override them. It is not an open object and
cannot contain an unknown property.

Components remain statically targeted and compiler-expanded. Recursion and an
expansion beyond the declared node budget reject by name.

### Tests and diagnostics

The old `contract` block is deleted. Its purpose returns as top-level tests
which execute, rather than clauses that may disappear in an emitter:

```contract
test "bad login"
  tap testId="title"
  type testId="who" text="alice"
  type testId="password" text="wrong"
  tap testId="login"
  clock settle
  expect tree has testId="login-error"
```

The verbs are only `tree`, `screenshot`, `tap`, `type`, `state`, `layout`,
`logs`, and `clock`. Assertions read those replies; they add no ninth agent
operation. Prefix counts over `testId` execute against `tree`, including rows
created by `each`.

One compile reports all failures. Every diagnostic has a stable id, exact span,
reason, and mechanical fix where one exists. Attribute type, root-region,
action-effect, event-payload, component-expansion, and conservatively
unbounded-scroll checks happen before bake. A construct without an accept
fixture and a runner expectation does not exist; a diagnostic without a reject
fixture does not exist.

## Two worked samples

### Weird Castle

```contract
enum Screen
  title
  login

shape Session
  ok: bool
  username: string
  token: string
  error: string

data
  mutation login(string, string) -> Session

component WeirdCastle
  state screen: Screen = .title
  state who = ""
  state password = ""
  mutation session: Session

  action openLogin writes screen
    screen = .login
  action setWho(value: string) writes who
    who = value
  action setPassword(value: string) writes password
    password = value
  action submit sends session
    send session = login(who, password)
  action logout writes screen, who, password resets session
    screen = .title
    who = ""
    password = ""
    reset session

  view
    main testId="weird-castle-main" width="100%" height="100%" background-color="#12081f"
      status session
        idle
          LoggedOut(screen=screen, who=who, password=password, error="", open=openLogin, setWho=setWho, setPassword=setPassword, submit=submit)
        pending previous
          match previous
            some(s)
              LoggedOut(screen=screen, who=who, password=password, error=s.error, open=openLogin, setWho=setWho, setPassword=setPassword, submit=submit)
            none
              LoggedOut(screen=screen, who=who, password=password, error="", open=openLogin, setWho=setWho, setPassword=setPassword, submit=submit)
        ready s
          when s.ok
            SignedIn(session=s, logout=logout)
          else
            LoggedOut(screen=screen, who=who, password=password, error=s.error, open=openLogin, setWho=setWho, setPassword=setPassword, submit=submit)

component LoggedOut(screen: Screen, who: string, password: string, error: string, open: action(), setWho: action(string), setPassword: action(string), submit: action())
  view
    when screen == .title
      Title(open=open)
    else
      Login(who=who, password=password, error=error, setWho=setWho, setPassword=setPassword, submit=submit)

component Title(open: action())
  view
    button press=open aria-label="Weird Castle — enter" testId="title" width="100%" height="100%"
      column justify-content="center" align-items="center" gap=12 width="100%" height="100%"
        text "Weird Castle" font-size=40 font-weight=800 color="#ffffff" testId="title-mark"
        text "tap to enter" font-size=14 color="#b8a1d9"

component Login(who: string, password: string, error: string, setWho: action(string), setPassword: action(string), submit: action())
  view
    column justify-content="center" width="100%" height="100%"
      column gap=14 padding=24 max-width=420 align-self="center" width="100%" box-sizing="border-box" testId="login-screen"
        text "Log in to Castle" font-size=24 font-weight=700 color="#ffffff"
        input value=who change=setWho placeholder="Username or email" aria-label="Username or email" testId="who" padding=12 border-radius=10 border-width=1 border-color="#5b4a7a" background-color="#ffffff"
        input value=password change=setPassword placeholder="Password" aria-label="Password" testId="password" padding=12 border-radius=10 border-width=1 border-color="#5b4a7a" background-color="#ffffff"
        when error == ""
          text " " font-size=13 color="#ff8a80"
        else
          text error font-size=13 color="#ff8a80" testId="login-error"
        button press=submit aria-label="Log in" testId="login" width="100%"
          row justify-content="center" padding=12 border-radius=10 background-color="#7c4dff" width="100%" box-sizing="border-box"
            text "Log in" font-size=15 font-weight=700 color="#ffffff"

component SignedIn(session: Session, logout: action())
  view
    column justify-content="center" align-items="center" gap=12 padding=24 width="100%" height="100%"
      text "Signed in as {session.username}" font-size=20 font-weight=700 color="#ffffff" testId="signed-in"
      text "The deck surface goes here (llp/0000)." font-size=13 color="#b8a1d9"
      button press=logout aria-label="Weird Castle — log out" testId="logout"
        text "Weird Castle" font-size=13 font-weight=700 color="#b8a1d9"
```

### Caltrain stations

```contract
shape Location
  lat: number
  lon: number

shape Station
  id: string
  name: string
  zone: number
  distance: number

data
  query nearest(Location, number) -> list<Station>
  query stations(Location) -> list<Station>
  query search(string, Location) -> list<Station>

component StationsScreen(location: Location, select: action(string), back: action())
  state query = ""
  state searchFocused = false
  state lastKey = ""

  query nearby: list<Station> = nearest(location, 3)
  query allStations: list<Station> = stations(location)
  query matches: list<Station> = search(query, location)

  action setQuery(value: string) writes query
    query = value
  action focusSearch writes searchFocused
    searchFocused = true
  action blurSearch writes searchFocused
    searchFocused = false
  action searchKey(keyName: string) writes lastKey
    lastKey = keyName
  action selectStation(id: string) writes query, searchFocused
    query = ""
    searchFocused = false
    select(id)
  action goHome writes query
    query = ""
    back()

  view
    section role="region" aria-label="Stations" gap=12 testId="stations-screen" background-color="#ffffffd9" border-radius=16 padding=14 box-sizing="border-box"
      input value=query change=setQuery focus=focusSearch blur=blurSearch key=searchKey placeholder="Search stations" aria-label="Search stations" testId="station-search" padding=12 border-radius=10 border-width=1 border-color="#cccccc"
      when searchFocused
        text "searching · last key {lastKey}" font-size=11 color="#999999" testId="search-hint"
      when query == ""
        column gap=8
          text "Nearest" font-size=12 font-weight=700 letter-spacing=0.8 color="#999999"
          each station in nearby key=station.id
            StationRow(station=station, select=selectStation)
          text "All stations" font-size=12 font-weight=700 letter-spacing=0.8 color="#999999"
          each station in allStations key=station.id
            StationRow(station=station, select=selectStation)
      else
        column gap=8
          text "Matches" font-size=12 font-weight=700 letter-spacing=0.8 color="#999999"
          each station in matches key=station.id
            StationRow(station=station, select=selectStation)
      button press=goHome aria-label="Back" testId="stations-back"
        text "Back" font-size=13

component StationRow(station: Station, select: action(string))
  state hot = false
  derive hotTestId = if hot then some("station-hot-{station.id}") else none

  action setHot(over: bool) writes hot
    hot = over

  view
    button press=select(station.id) hover=setHot aria-label=station.name testId="station-{station.id}" width="100%"
      row justify-content="space-between" align-items="center" padding-top=10 padding-bottom=10 border-bottom-width=1 border-color="#e0e0e0" width="100%" background-color=if hot then "#f2f2f2" else "transparent" testId=hotTestId
        column gap=2
          text station.name font-size=15 font-weight=600
          text "Zone {station.zone}" font-size=12 color="#999999"
        text formatDistance(station.distance) font-size=12 color="#666666"
```

## Why

- **§2.1, quiet failures.** Typed kernel attributes reject `width=true`; exact
  `href` semantics remove the split navigation spelling; scroll boundedness
  receives a conservative diagnostic. This answers 0102’s feature that
  “quietly did not exist” and moves root regions from host boot to compile.
- **§2.2, escape tax.** Contract `fn` and named styles cover small pure work.
  The Rust data seam covers the rest once. No sidecar or roster edit is needed
  for an application formatter. Unsupported host effects remain named walls;
  0099 was precise: “I missed the escape hatches,” not JSX.
- **§2.3, time.** Dispatch-time arguments stay. Branching actions make Enter
  possible. `mutation`/`send` makes POST an occurrence and removes `attempt`,
  password-bearing submitted state, `await`, and the generation reducers every
  0086/0102/0103 author rebuilt.
- **§2.4, composition.** Local keyed state removes Caltrain’s global hover
  pair. Typed slots, hidden context, grouped shapes, and styles address the
  31-prop `Content`, 22-prop bubble, theme drilling, and repeated button rows.
- **§2.5, generated seam.** The seam remains unbypassable and becomes smaller:
  one Contract signature and one Rust implementation, checked at bake and
  settlement. This keeps what 0102 called “the best idea here” without the
  defect-prone generated TypeScript products.
- **§2.6, vocabulary.** The tree is visibly Contract; CSS is exactly CSS.
  JavaScript-looking operators with different Option, truthiness, or equality
  rules are absent. Hyphenated CSS names are grammar, not accidental HTML.
- **§2.7, governance.** Tests execute through LLP 1012’s eight operations.
  Inert `contract` clauses are deleted. Accept, interaction, and reject
  fixtures remain the language authority.

The proposal keeps every repeated praise in §3: first-class `testId`, checked
`writes`, automatic `derive`, required `each` keys, primary arguments,
exhaustive async status, one route per file, separately testable pure helpers,
named refusals, and the data seam that view code cannot bypass.

## Familiarity

JSX would buy braces that survive refactors, existing editor machinery, faster
first guesses, and the largest human and model corpus. The todo report’s
“React was faster and less error-prone” is evidence for that advantage, not
noise.

The timed record places the loss elsewhere. 0102 said the indentation grammar
was fast; 0103 said it became readable in twenty minutes; 0099 said, “I did
not miss JSX as syntax.” The hours went to lifecycle, absent primitives,
generated seams, and silence. JSX would tell a model that arbitrary
expressions, closures, refs, effects, DOM events, and React component lifetime
exist. They do not. LLP 0477’s “agents think JSX = React” and LLP 0532’s
uncanny list predict more wrong priors, not fewer.

The answer is therefore no. Contract should borrow local component state,
typed children, and exact HTML/CSS names where their semantics agree. It
should remain visually distinct wherever the plan is not JavaScript or React.

## What it costs

Production-line estimates, ±25%, against LLP 1006:

| Area | Today | Restart |
|---|---:|---:|
| `contract-syntax` | 1,825 | 2,300 |
| `contract-types` | 1,100 | 2,000 |
| `contract-analyze` | 354 | 1,150 |
| `contract-lower` | 953 | 1,800 |
| `contract` driver | 149 | 500 |
| Compiler total | 4,381 | about 7,750 |

The syntax crate deletes present component inlining before adding enums,
functions, styles, tests, and local-slot ownership. The type and analysis
growth buys CSS value checking, complete action arity/effects, data signatures,
contexts, and layout diagnostics.

`exact-plan` adds component-local slot ownership, mutation cells, user-function
code, and send/reset/refresh operands: about 250 authored lines plus generated
rows. Its digest changes; no migration exists.

`exact-runner` adds keyed local-slot storage and mutation settlement: about 900
production lines and 600 test lines. LLP 1016’s executor remains about 150
lines per host. Rendering hosts otherwise do not change.

The test driver adds about 300 lines over `scripts/agent.mjs`; it uses the
existing protocol. A formatter is about 300 lines and shares the syntax tree.
No LSP or devtools UI is included.

Deleted: JavaScript imports, metadata sidecars, application roster edits,
general tasks, awaited actions, root-only state, cached-argument mutation
tricks, CSS aliases, the non-executing `contract` block, edition flags, and
pre-1.0 migration machinery.

The first-frame bake, plan validation, eight-operation API, host ABI, kernel
schema, and 100 ms budgets remain unchanged. Compile plus bake must retain the
current ≤20 ms p50 slice.

## Not doing

The React tier stays on `NOT-DOING.md`. Moving it would unblock ecosystem code
and JSX priors, but would add a second authoring model, JavaScript execution,
and a parity matrix; nothing of equal cost should come off the doing-list.

One effective v1 trade does move. Per-instance state comes off LLP 1006 §8’s
not-in-v1 side. Arbitrary lifecycle tasks, awaited actions, and per-instance
queries or mutations go onto it. This unblocks local draft, hover, disclosure,
and reaction state without adding a general effect system or N-request rows.

Also absent: generics, higher-order functions, recursive components, dynamic
component targets, open objects, reflection, optimistic mutation rollback,
automatic invalidation, retries, offline queues, remote-at-boot placeholders,
streaming, sockets, LSP, devtools, compatibility, and a ninth agent operation.

## How we would know

Run 36 blind lanes: three model families × explicit/familiar prompts × Weird
Castle/Caltrain stations × current Contract/new Contract/React reference.
Freeze data, pixels, `testId`s, and the eight-operation choreography.

The new language passes if:

- at least 35 of 36 milestone cells are green;
- its median wall time is ≤70% of current Contract and ≤125% of React;
- its median output tokens are ≤80% of current Contract;
- median syntax rejections before first successful compile are ≤2;
- no lane spends ten minutes on accepted-but-ineffective layout, navigation,
  event, or data behavior;
- every compiler run reports all authored defects at once;
- no green lane encounters a runtime attribute, root-region, action-arity, or
  data-shape refusal;
- source is no more than 15% longer than today’s Contract;
- compile plus bake remains ≤20 ms p50 and restart-to-present ≤100 ms p50;
- every test uses the eight operations, `clock settle`, and zero sleeps or
  app-authored delivery markers.

Record wall, tokens, compiler invocations, diagnostic ids, runtime refusals,
agent operations, source lines, plan bytes, and first-pixel module count.
