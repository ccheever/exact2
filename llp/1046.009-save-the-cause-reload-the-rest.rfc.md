Not linked into `llp/current/` (RULES caps it at fifteen).

## Summary

Contract's good properties have one root. It is **data run by a fixed
runtime**, not native code, so it can be checked whole at bake, proved in
Lean, and swapped into a running session in ~20 ms on every host — iOS
included, where no new native code can load. The same root decides what a
game can reload on the fly: whatever stays Rust is exactly what a phone
cannot reload. Moving a slice out of Rust *is* the reload principle.

Four games written since the September scene round (Tennis, Garden, Forest,
Rivals; ~22k lines of logic and tests) say where the line falls:

| Slice | Share | Shape | Proposal |
|---|---|---|---|
| Presentation (`present`, looks, effects, sound triggers, HUD view-models, code-built meshes) | largest: ~63% of Garden's 6.9k logic lines; ~1k Rivals; ~500 Forest | pure f(saved state, time, look) → drawn rows | a Contract-shaped declaration: the world's CSS (§3.2) |
| Rules and flow (tennis scoring, Rivals' rounds/respawn/reload/bandage, Garden's event heap and stages, Forest's camp/Fate/Mind/Pack) | 200–1,250 lines a game | event-driven transitions and timers over a few saved slots | Contract's semantics, run inside the tick (§3.3) |
| Tables (tuning, catalogues, arena/level layout, synth and emitter parameters) | 100–750 lines a game, plus copies | constant data | a typed data file, no language (§3.1) |
| Kernels (movement, ball flight, steering, combat queries, spatial grids) | a few hundred lines | per-entity numeric code every tick | stay Rust (§3.4) |

The principle (§4): **save the cause; derive everything else; anything
derived reloads into the running game on every host.** It extends
1046.008's rule from appearance to everything authored.

## 1. What changed since September

The September round asked one question — author the tick-0 world in a
language — and measured one game (Lanterns: 289 of 583 lines built the
world). Its typed-scene lane never reached main (1046.003 §1: Black's engine
was chosen without `game/scene`); main took the smaller pieces
(`Game::LEVEL`, `Placed`, presentation state). Four games later, world
construction is still there (Tennis 300 lines, Forest 840, Garden 550) but
it is not where the cost is. Presentation is the largest slice, rules are
where the bugs are, and tables are the thing copied between languages.

## 2. The evidence

**Tables drift between languages.** Forest's stalking deer moves at 3.2
(`forest/logic/src/creatures.rs:297`) while its walk cycle assumes 3.0
(`look.rs:63`); `app.contract:100` restates the day and night lengths and
`proof.mjs:7` restates them again. Rivals writes its reload window three
times (`fighter.rs:117`, `lib.rs:597`, `app.contract:198` as pixels of 240)
and its arena twice (Rust `BLOCKS` and `arena.json`, held equal by a test,
`arena.rs:180-193`). Garden's crop table is in `crops.rs` and again in
`art.mjs:302-317`. Tennis restates its contact tick and toss apex in
`proof.mjs:12`.

**Rule bugs outnumber every other logic bug.** Forest: starvation emitted
no `died` (the flag was read after the needs step), nights kept counting
after death, "E: chop" was offered while E was refused, feeding destroyed
surplus fuel, rescue progress contradicted "fire ready", a child could be
rescued at an extinguished fire (`005-forest.md:57,404,519,657,1244,1348`).
Garden: stale events in its heap filtered by a deadline check, and a
malformed `sell` sold the whole backpack (`004-garden.md:443`). Rivals: a
bot's search destination overwritten the next tick, training dummies
respawned through the combat rule (`006-rivals.md:782,392`). Tennis: an ad
hoc dropped-toss recovery (`tennis/logic/src/lib.rs:702-707`). Determinism,
by contrast, "held without effort" (`003-tennis.md:283`,
`006-rivals.md:308`): the lints already do that job.

**Presentation in the tick costs pins, and pins cost minutes.** A re-pin
runs 10–25 minutes (`005-forest.md:258`; Garden's strict seven-mode
refreshes). Rivals left its viewmodel posed in the tick because moving it
"would move the pins" (`006-rivals.md:1682`); Garden kept the farmer's walk
swing in the simulation and dropped the HUD fruit swatches for the same
reason (`004-garden.md:1705-1709`). Hand-written write-if-changed guards
caused Garden's three stale-HUD bugs (`004-garden.md:431,564,1149`) and
Forest's `&mut Visible` query that rebuilt every batch every tick, 31–330 ms
of feed (`005-forest.md:348-356`).

**No builder used the live loop.** From Beacons r2 through Rivals, every
builder iterated through proofs of 10 s to 3 minutes; none used the
world-carrying swap (`001-beacons-exact-r2.md:47` … `-r6.md:25`;
`005-forest.md:73`). Agent pages refuse the swap by design
(`host/web/dev.js:267`). The Godot twin's script reload earned Loop 5
(`001-scores.md:14,28`).

## 3. The four slices

### 3.1 Tables: a typed file, not a language

One file per game, checked against the game's Rust `Data` types (the
`Game::LEVEL` path, generalized), read by Rust, by the HUD, by `proof.mjs`
and by the art generators. Verifiable: names resolve, units and ranges hold,
cross-row invariants (Garden's "regrows ⇔ `fruit_s > 0`") are checks, not
tests. Reloadable: a table is a world input; editing it swaps the table and
the world continues.

One rule makes that work: **read a value from the table; do not copy it
into a component at spawn.** Garden copies growth spans into each plant
(`garden.rs:216,253`) and `Character` copies speed, jump and gravity
(`engine/src/character.rs:15-29`); an edit then reaches only what spawns
after it. A value that must be snapshotted (a deadline already scheduled)
is saved state and says so.

### 3.2 Presentation: the world's CSS

`Game::present` already exists and is already outside saves and hashes.
Make it a declaration in Contract's form, compiled at bake: rows keyed by
entity, as Contract's keyed list rows, producing `Drawn*`, material, clip,
opacity and sound rows.

- **Verifiable:** it cannot write the simulation, by construction, so a
  look change never moves a pin; model and sound names resolve against the
  bake's assets; per-entity cost is bounded.
- **Faster:** the compiler knows each row's dependencies, so the engine
  re-derives only what changed (what `p.each` and `Derived::Kept` do by hand
  today). A row that depends only on per-instance constants and time lowers
  to the vertex shader — what Forest did by hand for wind (feed 8.43 → 6.39
  ms at 20k trees, `e943116a0`) and what `shimmer`, `Tween` and `Spring` are
  special cases of. CSS animations run on the compositor for the same
  reason; a Rust closure never can.
- **Reloadable:** it is a plan, so it reloads as Contract does, on every
  host, without touching the world.

### 3.3 Rules: Contract's semantics inside the tick

Contract is already a rules language: state, actions as transactions,
timers, events, and `Reachable.invariant` in Lean (`semantics/README.md`).
Run that semantics inside the fixed tick, with its slots stored as a world
resource; Rust kernels raise typed events (`Bounce`, `Hit`, `Ripe`) instead
of writing flow state.

- **Verifiable:** every phase × event handled; no stuck phase; a match ends;
  a refused event changes nothing; the HUD prompt and the action read one
  predicate (Forest's "E: chop"). The Lean apparatus exists.
- **One schema with the HUD:** the Rust `Hud` structs that restate Contract
  shapes (`tennis/logic/src/lib.rs:47-68` vs `app.contract:1-19`) and the
  string commands (`forest/logic/src/lib.rs:155-163`) go.
- **Cost:** neutral; rules run at event rate, so Contract's boxed VM is
  enough. **Risk:** these slots enter saves and hashes, so the VM's
  cross-host determinism becomes the game's. Binary64 is modeled exactly.

### 3.4 Kernels stay Rust

Nothing per-entity-per-tick goes into either form. Stage (1041.008) proposed
batch bytecode for tick code and itself asked whether it could compete with
Rust; the four games show no need. The kernels were not where the bugs
were, and their performance came from the engine steering the author
(ray-then-write, 7–47×, `006-rivals.md:174-192`), not from a language.

### Levels: still and live

From Set (1041.009): the still part of a level — court lines, arena blocks,
fences, trees until felled — is a derivation of (table, seed), not saved
state. That is the performance Forest fought for (2.9 KB saved per trunk,
Rapier rebuilds; `005-forest.md:126-159`) and it makes a level reload safe
without identity matching: still things have no state to merge.

## 4. The principle

**Save the cause; derive everything else; anything derived reloads into
the running game on every host.**

1. **Saved state** — the world — is the only thing a reload keeps, carried
   by name through `Data` (it already is: unknown fields skip, missing
   fields default, `game/derive/src/lib.rs:425-451`).
2. **Everything derived from authored data** — tables, the still level,
   presentation, rules, HUD, shaders, models, textures, sounds — reloads as
   a new generation with the world untouched, within RULES' 100 ms p50 dev
   restart, iOS included.
3. **Rust** reloads by module swap with carry on the web (and macOS, if a
   dylib swap is built) and by relaunch on iOS. That is the one honest
   exception, and the reason to keep the Rust slice small.
4. **A reload that cannot carry the world keeps the old one running** and
   says why.

## 6. Steps, as experiments

1. **Reload plumbing (G1–G4).** No language: make the principle true for
   what is already data.
2. **Tables on Rivals.** Arena and tuning in one typed file read by Rust,
   Contract, the proof and `art-src`; edits reach the running world.
3. **Presentation declaration.** Port Forest's `look.rs` (243 lines) to a
   declaration; measure lines, reload latency, feed cost.
4. **Tennis rules on Contract's semantics.** Scoring as a Contract-semantics
   program inside the tick, with a Lean proof that a match ends.

Each reports what it measured and what it taught in §7.

## 7. What the experiments taught

Run 2026-10-05 by four parallel agents, each in its own worktree, merged
into `game/agentic-rescue`. Numbers are theirs, from runs, not estimates.

### 7.1 Reload plumbing (G1, G3, G4)

- **G1.** On macOS a canvas whose surface name is unique now hands its
  world to the next plan's canvas of that name (`43f9a682e`). Beacons
  on the dev loop: tick 144 → 1039 across a HUD edit, player still at
  x = 1.333; the generation applied in 4.5 ms. iOS shares the code path
  but was not built. On the web an unchanged module no longer saves and
  restores at all; the live surface is parked and adopted (`f266cfd43`).
  Rivals mayhem (456 KB world): 27.7 / 24.4 ms → 5.4 / 5.4 ms, same hash.
- **G3.** A swap the running world refuses now aborts before cutover:
  changing `HZ` on Beacons and Rivals is refused naming why, and the old
  world keeps ticking. Gap: a game that holds `setup` for declared assets
  defers its restore, so its refusal still lands after cutover.
- **G4.** `clock code`, a form of `clock` rather than a new operation,
  takes the newest gameplay at a boundary the driver chose (29.9 ms, hash
  equal across it); a drive *starts* on the newest build through
  `/__dev/gpu-settled` (`e8453f745`). Automatic swaps still never reach an
  agent page.

### 7.2 Data generations and Rivals' tables (G2, step 2)

- `rivals.level.json` (≈100 lines) holds the arena and every tuned number;
  `tables.rs` types it and checks what types cannot (25 distinct spawns,
  none inside a block, a valid reload window). Rust reads it where it is
  used, `art-src/gen.mjs` builds the arena model from it, `proof.mjs`
  reads its expectations from it, the HUD gets `max_hp` and the window
  through the published record. `arena.json` and the Rust `BLOCKS` copy
  are gone.
- A table edit reaches a running match in 351–551 ms (four runs), the
  match kept; an arena edit respawns the floor and blocks on the next
  tick while fighters, scores and the clock carry on. Of that, the page
  spends 0.8–1.3 ms; the server spends 100 ms polling, 50 ms debouncing
  and 170–240 ms rehashing all 41 MB of Rivals' assets per change.
- Art (`.model`, `.tex`, `.sound`) takes the same path; an `arena.gltf`
  edit rebakes in 2.5–3.4 s with a debug baker. Not yet seen landing in
  a page with the art look open. Native is not done.

### 7.3 Presentation as a declaration (step 3)

- `game/look` (a separate grammar in Contract's style; `.contract` gained
  nothing) and `forest/motion.look`: **85 code lines against `look.rs`'s
  204**, with the terrain height and grid cell as the only Rust it calls.
  Its rows equal the Rust's bit for bit at eleven samples through a day
  and a night, and the web proof's six reference frames match.
- It checks, with line and column and did-you-mean, every component,
  resource, field path, enum arm and row name against the game's linked
  types; it cannot write the simulation (no syntax for it, and reading a
  presentation component is refused); forward calls are refused, so it
  terminates. It cannot check `match` exhaustiveness, because `Data` does
  not list a type's arms.
- A declaration edit compiles in 262 µs and reaches the running `Sim` in
  1.04 ms, world hash unchanged; a bad field is refused with the real
  field list and the running look stays. Not wired to `dev.mjs`.
- **It costs about ten times the Rust**: 451 / 725 µs a present at 2k /
  20k trees against 48 / 71 µs. Dependency caching kept 0 of 6 rules while
  walking: tracking change per component type is too coarse, and most of
  Forest's rows read the player or the time. Forest therefore ships the
  Rust look (`6e153c460`); the declaration is held equal to it by test.
- The checker finds exactly the rows that follow only time — Forest has
  one, the limb swing, `pitch(p0 * sin(t * p1 + p2))` with three
  per-instance parameters — so GPU lowering is a decidable analysis.
  Lowering itself was not built.
- Forest's existing presentation tests passed while the declaration drew
  nothing; only the new row comparison noticed.

### 7.4 Tennis rules on Contract's semantics (step 4)

- `tennis/rules/rules.contract` (215 lines, existing syntax) holds the
  scoring and the point's flow; the kernels classify each bounce and
  raise one of eleven events; `game/rules` runs the plan inside the tick
  with its slots in a saved resource. Three seeded offline matches give
  byte-identical score, call and phase traces (4,032 journal lines)
  against the old Rust; web and Linux agree on the new hashes.
- Proved in Lean (`semantics/Apps/Proofs/TennisRules.lean`, ≈320 lines,
  standard axioms only): the phase is always one of its five values; the
  winner is always one of its three; **once over, no event changes that**,
  from any configuration. Not proved: that nobody passes four games and
  the winner is who reached four — that needs arithmetic through calls;
  a seeded test of 600 matches covers it.
- An event costs 2.98 µs; the tick went 14.7 → 20.0 µs, nearly all of it
  rebuilding the typed Rust view from slots by name. The web module grew
  1268 → 1427 KiB (gzip +64 KiB, +12%): a second copy of the runner's VM,
  which `app.wasm` already holds.
- A rules edit compiles in 3.1 ms and, posted to the world, adopts the
  running score by slot name mid-match (hostless; `dev.mjs` still treats
  `rules.contract` as a build input).
- The Rust `Hud`'s eleven rule fields are gone; `app.contract`'s `shape
  Hud` still restates their names, since a shape cannot be taken from a
  component's state.
- Writing the rules down found a real discrepancy: Jev's return check
  lacks the "a serve must bounce first" rule the player's has.

### 7.5 What it adds up to

1. **The live loop had rotted where nobody used it.** Contract edits had
   never reloaded for a game without `app.json` — every game `game/new.mjs`
   makes — because the compiler took the app id only from there and the
   loop refused every compile. Agent drives were silently running the
   gameplay module from when the loop started. Both were invisible because
   no builder used the loop (§2). A reload path that is not on the agent's
   path does not stay working; it needs a smoke that drives it.
2. **Bytes were never the obstacle; policy and plumbing were.** The engine
   already compared assets by digest. What refused was a rule ("a level
   cannot change after delivery") and a generation that restarted the plan
   and reshipped every asset. Applying data costs about a millisecond in
   the page; the 100 ms budget is now a server problem (poll, debounce,
   whole-tree rehash).
3. **"Derive everything else" needs the derivation declared.** A replaced
   level is read at once, but colliders built from it at setup change only
   when the game hears of it (`take_replaced`). Still/live (§3.4) is the
   systematic form: what is derived from a table is the engine's to
   rebuild, not the game's to remember.
4. **Snapshots are causes.** Reload deadlines, filled magazines, a
   rocket's launch velocity, a bot's skill keep their old values after a
   tuning edit — correctly: they are saved state. "Read, don't copy"
   reaches what is read each tick, and the rest is honestly a restart.
5. **Contract's VM fits rules, not presentation.** Rules run at event rate
   on scalars and strings; 3 µs an event is nothing. Presentation runs per
   entity on f32 vectors and quaternions and needs bit equality with
   glam's math to be compared at all; Contract's boxed f64 values cannot
   give that. Presentation wants its own executor, or one declaration with
   two backends: interpreted in development, generated Rust at bake.
6. **Shape invariants are cheap; numeric ones are not yet.** Guarding each
   action by its phase made "over is final" a local proof. Numeric
   properties need small-integer automation or a property language in
   `contract verify`.
7. **Both forms asked Contract for the same things:** variants (the
   phase is a string, so exhaustiveness is not a compiler check), a shape
   taken from a component's state, and `Data` that lists enum arms.
8. **Authoring in a constrained form is itself a review.** Jev's missing
   serve rule and Forest's restated `Grove::at` surfaced because the
   declaration had to say them.

### 7.6 Next, from what was learned

- The live loop on a smoke, so it cannot rot again (lesson 1).
- The server side of the 100 ms budget: file events, incremental hashing.
- `.look` and `rules.contract` delivered by the dev loop as data
  generations; both already reload in-process in 1–3 ms.
- Native asset generations; the deferred-restore refusal gap; an old save
  that crashes the Rivals module (`unreachable`) instead of being refused.
- One VM shared by the app and game modules.
- Presentation: per-entity, per-row change tracking; Rust generated at
  bake; GPU lowering of time-only rows.
- Rules: typed accessors generated from the plan (`contract rust` for a
  component's state); variants; a declared `events` section (the one
  syntax waiver to ask for).
- Charlie's amendment of `DEFERRED.md:342-346` for the game add-on's plan
  and asset generations, which all of this now uses.

## 8. Rules this runs into

- `rules/DEFERRED.md:342-346`: a dev reload "carries state … and is
  otherwise a restart: no patch format, no generations, no identity
  matching." §4 needs no identity matching (state carries by name; still
  things have none) but does need plan and asset generations for the game
  add-on. Charlie's amendment.
- `rules/DEFERRED.md:704`: no new Contract syntax until formatting and
  navigation land. §3.2 and §3.3 need a waiver or their own grammar sharing
  Contract's lexer and semantics (1046.002 F18: share the habit, not the
  grammar).
- `rules/DEFERRED.md:178-184`: `game/` stays a separate workspace; the core
  gains seams only. Everything here lives in the add-on or is a seam.
