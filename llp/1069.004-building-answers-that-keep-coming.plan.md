## Summary

LLP 1016.000 is the design. It adds a resource whose answer is a sequence:
each message commits as its own settlement, and the stream ends at a close,
a failure, or when the runner forgets the ticket. This plan lands it in
three slices. It does not reopen the design.

1. **The runner half, with no network.** `Answer::Stream`, a reply that can
   be delivered more than once, settlement per message, forget ends it,
   `clock settle` treats an open stream as quiet after its first message.
   Held by a scripted fake transport.
2. **Server-sent events on every host.** A streamed `fetch` body with an SSE
   parser: in the web glue over `response.body`, and in the native executor
   over `ibex2`'s existing `StreamingResponse`. Admitted by `net.fetch`, no
   new grant. Crew's event stream is the consumer.
3. **WebSocket.** Opened by the web glue and by a new `ibex2` transport on
   Apple and Linux, admitted by the `net.websocket` grant that `ibex2`
   already parses. Messages and Bluesky's Jetstream are the consumers.

Streamed `fetch` bodies as a `ReadableStream` in the module realm are **not**
part of this. A source never sees bytes, only parsed messages (1016.000 D3).

## What changed on main since 1016.000 (2026-09-24)

1016.000's design holds. Four things landed since, and they make it cheaper:

- **Device topics (LLP 1016.002, implemented 2026-09-26).** The runner
  already accepts pushes that arrive between pumps. It queues them
  deduplicated, wakes the host, and applies them before replies. 1016.002
  D1 rejected value streams *for device data* and named 1016.000 as "the
  design for network sources, where the value is only in the message". The
  division is settled: a device topic invalidates and the source re-asks; a
  network message carries its value. Slice 1 reuses the wake path, not the
  topic queue.
- **`native.later` (LLP 1067).** A long native call is a request to
  `exact-native:`, run on the independent HTTP lane with a 1 MiB ceiling
  and handed off, so no I/O worker waits for it. Slice 2's native stream
  should use the same lane and the same hand-off. An open SSE response then
  counts as one ticket and holds no worker thread. 1067 answers once and
  defers partial results to this plan. A native module that streams (words
  as they are transcribed) is the same `Answer::Stream` with the module as
  the transport. It is named here as a later consumer, not built.
- **The independent lane and hand-off.** `HttpScheduling::Independent`
  (`runner/src/request.rs:46`) and `Work::Later(Box<dyn FnOnce(Reply)>)`
  (`request.rs:401`) exist. `Reply` is `FnOnce` and reports `Aborted` when
  dropped unsent (`request.rs:366-390`). A stream needs a reply that can
  send many times and then ends. That is the one data-seam type change
  (slice 1).
- **Forget aborts on native hosts, not on the web.** The native executor
  aborts held HTTP when a ticket retires
  (`host/apple/src/executor_tests.rs:339`,
  `retirement_aborts_held_http…`), and Linux shares the executor. The web
  glue keeps an `AbortController` per fetch (`glue.js:697`) but never
  aborts a forgotten one. QUEUE.md's "The web's request wait counts
  requests the runner has let go" records the cost: one hung superseded
  fetch holds `clock settle` for 20 s. An open stream that isn't aborted
  would hold it forever. **That QUEUE item is a prerequisite of slice 2 on
  the web.**

Worker placement (LLP 1027.002) changes nothing for the design. `parse` runs
where the source's other parses run. Each message is one turn and commits
through the runner, as a single reply does today.

## Open questions from 1016.000, answered or put again

1. **Doing list and consumer.** Still Charlie's. Since 1016.000 was written,
   the consumers have grown:
   - Crew / Exact Live (chat and job progress over SSE; LLP 1049 D9).
   - Messages (a socket).
   - Bluesky, admitted as a consumer on 2026-09-27 for what its port asks
     (`rules/DEFERRED.md`, c74615a3). Sockets are not among those asks yet,
     but its Jetstream feed is a WebSocket.
   - grnl's transcription, if native modules stream.

   Nothing in `rules/DEFERRED.md` refuses push for app data. Its only
   "push" is update delivery. **Proposed:** Crew is the consumer
   of slices 1–2 and Bluesky of slice 3. The trade is Charlie's to name.
2. **SSE first or both at once?** **SSE first.** It covers Crew and needs no
   new grant kind. On Apple and Linux it rides the `StreamingResponse`
   `ibex2` already returns (`Transport::open`,
   `vendor/ibex2/src/stdlib/fetch.rs:301`), so no new transport is needed.
   WebSocket needs a new `ibex2` transport per surface, so it is its own
   slice. The runner half is shared, so slice 3 touches only transports and
   the glue.
3. **Coalesce only, or an append mode too?** **Coalesce only, for now**
   (1016.000 D4's default). A log uses the D6 cursor: the message carries a
   cursor, and a gap re-asks from it. The append mode waits for a consumer
   whose messages cannot be recovered by a cursor. Crew's and Bluesky's both
   can: SSE has `Last-Event-ID`, and Jetstream has a `cursor` parameter.

## Slices

Each slice lands alone, passes the five checks, and names what holds it.

### Slice 1 — the runner half, no network

- **Runner.** `Answer::Stream(Request)` beside `Now` and `Later`
  (`request.rs:31`). A stream ticket stays in `pending` after its first
  fulfil. Each fulfil parses and commits as a settlement pass (1016.000
  D1). `pending(r)` is false from the first message. A late message on a
  forgotten ticket is dropped, as today (`commit.rs:575`). `refresh`
  forgets and re-asks.
- **Data seam.** A reply that can be sent many times, with the final send
  distinct (`Outcome` plus an end mark, or a `Stream` reply type beside
  `Reply`). A drop with no end sends `Aborted` once, as `Reply` does.
- **Bounds (1016.000 D4).** One ticket on its lane while open; the existing
  response ceiling per message; the newest undelivered message per ticket
  is kept. Coalescing happens host-side before delivery, and the runner
  keeps a count.
- **Agent (1016.000 D5).** `clock settle` counts a stream as in flight only
  until its first message. `state` lists open streams with a message count
  and the coalesced count. No new operation.
- **Held by:** the executor's fake transports grow a scripted stream; a
  runner test sends three messages then a close, and asserts three commits
  and a final value; a forget-mid-stream test asserts the host abort and
  no commit after; a `clock settle` test with an open stream returns
  settled.

### Slice 2 — server-sent events on every host

- **Prerequisite (web).** The glue aborts a request the runner no longer
  holds, after each batch, through the existing `exact_request_active`
  (the QUEUE item above). This also fixes today's 20 s `settle` stall.
- **Web.** The request arm reads `response.body` incrementally and parses
  SSE (`data:`, `event:`, `id:`, `retry:`; UTF-8; blank-line dispatch). It
  delivers each event to the ticket and keeps the `AbortController`. The
  module realm keeps deleting `EventSource` (`module-glue.js:136`,
  `module-worker.js:44`).
- **Apple and Linux.** The native executor reads `StreamingResponse`
  incrementally on the independent lane, handed off (LLP 1067 D3), with the
  same parser as a small shared Rust function. One parser for the render
  host too, when it needs one.
- **Reconnect.** A dropped connection ends the stream with a shaped
  failure. The source's own `refresh` (or a `then`, LLP 1016.001) reopens
  it, with `Last-Event-ID` passed as an argument. The host does not
  reconnect on its own: a hidden retry loop would be a second lifetime
  (1016.000 D2).
- **Contract.** None; the source decides whether it streams. TypeScript
  sources get the streaming form in the prelude's `fetch` answer: exact
  spelling to be pinned in the spec, the smallest that marks a request as
  a stream.
- **Held by:** a web test and a native executor test against a local SSE
  peer (`stream_tests.rs` already runs real HTTP peers for both socket
  transports); `apps/exact-live` switches job progress from polling to SSE
  against a local server, driven by
  `smoke.mjs web|macos|ios|linux --app exact-live` with `clock settle`
  green while the stream is open.

### Slice 3 — WebSocket

- **Grant.** `net.websocket <origin>` is already parsed and checked
  (`vendor/ibex2/src/grant.rs:107-155`, with a test that a fetch grant does
  not admit a socket). A reconnect is admitted again.
- **Web.** The glue opens the socket; the module realm keeps no
  `WebSocket`. Inbound text frames are messages; binary frames are refused
  with a shaped failure until a consumer needs them.
- **Apple and Linux.** A new `ibex2` WebSocket transport over the existing
  TLS stack (rustls on Linux, the Darwin transport on Apple). One ticket
  per socket, on the independent lane.
- **Sending.** 1016.000 has no outbound frame, and this slice doesn't add
  one on its own. Jetstream is receive-only. Messages' send path is an
  ordinary `mutation` over HTTP. A socket that must carry client frames
  needs a design line in 1016.000 first.
- **Held by:** an `ibex2` transport test against a local WebSocket peer
  (upgrade, text frames, close, over-limit frame); the web glue's socket
  under the agent; one consumer driven by the smoke. That is Bluesky's
  Jetstream feed (outside the repo, `EXACT_APP_DIR`) or an in-repo
  fixture if that app cannot be run by the async lane.

## Not in this plan

- `ReadableStream` in the module realm (user sources, BYOB, piping;
  `fetch.js:42`). A source sees parsed messages, never bytes.
- Streaming answers from native modules (grnl's partial transcription).
  They use the same runner half and are named as the next consumer.
- Outbound socket frames, binary frames, and an append-only mode (above).
- Server-side anything: the render host (LLP 1048) serves pages, not event
  streams.
