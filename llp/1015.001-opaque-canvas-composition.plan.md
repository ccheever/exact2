# LLP 1015.001 — Opaque full-canvas CPU composition

Status: measured proposal awaiting parent review. Implementer: Codex Windows
owner, 2026-10-04. User authorized encountered engine papercuts and reviewed LLPs.
This replaces the deferred readback-allocation idea: that costs ~0.015 ms and
would add retained device state without a useful gain. No such cache is added.

## Evidence

Existing Skirmish package copied unchanged; DLL SHA-256
`dc1ad8d8f639ae09d5794cd38bfbf8df29fd219af20e0c81b7ca9c6b458df3f9`.
Ordinary Windows window, 600 frames at 1280x720: paint including game readback
p50/p95 11.34/13.06 ms, upload/present 0.44/0.68 ms. At 1920x1080, 300 frames:
21.92/39.89 ms paint, 1.31/1.67 ms upload. These runs were on the active shared
machine, not a controlled hardware-performance qualification.

The same DLL's public readback call (300 warm samples, initial battle) is around
2.2 ms at 720p and 5 ms at 1080p. Its existing GPU timestamps show forward/sky
~0.17 ms and shadows/cull ~0.10 ms at 720p. CPU tick/feed/encode are small.
Direct public `Raster::canvas` measurement links the same compiled app libraries,
with matching rustc 1.93.1, host proc-macro path and panic=abort; no app rebuild.
A captured real game frame has alpha 255 at every pixel. Warm p50/p95 canvas
composition at 720p: no explicit clips 2.68/2.97 ms; two viewport clips 3.87/4.47;
plus ancestor viewport clip 5.26/5.67. At 1080p: 5.95/7.38, 11.60/12.42 and
12.65/13.52 ms respectively. All clipped/unclipped outputs have identical bytes.
This identifies actual CPU canvas masking/blitting as significant; UI/layout
spikes remain separately un-attributed. Measurement artifacts stay in ignored
`target/skirmish-*-profile.*`, not a new shipped benchmark framework.

## Narrow change

Only `Raster::canvas`: copy source bytes into its current target when all of the
following are proved before mutation:

- source and destination cover the complete same-sized physical target;
- the composed image-to-device transform is exactly identity, with no epsilon;
- explicit clips are plain rectangles equal to the logical destination (no
  radii/corner shapes), or absent;
- the current inherited mask is absent or every coverage byte is 255;
- every source alpha byte is 255.

Otherwise take the existing path unchanged. No retained cache, new opacity
promise, renderer metadata, new public style or canvas ABI. Current opacity
layers stay ordinary targets and are composed by the existing layer stack; an
opaque image overwrites only its current layer. Checking alpha/mask is linear
but avoids the full shader-like bilinear source-over raster and duplicate mask
construction. The fast path does not generalize to subrectangles or translations.

## Verification and release bar

Keep an explicit reference path for tests only, comparing complete bytes for
real captured game pixels and small adversarial images. Cover one translucent
pixel anywhere (including last), clipped/masked pixel, rounded clip, different
size, nonidentity transform/fractional translation, scaled/DPI target, existing
opaque background, and opacity-layer composition. Every noneligible case uses
the ordinary path with exactly equal bytes. Test copies do not change source.

Measure the same Raster helper and ordinary packaged game frame after rebuilding
in coordination with the parent, then inspect real native/web gameplay pictures.
Report changed canvas and full-frame distributions; do not claim physical input
latency or pure layout speed from them. Run native raster/surface tests, strict
native lint, formatting, caps and boot. Parent review precedes implementation.

## Review accepted before implementation

Parent approved the narrow full-target copy, 2026-10-04. Prove destination origin
and the complete current target at physical size, not width/height alone. Scan
all source alpha and inherited-mask bytes before mutation. Cover near-identity
transforms, scaled DPI and opacity layers; no epsilon, translations or subrect
expansion. Qualify a separately built game package without changing the parent's
shared package or active proof. Complete byte comparisons of all baseline captured
frames against all ordinary full-viewport clip variants passed before this change.
