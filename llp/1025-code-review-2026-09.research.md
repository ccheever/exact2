## 1. What is actually solid

Checked by reading, against the specs and against the 2026-08-28/29 review folds:

- **Kernel apply** is still validate-then-write. A bad batch applies nothing. Style NaN, text-only children, zero timer intervals, and the agent `after_key` scan (keys inside string values) were closed and stay closed.
- **Motion.** One seek and sixty steps agree on Apple (`Host::commit` seeks to each timer's `at_ms`, then `motion_sync`, then `now_ms`). On the web the 2026-08-29 clock HIGHs are folded: `at` markers, `register`/`seek` after every batch, GPU `exact.now` in agent mode. The smoke holds the 50×50 freeze and the one-seek-equals-steps case.
- **Plan decoder.** Magic, `FORMAT_VERSION`, `FORMAT_DIGEST`, `MAX_COUNT`, trailing bytes, forward-only jumps. Fail-closed.
- **Boot identity.** Named plan against a differently-named crate is `AppMismatch`. Unnamed still matches anything.
- **Path containment** on the LAN servers (`dev.mjs`, `serve.mjs`, `agent.mjs`) is `dist + '/'` plus `isFile()`. The 2026-08-29 prefix escape is gone there. `metrics.mjs` still has it (`issues/20260901-metrics-path-containment.md`).
- **Linux `unsafe`** is three small, justified blocks (fcntl, poll, a no-op waker). GPU null / `checked_mul` refusals exist and are tested.
- **Layering.** No cargo feature on a core crate; optional work is a dylib or the browser. `forbid(unsafe_code)` on kernel, plan, runner, motion, contract, web.

This is a working runtime, not a prototype that happens to boot. The issues below are holes in a system that already runs four surfaces.

## 2. The data seam is not atomic with the commit

LLP 1016 D5 is clear on the wire: a forgotten ticket is not unsent. The runner's *bookkeeping* then treated "not on the wire" as "not in `pending`", and that leak shows up four ways, all the same bug class:

1. **Store write from `parse` does not dirty store-reading resources.** `store_readers[i]` is recorded and never used as a dirty bit. Settlement reuses on `args == args && !forced`. A login that `store.set`s a token leaves `remember()` stale until `refresh`. QUEUE already named this; the code still does it. `issues/20260901-store-write-stale-resource.md`.
2. **Mutation assignment `forget`s before `settle`.** A refused settle rolls back slots and commands and restores `pending_mut`, not `self.pending`. `pending(x)` can then lie. `issues/20260901-mutation-forget-on-rollback.md`.
3. **`fulfill` drops the ticket before parse/settle succeed.** A shape or data refusal of a still-wanted reply cannot be retried. `issues/20260901-fulfill-drops-failed-ticket.md`.
4. **Reload does not carry `pending` and does not abort the executor.** Web: `boot()` clears `inflight` and leaves the `fetch` promises running; `next_ticket` restarts at 1; the old ticket 1 commits into the new session. Apple: `boot_plan` `take()`s the live `Host` before the new plan boots; a failed boot is `"not booted"` and an empty window. `issues/20260901-web-fetch-reload-tickets.md`, `issues/20260901-apple-reload-drops-app.md`.

The rule that would close all four: **pending, store writes, and the instance tree commit together, or none of them do.** D5's "do not unsend" stays; it is a statement about the executor, not about the runner's maps. A deps table (LLP 1005 §8) is the larger form. A boolean dirty set plus "forget only after Ok" is enough for v1.

This is the highest-leverage class. It is not a sixth check and not a new opcode.

## 3. Four hosts, three copies of the same job

The kernel did the hard thing once. The hosts then grew three implementations of jobs that are the same fact:

| Job | Web | Apple | Linux |
|---|---|---|---|
| Envelope / URL load | `dev.mjs` JSON.stringify | `PlanURL.swift` (`JSONSerialization`) | `fetch.rs` (`find` / `split`) |
| Fetch executor | `glue.js` `fetch` | `host/apple/src/executor.rs` | `host/linux/src/executor.rs` (a copy) |
| Presenter apply | `glue.js` | `macos/Presenter.swift` (1,049) and `ios/Presenter.swift` (1,102) | `presenter.rs` paints the kernel tree; no DOM mirror |
| Grant check | `URL.origin` | ibex2 origin | ibex2 origin |
| `clock settle` bound | none on `inflight` | 20 s | 20 s |

The Apple/Linux executors are the same file with a wake socketpair. The two Apple presenters share `Bridge` / `Text` / `WebModule` / `PlanURL` and then diverge for 1,000 lines each of apply/hit-test/capture. That split is real (AppKit vs UIKit) and is also how `type="password"` landed on Apple and missed the web (`issues/20260901-web-input-type-attribute.md`): the web host remaps props by hand, Apple sends schema names, and `Type` / `InputMode` were never added to the web match.

The URL loaders disagree on origin. LLP 1023.001 says host:port, parenthetically "same-origin". Apple compares `URL.host` (no port). Linux includes port, ignores scheme. `issues/20260901-apple-planurl-skips-port.md`.

Do not add a "host abstraction crate". Do lift the origin check and the executor into one place each — the way `PlanURL.swift` is already one file the two presenters share. The web grant match is already origin; keep it that, and make the native URL loaders the same fact.

## 7. Addendum: admission, parity, and authority are one boundary

The second review pass covered every production subsystem, the four live host
paths, the external Weird Castle consumer, and browser-computed behavior. It
agrees with §§2–5 and adds five cross-cutting findings that do not reduce to a
local patch.

### 7.1 Valid is not yet bounded

The decoders validate many local shapes but do not define a common resource
envelope for an execution:

- a `NodeKey` has slot and generation but not the kernel incarnation, so a key
  retained across reset aliases the first replacement node;
- a finite clock target can demand effectively unlimited timer commits, and at
  `2^53` a 1 ms next-fire time can stop advancing and loop forever;
- validated plans have no VM-stack, instance-depth, text-run-depth, or work
  budget. Instance realization is recursive and repeatedly scans global rows,
  making a deep chain both stack-bound and quadratic;
- native page/envelope/plan/SSE reads buffer before their format limits apply.

These are not four independent magic constants. The plan/runner boundary needs
one declared execution envelope: maximum validated topology/value/VM depth,
monotonic clock range, bounded work per call, and byte limits before buffering.
Hosts may schedule chunks, but a host timeout cannot be the semantic guard.
The concrete aliases, timer loop, and network buffers have filesystem issues;
the envelope and refusal vocabulary are the design work.

### 7.2 The style table is both grammar and promise

`kernel/tables/schema.json` is currently a storage/codec table, an authoring
vocabulary, and an implied cross-host promise, but it carries no property-domain
grammar. Finite negative padding, gap, border width, and font size are accepted
and reach Taffy/native text even where CSS rejects them; opacity is not clamped
to CSS used-value behavior.

The presenters then narrow that promise after compilation. Web and Apple style
lowerers return named `Skipped` rows, but production create/update binds them to
`_skipped` and discards them. Native text also differs before presentation:
CSS's initial whitespace collapse and inherited text properties are absent.
Apple/Linux controls ignore some HTML state, while browser UA defaults leak
into node types that are not reset. Passing Contract compilation therefore
does not establish which semantics the plan will have on a selected host.

The admission invariant should be: every exposed row has its CSS grammar and
used-value domain in the shared schema; the web host implements that meaning;
each tier-one presenter either implements the same observable behavior or the
plan declares and selects an explicit fallback/capability before boot. A
`Skipped` value may be a diagnostic result, never dead data. This is the
missing join between LLP 1001's one table, LLP 1006's compiler admission, LLP
1007's web oracle, and LLP 1023 D10's declared fallback.

### 7.3 Compiler identity must be semantic and lexical

Component expansion currently lifts row-owned declarations and substitutes
syntax without carrying every lexical binder. That produces the concrete
parameter-capture and missing-row-scope issues, but the larger missing object is
a stable declaration environment. The same absence appears in multi-file
`use`: “declared identically” compares AST values that include source spans,
while diagnostics carry line/column without the imported source identity.

Do not patch this with name-by-name exclusions or message prefixes. Expansion
needs binder-aware substitution and a retained lexical/source identity for
every lifted declaration. Semantic equality must exclude location; diagnostics
must include it. This adds no language feature and preserves one compiler.

### 7.4 A generic host cannot own Castle policy

Both generic WebView arms recognize the Castle SDK protocol, answer
`user.getCurrent`, and reject other methods. The Apple arm additionally detects
Castle markup by substring and rewrites guest HTML/CSS. That makes authentication
and product-specific layout host authority, creates web/native guest divergence,
and is what made an origin-navigation identity leak possible.

LLP 1020's generic message seam needs a correlated app-owned reply capability.
Castle authentication and full-bleed styling belong in the app/deck content;
the host owns isolation, origin checks, transport, and rendering only. This is
not a new host abstraction and does not require a second authoring model.

### 7.5 GPU refusal is not yet a transaction

The GPU module's stated per-canvas failure boundary is not enforced by its API.
Wgpu validation runs without error scopes or an uncaptured-error handler under
an `extern "C"` call, so a validation panic can abort the process; device loss
has no recreation path. Separately, `GpuModule::bind` calls a mutable surface
before knowing whether the bind is accepted, and shipped surfaces replace or
clear fields before later parsing can fail. A refused bind can therefore change
the “last accepted” render state.

The design obligation is a staged validate/commit bind plus a non-panicking
error boundary and explicit device generation/recovery. Local null checks do
not close either invariant.
