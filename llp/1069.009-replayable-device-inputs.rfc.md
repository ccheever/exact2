## Summary

A run of an exact2 app should be reproducible from a log that is **finite,
ordered, and made of the calls a host already makes into the runner.** The
runner does no I/O (LLP 1016 D1). Time is seeked, not read (LLP 1012 §2).
Wall time, place and entropy arrive as facts (LLP 1027.000.000). A network
reply arrives as `fulfill(ticket, outcome)`. So nearly everything that
changes what the runner computes already crosses one of about twenty
methods, in an order the host chooses and can write down.

This RFC does three things:

1. It states that property as a rule for every new capability (D1).
2. It names the four inputs that bypass it today, with what would make
   each recordable (D2).
3. It fixes a journal format, the *input tape*, and says what a replay is
   (D3, D4).

It adds no agent operation. `rules/DEFERRED.md` refuses session
record/replay as one, and this keeps that refusal. What it buys now is that
replay stays *possible and cheap*. A test can prove determinism with no new
apparatus. A later ruling can then admit a tape for error reports (LLP 1069
§5 #16) without a redesign. §5 lists exactly what needs a DEFERRED.md
trade.

This is distinct from LLP 1069.007. There the agent *sets* a location or
*answers* a permission prompt, live, through the operations. Here the
question is whether the sequence of such inputs, from any source, can be
written down and played back to the same state.

## Motivation

- **Bugs from installed apps can't be reproduced today.** The journal
  (LLP 1012 §3) says what happened: `press view 12 (openStations) → epoch
  2`, commands, refusals. It doesn't carry what came *in*, such as the
  reply body, the viewport, the seed or the typed text. A journal line tells
  you a tap failed, but it can't make the tap fail again.
- **The inputs were made explicit for other reasons.** LLP 1027.000 made
  time and randomness explicit so the bake and cache mean something. LLP
  1027.000.000 made the date a fact so agent drives stop rendering 1970.
  The launch seed (`Place::seed`, `set_seed`) makes ids explicit. Each was
  a determinism fix for one input. This RFC notices that together they are
  most of a recording, and asks what's left.
- **Expo has no counterpart.** A React Native app reads `Date.now()`,
  `Math.random()`, `AsyncStorage` and native modules from anywhere,
  including render. No finite list of its inputs exists to record.

## Design

### D1 — The rule: an input is a runner call, or it is not an input

Anything that can change a slot, a resource's answer, the tree or a command
enters the runner through a public method, at a point in the host's order.
Today that set is:

| kind | calls | carries |
|---|---|---|
| boot | `boot`, `boot_carrying`, `boot_with_delivery`, `boot_stored` | the plan digest, the persisted store and kept answers, delivery facts, carried slots (LLP 1007 §6) |
| facts | `set_viewport`, `set_preferences`, `set_time`, `set_place`, `set_seed`, `set_delivery`, `set_surface_record` | the values themselves |
| input | `dispatch`, `dispatch_bound` | the `Event` with its payload: `Change` (text today; a typed `Value` after LLP 1069.001 D4), `Press`, `Hover`, keys, scroll/pan/transform geometry, `ReorderDrop` |
| clock | `advance`, `advance_timed`, `advance_until_request` | `now_ms`; timers fire inside |
| answers | `fulfill`, `refuse_request` | ticket and `Outcome` (HTTP, storage, surface, native reply) |
| device topics | `apply_announced` | the queued topic names (LLP 1016.002) |
| host feedback | `collection_feedback`, the reorder calls, `canvas_reply`, `set_canvas_geometry` | the host's measured values |

**The rule for new work:** every capability LLP 1069 ranks must enter by
one of these shapes. A fact goes through a setter. A device answer goes
through `fulfill` or a recorded `Answer::Now` (D2a). A user action goes
through `dispatch`. The rule costs nothing to follow. The survey's §1 shapes
(fact, command, tag, grant-gated request) already route this way, and
LLP 1069.007's substitutes are those same calls made by the driver. It is a
review rule and adds no check.

The siblings, placed:

- **Facts** (LLP 1069.000's `exactPage`, contrast, scheme): setters, like
  `set_preferences`. The root font size is a kernel input, like D2b's.
- **The picker** (LLP 1069.002): `dispatch` of `change` or `cancel` on the
  input, with the `Picked` records; the bytes behind the paths are host
  files a replay supplies as fixtures.
- **Share** (LLP 1069.003): no input. Its outcome goes to the journal only.
- **Auth** (LLP 1069.006): `fulfill` of an `exact-auth:` ticket. The
  callback URL carries a code, so it is written `{"redacted":true}` like a
  secret (D3).
- **Entropy** (LLP 1069.005): D2a's recorded answers. Under the agent the
  stream from `--seed` makes them repeat anyway.

### D2 — The four bypasses, and what makes each recordable

**D2a — Answers computed in process that read the device.** A source
answers `Now` without a request. That answer is a pure function of the
source's arguments and its module state, which is determined by earlier
calls, with three exceptions:

- `native.call` returns device state synchronously (LLP 1067 D3).
- A re-ask after `apply_announced` reads "whatever the device holds now"
  (LLP 1016.002 D1), because the topic carries no value.
- A Rust source may call the OS directly (LLP 1027.000 D4: "ordinary
  native Rust can still call OS APIs").

The first two are marked already. `Store::observe_external_read` counts
them, and so do `observe_topic` and native activation, which are counted
external reads for the bake's sake (LLP 1067 D4). **Fix:** when the read
count rose while an answer was made, the tape records that answer's
value, keyed by resource and arguments. A replay takes the recorded value
instead of running the source. The third exception stays outside. A Rust
source that reads the OS without going through `native` is unrecordable,
the same way it is unbakeable. The rule in D1 asks such code to use
`native`.

**D2b — Layout inputs the host gives the kernel directly.**
`Kernel::set_intrinsic_size` (an image's or video's pixel size, once
decoded) and the registered measurer (CoreText, cosmic-text) bypass the
runner. They change geometry, not state. The runner's slots, answers and
commands don't read the kernel's frames, and geometry reaches the runner
only as event payloads and collection feedback, which D1 records. So a
**state** replay is exact without them (ruled: state-only, for now). A
**pixel** replay is exact on the same host, build, fonts and assets, and
isn't claimed across hosts; that's the parity harness's job.

**Verified in r2, by reading.** No non-test runner path calls a kernel
geometry API. The runner uses `kernel.node`, `node_by_key`, `arena`,
`apply`, `incarnation`, `epoch`, `live_count`, `rows`, `row` and `roots`;
none of `frame`, `frames`, `layout`, `geometry`, `compute_layout*`,
`measure_*` or `set_intrinsic_size` appears in `runner/src` outside
`runner/src/instance/collection/tests.rs`. The host sets intrinsic sizes
on the kernel through `runner.kernel_mut()` (`host/apple/src/host.rs:791`,
`:806`), past the runner's methods, as this section says.
Hypothetical layout (LLP 1051.000) is a Draft with no code; if it lands, a
geometry read inside an action becomes a runner input, and it must enter
the tape as a recorded answer.

**D2c — Ordering between a worker and the runner.** A worker-placed source
(LLP 1027.002) answers on another thread, and the runner commits when the
host delivers it. The host's delivery order is the order on the tape, so
the thread's timing doesn't matter once the tape is written. Nothing to
add.

**D2d — Host-local state that never crosses.** An editor's selection
offsets "remain local to the editor" (`Event::Select`). Scroll offsets
live in the native view, and focus lives in the host. None of them enters
the runner except through an event, so none of them is in a state replay.
A pixel replay of a mid-scroll frame needs the scroll payloads, which
`dispatch` carries.

### D3 — The input tape: one line per call

The tape is newline-delimited JSON. It has one header and then one record
per call, in the order the host made the calls:

```
{"tape":1,"plan":"<digest>","runner":"<version>","host":"ios","boot":{"store":…,"delivery":…,"carried":…}}
{"t":0,"fact":"viewport","width":402,"height":874,"preferences":0}
{"t":0,"fact":"place","locale":"en-US","timeZone":"America/Los_Angeles","seed":3710452291}
{"t":0,"fact":"time","epochAtZero":1790553600000,"utcOffset":-420}
{"t":412,"advance":412}
{"t":412,"take":[{"ticket":1,"url":"https://api.example/feed"}]}
{"t":530,"fulfill":1,"outcome":{"status":200,"body":"…"}}
{"t":1810,"dispatch":{"testId":"like-3","view":88},"event":"press"}
{"t":1810,"answer":{"resource":"meter","args":[],"value":{…}},"external":true}
```

- `t` is the runner clock at the call. The call itself carries the value,
  so `t` only makes the tape readable.
- `take` records what the runner *asked* for. It isn't an input, but a
  replay compares against it (D4).
- `dispatch` names the view by `testId` where one exists, as well as by id.
  Ids are deterministic on the same plan, and the name keeps the tape
  legible.
- Answers from `secret.keep` reads are written as `{"redacted":true}`.
  A secret never enters a tape. A replay that needs one fails by name.

This is the journal's shape (LLP 1012 §3) turned from what happened into
what came in. The journal stays as it is.

### D4 — A replay, and divergence for free

A replay boots the recorded plan with the recorded boot record, installs a
data source that answers from the tape (D2a's recorded answers, and every
`fulfill`), and makes each recorded call in order.

- After each call, the runner's `take_requests` must equal the next `take`
  record. If it doesn't, the replay stops there and names the call. That
  mismatch is the whole divergence check. It needs no witness or dataflow,
  both of which stay refused.
- A replay needs no network, disk or device. Storage and HTTP arrive as
  recorded outcomes, and device reads as recorded answers.
- A replay against a *different* plan is a behavior diff, which
  `rules/DEFERRED.md` refuses. The tape records the plan digest, and a
  replay refuses a mismatch.

### D5 — Where a tape comes from, and what that costs

A tape is written by whatever makes the calls:

- **A runner test.** It makes the calls itself.
- **The agent driver.** It already makes most of them through the
  operations.
- **A host keeping a ring.** A host could keep a bounded ring of recent
  records beside the journal ring (`JOURNAL_RING` = 4,096 lines), to
  attach to an error report (LLP 1069 §5 #16).

The first two need nothing new. The third (ruled): **a ring in development
and agent builds only,** for now. It holds typed text and reply bodies,
which are the user's data, so a production ring waits for its own ruling
alongside LLP 1069 §5 #16.

## What needs a DEFERRED.md trade

`rules/DEFERRED.md` §Agent API: *"Not shipping: session record/replay, …
behavior diff and verify, …"*

**Doesn't need a trade** (it isn't an operation, a check or a production
feature):

- D1 as a review rule.
- D2's analysis.
- D3's format written down here.
- One runner test that drives a scripted call sequence twice and asserts
  identical slots and requests (the first slice).

**Needs a trade:**

- **A driver command** that writes or plays a tape (`record`, `replay`).
  That is session record/replay as an operation.
- **A host ring in production builds** (D5's third source). It is the
  runtime half of the same line, plus a privacy decision. The development
  and agent ring is admitted (ruled) and needs none.
- **Replaying against a changed plan.** That is behavior diff.

The line isn't split yet (ruled). The one-line unblock for a future trade:
*"an installed app's error report reproduces on a developer's machine."* It
pairs with §5 #16.

## First slice

A test in `runner/tests/`. It boots Caltrain's plan, then makes a fixed
sequence of calls: viewport, place with a seed, time, advances, a
`dispatch` of a search `Change`, and a `fulfill`. It does this twice, from
two fresh runners, and asserts equal slots, equal `take_requests` after
every call, and equal journals. A second case records D2a's answers: a
source whose answer calls `observe_external_read` returns a different
value on each call. The test shows that replaying the recorded value, and
not re-running the source, gives equal slots.

It adds no script, check, operation or host code. (D2b's check that no
runner path reads a frame was done in r2.)

## Substitute

None of its own: the tape records what LLP 1069.007's substitutes and the
host's real arms feed in, through the same calls (D1).
