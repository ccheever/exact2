## Summary

`glassGroup="auto"`: the merge spacing is the element's own gap along its main axis — Apple's spacing-equals-gap pattern (shapes apart at rest, merging when a press swells one, LLP 1053.000.000 §2 row 3) — so the number is not written twice and follows the gap when it changes.

## 1. What exists

- `glassGroup` is prop 216, `float` (`kernel/tables/schema.json:1239-1242`). Contract types a float attribute as a number (`contract/lower/src/values.rs:538-544`) and range-checks a numeric literal to 0–10,000 (`values.rs:497-508`); a bound value is not checked, and the Apple host clamps every finite value into 0–10,000 (`GlassGroup.swift:93-95`, LLP 1053.000.000 D1).
- The Apple Rust host sends props by name as strings (`host/apple/src/host.rs` `props_for`) and style through `style_json_for` / `style_json_presented` (`host/apple/src/style.rs`), which drop `row_gap`, `column_gap` and `flex_direction` (`style.rs:45-70`): Swift never sees a gap or an axis. A gap change sends a style op and no props.
- `row_gap` and `column_gap` are `f32` points, default 0 (`schema.json:1927-1938`); `rem`/`em` are points by then; there is no percentage gap. Block layout places children with no gap.
- The web writes the attribute `glassGroup` with the number (`host/web/src/element.rs:728`, `css::num`); the JS target writes a bound prop's evaluated value directly (`host/web-js/src/emit.rs:1087-1100`).

## 2. Design

**D1. Spelling and encoding.** `glassGroup="auto"`, or a choice whose arms are numbers or `"auto"`. Contract lowers the literal `"auto"` (in a choice too) to the float `-1`, so the prop's kind, the wire and the runner do not change; every other literal is range-checked as today. `-1` is reserved: a bound numeric `-1` is `auto` as well (written down, not checked); every other bound value still clamps.

**D2. The spacing.** The Apple Rust host resolves `-1` from the kernel's style, in points: `column-gap` when `flex-direction` is `row` or `row-reverse`; `row-gap` when it is `column` or `column-reverse`; for a grid the smaller of the two, so neither axis merges at rest; for any other display `0` (touching shapes merge, separated ones do not). It sends the resolved spacing two ways, so both changes reach Swift: as the `glassGroup` prop (with `glassGroupAuto=true`) when props are sent, and as the style channel `glass_group_spacing` on every style op of a node whose `glassGroup` is `-1`, since a gap or direction change sends style and no props. Swift's `glassGroupSpacing` prefers `glass_group_spacing` when `glassGroupAuto` is set. The agent's `layout` reports `{spacing, auto: true}`.

**D3. The web.** Both targets write `glassGroup="auto"` for `-1` (static and bound), the number otherwise. Nothing draws it, as today.

**D4. Tests.** Contract: `"auto"` and a choice of `"auto"` and a number lowered to `-1` and the number; a negative literal and a non-`"auto"` string refused. The Apple Rust host: the resolution for row, row-reverse, column, column-reverse, grid and block, and a style op carrying the new spacing when the gap or the direction changes. XCTests: a group's container spacing from `glassGroupAuto`'s channel, changed by a later style op. The web: the attribute's spelling on both targets. The fixture (`scripts/fixtures/glass-group.contract`) gains a row with `glassGroup="auto" gap=8` beside `glassGroup=8`, drawn alike.
