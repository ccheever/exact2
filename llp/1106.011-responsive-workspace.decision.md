## Composition decision

[decision] Implement the next root increment through the public `ExactModule.tabContainer` hook. One outer navigation root contains two stable tab panels: a single, inert sidebar route and the actual workspace `stack(nav)`. The root key always names the actual selected workspace route. An app-owned container holds the two vended navigation controllers and assigns their frames from the same geometry as the authored panel widths. It does not change Exact route-node frames, stack contents or delegate slots. The earlier static drawn-sidebar fallback remains unimplemented; the public container candidate now has sufficient isolated evidence to attempt the bounded app implementation.

[observed] A new isolated fixture with sibling sidebar and workspace navigation roots failed compilation with `lower-navigate-root`: `navigate` belongs on the first outer navigation root. The corrected fixture uses one outer root, direct-child routes and a static sidebar sibling. It compiled, including an import of the actual AdaptiveWorkspace shape. The sidebar button addresses that root's router action. The fixture was not launched or driven.

[observed] The host limitation is more specific than a compiler restriction. [contract/lower/src/lib.rs](../contract/lower/src/lib.rs) restricts `navigate` to the first outer element. [NavigationIOS.swift](../host/apple/Sources/ExactKit/IOS/NavigationIOS.swift) recognizes `presenter.root.subviews.first` with `navigationBack`, and assigns the installed controller's view to `root.bounds`. Removing the nested `navigate` attribute would not make the host adopt two side-by-side controllers. A compiled static pane therefore proves neither a narrower native workspace header nor an inspector outside that header.

[decision] Record the native containment finding as local gap 007, independent-native-sidebar. Existing X9 and issue #108 concern child resources and root-file composition, not native controller containment. GitHub issue searches on 2026-10-07 found no matching issue. The required behavior is an inert sidebar controller/scroller beside the actual root stack, with independent chrome and bounds, while Exact retains route, Back and sheet ownership. No framework patch or controller reparenting outside the public tabContainer ownership seam is authorized by this decision. The bounded candidate is now implemented in the mobile root and remains unproved in UIKit.
