## Source helpers

[observed] Split layout requires width at least 720 and height at least 600. The height condition keeps landscape phones compact. Sidebar width is `clamp(round(width * .32), 280, 380)`. Supplementary panes require at least 960 points after the sidebar; file inspectors require split layout and viewport width at least 820. Both use source width limits of 260 through 480 while preserving the 560-point main-pane target. A file inspector can suppress the sidebar without changing the user's preferred visibility. The chat content maximum is 960.

[decision] [adaptive-workspace.ts](../examples/t3-code/mobile/adaptive-workspace.ts) adapts the source component's geometry to a stateless scalar projection. Its [Contract shape](../examples/t3-code/mobile/adaptive-workspace.contract) carries the same result. Root state retains sidebar search, all visibility/width preferences, focused pane role and the inspector registration token. Home forces the sidebar shown without overwriting its preference. While the outgoing column remains supported, an exiting inspector remains registered while its target width becomes zero; only the still-current inactive owner may release its content after the exit transition.

[observed] Exit retention and renderer mounting have separate lifetimes. `AdaptiveWorkspaceLayout.tsx` recomputes the pane role from actual focus, falling back to the underlying path. An overlay over plain Thread can change the inspector role to supplementary. If `panes.auxiliaryPaneWidth` becomes null, `WorkspaceInspectorPane` unmounts its renderer but retains the callback registration and its close effect above the conditional subtree. The app must project no native pane while unsupported. An active registration survives without an exit deadline; an inactive registration survives until its current close callback. Resupport can remount the outgoing renderer before closure, with fresh visited-mode state. The source close effect depends on inspector width and resizing, so changing either while inactive restarts the260ms deadline and invalidates the previous completion token. Root supplies separate candidate support, column support, column width and resizing to the serialized model.

[observed] The helper also preserves source sidebar-toggle behavior, captured-start-width drag direction and 24-point accessibility resize increments. These functions do not install a gesture recognizer or prove VoiceOver behavior. The native holder implements the source's 260ms cubic in-out motion, reduced-motion handling, clipping and settled main width. These still need a native drive.

## Composition decision

[decision] Implement the next root increment through the public `ExactModule.tabContainer` hook. One outer navigation root contains three stable tab panels: an inert sidebar route, the actual workspace `stack(nav)`, and an inert inspector route. The root key always names the actual selected workspace route. An app-owned container holds the three vended navigation controllers and assigns their frames from the same geometry as the authored panel widths. It does not change Exact route-node frames, stack contents or delegate slots. The earlier static drawn-sidebar fallback remains unimplemented; the public container candidate now has sufficient isolated evidence to attempt the bounded app implementation.

[observed] A new isolated fixture with sibling sidebar and workspace navigation roots failed compilation with `lower-navigate-root`: `navigate` belongs on the first outer navigation root. The corrected fixture uses one outer root, direct-child routes and a static sidebar sibling. It compiled, including an import of the actual AdaptiveWorkspace shape. The sidebar button addresses that root's router action. The fixture was not launched or driven.

[observed] The host limitation is more specific than a compiler restriction. [contract/lower/src/lib.rs](../contract/lower/src/lib.rs) restricts `navigate` to the first outer element. [NavigationIOS.swift](../host/apple/Sources/ExactKit/IOS/NavigationIOS.swift) recognizes `presenter.root.subviews.first` with `navigationBack`, and assigns the installed controller's view to `root.bounds`. Removing the nested `navigate` attribute would not make the host adopt two side-by-side controllers. A compiled static pane therefore proves neither a narrower native workspace header nor an inspector outside that header.

[decision] Record the native containment finding as local gap 007, independent-native-sidebar. Existing X9 and issue #108 concern child resources and root-file composition, not native controller containment. GitHub issue searches on 2026-10-07 found no matching issue. The required behavior is an inert sidebar controller/scroller beside the actual root stack, with independent chrome and bounds, while Exact retains route, Back and sheet ownership. No framework patch or controller reparenting outside the public tabContainer ownership seam is authorized by this decision. The bounded candidate is now implemented in the mobile root and remains unproved in UIKit.
