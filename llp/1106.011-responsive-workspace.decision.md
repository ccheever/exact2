## Source helpers

[decision] Preserve the pinned pure geometry and navigation logic in app-local files. [layout-mobile.ts](../examples/t3-code/mobile/layout-mobile.ts) copies `lib/layout.ts` with local imports. [layout-typography.ts](../examples/t3-code/mobile/layout-typography.ts) contains the source typography constants and the exact appearance function slices needed by work-row sizing. Copied files name their source path, pin and original SHA256. [adaptive-navigation.ts](../examples/t3-code/mobile/adaptive-navigation.ts) changes only type imports and references. Its [structural types](../examples/t3-code/mobile/adaptive-navigation-types.ts) introduce no React Navigation runtime.

[observed] Split layout requires width at least 720 and height at least 600. The height condition keeps landscape phones compact. Sidebar width is `clamp(round(width * .32), 280, 380)`. Supplementary panes require at least 960 points after the sidebar; file inspectors require split layout and viewport width at least 820. Both use source width limits of 260 through 480 while preserving the 560-point main-pane target. A file inspector can suppress the sidebar without changing the user's preferred visibility. The chat content maximum is 960.

[decision] [adaptive-workspace.ts](../examples/t3-code/mobile/adaptive-workspace.ts) adapts the source component's geometry to a stateless scalar projection. Its [Contract shape](../examples/t3-code/mobile/adaptive-workspace.contract) carries the same result. Root state retains sidebar search, all visibility/width preferences, focused pane role and the inspector registration token. Home forces the sidebar shown without overwriting its preference. An exiting inspector remains registered while its target width becomes zero; only the still-current inactive owner may release its content after the exit transition.

[observed] The helper also preserves source sidebar-toggle behavior, captured-start-width drag direction and 24-point accessibility resize increments. These functions do not install a gesture recognizer or prove VoiceOver behavior. The source's 260ms cubic in-out motion, reduced-motion handling, clipping and settled main width remain root rendering work.

## Navigation and data ownership

[decision] Reuse [mobileHome](../examples/t3-code/mobile/home.ts), the existing client/fleet and root thread-selection command. Sidebar search has its own UI query while retaining the existing environment/query ownership of search results. Rendering compact Home and a sidebar must not create another transport, draft store or reducer.

[observed] The source thread-selection helper pushes from Home and compact layouts, changes params in place from a split base thread, and replaces a split nested destination. Overlay selection removes sheets and applies the destination atomically while preserving the underlying route key for a param update. File selection replaces the browser when a persistent inspector exists and pushes in compact layout.

[decision] Root maps those decisions to actual Exact route IDs and params, retaining the existing async request-route guard. The copied overlay helper accepts a React Navigation-shaped state; an Exact Router must not be passed to it directly. The root's one route declaration preserves Home as the declarative parent so direct thread links retain a compact Back destination. Changing viewport width must preserve the current route, draft and shared client selection.

## Composition decision

[decision] Implement the next root increment with one existing native navigation root and an app-local static Contract sidebar. Use the source scalar geometry and real Home actions. Keep route nodes direct children of that root, as [LLP 1038](1038-router.rfc.md#d6--screens-are-each-over-the-selected-stack-the-landed-projection-is-unchanged-two-hosts-catch-up) requires. This is a functional fallback; it does not supply the source's separate sidebar UINavigationController or establish native header parity.

[observed] A new isolated fixture with sibling sidebar and workspace navigation roots failed compilation with `lower-navigate-root`: `navigate` belongs on the first outer navigation root. The corrected fixture uses one outer root, direct-child routes and a static sidebar sibling. It compiled, including an import of the actual AdaptiveWorkspace shape. The sidebar button addresses that root's router action. The fixture was not launched or driven.

[observed] The host limitation is more specific than a compiler restriction. [contract/lower/src/lib.rs](../contract/lower/src/lib.rs) restricts `navigate` to the first outer element. [NavigationIOS.swift](../host/apple/Sources/ExactKit/IOS/NavigationIOS.swift) recognizes `presenter.root.subviews.first` with `navigationBack`, and assigns the installed controller's view to `root.bounds`. Removing the nested `navigate` attribute would not make the host adopt two side-by-side controllers. A compiled static pane therefore proves neither a narrower native workspace header nor an inspector outside that header.

[decision] Record the native containment finding as local gap 007, independent-native-sidebar. Existing X9 and issue #108 concern child resources and root-file composition, not native controller containment. GitHub issue searches on 2026-10-07 found no matching issue. The required behavior is an inert sidebar controller/scroller beside the actual root stack, with independent chrome and bounds, while Exact retains route, Back and sheet ownership. No framework patch or reparenting of Exact-owned controllers is authorized by this decision. The public tabContainer hook supplies actual tab controllers, but its selection and visibility semantics have not been proved suitable for this workspace. It is not an implemented alternative.
