## Rulings (Charlie, 2026-09-27)

- **Q1, the system scheme as a fact: yes** ("i think yes"). `prefersColorScheme` is admitted as the system's preference, as CSS reports it, with the lint D1 describes. This amends LLP 1034 D3.
- **Q2: `exactPage()` is a new source** (the recommendation). `canShare` (LLP 1069.003 D5) lives on it too.
- **Q3: `rem`/`em` and a host-set root font size: yes.**
- **Q4: `prefer` is the ninth operation** and sets every fact here (LLP 1069.007 §3 P1; `rules/DEFERRED.md` §Agent API). D6 stands.

## Summary

The survey's first item asked for reduced motion, locale, time zone, font
scale, foreground/background and online status as facts. Since then, main has
landed half of that:

| fact | where it is now | landed by |
|---|---|---|
| `prefersReducedMotion`, `prefersReducedTransparency` | `exactViewport()` | LLP 1061 D5 |
| `locale`, `timeZone`, `seed`, `epochAtZero`, `utcOffset` | `exactTime()` | LLP 1027.000.000, LLP 1060 |
| the system's colour scheme | macOS only, as a hidden field's value (`ExactDocuments.reportAppearance`, `DocumentsMac.swift:106`) | LLP 1033 D6 workaround |

What remains, and where each goes:

- **`prefersContrast`** and **`prefersColorScheme`** go on `exactViewport`.
  They are CSS media features, and the source's rule is "what `@media`
  answers" (LLP 1061 D5).
- **`visibilityState`** and **`onLine`** go on a new source, `exactPage()`,
  named for the Page Visibility API and `navigator.onLine`. They are not
  media features.
- **Text size** (Dynamic Type) is not a fact. It is CSS's root font size and
  a `rem` unit, so an app scales text by writing `rem`, as it would on the
  web.

```
shape Media
  prefersContrast: string        // "more" | "less" | "no-preference"
  prefersColorScheme: string     // "light" | "dark": the system's, under any setScheme
shape Page
  visibilityState: string        // "visible" | "hidden"
  onLine: bool

component Feed
  resource media = exactViewport() as shape Media
  resource page = exactPage() as shape Page
  view
    column border-width=(media.prefersContrast == "more" ? "2px" : "1px")
      when not page.onLine
        text "Offline — showing saved posts" font-size="0.875rem"
```

`prefer` sets every media feature by its CSS name. A second host-state
form covers the page facts (D6). No new operation is needed.

## Motivation

- **The scheme workaround.** The Markdown reader learns the system
  appearance by having the macOS host type into a hidden field
  (`session.change(testId: appearanceTestId, …)`, `DocumentsMac.swift:107`).
  That works on macOS only, and it spends a node and an event on a fact.
- **Offline.** Bluesky, Messages and RealWorld show a spinner and then a
  failure when the network is gone, because nothing tells them in advance.
  `fetch` failing is the only signal (LLP 1016 D4: failure is data).
- **Hidden.** An app has no way to stop a live tick while it is hidden, or
  to refresh on return. Examples are the crypto list's 100 ms tick (QUEUE)
  and Bluesky's notification poll. Hosts already observe the lifecycle for
  their own reasons:
  - `CanvasSeams.swift:664-670` (audio);
  - `CollectionIOS.swift:134` (collections);
  - `gpu-glue.js:118` (the GPU loop).

  Only the app is left out.
- **Contrast and text size.** These are the two accessibility settings after
  motion that a native app is expected to honour. App Store review and users
  notice Dynamic Type first.

Absences checked 2026-09-27 by grep over `host/`, `runner/` and `kernel/`:

- No `prefers-contrast`, `darkerSystemColors` or `IncreaseContrast`. The
  Linux agent test uses `prefers-contrast` only to check that `prefer`
  refuses it (`host/linux/src/agent.rs:646`).
- No `preferredContentSizeCategory` or `UIFontMetrics`.
- No `navigator.onLine`, `online` listener or `NWPathMonitor`.
- No `rem` or `em` length unit in `contract/lower` or `kernel/src`.

## Design

### D1 — Two more media features on `exactViewport`

`prefersContrast`: `"more" | "less" | "custom" | "no-preference"`,
CSS's values (Media Queries 5 §11.3). A host reports what it can read:

- **Web:** `matchMedia` for `more` and `less`, the same path as
  reduced motion.
- **iOS:** `UIAccessibility.isDarkerSystemColorsEnabled` → `more`, with its
  change notification.
- **macOS:** `NSWorkspace.accessibilityDisplayShouldIncreaseContrast` →
  `more`.
- **Linux and the renderer:** `no-preference`.

Both go through `exact_set_preferences`' bits: bit 2 is contrast `more`,
bit 3 contrast `less`. There is no new ABI entry.

`prefersColorScheme`: `"light" | "dark"`. This is **the system's**
preference, which is what CSS's media feature reports whatever a page's
`color-scheme` says. It is not the appearance an app's `setScheme` chose.
The app already knows its own override. Bit 4 is `dark`. Web: `matchMedia`;
Apple: the trait collection or `NSApp.effectiveAppearance` at the window
level, beneath the override; Linux: `light` unless the agent says otherwise.
This field needs Charlie's ruling on LLP 1034 D3 (see For Charlie). Without
it, the field is dropped and the macOS workaround stays.

*Rejected:*

- **`exactPreferences()`.** LLP 1061 D5 rejected it already: it would be a
  second copy of the source's bake handling.
- **A contrast enum of our own.** CSS's four values are the vocabulary.

### D2 — `exactPage()`: visibility and connectivity

These two are not media features, so they get their own source. A tick that
re-answers `onLine` would otherwise re-answer every size reader as well.
`exactPage` follows LLP 1039 D1–D3 exactly:

- It is filled by field name, and an unknown field fails the bake
  (`bake-page-field`).
- The runner holds the value and the host sets it
  (`Runner::set_page(visible, online)`, recommitting only its readers).
- It is device data the bake never fixes. The bake answers `visible` and
  `true`.

| field | web | iOS | macOS | Linux |
|---|---|---|---|---|
| `visibilityState` | `document.visibilityState`, `visibilitychange` | scene `didEnterBackground`/`willEnterForeground` | `NSApplication.didHide`/`didUnhide`, and every window occluded (`NSWindow.occlusionState`) | `visible` (DRM has one screen; headless is visible) |
| `onLine` | `navigator.onLine`, `online`/`offline` | `NWPathMonitor` `.satisfied` | `NWPathMonitor` | `true` |

`hidden` means what the web means: nothing of the page can be seen. It
doesn't mean "not key", so a Mac window behind another is still `visible`.

`onLine` also means what the web means, and says as little. `true` does not
promise the origin can be reached. The app still handles a failed `fetch`.
Apps and reviewers read `false` as "don't try".

A change arriving while iOS suspends the process is applied on return, in
the same turn as the foreground notification. This is the rule `set_time`
follows after a boot (LLP 1061 D5).

*Rejected:*

- **An `onvisibilitychange` handler.** `when` is the handler (LLP 1039 §6).
  A resource that reads `page.visibilityState` stops its tick by answering
  differently. A side effect on hide, such as flushing a draft, is storage's
  job: ordered storage commits as it goes (LLP 1018).
- **`native.watch("network")` through LLP 1016.002.** That seam is for an
  app's own native module. A fact every host reports belongs to the runner,
  where the agent and the bake see it.
- **Reachability of a named origin** (`SCNetworkReachability` with a host).
  The web has no such thing, and it lies as often as it helps.

### D3 — Text size is `rem` over a root font size the host sets

CSS has no media feature for text size. The web's mechanism is the root
element's font size, which the browser setting changes, together with
lengths relative to it. `px` does not follow it. Following CSS:

- The kernel gains `rem` for every length row. `em` comes with it, since
  the grammar is the same and it is relative to the inherited `font-size`
  row.
- It also gains one root value, `root_font_size`, initially 16 (CSS
  `medium`).
- The host sets that value:

  | host | source of the root font size |
  |---|---|
  | web | `getComputedStyle(document.documentElement).fontSize` |
  | iOS | `UIFontMetrics.default.scaledValue(for: 16)` for the current `preferredContentSizeCategory`, and its change notification |
  | macOS | 16; the Mac has no Dynamic Type |
  | Linux | 16 |

- A change relays out, the way `set_viewport` does. No resource is
  re-answered, because no app logic reads it.

An app that writes `font-size="1rem"` scales. One that writes `16px` doesn't,
exactly as on the web. Nothing changes for existing apps.

*Rejected:*

- **A `fontScale` fact.** It would push the scaling into every expression
  (`16 * media.fontScale`), and nothing on the web reads that way.
- **Scaling `px` on iOS.** That breaks the parity oracle: Chrome does not
  scale `px` for a font setting.

### D4 — What stays out, with triggers

These wait for a consumer, as LLP 1039 §6 left them:

- **`pointer`, `hover`, `any-pointer`.** Wait for an app that branches on
  touch versus mouse. On iPad with a trackpad they change at run time, and
  the fact path handles that.
- **Device pixel ratio.** LLP 1039 §6 applies unchanged.
- **`forced-colors` and `inverted-colors`.** Wait for a consumer. Windows
  isn't a host, and the iOS setting (Smart Invert) inverts images the app
  must opt out of, which is a presenter concern.
- **Battery, low-power mode and thermal state.** These have no web name.
  An app that wants them writes a native module (LLP 1067, 1016.002).
- **`navigator.connection` (effective type, save-data).** Chromium only.
  Wait for a consumer.

### D5 — Core, not a linked capability

The facts are a few booleans and strings in the runner, and hosts already
observe the lifecycle. Under LLP 1047, a capability that costs bytes only
when used is linked. These cost almost nothing, and a host that skips
observing them answers the defaults. `rem` is layout, so it is core.

### D6 — The agent sets them with `prefer`, and the page facts by name

`prefer`'s `PREFERENCES` table (`scripts/agent.mjs:153`) gains:

- `prefers-contrast more|less|no-preference`.
- `visibility-state visible|hidden` and `online true|false`. These are
  page facts, not media features, and `prefer` is where the agent already
  stands in for the device.
- A text size, `root-font-size <px>`.

On each host:

- **Web:** CDP's `Emulation.setEmulatedMedia` covers contrast.
  `Page.setWebLifecycleState` and `Network.emulateNetworkConditions
  {offline}` cover the page facts. The root size is set on
  `documentElement`.
- **Apple and Linux:** the agent's value stands in for the platform
  reading, as `DisplayPreferences.agent` does (LLP 1061 D5).

This is LLP 1069.007's rule applied: every fact here has a substitute on
every host. Whether `prefer` stays a ninth operation is `rules/DEFERRED.md`'s
open question, and this adds no tenth.

None of these facts needs a permission, so none has a grant or a usage
string (LLP 1069.008). `NWPathMonitor` needs no entitlement.

## Verification

- One fixture app reads all six fields and shows them.
- A `.test.contract` sets each through `prefer`, holds `state.resources`
  equal on web, macOS, iOS and Linux, and checks that a hidden page stops a
  1 s tick. It then `clock +5000`s, confirms no commit, sets `visible`, and
  sees one.
- For `rem`, a parity page at root sizes 16 and 24 against Chrome's pictures.

## Not in this RFC

- Any policy in the runner or engine. As with reduced motion, the app reads
  the value and chooses (`rules/DEFERRED.md` §Motion).
- A `@media`-like syntax in Contract. `when` and expressions stay the
  mechanism.
- Background execution while hidden (the survey's "not now").

## For Charlie

1. **LLP 1034 D3 and `prefersColorScheme`.** Should the system's scheme be a
   fact?
   - *For:*
     - CSS has the media feature, and the web is the standard.
     - `prefer` already accepts `prefers-color-scheme`, so the agent can set
       what no app can read.
     - The macOS reader's hidden-field workaround (`DocumentsMac.swift`) and
       its `theme.icons` filename suffix (LLP 1034 D3's surviving consumer)
       become one field on every host.
     - Canvas, GPU and SVG content and TypeScript-produced colours (chart
       palettes, map tile styles) have no `light-dark()` to lean on.
   - *Against:*
     - D3's point stands: a colour computed from a fact costs a recommit
       and a re-render on every appearance change, where a pair costs a
       host repaint.
     - A fact invites apps back into resolving colours in logic.
   - **Recommendation:** admit it as the *system's* preference only, as CSS
     does, and keep a lint that a literal colour chosen by branching on it
     should be a `light-dark()` pair.
2. **`exactPage` as a new reserved source**, versus two more fields on
   `exactViewport`. The recommendation is a new source (D2).
3. **`rem`/`em` (D3)** is a kernel vocabulary change that follows CSS. It
   doesn't need a `rules/DEFERRED.md` line, but it touches the schema, so
   it should be ruled.
4. **`prefer` grows** (D6). This extends a ninth operation that is itself
   awaiting a ruling. If `prefer` is folded into another operation, these
   forms go with it.
