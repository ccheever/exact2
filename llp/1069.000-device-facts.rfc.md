## Summary

The survey's first item asked for reduced motion, locale, time zone, font
scale, foreground/background and online status as facts. Main has landed
half of that:

| fact | where it is now | landed by |
|---|---|---|
| `prefersReducedMotion`, `prefersReducedTransparency` | `exactViewport()` | LLP 1061 D5 |
| `locale`, `timeZone`, `seed`, `epochAtZero`, `utcOffset` | `exactTime()` | LLP 1027.000.000, LLP 1060 |
| the system's colour scheme | macOS only, as a hidden field's value (`ExactDocuments.reportAppearance`, `DocumentsMac.swift:106`) | LLP 1033 D6 workaround |

What remains, and where each goes:

- **`prefersContrast`** and **`prefersColorScheme`** go on `exactViewport`.
  They are CSS media features, and the source's rule is "what `@media`
  answers" (LLP 1061 D5).
- **`visibilityState`**, **`onLine`** and **`canShare`** go on a new source,
  `exactPage()`, named for the Page Visibility API, `navigator.onLine` and
  `navigator.share`. They are not media features.
- **Text size** (Dynamic Type) is not a fact. It is CSS's root font size and
  a `rem` unit, so an app scales text by writing `rem`, as on the web.

```
shape Media
  prefersContrast: string        // "more" | "less" | "custom" | "no-preference"
  prefersColorScheme: string     // "light" | "dark": the system's, under any setScheme
shape Page
  visibilityState: string        // "visible" | "hidden"
  onLine: bool
  canShare: bool                 // LLP 1069.003 D5

component Feed
  resource media = exactViewport() as shape Media
  resource page = exactPage() as shape Page
  view
    column border-width=(media.prefersContrast == "more" ? "2px" : "1px")
      when not page.onLine
        text "Offline — showing saved posts" font-size="0.875rem"
```

`prefer` sets every one of these by its web name (D6).

## Motivation

- **The scheme workaround.** The Markdown reader learns the system
  appearance by having the macOS host type into a hidden field
  (`session.change(testId: appearanceTestId, …)`, `DocumentsMac.swift:107`).
  That works on macOS only, and it spends a node and an event on a fact.
- **Offline.** Bluesky, Messages and RealWorld show a spinner and then a
  failure when the network is gone, because nothing tells them in advance.
  `fetch` failing is the only signal (LLP 1016 D4: failure is data).
- **Hidden.** An app can't stop a live tick while it is hidden, or refresh
  on return: the crypto list's 100 ms tick (QUEUE), Bluesky's notification
  poll. Hosts already observe the lifecycle for their own reasons
  (`CanvasSeams.swift:662-670`, audio; `CollectionIOS.swift`, collections;
  `gpu-glue.js:118`, the GPU loop). Only the app is left out.
- **Contrast and text size.** The two accessibility settings after motion
  that a native app is expected to honour. App Store review and users notice
  Dynamic Type first.

Absences checked 2026-09-27 by grep over `host/`, `runner/`, `kernel/` and
`scripts/`, and rechecked in r2:

- No `prefers-contrast`, `darkerSystemColors` or `IncreaseContrast`. The
  only hit is the Linux agent test checking that `prefer` refuses it
  (`host/linux/src/agent.rs:646`).
- No `preferredContentSizeCategory`, `UIFontMetrics`, `navigator.onLine`,
  `online` listener or `NWPathMonitor`.
- No `rem` or `em` length unit: `kernel/src/style.rs` parses `px` and
  percent only, and says "percent/em unsupported" (`style.rs:415`).

## Design

### D1 — Two more media features on `exactViewport`

`prefersContrast`: `"more" | "less" | "custom" | "no-preference"`, CSS's
values (Media Queries 5 §11.3). A host reports what it can read:

- **Web:** `matchMedia` for `more` and `less`, the path reduced motion takes.
- **iOS:** `UIAccessibility.isDarkerSystemColorsEnabled` → `more`, with its
  change notification.
- **macOS:** `NSWorkspace.accessibilityDisplayShouldIncreaseContrast` →
  `more`.
- **Linux and the renderer:** `no-preference`.

Both go through `exact_set_preferences`' bits: bit 2 is contrast `more`,
bit 3 contrast `less`. No new ABI entry.

`prefersColorScheme`: `"light" | "dark"`. **The system's** preference, which
is what CSS's media feature reports whatever a page's `color-scheme` says.
It is not the appearance an app's `setScheme` chose; the app knows its own
override. Bit 4 is `dark`.

- **Web:** `matchMedia`.
- **Apple:** the trait collection, or `NSApp.effectiveAppearance` at the
  window level, beneath the override.
- **Linux:** `light`.

It amends LLP 1034 D3 ("never a fact in the app") for this one field. D3's
point stands for colours: a colour computed from a fact costs a recommit on
every appearance change, where a `light-dark()` pair costs a host repaint.
So the bake lints a literal colour chosen by branching on
`prefersColorScheme` and names the `light-dark()` pair to write instead.
What the fact is for: canvas, GPU and SVG content, TypeScript-made colours
(chart palettes, map tile styles), and the reader's `theme.icons` suffix.
The macOS hidden-field workaround is deleted when this lands.

*Rejected:*

- **`exactPreferences()`.** LLP 1061 D5 rejected it: a second copy of the
  source's bake handling.
- **A contrast enum of our own.** CSS's four values are the vocabulary.

### D2 — `exactPage()`: visibility, connectivity, and whether share exists

These are not media features, so they get their own source. A tick that
re-answers `onLine` would otherwise re-answer every size reader too.
`exactPage` follows LLP 1039 D1–D3:

- It is filled by field name; an unknown field fails the bake
  (`bake-page-field`).
- The runner holds the value and the host sets it
  (`Runner::set_page`, recommitting only its readers).
- It is device data the bake never fixes. The bake answers `visible`,
  `true` and `false`.

| field | web | iOS | macOS | Linux |
|---|---|---|---|---|
| `visibilityState` | `document.visibilityState`, `visibilitychange` | scene `didEnterBackground`/`willEnterForeground` | `NSApplication.didHide`/`didUnhide`, and every window occluded (`NSWindow.occlusionState`) | `visible` |
| `onLine` | `navigator.onLine`, `online`/`offline` | `NWPathMonitor` `.satisfied` | `NWPathMonitor` | `true` |
| `canShare` | `typeof navigator.share === "function"` | `true` | `true` | `false` |

- `hidden` means what the web means: nothing of the page can be seen. A Mac
  window behind another is still `visible`.
- `onLine` says as little as the web's. `true` doesn't promise the origin
  can be reached; the app still handles a failed `fetch`.
- `canShare` is LLP 1069.003 D5's; its meaning is owned there.
- A change arriving while iOS suspends the process is applied on return, in
  the same turn as the foreground notification, as `set_time` does after a
  boot (LLP 1061 D5).

*Rejected:*

- **An `onvisibilitychange` handler.** `when` is the handler (LLP 1039 §6).
  A resource that reads `page.visibilityState` stops its tick by answering
  differently. Flushing a draft on hide is storage's job: ordered storage
  commits as it goes (LLP 1018).
- **`native.watch("network")` through LLP 1016.002.** That seam is for an
  app's own native module. A fact every host reports belongs to the runner,
  where the agent and the bake see it.
- **Reachability of a named origin.** The web has no such thing, and it
  lies as often as it helps.
- **The two page facts as `exactViewport` fields.** Ruled (Q2).

### D3 — Text size is `rem` over a root font size the host sets

CSS has no media feature for text size. The web's mechanism is the root
element's font size, which the browser setting changes, and lengths
relative to it. `px` doesn't follow it. Following CSS:

- The kernel gains `rem` for every length row, and `em` with it (relative
  to the inherited `font-size` row). A schema change, ruled (Q3).
- One root value, `root_font_size`, initially 16 (CSS `medium`).
- The host sets it:

  | host | the root font size |
  |---|---|
  | web | `getComputedStyle(document.documentElement).fontSize` |
  | iOS | `UIFontMetrics.default.scaledValue(for: 16)` for the current `preferredContentSizeCategory`, and its change notification |
  | macOS | 16; the Mac has no Dynamic Type |
  | Linux | 16 |

- A change relays out, as `set_viewport` does. No resource is re-answered,
  because no app logic reads it.

`font-size="1rem"` scales; `16px` doesn't, exactly as on the web. Nothing
changes for existing apps.

*Rejected:* a `fontScale` fact (it pushes scaling into every expression,
and nothing on the web reads that way); scaling `px` on iOS (Chrome doesn't,
so it breaks the parity oracle).

### D4 — What stays out, with triggers

These wait for a consumer, as LLP 1039 §6 left them:

- **`pointer`, `hover`, `any-pointer`.** An app that branches on touch
  versus mouse. On iPad with a trackpad they change at run time; the fact
  path handles that.
- **Device pixel ratio.** LLP 1039 §6 unchanged.
- **`forced-colors`, `inverted-colors`.** Windows isn't a host, and Smart
  Invert is a presenter concern.
- **Battery, low-power mode, thermal state.** No web name; a native module
  (LLP 1067, 1016.002).
- **`navigator.connection`.** Chromium only.

### D5 — Core, not a linked capability

A few booleans and strings in the runner, and hosts already observe the
lifecycle. Under LLP 1047 a capability that costs bytes only when used is
linked; these cost almost nothing, and a host that skips observing them
answers the defaults. `rem` is layout, so it is core.

### D6 — Substitute: `prefer` sets every fact here

The shape is a fact (LLP 1069.007 D1). `prefer`'s table
(`PREFERENCES`, `scripts/agent.mjs:154`) gains, in LLP 1069.007 D2's
grouping:

| `prefer` name | values | source field | agent default |
|---|---|---|---|
| `prefers-contrast` | `more`, `less`, `no-preference` | `exactViewport().prefersContrast` | `no-preference` |
| `prefers-color-scheme` | `light`, `dark` (already accepted) | `exactViewport().prefersColorScheme` | `light` |
| `visibility-state` | `visible`, `hidden` | `exactPage().visibilityState` | `visible` |
| `online` | `true`, `false` | `exactPage().onLine` | `true` |
| `can-share` | `true`, `false` | `exactPage().canShare` | `true` (the substitute answers `share` on every host, LLP 1069.003 D6) |
| `root-font-size` | a px number | the kernel's root font size | `16` |

- **Launch:** each name is also a launch flag (`--online false`), as
  `--seed`, `--locale` and `--time-zone` are today (`scripts/agent-launch.mjs`).
- **Web:** CDP's `Emulation.setEmulatedMedia` for the media features;
  `Page.setWebLifecycleState` and `Network.emulateNetworkConditions
  {offline}` for the page facts; the root size set on `documentElement`.
  `can-share` is the glue's own value under `?agent=1`.
- **Apple and Linux:** the agent's value stands in for the platform
  reading, as `DisplayPreferences.agent` does (LLP 1061 D5).

None of these needs a permission, so none has a grant or a usage string
(LLP 1069.008). `NWPathMonitor` needs no entitlement.

## Verification

- One fixture app reads all seven fields and shows them.
- A `.test.contract` sets each through `prefer`, holds `state.resources`
  equal on web, macOS, iOS and Linux, and checks that a hidden page stops a
  1 s tick: `clock +5000`, no commit; `visible`, one.
- For `rem`, a parity page at root sizes 16 and 24 against Chrome's
  pictures.

## Not in this RFC

- Any policy in the runner or engine. As with reduced motion, the app reads
  the value and chooses (`rules/DEFERRED.md` §Motion).
- A `@media`-like syntax in Contract. `when` and expressions stay the
  mechanism.
- Background execution while hidden (the survey's "not now").

## Decided

1. `prefersColorScheme` is a fact, the system's only, with the
   `light-dark()` lint; LLP 1034 D3 amended (D1).
2. `exactPage()` is a new source, and carries `canShare` (D2).
3. `rem`/`em` and a host-set root font size (D3).
4. `prefer` sets every fact here; no tenth operation (D6).
