## Summary

Accept `image "symbol:sf/<name>"`, including a source computed at runtime.
On Apple, look up the exact name through the operating system. If the name
is unavailable, paint nothing. On web and Linux, paint nothing. Use the
same image source inside ordinary buttons and the existing native tab bar.
Exact maintains no SF Symbol catalog or OS availability table.

Every unresolved symbol — an SF name the OS lacks, any SF name off Apple,
an unknown dynamic portable role — is the same thing on every host: an
empty square one `font-size` on a side as its fallback intrinsic size.
This provides predictable geometry; a fixed icon slot still needs authored
dimensions. Agent inspection reports the current resolution result.
Absence is expected and cannot distinguish a typo from an unavailable name.

Keep `symbol:<role>` for the existing portable roles and their declared
fallback artwork. The two forms express different author intent.

Charlie's implementation instruction accepts this amendment. It replaces
1035.004 D1's prohibition of `symbol:sf/…`, narrows D3's unknown-role
diagnostic to portable roles, and gives unresolved symbols D2's em square.

## Motivation and evidence before implementation

James reports that missing SF Symbols are causing his agent to build a new
tab bar. He also wants symbols in buttons and images, with dynamic names
and blank rendering on an OS that does not support a name.

The present restriction is in Exact. `contract/lower/src/values.rs:497`
checks literal `symbol:` sources against the generated role table.
`host/apple/src/host.rs:1431` also resolves dynamic sources through that
table, emitting an empty `symbolName` for an unknown role, which the Swift
leaf journals as `refused: unknown symbol role`. The Swift image views
already call `UIImage(systemName:withConfiguration:)` and
`NSImage(systemSymbolName:accessibilityDescription:)`; the iOS tab bar
(`SegmentsIOS.swift:206`) and the macOS toolbar (`ToolbarMac.swift:179`)
already pass a string to the same lookups.

A local compiler probe on 2026-10-02 reproduced the boundary: `symbol:home`
compiled; literal `symbol:sf/house.fill` failed with `lower-attr-value`;
the same source in a state variable compiled. Dynamic compilation alone
therefore does not make the symbol render. This was a compiler probe, not
an end-to-end rendering test.

The other hosts, read 2026-10-02 (r2):

- **Web.** Both targets already paint nothing for a `symbol:` source that
  names no role: the JS target's `symbols.js` and the wasm host's
  `refreshSymbols` (`host/web/glue.js:369`) look the suffix up in the role
  table, miss, and write a 0×0 placeholder; neither emitter puts a
  `symbol:` source in `img.src` (`host/web-js/src/emit.rs:826`,
  `host/web/src/document.rs:439`). The wasm glue journals the miss as an
  unknown role; the JS target is silent. The live web paths need the new
  fallback size and recognition of expected SF absence. The HTML emitters
  also need to establish the fallback geometry before script runs;
  omitting `src` alone does not do that.
- **Linux.** The host has no symbol path. A `symbol:` source goes to the
  raster backend as a file source, is refused, and — because a changed
  source keeps "the old lease, bitmap and natural size … until acceptance"
  (`host/linux/src/image.rs:175`) — a raster → symbol change keeps showing
  the raster. That is a present bug for portable roles too, and D4 needs
  it fixed.

Apple's [UIImage initializer documentation](https://developer.apple.com/documentation/uikit/uiimage/init(systemname:))
specifies a nullable lookup result. Exact can let the running OS decide
availability instead of shipping a second catalog that ages independently.

## Proposed design

### D1 — One image source, with an explicit platform namespace

```contract
component App
  state symbolName = "house.fill"
  view
    image "symbol:sf/house.fill"
    button aria-label="Home"
      image ("symbol:sf/" + symbolName) width=24 height=24
```

The suffix after `symbol:sf/` is an opaque, case-sensitive OS name.
Pass it unchanged: do not add `.fill`, translate aliases, normalize names,
or check membership in a generated list. Literals and dynamic expressions
have the same acceptance and rendering semantics. An empty suffix is
accepted in both forms and paints nothing with D2's fallback intrinsic
size. `image "symbol:sf/"` can intentionally reserve a blank slot or keep
the symbol-over-label tab shape while no icon is selected. The compiler
checks neither name membership nor an invented name grammar.

`symbol:home` still names a portable role. Unknown literal portable roles
retain their diagnostic; unknown dynamic portable roles retain their
existing behavior, apart from D2's box. SF names are explicitly qualified,
so a future OS name cannot collide with an Exact role; to keep that true,
`kernel/build.rs` refuses a role named `sf` or containing `/`.

No new tag, button property, style row, registry or capability module is
needed. `kernel/tables/schema.json` remains the authority for portable roles;
raw names are values, not declarations in that table.

This amendment adds no controls for rendering modes (monochrome,
hierarchical, palette, multicolor), variable values or symbol effects,
and no custom symbols from an app's asset catalog. Raw names use the
existing native configuration and platform rendering defaults, including
the existing tint handling; this does not guarantee monochrome artwork.
Apple documents that an unspecified mode can select a symbol's preferred
rendering mode ([symbol configuration](https://developer.apple.com/documentation/uikit/configuring-and-displaying-symbol-images-in-your-ui)).
Adding explicit rendering controls is a separate request.

### D2 — The OS resolves names; absence is an empty em square

On iOS and macOS, pass the raw name through the existing symbol-image
path. Retain its font-size, font-weight, tint-color and object-fit behavior.
Availability depends on the OS running the app, not the SDK or machine
that compiled its Contract.

An empty name or failed lookup clears the glyph. It does not show a
placeholder, retain the previous glyph, or fail the app. Its intrinsic
size is a square one computed `font-size` on a side — the box the web's
portable renderer already gives a known role — on every host, for every
unresolved `symbol:` source (raw or portable). Explicit dimensions and
constraints still win (LLP 1011 §1). An SF glyph's own intrinsic box is
not necessarily square, so valid ↔ missing can change layout substantially;
authors who need a slot that never moves set its dimensions, as in D1.

r1 had the unresolved image supply no intrinsic size. That follows a bare
`<img>`, but `symbol:` is already a declared non-web scheme whose sizing
follows the font (1035.004 D2), and a zero box breaks the layouts this RFC
exists for: an icon-only button shrinks to its padding, and on the web —
the dev loop and parity oracle, where every SF name is unresolved — every
SF icon can collapse. The em square supplies predictable fallback
intrinsic geometry on the web; it does not reproduce the Apple glyph's
aspect ratio or guarantee identical used layout across hosts.

The containing button keeps its action, accessible name and authored
layout; no special minimum hit target is invented here.

**Inspection.** Extend the existing `layout` response with the requested
source/name and its current resolution result; on Apple, extend
`native.symbol`. `found` means this host resolved an image, not that pixels
were painted: visibility, clipping, opacity and native projection are
separate observations. A successful result has no `reason`. When `found`
is false, `reason` is `empty` for an
empty SF suffix, `role` for an unknown portable role, `platform` when the
host has no renderer for the source, or `os` when Apple lookup failed.
These distinguish expected absence without claiming to detect a typo.

An unavailable or empty SF name needs no journal warning. Keep inspection
about the current live node; add no session-wide set of previously missed
names or application-facing availability API. Existing bounded diagnostics
for unknown portable roles remain separate and must not mislabel a raw SF
source as an unknown role.

Source changes must work both ways: valid → unavailable → valid, empty →
valid, and between a raw symbol, a portable role and a raster image. Clear
old symbol, raster, tint-mask and measurement state through the existing
image lifecycle; late raster results must not overwrite a newer symbol.

### D3 — Buttons and native projections consume the same image

A button uses an image child, with its accessible name on the button.
Native button projection must carry the same resolved image, including
clearing a previously displayed image when lookup fails.

LLP 1059's symbol-over-label tab shape also accepts raw symbol sources.
Projection eligibility depends on the authored symbol source and label,
not on whether the current OS finds a glyph. A missing or empty name must
not switch the tablist to another control or remove its tab. The native
item keeps its title, action, enabled state and selection, with no image.
A dynamic name change updates the icon without resetting the selected tab
or its content. Native items take UIKit's and AppKit's own image sizing;
D2's em square is the kernel box, not theirs.

The existing projections that consume symbol names or resolved images
must each follow this:

- iOS tab bar — `TabBarFace` (`SegmentsIOS.swift:43`) refuses an empty
  `symbolName` today, so an empty dynamic name would drop the tablist out
  of projection. Eligibility keys on the image source instead.
- iOS image-only segmented control (`SegmentsIOS.swift`, `content`): a
  missing image clears the previous image and cached icon identity as well
  as the visible title.
- macOS image-only segmented control (`SegmentsMac.swift`): today a nil
  image falls through to a visible accessible-name label. Preserve the
  authored image-only presentation instead: no glyph and no substitute
  visible text, with the accessible name retained for assistive technology.
- macOS toolbar items (`ToolbarMac.swift:174`), which already clear the
  item image for an empty name and must do the same for a nil lookup.

This removes the symbol-list reason to replace the native tab bar. It does
not resolve the separate native-control ownership questions in LLP 1075.

### D4 — Web and Linux have an explicit empty result

Every non-Apple host recognizes `symbol:sf/…` as a symbol source and paints
an empty image with D2's box. In a browser this includes the JS target,
wasm host and prerendered HTML before adoption. Do not put the custom
source in a fetching `img.src`, show the browser's broken-image indicator,
or leave an earlier portable symbol's mask in place. Preserve authored
sizing and accessibility.

Even a name such as `house` that happens to have a portable equivalent stays
empty: there is no implicit reverse lookup or expanding SF-to-SVG table.
This source delegates to the native symbol service; Exact does not bundle
Apple's artwork for other hosts. An author needing artwork on the web can
choose an existing portable role or supply their own image/SVG through
existing composition.

On Linux, `symbol:` is recognized before the raster backend: the view drops
its lease and bitmap as for an empty source, reports D2's box, and records
no refusal. Portable roles keep LLP 1015 §7's declared gap (an empty box)
until the painter draws their paths; this fixes the stale-raster case for
them too.

This extends the already declared non-web `symbol:` source scheme. CSS
still determines the image box. At implementation, record the platform
lookup and empty fallback beside the existing declaration in LLP 1001
and the image source policy in LLP 1011.

## Implementation boundary and acceptance

The change is in source validation and host interpretation, without a new
plan opcode or author-facing API beyond the source form. In particular:

- Distinguish `symbol:sf/` before portable-role validation. Accept names
  absent from all compiler tables, including names supplied only by data
  and empty suffixes in either form. `kernel/build.rs` refuses a role named
  `sf` or containing `/`.
- Resolve Apple `symbolName` without the role table for this namespace.
  Update native batch size accounting in `content_region.rs:392` as well as
  property emission, so arbitrary name lengths are budgeted correctly.
- Apple leaf (`NodeViewIOS.swift:403`, the macOS twin): queue the em square
  as the intrinsic size when there is no glyph; report the current
  `found`/`reason` per D2 without tracking names over the session lifetime.
- Update native projection eligibility and image replacement, including
  the empty-name case currently excluded by `TabBarFace`.
- Web: in `symbols.js` and `glue.js` `refreshSymbols`, size the placeholder
  at the font size when the source is unresolved, and keep the
  unknown-role journal line to portable roles. Both HTML emitters establish
  the fallback geometry before scripts run, respecting inherited font
  size and authored dimensions; adoption preserves it. Changing only
  post-mount refresh is insufficient.
- Linux: the `symbol:` early-out in `image.rs` described in D4.
- Amend the parent RFC, image source policy and schema commentary when
  implementation lands; do not generate or bundle Apple's catalog.

Extend existing compiler, host and app-drive checks. Prove an OS-supported
name absent from Exact's role table renders in a standalone image, an
ordinary button and a native tab item. Prove a deliberately nonexistent
name and both literal/dynamic empty names paint nothing at the em square,
without missing-SF warnings, and `layout` reports `found: false` with the
appropriate reason. Successful resolution remains `found: true` even when
the node is hidden. Drive valid → missing → valid and symbol ↔ raster
transitions. Verify the
controls still activate, tab selection survives, an unresolved symbol
supplies em-square intrinsic geometry, and clearing the glyph replaces old
intrinsic sizing. A fixed-size authored slot keeps its size across source
changes. Include image-only segmented controls on both iOS and macOS:
neither keeps a stale icon or substitutes visible text for a missing one.

On web, cover static and data-provided names, prerender/adoption, no broken
image or custom-scheme fetch, and clearing a portable symbol's mask. Drive
the same cases on Linux, including raster → symbol (no stale picture).
Build and launch the touched Apple apps and inspect screenshots and native
control identity as well as agent state. Build both macOS and iOS after the
Swift edits; the five checks compile no Swift. Run the existing five
checks; add no script or blocking gate.

## Decision to make

Accept the raw namespace and its deliberate empty result on unsupported
platforms. Portable role diagnostics remain useful; arbitrary SF names
trade compile-time name checking for OS-owned availability, exactly as
James requests. D2 makes the lookup result inspectable, without claiming
to distinguish a typo from an intentional use of a newer symbol.

The cost to name plainly: an SF-only icon is verified only on an Apple
host. The web dev loop shows fallback geometry and nothing in it, so an agent
iterating on the web cannot see the icon it chose; an app that ships on
the web and wants an icon there still needs a portable role or its own
artwork. This amendment adds neither a
general native-property interface nor a fallback-image API.

## Revision r3 (Codex, 2026-10-02)

Applied the independent [Astra Max review of r2](reviews/1035.004.000-arbitrary-sf-symbols.astra.md),
requested by Charlie. The proposal remains Draft; the review did not
approve implementation. All four concerns and the implementation
clarifications were accepted:

1. **Current-resolution inspection, no session-wide missed-name journal**
   (D2). Unavailability is expected; no lifetime-growing deduplication set
   or claim of runtime typo detection.
2. **Empty literals and dynamic names behave alike** (D1).
3. **Preserve native rendering defaults** (D1). Removed the unsupported
   universal monochrome promise; rendering-mode controls remain separate.
4. **Include macOS image-only segments** (D3), preserving accessibility
   without substituting visible labels; explicitly clear iOS image caches.
5. **Clarify fallback geometry and inspection** (D2), and require both HTML
   emitters to supply the fallback before adoption. The raw namespace,
   OS lookup, em-square fallback and native-control stability stay.

D4 now states the implementation boundary directly instead of making a
broad licensing claim; no artwork redistribution is proposed.

## Implementation and verification (Codex, 2026-10-02)

Implemented the raw namespace without a catalog or new plan row. Apple
forwards the suffix and reports lookup independently of visibility and
zero-size painting. Web JS and wasm keep raw names empty; both Rust and
JavaScript prerenderers emit a transparent SVG with the inherited font
size as its natural dimensions, so CSS still owns aspect ratio and the
used box. The JS render DOM now supplies the descendant enumeration its
existing boot journal calls. Linux cancels raster demand and removes the
old bitmap before supplying the fallback size.

An image-only native segment uses a transparent image when unresolved:
UIKit's image accessibility label and AppKit's image description retain
the authored accessible name without a visible fallback title. Tab-bar
eligibility follows the source, including `symbol:sf/`.

Verified with `host/web-js/conformance/symbols.contract` on macOS, iOS,
Linux, JS web and wasm web. `airpodsmax` renders on both Apple hosts in
images, buttons and native controls. Missing/empty names clear the glyph,
retain selection and actions, and supply the 20-point then 28-point box;
fixed 40×24 and width-only 40×40 cases stay correct. Symbol/raster changes
and restored valid names work. Hidden and zero-font Apple symbols still
report `found: true`. Inspected screenshots and `layout`/`state`/`logs`;
there are no missing-SF journal warnings. Both prerenderers were loaded
without app scripts in Chromium, including explicit `aspect-ratio: auto`.
Local drive evidence is under `/tmp/exact-sf-*`.

Compiler admission, Apple property mapping, Linux stale-raster and Rust
prerender regression tests pass. Swift suites: 511 macOS tests (one skip)
and 103 iOS tests passed; Xcode hung after the iOS suite and its test
process was stopped after the pass report. Final macOS/iOS app builds
and drives passed. All five required gates passed: build; the default-member test run
(2,018 passed, eight ignored, zero failures); clippy and formatting; caps;
and boot. Host clippy also passed after removing an unnecessary string
allocation in the Linux picker call. JS and final wasm drives had matching
layout, state and symbol inspection, with pixel-identical final screenshots.

The broader host Rust run reported twelve shared network/stream timeout
cases across Apple/Linux and two Apple text-flow fixture errors. In a
follow-up requested by Charlie (2026-10-02), the shared text-flow fixture
was given `position="relative"` on its wrapping parent. All four Apple
text-flow tests now pass, including both previously failing cases, with
their assertions unchanged. The queue item is removed; transport code
remains unchanged.
