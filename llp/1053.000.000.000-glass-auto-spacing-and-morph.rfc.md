# LLP 1053.000.000.000: Glass groups — spacing from the gap, and a morph when glass is replaced

**Type:** RFC
**Status:** Draft r1 (2026-10-02)
**Systems:** Kernel (`glassGroup`'s value, one style row), Contract (`glassGroup="auto"`, `view-transition-name`), Apple host (`GlassGroup.swift`, both presenters), web (one CSS property written), docs
**Author:** Claude (Opus 5.5) for Charlie Cheever
**Date:** 2026-10-02
**Related:** LLP 1053.000.000 (glass groups; its §5 owes both of these, from James's prototype), LLP 1013 (view transitions, Draft: `view-transition-name`), LLP 1002 D1/D2 (one representation; the browser as oracle), LLP 1069.011 D9 (native glass buttons are glass bodies)
**Decision:** Charlie, 2026-10-02: "Do all these" (the owed list, "Glass groups still lack automatic spacing and morphing")

## Summary

Two things James's prototype had that `glassGroup` (LLP 1053.000.000) does not:

1. **`glassGroup="auto"`**: the merge spacing is the element's own gap, Apple's spacing-equals-gap pattern (shapes apart at rest, merging when a press swells one), so the number is not written twice and follows the gap when it changes.
2. **A morph when glass is replaced**: when, in one commit, a glass element leaves a group and another enters it with the same `view-transition-name`, the entering glass grows out of the leaving one's shape while the leaving one flows into it, and the group's container unions them — one shape that changes, as SwiftUI's `glassEffectID` does.

The morph is geometry driven by Exact's clock, not the platforms' materialize animations, because measured on iOS 27 and macOS 27 (§2): a glass that appears or disappears in a container does not morph into its neighbour (iOS cross-fades separately; macOS ignores a glass view's alpha and AppKit's animator jumps its frame), while glass moving through glass in a container unions frame by frame on both. The pairing key is CSS's `view-transition-name` (LLP 1013's), so the web's own view transitions can take the same declaration when LLP 1013 is built.

## 1. What exists

- `glassGroup` (prop 216, `float`, points, 0–10,000; LLP 1053.000.000 D1): `GlassGroup.swift` reads `props["glassGroup"]` as a number (`glassGroupSpacing`, 93-96) and sets `UIGlassContainerEffect.spacing` / `NSGlassEffectContainerView.spacing`. Contract checks the literal (`values.rs:576`). The web writes the attribute and draws nothing.
- Glass bodies (the pass's registered glass: a `backgroundMaterial` glass's material view, or a native glass button's control) sit in their group's container; isolation (D4) moves a body into a slot (iOS) or container (macOS) and back.
- Row gaps reach the Apple host as style channels (`row_gap`, `column_gap`, `Prepared.swift:58`).
- Presence: an exiting node keeps drawing until its exit animation ends (`beginExit`/`endExit`); an entering node is created in the commit that mounts it.
- Clocked host animation: SVG animations sample the session clock each frame (`svg.seek(clock:)`, `PresenterIOS.swift:625`), so the agent's `clock` moves them.

## 2. Measured (2026-10-02, probes in the session scratchpad)

- **iOS 27 simulator**, one `UIGlassContainerEffect` (spacing 20): *swap* — glass A's `effect = nil` and glass B's `effect = UIGlassEffect()` in one 2 s `UIView.animate`: A dematerializes and B materializes as two separate cross-fades, about 0.6 s, no union between them while both are partly drawn. *Move* — A's frame animated across B: A unions with B as it passes and the two read as one shape stretching (filmed at 10 fps, recorded and decoded).
- **macOS 27**, one `NSGlassEffectContainerView` (spacing 20): a glass view's `alphaValue` is ignored (a glass at alpha 0 draws fully), so a glass cannot fade in or out; `animator().frame` on a glass view jumps to the end; adding a glass beside another draws both at once, merged across the spacing. LLP 1053.000.000 §2 measured that per-frame geometry set by the host merges on both platforms.
- So the one motion both platforms union is **glass moving through glass, frame by frame**, and the one clock that drives it deterministically is Exact's.

## 3. Design

**D1. `glassGroup="auto"`.** Contract admits the literal `"auto"` (and a choice between it and numbers); the kernel stores it as `-1` in the `float` prop (negative values are otherwise refused, so the sentinel is unambiguous; the wire and the prop kind do not change). The Apple host's `glassGroupSpacing` reads `-1` as the element's gap in its main axis: `column-gap` for a flex row, `row-gap` for a flex column, the larger of the two for a grid or a block, in points; a percentage resolves against the element's content box; no gap is `0` (touching shapes merge, separated ones do not). A gap that changes changes the spacing in the same batch. The agent's `layout` reports `{spacing, auto: true}`. The web writes `data-glass-group="auto"`.

**D2. The morph's key: `view-transition-name`.** A style row, `view-transition-name` (a custom ident or `none`, not inherited), as CSS has it and as LLP 1013 proposes it. This RFC gives it one meaning and no other: pairing glass across a commit inside a glass group (D3). The web writes the CSS property; without `document.startViewTransition()` around the commit the browser does nothing with it (LLP 1013 is where the web's own transition is decided; nothing here forecloses it). Contract refuses two elements that can be mounted at once with the same literal name (CSS's own rule: duplicate names abort a transition).

**D3. The morph.** In a commit where a glass body *leaves* a group (its node exits with an `exit-animation`, or is destroyed) and another *enters* the same group (its node is created, or stops being hidden) with the same `view-transition-name`, the Apple host morphs the two bodies — the bodies only; the nodes' content (titles, symbols, children) appears and leaves as authored:

- The entering body starts in the leaving body's box (converted to the entering node's coordinates) with the leaving body's corner radius, and animates to its own box and radius.
- The leaving body animates from its box to the entering body's final box, and is removed when the morph ends (its node, if it exits, keeps its exit's own timing for everything else).
- Both are in the same container for the whole morph (the leaving body is held in the group if its node's view goes first), so the container unions them every frame: one shape that moves, stretches and settles.
- Timing: 350 ms on a smooth spring (UIKit's glass default, `UISpringTimingParameters` with `dampingRatio 1`, sampled as a cubic), on the session clock, sampled each frame as SVG animations are, so `clock +N` and `clock settle` move it and a screenshot at any clock is reproducible. A `transition` on `view-transition-name`'s pair is not read in this version (§5).
- Isolation (LLP 1053.000.000 D4) applies to each body as before; a body isolated at either end of the morph is not morphed (it does not union with its group).
- No pair, no morph: a glass that enters or leaves alone appears and leaves as today.

**D4. Where it does nothing.** Below iOS 26 or macOS 26, in an app that keeps the earlier design (`LinkedDesign.liquidGlass` false), on the web, Linux and Android: the name is written (web) or ignored, and the swap is immediate.

**D5. Tests.** Contract: `"auto"` accepted and lowered to `-1`; a negative number still refused; duplicate names refused. Apple XCTests: auto spacing from a row's and a column's gap, and changing with the gap; a paired swap in a group sampled at clock 0, 175 and 350 ms (the entering body's frame interpolated from the leaving box, both bodies in the container, the leaving one gone at the end); no morph without a pair, across two groups, or with an isolated body. The fixture (`scripts/fixtures/glass-group.contract`) gains an auto row and a swap (a compose button that becomes a send button) filmed with `screenshot … over 400 every 50` on iOS and macOS.

## 4. Build

1. Schema: the `view-transition-name` row; Contract: `"auto"` and the name, their checks; tests.
2. Apple: `glassGroupSpacing` for `-1`; the morph (pairing at batch end where the pass registers bodies, the per-frame sampler on the session clock); XCTests; the fixture.
3. Docs: LLP 1053.000.000 §5 (both owed items pointed here), LLP 1001's glass paragraph, LLP 1013's Related.

## 5. Open questions

1. Authoring the morph's timing: CSS controls a view transition's group animation with `::view-transition-group(name)`, which Contract has no selector for. Keep the fixed 350 ms until an app asks?
2. Should a glass that enters or leaves a group *alone* get the platform's materialize on iOS (a UIKit-timed cross-fade, not on Exact's clock)? This RFC says no: it would be the one glass motion an agent cannot seek.
3. `view-transition-name` taken before LLP 1013 is decided: if 1013 lands differently (another name, or scoped transitions), this row follows it.
