## P1 + P9 — no quiet failures; the words are the web's (landed 2026-08-30)

**The names (P9; LLP 1017 §8.1).** Every style attribute is its CSS property
name — `font-size`, `font-weight`, `color`, `background-color`, `opacity`,
`letter-spacing`, `line-height`, `text-align`, `gap`, `row-gap`,
`column-gap`, `padding` and its four sides, `margin` and its four sides,
`border-radius`, `border-width` and its four sides, `border-color`, `width`,
`height`, `min-`/`max-width`/`height`, `flex`, `flex-shrink`, `flex-basis`,
`flex-wrap`, `flex-direction`, `display`, `align-items`, `align-self`,
`box-sizing`, `object-fit`, `justify-content`, `position`, `top`/`left`/
`right`/`bottom`, `overflow`, `overflow-x`, `overflow-y` (new: the rows
existed, the attributes did not — `QUEUE.md`), `z-index`, `transition`,
`scale`, `rotate` — and every prop attribute its HTML or ARIA name:
`aria-label`, `aria-description`, `aria-level`, `role`, `placeholder`,
`value`, `href`, `disabled`, `lang`; `testId` is the one Exact-named
attribute; the tag names and the primary-argument sugar stay Contract's. No
aliases: `size`, `fontSize`, `radius`, `label`, and the rest are refused as
`lower-unknown-attr` with the CSS name they became in the message
(`contract/lower/src/tags.rs`, `renamed`). **The lexer** reads a hyphen
inside a name when a letter follows it, so `font-size` is one token and, as
in CSS `calc()`, subtraction between two names is written `a - b`; `x-1` still
lexes as `x`, `-`, `1`. An unknown hyphenated name says so
(`type-unknown-name`'s hint). Rewritten once, mechanically: `apps/caltrain/
app.contract` (58 attributes), the six corpus fixtures, and every test that
embeds Contract source; Weird Castle's `app.contract` with the merge.

**Values checked at compile time (P1a).** A literal style value goes through
the kernel's own parser before lowering — `StyleProps::set_dynamic` on a
probe, one row at a time — so `width=true`, `align-items="middle"`,
`background-color="red"`, and `padding="auto"` are `lower-attr-value` with the
row's name and the kernel's reason in the author's words (`describe` in
`contract/lower/src/lib.rs`); a computed value must be a number or a string
(`lower-attr-type`), and a prop's value must be the prop's type — text for
most, a bool for `disabled`, a whole number for `aria-level`
(`tags::prop_ty`). What the runner did at the first frame (LLP 1005 §6,
`StyleProps::set_dynamic` through `bridge.rs`) it still does for computed
values; the literal case is now the compiler's.

**The compiler refuses what the runner refuses (P1b).** A `when`, `each`, or
`match` at the root of a view is `lower-root-region` (the runner's
`RootRegion`, which used to surface in every host's `build.rs` — `QUEUE.md`).
A handler behind a child's `action` prop names the real action after
inlining, and its arity is `lower-handler-arity` there — LLP 1006 §8's
"checked at dispatch" circle-back, closed.

**Two layout refusals in the compiler (P1c), conservative.** A `scroll` with no
`height`, `max-height`, or `flex` whose parent stacks it top to bottom
(anything but a `row` or a `canvas`) is `lower-scroll-unbounded`; a `button`
or `link` with no children and no size (`width`, `height`, `flex`, a
padding, a `min-*`) is `lower-zero-size`. Only the case nothing on the path
can bound is refused; the parent that could have bounded it is bake's.

**The layout lint at bake (P1d).** `contract::bake` already booted the runner
on `Kernel::with_monospace()`; it now lays the first frame out at
`LINT_VIEWPORT` (390×844, a phone) and walks the tree: a `ScrollView` whose
`height`, `max-height`, and `flex_grow` are all unset and whose frame is
exactly as tall as its children's extent (not the kernel's `content`, which
follows `scrollHeight`'s max-with-box rule and would name every short list)
is `bake-scroll-unbounded`; a `Pressable` with zero area is `bake-zero-size`,
unless it holds an `Image` or a `Canvas`, whose size is the host's. Each
names the node by its `testId`. `bake` returns `BakeError` — `Runner(…)` or
`Lint { id, message }` — and every host's `build.rs` fails on either, so the
lint runs on the real app at every build (it passed Caltrain the first time).
The compiler cannot see layout; bake can, and it already had the kernel.

**Deviation from LLP 1017 §5.** None in substance. The lint compares to the
children's extent rather than `content` (the reason above), and `flex` counts
as a bound in the compiler's rule because CSS `flex: n` sets a basis of 0%
with growth, which a column parent resolves.

**Checks.** `contract/corpus/rejects.txt` — 33 fixtures, six new, each
refused by exactly its id; `contract/cli/tests/lint.rs` — the did-you-mean,
the value and type refusals, the hyphen hint, and the two bake rules with a
case the compiler passes and bake catches (a `scroll` under a content-sized
`row`); `cargo test --workspace`, clippy, fmt, `caps`, `boot` green;
`node scripts/smoke.mjs web` green on the rewritten app. Diagnostic ids
added: `lower-attr-value`, `lower-attr-type`, `lower-root-region`,
`lower-scroll-unbounded`, `lower-zero-size`, `lower-handler-arity`,
`bake-scroll-unbounded`, `bake-zero-size`, `bake-layout`. Cost: ~330 lines
across `contract-syntax`, `contract-lower`, `contract-types`, `contract`
(estimate in 1017 §5: ~350).
