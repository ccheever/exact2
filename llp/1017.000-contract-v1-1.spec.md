## P1 + P9 — no quiet failures; the words are the web's (landed 2026-08-30)

**The names (P9; LLP 1017 §8.1).** Every style attribute is its CSS property
name — `font-size`, `font-weight`, `color`, `background-color`, `opacity`,
`letter-spacing`, `line-height`, `text-align`, `gap`, `row-gap`,
`column-gap`, `padding` and its four sides, `margin` and its four sides,
`border-radius`, `border-width` and its four sides, `border-color`, `width`,
`height`, `min-`/`max-width`/`height`, `flex`, `flex-shrink`, `flex-basis`,
`flex-wrap`, `flex-direction`, `display`, `align-items`, `align-self`,
`box-sizing`, `object-fit`, `justify-content`, `position`, `top`/`left`/
`right`/`bottom`, `overflow`, `overflow-x`, `overflow-y` (new: the rows
existed, the attributes did not — `QUEUE.md`), `z-index`, `transition`,
`scale`, `rotate` — and every prop attribute its HTML or ARIA name:
`aria-label`, `aria-description`, `aria-level`, `role`, `placeholder`,
`value`, `href`, `disabled`, `lang`, and — from the peer lane's password
masking and Enter-to-submit (main `94c026e`, the same day) — `type`
(`"password"`) and `inputmode` on `input` (the kernel prop keeps the DOM
property's spelling, `inputMode`; the attribute is HTML's) and the `submit`
handler; `testId` is the one Exact-named
attribute; the tag names and the primary-argument sugar stay Contract's. No
aliases: `size`, `fontSize`, `radius`, `label`, and the rest are refused as
`lower-unknown-attr` with the CSS name they became in the message
(`contract/lower/src/tags.rs`, `renamed`). **The lexer** reads a hyphen
inside a name when a letter follows it, so `font-size` is one token and, as
in CSS `calc()`, subtraction between two names is written `a - b`; `x-1` still
lexes as `x`, `-`, `1`. An unknown hyphenated name says so
(`type-unknown-name`'s hint). Rewritten once, mechanically: `apps/caltrain/
app.contract` (58 attributes), the six corpus fixtures, and every test that
embeds Contract source; Weird Castle's `app.contract` with the merge.

**Values checked at compile time (P1a).** A literal style value goes through
the kernel's own parser before lowering — `StyleProps::set_dynamic` on a
probe, one row at a time — so `width=true`, `align-items="middle"`,
`background-color="red"`, and `padding="auto"` are `lower-attr-value` with the
row's name and the kernel's reason in the author's words (`describe` in
`contract/lower/src/lib.rs`); a computed value must be a number or a string
(`lower-attr-type`), and a prop's value must be the prop's type — text for
most, a bool for `disabled`, a whole number for `aria-level`
(`tags::prop_ty`). What the runner did at the first frame (LLP 1005 §6,
`StyleProps::set_dynamic` through `bridge.rs`) it still does for computed
values; the literal case is now the compiler's. Literal results inside ternary
and option-match branches use the same row checks, including inactive branches;
a refusal points to the offending literal. Computed results keep the runtime
check, and match-bound names are typed in their arm's scope.

**The compiler refuses what the runner refuses (P1b).** A `when`, `each`, or
`match` at the root of a view is `lower-root-region` (the runner's
`RootRegion`, which used to surface in every host's `build.rs` — `QUEUE.md`).
A handler behind a child's `action` prop names the real action after
inlining, and its arity is `lower-handler-arity` there — LLP 1006 §8's
"checked at dispatch" circle-back, closed.

**Two layout refusals in the compiler (P1c), conservative.** A `scroll` with no
`height`, `max-height`, or `flex` whose parent stacks it top to bottom
(anything but a `row` or a `canvas`) is `lower-scroll-unbounded`; a `button`
or `link` with no children and no size (`width`, `height`, `flex`, a
padding, a `min-*`) is `lower-zero-size`. Only the case nothing on the path
can bound is refused; the parent that could have bounded it is bake's.

**The layout lint at bake (P1d).** `contract::bake` already booted the runner
on `Kernel::with_monospace()`; it now lays the first frame out at
`LINT_VIEWPORT` (390×844, a phone) and walks the tree: a `ScrollView` whose
`height`, `max-height`, and `flex_grow` are all unset and whose frame is
exactly as tall as its children's extent (not the kernel's `content`, which
follows `scrollHeight`'s max-with-box rule and would name every short list)
is `bake-scroll-unbounded`; a `Pressable` with zero area is `bake-zero-size`,
unless it holds an `Image` or a `Canvas`, whose size is the host's. Each
names the node by its `testId`. `bake` returns `BakeError` — `Runner(…)` or
`Lint { id, message }` — and every host's `build.rs` fails on either, so the
lint runs on the real app at every build (it passed Caltrain the first time).
The compiler cannot see layout; bake can, and it already had the kernel.

**Deviation from LLP 1017 §5.** None in substance. The lint compares to the
children's extent rather than `content` (the reason above), and `flex` counts
as a bound in the compiler's rule because CSS `flex: n` sets a basis of 0%
with growth, which a column parent resolves.

**Checks.** `contract/corpus/rejects.txt` — 33 fixtures, six new, each
refused by exactly its id; `contract/cli/tests/lint.rs` — the did-you-mean,
the value and type refusals, the hyphen hint, and the two bake rules with a
case the compiler passes and bake catches (a `scroll` under a content-sized
`row`); `cargo test --workspace`, clippy, fmt, `caps`, `boot` green;
`node scripts/smoke.mjs web` green on the rewritten app. Diagnostic ids
added: `lower-attr-value`, `lower-attr-type`, `lower-root-region`,
`lower-scroll-unbounded`, `lower-zero-size`, `lower-handler-arity`,
`bake-scroll-unbounded`, `bake-zero-size`, `bake-layout`. Cost: ~330 lines
across `contract-syntax`, `contract-lower`, `contract-types`, `contract`
(estimate in 1017 §5: ~350).

## P2 — actions branch (landed 2026-08-30)

`if cond` … `else` … and `match option` with `case some(x)` / `case none`
as **statements** in an action body, nesting freely; still assignments,
commands, `send`, and `refresh` inside, no loops, no `let`, no `await`.
The parser mirrors the view's `when`/`match` (`contract/syntax/src/
parser.rs`, `stmt`); the type pass walks every branch (`check_stmts`: an
`if` needs a bool — `type-condition`; a `match` needs an option and binds
its name as `Ref::Local`, exactly as the inline `match` expression does);
the analyzer's `writes` check covers every branch (`writes_of`, so a write
inside an `if` that is not declared is still `analyze-write-not-declared`);
lowering is the ternary's and the inline `match`'s shape — a forward
`JumpIfFalse` over the arm not taken, `JumpIfNone` + `Unwrap` + `BindLocal`
for the `some` block, `Pop` for `none` — so the VM (LLP 1005 §4) gained
nothing and the plan format did not change. Caltrain's search field can now
say `if k == "Enter"`; Weird Castle's login `if session.ok`.

**`submit` (F3)** is not in this landing: the peer lane building Weird
Castle's asks (`QUEUE.md` §3 — password masking, Enter to submit) adds the
`submit` handler with `type`/`inputmode` on `input`, and the two meet at the
merge (LLP 1017 §10 F3: `submit` is one event kind on three hosts; `key`
stays for Escape and arrows).

**Checks.** `contract/corpus/branch.contract` (an `if`/`else` on a key and a
`match` on an option slot) proven on the runner in `contract/cli/tests/
branch.rs` (two tests: the fixture's four actions; nesting and an empty
`else`); two reject fixtures (`analyze-write-not-declared` inside a branch,
`type-condition`); 35 reject fixtures in all. Cost: ~230 lines across
`syntax`, `types`, `analyze`, `lower` (estimate in 1017 §5: ~150).

## P6 — named styles (landed 2026-08-30)

`style Name` at file scope holds lines of `attr=literal` — style rows and
`flex` only (`lower-style-attr` for a prop or a handler; `contract-style-
literal` for a computed value: a style is constant, a node may compute);
a node applies one with `class=Name` — HTML's attribute for exactly this —
and its own attribute of the same name replaces the style's. The compiler
expands the class into the node's attribute list before lowering, and two
bindings for one row (a style's and the node's, or a tag's fixed row and an
attribute) resolve to the last, so `class=Card padding=4` is padding 4 on
all four sides whatever `Card` says. No selectors, no cascade, no runtime:
the kernel sees rows as before. `lower-unknown-class`, `lower-style-
duplicate`, `type-class-name` (a `class` value that is not a name).
Deviation from LLP 1017 §5: the use-site spelling is `class=`, not
`style=`, because it is HTML's word for a named set (§8.1's rule).
Checks: `contract/corpus/styles.contract` proven on the kernel's rows in
`contract/cli/tests/styles.rs`. ~110 lines.

## P8 — `use` across files (landed 2026-08-30)

`use Name from "./file.contract"` at file scope: only a `.contract` path
(anything else is `contract-no-imports`, as before — the same rule, one
keyword, one meaning). Resolution is the driver's: `contract::compile_path`
loads the file, loads each used file the same way (transitively; a cycle is
`contract-use-cycle`, a missing file `contract-use-unreadable`), requires the
named declaration to exist there (`contract-use-unknown`), and merges *all*
of the used file's shapes, styles, and components in after the using file's
own — so the using file's first component stays the root, a used component
is a child, and whatever the used component itself needs comes with it. A
name declared differently in both is `contract-use-duplicate`; declared
identically, it is one. `compile(src)` on a text with a `use` is
`contract-use-unresolved` (a text has no path). The app's build scripts,
`caltrain::compile`, `metrics`, the dev loop, and `contract build` compile
by path now. Not yet: the dev loop watches the app file only — an edit to a
used file needs a save of the app file to be seen (`QUEUE.md`). Checks:
`contract/corpus/use/{app,row}.contract` — a component, its shape, and its
style from another file, proven on the runner — and the four refusals, in
`contract/cli/tests/use.rs`. ~140 lines.

The loader parses each canonical file once and, within each importing file,
merges a dependency only once. Later names from the same dependency still check
its exports (including transitive declarations); path and cycle checks run at
every use site. Completed dependencies retain ordered declaration indices into the original
source ASTs, so overlapping dependency graphs and repeated names do not resolve
the same subgraph again. Duplicate equivalence and first-declaration order remain
unchanged; the final merged AST takes ownership of each selected declaration.
Transitive index lists are retained, not copies of transitive syntax trees.

## P4a + P4b — provide/inject and `slot` (landed 2026-08-30)

Both are the inliner's (`contract/syntax/src/inline.rs`); the plan, the
runner, and the type of a component did not change. **Inject.** A component
declares `inject` like `props` — typed names — and a use site does not pass
them: the nearest enclosing `provide name = expr` above the use fills each
one at inlining, exactly as a prop is filled from an argument, so the child
sees the provider's expression in the provider's scope (state, a derive, a
literal) and follows it. The innermost `provide` wins; a use with no provider
on its path is `syntax-missing-provide`. No runtime lookup, nothing hidden
from the type checker — an inject is a prop the compiler passes (LLP 1017 §10
F5; 0251 F8's theme drilling closed). **Slot.** A component declares `slot`
and writes `children` in its view; the nodes indented under a use fill it,
inlined in the *use site's* scope (they see the parent's names, not the
child's); a `children` node outside a `slot` component is
`syntax-children-without-slot`, nodes under a use of a component with no
`slot` are `syntax-no-slot`, and an empty fill is fine. Caltrain now says its
sky once: `Sky(on=skyOn, …)` with the content indented under it, where the
31-argument `Content(…)` call was written twice, and `provide accent =
"#c0392b"` reaches `Content` and `DirectionCard` through `inject accent:
string` instead of a literal in three places. **Not in this landing: P4c,
per-instance state** — the runner change; the peer lane is in the runner for
LLP 1018 the same day, so it lands after the merge, as its own section.
Checks: `contract/corpus/{slot,provide}.contract` on the kernel in
`contract/cli/tests/compose.rs` (the fill's scope, an empty fill, the
innermost provider, a provided state that follows an action), three reject
fixtures; the Caltrain smoke. ~150 lines.

## P5 — `fn` in Contract (landed 2026-08-30)

`fn name(param: type, …): type = expr` at file scope — one expression, its
parameters and the roster the only names in scope (a state name in a body is
`type-unknown-name`: pure by construction), typed like a roster call at every
use (`type-arity`, `type-argument`), the body against the declared result
(`type-fn-return`). **Expanded inline where it is called**: the arguments are
compiled and bound as locals, the body compiled in place with the parameters
as those locals, the locals dropped after — so the plan format, the VM, and
the runner did not change, the corpus's byte-identity holds, and a cycle
through calls (`type-fn-recursive`, found by a walk over the call graph) is
the one thing the form cannot express, which is the bound LLP 1017 §5 P5 set:
the first `fn` that wants a loop is evidence for the data crate. A `fn` may
call a `fn`; a `fn` with the roster's name is `contract-fn-shadows-roster`;
a `use` may name a `fn`. Deviation from §5: "one `fns` table and a `CallFn`
opcode" became no table and no opcode — expansion is smaller and leaves the
runner alone, which mattered the day the peer lane was in it. Checks:
`contract/corpus/fn.contract` (a price string, a choice, a `fn` calling a
`fn`) on the runner in `contract/cli/tests/fns.rs`, three reject fixtures;
47 reject fixtures in all. ~170 lines.

**Cycle-check scaling (2026-09-20):** declaration validation remembers active
and completed function subgraphs across roots and repeated calls. Each function
body's outgoing edges are visited once, rather than once per dependency path;
unused shared helpers therefore do not cause exponential compile work. Active
back edges still refuse direct and indirect recursion. Function inlining and
executable plan bytes are unchanged.

## P7 — tests in the language, run by the agent driver (landed 2026-08-30)

`test "name"` blocks, beside the app in `app.test.contract`, whose steps are
the agent API's own operations by name — `tap "testId"` (`hover`), `type
"testId" "text"`, `type "testId" key "Enter"`, `clock settle` / `+ms` / `ms`,
`screenshot "file.png"` — and `expect` lines that read their replies:
`expect tree has|missing "testId"`, `expect text "testId" == "…"` (the
node's `text` prop), `expect state name == literal` (a slot, derive, or
resource from the `state` reply, against a number, string, bool, or
`none`). The compiler parses them and prints JSON (`contract test <file>`,
hand-written, no serde); `bun scripts/agent.mjs <host> --test <file>`
turns that into a session and runs it — the same `open`, `tap`, `type`,
`clock`, `tree`, `state` the smoke and an agent use — printing each test's
verdict and, for a failed `expect`, the test, the line, and what was seen.
`expect` is test grammar reading a reply, not a ninth operation (LLP 1017
§10 P7; `rules/NOT-DOING.md`). The old `contract` block's purpose returns as
something that executes, on every host, through one evaluator. Caltrain's
`apps/caltrain/app.test.contract` holds three tests (the station name, the
stations screen through search and selection with `expect state`, the
driver's clock) and the smoke runs them as its last step. `syntax-expected-
step` for a step that is not an operation. Checks: `contract/cli/tests/
tests_decl.rs` (the steps and the JSON), the reject fixture, the live run in
the smoke on every host. ~330 lines (parser ~150, driver ~100, `agent.mjs`
~70).

The driver invokes the compiler through Cargo from the compiler workspace, so
`CARGO_TARGET_DIR` and compiler freshness are Cargo's responsibility. Compiler
diagnostics and executable-launch failures reach the caller directly. This fixes
the custom-target smoke crash that tried to run a nonexistent `target/debug/contract`
and reported a JavaScript `TypeError` instead of running the authored tests.

## P4c — per-instance state (landed 2026-08-30)

A child component may own `state`, `derive`, and `action` — never a
`resource`, `mutation`, or `task` (`type-child-resource`: a row must not
open N requests, and only the root has a clock). **The compiler** lifts them
into the root at inlining (`contract_syntax::expand`, run once by the type
pass and retained in `Checked` for analysis and lowering, so their slots
line up): each use gets its own copies,
renamed apart with the use's number (`hot__3`, `bump__1`); a child `derive`
becomes an expression substituted at each read (no runtime derive); a child
action's `writes` and assignment targets are renamed with its states, and its
handlers name the lifted action. A use *outside* any `each` yields ordinary
root slots — carried by name across a reload like any other. A use *inside*
an `each` yields **row slots**: the plan's `slots` table gained an `owner`
column (`opt:regions`), set to the innermost enclosing `each`'s region,
which the inliner names by a tag on the `Each` node before regions exist.
**The runner**: a row slot lives on its `Row` (`RowSlots`, shared with the
row's `Frame`), initialized from its initializer when the row is created —
in the row's frames, so an initializer may read the item — kept with the key
across a reorder, dropped with the row; `LoadSlot`/`StoreSlot` on an owned
slot go through the innermost frame of its region (as `LoadItem` does), so a
site's update reads it and a row action, dispatched with the frames in force
at the view, writes it — applied on commit, undone with the action's
rollback like a root write; an action run with no row (`act`, a timer) that
writes a row slot is a typed refusal (`Trap::BadScope`) with the kernel
untouched. Root-side, a row slot is a placeholder: not in `Runner::slot`,
not in the agent's `state`, not carried — a reload restarts instance state
(Charlie, 1017 §8.4). Nothing else in the plan changed; `FORMAT_DIGEST` did,
and every host re-baked. Deviation from §5 P4c: identity is the row's key
(what the instance tree already kept), never a source address.
Checks: `contract/corpus/instance.contract` in `contract/cli/tests/
instance.rs` — two `Counter` uses with their own state and derive; rows whose
`hot` follows the key through a reorder; the outside-a-row refusal; carry —
plus `type-child-resource` as a reject fixture (replacing
`analyze-child-state`, whose rule is gone); the runner's and hosts' tests.
~430 lines (runner ~120, plan ~10, inliner ~150, types/analyze/lower ~80,
tests ~70).
