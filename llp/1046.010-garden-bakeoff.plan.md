## Summary

Grow a Garden, the largest game built on exact2 so far, is rebuilt from one
engine-neutral brief in each of four engines — exact2, three.js, Godot 4 and Unity 6 —
by the same model at the same effort, from the same art. Each build is measured on
four things:

1. **Wall clock**, from the first prompt to the builder's `DONE.json`.
2. **Tokens** (and their cost), from the builder's own session accounting.
3. **Fidelity**, 0–100, by an independent judge who reruns the proof, looks at the
   running game beside the reference screenshots, and scores every requirement id in
   the brief.
4. **Agentic ergonomics**: the builder reads its own diary and scores the engine — a
   holistic 0–10 that is *not* the mean of ten 0–10 subscores.

The orchestrator then ranks the engines by how strongly it would recommend each one
again to someone building a similar game with an agent, and says why.

**To run it again**, an agent follows §4 from the top. Say "run the garden bakeoff
benchmark again".

## 1. What is held constant

| | |
|---|---|
| Brief | `game/bakeoff/garden/BRIEF.md`, byte-identical in every lane. Requirement ids G1–G10 (world), R1–R15 (rules), U1–U9 (interface), P1–P10 (proof). |
| Art | `game/bakeoff/garden/art/` — 294 glTF models and 7 textures, the reference's own "art pass" — copied into every lane. `ART.md` says what each model is and where its joints are. |
| Reference | Seven screenshots of the reference build, frozen in `game/bakeoff/garden/reference/`, copied into every lane's `reference/`. No lane may read any Grow a Garden source. |
| Builder | One headless Grok session per lane: `grok-4.7`, `--effort high`, `--no-subagents`, `--sandbox off --always-approve`, web search allowed. The same opening prompt, which warns that the session is headless (ending the turn ends it; a background command wakes no one). When a session stops without `DONE.json` the runner resumes it with the same continuation prompt, up to 8 times (`BAKEOFF_MAX_RESUMES`); the cap on wall clock is what bounds a lane. |
| Cap | 240 minutes of builder wall clock per lane (`--cap-min`). |
| Machine | One Mac; lanes run in parallel (§6 on what that costs the comparison). |
| Lane note | `lanes.json`: the engine, where it is installed, and the one or two facts a builder could not reasonably guess (Godot has no editor here; exact2's reference sources are off limits). |

Engine versions must be recorded by the builder in its diary (especially the three.js
package version); `run.json` records the exact2 revision and input SHA-256 hashes,
while the lane notes name the expected installed versions. Run 1 used:
exact2 at the checkout's `HEAD`, three.js latest from npm on the day, Godot 4.7.2
(`brew install --cask godot`), Unity 6000.3.25f1 LTS (Unity Hub CLI).

|---|---|---|

## 3. What each builder hands back

In its lane directory: the game; one proof command (`README.md`); `DIARY.md`, kept as it
works (timestamps, a friction log, line counts, what is not done); `DONE.json`
(`proof_command`, `proof_passed`, `not_done`, `game_dirs`). After the self-score turn:
`SELFSCORE.json`. After judging: `FIDELITY.json`. The runner keeps `.bakeoff/` beside
them: the streamed session log, `build.json` (segments, wall times), `*-usage.json` and
`*-transcript.md` (from `grok usage` and `grok export`).

## 4. Running it (the runbook)

All commands from the exact2 root. Lanes live under
`~/Library/Caches/exact2-game/bakeoff/garden/<run-id>/` (override with
`BAKEOFF_ROOT`); results worth keeping are copied into
`game/bakeoff/garden/results/<run-id>/` and committed.

0. **Preflight.** `~/.grok/bin/grok models` lists `grok-4.7` (otherwise `grok login`);
   `godot --version` is 4.7.2 (`brew install --cask godot`); for Unity, the editor is
   installed (`"/Applications/Unity Hub.app/Contents/MacOS/Unity Hub" -- --headless
   install --version 6000.3.25f1 --architecture arm64`) and, if the person wants the
   lane, ask them to sign in to Unity Hub and add a Personal license first. Note
   uncommitted changes in the exact2 checkout: the exact2 lane builds against it.
1. **Prepare.** `bun game/bakeoff/garden/run.mjs prepare [--run <id>] [--lanes
   exact2,three,godot,unity]`. Copies the brief, art, reference and lane notes.
2. **Build.** `bun game/bakeoff/garden/run.mjs build --run <id> [--cap-min 240]`, in the
   background; it returns when every lane has `DONE.json`, reaches the resume limit (8 by default), or the cap.
   `run.mjs status --run <id>` shows each lane's last diary line. Do not help a
   builder: an intervention invalidates its lane's numbers.
3. **Self-score.** `run.mjs selfscore --run <id>`: each builder's session is forked and
   given `SELFSCORE.md`; it reads its own diary and writes `SELFSCORE.json`.
4. **Judge.** The orchestrating agent starts one judge per lane with `JUDGE.md`
   (`{ENGINE}`, `{LANE}`, `{EXACT2}`, `{OUT}` = `<lane>/FIDELITY.json` filled in), a
   model of a different family from the builder, told nothing about the other lanes.
   Judges run their lane's proof, so run them one at a time if proofs contend for a
   port or the GPU.
5. **Report.** `run.mjs report --run <id>` writes `results/<id>/RESULTS.md` (the
   measured table) and `metrics.json`, and copies each lane's diary, scores and README.
6. **Rank** (§5) and add the run's row and ranking to §8 of this document. Commit
   `game/bakeoff/garden/results/<id>/` and this file.

## 5. The measures and the ranking

- **Wall clock**: the sum of the builder's session segments, from the first prompt to
  its exit after `DONE.json` (or the cap). The diary's own "first passing proof" time is
  reported beside it.
- **Tokens**: `grok usage` on the build session — total, uncached input, output
  (including reasoning), model calls, cost. The self-score turn is reported separately
  (a forked session's usage includes its parent's; the report subtracts).
- **Lines of game code**: non-blank lines of source and config the builder wrote, by
  extension, excluding dependencies, engine-generated files, art and artifacts.
- **Fidelity** (judge): every requirement id scored 0/1/2 with evidence; `fidelity =
  0.25 world% + 0.30 rules% + 0.20 ui% + 0.15 proof% + look` (look 0–10). The proof
  counts only as the judge's rerun saw it.
- **Ergonomics** (builder, about the engine and its tools): `overall` 0–10, holistic;
  subscores `setup`, `docs`, `loop`, `verification`, `debugging`, `assets`, `ui`, `api`,
  `reliability`, `visuals`, each 0–10 with diary citations.
- **The ranking** is the orchestrator's judgment, not a formula: *how much would I
  recommend this engine again to someone who has to build a game like this with an
  agent?* Read in this order: did the agent get a working, proven game (proof rerun,
  fidelity); then what it cost (wall clock, tokens); then what it was like (ergonomics,
  the diary's frictions). Each rank carries one or two sentences of why. A blocked lane
  is listed, unranked, with its reason.

## 6. What this does not control

- **One sample per lane.** Agent runs vary; a gap of a few fidelity points or a
  20% wall-clock difference is noise until a second run agrees. Run it twice before
  acting on a close result.
- **Parallel lanes share the machine.** exact2's Rust builds and Unity's imports are
  CPU-heavy; three.js and Godot are light. Contention inflates the heavy lanes' wall
  clock. Pass `--lanes <one>` per run to time a lane alone.
- **The home engine.** exact2's lane reads this repository's docs, which were written
  for agents; the others read the web. The reference is exact2's own game, so its art
  pipeline fits exact2's renderer. The judge is told to be adversarial; the builder
  scores the engine, not itself.
- **A known flaw in brief 1.** G3 says "a blue water barrel", but the kit's
  `barrel.glb` (the art pass) is a brown wooden cask; the blue barrel in the reference
  screenshots comes from another look. Judges score G3 on placement and function. Fix
  it in the next series (§7) by saying "the barrel".
- **Headless ends on end-of-turn.** In run 1, the exact2 lane's Grok twice started its
  slow Rust proof in the background and ended its turn to wait for it, which ends a
  headless session. Fast-proof lanes never hit this. The opening and resume prompts now
  say so, and resumes are bounded by the wall-clock cap rather than a small count; run
  1's exact2 lane started with the old prompt and was continued under the new limit.
- **Self-scoring.** The builder scores its own experience. That is the point (it is
  the agent's experience), but it is one model's taste; the subscores' citations are
  what make it checkable.

## 7. Changing the benchmark

Changing `BRIEF.md`, `ART.md`, `JUDGE.md`, `SELFSCORE.md`, the model, or the effort
starts a new series: note it in §8 and do not rank across the change. The runner's
mechanics may change freely.

## 8. Runs

Series 1 (brief 1). Builder `grok-4.7` at `high`; fidelity judges Claude Opus.

**Run 1, 2026-10-06** (`game/bakeoff/garden/results/2026-10-06-r1/`). Lanes in parallel on
one Mac; Unity not run (no license).

| | three.js | Godot 4.7 | exact2 |
|---|---:|---:|---:|
| wall clock | 89 min | **69 min** | 105 min (3 segments) |
| tokens (cached + uncached) | 14.0 M | **12.4 M** | 40.0 M |
| cost | $3.60 | **$2.73** | $8.44 |
| lines of game code | 3,451 | 2,950 | 3,095 |
| proof passes on the judge's rerun | yes (47 s) | yes (4 s) | yes (24 s) |
| fidelity | **93** | 87.5 | 81 |
| ergonomics (builder, 0–10) | 7 | 7 | **8** |
| **recommend again** | **1** | 2 | 3 |

Why, in one line each: three.js built the most complete, playable game on the most
reliable tooling; Godot was fastest and cheapest but its camera never follows and its
proof never touches the game scene; exact2 had the strongest proof (real input, pins
held across hosts) but the most player-visible defects at the highest cost. Run 1's
Godot judge scored before `JUDGE.md` gained the camera and real-input checks and was
asked to re-score under them (P items: 95 → 60). One sample: run it again before acting
on the Godot/three.js order.
