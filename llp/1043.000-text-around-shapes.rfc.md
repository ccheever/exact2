## Summary

Charlie asked, 2026-09-18, after LLP 1043: *"what if wanted to be able to
do those cool things like have a ball go through a paragraph or a dancer
in the middle of text? how could we add those features to exact2 even if
we don't add the literal pretext library? can it be ported to rust and
grafted onto taffy or something"*.

Yes to the port, no to Taffy. Taffy lays out boxes, and to it a paragraph
is an opaque measured leaf; flowing around a shape is a different width
and origin for each line *inside* that leaf. What Taffy needs back is the
paragraph's height, which the measure callback already carries. The
proposal:

- **Three CSS rows** (D1): `wrap-flow` on an absolutely positioned node
  makes it an exclusion; `shape-outside` and `shape-margin` give its
  outline. They are CSS's names for this. No current browser executes
  `wrap-flow`, so the web host does — a declared deviation, the first
  where the oracle is absent rather than wrong.
- **The kernel resolves exclusions into each affected text leaf's own
  coordinates** (D2–D4). A paragraph with a definite height needs nothing
  from Taffy and is built first. An auto-height one needs its block
  offset at measure time, and by Charlie's ruling that comes from
  upstream Taffy's `BlockContext` after an upgrade from the vendored
  0.9.2, not from re-layout passes (D3).
- **One shared crate, outside the kernel** (D5–D6), holds the band
  geometry and a line walker over advances the host's engine supplies —
  Pretext's `layoutNextLineRange`, in Rust, its corpus as tests. The
  Apple host can start without the walker: CoreText already breaks one
  line at a given width, and §2 measured it flowing a screenful around a
  bouncing circle at 1.1 ms a frame. The web and Linux hosts cannot start
  without it.
- **A shape moves by commits, not by `translate`** (D8), as in CSS, where
  a transform never affects layout. `every(16, step)` does it with what
  exists; the agent's `clock` makes it reproducible.

**Built 2026-09-18 → 19 on `lane/textflow`; landed on `origin/main` 2026-09-19 as one squash, with the Taffy 0.14
upgrade, on Charlie's instruction after he tried the macOS app ("land … origin/main, everything"). §8 is the
as-built record, and where it differs from §3–§4 it is what exists.**

Not linked into `llp/current/`: the working set is at its cap of fifteen,

## 1. What is wanted, and what CSS has

The effects are Pretext's demos: a ball passing through a paragraph with
the words parting around it; a dancer's silhouette in the middle of a
column with text down both sides, reflowing as she moves. Mechanically:
for each line band, subtract the shape from the paragraph's width, and
break one line *fragment* into each interval that remains.

CSS has two halves of this and no browser has both:

- **CSS Shapes** (`shape-outside`, `shape-margin`,
  `shape-image-threshold`) — shipped everywhere, but only on floats. A
  float sits on one side, and flow decides where; it cannot be in the
  middle, and its position is not free to animate.
- **CSS Exclusions** (`wrap-flow: both`, on any block-level element,
  under any positioning scheme) — the exact feature. A Working Draft last
  published 15 January 2015, implemented only by IE and EdgeHTML behind
  `-ms-`; no current engine has it.

So the vocabulary exists and the executor does not. Upstream Taffy has
had floats since 0.10.0 (a `FloatContext` shared across a block
formatting context; 0.14.0 is current); exact2 vendors 0.9.2 with six
patches. Floats themselves would give the one-sided, flow-positioned
case and not the ball. What this document takes from the upgrade is the
block context that came with them (D3, stage 0).

## 2. Measured

**CoreText, flowing around a moving circle** (§7.1; M5 Max, macOS
26.6.2, Swift 6.4 `-O`, the machine shared with other builds). One
typesetter per paragraph, made once. Each frame: for every 22-point
band, the free intervals left of and right of a circle of radius 90 +
8, `CTTypesetterSuggestLineBreak` into each interval at least 48 wide.
600 frames of a bouncing ball, best of five. Every UTF-16 unit was
placed exactly once, in order.

| Paragraph at 640 wide | Fragments per frame | Breaks only | Breaks and `CTLine`s | Per fragment |
|---|---|---|---|---|
| 1,069 units, 14 lines | 20 | 0.14 ms | 0.15 ms | 6.9 µs |
| 2,097 units, 26 lines | 36 | 0.40 ms | 0.42 ms | 11 µs |
| 4,200 units, 51 lines — a screenful | 61 | 1.08–1.13 ms | 1.06–1.21 ms | 18 µs |
| 8,391 units, 103 lines | 113 | 3.75 ms | 3.84 ms | 33 µs |

Two things. It works today, on the engine that paints: a screenful is
13% of a 120 Hz frame. And `CTTypesetterSuggestLineBreak` costs more per
call the longer the paragraph — five times from 14 lines to 103 — so the
whole is worse than linear, and LLP 1043 F4's 3.4–5.0 µs per line was a
figure for 900-unit paragraphs, not a constant. The 51-line paragraph's
height ran 1,166–1,210 as the ball moved, against 1,122 unobstructed: an
auto-height paragraph pushes whatever is under it around, every frame.

**Arithmetic over cached advances** was 0.16–0.22 µs per paragraph-width
for 19-line paragraphs (LLP 1043 F4). With interval arithmetic per band,
a screenful around a circle would be a few microseconds. An estimate
from that unit cost; the walker does not exist yet.

**UAX #14 in a binary** (§7.2): `unicode-linebreak` 0.1.5 added 33,024
bytes to a stripped arm64 release binary (`opt-level = "s"`, LTO,
`panic = "abort"`), give or take a 16 KB page. It is already in the
Linux host's tree, through cosmic-text.

Not measured: canvas `measureText` per distinct segment from the wasm;
cosmic-text's shaped advances as a source; a 60–120 Hz commit through
the runner, kernel and host apply; the web glue placing fragments.

## 3. Design

**D1. The rows are CSS's.** `wrap-flow` (`auto` | `both` | `start` |
`end` | `minimum` | `maximum` | `clear`; v1 implements `auto` and `both`
and refuses the rest at lowering), `shape-outside` (`none` | `circle()` |
`ellipse()` | `inset()` | `polygon()`, then an image in stage 4), and
`shape-margin`. A node is an exclusion only when `position: absolute` and
`wrap-flow: both`; other wire values behave as `auto`, and `wrap-flow`
on a non-absolute node is ignored. With `shape-outside: none` its exclusion area is its border box,
as the draft says, and `shape-outside` replaces it. The draft allows an
exclusion under any positioning scheme; v1 narrows that to
`position: absolute` and lowering refuses the rest, because an in-flow
exclusion's place depends on the text it displaces. Nothing is renamed or
reshaped, so a browser that ever ships the draft becomes the oracle.
`llp/1001-kernel-v1.spec.md` declares the deviation: *the web host
executes `wrap-flow` itself, because no browser does; there is no parity
oracle for a flowed paragraph's lines.*

**D2. The wrapping context is the exclusion's parent.** In this kernel
an absolute node is placed against its parent (Taffy's containing block;
there is no `static`). Every text leaf that is a descendant of that
parent, and whose frame meets the exclusion's outline, flows around it.
`wrap-through` is not in v1; a subtree opts out by not being under the
context.

**D3. Where a leaf is, when it is measured.** The draft's own processing
model is two steps per containing block: resolve the exclusions'
positions and sizes, then lay out the content with wrapping applied. The
second step needs each text leaf's origin *while* it is measured, and in
vendored Taffy 0.9.2 a measure function is told a width and nothing
about where. Two cases:

- *A leaf with both dimensions definite* is never measured by Taffy and
  moves nothing. After the one layout pass the kernel takes each
  exclusion's area in absolute coordinates, subtracts the leaf's origin,
  and writes the leaf's *resolved exclusions* (D4). One pass, no engine
  change. This is what stage 1 builds.
- *An auto-height leaf* changes height with its exclusions, so its size
  must be right in the pass that places what follows it. **Ruled
  (§6.3): upgrade Taffy rather than iterate.** Upstream 0.14.0 lays out
  block children through `compute_block_child_layout(node, inputs,
  block_ctx)`, and `BlockContext` carries the block's `y_offset` and
  x-insets from the root of its block formatting context — the origin
  this needs, in the pass that needs it. Read 2026-09-18, two caveats
  stage 0 inherits. The high-level `TaffyTree` exact2 uses hands the
  context to block containers and *not* to a measured leaf (`leaf.rs`
  never sees it; the measure closure is `FnMut(LayoutInput, NodeId,
  Option<&mut NodeContext>, &Style)`), so either that closure gains the
  context — a small patch, and an upstreamable one — or `LayoutTree`
  moves to Taffy's low-level traits over the arena. And `FloatContext`
  knows left and right floats only: `find_content_slot` returns one slot
  per band, so text on *both* sides of a shape stays this document's band
  geometry (D6), fed the offset Taffy now supplies. Under flex and grid
  parents there is no block offset; there an auto-height leaf is laid out
  unobstructed and lowering says so.

Either way the result is a function of the tree, never of the previous
frame, so `layout_equality.rs`'s rule — a layout equals its fresh replay
— holds. The draft first proposed bounded re-layout passes on 0.9.2
(three, then an "unsettled" receipt); that is withdrawn.

**D4. Resolved exclusions are a derived column, published with frames.**
They ride in the measure request when a leaf is measured, and in the
host's batch beside the leaf's frame for painting. One set feeds both,
so what was measured is what is painted (LLP 1008 §3). A definite-size
leaf is never measured by Taffy at all; its host still receives the set
and lays its lines at apply time. The set is a key beside the offer, not
part of the `ParagraphStamp`: the stamp is proof of a paragraph's inputs,
"not its geometry", and a shape moving past a paragraph changes none of
them — so a host's retained shape (`TextShape`, `ShapedSource`) survives
every frame of an animation and only fragments are rebuilt.

**D5. The seam gains shapes, not lines.** `TextMeasureRequest` gains
`exclusions: &[FlowShape]` — circle, ellipse, rounded rectangle, polygon,
in the leaf's coordinates, already grown by `shape-margin`.
`TextMetrics` is unchanged: the kernel wants a size and a baseline. The
Apple C ABI (`host/apple/src/measure.rs`) carries them as a counted array
and the ABI version moves. Bands need a height before a line is broken:
the band is the paragraph's line box — the strut's `line-height`, or the
tallest run's where runs differ — fixed for the paragraph, as Pretext's
`lineHeight` argument is. A fragment narrower than four ems of the strut is
not used (the floor is clamped to the paragraph width, never bypassing shapes).
Found in review (M9): a one-em gap strands single short words beside a shape;
the owner retained the four-em floor after looking at all three hosts.
`exact_textflow::MIN_FRAGMENT_EM` is the one definition.

**D6. One crate below the hosts, above nothing.** `exact-textflow`
depends on nothing of exact2's — and on nothing at all until the walker
brings `unicode-linebreak` at stage 3:

- *Bands:* shapes and a band to free intervals. Pure geometry; every
  host uses it, so every host agrees on where text may go.
- *The walker:* a prepared paragraph — segments at UAX #14 opportunities
  with CSS's tailoring, each with an advance and a trailing-whitespace
  advance the host supplied once — and `next(cursor, width) -> range`,
  arithmetic. `white-space: normal`, both `overflow-wrap` values,
  `letter-spacing`, soft hyphens, hanging spaces; bidi reorders within a
  fragment and is the host engine's when it draws the range. Pretext
  (MIT) is the reference: its glue rules, its corpus and its platform-bug
  ledger arrive as this crate's tests, with attribution, and with fixed
  advances so every host gives the same ranges by construction.

It is linked by the hosts — the Apple host's Rust half, the Linux host,
the web host's wasm. `exact-kernel` depends on it as it depends on
`exact-motion` for `transition`: for the row's type (`ShapeOutside`), the
resolved `FlowShape`, and the test of which leaves a shape meets. The
kernel never calls the walker, still "never embeds a platform text API",
and its measurer stays a trait object. (Found while building, 2026-09-18:
the first draft said the kernel would not depend on the crate at all,
which would have meant two copies of the shape types.) Only
paragraphs with a resolved exclusion go through it; all other text stays
on the hosts' engines, so LLP 1043 §4's standing obligation — agree with
the browser's breaks — is not taken on for ordinary text, and for flowed
text there is no browser to disagree with.

**D7. Each host draws the ranges it was given.**

- *Apple.* Stage 1 needs only the bands: `layout(shape, width:, breaks:)`
  already
  calls `CTTypesetterSuggestLineBreak(typesetter, start, limit)` per
  line; `limit` and an x origin come from the band's intervals, and a
  `Paragraph` holds fragments where it held lines (selection in
  `TextSelectionMac.swift` walks `paragraph.lines` and would take each
  fragment's origin with it). Stage 4 moves it to
  the walker and `CTTypesetterCreateLine` over the walker's ranges — what
  `layout(_, breaks:)` does today for colored specs — if §2's
  worse-than-linear cost is met in an app.
- *Linux.* `ShapedSource` already keeps the paragraph's `ShapeLine`s, but
  `layout_to_buffer` lays a whole line out at one width; a flowed
  paragraph's glyph advances feed the walker instead, and the painter
  draws glyph ranges at fragment origins.
- *Web.* The browser lays out everything except this. For a flowed
  paragraph the glue measures distinct segments with canvas
  `measureText` under the font string the host's CSS already emits,
  hands advances to the wasm's walker, and renders each fragment as an
  absolutely positioned `white-space: pre` span, in DOM order inside the
  one paragraph element — selection and a screen reader still read it
  in order — with an explicit height when the paragraph's is `auto`. It
  reads the context's and the paragraph's rects after the browser's
  layout; an auto-height paragraph's new height can move what is below
  it and nothing above it, so under a block parent one read settles it.

**D8. A shape moves by commits.** In CSS a transform never affects the
flow of content around the transformed element, so an exclusion area is
the untransformed box's; the same holds here, and `exact-motion`'s four properties stay what the
executor runs off the layout path (LLP 1002 D2). A ball that parts text
is animated `left`/`top` (or `shape-outside`'s arguments): state, written
by a commit. `every(16, step)` does that with what exists, through
`Runner::advance_timed`, and the agent's `clock +16` steps it
reproducibly on every host — a flowed paragraph at a given clock is a
fact a smoke can hold. Whether that path is fast enough at 120 Hz is
unmeasured (§2), and whether the Contract wants a frame-cadence source
rather than a 16 ms timer is §6's.

The iOS `pan` adapter retains the original contact position in window space
and converts it to viewport coordinates for each recognized sample. Like the
web and AppKit paths, its first delta includes movement before recognition;
UIKit still decides when recognition begins. A Shop price-slider comparison
(2026-09-20) exposed a lost initial distance with UIKit translation alone. The
corrected signed Mac-hosted iOS build matches the reference's 52-pixel and
8-pixel drags and upper/lower bounds. This is endpoint/input evidence, not a
physical-device frame-pacing claim. Cancellation keeps the last committed value.

## 4. Stages

Charlie's sequencing ruling (§6.3a): the upgrade gates only what needs
it. Stages 0 and 1 run in parallel; 1 does not wait.

0. **Taffy to upstream 0.14.** Its own lane. For each of the six patches
   in `vendor/taffy/EXACT-PATCHES.md`: upstream already, re-applied, or
   dropped, each held by the tests that patch names (`reader.rs`,
   `layout_equality.rs`, the generated fixtures). The measure closure's
   new signature. Then the block context reaching a measured leaf, by the
   smaller of D3's two routes. No exclusion code.
1. **Definite-height flow: kernel and Apple.** The three rows and their
   lowering (D1, with the web host's CSS emission a no-op until stage 2);
   the resolved-exclusions column for definite-size leaves (D3, D4);
   `FlowShape` in the request and the C ABI; the *bands* half of
   `exact-textflow`; fragments in `TextEngine`; `layout <node>` (LLP
   1012) printing a text leaf's fragments. A Contract fixture — a
   fixed-height paragraph, a circle on `every(16, …)` — driven by
   `bun scripts/agent.mjs macos … "clock +16" "layout para"`, and the
   commit path's cost at that cadence measured (§6.5). Shapes:
   `circle()`, `inset()`, the border box.
2. **Auto-height flow.** Stage 0's offset feeding the same bands; the
   magazine layout — a static shape in an article — as its fixture.
3. **The walker; Linux and web.** The second half of the crate with the
   ported corpus; the Linux line loop; the web glue's fragments. The
   unmeasured rows of §2 are measured here, and the crate's real size in
   the wasm and an iOS binary reported before it lands (§6.2).
4. **Apple onto the walker**, only on a measured need.
5. **`shape-outside: <image>`** with `shape-image-threshold`: an alpha
   mask scanned into band intervals once per image, then per video
   frame — the dancer. Depends on LLP 1042 for a frame's pixels.

## 5. Refused, and why

- **The Pretext library itself.** LLP 1043 F1/F2 stand. The web glue
  *could* import it for D7; the walker in the wasm is preferred because
  one breaker then decides fragments on every host, and the glue stays
  glue.
- **Floats.** A different feature (one side, flow-positioned), upstream
  in Taffy since 0.10.0; it arrives with that upgrade or not at all, and
  this document does not pull it forward.
- **A shape that follows `translate`, or a `transition` on `left`.** The
  first would make layout depend on the motion executor, which on the web
  is the browser and is never sampled (LLP 1002 D2); the second is
  `rules/NOT-DOING.md`'s "layout transitions", gated on an
  incremental-relayout number that does not exist. A commit per tick is
  neither (D8, §6.5).
- **Doing it in a `canvas` surface.** A module could draw parted text
  today. It would be pixels: no selection, no semantics, no `tree`.
  Right for a title screen, wrong as the answer to "text around shapes".
- **`wrap-through`, `wrap-flow: start | end | minimum | maximum | clear`,
  in-flow exclusions, `shape-inside`.** Named in the drafts, no consumer
  here.

## 6. Rulings (Charlie, 2026-09-18)

Asked as six questions in the first draft; answered in session the same
day. The options not taken are kept because they are the record of what
was weighed.

1. **The vocabulary: CSS's `wrap-flow`.** Not an exact2 word, and not
   `shape-outside` alone (which would change the meaning of a shipped
   property — in browsers it does nothing off a float).
2. **The size: always linked.** `exact-textflow` goes into every host and
   the web wasm; no on-demand artifact, no native/web split. Stage 3
   reports the real deltas before landing, and it is revisited if the
   wasm's is over about 64 KB. The runtime-size pass requested on 2026-09-23
   revisits browser packaging: §8 records the separate walker artifact;
   native linkage and the shared shape types remain.
3. **Where a leaf is: upgrade Taffy first.** Not three passes on 0.9.2,
   and not a seventh patch on a block layout upstream has since rewritten.
   **3a. The upgrade gates only what needs it:** definite-height flow
   proceeds in parallel; auto-height flow waits for it (D3, §4).
4. **Auto-height under a moving shape: allowed, cost documented** (§2: a
   51-line paragraph's height moved 44 points as the ball crossed it, and
   what is below re-lays out each time). No journal note, no lowering
   refusal — the static magazine layout is the common case and needs
   auto height.
5. **What moves a shape: `every(16, …)` for v1.** 62.5 Hz against a 60 or
   120 Hz display will judder slightly. Stage 1 measures the commit path
   at that cadence; a display-linked source is its own document, written
   only if judder or cost shows. No sampled, layout-affecting motion
   class.
6. **Implementer: astra codes it; not started.** First answered "Claude,
   in a lane worktree, now"; revised the same day: *"don't start
   implementation right away. let's actually use astra for coding
   here."* So: astra (codex `gpt-6-astra`) writes the code, Claude briefs,
   supervises and reviews, and nothing starts until Charlie says go. The
   lane exists — `lane/textflow`, cut from `origin/main` — and holds these
   two documents only; an hour of stage 1 Claude had begun (a partial
   `exact-textflow` crate, unverified) was stopped and set aside, not
   committed. A start date is owed with the go.

### 7.1 CoreText around a circle

`swiftc -O main.swift -o flow && ./flow <words>`.

```swift
import CoreText
import Foundation
import QuartzCore

let dict = (try! String(contentsOfFile: "/usr/share/dict/words", encoding: .utf8)).split(separator: "\n").map(String.init)
var seed: UInt64 = 0x9E3779B97F4A7C15
func next() -> Int { seed = seed &* 6364136223846793005 &+ 1442695040888963407; return Int(seed >> 33) }
let wordCount = CommandLine.arguments.count > 1 ? Int(CommandLine.arguments[1])! : 400
let text = (0..<wordCount).map { _ in dict[next() % dict.count] }.joined(separator: " ")
let font = CTFontCreateWithName("Helvetica Neue" as CFString, 16, nil)
let attrs: [NSAttributedString.Key: Any] = [NSAttributedString.Key(kCTFontAttributeName as String): font]
let length = (text as NSString).length
let typesetter = CTTypesetterCreateWithAttributedString(NSAttributedString(string: text, attributes: attrs))   // once: prepare

let width = 640.0, lineHeight = 22.0, radius = 90.0, margin = 8.0, minFragment = 48.0

struct Fragment { var range: CFRange; var x: Double; var y: Double; var line: CTLine? }

/// The free horizontal intervals of the band [y, y + lineHeight) around a circle.
func intervals(_ y: Double, _ cx: Double, _ cy: Double) -> [(Double, Double)] {
    let r = radius + margin
    let nearest = max(y, min(cy, y + lineHeight))          // the band's closest approach to the center
    let dy = abs(cy - nearest)
    if dy >= r { return [(0, width)] }
    let half = (r * r - dy * dy).squareRoot()
    return [(0, cx - half), (cx + half, width)].filter { $0.1 - $0.0 >= minFragment }
}

func flow(_ cx: Double, _ cy: Double, lines: Bool) -> (fragments: [Fragment], height: Double) {
    var out: [Fragment] = []
    var start = 0, y = 0.0
    while start < length {
        for (x0, x1) in intervals(y, cx, cy) where start < length {
            let count = max(CTTypesetterSuggestLineBreak(typesetter, start, x1 - x0), 1)
            let range = CFRangeMake(start, count)
            out.append(Fragment(range: range, x: x0, y: y, line: lines ? CTTypesetterCreateLine(typesetter, range) : nil))
            start += count
        }
        y += lineHeight
    }
    return (out, y)
}

let frames = 600
func run(lines: Bool) -> (Double, Int, Double, Double) {
    var fragments = 0, minH = Double.infinity, maxH = 0.0
    var best = Double.infinity
    for _ in 0..<5 {
        fragments = 0
        let t = CACurrentMediaTime()
        for f in 0..<frames {
            let p = Double(f) / Double(frames)
            let cx = 60 + p * (width - 120), cy = 100 + 250 * abs(sin(p * 9))     // a bouncing ball
            let r = flow(cx, cy, lines: lines)
            fragments += r.fragments.count; minH = min(minH, r.height); maxH = max(maxH, r.height)
        }
        best = min(best, (CACurrentMediaTime() - t) * 1000)
    }
    return (best * 1000 / Double(frames), fragments / frames, minH, maxH)
}
let plain = flow(-1000, -1000, lines: false)
print("paragraph: \(length) UTF-16 units, \(plain.fragments.count) lines unobstructed at \(Int(width)) wide, height \(Int(plain.height))")
let a = run(lines: false), b = run(lines: true)
print(String(format: "breaks only:         %.1f µs per frame, %d fragments per frame, height %.0f–%.0f", a.0, a.1, a.2, a.3))
print(String(format: "breaks + CTLines:    %.1f µs per frame (what a painter needs)", b.0))
// Every character placed exactly once, in order.
let check = flow(320, 200, lines: false).fragments
var at = 0; var ok = true
for f in check { if f.range.location != at { ok = false }; at += f.range.length }
print("coverage: \(ok && at == length ? "every unit placed once, in order" : "BROKEN")")
```

### 7.2 The size of UAX #14

A bin crate with `unicode-linebreak = "=0.1.5"` behind a feature, the
same greedy breaker either way (opportunities from `linebreaks(text)`,
or from ASCII spaces), `opt-level = "s"`, `lto = true`,
`codegen-units = 1`, `panic = "abort"`, `strip = true`, arm64 macOS:

**Known gaps, honestly.**
