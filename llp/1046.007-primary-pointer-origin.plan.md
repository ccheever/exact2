# LLP 1046.007: Primary pointer press origin

**Type:** Plan
**Status:** Implemented
**Author and implementer:** Codex for Charlie Cheever, 2026-10-04
**Related:** LLP 1046.003, LLP 1015.000

Skirmish box selection needs the point where a press began. Several real browser
events can arrive before one simulation tick. `PointerState.position` is then the
latest position, and `delta` can include earlier hover motion. The private raw
contact's origin is removed on Up, so exposing that contact alone does not fix a
complete down/move/up sequence delivered in one tick.

Add `PointerState.press_origin: Option<Vec2>`, the most recent primary press on
that pointer: MouseLeft's transition from up to down, or a touch Down with zero
mouse buttons. It is a snapshot, not an edge. Games still gate work on their
existing pressed/released actions. Preserve the origin through Move and normal
Up, simulation ticks, and save/restore. Clear it on Cancel, Blur or replacement
by another pointer; replace it at the next primary Down. Secondary presses must
not overwrite it. Capture the previous mouse-button mask before updating keys.
When a secondary button is released while another mouse button remains held,
the pointer and raw contact stay down; keep the contact's original origin too.

The serialized snapshot changes, so write EXSIM v7 and explicitly refuse v6 and
earlier saves, with the existing actionable rebuild/recreate message. No migration,
file normalization or platform-specific save tolerance is admitted. Finite-point
validation includes the new field before any restore changes live state.

Tests cover down/move/up within one tick, unrelated prior hover, touch, successive
primary presses, both mouse-button chord orders and secondary release, Cancel,
Blur and pointer replacement. Save tests cover a queued complete press and an
active drag carried to a new host epoch, exact reserialized bytes, and atomic
refusal of malformed origins or an old container. Skirmish will consume the field
after this engine change and repin actual native/web proof bytes for v7.

The parent reviewed and approved these semantics on 2026-10-04 before engine
implementation, explicitly requiring secondary-release/chord coverage and the
EXSIM version refusal. This follows Charlie's authorization to improve the engine
for Skirmish after a reviewed LLP; multiplayer remains behind single-player input.

The full exact-game suite passes: 399 tests, seven existing ignored observations.
This includes the three simulation/checkpoint cases and atomic finite-origin and
v6-container refusals. Both chord press/release orders pass; the existing raw-Move
drag behavior remains unchanged, while Up with remaining mouse buttons no longer
ends the raw pointer/contact. Strict exact-game all-target Clippy and formatting
pass, as does the locked wasm32 engine check. Native/web Skirmish v7 proof and
baseline capture follow in the consumer.
