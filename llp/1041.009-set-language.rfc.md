## Summary

Contract is a **view**: state in, a CSS tree out, re-run when slots change. A game
scene is a **constructor**: it runs once, then the world mutates on its own. The
wrong move is to extend `.contract` with 3D tags (LLP 1041.002 F18) or to ship
typed JSON and wait for friction (1041.006 §10 Q3). JSON cannot say what is
scenery; a constructor that cannot say that cannot make the tick cheaper.

**Set** is a small indented language whose compiler is a baker. Source is
`.set`. Output is a **kit**: packed tables the engine loads without a parse,
not a script it interprets. The one semantic the language exists to carry is
**still vs live**.
Still objects leave the ECS, the observation scan, and the dynamic physics set;
they become instance rows, a cooked static collider, and a digest. Live objects
spawn as archetypes — memcpy of a packed row, then field overrides. Tick code,
synths, and win/lose stay Rust. HUD stays Contract. The eight operations grow
no ninth.

The exhibit is in the game lane (`exact2-wt-lanterns`):
`game/games/lanterns/level.json` lists the crate, the ledge, and twelve
lanterns, and the running game does not load it. `LANTERNS` in
`logic/src/lib.rs` is a second copy. A content edit today is a Rust edit.
Set makes that a kit swap. The working-set link for this draft replaces
[LLP 1033](1033-markdown-viewer.plan.md); that plan stays in the corpus.

## 1. Why a language, and why not the two obvious ones

Two jobs, both named in the request:

1. **Ergonomics.** An agent (or a human) authors a spatial tree as text, gets a
   span on a bad field, and finds an inspected entity's declaration from
   `state`. Rust spawn tuples and JSON object arrays both fail this: the first
   because a lantern position is buried in a crate rebuild, the second because
   a tree of components with parents, defaults, and reuse is a hostile JSON
   shape (no comments that survive a round-trip, no `each`, no kinds).
2. **Speed.** The language has to make **running** games faster, not only
   **editing** them. A constructor that emits the same ECS the Rust `setup`
   already emits is an authoring skin. The speed is in what it *does not emit*.

**Not Contract.** Contract re-evaluates a view. Re-evaluating a scene would
reset the crate. Contract's oracle is a bare `<div>`; a scene's units are
metres, Y-up, −Z forward, no measurement. They meet at one already-built
point: a canvas child with a placement (1041.002 F5, F16, F18). Share the
habits — closed types, fail at bake with a span, 2-space indent, `use`, bake
never on device — not the grammar, not the crate, not the plan.

**Not typed JSON first.** 1041.006 Slice D starts there so the catalog and
source map can exist before a grammar. That is the wrong order. The catalog
is a derive (D5); the source map is a sidecar of whatever the compiler emits
(D8). JSON is a fine **debug dump of a kit**. It is a poor **authoring
surface**, and it has no place to write `still`. Without `still`, the compiler
cannot do the one job that pays for it at 60 Hz. Lanterns already tried JSON;
the game ignored it.

**Not a tick VM.** A per-entity interpreter would lose the "a tick is a
function that calls functions" rule (`game/README.md`) and the 200 k entity
path. Set attaches components. Rust matches them.

## 2. Decisions

**D1 — A new language, Set, in the game workspace.** Files are `.set`. The
entry is `world.set` next to `app.contract`, named in the game's manifest the
way the canvas is named. The compiler is Rust crates under `game/set/`, absent
from the root workspace, never on a device, never a cargo feature on a core
crate. Indentation, comments, and `use` follow Contract's rules as a
description; the lexer is its own. Depending on `contract-syntax` is refused.

**D2 — The kit is the constructor.** Analog of LLP 0480 / 1005: the compiler
and the engine are two ends of one format. `game/set/tables/format.json` is
the one declaration authority; encoder and decoder are generated; a kit
header carries a format digest, the component-catalog digest, and the source
digest. `World::install(kit, args)` is setup. A game may still write Rust
after that (sounds, a `Session` resource). A world with no `.set` is
unchanged.

**D3 — Still vs live is the load-bearing semantic.** Every authored entity is
one or the other, decided at bake, not inferred from "it didn't move last
tick."

| | Still | Live |
|---|---|---|
| Storage | instance rows (transform, mesh, material, parent slot) | ECS pages, as today |
| Tick queries | invisible | visible |
| `world.hash()` | one kit digest on a resource | per-component, as today |
| Physics | cooked static compound / trimesh, loaded once | Body / Collider / Character, as today |
| Renderer | instance buffer uploaded once; rewritten on still-swap | the live instance record (D4) |
| Save | not saved; identity is the digest | saved |
| Mutation | refused (`get_mut` names the still) | ordinary |

A still child of a live parent is an **attached instance**: it has no ECS
slot; its world pose is the parent's interpolated pose times a packed local.
Lantern posts and caps are this. A live child of a still parent is refused
(parent it to a live anchor, or lift the parent). `still` cannot carry
gameplay components (`Lantern`, `Player`, `Character`, dynamic `Body`,
`Follow`, `PointLight` whose intensity ticks, `Animation` that tick code
writes). Marking one so is a bake error that names the component.

**D4 — Draw instances are not entity slots.** LLP 1041.004 L7 already called
the entity-index-as-GPU-slot wrong for assets, skinning, and particles.
1041.005 C5 parked a draw-instance record behind the asset slice. Set needs
it on the first still object: a row is (transform slot or packed local,
geometry, material, parent live slot or none). Live meshes use the same
record. Without this, still is a second renderer.

**D5 — The component catalog is the derive.** `#[derive(Component)]` already
owns `NAME` and the `Data` walk. It also emits catalog rows: field names,
closed field types, defaults, still-legality. The Set compiler loads the
game's catalog the way `contract-types` loads the roster. There is no hand
JSON schema. A field Set cannot spell (`Vec<Triangle>` on a cooked mesh, an
opaque physics snapshot) is a **construction boundary**: named in the catalog
as `opaque`, settable only from Rust. Unknown component, unknown field, wrong
type, missing required asset: bake fails with `file:line:col [id]`.

**D6 — Bake-time evaluation only.** `fn`, `each`, `when`, arithmetic, table
rows, and generator invocations run at bake, against args that are
construction arguments (not `#[live]`). There is no opcode in the kit for
them. A `#[live]` arg (pause, started) does not exist in Set; it never did
in setup identity either. Changing a construction arg (`seed`, `round`) is a
restart, as 1041.006 Slice C already says.

**D7 — Behaviour stays Rust; Set attaches a closed verb list.** v1 verbs are
components the engine already has, plus one new one:

- existing: `Transform`, `Parent`, `Mesh`, `Material`, `Camera`, `Follow`,
  `Visible`, `Ambient`, `DirectionalLight`, `PointLight`, `Animation`,
  `Collider`, `Body`, `Character`, `AudioListener`, `AudioSource`
- new: `Actable { action: string, radius: f32 }` — "if this action is pressed
  and the named origin is within radius, the entity is the target"

Lantern lighting, fox clips, sun travel, win/lose, footsteps stay in `tick`.
`Actable` deletes the duplicated near-and-press loops in Beacons and
Lanterns; it does not glow a lantern. No expressions over live state. No
`on light: …` scripts.

Tuning that is currently a magic number in `tick` (Lanterns: speed `4.5`,
jump `6.4`, gravity `12`) moves onto `Character` (Beacons already put them
there). Set can then author them. A tick that hardcodes what the component
carries is a bug the catalog makes visible.

**D8 — Reload is three operations, with still-swap as a fourth cheap path.**
1041.006 Slice C's continue / restart / restore stand. Set adds:

- **Still-swap.** The live table's names, kinds, and component masks match;
  only still rows, attached locals, or the cooked static collider changed.
  Install the new still buffers, update the kit digest, do not respawn live
  entities, do not step. A lantern *position* is live (the root carries
  `Lantern`), so moving one is a **live patch** of that named transform
  (teleport + recook that collider) when the live table otherwise matches, or
  a restart when kinds/counts changed.
- Content-only kit rebuild does not invoke rustc. Target: Contract's ~20 ms
  edit → present class on the web, measured, not asserted.

**D9 — The agent sees still names without still being entities.**
`tree` / `state` / `layout` on `world:ledge` resolve live first, then the
kit's name table. Replies carry `still: true` and, in development, a
digest-bound source span (`island.set:24:3`). Procedural stills report
`generator` + params, not a fake line per rock (1041.006 §7). `query::<&T>()`
in tick code does not see them. `get::<Transform>("ledge")` does.
`get_mut` on a still name is a named refusal. No ninth operation.

**D10 — Seeded content is a recipe in the kit, not N entities in `setup`.**
A `scatter` names a Rust generator registered on `Game` the way assets are
(`Game::generators()`, deterministic, libm, `world.rng()` equivalent at
bake or at install from the construction seed). The kit stores params, not
the expanded rocks. Install expands into the still instance buffer and the
static collider. The generator may not spawn live entities; a live scatter is
a different declaration and a different ( rarer ) path.

## 3. The language

File-scope declarations: `kind`, `stage`, `table`, `use`, `fn`, `resource`.
The first `stage` is the entry. Significant indent, two spaces, `//`
comments. PascalCase is a catalog type or a kind; kebab-case is an instance
name. `name=value` attributes. `at=`, `scale=`, `look=`, `euler=` (degrees,
YXZ, baked to a quat) are Transform sugar; a second Transform block merges
or refuses a conflict. Colours are linear 0–1; `#rrggbb` is admitted and
converted from sRGB at bake (agents copy from Contract). Units: metres,
seconds, kilograms, degrees in source, radians in `Data`.

A kind is a spawn template with props. Its body is the entity tree; indent
parents. Using a kind:

```
Lantern lantern-1 at=-12, 0, 10
```

The instance name prefixes inner names (`lantern-1-post`). Duplicate
identities, parent cycles, and unknown props fail at bake.

`each` and `when` are bake-time. `fn` inlines at bake, one expression, no
recursion (Contract P5's rule). `use Name from "./props.set"` merges
declarations; a cycle or a collision is refused by name.

**Tables** are the construct Contract never needed and JSON fakes with
arrays of objects:

```
table lanterns
  name: string     at: vec3
  lantern-1        -12, 0, 10
  lantern-2        -10, 0, 2
  lantern-3        -12, 0, -8
  lantern-4        -6, 0, -12
  lantern-5        0, 0, -10
  lantern-6        6, 0, -12
  lantern-7        12, 0, -8
  lantern-8        12, 0, 0
  lantern-9        5, 0, 2
  lantern-10       0, 0, 0
  lantern-11       0, 0, 7
  lantern-12       10, 2.4, 8
```

A lantern kind is a live root (so `lit` and glow save), a live bulb
(`PointLight` intensity ticks), and attached still children (post, cap).
Twelve lanterns today are 48 entities (`spawn_lantern`); after: 24 live
(root+bulb) and 24 attached stills, and the 40 trees/rocks plus five named
boxes are not in the tick at all.

`Collider` contributes to the cooked static body, with user-data the still
name so a pick can say `ledge`. Synth graphs stay Rust (`define_sounds`).
The signpost's *text* stays a Contract child on a placement (1041.000); Set
does not grow a text shaping engine.

## 4. The kit

Magic `EXKIT1`. Little-endian. Same bytes on every host. Header: format
digest, catalog digest, source digest, construction-arg shape. Tables
(declared in `format.json`, not invented per game):

- interned strings
- still instance rows (local TRS, mesh id, material, collider piece, parent
  live slot or none, optional name)
- live archetypes (component mask, default packed row)
- live entities (archetype id, name, override fields as catalog-tagged
  patches, parent live index)
- resources (Environment, Physics gravity, …)
- scatter recipes (generator id, params, seed slot)
- asset refs (name, expected digest)
- cooked static collider blob (opaque to Set; hashed)
- development source map (omitted from production kits; digest-bound)

`install` is deterministic: live entity indices assigned in kit order, then
scatters expand still rows in generator order. A restored save carries the
kit digest; a mismatch refuses and keeps the live world (1041.006 C). A kit
is not a save.

## 5. Engine changes the language is not worth making without

These are the redesign. Without them Set is a prettier `setup`.

1. **Still store** on `World`: instance pages, name table, digest resource.
   Not component storage. Not saved. Not observed per row.
2. **Draw-instance records** (D4 / L7 / C5), shared by still and live.
3. **Catalog emission** from the derive; `Game::catalog()` bytes the compiler
   reads.
4. **`World::install`**, and `get`/`named` walking the still name table for
   still-legal components.
5. **Physics cook at bake**, loaded as one static body plus named shape
   user-data. Dynamic `n` in the query-scene rebuild (physics README: O(n)
   on membership edits) no longer includes the island. Characters still
   collide with it.
6. **`Actable` + Character tuning fields** so Beacons/Lanterns ticks read
   data the kit supplied.
7. **`Game::generators()`**, bake-or-install expansion into still rows only.
8. **Observation and quiescence:** still is not a changing reason. The kit
   digest changing (a still-swap) is one reason, named `still`, for one
   tick, then quiet. Pause still settles (G1c).
9. **Web reload:** `.set` in the game module's watched inputs, but a
   content-only digest change takes the still-swap / live-patch path and
   does not wait on rustc. Native advertises rebuild-and-relaunch until a
   live replacement is separately proven (1041.006 C).

What does **not** change: the clock, the eight operations, `Data` as save
and hash, interior-mutability leases, Rapier as the solver, Contract as HUD,
one module for sim and GPU, no editor application, no boot-path compiler.

## 6. Speed, stated as claims to measure

Not measurements. The diaries give the baselines these claims have to beat.

| Claim | Baseline in the tree | Expected if Set is doing its job |
|---|---|---|
| Content edit → playable frame (web, warm) | Rust logic rebuild; after the dep-info fix, under a second, plus module swap | Kit rebake + still-swap / live-patch, Contract's ~20 ms class; no rustc |
| Lanterns live entity count at setup | ~100 (12×4 lanterns, 18×2 trees, 22 rocks, named boxes, actors) | ~30 live (player, fox, camera, sun, crate, 12 roots, 12 bulbs, session-less) |
| Tick queries / observation | every living transform (200 k Transform-only observe ≈ 15 ms median on the Mac, G1 diary) | live set only; still is a digest |
| Physics query rebuild | union of Body/Collider membership, O(n) | n is dynamic + kinematic + characters; the island is one static |
| Still scenery draw | one live slot per mesh, parent propagate | one upload of the still buffer; attached posts ride the parent's interpolated slot |
| Beacons `setup` hash vs kit install | `67e5994bda318b9a` on three hosts at seed 7 | **equal**, bit for bit, on the same seed — the conversion acceptance |

The 200 k rotating-cube bench is live on purpose; Set does not claim it.
Headless `Sim::install` must remain a function of (kit, args, seed) with no
clock.

## 7. Ergonomics, stated the same way

| Motion | Today | With Set |
|---|---|---|
| Move lantern-12 | edit `LANTERNS` (or the unused JSON), rustc, reload, restart | edit a table cell; kit; live-patch that transform |
| Reuse a lantern in Beacons | copy the spawn function | `use Lantern from "../lanterns/props.set"` — refused if the catalog differs |
| Bad field | rustc, or a runtime Default | `props.set:18:5 [set-unknown-field] Beacon.gloww` |
| `state world:ledge` | an ECS box | `still: true`, span in development |
| Add a thirteenth lantern on a new ledge (1041.000 §5) | Rust + proof | table row + a still box; proof; no rustc if `Lantern` already exists |

A game is still two or three files of *behaviour* (1041.005 §3a E4):
`app.contract`, `world.set`, `logic/src/lib.rs`. Host crates stay
synthesized.

## 8. Refused

- Extending `.contract` with meshes, or compiling Set with the Contract
  compiler.
- Typed JSON as the authored source (debug dump of a kit is fine).
- A tick VM, `on act:` scripts, live `when` that spawns, deep merges,
  multiple inheritance, CSS, hex-as-linear-without-conversion.
- An editor GUI, a ninth agent operation, session record/replay, a
  sixth blocking check, a core cargo feature, compiling on device.
- Still objects that tick code mutates. If it moves because the game says
  so, it is live.
- Generators that touch live entities on the still path.
- Synth graphs, animation blend trees, and shader authoring in Set. Those
  are other slices (1041.005 §4).
- Compatibility shims for `level.json` or for `setup` that duplicated it.
  Delete the JSON when Lanterns installs a kit. Pre-1.0, names change.

## 9. Slices

Unassigned. Each slice ends driven, hashes pinned, no "iterate until green"
past three rounds.

| Slice | Lands | Acceptance |
|---|---|---|
| S0 | Catalog from the derive; kit format; `install` of **live-only** kits built by a test helper (no parser yet) | Beacons setup hash equal to today's Rust `setup` at seed 7, three hosts; a wrong field in the helper's table refuses by name |
| S1 | Draw-instance records; still store; cooked static collider; attached instances; `get` through the name table | Lanterns island with trees/rocks/ground as still; live count reported; crate push `clock settle` pins the same coordinates as today; `state world:ledge` is `still: true` |
| S2 | Set parser, kinds, tables, `each`/`use`/`fn`, Beacons+Lanterns converted, `level.json` deleted | Edit lantern-12 without rustc; `use` of `Crate` from Beacons in a one-file proof game; duplicate names and a live child of still refuse with spans |
| S3 | Scatters as recipes; still-swap and live-patch on the web loop; development source map | Change a still material, keep the crate in the air; add a lantern kind field, get a restart offer not a silent continue; `state` names `island.set:…` in development and omits paths in production |
| S4 | `Actable`; Character tuning read from the component in both games | Beacons tick loses its near-loop; Lanterns jump/speed/gravity come from Set; both proofs green |

S0 can start without a grammar and without admitting Set as a language, but
S2 is not optional later: the request is a language, and S0's helper is not
one. S1 before S2 so the parser emits still for real. Native still-swap is
not in S3; advertise rebuild.

## 10. Open questions

1. **Set vs another name.** "Set" as in a film set (standing set vs cast).
   It collides with the English word in prose; the language is always
   capitalized. Rename on acceptance if Charlie prefers. This draft does
   not use "Stage" or "Scene" as the language name, because those strings
   already title contemporaneous drafts.
2. **Live-patch of a named transform (D8) vs always restarting live.**
   Recommendation: patch when the live table matches, restart otherwise.
   Physics teleports already exist (`World::teleport`). A mismatched live
   table that we tried to patch is the class of bug Slice C is there to
   refuse.
3. **Bake scatters vs install scatters.** If the seed is a construction
   arg, either works. Recommendation: store the recipe, expand at install,
   so one kit serves every seed and a seed change is a restart without a
   rebake. Measure. If expansion is the warm-frame cost, bake a default
   seed and treat other seeds as restart-with-rebake.
4. **How much Environment/Fog/Bloom belongs in Set vs a Rust default.**
   Recommendation: all of it is data, so Set. Same for Physics.gravity.
5. **Who implements this, and when?** Unassigned.

## 11. Relation to 1041.006 Slice D

Slice D asked for typed JSON, fragments with explicit parameters, and a
custom syntax only after friction. This RFC answers Q3 the other way: the
custom syntax *is* the first scene authoring, because the semantic it
carries (`still`) is the speed, and JSON has nowhere to put it. Fragments
are `kind` with props; no implicit merge. A scene is still an initial
condition, not a save. Contract still owns UI. Rust still owns `tick`.
The conversion acceptance (Lanterns roster in data, Beacons reuse, content
edit without a behaviour rebuild) is the same bar, plus the live-count and
hash bars in §6 that Slice D did not ask for.
