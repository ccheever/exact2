# LLP 1069.002: The file picker — `<input type=file accept="image/*,video/*">`

**Type:** RFC
**Status:** Draft r2; Charlie's rulings folded 2026-09-27
**Systems:** Contract (`input type=file`, `accept`, `multiple`; the `showPicker` command; `change` carrying a file list; `cancel`); Kernel (no new node type; three props); Runner (the command, the `Picked` shape); Apple host (PHPicker on iOS, `NSOpenPanel` on macOS, `UIDocumentPickerViewController` for non-media types); Web host (the element itself, blob-backed `app:/tmp` entries); Linux host (refused, with the agent substitute); `image`/`video` (`app:/` sources); Agent API (`type @t` answers a picker)
**Author:** Claude (Opus 5.5) for Charlie Cheever
**Date:** 2026-09-27
**Revised:** 2026-09-27, r2: rulings folded; native hosts don't enforce user activation; `accept` widened to the manifest's `file_handlers` types, which makes this element LLP 1069.010's import; the substitute aligned with LLP 1069.007 D4
**Related:** LLP 1069 §5 #3 (the survey's ranking); LLP 1045 D10 and slice 7 (the admission, the `upload` verb this replaces); `rules/DEFERRED.md` (the admission, widened 2026-09-27 to `file_handlers` types); LLP 1027.001 and `vendor/ibex2/src/bindings/storage.d.ts` (`app:/data`, `app:/cache`, `app:/tmp`; the `fs.*` grants); LLP 1033 and `DocumentsMac.swift` (`file_handlers`); LLP 1011, LLP 1042 (image and video sources); LLP 1012 (the agent's operations); LLP 1069.007 D3, D4, D7 (the substitute); LLP 1069.008 (the reach table); LLP 1069.010 (documents: handles, save and export, which this is not)

## Rulings (Charlie, 2026-09-27)

- **Q1: the element plus `showPicker(id)`,** not LLP 1045 D10's `upload`.
- **Q2: native hosts do not enforce user activation** (Charlie: "don't enforce it ourselves. let's just trust developers"). **This overrides D2's refusal.** A native host opens the picker from any action. On the web the browser's own rule still applies, so a picker opened outside a press fails there. That difference is documented for authors, not enforced.
- **Q3: iOS Safari's conversion rule on every host.**
- **Q4: Linux refuses** and only the agent substitute answers, until a desktop Linux host exists.

## Summary

The picker was admitted on 2026-09-21 (LLP 1045 D10) and never built. The
only picker today is the macOS document panel (`DocumentsMac.swift`), which
serves `file_handlers`. A search over `host/`, `contract/lower/src`,
`runner/src` and `js/src` for `upload(`, `PHPicker`, `fileinput` and
`accept` finds no picker: the hits are a GPU texture `upload`
(`host/linux/src/gpu/images.rs:45`) and a socket `accept`
(`AgentIOS.swift:83`).

This RFC builds it with the web's spelling:

```
input type="file" accept="image/*,video/*" multiple testId="attach"
    change=attach display="none"
button press=choose aria-label="Add photo"
  image "symbol:photo"

action choose
  showPicker("attach")

action attach(files: list Picked) writes drafts
  ...
```

- **D1–D2, the tag and the command.** `input type=file` is the tag;
  `showPicker(id)` is `HTMLInputElement.showPicker()`. D10's
  `upload(id, "image")` becomes these two: the kind moves into `accept`.
- **D3, the value.** `change` carries a list of records: an
  `app:/tmp/picked/…` path, the name, the MIME type, the size and, for
  media, the pixel size and duration.
- **D4–D5, the bytes.** Native hosts copy them into `app:/tmp/picked/`
  before `change` fires; on the web the browser's `File` backs the entry.
  The runner never sees bytes.
- **D6, the formats.** iOS Safari's rule: HEIC becomes JPEG only when
  `accept` excludes it.
- **D7, previews.** `image` and `video` take an `app:/` source.
- **D9, the substitute.** A held picker is answered with `type @t <path>…`
  on every host, Linux included.

`accept` is bounded by the compiler: media types, or the types the
manifest's `file_handlers` declares (D1). `capture` is refused, so there is
no camera, and no picker takes "any file".

## Motivation

Three admitted consumers:

- **Interview (LLP 1045).** Captioned figures: pick, store or upload, then
  `format(id, figure(url))` inserts `![](url)` with the caret in the
  caption.
- **Bluesky** (`bluesky-exact2`, admitted 2026-09-27). Compose attaches up
  to four images or one video. `app.bsky.embed.images` wants each image's
  `aspectRatio` beside its blob, so D3 reports the pixel size and the app
  never decodes a file just to post it.
- **Fieldnotes' import** (LLP 1069.010 D3). A backup `.json` chosen by the
  person, copied into `app:/tmp`: the same element with `accept` from
  `file_handlers`.

`expo-image-picker` is among the most used Expo packages (LLP 1069 §2.2).

## Design

### D1 — The tag is HTML's: `input type=file` with `accept` and `multiple`

The kernel's input node gains `type=file` and two props, `accept` (the MIME
list as HTML writes it) and `multiple`. No new node type.

A visible file input presents as the platform's own button: the browser's
"Choose File" control on the web, a system button titled by `aria-label` on
Apple. Almost every app hides it and opens it from its own button (D2), as
on the web.

**`accept` may name:**

- `image/*`, `video/*`, `image/<subtype>`, `video/<subtype>`;
- a MIME type or extension that a `file_handlers` entry in `app.json`
  declares (`rules/DEFERRED.md`, widened 2026-09-27 with LLP 1069.010).

**The bake refuses**, each citing `rules/DEFERRED.md`'s sentence:

- an `accept` that is not a literal, or is missing;
- any other type, `*/*`, or an extension no `file_handlers` entry names;
- `capture`.

Widening further is a DEFERRED line and a bake change, never an attribute
value.

*Rejected:* D10's `upload(id, "image" | "video")` with no element. Its
value has no node to arrive on (`Outcome.commands` is fire-and-forget), so
it would need a "command with a reply" path nothing else uses. The element
gives the value a home and the agent a target, and matches what a web
author writes. D10's text points here.

### D2 — `showPicker(id)` opens it

`showPicker` joins `focus`, `selectText` and `blur` in `HOST_COMMANDS`
(`contract/types/src/checks.rs:682`): a command naming an element by id,
issued from an action. On the web the glue calls
`HTMLInputElement.showPicker()`.

**User activation.** Browsers allow `showPicker()` only under transient user
activation. The glue runs commands inside the input dispatch, so a
`showPicker` in a pressed action works on the web. Native hosts don't
enforce activation: a picker opens from any action, a timer or an answer
included (ruled). On the web the same `showPicker` outside a press is
refused by the browser (`NotAllowedError`), journaled as `picker: refused:
NotAllowedError`, and fires `cancel`. The authoring guide says so; nothing
in the compiler or the hosts enforces it.

A second `showPicker` while one is open does nothing and journals it.
Cancelling fires HTML's `cancel` event on the input (a new `EventKind`), so
a compose screen can clear its "choosing…" state.

### D3 — `change` carries a list of `Picked` records

| field | type | always | notes |
|---|---|---|---|
| `path` | string | yes | `app:/tmp/picked/<id>.<ext>`; `<id>` from the launch seed and a counter (LLP 1027.000), never the user's file name |
| `name` | string | yes | the original name, for display (`IMG_0412.HEIC`) |
| `type` | string | yes | the MIME type of what is at `path` (after D6) |
| `size` | number | yes | bytes at `path` |
| `width`, `height` | number | images and video | pixels, orientation applied (EXIF, or the track transform) |
| `duration` | number | video | seconds |

`Picked` is a shape the compiler supplies, as `exactViewport`'s is, so
`action attach(files: list Picked)` type-checks. Without `multiple` the list
has one element, in the order the user selected.

- **Apple.** Pixel size from the ImageIO header (no decode) or `AVAsset`'s
  track: microseconds.
- **Web.** `createImageBitmap` for images, a `<video>`'s `loadedmetadata`
  for video, then `change`.
- A file whose metadata can't be read is delivered without the size fields.
  It is not an error.

### D4 — The bytes go to `app:/tmp/picked/`, and the app decides what's next

**Native hosts** copy each picked file into `app:/tmp/picked/` before
`change` fires. The copy is required: PHPicker's `loadFileRepresentation` URL
is deleted when its callback returns, and `NSOpenPanel`'s URL is
security-scoped. A path the app holds must outlive both.

What the app does next is its own logic, through grants it already declares
(LLP 1027.001, LLP 1069.008):

- read it: `fs.read app:/tmp`;
- keep it: `fs.write app:/data`, then `rename`;
- upload it: `net.fetch <origin>`, with `readFile`'s bytes as the body.

The picker needs no grant. The user's selection is the consent, as on the
web and for PHPicker, which needs no photo-library permission and no usage
string. LLP 1069.008 D7's reach table lists "picks files (`accept`)",
derived from the tag's presence in the plan.

`app:/tmp/picked/` is emptied at launch.

*Known cost:* uploading a large video puts it all in the source's memory
(`readFile`). A streamed request body from a path belongs to LLP 1016.000's
streaming work.

### D5 — On the web the `File` backs the entry; nothing is copied

The web's `app:/tmp` lives in IndexedDB (`host/web/storage-fs.js`). Copying
a 300 MB video into it before `change` would stall the pick and double the
storage. The glue registers each `File` as a blob-backed entry at its
`app:/tmp/picked/…` path:

- `stat` answers from `File.size`;
- `readFile` answers `await file.arrayBuffer()`;
- `rename` into `app:/data` is where a real copy is written.

A `File` is structured-cloneable, so the storage worker holds it the same
way. The entries last as long as the page.

### D6 — The host delivers a type `accept` names, converting when it must

This follows iOS Safari, on every host (ruled). Given `accept="image/jpeg"`,
Safari hands a HEIC photo over as a JPEG; given `image/*`, the original.

| accept | the photo is HEIC | the video is HEVC/ProRes |
|---|---|---|
| `image/*`, `video/*` | HEIC, as is | `preferredAssetRepresentationMode = .current` |
| `image/jpeg,image/png` (no HEIC) | JPEG, quality 0.9, orientation applied, location metadata stripped | `.compatible` (H.264) |

- **macOS.** `NSOpenPanel` returns the file on disk; the same rule converts
  with ImageIO and `AVAssetExportSession`.
- **Web.** The browser has already chosen what it hands over.
- **Non-media types** (`file_handlers`) are never converted.
- **No other transforms:** no resizing, compression, cropping or size
  limit. A cap is the app's decision, made with `size`. Image editing
  stays out (LLP 1045 §5).

### D7 — `image` and `video` take `app:/` sources

A compose screen shows the picked image before it is uploaded:

- **Apple:** the owned directory's file URL.
- **Linux:** the path.
- **Web:** a blob URL for the storage entry, revoked when the node leaves.

The read is the host's. A source outside `app:/tmp`, `app:/cache` and
`app:/data` is refused, and so is `..`.

### D8 — Per host

| host | presents | notes |
|---|---|---|
| iOS | media: `PHPickerViewController`, filter from `accept`, `selectionLimit` 1 or 0 for `multiple`; other types: `UIDocumentPickerViewController(forOpeningContentTypes:asCopy: true)` | no permission prompt, no usage string; presented from the session's view controller (LLP 1035.001) |
| macOS | `NSOpenPanel` with `allowedContentTypes` from `accept` (`UTType(mimeType:)`, `.image`, `.movie`), `allowsMultipleSelection` from `multiple` | a sheet on the window; separate from `DocumentsMac`'s `open-file` route, which stays the manifest's |
| web | the element's own `showPicker()` | Safari, Chrome and Firefox support it on file inputs |
| Linux | refused: `showPicker` journals `picker: refused: unavailable` and fires `cancel` | an XDG portal `FileChooser` when a desktop Linux host exists (ruled). The substitute (D9) still answers |

### D9 — Substitute

LLP 1069.007 D7's paragraph for this capability:

1. **Shape:** a request, command-shaped: the answer arrives as `change` (or
   `cancel`) on the input.
2. **Pending:** `showPicker` under the agent presents nothing. `state.pending`
   lists `{ticket, device: {capability: "pick", args: {id: "attach",
   accept: ["image/*", "video/*"], multiple: true}}}` (LLP 1069.007 D3).
   **Answer:** `type @t <path>…`, each a file on the driver's machine,
   copied in through D4/D5's path; the host then reads the metadata (D3),
   converts (D6) and fires `change`, so a HEIC fixture tests the JPEG
   conversion. `tap @t cancel` fires `cancel`. **Fixture:**
   `--answer pick=<path>[,<path>…]`. The answer's `delivery` is
   `substituted`.
3. **Web override:** CDP's `Page.setInterceptFileChooserDialog`, then
   `DOM.setFileInputFiles` on `Page.fileChooserOpened` (`delivery:
   "platform"`).

Every host takes it, Linux included, so a smoke drives a compose flow
headlessly. The repo carries one HEIC image and one short H.264 video at
`scripts/fixtures/picker/`.

## Consumers, as written

**Interview's figure** (LLP 1045 D10 unchanged but for the verb):

```
input type="file" accept="image/*" testId="figure-file" display="none" change=figurePicked
button press=chooseFigure aria-label="Insert image"
  image "symbol:photo"

action chooseFigure
  showPicker("figure-file")
action figurePicked(files: list Picked) writes uploading
  uploading = first(files).path     // the app's source uploads it and answers a URL
```

**Bluesky compose.** Four images, or one video. The app's TypeScript
uploads each file to `com.atproto.repo.uploadBlob` and builds the embed
with `aspectRatio: { width, height }` from the record:

```
input type="file" accept="image/jpeg,image/png,image/webp" multiple
    testId="compose-images" display="none" change=attach
```

**Fieldnotes' import** (LLP 1069.010 D3), with `file_handlers` declaring
`application/json`:

```
input type="file" accept="application/json" testId="import-file" display="none" change=importBackup
```

## Verification

- A fixture app, `apps/picker-fixture`: picks one image, many images and a
  video; previews them over `app:/tmp/picked/`; moves one into `app:/data`;
  restarts to show `tmp` emptied and `data` kept.
- Driven by `smoke.mjs` on web, macOS, iOS and Linux through D9.
- On iOS, one manual pass on a phone with a real HEIC and a Cinematic
  video, against D6's table.
- On the web, a `showPicker` from a timer is refused by the browser and
  journaled (D2); on macOS the same action opens the panel.

## Not in this RFC

- A camera and `capture` ("No camera anything").
- Any `accept` beyond media and `file_handlers` types.
- Directory picking, save panels, handles to documents edited in place
  (LLP 1069.010 D1–D2).
- Drag and drop of files onto the app; receiving shares.
- Image editing or resizing; upload progress (the app's state).
- A streamed request body from a path (LLP 1016.000).
- The photo library as a data source (`expo-media-library`).

## Decided

1. The element plus `showPicker(id)`; LLP 1045 D10's `upload` is replaced
   (D1, D2).
2. Native hosts don't enforce user activation; the web's rule is the
   browser's and is documented (D2).
3. iOS Safari's conversion rule on every host (D6).
4. Linux refuses; only the substitute answers there (D8).
5. `accept` widens to `file_handlers` types, per `rules/DEFERRED.md`'s
   2026-09-27 widening; this element is LLP 1069.010's import (D1).
