## Scope and state

[confirmed] Nate's supplied handoff on 2026-10-07 requests this library map in M1. It authorizes new app LLPs and requires all replacements to remain inside the mobile app. This spec maps behavior, not npm installation commands. No framework change or current/foundation link is authorized.

[observed] Upstream `365aa87982` declares 82 runtime dependencies and seven development dependencies in [`apps/mobile/package.json`](https://github.com/pingdotgg/t3code/blob/365aa87982/apps/mobile/package.json). Every dependency appears once in the roster below. Manifest constraints are quoted as written; `catalog:` is not an installed version. Config plugins, autolinking and dynamic imports count as uses even when a direct source import was not found.

[observed] The current clone has only the M0 root, its TypeScript source, iOS crate and one unchanged pinned pairing-parser copy. Its build and input drive do not prove any replacement below. M1 has since copied the three DM Sans faces with notices and extracted the 12 theme JSON files; LLP 1107.002 records those assets. They are not registered or consumed by the app runtime. No native view, full client or transport has been adopted. Implementation status for all roster replacements is planned unless the row explicitly says oracle-only or no iOS replacement.

## Rules for implementation

[confirmed] Reuse Daehyeon's shared logic before porting mobile logic. The current source-capture restriction is Gap 001 in LLP 1107.000: a parent import failed and ancestor mounts are refused. A required copy must retain its source SHA and license. When the adopted base changes the original, refresh the copy and SHA, compare its body, rebuild and drive the affected screen. Rebuilding an old copy alone does not update it.

[inferred] Prefer the existing Exact control/router when it matches the upstream mobile behavior. Otherwise use the app's one native module and UIKit. A row naming UIKit is a proposed implementation location, not evidence that the manifest or module API already supports every extension. Record a demonstrated framework restriction under the existing X-id where one exists; keep new gap reports in the local handoff folder.

[confirmed] Keep each upstream package until the oracle no longer needs it. The clone does not install React, Expo or Effect just to reproduce their abstractions. It reuses the client model and implements the visible or persisted behavior that the package provides.

## Verification and unresolved work

[confirmed] A replacement is complete only when its mobile consumer is built and driven against the pinned upstream on the same fixture, with pixel evidence where visible. Test failures and limitations remain named; a successful package build is not feature parity.

[inferred] The largest unproven app-local integration points are WidgetKit/share-extension packaging, mobile auth and encrypted Connect state, the GhosttyKit artifact, and native text/navigation ownership. They need focused implementation proofs in their milestones. This spec does not declare new framework gaps for them before reproductions exist.

[observed] This is an M1 source map. It has no upstream capture or performance result and an independent-session Codex review in [the review artifact](reviews/1107.001-expo-library-map.codex.md). Cross-family review remains unavailable.
