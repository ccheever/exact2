# LLP 1101.000: Authoring in cells — what the todo fixture taught

**Type:** RFC
**Status:** Draft (r1, exploratory, as LLP 1101 is)
**Systems:** The terminal profile (`contract/cli/src/terminal.rs`, the schema's `terminal` key), the terminal host (`host/terminal`), `exact:terminal` (LLP 1101 D2, unbuilt), Contract lints (`contract/lower/src/lib.rs` `lower-scroll-unbounded`), `docs/agent-pitfalls.md`
**Author:** Claude (Opus 5.5) for Charlie Cheever
**Date:** 2026-10-06
**Implementer:** none yet
**Related:** LLP 1101 (terminal apps; §11 records the spike this document reads), LLP 1101 Q2 (bare integers as cells), LLP 1091 D8 (`exact:` built-ins), LLP 1035.005.000 (Contract after the apps: the same kind of evidence, from the GUI apps), LLP 1088 (what the app diaries ask of Contract). Evidence: branch `terminal-spike`, `apps/todo/terminal.contract` (cited below by line on that branch).

## Summary

The todo fixture is the first app written in cells. It took one sitting: about
eighty lines of Contract, two host bugs found and fixed along the way, and
two compile errors on the author's side. Charlie ran it on 2026-10-06 and
said it "looks quite nice and feels quite nice."

LLP 1101 bet that a terminal UI can be written in the ordinary vocabulary if
it is designed for the terminal. That bet held. Everything below the view
(state, actions, records, the filter) is plain Contract that never mentions
the terminal. The view uses ordinary tags and CSS properties in `ch` and `lh`,
and the edit loop was the fastest of any surface, because the screen came back
as text.

Where it chafed, the cause is narrow, and each fix is small:

- the profile checks *that* a length is in cells, not *which* cell;
- borders are written in a unit that lies;
- a few web defaults that are right for a page are wrong for a terminal list;
- some things are written by hand that the host could do or a component could
  carry.

§3 proposes nine changes, ordered by how much they buy for what they cost. The
first three are compiler checks of a few dozen lines each.

## 1. What went well

**G1. The logic never knew.** Lines 1–37 (shapes, state, `derive`, actions)
are Contract that would compile unchanged in a web entry: `concat`, `map`,
`filter`, record copies with `Todo(t, done=not t.done)`. That was LLP 1101
D1's claim (share everything below the view), and the fixture shows it costs
nothing. The terminal-specific part of the app is the view and nothing else.

**G2. The loop was the best yet.** The host compiles the `.contract` at
startup, so an edit is one command (`exact-terminal app.contract --size 60x16
print`), and what comes back is the screen as text. An agent can read that
directly, with no screenshot and no vision step: a misaligned column or a
border on the wrong row is visible in the diff of two prints. Every host bug
the spike found (borders a pixel thick, heavy corners) was
found this way in seconds. LLP 1101 D8 made `.txt` screenshots a form of
`screenshot`. The fixture says they should be the *first* thing an agent
reaches for on this surface (P9).

**G3. Cells are the right unit.** `height="1lh"`, `gap="2ch"`, `width="4ch"`
and `margin-left="auto"` mean what a terminal author expects, flex
distribution snapped without gaps or overlaps (D3's tiling rule), and no box
ever landed between cells.

**G4. The terminal's own idioms came out of CSS.** A rounded panel is
`border-radius` on a bordered box. A struck-through finished task is
`text-decoration-line`, and a faint one is `font-weight=300` (SGR 2). An
ellipsis is `text-overflow`, a key is `aria-keyshortcuts`, and the cursor in
the field is the terminal's own. None of these needed a terminal name.

**G5. The profile caught what it was built to catch.** A file with
`padding=16`, `margin="1lh 2px"`, `box-shadow`, `font-size` and a `canvas`
got five refusals at once, each with its span and the reason (LLP 1101 §11).

## 2. Where it chafed

**C1. Cells have an axis, and the profile doesn't check it.** A vertical
length in `ch` or a horizontal one in `lh` is legal and rounds silently,
measured on the spike:

| Written | Becomes |
|---|---|
| `padding-top="1ch"` | 1 row (8 px rounds up) |
| `padding-top="2ch"` | 1 row |
| `padding-top="3ch"` | 2 rows |
| `padding-left="1lh"` | 2 columns |

The box shorthands make it easy to get wrong: `padding="1lh 1ch 0"` (line
44) is right, but `padding="1ch"` looks right and is half a row on two sides.
This is the trap LLP 1101 Q2 worried about, but the fix it considered (bare
integers as cells) answers verbosity, not the axis.

**C2. Borders are written in a unit that lies.** Line 57 says
`border="1px solid #5f87af"` and line 58 `border-radius=4`. In a terminal the
first means "one cell, light" and the second means "rounded corners". LLP
1101 §4 says the width is `thin` or `medium`. But the `border` shorthand
reaches the profile as `AttrTarget::Shorthand`, which it skips, and radius is
`quantize`, which admits any number. So the spike's own fixture is written in
pixels the terminal ignores, which is exactly the "a number that means
something else here" problem D3 rejected for lengths.

**C3. Web defaults that are wrong for a terminal list.** Every list row
needed `display="flex" gap="1ch" width="100%" text-align="start"` (lines
64–67). `text-align="start"` is there because CSS centres a button's content,
which is right for a web button and wrong for a terminal row, where almost
every button *is* a row. Every truncating line needed `white-space="nowrap"`
`text-overflow="ellipsis"` and, on the footer, `min-width=0` before it stopped
wrapping into the row beneath. That is all CSS-correct, but a terminal entry
pays it on every row.

**C4. Repetition a component would carry.** The filter's "selected" look is
the same `font-weight` and `text-decoration-line` condition written three
times (lines 45–53). The key-hint footer is a hand-written string that
repeats what `aria-keyshortcuts` already says on each button, and goes stale
when a key changes. The `[x]`/`[ ]` box is text with a colour condition (line
68), not a checkbox, so the tree says "button" where it should say "checked".

**C5. Focus can only look one way.** The host's reverse video is the only
focus indicator (LLP 1101 D6). Contract has no `:focus-visible` style; an app
that wants its own focus look writes `focus`/`blur` handlers and state, as
Caltrain does for its search field. For a list of twenty rows that is not
reasonable, so in practice every terminal app will look focused the same way.

**C6. Two Contract snags that aren't terminal-specific.** `color=light-dark(a,
b)` is refused as an unknown function. It must be the string
`"light-dark(a, b)"`, unlike every other expression-shaped value. The
`lower-scroll-unbounded` lint accepts `flex=1` but not `flex-grow=1
min-height=0`, which bounds the scroll just as well; the fixture switched to
`flex=1` to get past it (line 60).

**C7. Too small collapses rather than refusing.** At 60×6 the panel drew as
an empty border: the list had no room, and nothing said so. LLP 1101 D1's
`minimumColumns`/`minimumRows` screen is the answer, and it isn't built.

## 3. Proposed changes

| # | Change | Where | Cost | Fixes |
|---|---|---|---|---|
| P1 | The profile checks each length's axis | `terminal.rs` | small | C1 |
| P2 | Borders in words; pixel widths refused | `terminal.rs`, the painter | small | C2 |
| P3 | `checkbox` drawn as `[x]` | the host | small | C4 |
| P4 | A host-drawn key help on `?` | the host | small | C4 |
| P5 | `exact:terminal`: `Row`, `Tabs`, `Panel` | Contract module | medium | C3, C4 |
| P6 | The minimum-size screen | the host, `app.json` | small | C7 |
| P7 | The two Contract snags, filed where they belong | `docs/agent-pitfalls.md`, QUEUE | trivial | C6 |
| P8 | `:focus-visible`: keep reverse video; ask the cross-surface question separately | — | none now | C5 |
| P9 | `.txt` screenshots first in the terminal's agent guide | docs | trivial | G2 |

**P1 — The profile checks each length's axis.** Each `cell` row has an axis
in the schema's terms. `lh` is block-axis: `height`, `min-`/`max-height`,
`padding-`/`margin-top`/`-bottom`, `top`, `bottom`, `row-gap`. `ch` is
inline-axis: `width`, `min-`/`max-width`, `-left`/`-right`, `column-gap`,
`text-indent`. A length in the other axis's unit is `terminal-axis`, naming
the unit to write instead. Box shorthands check each piece by its CSS
position (top, right, bottom, left). `flex-basis` follows `flex-direction`
when it is a literal. A one-value `gap` is checked against the axis its
container actually uses (a `row` spaces with `column-gap`, a `column` with
`row-gap`), so line 44's `gap="2ch"` on a row passes. Either check accepts
both units when the direction isn't a literal.
This keeps `ch`/`lh` (the web-honest spelling) and makes the trap
impossible, so LLP 1101 Q2 can stay "no".

**P2 — Borders in words.** In a terminal entry the `border` shorthand and
`border-width` take `thin` (one cell, light `─│`) or `medium` (one cell,
heavy `━┃`), or `0`/`none`. A pixel width and `thick` are `terminal-length`,
since §4 already refuses them and the profile now enforces it. This means
checking the shorthand's string before lowering turns it into numbers. The
painter keeps reading weight from the lowered number (`thin` = 1, `medium` =
3), as it does now. For radius, a terminal entry writes `border-radius` with
any nonzero length to mean "rounded", and the profile admits `1ch` there so
the fixture has a cell-honest spelling. Whether a keyword would read better is
Q1.

**P3 — `input type="checkbox"` drawn as `[x]`.** Admit the checkbox in the
terminal entry and draw it as `[x]`/`[ ]` (`(•)`/`( )` for a radio), with the
label beside it and Space toggling it. The fixture's line 68 becomes a real
control, so the tree reports `checked`, and the colour condition moves into
`accent-color`, which is then `quantize`.

**P4 — A host-drawn key help on `?`.** The host already finds shortcuts by
walking `aria-keyshortcuts` on visible nodes (`host.rs` `shortcut`). On `?`
(when the focused node doesn't take text), it can draw an overlay listing
each visible shortcut with its node's accessible name, and Esc closes it. The
fixture's hand-written footer goes away, and every terminal app gets the same
help for free. exact1's 0368 asked for the same ("A help surface can
enumerate active commands"). It is host behaviour, not vocabulary, so it
needs no Contract change.

**P5 — `exact:terminal`'s first three components**, in ordinary Contract over
admitted rows (LLP 1101 D2, LLP 1091 D8), each earning its place from this
fixture's lines:
- **`Row`**, a pressable full-width row: `display="flex" gap="1ch"
  width="100%" text-align="start"`, with its content truncating. That is
  lines 62–73's boilerplate, written once.
- **`Tabs`**, labelled options with keys, the selected one bold and
  underlined, writing one value. That is lines 44–53.
- **`Panel`**, a bordered, rounded box with a title drawn into its top edge
  (the one thing CSS can't say directly; the painter would need a `legend`-like
  row, see Q2), flexing to fill its parent with a bounded scroll inside.

This is deliberately composition, not defaults. Changing the UA's button
alignment in a terminal entry would be a terminal-only default, and that is
the four-disagreeing-layers class (CLAUDE.md, "The web is the standard").

**P6 — The minimum-size screen.** Build LLP 1101 D1's `minimumColumns`/
`minimumRows`: below them the host draws its own centred "make the window
larger (60×16)" instead of the app. Until the `app.json` entry exists, the
host can derive a floor from the root's laid-out min-content size.

**P7 — The two Contract snags.** Add to `docs/agent-pitfalls.md` that a
colour function is a string (`color="light-dark(#000, #fff)"`), and add a
QUEUE line for `lower-scroll-unbounded` to accept `flex-grow` with
`min-height=0` as bounding the scroll. Neither belongs to the terminal.

**P8 — `:focus-visible`.** Keep reverse video as the terminal's focus look.
It reads well, and the fixture never wanted another. Whether Contract should
gain `:focus-visible` styling is a question for every surface (Caltrain's
handler-and-state pattern is the workaround everywhere), so it belongs in its
own document, not here.

**P9 — Text first.** When `scripts/agent.mjs terminal` exists, its guide
leads with `screenshot out.txt` and a printed grid, not a PNG. G2 is the
reason, and it is an advantage the terminal has over every other surface.

**Not proposed: bare integers as cells (LLP 1101 Q2).** The fixture has
about twenty lengths in cells. With P1 catching the axis, the remaining cost
is a few characters each. Bare integers would make `padding=1` mean pixels in
one file and cells in another, so keep the answer "no".

## 4. Open questions

- **Q1. Rounded corners: `border-radius` or a word?** Any nonzero radius
  reads as "rounded", which is honest about what a terminal can do but says
  nothing about how round. Should the profile want `border-radius="1ch"` as
  the canonical spelling, or accept any value as it does now?
- **Q2. `Panel`'s title in the border.** A title sitting in the top edge
  (`╭─ Tasks ───╮`) is the most terminal-native thing the fixture lacks.
  HTML's `fieldset`/`legend` is exactly this. Should the terminal draw a
  `legend` into its `fieldset`'s border, and are those tags admitted?
- **Q3. Hover.** The fixture never asked for it. Should mouse-motion tracking
  stay off until an app has a hover handler (LLP 1101 D6's rule), or is a
  hovered row worth a default?
