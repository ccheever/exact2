## Summary

An agent plays, inspects and debugs a game through **the eight operations
it already has** — `tree · screenshot · tap · type · state · layout · logs ·
clock`. exact1's Acto answered every new question with a new wire name;
`NOT-DOING.md` answers it with a count. A game is the hardest test that
rule has had, and it holds: a new question is a form of `tree`, `state` or
`layout` addressed at an entity; a new input is a phase of `tap` or `type`;
time is `clock`. The world is one more thing that answers.

Three things make the interface worth having, and none is an operation:
the simulation is **deterministic under the agent's clock** (D4, D5), the
world **describes itself from its own component table** (D2), and a **save
state is a save game** (D6).

## 1. Decisions

**D1 — No ninth operation; a world is a guest, and an entity is a
target.** This has been decided once already. An `iframe`'s document is a
second world inside a node, and LLP 1020 D4 ruled: "the guest joins the
eight operations. No ninth op, no controller" — `tree` shows a guest
outline under the node, `tap` and `type` address into it with a `selector`
beside the node's id. A game world is the same shape behind a `canvas`.

Where LLP 1012 takes a target — a `testId` or a view id — an **entity
target** is `<canvas>:<entity>`: `world:fox`, `world:lantern-3`,
`world:#214`; on the wire the entity rides beside the view id as the
guest's `selector` does (`{"op":"layout","id":V,"entity":"fox"}`). Names
are the level's; a level that declares two entities with one name is
refused at build; a spawned entity is `name#n`. The driver resolves the
canvas through `tree` as it does today, and the host passes the entity half
to the module (§2). The runner never learns what an entity is.

**D2 — Reads: the world answers `tree`, `state`, `layout` and `logs` from
its own tables.** Every reply carries LLP 1035.002 D3's tags plus `tick`.

| form | reply |
|---|---|
| `tree` | unchanged; a canvas row whose surface is a world gains one summary, `world{name, entities, tick}`, merged by the host as an iframe's `{url, loading}` is — today a `Canvas` row carries neither its surface's name nor its arguments (they are a runner side-output, `SurfaceUpdate`, not props) |
| `tree <canvas> [under <entity>]` | the world in transform-hierarchy preorder: `id`, `name`, `parent`, `depth`, `components[]` (type names), `tags[]`; capped, with `truncated` |
| `state` | one more section beside the host's three (LLP 1035.002 D2): `world{canvas, tick, hz, seed, hash, entities, resources{…}, input{actions{name: bindings[]}, held[]}, audio{voices[]}, perf{…}}` — `perf` is wall-clock, flagged so, and outside the hash and every golden |
| `state <entity>` | the entity's components as typed JSON, by component and field name |
| `layout <entity>` | `entity{world{position, rotation, scale}, bounds{min, max}, screen{x, y, w, h}, depth, visible{inFrustum, behindCamera, distance, occluded?}}` — `screen` in `layout`'s own space (LLP 1012 §1: viewport, top-left, points), so an entity and a button are comparable numbers |
| `layout <canvas> at <x> <y>` | the pick: which entity is under a viewport point, and where the ray hit |
| `logs` | world events as journal lines, stamped with the clock and the tick (below) |

Component JSON is generated from the add-on's component table
(LLP 1041.002 F12) — the same table that writes the save format and the
hash — never a hand-written debug view. That is 0495 §4.1's lesson, applied
before the bug instead of after.

**The journal carries events, never samples.** `spawn`, `despawn`,
`collide fox × crate` (begin only, declared pairs only), `anim fox: walk →
run`, `sfx chime at lantern-3 gain 0.8`, `music dusk → night`, the game's
own (`lantern-3 lit`), and every refusal. An agent cannot listen, so **the
journal is how it hears**: what played, when, where, how loud. The ring is
4,096 lines (LLP 1012 §3); anything per-tick would empty it in a minute. A
sample is `state` read at a clock the agent chose.

**D3 — Inputs are real inputs, held across requests.** LLP 1012 §6's first
decision — one delivery path — stands: the agent drives **devices**, never
game actions. An action-level injection is `Runner::act`'s cousin: for
tests, never an agent.

- **Keys:** `type <canvas> key <Name> down` and `… up`, beside today's
  `key <Name>` (down then up). Held across requests, as a contact is.
  LLP 1005 §6 lists `keyup` as "not an event"; it still is not one — a held
  key goes to the module through the input seam (LLP 1041.002 §3 S1), not
  to the runner.
- **Pointer:** LLP 1035.003 D1's phases as they are — `tap <canvas> down at
  x y`, `tap move by dx dy over ms`, `tap hold`, `tap up`: mouse-look, a
  thumb stick, a drag.
- **`tap <entity>`:** the driver reads the entity's `screen` box and
  presses at its centre through the platform's path. It **refuses by name**
  when the entity is off screen or the pick at that point is another entity
  (LLP 1035.003 D7) — it never teleports a click to the thing it was asked
  to hit.
- **Gamepad:** a button is a key under the name the action map declares;
  an axis is a form of `tap` — `tap <canvas> stick left 0.7 -0.2`. No
  carrier can synthesize a real pad, so the reply's `delivery` is
  `recognized` (LLP 1035.003 D2) and says so.
- The controls are discoverable: `state.world.input.actions`.

**D4 — `clock` is the only thing that moves the world.** In agent mode the
GPU module already "never reschedules itself; `clock` asks it for a frame"
(LLP 1012 §2). The world extends that sentence and adds nothing to it:

- `tick = floor(clock_ms × hz / 1000)`. Asked for a frame at a new clock,
  the module steps every whole tick up to it, then renders **once**. A
  `clock +60000` is 3,600 ticks and one frame — headless throughput is the
  default, not a mode.
- **A seek is a seek** (LLP 1005 §6): `clock +1000` and sixty seeks of one
  tick end in the same hash. It holds because the timestep is fixed and an
  input takes effect at the first tick boundary after its clock stamp. It
  is a fixture (LLP 1041.000 §5 step 5).
- An input held across a seek is held for every tick in it.
- `clock settle` gains one participant, as LLP 1016 added requests in
  flight: the world reports when it is **quiescent** — dynamic bodies
  asleep, no one-shot animation or sound unfinished. Ambient loops and
  anything the level marks as weather (the sun) are outside the definition,
  or a world with a sky would never settle. Bounded (600 ticks), then
  `settled: false, reason: "world"`.
- The reply gains `world{tick, hash}`. Ticks are never a unit on the wire;
  `clock +3t` is the driver multiplying by `1000 / hz`.

**D5 — Determinism is the contract; the hash is its instrument.**
`world.hash` is a hash of the world serialized in canonical order at a
tick. **Simulation state is held bit-exact across hosts; pixels are held to
a band** (LLP 1009 D1). What that costs the add-on: a fixed timestep; every
seed an explicit input (LLP 1027.000 D1, which already says "Rust providers
follow the same explicit-input contract"); no clock but `Frame::now_ms`;
`rapier`'s cross-platform-deterministic build; `libm` for transcendentals;
ordered iteration everywhere; no threads inside a tick.
**Unverified:** that wasm, arm64 and x86-64 agree to the bit through all of
that. LLP 1041.000 S1 is the experiment. If it fails, the fallback is
declared, not hidden: exact per host, ε across hosts, and the parity number
becomes a band.

**D6 — A save state is a save game; restoring one is session setup.**
World serialization is something the game needs anyway (LLP 1041.000 §1).
A session starts from a save with `open({world: path})` / `--world <file>`,
beside `--plan` — "session setup, not a drive" (LLP 1012 §1). Forking a
world is starting two sessions from one file. `NOT-DOING.md` refuses session
record/replay, and this is neither: there is no recorder and no replayer —
a script, a seed and a file.

Getting the file *out* is the one place the count is strained. A player's
save goes to app storage, and agent mode creates none (LLP 1027: "Agent
mode rejects storage"; LLP 1012 as amended: a drive "leaves nothing
behind"). Proposed: a capture of the world is a form of the operation that
already captures to a path — `screenshot save.world world` — the bytes the
game's own save would have written, to the driver's path. The alternative
is a declared scratch directory under agent mode. Charlie's call (§5 Q1).

**D7 — The simulation never needs a GPU.** `tree`, `state`, the world half
of `layout`, `logs` and `clock` answer with no device; `screenshot`, picks
through the ids buffer and `visible.occluded` need one and say
`unavailable` without it, as the Linux host's `state` sections do
(LLP 1012 §1). So the fleet's GPU-less builders (LLP 1041 F18) could run
every logic test, balance sweep and fuzz; only pixels wait for lavapipe or
a Mac. One owed piece stands in the way: the Linux host does not load the
GPU module at all yet (LLP 1015 §7). Loading a module whose simulation runs
without a device is the smaller half of that, and D7 is the reason to do it
first. A session is a process; a thousand games is a thousand processes.

**D8 — `screenshot` gains views; the filmstrip is the driver's.**
`screenshot out.png view <color | ids | depth | normals | collision | top>`.
`ids` paints each entity a flat colour and returns the legend — a
segmentation the agent can read instead of guessing; `top` is an
orthographic map with names; `collision` draws the colliders the physics
actually has. A filmstrip — motion in one image — is
`screenshot strip.png every 100 for 8`: the driver runs `clock +100` and
`screenshot` eight times and tiles the PNGs. No host code, and it works on
any app's motion, not only a game's.

The driver may explain a refused placed-child tap by reading `state` and `layout`;
it reports the world's visibility and the command that exposes the box. `state
world:* busy` adds the moving component values and busy reasons to the existing
state form without changing ordinary snapshots. Proof `--report` summarizes only
recorded refusals/stalls and names unused facilities. Pin regeneration is a JS
proof command over the existing operations, comparing continuous, Save and
FreshGame observations before writing the game's single `pins.json`.

## 2. How it is carried

One export on the GPU module's ABI beside `gpu_render`, mirroring
`exact_agent(len)` — the iframe module already has its twin,
`exact_web_agent_eval` (`WebModule.swift`). The host hands the module an
agent read whose target resolved to its canvas and merges the reply into
its own, as it merges the runner's half of `layout <target>` (the private
`node` message, LLP 1012 §1) and its own `state` sections (merged in the
presenter, outside the runner — `runner/src/agent.rs` emits a fixed key set
and has no registration hook, and needs none). Journal lines reach the ring
through `exact_log` (LLP 1035.001 D6). Input reaches the module through
LLP 1041.002 §3 S1. Nothing here is in the runner, and an app without a
world compiles none of it.

## 3. The transcript form

One rendering, a pure function of the reply, never parsed back
(LLP 1012 §7):

```
tree world
         epoch 4 · incarnation 1 · clock 21500 ms · tick 1290 · 214 entities
         Island#1 (Transform, Terrain, Collider)
           Fox#2 (Transform, Character, Skin, Animator) anim=run
           Crate#9 (Transform, Body, Collider) asleep
           Lantern-3#14 (Transform, Lantern, Trigger, Light) lit
layout world:lantern-3
         #14 Lantern-3 world 12.50,3.00,-4.25 · screen 612,240 38×71 · depth 18.4 · in frustum
logs     t=21340 tick=1280 anim fox: walk → run
         t=21480 tick=1288 lantern-3 lit
         t=21480 tick=1288 sfx chime at lantern-3 gain 0.80
```

## 4. Refused, and why

- **A ninth operation** — `world`, `query`, `step`, `snapshot`, `replay`.
  Each has a form above or is session setup.
- **Action-level input for agents.** One delivery path.
- **A query language over the world.** A filter is the driver's, over
  `tree`.
- **Subscriptions and streaming.** Nothing moves between two operations;
  there is nothing to subscribe to.
- **A performance operation.** Numbers in `state.world.perf`, flagged
  wall-clock.
- **Recording.** The script is the recording.

   under agent mode, or neither (saves are tested outside agent mode only)?

   contain `:` today is unchecked.
3. Is `layout <canvas> at <x> <y>` a form `layout` should have for every
   node, not only a world's? It reads like one.
4. The quiescence definition (D4) is the game's to declare or the
