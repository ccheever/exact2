# LLP 1149.001: The renderer's cost program

**Type:** RFC
**Status:** Draft r1, 2026-10-30. Not yet reviewed.
**Systems:** host/ink, host/apple-painted, host/windows, host/linux (the painter and the presenter), kernel (row change bits), bench/heavy-list
**Author:** Claude Fable 5.1 (orchestrator); Astra (gpt-6-astra) builds each stage
**Date:** 2026-10-30
**Related:** LLP 1149 (the renderer: this refines its D2, D4, D7, D11 and D15), LLP 1148 (the options), LLP 1142 (traces), LLP 1079 (`perf`), `bench/heavy-list/gpui/RESULTS.md` (G3c, G4, G6c: the scoreboard)

## Summary

Ink is now measured against egui, GPUI and the native hosts on the same screen, the same
input and the same probe, on the Mac and on Windows. It starts fastest on Windows, matches
the field on cadence, and costs more CPU during a fling than egui on both platforms and more
than GPUI on neither. The traces say where that cost is, and most of it is plumbing around the
renderer, not the renderer. This document is the program that removes it: ordered stages,
each with the trace that names it, the decision of LLP 1149 it amends, and the movement it
predicts; a scoreboard every landing must rerun; and the things it will not do. The target
is a fling at or under egui's cost on both platforms with the kernel and the app model
intact, GPU work per frame cut to the scene itself, nothing at rest, and a first screen on
the way to LLP 1149's 100 ms.

## 2. Where the cost is

The ink carrier's ten-second Mac fling, main thread, exclusive time per phase from the
S1.4 trace (`target/s1-4/g3-control`, joined as RESULTS.md S1.5 describes):

| Phase | ms/s | Notes |
|---|---:|---|
| Event-loop service passes | 12.6 | 358 passes a second, ten per presented frame: the runner, hatches and image polling pumped on every wheel event, tick and wake |
| Paint walk | 5.7 | every visible node, every frame, kept rows included |
| Carrier draw and scene encode | 5.9 | the instance buffer rebuilt every frame |
| Glyph raster, layout, refine | 2.6 | 480 incremental layouts a second at a microsecond each |
| Wheel input | 1.3 | |
| Unattributed | ~15 | AppKit and winit delivery, display-link wakes, the probe; not yet marked |

On the GPU, per frame: the scene 0.23 ms; the pass that samples the compose target into the
drawable 1.0 ms. Off the main thread: ImageIO decodes at the drawn size (shared with egui's
arm), the staging ring's waits, the present worker's completion wait.

## 3. The program

Each stage is one lane: trace, predict in writing, change one thing, rerun the scoreboard,
two-family review, land. A stage that moves a scoreboard row the wrong way does not land
until the row is explained. Stages are ordered by evidence, not by size.

### Stage 1: plumbing the traces already name

- **M1, one service per frame.** Inputs mark the presenter dirty and nothing else; the frame
  pumps the runner, hatches and images once. Amends nothing in LLP 1149; it is the carriers'
  contract (Mac, Windows, Linux). Predicted: Mac main thread 44 → ~34 ms/s.
- **M2, nothing at rest.** The carriers' idle timers wake for nothing; the Mac carrier
  sleeps at 1.5 ms/s and Windows at 4.7. Predicted: ≤ 0.4 on both.
- **M3, render into the drawable.** The compose target is sampled into the drawable every
  frame for LLP 1149 D7's readback. Render the scene into the drawable or swap chain
  directly; a readback (`screenshot`, the agent's pixels, the oracle comparisons) renders the
  retained scene once more into an offscreen target on demand. Amends D7 ("no window frame is
  read back" still holds: the readback is a re-render). Predicted: GPU per frame 1.2 → ~0.3
  ms, a worker wake and ~3 ms/s of CPU per second gone; the battery line.
- **M4, one staging arena per frame.** Uploads copy once into a per-frame arena fenced on
  that frame's completion, instead of twice through a two-slot ring that serializes a burst
  of thumbnails at GPU latency. Amends D11's retirement only in granularity. Predicted: a few
  ms/s, and the 340 MiB transient cut to the frame's own uploads.
- **M5, the display link.** The Mac carrier's `CVDisplayLink` callback lands five
  milliseconds after vsync and the link is stopped and restarted every frame. `CADisplayLink`
  from `NSView.displayLink` (macOS 14, the carrier's minimum), kept running through a gesture
  and a short grace after it. Predicted: about one frame less input latency; no CPU change.
  Windows keeps the frame-latency waitable, which G6c made one paint per present.

After stage 1 the Mac fling is predicted at about 60 ms/s process, 25 to 30 main, and the
Windows fling at or under 60.

### Stage 2: cost that scales with change

- **M6, a change bit per row from the kernel.** The painter walks every visible node every
  frame; the kernel already knows which nodes changed. A kept row whose subtree did not
  change replays its instance list without a walk. Amends D4 (kept rows pin what they
  reference; now they also skip the walk). Predicted: the walk near zero on a static screen,
  new rows only in a fling; this is where immediate mode cannot follow.
- **M7, retained instance ranges.** Kept rows keep their ranges in a persistent instance
  buffer; only rows that changed are written. Amends D1.1's "the instance buffer is rebuilt
  per frame" and D4. Predicted: encode 2.9 → under 1 ms/s; with M6, a static screen with one
  animating element costs that element.
- **M8, a plain pipeline.** Every pixel today runs the general shader with two rounded clips
  and a coverage clip. An axis-aligned rectangle or glyph with a solid or image brush and no
  rounded clip is most of any UI; a second pipeline draws those instances. Amends D2 (the
  pipelines). Conditional on G5's GPU numbers: if the GPU's share after M3 is already small,
  M8 is not worth its second shader on four device layers. Predicted, if done: GPU per frame
  down a third to a half.

### Stage 3: the platforms, where measured

- **M9, DirectWrite glyphs on Windows**, ClearType included; a tell as much as a cost.
- **M10, the first screen, phase by phase, on both platforms.** The device is 35 to 50 ms
  of a 150 to 180 ms first screen; the rest is plan load, the runner and layout. Only this
  reaches LLP 1149's 100 ms. Shares its instrument with S2's queued startup tail.
- **M11, the direct Metal boot obligation** (an archive miss never blocks first pixel; by
  2026-11-04), and ink replacing vello on Linux and Android as D15 decided.

## 4. The scoreboard rule

Every landing of this program reruns the four-arm Mac series and the three-arm Windows series
with the committed drivers and `aggregate.mjs`, appends its section to `RESULTS.md`, and
updates the table in LLP 1149 §4.1. G5 (the static screen: a bar advancing every frame and a
caret blinking at 2 Hz; GPU busy time from the probe's command-buffer hook; power from
`powermetrics`) joins the series before M6, since M6 and M7 are measured by it. A row that
cannot be reproduced from the retained raw files is not a number.

## 5. Not in this program

Thinning the kernel or the runner to chase egui's 25 ms/s: that is the app model's price and
it is small in absolute terms. GPUI's re-presentation policy. Returning to vello. A second
renderer per platform: the per-platform work is device layers and text, as D5.2 has it.

## 6. Questions

- **Q1.** M3 makes a `screenshot` cost one re-render (about a frame of GPU time at the time
  of the request) instead of a copy. Acceptable? Recommendation: yes; the agent waits on
  `clock settle` anyway. Confidence 90%.
- **Q2.** M5 drops nothing (the carrier's minimum is macOS 14) but leaves `CVDisplayLink` in
  no host. Recommendation: yes. Confidence 90%.
- **Q3.** M8 waits for G5's GPU numbers; if the GPU share after M3 is under 15% of the frame
  on both platforms, drop it. Recommendation: that rule. Confidence 80%.
- **Q4.** Order against S2's Windows queue (RichEdit into Shelf's field, the startup tail):
  M1 to M5 first, then M9 with the RichEdit field, then M10 with the tail. Confidence 75%.

## 7. Decisions, as amendments to LLP 1149

- **A1 (D7).** The scene renders into the window's drawable or swap chain; readback is a
  re-render of the retained scene into an offscreen target, on demand.
- **A2 (D4, D1.1).** Kept rows carry a change bit from the kernel and persistent instance
  ranges; an unchanged row is neither walked nor re-encoded.
- **A3 (D2).** A plain pipeline for clip-free rectangles and glyphs with solid or image
  brushes, if G5 earns it.
- **A4 (the carriers).** One service pass per frame; inputs only mark dirty; nothing wakes at
  rest; the Mac carrier paces on `CADisplayLink`.
- **A5 (D15).** The comparison arms are the native host, GPUI and egui on the Mac, and ink's
  own wgpu arm and egui on Windows; the scoreboard in §1 is the gate for every landing of this
  program, with the targets in §1.
