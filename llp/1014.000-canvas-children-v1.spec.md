# LLP 1014.000: Canvas children v1 — laid out by the kernel, through the surface on macOS, as built

**Type:** Spec
**Status:** Draft (unreviewed; transcribes what landed 2026-08-29)
**Systems:** Kernel (`Canvas` holds children), Contract (corpus), Web host (the wrapper element), Apple host (the overlay, capture, the repaint sources), GPU module (`gpu_texture`, `gpu_wants_children`; `Surface::wants_children`/`children`), Tooling (`scripts/smoke.mjs` steps 6a and 9; `host/apple/build.mjs`)
**Author:** Claude (Fable 5) for Charlie Cheever
**Date:** 2026-08-29
**Implementer:** Claude (Fable 5); landed 2026-08-29 (this document transcribes it)
**Related:** LLP 1014 (the decisions; §2 names what this leaves undone), LLP 1009 (the canvas), LLP 1012 (the smoke and the agent API this is verified through), LLP 1008 §1 (one `NSView` per node), LLP 1007 §1 (the web host's elements)

## Summary

A `canvas` holds children. The kernel lays them out in its box (LLP 1014
D1); the web host composites them over the surface inside a wrapper element
(D2); the macOS presenter, when the surface asks, paints them into a texture
the surface samples and composites the children themselves at alpha 0 (D2,
D3), capturing again on four sources of change (D4) — with hit-testing and
accessibility still the kernel's boxes (D5). The Caltrain aurora is the first
use: three texts refracted through it. Where this document and the code
disagree, the code and its checks are the authority.

## 1. What landed

- **Kernel** — `NodeType::can_hold_children` includes `Canvas`
  (`kernel/src/node.rs`); nothing else: a `Canvas` is `display: block`, never
  measured, sized by its rows, and Taffy lays out what it holds.
  `kernel/tests/canvas.rs` holds the three facts: block children fill the
  canvas's width at its origin; a taller child overflows and never sizes it;
  a percentage child resolves against it.
- **Contract** — the lowering's `lower-leaf-children` refusal lifts with the
  predicate (no corpus reject named `canvas`). `contract/corpus/canvas.contract`
  gains children under `map` and a third canvas, `sky`, whose surface samples
  its children and which holds a button and an input — the smoke's fixture.
- **Web host** — the create op for a `Canvas` still carries `tag: "canvas"`;
  the glue makes a `<div>` for the node and puts a `<canvas data-surface>`
  inside it (`position:absolute; inset:0; z-index:-1`), the kernel's children
  after it in flow; the `children` op skips `data-surface`; the GPU glue
  resolves a canvas node's surface element through the wrapper. The host
  appends `position:relative;` (unless the author positioned the canvas) and
  `isolation:isolate;` to a canvas's CSS — the containing block and the
  stacking context that keep the surface above the canvas's background and
  below its children (`host/web/src/host.rs::host_css`;
  `host/web/tests/canvas.rs`).
- **GPU module** — `Surface::wants_children(&self) -> bool` (default
  `false`) and `Surface::children(&mut self, Option<&TextureView>)` (default
  no-op); `Module::wants_children`, `Module::texture` (an `Rgba8Unorm`
  texture, `TEXTURE_BINDING | COPY_DST`, created or replaced at a new size,
  `write_texture` in place, the canvas marked dirty); the C ABI gains
  `gpu_wants_children(id)` and `gpu_texture(id, w, h, bytes, len)`. The web
  ABI is unchanged.
- **The aurora** — `wants_children` is `true`; a texture and a sampler join
  its bind group (a 1×1 transparent texture when there are no children); the
  fragment samples the children at the fragment's uv, refracted by the warp
  field, split per channel, glowing under bright ribbons, composed
  premultiplied over the sky.
- **Apple presenter** — a canvas node's children live in a flipped overlay
  view above the `MetalView` (`NodeView.overlay`, the `container`). When the
  module creates a canvas's surface, it asks `gpu_wants_children`; a surface
  that wants them is captured (`Capture.bitmap`: `cacheDisplay` into
  premultiplied RGBA at the window's scale, the overlay painted opaque
  regardless of its alpha, `Capture.capturing` set for the duration),
  uploaded with `gpu_texture`, and the overlay composites at alpha 0 from
  then on. It captures again when: (a) a batch touched a node under it
  (`Presenter.touched`, every op but `roots` and `create`; a `children` op on
  the canvas itself) — at the end of `apply`; (b) a node view under it draws
  outside a batch (`NodeView.draw` → `repaintThrough`); (c) a scroll node
  under it scrolls (`boundsDidChangeNotification` on the clip view); (d)
  every display-link frame while the first responder is under it
  (`Canvases.editing(under:)`, which also keeps the display link running).
  (b) and (c) coalesce per run-loop turn (`scheduleCapture`) and are
  ignored on the turn a capture already ran (`paintedThisTurn`), so a batch
  never captures twice. An overlay with no subviews is never captured unless
  a texture was uploaded before (then once more, to clear it). In agent mode
  each capture writes `canvas <id>: captured WxH in N ms, uploaded K KiB in
  N ms` to stderr, which `logs` carries.
- **Build** — `host/apple/build.mjs` replaces the GPU dylib instead of
  overwriting it: rewriting a mapped, ad-hoc-signed file in place poisons the
  kernel's cached signature for that inode, and every later `dlopen` died with
  `SIGKILL (Code Signature Invalid)` (found landing this, three crash reports
  deep).
- **The app** — the aurora canvas holds a column of three texts
  (`aurora-title` is the station's name).

## 2. Deviations from LLP 1014's text

- D2 named `wants_children` as the trait's question; it is, and the module
  answers it per instance (`gpu_wants_children`) so the presenter captures
  only canvases whose surface samples — the map's overlay is never captured.
- D4's four sources are built as listed; the coalescer and the
  `paintedThisTurn` guard are the transcription of "captures coalesce per
  run-loop turn". Source (b) fires for every `NodeView.draw` under an
  overlay, which today means images finishing their load; nothing else draws
  outside a batch yet.
- The agent-mode stderr line is new: the smoke needs to see captures, and
  `logs` already carries the host's stderr.
- §2 step 3 (a screenshot fixture against a recorded reference; Chrome's
  flag as the readback oracle) is **not built** — §5.

## 3. Numbers (2026-08-29, this machine, Retina 2×, release)

- The app's aurora (760×440 px): captured in **0.55–0.59 ms**, uploaded
  (1,306 KiB) in **0.25–0.64 ms** — the probe's numbers, in the tree.
- The fixture's sky canvas while its input is edited: 26 captures over the
  smoke's ~150 ms of editing at the display link (D4 d).
- The web host is unchanged in size; the wrapper is two elements per canvas.

## 4. Checks that hold this

- `cargo test`: `kernel/tests/canvas.rs` (layout), `host/web/tests/canvas.rs`
  (the wrapper's CSS; both surfaces of the fixture publish), the corpus
  (`canvas.contract` compiles byte-identically and runs).
- `node scripts/smoke.mjs <web|macos>` — step 6a: the aurora's title is the
  station's name and its box lies inside the aurora's, on both hosts; step 9:
  the canvas fixture — the button's box inside the canvas's; a `tap` on it
  reaches it (on macOS through the alpha-0 overlay, after the first capture
  is seen in `logs`); `type` reaches the input; on macOS at least three
  captures (the first, the tap's batch, the edit).
- The five checks, green on the tree this landed in.

## 5. Not in v1 (and where each is declared)

Transforms and per-child textures (LLP 1014 D5); nested canvases and text
selection inside a canvas (1014 "not decided"); the screenshot fixture and
Chrome's flag as the readback oracle (1014 §2 step 3); the web host painting
children *through* a surface (1014 D2: the browser's, when a browser ships
it); the `gpu_render` tail and the accessibility role of children under a
canvas (1014 §4); zero-copy capture (1014 D3).
