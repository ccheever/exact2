# LLP 1091.001 — Windows package staging without symlink privilege

**Status:** superseded by original-source compilation on origin/main, 2026-10-06.

The October 6 rebase removes this plan's staging helper: upstream now compiles
Contract at the app's original path and checks source/package bytes around the
compile. No package links need to be created by the producer. Keep the Windows
integration test for scoped/unscoped aliases, Unicode paths, source-map identity
and unchanged inputs; delete the obsolete staging-helper tests. The implementation
and measurements below describe the October 5 state.
**Implementer:** Codex, 2026-10-05.
**Authority:** Charlie's Windows port and papercut work, including an LLP before
engine changes; the lead requested this bounded completion of LLP 1091 D10 and
its round-3 package identity fix. No new runtime feature or blocking check.

## Problem and evidence

At `1c39a7937`, `js/bake/src/lib.rs::link_packages` links each imported Contract
package into the producer's private stage. The Windows branch calls
`std::os::windows::fs::symlink_dir`. This machine lacks that privilege and has
Developer Mode disabled. A native CLI containing the unchanged production
helper fails with OS error 1314; the package's original bytes remain intact.
An app without imported packages does not hit this branch.

The ignored reproduction is
`target/windows-package-link-probe-858f16d63546446ca9c3e7807a863e6a/`.
`evidence.json` binds the copied production helper; `before.log` records 1314.
This isolates staging; it is not a successful full producer bake.

Bun 1.4.2's native directory junction succeeds for an existing package path
containing spaces, `#`, accented text and CJK. A raw canonical `\\?\` target
is a separate papercut: Bun creates an unreadable junction. Resolving the target
with `realpathSync.native` first gives the ordinary absolute path and works.
`candidate-normalized-aliases-r3.log` proves a scoped and an unscoped alias have
the original canonical identity and bytes. `after-junction-rebuild.log` proves
the current Rust stage cleanup removes those aliases without deleting the
package. Earlier probe logs are retained, including an initially malformed
prefix fixture and the correctly formed canonical-prefix failure.

Do not return to copying package files: LLP 1091 round 3 fixed split identities,
linked exports, relative imports, hidden directories, and two names for one root.

## Decisions

1. Keep a link to the compiler-resolved package directory. On Windows create a
   directory junction through the producer's existing pinned Bun support;
   `exact_bake::bun()` already honors `BUN` and names a missing installation.
   Other platforms retain their existing directory symlink operation. No admin
   setting, PowerShell/CMD shell, new native library, or runtime dependency.
2. Windows staging launches at most one Bun child when packages are nonempty.
   Send the list over stdin, so a large graph does not encounter Windows' command
   line limit. Paths are UTF-16 code-unit arrays in JSON, decoded losslessly to
   JS strings; do not use a lossy Rust path-to-string conversion. No path is
   interpolated into JavaScript or shell text.
3. The small constant program canonicalizes each existing target with
   `realpathSync.native` before `symlinkSync(target, link, 'junction')`. It also
   normalizes each already-created link parent before joining its final name,
   covering Rust's canonical stage paths. A filesystem refusal names the link
   and original error; there is no copy fallback or privilege prompt.
4. Keep the current ownership boundary: `link_packages` only clears the private
   stage's `node_modules`; all link parents are inside that stage, and package
   roots remain read-only. Names come from the compiler's admitted package graph.
   Do not add a second resolver, package registry, manifest or capture algorithm.
5. Always close stdin and reap the Bun child, including a failed input write or
   child failure. Propagate spawn/write/wait/status errors; never publish a
   partially staged bake. A subsequent call rebuilds the stage as it does today.
6. No-package bakes keep the existing cleanup and launch no additional process.
   The ordinary producer still performs the capture comparison, compiles and
   bakes through the real lean VM, and produces its existing receipt/source map.
   The runtime boot graph and shipped binary remain unchanged.

This is local Windows directory staging. No network-share authentication,
Chrome, browser, GPU, or native UI process is needed or authorized for these
checks. Remote-share junction behavior is not claimed from the local fixture;
an unsupported filesystem reports its actual refusal.

## Implementation

Factor the small platform link operation beside `link_packages`, keeping cleanup
and parent creation in that function. The Windows helper gathers target/link
UTF-16 paths and runs the constant Bun program once. Use the existing
`exact_bake::bun_error` diagnostic on spawn failure. Drop the piped stdin before
waiting; retain the input-write result until the child has been reaped.

Add the Windows filesystem cases to the existing bake test surface. Add one
actual imported-package case to `js/bake/tests/producer.rs`; avoid a new runner,
CLI or permanent benchmark. The independent `witness_svg` cfg hygiene fix is
separate and has already passed the strict native host Clippy gate.

- Real Windows helper tests use canonical extended paths, spaces, `#`, Unicode,

- Restage from root A to root B, then remove all packages. Old aliases must go

- Run the existing bake source/capture and producer suites with real Hermes.
  Inspect their entrypoints first; no browser execution. Run strict Clippy and

- Record the bounded staging cost and confirm zero children for zero packages,
  one for several packages. No separate performance harness or blocking gate.

## Risks and alternatives

Bun's canonical-target quirk makes path normalization part of this change, not
an optional cleanup. Tests must include the exact extended-path form Rust emits.
Canonicalization does not freeze a concurrently replaced package; this change
keeps the existing compiler graph/capture ownership rather than claiming a new
filesystem security boundary. A root disappearing during staging is a refusal.

Calling Bun once per package would avoid stdin plumbing but multiply process
cost. Passing all paths as command arguments hits the same Windows size limit
already seen in `cargo fmt`. A copied mirror regresses the accepted identity
semantics. A new Win32 reparse-point implementation or dependency would add
unsafe/platform machinery to duplicate the build tool already in use.
