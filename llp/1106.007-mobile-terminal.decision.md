## Native renderer

[decided] Include the pinned GhosttyKit.xcframework device and simulator slices byte-for-byte under mobile/modules/apple. GHOSTTY-VERSION pins cf8edc23f3a6a87a96e41a90013e89e987d34980; GHOSTTY-NOTICES.md preserves the pinned upstream notices and LICENSE-GHOSTTY preserves the MIT license. Adapt only the Expo owner and event callbacks of the pinned T3TerminalView into T3MobileTerminalSurface. It retains the upstream UIKit text input, hardware key commands, pan scrolling, visible-text capture, Ghostty buffer/configuration and Metal surface code.

[observed] The pinned podspec names IOSurface, Metal, MetalKit, QuartzCore and UIKit frameworks, plus c++ and z libraries. The future mobile manifest must include these links. The surface's isolated arm64 iOS18 simulator Swift typecheck passes. This does not prove linking, native startup or rendering.

## Stream ownership

[decided] App-local T3MobileTerminalSessions and T3MobileTerminalOutput include the existing887b249 desktop session/buffer implementation with mobile type names. They use the existing T3Transport terminal attach/write/resize/detach protocol. Output stays native, acknowledgements occur after buffering, retained sessions replay their bounded buffer and resize uses the existing latest-wins queue.

[decided] The mobile adaptation gates attachment by the actual connected environment descriptor. Read-only attachment sends only threadId and terminalId; operating attachment includes the actual workspace/grid/environment. Permission checks come from the real auth session. Retained sessions from a previous focused environment are discarded before reconnect. The view queues writes in source-faithful65536 UTF16-unit chunks without splitting surrogate pairs and owns one-shot modifiers and explicit clipboard paste on the main thread. No synthetic terminal output is generated.

[observed] The parent subsequently typechecked all mobile Swift sources together with the actual Ghostty headers on the first integrated terminal attempt. Reconnect/replay tests and device keyboard behavior remain outstanding. The source is unregistered and is not an active route.

## Root seam

[observed] terminal-mobile.ts exposes mobileTerminalPrepare(requestedId,scheme,palette,fontSize,now,native,client) and mobileTerminalAction(action,terminalId,value,native,files,client). Preparation reads real permissions and shared terminal metadata, then returns a strict snapshot plus a credential-free terminal-source JSON. Actions use real terminal RPCs or the app-owned mobileTerminalControl bridge. New/close update shared UI ownership only after RPC success. Persistence uses the existing native file seam.

[observed] Snapshot fields are revision, environmentId, threadId, terminalId, sessionKey, title, subtitle, ready, readOnly, sourceJSON, error, emptyTitle, emptyDetail, tabs, hostPlatform and colors. Native change events identify their session key and carry status, error, modifier or captured visible text; output bytes never enter the TypeScript inbox.
