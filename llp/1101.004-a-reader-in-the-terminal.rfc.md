## Summary

The second terminal app after the harness is a reader for an LLP corpus,
full screen, over the windowed reader's own data module. It renders
Markdown in cells, finds in the page, and shows the corpus as a tree, the
outline and the links as overlays. Building it found twelve places where
writing it cost more than it should. Nine were gaps in the platform and are
fixed here (§2). Three were the web being the web, and are pitfalls instead
(§3).

Every fix follows the web where the web has an answer: `Element.scrollBy`,
`KeyboardEvent`'s Shift, a click on an `a` or a `span`'s `onclick`. Each has
a test that fails with the fix undone.

## 1. The reader

- **The binary:** `cargo build --profile host-dev -p llp-terminal`, then
  `./target/host-dev/llp [corpus-or-document]`. With no path it opens the
  nearest `llp/` above the working directory.
- **The data:** two sources join `apps/llp/data`, and the windowed readers
  are untouched. `start()` is the path the binary was given. `page(path,
  find)` is the open document as a terminal draws it:
  - every run split where `find` matches, each match numbered, and the block
    each match is in (`marks`), for `scrollIntoView`;
  - the page's links as a list, a corpus document's title beside it;
  - the documents before and after it in number order;
  - an LLP's metadata header (`**Type:** … **Status:** …`, one paragraph in
    Markdown) as one labelled row per field;
  - each table column weighted by its widest cell, so columns line up.
- **The screen** (`apps/llp/terminal.contract`): the keys are a status line
  of buttons, each with `aria-keyshortcuts`, so every key is also a click.

| Key | Does |
|---|---|
| arrows, `j` `k`, Space, Page Up/Down, Home/End | scroll |
| `g` `G` | top, end |
| `t` | the tree of documents; `/` in it filters by any text |
| `o` | the outline |
| `/`, `n` `N`, Esc | find in the page, walk the matches, drop them |
| `l` | the links |
| `[` `]` | the documents before and after |
| `b` | back |
| click a cross-reference | opens it |
| `q` | quits |

- **Measured** (`llp/1041`, 600 KB, `host-dev`, an unloaded M-series Mac):
  the first layout is 78 ms; a find keystroke lays out again in about 35 ms.
  Scrolling lays out nothing. Numbers taken at a load average of 300–500 were
  60–200 times worse, and are not the reader's.

## 2. What it asked of the platform

| # | Friction | Fix |
|---|---|---|
| R1 | `scrollIntoView` was Contract's but not the terminal's. | The terminal host aligns an element by `block` (`start`, `center`, `end`, `nearest`) in every scroller above it. |
| R2 | With nothing focused, the arrows moved the focus and nothing scrolled. | With nothing focused, the arrows, Space, Home and End scroll the first presented scroller, as a page's keys do on the web. With a control focused, the arrows still move among controls (LLP 1101 D6). |
| R3 | An app could not scroll by a line (`j`, `k`). | `scrollBy(id, x, y)`, the web's `Element.scrollBy`, in pixels (a terminal row is 16). Typed, and taken by the terminal, Linux and the web's JS target. Apple and the wasm web host do not take it yet; they lag a row (LLP 1023 D10). |
| R4 | A shortcut took the focus, so the arrows stopped scrolling after one. | A key shortcut presses its button without moving the focus. A click still focuses. |
| R5 | `n` and `N` were one shortcut. | A typed capital is `Shift+N`, as the web's `KeyboardEvent` has it, and shortcuts match modifiers exactly, as the web host already did. |
| R6 | A link in the text could not be clicked. | The terminal hit-tests inline runs. A run's `press` runs; otherwise its `href` is followed by LLP 1038 §7's rule: a route is `navigate` on the navigation root, and an `http`, `https`, `mailto` or `tel` URL leaves the app. `openURL` is taken too: the interactive loop hands URLs to `open` or `xdg-open`, and headless the driver reports them. The agent's `tree` lists a run with a `testId`, and `tap` clicks it. |
| R7 | A source that answered `Later` never answered: the terminal ran no requests. | The terminal host runs a data module's continuations on a thread and fulfills them through the loop's wake (LLP 1016 D2, LLP 1027.002 D3). Any other request is refused with a reason; the terminal has no network executor. |
| R8 | `indexOf(map(…), true)` was found by trial. | `findIndex` stays refused (LLP 1017.003; it would also need the Lean semantics). The refusal now names the composition for `findIndex`, `find`, `some` and `every`. |
| R9 | A test could not compile source text with the terminal profile. | `contract::compile_terminal(src)`. |

## 3. What was the web, not a bug

- **A button in a block container shrinks to fit.** A `button` is
  `inline-block`, so in a `scroll` a row's `flex-grow` title did not grow.
  This is what a browser does. The fix is `width="100%"` or a `column`, and it
  is a pitfall now.
- **`box-sizing` is `content-box`.** A `width="100%"` column with padding
  overflowed into the scrollbar's column. This is the web's default; the
  pitfalls already had it twice.
- **A `display="none"` button's shortcut never fires**, on the web too. It is
  a pitfall, with the `Shift+N` rule beside it.

## 4. Not done

- Find does not match across a run boundary (half of a match bold).
- `findIndex` and its siblings, as above.
- `scrollBy` on Apple and in the wasm web host.
- A route-based reader. Routes keep every visited screen mounted, which for
  600 KB documents is the wrong trade; the reader keeps its own history for
  `b`.
