## Summary

No host reports what assistive technology is actually given. Three hosts attach
an `accessibleName` to `tree`, and each computes it from props:
- web: `glue.js:1063`, `web-js/agent.js:45`;
- Apple: `Accessibility.swift:26`, `:211-237`;
- Linux: `agent.rs:524-548`.

None of them reads back what the platform holds after the host's own projections
are done. Those projections include swipe cells, text elements, native controls
and modal layers. The browser computes an accessibility tree for every page, and
nothing reads it.

This RFC adds **a form of `tree`**: `tree --ax`, wire `{"op":"tree","ax":true}`.
It returns the elements the platform exposes, each with:
- the platform's role, name, value, description and states;
- a frame where the platform has one;
- the Exact view it belongs to, found through ownership.

It also returns the host's intent facts for those views, and the findings
computed from both. The sources:
- web: Chrome's computed tree;
- iOS: UIKit's accessibility properties;
- macOS: AppKit's tree in navigation order;
- Linux: `unavailable`.

The reply makes no claims about VoiceOver's reading order. Parity against the
web joins by `testId` on a fixture of named controls.

## 1. Motivation — what the reads carry today

- **Names are computed, never read back.**
  - iOS assigns `accessibilityLabel` from props on every node
    (`NodeViewIOS.swift:1043`), on custom buttons (`Accessibility.swift:88-96`),
    and on native controls (`ControlsIOS.swift:133`).
  - The swipe projection then replaces what UIKit exposes with a cell
    (`SwipeActionsIOS.swift:263-269`). An interactive paragraph exposes its
    whole text plus one element per run (`TextInteraction.swift:58-82`).
  - No read reports the result of those steps. The swipe cells' missing names
    (LLP 1008) were found with a one-off script.
- **Exposure is unread.**
  - iOS's `tree` reports `accessibilityHidden` only for placed views. It
    reports nothing about `accessibilityElementsHidden`
    (`NodeViewIOS.swift:209-214`) or about the modal layer's hidden background
    (`ModalIOS.swift:242`).
- **The oracle is unused.**
  - `Accessibility.getFullAXTree` is available on the pipe the web carrier
    already holds (`agent.mjs:162`).
  - DEFERRED line 81 leaves the JS target's accessibility props open. Nothing
    shows how far the JS target's DOM and the wasm target's DOM disagree for
    an assistive technology.
- **Linux claims what it does not expose.** LLP 1015 §7 excludes accessibility
  on Linux, yet its `tree` carries `accessibleName`.

## 2. Decisions

### D1 — A form of `tree`

Wire: `{"op":"tree","ax":true[,"target":V|"testId"][,"limit":N][,"excluded":true]}`.
CLI: `tree --ax [<target>]`. Library: `tree(target, {ax: true})`.

Why `tree`:
- The accessibility tree covers the same views.
- `tree` already carries the guesses that this form replaces (D9).
- `layout` explains one node in Exact's own geometry, and `state` is app and
  host state. Neither has a place for a second tree.

Request rules:
- `shallow` together with `ax` is refused.
- A stale target is refused as LLP 1035.002 D3 refuses one.
- The reply carries the runner's tags and `ax{}`. It has no `nodes[]`.

### D2 — Per-host source, coverage and order

| host | source | order | not observable (capability table) |
|---|---|---|---|
| web (Chrome carrier) | `Accessibility.getFullAXTree` for the main frame. Unignored nodes are kept with Chrome's role, name, `nameFrom`, value, description and properties exactly as given. Traversal is depth-first from the root through `childIds`. An ignored node is dropped and its children promoted into its place. `InlineTextBox` is dropped. | `"tree"`: Chrome's AX tree order | — |
| iOS | UIKit's public properties on each object walked: `isAccessibilityElement`, `accessibilityLabel`, `Value`, `Hint`, `Traits`, `Identifier`, `Frame`, `CustomActions`, `accessibilityRespondsToUserInteraction`, `accessibilityViewIsModal`, `accessibilityElementsHidden`. Children are `accessibilityElements` (or `accessibilityElementCount`/`accessibilityElement(at:)`) when the object declares them, else its subviews. The walk does not descend into an element. A subtree is excluded only by documented properties: `isHidden` and `accessibilityElementsHidden`. `excluded: true` lists those elements too, with the reason. | `"containment"`: declaration order, then subview order. **Not a reading order.** | reading order; heading level; `description` beyond the hint; exclusion by alpha (an alpha-0 view is over-reported, and the reply says so in `coverage.limits`) |

### D3 — Roots: the session's own surfaces

- **iOS.** The roots are:
  - the session's `ExactView`;
  - the view of each controller in the session's modal layers
    (`ModalIOS.swift`, `layers`), which holds the viewport while presented
    (`:265`);
  - the navigation bar and toolbar of the session's own navigation controller,
    as chrome.
- **macOS.** The roots are the session's view, a sheet attached to its window
  by this session, and toolbar items the session owns (`ToolbarMac.swift`). It
  walks the session's own window, never `NSApp.keyWindow`.
- **Session boundaries.** The walk stops at any `ExactView` (or macOS session
  view) that belongs to another session. An unmounted session replies
  `{"unavailable": true, "reason": "unmounted"}`.

### D4 — The web read: one bracketed, batched pass

1. **One `Runtime.evaluate`** calls `exact.axStamp()`, which is in `glue.js`'s
   agent mode and in `web-js/agent.js`. It:
   - returns the tags and the document nonce (`performance.timeOrigin`);
   - writes `data-agent-view=<id>` onto every live view, using the ids that the
     plain `tree` walk assigns. The JS target's ids are lazy and per page
     (`rt.js:607`), so the stamp and `tree` must share them.

   The write is idempotent. The page's attribute observers filter on other
   names (`gpu-glue.js:508`, `native-glue.js:118`), and `markup-editor.js:116`
   does not watch attributes.
2. **`Accessibility.getFullAXTree`.**
3. **`DOMSnapshot.captureSnapshot({computedStyles: [], includeDOMRects: true})`.**
   This gives, for each `backendNodeId`, the node's attributes (the stamp) and
   its layout bounds. Bounds move into viewport points by subtracting the
   snapshot's scroll offset.
4. **`exact.axStamp()` again**, comparing tags and nonce.
   - If they differ, or a joined node is gone, the read retries, at most twice.
   - After that it replies with the last result and `spanned: true` (LLP
     1035.002 D3).
   - Navigation changes the nonce, which forces the retry.

`Accessibility` is enabled at the first `ax` read, never at launch. Iframe
guests are `coverage.excluded: [{"frame": url, "reason": "frame-scoped AX tree;
the carrier attaches one page target"}]`.

### D5 — Joining an element to its view

Each element's view is found by the first of these rules that applies:

1. **`via: "self"`.** The element is a `NodeView`, or on the web its DOM node
   carries `data-agent-view`.
2. **`via: "owner"`.** The element belongs to a view by declaration:
   - a swipe cell, through its `control` (`SwipeActionsIOS.swift:263`);
   - an inline run's element, through its `id` (`TextInteraction.swift:116`);
   - a segment, through the tab it was made from;
   - a native control, through its `NodeView` owner;
   - on the web, a text node, through its parent element's stamp.

   On Apple this is a small internal protocol, `AgentOwned { var agentViewId:
   UInt32 }`, adopted by those four classes.
3. **`via: "ancestor"`.** The nearest view above the element, reported as such.
4. **`id: null`, `via: "none"`.** Chrome or a guest, with `native.class`
   naming the platform class, for example a `UINavigationBar` button.

`native.identifier` is reported when the platform's `accessibilityIdentifier`
differs from the joined view's `testId`.

### D6 — Normalization, capabilities and parity

Raw facts are always kept in `native`. Normalization is defined only for the
fixture's control kinds:

| fixture control | web (Chrome) | iOS | macOS |
|---|---|---|---|
| button | role `button` | trait `button` → `button` | `AXButton` → `button` |
| link | `link` | trait `link` → `link` | `AXLink` → `link` |
| heading (`aria-level` 2) | `heading`, `level` 2 | trait `header` → `heading`; level not observable | `AXHeading`, value 2 → `heading`, `level` 2 (`TextInteraction.swift:44-49`) |
| text field | `textbox` | `UITextField`/`UITextView` → `textbox` | `AXTextField`/`AXTextArea` → `textbox` |
| checkbox (`Control`) | `checkbox`, `checked` | trait `button` + value `"checked"`/`"unchecked"` (`ControlsIOS.swift:30-34`) → `checkbox`, `checked` | `AXCheckBox` → `checkbox`, `checked` |

Any other platform role passes through unmapped (for example `adjustable` and
`toggleButton` on iOS).

The name is the platform's own name:
- web: Chrome's computed `name`;
- iOS: `accessibilityLabel`;
- macOS: the label, else the title.

Values are strings, exactly as the platform reports them. `mixed` and
`pressed` are not normalized in r2.

**Parity** (`axParity(web, other)`):
- Elements are joined by their view's `testId`, and only where that `testId` is
  unique on both sides. Duplicates and unmatched elements are listed as
  `unjoined`, never compared.
- For each joined pair it compares the normalized role, the trimmed name, and
  each state that both hosts' capability tables say they can observe. A state
  one side can observe and does not report is a `missing` finding.
- There is no order parity and no text grouping.
- If either side is truncated or `spanned`, parity refuses.

`axParity` gates only the fixture test. On an app it is a library call whose
result is informational.

### D7 — Reply, findings, targeting and bounds

```
{ epoch, incarnation, clock, spanned?,
  ax: {
    source: "chrome-cdp" | "uikit" | "appkit", platform: "Chrome 153.0…" | "iOS 27.1" | "macOS 27.0",
    order: "tree" | "containment" | "navigation",
    coverage: { roots: [ … ], complete: bool, visited: N, excluded?: [ {frame|root, reason} ], limits?: [ "alpha" … ] },
    modal: { present: bool, element?: i, id?: V | null, by: "dialog:modal" | "accessibilityViewIsModal" | "sheet" },
    elements: [ { i, parent: i | null, id: V | null, via, testId?,
                  role, name, nameFrom?, value?, description?,
                  states: { disabled?, selected?, checked?, expanded?, focused?, busy?, level?, protected? },
                  interactive: bool,             — an interactive role (D8), or UIKit's respondsToUserInteraction
                  frame?: { x, y, w, h, source: "element" | "layout" },
                  excluded?: [ "hidden" | "elementsHidden" ],   — only with "excluded": true
                  actions?: [ … ], native: { role, class?, identifier?, ordered? } } ],
    intent: { "<V>": { inert?, ariaHidden?, modal?, dialog?, handlers? } },   — every joined id and its ancestors
    ancestors?: [ { id, role, name } ],          — a targeted read: the exposed chain above the target, outermost first
    findings: [ { kind, i, id, testId?, detail } ],
    truncated?: { elements: N | "unknown", fields: N } } }
```

- **`intent`** is the host's own reading of its props.
  - The runner supplies it on the Rust hosts.
  - On the JS target, `agent.js`'s `PROPS` (`agent.js:10`) gains `inert`,
    `aria-hidden` and `aria-modal`, and `dialog` is read from the element.
  - `modal` comes from the platform, not from intent.
- **Targeting.** A targeted read walks the session as usual, within the
  budgets. It returns:
  - the elements whose joined `id` is in the target's runner subtree;
  - `ancestors`;
  - `intent` for the target's ancestors, so that an inert ancestor is visible.
- **Bounds.**
  - `limit` must be an integer from 1 to 2000 (default 500); anything else is
    refused.
  - The native walk visits at most `5 × limit` objects at depth ≤ 64. It
    tracks visited objects, so a cycle in `accessibilityElements` is cut and
    counted.
  - `name`, `value`, `description`, `identifier` and each action are cut at
    200 characters. `actions` keeps at most 16 entries. The reply is at most
    256 KB.
  - Each cut adds to `truncated.fields`.
  - When a walk stops early, `truncated.elements` is `"unknown"`. On the web,
    where the whole list is in hand, it is a count.
  - The web's `getFullAXTree` and snapshot cost is Chrome's, bounded by the
    page. Only the output is bounded.
- **Protected values.** A secure field's value is omitted on every host and
  `states.protected` is set:
  - web: the joined element is `input[type=password]`;
  - iOS: `isSecureTextEntry`;
  - macOS: subrole `AXSecureTextField`.

  Nothing reads the editor instead.

### D8 — Findings

`axFindings(reply)` runs in the driver over the reply alone. It produces four
kinds of finding:

- **`unnamed`.** An exposed element with an empty trimmed name that either has
  an interactive role or is `interactive` per UIKit. The interactive roles are
  button, link, textbox, searchbox, checkbox, switch, slider, tab, menuitem,
  combobox and option.
- **`exposed-hidden`.** An exposed element whose `id`, or an ancestor's id in
  `intent`, is `inert` or `ariaHidden`.
- **`outside-modal`.** While `modal.present`, an exposed element that is not
  inside the modal element and is not `via: "none"` chrome.
  - iOS applies UIKit's documented rule: `accessibilityViewIsModal` hides only
    the modal view's siblings. Elements outside those sibling subtrees are
    flagged, because they leak.
  - The finding carries `basis: "documented-rule"` on iOS and
    `basis: "platform"` on the web, where Chrome itself excludes them.
- **`parity`** (D6). Only when two replies are compared.

There are no other rules (D10).

**A clean read requires coverage.** "No findings" counts as clean only when all
of these hold:
- `coverage.complete` is true and nothing is truncated or `spanned`;
- every element the caller expects is present and joined `self` or `owner`.

`renderAx` prints `(no findings — coverage incomplete)` otherwise.

## 3. Stages, proofs, and where each runs

The fixture, `contract/corpus/accessibility.contract`, gains these nodes:
- an icon-only `button testId="unnamed"`;
- a `column inert=true testId="inert-box"` holding a button;
- a `column role="img" aria-label="Chart" testId="chart"` holding a focusable
  button;
- a link, an `aria-level=2` heading and a `Control` checkbox;
- a `textinput type="password" testId="secret"`;
- a `name-it` button that gives `unnamed` an `aria-label`.

It builds `--wasm`, as the smoke's fixtures do.

1. **Web and Linux.**
   - Work: D1–D9 on the web, Linux `unavailable`, and the deletions.
   - **`host/web/tests/accessibility-tree.test.mjs`**, added to `async.mjs`'s
     `web-build-test` step (it compiles the fixture). On the wasm and the JS
     target it checks:
     - **coverage:** every fixture control is present, joined `self` or
       `owner`, with the expected role and name. The number of collected
       elements equals the number of Chrome's unignored nodes outside the
       dropped kinds. `chart`'s focusable button is present whenever Chrome
       exposes it;
     - **`unnamed`** fires exactly once, then is absent after `tap name-it`;
     - **a negative through the collector, wasm page:** removing the DOM `inert`
       attribute from `inert-box` makes `exposed-hidden` fire, because intent
       still says inert. Restoring it makes the finding go;
     - **protected values:** after `type secret hunter2`, `secret` has no
       `value`;
     - **spanning:** a reload between brackets yields a retry, then `spanned`;
     - **parity:** wasm against JS by `testId` over the fixture controls has no
       findings. Any JS-target gap from DEFERRED line 81 is fixed or listed as

     - **Caltrain:** launch, then the stations screen (`tap change-station`).

### 7.1 Round 1 of Astra's code review (2026-10-03)

The review is `llp/reviews/code-2026-10-03-1080.002-ax-tree.astra.md`; its
Disposition section has one line per finding. What changed in the design:

- **The web read brackets the plain tree too.** The order is: stamp, plain
  tree, AX tree, snapshot, stamp. All of it is one document nonce, retried
  whole. A native read checks the plain tree before and after its `ax` read.
- **Findings are judged on everything collected, then the target scopes.**
  The reply is then cut to 256 KB of serialized UTF-8. Its intent and
  findings are rebuilt from the elements it keeps.
- **A web depth cutoff is incomplete coverage** with an unknown remainder.
- **Parity distinguishes states.** A state that applies to the role and that
  one side can observe but does not report is a `missing` finding.
  `disabled` is reported only when true on every source, so its absence
  agrees.
- **AppKit's walk reads every accessibility participant.** A view or an
  element answers through its typed accessors. Anything else (a control's
  cell, AppKit's own parts) answers through the attribute protocol, and a
  cell joins its control's view.
  - r1's "absent from AppKit's tree" for the checkbox, the password field and
    Caltrain's search field was the collector's own omission, not AppKit's.
    Read correctly, the search field is `textbox "Search stations"` (named by
    its placeholder, the last of AppKit's name sources).
  - The secure-field test is restored and passes.
- **Modal.**
  - **macOS:** a session's attached sheet is the modal (`by: "sheet"`), and
    the window behind it is judged against it.
  - **iOS, a session-owned modal view:** UIKit's sibling rule now removes
    the siblings (`excluded: modalSibling`, listed only with
    `excluded: true`).
  - **iOS, a modal view UIKit owns (a presentation's dimming view):** it is
    reported, the rule is not guessed, and coverage says so.
- **The wire.**
  - The native host validates `limit`, `excluded` and `shallow`, and refuses
    a stale `target`. It scopes a targeted read with its `ancestors`.
  - The driver still reads the whole session and scopes the target itself,
    so its findings see the whole tree.
- **Bounded enumeration.** UIKit's and AppKit's children are taken no further
  than the visits left. A reported count past them stops the walk, with an
  unknown remainder. Native producers also stop emitting at 240 KB of
  element JSON.
- **Narrowed rather than built.**
  - **Segments:** a projected segment or tab bar item joins its tablist
    (`coverage.limits: "segments"`), not its tab.
  - **macOS toolbar:** a window toolbar the session projected is not walked.
    Coverage is incomplete and names it.

### 7.2 Round 2 of Astra's code review (2026-10-03)

The review is `llp/reviews/code-2026-10-03-1080.002-ax-tree-r2.astra.md`;
its Disposition has one line per finding. What changed:

- **A macOS sheet is the session's only when it holds the session's views.**
  Otherwise it is not walked, and coverage is incomplete. This includes a
  session's own alert sheet that holds no Exact views.
- **A native `target` is resolved through the runner's logical tree,**
  inline runs included. The reply keeps the elements joined to that subtree's
  ids, so a projected control stays with its view.
- **`expanded` is collected and compared.**
  - UIKit reports true, false or nothing, from `accessibilityExpandedStatus`.
  - AppKit's accessor cannot tell false from unsupported, so AppKit reports
    it only when true, and parity reads that side as true-only.
- **Metadata is bounded too.**
  - At most 8 guest frames are named, each URL is cut at 200 characters, and
    the rest are counted.
  - The 256 KB limit is measured with the truncation fields included.
  - When the metadata alone is over the limit, it gives way, counted.

### 7.3 Round 3 of Astra's code review (2026-10-03)

The review is `llp/reviews/code-2026-10-03-1080.002-ax-tree-r3.astra.md`.

- **The host resolves a target, inside the bracket.** The driver sends its
  ordinary `tree <target>` request, so the runner picks, preferring the
  active route's view. The reply is then scoped by the resolved id.
- **Ancestry is unbounded.** Subtree membership, intent and the
  hidden-ancestor walk follow the logical tree to its root.
- **The native reply is bounded at the boundary.**
  - Each candidate is budgeted before it is appended, and `testId` is cut like
    every other string.
  - The whole reply is held to 256 KB, and every cut is counted.
- **`ax.observes` names the states a runtime can observe.** UIKit's
  `expanded` needs iOS 18. Parity skips what a side cannot observe.
