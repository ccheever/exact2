**Status:** Draft r2 (r1 reviewed once for direction by two families, 2026-09-30: `llp/reviews/1012.001.000-r1.{astra,grok}.md`, both RIGHT WITH CHANGES. r2 folds their corrections to F3, F4 and F6, and adds F9 from the implementation)

**Related:** LLP 1012 (the nine operations), LLP 1012.000 (attached sessions), LLP 1035.002 (result inspection, the source map D6), LLP 1071 (the JS target), `rules/DEFERRED.md` §Agent API; the proposal is LLP 1012.001.000

## Summary

Charlie asked (2026-09-30) whether everything exact2 does is inspectable,
scriptable and verifiable by an agent: screenshots, video, the UI hierarchy,
and what to add or take away. Caltrain was driven on web, macOS and headless
Linux with `scripts/agent.mjs` at `c1ea6eb3c`; iOS was not driven. The runtime
surface is strong: hierarchy, state, the journal, per-node style provenance,
screenshots and a seekable clock work on all three hosts, at about one second of
wall time per invocation. The weaknesses are around that surface:

- the driver runs **stale builds without saying so**;
- **video** does not exist, although the clock already makes it cheap;
- the hosts answer the same question differently, and the JS target's
  `layout <node>` has lost its authored rows;
- the agent API's own JavaScript tests fail on main, outside every gate.

## Findings

### F1 — Stale builds are driven silently (high)

`openStdio` checks only that the Linux or macOS binary **exists**
(`scripts/agent.mjs:457`). The web carrier's `builtAppMatches`
(`host/web/serve.mjs:521`) checks that `dist/` is intact and names the app. It
does not check that the build is current. The first drives of this review ran a
Linux binary from 2026-09-26 and a wasm-target `dist/` from 2026-09-28 against a
2026-09-30 tree. Nothing warned. The staleness surfaced only when `--plan` met
the old binary and the host answered `FormatDigestMismatch`. After rebuilding,
the web tree changed: `station-search`'s handler went from `change` to `input`.
An agent verifying a change this way gets a false pass or a false failure
without knowing which.

Each build already knows its inputs, in three different ways:

- the Linux binary has Cargo's dep-info (`target/release/caltrain-linux.d`,
  581 paths, including `apps/caltrain/app.contract` and the compiler's sources);
- the macOS bundle has a receipt whose `build.binary.inputs` carries 3,540
  inputs by sha256 (Rust and Swift). `pendingBuildInputs` (`scripts/app.mjs:1051`)
  checks them all in 147 ms. The receipt does **not** name `app.contract`,
  whose plan is baked in;
- the JS-target `dist/` names no inputs.

### F2 — No video, although the clock makes it exact (medium)

No carrier records motion. Under agent mode nothing moves between two
operations, so a video is just `screenshot`, `clock +N`, `screenshot`, … On
macOS, `contract/corpus/motion.contract` stepped 30 ms per frame gave ten
distinct frames in about one second of wall time, the spring's overshoot
included (109.24 × 109.24 at its peak). What is missing is the loop and an
output. `rules/DEFERRED.md` refuses "session record/replay". A picture of the
clock is not a replay of a session.

An agent cannot watch an animated image; it reads stills. So the useful form for
an agent is a **contact sheet** (frames in a grid). The useful form for a person
is an animated PNG. `scripts/png.mjs` already decodes and encodes PNG with no
dependency, and ffmpeg is not installed here.

### F3 — The JS target's `layout <node>` lost its authored rows (high)

On the web build that ships today (the JS target, LLP 1071), `layout <node>`
lists only the twelve inherited text rows, all as `(initial)`, with the
browser's computed values. Padding, border and display are absent. Linux and
macOS list every authored row for the same node.

The cause is in `host/web-js/agent.js` `declared()`. It matches rules whose
`selectorText === '.' + class`. The JS target emits its classes nested inside a
specificity wrapper, `#exact-root#exact-root { & .c22 { … } }`
(`host/web-js/src/emit.rs`), so no top-level rule ever matches. The web is the
dev loop and the parity oracle, and its inspection is currently the weakest of
the three.

The same top-level test is in `host/web-js/flow.js` `classHeight`, which decides
whether a paragraph's height is definite for text around shapes (Grok's review).
There it is a runtime bug, not only an inspection bug. It is latent in Textflow,
whose prose height is a binding (an inline style): the app renders identically
before and after the fix.

### F4 — The hosts answer the same question differently (medium)

- **Linux ignores `tree`'s target.** `accessibility_tree` asks the runner for
  `{"op":"tree"}` rather than forwarding the request, so it drops the target
  and `shallow` (`host/linux/src/agent.rs:147`, `:421`). `tree station-search`
  answered 46 nodes on Linux and 1 on web and macOS. `queue/` recorded this
  2026-09-23.
- **Row vocabulary differs.** The JS target reports the browser's computed
  strings (`font_size = 16px`, `text_color = rgb(0, 0, 0)`,
  `font_family = system-ui, sans-serif`). The runner reports its own rows
  (`16`, `#000000`, and `font_family = 0`, an index where a name belongs).
- **Default viewports differ.** Web is 420×900 (`openWeb`'s default); the
  native carriers are 420×860.
- **The JS target has no `site` or `instance`**, so node → source cannot attach
  there even with a map.
- **The JS target numbers views differently.** Caltrain's root is `View#2`
  over `Canvas#1` on the page and `View#1` over `Canvas#2` on the runner's hosts.
  Its `layout` listing is not rounded to two decimals
  (`32,296.421875 356×450`).
- **The two sides of the row difference are both real.** A browser's computed
  `16px` and the runner's `16` are observations of different things. Rewriting
  one into the other would hide real CSS/native differences (both reviews).
  Only `font_family = 0`, an index where a name belongs, is simply wrong.

The same drive surfaced a real layout difference. `station-search` (an `input`
in a `section`) is **201 px wide on web and 352 px on macOS and Linux**. A bare
`<input>` keeps its intrinsic width even as `display: block`, so by the house
rule the native hosts are the ones that deviate. Nothing flagged it, and the
conformance run does not pin it.

### F5 — The agent API's own tests fail on main, outside every gate (medium)

`bun test ./host/web/agent.test.mjs`: 31 pass, 4 fail, all
`ReferenceError: imageHold is not defined` in the clock path. The test fixture
evaluates `glue.js` pieces without the `imageHold` binding added for animated
images (LLP 1011.000). `queue/` recorded the failures 2026-09-28. None of the
five checks and nothing in `scripts/async.mjs` runs `host/web/*.test.mjs`, so
they can stay red indefinitely.

### F6 — Node → source works only when a plan is passed (medium)

`layout <node>` names a source location (`@ apps/caltrain/app.contract:223:13
(Content) · compatible source map`) when the driver finds a plan with a
`.map.json` beside it: from `--plan`, `--url` or `EXACT_DEV_PLAN`, and on the
web from the built `dist/app.plan` (Astra's correction: the driver already
looks there, `scripts/agent.mjs` `mapLocator`). No build writes that map, so
driving the app as built says `no development source map`. The map cannot be recompiled
on demand from the source: the running plan is the **bake** (compile plus the
data source's types), whose digest (`aaf1eca3…`) differs from a plain
`contract build` of the same file (`60ef1b33…`). So the map has to come from
the bake that made the plan.

### F7 — Every invocation is a new process (known; LLP 1012.000)

A flow must fit in one argv list, and an in-memory store is lost between calls.
LLP 1012.000 (`--keep`/`--attach`, Draft) is the design. It remains the
largest workflow gap and is not re-proposed here.

### F8 — The documents and the grammar have grown past their purpose (low)

- LLP 1012 is 632 lines, 48 KB. Its Summary carries several pages of an iOS
  touch-crash investigation (PIDs, `.ips` names, `/tmp` evidence paths), so an
  agent learning the API reads an incident log to find the grammar.
- The nine-operation count holds, but the modifier grammar grew instead. `tap`
  has about fifteen positional forms (wheel, gesture, into, hover, history,
  contextmenu, dblclick, pinch, down/move/hold/up/cancel, `@N`), parsed by hand
  in `main()`, with a usage string kept separately in two places.

### F9 — Two build failures don't name what is missing (low; found implementing)

- **The bake's shader inventory runs `bun`.** Without Bun on `PATH`,
  `cargo build --release -p caltrain-linux` panics with `compatibility id: No
  such file or directory (os error 2)` (`bake/src/compat.rs`,
  `crate::bun().output().map_err(|e| e.to_string())`). The message names
  neither program nor fix.
- **The JS target's text-flow module runs `wasm-opt` unchecked.**
  `host/web-js/module.mjs` `buildFlow` ignores `wasm-opt`'s exit. Without
  binaryen on `PATH` the build then dies with an `lstat` ENOENT on a `.wasm`
  path, and `host/web/build.mjs` prints only the last stack frame.

An agent reads both as a broken tree, not a missing tool.

## What works (verified)

- `tree` (targeted, handlers, labels, test ids, focus), `state` (slots,
  derives, resources, pending, focus/keyboard/navigation), `logs` (the journal
  plus host lines), and `layout <node>` with row provenance and coordinate
  spaces on macOS and Linux.
- `screenshot` on all three hosts, and `clock` as a seek (`clock settle`
  names why it stopped).
- A full drive costs about 1.0–1.3 s of wall time (web 1.27 s, macOS 0.99 s,
  Linux 0.31 s).
- `contract build --json` gives structured diagnostics with stable ids.

## Confidence

High for F1, F3, F5 and the F4 items: each was reproduced here, and F3 and F5
to a root cause. F2's frame loop was measured on macOS only; APNG playback was
not tested because nothing here assembles one yet. iOS was not driven: `queue/`
(the held contact under Xcode 27) and `queue/` (screenshots before image
decodes) are its open items. The 201 vs 352 px judgement rests on CSS's
intrinsic input width and was not traced into the kernel.
