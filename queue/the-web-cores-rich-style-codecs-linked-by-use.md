**The web core's rich style codecs, linked by use** (2026-09-27, [LLP 1047.000 §9](../llp/1047.000-staged-loading-by-capability.rfc.md)). RealWorld's core grew 70.7 KB in a day (238.9 → 309.6 KB brotli); Canvas 2D is now linked by use (`c1663d51`, −10.3 KB). What remains is style rows whose `CssValue` codecs parse CSS text (paint, marker, dash array, paint order, transform and its origin, filter, clip path, shape outside, aspect ratio, background image): the generated `StyleProps` code reaches every codec, so every app carries every parser. A throwaway build stubbing every `CssValue` parse and format call bounds the saving at **10.9 KB** (299,236 → 288,375 B), so the type-erased storage Charlie agreed to (rich rows behind a trait, parsers linked by use; `kernel/build/codec.rs`'s one template plus ~45 consumer sites across the SVG and paint lanes) waits until those lanes next reshape `StyleProps`. Also left: Canvas 2D's TypeScript draw seam and per-batch web turn (~3.5 KB), which need a registration in the generated entry. `metrics.mjs --long` now holds each tracked app's core to a ceiling (`WEB_CORE_KIB`), so growth like this is a VIOLATION on the commit that causes it.
