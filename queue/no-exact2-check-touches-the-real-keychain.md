**No exact2 check touches the real Keychain** (2026-09-27, apple tests). `exact-apple`'s `fresh_preparation_reads_platform_secrets…` now stands in a shared memory store for the platform's (`store::PLATFORM`), because the login keychain is locked in a non-interactive session ("User interaction is not allowed"). The Keychain itself is `vendor/ibex2`'s `secrets::darwin::tests::the_keychain_round_trips`, which nothing here runs (vendor is excluded from the workspace) and which needs an unlocked login keychain too. A hermetic real-Keychain test needs the shim (`darwin_keychain.mm`) to take a keychain (`kSecUseKeychain` on a temporary one the test creates and deletes); changing the user's default keychain would reach every other process.
