**GPU canvases: what is left of an animated shader row's CPU** (LLP 1009 D7 and §3; re-traced 2026-09-30 with one Metal command buffer a canvas frame). At rest on an iPad Pro M1 the 19-kind feed's one animated shader row costs the main thread about 55 ms/s under the profiler (the starved pass: wgpu-core's `finish` 21, its submit 11, the render call 6; the tick 8) where UIKit's `MTKView` draw costs 35, and process CPU 245 ms/s against UIKit's 172 without the profiler (main 102 against 60). What is left is wgpu-core's bookkeeping for a pass and a submit, on the main thread, and a starved canvas's two passes a frame — D8 (the module on a thread of its own) is the design for the main thread; process CPU stays about 1.4× UIKit's for one canvas at 120 Hz with wgpu-core encoding the pass. In a fling the acquiring threads' `nextDrawable` is mostly new IOSurfaces for rows that scroll in (next line).
