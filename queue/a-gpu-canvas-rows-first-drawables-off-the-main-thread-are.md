**A GPU canvas row's first drawables, off the main thread, are the crypto ladder's creation cost** (LLP 1068 Q4, profiled 2026-09-28, M1 iPad Pro, crypto list `ladder 0`, Time Profiler per second). At 24k pt/s (about 97 fps) and 48k (about 39 fps) the main thread is 680–850 ms/s, nearly all the list's mount (`CollectionHost.flush`, `ExactSession.apply`, the `CA::Transaction` commit — LLP 1072's area); the canvas's own creation on it is small: the `MetalView` and its `CAMetalLayer` 7–16 ms/s, `gpu_create` 6–10 ms/s (nearly all `configure`). Off it, the acquiring threads spend 150–250 ms/s in the first `nextDrawable`s, 18% of the process at 48k. Layer creation is not a large share of the main thread, so no pool follows; a pool (LLP 1068 §4.5 stage 3) would be for the first drawables' CPU off it, if that is ever the limit.
