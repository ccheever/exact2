**The Apple batch wire's cost** (2026-09-30, cpu lane, iPad M1, 19-kind fling, `~/bench/xheavy/results/cpu/ipad/tr1`). LLP 1044.000 §6 S8 kept the JSON wire between the owner's Rust and Swift. Its price over the fling, all threads: `Batch.decode` 21.9 ms/s on the owner (BatchReader into string-keyed dictionaries, 8 of it building them), the Rust side's write inside `commit_tree` (style JSON 1.6, the collections snapshot 6.1, the ops themselves in the rest of the ~8 ms/s of encode), and on main the dictionary lookups the apply then does per op (~7 ms/s of hashing and finds in `Presenter.apply`). A binary layout for the hot ops (create, frame, style, children, collections) would take most of the 22 + 8 and some of the 7 out of a 632 ms/s run. **Ruled (Charlie, 2026-09-30):** JSON stays the wire; first decode it straight into typed values with no intermediate dictionaries (LLP 1044.000 S13's "batches read at memory speed … over the same JSON wire"), measured; a binary layout for the hot ops only if that leaves more than about 10 ms/s.
