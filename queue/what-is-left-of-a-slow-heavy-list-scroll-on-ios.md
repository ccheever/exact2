**What is left of a slow heavy-list scroll on iOS** (2026-09-26, perf/slow-frame, Time Profiler on the M1 iPad Pro trace and the iPad Pro 13" simulator). At 1k pt/s, after the focus-search, text-scan, timer and travel-report fixes, the main thread is mostly building rows: `Host::commit` layout and `create_row` in Rust, `Presenter.apply` in Swift, and the CA commit. Three pieces are separable. An ellipsized paragraph (`text-overflow`) never rasters on a worker, so each new row's author name is shaped and drawn on main in `NodeView.draw` (`paragraphLayout`, ~2% of main on the iPad); a worker raster that truncates would take it off. Every commit re-serializes every mounted row's snapshot (`collections_json`) and Swift re-parses it (`applySnapshots`, `CollectionSnapshot.init`), ~3%, including the measurement-only report that follows each built row. And each report still carries every mounted row's height (`CollectionHost.height` walks each row's ancestors for `hidden`), which the runner now ignores when unchanged but the host still gathers and encodes.
