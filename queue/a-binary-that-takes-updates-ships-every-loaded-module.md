**A binary that takes updates ships every loaded module** (2026-10-04; LLP 1047 D8, "after the web target"; LLP 1036.000 §8). A production Apple build at store level 0 now leaves out each of the four its plan cannot reach (the bake's `loads`: the Canvas 2D GPU module, the SVG island module, the video and web arms; Sparkline's Mac bundle 16.3 → 11.6 MB), because that plan is the only one the binary will ever run. A binary at any other level carries all four (4.7 MB on a Mac) for a later bundle that might reach one, and dropping them there needs the linked set as a compatibility input, so a bundle that reaches a module its binary lacks is refused before it is applied (D6, D8). Also seen on the way: an IPA wraps the web and video arms as frameworks and leaves `libexact_svg.dylib` and `libexact_canvas_gpu.dylib` loose in `Frameworks/`, the form ITMS-90171 names; nobody has uploaded one that carries them to find out.
