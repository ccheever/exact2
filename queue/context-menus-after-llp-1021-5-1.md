**Context menus after LLP 1021 §5.1** (2026-10-05): the Signal clone moves its chat-list preview onto `contextPopover`/`contextPreview` (its agent has the syntax). Owed: a swipe row (the Signal chat list's) never parks in the iOS node pool, menu or not (its live scroll view), and that list is not a virtualized `list` anyway; macOS's `MenuHost.context` and right-mouse path have no test (`popUp` is modal); the compiler does not refuse a literal `contextPopover` naming no popover, or two `contextPreview` rows (iOS logs both, macOS the first, the web neither); no interactive content inside a preview (UIKit takes any touch on it as the commit), so Signal's reaction bar stays authored; after a bar item's menu, `ExactView`'s focus (key commands) comes back only at the next touch on the page, not when the menu ends (UIKit says nothing then), and any touch on such a bar blurs a focused node (UIKit exposes no bar item's view to tell a menu item's touch from another); Linux shows nothing; on the web a bound `contextPopover` that the node's own action changes opens the old popover when the commit is deferred (a view transition on the JS target, presence loading on the wasm host): resolve it after the applied commit, not in a timeout.
