**A list benchmark row is now mostly the runner and the batch** (2026-09-25, perf/rowcost, simulator Time Profiler over the fill slices; it was mostly UIKit). The iOS presenter's share of a built listbench row fell from about 1.5 to 0.75 ms (no window layout engine, no scroll view per closed swipe row, parked row views reused by shape: `NodePoolIOS.swift`). What is left per row: the runner's commit and a Taffy layout from the root on every report (about 0.7 ms, the perf/layout lane), `Batch.decode`'s JSON (about 0.25 ms), `CollectionSnapshot` parsing the whole snapshot each batch (about 0.12 ms, `Collection.swift`), and `UIImageView` resolving a symbol it is handed anew (about 0.08 ms). Layout from the collection, a binary batch, or a snapshot that sends only what changed would each go further. View reuse is iOS-only; macOS and web could follow the same contract.
