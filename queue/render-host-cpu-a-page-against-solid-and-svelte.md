**Render host CPU a page against Solid and Svelte** (2026-09-29, the SSR-cost lane, LLP 1048.000 D10). RealWorld's `/` is ~4.3 ms of CPU a page on this Mac under load (Solid ~0.8), and the grid benchmark's 1,000-row `/` ~125 ms (Solid 24 on the same load), after this lane's commits. Measured by A/B, not by profile alone: (1) Apple's transport was ~30% of it; the render host now uses rustls on macOS too (Charlie, 2026-09-29; LLP 1048.000 D10), −17–18%. (2) The fresh Hermes realm is ~14% (`EXACT_RENDER_REALMS=warm`'s saving): Runtime creation (its internal bytecode, the global object) and teardown; this Hermes has no heap snapshot, and a realm's module state lives in closures no reflection reaches, so a proven reset needs an engine snapshot or a bake that proves a module keeps no mutable state. (3) The kernel's apply and the projection are gone for pages the plan allows (LLP 1048.004 stage 1, 2026-09-30: RealWorld −18%, grid −49%); the rest is the render itself: the tree's realization and bindings (the plan VM), the kernel's apply (style validation, inheritance, the testId index), the projection and its CSS, JSON across the Hermes boundary. Reaching Solid's cost needs a render that writes the document from the plan and the settled state without the kernel (precompiled static fragments, as Solid and Svelte do), plus (1) and (2). At concurrency 64 the server's defaults (`--renders 4 --queue 32`) answer most requests 503 at once, so a CPU-per-page number there counts cheap refusals unless statuses are checked.
