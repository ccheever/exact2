**Presize the transaction's per-commit sets from the batch** (2026-09-24, the size lane): `txn::apply`'s `created` set, `Staged`'s maps (`created`, `parents`, `children`, the root sets) and `Detach`'s `seen` start empty on every commit and grow as its ops arrive, about seven doublings each for a batch that moves 220 children. Under a compact id map that growth cost 55–70% more cycles on a native churn bench (500 commits, each creating 20 rows, moving 220 and destroying 20: 203M → 313–348M cycles, for 1% more instructions), which is why hashbrown stays (LLP 1047 §10). hashbrown pays for the same growth, less. Sizing each set from the batch's op count before its first insert would take that growth off the commit path, on native and the web.
