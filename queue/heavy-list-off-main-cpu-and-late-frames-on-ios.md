**What is left of the heavy list's off-main CPU and late frames on iOS** (2026-09-26, perf/offmain, M1 iPad Pro Time Profiler and System Trace). Off-main is image decode (about two thirds at 6k pt/s and up) and worker text; inside a decode, ImageIO's own thumbnail (hardware JPEG decode, then a high-quality resample from full size) is nearly all of it, so what is left to cut is decode count, not decode cost. Four pieces: (1) a fifth of decodes still draw into a copy because the plan rounds a side up (`RasterDecodePlan.scaled`) where ImageIO rounds down, so the thumbnail is one pixel short and gets stretched; agreeing on rounding drops the draw but moves those images' pixels by that stretch. (2) Every image layer's contents are copied by Core Animation at commit on main (`CA::Render::create_image_by_copying`, ~2% of main at speed); an IOSurface-backed image would not be. (3) The text-pixel cache (`TextRasterizer.kept`) is iOS only; the AppKit rasterizer has the same repeated labels. (4) With off-main load lower, the main thread at ±12k/24k pt/s spends more CPU-ms for the same rows (more samples on E cores, fewer P-core cycles per ms); total CPU still falls. The one late frame left per ladder run at the +12k start is the probe's segment checkpoint (6-12 ms of JSON written on main in `-[LBProbe emit:]`) plus rows the next frame needs; the harness could write it off main.
