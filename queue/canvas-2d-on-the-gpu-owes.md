**Canvas 2D on the GPU owes** (2026-09-29, LLP 1056 §8.5, `land/canvas-gpu`). (1) Memory: F2 full screen ended 19 MB (iPhone) and 4–7 MB (iPad) over SwiftUI's at the landing tip (24 and 32 MB on the bake branches), within one full-screen IOSurface, the second a canvas drawn off the main thread keeps while Core Animation shows the first; a smaller-than-device backing for a canvas that animates, or one surface when the lists always cover, would close it. (2) vello's main thread was 172–191 ms/s against Skia's 118–148: traced (2026-09-30, iPhone, the same app with each module swapped in; `~/bench/canvasbake/swap`, `exp`, `ab`). It is not main's own work (main's CPU 29 against 25 ms/s) but its wait for the runtime owner's canvas draw each frame (`Runtime.advance` → `Owner.sync`): the same draw costs 2.9 ms under vello and 1.75 under Skia, slower evenly in every function, both on the performance cores, and 2.4 ms with no replay at all, so the performance cluster runs slower when vello leaves the CPU idle while the GPU works (Skia's replay burns ~5 ms of CPU a frame). Cut on `perf/canvas-gpu-main`: main's font scan reads record headers (main CPU 29 → 22 ms/s), and the recorder keeps parsed palette colours and the reply finds text by headers (owner −6 to −9 ms/s, main busy 173 → 167). The lever left is the next line. (3) The module is in every Apple app's bundle (3.98 MB on iOS), as the SVG island module is; embed it only for a plan with a 2D surface. (4) It needs Xcode's Metal toolchain to build; a Mac without it builds apps that draw animating canvases with Core Animation's recording (§8.4), which then remains only as that fallback: delete it when every build machine has the toolchain. (5) A canvas is given to the GPU at its fresh bitmap's first lists; one that starts animating later stays on Core Graphics until its next fresh bitmap (a state prologue from the tracker would move it). (6) Text on the GPU is filled glyph outlines (no colour glyphs); Skia drew glyph masks. (7) The same module could replay Linux's canvases (kernels to SPIR-V at build time), so Apple and Linux would match each other.
