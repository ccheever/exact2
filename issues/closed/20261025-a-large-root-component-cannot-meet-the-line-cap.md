**Status:** Closed
**Resolution:** Ask 1 built as LLP 1091.002 (members files); the T3 Code clone's root is split into nine members files under the cap with a byte-identical plan (#1063, daehyeon/t3-code-main 1554a4f912)
**Systems:** `rules/RULES.md` (1,500 lines per source file), `scripts/caps.mjs` (counts `.contract` since #885), the Contract component model (`docs/contract-grammar.md`, "Components and actions")
**Severity:** P2
**Author:** Claude (Opus 5.5), from the T3 Code clone (`examples/t3-code` on `daehyeon/t3-code-main`, PR #498)
**Date:** 2026-10-25

## Symptom

Since #885 (`29a5cbeec1`), `bun scripts/caps.mjs` counts authored `.contract` files
against RULES' 1,500-line budget. The T3 Code clone's root, `examples/t3-code/app.contract`,
is 3,006 lines, so caps fails on the clone branch and PR #498 cannot land on main.

The file is one component, `T3Code`, and almost all of it is members, not view:

| Member | Count | Lines |
|---|---|---|
| `action` | 306 | 2,126 |
| `state` | 268 | 341 |
| `task` | 103 | 217 |
| `resource` | 85 | 86 |
| `let` (derive) | 59 | 73 |
| `mutation` | 44 | 48 |
| `provide` | 1 | 56 |
| `use` and routes header | | 56 |
| `view` (one `T3Window(...)` call) | 1 | 1 |
| comment-only lines | | 180 |

The view already lives in child components. #885 split the design tool by moving
view panels out of its root; the clone has no view left to move.

## Why the root cannot shrink app-side

Three rules of the component model keep these members in the root:

- **Only the root may own resources, mutations and tasks** (`docs/contract-grammar.md:310`).
  So the 103 tasks, 85 resources and 44 mutations stay in the root.
- **A task's schedule names an action with no parameters** (`docs/contract-grammar.md:291-292`,
  `after(expr, IDENT)` / `every(expr, IDENT)`). Each task keeps a named root action for its
  timer, about 107 of the 306 actions.
- **`send` targets a mutation owned by the same component** (`docs/contract-for-agents.md:478`).
  A child cannot send, so every action that sends stays in the root as at least a header
  and a `send`.

A dependency closure over the root (every member reachable from a task, a resource, a
mutation or `provide`) finds 17 members, 72 lines, that a mounted child could own.

## What was measured

Every app-side lever, keeping behaviour identical (the reference T3 Code is the oracle):

| Step | Root lines |
|---|---|
| Today | 3,006 |
| Comments made trailing, the one dead state (`originEdited`) removed | 2,851 |
| `provide` moved into `T3Window`; the 17 child-ownable members moved | 2,726 |
| States grouped into records, action logic moved into `fn`s in other files | ~1,896 |
| Pure setters folded into one `set(field, value)` | ~1,870 |
| Every action cut to its effects (headers, effects, guards) | ~1,800 |

The floor stays near 1,800 lines because each of the 306 actions keeps its header and its
effects, and the tasks, resources and mutations keep theirs.

Two alternatives were rejected:

- **State moved into TypeScript data code** lands one turn later (a mutation, then a
  refreshed resource). Actions such as `composerKeyEvent` decide `preventDefault` and
  `focus` in the commit of the event, so the lag is visible. It also saves no lines, since
  every root action still needs its `send`.
- **Generating `app.contract` from fragments** would pass `caps.mjs` through its
  "generated by" exemption without meeting the rule.

## Ask

One of:

1. **A component declared across files.** A root names other files that continue its
   sections, so its actions, tasks and resources can be grouped by feature. This is the
   smallest change to the model, and it serves any large app, not only this one.
2. **Tasks, resources and mutations owned by a non-root component that stays mounted.**
   This would also let a feature's state live with its view, but it changes when requests
   open and close.
3. **A named exemption** for `examples/t3-code/app.contract` in RULES, with its reason.

Until then the clone's caps check fails and #498 waits. Everything else on the clone
branch passes (7,271 Bun tests, the plan build, tsc, the macOS build).
