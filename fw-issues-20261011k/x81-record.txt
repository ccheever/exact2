App: `bun scripts/exact.mjs new <dir>` on that revision; app.ts exports an empty `sources`;

Three groups of five rows, each row a `row` holding a label `L<n>` with `user-select="none"` and a code text:
  V  `list virtualized=true`, the label before the code (a gutter)
  W  `list virtualized=true`, the label after the code (as T3 PR #417's DiffNumber)
  P  the same rows as V in a plain `column` (no list)
Every scenario drags with the mouse from the start of row 1's code to the end of row 3's code, then copies.
`\n` below is a newline in the clipboard text.

1. Exact web, JS target (`bun exact.mjs web-build`, the web build that ships), Chrome 155, Playwright's mouse
   (x81-chrome-copy-probe.mjs.txt): `document.execCommand('copy')` and the Meta+C chord, read back with
   `navigator.clipboard.readText()` (headless Chrome's own clipboard; the system pasteboard was not touched)
     V  drag (65,55) -> (151,111)   clipboard "vcode 1 body\nvcode 2 body\nvcode 3 body"
     W  drag (29,222) -> (118,278)  clipboard "wcode 1 body\nwcode 2 body\nwcode 3 body"
     P  drag (65,389) -> (152,445)  clipboard "pcode 1 body\npcode 2 body\npcode 3 body"
   getSelection().toString() is the same text in each. Computed `user-select` of the three L2 labels: none.
   -> no label in any copy. host/web-js/list.js has no copy handler: the JS target leaves a list's copy to the
      browser, which leaves out `user-select: none` text.

2. Exact web, wasm target (`bun exact.mjs web-build --wasm`: index.html loads glue.js + app.wasm), the same probe

   runner does, so the endpoints land right and only the labels between them come in.
