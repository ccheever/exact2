# LLP 1155 Stage 0a frontend transcript

Stock Google Chrome 156.0.8078.74 on macOS, 2026-10-30. This is the complete
request, response and event record of the two final screenshot sessions, with
HTTP discovery requests too. Earlier bootstrap/debugging sessions are not part
of these counts. No live Exact app was attached. The synthetic target has a
Document, `main#page` (runner #1) and `button#tinted-control` (runner #2).

The real browser was launched through `chromium({needs: ['perf']})` with
`CHROME=/Applications/Google Chrome.app/Contents/MacOS/Google Chrome`, a private
profile and `--remote-debugging-pipe`. The existing `Cdp` client drove the
frontend and captured it through `Page.captureScreenshot`. That outer browser
connection is separate from the target connection recorded below: evaluating
frontend DOM to locate a control did not implement evaluation on the target.

## Actions and scope

1. Open the bundled `inspector.html?ws=127.0.0.1:<port>/<capability>/page`
   URL through `Target.createTarget`. The stock frontend requests the document
   and expands `main` by `DOM.requestChildNodes`; the reply is an event.
2. Hide the unavailable screencast with its toolbar control; select the button
   in Elements. Hover it and toggle the picker on and off. The stub has no
   app to outline or pick, so Overlay calls return errors, never successes.
3. Click `prototype.contract:4` in Styles. `CSS.getStyleSheetText` returns the
   exact fixture, and Sources opens its fourth line. Return to Elements.
4. Capture Styles; open Computed and capture its two values; filter for
   `font-family`, enable Show all, and capture “No matching property”.
5. Attach a second target with D3's inspector-origin platform-rule candidate;
   select the same button and capture the fabricated override.
6. In a separate Chrome tab, open `chrome://inspect/#devices`, click Configure
   for Discover network targets, add `127.0.0.1:51677` and click Done. Chrome
   requests the root discovery paths; both return 404. It never discovers the
   capability-scoped target.

The first target's port was 64597; the second's was 51677. Capability values
are omitted. Discovery exists only at `/<capability>/json/list` and
`/<capability>/json/version`; the WebSocket is single-use and revoked on
close, with a ten-minute unused lifetime. The server checks loopback, Host
and Origin. The successful WebSocket Origin was `devtools://devtools`.

A separate attempt typed the URL into the private Chrome process's omnibox
through System Events. `osascript` returned zero, but a bounded observation
still saw `about:blank`; that physical entry route is **unverified**, not a
successful attachment. Direct bundled-URL navigation worked. No pinned web
frontend or fork was used.

source mutation or execution. Every unimplemented method returned `-32601`.
