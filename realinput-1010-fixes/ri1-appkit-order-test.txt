realinput-1010-fixes RI-1: a launcher letter under either order of the window's local key monitors (AppKit test).
The same test (macos/tests/r8-keys/main.swift, testALauncherLetterReachesExactsKeyRouteInEitherMonitorOrder) compiled
against the feature-branch tip's Swift (before) and this branch's (after). It stands in Exact's session monitor
(ExactViewMac shortcutMonitor -> Presenter.routeKey, the only place a Contract key handler runs) beside the
composer's real monitor (T3Composer.handle) and presses F with the launcher focused and D from the bare window,
with the composer's monitor after Exact's (false) and before it (true).

Why the order matters: AppKit calls local monitors in no fixed order. A probe that adds monitors A and B and sends
one key ran them as [A, B] in 5 of 8 launches and [B, A] in 3 (and a monitor that returns nil stops the rest).
