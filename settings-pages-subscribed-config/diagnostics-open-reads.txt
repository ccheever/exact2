# settings-pages-subscribed-config, review round: Settings › Diagnostics reads its resource timeline once per open

The review found that Diagnostics sent server.getResourceTelemetryHistory twice when it opened (the reference: once).
Lane trace of the previous after drive (head 262ea528e, lane settings-pages-subscribed-config, clone server 127.0.0.1:16202),
times relative to the subscribe span's start (2026-10-09T16:41:11.874Z):

  subscribeResourceTelemetry          start  +0.0 ms   (subscribeBeforeSnapshot +0.1 ms: the server sends the current sample at once)
  server.getResourceTelemetryHistory  start  +9.8 ms, end +25.0 ms
  server.getResourceTelemetryHistory  start +38.2 ms, end +40.4 ms   <- 13.2 ms after the first reply ended

Cause: the stream's first sample arrives at once; draining it moves data.telemetry, Exact asks Diagnostics again and
forgets the opening answer (LLP 1016 D5). The first read's reply had reached the transport but not that answer, so it
was dropped (host/apple/src/executor_core.rs forget: a completed outcome is dropped undrained). T3Transport's shared
read joins only a read still pending, so the next answer sent the read again.

Fix (5d28da9bf): the page's three reads and the timeline land before the page opens the telemetry stream
(diagnostics-view.ts diagnosticsPage, settings-a-telemetry.ts telemetryPage).
