The banner is the transcript's ThreadErrorBanner (chat.contract, data.error), behind the Settings backdrop on screen, so
the screenshots do not show it; the accessibility tree does.

Cause, found by reading the code and reproduced under Bun (no live session was left to confirm the fix): clone code.
let-go.ts letGoAware passed watch() through after its answer was let go. A refresh let go inside one of fleet.sync's
tolerated reads (settings-b-fleet.ts: environments, learnRoutes, announceJobs, announceServerUpdates, each swallowed)
went on to readLocalBackend (local-backend.ts), whose native.watch('t3.local') the prelude refuses outside an answer
(js/src/prelude.js, unchanged in this merge except database tracking). The refresh's catch (client.ts) wrote that Error
into client.error, where it stays until Dismiss or a later connection clears it. let-go.test.ts "a refresh let go inside a read it tolerates
watches nothing outside its answer": client.error was "native.watch outside an answer" before the fix, empty after.
The path is the same on the base. Why only the after build reached it is not proven: round 5 made shellView, the details
card and SnapShot settings depend on exactPage().hasFocus, so each window activation (each orca computer action shows the
app) re-asks them and adds native round trips (notifyStatus, activityFacts, vcs.refreshStatus) beside the snapshot
answer, which changes when its let-go lands. No main commit introduced it.
