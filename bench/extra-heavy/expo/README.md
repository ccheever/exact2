# Extra Heavy feed — the Expo (React Native) app

The Expo port of the Extra Heavy feed (`../SPEC.md`, especially "Decisions"). Bundle id
`dev.exact.xheavy.expo`, display name "XHeavy Expo". The same source builds for iOS and, with
react-native-web, for the web pair (`../web/`): `index.web.ts`, `metro.config.js`, `web/` and
`modules/bench-env/index.web.ts` are the web's and change nothing on iOS.

`data/` (a copy of `../data` without `svg/`), `assets.ts`, `embed.ts` and `assets/icon.png` are
generated by `../prepare.sh` (`gen-assets.py`) and not committed; neither are `node_modules/`,
`ios/` or `dist/`.

## Shape
- `App.tsx`: `feed.json` is imported and inlined into the Hermes bundle by Metro (as the other
  benches do). One `LegendList` over the 3,000 rows: `keyExtractor = id`, `getItemType = kind`,
  `recycleItems`, `estimatedItemSize={470}` (the spec's ~1.4 M pt over 3,000 rows; LegendList then
  averages measured sizes per type), default `maintainVisibleContentPosition`,
  `initialScrollIndex = BENCH_START_INDEX` alone (it lands 500 and 1500 exactly). Contexts carry C
  (= min(width − 32, 600)), the live clock s (React state, `setInterval(1000)`) and the motion clock t
  (a Reanimated shared value set by one `useFrameCallback`).
- `rows.tsx`: `Row` (`memo`) = header + `Body` switching on kind. `assets.ts` (from `gen-assets.py`)
  maps asset names to static `require`s; `embed.ts` holds `embed.html` as a string.
- `skia.tsx`: shader (SkSL RuntimeEffect with an `ImageShader fit="cover"` child; uniforms from a
  derived value of t), canvas kind (`Path.cubicTo`, `Circle`, `LinearGradient`, `Image` under a
  circle `clip`, `Text` with `matchFont({fontFamily: 'System'})`), rings (`Path` arc with `end`
  derived from t), waveform (one bar path drawn grey, then blue under a clip rect derived from t).
- Thumbs skeleton: `useLayoutEffect` keyed on row id → 1,200 ms of grey cells with an
  `expo-linear-gradient` band in an `Animated.View` translated by a repeating 1,000 ms timing (one
  band across the grid: each cell offsets it by its own x), then the images' opacity 0 → 1 (200 ms).
  Images mount under the skeleton so they decode during it.
- Thread: expansion and drafts live in module-level maps keyed by row id (app state that survives
  recycling), read into LegendList's `useRecyclingState` (reset when a recycled cell gets another
  row; its setter re-lays out the cell); a flip calls `LayoutAnimation.configureNext(250 ms
  easeInEaseOut)`. LegendList has no `prepareForLayoutAnimationRender`.
- Video: `useVideoPlayer(source)` per row (`loop`, `muted`, `play()` unless frozen) + `VideoView`
  `contentFit="cover"`, `nativeControls={false}`.
- Map: `MapView` with `region` (controlled, so a recycled cell moves), every gesture disabled,
  `pointerEvents="none"` on its wrapper, a default `Marker`.
- Carousel: `LegendList horizontal`, `recycleItems`, `getFixedItemSize` 140, `contentContainerStyle={{ gap: 10 }}`,
  `dataKey = row.id` (a recycled row is a new dataset, so it starts at its first card).
- Filmstrip / inbox (`nested.tsx`): a nested `LegendList horizontal` of 2,000 items (`recycleItems`,
  `keyExtractor`, `getFixedItemSize` 112, `contentContainerStyle={{ gap: 8 }}`) and a nested vertical
  `LegendList` of 1,000 in a 400 pt box (`recycleItems`, `keyExtractor`, `estimatedItemSize={70}`,
  `nestedScrollEnabled`, Android-only, a no-op on iOS). LegendList's own examples nest lists this way (its
  "Media Rails": a recycling vertical list of recycling horizontal lists) and document nothing more for
  nesting. `onScroll` records the offset in a module-level `Map` by row id; the inner list's `dataKey` is
  the row id and `initialScrollOffset` is the map's entry, so a recycled cell handed another row restarts
  as that row's dataset at its kept offset.
- `BENCH_START_INDEX`: `initialScrollIndex` alone.

## Launch environment (`modules/bench-env`)
Copied from the crypto bench's app: `BENCH_LIVE`, `BENCH_SCENARIO`, `BENCH_FREEZE`, `BENCH_START_INDEX`.
Live ticks iff (`BENCH_LIVE=1` or `BENCH_SCENARIO=rest`) and `BENCH_FREEZE≠1`. Freeze: shader t = 1.25,
rings at their base, waveform q = 0.4, videos not played (frame 0), GIF/WebP `autoplay={false}`,
Lottie `progress={0.5}`, no skeleton, spinner paused, threads collapsed.

## Build
iOS, after `../prepare.sh`, with Xcode selected (`DEVELOPER_DIR`):

```sh
npm ci && npx expo prebuild -p ios && (cd ios && pod install)
xcodebuild -workspace ios/XHeavyExpo.xcworkspace -scheme XHeavyExpo -configuration Release -sdk iphoneos \
  -destination generic/platform=iOS -derivedDataPath build/dd CODE_SIGNING_ALLOWED=NO build
```

The `.app` under `build/dd/Build/Products/Release-iphoneos/` is unsigned: sign it with the probe embedded by
`../../heavy-list/probe/resign.sh <App.app> dev.exact.xheavy.expo` (`../README.md`, "iOS"). The published
numbers are LegendList 3.4.0; an earlier FlashList 2.0.2 build is described below for the record.
Web: `npx expo export -p web` (`../web/build.sh` does it).

## Smoke, LegendList 3.4.0 (iPad, 2026-09-27)
- fling 0: 104–107/100–101/97–98/78–79/32–33 fps at 1k/3k/6k/12k/24k pt/s, main 513 ms/s, peak 415 MB
  (FlashList: 116–119/110–111/105–108/97–98/61–64, main 495, peak 598 MB). Slower at every speed, half the
  frame rate at 24k; busy/frame at 24k 28 ms (FlashList 14–16).
- rest 0: 119.5 fps, busy 924 ms/s.
- innerfling 0 (the strip, `getFixedItemSize`): 119–120 fps to ±12k, 116–119 at ±24k, 102–104 at ±48k, 87–91
  at ±96k — FlashList's numbers.
- innerfling 0 (the inbox): 120 fps to ±12k, 114–115 at ±24k, 84–87 at ±48k, 100–103 at ±96k (FlashList:
  118 / 115–117 / 109–110 / 69–76 / 79–81 / 92–97). The measured content is 64,500 pt (FlashList reported
  its 200,000 pt estimate).
- innerfling 4 (sampled): the strip blanks from ±24k (11–13/43 samples), then 33–35/41 at 48k and every
  sample at 96k, bands the whole 600 pt strip — worse than FlashList (7–11/42 at 24k, 12/38 at 48k,
  23–27/37 at 96k). The inbox: none to ±12k, then 14–16/25–28 samples at 24k–48k and 7–8/30 at 96k, bands
  up to 396 pt (FlashList blanked from ±6k: 1/33, 4/30 at 12k, 12–16/24 at 24k, 9–12/27 at 48k). Sampled frame rates: strip 72–91, inbox 49–69 (FlashList 74–88, 48–67).
- innerkeep 0: the strip kept both marks (`sameView` true). The inbox came back **44 and 53 pt short**
  (5,432 → 5,388, `sameView` true; 8,765 → 8,712, `sameView` false). This is LegendList's default
  `maintainVisibleContentPosition` (scroll-time size stabilisation): as rows above the jumped-to offset
  are measured against the 70 pt estimate, it shifts the offset so the visible messages stay put, and
  `onScroll` records the shifted offset. A diagnostic build with `maintainVisibleContentPosition={false}` on
  the inbox kept all four marks exactly (`expo-legend-innerkeep-0-inbox-mvcp-off.json`); the shipped build
  keeps the default. Feed flings during innerkeep: 78–102 fps.

## Gaps and divergences (device, 2026-09-27)
- LegendList: `BENCH_START_INDEX` 500 and 1500 land exactly (row 500, row 1500 at the top); **2500 lands
  about 200 pt low** (row 2500, a map, has only its bottom ~140 pt on screen). Recorded, not tuned.
- FlashList (until 2026-09-27): **`BENCH_START_INDEX=500` lands on row 566** (a photo row's bottom, then 567 markdown), in every build:
  `initialScrollIndex`, then `scrollToIndex`, then `scrollToOffset(getLayout(500).y)` all give the same
  place, so FlashList's own layout puts row 500's y where 566 is drawn. 1500 and 2500 land right.
  Three rounds; recorded, not fixed. `shots/ipad-expo-freeze-*.png` are FlashList's, `shots/ipad-expo-legend-freeze-*.png` LegendList's.
- Markdown: the library's bullet is "·" and its blockquote renders body text; both replaced by two
  small `rules` (`list_item`, `blockquote`) to meet the spec ("•", 16 italic #3C3C43).
- Map marker is react-native-maps' default (a red pin with a dot), not SwiftUI's balloon (SPEC
  Decisions).
- The canvas title uses `matchFont({fontFamily: 'System'})`, which resolves to SF on iOS.
- The `rest` probe JSON says `live=false` (the probe reads only `BENCH_LIVE`); the app's ticks are on in
  `rest` per the spec.
