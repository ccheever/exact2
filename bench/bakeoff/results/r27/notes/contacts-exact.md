# Contacts build notes

Finished and installed as **Contacts** (`dev.bakeoff.contacts.bc444fa`) on simulator `486FD498-0E3E-4B64-8E4B-152BD8265EE7`. The final app was launched after installation. All requested features are implemented.

- **Data:** The 320 starting people are bundled through the JSON import. Changes use a separate atomic JSON file, with serialized writes to prevent lost updates. Empty saved directories do not reseed themselves.
- **Choices:** Favorites appear above the complete alphabetical directory. Contacts without a last name sort under their first name. Add/edit requires a nonblank first or last name; editing preserves existing birthdays and favorite status.
- **Hard parts:** Native search presentation and keyboard dismissal needed separate updates before navigation. Search is deactivated on departure so returning to the directory leaves Add reachable. A section container was not a working native scroll target; jumping to its first contact row worked. The cold Exact host build took several minutes.
- **Lookups:** Exact’s start guide, list-detail pattern, search, swipe, grouped forms, keyboard/focus, file persistence, and iOS-driving references. Native source inspection showed that the automatic section index requires every heading to be a letter, which excludes a Favorites section; this app therefore supplies a compact accessible index.
- **Accessibility:** Checked light/dark mode and the largest accessibility text size. Removed redundant stars from Favorites rows to leave more space for names. The index uses compact directory-style targets and capped caption text. Verification exceptions document those targets, intentionally hidden swipe actions, and native pinned section headers covering rows during scrolling.
- **Validation:** Final web verification passed all 8 tests and layout checks. Final native feature run passed all 8 tests. iOS verification checked light/dark layouts, largest text, relaunch persistence, and real scrolling; its final layout pass had no unaccepted findings. One intermittent native row-mount timing failure was resolved by explicitly checking detail readiness before the deletion test. Scrolling physics required no app changes; machine load prevented a reliable timing comparison.
- **Unfinished:** No requested app features remain unfinished. Real telephone calls cannot be exercised in the simulator; phone and email rows use `tel:` and `mailto:` links.
- **What would make this faster:** Warm native build caches, documented keyboard/navigation update ordering, mixed-heading native section indexes, and layout checks that automatically recognize pinned section headers and compact alphabet controls. Disabling the simulator’s first-use keyboard tutorial ahead of testing would also help.
