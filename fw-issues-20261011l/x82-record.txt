X82: on macOS, after a live colour-scheme switch, a rastered text that is not selectable keeps the old half of its
`light-dark()` colour until it mounts again (T3 clone, from diff-gutter-selection-followups, T3 PR #417 observation 3)
Revision: exact2 main e2c6fcc4318e1e47e21e5fd4df7a872f01f468ef. macOS 26.6.2 (25G83), Apple Silicon, a 2x display.
Chrome 155.0.8059.39 (Playwright's launch of /Applications/Google Chrome.app, headless).
The Mac's own appearance is Dark and was not changed. The agent pins light at its first operation (Agent.init,
`systemScheme(dark: false)`), so a drive starts light.

App: `bun scripts/exact.mjs new <dir>` on that revision; app.ts exports an empty `sources`; app.contract is
x82-app.contract.txt beside this file (`contract build`: no diagnostic). Every probe text is
`light-dark(#d00000, #00b4ff)` (red in light, blue in dark) on a `light-dark(#ffffff, #111111)` page, 13 px bold.
"Mount" mounts the probes, so their first pixels are drawn in the scheme of that moment.
  S1-S5  selectable texts: plain own colour; inherited from a column; a component prop (`Ink(ink=…)`); a coloured run
         in a paragraph; the rows of a `list virtualized=true`
  U1-U5  texts the Mac host counts as not selectable (TextSelectionMac.swift `textSelectable`), three each: a button's
         label; `user-select="none"`; a paragraph of runs under a container with `press=` (as the clone's Files
         surface lines); under `role="tree"`; a button's label inheriting the button's `color`
  small  three button labels too small to raster (`M1`-`M3`)
Each U text is 420 points wide or more, so on a 2x display it rasterizes (TextRasterizer.minPixels 16384).

How the colours were read
- Web: `getComputedStyle(e).color` of each probe and each run, and Chrome's own screenshots.
- macOS: the agent's `sample <x> <y> …`, which renders the view's layers (`layer.render(in:)`), so a text's raster
  surface is what is read, at 1 point per sample. The agent's plain `screenshot` cannot show this gap: it captures
  the view by drawing every text again through `draw` (Capture), with the current colours
  (x82-macos-agent-screenshot-live-dark.png shows every text right). `screenshot … window` (the window server's
  picture) is what T3 PR #417 used; on this run the window server gave no picture of the window ("a display that
  is asleep or a locked screen"; neither was the case, the window was likely not on the visible Space), so the
  layer render stands in for it.
- A sample point counts as red (R > 0.15, R > 3B, R > 3G) or blue (B > 0.25, B > 2R) in linear sRGB; the counts
  are the 2 x 160 points across each text's middle.
