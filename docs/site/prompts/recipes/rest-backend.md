```prompt Add my own REST server
Give the Exact app in this folder its own REST server, written in Bun. Use https://github.com/ccheever/exact2/blob/main/docs/recipes/rest-backend.md as the source for each step. The exact2 checkout has the same page at docs/recipes/rest-backend.md.

1. If this folder is not an Exact app (it has no exact.mjs and app.contract), stop and tell me.
2. Ask me whether to start from the REST starter or to connect a server I already have. For the starter, run `bun exact.mjs pattern rest`: it writes the Contract app and the Bun server together. If it refuses a file I edited, tell me; do not add `--force` without asking.
3. Put the server where `test` and `verify` find it: `server.ts`, `server/index.ts` or `server/server.ts`, or the entry `"commands": { "server": [...] }` names in app.json. Its address is the first `http://127.0.0.1:<port>` in app.ts. Its database is the path in `DB` (`new Database(process.env.DB ?? 'data.db')`); a server with no database needs `"server": { "database": false }`.
4. If the app must reach a deployed API, make its origin a setting: `"env": ["API_BASE_URL"]` in app.json, and in app.ts `import.meta.env.API_BASE_URL` with the local server's address as the default. The value is public: never put a secret there.
5. Validate each read in the data source before it returns. Return a shaped reply for each refused write (for example, a duplicate), so `then` keeps the form open and shows the reason.
6. The starter's `persona` values are public development identities, not sign-in. If the app needs real authentication, tell me: the session helper is the app's to write, and Exact does not provide it.
7. In app.test.contract, add a test for each read and write, and one for each refusal. `request POST "/<path>" {…} as <persona> expect <status>` writes through the server as another person.
8. Follow the platform checks in docs/start-here.md (`bun exact.mjs docs platform checks`) for the targets in the app's AGENTS.md and app.json until they pass. Read the reports, including counted findings; a zero exit code alone does not mean clean. They start the server on an empty database and stop it: start none of your own. If a dev server is on that port, they stop and name its pid: tell me, and stop it only if you started it. Fix the app, not the test. If a finding stays after three rounds of fixes, or the app had it before you changed anything, record it (step 9) and report it; do not keep trying.
9. When a doc was wrong or missing, or a step needed a workaround, read `bun exact.mjs feedback status`. Under `never`, keep no note. Otherwise record it locally: `EXACT_FEEDBACK=0 bun exact.mjs feedback note "<what happened>"` (use your shell's environment syntax). Do not change the saved policy or send notes, even under `always`; tell me how many you kept.
10. Tell me the server's entry, address and database, what the tests and verify reported, and the launch command for each target platform.
```
