Result: both agent-opened pages laid out first at 1280 x 800 (the shown tab_1, and tab_2 opened with open:false in no stage).
Why: the page is made by the data module's browserSync at the web view's initial 640 x 480 frame and starts loading at once;
for an agent tab the host's open waits for the page (polling every 50 ms) and sets 1280 x 800 (T3BrowserViewport.hold) before
a new WebContent process has the page parsed. That is a race the host wins here, not an ordering. A tab that arrives at a fixed
size with no host wait (part 4's default viewport, or a tab another client opens at a fixed size) has no hold, so its first
layout is 640 x 480 until the stage sizes it: the fix belongs where the page is made (browserSync could carry the fixed size).
