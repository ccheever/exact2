# X7: App Transport Security keys cannot be set from `app.json`, so a rendered HTML preview cannot load `http://` assets from a named host

## Summary

T3 Code shows an `.html` file or attachment in a sandboxed frame whose page may load stylesheets,
scripts, images and fetches from any `http` or `https` host. The clone shows the same page in a
`WKWebView`; App Transport Security (ATS) refuses plain `http://` to a host that is not an IP address,
and `app.json` has no field to set ATS keys. The clone has no workaround. Needed: an `app.json` field
that writes the ATS keys into the macOS `Info.plist`.

## Why this issue arose

### The T3 Code behavior
- Files panel, an `.html` file in rendered mode: a spinner while the asset URL is minted, "Unable to
  load file preview." if minting fails, otherwise `<iframe sandbox="allow-scripts allow-forms
  allow-popups allow-modals">` on a white background with an opaque origin
  (`apps/web/src/components/files/FilePreviewPanel.tsx:205-232`,
  `.../files/BrowserDocumentFrame.tsx`). Sent attachments use the same frame
  (`.../files/AttachmentFilePreview.tsx:245`).
- The desktop renderer's content security policy admits frames from `'self' blob: http: https:`
  (`apps/desktop/src/electron/ElectronProtocol.ts:101`; test `ElectronProtocol.test.ts:275`). The page
  inside the frame keeps its own policy, so its sub-resources load from any host. Chromium has no ATS.
- A page can link a dev server or a CDN by name, for example `http://app.test:5173/main.css`; the
  frame has no rule against it, so the page renders fully.

### What exact2 does today
- GAPS X7 (EXACT2-GAPS.md, written by earlier sessions from framework source at exact2 `c1522fdac`,
  checked against `main` `d2cb661eb`): "WKWebView blocks plain `http://` to hosts that are not IP
  addresses (App Transport Security; r12-render finding). `app.json` cannot set ATS keys. Support needed:
  An `app.json` field that writes ATS keys (e.g. `NSAllowsArbitraryLoadsInWebContent`) into `Info.plist`."
- Bundled library (`20261005-platforms-v3`): not covered: unknown.
- Observed in the clone tree (mc-orch, 2026-10-05): a search of the whole tree finds no
  `NSAppTransportSecurity`, `NSAllowsArbitraryLoads` or `NSAllowsLocalNetworking`; `app.json` sets none. The refusal itself was observed by the earlier
  r12-render session, not re-run for this plan.

### Where the clone hits it
- `modules/apple/R6MediaPreview.swift` (hook `t3-media`) hosts the page. Its wrapper policy already
  admits `frame-src 'self' blob: http: https:` (line 34) and the frame carries the reference's sandbox
  (line 31), so the application layer matches the reference; only the system refuses.
- Callers: the Files panel's rendered HTML (`r10-device-files-html.ts`, `r4-surfaces-files.*`) and the
  attachment preview (`r6-media-preview.ts`).
- Workaround: none. What loads today: `https` hosts and `http` IP literals (the round-11 check
  "`page.html` paints style.css, `img/logo.png` and runs `js/app.js`", AGENT-HANDOFF.md:91). What a
  user sees differently: a page that references `http://<named host>/…` shows unstyled text and missing
  images. `README.md:268` and AGENT-HANDOFF.md "Remaining gaps" #1 say the preview loads "only its
  token directory"; that text is stale and `20261005-media-actions` corrects it.

## Why it must be resolved

The goal is to clone T3 Code completely, and a declared difference is not an end state. A preview that
renders differently from the reference's is visible in the first screenshot of any generated page.
`20261005-media-actions` carries one acceptance row ("Rendered HTML, http host") that cannot pass
without this support; every other row of that ticket proceeds. Keeping the current state costs no
code, but leaves the row permanently blocked.
Also to confirm: whether the clone's own `URLSession` pairing to a remote server at
`http://<tailnet or LAN name>:<port>` is refused the same way. If it is, this issue also decides
whether remote pairing over plain HTTP by name works, which is far more visible than previews.

## Requested support

There is no web equivalent (browsers have no ATS; they have mixed-content rules instead). On the macOS
host:
- **A (recommended).** A typed `app.json` field, for example `host.macos.appTransportSecurity`, that
  accepts `allowsArbitraryLoadsInWebContent: true` and writes
  `NSAppTransportSecurity › NSAllowsArbitraryLoadsInWebContent`. This relaxes web views only; module
  networking (`URLSession`) stays under ATS.
- **B.** A general `host.macos.infoPlist` pass-through for any key. More flexible (also covers per-domain
  exceptions or `NSAllowsLocalNetworking`), but a wider surface to review.
- **C (rejected).** Fetch the assets in the app module and feed them to the web view through a custom
  scheme. ATS also governs `URLSession`, so this needs a lower-level client and still breaks the page's
  own `fetch` calls. To confirm.
Other hosts: iOS has the same ATS keys; web and Linux are not affected.

## How to reproduce
To confirm on the pinned `main` at `issue-open`.
1. Minimal app (preferred): a Contract app with an `iframe` (or a native web view) whose `src` is
   `http://<named host>/` that serves one image. Build for macOS, run, screenshot. Expected (reference
   and a browser): the page and image load. Actual: blank frame; the app log shows an ATS refusal.
2. Clone scenario: a lane fixture server on `127.0.0.1:16xxx` and a workspace containing `page.html`
   with `<link rel="stylesheet" href="http://assets.<name>:16xxx/style.css">` and an `<img>`. The name
   must resolve to the fixture and must not be an IP literal or a `.local` name (Apple's documentation
   lists those as ATS-exempt; not re-read here). A wildcard DNS name that resolves to 127.0.0.1 needs
   network access; otherwise the user adds a host entry. Open the file in Files. Compare with the
   reference desktop oracle (`target/t3-ui-parity/electron-oracle.mjs` from
   `20261005-desktop-oracle-and-trace`) on the same page.

## Acceptance for the fix
- `plutil -p` on the built app's `Info.plist` shows the requested key; with the field absent the key is absent.
- The reproduction page loads its stylesheet and image from the named `http` host (agent screenshot and
  `layout` of the frame), and the AppKit test binary `r6-media` gains a case for it.
- Negative control: the same build without the field still refuses (so the field is what changes it).
- If the `URLSession` question above is answered "affected": pairing to an `http://` named host works,
  or the issue states that it needs a separate decision.

## App adoption after resolution

- Move EXACT2-GAPS.md X7 to "fixed". `issue-close` checks the Info.plist, the page, and that the
